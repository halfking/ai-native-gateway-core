## 1. 目标与审计原则

本审计验证网关从客户端请求进入、解析、路由、调用供应商、恢复响应、持久化、展示、统计与反馈的完整链路。每项结论必须以当前代码、测试、数据库结构或运行证据为准；旧报告和方案只用于定位意图与历史风险。

审计要求：

1. 结论区分“已证实”“候选问题”“待外部环境验证”“未覆盖”，不把设计文档或测试名称当作实现证据。
2. 每条问题记录触发输入和调用路径、受影响数据/用户、代码位置、复现方式、级别、修复方案、回归验证及提交。
3. 子代理结论作为线索，由主审复核代码与测试后定级。若并行能力不可用，记录原因并由主审串行覆盖。
4. 先确认不变量与归属，再改行为；迁移必须核对编号、安装器嵌入路径、全新安装与存量升级两种路径。
5. 不以清理为由删除尚未证明无生产消费者的代码。重复实现先形成调用图、行为差异和移除条件。
6. 保持客户端已支持协议的响应语义和流式连接；有可用备用路由时错误留在网关内部并记录，不把内部错误、凭据或敏感原文回显给客户端。

## 3. 全链路与闭环标准

| 阶段 | 必须核对的来源与去处 | 闭环证据 |
|---|---|---|
| 接入 | 客户端协议、tenant/project/user/task、API key、模型、流式模式、原始轮次请求 | 鉴权、身份归属、请求大小边界、请求 ID 唯一且可追踪 |
| 解析与净化 | 原始消息、工具调用、多模态块、附件、未知厂商字段 | IR 解析可逆；敏感信息替换有映射和 occurrence identity；未知字段有协议范围与 TTL |
| 调度 | 候选供应商/凭据、协议能力、权重、限流、队列、路由瀑布、重试 | 记录选择原因、权重、被跳过候选、退避、重试与终态；限流隔离不阻塞无关队列 |
| 出站与恢复 | 厂商原生协议、请求扩展、文件/媒体引用、超长上下文 | 原厂格式匹配；供应商特有参数只在正确请求/供应商/轮次恢复，不串请求 |
| 响应 | 流式 chunk、结束原因、usage、错误、工具调用 | 上游正常/失败/超时/取消/断连均有确定终态；有备用时保持客户端会话连续 |
| 存储 | PG/Redis/memory/files 与 SQLite lite 模式、附件/媒体、三层会话体 | 写入、回填、重放、过期、归档与删除有版本/租户边界和可对账指标 |
| 展示与反馈 | 会话详情、轮次摘要、凭据错误、节点状态、统计、账单/对账 | UI/API 状态一致；用户纠错、供应商错误与自检反馈进入单一可追踪的数据路径 |

闭环验收必须覆盖成功、可重试失败、不可重试失败、客户端取消、供应商切换、进程重启、缓存失效、数据库降级及恢复。报告不得只证明“写成功”，还要证明读取、展示、聚合和清理语义。

## 4. IR 核心身份与数据契约

IR 可以由多个有版本的 Go 类型和持久化记录组成，不要求塞进一个超大结构；但下列身份、关联和语义必须明确，序列化/反序列化后可对账：

| 分组 | 必审字段与不变量 |
|---|---|
| 身份与时间 | `request_id`、`conversation/session_id`、`turn_id`、`turn_index`、`parent_turn_id`、tenant、project、user、task、创建/接收/开始/完成 UTC 时间；唯一性、幂等键、时区和跨重试一致性 |
| 内容与轮次 | 原始请求与响应、关键文本、角色、工具调用/结果、多轮顺序、每轮人类可读摘要、格式剥离前后来源；不得以摘要替代原始数据 |
| 协议与供应商 | ingress/egress/client/provider 协议、请求类型（chat/message/response）、stream 标记、模型原名与归一名、provider ID、credential ID；凭据密钥不得进入 IR 展示/日志 |
| 路由与流程 | route/attempt ID、候选集、瀑布阶段、权重/限流结果、决策来源、节点、fallback、重试次数、流程阶段、错误类别与终态 |
| 内容版本与隐私 | `original → sanitized → compressed` 版本、内容哈希、身份/occurrence 映射、SanitizedMessageRefs、AlignmentMap、offset 分配器版本、TTL、脱敏策略版本 |
| 扩展与能力 | provider/model/protocol 范围的未知原厂参数、schema/来源、有效期与恢复条件；过期、冲突和不支持字段须可观测且不得泄漏至其他供应商 |
| 附件与媒体 | attachment ID、原始文件名、检测 MIME、大小、digest、解析器/版本、owner/tenant、对象或文件 URI、存储版本、保留期、扫描/解析状态 |
| 用量与费用 | input/output/cache/reasoning token、usage 来源与置信度、供应商成本、内部计价规则版本、API key/credential/model 归属及对账状态 |
| 标签与观测 | 多个 tag 的类型/来源/生命周期、trace/span、provider-window source telemetry、缓存层命中、队列等待/供应商耗时；限制高基数与敏感维度 |

每个字段应能回答：谁创建、谁修改、谁持久化、谁读取、是否可缺省、保留多久、跨协议是否有损、如何迁移。强类型字段、扩展字段和派生展示字段要分清。

## 6. 横切验收门

### 6.1 超长会话与连续性

- 明确 1M 阈值的计量单位（token、字符、字节或窗口比例），阈值与开关可配置并有边界钳制。
- 普通压缩、供应商 context overflow 重试、handoff 三条路径分别验证；重复压缩/重试有最大次数、总时限、取消和幂等保护。
- handoff 只在客户端 agent 协议支持时自动执行；`/new` 的所有者、调用格式、上下文移交内容、失败回退和用户可见反馈须有契约。未知客户端不得收到伪造工具指令；不可执行时不中断现有会话并提供非阻塞提示。

### 6.2 迁移与大表

为每张大表维护一行清单：表/数据量/热表与分区表/分区键/保留期/查询读面/写入者/清理任务/迁移和回滚/安装器登记/真库验证。归档应有分批上限、租约或互斥、重启续跑、幂等校验、行数与内容对账；禁止把 DELETE 或 UPDATE 从 hot 扩散到长期分区表。

### 6.3 计费、错误与节点状态

内部计价与供应商对账须能下钻到 API key、credential、model、provider、请求/轮次；展示分清估算/实报、币种、价格版本和差异。供应商错误记录需去敏、可关联凭据且可评估质量。节点状态更新必须有单一权威写路径，探测、请求成功/失败、人工干预和熔断反馈有清晰优先级。

## 7. 证据、分级与验证

沿用 [审计纪律](audit/playbook/conventions.md)：P0 部署阻断或硬失败，P1 数据/契约/闭环正确性，P2 边界/一致性/并发，P3 代码卫生和低风险债。每项至少写明：`file:line`、触发输入、执行路径、实际结果、预期结果、影响面、复现/测试、修复和复核状态。

每次修复按影响面验证：

- Go：`go build ./...`、相关包 `go vet`、相关包 `go test -count=1`；共享状态/队列/offset/异步 worker 使用 `-race`。
- 协议：表驱动 golden 往返覆盖 stream/non-stream、结束原因、工具调用、usage、媒体、原厂扩展和错误。
- 存储/迁移：clean install、存量库升级/回滚、full PG 与 lite SQLite、故障恢复、分区边界/时区、热表与分区表对账。
- 安全：恶意/超大/畸形输入、未知占位符、跨租户、超时/取消/断连、锁竞争、重试风暴、秘密扫描。
- Web/API：权限、错误状态码、i18n、API 与页面状态一致、菜单入口及交互路径。
- 用户已要求单测或集成测试；根据风险使用 `deploy-local.sh` 建立本地环境。没有凭据或一次性数据库时标记未验证，不对生产库执行迁移。

验证日志记录原始命令、退出码、平台/依赖环境和失败分类；流水线截断器的退出码不能代替命令退出码。既有环境失败须在干净 HEAD 对照后再归因。

## 8. 执行顺序与交付

1. **基线冻结**：fetch、检查工作区、确定 48h/96h 时间和 SHA 区间；刷新 codegraph；保存变更文件并集。
2. **方案复核**：逐份对照近 96h 修改的方案、审计、handoff 与当前 main；标注已落地、偏差、未完成和过时信息。
3. **域分派审计**：按 D01–D17 和当前改动命中情况分组；D14 安全、D16 闭环、D17 卫生恒查。读取生产调用链及测试，不只查改动行。
4. **主审复核与分级**：合并候选、去重、实读代码/调用方/SQL/前端，补证据和复现；记录健康链路及未覆盖原因。
5. **方案先行与修复**：P0→P1→P2→P3；新增或行为修复先写小范围方案和回滚/开关，再修代码并添加有效回归测试。跨域风险高的修复互斥分工。
