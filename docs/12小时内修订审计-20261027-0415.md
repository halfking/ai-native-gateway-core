### 0.2 方法（三条腿，缺一条就会漏）

1. **读 diff + 读当前态**：每笔提交都 `git show <sha> --stat` + `git show <sha> -- <file>`，
   再读 `main` 的**当前文件**——因为**提交时的结论 ≠ 合并后的结论**（本轮就有三例，见 §5）。
2. **跑门**：不是读门文件，是**真跑**。`go build ./...`、`installer` 模块全量、
   审计守卫七包、`guards-sync`、迁移投递腿门、启动清单门、`scripts/ursmcheck` 整包。
3. **读数用 overlay 复现**：怀疑某处有缺陷时，用 `go test -overlay` 把**临时探针**
   从 `/tmp` 注入到包里跑，**不碰共享工作树的源文件**——本轮 3 个 P1 结论都是这样拿到
   运行时证据的（不是靠读代码猜）。
