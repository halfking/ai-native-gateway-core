# i18n 初始化时机问题修复总结

**日期**: 2026-07-08  
**问题类型**: Vue组件中i18n函数调用时机错误

## 问题描述

在Vue 3 + Composition API项目中，多个组件在setup函数的顶层直接调用`t()`函数来定义常量数组或对象。由于`useI18n()`的初始化时机问题，这些调用可能在i18n实例准备好之前执行，导致翻译失败或返回undefined。

## 根本原因

Vue 3的响应式系统要求：
1. `useI18n()`返回的`t`函数只能在组件渲染时或响应式上下文中调用
2. 顶层的常量定义会在setup函数执行时立即求值，此时i18n可能未完全初始化
3. 即使i18n已初始化，顶层常量也不会响应语言切换

## 修复方案

将所有在顶层直接调用`t()`的常量改为`computed`响应式计算属性。

## 已修复的文件

### 1. SessionConfigView.vue (行12-16)

**修复前**:
```typescript
const tabs = [
  { key: 'approval', label: t('sessions.config.approvalTab'), icon: '✓' },
  { key: 'compression', label: t('sessions.config.compressionTab'), icon: '🗜️' },
  { key: 'health', label: t('sessions.config.healthTab'), icon: '💚' },
]
```

**修复后**:
```typescript
const tabs = computed(() => [
  { key: 'approval', label: t('sessions.config.approvalTab'), icon: '✓' },
  { key: 'compression', label: t('sessions.config.compressionTab'), icon: '🗜️' },
  { key: 'health', label: t('sessions.config.healthTab'), icon: '💚' },
])
```

**影响**: 修复标签导航的翻译显示，同时需要在使用处将`tabs`改为`tabs.value`（行27、29）

## 检测方法

使用以下脚本可以自动检测类似问题：

```bash
#!/bin/bash
cd web/src
for file in $(find . -name "*.vue" -type f); do
  if grep -q "useI18n" "$file"; then
    awk '
      /<script[^>]*>/ { in_script=1; next }
      /<\/script>/ { in_script=0 }
      in_script && /^const .* = \[/ && /t\(/ && !/computed\(/ { 
        print FILENAME ":" NR ":" $0 
      }
    ' "$file"
  fi
done
```

## 最佳实践

1. **禁止在顶层直接调用`t()`**: 所有i18n翻译调用都应该在computed、函数或template中
2. **使用computed包装**: 需要在setup中定义的翻译常量应使用`computed(() => ...)`
3. **自动解包**: 在template中使用computed时Vue会自动解包，script中需要`.value`
4. **响应式支持**: computed方式还支持运行时语言切换
