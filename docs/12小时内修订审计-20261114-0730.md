## 二、问题清单（本轮发现）

### D-A1（P1，已修）— WIP zstd 并发编码器顶爆 RAW 内存门

- **现象**：主仓 HEAD=ea624ed29 跑 `TestLargeIngressMemoryScaling` 稳定红（100MB×16 并发 heap_delta 172M/185M/182M > 门 144M，三连红）；同提交在隔离 worktree 上全绿。
- **归因**（stash/复原二分 + 逐文件撤回）：**WIP 的 largebody zstd 压缩是根因**。`zstd.NewWriter` 默认 `EncoderConcurrency=GOMAXPROCS`（本机 10+），每个 Encoder 预分配并发 block 池（数 MB/实例）；LargeIngress 4 并发槽 × 池 ≈ 38M 缺口，与实测吻合。
- **修法**：`codec.go` 显式 `zstd.WithEncoderConcurrency(1)`——文件顺序流式写，并发编码零收益。补丁后内存门三连绿，largebody 27 测全绿。
- **教训**：并发组件进内存门路径前必须显式收并发度；「门禁红先查是否在制引入」用 stash 二分比逐提交 checkout 快。

### D-A2（P2，登记不修）— dispatch 旁路检测 chunked 盲区

WIP `main_pipeline.go` 旁路防御：`r.ContentLength > 32<<20` 对 `ContentLength==-1`（chunked）失效。LargeIngress 在役时归档路径已换 body（有 ContentLength），盲区仅在「旁路+chunked」复合异常态；MaxBytesReader 100MB 第三层兜底仍在。修法指针：检测旁路改用「读前先包 32MB MaxBytesReader 再读」或 io.LimitReader 试探。归下一修复轮（与 P2-2/P2-3 同批）。

### D-1（P2，已修）— pluginapi GetPlugin 路径穿越

- **现象**：`GetPluginHandler` 的 `pluginID` 直接 `filepath.Join(pluginDir, id, "plugin-manifest.json")`。PoC 实证：URL `/api/v1/plugins/%2e%2e`（Go ServeMux 解码后 id=".."）拼出 `pluginDir/../plugin-manifest.json`——越一级读任意目录中恰好叫 plugin-manifest.json 的文件。泄露面低危（文件名固定），但这是 d1e3a1832 刚接通的生产活路由。
- **修法**：id 为空/`.`/`..`/含 `/\\`/`filepath.Base(id)!=id` ⇒ 400 fail-closed。pluginapi 全测绿。

### D-2（P2，已修）— ipc connectionPool Close 竞态（send on closed channel）

- **现象**：`Close()` 持锁 `close(p.conns)` 后 drain；`Put()` 先验 closed（持锁）→ Unlock → select send。时序「Put 过了 closed 检查 → Close 执行 close → Put send」⇒ panic。
- **附带实锤**：`Client.Send` 直接 `pool.dial()+conn.Close()`，**pool.Get/Put 零调用**——整个 pool 是死代码（死面），但 377e8840a 刚把六模块测试修绿，接线前必须清掉这颗雷。
- **修法**：Close 不 close channel，改「closed 标志 + 持锁非阻塞 drain」；channel 永不 close ⇒ 任意时序 send 安全。ipc 全测绿。

### D-3（P3，登记不修）— compressedFile ReadAt 向后跳重开整文件

span 乱序访问最坏 O(n²/64KiB)（每次回跳重解压全文件）。1MB 归档体可接受；100MB 体在 Reduce 的 span 顺序访问模式下极少回跳。修法指针：FrameReader 支持帧目录（header 记帧偏移表）跳帧解压。归 100MB 专项后续轮。

### O-1（观察，不修）— strict 模式 oversized 条目 DB 回读循环

`getLocal` strict 拒 oversized → loadFromDB → setL1 重存 oversized → 下次再拒。strict 语义=「宁打 DB 不交大 body」，行为自洽；仅提示 strict+大 body 会话高频时 DB QPS 放大。

- F3「session_turns 写入错误」结论过期成立（377e8840a 订正正确）：session 层无独立归因写路径，turn_writer 直传 ProcessedRequest.ErrorKind。
