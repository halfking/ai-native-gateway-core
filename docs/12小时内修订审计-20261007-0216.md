## 二、修复明细（本轮代码/文档改动）

### 2.1 R49-C1 — errors/trend 租户越权（P1，唯一数据面越权）

根因是「解析了但没接线」：`EffectiveTenantIDAll(r)` 的返回值写进 statsQuery.TenantID 后，三条 SQL（loadFromStats/loadFromDetail/loadBreakdowns）无一引用，而读事务主动 `set_config('app.bypass_rls','true')` 把 V371 的 FORCE RLS 租户策略也一并绕掉——两个「本应保护」的机制互相抵消成裸通读。修复按两条腿分治：stats 表**没有 tenant_id 列**（聚合键 stat_time/granularity/supplier/credential_id/error_type/model——子代理声称「两表均含 tenant_id」经主代理实读 V371:327-350 证伪），借 `credential_id IN (SELECT id FROM credentials WHERE tenant_id=$7)` 落实；unified 明细腿直接 `($6='' OR tenant_id=$6)`。super_admin/admin_key 空串语义不变。回归门用「期望正则匹配 SQL 文本中的租户谓词」构造，变异（期望参数 acme→wrong-tenant）实测红，恢复后绿。

### 2.2 R49-D1 — bg 门测试环境变量改名遗留（P1）

0222cb254 把 destructiveGate 的逃生阀从 `URSM_825_ALLOW_ANY_DB` 改名 `URSM_830_ALLOW_ANY_DB`（830 改标 .sql.skip 的连带），只改了门和 realdb 测试、漏了同目录的 destructive gate 单测——`t.Setenv` 设旧变量，门读新变量，逃生阀测试从此必红。修复=sed 同步 4 处（:69/:84/:86/:92）；bg 全包复跑转绿（此前它是 bg 唯一红点，主干红会掩盖真回归）。

### 2.3 R49-A1 — /m 与 /maintain 进安全头链（P1）

原结构 `chain(mux)` 之后 `mobile(maintain(chain))` 再包一层——两个挂载在链外。修复：`publicSurface = mobile(maintain(mux))` 先组合，链 `Build().Then(publicSurface)` 包最外。连带两个正确性细节：① AuthMiddleware bypass 名单必须补 `/m`（exact）+ `/m/`、`/m-assets/`（前缀），否则 /m 全部 401 missing_key（名单里原有的 `/maintain/`、`/assets/` 条目证明 bypass 意图早已存在，只是从未生效——挂载在链外时这些条目是死配置）；② maintain 网关同享修复（它同样是带登录态的运维面）。门×3：行为面两条（/m 三形态与 /m-assets 响应必须带 X-Frame-Options/nosniff/Referrer-Policy 且不 401）+接线面一条（main.go 必须 `Then(publicSurface)` 且不得再出现链外包裹形态——组合函数行为正确不代表调用点没被挪回链外，文本锚定防回归挪位）。

### 2.4 R49-C2 — audio 错误投影结构化提取（P2）

`audioUpstreamStatusError`（audio_service.go:424）是 2026-10-04 为小米 400 归因引入的自有类型，只有 Error() 文本。buildRow 的类型阶梯（*upstream.Error → 消息分类）没有它的位置，于是 audio 每条失败 http_status=NULL、error_kind 兜底 transient——凭据详情 distinct_status_codes、类型分布对音频面全失真。修法选**结构化接口**而非具体类型断言：executors 不 import streaming（反向会成环），`interface{ StatusCode() int; Body() string }` 沿解包链匹配，未来其它 modality 的自有错误类型实现同方法即自动纳入；kind 用现成的 `ClassifyErrorWithBody(status, body)`（429 状态门+配额词面与 chat 面同语义）；audio 侧补两方法+编译期契约断言防签名漂移。

### 2.5 R49-D2 — SET LOCAL 死守卫（P2）

`SET LOCAL` 的作用域是**当前事务**；pgxpool 单语句 Exec 是 autocommit，GUC 随语句结束蒸发。合并为与 DDL 同串（SimpleProtocol 多语句单隐式事务，db.go:73 配置实证；同文件 ensureSessionSummariesAccessColumns :989 是既有正确范式）。

## 七、方法论沉淀（给下一轮）

1. **「解析了但没接线」的越权形态比「没解析」更隐蔽**：EffectiveTenantIDAll 的调用看起来就是防线（grep 有命中、参数包有字段），但参数包进 SQL 前散伙了。租户谓词要有自己的门（本轮回归门用「期望正则匹配 SQL 文本」使无谓词实现直接红），RLS 旁路与应用层过滤必须成对审计——旁路把最后一道兜底也拆了。
2. **中间件链外的挂载 = 安全头/日志/追踪全免**：新 SPA 挂载（maintain/mobile 先例）默认包在链外是惯性错误，AuthMiddleware bypass 名单里躺着的死配置（/maintain/ 早登记却从未生效）是「接线意图存在但从未验证」的形态学特征——bypass 名单与实际挂载拓扑要有对账门。
3. **门改名是 env 变量/配置键级别的高危重构**：门、realdb 测试、单测、文档四处读同一把钥匙，改名漏一处就是把该门的测试变恒红或恒绿——bg 唯一红点潜伏两天无人发现，主干红必须当天归因。
4. **「重复存在 ≠ 重复被拒」二犯**（R48-F1 同族）：ON CONFLICT 语义（拒）与双写语义（并存）在注释里被混用，实测 dup_ratio=2.000+distinct_pkey==total 才能定案——凡「N% 被拒」类声称必须给出被拒行的直接证据。
5. **子代理断言也要复核**：C1 修复时子代理报告「supplier_error_stats 含 tenant_id」经实读证伪（V371:327-350 无此列）——若照单全收，修出的 SQL 会直接 42703。
