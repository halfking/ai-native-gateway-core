## 问题1: 登录验证码阻塞测试

### 问题描述
在执行 Maestro 自动化测试时，`02-account-close-logout.yaml` 测试失败，原因是登录时触发了验证码要求。

**错误现象**：
- 测试断言失败：无法找到"总览"(Overview)元素
- 实际页面显示："连续登录失败次数过多，请输入验证码"

### 根本原因
后端安全机制 (`admin/auth_captcha.go`) 在连续登录失败3次后会强制启用验证码：

```go
// CaptchaFailureThreshold 是**强制**验证码所需的连续失败次数。
// 低于它：验证码可选（required=false）。达到它：required=true，
// 登录必须携带验证码。任何一次登录成功都会清零计数。
CaptchaFailureThreshold = 3
```

由于多次运行测试（包括失败的尝试），触发了这个阈值，导致后续测试无法通过登录。

### 解决方案

#### 临时方案（已执行）
重启后端容器清空失败计数器（因为是内存态存储）：

```bash
docker restart llm-gateway-local-8782
```

#### 长期方案（建议）

1. **测试环境配置优化**：
   - 为测试环境提供更高的失败阈值
   - 或者提供测试专用账号，跳过验证码检查

2. **测试流程改进**：
   - 在测试套件开始前重置失败计数
   - 或者在测试脚本中添加验证码处理逻辑
   - 确保每次测试使用正确的凭据

3. **监控和诊断**：
   - 在测试日志中记录验证码触发情况
   - 测试失败时检查是否是验证码问题

### 验证结果
重启后端服务后，重新运行测试，预期能够正常登录并完成测试流程。

## 经验教训

1. **自动化测试需要考虑安全机制**：
   - 验证码、频率限制等安全功能会影响自动化测试
   - 测试环境应该有配置选项来调整这些阈值

2. **失败分析需要查看实际UI状态**：
   - 不能只看测试断言失败的元素
   - 需要检查截图和UI层次结构，了解页面实际状态

3. **状态管理很重要**：
   - 连续测试运行会累积状态（如失败计数）
   - 需要在测试套件中考虑状态重置

4. **文档化配置参数**：
   - `CaptchaFailureThreshold = 3` 这样的配置需要在测试文档中说明
   - 测试人员需要知道这些限制
