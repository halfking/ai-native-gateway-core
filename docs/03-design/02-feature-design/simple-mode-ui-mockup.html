简易模式 · 控制台效果稿

这份稿子把《简易模式与专家模式 · 设计方案》里描述的界面画出来。外壳结构照抄 App.vue / AppTopbar.vue / AppNavDrawer.vue 的真实形态：桌面是顶栏加分组标签，悬停下拉展开该组条目，没有常驻侧栏。

稿子与方案的关系：方案文档回答「为什么这样分层、机制怎么落地」，这份稿子回答「用户实际看到什么」。两处的口径一致：导航从 67 个入口收到 14 个可见页面，专家面收进折叠组而不是消失，设置页只露 3 个类别。

本稿是提案而非现状截图。当前控制台的导航图标用的是 emoji 字形（appNav.ts 里 icon: '🤖' 这样），与 DESIGN.md §6「图标是画出来的」冲突。本稿统一用 SVG，落地时顺带把这批导航图标换掉。

简易模式 · 系统设置

24 个类别只露 3 个，其余收进高级区

工作模式开关放在设置页顶部，切换前列出影响清单并区分「立即生效」与「需要重启」。被降级的项带徽标标出来，不藏在没有标记的灰色里。

稿子里的设计取舍

每一条都对应方案里的原则
决定做法理由
专家面折叠不隐藏 收进「高级」分组，54 条，展开可见 与仓内「不擅自改菜单」约定一致；深链可达；用户以后变专业了东西还在
用量统计是简易模式新页 另起一页「用量统计」，只呈现本租户的 Token 与花费 个人用户要知道花了多少钱，但不需要供应商维度拆分、模型分线与对账口径
系统设置单独成组 从「数据运维」组里提出来，顶栏单列 工作模式开关在那里，它不该藏在高级折叠组里
模式指示器在顶栏 只显示当前模式，切换动作指向设置页 权威入口是设置页（那里有影响清单）；顶栏只做状态可见，不做第二份真相
降级项带「已降级」徽标 开关行内标出，并标「需重启」 降级了要说降级了。灰色但无标记等于不可见的强制行为
指标做成一条分格面 4 格共处一个面板，每格带口径 指标要有语境，不是四个数字并排
简易模式保留新手引导 总览顶部一条 4 步进度，当前步高亮 个人用户第一次打开控制台，应该先看见「还差什么」
导航图标用 SVG 手写线条图标，非 emoji DESIGN.md §6「图标是画出来的」。当前控制台导航仍在用 emoji 字形，落地时一并换掉

稿子没画的部分：移动端（AppBottomNav 的底部导航在简易模式下的取舍）、供应商凭据页与密钥签发页的具体表单收窄、以及熔断语义改写后错误文案的措辞。这几处需要先定行为再画，不是画完再定。

本稿的界面数据是示例值，用于呈现布局与层级，不代表生产数据。结构照抄 App.vue / AppTopbar.vue / AppNavDrawer.vue，令牌取自 web/src/style.css，遵循 DESIGN.md 的控制台规范。
