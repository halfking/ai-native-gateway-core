v1 的四个问题

先认账：v1 做对了什么，卡在哪

v1 稿已经完成三件硬事：把专家面入口压成「14 露出 + 47 折叠」、 把功能分成保留 / 降级 / 隐藏三档、把「装到能用」拆成 5 步。 这三件事 v2 一条不动。卡住的是首页的信息形态与接入的步骤数。

v2 改首页与接入的形状 v2 不动v1 的全部纪律
问题证据v2 的处置
Q1 首屏是仪表盘，不是清单 v1 概念稿首页同时摆着 8 个并列区块：4 个 KPI 格（今日请求 / 成功率 / Token 用量 / 首字延迟）、 引导条、最近请求表、接入客户端面板、上游状态面板、工作模式面板。
用户心里的对象是「我客户端在用哪个模型、能不能用」；首页回答的却是「网关今天跑了多少」。		 首页换成接入清单：一行一个网关密钥/客户端，行内显示 当前模型 / 健康 / 今日请求 / 失败 / 预算。 KPI 不删，收成清单页头一行小字。
Q2 接一个上游要跨三个表单、两道门 新增供应商表单要填 目录代码 / 名称 / 协议 / base URL / 备注（ProvidersView.vue:1146-1246） → 再加凭据（API Key + 标签，:1582-1600）→ 再建模型绑定； 可达性探测是提交前的串行门。 两字段快速接入：选目录 → 贴 Key → 完成。 base URL / 协议 / 模型清单由 provider_catalog 自动填，探活转后台， 并发 / 余额 / 标签 / 备注进「更多设置」抽屉。
Q3 模型清单对普通用户是静态目录 真能力其实有：discovery/discovery.go:326-347 能按厂商端点拉模型， admin 有「从供应商读取」按钮（providerDetail.ts:295）， cmd/verify-model-fetch 与它同一条解析路径。
但这些都在专家面的供应商详情页里，简易模式看不到。		 模型选择器改三段：① 该供应商当前提供的 ② 本区间有请求的 ③ 完整目录。 ① 走既有 discovery，不是新数据源；② 沿用 11-16 审计落地的置顶组。
Q4 关停 / 零流量对象没有位置 11-16 审计刚修完一个真问题：43 家在册但零流量的供应商此前完全不可见 （dc263b085，修法＝把在册供应商并进候选、requests=0 排在有请求的之后）。 供应商页加「已关停 / 零流量」折叠带计数：折叠起来但计数可见，排序契约不变。

v1 做对的八条，v2 一条不动

① 模式是投影，不是第二套实现
两个模式跑同一份代码，差别只在「哪些装配点被调用」和「哪些面板被渲染」。为简易模式另写一套逻辑，几个月后没人说得清哪条是活的。
② 一个开关，一个真源
模式只有 gateway.mode 一个注册项；可见性判定只有 canShowNavItem() （appNav.ts:299）一处。禁止在 63 个入口各写一个 if (simple)
③ 显式高于隐式，两种强度分开
override（模式决定，env 也盖不过）与 default（数据库 > env > 预设）分开， 避免「0=禁用 被实现成 0=全量」那类语义反转。
④ 降级必须可见
凡是简易模式改了运行时行为，界面必须标「已降级」，并给出详情入口与降级后的实际取值。
⑤ 专家模式是严格超集，切换不丢数据
不删数据、不重置设置；模式自身的写入面只有一个键 ⇒ 否掉「切模式时批量写 settings_kv」。
⑥ 折叠，不隐藏
不露面的条目仍然可达、不删除；v2 只是把「折叠」做得更显式（带计数）。
⑦ 三档功能清单
保留 / 降级 / 隐藏，第三档专门治「不可见的强制行为」——这一档一个都不许省。
⑧ 接上游只填一个 Key、密钥只填两个字段
v2 把这两条从「纸面承诺」兑现成真的表单形状：两字段就是两字段，其余进抽屉。

借鉴与不照搬

学到什么，以及学到哪一步为止

借鉴五条（v2 的全部改动来源）

B1 · 首页清单化：一行一个对象，行内可改关键属性
来源：magpie 首页即 Agents 清单（index.html:117）。落点：接入清单页，行内显示 当前模型 / 健康 / 今日请求 / 失败 / 预算；点行进详情，不跳页。
B2 · 默认值替用户做完决定，细节收进抽屉
来源：magpie 的 preset + hiddenDrawers（app.js:9300）。落点：快速接入面板复用 provider_catalog（base_url_template / protocol / models_manifest_json）。
B3 · 清单来自事实源，不编译进代码
来源：magpie「nothing compiled in」。落点：模型选择器第一段走既有 discovery；★ 不新造数据源、不新造组件。
B4 · 关停对象折叠且计数可见
来源：magpie「Turned off + 计数」。落点：供应商页折叠「已关停 / 零流量」，并保持 11-16 审计的排序契约（有请求的在前）。
B5 · 一键遮蔽 + 能力门灰显
来源：magpie「Hide accounts」与 data-feature。落点：上游页遮蔽开关；授权不足的可选块灰显并写明原因。

不照搬五条（跟了就丢功能特性）

N1 · 不改用户机器上的客户端配置
magpie 直接改 settings.json / config.toml。我们是服务端网关，客户端配置不归我们写，也不该写（越权 + 不可回滚）。
N2 · 不靠删能力换界面干净
租户 / 角色 / 配额 / 审计 / 对账 / 插件 / 运维中心是我们的产品边界与商业价值。简单必须靠投影与折叠，不能靠删能力——这是 v1 原则⑤的延续。
N3 · 首页不只留一个模型选择器
我们的用户还要管预算、限额、密钥与路由，这些不能消失，只能被折叠、被收进抽屉。
N4 · 不引入文件态配置
本仓事实源是 PG + Redis，多实例；文件态会引入一致性事故（10-30 轮 magpie 对比已列为产品差异）。
N5 · 不引入进程内 JS 中间件
本仓插件运行时是 supervisor + 进程外（10-24 轮 §不照搬清单）；形态不同不能照搬。
