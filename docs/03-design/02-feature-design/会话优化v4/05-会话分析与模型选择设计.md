### 1.3 供应商切换指标（implemented；deployment pending）

| 指标/事件 | 当前用途 | 验收口径 |
|---|---|---|
| `dispatch_failover_total{kind="cred_retry|cred_switch|model_change"}` | 统计同凭据重试、凭据/供应商切换和模型变化 | `cred_switch` 结合 journey/live action 的 provider/credential 字段区分是否跨供应商；不得把模型切换等同于供应商切换 |
| `gateway_survival_attempts_total{kind,provider}` | 按供应商归因 survival attempt 成败 | 计算供应商尝试、错误种类与最终成功；切换率需按同 request/attempt 序列关联，不能仅用单个 counter 推断 |
| `routing_state_source_total{source}` | 观测 authoritative/off/canary/fallback 等状态源 | authoritative 上线后 `source="authoritative"` 应增长，`fallback` 非零按 runbook 触发回退 |
| `dispatch_forwarded_total{credential,result}` / `dispatch_overflow_total{reason}` | 首字节前后失败与无路由/队列溢出 | 与切换成功率、无候选率和 P99 联合判定，避免只看切换次数 |
| `node_switch` live action / request journey | 还原 from/to credential、provider、reason、retry_seq | 用于单请求证据和审计，不替代聚合指标 |

客户端 TCP 已断开时不能将后续 detached/pending/durable 处理计为“同连接切换成功”。首语义帧后禁止透明重放。完整边界见[稳定性审计](../audit/2026-08-17-ursm-v2-client-provider-stability-audit.md)，部署阈值与回退见[cutover runbook](../runbooks/ursm-v2-cutover.md)。

## 2. 任务模型选择（主题⑧）

### 2.1 已实现（implemented）
- **Goal cost_mode 三档 preset**：minimal（2 retries/40s，monthly 500K）/ balanced（3/50s，2M）/ aggressive（5/120s，10M）。
  - ⚠️ 勘误：minimal 与 balanced preset 均为 `UseAudit=false`，aggressive 为 `UseAudit=true`。运行路径通过 `ModeConfig.UseAudit`/`goal.audit_enabled` 决定是否审计；`UseAutorouteForAudit` 只决定审计模型选择。
- 配置优先级：租户显式配置 > Cost Mode Preset > 平台默认（minimal）> 硬编码 fallback。
- **LoopDetector**：hash 命中切模型（`model_switch_count` 指标）。
- **审计/修复模型选择**：autoroute.Decider（`UseAutorouteAudit`）。
- **客户端类型识别**（41/42）：holder=`{userKey}|{clientType}`；userKey = StickyKey（`{tenant}:{app}:{apiKeyID}:{profile}`）→ X-Request-Id → "anon"；clientType = X-Gw-Client-Type 头 → UA 匹配（11 类）→ "unknown"。不用 IdentityHash。
- **Goal 检测三策略**：P0 Structured Output / P1 Keywords / P2 LLM 信心分。
- 不可重试错误黑名单：KindAuth / KindContentFilter / KindContextLength / KindQuotaPermanent。
