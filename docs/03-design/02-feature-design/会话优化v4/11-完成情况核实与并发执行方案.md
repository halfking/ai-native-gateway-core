## 2. 当前事实重核（authoritative）

### 2.1 四态定义

| 状态 | 定义 | 是否可发布 |
|---|---|---|
| **IMPLEMENTED** | 代码/schema 已存在，可能仅有单测或静态证据 | 否 |
| **LOCAL_VERIFIED** | 当前基线在本地 build/vet/test/race 或隔离依赖验证通过；所有 SKIP/模拟已明示 | 否 |
| **RELEASE_READY** | G0..G4 全过，真实 Redis/PG/provider/目标环境无关键 SKIP，回滚可执行 | 可进入 G5 |
| **BLOCKED** | 存在产品决策、migration ledger、真实依赖、环境或未解释回归阻塞 | 否 |

状态只能按证据升级；`IMPLEMENTED ≠ LOCAL_VERIFIED ≠ RELEASE_READY`。同一主题有 blocker 时，以最低安全状态为发布裁决。

## 3. 当前阻塞事实

### 3.1 Handoff expiry（已关闭 2026-08-17）

历史问题：`TestConfirmationStoreAcceptsTargetCreatedWithinProposalSecond` 曾使用固定 `proposalTime=2026-08-17T03:00:00.9Z`，fixture 随现实时间推进不稳定；`NewConfirmationProposal` 正确要求 `expiresAt.After(time.Now())`，生产 expiry 约束本身无错。

2026-08-17 裁决已执行（采用"相对未来时间"分支，未改生产代码）：

- 固定日期替换为整秒锚点相对时间（`secondAnchoredNow()` + 900ms 亚秒偏移），同秒 target 语义保留，任意时间运行稳定；定向 30 次重复、handoff 包 `-race -count=2`、全仓 `-count=1` 均通过。
- 新增边界覆盖：非未来 expiry 拒绝（过去/当前时刻）、刚过期（-1ms）及过期后重复确认仍 expired、确认后同 key 幂等重放/异 key `ErrConfirmationReplay`、restore 重启恢复链（accounting 提交后 attempt→restored 独立推进、终态重放安全、恢复后 confirm 幂等）。
- 生产 `confirmation.go` / `confirmation_pg.go` expiry 校验零改动，未删除/放宽任何约束。

### 3.3 真实依赖边界

- Redis：`miniredis` 与不可达地址 client swap 只能证明客户端错误路径，不能证明真实 Redis restart、script cache、Pub/Sub 和连接池重连。
- PostgreSQL：525/526 已有真实 PG17 隔离 schema 验证；但 handoff/durable fault injection 仍有 PG 场景 SKIP，二者不能混为“真实 PG 全通过”。
- provider：httptest 与 attempt gate 单测不证明真实 TLS/HTTP2、代理、服务端 close 与公网抖动。

以上任一未关闭，整体状态保持 `BLOCKED`，最高只能写 `LOCAL_VERIFIED`。

## 6. 验证基准

### 每段基础门禁

- `.go` 修改：`go build ./...`
- migration 修改：版本唯一性 + schema lint + 真实 PostgreSQL apply/reapply/down
- 合流：`go vet ./... && go test -race <相关包>`
- M5-1：`go test -count=1 ./...`、全仓 vet/build、相关 race 与 integration tag

### 必须显式记录

1. 命令、commit、开始/结束时间、退出码。
2. Redis/PG/provider 是真实实例、容器、miniredis、sqlmock、httptest 还是不可达地址模拟。
3. 每个 SKIP 的测试名和原因。
4. 失败是否可复现，是否属于当前改动。
5. 发布 smoke 的环境、版本、目标、回滚点；不得记录 secret 原文。
