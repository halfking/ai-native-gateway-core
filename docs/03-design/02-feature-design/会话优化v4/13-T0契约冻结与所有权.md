## 2. 身份契约

| 标识 | 冻结语义 | 禁止混用 |
|---|---|---|
| `gw_session_id` | 网关/客户端逻辑会话的文本标识 | 不能当作数值主键或 client request ID |
| `session_id` | Sessions V2 的文本会话标识 | 不能描述为 `public.sessions.id` |
| `SessionPK` / `session_pk` | `public.sessions.id` 的数值 surrogate key，仅 admin resolver 使用 | 不是文本 session ID，也不是 VibeCoding session ID |
| `request_id` | 服务端为一次 HTTP 请求生成的标识 | 不得与 `client_request_id` 合并；格式不是跨路径稳定契约 |
| `attempt_id` + `attempt_no` | 一次 provider/credential 执行尝试，且 `attempt_no > 0` | retry 不能复用旧 attempt identity |

跨包 fixture 使用可辨识的值，防止同值掩盖字段混用。fixture 只冻结 JSON 形状与字段语义；`SessionPK -> session_id` 的实际解析仍由 `admin` 包内测试覆盖，不能为测试暴露新的生产 API。

- `requestjourney` 的 event、stage、lifecycle 和已知 dispatch error subset 是已冻结词表；增加值必须同时更新 versioned fixture。
- `liveactions.Actions` 是已冻结 action 词表。

- `nodestatecache` 的 `concurrency`、`fp_slot`、`rpm` 仅是 derived read-model 的资源类别；Full bitmap 是 cache projection，Governor/FP 仍是准入权威。T0 不创建新的 resource authority。

## 4. 重启语义

| Lane | 执行恢复 | 结果回放 | Lease / fencing | Mirror 重建 | 上游执行 |
|---|---:|---:|---:|---:|---|
| ordinary dispatch | 否 | 否 | 否 | 不适用 | 重启后不自动继续 |
| pending | 否 | 是 | 否 | 不适用 | 回放读取不得新发起 |
| durable | 是，仅 lease 过期后 | 可投影 | 是 | 不适用 | 仅新 owner 一次；旧 owner 被 fencing 拒绝 |
| queue mirror | 否 | 否 | 否 | 是，仅观测元数据 | 重建不得触发 |

普通 dispatch、retry scheduler 和 registry 是进程内状态。pending 是结果存储而不是 execution recovery。仅 durable snapshot、lease 和 fencing 可以承担重启执行恢复。queue mirror、liveactions 和其他 projection 永远不是执行或计费真值。

## 5. URSM authoritative 契约

1. `ready=false` 必须优先拒绝，full NodeMirror 不得绕过 ready gate。
2. `ready=true + Redis unavailable + full fresh NodeMirror` 必须保护性拒绝，且失败路径不记录 routing source。
3. mirror grace 只能由显式开关启用，并仅限 soft TTL 内；过期后必须回 Redis，Redis 不可用则拒绝。
4. authoritative request-path 的空 tenant 必须拒绝，不能退回 legacy non-tenant key。
5. tenant/model key 使用无碰撞 canonical 编码，并必须直接测试 tenant A 写入对 tenant B 的读取/评分不可见。
6. NodeMirror 读取的 key 必须使用 Manager 配置的 prefix；不得以硬编码 prefix 形成第二套 cache namespace。

若 canonical key 修改要求读取旧 Redis 状态，必须先把双读、切换和过期边界写成单独决策，并交由 Migration owner 评估。本轮不得以静默 key 格式切换代替兼容设计。

## 6. 当前阻断项

### 6.1 delimiter-safe canonical key 尚未实现

当前 `NodeKeyForTenant`、`WindowKeyForTenant` 和 `CandidateIndexKey` 以 `:` 分隔并保留 tenant/model 原文。对于普通、不含分隔符的 tenant/model，T0 测试已经冻结 exact bytes 与 A/B tenant 隔离；但 tenant 或 model 包含 `:` 时，当前编码不能提供无歧义 parse/collision 证明。

此问题保持 **T0 BLOCKED**。修复会影响 Redis 状态 key、`ParseNodeKey`、persist/recovery 扫描、Lua 调用和旧状态读取，必须先形成包含 dual-read、切换窗口、TTL/清理和回滚策略的兼容设计，并交由 Migration owner 评估。当前轮次不得静默引入只写新 key 的变化。
