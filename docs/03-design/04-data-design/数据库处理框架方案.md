# 数据库处理框架方案（internal/dbx）

> 状态：实施方案 v3 · 含模块独立性硬约束与元数据门禁
> 最后更新：2026-08-27（Phase 3 后半：元数据门禁强化 + 真实表试点 manifest）
> 事实基线：`stage-F-2@aeb94f62f`（文档内行号引用以该时点为准）；`pgx/v5 v5.9.2`；Go 1.25
> 阅读对象：网关后端开发、数据库变更评审人
> 关联标准：[数据库变更与真实验证标准](../../standards/database-change-and-real-verification.md)、[sql/ 资产 SSOT](../../../sql/README.md)

## 1. 结论摘要

采用 **pgx-first 自研数据访问框架**：运行时继续复用仓库现有 `*pgxpool.Pool` 与 `pgx/v5`，在 `internal/dbx` 建立一个可整体抽取为独立项目的薄框架层，提供元数据注册、租户作用域事务、严格字段更新、注册表驱动的 CRUD 构造与脱敏观测。框架先在隔离探针表上验证，再按低风险领域渐进迁移；不一次性替换全库数据访问，不接管生产迁移执行。

三条模块独立性硬约束（用户裁决，贯穿所有阶段）：

1. **框架将来可独立成为项目**——模块内禁止 import 任何宿主业务包，项目特定约定（RLS GUC 名等）全部注入式配置；
2. **实体与查询在模块外**——模块只含机制，不含任何业务表清单、实体 struct、业务 SQL；
3. **代码集中在独立目录**——全部框架代码与测试都在 `internal/dbx/` 单一目录树内。

## 2. 模块独立性与抽取边界

### 2.1 依赖白名单

`internal/dbx` 内允许的外部依赖只有：

| 类别 | 允许项 |
|---|---|
| 标准库 | `context`、`errors`、`fmt`、`strings`、`time`、`sync`、`encoding/*`、`math` 等 |
| 驱动 | `github.com/jackc/pgx/v5`（含 `pgconn`、`pgtype`、`pgxpool`） |
| 测试 | `pashagolub/pgxmock/v4`、`testcontainers-go` + `modules/postgres`、`stretchr/testify` |
| 可选 | `go.opentelemetry.io/otel/trace`（仅 trace API，不引入 exporter） |

禁止出现在模块内的 import：`github.com/kaixuan/llm-gateway-go/db`、`domains/*`、`admin/*`、`internal/<其他包>`、Redis、HTTP 框架、业务配置包。验收用 grep 证实（见 §9）。

### 2.2 注入式项目约定

本项目既有约定**不硬编码**进框架，由宿主侧 `db/dbxmanifest` 装配后注入：

| 约定 | 本项目取值（宿主侧填入） | 框架侧形态 |
|---|---|---|
| 租户 GUC | `app.current_tenant` | `ScopeConfig.TenantGUC` |
| 角色 GUC | `app.current_role`，特权值 `super_admin` | `ScopeConfig.RoleGUC` / `SuperAdminValue` |
| 绕过 GUC | `app.bypass_rls=true` | `ScopeConfig.BypassGUC` / `BypassValue` |
| 租户缺省 | `'default'`（数据库函数回退） | 框架侧不设缺省：缺 scope 即失败关闭 |

抽取为独立仓库时：新建 `go.mod`（依赖仅 pgx + 可选 otel trace）→ 整目录拷贝 → 宿主改 import 路径。`internal/dbx/README.md` 记录该步骤。

### 2.3 实体与查询的位置

| 内容 | 位置 |
|---|---|
| 机制代码（接口、注册表、Scope、事务、Patch、CRUD 构造、错误、观测） | `internal/dbx/` |
| 真实表 manifest 注册、ScopeConfig 装配 | 宿主 `db/dbxmanifest/` |
| 业务实体 struct、手写 SQL、领域 repository | 各业务包（现状不变） |
| 探针验证实体（`dbx_probe_records`） | 仅 `internal/dbx/probe_integration_test.go` |

## 3. 当前实现与约束（现状事实）

以下为 `main` 分支当前事实，框架设计不得破坏：

- **连接层**：`db.Open`（db/db.go:20）持有唯一 `*pgxpool.Pool`：MaxConns=32 / MinConns=2、30min 生命周期、强制 `QueryExecModeSimpleProtocol`（防 schema 变更后的陈旧 prepared statement）；启动 Ping 3s。
- **启动迁移**：`ApplyMigrations`（db/db.go:83）以 3 分钟预算、失败一次 5s 退避重试，顺序调用约 50 个幂等 `ensure*` 函数；`gateway migrate` 子命令复用同一路径。框架**不得**引入第二套启动 DDL。
- **迁移多路径并存**：`sql/schema`（SSOT 快照）、`sql/objects`（拆分 DDL）、`sql/migrations/startup`（500+ 文件）、`sql/migrations/domain`、`db/migrations`（历史）、`deploy/sql`、installer 内嵌 SQL、`scripts/run-migrations-strict.sh`（`repository_schema_migrations` + SHA-256 校验账本）。框架不改变任一路径的执行权。
- **RLS 租户隔离**：会话 GUC `app.current_tenant` 由 `public.get_current_tenant()` 读取，缺省回退 `'default'`；特权通道 `app.current_role='super_admin'` / `app.bypass_rls='true'`。安全范式是事务内 `SELECT set_config('app.current_tenant',$1,true)` + 用后 RESET（apihub/pg_store.go:392-459、admin/tenant_ctx.go:13）。已知反例：连接级裸 `SET` + 吞错（domains/freeresource/rls_helper.go）。
- **分区与列存**：写入只进 `*_hot`/`*_default` heap 表；月度历史分区 columnar（不支持 UPDATE/DELETE/UPSERT）；当月全量读走 `*_with_current_month` 视图；`bg.PartitionManager` 负责建分区与 promote。框架的 CRUD 能力位必须能表达"该表不可更新/不可删除"。
- **观测**：slog 结构化日志 + Prometheus 业务指标 + OTel（默认关闭、环境变量开启）；当前没有统一 pgx 查询拦截器。框架 observer 以脱敏结构补充，不替换现有指标。

## 4. 目标与非目标

**目标**

1. 统一"实体字段 ↔ 表列"显式契约（manifest 注册表），杜绝任意表名/列名进入业务 API；
2. 统一租户作用域事务范式（事务内参数化 GUC + 失败关闭 + 双重谓词）；
3. 严格更新语义：missing/null/zero 三态区分，未知字段拒绝，保护列不可写；
4. 注册表驱动的安全 SQL 构造（`$n` 占位 + 白名单标识符）；
5. 脱敏查询观测（QueryID/耗时/rows/SQLSTATE）；
6. 模块可独立抽取（§2）。

**非目标**

- 不做全库 ORM 替换、不生成代码、不做关系图遍历；
- 不做启动期 schema 自动修复（drift 只报告/失败，修复走评审过的迁移）；
- 不接管生产迁移执行（ensure*、strict runner、installer 均维持现状）；
- 不引入第二连接池或 `database/sql` 主路径；
- 不在框架内内置任何业务表、业务 SQL 或项目 GUC 常量。

## 7. 核心契约

### 7.1 DBTX seam

```go
type DBTX interface {
    Exec(context.Context, string, ...any) (pgconn.CommandTag, error)
    Query(context.Context, string, ...any) (pgx.Rows, error)
    QueryRow(context.Context, string, ...any) pgx.Row
}
type TxBeginner interface {
    BeginTx(context.Context, pgx.TxOptions) (pgx.Tx, error)
}
```

`*pgxpool.Pool`、`pgx.Tx`、`pgxmock.PgxPoolIface` 天然满足；不新增全局状态。

### 7.2 Manifest 与 Registry

```go
type TableManifest struct {
    Table        string        // 物理表名（hot/default 表名，绝不写分区父表）
    TenantColumn string        // 租户列，通常 tenant_id
    PrimaryKey   string
    Columns      []ColumnSpec
    SoftDelete   *string       // 无软删除列则 nil：Delete 直接拒绝
    VersionColumn *string      // 乐观锁列，可选
    TouchColumn  *string       // 更新时置 now() 的列（如 updated_at），可选
    Readonly     bool          // columnar/视图等只读能力位
    MaxUpdateRows int64        // 声明的单写行数上限，默认 1（当前写路径全部为单行主键语义）
}
```

- `ColumnSpec` 声明：列名、Go 类型类别、是否可写、是否 JSONB（含大小上限）、默认值由数据库持有的不可写列（created_at 等）；
- 注册期校验：表名/列名合法字符、主键在列集合内、可写列不含主键与租户列、软删/version/touch 列框架管理不可写、重复注册冲突即报错；
- Registry 构建后不可变（快照 + 版本号 + 深拷贝列声明），Lookup 返回防御性拷贝，未注册表返回 `ErrUnknownTable`。

### 7.3 ScopeRunner（注入式 GUC）

```go
type ScopeConfig struct {
    TenantGUC  string // 宿主填 "app.current_tenant"
    RoleGUC    string // 宿主填 "app.current_role"
    BypassGUC  string // 宿主填 "app.bypass_rls"
    SuperAdminValue string // "super_admin"
    BypassValue    string // "true"
}
```

- 租户值只来自**可信认证上下文**（调用方传入），绝不从请求 payload 取；
- 事务内执行参数化 `SELECT set_config(<TenantGUC>, $1, true)`，事务结束自动失效，无需依赖 RESET；
- `WithReadOnlyTx` 使用 `pgx.TxOptions{AccessMode: pgx.ReadOnly}`；
- super-admin/bypass 是**显式独立入口**（`WithSuperAdminTx`），必须由宿主完成鉴权后调用；
- 缺失租户 scope：返回 `ErrMissingScope`，**失败关闭**，不回退 `'default'`；
- RLS 之外，CRUD 谓词同时带 `tenant_id = $n`，形成双重防护。

### 7.4 事务

- `WithTx` / `WithReadOnlyTx`：`BeginTx` → `defer Rollback`（幂等）→ commit；panic 安全；
- savepoint 支持嵌套局部回滚；
- `RetryOnConflict`：对 SQLSTATE 40001（serialization）与 40P01（deadlock）做有限指数退避重试，其余错误立即返回；
- 允许调用方持有 Tx 传播（`WithTxRunner`），repository 禁止私自开并行事务。

### 7.5 Strict Patch 语义

- 输入是宿主定义的 DTO（struct，带 `dbx` 标签）或 `map` 形态的 JSON 对象；
- **missing ≠ null ≠ zero**：未出现（不改）、显式 null（置 NULL，仅可空列）、零值（按类型写入）；
- 未知字段默认 `ErrUnknownField`；`WithLenientUnknown()` 显式开启后必须把 dropped 字段名回传给调用方（绝不静默）；
- 保护列（主键、租户列、审计列、密文列）出现即 `ErrProtectedField`；
- 空补丁（无可写变更）返回 `ErrEmptyPatch`。

### 7.6 CRUD 安全规则

- 只接受已注册 manifest 的表；表名/列名/排序键/操作符全部走白名单校验（`pgx.Identifier.Sanitize` + 正则 `^[a-z_][a-z0-9_]{0,62}$`，63 字节上限对齐 PostgreSQL NAMEDATALEN-1）；
- 值永远 `$n` 占位绑定，标识符永不来自用户输入；
- Insert：仅 Insertable 列，`RETURNING` 全量回读；
- Update：强制主键谓词 + 租户谓词；可选 `version` CAS（零行返回 `ErrConflict`，与 404 语义合并，需区分时先 SELECT）；`RETURNING` 多行返回 `ErrTooManyRows`（运行时最后防线，门禁层见 §7.10 的单列唯一键拦截）；
- 唯一约束冲突（SQLSTATE 23505）映射为 `ErrUniqueViolation`，原始 `pgconn.PgError` 仍可 `errors.As`；
- Delete：manifest 无软删除列直接拒绝（`ErrUnsupported`）；有则置软删列（仅软删列本身，`deleted_by` 等伴生列需宿主显式 patch）；
- Readonly 表（columnar 历史/视图）上 Update/Delete/Insert 全部拒绝。

### 7.7 JSONB 校验

manifest 声明 JSONB 列后，写入前校验：UTF-8 合法、序列化大小 ≤ 上限（默认 256KB）、JSON 结构合法（编码后回解验证）、数值不出现 NaN/Inf（编码即拒绝）。嵌套 map 不做关系表拆分——复杂对象由宿主显式 repository 编排。

### 7.8 Observer（脱敏）

```go
type QueryFact struct {
    QueryID   string        // 归一化 SQL 指纹
    Op        string        // insert/select/update/delete
    Table     string        // manifest 表名
    Duration  time.Duration
    Rows      int64
    SQLState  string        // pgconn.PgError.Code
}
```

结构上**不存在**参数值字段：不记录 raw args、JSON 载荷、密钥、请求正文。宿主可把 `QueryFact` 桥接到 slog/Prometheus/OTel，桥接代码在宿主侧（模块外）。

### 7.9 探针表（隔离验证）

```sql
CREATE TABLE dbx_probe_records (
    id          BIGSERIAL PRIMARY KEY,
    tenant_id   TEXT NOT NULL,
    name        TEXT NOT NULL,
    enabled     BOOLEAN NOT NULL DEFAULT TRUE,
    metadata    JSONB NOT NULL DEFAULT '{}'::jsonb,
    version     BIGINT NOT NULL DEFAULT 1,
    deleted_at  TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
ALTER TABLE dbx_probe_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE dbx_probe_records FORCE ROW LEVEL SECURITY;
-- policy USING/WITH CHECK: tenant_id = current_setting(<TenantGUC>, true)
-- super-admin/bypass policy 同型（GUC 名取自注入配置）
```

仅存在于集成测试，不进入任何迁移目录。

### 7.10 元数据门禁（introspect + diff）

manifest 注册只是声明；接入前必须通过**只读目录对账门禁**：

- `MetadataReader.ReadTable/ReadRegistry`：仅查询已注册表（`information_schema.columns` + `pg_class`/`pg_namespace`/`pg_am`/`pg_inherits` + `pg_index`），不扫描全库；任一注册表读取失败则整体 fail closed（不产出半可信快照）；
- 采集事实：列类型/可空/default/identity/generated、relkind、access method、RLS、FORCE RLS、分区父/子（`pg_inherits` 双向）、**单列唯一键**（有效、非部分、非表达式的主键或唯一索引）；
- `MetadataCache`：不可变快照 + 显式 `Invalidate`（epoch 递增）；宿主在评审过的迁移完成后手动失效，不在请求路径轮询目录；
- `CompareManifest` / `CompareSnapshot` 产出 drift 报告，blocking 规则：
  - 列缺失/类型不匹配/可空不匹配（视图列在目录中恒为 nullable，豁免可空比对）；
  - manifest 声明可写/可插入的列在目录中是 identity/generated（`readonly_mismatch`）；
  - **主键不在单列唯一键集合内**（`pk_mismatch`）——UPDATE ... WHERE id=$n 无单行保证时拒绝接入；
  - relkind 非 r/v/m、分区父表、分区/继承子表、可写 manifest 挂非 heap access method（`storage_mismatch`）；
  - RLS 未启用（`rls_mismatch`）；可写 manifest 未 FORCE RLS（`force_rls_mismatch`，防表 owner 角色静默绕过）；
  - 额外物理列仅报告不阻断（manifest 是显式投影）；快照缺表（`missing_table`）阻断；
- **任何 drift 都不触发 DDL**：修复只能走 reviewed migration，框架侧永远只报告/失败关闭。

## 8. 测试与验收矩阵

| 类别 | 用例 | 层 |
|---|---|---|
| manifest/registry | 注册校验、重复注册、未知表/列 | 纯单测 |
| identifiers | 合法标识符引用、注入样例拒绝 | 纯单测 |
| patch | missing/null/zero 三态、未知字段、保护列、空补丁、宽松模式回传 dropped | 纯单测 |
| jsonb | 非法 UTF-8、超限、NaN/Inf、结构回解 | 纯单测 |
| scope/tx | GUC 语句形态、只读选项、回滚/savepoint、重试分类 | pgxmock |
| crud | SQL 构造形态、$n 绑定、CAS 冲突、行数上限 | pgxmock |
| 探针元数据集成 | `information_schema`/`pg_catalog` 快照、缓存失效、漂移只报告、分区父/子与 FORCE RLS 与单列唯一键判定、ctx 取消后连接存活 | Testcontainers |
| 真实表试点 | tenant_model_policies：manifest + 静态 DDL 对账 + 影子读集成（迁移形状门禁绿 / dump 形状 PK 漂移拦截 / 与 admin 手写语句结果一致 / 跨租户隔离 / 23505 typed） | 已交付（仅 `db/dbxmanifest`，不接线生产流量） |

**候选表核对结论（逐表落字）**：`work_type_config` 无 tenant_id 列；`tenant_settings_kv` 复合身份主键（tenant_id+key，无单列 PK）；`session_title_states` 复合 PK 且含 fencing_token/lease 列属并发状态机高危——三者均不合格。合格首选 `tenant_model_policies`（单列 PK 意图 + tenant_id NOT NULL + FORCE RLS + 软删列 + 非分区 + denylist 配置低风险），次选 `output_compliance_custom_keywords`（无软删列，dbx Delete 不可用）。

## 12. sqlc 试点设计（Phase 4 · 已备未实施）

**裁决（2026-08-27）**：本阶段不引入 sqlc 工具链。原因：(1) sqlc CLI 是外部二进制，需安装脚本 + checksum + Makefile target + CI 校验步骤，其中 Makefile/CI 是共享工作流文件，在多会话并行期改动风险不对称；(2) verify.sh 门禁当前无 codegen 校验步骤，先行落地配置会造成"配置存在但无生成物、无一致性门禁"的半接线状态；(3) go.mod/vendor 零改动是本阶段核心安全属性。设计如下，供工具链决议后直接落地。

**现状证据**：仓库无 sqlc.yaml/sqlc.json、go.mod 无 sqlc 依赖、Makefile/CI（4 个 workflow）无 codegen 步骤；`pgx/v5 v5.9.2` 已直接依赖且已 vendor——sqlc pgx/v5 生成代码只 import pgx/v5/pgtype/pgconn，**go.mod 与 vendor 零改动即可编译**。

**候选查询**（`domains/intentconfig/store.go`，pgx 原生、普通 heap 表、无分区/lease/fencing、结果形状固定、列清单与 `sql/objects/tables/session_intent_evolution.sql` 逐列一致）：
- `GetSessionHistory`（store.go:118-130）：`WHERE session_id = $1 ORDER BY turn_number DESC LIMIT $2`；
- `GetByRequestID`（store.go:174-185）：`WHERE request_id = $1 LIMIT 1`。

**配置草案**（输出目录在模块外，schema 输入选方案 A：指定单表 SSOT 文件，漂移在 regen diff 显式暴露；排除 `intent_classifier_config`——其 objects 快照缺 enabled/version 列，是已证实的漂移反例）：

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema:
      - sql/objects/tables/session_intent_evolution.sql
    queries:
      - db/querygen/queries/intentconfig.sql
    gen:
      go:
        package: "querygen"
        out: "db/querygen"
        sql_package: "pgx/v5"
        emit_interface: true
        emit_empty_slices: true
        # 不开 prepared_queries：与 SimpleProtocol 防"陈旧 prepared statement"动机冲突
```

**SimpleProtocol 兼容性**（已核实）：sqlc pgx/v5 生成 `New(dbt DBTX)`，其 DBTX（Exec/Query/QueryRow）与 `internal/dbx` 的 DBTX 逐方法一致；`*pgxpool.Pool`/`pgx.Tx` 直接满足，协议模式由运行时连接配置决定（db/db.go:41），生成代码不感知、不 Prepare、不形成第二连接池。已知约束：参数用 text/int 原生类型；可空列默认 pgtype.*（试点查询列均 NOT NULL 或可接受 []byte jsonb）。

**版本锁定与审查**：pin sqlc CLI 精确版本（当前稳定 v1.31.1，2026-04-22）+ `scripts/install-sqlc.sh`（release 二进制 + SHA256 校验，装到 GOPATH/bin 不进 vendor）+ Makefile `sqlc-generate`/`sqlc-verify`（regen 到临时目录 + `git diff --exit-code`，防手改生成物）；生成物提交入库、CI 只校验不生成。

**回滚**：`rm -rf db/querygen sqlc.yaml` + revert Makefile/CI 即零残留；go.mod/vendor 全程未动。

**边界**：sqlc 只负责 query typing；迁移、RLS、授权仍在现有链路；试点期不接线生产调用方（或仅影子读对比），`store.go` 保持原样。
