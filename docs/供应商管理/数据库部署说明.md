# 供应商画像系统 - 数据库部署说明

## 部署到 252 服务器

### 方法 1: 使用自动化脚本（推荐）

在项目根目录执行：

```bash
# 使用默认配置（192.168.1.252, postgres, llm_gateway）
./deploy/sql/deploy-provider-profile.sh

# 或使用自定义配置
DB_HOST=192.168.1.252 \
DB_USER=postgres \
DB_NAME=llm_gateway \
./deploy/sql/deploy-provider-profile.sh
```

脚本会自动：
1. ✅ 检查数据库连接
2. ✅ 检查表是否已存在
3. ✅ 执行迁移脚本
4. ✅ 验证表和索引创建
5. ✅ 验证 credentials 表扩展

### 方法 2: 手动执行

```bash
# 连接到数据库
psql -h 192.168.1.252 -U postgres -d llm_gateway

# 执行迁移脚本
\i deploy/sql/migrations/2026-07-26-provider-profile-system.sql

# 验证部署
\dt provider_*
```

### 方法 3: 通过 SSH 远程执行

如果你在本地，需要先上传文件：

```bash
# 上传迁移脚本到服务器
scp deploy/sql/migrations/2026-07-26-provider-profile-system.sql \
    user@192.168.1.252:/tmp/

# SSH 到服务器执行
ssh user@192.168.1.252
psql -h localhost -U postgres -d llm_gateway \
  -f /tmp/2026-07-26-provider-profile-system.sql
```

## 部署后配置

### 1. 在平台配置中启用系统

在网关的配置文件或数据库配置表中添加：

```yaml
provider_profile:
  enabled: true
  collection_interval: 7200      # 2小时（秒）
  aggregation_interval: 86400    # 24小时（秒）
  cleanup_interval: 604800       # 7天（秒）
```

或通过 SQL 直接插入配置：

```sql
-- 假设使用 settings 表
INSERT INTO settings (key, value, updated_at)
VALUES 
  ('provider_profile.enabled', 'true', NOW()),
  ('provider_profile.collection_interval', '7200', NOW()),
  ('provider_profile.aggregation_interval', '86400', NOW()),
  ('provider_profile.cleanup_interval', '604800', NOW())
ON CONFLICT (key) DO UPDATE 
  SET value = EXCLUDED.value, updated_at = NOW();
```

### 2. 重启网关

```bash
# 使用 systemd
sudo systemctl restart llm-gateway

# 或优雅关闭后重启
kill -TERM $(cat /var/run/llm-gateway.pid)
/usr/local/bin/llm-gateway
```

### 3. 验证系统启动

查看日志：

```bash
# 查看最近的日志
tail -f /var/log/llm-gateway/gateway.log | grep "provider profile"

# 或使用 journalctl
journalctl -u llm-gateway -f | grep "provider profile"
```

**期望日志输出**：
```
[INFO] provider profile system initialized collection_interval=2h0m0s ...
[INFO] provider profile collector started interval=2h0m0s
[INFO] provider profile aggregator started interval=24h0m0s
[INFO] provider profile cleaner started interval=168h0m0s
[INFO] CHECKPOINT: provider profile system started
```

如果看到 `provider profile: disabled via settings`，说明配置未启用。

## 监控数据采集

### 等待第一次采集（最多2小时）

系统启动后会立即执行第一次采集，然后每2小时执行一次。

### 查看采集数据

```sql
-- 查看最近的采集记录
SELECT 
    credential_id,
    metric_time,
    time_slot,
    network_latency_p95,
    availability_total_requests,
    availability_success_requests
FROM provider_profile_metrics
ORDER BY metric_time DESC
LIMIT 10;
```

### 查看每日画像（次日凌晨4点后）

```sql
-- 查看最新的每日画像
SELECT 
    credential_id,
    profile_date,
    network_score,
    availability_score,
    stability_score,
    scale_score,
    total_score
FROM provider_profile_daily
ORDER BY profile_date DESC, total_score DESC
LIMIT 10;
```

## 故障排查

### 问题 1: 数据库连接失败

**症状**: `psql: could not connect to server`

**解决方案**:
1. 检查数据库服务是否运行：`systemctl status postgresql`
2. 检查防火墙规则：`sudo firewall-cmd --list-ports`
3. 检查 pg_hba.conf 配置

### 问题 2: 权限不足

**症状**: `ERROR: permission denied for schema public`

**解决方案**:
```sql
-- 授予必要权限
GRANT ALL PRIVILEGES ON DATABASE llm_gateway TO postgres;
GRANT ALL PRIVILEGES ON SCHEMA public TO postgres;
```

### 问题 3: 表已存在

**症状**: `ERROR: relation "provider_profile_metrics" already exists`

**说明**: 这不是错误！脚本使用 `CREATE TABLE IF NOT EXISTS`，可以安全重复执行。

### 问题 4: 系统未启动

**症状**: 日志中没有 "provider profile" 相关信息

**检查清单**:
1. ✅ 数据库表是否创建成功
2. ✅ 配置中 `provider_profile.enabled` 是否为 `true`
3. ✅ 网关是否重启
4. ✅ 查看日志中是否有错误信息
