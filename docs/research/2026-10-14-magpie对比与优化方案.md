## 一、magpie 三大职能方案速写（修订版，引用到函数）

### 1.1 多模型转换

- **IR hub-and-spoke**：统一入口 `parse`(gateway.go:5093) / `build`(5148) / `decoder`(5172) /
  `encoder`(5233) / `render`(5258)；各协议 `parseChat/parseResponses/parseAnthropic/parseGemini`
  + `buildChat/buildResponses/anthropicBody/buildGemini`；`collector`(ir.go:416) 聚合事件流。
- **翻译路径非流式强制上游流式**（`translate` gateway.go:4921）；**同协议直通不强制**。
  反方向 `wholeAsStream`（whole_stream.go）：上游无视 `stream:true` 回整包时拆成客户端协议的流。
- **unfit 学习族**（「失败一次 → 改写重试 → 记住」，键 `providerID\0key\0proto`，**仅内存**）：
  `optionalFields` 11 个可剔字段（store/metadata/service_tier/prompt_cache_key/
  prompt_cache_retention/safety_identifier/stream_options/parallel_tool_calls/verbosity/
  thinking/enable_thinking）、`refusedOptional`(4573，先读结构化 error 再匹配 pydantic
  `extra_forbidden` loc)、`refusedInMessages`(4733，消息内字段)、`formatRefused`（response_format
  → system 指令）、`prefillRefused`、`toolStrictRefused`、`bareReasoningRefused`、
  `geminiLevelRefused`、`imageToolRefused`、`rootUnionRefused`、`refuseShapes`。
- **协议级 unfit**：`wrongEndpoint`(4785) 命中 → `markUnfit` → 按 ResponsesFirst/MessagesFirst 换协议。
- **thinking 映射**：`effortOf`(ir.go:684) / `budgetOf`(731，low 4096 / medium 10000 / high 24000 /
  xhigh·max 32000) / `effortOfBudget`(746)；**有损点**：max 往返塌成 xhigh。
- **DeepSeek 回放规则三 API 各一**：`chatReplaysReasoning`、`replaysReasoning`、
  `anthropicReplaysThinking` + 工具轮补占位推理（`noReasoning=" "`）。
- **散文工具调用**（textcalls.go，#823/#906/#917/#1945）：Hermes JSON、GLM `<arg_key>`、DeepSeek
  DSML（含全角 `｜`）、半 Hermes / Qwen `<parameter=k>`、残标签清理；三条接入：翻译流、中转 Chat 流、非流式。
- **工具消息修补**：见 0.1 表第 4 行，四协议都有。
- **Grok 整数**（grok_integral.go，#1431）：流式状态机只扣 `.0` 尾，任意切分点结果一致（`TestWholeNumsAnyCut`）。

### 1.2 请求转发

- **holdWriter**（fallback.go:1287）：未发内容前失败无感切换；15s 后 SSE 注释保活；仅前置帧的 200
  继续扣 `holdLead=4min`；reasoning 先行扣 `holdThinking=4min`；`agentQuietMost=4min` 避开 Codex 300s 空闲超时。
- **失败分十余类**（routing.go:170-221 `fail*`），**只有 rest 决定谁被排除**：内容/形状/代理/认证错误
  **不罚账号**，模型拒绝只罚 `restID`（账号×模型）。rest 分级（routing.go:90-121）：credit 30m /
  quota 15m 起上限 8d / rate 1m 翻倍上限 30m（30m 内再犯算连续）/ restricted 2h / 未知 1m→10m。
- **probeOne**（fallback.go:761，#1799）：全员 rest 时每请求只问最早到期的一个（半开探测）；
  **quotaHeld**（816，#1772）：剩下的全是额度/余额耗尽者时一个都不问，直接复述原拒绝 + 恢复时间。
- **同候选重试** `passing`(fallback.go:1193)：`lastRetries=2`、`rateRetries=3`，**预计等待 >8s 即转下一候选**。
- **Patience**：默认 60s、上限 240s；`replanRounds=12`，pause 2s 起翻倍上限 30s。
- **loop guard**（loop_guard.go）：256 窗 / ≤24 去重 → 502 + 取消上游，不换候选、不罚账号，`loopReasks=1`。
- **ended-short + 续写**（continuation.go）：只对支持续写的上游续，已开始的 tool call 不续。
- **限流**：FIFO lanes + `errQueueFull/errQueueWait`；RPM 用「预约未来时间戳」实现，锁内不睡眠，
  `rpmSlack=1s`；附带请求（count_tokens）也计费。**429 必带 Retry-After**（`soonestBack` 补齐）。
- **FirstToken**：超时 504 `no first token in %ds`，换成员但**不罚**（failSlow）。
- **affinity**：auto/session/turn/strict/off；`cacheWorth=1024`、`cacheCold=5min`、`stickKeep=24h`；
  流中断后忘掉粘性重新路由（#733）。
- **网关 key 预算预留**（key_limit.go，#585）：在途预留「body/4 + 本窗平均输出」，结束按实际结算；
  超额 429 + `Retry-After` + **`X-Should-Retry: false`**（阻止 SDK 自动重试）。
- **错 key 全局令牌桶**（auththrottle.go）：burst 50、每秒回 1，有效 key 完全绕过，不按 IP 分桶。

### 1.3 会话与观测

- **会话身份只认请求头**（`sessionOf`，7 个候选头，截断 128 字节）；无头不录会话文本。
  对话指纹 `conversationID`（首条 user 消息 sha256）只用于路由亲和/通知分桶等尽力场景，
  **绝不用于会话列表与用量归属**（bede73c3 的修法即此）。
- **usage 契约**：cache_read/cache_write 无 omitempty（0 也写，区分「未命中」与「未记录」，#1839）；
  tier 三记 asked/sent/served（served 只取回复明说值）；终局行 + `handed_on` 子行。
- **决策 trace**（trace.go）：在决策点用决策值当场写，不事后重算；Route/Weighed/Try 三层字段
  （含 `Left` 排除原因、`Served/Swapped` 检测上游偷换模型）；内存 60 条 + 磁盘 30 天/200MiB；长轮询接口。
- **两套脱敏**：可逆 `Mask/Restore`（发往厂商）+ 不可逆 `Scrub`（落盘），后者按字段名抹值但排除 `*tokens`。

### 1.4 工程方法（v1 未涉及，对多会话共享仓库价值最高）

- 子系统设计文档与代码**同 PR 更新**；文档链接到符号不写行号；PR 写语义变更说明（触发/前后行为/兼容影响）。
- `LESSONS.md`：规则 → 原因 → 出事与修复 commit → `Seen N×`；**同一教训第 3 天再现即「毕业」进代码规范**。
- 代码规范要点：修一个修全类（grep 同模式）；读/解析失败一律视为「未知」；修复必带「去掉即红」的测试；
  红测试即当下 bug，「main 上也红」须写明刚 fetch 的 sha；跑全量而非挑包；两会话不在同一 checkout 提交。
- 测试基础设施：可编程假上游（`refuse func(body)` 模拟 400 驱动学习链）、**上游字节黄金文件门**
  `TestUpstreamBodiesUnchanged`（14 例覆盖 3 协议 × 直通/组/跨协议，`UPDATE_UPSTREAM_BODIES=1` 重生成）、
  真实捕获夹具（用户 rollout jsonl、厂商原样回复）、切分点性质测试。

## 二、本仓已知稳定性/性能痛点（需求侧，AGENTS.md 审计史）

1. **严格中转字段 400 连环修**：stream_options 三腿（r1026 pass1/pass2、r1026b 原生腿）、thinking（r1021）、
   reasoncap xhigh（r1026b）、Bedrock `output_config.effort`（r1027）——根因是**静态名单 + 多出站腿各自为政**。
2. **5h 挂起**：154 p99=889s、max 85min（survival deadline 18000s；P0-2 在途修）。
3. **全灭后放大**：wait_recovery 30s 轮询 + 同步探测救援，等待期反复打上游；r1026 tentative 回环同族。
4. **客户端错误级联节点冷却**：r1027 json-word 契约 400 按 transient 冷却 → 数分钟 no_candidate。
5. **流被静默吞**：r1028 策略拦截呈现为 keepalive-only + success=true（已修，但「永不静默」尚无通用契约）。
6. **错误外显误导**：上游 400 包装成 model_not_found/transient（登记未修）。
7. **中途断流**：eof_without_done 终态化，客户端拿到截断流。
8. **冷启动空窗**：部署后候选预热 3min；稀疏模型键过期冷请求 15.8s（r1026 已修 TTL 砍缩）。

## 四、优化方向确认（v2）

### 4.1 六条方向性原则

1. **扩展既有，不另起平行机制**。reqprobe、breaker/writer、attempt_commit_gate、tool_call_xml 都已在线，
   magpie 的方法论按「补覆盖面」落进去，而不是新建同职能包（0.3 的 paramrefusal / reset_time_parser 即反例）。
2. **先归责，再处罚**（magpie 原则「只有 rest 决定谁被排除」）：请求内容/形状/客户端契约错误不罚节点；
   模型级拒绝只罚 (credential, model)；只有账号级证据才罚凭据。这是 r1027 级联冷却的通用解。
3. **等待有界、永不静默、终态可读**：交互等待 ≤240s；全灭时只半开探测最早到期者；
   客户端拿到的终态必须带原因 + 最早恢复时间 + Retry-After，SSE 期间注释保活。
4. **改写重试在同候选，学习结果多实例共享**：保留本仓 Redis 学习的优势（magpie 仅内存）；
   学习键统一为 (provider, model, wire_protocol)；所有出站腿共用一个 choke point 应用学习结果。
5. **字节保真优先**：改写只动目标字段，评估 IR 重序列化对 prompt cache 前缀的破坏——这是性能与成本问题，不只是正确性。
6. **判据纪律对齐 magpie 的测试基础设施**：真实字节夹具、可编程拒绝假上游、上游字节黄金门、去掉即红。
