# magpie 对比研究：多模型转换 / 请求转发 / 会话管理 —— 逐项对比与优化方案

> 日期：2026-10-14。研究动机：解决某些模型/供应商下的**稳定性与性能**问题。
> 学习对象：`~/workspace/ai/magpie`（yetone/magpie，Go 本地多协议 LLM 网关，
> MIT，v0.1.1228 时代源码快照）。它面向个人单机场景，但四协议互译 +
> 多账号失败转移的工程密度极高（gateway 包 563 个测试文件 / 1851 个测试），
> 与本仓同域可直接对标。
> 证据方法：magpie 侧读 `docs/subsystems/` 四篇设计文档（gateway-routing 142KB、
> gateway-sessions、gateway-middleware、providers-accounts）+ 三路源码调研；
> 本仓侧以 AGENTS.md 审计史 + 源码抽验（survival_coordinator / executor_dispatch /
> breaker / tool_call_xml 等均实读）。本文引用均给到文件级证据。

## 一、magpie 三大职能方案速写

### 1.1 多模型转换（协议互译）

- **统一 IR，hub-and-spoke**：`internal/gateway/ir.go` 的 `Request`/`Event`/
  `Part`/`Result` + `collector`（事件流重组整体回复）。每种线格式实现
  五件套：`parseX`（入→IR）、`buildX`（IR→出）、`xDecoder`（上游 SSE 帧→Event）、
  `xEncoder`（Event→客户端 SSE）、`renderX`（非流式整体）。复杂度 O(4N) 而非 N²。
- **非流式统一走流**：客户端不要流时，对上游仍强制 `stream:true`
  （gateway.go:4921），收完用 `collector` 聚合成 JSON——所有失败转移/
  完整性检测/保活机制只有一条路径。
- **Sealed reasoning 原字节透传**（ir.go:59-81）：Anthropic
  `redacted_thinking`、Responses reasoning item（id/summary/encrypted_content）、
  Gemini thoughtSignature（藏进 tool call id 回传）按原始字节透传、只回原协议。
  跨账号 failover 时模型自带的密封推理不丢。
- **动态字段裁剪记忆**：`optionalFields`（gateway.go:4567）+ `refusedOptional`
  （解析上游 400 指名的参数，:4573-4599）+ `withoutRefused`（:4700 记忆并剔除，
  重启前不再发）。同类还有一整族 unfit 标记：`formatRefused`（response_format
  被拒→改系统提示词重问）、`thinking_config`、`levelRefused`、`prefillRefused`、
  `toolStrictRefusal`、`shapeRefused`（422 unknown item type）、
  `bareReasoningRefused`——**全部是「失败一次 → 改写重试 → 记住不再犯」模式**。
- **协议级 unfit + 自动换协议**：`fits/markUnfit/unfit`（gateway.go:4167-4186），
  「模型不在此端点」→ 换下一个协议重建重发（`forwardTranslated` :4203）。
- **thinking 双向映射**：effort ↔ budget_tokens ↔ thinkingLevel 三协议互转
  （ir.go:684/731/746）；DeepSeek 三 API 的 thinking 回放规则各自实现
  （chat.go / responses.go / anthropic.go 各有 `xxxReplaysReasoning`）。
- **散文工具调用解析**（textcalls.go，#823）：模型把工具调用写进正文时
  （Hermes `<tool_call>`、DeepSeek DSML、半 Hermes `<parameter>`、GLM
  `<arg_key>/<arg_value>`），流式与非流式都转成真正的 tool_calls。
- **工具消息修补**：发往 Anthropic 上游的 `pairToolBlocks`（未应答的
  tool_use 补合成 tool_result）、Responses 的 `joinToolRuns`/`pairToolItems`
  ——客户端中断重放的残缺历史不再被上游 400。
- **厂商数字修正**：Grok 把整数写成 `2500.0` 致 Codex serde 拒收 →
  流上改写为 `2500`（grok_integral.go）。
- **测试策略**：无 4×4 golden 全矩阵；按 issue 编号写场景回归（#613/#1445/…），
  282 个 httptest 假上游端到端，真实失败 body 存 `testdata/upstream_bodies/`。

### 1.2 请求转发（路由与失败转移）

- **候选粒度 = 账号/key**：`plan/planGroup`（fallback.go）展开为有序候选链，
  含 fallback 模型、组嵌套；`restLast` 把 resting 者排尾。
- **holdWriter ——「明确通过前扣住回复」**：候选失败且**尚未向 agent 发出
  任何回复内容**即换下一个；15s 后开始发 SSE 注释保活（keepAlive）；
  仅含前置帧的 200（`eventLead`）继续扣最长 4min——晚期才到的
  `server_is_overloaded` 仍能无感切换；reasoning 先行后 refusal 的也扣
  （`holdThinking` 4min）。agent 断开检测（499）终止重试。
- **rest 分级冷却**：欠费 30min / 配额到 resetsAt / 限速到 Retry-After
  （1min 指数至 30min）/ 未知 1min 至 10min；**模型级 rest**（restID：错误
  指名某模型时只 rest 该模型，账号其它模型继续服务）；**账号被封**
  （restricted）2h；**登录被吊销**（signin_revoked）标记后不再外发。
  resetsAt 从 429/402 正文解析（中英文「将在 2026-10-11 20:16:02 UTC+8重置」、
  \uXXXX 转义解码，routing.go:480-577）。
- **probeOne 纪律**（#1799）：全部候选都在 rest 时，**每个请求只探测
  「最早到期」的那一个**——一条成员挂了不会被每个请求轮流打一遍；
  且 keys 超限直接复述上次错误不再打（quotaHeld）。
- **组 Patience 等待预算**：全员 busy（408/5xx/短 429）时轮流重问，
  指数 pause（上限 = Patience，默认 60s、最大 240s；pause 累计到预算即放弃），
  等待期间 SSE 注释保活，重试轮数只是后备。
- **loop guard**（#1359）：滑动 256 单位窗口内去重单位 ≤24 → 判定循环，
  切断 + 502 + 按模型计数（`reply_loop`）；reasoning-only 循环原地重问一次。
- **ended-short 检测 + 原地续问**：上游流在说完整前断掉（无 stop_reason/
  response.completed/finishReason）→「回复未完成」502 → **同候选 prefill
  续问**（continuation.go）而非换人。
- **wholeAsStream**：vendor 忽略 `stream:true` 返回整体 JSON → 拆成流发给
  客户端而不是报错。
- **错误词典 + 四动作**：quotaWords/unservedWords/shapeWords/retiredWords/
  protectionWords/creditWords…… 分类后驱动四种动作：换账号 / rest 谁+多久 /
  换模型（`modelRefused`/`modelRetired`，410 记忆到 retired.json，成功自动复活，
  1 周过期）/ **改写请求重试**（剥 encrypted_content、抬 max_tokens、去 effort）。
- **限流面**：每 key/账号 MaxConcurrency lanes + QueueLimit/QueueWait（满则 429）+
  **MaxRPM 滚动 60s 窗**（含拨号延迟余量）+ `laneMate`（排队时先问同组有空位者）；
  组 FirstToken 首 token 超时 → `failSlow` 换成员不 rest。
- **affinity 粘性**（affinity.go）：会话粘在答过的 key/账号（吃 prompt cache），
  模式 auto/session/turn/strict/off；**cacheWorth（cache_read ≥1024 token 才值得粘）
  + cacheCold（5min 无流量释放）**；affinity.json 落盘重启不丢；
  新会话 leastHeld 分散。
- **allowance 窗口路由**：smart 模式按「最快续期的窗口」排候选（先花掉快
  作废的配额），窗口续期自动解除 rest（OnRenewed）。

### 1.3 会话管理

- **会话身份 = AgentOf(record.Agent) + 客户端会话头**，从不猜测；
  无会话头的请求不记文本。
- **会话视图 = usage 账本投影**（不持久化）+ 原生 agent 会话文件合并
  （native wins）；模型/token/时间/价格全部来自 usage 记录。
- **可选本地对话记录**：默认关、需明示同意；`turns.jsonl` append-only，
  每 `gateway-conversations/<UTC日>/<身份hash>/`，7 天 / 每日 256MiB /
  每轮 1MiB 上限，8MiB spool，0700/0600 权限，已知秘密洗刷。
- **usage 记录契约**：每请求**一条**（含 tries 计数），cache_read/cache_write
  每路必填（0 也写），tier 三记法（asked/sent/served）。
- 全文搜索：字节预过滤 + 行级词过滤（58 个 3GB 会话 3-7s）。

### 本仓已知稳定性/性能痛点（AGENTS.md 审计史，对比的「需求侧」）

1. **严格中转字段泄漏三连修**：vapeur 类 unknown-relay 对未知字段 400——
   stream_options（r1026 pass1）→ pass2 回写（r1026）→ 原生透传腿（r1026b D1）；
   thinking 对象（r1021）；reasoncap 缺 xhigh（r1026b D2）。每案都是一次性代码修。
2. **5h 挂起**：154 事故 p90=16.8s、p99=889s、max 85min——候选全灭后
   wait_recovery_window 30s 轮询、deadline 5h（survival_coordinator.go:72 默认值）。
3. **URSM 节点键 TTL 被流量砍缩**（r1026 修复）：稀疏流量模型空闲 >15min 键过期
   → 冷请求 15.8s（热 7-9s）；probe tentative restore 回环（同轮修复）。
4. **候选预热空窗**：部署重启后实测 3min。
5. **fp_slot × 钉扎缝隙**（r1025）：钉扎候选先被预过滤剔除 → 0 候选 503。
6. **错误外显误导**：上游 400 包装成 model_not_found/transient（登记未修）；
   EOL 识别措辞 contains 脆弱。
7. **死凭据 advertise**（r1027 修列表侧）+ probe_direct_auth_failed 风暴
   （30min 204 条）；漂移清退回潮 ~95 条。
8. **中途断流终局化**：eof_without_done 直接终态，客户端拿到截断流
   （无原地续问）。
9. **persist collect 全库 SCAN 30s 超时** → redis_unavailable 假恢复（登记）。

## 四、下一步优化方案（按优先级）

> 总原则：**不改产品定位**（多租户/DB/合规保留），只吸收 magpie 的
> 「失败→改写→记忆」与「等待有界化」两个方法论。

### P0-1 动态可选字段剔除记忆（ kills vapeur 类 400 整族）

- **做法**：在出站 choke point（r1026b D1 已建 StripStreamOptions 调用点）
  与 paramreg 恢复层之间加「400 指名参数解析 → 剔除该字段重试一次（同候选）
  → 按 (provider_id, model, wire_protocol) 记忆（TTL 24h 或到重启）」。
  词表参考 magpie refusedOptional：`Unknown parameter`、
  `Extra inputs are not permitted`、pydantic `extra_forbidden`、
  `Unsupported … field`。**白名单约束**：只剔除 paramreg 已登记为 optional 的
  字段 + Extensions 未登记键；model/messages/tools 等核心字段永不剔。
- **落点**：internal/ir（解析+剔除）、internal/paramreg（记忆表）、
  executors（重试一次钩子）。
- **判据**：raw-logs 回放 vapeur 三案（stream_options×3 腿 + thinking）+
  变异验证（去掉记忆→红、去掉白名单→红）；前提在场配对。
- **预期**：把「每个新字段一次线上事故 + 一次代码修」变成「一次自动重试 +
  一行日志」。直接对应 A3/B11。

### P0-2 等待预算分级下调（kills 5h 挂起）

- **做法**：survival_coordinator 默认 Deadline 5h → **交互预算 240s**
  （settings_kv `survival.interactive_deadline_seconds` 可调，热加载）；
  deadline 到期输出**可读错误**（候选全灭 + 各自原因 + 最早恢复时间），
  而非静默挂死。SSE 注释保活已在该协调器内。
- **判据**：候选全红场景下 p99 < 5min；错误体含 probeOne 式「最早恢复时间」；
  变异：改回 5h 默认→契约测试红。
- **预期**：154 事故形态（p99=889s、85min 挂起）结构性消除。对应 B5。

### P0-3 断流原地续问（post-first-content recovery，Phase 2）

- **做法**：eof_without_done 且已发内容时，同候选以已发文本为 prefill 续问
  一次（每请求预算 1 次），客户端流无缝续接；续问也失败才终态化。
  Anthropic 腿天然支持 prefill；Responses/chat 腿用 continue 语义。
  上限：续问注入的 prefill token 计费需入 telemetry（防隐性成本）。
- **判据**：真实切断注入（httptest 半关流）+ 客户端拼接后内容完整；
  ADR-Disp-003 契约（不产生第二个 terminal）回归。
- **对应**：A8，vapeur 502/截断类体感问题。

### P0-4 rest 分级 + resetsAt 正文解析 + 模型级隔离

- **做法**：errorsx 增加 429/402 正文重置时间解析（中英文「将在 …重置 /
  resets in 0h 19min」、\uXXXX 解码）；breaker 对 quota 类冷却对齐 resetsAt
  而非固定窗；**错误指名模型时只隔离该 (credential,model) 绑定**
  （node_probe_state 已有 model_probe_broken 词汇可挂）而非整凭据；
  QUARANTINED 保留给 auth 类。402 credit/quota 二分（money 词 vs quota 词）。
- **判据**：WorkBuddy/GLM/Factory 文案样本回放；同凭据其它模型不被连坐
  （前提在场配对）。
- **对应**：B3，死凭据连坐与清退回潮。

### P1-5 per-credential RPM 滚动窗（防 429/探测风暴）

  超限请求在候选环内让位给下一候选而非打出；全超限时 429 + Retry-After。
  探针（node_probe）也计入。对应 B7 + probe_direct_auth_failed 风暴。
