## P1 — internal/paramreg

**产出**：`internal/paramreg/{dialect.go, spec.go, registry.go, decide.go, translate.go}` + 测试

参数全集来源见 01 文档第 4 节一手来源索引。登记范围：

- OpenAI Chat Completions 全集（含 `prompt_cache_options`、`moderation`、`prompt_cache_retention` 等新参数）
- OpenAI Responses 全集（含 `context_management`、`max_tool_calls`、`prompt`、`include`）
- Anthropic Messages 全集（含 GA 的 `output_config`、`inference_geo`、`cache_control` 顶层形态；
  beta 的 `context_management`、`mcp_servers`、`speed`、`fallbacks`、`fallback_credit_token`、`diagnostics`）
- Gemini generateContent 全集（含 `serviceTier`、`store`、`labels`、`generationConfig` 全部子字段）
- 各厂商私有：DeepSeek / Qwen / GLM / MiniMax / Kimi / Ark / Grok / Mistral / OpenRouter / vLLM / Ollama

**注意**：01 文档「需要标注的不确定项」列出的过时字段（MiniMax `bot_setting` 等、
OpenRouter `transforms`、vLLM `guided_*`）**仍需登记**为 `KindDialectOnly`，
因为老客户端可能还在发；但备注标注"已从现行 spec 移除"。

**验收**：`paramreg.Decide` 单测覆盖决策矩阵 7 种情形；未知字段必须返回 `ActionRestore`。

1. `internal/ir/serialize_openai.go:179` — 删 `SourceProtocol` 门禁，逐 key 走 `paramreg.Decide`

**名称模式表覆盖**（当前 autocombo 只匹配 `reason`/`o1`/`o3`/`deep`，漏掉全部主流思考模型）：

| 模式 | dialect | 备注 |

| `gemini-2.5-*` | gemini_budget | 每模型最小预算不同（flash=1/pro=128/flash-lite=512） |
| `gemini-3*` | gemini_level | `thinkingLevel` 而非数字预算 |
| `deepseek-reasoner`/`deepseek-r1`/`*-r1` | deepseek | effort `low\|high\|max` |
| `glm-4.5+`/`glm-5*`/`glm-z1` | glm | effort 7 档，`low`/`medium` 会被折叠 |
| `qwq*`/`qwen3*`/`qwen-*-thinking` | qwen_bool | `enable_thinking` + `thinking_budget` |
| `kimi-k2*` | kimi_thinking | `thinking.keep` |

**验收**：单测覆盖上表每一行；`Source` 字段正确反映命中层级。

## P5 — ReasoningIntent 归一化

**产出**：`internal/ir/reasoning.go` + 各 parse/serialize 接线

**parse 侧**归一化 6 种入向形态 → `ReasoningIntent`：
`reasoning_effort` / `reasoning{}` / `thinking{}` / `enable_thinking`+`thinking_budget` /
`thinkingConfig{}` / `chat_template_kwargs.enable_thinking` / `thinking_token_budget`

**serialize 侧**按 `reasoncap.Caps.Dialect` 渲染，effort↔budget 双向映射用 LiteLLM 表：

```
effort → budget:  none=省略  minimal/low=1024  medium=2048  high=4096  xhigh=8192  max=16384
budget → effort:  取最近档位（填补 Anthropic→OpenAI 方向的缺口）
```

覆盖规则（LiteLLM 生产验证）：adaptive 模型忽略 effort 直接 `{"type":"adaptive"}`；
1024 硬下限；budget cap 到 `max_tokens - 1`。

**同时修复**：`MaxReasoningTokens`（`types.go:437` 声明但无任何读写方）接线或删除。

**验收**：6×6 dialect 互转矩阵测试；重点验证当前静默消失的两条
（budget-only → OpenAI、effort-only → Gemini）。
