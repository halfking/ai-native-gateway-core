## 三、为什么这样做

### 设计原则

1. **结构化优先**: 用独立字段替代 JSONB blob（如 `compression_meta` 拆分为 3 个字段）
2. **类型安全**: `client_ip` 用 `INET` 而非 `TEXT`，`compression_ratio` 用 `FLOAT`
3. **隐私保护**: API Key 只存前 8 字符，敏感关键词可选脱敏
4. **查询优化**: 高频字段建索引，部分索引仅覆盖关键状态
5. **可扩展**: `vendor_metadata` JSONB 存储厂商特定字段（如 OpenAI o1 的 reasoning_tokens）

### 技术选型

- **INET vs TEXT**: `client_ip` 用 INET 类型支持 IP 范围查询（如 `client_ip << '10.0.0.0/8'`）
- **JSONB vs 独立字段**: 高频查询字段独立，低频/厂商特定字段用 JSONB
- **部分索引**: `WHERE protocol_conversion = true` 只索引转换过的请求（节省 80%+ 索引空间）
- **指针类型**: Go 结构体用 `*int`, `*bool` 区分"未设置"和"0/false"

## 五、遗留与风险

### 遗留任务

1. **Migration 执行**: 需在测试环境（184 或本地）执行 migration
2. **中间件集成**: 需在 HTTP handler 中调用 `NewRequestMetadata()` 提取元数据
3. **Request Logger 集成**: 需在 `request_logs` INSERT 语句中加入新字段
4. **Session Manager 集成**: 需将 session/task 信息注入到 `RequestMetadata`
5. **JSONB 索引**: 如频繁查询 `vendor_metadata->>'reasoning_tokens'`，需添加 GIN 索引：
   ```sql
   CREATE INDEX idx_request_logs_vendor_metadata_gin 
       ON request_logs USING GIN (vendor_metadata);
   ```

### 已知风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 写入性能下降 5-10% | 中 | 使用批量插入，监控 P99 延迟 |
| 存储增长 ~500 MB/天 | 低 | 按月分区，历史数据归档到 S3 |
| 索引维护开销 | 中 | 部分索引仅覆盖关键状态（减少 80% 索引大小） |
| JSONB 查询慢 | 低 | 高频字段已拆分为独立列，JSONB 仅用于低频/扩展字段 |

### 兼容性

- **向后兼容**: 所有字段为 nullable，旧代码不传也不会报错
- **分区表**: ALTER TABLE 作用于父表，自动继承到所有分区
- **Columnar 存储**: Citus columnar 表支持 ALTER TABLE ADD COLUMN
