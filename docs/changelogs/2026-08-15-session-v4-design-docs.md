本次整合为「会话优化v4」权威设计方案 + 对齐代码基线的实施计划。

## 核心裁决（以代码为真相）

1. **schema 归属**：所有业务表在 `public.*`（分区表除外）。`gateway.*` schema 已于
   migration 513（08-14）整库 DROP（原文：「gateway 这个库不应该存在」）。历史文档
   v1/v2 的 ADR-V2-001（gateway.* 为正式 schema）为错误记录，以代码/migration 513 为准。
2. **会话管理架构**：采用 `ursm/v2` 三模式基座（ModeOff / shadow / canary），
   `main.go:609-630`（T20）已接线。路由优化v3 的 URSM 蓝本（五维评分/P2C）多为纸面。
3. **会话缓存定义**：指会话「三层数据」而非 Redis/内存缓存层——
   ①原始多轮会话 → ②压缩后多轮会话（可跨轮次）→ ③安全脱敏后发送会话。
4. **会话存储维度**：项目 + 任务 + 会话 + 轮次 + 附属会话 + 附属信息。
   会话轮次采用 hot + 分区表模式（对齐 `request_logs_hot`）；旧 `request_logs` 存储模式
   保留双写，逐步移除。
