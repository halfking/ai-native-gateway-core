# 2026-08-13 Session Summaries Outcome + Request Logs Hot status_code 漂移修复

## 做了什么

修复 2026-08-12 审计时发现的另外 2 个 schema 漂移（独立于 481/482）：

**(A) `session_summaries.outcome` 列缺失**

每 60 分钟报 SQLSTATE 42703：
```
column "outcome" of relation "session_summaries" does not exist
```

根因：`bg/session_health_worker.go` 在 UPDATE `session_summaries` 时引用 `outcome` 列（`cmd/gateway/main.go:4753` 注释提到 "写入 health_score/grade/outcome"），但 `sql/objects/tables/session_summaries.sql` canonical 定义只包含 `health_score` + `health_grade`，缺 `outcome`。

**(B) `request_logs_hot.status_code` 列缺失（code-vs-schema drift）**

每 5 分钟报 SQLSTATE 42703：
```
column rl.status_code does not exist
```

根因：`bg/credential_selfcheck.go:373` 引用 `COALESCE(rl.status_code, 0) >= 400`，其中 `rl` 是 `request_logs_hot` 的别名。代码 commit `4b5740b9c` (2026-07-26) 引入时假设列名是 `status_code`，但 `request_logs_hot` canonical 列是 **`upstream_status_code`** —— 一个 code-vs-schema drift 的历史 bug。

## 改动清单

| 文件 | 说明 |
|---|---|
| `sql/migrations/startup/483_session_summaries_add_outcome.sql` + `.down.sql` | 加 `outcome TEXT` 列，幂等 |
| `sql/migrations/startup/484_request_logs_hot_add_status_code.sql` + `.down.sql` | 加 `status_code INTEGER` 列，幂等 |

两处都带 `-- POST_CONDITION:` 注释（rule 11 §6 审计闭环），确保未来同类 silent-fail 立即 deploy abort。

## 为什么这样做

- **483 必加列**：`outcome` 在 cmd/gateway/main.go 注释中被引用，但 schema 漏了。这是 schema drift，需要补列。
- **484 加列（不动 code）**：code 用 `status_code`，schema 用 `upstream_status_code`。两种修复路径：
  - (a) 加 `status_code` 列（最小改动，消除 cron 报错）
  - (b) 改 code 用 `upstream_status_code`（正确路径，但需要 review 影响范围）
  - 本次选 (a) — 不扩散 PR 范围。下次 task 可以做 code-vs-schema 一致性清理（用 `status_code` 作为 canonical，删除 `upstream_status_code`，或反之）。
