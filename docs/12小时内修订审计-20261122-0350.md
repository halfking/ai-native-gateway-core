## 七、本轮沉淀通用式（4 条）

1. ★ **「端点 200」与「功能可用」之间隔着一个真库**。本轮 3 个 P0 全部满足：编译绿 + 单测绿 + 门禁绿 + 运行期必然失败。⇒ 凡新写 SQL，判据必须包含**真库执行**；仓内已有本地 PG 的场景下，「把 SQL 拷进真库跑一遍」的成本远低于「上线后看 500」。
   ⇒ 通用式：**判据要落在「运行期会发生什么」，不是「编译期通过了什么」**。
2. ★ **契约要按「层间」对拍，不是按「层内」对拍**。本轮两处断裂都在层间：Go↔TS 的**容器键**（项级 10 字段全一致，唯一不一致的是容器键）、Go↔PG 的**表名/列名**。层内单测各自全绿。
   ⇒ 通用式：**每个跨层契约都要有一份「两侧逐字对拍」的断言**；字段名不是契约的最小单位，**容器键也是**。
3. ★ **被测对象与量具必须同源**。探针读 `api_keys`、页面读 `keys`；探针表头按另一套 i18n 写；「tab 找不到」用 `gauge`（不计失败）。
   ⇒ 通用式：**量具的失败判定必须比「失败集合」而不是比「计数」**；量具与被测物不同源时，「全绿」与「全坏」不可区分。
4. ★ **typed-nil 接口是 Go 里「依赖缺项守卫」的隐形杀手**。把 nil 具体指针装进接口字段 ⇒ `x != nil` 恒真 ⇒ 「缺项就不装配」的守卫全部失效；而 nil 接收者取字段会 **panic**。
   ⇒ 通用式：**装配期显式判空再装接口**；「依赖存在才注册能力」的写法，判空必须发生在**装箱之前**。
