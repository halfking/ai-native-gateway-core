## 🔄 典型业务流程

### 审批流程（端到端）

```
1. 用户发送请求
   └→ Pipeline接收

2. 安全检测
   └→ SessionAudit.Detector实时检测
      └→ 评分: 8/10 (高风险)

3. 状态转换
   └→ SessionStateMachine: Active → Suspended

4. 创建审批记录
   └→ ApprovalManager.Create()
      └→ 保存到approval_queue表

5. 路由审批人
   └→ ApprovalRoutingTable.Route(tenant, "high")
      └→ 返回审批人列表

6. 发送飞书通知
   └→ ApprovalNotifier.NotifyApproval()
      └→ LarkBotChannel.SendCard()
         └→ 发送交互式卡片

7. 用户在飞书中操作
   └→ 点击"批准"按钮

8. 回调处理
   └→ CallbackServer接收回调
      └→ ApprovalNotifier.HandleApprovalCallback()
         └→ ApprovalManager.Approve()
            └→ 更新审批状态

9. 状态恢复
   └→ SessionStateMachine: Suspended → Active

10. 继续处理请求
    └→ FlowController继续执行流程
```

## 🎨 设计原则遵循

### SOLID原则 ✅

1. **单一职责 (SRP)**: 每个组件职责明确
   - SessionStateMachine仅管理状态
   - FlowController仅控制流程
   - LarkBotChannel仅处理飞书通知

2. **开闭原则 (OCP)**: 对扩展开放，对修改封闭
   - NotificationChannel接口易于扩展新渠道
   - StepExecutor易于添加新步骤类型

3. **里氏替换 (LSP)**: 子类可替换父类
   - 所有NotificationChannel实现可互换

4. **接口隔离 (ISP)**: 接口最小化
   - 接口职责清晰，不冗余

5. **依赖倒置 (DIP)**: 依赖抽象
   - 核心组件依赖接口而非具体实现

### 设计模式应用 ✅

| 模式 | 应用位置 | 说明 |
|-----|---------|------|
| **状态模式** | SessionStateMachine | 状态管理 |
| **策略模式** | StepExecutor, LoadBalancer | 可插拔策略 |
| **责任链模式** | Hook Pipeline | 请求处理链 |
| **观察者模式** | EventBus | 事件发布订阅 |
| **工厂模式** | NotificationChannel | 渠道创建 |
| **命令模式** | FlowStep, RemoteCommand | 命令封装 |
| **适配器模式** | LarkBotChannel | 适配飞书API |

