### 2.2 5b558deab + f92829f23 + 7b828a8a7：session_turn_logs 可配 TTL（17:09–17:10）—— ✅ 成立

- **修正原因核验**：430 的 `cleanup_expired_session_turn_logs()` 全仓零调用方（Go/pg_cron/shell 三面查无），`session_turn_logs` 生产从未被清理、无界增长——「第一次真正接上清理」的定性属实（非参数化既有清理）。
- **方案核验**（数据来源与去处 + 流程闭环）：保留期单一真相源 = 写入时烘焙的 `expires_at`（turn_logs_writer.go `sessionTurnLogsTTL()` 读 `lifecycle.session_turn_logs_ttl_hours`，钳 [1,168]）；清理走 bg.PartitionManager.runCleanup step11 → 迁移 753 函数 `cleanup_session_turn_logs_by_ttl`，谓词 `expires_at < NOW()` 命中 430:275 索引；`p_ttl_hours` 退化为 fail-closed 联锁（区间外 RAISE），Go 侧另有 `clampSessionTurnLogsTTLHours` 预钳——双层防御下坏配置不会静默清空或永不清扫。bg 侧 nil-pool no-op + 5min 超时 + 错误只记日志不炸 worker。
- **HotReload 语义**：设置每 tick 重读，改动只影响新写入行（已写行按原到期时间清扫）——注释与代码一致。
- **结果**：与本轮原生实跑一致（migration_753_test.go 契约钉桩绿）。

### 2.3 14d34867f + d10d782d9：TTL 语义批判修正（17:29）—— ✅ 成立

### 2.4 8a34eab76：turn-logs FIFO poll + merge-on-flush + 精确删除（19:56）—— ✅ 三修成立；「每批 turn_N 互不相同」假设存在窄竞态缺口 → 本轮 D-1 收口

- **F-7（无 ORDER BY 轮询）**：无序 `LIMIT 100` 下安静会话可被持续挤出候选集，且截断=静默丢数（TTL 扫描先于聚合删除）——缺陷真实；`ORDER BY MIN(started_at), tenant, session` 全序 FIFO + 行删除即出队，论证成立。吞吐注记（100/5min = 28800 会话头room）算术复核无误。
- **F-9（整列覆盖）**：`SET turn_logs_summary = $1` 全量替换 + flush 后 DELETE = 活跃会话只剩最后一批 turn——缺陷真实；`COALESCE(...,'{}') || $1` 顶层键浅合并 + 两语句间崩溃重放幂等（同键等值覆盖）成立。
- **F-10（SELECT→DELETE 竞态）**：谓词重推导会删掉 SELECT 之后新写入的未聚合行——缺陷真实；捕获 `id` 后 `WHERE id = ANY($1)` 精确覆盖读集，空分支死代码删除正确。
- **本轮独立发现（D-1）**：合并语义是**顶层键替换**。写入侧（session_writer_v2 step5）此前以**逐行循环**写同一 turn 的 stage 行；5 分钟 tick 若落在循环中间（窗口=循环宽度，毫秒级，概率≈循环时长/300s 每turn），flush 聚合到部分 stages 并删除，下批以**同一 turn_N 键**只携带剩余 stages 顶层替换——前几条 stage 从摘要静默消失。「键每批互不相同」的论证只覆盖了「turn 不跨 tick 完成写入」的情形，未覆盖写入循环本身被 tick 切开。修复见 §三。
