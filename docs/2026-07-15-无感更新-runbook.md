# 无感更新 Runbook — database not configured 加固

**日期**: 2026-07-15  
**关联**: [154 schema 事故经验](./2026-07-14-deploy-154-schema-mismatch-lessons.md) · [无缝部署指南](./分发与激活/seamless-deployment-guide.md)

---

## 1. 问题摘要

首页报错 **`database not configured`** 时，HTTP 层往往仍 **200**：

| 端点 | 依赖 DB | 典型状态 |
|------|---------|----------|
| `/healthz` | 否 | 200 |
| `/api/system/version` | 否 | 200 |
| `/api/admin/dashboard/board` | 是 | **503** |
| `/api/system/background-tasks` | 是 | **503**（未登录）或 401（DB 正常） |

**根因链**（2026-07-15 154 实例）：

```
启动 → postgres connected → EnsureSchema 进行中
     → 60s 共享 migCtx 超时 (context deadline exceeded)
     → postgres disabled → dbConn=nil
     → admin 看板 503 "database not configured"
```

与 07-14 schema 列缺失不同：本次 **DSN 存在、PG 可达**，是 **启动阶段迁移超时** 或 **252 PG 磁盘/锁** 导致。

---

## 2. 已加固项（本仓库）

### 2.1 代码

- `db/db.go`：`EnsureSchema` 共享超时 **60s → 3min**（252 压力/autovacuum 锁等待）

### 2.2 脚本 `scripts/deploy-lib/post-deploy-verify.sh`

| 函数 | 作用 |
|------|------|
| `deploy_preflight_pg_from_remote_env` | 部署前远端 `psql SELECT 1` |
| `deploy_verify_gateway_ready` | restart 后最长 120s 轮询：`background-tasks ≠ 503` 且无 `postgres disabled` |

**已接入**：`deploy-154.sh`、`deploy-245.sh`、`deploy-seamless.sh`

### 2.3 关键改进

- 使用 **`127.0.0.1`** 替代 `localhost`（避免 IPv6 `::1` 误报）
- restart 后 **等待 EnsureSchema 完成**，不再 sleep 3–8s 即判成功
- seamless：**healthz 通过但 DB 503 → 自动 rollback**（与 healthz 失败同等对待）


```bash
SERVICE=llm-gateway-go.service

# A. 日志：不得出现 postgres disabled
journalctl -u $SERVICE --since '5 min ago' | grep -E 'postgres disabled|schema ensured'

# C. 252 PG 磁盘（历史 ENOSPC 会直接拖垮迁移）

```

## 5. 故障处置

### 5.1 部署脚本已拦截（理想）

脚本 exit 1，seamless 已自动 rollback。确认：

```bash
bash scripts/deploy-seamless.sh status 154
journalctl -u llm-gateway-go.service --since '10 min ago' | tail -50
```

### 5.2 生产已坏、需手动回滚

**seamless 布局**：

```bash
bash scripts/deploy-seamless.sh rollback 154
```

**老 flat 二进制布局**：

```bash
ln -sfn /opt/llm-gateway-go/llm-gateway-go.v<上一版本>.linux.amd64 \
        /opt/llm-gateway-go/llm-gateway-go
systemctl restart llm-gateway-go.service
```

回滚后同样检查 `background-tasks` 非 503。

### 5.3 EnsureSchema 超时（非 schema 漂移）

1. 查 252：`df -h`、慢查询、`pg_stat_activity` 锁
2. 临时：回滚上一 verified 版本恢复业务
3. 修复 PG 后重部署（3min 超时 + 脚本 120s 等待）

### 5.5 分区表统计未更新（autovacuum analyze 未触发）

**现象**：`credential_model_index_2026_07` 等 columnar 分区行数很大但 `last_autoanalyze` 为空。

**原因**：PG17 集群 `autovacuum=on`，但 columnar 分区 bulk promote 后 `n_mod_since_analyze` 常为 0，analyze 不自动跑。

**处置**：

```bash
# 154 / 245 经 SSH 对 252 llm_gateway 执行（需 migration 404 函数）
bash scripts/ops/analyze-partition-stats.sh 154
bash scripts/ops/analyze-partition-stats.sh 245 --months 3
```

**长期**：migration `404_partition_autovacuum_analyze.sql` + `partition_manager` 每 promote 周期调用 `analyze_llm_gateway_table_stats(2)`；热表显式 `autovacuum_enabled=true`。

### 5.4 Schema 列缺失（07-14 类）

见 [deploy-154-schema-mismatch-lessons.md](./2026-07-14-deploy-154-schema-mismatch-lessons.md)：`ALTER TABLE ADD COLUMN IF NOT EXISTS` + 迁移版本对齐。
