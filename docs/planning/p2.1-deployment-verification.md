## Deployment Summary

After resolving a migration timeout issue, the P2.1 human annotation feature has been successfully deployed to production.

### Issues Encountered and Fixed

1. **Migration Timeout (20s default)**
   - **Problem**: Migration 664 (301 lines, 4 indexes) took >20s to complete
   - **Root Cause**: systemd `TimeoutStartSec=30s` killed the gateway before migration finished
   - **Solution**: 
     - Created systemd drop-in override: `/etc/systemd/system/llm-gateway-go@.service.d/timeout.conf`
     - Increased `TimeoutStartSec` from 30s to 90s
     - Added `LLM_GATEWAY_DB_BOOT_RETRY_SECONDS=60` to env file
   - **Result**: Migration now completes successfully within timeout window

2. **Service Outage During Failed Deployment**
   - **Problem**: Failed canary deployment stopped both old and new instances
   - **Solution**: Manually restarted old gateway version (1956-b3413208)
   - **Prevention**: The seamless deploy script now keeps old instance running on handoff failure

| # | Bug | 根因 | 修复 | 迁移 |
|---|-----|------|------|------|
| 1 | `GET /samples` 500: `column ars.model_name does not exist` | 查询引用了 `auto_route_selections` 中不存在的列（`model_name`/`prompt_token_count`/`is_streaming`/`has_vision`/`region`/`selected_provider`/`created_at`）；真实列为 `chosen_model`/`ts` 等（migration 478/658） | `admin/annotation_handler.go` querySamples 改用真实 schema：`chosen_model`（模型名 + auto 标签）、`ts`（时间过滤/排序）、`auto_route_selections_all` 视图；不存在于隐私最小化 schema 的字段在 payload 中置零值 | — |
| 2 | `GET /stats` 500: `cannot scan NULL into *float64`（**空表必现**） | `annotation_stats` 视图 `AVG(is_correct::int)` 空表返回 NULL，pgx 无法 scan 进 float64；Go 侧 `time.Time` 无法接受 NULL 时间戳 | 视图聚合加 `COALESCE(...,0)`；Go `FirstAnnotationAt/LastAnnotationAt` 改 `*time.Time`（前端本就声明 `string \| null`） | **665** |
| 3 | stats/前端全部显示 undefined | Go 结构体只有 `db` tag 无 `json` tag，序列化为驼峰键，前端读蛇形键 | `annotation/types.go` 四个统计结构体补 json tag（`reason→percentage` 对齐前端） | — |
| 4 | `POST /annotations`、`/batch` 一律 500: `no unique or exclusion constraint matching ON CONFLICT (42P10)` | 664 把 `request_id` 建成普通索引，而写入路径依赖 `ON CONFLICT (request_id) DO NOTHING` 幂等 upsert；且 INSERT 引用不存在的 `reason` 列（实际 `annotation_reason`）、未写 NOT NULL 的 `auto_label/auto_confidence` | 新增 `request_id` 唯一索引；INSERT 补全列名；`auto_label/auto_confidence` 由服务端从 `auto_route_selections_all` 按 request_id 回填（不信任客户端），查不到返回 400 | **666** |

## API Quick Reference

**Authentication**: JWT — `POST /api/auth/token` (`{"username","password"}`) → `Authorization: Bearer <access_token>`

```bash
TOKEN=$(curl -s -X POST https://llm.kxpms.cn/api/auth/token \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"..."}' | jq -r .access_token)

# 待标注样本（分页 + 过滤）
curl -H "Authorization: Bearer $TOKEN" \
  "https://llm.kxpms.cn/api/admin/annotations/samples?page=1&size=50&annotated=false"

# 统计
curl -H "Authorization: Bearer $TOKEN" https://llm.kxpms.cn/api/admin/annotations/stats

# 创建标注（auto_label/auto_confidence 由服务端按 request_id 从 auto_route_selections 回填）
curl -H "Authorization: Bearer $TOKEN" -X POST https://llm.kxpms.cn/api/admin/annotations \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "req_123",
    "human_provider": "anthropic",
    "is_correct": false,
    "reason": "quality",
    "annotator": "alice"
  }'
# reason ∈ performance / cost / availability / quality / other / correct

# 批量 / 删除
curl -H "Authorization: Bearer $TOKEN" -X POST https://llm.kxpms.cn/api/admin/annotations/batch \
  -H "Content-Type: application/json" \
  -d '{"request_ids":["req_1","req_2"],"human_provider":"openai","is_correct":true,"reason":"correct","annotator":"alice"}'
curl -H "Authorization: Bearer $TOKEN" -X DELETE https://llm.kxpms.cn/api/admin/annotations/req_123
```
