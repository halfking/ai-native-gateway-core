## 关键设计落点

### Track A — Redis 亲和力缓存
- `AffinityCache` 包装 `UserAffinityDAO.GetByUserID`，Redis hash TTL 1h；miss 回源 DB + 回填。
- DB miss 后 30s 负缓存，Redis 故障降级直查 DB。
- 构造函数接受 `nil` redis.Client；命中率计数器（hits/misses）导出供 Track C 复用。
- 并发 `-race` 测试已通过：100 goroutine × 200 ops 无竞态。

### Track B — 异步批量反馈写入
- `FeedbackBatcher`：buffered chan(10000) + 后台 goroutine；满 100 条或每 5s 批量 INSERT（pgx.Batch）。
- 通道满丢弃并计数 `dropped_total`；导出 `Flush(ctx)`。
- `FeedbackIntegrator.RecordFeedback` 改为入队；`Options.ControlledSyncFallback=true` 仍走旧同步路径。
- `enrichFromHumanAnnotations` 批量刷盘前回写，避免 9.7s 失败放大回源。
- 验收：Flush 零丢失 + 通道满丢弃计数 + 批量聚合三组测试全过。

### Track C — Prometheus 指标 + Admin API
- 直方图：`preclassify_ms` / `postclassify_ms` / `recommend_ms`。
- 计数器：`feedback_written_total{result}` / `feedback_dropped_total` / `exploration_total{strategy}` / `affinity_cache_{hits,misses}_total`。
- Gauge：`weighted_accuracy` / `affinity_cache_hit_ratio`（30s 刷）。
- Admin API（参数化查询防注入）：
  - `GET /api/admin/routing-opt/stats`
  - `GET /api/admin/routing-opt/accuracy?hours=24`
  - `GET /api/admin/routing-opt/parameters`
- 验收：handler nil-pool 返回 503；SQL 参数化（不拼接字符串）；`go build ./...` 通过。

### Track D — 主动学习采样
- `Exporter.Export` 新增 `--sampling=uncertain`：优先置信度 [0.4, 0.6]，不足回填 <0.4；每任务类型保底配额防偏斜。
- 导出列不变（隐私红线：不导出 prompt/messages/response）；CSV header 兼容现有 importer。
- 配额分配纯函数 `AllocateUncertain(records, quota)` 已加单测。
- CLI：`llm-gw-annotator export --sampling uncertain --max 5000`。

### Track E — Staging 部署验证（运维轨道）
- 验证报告模板：`docs/planning/p2.2-staging-verification-report.md`。
- 包含：迁移确认 SQL、env 注入清单、100 AUTO 请求 curl 模板、P99/连接增量记录区。
- 需运维在 staging 实际执行填值（`\dt routing_*`、grep log、psql 慢查询）。
