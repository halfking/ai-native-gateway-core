## 1. Executive Summary

P2.2 brings four optimization modules into production routing — pre-classify affinity signals,
post-classify multi-objective model recommendation, asynchronous feedback integration, and
adaptive parameter learning — plus a Redis affinity cache, Prometheus metrics, Admin API,
uncertainty-based active-learning sampling, and a full staging deployment playbook.

All five tracks (A–E) are merged. Every code-level claim in this report has been re-verified
against the working tree during the final accuracy audit (2026-09-07): `go build ./...` clean,
`go test -race` clean across `routingopt` / `annotation` / `admin` / `cmd/gateway`.

## 2. Track-by-Track Delivery

### Track A — Redis Affinity Cache
**Files:** `routingopt/affinity_cache.go` (new) · `routingopt/affinity_cache_test.go` (new) · `routingopt/enhancer.go` (wired) · `routingopt/options.go` · `cmd/gateway/routing_optimizer_init.go`

| Aspect | Implementation |
|---|---|
| Cache key | `routingopt:affinity:<userID>` (single hash) |
| Cached fields | `task_type_distribution` + `preferred_providers` |
| TTL | 1h (positive), 30s (negative — DB miss) |
| Nil-Redis fallback | `AffinityCache` optional on `Enhancer` via `SetAffinityCache`; nil = direct DAO call |
| Consistency | `Invalidate(userID)` del-on-write after `UpdateUserAffinity` upsert |
| Gate | `Options.EnableAffinityCache` (assembly-time only; wired from `ROUTING_OPT_AFFINITY_CACHE`) |

**Known limitation (documented, by design):** `Options.LoadUserAffinity` defaults to `false`
because the Classifier does not yet consume `EnhancedSignals` (Week 2 work). The cache is
wired and counted, but the PreClassify read path stays dormant until that lands — this is
the explicit Week-2 gating decision recorded in `options.go:26-29`, not an oversight.

### Track B — Asynchronous Batch Feedback
**Files:** `routingopt/feedback_batch.go` (new) · `routingopt/feedback_batch_test.go` (new) · `routingopt/integrator.go` · `cmd/gateway/routing_optimizer_init.go`

| Aspect | Implementation |
|---|---|
| Queue | buffered channel, capacity 10 000 |
| Flush trigger | 100 records OR 5 s ticker (whichever first) |
| Writer | `pgx.Batch` + `SendBatch` — single round-trip per flush |
| Backpressure | Channel full → drop + `StatsDropped()` counter (routing beats data) |
| Graceful shutdown | `Flush(ctx)` drains queue; wired before pool close in shutdown path |
| Sync fallback | `Options.ControlledSyncFallback=true` → legacy single-INSERT path |
| Annotation enrichment | Runs inside the worker before each batch INSERT (`enrichFromHumanAnnotations` passed as worker hook at `integrator.go:72`) |
| Metrics hook | `AttachFeedbackCounters(batch.Counters)` → `llmgw_routingopt_feedback_writes_total{result=ok\|error\|dropped}` |

### Track C — Prometheus Metrics & Admin API
**Files:** `routingopt/metrics.go` (new) · `routingopt/metrics_test.go` (new) · `admin/routing_opt_handler.go` (new) · `admin/routing_opt_handler_test.go` (new) · `admin/handler.go:1315-1321` (registration)

**Metrics (prefix `llmgw_routingopt_*`):**
- `llmgw_routingopt_preclassify_ms` / `postclassify_ms` / `recommend_ms` (histograms)
- `llmgw_routingopt_feedback_writes_total{result}` (counter via `AttachFeedbackCounters`)
- `llmgw_routingopt_exploration_requests_total` (counter)
- `llmgw_routingopt_cache_hits_total` / `cache_miss_total` (counters, fed by Track A)
- `llmgw_routingopt_weighted_accuracy` (gauge, fed by `learner.GetStats`)

**Admin endpoints (registered unconditionally at `admin/handler.go:1319-1321`, admin-auth wrapped):**
- `GET /api/admin/routing-opt/stats` — weighted accuracy + parameter version + annotation count
- `GET /api/admin/routing-opt/accuracy?hours=24` — per-hour × per-task-type aggregates over
  `routing_feedback_log`; hours clamped to `[1, 720]`, fully parameterized SQL
- `GET /api/admin/routing-opt/parameters` — active parameter version JSON

Handler returns 503 on nil pool (covered by `routing_opt_handler_test.go`).

### Track D — Active Learning Sampling
**Files:** `annotation/exporter.go` · `annotation/exporter_test.go` · `cmd/llm-gw-annotator/main.go`

| Aspect | Implementation |
|---|---|
| Sampling mode | `--sampling=uncertain` (alongside default `all`) |
| Tier priority | mid-band [0.4, 0.6) > low (<0.4) > high (≥0.6, fallback only) |
| Per-type quota | `MinPerTaskType` (default 10) floor, round-robin across task types; shortfall flows back to other types |
| Pure function | `SelectUncertainSamples(candidates, limit, opts)` — defined inline in `exporter.go` (no separate allocation file), deterministic, does not mutate input |
| CSV header | Identical to `all` mode — P2.1 importer unaffected |
| Privacy | Export columns unchanged — `prompt` / `messages` / `response` never exported |

**Known gaps (deferred, not regressions):**
- No `--uncertain-low/high` CLI flags — band is fixed at defaults unless `UncertainSamplingOptions` is set programmatically.
- No tenant filter in `querySamples` — candidates are not partitioned by tenant; acceptable for single-tenant staging but flagged for multi-tenant hardening.

**Audit fix verified:** 11 `SelectUncertainSamples` unit tests cover basic allocation,
backfill across types, mid-band priority, boundary semantics, shortage, empty input,
single-type non-skew, unlimited mode, no-mutation, determinism, and zero-options fallback,
plus `TestExportCSVHeader_Compatibility` pinning the P2.1 header contract.
