## 🎯 一、架构原则

### 1.1 核心设计原则

1. **插件化 (Plugin Architecture)**
   - 所有企业功能以Hook插件形式实现
   - 支持配置文件动态启用/禁用
   - 插件间相互独立，可并行开发

2. **契约优先 (Contract-First)**
   - 跨服务API使用OpenAPI 3.0规范
   - 先定义契约，后并行实现
   - 真实数据调用，无Mock层

3. **模块化开发 (Modular Development)**
   - 每个模块独立验收
   - 支持团队并行工作
   - 清晰的依赖关系

4. **可观测性 (Observability)**
   - 所有插件埋点Prometheus指标
   - 结构化日志
   - 分布式追踪

5. **渐进式增强 (Progressive Enhancement)**
   - 不破坏现有功能
   - 向后兼容
   - 灰度发布

### 2.2 数据流向

#### 2.2.1 会话处理流程

```
客户端请求
    ↓
[PreRouting Hook链]
    ├─ SessionAuditHook (Priority 10)
    ├─ PromptInjectionHook (Priority 20)
    └─ AuthenticationHook (Priority 5)
    ↓
[Routing Hook链]
    └─ IntelligentRoutingHook
    ↓
[PreUpstream Hook链]
    ├─ SessionCompressionHook (Priority 10)
    └─ TransformationHook (Priority 20)
    ↓
上游LLM调用
    ↓
[PostUpstream Hook链]
    ├─ OutputSanitizerHook (Priority 30) 🔨 NEW
    └─ SemanticCacheHook (Priority 50)
    ↓
响应客户端
    ↓
[PostResponse Hook链] (异步)
    ├─ MemoraAutoHook (Priority 100) 🔨 NEW
    ├─ CrossSummaryHook (Priority 110) 🔨 NEW
    └─ MetricsHook (Priority 200)
```

#### 2.2.2 知识沉淀流程

```
llm-gateway-go 会话
    ↓
[Idle检测: 最后活动>1小时 且 请求数≥3]
    ↓
MemoraAutoHook 触发
    ↓
POST /api/sessions/ingest (kxmemory)
    ├─ 请求体: preview_turns, metadata
    └─ 响应: task_id, status
    ↓
kxmemory 异步处理
    ├─ 1. 规则过滤 (去噪音)
    ├─ 2. LLM智能提取 (结构化)
    ├─ 3. 实体识别 (NER)
    ├─ 4. 关系抽取 (RE)
    ├─ 5. 自动标签 (分类)
    └─ 6. 写入存储
        ├─ L1: Qdrant向量 (会话记忆)
        ├─ L2: Qdrant向量 (事实知识)
        └─ L3: Neo4j图谱 (实体关系)
    ↓
知识检索增强
    ├─ 压缩时注入相关知识
    └─ 跨会话总结生成
```

## 📊 三、核心组件

### 3.1 Hook插件系统

#### 3.1.1 Hook接口定义

```go
// domains/hooks/types.go

type Hook interface {
    Name() string                                    // 插件名称
    Priority() int                                   // 执行优先级（小值先执行）
    Enabled() bool                                   // 是否启用
    Phase() Phase                                    // 执行阶段
    Execute(ctx context.Context, env *Environment) error  // 执行逻辑
}

type Phase string

const (
    PhasePreRouting    Phase = "pre_routing"    // 路由前
    PhaseRouting       Phase = "routing"        // 路由中
    PhasePreUpstream   Phase = "pre_upstream"   // 上游前
    PhasePostUpstream  Phase = "post_upstream"  // 上游后
    PhasePostResponse  Phase = "post_response"  // 响应后(异步)
)
```

#### 3.1.2 配置文件格式

```yaml
# config/hooks.yaml

hooks:
  # 输出脱敏插件
  - name: output-sanitizer
    enabled: true
    priority: 30
    phase: post_upstream
    config:
      pii_detection: true           # 启用PII检测
      sensitive_words: true         # 启用敏感词检测
      stream_mode: true             # 流式脱敏
      redaction_style: "[REDACTED]" # 脱敏样式
      custom_patterns:              # 自定义规则
        - name: api_key
          pattern: "sk-[a-zA-Z0-9]{32}"
        - name: jwt_token
          pattern: "eyJ[a-zA-Z0-9_-]+\\.[a-zA-Z0-9_-]+\\.[a-zA-Z0-9_-]+"
  
  # Memora自动沉淀插件
  - name: memora-auto
    enabled: true
    priority: 100
    phase: post_response
    config:
      idle_timeout: 3600            # Idle超时(秒)
      min_requests: 3               # 最小请求数
      use_llm_extract: true         # 使用LLM提取
      kxmemory_base_url: "http://localhost:8000"
      retry_attempts: 3             # 重试次数
      retry_backoff: 2              # 退避系数
  
  # Vibe Coding质量评估
  - name: vibe-coding
    enabled: false                  # 默认禁用
    priority: 40
    phase: post_upstream
    config:
      code_quality_threshold: 70    # 质量阈值
      max_iterations: 3             # 最大迭代次数
      rules:
        - style_check
        - security_scan
        - complexity_analysis
```
