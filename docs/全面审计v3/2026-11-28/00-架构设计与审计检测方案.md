## 一、当前架构快照（结合代码实证，非设计稿）

### 1.1 请求业务流（IR 主链）

```
客户端（chat/messages/responses/Gemini 四协议入口）
  → 认证与鉴权（api_keys / JWT；users.role 多角色化，Roles claim）
  → 三级配额预检（tenant → org → user；fail-open）
  → 三级模型过滤（tenant deny/allow → org → user；scope 前缀 t:/o:/u:）
  → 注入检测 / 敏感信息脱敏（domains/hooks；original → sanitized 映射）
  → IR 转换（协议 ↔ 原厂格式自适应：98ef46b77e 协议自适应线）
  → 路由与凭据池（autoroute；权重负载均衡；代理出口）
  → 上游请求（流式/非流式；错误以 think 模式旁路不影响会话）
  → 输出检测 / 脱敏还原（AlignmentMap 反向恢复）
  → 归因与计费（request_metrics 投影：org_id JOIN users 落表）
  → 会话存储（session_turns 家族；request_logs v1 已退役）
```

### 1.2 存储分层（全量 / 本地简化双架构）

| 层 | 全量模式 | 简化模式 |
|---|---|---|
| 热数据 | PostgreSQL（session_turns + session_turns_hot 索引族）| sqlite |
| 分区/列存 | session_bodies 按（月）分区 + columnar | memory/files |
| 缓存 | Redis + 进程内 memory | memory |
| 文件 | 附件与媒体目录存储 | 同 |

**纪律**: 更新/删除只在 hot 表；hot 窗口 8 小时，批量转移任务下沉分区表（`mv-refresher` 同族调度）。

### 1.3 三层 provenance 缓存

- 原文 → 脱敏 → 压缩三层 identity/occurrence 映射，落点：`domains/hooks/compression/alignment.go`（正向）、`alignment_reverse.go`（还原）、`SanitizedMessageRefs` / `AlignmentMap` 生产链接入 V2 metadata（`domains/streaming/executors/executor_responses_provenance.go`、`domains/transformation/responses_compress.go`）。
- sanitizer 跨进程 offset 原子预占 + provider-window source telemetry：`domains/streaming/request_log_pipeline.go`。

### 1.4 超长会话链

自动压缩（`domains/hooks/compression/session_compressor.go`）→ 供应商返回上下文超长时保持连接、压缩后重试（不向客户端报错）→ 1M 阈值开关走 handoff 技能 /new 切新会话。相关包：`internal/contextagent`、`internal/contextbudget`、`internal/sessioncontext`。
