## 三、关键技术发现详解

### 3.1 核心数据流架构

**请求生命周期**:
```
HTTP Request → MessagesHandler/ChatHandler
  → 生成 RequestID (server UUID)
  → 生成/恢复 SessionID
  → 状态机初始化 (SP-02)
  → Request Journey Tracking (10个时间戳 T0-T9)
  → Sanitize Input (可选)
  → Context Fitting (超长会话压缩)
  → IR Validation & Fixing (5步)
  → Routing & Model Selection
  → Upstream Request (协议转换)
  → Response Interception (流式, 最大16MB)
  → Response Delivery (StreamSession)
  → Storage Layer (V1/V2 双轨)
```

### 3.2 V2 存储架构详解

**分层结构**:
```
sessions (会话快照, 1 per session)
  ↓
session_turns (轮次元数据, 200+ 字段, 不含正文)
  ↓
session_bodies (增量消息delta, columnar)
  ↓
session_turn_logs (处理阶段日志, 24h TTL)
```

**TurnRecord 关键字段**:
- **提交模式**: full | delta | snapshot | inferred_compressed | attachment_only
- **压缩元数据**: CompressionApplied, CompressionStrategy
- **治理判决**: InjectionVerdict, OutputVerdict (pass|warn|block|skip)
- **10阶段时间戳**: T0-T9 (到达→入队→出队→转发→响应)
- **存储优化 v2 S1a**: RequestDeltaJSON, ResponseDeltaJSON
- **成本跨单位**: CostUSD (float64) + CreditsCharged (int64) ⚠️

### 3.3 会话压缩机制（Fit函数）

**保护区识别**:
- 首个任务消息
- 所有特权指令  
- 最新的完整用户/工具交互组

**压缩策略**:
1. 构建基线 (只保护区，无摘要)
2. 如果基线超预算 → 拒绝 (ErrProtectedContext)
3. 计算剩余预算
4. 采样旧历史文本 (SHA256 digest 追踪)
5. 迭代尝试不同采样长度
6. 兜底返回基线

**新增功能（48小时内）**:
- **P1-C**: `ErrSingleMessageTooLarge` 单条消息超限
- **P1-D**: 媒体省略标记 `[media omitted from bounded context]`
