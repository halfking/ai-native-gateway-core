## 1. 问题详解

### 1.1 现象

**用户视角**:
- 会话统计页面显示费用：$8,577.79
- 看板页面显示费用：$9,899.22
- **差异：$1,321.43 (13.4%)**

用户困惑：
- "为什么两个页面的数字不一样？"
- "哪个数字是对的？"
- "会话统计是不是有 bug？"

### 1.2 根本原因

**问题定位**: `admin/dashboardapi/session_overview.go:439-508`

**错误实现**:
```go
func (h *SessionOverviewHandler) querySessionSummaryAggregates(
    ctx context.Context, params QueryParams, win sessionWindow,
) (*sessionSummaryAggregates, error) {
    // ❌ 错误：只过滤首次请求时间
    where = append(where, fmt.Sprintf(
        "first_request_at >= NOW() - INTERVAL '%d days'", 
        params.Days,
    ))
    
    query := `
        SELECT
            COUNT(*) as total,
            COALESCE(SUM(ss.total_cost_usd), 0) as total_cost,
            COALESCE(SUM(ss.request_count), 0) as total_requests,
            ...
        FROM session_summaries ss
        [+ 宇宙过滤 (owner非空、排除探测)]
        WHERE first_request_at >= NOW() - INTERVAL '7 days'
    `
    // ⚠️ 问题 1: session_summaries.total_cost_usd 是全生命周期累计值
    // ⚠️ 问题 2: 会话首次请求在8天前但7天内仍活跃的会话被完全排除
}
```

**为什么这是错的？**

示例场景（7天窗口：Nov 16-23）:

| 会话 | 首次请求 | 窗口内请求 | 窗口内费用 | 当前行为 | 正确行为 |
|------|---------|-----------|-----------|---------|---------|
| **Session A** | Nov 15 | Nov 17($10), Nov 18($5), Nov 19($8) | $23 | ❌ **完全排除** | ✅ 应统计 $23 |
| **Session B** | Nov 17 | Nov 17($12), Nov 18($7) | $19 | ✅ 统计 $19 | ✅ 统计 $19 |
| **Session C** | Nov 20 | Nov 20($15) | $15 | ✅ 统计 $15 | ✅ 统计 $15 |

**当前结果**: $19 + $15 = **$34** ❌  
**正确结果**: $23 + $19 + $15 = **$57** ✅  
**漏算**: $23 (40%)

在生产环境中：
- 7天窗口内实际费用：$9,899.22
- 会话统计显示：$8,577.79
- **漏算：$1,321.43 (13.4%)**

### 1.3 为什么会有这个问题？

**设计缺陷根源**:

1. **数据结构不匹配**:
   - `session_summaries` 存储的是**会话全生命周期累计值**
   - 但查询需要**时间窗口内的增量值**
   - 两者不兼容！

2. **过滤逻辑错误**:
   ```sql
   -- 错误逻辑：
   WHERE first_request_at >= '2026-11-16'
   
   -- 这排除了：
   -- • 11月15日开始，但16-23日仍活跃的会话
   -- • 10月开始，但一直活跃到11月的长会话
   -- • 任何跨月/跨周的会话
   ```

3. **累计值误用**:
   ```sql
   SUM(ss.total_cost_usd)  -- 累计了会话的全生命周期费用
   -- 即使加上正确的时间过滤，这个值仍然包含窗口外的费用
   ```

**正确的做法**:
- 不应使用 `session_summaries` 的累计值
- 应直接聚合 `request_logs` 表按 `ts >= window_start` 过滤

## 4. 完整修复方案

### 4.1 推荐方案：混合查询（方案 C）

**设计思路**:
- **核心指标**（请求数、费用）→ 从 `request_logs` 聚合（准确）
- **质量指标**（健康度、合规度）→ 从 `session_summaries` 获取（可用）

**实现代码**:

```go
// admin/dashboardapi/session_overview.go

func (h *SessionOverviewHandler) querySessionSummaryAggregates(
    ctx context.Context, params QueryParams, win sessionWindow,
) (*sessionSummaryAggregates, error) {
    
    // 构建查询
    query := `
    WITH window_sessions AS (
        -- 步骤 1: 找出窗口内所有活跃的会话
        SELECT DISTINCT rl.gw_session_id, rl.tenant_id
        FROM request_logs_with_current_month rl
        WHERE rl.ts >= NOW() - INTERVAL $1  -- 时间过滤：请求在窗口内
          AND rl.origin_stage = 'business'   -- 只统计业务流量
          AND rl.gw_session_id IS NOT NULL   -- 必须有会话ID
    ),
    universe_sessions AS (
        -- 步骤 2: 应用会话宇宙过滤（排除探测、匿名等）
        SELECT ws.gw_session_id, ws.tenant_id
        FROM window_sessions ws
        JOIN (
            -- D2去重: 每个会话取最新分区的一行
            SELECT DISTINCT ON (session_id, tenant_id)
                session_id, tenant_id, is_probe, owner_user, 
                client_type, title
            FROM sessions
            ORDER BY session_id, tenant_id, partition_date DESC
        ) s ON s.session_id = ws.gw_session_id 
           AND s.tenant_id = ws.tenant_id
        LEFT JOIN session_dim sd 
            ON sd.session_key = ws.gw_session_id 
           AND sd.tenant_id = ws.tenant_id
        WHERE 
            -- 要求有 owner（排除匿名）
            NULLIF(COALESCE(s.owner_user, sd.api_key_owner_user), '') 
                IS NOT NULL
            -- 排除标记为探测的会话
            AND NOT COALESCE(s.is_probe, false)
            -- 排除通过启发式判定为探测的会话
            AND NOT session_analytics_is_probe(
                COALESCE(s.owner_user, sd.api_key_owner_user), 
                s.client_type, s.title
            )
    ),
    window_metrics AS (
        -- 步骤 3: 聚合窗口内的请求（准确的费用和请求数）
        SELECT 
            COUNT(DISTINCT r.gw_session_id) AS total_sessions,
            COUNT(DISTINCT r.gw_session_id) FILTER (
                WHERE r.ts >= NOW() - INTERVAL '24 hours'
            ) AS active_sessions,
            COUNT(*) AS total_requests,
            COALESCE(SUM(r.cost_usd), 0) AS total_cost,
            COALESCE(AVG(r.latency_ms), 0) AS avg_latency
        FROM request_logs_with_current_month r
        JOIN universe_sessions us 
            ON r.gw_session_id = us.gw_session_id 
           AND r.tenant_id = us.tenant_id
        WHERE r.ts >= NOW() - INTERVAL $1
          AND r.origin_stage = 'business'
    ),
    session_quality AS (
        -- 步骤 4: 获取会话质量指标（健康度、合规度）
        SELECT 
            COUNT(*) FILTER (WHERE ss.health_grade = 'A') as health_a,
            COUNT(*) FILTER (WHERE ss.health_grade = 'B') as health_b,
            COUNT(*) FILTER (WHERE ss.health_grade = 'C') as health_c,
            COUNT(*) FILTER (WHERE ss.health_grade = 'D') as health_d,
            COUNT(*) FILTER (WHERE ss.health_grade = 'F') as health_f,
            COUNT(*) FILTER (
                WHERE ss.compliance_status = 'compliant'
            ) as compliant,
            COUNT(*) FILTER (
                WHERE ss.compliance_status = 'non_compliant'
            ) as non_compliant,
            COUNT(*) FILTER (
                WHERE ss.compliance_status = 'unknown'
            ) as compliance_unknown
        FROM session_summaries ss
        JOIN universe_sessions us 
            ON ss.session_key = us.gw_session_id 
           AND ss.tenant_id = us.tenant_id
    )
    SELECT 
        wm.total_sessions,
        wm.active_sessions,
        wm.total_requests,
        wm.total_cost,
        wm.avg_latency,
        sq.health_a,
        sq.health_b,
        sq.health_c,
        sq.health_d,
        sq.health_f,
        sq.compliant,
        sq.non_compliant,
        sq.compliance_unknown
    FROM window_metrics wm, session_quality sq
    `
    
    args := []interface{}{
        fmt.Sprintf("%d days", params.Days),
    }
    
    var result sessionSummaryAggregates
    err := h.db.QueryRowContext(ctx, query, args...).Scan(
        &result.Total,
        &result.Active,
        &result.TotalRequests,
        &result.TotalCost,
        &result.AvgLatency,
        &result.HealthA,
        &result.HealthB,
        &result.HealthC,
        &result.HealthD,
        &result.HealthF,
        &result.Compliant,
        &result.NonCompliant,
        &result.ComplianceUnknown,
    )
    
    return &result, err
}
```

**关键改进**:

1. ✅ **window_sessions**: 识别在时间窗口内有请求的所有会话
   - 过滤条件：`rl.ts >= window_start`（请求时间）
   - 而非：`first_request_at >= window_start`（会话开始时间）

2. ✅ **universe_sessions**: 应用会话宇宙过滤
   - D2去重：`DISTINCT ON (session_id, tenant_id)`
   - owner非空
   - 排除探测

3. ✅ **window_metrics**: 聚合准确的费用和请求数
   - 从 `request_logs` 直接聚合
   - 只统计窗口内的请求
   - 不使用 `session_summaries` 的累计值

4. ✅ **session_quality**: 获取质量指标
   - 健康度、合规度从 `session_summaries` 获取
   - 这些指标是会话级的，不受时间窗口影响

**验证 2: 跨窗口会话包含性**

```sql
-- 找出首次请求在窗口外，但窗口内有活动的会话
WITH cross_window_sessions AS (
    SELECT 
        ss.session_key,
        ss.first_request_at,
        COUNT(*) FILTER (
            WHERE rl.ts >= NOW() - INTERVAL '7 days'
        ) AS window_requests,
        SUM(rl.cost_usd) FILTER (
            WHERE rl.ts >= NOW() - INTERVAL '7 days'
        ) AS window_cost
    FROM session_summaries ss
    JOIN request_logs_with_current_month rl 
        ON rl.gw_session_id = ss.session_key
    WHERE ss.first_request_at < NOW() - INTERVAL '7 days'
      AND rl.ts >= NOW() - INTERVAL '7 days'
    GROUP BY ss.session_key, ss.first_request_at
    HAVING COUNT(*) > 0
)
SELECT 
    COUNT(*) AS cross_window_sessions,
    SUM(window_requests) AS missed_requests,
    SUM(window_cost) AS missed_cost
```
