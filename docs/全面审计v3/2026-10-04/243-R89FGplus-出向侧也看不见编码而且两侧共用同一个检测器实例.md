   插入位置在 restore 之后（`:571-585`，236 号审过该顺序）——**这两点都对，本轮不动它们。**

## §一 三次差点得出错误结论的坑（**本轮最有价值的部分**）

### 坑 1：把「响应被清空」当成「泄漏的证据」

第一次跑流式与非流式对照，编码臂的 `client_body` 打印出来是**空字符串**。
我第一反应是「客户端拿到空体」——**方向完全错了**。
加临时探针打印整个 result 才看清契约：

```
明文臂： ModifiedBody=[...] Action:output_compliance_redact Metadata:{issue_count:1 …}
编码臂： ModifiedBody:[]          Action:(空)                Metadata:map[](空)
```

⇒ **未检出时链条返回「非 nil 但 `ModifiedBody` 为空」，语义是「无修改，沿用原体」。**
我的辅助函数把它当成「响应体」返回了。
⇒ 若当时照抄，报告里会写「编码形态导致响应被清空」——**一个凭空捏造的故障形态**。

### 坑 2：两次被控制台截断的输出骗了

`Select-String` 打印长行时，控制台按宽度截断。
第一次我只看到 `data: {...content":"call MTM4MDAx"}]}`，据此判断「第二帧被丢了」，
并顺手写了「本夹具不透传未检出帧」的中性臂说明——**那是错的**。
中性臂实测证明 `hello `/`world` 两帧**都在**，说明透传是正常的。
⇒ **长行输出必须带定界符或改用长度/布尔量，不能靠肉眼看被截断的片段。**

### 坑 3（最要紧）：**断言的形式让被测性质不可观测**

修好辅助函数后，流式编码臂仍然报「盲区已消失」。
这次不是夹具问题，而是**我的断言写错了单位**：

```go
if strings.Contains(wire, enc) { … 盲区仍在 … }
//    ↑ enc 是完整的 16 字符 base64；wire 里它被拆在两个 SSE 帧的 content 里
```

⇒ **无论有没有被遮蔽，这个连续子串都不会出现在 wire 里** ——
**断言观察的是一个在它那个形式下无法被观察的性质。**
实测 wire 长度 147，**三帧全在**，`MTM4MDAx` 与 `MzgwMDA=` 都在。
⇒ 改成「**两半都在 ⇒ 按帧序拼接可还原**」，这才是可观测、且才是真正的命题。

⚠️ 这与 196 号的 M2（合并顺序倒置在空增量上不可观测）
和我 242 号的「对照组是许可证」是**同一族的三次复发**：
**判据不在被测性质上。**

## §五 playbook

### §203-A **「响应体是空的」有三种可能，先把契约读完再解释它**

坑 1 的教训不是「要小心」——而是：**当一个字段的值是"空"时，
在写进结论之前必须先确认"空"在这个接口里代表什么**。
本仓的链条在未检出时返回 **非 nil + 空 `ModifiedBody` + 空 `Action` + 空 `Metadata`**，
而调用方被期望沿用原体。
⇒ **How to apply**：测一个拦截器/中间件时，**先用一个"什么都没发生"的输入跑一遍**，
把返回值的「无事发生形态」记下来，再去解释「有异常」时的返回值。
⇒ 坑 2 是它的兄弟：**控制台截断的输出与"字段是空的"长得一模一样**。

### §203-B **同一个性质在不同 lane 上的单位可能不同 —— 判据的单位必须跟着变**

非流式里敏感值是**一段连续的字节**；流式里它被拆进**多个帧的 content**。
用同一种判据（连续子串）去测两个 lane，在非流式上正确、在流式上**恒不可观测**。
⇒ **How to apply**：写「某值是否泄漏」的断言时，先问
**「这个值在传输层会不会被拆开？」**；
会被拆开时，判据必须是「**各片都在**」（可拼接），而不是「整串在」。
⇒ 这已经是同一族在本会话的**第三次**复发（196 号 M2 / 242 号对照组 / 本轮），
说明它值得单独立条，而不是继续以个案处理。

### §203-C **「共用一个实例」比「用了同一套逻辑」强得多，报告要说前者**

F1 只说「两侧用同一套正则」时，听起来像「两处独立实现碰巧一样」；
查证后发现是 `:546` 的**同一个对象**被送进链路三处。
⇒ 前者是巧合，可以各自修；**后者是一个能力边界，改它一次两侧同时变**。
⇒ **How to apply**：报告「两条路径行为一致」时，
**追到对象身份再下结论**——追不到就明确写「同源还是巧合未确认」，
不要用「都用正则」这种描述把两者混过去。
