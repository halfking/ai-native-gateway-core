## R-41② F-44（P3）：StickyCache.Close 并发非幂等

- **缺陷**：`domains/streaming/executors/sticky.go` Close 用 `select { case <-s.stopSweep: return; default: close(s.stopSweep) }` 判「已关」——两 goroutine 并发 Close 可同时进 default 臂 ⇒ double-close panic；注释自称「sync.Once pattern」实则不是。当前调用面仅停机/测试单线程，属潜伏缺陷。
- **修复**：结构体加 `closeOnce sync.Once`；Close 改 `s.closeOnce.Do(func() { close(s.stopSweep) }); s.sweepDone.Wait()`（WaitGroup.Wait 对等待者安全，每次执行无妨）。
- **钉测**：`sticky_close_idempotent_test.go` 两枚——并发 Close×16（捕获 recover 证明无 panic）＋重复 Close 2s 内返回（无泄漏）；nil receiver 语义保持。
- **变异验证**：回退旧 select-default 形态 ⇒ `-race -count=3` 下 **FAIL（「并发 Close 触发 panic」）** ✔；还原 ⇒ 绿；md5 一致 ✔。
