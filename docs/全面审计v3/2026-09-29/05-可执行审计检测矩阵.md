# D01–D17 可执行审计检测矩阵（2026-09-29）

## 1. 测试数据、环境与证据格式

每次执行固定 `BASE..HEAD`、Go/Node/PG/Redis 版本、开关快照和 Git 工作树差异。请求样本使用合成身份和假密钥；真实密钥、原文敏感数据、供应商响应正文不进入测试报告。每项证据记录输入 fixture、协议、stream 标志、expected/actual、request/session/attempt ID、落库行数、错误分类、测试命令和退出码。负例也必须有客户端终态和 durable 状态；不允许只看 200 或单个函数调用。

本地 `deploy-local.sh` 可作为隔离全栈环境，但先验证它使用的数据库、Redis、端口与当前用户数据无冲突；测试脚本的旧目录扫描 migration 路径与生产显式序列不同，不能用它代替生产升级验证。收费供应商、代理出口和共享数据库测试单独设置额度/隔离凭据。本轮没有执行这些环境门。

## 2. 主业务流纵向矩阵

| 测试 ID | 输入与故障注入 | 必须观察的结果 |
|---|---|---|

| FLOW-06 | >1M token 客户端能力有/无、handoff 开关开/关、同 ID 重试与确认 | 有能力时只生成一次 resume packet 并等待客户端 `/new`；无能力按明确定义的兼容退路。网关不得伪造客户端命令；原会话与新会话引用可追溯。 |

## 4. 数据库验证脚本提纲（仅隔离库）

对每张大表先查 `pg_class`、`pg_partition_tree`、access method、约束和索引，再查 writer SQL 是否只向 `_hot` 写/更新/删除，最后按固定 8 小时边界插入合成数据，运行迁移任务两次并比较行数、哈希、重复数与归档查询。`EXPLAIN (ANALYZE, BUFFERS)` 只对隔离或允许的只读样本执行；对在线大表避免无边界全扫。migration 756 的非并发索引有写锁，必须在受控窗口验证锁等待与 rollback；757/758 的前后断言在存量 schema 上实跑。迁移执行记录应含 schema_migrations、role、session `statement_timeout` 与真实 DDL 后系统目录验证。
