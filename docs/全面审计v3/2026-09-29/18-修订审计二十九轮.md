## 一、R28-P-1（P1）数据面 egress 路由 ✅

**问题回顾**：providers.egress_profile/proxy_subscription_id 只落库展示，订阅节点池（管理面 proxy.Manager：订阅/探测/避港/切流）仅 free-pool 探活消费——「海外必须走代理」生产路径不成立；探活（节点池）与真实流量（env 单代理/直连）出口不一致（R28-F-2）。

**实现**（六件）：
1. `upstream/egress.go`：EgressMeta（请求 context 携带 ProviderID）+ `EgressTransportProvider` 接口（nil transport=默认路径，error=fail-closed）。
2. `upstream/client.go`：`Client.Do` 与 `DoWithHTTPClient`（身份池路径）双入口 egress 分发——**代理正确性优先于连接池复用**（注释明示取舍）；无标记 provider 零开销旁路。
3. `proxy/egress_provider.go`：`EgressProvider` 实现——providers 表策略 TTL 缓存（60s，Invalidate 支持运营改配即时生效）；profile='proxy' → `Manager.GetProxyTransport`（跨订阅选优，subscription NULL 时）；**标记 proxy 但无健康节点 → 请求失败（fail-closed，错误信息明示原因）**，不再静默直连；DB 故障 fail-open 回 legacy 路径（未标记行安全默认）。
4. 三协议 executor BuildRequest（chat/anthropic/ollama）+ 压缩调用（context_summarize）共 4 处注解 `WithEgressMeta(req, cand.ProviderID)`——**Candidate/大 SQL 零改动**（策略在分发端缓存解析）。
5. `admin.Handler.EgressProxyManager()` 暴露管理面 Manager（Start 幂等）。
6. `cmd/gateway/main.go` 接线：adminDB 就绪时 `upClient.SetEgressProvider(proxy.NewEgressProvider(...))`。

**R28-P-3 同批**：`loadDirectEgressHosts`（main_helpers.go）把 egress_profile='direct' 的 provider 主机注入 `ProxyResolver.AddDomesticHosts`——境内白名单从硬编码表升级为**策略驱动**（direct 标记=永不走 env 代理）。

**R28-F-2 结构性消除**：探活与生产流量同走 egress 分发（同一节点池同一 transport 工厂），出口一致性成立。

**测试**：upstream 3 态分发（custom RT/nil 默认/错误 fail-closed + 无标记旁路 + 池路径覆盖）+ proxy 5 例（direct 默认/proxy 走节点池/无节点 fail-closed/缓存一次命中+Invalidate/DB 故障 fail-open）全绿。

## 二、R28-Q-1（P1）dispatch 热配置接线 ✅

**问题回顾**：`llmgw_dispatch_*` 12 个热配置旋钮生产零消费——LoadConfig 无调用方、Deps.HotCfg 不传、Reload 无人调；总闸容量/队列深度/重试预算全部死默认。

**实现**：`NewDispatchPipeline(hotCfg *hotconfig.Config)`（构造时 LoadConfig 种子进 Deps.HotCfg）+ `startDispatchConfigReload`（main_dispatch.go：立即应用 + 30s tick 跟随 hotconfig 轮询重 Reload）；main.go 传入 executorHotConfig（与 RequestJourney 同一热载源）。生效边界遵循 Pipeline.Reload 既有文档：队列等待/重试/registry 限额即时生效，worker 数重启生效（注释明示）。测试调用方 4 处同步补 nil。
