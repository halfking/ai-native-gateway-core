## 26. 三十五轮增补（续十）——P1-5 复核：撤销一条伪 GAP，发现一条真死路径

§22 把「D01 unknown extension TTL」排进 P1。本轮动手前先核实现状，**结论是这条 GAP 不成立**，遂撤销并重新定性。

### 撤销：Extensions 不落库，「无界增长」是伪问题

- 该 GAP 源自子 agent 报告，本次 §20 原样引用。核实证据：
  - `ir.InternalRequest.Extensions`（`internal/ir/types.go:210`）由 `domains/transformation/ir_converter.go:435 extractRequestExtensions` **每请求从入站 wire 填充**；
  - 由 `ir_converter.go:306/320/343 restoreExtensions` 消费并写回**出站** wire body；
  - 全仓**无任何持久化写点**引用它（`domains/session/`、`internal/requestfact/` 均无）。
- 结论：它是**请求级内存容器**，生命周期 = 单次请求。为它谈 TTL / 无界增长属**照搬验收标准措辞**，不构成真实风险。
- **验收标准的「TTL 明确」只有在两种情形下才有意义**：① doc 08 的 `EnvelopeV3` 落地后（影子双写持久化——目前**未落地**）；② 下方这条**本应**持久化的路径。二者都不是现状。
- 已同步修订 §20 的 D01 条目与 §22 的 P1 排序（改为撤销线）。

### 真发现：`ProviderExtensions` 持久化链在生产是**死路径**（属 D17，非 D01）

追查「谁会把未知扩展字段真正持久化」时的结果：

| 环节 | 位置 | 状态 |
|---|---|---|
| 抽取器 | `ExtractProviderExtensions`（`domains/session/v2/provider_extensions.go:14`） | ❌ **零生产调用方**——全仓仅出现在它自己的文档注释里 |
| 字段声明 | `ProviderExtensions`（`session_writer_v2.go:307`、`dual_writer.go:136`） | ✅ 存在 |
| 唯一赋值 | `dual_writer.go:274` `ProviderExtensions: req.ProviderExtensions` | ⚠️ 只是**拷贝**，而 `req.ProviderExtensions` **在生产从未被填充**（因抽取器无调用方） |
| 落库 | — | ❌ 因此**无任何扩展字段真正落库** |

- 即：设计意图是「供应商私有字段跨轮保真」，实际生产**一个字段都没存**。
