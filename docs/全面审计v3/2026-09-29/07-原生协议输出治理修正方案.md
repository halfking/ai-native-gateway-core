# 原生 Messages / Responses 输出治理修正方案（V3-F02）

## 证据与安全边界

Messages 和 Responses 的 survival 流已通过 `newInterceptingStreamWriter` 在真实 writer 前拦截（`domains/streaming/messages.go:761`、`responses.go:751`），普通流则直接交 `w` 给 executor（两文件约 `:783`、`:773`）。非流在 handler 的 `writeNonStreamResponse` 直接写成功 body（`messages.go:1314`、`responses.go:1204`），此前未调用 interceptor。`OutputComplianceInterceptor.InterceptStreamChunk` 为空（`domains/hooks/outputcompliance/interceptor.go:96`），流结束才检查已发送内容；非流实现目前把整份 JSON 交 checker，`rewriteAssistantContent` 又只改 Chat `choices`。`SanitizeRestoreInterceptor.restoreResponseBody` 同样只识别 `choices`，虽流 delta 能处理 Anthropic/Responses。必须以**客户端真实接收的字节**验证整改，不能以遥测的 ModifiedBody 代替。

## 分阶段实施

1. **写入权与拦截链基线（本轮局部已改）**：`responseSink` 在非流 `SuppressSuccessWrite` 下丢弃 executor 成功写，仍返回 `ResponseBody`；Ollama 成功路径改用该 sink。原生 Handler 的缓存重放暂不走直接写的捷径，交真实执行路径处理，后续再做带协议的缓存。`response.InterceptorChain` 首个 ModifiedBody/Chunk 现在向下游传播，并完整复制新增的请求能力字段。上述改动只消除明确的前置旁路，**不关闭输出合规缺口**。Ollama/Anthropic 非 2xx 的直接透传属于错误路径，另定错误体协议和拦截契约。
2. **非流先算最终 body，再提交 HTTP**：将两个 Handler 的 `writeNonStreamResponse` 拆为纯转换和一次性提交；转换后、首次 `WriteHeader/Write` 前，调用 `InterceptNonStream` 并检查 `ShouldBlock`、`ModifiedBody`。按原生协议从可见文本字段提取检测内容，再回填原位：Messages 的 `content[]`，Responses 的 `output[]`、tool output/refusal。还原只使用已认证租户与当前会话的映射。阻断返回各自合法的安全错误，遥测和 durable 捕获使用提交后的同一 body。明确 `Content-Length` 重算、空响应、首轮无映射和失败记录。
3. **普通流预写拦截**：在普通流调用 executor 前也包 `newInterceptingStreamWriter`，携带 session/tenant/request/model 和 per-stream `StreamState`。已有 writer 支持分片成帧及 16 MiB 上限，但目前 `writeFrame` 的 `ShouldBlock` 只丢当前帧、后续仍可发送；interceptor 错误时可能透传原帧。先定义“阻断后停止后续内容与 completed 帧，并写协议合法失败终态”，再启用强制合规。还原器对 Anthropic/Responses 文本和工具参数 delta 的已有支持须以真实客户端流验证。
4. **流式输出检测**：按协议与文本 lane 做有界跨帧留存，保证手机号/邮件/自定义敏感串跨 delta 时仍可检查并改写；同时处理 chunk 内多个 SSE 事件、`data:{}`、多行 `data:`、工具参数与 refusal。检测失败、超大帧、客户端取消都需要明确终态和 durable 结果。链顺序当前为 goal→audit→output_compliance→sanitize_restore（`cmd/gateway/goal_control.go:358-376,579-582`）；合规改写后还原可能改变可见内容，必须选择并测试安全顺序，不能仅靠接线完成验收。

## 验证矩阵

| 情形 | 断言 |
|---|---|
| Messages/Responses × native/转换上游 × 非流 | 首次客户端写前拦截；正文只改被检查的文本字段；阻断是合法错误；客户端字节、`Content-Length`、遥测一致。 |
| Ollama/Anthropic/缓存重放 | 非流 executor 不提前写；缓存不绕协议转换和拦截；错误体单独分类。 |
| 普通流/survival 流 × 两协议 | 跨 `Write` 的 SSE 完整帧只拦截一次；占位符与工具 delta 正确还原；无映射不跨租户恢复。 |
| 合规与链 | 首/中间拦截器改写向下游传递；敏感串跨帧、跨 lane 不泄漏；`ShouldBlock` 后无正文或 completed；流最终状态与 durable 一致。 |
| 边界 | 空 body、首轮无映射、超大帧、客户端取消、重试与 `-race`。 |

现有 `nonstream_response_test.go`、`response_interceptor_helpers_test.go` 覆盖部分 passthrough/SSE 拼帧；缺少两个原生 Handler 的真实预写联测和 outputcompliance 的协议字段回填测试。相关 F10 SSE parser 与 R76 stream `ShouldBlock` 必须与本方案一同验收。
