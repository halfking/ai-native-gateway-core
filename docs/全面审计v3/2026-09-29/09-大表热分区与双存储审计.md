## 1. 需求判据和方法

用户要求所有**大数据事实/事件表**具备 `hot（仅 8h，所有可变操作只在 hot）→ 分批确认 → columnar 历史分区 → 统一查询`。这是目标架构，当前代码的例外不是自动获准的验收豁免。需要先区分操作型状态表（可能需另设小型可变状态层）与不可变事件事实，避免把正在更新的月表直接切为 columnar。

本轮逐项核了 `bg/partition_manager.go:1217-1352` 的 ensure/archive/promote 注册和 `:1387-1533` 的跨实例锁、预算、事务；对照 `sql/migrations/startup` 与 `sql/schema/01-schema.sql`、应用写入 SQL、`storage/factory`；再以 `pg_inherits`、`pg_class.relam`、`pg_total_relation_size`、`information_schema` 和 `schema_migrations` 只读查询交叉验证本机实际状态。`pg_stat_user_tables.n_live_tup` 可能陈旧，故下表只报访问方法和大小，不以估算行数证明容量。

### 调度契约

- `promoteSpecs()` 登记 20 个 hot 表族（`bg/partition_manager.go:1322-1351`），默认每 1h 运行、周期 5min / 100 批，每表至少一批；批内事务有 advisory lock、RLS bypass 和 60s 超时（`:24-69`, `:1387-1533`）。**默认 8h 是 eligible cutoff，不是 hard deadline**：进程停摆、锁冲突、函数失败、积压可使行晚于 8h。必须用 `oldest_row_age_seconds`、过期行数和告警证明 SLO。
- 设置 `lifecycle.hot_retention_hours` 范围为 1–720h，而 `request_logs_bodies` 有独立默认 24h（`bg/partition_manager.go:1700-1719`、`settings/spec_lifecycle.go:7`）；本机该设置实值为 8h。用户的“只保留 8h”若是**固定上限**，现有可配 720h 与正文默认 24h 均不满足。
- `archiveSpecs()` 仅每月 1–3 日处理 routing/状态表/credential index（`bg/partition_manager.go:1300-1306`）；`request_logs` 摘要另外每日 03:xx 抽取（`:575-659`），而不是冷数据删除。

## 3. P1：`session_turn_details_hot` 冗余行永久留热

### 现象与根因

本机只读查询：`session_turn_details_hot` 20,085 行中 17,344 行年龄超过 8h，最老 2026-09-20；17,329 行已与 parent 共享 `(tenant_id,request_id,partition_date)`。本机 `lifecycle.hot_retention_hours=8`，函数存在，`promoteSpecs()` 已登记（`bg/partition_manager.go:1338`）。733 SQL 的 ensure/候选两处都用 `NOT EXISTS(parent)`（`733:331-357`），因此已回填至 parent 的 hot 行根本进不了 `moved/inserted`。虽然 `:369` 写 `ON CONFLICT ... DO UPDATE`，对这些行**不可达**。一小时跑多少次都不会清掉它们。

逐字段只读比对（17,329 对；排除身份列 `id`）：**没有任何 hot 非 NULL 与 parent 不同**；差异仅 6 列且方向全为 hot `NULL`、parent 非 NULL：`quality_fix_actions` 17,329，`request_type` 17,329，`stream_chunks_sent` 11,378，`quality_flags` 5,951，`protocol_conversion` 3,028，`request_class` 2,832。parent 当前是 hot 的信息超集。05:30 再用目录生成的逐列 typed `h.col IS NULL OR h.col IS NOT DISTINCT FROM p.col` 在 `BEGIN READ ONLY` 中复核，**17,329 对中冲突数仍为 0**；该方法可以区分 SQL `NULL` 和 JSON `null`，严于首轮 JSONB 展开。盲目解除 `NOT EXISTS` 并沿用 `DO UPDATE SET col=EXCLUDED.col` 会把这些 parent 已补齐的字段改回 NULL，**不能这样修**。

### 可执行修法（迁移 759）

1. 先在单条受事务保护的 SQL 中选出过期、与 parent 同键且“hot 所有非 NULL 字段逐字段等于 parent”的冗余行，锁 hot 行，按有界批次删除。跳过 `id`，由目录动态生成逐列 `(h.col IS NULL OR h.col IS NOT DISTINCT FROM p.col)`，保持 SQL `NULL`、JSON `null`、数组顺序的正确语义。
2. 对 parent 尚无键的 hot 行，改成 **先 INSERT parent，确认 RETURNING，再 DELETE 对应 hot**。并发回填/唯一冲突时不删除 hot，待下轮复检。停止 parent `DO UPDATE`，为未来列存不可变打基础。
3. 对 hot 非 NULL 与 parent 冲突的重复键，**保留 hot**。过期滞留行按 request key、session/turn key、id/date key、可搬/被锁四个互斥状态记录；需要确认源优先级后才能清除真实冲突。迁移代码不接触本机现有数据，执行期由正常调度器逐批迁移。
4. 验收：在独立 PG fixture 同时插入新键、parent 超集重复键、真实冲突键、未来时戳，首次/重跑比对所有字段与行数；在目标库发布前看 `schema_migrations`、函数定义和 8h 老行计数。

## 4. 聚合迟到写入的架构缺口

`domains/session/v2/session_aggregator.go:165-210` 先对 `session_turns` parent 的 `aggregate_applied_at` 做条件 UPDATE，再 fallback 更新 hot；这样才支持 promote 后迟到的 exactly-once 聚合。直接删 parent UPDATE 会使这类会话的成本/轮数汇总永久少算，不能作为“hot-only 修复”。目标设计：独立 durable claim（唯一 `(tenant_id, request_id, partition_date)`）与 session snapshot 同事务写；当前可变 claim 保留在 hot 状态表，过期后以不可变 claim 事件列存归档；跨冷热 claim 与 promote 之间用同一请求键锁或可证明的唯一仲裁，回放测试覆盖 8h 边界、并发与重启。后续再移除 parent UPDATE，并将 `sessions` 当前状态和历史快照拆开。**本轮不做猜测式改写**。

## 5. 双模式边界

`storage/factory/factory.go:1-5,177-262` 标称 full/lite 双模式，但 full 的 Session/Bodies/Turns/RequestLog/State Store 来自 `storage/factory/stubs.go:1-112`，全部返回 `ErrNotImplemented`；生产 full 在 `cmd/gateway` 直接组装 PG/Redis，不走该工厂。`cmd/gateway/storage_mode_init.go:143-146` 仅为 lite 返回 runtime，SQLite + 文件 + memory 有真实实现和 TTL/一致性 worker（`:173-276`）；因此当前不能以工厂的共同接口测试证明 PG/SQLite 语义对等。需要选一个权威 full 实现接入同一存储接口，再以相同请求序列回放覆盖会话/轮次/正文、重启、TTL、失败恢复；同时保持旧 full 路径到新路径的渐进对照。hotzone full 镜像接线 H2/H3 仍未落地（`storage_mode_init.go:286-295`）。

## 8. 759 实施与复审结果（2026-09-29，Asia/Shanghai）

- 新迁移 `sql/migrations/startup/759_session_turn_details_duplicate_drain.sql` 只 `CREATE OR REPLACE FUNCTION`，不在迁移阶段修改既有行；安装器 embed、runner、canonical 字节一致性测试、升级序列和有意重定义链均已登记。733 历史文件保持不变，759 必须晚于 733 生效。
- 函数一次调用最多移走 `p_batch_size` 行。重复键先用每个有类型列的 `IS NOT DISTINCT FROM` 比对（排除代理 `id`，允许 hot SQL `NULL` 由 parent 补充）；仅证明 parent 信息不弱于 hot 时清 hot。新键先 `INSERT parent ... ON CONFLICT DO NOTHING RETURNING`，仅在拿到返回键后删除 hot。候选过滤覆盖 parent 的 request key、session/turn key 和主键三种唯一冲突，避免固定冲突键排在批次首位使后续正常行永久饥饿。真正冲突保持原位，不写回 parent。
