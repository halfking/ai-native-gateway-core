# IR v3 类型、映射与存储设计（提案，2026-09-29）

本文件是待实现的内部契约；当前生产内容 IR 是 `internal/ir/types.go` 的 `InternalRequest`，会话状态和请求事件分属 `domains/session/v2` 与 `domains/requestjourney`。v3 不替换现有厂商 wire，也不在请求体里暴露审计字段。以版本化 envelope 串起三者，先双写/旁路比对，再迁移读端。

## 1. 分层与所有权

```text
客户端 wire ──原样捕获──▶ OriginalTurn（权限受控，append only）
      │                         │
      └─解析为 InternalRequest ──┼─▶ SanitizedTurn ──▶ CompressedTurn
                                │         │                   │
                                └─────────┴── ProvenanceMap ──┘
                                         │
                              EnvelopeV3 / attempt / usage
                                         │
                     PG 或 SQLite 权威元数据 + 文件正文；Redis/memory 加速
```

一个 `request_id` 标识一次客户端请求；一个逻辑 `turn_id` 可含多次上游 attempt 和压缩重试；`session_id` 标识多轮会话，`task_id` 可跨多个 session。`turn_no` 是会话内原始顺序，`total_turns` 是观测到的总轮数快照，不能用重试次数代替。原始正文和媒体由受控 body store 保存，envelope 只存引用、哈希和可公开摘要；凭据仅存内部 ID，绝不存明文密钥。

## 2. 建议类型（说明性 Go 结构，尚未落地）

```go
type EnvelopeV3 struct {
    SchemaVersion uint16             `json:"schema_version"` // 固定 3
    Identity      RequestIdentity    `json:"identity"`
    Wire          WireContract       `json:"wire"`
    Turn          TurnRecord         `json:"turn"`
    Provenance    ProvenanceV3       `json:"provenance"`
    Dispatch      DispatchTrace      `json:"dispatch"`
    Usage         UsageLedger        `json:"usage"`
    Lifecycle     Lifecycle          `json:"lifecycle"`
}
type RequestIdentity struct {
    TenantID, ProjectID, UserID, APIKeyID, TaskID string
    SessionID, TurnID, RequestID                   string
    TurnNo, TotalTurns                              uint64
    Tags                                            []string
    ClientType                                      string
    CreatedAt                                       time.Time // UTC
}
type WireContract struct {
    SourceProtocol, TargetProtocol string // chat/messages/responses/gemini/…
    IsStream                       bool
    RequestedModel, EffectiveModel string
    ProviderID, CredentialID       string
    ProtocolDecisionID             string
    VendorExtensions              []VendorExtension
}
type VendorExtension struct {
    SourceProtocol, TargetProtocol, FieldPath string
    ValueRef, ValueHash                    string // 可逆值存受控 TTL 存储
    ExpiresAt                               time.Time
    PolicyVersion                           string // allow / reject / metadata-only
}
type TurnRecord struct {
    OriginalBodyRef, OriginalBodyHash string
    Messages                          []MessageRef
    Summary                           HumanSummary
}
type MessageRef struct {
    Identity, Role string
    Occurrence     uint32
    Blocks         []BlockRef
}
type BlockRef struct {
    Identity, Kind, Path string // text/tool/image/audio/document/…
    Occurrence           uint32
    BodyRef, BodyHash    string
    Media               *MediaRef
}
type MediaRef struct {
    AttachmentID, MIME, SHA256 string
    Version, ByteSize          uint64
    SourceRef, DerivedRef      string
    RetentionUntil             time.Time
}
type HumanSummary struct {
    Text, Method, ModelVersion string // 去格式、去敏感值，便于人看
    SourceTurnIDs              []string
    GeneratedAt                time.Time
}
type ProvenanceV3 struct {
    OriginalRef, SanitizedRef, CompressedRef string
    SanitizedMessageRefs                    []SanitizedMessageRefV3
    AlignmentMap                            []AlignmentEdge
    PlaceholderMapRef                       string
    PolicyVersion, ContentVersion           string
}
type SanitizedMessageRefV3 struct {
    MessageIdentity string
    Occurrence      uint32
    BlockPath       string // 顶层 system/instructions 也须有合成路径
    RawHash, SanitizedHash string
}
type AlignmentEdge struct {
    SourceLayer, SourceIdentity, SourcePath string
    SourceOccurrence                        uint32
    TargetLayer, TargetIdentity, TargetPath string
    TargetOccurrence                        uint32
    TransformID, TransformVersion           string
}
type DispatchTrace struct {
    QueuedAt, DequeuedAt time.Time
    QueueLane, RoutePolicyVersion string
    CandidateSnapshotRef, WaterfallRef string
    Attempts []AttemptRecord
}
type AttemptRecord struct {
    AttemptID, ProviderID, CredentialID, Model, Protocol string
    StartedAt, FirstByteAt, EndedAt time.Time
    HTTPStatus, ErrorClass, RetryReason, WindowSource string
    CompressionRef, UpstreamUsageRef string
}
type UsageLedger struct {
    Source, Confidence, PriceVersion, Currency string
    InputTokens, OutputTokens, CacheReadTokens, CacheWriteTokens uint64
    InternalAmountMinor, ProviderAmountMinor int64
    ReconciliationStatus string
}
type Lifecycle struct {
    Status, TerminalReason, EncryptionKeyVersion string
    UpdatedAt, RetentionUntil time.Time
}
```

类型草图中字符串 ID 是为跨 PG/SQLite/文件日志统一序列化；实际 Go 实现可保留现有整数 DB ID，但序列化边界要规范一次。金额使用最小单位或定点 decimal，不用 float；token/字节和时间计算用溢出检查。`Tags` 去重、排序及上限由入口统一校验，保持原始标签另有引用。`CreatedAt`/`UpdatedAt` 使用 UTC，展示端按用户时区换算。未知字段分“可跨协议表达/仅元数据/拒绝”，过期后不能从缓存或队列恢复到上游请求。

## 3. 三层 identity / occurrence 不变量

1. 同一轮原始 message/block 的 identity 在重试、脱敏、压缩中不变；同一内容重复出现以 occurrence 区分，不以正文哈希当唯一 ID。
2. 每条转换边包含源层、目标层、位置、版本和变换 ID。被压缩删除的 block 记录显式 tombstone；合并摘要记录多对一来源，不虚构一对一映射。
3. `SanitizedMessageRefs` 覆盖 Chat `messages[]`、Messages 顶层 `system`、Responses 顶层 `instructions`、字符串 `input`、工具结果和文本 block。现有入站修复只对 `messages[]/input[]` 建 refs，顶层字段仍是本轮开放项。
4. 占位符 offset 按 `(tenant_id, session_id, sensitive_type)` 原子预占；映射引用和 offset 的持久化要同一个成功边界。还原先查租户与会话所有权，再在**客户端可见层**按原协议字段恢复；无映射或过期不得猜测。
5. 原始请求、脱敏派生与压缩派生的哈希分别计算；日志只存引用/允许摘要。每一轮通过 `raw_hash → sanitized_hash → compressed_hash` 双向查询和数量守恒测试；附件以独立 SHA256/版本校验。

## 4. 队列、存储与升级

| 介质 | 建议保存 | 一致性和清理 |
|---|---|---|
| 请求内存 | 当前 `EnvelopeV3`、候选快照、短时变换 buffer | 请求取消释放；有总字节和 goroutine 上限。 |
| 调度/遥测队列 | `request_id/attempt_id`、租户、版本、body ref、过期时间 | 不传原文/凭据；重放以幂等键 `(request_id, attempt_id, event_kind)` 去重。 |
| Redis | TTL 参数扩展、sanitizer map/offset、会话热点与限流 | key 带租户+版本；映射与 offset 原子提交，故障按安全策略停止外发。 |
| 文件 | 加密或受控的原始正文、媒体、可重建派生物 | 原件 append only/版本化；写临时文件→fsync→原子 rename→DB 引用；孤儿 GC 可重试。热区清理只碰衍生文件。 |
| PG full / SQLite lite | 权威 identity、轮次、attempt、账本、provenance 元数据 | 两种模式同一 schema version 和查询语义；PG 大表 hot 8h 后幂等迁移至 columnar；更新/删除仅 hot，历史更正以补偿记录。 |

升级次序：先定义可读 v3 schema 与旧字段映射；以 shadow writer 双写且只读旧数据；在合成与历史样本上逐层对账；再选择新读路径；最后按保留期清理旧列/缓存。任一步能回退读端，但不得删除已写原始轮次。每个阶段产出 full/lite、重启、跨副本、流/非流的验证记录。相关执行批次为 `03-执行方案与进度.md` 的 D/E；审计断言见 `05-可执行审计检测矩阵.md`。
