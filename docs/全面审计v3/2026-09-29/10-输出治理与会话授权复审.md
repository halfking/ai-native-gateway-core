> 基线：本批开始时本地 `main=origin/main=ed70cb5a9147512101a042f9ff04a2b554547ca7`，此前 F01–F12 审计冻结于 `d141c8036bae77f5f25427e58eaf04b7bb9fed63`。本文件只登记本次代码和隔离测试证据；未把测试实例当作生产验收。

## 1. 客户端响应的唯一安全边界

目标链路为：上游字节 → 客户端协议转换 → 会话占位符还原/未知值遮蔽 → 按客户端可见文本字段做合规检测 → 计算最终 body/事件及长度 → 客户端写入与 durable capture → 失败或成功审计。每一步应使用当前请求已认证的租户、API key、会话 ID 和调用者 owner。审计/goal 可以读取 sanitized 原文，但不得作为客户端字节的放行凭据。

旧链把 `sanitize_restore` 放在 output compliance 之后，合规检查过的占位符还会变成明文。旧 Messages/Responses 非流式 Handler 自己写成功 JSON，普通流未接 response interceptor；Chat 非流式 executor 也先于 hook 写入。因此只在 `InterceptStreamEnd` 或日志里改 `ResponseBody`，不能证明客户端安全。

## 3. 数据所有权和并发契约

`CallerOwner` 是本次请求的认证事实，不能从 request ID、最近日志或会话历史反推。`session_dim.owner_user` 是数据 owner，查询失败或不存在时取空值，`owner_mismatch` 模式下脱敏。此规则与会话访问控制互补：先拒绝不属于当前 key/tenant 的会话，再决定已授权响应的可见文本。原生 Handler 的认证/会话校验在任何 provider dispatch、sanitize map 读取或输出恢复前完成。

SSE 每个事件可含多个字段或候选。所有跨帧状态按 stream writer 生命周期保存，不用全局 session map；解析失败、状态超额或合规检查失败时终止本请求，禁止后续 `completed` 或正文透传。正文待验缓存需要全局并发容量/延迟基准和可取消释放测试；仅有单请求 64 KiB/其他上限不能证明生产大响应体验。历史签名 thinking、JSON 参数片段、binary media 必须分开处理；不得以字符串正则扫描整份 JSON 代替字段级协议检查。

旧 Chat D5 外层模型 fallback 分支还有布尔条件互斥的结构：`dispatchModelAlternativesConsumed := dispatchAllowModelChange`，但分支同时要求 `!dispatchModelAlternativesConsumed` 与 `dispatchAllowModelChangeEnabled()`。本批给该分支保留抑制预写的防御参数，正式清理前需先冻结产品上可达的 fallback 语义，不为不可达条件制造伪联测。
