# 推理方言与型号能力复审（2026-09-29）

## 范围和证据

本复审承接并行主分支的《24 小时内修订审计·二十一轮》N21-1/N21-2。输入是 OpenAI Chat 的 `reasoning_effort`、IR 的 `ReasoningConfig`/原生 `ThinkingConfig`，输出是 Anthropic Messages 或 Gemini `generateContent` 请求。原缺陷可复现：`disabled` 在 Anthropic 被发成 `enabled` 加 8192 token，在 Gemini 被静默丢弃。此处的单测只证明本仓序列化结果；尚未向付费供应商验证全部型号。

| 客户端关闭意图 | 本批已落地的出站语义 | 不能保证的部分 |
|---|---|---|
| Anthropic，已知允许禁用的型号 | 显式 `thinking.type=disabled`，不带预算。原生 `Thinking` 优先于跨协议 `Reasoning`。 | 未枚举所有未来型号的支持矩阵。 |
| Claude Opus 5.5 | 省略供应商拒绝的 `thinking.type=disabled`，写 `ir_protocol_loss`，携带型号、源协议、请求 ID 和 `unsupported` 原因。 | 客户端禁用意图无法满足；省略只维持请求可用性，需在用户可见能力反馈中表达语义损失。其它新版 Claude 的手工预算尚未门控。 |
| Gemini 2.5 Flash / Flash Lite | 显式 `thinkingConfig.thinkingBudget=0`，不设置 `includeThoughts`。 | 厂商可能按新型号改变能力，需更新注册表和回归。 |
| Gemini 2.5 Pro、Gemini 3、未知别名 | 省略非法或未确认的 `thinkingBudget=0`，写 `ir_protocol_loss`；内置 2.5 Pro/未知 2.5 变体 `CanDisable=false`。 | 关闭意图无法满足；Gemini 3 的非禁用预算仍按旧 `thinkingBudget` 格式输出，需适配 `thinkingLevel`。 |

冲突字段按 **显式 Type → 显式 BudgetTokens → Effort** 裁决；显式正预算胜过 `disabled` 字符串，显式零预算要求禁用。序列化器的型号门依据供应商文档只覆盖确认家族，不能把不认识的型号猜成支持。来源：[Gemini thinking 文档](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[Claude Opus 5.5 迁移文档](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide)、[Claude 新型号说明](https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-6)。
