## 一、P2-3 架构误判结论（深度验证后撤回）

### 验证过程
1. **定位 responses→chat 转换真实路径**：executor_chat.go:3156-3183，ParseResponses(sourceBody) → SerializeOpenAI
2. **确认 trim 所在分支**：executor_chat.go:1019 CompressResponsesInput 只在 `nativePair=true` 分支
3. **验证分支隔离**：responses→chat 走 `nativePair=false` 分支（1031 行），**拿未 trim 的 sourceBody**
4. **检查 sessioncontext 保护**：protected.go:76-123 保护首条/最新 human user

### 三层架构事实（证伪依据）
| 层级 | 事实 | 对零 user 的影响 |
|---|---|---|
| **executor trim vs 转换** | nativePair 判定产生**互斥分支**：trim（1019）只在原生上游分支；转换（3156）走另一分支，拿未 trim 的 sourceBody | ❌ 两者不在同一路径 |
| **sessioncontext Reduce** | protectInfo 保护首条 human user（85-93 行）+ 最新 human user + 工具链闭包 | ❌ 至少保留一条 user |
| **responses trim 作用域** | trim 只对 responses 原生上游生效，零 user 约束是上游自己的规范 | ✅ 可能产出零 user，但不影响转换路径 |

### 结论
**P2-3 是架构误判**。「trim 产出零 user，转 chat 上游时触发」的场景**不可能发生**——两者分属 nativePair 判定的互斥分支。首版 trim 层守卫被 KeepFunctionCallPairAtomic 抓红是正确的（trim 层零 user 是合法契约），但该契约不适用于转换层因为两者根本不在同一路径。

## 二、P2-2 分析档完成（IR 统一化推荐）

### 问题确认
`/v1/completions` 的 `prompt` 字段与 `/v1/responses` 的 `input` 字段支持 **string 形态**（协议合法），但 LargeIngress sessioncontext 的缩减路径（file.go / fit.go）只认**数组形态**，string 形态被 `ErrProtectedContext` 拒绝 ⇒ 1.2MB 纯文本 prompt 必 422。

### 三条可行路径（分析档完成）
| 路径 | 改动点 | 优点 | 缺点 |
|---|---|---|---|
| **A. 数组包装**（file.go/fit.go） | 检测 string 形态时自动包装为单元素数组 | 改动集中，复用现有缩减逻辑 | prompt 字段不在通用键集合（completions 特有） |
| **B. plainText 摘要**（file.go） | 对 string 直接调 sampleText 生成摘要 | 不依赖数组结构，逻辑最简 | 丢失 message-level protected 判定 |
| **C. IR 统一化**（推荐） | parse_openai.go / parse_responses.go 把 string 统一转内部数组 | 下游无感知，关注点分离，扩展性强 | IR 层改动，需确认 serialize 是否还原 |

### 推荐方案（路径 C）
**IR 层标准化** + sessioncontext 保持现状：
1. ParseOpenAI / ParseResponses 对 string input/prompt 自动包装为单条 user message
2. InternalRequest.Messages 始终是数组（下游缩减逻辑不变）
3. SerializeOpenAI / SerializeResponses 可选还原回 string（若目标上游偏好）

**理由**：IR 是协议适配层（外部多样性→内部统一）；sessioncontext 是缩减层（只处理统一数据模型）；未来其他端点引入 string 形态只需在 parse 层统一处理。

### 实施前置（待核实）
1. IR 层是否已统一 prompt 字段（completions 的 prompt 映射）
2. 目标上游对 string 的依赖（是否有上游只认 string 不认数组）
3. IR 数组化的副作用（tool chain 判定、modality 分类）
