## 二、最有价值的三个发现

### ① 一行注释拆分 = 全仓前端构建链断裂（P1，主控首查即中）
`web/src/locales/de-DE/common.ts:300-301`：基线上完整一行的注释（含乱码但语法合法）被合并笔 c6bf29aea 的「locale 并集」解析拆成两行且第二行丢 `//` ⇒ de-DE 语言包整模块编译失败。首跑全量 vitest **13 文件/32 红**，全部 i18n 门禁族 + 4 个测试套件被这一个文件的 import 失败级联放倒；`pnpm build` 链断 ⇒ **当前 main 无法出前端产物**。
⇒ ★ **通用式：locale 合并是「语法级」操作不是「文本级」操作——并集解析后必须跑一次 esbuild/构建级验证；一个文件坏 = 全族假红，归因时先找「第一个 SyntaxError」而不是逐用例排查。**

### ② JS 对象重复键「后值覆盖」把好翻译吃掉（P2，棘轮是显微镜）
合并注入的**未翻译重复键**（与 en/zh 逐字相同）排在既有好翻译**之后**（fr 'Opérations'→'Actions'、ja '軽微'→'低'、zh-TW '等待分析'→'待分析'）——运行时静默降级为原文，唯一可见信号是 localeValueQuality 棘轮 +3/+7/+9。
⇒ ★ **通用式：棘轮是「质量漂移的显微镜」——它红的往往不是新缺陷本身，而是「覆盖了既有资产」的静默回归；差集必须对基线树逐键算（baseline JSON 只存计数，不存键集）。**

### ③ 交付面缺口的「通道差」是系统性的（A/E 路）
995 迁移九面齐但缺**离线升级通道**第三副本（installer/migrations/，offline_apply.go 消费）；MaaS 10 端点接了 gin 版+echo 版**两套**却零消费者；modelbudget 闸门只进 serveWithExecutor 一面。三个缺口同型：**每一代作者按「自己那轮的通道」登记，通道清单没有 SSOT**。
⇒ ★ **通用式：迁移/端点的「登记面清单」要按通道枚举并钉测化（995 第⑩面已钉），新交付先问「这个产物有几个消费通道，每个通道能不能拿到它」。**

## 七、本轮沉淀通用式（6 条）

1. **locale 合并是语法级操作**——并集解析后必须构建级验证；一个文件坏=全族假红。
2. **棘轮是质量漂移的显微镜**；差集对基线树逐键算（baseline JSON 只有计数）。
3. **登记面按通道枚举并钉测化**——「这个产物有几个消费通道，每个通道能不能拿到它」。
4. **JS 对象重复键后值覆盖**——locale 文件合并后 grep 重复键（同键双行）应成为交付门。
5. **「实现完成 ≠ 交付完成」是本轮最重的系统性缺口**（MaaS/统计/modelbudget 三处同型）——验收问题从「写完没」改为「谁消费它」。
6. **unhandled rejection 的家族形态**（`data?.x.length`）一旦出现必扫同文件同形态——L11 三处三列三修。
