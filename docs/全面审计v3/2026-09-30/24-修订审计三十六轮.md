## 二、主审发现与修复（预存在红，Windows 实证）

### R36-B1（P2/Windows）：AsyncFileWriter 裸 rename 并发替换同目标报 ACCESS_DENIED

`storage/file/async_writer.go` `writeAtomic` 的裸 `os.Rename` 在 Windows 上多 worker 并发覆盖写同一路径时得 ACCESS_DENIED（POSIX 原子替换语义在 Windows 不成立）。实证：`TestConcurrentWritesSamePath`（8 writer×50 写）连续红，`total_writes=93 want 400, failed_writes=7`；单跑 Async 用例不触发（模式盲区）。消费方含 FileBodiesStore、RequestMirror（hotzone requests 子树）与 lite/hotzone session_bodies——**Linux 生产不受影响，Windows 开发机必红**。

### R36-B2（P2/Windows 同类）：FileCache Set rename 与 Delete/removeExpired 四处 `os.Remove` 共享冲突

`domains/session/v2/cache_v2_file.go`：Set 的裸 rename 同 B1；Delete/evict/removeExpired/removeIfUnchanged 的 `os.Remove` 与并发读者（Get 的 os.ReadFile，Go 打开不带 FILE_SHARE_DELETE）冲突报 "being used by another process"。实证：stash 双向验证——HEAD 干净树下 `TestFileCacheConcurrentAccess`/`TestFileCacheIndexConsistency` 即红（含 rename ACCESS_DENIED），属**预存在红**非本轮引入。

### 修复方案：`internal/atomicrename` 共享包（两平台 build-tag 拆分）

- `Replace(tmp, final)`：Windows 对瞬态 `ERROR_ACCESS_DENIED(5)`/`ERROR_SHARING_VIOLATION(32)` 有界退避重试（10 次 ≈1.9s——短预算 190ms 在杀软扫描窗口下实测仍漏，连续 6 次压力复现实证后扩）；非 Windows 直通 `os.Rename`。
- `Remove(path)`：同瞬态重试 + 不存在归一 nil（幂等，POSIX unlink-while-open 对齐）。
- 接线：`async_writer.go` rename 一处；`cache_v2_file.go` rename 一处 + remove 四处（tmp 清理的 best-effort `_ = os.Remove` 不动）。
- 新增 ADR-0019 依赖方向合法（domains→internal 先例 internal/redis、internal/ir）。
- 测试：`rename_test.go` 三用例（覆盖/并发同目标/幂等删除），`-race` 绿；扩预算后连续 6 次 100% 绿。
