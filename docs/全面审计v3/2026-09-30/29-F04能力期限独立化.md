# 四十五轮：F04 能力期限独立化

## 范围与基线

- 日期：2026-09-30
- 基线：`545bf0a3d3809e42a99f72cadc52d59af81143bf`
- 工作分支：`codex/f10-sse-frame`
- 缺陷：F04 capability verdict 和 NodeState health 共用 Redis key TTL。普通健康请求不断刷新 NodeState 时，旧的 unsupported verdict 可能被无限续命，延后 native Responses 重测。

## 修复

- `NodeState` 增加 `CapabilityExpiresAt`，协议能力 verdict 使用独立 3600 秒期限。
- capability Lua 写入时读取 Redis `TIME`，用服务端时钟计算 `CapabilityExpiresAt`；避免不同应用实例时钟偏差影响期限。
- 健康状态 Lua 继续刷新 NodeState key TTL，但不会更改 `CapabilityExpiresAt`。
- 读端遇到独立期限已过、字段缺失或旧 JSON 格式时返回 unknown，让 executor 回到实时检测路径。
- 原生 Responses 完整成功才写 positive verdict；Chat fallback 成功不作为 Responses 正向能力证据。

## 回归证据

- `TestF04_CapabilityExpiryIsIndependentFromRefreshingNodeHealth`：先记录 negative verdict，再刷新健康状态；NodeState key 仍存在、能力到期值未被重写。即使健康 key 仍活跃，已过期 verdict 也读取为 unknown。
- `TestF04_LegacyCapabilityWithoutExpiryReadsAsUnknown`：预置无 `capability_expires_at` 的旧 payload，确认不会将旧 verdict 视作永久有效。
- `TestF04_LiveSuccessfulResponsesPersistsSupportedVerdict`：保持 NodeState key 存在，仅让能力期限过期，再通过 executor 运行真实 native Responses 成功路径并确认 positive verdict。
- 聚焦用例已通过：`go test ./credentialfpslot -run '^TestF04_(CapabilityExpiryIsIndependentFromRefreshingNodeHealth|LegacyCapabilityWithoutExpiryReadsAsUnknown)$' -count=1` 与 `go test ./domains/streaming/executors -run '^TestF04_LiveSuccessfulResponsesPersistsSupportedVerdict$' -count=1`。
- 全量改动包与邻接包通过：`go test ./credentialfpslot ./domains/streaming/executors -count=1 -timeout=240s`、`go test ./bg -count=1 -timeout=240s`。
- race 通过：`go test -race ./credentialfpslot ./domains/streaming/executors -count=1 -timeout=360s`。
- 静态构建检查通过：`go build ./...`、`go vet ./bg ./domains/streaming/executors ./credentialfpslot`、`git diff --check`；Go 文件 `gofmt -l` 无输出。
