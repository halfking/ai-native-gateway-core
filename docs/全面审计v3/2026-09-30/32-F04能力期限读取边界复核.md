# 四十八轮：F04 能力期限读取边界复核

## 复核问题

四十七轮把 `GetSupportsResponses` 分两步执行 `GET NodeState` 和 `TIME` 登记为可能在 expiry 边界返回陈旧 verdict，并建议改成 Lua 原子读。本轮先验证这个风险是否成立。

## 可控时序

- 新增 `TestF04_CapabilityReadRechecksRedisTimeAfterStateFetch`。
- miniredis 的服务端时间先设为 `t0`，能力 verdict 到期时间设为 `t0+1s`。
- Redis client hook 在 `GET` 已读取 NodeState 后，将 miniredis 的服务端时间推进至 `t0+2s`；随后原实现执行 Redis `TIME`。

## 结论

测试观测到 `GetSupportsResponses` 返回 unknown，而非过期之前读到的 negative verdict。因为过期判断读取的 Redis 时间晚于 NodeState GET，恰好在两条命令之间跨越期限会被检测出来。GET 时读取的能力值本身是该 Redis 操作时刻的快照；若 verdict 在读取后被并发更新，返回旧快照仍可线性化在 GET 之前，并不构成能力归属错误。

因此撤回“GET/TIME 分离必然导致返回过期 verdict”的误报，暂不增加 Lua 原子读取路径。

## 验证

- `go test ./credentialfpslot -run '^TestF04_CapabilityReadRechecksRedisTimeAfterStateFetch$' -count=1 -timeout=60s`，通过。
- `go test ./credentialfpslot -count=1 -timeout=240s`，通过。
- `go test -race ./credentialfpslot -run '^TestF04_CapabilityReadRechecksRedisTimeAfterStateFetch$' -count=1 -timeout=120s`，通过。
