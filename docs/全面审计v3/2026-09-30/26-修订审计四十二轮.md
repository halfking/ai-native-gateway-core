- **范围**：V3-F02、V3-F10。本轮只记录代码与本地回归证据；真实客户端、供应商、PG/Redis 与部署验收维持开放。

## 1. 复现与修复

1. **策略拦截后的 handler 状态**：Messages/Responses 的流结束路径原先只在 defer 中 flush writer；通用 `execErr` 分支先于 flush 读取不到最终 block 状态，可能追加 provider error 或错误归因。两个 native handler 现在在 executor/coordinator 返回后幂等 finish，再于通用错误/成功分支前判断 `OutputPolicyBlocked`。策略阻断记一条 `output_policy_blocked` 失败、审计 success=false，并跳过通用错误写入；writer 发出的 Messages `error` / Responses `response.failed` 终态唯一。Survival terminal callback 同样在策略已 block 时不再写终态。
2. **还原后再检查**：SmartSaniGuard 的 restore interceptor 改为插到 output compliance 之前。新增组装顺序回归和真实恢复→合规→客户端 wire 测试，检查器现在看到真实恢复文本，而不是 `{SENSITIVE:...}` 占位符。
3. **共享 SSE parser**：新增 `internal/sse` data-field 解析/重写与帧边界 helper。支持 `data:` 与 `data: `、多条 data 的 LF join、LF/CRLF/CR/混合空行分隔、跨 `Write` 的 delimiter 以及 EOF trailing CR。sanitize restore、output compliance、native intercepting writer 复用该实现；未知/转义 reserved marker 的 fail-closed 检查沿用 origin/main 既有逻辑。
4. **执行器中断归因**：向 first-semantic writer 暴露 output-policy block 状态；Chat stream outcome 与 dispatch error 保留 typed policy interruption，避免重试/遥测把策略 block 归成普通 provider failure。网关策略 block 不写供应商 circuit/credential failure；普通流端到端测试断言该 provider 的断路器 failure counter 不增长。

## 2. 证据与验证

- `TestNativeNormalStreamBlockWritesOneProtocolTerminalAndFailure`：Messages/Responses 普通流经过真实 HTTP 上游和协议 bridge；断言无 provider 内容泄漏、无第二 provider 错误终态、只一条带 provider/credential 归因的 `output_policy_blocked` failure，且供应商断路器不因网关策略而累加。
- `TestNativeSurvivalStreamBlockWritesOneProtocolTerminalAndFailure`：Messages/Responses survival 流断言单一 native failure terminal 与单条失败审计。
- `TestRestoredSensitiveFrameIsHeldUntilRealOutputComplianceApproval`：Chat/Messages/Responses 的真实 sanitizer Redis fixture + checker，断言原文被恢复后仍须通过 output-compliance 才能释放。
- `TestInterceptingWriterFramesAllSSELineEndingVariants` 与 `internal/sse` tests：CR/LF 变体、混合 framing、delimiter 分片、data 多行解析与重写。
- 验证通过：
  - `go test ./internal/sse ./security/sanitize ./domains/hooks/outputcompliance ./domains/streaming ./cmd/gateway -count=1 -timeout=300s`
  - `go test -race ./internal/sse ./security/sanitize ./domains/hooks/outputcompliance ./domains/streaming -count=1 -timeout=360s`
  - `go build ./...`
  - `go vet ./internal/sse ./security/sanitize ./domains/hooks/outputcompliance ./domains/streaming ./cmd/gateway`
  - 改动 Go 文件 gofmt；`git diff --check`

这些结果证明受影响的本地 Go 包和协议字节回归通过，不证明真实 Messages/Responses SDK 会按预期展示/消费终态，也不证明生产级 durable stream、Redis/PG 或收费供应商的完整行为。
