# 四十九轮：F04 多路径探针能力反馈统一

## 目标与证据范围

前几轮已完成业务请求的 capability 回写、V2 探针调用级 verdict 隔离、独立 TTL 和管理健康重置保留能力。本轮沿生产调用链复核仍在运行的三类 Responses 探测：`NodeProbeWorker.probeDirect`、`ActiveProbeExecutor.Run` 与 `ModelProbeRunner` 的 Featured Layer 4 (`probeWithRetry`)。它们都能确定原生 endpoint、credential ID 和 raw model，但之前只影响健康/可用性结论，没有更新 `credentialfpslot` 的协议能力状态。

## 修复

- 增加 `ResponsesCapabilitySink` 写入接口，直接复用 `credentialfpslot.Manager.SetSupportsResponses`，由该 Manager 继续负责 Redis 原子写入和 `CapabilityExpiresAt` TTL。
- NodeProbe 与 ActiveProbeExecutor 只对原生 Responses 2xx 记 positive；只有 `ResponsesUnsupportedError` 明确命中时记 negative。401/403、限流、网络错误和其它 4xx/5xx 均无能力 verdict。
- `probe_http.singleResponsesPing` 暴露相同的三态证据；Chat fallback 成功时保留原 Responses negative，不把 Chat 可用误写成 Responses 可用。
- `ModelProbeRunner` 在 Featured Layer 4 调用结束后写回 `(credentialID, rawModel)`；ActiveProbeWorker、队列 executor、两种 NodeProbeWorker 主程序接线与 ModelProbeRunner 均接到同一个 `fpSlots`。
- sink 写入错误只记录 credential/model 与错误，不改变探针原有健康处理。真实 Redis 不可用时能力状态可能暂时保持旧值，因此运行环境门仍必须验收。

## 回归与验证

- 新增 ActiveProbeExecutor native success / unsupported 后 Chat fallback 写回断言。
- 新增 NodeProbe direct Responses success 与 unsupported→Chat fallback 流程测试，并检查持久写入使用 raw model。
- 新增 ModelProbe Featured 结果的 capability sink 写回测试；`probeWithRetry` wire/fallback 测试断言正负 verdict 不受 fallback 状态影响。
- RED 证据：仅测试提交 `56bd029ab` 时，定向用例因缺少 `supportsResponses` 字段与 sink setter 编译失败；实现后同一组定向用例通过。
- 通过：`go test ./bg ./credentialfpslot -count=1 -timeout=360s`、`go test -race ./bg ./credentialfpslot -count=1 -timeout=480s`、`go build ./...`、`go vet ./bg ./credentialfpslot ./cmd/gateway`、`git diff --check`。

## 保持开放

此轮只闭合本地进程内已识别的探针 writer 接线。真实 PG/Redis 多进程和 Redis Cluster、Redis 写失败/恢复、部署、真实供应商 Responses/Chat 双协议及真实客户端行为仍未验证；D09 的模型绑定恢复 SQL 也仍缺真 PG 证据。因此 F04/D09 域级验收继续开放。
