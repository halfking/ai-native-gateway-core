## 修复

### D09：避免 sibling 探活重开模型级 404/410

凭据级探测成功只证明该凭据可达，不足以证明它下的每个模型都可用。`restoreAllBindingsOnCredentialSuccess` 现在在 `credential_model_bindings` 与 `model_offers` 恢复谓词中排除 `auto_model_not_found` 和 `auto_model_deprecated`。`restoreBindingOnProbeSuccess` 仍按 `provider_models.raw_model_name = $2` 精确限定模型，并允许该模型的后续成功探测清除 `auto_probe_model_binding`、`auto_model_not_found`、`auto_model_deprecated`。`model_offers` 是 `credential_model_bindings` 的视图；精确模型绑定变更由视图读取时反映。

回归测试覆盖：

- 凭据级恢复谓词在 CMB 和 view 更新两侧都保留 404/410 原因。
- 同模型恢复需同时满足 raw model 条件与明确原因白名单。
- 既有守卫同步更新到新的精确模型原因集合。

这些 D09 测试是源代码谓词合同，不会执行 SQL；隔离 PostgreSQL 的行级行为与锁/并发语义仍未验证。

### F04：live Responses 结果写回能力记录

`executeOpenAI` 在发现精确的 `ResponsesUnsupportedError` 时，按候选 credential 与 raw model 写入 `supports_responses=false`，即使当前 Handler 不允许安全 Chat fallback，也保存这条协议证据。仅当原生 Responses 的完整成功路径调用 `recordAttemptSuccess` 时写入 `true`；Chat fallback 成功不会翻转 negative verdict。Redis 写入脱离客户端取消并有 2 秒超时，写失败只记录 warning，不让观测存储故障阻断本请求。

同步更正 [F04 设计提案 §3.4/§4](../2026-09-29/12-F04持久化协议能力设计.md)：Chat 可用不代表 Responses 可用，positive verdict 必须由同一模型的 native Responses 成功响应提供。

新增 executor + miniredis 行为验证：

1. 首次 Responses unsupported 后本请求转 Chat，Redis 持久记录 `(credential, model) → false`；后续请求直接 Chat，不再触发 `/responses`。
2. 完整 native Responses 成功记录 `true`。
3. 等 Redis node-state TTL 过期后，native success 将预置的旧 `false`（随 node-state 一同过期）对应的新鲜请求写成 `true`；后续 Chat fallback 不会覆盖 `false`。

## 仍开放

- F04 的 `node_probe`、`probe_http`、`active_probe_executor` 等其它探针结果仍未统一写入同一 capability 状态模块。
- D09 绑定恢复目前仍在 `CredentialProbeV2` 中直接更新状态表/视图；统一状态写入面要求尚未闭合，本轮只修复错误的恢复范围。
- capability 与 node-health 共用 Redis key TTL；普通健康写可能续期能力结论，TTL 独立语义仍未落地。
- durable negative 命中时 executor 会跳过 Responses，所以它不能靠同一路 live 请求立刻自愈；当前测试模拟 node-state key 过期后重新尝试并由 native success 写 positive。若健康流量持续续期整键，过期重测仍可能延迟，这项与独立 capability TTL 一起保持开放。
- `CredentialProbeV2` 的共享单槽 verdict 和跨调用并发错配仍开放；本轮 live writer 没有重构所有探针的 invocation-scoped 状态传递。
- D09 SQL 谓词未在真 PG 执行；F04 未跑真实多进程 Redis、Redis Cluster、部署栈或供应商验证。
- D09/F04 域级验收门保持开放。本轮仅关闭上述本地代码回归覆盖的子项。
