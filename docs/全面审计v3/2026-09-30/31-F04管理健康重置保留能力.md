# 四十七轮：F04 管理健康重置保留能力

## 范围与证据

- 日期：2026-09-30
- 基线：`d40787ec2b858f5a215755b0039348a082e0b2bb`
- 路径：`admin/routing.resetInMemoryNodeState` → `credentialfpslot.Manager` → Redis NodeState。
- `force_enable` 与 `clear_circuit` 会重置路由健康状态。旧路径把仅含 credential/model 的零值 `NodeState` 交给 `SetNodeState`，整体覆盖 Redis JSON，也删除了 capability verdict 和 `CapabilityExpiresAt`。已知 Responses unsupported 的模型会重新尝试原生 `/responses`，产生可避免的失败。
- 红测：`TestF04_ResetNodeHealthPreservesCapabilityVerdict` 先因新的 reset API 不存在而无法编译；管理入口集成回归 `TestResetInMemoryNodeStatePreservesResponsesCapability` 在旧路径下运行失败，观测到 `known=false`。测试检查点：`c7df8bcbf`、`1081e7cbf`。

## 修复

- 新增 `Manager.ResetNodeHealthState`，通过 Redis Lua 原子执行。脚本清除 cooldown、失败/成功计数、最近时间戳、禁用原因和滑窗，将节点恢复为可路由状态。
- 有效 capability 子树及 `capability_updated_at`、`capability_expires_at` 保持原值。能力结构损坏或无法识别时才清除为 unknown；NodeState key 继续按默认 health TTL 写回。
- `admin/routing.resetInMemoryNodeState` 改用健康专用 reset 操作，不再提交零值全量 NodeState。代码修复提交：`cbfcbee86`。

## 未关闭的门

- `GetSupportsResponses` 目前先 `GET` NodeState，再另发命令读取 Redis `TIME`；正好在两条命令之间跨过 expiry 时，单个调用可能仍返回已过期 verdict。后续可用 Lua 将解码、身份/期限检查与 Redis 时间合并为原子读。
- `node_probe`、`probe_http`、`active_probe_executor` 等其它 probe writer 尚未统一 capability 持久化。
- 未运行真实 PostgreSQL、真实 Redis 多进程/Cluster、`deploy-local.sh`、真实供应商或客户端验证。

本轮只修复“管理员健康重置误清能力 verdict”子项；F04/D09 域级验收仍开放。
