## 六、本轮沉淀通用式

1. ★ **「接线」是交付的最后一公里，但它不在任何九面登记清单里**：997/998/999 的九面登记全齐、交付钉测全绿、SQL 修复到位——而三包不在二进制里，功能=0。九面登记保的是「表能建出来」，**「谁往表里写」是第 10 面，只能靠 `go list -deps` 对拍**。⇒ 凡「新表 + 新包」列车，验收判据必须含「包在二进制依赖图里 + 至少一条活跃写路径」。
2. ★ **共用判定体抽出来的时候，协议形状要跟着抽**：F3 把四面接进同一道门，却让四面共用 chat 面的响应信封——「闸门语义统一」不等于「响应形状统一」，SDK 按**各自协议**解析。⇒ 抽共用体时，凡涉及「写给客户端的字节」，必须按面注入；钉测要断言形状而不只断言状态码。
3. ★ **后端加了降级标记、前端没人读＝修了一半**：F11 让载荷可区分「算不出来 vs 没数据」，但前端照旧 `arr.length` 直取 ⇒ 降级路径反而变成新炸点（比修之前更糟：修复前是 42P01 500，修复后是 200 + 整页崩）。⇒ 凡新增「降级载荷」字段，同一笔提交必须包含**消费方**的空安全与降级 UI；钉测要打「降级载荷进真实渲染」这条腿。
4. ★ **占位探针必须显式声明自己是占位**：恒 exit 0 的空壳被 runner 当门、被报告引用成 PASS——「报绿但没做」与「量具失效」之间隔着 exit 2。⇒ 未实现断言的探针一律 exit 2 + NOT_EVALUATED（仓内 result.mjs 口径），runner 与报告不得把它算进「通过」。
5. ★ **窗口级检查 ≠ 当轮文件级检查**：12h 轮宣称「gofmt 0 漂移」属实——只对自己经手的文件；窗口里其它 6 个文件照样违规。⇒ 审计轮跑门禁按**窗口 diff 全集**跑（含 _test），不采信上轮的「当轮」口径。
