## 一、结论先行

`GET /api/admin/provider-cost-reconciliation` **不带 `?month=` 参数时，永远返回 0 条**。

`admin/provider_cost_reconciliation.go:112`：

```go
month := time.Now()          // ← 2026-10-03 14:23:11 +08，不是月初
if v := r.URL.Query().Get("month"); v != "" { ... }
items, err := h.service.ListByMonth(r.Context(), month)
```

`PGReconciliationStore.ListByMonth`（`domains/providerprofile/pg_reconciliation_store.go:138`）执行
`WHERE reconciliation_month = $1`，而该列是 **`date`**（`sql/objects/tables/provider_cost_reconciliation.sql:8`）。

**PG 在 `date = timestamptz` 上没有直接操作符**，会把 date 侧提升为 timestamptz（用会话 TimeZone 解释该 date 的零点）再做绝对时刻比较。
⇒ 传 `2026-10-03 14:23:11+08` 进来，与列里的 `2026-10-01` **恒不相等**。

**这不是「可能错」，是恒错。** 且失败形态是**静默空集 + HTTP 200 + `"count": 0`** ——
正是本审计反复登记的「『未定义/未命中』不可编码进 0」家族的第五个出现位置，
但这里的载体是**一个对外的商务数字**（运营会看到「本月零对账记录」）。

**为什么此前没被发现**：111 号把 store/worker/sink 三层审得很深（F2/F6/F7/F9/F10），
**但停在 handler 之下**；而 admin 层的测试又恰好对这条完全失明 —— 见 §三。

## 二、与 111 号的关系：为什么这不是重复登记

111 号 §三（F6）确实提到了时区，但它说的是**标签**问题：`reconciliation_month` 传 timestamptz 后按 PG 会话时区转型，
在「会话 UTC + 进程 +08」的组合下整月被标成上一个月，**且判为 latent P3**（实测本库 `SHOW TimeZone = Asia/Shanghai`）。

本条**不是**那条：

| 维度 | 111 号 F6 | 本条 222 号 |
|---|---|---|
| 前提 | PG 会话时区 ≠ 进程时区 | **无前提，任何时区下都成立** |
| 表现 | 标签落到**上一个月**（仍能查到） | 落在**某一天**（查不到任何行） |
| 触发条件 | 跨时区部署 | **默认参数即可** |
| 层 | store 参数的**语义正确性** | handler 参数的**归一契约** |

⚠️ 两者可以**叠加**：在 UTC 会话下，`time.Now()` 既不归一（222 号）又跨时区（F6）。

**同族但独立的镜像面**（承 211 号的教训「复盘里记下『已修』不等于同族副本已修」）：
111 号修 store 层不会让 handler 层的缺省值变正确。

## 三、⚠️ 为什么 admin 层的测试没能抓到它 —— 一道**结构性失明**的门

`admin/provider_cost_reconciliation_test.go:35-37`：

```go
func (s *fakeCostReconciliationService) ListByMonth(ctx context.Context, month time.Time) ([]..., error) {
	return s.records, nil          // ← month 参数被丢弃
}
```

**fake 直接把 `month` 扔了、返回预置记录** ⇒ 任何 month 值（归一的、未归一的、随机的）
都会得到同样的 0 或 1 条结果。

而缺省月的那个用例（`:162-170`）**只断言 HTTP 200**：

```go
// 缺 month 参数：默认当前月（不报错）。

...
```

⇒ **它证明了「不报错」，没有证明「查到的是本月」。**
按本审计的判据纪律：*断言必须取可观测后果*。「不报错」在这里恰恰是缺陷的**症状**。

⚠️ **诚实边界**：这个 fake 也服务另外三个用例（都显式传 `?month=2026-07`），改成按 month 过滤

## 五、⚠️ 写这条守卫时我踩的三个坑 —— **都记进 playbook**

### 坑 1：正则在它**最该判对**的那行上失效（`srcLooksNormalized`）

源码写的是：

```go
current := time.Date(now.Year(), now.Month(), 1, 0, 0, 0, 0, now.Location())
```

我最初的判据是 `time\.Date\([^)]*,\s*1,` —— **day 位确实是字面 `1`，但前两个实参里有 `now.Year()` / `now.Month()` 的括号**，
`[^)]*` 被 `now.Year()` 的右括号截断 ⇒ **恒不匹配** ⇒ 一条正确代码被判成「未归一」。

⇒ **一道会误报正确代码的门比没有门更坏。** 改法：括号配平截取实参列表，按**顶层逗号**切分，取第 3 个实参。

### 坑 2：`go test` 的工作目录是**包目录**，不是仓库根

写 `".."` 指向 `internal/`，于是 4 个锚点全读不到 ⇒ 门以「锚点缺失」转红。
**那个红脸会被读成「源码有问题」，实际是尺子坏了。**
⇒ 改用哨兵文件（`go.mod` + `Makefile`）自证根目录，并把这条前提本身做成会失败的断言。

### 坑 3（最狠）：**验证尺子的断言是自证的**（NC3 的直接产物）

`repoRootCanBeRead` 最初这样写：

```go
root := repoRootFromPackageDir()          // ← 复用被测函数
if _, err := os.Stat(filepath.Join(root, "go.mod")); err != nil { t.Fatalf(...) }
```

而 `repoRootFromPackageDir` 在找不到根时**回退返回 `"../.."`**（写死的默认值）。
⇒ **尺子错时，这条"验证尺子"的断言跟着错，永远自洽、永远不会响。**
NC3 实测：把候选列表缩成 `[]string{".."}`（必然找不到根），门**仍然 PASS**。

修法两条：
1. `repoRootFromPackageDir` 找不到时返回 **`""`（不猜）**；
2. 断言**不复用被测函数的返回值**，改为从 `.` 独立逐级上溯 + 检查哨兵，再交叉比对两者。

⚠️ 交叉比对时又踩了 Windows 分隔符坑：`filepath.Join` 归一成 `..\..`，候选表里是字面 `../..` ⇒ 直接比字符串永远不等，
门对着**正确代码**报红。⇒ 必须先 `filepath.Clean` 再比。

## 六、待裁决 88（P2）：`handleList` 缺省月份未归一

- **现象**：`GET /api/admin/provider-cost-reconciliation`（无 `?month=`）**恒返回 `count: 0`**，HTTP 200。
- **机制**：`admin/provider_cost_reconciliation.go:112` 裸传 `time.Now()` ⇒ 与 `date` 列的月初值恒不等。
- **影响面四维**：
  - 不失败（200）；
  - 不波及（带 `?month=` 的调用完全正常；前端 0 命中该端点，**当前无 UI 消费**）；
  - 理论知道实际不会知道（响应里的 `"month"` 字段会被格式化成 `"2026-10"`，**看起来完全合理**）；
  - **无痕迹**（无日志、无告警）。
- **为什么不是 P1**：
  ① 该功能默认关闭（111 号 F10 已登记：关闭时路由不注册 ⇒ 404）⇒ **当前生产根本调不到这个端点**；
  ② 前端 0 命中 ⇒ 没有用户可见的错误数字。
- **修法**（一行，不影响客户端观感）：
  ```go
  month := time.Now()
  month = time.Date(month.Year(), month.Month(), 1, 0, 0, 0, 0, month.Location())
  ```
  ⚠️ **本代理不擅自动手**：它改的是管理端查询端点的默认行为（对外可见契约），
  且与 111 号 F6 是同族而 F6 尚未裁决 ⇒ 建议**与 F6 一起裁决**（两者都是「月份键的时区/形态契约」，
  一次改动可同时收口，避免改两遍）。

## 九、playbook §170–§172

**§170 判据的正则不能对源码的排版/嵌套脆弱 —— 判据失效最常见的方式是「看起来对」。**

222 号的 `srcLooksNormalized` 最初是 `time\.Date\([^)]*,\s*1,`，用来认「构造了月初」。
源码写的是 `time.Date(now.Year(), now.Month(), 1, 0, 0, 0, 0, now.Location())` ——
**day 位确实是字面 `1`，判据的立意完全正确**，但前两个实参里有 `now.Year()` / `now.Month()` 的括号，
`[^)]*` 被 `now.Year()` 的右括号截断 ⇒ **恒不匹配** ⇒ **一条正确代码被判成「未归一」**。

⇒ 这不是"正则写得不好"，是**判据的立意与判据的实现分属两件事**，而我只验证了前者。
⇒ 写形态判据时问三句：**① 嵌套调用会不会截断我的模式？② 参数顺序变了它还成立吗？
③ 换一种等价排版（多行、命名常量）它还成立吗？**
⇒ 改法：括号配平截取实参列表 ⇒ 按**顶层逗号**切分 ⇒ 取第 N 个实参（而不是正则里数逗号）。
⚠️ 与 §120 同族，但**方向相反**：那里是**恒真谓词**（装饰），这里是**对正确代码的恒假谓词**（误报）。

**§171 验证「尺子本身是好的」的那条断言，若复用了尺子的返回值，就是自证的。**

`repoRootCanBeRead` 最初这样写：

```go
root := repoRootFromPackageDir()                       // ← 复用被测函数
if _, err := os.Stat(filepath.Join(root, "go.mod")); err != nil { t.Fatalf(...) }
```

而 `repoRootFromPackageDir` 在找不到仓库根时**回退返回写死的 `"../.."`**
⇒ **尺子错时，这条"验证尺子"的断言跟着一起错，永远自洽、永远不会响。**
负控 NC3 实测：把候选列表缩成 `[]string{".."}`（必然找不到根），**门仍然 PASS**。

⇒ 这是 211 号记的「**自证的断言在关键处等于没有断言**」的**第三种形态**：
前两种是「断言挂在它要守护的那个包里」和「校验目标与被守护对象同源」；
这里是「**校验函数与被校验函数同源**」。
⇒ 修法两条同时要：**① 被测函数失败时必须显式失败（返回空串、不猜默认值）**，
**② 校验方走一条独立的实现路径，最后交叉比对两者**（交叉比对本身也要能响，
⚠️ 本轮交叉比对又踩了 Windows 分隔符：`filepath.Join` 归一成 `..\..` 而候选表是字面 `../..`
⇒ **门对着正确代码报红** ⇒ 必须先 `filepath.Clean` 再比）。
⇒ **判别式**：把被测函数的候选列表改坏，那条"验证它"的断言**会不会响**？不会 ⇒ 它是自证的。

**§172 一道门「能过」不能证明它有牙齿 —— 必须去掉豁免看它是否转红。**

222 号的 `TestNoBareNowAsMonthKey` 第一次跑就 PASS。
按常理这说明"仓内没有未归一月键"，但**本轮要找的那条缺陷就在仓内、就在这个门想抓的地方**。
去掉豁免跑负控 ⇒ **仍然 PASS** ⇒ 尺子坏了：`scanBareNowMonthAssignments("..")` 传的是 `..`
（不是 `../..`），Walk 扫的是 `internal/` 子树、**根本走不到 `admin/`**
⇒ 这道门对它自己要抓的 `admin/provider_cost_reconciliation.go:112` **结构性失明**。
修正后重跑负控 ⇒ 转红，并**精确点名** `admin/provider_cost_reconciliation.go:112`。

⇒ 与 218 号「负控先在未修复代码上跑」同源，但补一个更前置的纪律：
**豁免清单本身必须被负控覆盖** ——
有豁免的门，其"通过"信息量约等于零，因为**它对你最关心的那处默认是不表态的**。
⇒ 每条豁免都要配一条"去掉它看门是否转红"的负控，把豁免从**声明**变成**可证伪的**。
⚠️ 配套：运行时间也是信号 —— 修正前后该门从 **0.89s 变 41s**（走真仓库根 vs 只扫 `internal/`）。
**门"变快"和门"变绿"一样，都是尺子出错的信号。**
