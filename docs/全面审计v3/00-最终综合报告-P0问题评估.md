### 问题 2: V1/V2 双轨存储同步机制

**状态**: ⚠️ **设计使然，需要监控**

**架构发现**:

```
请求处理流程:
1. 写入 V1 (request_wal) ← 主存储，同步，事务保证
2. 触发 telemetry hook
3. 异步写入 V2 (session_turns) ← 影子副本，最终一致性
   - 8 并发协程池
   - 2秒超时
   - 三层回退：直接写入 → 持久化队列 → 内存缓冲
```

**数据差异（7天窗口）**:

| 指标 | V1 (request_wal) | V2 (session_turns) | 差异 |
|------|------------------|-------------------|------|
| 记录数 | 175,789 | 77,576 | **-55.9%** |
| 会话数 | 134,384 | 35,957 | **-73.2%** |

**根因分析**:
- ✅ **非系统故障**：差异由设计意图的过滤规则导致
- ✅ **Outbox 为空**：重试机制工作正常
- ⚠️ **过滤类别**：
  - 探针流量（30-40%）
  - 进行中状态占位符（5-10%）
  - 内部自动请求（5-10%）
  - **合计过滤：40-60%，与实测 56% 吻合**

**一致性保证**:
- ❌ **无跨系统事务**：V1 和 V2 在独立事务中
- ⚠️ **V1 为准**：所有查询应优先使用 V1 或明确标注数据源
- ✅ **V2 是影子副本**：用于验证和准备未来迁移

**风险矩阵**:

| 失败场景 | V1 状态 | V2 状态 | 数据一致性 |
|---------|---------|---------|------------|
| V2 超时 | ✅ 成功 | ⏱️ 超时 | ⚠️ V1 有，V2 无 |
| V2 DB错误 | ✅ 成功 | ❌ 失败 | ⚠️ V1 有，V2 无 |
| 过滤规则 | ✅ 成功 | 🚫 跳过 | ⚠️ V1 有，V2 无（设计） |

**立即行动**:
1. 🔴 建立 V1/V2 一致性监控
   - 覆盖率 < 40% → P2 告警
   - 覆盖率 < 30% → P1 告警
   - 单日下降 >10% → P0 告警

2. 🔴 验证 shadow_write 开关状态
   ```sql
   SELECT key, value FROM settings_kv WHERE key LIKE '%sessions_v2%';
   ```

3. 🟡 明确迁移路线图（需 Owner 决策）
   - V2 何时成为主存储？
   - 是否移除过滤规则达到完全覆盖？
   - 迁移时间表和里程碑？

**报告**: `04-V1V2存储同步机制验证报告.md`

### 问题 3: 会话统计口径问题

**问题描述**:

会话统计漏算约 **13%** 的费用和请求，导致：

- 漏算：$1,321.43 (13.4%)

**根本原因**:

```go
// ❌ 错误逻辑

// 问题：排除了首次请求在窗口外，但窗口内仍活跃的会话
```

| Session B | Nov 17 | Nov 17-18 有请求 | ✅ 统计 | ✅ 统计 |

**影响评估**:

| 受影响功能 | 漏算程度 | 影响等级 |
|-----------|---------|---------|
| 总费用 | -13.4% | 🔴 严重 |

| 会话数 | -11.8% | 🟡 中等 |
| Top 10排行 | 未知 | 🔴 严重 |

**当前临时方案**（commit `b2015776e`）:

- ⚠️ **这只是临时措施，核心问题未修复**

**完整修复方案**（已文档化）:

```go
// ✅ 正确逻辑：混合查询方案
WITH window_sessions AS (
    -- 识别窗口内所有活跃会话
    SELECT DISTINCT gw_session_id
    FROM request_logs_with_current_month
    WHERE ts >= NOW() - INTERVAL '7 days'  -- 请求时间在窗口内
      AND origin_stage = 'business'
)
SELECT 
    COUNT(DISTINCT r.gw_session_id) AS total_sessions,
    COUNT(*) AS total_requests,
    SUM(r.cost_usd) AS total_cost
FROM request_logs_with_current_month r
JOIN window_sessions ws ON r.gw_session_id = ws.gw_session_id
WHERE r.ts >= NOW() - INTERVAL '7 days'
```
