## 五、审计方法论

### 5.1 检查清单方法

每个模块审计使用标准化清单:

✓ **结构完整性**
- 数据结构定义清晰
- 字段类型正确
- 必填字段验证

✓ **流程闭环性**
- 入口明确
- 出口明确
- 异常路径处理

✓ **并发安全性**
- 临界区保护
- 资源释放
- 死锁避免

✓ **错误处理**
- 错误检查完整
- 错误传播正确
- 错误日志准确

✓ **性能考量**
- 无明显瓶颈
- 资源使用合理
- 可扩展性

### 5.2 审计证据

每个发现必须包含:

1. **问题描述**: 清晰、具体、可复现
2. **影响范围**: 功能/性能/安全影响
3. **严重级别**: P0(阻塞)/P1(严重)/P2(重要)/P3(建议)
4. **代码位置**: 文件路径、行号、函数名
5. **复现步骤**: 如何验证问题
6. **修复建议**: 具体可行的解决方案

### 5.3 工具支持

- **静态分析**: `go vet`, `staticcheck`
- **竞态检测**: `go test -race`
- **覆盖率**: `go test -cover`
- **性能分析**: `pprof`, benchmarks
- **代码图谱**: codegraph (已生成)
- **数据库检查**: SQL 查询验证
