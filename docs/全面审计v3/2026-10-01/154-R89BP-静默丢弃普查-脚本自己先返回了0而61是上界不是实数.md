## 一、先说方法论：脚本返回了 0，而 0 是危险信号

第一版扫描脚本对全仓 2,169 个生产 `.go` 文件跑出 **`select 型 default: 分支总数: 0`**。

按 §39「一个检索形态对所有目标都返回 0 时先怀疑形态」，我停下追了下去，两次都追对了：

| # | bug | 症状 | 根因 |
|---|---|---|---|
| 1 | 向上回溯找同缩进 `case` 时用了 `ind_j < indent` | 0 命中 | select 里的 `case` 与 `default` **同缩进**，永远不满足 `<` |
| 2 | 判空用 `re.compile(r'\S').match(line)` | **仍然是 0** | `.match()` 锚定**位置 0**，`'\tcase ...'` 第 0 位是空白 ⇒ **所有缩进行都被当成空行跳过** |
| 3 | 计数器正则只认 `.Add/.Inc/.Store/Counter/metric/stats.` | 虚高 | **漏掉裸 `x++`**，而 `admin/telemetry.go:800` 正是 `errCount++` |

⚠️ **bug 2 是本轮最值得留下的东西**：`\S` 配 `.match()` 与 `\S` 配 `.search()` 差一个缩进，
而**任何 Go 源码几乎都是缩进的** ⇒ 这个「看起来完全正确」的过滤器会**静默地把每一行都判成空**。
它不报错、不抛异常，只是安静地返回空集。

⇒ 已升级为 playbook **§47**。

## 三、「61」是上界，不是缺陷数 —— 逐个看下来大部分是良性的

我按纪律没有把 61 直接写成「61 处静默数据丢失」。抽查原代码后，**至少 8 类一眼可判为良性**：

| 位置 | 分支体实际做的事 | 为什么良性 |
|---|---|---|
| `tuning_signal_writer.go:191` / `selection_writer.go:184` | `if len(batch)>0 { w.flush(batch) }` + `return` | **这是 `run()` 停机 drain 循环的终止条件**，不是入队丢弃（真正的入队丢弃在 `:167`/`:149`，有计数器） |
| `routingopt/feedback_batch.go:167` | `w.writeBatch(ctx, pending)` + `return` | **退出前先 flush**，不丢数据 |
| `executors/executor.go:1939` | 注释「fall back to synchronous release」 | **降级为同步释放**，不是丢弃 |
| `dispatch/forwarder.go:297` | `goto swapped` | **重试**，不是丢弃 |
| `capture_forwarder.go:163` | 注释「Another consumer drained between the failed send…」 | **自愈重试** |
| `security/sensitive/engine.go:241` | 向 `errCh` 发 error 后 `default:` | **「首次错误胜出」**语义；外层是 ticker 轮询 ⇒ **我的形态分类器把它误判成发送丢弃** |
| `admin/freepool_stream_sse.go:167` | `delete(h.clients, c)` + 注释「drop and disconnect」 | **有意的断开策略**，注释写明 |
| `bg/node_probe.go:1875/1894`、`auto_route_realtime_listener.go:228` | `break drain` / `break sweep` | **循环终止**，非丢弃 |

⇒ **61 至少要再筛两轮才能变成缺陷数**：
① **可达性**（§30：不可达的不是缺陷）；
② **是否已有包裹函数持有计数器**（153 号已证：计数器常在分支之外）。

⚠️ **我没有做完这两轮，因此本轮不发缺陷条目。** 如实登记为待查，而不是把 61 写进待裁决。

## 五、诚实边界

- **未改动任何生产代码或数据库**（本轮为纯只读普查 + 一次性脚本）。
- **脚本是一次性分析，未入库**（放 `/tmp`）——但**口径与自洽性全部写进本文**，可复现。
- ⚠️ **本表的三个已知不可靠点**：
  1. **形态分类只看 case 表达式、不看上下文** ⇒ `security/sensitive/engine.go:241` 已实证误判
     （ticker 循环里的 errorCh 被当成「发送丢弃」）。**61 里的定时器内发送可能还有别的。**

     ⇒ 真实的「完全静默」数**可能高于 61**。
