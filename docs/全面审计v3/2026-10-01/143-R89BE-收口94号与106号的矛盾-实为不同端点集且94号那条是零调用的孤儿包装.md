# 143 号｜R89-BE：收口队列里那处**互相矛盾**的记录 —— 94 号的 P3 定性要改：**不是「前端在调不存在的端点」，是三个零调用的孤儿包装**

- 日期：2026-10-01
- 轮次：R89-BE
- 起因：台账下轮队列记着一处矛盾——
  **94 号**记「前端调 3 个不存在端点」，**106 号**记「`health-checks` 在 `web/` 里 0 命中」，
  106 号明确写下「两者可能指的是不同的端点集合，也可能有一方是错的。**登记为待复核，本轮不下结论**」。
- **结论先行**：
  1. **矛盾解除：两者指的是完全不同的端点集，各自都成立。**
     94 号说的是 `session-recent` / `session-anomalies` / `session-export`（**dashboard 族**）；
     106 号说的是 `/admin/api/v1/health-checks`（**health-check 族**）。
     **106 号的谨慎是对的**，本轮给出它当时拿不到的证据。
  2. **⚠️ 94 号那条 P3 的定性要改**：三个前端 API 包装函数
     （`getRecentSessions` / `getSessionAnomalies` / `exportSessionData`，`web/src/api/dashboard.ts:386/549/582`）
     **在 `web/` 全域的调用点均为 0** ⇒ **没有任何组件在用它们** ⇒
     **不存在「用户点了 404」这件事**。
     **正确的定性是「三个零调用的孤儿前端包装」，不是「前端在调不存在的端点」。**
  3. **⚠️ 94 号还漏了一层：它只查了「存在性」，没查「路径一致性」。**
     `session-export` **后端确实存在**——`cmd/gateway/main.go:6887-6889` 注册
     `GET /api/admin/session-export`（及 `/import`、`/pack`），**且带 `wrapAdmin` 鉴权**；
     而前端调的是 **`POST /api/admin/dashboard/session-export`** ⇒ **路径与方法双错**。
     ⇒ **94 号的「不存在」在这一个上是错的**（真实描述是「存在但地址对不上」）。
  4. **106 号的「0 命中」口径经复核有效**：`web/` 里 `health-check` 共 **15 处命中**，
     **全部是 `/api/proxy/*` 族**（`/api/proxy/nodes/{id}/health-check`、`/api/proxy/health-check-all`），
     **与 `/admin/api/v1/health-checks` 无关** ⇒ **反向对照成立，94 号与 106 号互不矛盾。**
  5. **playbook §37 新增**：**「端点存在性」必须三维度核对 —— 路径全等 + 方法匹配 + 鉴权 wrapper。
     只看「这个名字在仓库里出现过没有」会同时产生假阳性与假阴性。**

## 一、逐项取证

### 1.1 `session-recent` / `session-anomalies` —— 后端确实不存在 ✅

```bash
grep -rn --include=*.go "session-recent\|session-anomalies" . | grep -v vendor
# ⇒ 0 命中（连同裸名一起搜，均为 0）
```
前端定义处（真实存在）：
- `web/src/api/dashboard.ts:387` `GET /api/admin/dashboard/session-recent?${searchParams}`
- `web/src/api/dashboard.ts:557` `GET /api/admin/dashboard/session-anomalies?${searchParams}`

⇒ **这 2 个「后端无对应实现」成立。**

### 1.2 `session-export` —— 后端**存在**，但地址/方法都不匹配 ⚠️

```bash
grep -rn --include=*.go "session-export" . | grep -v vendor | awk -F: '{print $1}' | sort | uniq -c
#   11 admin/session_export_test.go
#    7 cmd/gateway/main.go          ← 路由注册在这
#    6 domains/sessionforensics/client.go
#    6 admin/session_export.go
#    …
```
`cmd/gateway/main.go:6887-6889`：
```go
mux.HandleFunc("/api/admin/session-export",          wrapAdmin(exportAPI.ServeHTTP))
mux.HandleFunc("/api/admin/session-export/import",  wrapAdmin(exportAPI.ServeHTTP))
mux.HandleFunc("/api/admin/session-export/pack",    wrapAdmin(exportAPI.ServeHTTP))
```
前端 `web/src/api/dashboard.ts:583`：
```ts
return req(..., 'POST', '/api/admin/dashboard/session-export', …)
```

| 维度 | 前端 | 后端 | 一致？ |
|---|---|---|---|
| 路径 | `/api/admin/dashboard/session-export` | `/api/admin/session-export` | ❌ **多一层 `/dashboard`** |
| 方法 | **POST** | **GET**（基础路径） | ❌ |
| 鉴权 | — | `wrapAdmin` | — |

⚠️ **⇒ 「这个端点不存在」是错的；真实描述是「端点存在、鉴权齐备，但前端写错了地址和方法」。**
**这两个问题的修法完全不同**（前者要新增端点，后者改一个字符串常量）。

### 1.3 ⚠️ 决定性的一步：这三个函数**根本没人调**（94 号与 106 号都没做这一步）

```bash
for fn in getRecentSessions getSessionAnomalies exportSessionData; do
  grep -rn "$fn" web/src/ | grep -v "api/dashboard.ts" | wc -l
done
# ⇒ 0 / 0 / 0
```
- 定义处：`web/src/api/dashboard.ts:386` `export function getRecentSessions`
  `:549` `export function getSessionAnomalies`、`:582` `export function exportSessionData`
- **调用点：三个全部 0。**

⇒ **没有任何组件 import 并调用它们** ⇒ **不存在运行时 404，不存在用户可见故障。**
⚠️ **这正是 135 号 §32「盲区是否引入新实体」的对偶问题：
「这个坏掉的东西，有没有人会碰到它？」——本轮答案是「没有人」。**

## 二、94 号那条 P3 的重新定性

| 项 | 94 号原述 | 本轮修正 |
|---|---|---|
| 标题 | 「前端调 3 个不存在端点」 | **「三个零调用的孤儿前端 API 包装」** |
| 暗示的影响 | 前端在调用 ⇒ 会 404 | **无调用方 ⇒ 无运行时影响** |
| 3 个端点是否都不存在 | 是 | **否 —— `session-export` 后端存在**（路径/方法双错） |
| 定级 | P3 | **P3 维持**（死代码，非缺陷），**但性质从「调用失败」变成「可删除的孤儿」** |

**⚠️ 诚实边界**：
- 本轮**没有**在运行时验证（未部署、未抓包）——结论基于**静态引用计数**（`web/src/` 全域 0 调用点）。
  ⚠️ **引用计数是本仓判死代码的既定口径**（114–120 号零导入包同一方法），
  **但它不能覆盖「通过动态字符串拼接/插件形式调用」这类形态**——本仓前端未见此类形态。
- **未检查这三个函数是否被 E2E 测试或 Storybook 引用**（`web/` 之外的目录）。

## 三、playbook §37 新增

> **「端点存在性」不是一个布尔命题，必须三维度同时核对：**
> **① 路径全等**（不是「名字出现过」）**② 方法匹配**（GET/POST/PUT…）
> **③ 鉴权 wrapper**（注册时收了几个 wrapper）。
>
> **只看①会同时产生两类错误**：
> - **假阳性（本轮 1/3）**：`session-export` 在仓库里能找到 ⇒ 误判为「存在」，
>   **实际路径多一层 `/dashboard`、方法也不同** ⇒ 前端调不通，
>   **而「新增端点」与「改个常量」的修法成本差一个数量级**；
> - **假阴性**：仓库里找不到 ⇒ 误判为「后端没有这个能力」，
>   **实际能力在别的路径/别名下**（与 14 号「这里缺 X，先问仓里有没有已实现好的 X」同族）。
>
> **配套第三条纪律（本轮新发现的、两者都漏了的）**：
> **④ 「这个坏掉的东西有没有人碰到它」必须在定性之前回答。**
> 94 号与 106 号都做了①②③（部分），**都没做④** ——
> 而④恰恰把这条从「前端会 404」降成「可删除的死代码」。
> **这是 §32「盲区是否引入新实体」的对偶：不是问「有没有新实体」，而是问「有没有人会撞上它」。**

**同族**：§13（注释承诺不成立）、§14（缺 X 先问仓里有没有）、§31（可能是一类问题要真去数）、
§32、§35、§36。
