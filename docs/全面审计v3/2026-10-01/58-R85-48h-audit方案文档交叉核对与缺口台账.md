## 0. 为什么单独做这件事

用户 objective 里有一条容易被当成客套话、实际信息量最高的指令：**读 96 小时内改动的方案文档，并据此更新审计**。本轮执行时发现仓内已存在一整套成体系的审计域目录 `tests/48h-audit/`（D01–D17），每域都有 `plan.md` + `reports/latest.md`，**且大多写于 96 小时窗口内**（D01–D06/D08–D16 最新提交 2026-09-28，D07 为 09-30，D17 与 `gates/` 为 09-29）。

这意味着 v3 审计不是第一次审计，而是**对同一批 48 小时修正的第二次独立审计**。那么「v3 的结论相对既有方案文档是补充、还是推翻」就成了必须回答的问题。本文只建立台账，冲突判定留给对应域的轮次。

## 2. 关键判断：5 个 3 行报告**不掩饰自己的空白**

逐字读了 5 份 3 行报告（`cat` 原文）：

- **D03**：「lite telemetry 并发 journal 去重与流式 capture 定向验证通过；F03 reader 使用实际 upstream response context。**跨进程 offset、真实 Redis/PG 回填和故障恢复未验证。**」
- **D05**：「Ollama 已接入候选窗口预压缩及一次性 context-length 4xx 内部恢复；httptest 证明第二次请求体变小且成功，context marker 防循环。**真实 tokenizer、Redis session cache 与 provider probe 未验证。**」
- **D10**：「lite journal 幂等与压缩/限流 provenance 的本地定向证据在位；**PG 分区读面、跨日重算及 provider billing 对账未验证。**」
- **D12**：「本轮仅静态核对 candidate URL/协议、Ollama local endpoint、Authorization 与 scope header 边界；**真实代理订阅、地区网络和供应商探测未验证。**」
- **D13**：「self-check 429 可信作用域与 credential 隔离定向验证通过；**真实 token 来源、配额服务、过期回收和供应商凭据未验证。**」

**结论：既有文档体系没有虚报**。每份都主动写明了「哪部分只有本地定向证据、哪部分根本没验」。这与本会话反复遇到的形态（注释承诺 vs 实现漂移、面板存在但数据源恒空）形成对比——**写这些报告的人是诚实的**。

因此 R85 对账的真正目标不是「抓既有报告的谎」，而是**把它们列出的未验证项逐条接过来**。这也让 57 号报告的域 A 真库线索（`discovery_tasks` 260/260 failed、catalog 空）与 D13 自述的「真实 token 来源、配额服务未验证」**完全对上**——不是新发现，是既有文档早就标出的坑一直没填。

## 4. D14 单独说明：域名叫 security，报告只覆盖了脱敏还原一条线

`tests/48h-audit/D14-security/plan.md` 标题是「**场景安全**（含敏感信息处理）」，`§1 审计要点` 列了 **7 条**，但 `§2–§5` 勾选的 **10 条测试（B-01..03 / D-01..02 / S-01..02 / SF-01..02）全部集中在「脱敏还原」这一条线上**：

- 第 15 行「资源/锁安全：`SanitizeInputMiddleware.stateMu` + `acquireOffsetsLock` 串行化 read-modify-write，防止跨进程 race」——**无任何对应勾选测试**。
- 第 16 行「不可达降级：Redis 不可达时映射表持久化失败 → 还原降级为单轮；日志 warn 但不阻断」——**无任何对应勾选测试**。

plan 自己诚实地写了状态：「R73 续审进行中……**D14 全域验收仍未完成**」。但**"未完成"这三个字掩盖了缺口的形状**：不是「差几条测试」，而是 §1 的 7 条要点里有 2 条（资源/锁安全、不可达降级）**从未被任何测试触及**。

**并且 objective 里那条最宽的「检查各类场景安全：并发锁控制、多线程资源竞争、内存或句柄泄漏、异步处理异常、异常错误的处理、请求数据转换、各数据结构与参数有无溢出可能性、网络请求处理的可靠性、tcp 会话维持的可靠性、密钥可用、数据 api 的可用情况」，在两套体系下都缺覆盖**——实测：

```bash
cd tests/48h-audit
for k in "fd.Close" 句柄 MaxInt gosec 整数溢出; do
  echo "$k -> $(grep -rli -- "$k" --include=*_test.go . | wc -l | tr -d ' ') 个测试文件"
done
# fd.Close -> 0    句柄 -> 0    MaxInt -> 0    gosec -> 0    整数溢出 -> 0
```

`overflow` / `溢出` / `leak` 各命中 3 个文件，经核为中文注释里的偶发词，非定向测试。⇒ **溢出、句柄泄漏、静态安全扫描在既有 48h-audit 套件里是 0 覆盖**。v3 自身也没有独立的安全轮次（脱敏侧由 R71 覆盖，安全面未覆盖）。

**定级建议：作为覆盖缺口登记为待办（下一轮候选），本轮不定级**——「没有测试」不等于「有缺陷」，但它意味着 objective 那条最宽的安全要求**目前没有任何一道门在守**。这与本会话反复出现的「面板存在但数据源恒空」「指标声明但从不记录」是同一族：**存在物 ≠ 起作用的物**。
