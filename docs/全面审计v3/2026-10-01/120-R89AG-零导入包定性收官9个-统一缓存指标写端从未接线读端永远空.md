## 一、【本批最强】`domains/cachemetrics` —— 表 + 读端齐备，写端从未接线

### 1.1 包的职责（注释原文）

> Package cachemetrics provides unified cache observability (**docs/omni-ref3 D2**).
> All cache layers (**semantic/prefix/delta/kv/session_state**) report hit/miss events
> to a unified `CacheMetricsRecorder`, which writes to **cache_metrics** table.
> Enables answering "**overall cache hit rate**" and "**tokens saved**"
> without scattered in-memory counters.

导出 `CacheLayer` / `EventType` / `Event` / `Recorder`（接口）/ `NullRecorder`。

### 1.2 三段证据

1. **写端零引用**：`grep -rn "NullRecorder"` 在 `domains/cachemetrics` 之外 **0 命中**；
   `domains/cachemetrics` 整包不在任何 main 包依赖图里（114 号已用可复现命令确认）。
   ⇒ **不是「接了但用空实现顶替」，是整个 recorder 体系从未被引用。**
2. **读端存在**：`admin/cache_metrics_handler.go` **确实引用 `cache_metrics` 表**。
3. **表是完整建好的分区表**（真库 `\d cache_metrics`）：

```
Partitioned table "public.cache_metrics"   Partition key: RANGE (partition_date)
  id, tenant_id, cache_layer, event_type, tokens_saved, session_id, request_id, recorded_at
Indexes: idx_cache_metrics_event_type (event_type, recorded_at DESC)
         idx_cache_metrics_tenant_layer_ts (tenant_id, cache_layer, recorded_at DESC)
Check:   cache_metrics_cache_layer_check CHECK (cache_layer = ANY (
           ARRAY['semantic','prefix','delta','kv','session_state']))
```

**CHECK 约束枚举的 5 个层与包注释里的 5 个层逐字一致** ⇒ **这张表就是为这个 recorder 建的。**

### 1.3 结论

**`cache_metrics` = 0 行**（真库实测）。

**⇒ 表（含分区、2 个索引、CHECK 约束）+ 读取 API 全部齐备，
唯独写入端（recorder）从未接线 ⇒ 管理端「缓存命中率 / 省了多少 token」永远返回空。**

**⇒ 这与 106 号（dashboard 访问事件）是**同型但更尖**的一类**：
106 号是「注入 setter 零调用点」，本条是**「写入器整包零引用」**——
**范围更大（整个包），而读端还多了一层「看起来能用」的包装**。

**直接命中 objective 的「优化流程的可观测性」**：
五层缓存（语义/前缀/增量/kv/会话状态）的命中率与节省 token，
**在本仓从来没有被采集过一次**。
运维现在能看到的只有散落各处的内存计数器（包注释自己说的正是这个痛点）。

**⇒ 登记 B 类 + 待裁决**：~~接线成本低（5 个缓存层各调一次 `Recorder`）~~
  → ⚠️ **121 号已更正：「5 个层各调一次」是错的**——实测顶层 `cache/` 目录**只有 `prefix`**
  一个子包，**`cache/semantic` 与 `cache/kv` 不存在** ⇒ **现役只有 3 层**
  （`prefix`/`delta`/`session_state`），`semantic`/`kv` **要么等实现、要么从枚举删掉**。
  且表上的 CHECK 约束**允许**写入这 5 个值，**不阻止** semantic/kv 的空语义行。
  **⇒ 读约束不能替代读代码**（§20 同族）。指标口径与 `event_type` 枚举是否一致**仍未核**。

## 二、`domains/ursm/v2/integration` —— **不是「实现缺失」，是集成测试独立成包**（我先猜错了）

`ls` 结果：**只有 2 个测试文件，没有任何 `.go` 源文件**。
我最初判断这是「测试先行、实现未落地」，**读注释后推翻**：

> // Package integration: simulates a Redis restart against the v2 recovery gate.
> The behavior under test is:
> > 1. The v2 pipeline can become ready (warmup writes the ready key).
> > 2. After Redis "restarts" (fresh miniredis instance with a fresh redis client),
> >    **the ready gate is closed because the keys are [gone]**

它只依赖 `miniredis`（`redis.RunT` / `redis.NewClient` / `redis.Options`），
通过**公开 API 驱动 v2 管线**，不需要包内符号。

**⇒ 判为「测试包（活的）」，不是运行时能力，也不是死代码。**

**但它揭示了一条值得记住的行为契约**：
**Redis 重启后，URSM v2 的 ready 闸门必须关闭**（不能让旧 ready key 骗过健康检查）。
这条有测试钉住，**是本仓少见的、把「分布式状态一致性」写成测试的案例**。
**是否在 CI 中执行，本轮未核**（`internal/ursm` 不在 `make guards` 名单里，需查 CI 配置）。

**⇒ 归类提醒**：这提醒 A/B/C/D 四类之外还有第五种——
**「只有测试没有源文件的包」既不是死代码也不是未接线能力，它是一条契约的载体。**
