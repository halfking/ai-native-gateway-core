## 〇、先更正 117 号的一处错误陈述

117 号写「现役 `domains/orchestration` **主体在用**（不在零导入名单），但它**自己的 `observ` 子包没接**」。

**这句话是错的。** 实测：

```
$ ls domains/orchestration/
observ
$ head domains/orchestration/*.go
head: domains/orchestration/*.go: No such file or directory
```

**`domains/orchestration` 目录下只有 `observ` 一个子目录，没有任何 `.go` 文件**
——它不是一个 Go 包，只是一个**空的命名空间目录**。

**⇒ 更正后的结论**：`domains/orchestration/` **整棵树都未接线**，
不是「主体在用、子包没接」。

**错误来源（已入册方法论）**：我把「不在零导入名单里」读成了「在用」，
**但一个没有 `.go` 文件的目录根本不会出现在任何包的清单里，它的「不在名单里」不携带任何信息**。
这与 114 号（§22）是同一族错误的另一个面：
**「不在某个清单里」有两种原因——「不在那里」和「根本不是那一类东西」，必须先区分。**

## 三、`webcookie`（315 行）—— 直接命中 objective 的「OmniRoute 借鉴」要求项

包注释：

> Package webcookie provides the framework for browser-reverse-engineered
> ("web-cookie") free LLM providers — e.g. **deepseek-web, chatgpt-web, gemini-web**.
> These providers expose a free chat UI in the browser but **no official free API**;
> OmniRoute wraps them by **reverse-engineering the browser's HTTP/WS/SockJS calls
> with cookie/session injection and TLS fingerprinting**.
>
> This package is the **Go analogue of OmniRoute's `open-sse/executors/*-web.ts` adapters**.

含 `SessionManager`（Put/Get/过期驱逐）、`Registry`（注册/替换）、`SessionClient`、
`deepseek_web.go`，测试覆盖会话过期驱逐与 nil 安全的 transport 回退。

**⇒ 判读（三点，都要说清）**：

1. **它就是 objective 点名要的那个「跨项目借鉴」的落地物**——
   objective 写「需求有考虑不完整的，需要从 `~/workspace/ai` 目录下的多个项目源代码
   进行分析���借鉴，包括：**OmniRoute**、cc-switch 等」。**这个包是 OmniRoute web 适配器的 Go 版。**
2. **免费 token 池的现役实现另有其人**：`domains/freediscovery` + `domains/freeresource`
   （**不在零导入名单 ⇒ 在用**）。**⇒ 两条免费池路线并存**：
   官方 API 路线（freediscovery/freeresource，在用） vs
   浏览器逆向路线（webcookie，零引用）。
3. **合规提示（不是缺陷，是决策前提）**：`TLS fingerprinting` + `cookie/session injection`
   属于**规避反爬机制**的技术。**是否采用这条路线是产品与合规决策，不是技术优劣问题。**

**⇒ 登记 B 类 + 待产品/合规裁决**：「免费池是否走浏览器逆向路线」。
**不建议按 A 类删除**（它是 objective 明确点名的借鉴项的实现）。

## 五、`internal/ctxpool`（340 行）—— 优化从未落地，但**不判为缺陷**

包注释给出了明确的动机与出处（「Handoff-B #4 in `tests/stress/CAPACITY_HANDOVER.md`」）：
生产热路径每请求发 4-6 次 `context.WithCancel`/`WithTimeout`，
每次分配 `cancelCtx` struct + done channel + propagator。
测试含 `TestRelease_DoubleCallPanics`、`TestRelease_NilSafe`。
**外部引用 = 0。**

**⇒ 判 B 类，但明确写清「不构成缺陷」**：
context 分配是**已被 Go 运行时与中间件广泛优化的常规路径**，
零引用只说明**这项特定优化没做**，不说明存在内存或句柄泄漏。
objective 的「内存或句柄泄漏」一项**仍需 pprof 实测**才能判断
（已长期登记为「需真实负载部署实例」的覆盖缺口，本轮仍未闭合）。
