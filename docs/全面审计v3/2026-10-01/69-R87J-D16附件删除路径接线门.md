## 1. §10 定点核实：59 号说「从不删」，这个说法过宽

59 号 §2.2 断②写的是「清理只置 JSONB 为 NULL、**从不删** `request_attachments` 行」。三项核实：

1. **读包围函数** — `domains/attachments/repository.go:281` 是
   `func (r *Repository) DeleteOlderThan(ctx, cutoff) (int64, error)`；
2. **查调用方** — `grep -rn "DeleteOlderThan" --include=*.go .` 的全部命中：
   - `domains/attachments/repository_test.go:103`（且**只测 nil repo 的 `errNoDB` 分支**）；
   - **零生产调用方**。
3. **读那段 SQL** — `repository.go:294` **确实是** `DELETE FROM public.request_attachments`，
   而且是**分块的**（`ctid IN (SELECT ctid ... LIMIT $2)`，2026-09-17 仿 `session_summaries_trimmer`，
   避免单批无界 DELETE 长时间持行锁与 WAL 拖垮 vacuum/复制）。
   **实现本身是正确的。**

**而它的文档注释写着：**

> `// Cleanup is best-effort; admin tooling calls this on a schedule to bound table growth.`

⇒ **这是一条未兑现的注释承诺。** 与 D13 的 `enabled` 注释、R87 域 A 的 `template_manager.go` 注释同型：**代码说自己被谁调用，`grep` 说没有。**

**真正在跑的清理端点**（`admin/handler.go:1006` 注册，`super_admin`）：
`POST /api/admin/attachments/cleanup/execute` → `handleDataLifecycleAttachmentCleanupExecute`

**既不调用 `DeleteOlderThan`，也不删附件行。**

## 2. 落地的两条断言

文件：`domains/attachments/cleanup_wiring_test.go`

### 2.1 `TestRequestAttachmentsDeleteIsCentralized`（结构不变量，今天成立）

`DELETE FROM request_attachments` **只允许出现在 `domains/attachments/repository.go` 一处**。

**语义量**是「删除逻辑集中在一处、便于统一分块与保留策略」，**不是**「某文件里出现过这个字符串」。
理由：分散的多条删除路径会各自发明分块/保留策略，**绕过分块 DELETE 的行锁与 WAL 保护**——
而那正是 2026-09-17 那次修复要解决的问题。**接线时也不该破坏这条**。

### 2.2 `TestDeleteOlderThanHasNoProductionCallerYet`（FIXME 门，钉现状）

断言 `DeleteOlderThan` **当前没有生产调用方**。

**这个断言看起来是反的**（断言「没有调用方」），它是刻意按「**红门不能进主干**」纪律写的：
未修的缺陷用「断言当前行为 + `FIXME` 标注」钉住，使将来修改必须**显式发生**。
F1 的 `deploy/sql/verify/routing_gate_warning_pg_test.go` 与 D13 的
`TestDiscoveryEngine_Run_TemplateDisabled` 是同一模式（本会话已三处使用）。

**失效即红**：一旦有人接线，`len(callers) != 0` ⇒ 转红并打印
「请把本用例改为正向断言（接线是本次裁决要达成的目标），并订正 repository.go 里
『admin tooling calls this on a schedule』这句注释」——
**即「门失效」与「注释失真」被绑在同一条消息里。**

## 4. 为什么这个门值得写（而不只是「又一道门」）

它同时干了两件事：

1. **守住一条会随接线而破坏的结构不变量**（DELETE 必须集中）——
   接线的人很容易在 admin 的清理 SQL 里顺手加一条 DELETE，**绕过**已有分块实现；
2. **把「注释承诺 vs 实际接线」这个本会话反复出现的形态变成可执行断言**——
   `FIXME(R87-j-1) 已失效` 那条消息会在有人接线时**同时提醒订正那句假注释**。

**这比再加一条「XX 不存在」的门更有价值**：前者防退化，后者只是记录现状。

## 5. 过程中的一次自伤（诚实登记）

用 `sed` 批量修变量名时，把两处中文全角引号附近的字符串字面量改坏了
（`"…一处，"实际命中…"` 导致 `string literal not terminated`），
又因为 `python3 -c` 里嵌了中文双引号而产生二次破坏，**连续两次编译失败**。
最终用 `edit` 工具逐处精确替换修好，`gofmt -l` 确认干净。

**教训**（与 R87-g「先跑一次编译比先写完三个文件更省」同源）：
**批量替换中文文案时不要用 shell**；引号层级在 shell → python → Go 三层传递中极易被吃掉。
**能用 `edit` 精确改就别用 `sed`。**
