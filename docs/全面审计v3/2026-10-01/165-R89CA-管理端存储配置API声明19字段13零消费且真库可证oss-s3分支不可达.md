## 四、⚠️ 必须自己降级的两点（防止夸大）

这一节是本报告最重要的部分。D1 看起来是教科书式的「静默丢弃」，**但它不是**。两条自我修正：

### 4.1 不是静默丢弃 —— 因为响应是回显型的

`storageConfigPut` 结尾（`:344-349`）不是自造响应体，而是**直接再跑一次 GET**：

```go
// 返回更新后的配置。若触发了迁移，把 migration_run_id 附进响应。
if triggeredMigration != nil { h.pendingMigrationRunID.Store(...) }
h.storageConfigGet(w, r)
h.pendingMigrationRunID.Store("")
```

于是提交 `{"storage_type":"oss","oss_bucket":"my-bucket"}` 会收到：

```json
{"storage_type":"local", "oss_bucket":"", ...}
```

按 playbook **§50 第三问**（「返回值能不能传播给调用方」）——**答案是「能」**。只要调用方对比请求与响应，13 个字段未生效这件事**就在响应里明摆着**。

⇒ **不能称「静默」。** 正确的定性是 **「契约不诚实」**：API 声明支持某字段，行为上不支持，且不报错。

**这一条也成了 playbook §58 的由来**：「静默」是 **「端点 × 缺陷」** 的属性，不是「缺陷」本身的属性。同一个 13 字段丢弃，如果发生在**响应不回显**的端点上，它就是货真价实的静默丢弃。**换个 handler 形状，同一段代码的定级就会翻。**

### 4.2 §41 桶① 不成立 —— 文档没有承诺后台可配

如果 2026-07-15 那份 changelog 写着「在后台配置 OSS」，那就是桶①（承诺已接线 = 缺陷），定级会高一档。实际原文（`:17-18` / `:141-145`）：

> **核心安全保证**：默认行为不变。245/154 当前线上版本的 `.env` 里都没有 `LLM_GATEWAY_STORAGE_TYPE`，升级后行为应当完全一致。

> 1. `build-image.sh` 加 `TAGS="cloudreve_storage"` 之类（按目标 backend）
> 2. `.env` 加 `LLM_GATEWAY_STORAGE_TYPE=cloudreve` + 凭据
> 3. SSH 注入 凭据到 `EnvironmentFile=/opt/llm-gateway-go/.env`
> 4. **业务 owner review** —— 涉及 LLM 网关的存储 backend 切换是 **P1 变更**
> 5. 245 staging soak（含真实 multipart / presign / 大文件 smoke）

⇒ **桶②（明确声明未接线 = 不是缺陷）**。文档是诚实的、甚至是过度小心的。**缺陷只存在于 API 契约面，不存在于文档面。**

## 五、N1 / N2 / N3：三条否定结论（按 §16 分轮登记，不外推）

### N1：`Storage.BaseDir()` 的注释是**对的**，不是缺陷

`storage.go:156-168`：

```go
// BaseDir 返回当前存储根目录（绝对路径）。
// 注意：仅对本地文件系统后端有效，其他后端返回空字符串。
func (s *Storage) BaseDir() string {
	if local, ok := s.GetBackend().(*LocalStorageBackend); ok { return local.BaseDir() }
	return s.baseDir          // ← 看着像"违约"，实际不是
}
```

第一眼像是「注释说返回空串，实现却返回 `s.baseDir`」的文档/实现背离。**但 `s.baseDir` 在远程后端下确实是空的**：`baseDir` 只在 `NewStorage(baseDir)`（`:120`）里赋值，而远程路径走的是 `NewStorageWithBackend(backend)`（`cmd/gateway/attachment_storage_init.go:101` → `storage.go:126-131`），**该构造器不设 `baseDir`**。

唯一的更新点 `SetBaseDir`（`:186-189`）在非 local 后端下**直接 return error**，所以「先 local 构造、后热切到远程」这条路也走不通。

**并且 `SetBackend` 全仓零调用方**（只有 `storage.go:134` 的定义本身；`pkg/georesolve/geo.go:160` 是同名不同包的另一个东西）⇒ 运行时的后端切换**只发生在 boot 期**，不存在「热切换后 `BaseDir()` 撒谎」的窗口。

⇒ **N1 成立：注释成立，不是缺陷。**（记录它是因为我确实先把它当成了缺陷。）

### N2：见 §4.2。

### N3：第二个本地磁盘仓是设计如此

`storage/file/request_mirror.go`（会话 body 镜像）有**自己独立的** `baseDir`（`NewRequestMirror` → `HotZone.Dir`，`:71-77`），**不接入 `StorageBackend` 抽象**。检索该文件：`StorageBackend` / `GetBackendType` / `OSS` / `S3` 全部 0 命中。

这**不是** 162 号意义上的「语义失效」：body 镜像是热区/临时数据，由独立的保留期管理，压根不该跟着附件后端切换。**登记为「有意为之」，防止下一轮有人把它当漏网之鱼。**

⇒ **162 号「其它路径」这条未核，本轮只答了「管理端 API 层」与「body 镜像」两处；全仓其它存储相关路径仍未穷举。**

## 八、playbook §58 新增

> **§58 「静默」是「端点 × 缺陷」的属性，不是「缺陷」的属性 —— 且同一概念存在两个表示时，先查哪个有写入方**

**前半：定级前先看响应体形状。**

判「静默丢弃」时，除了 playbook §50 的四问（日志 / 计数器 / 返回值能否传播 / 注释论证无害），还要再加一问：

> **这个端点的响应体是回显型的，还是自造/空的？**

- **回显型**（本轮 `storageConfigPut` 末尾直接调 `storageConfigGet`）⇒ 差异会自己跑进响应 ⇒ **不静默**。
- **自造型 / 空体 / 只回 `{"ok":true}`** ⇒ 同一个缺陷立刻变成货真价实的静默丢弃。

**⇒ 同一段代码换个 handler 形状，定级就翻。** 因此「静默」必须写成 `端点 A 上的静默丢弃`，不能只写「静默丢弃」。

**后半：一个概念被两个字段表达时，先问「哪个有写入方」。**

不要先去找「读」的那一侧。本轮先看到的是 GET 里 24 行 `case "oss"` / `case "s3"` 读逻辑（很显眼），**先查写入方才发现 0 个**——而那 24 行本身只是症状。

**落地顺序固定为：**
1. `grep '<概念关键词>'` 列出**全部**出现点；
2. 按 **读 / 写** 两栏分开列；
3. **先数写方**（0 ⇒ 那一侧全死，再去谈读的语义）；
4. 写方为 0 时，**去真库确认那些键真的 0 行**（本轮 `settings_kv` 实测 0 行，把「看着像死代码」变成「可证不可达」）。

**同族**：§50（返回值能否传播）/ §16（否定结论分轮登记）/ §41 桶②（明确声明未接线 = 不是缺陷）/ §56（把实现成本问掉再登记）。
