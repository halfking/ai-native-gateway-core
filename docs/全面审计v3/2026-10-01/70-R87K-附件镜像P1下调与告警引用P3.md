## 1. §10 核实过程（三项逐步收窄）

### 1.1 读包围函数

`internal/attachmentmirror/hook.go:36` 是
`func PersistHook(repo *attachments.Repository) func(entry *telemetry.RequestLogEntry)`，
返回的是 **telemetry 后处理钩子**。

### 1.2 读错误分支（关键）

```go
ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
defer cancel()
if _, err := repo.InsertBatch(ctx, rows); err != nil {
    slog.Warn("attachmentmirror: persist into request_attachments failed", ...)
    // P0-2 (audit §3.6 R-3.3): count this lost-row event so the
    // Grafana rule in deploy/.../shadow-write-failures.yaml can fire.
    // The primary request_logs INSERT already succeeded upstream — these rows
    // are persisted in JSONB but the relational mirror is missing.
    // No retry: best-effort contract per the package doc above.
    metrics.Global().RecordShadowWriteFailure("attachment")
}
```

**⇒ 注释原文就写着「No retry: best-effort contract」。** 有 WARN、有指标。

### 1.3 读注释指向的告警规则（这一步决定定级）

初查时 `deploy/monitoring/grafana-alerts/shadow-write-failures.yaml` **报不存在** ⇒ 顺藤摸瓜找到真实路径 `deploy/prometheus/alerts/shadow-write-failures.yaml`，内容确认：

```yaml
- alert: ShadowWriteAttachmentFailing
  expr: rate(llm_gateway_shadow_write_failed_total{kind="attachment"}[5m]) > 10/60
  for: 5m
  summary: "attachmentmirror hook writing >10/min into request_attachments"
  runbook: "Check request_logs vs request_attachments row counts; if divergent, file incident."
```

**⇒ 告警存在、表达式正确、runbook 可执行。这不是「静默丢失」。**

### 1.4 与 `sessionv2mirror` 的差异是有意的

`internal/sessionv2mirror/` 有 `outbox.go` / `replay.go` / `backlog.go` 三件套，而 attachmentmirror 没有。**但这是设计差异不是疏漏**：

- `sessionv2mirror` 的产物是**用户要读的数据**（会话列表/详情），缺失 = 用户可见的数据丢失；
- `attachmentmirror` 的产物是**关系化镜像**，`request_logs` 的 JSONB 里**本来就存着**同一批附件（注释原文：「The primary request_logs INSERT already succeeded upstream — these rows are persisted in JSONB but the relational mirror is missing」）；
- 且 telemetry 钩子有 **500ms 超时**与 **30s flush 预算**的硬约束，塞不进 outbox 重放。

**⇒ playbook §2 声称的「mirror_outbox 失败登记+重放」是 session 镜像的契约，不适用于 telemetry 镜像路径。** 59 号把两者当成同一契约来比，是一次**契约错配**。

**定级：P1 → P3**（降为「有意设计的 best-effort，契约需在 playbook 里写明边界」），并**不修**。

## 4. 一次「复核救了场」的记录

第一次全仓替换时我用了 `grep ... | head -3` 做复核，**它把结果截断到 3 行**，看起来「已清」。实际上第一次替换（只针对 `shadow-write-failures` 字面量）漏掉了 3 处——因为**首次 grep 也被 `head -5` 截断了**，我没看见全部命中。

**⇒ 这是本会话第 8 次「假 0 命中 / 截断导致的假干净」**（前 7 次：搜错范围 2、变异没生效 3、判据量了代理量 1、判据自证漏洞 1）。

**教训**：`grep | head -N` **不是清空判据**——它会同时隐藏「还没改完」和「本来就没有」两种完全不同的情况。**清空类断言必须用计数**（`| wc -l`）或去掉 `head`。
