# 78 号报告：R88-k 关闭 R88-i 自列的未验证项 —— 5XX 恢复窗口在**所有**执行器上成立

- 承接：76 号 §5「未穷举 20 类 executor 各自构造 `upstream.Error` 时是否都填 `StatusCode`」

## 0. 结论先说

**未验证项关闭，76 号的结论没有被推翻。**

- `domains/streaming/executors/` 内 `&upstreampkg.Error{` 构造点共 **52 处**：
  **42 处填了 `StatusCode`**，**10 处没填**；
- **10 处逐一核实，全部正当**——要么本就拿不到 HTTP 状态（网络层失败、`resp == nil`），
  要么是入参校验类错误（`KindClientBug`），要么是刻意合成的 skip；
- 其中唯一「与路由决策相关」的一处（`executor_ollama.go:1297`，`resp == nil`）
  **已显式钉 `Kind: errorsx.KindUpstreamDown`** ⇒ 经 `classifyExecError` 的
  `ue.Kind != ""` 分支直接落回中央策略，**行为与有 StatusCode 时一致**。

⇒ **「裸 5XX 走 `ActionWaitRecovery` + 同节点有界重试」在全部执行器上成立。**

## 1. 核实方法

用脚本提取每个 `&upstreampkg.Error{` 的完整花括号块（跨行直到括号配平），
检查块内是否出现 `StatusCode`，再**逐个人工读**那 10 处缺 `StatusCode` 的上下文
（读包围函数 + 确认当时手上有没有 HTTP 响应），符合 `conventions.md` §10。

数法可复现：

```python
pat = re.compile(r'&upstreampkg\.Error\{')
# 逐行命中后向下收集到括号配平，判 'StatusCode' in block
```

## 2. 10 处逐一归因

| 位置 | `Kind` | 为什么正当 |
|---|---|---|
| `executor_anthropic.go:549` | `KindToolCallIdMismatch` | IR 反序列化解析错，**不涉及 HTTP** |
| `executor_anthropic.go:606` | `KindToolCallIdMismatch` | IR 序列化解析错，**不涉及 HTTP** |
| `executor_anthropic.go:1074` | `ClassifyError(doErr)` | `httpClient.Do` 返回 `doErr` ⇒ **无响应体、状态不可得** |
| `executor_anthropic.go:1407` | — | 同族 retryable 包装，无响应 |
| `executor_chat.go:896` | `kind` | 同上，`httpClient.Do` 的网络层失败 |
| `executor_dispatch.go:1016` | `KindUnsupportedFeature` | **刻意合成的 skip**（无 executor 分支，主动跳过候选） |
| `executor_ollama.go:1053` | `ClassifyError(doErr)` | `http.DefaultClient.Do` 网络层失败 |
| `executor_ollama.go:1297` | **`KindUpstreamDown`** | `resp == nil \|\| resp.Body == nil` ⇒ 状态不可得；**但 Kind 已显式钉住**，经 `ue.Kind` 分支落回中央策略 |
| `executor_ollama.go:1408` | `KindClientBug` | 入参校验：上游 body 为空 |
| `executor_ollama.go:1457` | `KindClientBug` | 入参校验：入参有 trailing JSON |

**规律**：凡「拿得到 HTTP 状态」的路径（52 处的 42 个）**一律填了 `StatusCode`**；
拿不到的 10 处要么是网络层、要么是校验类、要么是合成 skip。
**没有出现「状态拿得到却漏记」的路径。**

## 3. 顺带确认的对照：`upstream` 包自身

`upstream/client.go` 的 5 个构造点（`:363`、`:379`、`:385`、`:387`、`:490`）
**全部填 `StatusCode`**，且 `StatusCode` 字段注释明写「0 for pure network errors
like connection reset」⇒ 字段契约与实际用法一致。

## 4. 这条为什么值得单独记

76 号把「`classifyExecError` 对 5xx 的归类」列为**实施前必须先答**的未验证项，
理由是「若某类 executor 漏填 `StatusCode`，5XX 就走不到中央策略的那条分支」。
**这正是可能推翻 76 号结论的路径**，所以值得真去查而不是略过。

结果：**这条推翻路径不存在**。⇒ 76 号的「待裁决第 31 条作废」**保持有效**。
