## 6. 【R88-l 补】§5 第 2 项未验证项已关闭：`retryableError` **不绕过**分类

### 6.1 它能穿透

`executor.go:3474-3485` 的 `retryableError` 实现了 `Unwrap() error`：

```go
func (e *retryableError) Unwrap() error { ... return e.err }
```

而 `classifyExecError`（`executor.go:3557`）用的是 `errors.As(err, &ue)`
⇒ **能穿透包装层拿到内层 `*upstream.Error`**，不会丢 `StatusCode` / `Kind`。

### 6.2 但真正要问的是：有没有代码据此**自己重试**从而绕过中央策略

全仓仅 2 处断言 `*retryableError`（排除 vendor）：
`executor_chat.go:1993` 与 `executor_anthropic.go:912`，**结构完全同构**：

```go
lastErr = tryErr
if _, ok := tryErr.(*retryableError); !ok {
    return nil, tryErr        // 非 retryable → 立刻上抛
}
// retryable → 继续下一轮同凭据重试
```

⇒ **存在两段式重试，两段都在**：

| 层 | 行为 | 等待 |
|---|---|---|
| **executor 内** | 对 `*retryableError` 做**同凭据有界重试**（`executor_chat.go:622` `effectiveOpenAIRetryBudget(maxRetries, params.DispatchAttempt)`；dispatch 尝试时预算被采信，否则退化为 1） | **无**（该循环内无 sleep） |
| **dispatch 层** | 错误逃逸后 `classifyExecError` → `PlanAfterFailure` → `DecideNextAction`：5XX 走 `ActionWaitRecovery`+`RetryAt` 或同节点有界重试 | **有**（队列 park + `retry_at`） |

⇒ **不是绕过，是分层**：executor 层给「立刻再打一次」，dispatch 层给「等一会儿再换节点」。
76 号的结论**再次成立**。

### 6.3 这反而补强了 76 号

一个瞬时 5XX 的实际待遇是：**N 次同凭据立即重试 → 仍失败则获得一个恢复窗口 → 再换凭据/模型**。
这比 R88-g 里 9router 的「一次短等待就换账号」**多了一层同节点重试**。
