## 二、🔴 F2：代码注释白纸黑字写着这件事，但没人解决

`ratelimit/scope.go:13-16`：

```go
// GatewayRateLimitScopeSharedKey means the caller API key itself was rejected
// by local gateway admission. **Credential self-check requests all use the same
// worker API key, so this scope is shared across credentials.**
const GatewayRateLimitScopeSharedKey = "shared_key"
```

`:18-20` 再说一遍：

> **Self-check workers share one API key across credential probes, so this signal has worker-wide scope.**

**⇒ 作者完全知道「自检请求共用一个 worker API key」。**
**⇒ 但这个设计有一个他没有解决的后果：自检流量与被自检的凭据共享同一份 RPM 配额 ⇒ 自检会把自己限流。**

`handler.go:3229-3234` 是被打断的地方：

```go
if rlOutcome.Blocked {
    recordGatewayRateLimitRejection(rlOutcome)
    captureAndEmitRateLimited("rate_limit_exceeded", "rate limit exceeded", nil, nil)
    ratelimit.MarkGatewaySharedKeyRateLimit(w)
    writeErrorJSONCtx(r.Context(), w, http.StatusTooManyRequests, requestID, "rate_limit_error", …)
    return   // ← 直接 429 返回，自检拿不到任何探测结果
}
```

**⇒ 自检一旦撞上自己的闸门，那一轮探测就完全没有结果、没有冷却状态更新、没有错误分类。**

**⚠️ 佐证（口径不同，只作量级参照）**：`origin_stage='self_check'` 的行**只有 184 行**，
而同一子系统的限流拒绝有 **326,126** 次。**两者相差三个数量级。**
⚠️ **诚实边界**：这两者**不是同一口径**（184 行是「被标记为 self_check 的成功/落库行」，
326,126 是「被限流的请求行」），**不能直接相减**；但**量级差本身说明自检在 09-22→09-26 期间基本没跑起来**。

## 六、playbook §64 新增

> **§64「配了闸门 + 从不触发」有两种解释，必须用「那个 key 到底有多少流量」分辨**

**由来**：本轮我统计出 `budget_exhausted` / `tpm_limit_exceeded` / `concurrent_limit_exceeded`
在生产**全是 0 行**，而 `api_keys` 里**确实有 6 / 2 / 1 个 key 配了这些阈值**
—— 组合起来非常像「闸门配了但从不生效 = fail-open 坏了」。

**去查那 8 个 key 的实际请求数**：513 / 10 / 1 / 0 / 0 / 0 / 0 / 0。
**⇒ 「0 触发」被「几乎没流量」完全解释 ⇒ 不是缺陷。**

**⇒ 判别公式：**

```
「0 触发」的两种解释：
  (a) 闸门没生效  ⇒ 该 key 的实际流量 ≫ 阈值，却一次没触发   ← 缺陷
  (b) 没流量      ⇒ 该 key 的实际流量 ≪ 阈值              ← 正常
⇒ 必须查「该 key 的实际请求数 / token 数」，再和阈值比
```

**⇒ 与既有条目的关系**：
- **§16**「0 行不等于缺陷」是**结论**（不要发条目）；
- **§64** 是**§16 的执行方法**（怎么证明 0 行是正常的）；
- **§52** 是**定级纪律**（机制成立 ≠ 发 P1）。

**⇒ 顺带记一条「未解项的登记纪律」**：
本轮 F4 出现了一个我**查了两层还没查清**的问题（NULL 阈值为何仍限流）。
**正确做法是把它写进报告的「未解项」并排进下一轮顺位，而不是：**
① 猜一个最可能的解释写进结论；② 或者干脆不提（那会让「40 万次限流」看起来像已完全解释）。
**⇒ 报告里允许、并且应该出现「我不知道」这句话。**
