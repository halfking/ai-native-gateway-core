### ② `admin/session_bodies_batch.go:139` —— 扫描器的**第六个 bug**

```go
func acquireBodyFetchSlot(ctx context.Context) (func(), error) {
	select {
	case bodyFetchGate <- struct{}{}:
		return func() { <-bodyFetchGate }, nil
	default:
	}                                    // ← 块是空的，但代码继续往下走
	if err := ctx.Err(); err != nil { return nil, err }
	return nil, ErrBodyFetchSaturated     // ← :144 明确返回饱和错误
}
```

注释写明：**「调用方应快速失败（503）而不是继续占用连接」**。
⇒ **这是全链路最响的信号之一，被我的分支提取判成了「空 default = 静默丢弃」。**

⚠️ **第六个 bug 的形态值得单独记**：`default:` 块为空**不等于**「select 结束后直接结束」——
**Go 的 select 不是语句块作用域，块外的代码照样执行**。
⇒ 扫描器必须判断「select 之后还有没有可达代码」，否则会把「空 default + 落到 select 之后」
与「空 default + 函数结束」混为一谈。

## 三、本条线的结论：一条有意义的**否定结果**

**跨 3 轮、约 1,700 个生产 `.go` 文件，把「静默丢弃」从 61 收敛到 0 个确认缺陷。**

- 61 处里 **35 处是分类器把「接收」当「发送」**；
- 剩下 26 处里 **9 处包裹函数本来就有计数器**、**7 处把错误返回给了调用方**、**10 处有注释自证无害**、**1 处是分类器误判**。
- **真正「无日志 · 无计数 · 无返回值 · 无注释论证」的站点：0 个。**

⚠️ **这不等于「本仓不存在静默丢弃」**，它只等于：
**「非阻塞 channel 发送被拒」这一形态，在本仓已经被写好或已被调用方感知。**
本仓若真有静默丢弃，形态更可能在 **153 号报告 §七 点名的 `if !Enqueue() { return }` 这类无 select 写法**——
⚠️ **那一类至今未普查**，如实登记为待查。

**这个否定结果本身有价值**：
它把「异步 best-effort 写入器丢数据没人知道」这个**听起来很严重的担忧**，
在**有日志可查的整个 70 站点（153 号）+ 无日志的 61 站点（本条线）两个面上同时证伪了**。
⇒ §30「不可达的不是缺陷」的同族结论：**不是缺陷的东西，也不能靠「听起来像缺陷」立项。**
