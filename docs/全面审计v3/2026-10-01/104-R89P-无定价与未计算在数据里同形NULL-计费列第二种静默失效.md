## 0. 一句话

103 号查出 `cost_usd` 会**算成负数**。本轮查出它**还有第二种静默形态**：
**目标没有可用定价时，`CalcCost` 直接返回 nil ⇒ `cost_usd` 落库为 NULL
⇒ 不计费、不告警、无指标、无标记。**
**而「本来就没配价」与「我们忘了算」在数据里长得一模一样。**

## 1. 真库量化（`llm-gateway-pg` / `llm_gateway`）

### 1.1 量纲上界核对先行

`usage_ledger_hot` 与 `request_logs_hot` 各 **2435** 行，两者相等；
所有子集计数均 ≤ 2435，且内部自洽（309+12=321 ✓）。
**计数可信**——这与 97 号记录的「Citus 列存 join 返回超表规模」是不同对象
（本次为**堆表**上的单表聚合，未跨列存分区 join）。

### 1.3 关键一步：不是 token 缺失，是**定价缺失**

抽样这批「成功但无金额」的行：

| 模型 | 样本数 | `prompt_tokens` 为 NULL | `completion_tokens` 为 NULL |
|---|---|---|---|
| kimi-k3 | 39 | **0** | **0** |
| deepseek-v4-pro | 28 | **0** | **0** |
| glm-5-2-260617 | 27 | **0** | **0** |
| kimi-k3 | 26 | **0** | **0** |
| glm-5.3 | 22 | **0** | **0** |

**token 全都在。** 所以不是提取失败，回到代码：

`domains/streaming/usage.go:206-209`（`CalcCost`）：

```go
priceIn := floatPtr(input.PriceIn, 0)
priceOut := floatPtr(input.PriceOut, 0)
if priceIn == 0 && priceOut == 0 {
    return nil          // ← 无定价 ⇒ 成本「未定义」⇒ nil
}
```

`AssignRequestCost`（`:255-260`）拿到 nil 就 `return nil, nil, nil`
⇒ `reqLog.CostUSD = nil` ⇒ 落库 `cost_usd = NULL`。

**⇒ 「没有价格」被编码成「成本是未定义的」，然后未定义被编码成 NULL，
最后 NULL 在报表里与一切正常值加在一起。**

## 2. 定性（这是本报告真正要说的）

**必须严格区分两件事：**

| | 状态 | 可信度 |
|---|---|---|
| **A. 代码失效模式** | 无可用定价 ⇒ `CalcCost` 返回 nil ⇒ `cost_usd` NULL ⇒ **不计费、不告警、无指标、无任何标记** | ✅ **无条件成立**，与部署无关 |
| **B. 本实例的量级** | 96.3% 成功请求无金额；`model_offers` 仅 1.8% 有价 | ⚠️ **本实例配置事实**。这是开发实例、仅 8 小时数据、`pricing_source` 普遍未填 ⇒ **很可能是「没配价」而不是「代码算错」** |

**所以我不报「生产少收 96%」——那是把实例配置当成生产结论。**

**但 A 本身就够了**，理由：

1. **它与 103 号是同一类缺陷的两个形态**：`cost_usd` 的两种失效（**负数**、**NULL**）
   **都没有任何可观测信号**。列本身不携带「这个值是怎么来的」。
2. **它会让运维无法自查**：打开费用面板看到金额偏低，
   **分不清是「价格没配」还是「算错了」还是「本来就没这批流量」**——
   三者在数据里完全同形。这正是 101-2（「未定义」坍缩成 0/NULL）的**成本列版本**。
3. **它直接削弱两条已有结论的可信度**：
   - 对账 `gateway_total_cost`（`pg_reconciliation_store.go:199`）对本实例的系统性偏低，
     **一部分可能是漏账而不是供应商差异** ⇒ 101 号并入 F2/F3 的「偏差叠加」还要再加一路；
   - `verifier.go:786` 的预算强制对这部分请求**等于不设防**。

## 3. 建议修法（登记待裁决，本轮不动）

1. **区分「无定价」与「未计算」**：落库时用一个**显式哨兵/枚举**
   （如 `cost_status ∈ {priced, unpriced, unknown}`），**不要用 NULL 兼表两种含义**；
   读回路径**不得 `COALESCE(cost_usd, 0)` 抹平**。
2. **给「已成功但 `cost_status = unpriced`」加指标与告警**：
   `unpriced_success_total{model}` —— 这是纯新增观测，**不改客户端观感**，
   也不改任何现有金额，先让缺口可见。
3. **启动自检**：在 `verifier.go` / `auth.go` 已有的「视图缺失则降级并告警」范式旁，
   加一条「存在已定价能力的模型却无价格」的启动期检查。
4. 103 号的约定判定 + 负值钳制**照旧**（两者与本条互不替代：
   一个修「算成负数」，一个修「根本没算」）。
