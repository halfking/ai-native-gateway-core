### 1.3 R85 必须先回答的三个问题（**以下均未验证**）

1. **「扫描成功 → 进池」这条路在本环境从未走通过**。260/260 失败、catalog 与 quota 全空，最后一次任务在 2026-09-24（7 天前）。要区分三件事：(a) 这是**环境未配**（合理）；(b) 这是**设计使然**——模板要求每家免费厂商各自的 env API key，而网关本来就有这些厂商的**已注册凭据**（`credentials` 表 86 条），扫描器却绕开凭据体系去读 env ⇒ 与 objective「注册、聚合使用，做为一个**标准的供应商池子**来处理」的措辞存在落差；(c) 这是**缺陷**（例如 `trigger_type` / `template_id` 派发错、扫描器本身报错被吞）。**判别方法**：读 `import_service.go` 与 `discovery_engine.go` 的 key 解析来源，再对照 `credentials` 表是否有同厂商凭据；不要只看错误信息就断言设计问题。
2. **同一条错误有两套文案**：`env X referenced by template N is not set`（46 次，模板维度）vs `environment variable X (referenced by provider …)`（18 次，provider 维度）。这暗示**两条 key 解析路径**（或两代实现未收敛）。需确认是「旧路径仍在被调用」还是「不同入口的正常差异」。
3. **`donations` 表 0 行**。它同时出现在 `sql/objects/sequences/donations_id_seq.sql` 与 `idx_donations_status/email`，且有 `donations_donations_holder_id_fkey` 外键 ⇒ 像是更早一代的「赠送额度」实现。要判定它与 `free_resource_catalog` 是**并存双实现**还是**已被替代的遗留**（objective 的「冗余实现标注整理」正指这类）。**这一问只能靠代码 + 迁移历史回答，0 行本身不构成任何结论。**

## 5. 本轮踩到 / 复用的纪律

- **搜错范围拿到 0 命中的第 3、4 次**：本轮 `grep -rniE "free_?(token|quota|pool)|OmniFree|omnifree"` 若不加 `--include=*.go --include=*.sql --include=*.vue --include=*.ts` 并排除 `vendor/`、`docs/`，会被归档文档（`docs/archive/process/omnifree/` 共 12 份）淹没；真正的代码只占命中的一小部分。**判定「某域不存在」前，先确认自己搜的是代码而不是归档。**
- **0 行不是结论**：`free_resource_catalog` 0 行、`attachments` 0 行、`discovery_results` 0 行，三者都同时兼容「缺陷」「未部署」「未配置」三种解释。本文因此把所有 0 行都写进「待验证」而非「已判定」。
- **`web/src/router/` 目录不存在**这件事本身是「按惯例猜路径」的又一次失败（曾按 Angular/Vue 惯例找 `router/`）。**先 `ls` 再 grep。**
