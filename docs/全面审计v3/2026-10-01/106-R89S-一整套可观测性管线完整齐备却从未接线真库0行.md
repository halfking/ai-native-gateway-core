## 2. 定级 **P2**，理由与边界

**不是 P1**，因为：
- **无数据面影响**：业务请求、计费、会话、响应全部正常；
- 7 个端点**本身是好的**，只是它们外面的那层包装是空转。

**是 P2**，因为：
1. **objective 第 21 项「可观测性」有一个面永久空白，而且不自知**——
   代码里有一层 `serveDashboardAPI` 包装、有 nil 保护，
   **读起来像是接好了**，实际是死路（这正是 playbook §13 的形态）；
2. **运维成本真实存在**：`PartitionManager` 每个周期都在 promote 一张**永远 0 行**的表，
   8 小时保留策略也在跑；
3. **修复成本极低**：一次 setter 调用即可接通（第 6 节）。

**边界说明（不夸大）**：我**没有**查到前端是否有面板在读这些统计。
若前端确实没接，则本条降为 P3（纯冗余能力）。
**这一项需要下一轮核前端**——但无论前端接没接，
「管线齐备却零接线 + 真库 0 行」这个事实本身都成立。

## 4. 与既有条目的关系

这**不是** 105 号那种「假阳性」——105 号证伪的是「路由未挂载」，
而本条是**真的没接**，只是**没接的环节比子代理描述的更靠后**：
路由树是好的、包装层是好的、连 nil 保护都写好了，**只差注入那一下**。

**⇒ 这正好说明「B 类 vs A 类」的判定必须看到最后一环**：
105 号的子代理把「类型外部引用为 0」直接判成 A 类（删），
而正确答案是 B 类（接）——**差一次向上追踪的深度**。
