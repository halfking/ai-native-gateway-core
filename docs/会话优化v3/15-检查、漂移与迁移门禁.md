## 5. 漂移检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 入口存在 | 文档路径和符号在代码中存在 | 回到 `12` 修订事实 |
| migration 安全 | DROP/ALTER 顺序和 schema 目标一致 | CRITICAL，禁止部署 |
| 状态可信 | CURRENT 具有代码+测试或 runtime 证据 | 降为 CURRENT-PARTIAL |
| 数据源一致 | online timeline 明确 hot/V2/merged 口径 | 禁止称完整 |
| 租户边界 | 每张派生表/API/event 有 tenant 证据 | 阻断 |
| 事件幂等 | event_id/idempotency key/replay 有测试 | 阻断 |
| 人工优先 | 重跑不覆盖 override，有 undo/revoke | 阻断 |
| 回滚闭环 | flag off、停 worker、重建 projection、保留原事实 | 不部署 |
| 逻辑点粒度 | 每点 ≤300 行预估且可独立验收 | 重新拆分 `14` |

## 6. 发布状态定义

- `DESIGN`：只有设计，没有实现证据；
- `CURRENT-PARTIAL`：部分代码/路由/迁移存在，但至少一个运行时或契约门禁未过；
- `CURRENT`：代码、测试、真实环境、权限/安全和回滚证据齐全；
- `SHADOW`：worker/投影运行但不影响既有读写；
- `MIGRATION-GATE`：等待数据库、RLS、数据对账或部署证据；
- `MIGRATION-BLOCKED`：发现 schema 目标、执行顺序、tenant/RLS 或回滚存在阻断问题；
- `RELEASED`：仅在所有阻断门禁通过且有版本化验收报告后使用。
