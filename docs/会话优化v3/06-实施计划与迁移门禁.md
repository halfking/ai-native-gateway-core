# 实施计划与迁移门禁

## 1. 阶段总览

| 阶段 | 目标 | 默认状态 | 影响请求路径 |
| --- | --- | --- | --- |
| V3-P0 | 基线、脱敏、输入契约、事件和 shadow worker | `TARGET` | 无 |
| V3-P1 | 会话语义卡片：标题、摘要、意图、候选标签、实体 | `TARGET` | 无 |
| V3-P2 | 边界、聚类、stable project 和人工 split/merge | `TARGET` | 无 |
| V3-P3 | 关系图、长期记忆和跨会话检索 | `TARGET` | 默认无；需单独门禁 |
| V3-P4 | 数据集、自动评估、漂移监测和有限自动化 | `TARGET` | 无；记忆注入另立 RFC |

## 2. V3-P0：基线和契约

**输入**：`request_logs`、V2 turns/bodies、现有 terminal 事实。  
**输出**：规范化 turn、脱敏策略、`input_hash`、事件 envelope、最小 worker、失败/DLQ、指标。

完成条件：

- 对账 request/turn 数量和关键字段；
- tenant、正文引用、retention 和 RLS 契约冻结；
- `analysis.requested/completed/failed` 可幂等 replay；
- worker 失败不影响 canonical request；
- feature flag 默认关闭或 shadow；
- 记录成本、延迟、队列积压和脱敏命中。

回滚：停止 consumer、保留 canonical/outbox，删除/重建 projection，不删原始事实。

## 3. V3-P1：语义卡片

**输入**：规范化 turn。  
**输出**：summary/title/intent/entity/event、任务/项目/岗位候选、evidence 和模型版本。

门禁：

- LLM 不可用时规则摘要和 `unknown` 正常返回；
- 结构化 JSON 解析失败不会写 accepted；
- 每个结果有 input hash、source、version、freshness；
- 与现有 title/summary 读 API 做双读对比；
- 不把 `task_type`/`work_type` 自动升格为人工事实。

灰度：按 tenant allowlist → 1% → 10% → 50% → 全量 shadow；任何阶段都可停 worker。

## 4. V3-P2：聚类和人工闭环

**输入**：语义 embedding、边界候选、P1 结果。  
**输出**：cluster runs、membership candidates、stable project、override events、current projection。

门禁：

- cluster run 可重跑且历史不被覆盖；
- noise 和低置信结果可保留；
- split/merge/undo 幂等、权限正确、审计齐全；
- 模型重跑不得删除人工 override；
- current projection 可从事件重建并与在线结果对账；
- 跨租户 session/project/member 查询全部负向通过。

回滚：切换 `semantic.read_mode=legacy`，停止写 projection；保留 cluster run 和 override 供调查。

## 5. V3-P3：关系和长期记忆

**输入**：已确认标签/实体/关系。  
**输出**：时序关系、记忆候选、作用域检索和外部 adapter。

额外门禁：

- memory scope 明确为 session/apiKey/global 或等价租户边界；
- 访问衰减、删除、legal hold、撤回和重新索引可解释；
- graph/vector/memory 不可绕过 Gateway tenant authorization；
- 外部服务不可用时只降级为本地关系/lexical 检索；
- 默认不把候选记忆注入请求，注入另需 latency、质量和安全评审。

## 6. V3-P4：评估和自动化

**输入**：人工标注、golden set、线上结果。  
**输出**：离线回归、阈值校准、漂移告警、模型/规则版本选择。

自动化只能在通过评估阈值、人工审查和灰度回滚后启用；任何标签 taxonomy 或 stable project 自动变更都要有变更事件。

## 7. 迁移门禁矩阵

| 门禁 | 证据 | 不通过时 |
| --- | --- | --- |
| Schema/up-down | migration、备份、down rehearsal | 不部署 |
| RLS | real PG + NOSUPERUSER/NOBYPASSRLS | 只允许本地 fixture，不上线 |
| 跨租户负向 | API/SQL/worker 测试 | 阻断 |
| 幂等/replay | 重复 event、网络重试、worker restart | 阻断 |
| 正文最小化 | secret scan、payload snapshot、脱敏测试 | 阻断 |
| projection 对账 | canonical/result/event 重算 diff | 只 shadow |
| 延迟/成本 | worker p95、LLM/embedding budget | 降级或停用 |
| 外部故障 | timeout、503、DLQ、fallback | 不允许影响请求 |
| 人工审计 | actor/reason/scope/undo | 禁止写操作 |
| 删除/保留 | retention/legal hold/reference check | 禁止物理清理 |
| 部署/回滚 | staged rollout、flag off、projection rebuild | 不扩大灰度 |

## 8. 推荐 feature flags

```text
LLM_GATEWAY_SEMANTIC_PIPELINE_ENABLED=false
LLM_GATEWAY_SEMANTIC_SHADOW=true
LLM_GATEWAY_SEMANTIC_EMBEDDING_ENABLED=false
LLM_GATEWAY_SEMANTIC_CLUSTER_ENABLED=false
LLM_GATEWAY_SEMANTIC_MANUAL_WRITE_ENABLED=false
LLM_GATEWAY_SEMANTIC_MEMORY_INGEST_ENABLED=false
LLM_GATEWAY_SEMANTIC_MEMORY_INJECT_ENABLED=false
```

配置必须有来源、默认值、租户覆盖、审计和运行时读取规则；不能仅存在环境变量而没有 effective config 记录。

## 9. 回滚顺序

1. 关闭记忆注入；
2. 关闭外部 graph/vector adapter；
3. 将查询切回 legacy/旧 projection；
4. 停止 worker consumer，保留 outbox/DLQ；
5. 重新构建或标记 stale projection；
6. 仅在 retention/legal hold/引用检查通过后清理派生数据；
7. 原始 `request_logs`、V2 turns/bodies 不回滚、不删除。
