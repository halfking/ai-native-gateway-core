# 会话优化 v3

> 状态：`TARGET` / 方案基线（不代表生产已接线）  
> 更新时间：2026-07-28  
> 适用范围：`llm-gateway-go` 会话语义、归类、聚类、关系、记忆与评估闭环

## 1. 这套文档解决什么问题

v3 将会话优化定义为一条可回放的语义管线，而不是一个单独的“摘要接口”：

```text
request_logs / gateway.session_turns
        │
        ▼
规范化 turn、脱敏、输入指纹
        │
        ├── 摘要 / 标题 / 意图 / 实体 / 事件
        ├── 任务 / 项目 / 岗位候选标签
        ├── 时间边界与语义聚类
        └── 记忆候选与统计事实
                │
                ▼
人工确认、拆分、合并、纠错、撤销
                │
                ▼
版本化事实 + 投影 + 向量/图索引 + 可重算统计
```

目标同时覆盖：

- **会话理解**：知道会话在做什么、涉及什么实体、完成到哪一步；
- **会话组织**：把混杂会话拆成任务/项目，把相似会话归为可解释主题；
- **记忆增强**：把摘要、事实、程序性知识按类型和作用域保存并可检索；
- **数据闭环**：人工修正可追溯，模型版本可比较，统计可以从事实重算。

## 3. 状态标签

- `CURRENT`：生产代码/SQL/wiring 已证实存在；
- `CURRENT-PARTIAL`：存在实现，但有明确缺陷、占位、旁路或未完成接线；
- `TARGET`：本 v3 设计目标；
- `NOT-WIRED`：已有表、接口或提案，但没有证明生产链路正在使用；
- `MIGRATION-GATE`：只有通过门禁后才能宣称已上线；
- `HISTORICAL`：历史快照，只用于追溯。

源码、SQL、启动 wiring、真实数据库测试的优先级高于设计文档。每完成一个阶段，必须先更新基线和执行记录，再更新宣传性文档。

## 4. 与既有方案的关系

- V2 的正式存储表是 `gateway.sessions`、`gateway.session_turns`、`gateway.session_bodies`、`gateway.session_turn_logs`；v3 消费这些事实，不替换 turn/body writer。
- 根仓 `docs/拆分/23–31` 定义了 session ownership、事件 envelope、租户隔离、RLS 和迁移门禁；v3 遵守这些边界。
- `request_logs` 仍是当前已落库正文事实源；V2 是否完成 ownership 切换，以真实 wiring 和门禁为准。
- `session_clusters`、`session_cluster_members`、`session_titles`、`session_state_snapshots` 和现有摘要/聚类 API 是可复用的 CURRENT/CURRENT-PARTIAL 能力，但不能直接当作完整的 v3 语义事实层。
- OmniRoute 的记忆/向量能力作为外部能力参考和可选 consumer，不把其实现状态误写成网关生产能力。

## 5. 非目标

v3 第一阶段不做以下事情：

- 不在 relay 热路径同步调用 LLM、embedding 或图数据库；
- 不直接覆盖或删除 `request_logs`、V2 turns/bodies 原始事实；
- 不把一次聚类结果永久当作稳定项目实体；
- 不承诺外部开源项目可以直接提供完整的“导入历史—分类—拆分/合并—图谱—记忆”产品闭环；
- 不用 ROUGE 单独证明摘要正确，不用聚类数量单独证明项目归类正确。

## 6. 一句话决策

采用“规则与既有字段兜底 + embedding 候选召回 + 受限 LLM 判别 + 可解释聚类 + 版本化人工覆盖 + 可重算投影”的混合架构；分析旁路异步、原始事实不可变、人工事实优先、所有结果带租户和输入指纹。
