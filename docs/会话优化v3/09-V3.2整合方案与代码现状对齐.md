## 3. ADR 增补（V3.2）

### ADR-V3-101：后端合流，单 SSE 出口

首页实时请求流保持单 SSE 连接 `/api/admin/live-stream`。节点状态、队列快照、子请求树全部并入现有 envelope（扩展 `initial_data`/`health_update`，新增 `queue_snapshot`/`node_update` 消息类型），**不**新建 SSE Hub、**不**让前端多连接合流。理由：协议统一、状态一致、前端简单。

### ADR-V3-102：复用 request_id / parent_request_id 作为唯一关联键

主从请求、状态变更历史、trace 全部以 `request_id` + `parent_request_id` 关联，不引入新的链路 ID。理由：底层贯穿机制已存在（`middleware/requestid_mw.go`、`internal/trace`）。

### ADR-V3-103：节点状态以 credentialhealth/circuit 为唯一真相

live-stream 的节点矩阵只**投影** `circuit`/`credentialhealth`/`quota` 的现有状态，不维护第二份状态。理由：避免状态漂移。

### ADR-V3-104：可观测性写入旁路异步

队列指标、状态变更历史、子请求查询全部旁路异步，不阻塞 relay 主链路（继承 ADR-V3-001）。写失败只记日志。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| live-stream envelope 扩展导致前端兼容问题 | 新字段全部 optional；前端渐进增强，旧字段不变 |
| 节点状态推送频率过高 | 状态变更才推送 + 2s 快照节流 |
| 子请求查询拖慢 SSE | 异步查询 + 深度≤3 + P95<50ms 验收 |
| 状态变更历史表膨胀 | 7 天清理任务（BE-B1） |
| 队列指标开销 | benchmark < 5% 门禁（BE-A1） |
