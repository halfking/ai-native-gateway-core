## 0. 任务分解总览

本文档将 [20 号文档](./20-统一可观测性平台需求分析.md) 中的方案拆解为 **5 个可并行的子任务**，每个任务都有明确的：

- **输入**：前置依赖 + 需要的文档/代码
- **输出**：产出的代码文件 + 测试用例 + 文档
- **验收标准**：功能 checklist + 性能指标
- **工期估算**：开发时间 + 测试时间

## 1. 任务拆分（5 个子任务）

### Task 1: Dispatch 队列状态暴露与时间戳增强

**负责模块**: 后端 - dispatch + telemetry  
**依赖**: 无  
**工期**: 3 天  
**优先级**: P0

| 子任务 ID | 描述 | 工期 |

| **T1.4** | 在 dispatch 各阶段插入时间戳记录点 | 1 天 |
| **T1.5** | 单元测试 + 集成测试 | 0.5 天 |

#### 1.3 输入

- **前置文档**:
  - [v2/57-多层队列调度架构设计方案.md](../会话优化v2/57-多层队列调度架构设计方案.md)

## 3. 风险与缓解

### 3.1 时间风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **Task 1 时间戳插入点遗漏** | 9 阶段时间戳不完整 | 🟡 中 | 1. 详细代码审查<br>2. 集成测试覆盖所有阶段 |
| **Task 5 前端性能调优超期** | 1000+ 请求卡片渲染卡顿 | 🟡 中 | 1. 优先实现虚拟滚动<br>2. 设置性能预算（30 FPS） |
| **Task 2/3/4 API 设计变更** | 前端需要返工 | 🟢 低 | 1. Phase 1 结束后 API 冻结<br>2. 先实现 Mock API 供前端开发 |

### 3.2 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **SSE 带宽暴增** | 新增字段导致事件体积 ×3 | 🟡 中 | 1. 队列状态仅推送变化（delta）<br>2. Feature Flag 灰度 |
| **会话查询慢** | 1 万活跃会话查询 > 1s | 🟢 低 | 1. Redis 缓存热数据<br>2. 增加 DB 索引 |
| **节点测试并发过载** | 批量测试导致节点故障 | 🟢 低 | 1. 测试限流（1 req/s）<br>2. 测试超时短（10s） |
