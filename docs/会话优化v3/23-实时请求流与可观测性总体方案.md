## 2. 架构原则（继承并强化既有 ADR）

1. **单 SSE 出口**（ADR-V3-101）：一切实时数据并入 `GET /api/admin/live-stream` envelope，不新建 Hub。自检事件复用 `admin/probe_stream_sse.go` 独立出口 `GET /api/admin/probe/stream`（自检 tab 专用），但节点状态投影仍走主流 `node_update`。
2. **投影不复制**（ADR-V3-103）：节点状态只投影 circuit/credentialstate/quota/fpslot 权威状态，SSE 层不维护第二份状态机。
3. **管道两端解耦**：客户端请求（inbound：协议、模型名、会话）与上游转发（outbound：节点、凭据、协议适配）是两个独立的可观测维度。一个 inbound 请求可因 auto 模式或节点不可用而依次落在多个模型队列与多个节点队列中——所有落点都是同一 request_id 下的动作事件，而不是新请求。
4. **主从关联键**：`request_id` / `parent_request_id`（`request_logs_hot.parent_request_id`，扩展请求带 `X-Gw-Parent-Request-Id` / `X-Gw-Source-Actor` 头）。不引入新 ID 体系。
5. **可观测写入旁路异步**：事件埋点不得阻塞请求热路径；Redis 队列满即丢 + 计数（继承 Stats 非阻塞原则）。
6. **安全红线**：正文、API key、系统 prompt 不得进入 SSE（继承 13 号契约 §3）。

## 4. 关键设计决策

### 4.1 动作事件（R2）以 request_id 为主键的 append-only 流
- 每个动作 = `{request_id, seq, action, ts, model?, credential_id?, error_kind?, retry_seq?, detail?}`。
- 动作枚举与 trace 阶段对齐：`arrive / route_resolved / model_enqueued / credential_selected / node_enqueued / node_selected / node_switch / upstream_request / first_byte / reply / retry / state_change / failover_model / no_route`。
- 重试（retry）与节点切换（node_switch）在前端打特别标（角标/描边），与普通动作区分。
- 前端按 request_id 聚合成"请求卡"，卡内按 seq 展示动作时间线（大形态）；队列视图里只显示当前所在队列与最新动作（小形态）。

### 4.2 三层队列展示（R1）
- 总队列（pipeline）→ 模型队列（model，含 auto 桶）→ 节点队列（credential）。
- 请求卡片在三层之间的迁移通过动作事件推导，不由前端猜测。
- 现状基线：`QueuePerspectivePanel.vue`（V3.2 FE-A1）已渲染三层深度 + 节点摘要，数据来自 `queue_snapshot`；`RequestProcessingTrail.vue` 渲染最近请求轨迹。

### 4.3 节点操作面板（R3）
- 每个节点行：状态徽标（circuit/availability/quota/manual_disabled 四合一）+ in-flight + 最近延迟 + 最近错误。
- 行内动作：`test-now`（受控探测，不改长期状态）、强制启用/手工禁用（走 `PATCH /api/routing/emergency-repair`）、清除熔断、重置错误。
- 两种禁用必须区分展示：**手工禁用**（manual_disabled，需人工恢复）与**系统降级**（availability/quota/circuit 自动态，到期或探测成功自动恢复）。

### 4.4 会话与统计（R5）
- 层级：用户 → 项目/任务 → 会话（session_key）→ 轮次（turn）→ 附属请求（title/summary/sensitive_word，与轮次并级，经 parent_request_id 关联）。
- 现状基线：`SessionStatsPanel` / `SessionTurnsPanel` / `SessionTurnDrawer` 已存在；在线会话来自 Redis 索引（`admin/session_online.go`），timeline 读 `request_logs_hot`（CURRENT-PARTIAL，见 12 号 §3）。
- 目标：轮次时间线中内联展示该轮的主请求 + 子请求树（R4 与 R5 在此汇合）。

### 4.5 自检队列展示规则（R8）
- 自检请求与业务请求同构渲染，但使用小形态卡片 + `probe` 徽标，从视图右侧进入（与实时请求流一致的方向）。
- 三态流转：计划生成 → `pending`（待请求队列）→ `in_flight`（正在请求，系统按参数生成真实探测请求）→ `completed`（已完成队列）。
- 智能回退（active probe backoff 链）场景：只生成第一个自检需求；后续定时自检在到期时才入执行队列，不长期占用待请求队列（见 25 号 §6.2）。

## 5. 非目标（本期）
- 不重构 probe-stream 为独立大屏（保持独立出口，只投影节点状态进主流）。
- 不做 V3.0 语义层（semantic_sessions/turns）接线（沿用 12 号缺口排序）。
- 不新建第二套节点状态存储。

## 6. 成功指标（继承 20 号 §9）
- SSE 推送延迟 ≤500ms；队列深度查询 ≤100ms；会话列表 ≤200ms；1000 卡片 ≥30FPS。
- 稳定性 ≥99.5%（对比直连 99.0%）；问题定位 <5min。
- 强制启用后 1 个路由周期内节点回到可用集（本期修复的验收标准，见 29 号）。
