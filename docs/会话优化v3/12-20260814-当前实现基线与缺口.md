# 会话优化 v3 当前实现基线与缺口

> 基线日期：2026-08-14
> 文档性质：CURRENT / CURRENT-PARTIAL / TARGET 事实基线
> 证据优先级：Go/SQL/wiring/测试 > 本目录历史文档 > 外部方案

## 1. 范围决策

v3 统一方案包含两条独立轨道：

- **V3.0 Semantic Track**：规范化 turn、脱敏、摘要、分类、边界、聚类、人工事实、关系和记忆；当前整体为 TARGET。
- **V3.2 Observability Track**：实时请求流、队列与节点状态、请求状态变更、在线会话浏览；后端已有部分接线，前端和运行时门禁仍未闭环。

两条轨道共享 V2 canonical facts，但不共享未冻结的内部表写权限。V3.2 是 V3.0 的前置可观测性能力，不代表 V3.0 语义能力已经实现。

## 4. V3.0 Semantic Track 事实

以下能力均未发现生产 migration、worker wiring、稳定 `/api/v1/semantic/*` 路由或人工闭环：

- `semantic_sessions`、`semantic_turns`、`semantic_results` 等表；
- `analysis.requested/completed/failed` durable event/outbox 链；
- semantic worker、重试/DLQ、replay；
- 版本化 summary/label/entity/cluster result；
- split/merge/undo 人工事实；
- graph/vector/memory adapter；
- golden set、标注、自动回归门禁。

`cmd/gateway/logging_init.go` 中的 semantic analyzer 是诊断/IR 能力，不得标记为 V3.0 semantic worker。

## 4.1 阻断发现

- **CRITICAL-MIG-513-001**：`513_schema_unification_and_session_turns_dual_write.sql` 的注释目标是删除重复 `gateway.*`，实际语句删除 `public.*`；同一事务随后对 `public.session_turns` 执行 `ALTER TABLE`。在 migration owner 修正 SQL、补数据备份/恢复演练并通过人工确认前，`public.*` canonical 结论和 V3.2 dual-write 均不得标记为 CURRENT/RELEASED。
- **HIGH-TENANT-511-001**：`511_state_transitions_table.sql` 当前缺少 tenant_id/RLS 设计，`admin/request_transitions.go` 不能仅按 request_id 宣称跨租户隔离已完成。V32-LP2 必须先补 schema 或服务端 tenant 关联方案。

## 5. 统一不变量

1. `request_logs` 与 V2 `public.*` 是 canonical facts；V3 派生结果不得回写覆盖原始事实。
2. 所有派生事实带 tenant、input hash、source/model version、result version 和 freshness。
3. 人工事实 append-only，模型重跑不能删除或静默覆盖人工 override。
4. relay 热路径不同步调用 LLM、embedding、图数据库或 semantic worker。
5. tenant 来自认证主体/服务端上下文；查询参数只能做一致性校验。
6. 事件至少一次投递；consumer 必须 event/idempotency 幂等，失败进入 retry/DLQ。
7. 任何 TARGET schema 在 up/down、RLS、低权限角色、回滚和重算门禁通过前不得部署。
8. V3.2 后端接线、前端启用和运行时验收分别计状态，不得用“路由已注册”代替“功能完成”。
