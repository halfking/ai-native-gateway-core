# V3.2 实际 API 与 SSE 契约

> 基线日期：2026-08-14
> 状态：CURRENT-PARTIAL 契约冻结草案
> 证据原则：以 `admin/`、`cmd/gateway/`、`domains/dispatch/` 和实际路由注册为准

## 1. 端点清单

| 用途 | 实际端点 | 当前实现 | 说明 |
| --- | --- | --- | --- |
| 实时请求流 | `GET /api/admin/live-stream` | `admin/live_stream_sse.go`、`admin/handler.go` | 单 SSE 出口；保持旧消息兼容 |
| 请求 trace | `GET /api/admin/requests/{id}/trace` | `admin/request_trace.go` | Redis 优先、PG 兜底 |
| 状态变更 | `GET /api/admin/requests/{id}/transitions` | `admin/request_transitions.go` | 查询 `request_state_transitions` |
| 节点探测 | `POST /api/admin/providers/{id}/test-now` | `admin/node_operations.go` | provider 级 test-now |
| 节点启停 | `PATCH /api/admin/providers/{id}/enable` | `admin/node_operations.go` | 当前是 provider 下 credentials 的批量状态操作 |
| 在线会话 | `GET /api/admin/sessions/online` | `admin/session_online.go` | Redis 在线索引 + 热请求 enrich |
| 会话时间线 | `GET /api/admin/sessions/{id}/timeline` | `admin/session_online.go` | 当前主要读 `request_logs_hot`；`public.session_turns` dual-write 已存在，但仍不是完整归档 V2 timeline |

旧设计中出现的 `internal/admin/liveSSE.go`、`internal/admin/sessions.go`、`domains/telemetry/request_telemetry.go`、`/api/admin/credentials/{id}/test` 等路径不再作为实现落点；后续文档必须引用上述实际路径。

## 2. live-stream 消息兼容

现有消息类型继续保留：

- `initial_data`
- `request`
- `idle_marker`
- `health_update`
- `incident_update`
- `snapshot_refresh`

V3.2 可新增但必须向后兼容：

- `queue_snapshot`
- `node_update`
- `state_transition`
- `child_request`

新增字段均 optional；旧客户端忽略未知字段不得报错。单 SSE 连接由 `liveStreamStore.ts` 负责消费，禁止再创建第二个并行实时出口。

## 3. 请求事件最小结构

```json
{
  "type": "request",
  "requestId": "r-1",
  "parentRequestId": "r-0",
  "requestType": "chat|title|summary|sensitive_word|unknown",
  "tenantId": "server-derived",
  "stage": "route_resolve",
  "retrySeq": 0,
  "retryReasonClass": null,
  "model": "model-name",
  "provider": "provider-name",
  "credentialId": "redacted-or-authorized-id",
  "occurredAt": "2026-08-14T00:00:00Z"
}
```

正文、API key、authorization、系统 prompt、未脱敏附件不得进入 SSE、日志或状态事件。

## 4. queue_snapshot 最小结构

> **当前/目标分层**：当前 `LiveQueueSnapshot` 主要已有 model/credential depth、enabled/wired 等字段；pipeline depth、waiting p50/p95、inFlight、degraded 属于本契约冻结的 TARGET 字段。在实现补齐前不能要求前端读取这些字段，也不能用零值冒充真实统计。

```json
{
  "type": "queue_snapshot",
  "occurredAt": "2026-08-14T00:00:00Z",
  "queues": {
    "pipeline": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0},
    "model": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0},
    "credential": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0}
  },
  "degraded": false,
  "sourceVersion": "queue-stats-v1"
}
```

如果当前实现无法提供某个统计量，必须返回 `null` 并带 `degraded=true`，不得填零冒充真实值。队列口径必须在实现前冻结：depth、等待时间窗口、in-flight 的 owner 和采样周期。

## 5. 节点操作语义

- `test-now` 是一次受控探测，不改变 provider/credential 的长期状态；结果至少包含 success、latency、error_code、observed_at。
- `enable` 当前操作粒度是 provider，而非单个 credential。文档、前端文案和审计事件必须明确“批量影响范围”。如果需要 credential 级操作，应另立 API，不复用该端点。
- 所有状态改变必须包含 operator、reason、correlation_id、idempotency key，并记录审计；当前 `node_operations.go` 的 TODO 在审计门禁前必须关闭。

## 6. 在线会话语义

- 在线索引来自 Redis，时间线当前主要来自 `request_logs_hot`；它只能称为“在线热请求时间线”。
- 要称为“完整会话时间线”，必须补齐 `public.sessions/session_turns/session_bodies` 读取、归档数据覆盖、tenant 过滤和正文权限控制。
- 跨租户或无权资源统一返回 not found 语义，不泄露资源存在性。
- 分页、排序和 freshness 必须由 API 响应明确声明；未完成聚合返回 `degraded/stale`，不得伪装 current。

## 7. 权限与安全契约

| 操作 | 要求 |
| --- | --- |
| live-stream/trace/timeline 读取 | 管理端认证 + tenant 上下文 |
| provider test-now | 管理操作 scope + 频率限制 |
| provider enable | 管理操作 scope + 二次确认 + 审计 |
| transitions 查询 | 请求可见范围授权 |

服务端不得信任 query/body 中的 tenant_id 覆盖认证主体。错误响应使用稳定 code，不返回 SQL、上游原文或内部堆栈。
