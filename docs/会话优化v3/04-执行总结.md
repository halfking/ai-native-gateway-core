## 2. 方案核心亮点

### 2.1 架构层面

1. **最小侵入式改造**
   - 不破坏现有 SSE 结构
   - 新增端点独立于现有 API
   - 前端组件隔离，不修改核心逻辑

2. **性能优先设计**
   - 队列指标收集使用无锁数据结构
   - SSE 推送频率可配置
   - 子请求查询强制使用索引
   - 前端虚拟滚动支持大列表

3. **可观测性全覆盖**
   - 请求生命周期 9 个阶段追踪
   - 三层队列实时透视
   - 节点级健康度监控
   - 状态变更历史完整记录

### 2.2 功能层面

1. **统一请求流面板**（P0）
   - 队列透视区：实时显示三层队列状态
   - 节点状态矩阵：一键测试、快速切换
   - 增强泳道：主从请求树状展示

2. **会话实时管理**（P1）
   - 在线会话列表：活跃会话实时更新
   - 多轮次时间线：垂直时间线展示
   - 扩展请求树：每轮次子任务可视化
   - 健康度实时计算：动态评分

3. **状态变更追踪**（P0）
   - 路由决策记录
   - 节点切换记录
   - 重试逻辑记录
   - 完整回溯能力

### 2.3 实现层面

1. **数据结构设计精准**
   - QueueSnapshot: 三层队列完整快照
   - LiveRequestWithChildren: 主从请求关联
   - NodeStatus: 节点操作所需全部信息
   - ActiveSession: 会话实时缓存结构

2. **API 设计 RESTful**
   - GET /admin/live-stream/queue-snapshot (SSE)
   - POST /admin/providers/{id}/test-now
   - PATCH /admin/providers/{id}/enable
   - GET /admin/sessions/active
   - GET /admin/sessions/{id}/turns

3. **前端组件化清晰**
   - QueueOverviewSection: 队列透视
   - NodeStatusMatrix: 节点矩阵
   - EnhancedSwimLane: 增强泳道
   - ActiveSessionList: 会话列表
   - SessionTurnTimeline: 轮次时间线

## 6. 风险提醒

### 6.1 关键风险点

⚠️ **队列指标收集性能影响**
- 缓解：提前做 benchmark，确保开销 < 5%
- 降级：如果性能不达标，降低采样频率

⚠️ **SSE 连接数过多**
- 缓解：限制单租户连接数为 5
- 降级：使用 Redis Pub/Sub 扇出

⚠️ **状态变更历史表膨胀**
- 缓解：定期归档（保留 7 天热数据）
- 降级：按租户分表

⚠️ **前端渲染性能问题**
- 缓解：虚拟滚动 + 限制泳道数量
- 降级：分页加载会话列表

### 6.2 回滚预案

如果 V3 上线后发现严重问题：

1. **数据库回滚**: 执行 down.sql 脚本
2. **代码回滚**: `git revert` 合并提交
3. **配置降级**: 通过 feature flag 关闭新功能
4. **缓存清理**: 清空 Redis 活跃会话缓存
