## 1. 用户需求原文与拆解

### 1.1 原始需求（2026-08-13）

> 我们需要检查代码中的关于首页的"实时请求流"与我们为了满足并发与状态管理的总请求流、模型请求流、供应商的节点请求流等多个队列，能否将它们整合并在首页的"实时请求流"中呈现，能够做到请求的到达、路由、选择节点、切换节点、收到回复（包括错误）、重试（可以打特别标）、并进行状态的变更等，需要做到一个页面能够简捷完整地看到所有可用的的节点对应的请求流、节点状态、请求状态、多个请求的队列等，可以及时点击节点进行测试与验证，并切换节点状态等。
>
> 并且需要能够展示请求延伸的类似标题生成、总结、敏感词检查等操作的状态，相当于有主从相关的。
>
> 并且规划在线的会话，及会话的多轮次请求及相关的扩展请求等的浏览与展示，位于首页的会话与统计中
>
> 我们需要做到比直连供应商更高的稳定性、可靠性、可观测性。

### 1.2 需求拆解（6 大核心诉求）

| # | 核心诉求 | 详细描述 | 优先级 |
|---|---------|---------|--------|
| **R1** | **多层队列整合展示** | 将总请求队列、模型队列、供应商节点队列整合到首页"实时请求流"中 | P0 |
| **R2** | **请求全生命周期可视化** | 展示：到达 → 路由 → 节点选择 → 节点切换 → 响应/错误 → 重试（标记）→ 状态变更 | P0 |
| **R3** | **节点维度聚合 + 快速操作** | 每个节点的请求流、状态、队列深度；点击测试/验证、切换状态 | P0 |
| **R4** | **扩展请求（主从关系）可视化** | 主请求（chat-completions）+ 从请求（标题生成、总结、敏感词检查）的关联树 | P1 |
| **R5** | **在线会话管理** | 会话列表、多轮对话、扩展请求关联，位于"首页 → 会话与统计" | P1 |
| **R6** | **超越供应商的三高指标** | 比直连供应商更高的：稳定性（failover）、可靠性（重试/降级）、可观测性（全链路 trace） | P0 |

**dispatch 三层队列架构**（[v2/57号文档](../会话优化v2/57-多层队列调度架构设计方案.md)）：
```
[1] Pipeline (总调度队列)
     → RouteFunc (路由选择)
     → 选择 modelID + providerID
          ↓
[2] Model Queue (按 modelID 分组)
     → Governor (concurrency/rpm/tpm 限流)
     → 选择 credentialID
          ↓
[3] Credential Queue (按 credentialID 分组)
     → ForwardFunc (实际转发)
     → 返回 ResponseCh
```

**Gap（缺失能力）**：
- ❌ **队列状态未暴露**：`Pipeline`、`ModelQueue`、`CredQueue` 的深度、等待时长未通过 API 暴露
- ❌ **节点操作 API 缺失**：无 `/api/admin/credentials/{id}/test` 测试接口、无状态切换 API
- ❌ **扩展请求事件缺失**：Goal Audit / 标题生成等扩展请求未发送 SSE 事件
- ❌ **在线会话 API 缺失**：无 `/api/admin/sessions/online` 查询接口、无多轮历史 API

## 4. 数据模型与 API 契约

### 4.1 9 阶段时间戳定义

**请求生命周期的 9 个关键时间点**：

| 阶段 ID | 名称 | 字段名 | 说明 | 记录位置 |
|---------|------|--------|------|---------|
| **S1** | 请求到达 | `received_at` | HTTP 请求到达网关 | `request_logs.created_at` |
| **S2** | 入队总队列 | `enqueued_pipeline_at` | 进入 dispatch.Pipeline | `telemetry` 新增 |
| **S3** | 路由完成 | `routed_at` | RouteFunc 返回 modelID+providerID | `telemetry` 新增 |
| **S4** | 入队模型队列 | `enqueued_model_at` | 进入 Model Queue | `telemetry` 新增 |
| **S5** | 凭据选择完成 | `credential_selected_at` | Governor 返回 credentialID | `telemetry` 新增 |
| **S6** | 入队节点队列 | `enqueued_cred_at` | 进入 Credential Queue | `telemetry` 新增 |
| **S7** | 开始转发 | `forward_started_at` | ForwardFunc 开始执行 | `request_logs.forwarded_at` |
| **S8** | 首字节到达 | `first_byte_at` | 收到供应商第一字节响应 | `request_logs.first_byte_at` |
| **S9** | 响应完成 | `completed_at` | 流式响应结束 OR 非流式响应返回 | `request_logs.completed_at` |

**队列等待时长计算**：
- `pipeline_wait = S3 - S2`（总队列等待）
- `model_queue_wait = S5 - S4`（模型队列等待）
- `cred_queue_wait = S7 - S6`（节点队列等待）
- `forward_latency = S8 - S7`（转发延迟）
- `stream_duration = S9 - S8`（流式传输时长）
- `total_latency = S9 - S1`（端到端延迟）

```typescript
interface LiveRequest {
  id: string;             // request_log_id
  tenantId: string;
  apiKey: string;
  model: string;
  provider: string;
```

**v3 扩展字段**：
```typescript
interface LiveRequestV3 extends LiveRequest {
  // 队列信息
  queueInfo?: {
    pipelineDepth: number;      // 总队列深度
    modelQueueDepth: number;    // 模型队列深度
    credQueueDepth: number;     // 节点队列深度
    pipelineWaitMs: number;     // 总队列等待时长
    modelWaitMs: number;        // 模型队列等待时长
    credWaitMs: number;         // 节点队列等待时长
  };

  // 9 阶段时间戳
  timestamps: {
    receivedAt: string;         // S1
    enqueuedPipelineAt?: string; // S2
    routedAt?: string;          // S3
    enqueuedModelAt?: string;   // S4
    credentialSelectedAt?: string; // S5
    enqueuedCredAt?: string;    // S6
    forwardStartedAt?: string;  // S7
    firstByteAt?: string;       // S8
    completedAt?: string;       // S9
  };

  // 节点信息
  nodeInfo?: {
    credentialId: string;
    credentialName: string;
    credentialStatus: 'active' | 'suspended' | 'disabled';
    healthScore: number;        // 0-100
  };

  // 扩展请求关联
  extendedRequests?: {
    parentRequestId?: string;   // 如果是子请求，指向父请求
    childRequestIds?: string[]; // 如果是主请求，包含子请求列表
    extendType?: 'goal_audit' | 'title_gen' | 'summary' | 'sensitive_check';
  };

  // 重试信息
  retryInfo?: {
    attemptCount: number;
    isRetry: boolean;
    originalRequestId?: string;
  };
}
```

### 6.3 在线会话 API 实现

**Endpoint**: `GET /api/admin/sessions/online`

**实现**：
```go
func (s *SessionService) ListOnlineSessions(ctx context.Context, query OnlineSessionsQuery) (*OnlineSessionsResponse, error) {
    // 1. 查询 gateway.sessions + session_summaries
    sessions, err := s.db.Query(`
        SELECT 
            s.id, s.session_key, s.tenant_id, s.api_key,
            ss.gw_project_id, ss.gw_task_id, ss.title,
            s.created_at, s.updated_at,
            COUNT(st.id) as turn_count
        FROM gateway.sessions s
        LEFT JOIN session_summaries ss ON s.id = ss.session_id
        LEFT JOIN gateway.session_turns st ON s.id = st.session_id
        WHERE s.tenant_id = $1
            AND s.updated_at > NOW() - INTERVAL '1 hour'  -- 1 小时内活跃
        GROUP BY s.id, ss.id
        ORDER BY s.updated_at DESC
        LIMIT $2 OFFSET $3
    `, query.TenantID, query.Limit, query.Offset)

    // 2. 计算健康度评分
    for _, session := range sessions {
        session.HealthScore = s.calculateHealthScore(session.ID)
    }

    return &OnlineSessionsResponse{
        Sessions: sessions,
        Total:    len(sessions),
        HasMore:  len(sessions) == query.Limit,
    }, nil
}

func (s *SessionService) calculateHealthScore(sessionID string) float64 {
    // 50% 成功率 + 30% 延迟 + 20% 成本
    successRate := s.getSuccessRate(sessionID)       // 0-1
    avgLatency := s.getAvgLatency(sessionID)         // ms
    avgCost := s.getAvgCost(sessionID)               // $

    // 归一化
    successScore := successRate * 50
    latencyScore := (1 - min(avgLatency/10000, 1)) * 30  // 10s 为满分
    costScore := (1 - min(avgCost/1.0, 1)) * 20          // $1 为满分

    return successScore + latencyScore + costScore
}
```

## 8. 风险与缓解

### 8.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **SSE 带宽暴增** | 新增字段导致事件体积增大 3-5 倍 | 🟡 中 | 1. 队列状态仅推送变化（delta）<br>2. 时间戳压缩（相对时间戳）<br>3. Feature Flag 灰度 |
| **前端渲染性能** | 瀑布流组件在 1000+ 请求时卡顿 | 🟡 中 | 1. 虚拟滚动（仅渲染可见区域）<br>2. Canvas 渲染替代 DOM<br>3. Web Worker 计算聚合数据 |
| **会话查询慢** | 1 小时内活跃会话可能达 10000+ | 🟢 低 | 1. 分页查询（默认 20 条）<br>2. Redis 缓存热数据<br>3. 增加 `updated_at` 索引 |
| **节点测试并发** | 批量测试导致节点过载 | 🟢 低 | 1. 测试请求限流（1 req/s）<br>2. 测试超时时间短（10s）<br>3. 批量测试排队执行 |

### 8.2 业务风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **用户反馈复杂难用** | UI 信息过载，用户找不到关键信息 | 🟡 中 | 1. 提供"简洁/详细"视图切换<br>2. 默认折叠扩展请求<br>3. 增加"快速入口"（最近失败、最慢请求） |
| **扩展请求关联错误** | 主从请求对不上，展示混乱 | 🟢 低 | 1. Goal 模式生成 `parent_request_id`<br>2. 前端容错（缺失父请求时独立展示） |
| **节点状态切换误操作** | 误停用关键节点导致业务中断 | 🟡 中 | 1. 二次确认对话框<br>2. 限制操作权限（仅管理员）<br>3. 审计日志记录所有操作 |
