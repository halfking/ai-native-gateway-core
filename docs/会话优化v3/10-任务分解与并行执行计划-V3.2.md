## 2. 任务清单

### 2.1 Task-DB-01：数据库迁移（P0 阻塞，0.5d，无依赖）

**输出**：`sql/migrations/510_request_tracing_fields.{up,down}.sql`、`511_state_transitions_table.{up,down}.sql`、`test_510_511.sql`

**内容**：
- 510：`request_logs` 加 `parent_request_id TEXT NULL`、`request_type TEXT NOT NULL DEFAULT 'main'`（CHECK: main/title_gen/summary/sensitive_check/compression/other）；部分索引 `idx_request_logs_parent`
- 511：新表 `request_state_transitions(id BIGSERIAL PK, request_id TEXT NOT NULL, transition_type TEXT CHECK IN ('route','node_switch','retry','error','state'), from_state TEXT, to_state TEXT, metadata JSONB, created_at TIMESTAMPTZ DEFAULT NOW())`；索引 `(request_id, created_at DESC)`

**验收**：空库/现有库可执行；down 可回滚；幂等；索引与 CHECK 生效。

> 注：先 `ls sql/migrations/` 确认 510/511 未被占用，被占则顺延编号。

### 2.2 后端任务组 A（并行）

#### Task-BE-A1：队列可观测性模块（P0，3d，依赖 DB-01）

**负责模块**：`domains/dispatch`

**实现**：
1. `queue_metrics_collector.go`：`QueueSnapshot`（总队列 depth/waiting_ms_p50/p95；按 model 分组；按 credential_id 分组 depth/in_flight/concurrency）；`sync.RWMutex`；`Snapshot()`
2. `queue_metrics_hook.go`：Pipeline middleware，OnEnqueue/OnDequeue 更新指标
3. main 装配注入 `LiveStreamSSEHub`
4. SSE 新增 `queue_snapshot` 消息，2s 节流推送（复用现有 Hub）

**验收**：并发 100 请求统计准确无竞态（`go test -race`）；SSE 稳定无泄漏；benchmark 开销 < 5%。

#### Task-BE-A2：节点操作 API（P0，1.5d，**无依赖，可立即并行**）

**负责模块**：`admin`

**实现**：
1. `admin/node_operations.go`：
   - `POST /api/admin/providers/{id}/test-now`：同步 probe（复用 `doChatProbe`，5s 超时兜底）→ `{provider_id, latency_ms, status, tested_at, error?}`
   - `PATCH /api/admin/providers/{id}/enable`：`{enabled: bool}` → 切 `manual_disabled` + 候选缓存失效（`provider/client.go:352`）
2. `admin/handler.go` 注册路由；super_admin 鉴权
3. 操作审计日志（DB-01 完成后对接 `request_state_transitions` 风格记录）

**验收**：test-now 返回正确延迟；禁用后立即摘除路由；非 super_admin 403；单测覆盖。

#### Task-BE-A3：请求链路追踪增强——主从请求（P0，3d，依赖 DB-01）

**负责模块**：`domains/hooks/observability/telemetry`、`admin`

**实现**：
1. `RequestLogEntry` 加 `RequestType`；telemetry 写入时从 `X-Gw-Source-Actor`/路径推断填充
2. `admin/live_stream_redis_store.go` 加 `QueryChildRequests(ctx, parentID)`（Redis 维度索引 + PG 兜底）
3. `LiveRequest` 加 `Children`；SSE 推送主请求时异步附带子请求树（深度≤3，循环保护）
4. 非请求型扩展操作（敏感词 verdict）定义轻量 `ChildEvent` 挂父请求

**验收**：标题生成正确挂父请求并在 SSE 出现；子查询 P95<50ms；单测含深度保护。

#### Task-BE-A4：节点请求流整合进 live-stream（P0，2d，依赖 DB-01，**新增**）

**负责模块**：`admin`

**实现**：
1. Redis 新增 `llmgw:live:dim:node`（按 credential_id 分桶在途/近期请求）
2. `LiveStreamSnapshot/Delta` 加 `nodes` 段：每节点 circuit/availability/quota/health/in_flight/最近延迟/最近错误
3. 节点状态变更（熔断开合/配额耗尽/手动启停/probe 结果）推送为 `node_update` 消息
4. `initial_data` 快照含全量节点矩阵

**验收**：initial_data 含节点矩阵；状态变更 2s 内推送；节点队列与 main 队列对账一致。

### 2.3 后端任务组 B（依赖组 A）

#### Task-BE-B1：状态变更历史记录（P0，2d，依赖 DB-01 + BE-A1）

**实现**：
1. `domains/dispatch/state_transition_logger.go`：`LogRouteDecision/LogNodeSwitch/LogRetry/LogError`，异步批量写 `request_state_transitions`
2. 埋点：`route_resolve`/`route_credential` 记路由决策（含候选与 BlockReason）；streamretry 重试/切换记 `from_node→to_node`、原因、retry_seq；终态错误记录
3. 查询 API：`GET /api/admin/requests/{id}/transitions`
4. 清理任务：删 7 天前数据

**验收**：构造 429 触发重试，transitions 返回完整 route→retry→node_switch→complete 链；清理任务单测。

#### Task-BE-B2：在线会话浏览 API（P0，2d，仅依赖 DB-01，**新增**）

**实现**：
1. `GET /api/admin/sessions/online`：在线会话列表（Redis SCAN `session:*` + `session_last_requests` 丰富：最后请求状态/模型/供应商/活跃时间/设备数），分页 + 租户过滤
2. `GET /api/admin/sessions/{id}/timeline`：多轮次时间线——每轮主请求 + 扩展请求子树（parent_request_id 关联），来源 V2 `session_turns` + `request_logs`
3. 租户隔离（ADR-V3-005）

**验收**：在线列表与 Redis 一致（P95<200ms）；timeline 正确展示主从树（P95<500ms）；禁 KEYS 用 SCAN。
