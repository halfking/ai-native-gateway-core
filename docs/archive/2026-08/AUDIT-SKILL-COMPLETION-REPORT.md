## 🎯 5大审计标准说明

### 1. 📊 数据流溯源标准
**原则**: 所有数据要有来源、有去处、至少有规划的用途

**实施**:
- 要求所有数据字段有 `// SOURCE:` 注释
- 要求所有数据库写操作有 `// DESTINATION:` 注释
- 要求所有数据收集有 `// USAGE:` 注释
- 自动检测写入但从未读取的字段

**价值**: 防止数据泄漏、减少存储浪费、提高系统可维护性

### 2. 🔄 业务流程闭环标准
**原则**: 所有业务流程需要是闭环

**实施**:
- 检查异步操作是否有结果跟踪
- 检查是否有超时保护
- 检查是否有错误处理
- 检查是否有重试逻辑
- 验证幂等性标记

**价值**: 防止流程卡死、提高系统可靠性、便于问题诊断

### 3. 🔀 状态机转换验证标准
**原则**: 所有涉及状态的变化要用状态机的转换进行检查

**实施**:
- 检查状态更新是否有WHERE子句验证当前状态
- 检查是否使用事务包装状态更新
- 验证所有状态转换有文档记录
- 检查状态不变量是否被强制执行

**价值**: 防止非法状态转换、保证数据一致性、便于状态追踪

### 4. ⚡ 并发安全标准
**原则**: 所有并发处理需要检查并发问题、资源抢占问题

**实施**:
- 运行 `go test -race` 检测数据竞争
- 检查共享map是否有mutex保护
- 检查goroutine是否有退出条件
- 检查channel操作是否有超时
- 检查锁的获取顺序是否一致

**价值**: 防止数据竞争、避免死锁、防止goroutine泄漏

### 5. 🔄 数据兼容性标准
**原则**: 所有的数据查询与更新需要注意兼容性

**实施**:
- 检查新增NOT NULL列是否有DEFAULT
- 检查DROP COLUMN是否有宽限期
- 检查RENAME COLUMN是否使用两步迁移
- 验证所有迁移有回滚脚本
- 检查索引创建是否使用CONCURRENTLY

**价值**: 支持灰度发布、降低部署风险、便于回滚
