## 🎯 核心概念速查

### 什么是供应商质量画像？

为每个 LLM 供应商（Claude、GPT-4、Gemini 等）建立一个"健康档案"，包含：
- 成功率、错误率、响应时间等**实时指标**
- 综合评分（0-100）和等级（S/A/B/C/D）
- 自动告警和熔断决策

### 为什么需要它？

- ❌ **现状**：供应商故障时才发现，手动切换慢
- ✅ **改进**：实时监控，自动切换，智能路由

### 典型场景

```
场景1：Claude 突然 5xx 激增
┌─────────────────────────────────────────┐
│ 1. 系统检测到 5xx 错误率 > 5%           │
│ 2. 自动降低 Claude 权重 50%             │
│ 3. 流量自动转移到 GPT-4                │
│ 4. 发送飞书告警通知运维                │
│ 5. Claude 恢复后自动恢复权重            │
└─────────────────────────────────────────┘
```

```bash
psql -h localhost -U postgres -d llm_gateway << 'EOF'
INSERT INTO provider_quality_profiles (provider_id, model_name)

ON CONFLICT DO NOTHING;

ON CONFLICT DO NOTHING;
EOF
```

## 🔍 常见问题排查

### Q1: 质量画像数据为空？

```bash
# 检查是否有请求日志
psql -c "SELECT COUNT(*) FROM request_logs WHERE created_at > now() - interval '1 hour';"

# 检查 Redis 连接
redis-cli PING

# 检查聚合任务是否运行
ps aux | grep quality-aggregator
```

### Q2: 告警没有触发？

```bash
# 检查告警配置
cat config/quality_profile.yaml | grep -A 10 alerts

# 检查健康事件表
psql -c "SELECT * FROM provider_health_events ORDER BY created_at DESC LIMIT 10;"

# 手动触发测试告警
curl -X POST http://localhost:8080/internal/quality/test-alert
```

### Q3: 路由没有使用质量评分？

```bash
# 检查路由集成是否启用
grep "routing_integration" config/quality_profile.yaml

# 查看路由决策日志
tail -f logs/gateway.log | grep "quality_score"

# 检查是否在灰度模式
curl http://localhost:8080/internal/quality/status | jq .mode
```

### 业务效果指标

```sql
-- 查看整体成功率（上线前后对比）
SELECT
    date_trunc('hour', timestamp) as hour,
    COUNT(*) FILTER (WHERE status_code BETWEEN 200 AND 299) * 100.0 / COUNT(*) as success_rate
FROM request_logs
WHERE timestamp > now() - interval '7 days'
GROUP BY hour
ORDER BY hour;

-- 查看供应商流量分布
SELECT
    p.name,
    COUNT(*) as requests,
    AVG(rl.latency_ms) as avg_latency,
    pqp.quality_score
FROM request_logs rl
JOIN providers p ON rl.provider_id = p.id
JOIN provider_quality_profiles pqp ON p.id = pqp.provider_id
WHERE rl.timestamp > now() - interval '1 hour'
GROUP BY p.name, pqp.quality_score
ORDER BY pqp.quality_score DESC;
```

### 自定义评分权重

```sql
-- 调整某个供应商的评分权重
UPDATE provider_quality_configs
SET
    weight_availability = 0.5,    -- 提高可用性权重
    weight_performance = 0.3,
    weight_stability = 0.15,
    weight_cost_efficiency = 0.05
WHERE provider_id = 1;
```

### 自定义告警阈值

```sql
-- 为关键供应商设置更严格的阈值
UPDATE provider_quality_configs
SET
    alert_error_rate_5xx_p0 = 3.0,  -- 降低到 3%
    alert_latency_p99_p0 = 20000    -- 降低到 20s
WHERE provider_id = 1;
```
