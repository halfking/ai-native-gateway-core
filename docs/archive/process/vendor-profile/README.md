# 供应商质量画像系统

## 📋 概述

供应商质量画像系统是 LLM Gateway 的核心质量保障模块，通过多维度指标评估每个供应商的服务质量，为智能路由决策提供数据支撑。

## 🎯 核心价值

1. **智能路由**：基于实时质量评分动态调整供应商权重
2. **故障预警**：提前识别质量下降趋势，自动切换备用供应商
3. **成本优化**：在质量相当的情况下选择成本更低的供应商
4. **可观测性**：完整的供应商健康状态可视化

## 📊 四层指标模型

### L1: 核心可用性 (40%)
- **成功率**: 成功请求 / 总请求
- **错误率**: 5xx/4xx/timeout 错误占比
- **可用性**: 连续可用时间占比

### L2: 性能 (30%)
- **响应时间**: P50/P95/P99 延迟
- **TTFT**: Time To First Token
- **吞吐量**: Tokens per second

### L3: 稳定性 (20%)
- **波动性**: 成功率的标准差
- **错误分布**: 错误类型的多样性
- **恢复时间**: MTTR (Mean Time To Recovery)

### L4: 成本效益 (10%)
- **单价**: 每 1K tokens 成本
- **性价比**: 成本 / 质量
- **配额利用率**: 使用量 / 总配额

## 🎚️ 质量等级

| 等级 | 综合评分 | 描述 | 路由策略 |
|-----|---------|------|---------|
| S   | 90-100  | 优秀 | 优先使用，权重 +20% |
| A   | 80-89   | 良好 | 常规使用，权重 +10% |
| B   | 70-79   | 一般 | 谨慎使用，正常权重 |
| C   | 60-69   | 较差 | 降低权重 50% |
| D   | < 60    | 极差 | 停用或仅作备用 |

## ⏱️ 时间维度

每个指标在多个时间窗口计算：
- **实时** (5分钟): 用于快速告警
- **短期** (1小时): 用于趋势判断
- **中期** (24小时): 用于稳定性评估
- **长期** (7天/30天): 用于历史分析

## 🚨 告警规则

### P0 严重告警（1分钟内触发）
- 5xx错误率 > 5% 持续 5分钟 → **立即切换备用供应商**
- 可用性 < 95% 持续 5分钟 → **立即切换备用供应商**
- P99延迟 > 30s 持续 10分钟 → **降低权重 50%**

### P1 警告告警（5分钟内触发）
- 5xx错误率 > 1% 持续 10分钟 → **降低权重 20%**
- 成功率 < 98% 持续 10分钟 → **记录并监控**
- P95延迟 > 10s 持续 15分钟 → **降低权重 10%**

## 🔄 灰度上线策略

1. **观察模式**（第1周）：启用数据采集和指标计算，不影响路由
2. **影子模式**（第2周）：记录路由决策，但不实际应用
3. **小流量验证**（第3周）：10% 流量使用质量驱动路由
4. **全量上线**（第4周）：100% 流量 + 7天观察期

## 🔒 重要补充：L5 可信度指标（反欺诈）

### 问题：模型伪装（Model Spoofing）

部分供应商可能用**低阶模型冒充高阶模型**骗取高价：
- 声称 GPT-4，实际 GPT-3.5（20倍差价）
- 声称 Claude Opus，实际 Claude Haiku
- 高峰时段偷偷切换到小模型

### 解决方案：六维特征检测

| 维度 | 检测方法 | 示例 |
|-----|---------|------|
| 1. 响应延迟 | TTFT 突然下降 30%+ | Opus TTFT 应该 800-1500ms，如果只有 400ms 可疑 |
| 2. Token 消耗 | 输出/输入比例异常 | GPT-4 平均输出 > 500 tokens，如果只有 200 可疑 |
| 3. 输出长度 | 平均长度偏离基线 | 高阶模型通常输出更长、更详细 |
| 4. 内容质量 | LLM-as-Judge 评分 | 用 GPT-4 评估输出质量，低于 0.7 可疑 |
| 5. 错误模式 | 特定模型典型错误 | Opus 很少幻觉，如果幻觉率 > 2% 可疑 |
| 6. 版本指纹 | API 响应头/格式 | 检查特定 header 和 stop_reason 格式 |

### 可信度等级

| 等级 | 分数 | 处理策略 |
|-----|------|---------|
| 可信 | 90-100 | 正常使用 |
| 基本可信 | 80-89 | 持续监控 |
| 存疑 | 70-79 | 降权 50% + 人工审核 |
| 不可信 | 60-69 | 降权 80% + 告警 |
| 确认作假 | < 60 | **立即停用** + 合同违约 |

### 检测方法

1. **静态基线对比**：建立每个模型的特征基线，实时对比偏离度
2. **探针请求**：每小时发送测试请求验证（成本 ~$73/月）
3. **LLM-as-Judge**：抽样评估输出质量（成本 ~$360/月）
