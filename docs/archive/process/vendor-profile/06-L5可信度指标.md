# 供应商质量画像 - L5 可信度指标（反欺诈）

## 1. 问题背景

### 1.1 什么是"渗水率"问题？

**渗水（Model Spoofing）**：供应商用低阶模型冒充高阶模型，骗取更高价格。

```
声称提供: GPT-4 Turbo ($0.01/1K tokens)
实际提供: GPT-3.5 Turbo ($0.0005/1K tokens)
差价: 20倍！
```

### 1.2 真实案例

- 某供应商声称提供 Claude Opus，但响应质量、延迟、token 消耗都不符合 Opus 特征
- 某 API 声称 GPT-4，但输出长度限制、推理能力明显是 GPT-3.5
- 某代理商混用模型，高峰时段切换到低价模型

### 1.3 业务影响

- **成本损失**：按高价计费，实际获得低价服务
- **质量下降**：用户以为用了顶级模型，实际得到劣质输出
- **信任危机**：用户发现后投诉，损害平台声誉

## 2. L5 可信度指标设计

### 2.1 指标定义

**可信度（Trustworthiness Score）**：供应商声称的模型与实际表现的匹配度。

```
可信度 = 100 - (实际特征偏离度 × 100)

偏离度 = Σ (实际值 - 期望值)² / 期望值² / 特征数
```

### 2.2 六维特征检测

| 维度 | 检测指标 | 预期范围（以 Claude Opus 为例） | 偏离阈值 |
|-----|---------|---------------------------|---------|
| **1. 响应延迟** | TTFT, 总延迟 | TTFT: 800-1500ms<br>总延迟: 2-5s | > ±30% |
| **2. Token 消耗** | 输入/输出比例 | 输出/输入: 1.5-3.0 | > ±50% |
| **3. 输出长度** | 平均输出 tokens | 500-2000 tokens | > ±40% |
| **4. 内容特征** | 推理链长度、代码质量 | 推理步骤: 3-7步 | 质量评分 < 0.7 |
| **5. 错误模式** | 特定模型的典型错误 | Opus 很少幻觉 | 幻觉率 > 2% |
| **6. 版本指纹** | API 响应头、格式 | 特定 header 存在 | 缺失关键指纹 |

### 2.3 可信度等级

| 等级 | 可信度分数 | 含义 | 处理策略 |
|-----|----------|------|---------|
| **可信** | 90-100 | 特征完全匹配 | 正常使用 |
| **基本可信** | 80-89 | 轻微偏离，可能是正常波动 | 持续监控 |
| **存疑** | 70-79 | 明显偏离，需进一步验证 | 降低权重 50% + 人工审核 |
| **不可信** | 60-69 | 多维度偏离，高度怀疑 | 降低权重 80% + 告警 |
| **确认作假** | < 60 | 确凿证据，已确认作假 | 停用 + 合同违约处理 |

## 3. 检测方法

### 3.1 静态特征基线（Baseline）

为每个模型建立特征基线：

```yaml
# config/model_baselines.yaml
models:
  - name: "claude-opus-4"
    vendor: "anthropic"

    # 性能基线
    performance:
      ttft_p50: 1000        # ms
      ttft_p95: 1500
      latency_p50: 3000
      latency_p95: 6000
      throughput: 50        # tokens/s

    # Token 基线
    tokens:
      avg_output_length: 800
      output_input_ratio: 2.0
      max_output_tokens: 4096

    # 质量基线
    quality:
      reasoning_steps: 4.5    # 平均推理步骤数
      code_quality_score: 0.9
      hallucination_rate: 0.01

    # 版本指纹
    fingerprints:
      - type: "header"
        key: "anthropic-version"
        expected: "2024-01-01"
      - type: "response_format"
        key: "stop_reason"
        values: ["end_turn", "max_tokens", "stop_sequence"]
```

### 3.2 实时检测（Runtime Detection）

#### 方法 1: 统计偏离检测

```go
// internal/quality/trustworthiness_detector.go

type TrustworthinessDetector struct {
    baselines map[string]*ModelBaseline
    db        *sqlx.DB
}

func (td *TrustworthinessDetector) CalculateTrustworthiness(
    providerID int64,
    modelName string,
) (float64, []string) {
    baseline := td.baselines[modelName]
    actual := td.getActualMetrics(providerID, modelName)

    deviations := []Deviation{}

    // 1. 延迟偏离
    if actual.TTFTP50 < baseline.TTFTP50 * 0.7 {
        deviations = append(deviations, Deviation{
            Dimension: "ttft",
            Expected: baseline.TTFTP50,
            Actual: actual.TTFTP50,
            Severity: "high",
            Reason: "TTFT 异常快，可能使用了更小的模型",
        })
    }

    // 2. Token 消耗偏离
    ratio := actual.AvgOutputTokens / actual.AvgInputTokens
    if abs(ratio - baseline.OutputInputRatio) > 0.5 {
        deviations = append(deviations, Deviation{
            Dimension: "token_ratio",
            Expected: baseline.OutputInputRatio,
            Actual: ratio,
            Severity: "medium",
            Reason: "输出/输入 token 比例异常",
        })
    }

    // 3. 质量偏离（需要 LLM-as-Judge）
    qualityScore := td.assessOutputQuality(providerID, modelName)
    if qualityScore < baseline.CodeQualityScore - 0.1 {
        deviations = append(deviations, Deviation{
            Dimension: "quality",
            Expected: baseline.CodeQualityScore,
            Actual: qualityScore,
            Severity: "high",
            Reason: "输出质量明显低于预期",
        })
    }

    // 计算综合可信度
    trustScore := 100.0
    for _, dev := range deviations {
        penalty := dev.calculatePenalty()
        trustScore -= penalty
    }

    reasons := []string{}
    for _, dev := range deviations {
        reasons = append(reasons, dev.Reason)
    }

    return trustScore, reasons
}
```

#### 方法 2: 探针请求（Probe Requests）

定期发送"测试请求"验证模型真实性：

```go
type ProbeRequest struct {
    Type        string  // "reasoning", "coding", "multilingual"
    Input       string
    ExpectedMin int     // 最小输出长度
    ExpectedMax int     // 最大输出长度
    Keywords    []string // 预期关键词
}

var OpusProbes = []ProbeRequest{
    {
        Type: "reasoning",
        Input: "Explain step-by-step: why is the sky blue?",
        ExpectedMin: 300,
        ExpectedMax: 1000,
        Keywords: []string{"Rayleigh scattering", "wavelength", "atmosphere"},
    },
    {
        Type: "coding",
        Input: "Write a binary search in Python with type hints",
        ExpectedMin: 200,
        ExpectedMax: 500,
        Keywords: []string{"def", "List", "Optional", "mid"],
    },
}

// 每小时发送一次探针请求
func (td *TrustworthinessDetector) RunProbe(providerID int64, modelName string) {
    probe := selectRandomProbe(modelName)
    resp, err := td.sendRequest(providerID, modelName, probe.Input)

    // 验证输出
    if len(resp.Content) < probe.ExpectedMin {
        td.recordAnomaly(providerID, "output_too_short")
    }

    keywordCount := countKeywords(resp.Content, probe.Keywords)
    if keywordCount < len(probe.Keywords) / 2 {
        td.recordAnomaly(providerID, "missing_expected_keywords")
    }
}
```

#### 方法 3: LLM-as-Judge 质量评估

使用独立的评判模型评估输出质量：

```go
func (td *TrustworthinessDetector) assessOutputQuality(
    providerID int64,
    modelName string,
) float64 {
    // 从最近100个请求中随机抽样10个
    samples := td.db.GetRandomSamples(providerID, modelName, 10)

    scores := []float64{}
    for _, sample := range samples {
        // 使用 GPT-4 作为 Judge（或本地开源模型）
        prompt := fmt.Sprintf(`
评估以下 AI 助手回答的质量（0-1分）：

用户问题：%s
AI 回答：%s

评分标准：
- 准确性 (0.4)
- 完整性 (0.3)
- 推理清晰度 (0.2)
- 格式规范性 (0.1)

只输出一个 0-1 之间的数字。
`, sample.Input, sample.Output)

        scoreStr := td.judgeModel.Call(prompt)
        score := parseFloat(scoreStr)
        scores = append(scores, score)
    }

    return average(scores)
}
```

### 3.3 异常模式识别

#### 模式 1: 突然变快

```sql
-- 检测 TTFT 突然下降（可能切换到小模型）
SELECT
    provider_id,
    model_name,
    AVG(ttft_ms) FILTER (WHERE timestamp > now() - interval '1 hour') as ttft_recent,
    AVG(ttft_ms) FILTER (WHERE timestamp > now() - interval '7 days') as ttft_baseline,
    (ttft_recent - ttft_baseline) / ttft_baseline as change_rate
FROM request_logs
GROUP BY provider_id, model_name
HAVING change_rate < -0.3  -- 快了 30% 以上，异常
```

#### 模式 2: Token 消耗异常

```sql
-- GPT-4 平均输出应该比 GPT-3.5 长，如果反而短了，可疑
SELECT
    provider_id,
    model_name,
    AVG(output_tokens) as avg_output,
    PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY output_tokens) as p50_output
FROM request_logs
WHERE model_name LIKE '%gpt-4%'
  AND timestamp > now() - interval '24 hours'
GROUP BY provider_id, model_name
HAVING avg_output < 300  -- GPT-4 平均应该 > 500
```

#### 模式 3: 错误率突然下降

```sql
-- 如果一个供应商的 GPT-4 错误率突然降到 0，可能切换到更稳定的小模型
SELECT
    provider_id,
    model_name,
    COUNT(*) FILTER (WHERE status_code >= 500) * 100.0 / COUNT(*) as error_rate
FROM request_logs
WHERE timestamp > now() - interval '1 hour'
GROUP BY provider_id, model_name
HAVING error_rate < 0.1 AND COUNT(*) > 1000  -- 错误率过低也可疑
```

## 5. 告警规则

### 5.1 P0 严重告警（立即人工介入）

| 触发条件 | 阈值 | 动作 |
|---------|------|------|
| 可信度 < 60 | 持续 30 分钟 | **立即停用** + 飞书 @所有人 + 合同审查 |
| 多维度同时偏离 | ≥ 3 个维度偏离 > 30% | 降权 80% + 立即人工审核 |
| 探针连续失败 | 连续 3 次 | 降权 50% + 人工审核 |

### 5.2 P1 警告告警（24小时内处理）

| 触发条件 | 阈值 | 动作 |
|---------|------|------|
| 可信度 70-79 | 持续 2 小时 | 降权 30% + 记录 + 飞书通知 |
| 单维度严重偏离 | 任一维度 > 50% | 持续监控 + 增加探针频率 |
| 质量评分下降 | 低于基线 0.15 | LLM-as-Judge 深度评估 |

### 7.2 基线数据收集

**冷启动问题**：新供应商没有历史数据怎么办？

**解决方案**：
1. 使用官方模型（Anthropic/OpenAI）作为"黄金标准"
2. 新供应商前 1000 次请求作为"观察期"
3. 对比新供应商与黄金标准的偏离度

```go
// 黄金标准：使用官方 API 建立基线
func buildGoldenBaseline(modelName string) *ModelBaseline {
    officialAPI := getOfficialAPI(modelName)  // Anthropic/OpenAI 官方

    // 发送 100 个标准测试请求
    for _, testCase := range standardTestCases {
        resp := officialAPI.Call(testCase.Input)
        collectMetrics(resp)  // TTFT, tokens, quality
    }

    return aggregateBaseline()
}
```

## 8. 成本控制

### 8.1 探针请求成本

- 每个供应商每小时 1 次探针 = 24 次/天
- 假设 10 个供应商 × 24 次 = 240 次/天
- 每次探针成本约 $0.01
- **总成本**: $2.4/天 ≈ $73/月（可接受）

### 8.2 LLM-as-Judge 成本

- 每个供应商每小时抽样 10 个请求评估
- 10 个供应商 × 24 小时 × 10 样本 = 2400 次/天
- 每次评估成本约 $0.005
- **总成本**: $12/天 ≈ $360/月

**优化**：
- 仅对"存疑"供应商增加评估频率
- 使用本地开源 Judge 模型（Llama 3, Qwen）降低成本

```go
func (td *TrustworthinessDetector) saveEvidence(providerID int64, event *TrustworthinessEvent) {
    evidence := &Evidence{
        ProviderID: providerID,
        EventType: event.Type,
        Timestamp: time.Now(),

        // 原始数据

        JudgeScores: event.JudgeScores,
```

### 10.2 路由决策更新

```go
func (de *DecisionEngine) filterByQuality(candidates []*Provider) []*Provider {
    var qualified []*Provider

    for _, p := range candidates {
        profile := de.qualityStore.Get(p.ID)

        // 原有过滤
        if profile.QualityScore < 60 {
            continue
        }

        // 新增：可信度过滤（红线）

            log.Warn("provider %d filtered out: trustworthiness too low (%.2f)",

            continue
        }

        qualified = append(qualified, p)
    }

    return qualified
}
```
