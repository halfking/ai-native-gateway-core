# 算法与外部项目选型

## 1. 选型结论

没有发现一个成熟开源项目同时提供：完整历史导入、自动主题/项目分类、稳定项目 ID、项目级人工 split/merge、摘要与知识图谱持续更新、运行时记忆和独立评估。v3 采用组合式架构，外部项目只在旁路 worker 或 adapter 中复用。

| 层 | v3 选择 | 说明 |
| --- | --- | --- |
| 文本规范化 | 规则、脱敏、hash、既有 preview/turn | 低成本、可回放、无需模型 |
| 边界检测 | idle gap + turn role/intent change + embedding distance | 时间线索不能单独决定 split |
| 任务归类 | 受控 taxonomy + 规则/已有 `work_type` + embedding top-k + 受限 LLM | 输出候选和证据，不自由生成无限标签 |
| 主题聚类 | embedding → HDBSCAN/BERTopic；保留 noise | 候选聚类，不生成稳定项目 ID |
| 实体关系 | 归一化词典 + LLM candidate + 时序有效期 + 人工确认 | 初期 PostgreSQL，规模后接图 adapter |
| 记忆 | session summary/fact/procedure 分层，按作用域检索 | 复用 OmniRoute/Mem0/LangMem 的思路 |
| 人工闭环 | 自建 override/event/projection；可选 Label Studio 前端 | split/merge 语义不能依赖外部项目默认行为 |

## 2. 分类算法

### 2.1 三级决策

```text
受控标签/明确规则
      │高置信直接候选
      ▼
embedding 召回 taxonomy top-k
      │相似度、租户历史、上下文特征
      ▼
受限 LLM 判别（只能从候选集合选择或 abstain）
      │
accepted / candidate / unknown
```

特征优先级：人工 override > 明确用户标签/项目上下文 > `task_type_chosen`/`work_type` > 规则关键词 > embedding 相似度 > LLM 判别。每个候选保存 evidence spans、source、score、model/rule version。

建议初始标签命名空间：`task`、`project`、`role`、`domain`、`risk`。标签 taxonomy 由租户管理，模型不能自动创建生产标签；新标签先进入 review queue。

### 2.2 置信度和 abstain

- 规则有冲突时不强选；
- top-1 与 top-2 差距小于阈值时返回 `candidate`；
- LLM 输出非法标签、证据缺失或与输入不一致时拒绝；
- `unknown/noise` 是合法结果；
- 阈值按标签命名空间和评估集校准，不用单一全局阈值。

## 3. 边界、聚类和人工组织

### 3.1 会话内拆分

边界 score 可组合：

```text
boundary = w1 * idle_gap
          + w2 * intent_change
          + w3 * entity_change
          + w4 * embedding_distance
          + w5 * explicit_user_marker
```

时间 gap 是候选信号，不是最终事实。split 后保留原 `session_id` 和 turn scope，生成逻辑 thread/project membership；原始 session 不被复制成多个事实会话。

### 3.2 跨会话聚类

推荐 pipeline：sentence embedding → 可选 UMAP → HDBSCAN/BERTopic → c-TF-IDF/关键词解释 → cluster candidate。关键规则：

- 保留 HDBSCAN noise；
- cluster label 由关键词/LLM 解释，但 label 不是 stable project ID；
- 新数据优先增量 assign，周期性重跑发现漂移；
- 重跑创建新的 `cluster_run_id`，不覆盖历史 run；
- 人工 include/exclude/split/merge 永远优先；
- 评估使用 purity、ARI、NMI、coverage 和 stability，不能只看 cluster 数量。

### 3.3 实体和关系

实体抽取后先做租户内 canonicalization：大小写、别名、repo URL、服务名和 ID 归一化。关系至少包含：`works_on`、`depends_on`、`fixes`、`uses`、`belongs_to`、`replaces`。每条关系带 evidence、source、confidence、valid_from/to 和状态；冲突事实并存，current projection 根据人工优先、时间有效性和来源等级选择。

## 4. 公开项目核验与复用边界

以下能力来自公开 README/源码核验（`OPEN-SOURCE`），不是本仓库已接线事实。

| 项目 | 许可证/定位 | 可复用 | 明确限制 |
| --- | --- | --- | --- |
| [Mem0](https://github.com/mem0ai/mem0) | Apache-2.0；多级长期记忆 | fact extraction、memory add/search、向量/图配置 | 不提供项目级 split/merge 审计；需外部向量库/LLM |
| [Graphiti](https://github.com/getzep/graphiti) | Apache-2.0；实时/时序知识图谱 | episode、实体关系、时间事实、混合检索 | 不是会话项目归档器；图数据库和 LLM 成本较高 |
| [Microsoft GraphRAG](https://github.com/microsoft/graphrag) | MIT；图索引/RAG | entity/relationship、community detection、社区摘要 | 偏批处理 RAG，不负责会话生命周期和人工拆并 |
| [Neo4j LLM Graph Builder](https://github.com/neo4j-labs/llm-graph-builder) | Apache-2.0；文档到图 | schema/entity/relationship、community、Ragas 入口 | 需适配会话边界和人工项目模型 |
| [Letta](https://github.com/letta-ai/letta) | Apache-2.0；有状态 agent/memory | compact/self-summary、持久 memory blocks | 不提供跨会话主题聚类和项目审校 |
| [BERTopic](https://github.com/MaartenGr/BERTopic) | MIT；embedding + UMAP/HDBSCAN + c-TF-IDF | 主题聚类、解释、topic merge/reduce/visualization | 参数敏感；人工 split/稳定 ID/审计需自建 |
| [Label Studio](https://github.com/HumanSignal/label-studio) | Apache-2.0；通用标注平台 | 预标注、批量标注、人工审校和 ML backend | 不是现成会话聚类器；split/merge 语义需自定义 |
| [Basic Memory](https://github.com/basicmachines-co/basic-memory) | AGPL-3.0；Markdown/wikilink 图谱 | 可读项目 workspace、人工编辑、ChatGPT/Claude 导入 | 不可靠地自动拆混合会话；AGPL 需单独合规评估 |
| [LangMem](https://github.com/langchain-ai/langmem) | MIT；LangGraph memory | namespace、manage/search memory、增量 running summary | 默认内存 store 不适合生产持久化；无项目聚类 UI |
| [Memori](https://github.com/MemoriLabs/Memori) | Apache-2.0；结构化记忆/混合召回 | conversation turn、entity/fact、summary/recall | 项目归并拆分不是主 API；项目自报 benchmark 不等于独立复现 |
| [Cognee](https://github.com/topoteretes/cognee) | 开源 memory/knowledge graph | remember/recall/forget/improve、图与 session memory | 后端选择和许可证需最终复核；非现成项目组织器 |
| [Claude Constellation](https://github.com/Eburstz/claude-constellation) | MIT；历史扫描/语义分组 | idle gap 切 arc、TF-IDF/embedding、kNN、label propagation、digest | 原子粒度偏 session/arc；没有持久人工 split/merge 模型 |

## 6. 组合和合规建议

- **MVP**：规则/已有字段 + sentence embedding + BERTopic/HDBSCAN + 自建人工 override；外部项目只做离线 worker 参考。
- **生产记忆**：优先评估 Mem0、Memori、LangMem 之一；由 adapter 统一 tenant/scope/retention，不能把外部 API 直接暴露给 Gateway 热路径。
- **时序关系**：Graphiti 或 Cognee 作为可选 adapter；初期 PostgreSQL relation table 更易 RLS、审计和回滚。
- **人工工作台**：可嵌 Label Studio，但 split/merge 事件、stable project ID、冲突处理必须由 v3 数据模型拥有。
- **许可证**：Apache/MIT 与 AGPL 的部署、修改、网络服务义务必须由法务确认；本文不构成合规结论。
