# 验收与评估

## 1. 验收原则

验收不能只看 HTTP 200。必须同时验证 Go 代码、SQL/RLS、worker、API 权限、前端行为、真实数据库、部署回滚和线上观测。没有真实 PG/RLS 证据的项目只能标记 `CURRENT-PARTIAL` 或 `MIGRATION-GATE`。

## 2. 测试矩阵

| 层 | 必测内容 | 通过证据 |
| --- | --- | --- |
| Go unit | normalize、redact、hash、规则分类、阈值、事件幂等、split/merge replay | `go test ./...` 相关包 + fixture |
| Go integration | worker restart、retry/DLQ、external timeout、projection rebuild | 可重复 integration log |
| SQL | up/down、约束、唯一键、索引、retention | migration test DB |
| RLS | tenant/admin/super-admin、跨租户负向、NOSUPERUSER/NOBYPASSRLS | real PG fixture |
| API | cursor、ETag、202 job、错误码、Idempotency-Key、scope | handler/API tests |
| Security | secret scan、正文 payload 断言、日志脱敏、SSRF/URL allowlist | CI 报告 |
| E2E | 从 request/turn 到 semantic card、人工 override、stats 对账 | 跨服务 trace |
| Deployment | flag off、灰度、worker stop、projection rebuild、rollback | runbook + 记录 |

## 3. 质量指标

### 3.1 摘要

- factual consistency / contradiction rate；
- key point recall；
- human relevance、coherence、fluency；
- 事实遗漏率和敏感信息泄漏率；
- 摘要版本和输入 hash 可追溯率：目标 100%。

ROUGE/BLEU 只能作为辅助，不能替代事实一致性和人工评审。

### 3.2 分类

- task/project/role macro-F1、micro-F1；
- unknown/abstain precision；
- calibration：ECE/Brier；
- evidence validity rate；
- 人工 override rate 和 override 后回归准确率。

建议初始上线门槛：关键命名空间 macro-F1 ≥ 0.85、unknown precision ≥ 0.90；实际阈值必须由领域 golden set 校准。

### 3.3 边界和聚类

- turn/thread boundary precision、recall、F1；
- cluster purity、ARI、NMI、coverage；
- noise rate、cluster stability、跨重跑 membership churn；
- 人工 split/merge 后的 projection 一致性和撤销正确率。

### 3.4 实体关系

- entity exact/partial match；
- relation precision/recall/F1；
- canonicalization collision rate；
- temporal validity accuracy；
- 冲突关系的人工 resolution rate。

### 3.5 记忆

- session/API key/global scope 隔离负向；
- recall@k、MRR、answer correctness；
- temporal reasoning accuracy；
- stale/conflicting fact handling；
- 删除、撤回、legal hold 后不可召回率。

### 3.6 工程指标

- event consumer lag、DLQ count、replay success；
- semantic card freshness；
- worker p50/p95/p99；
- 每会话 token/embedding/LLM 成本；
- canonical/result/projection 对账差异；
- 请求 relay latency 和 error rate 必须无回归。

## 4. 自建标注集

每条 item 至少包含：

```json
{
  "item_id": "...",
  "tenant_scope": "synthetic-or-approved",
  "turn_refs": ["s-1:1", "s-1:2"],
  "boundary_gold": [false, true],
  "task_labels": ["debug"],
  "project_key": "gateway",
  "role_labels": ["developer"],
  "summary_facts": ["..."],
  "entities": [{"name": "...", "type": "repo"}],
  "relations": [{"subject": "...", "predicate": "depends_on", "object": "..."}],
  "sensitive_spans": [],
  "adjudication": "..."
}
```

标注指南必须规定：边界判定、混合任务、unknown、同义项目、时间冲突、敏感信息和摘要事实最小单元。至少双人标注，争议由 adjudicator 处理，报告 Cohen/Fleiss kappa 或 Krippendorff alpha。按时间和项目切分 train/dev/test，避免同一会话泄漏。

## 5. 外部评估集映射

- LongMemEval/LoCoMo：长期记忆、多会话事实和时间推理；
- DialSummEval：摘要质量维度；
- GoodAI LTM Benchmark：延迟回忆、冲突信息、前瞻性记忆；
- Mem0 benchmarks：工程化 ingest/search/answer pipeline 对照。

外部数据的许可证、隐私和适配成本必须单独记录；不把外部 benchmark 分数直接当成本业务上线指标。

## 6. 可复用验证命令模板

以下命令是后续实施门禁模板，本次不要求真实环境执行：

```bash
# 只读检查事实字段和目标引用
rg -n "gw_session_id|gw_task_id|task_type_chosen|work_type" \
  sql admin domains
rg -n "session_turns|session_bodies|session_clusters|session_titles" \
  sql admin domains docs

# Go 单测（实施后按包收敛）
go test ./admin/... ./domains/... ./internal/...

# secret / 正文事件检查
rg -n "api[_-]?key|authorization|password|secret|system prompt" \
  semantic-worker/ events/ --glob '*.go' --glob '*.json'

# migration 静态检查
rg -n "ENABLE ROW LEVEL SECURITY|CREATE POLICY|tenant_id|down" \
  sql/migrations sql/objects

# 真实 PG/RLS 门禁（需要显式环境变量，不使用 superuser）
TEST_DATABASE_URL=... go test ./... -run 'TestRLS|TestSemantic.*RealDB'

# 结果重算/统计对账（实施后提供具体 CLI）
# semantic-worker replay --tenant ... --from ... --to ... --dry-run
# semantic-worker projection-check --tenant ... --as-of ...
```

## 7. 验收报告必须包含

- commit、migration、wiring 和 feature flag；
- 测试命令、环境和完整结果；
- 真实 PG/RLS 角色证明；
- 样本量、数据集版本、模型/规则版本；
- 延迟、成本、错误、DLQ、freshness 和对账差异；
- 灰度范围、回滚演练和未通过项；
- 任何未实施/跳过项必须写明原因，不得用“已完成”替代。
