## 3. 现有数据字段的使用边界

### 3.1 `request_logs`

推荐读取：

- 身份与租户：`tenant_id`、`api_key_id`、`owner_user`、`application_code`；
- 会话关联：`gw_session_id`、`gw_task_id`、`parent_request_id`；
- 文本线索：`request_preview`、`response_preview`、按策略允许的 body 引用；
- 工作线索：`task_type`、`work_type`、`task_type_chosen`、`confidence_num`、`strategy_used`；
- 质量/资源：token、cost、latency、success、quality flags、compression metadata。

正文不应被复制进事件 payload；语义 worker 应保存 `body_ref`、sha256、长度、脱敏版本和 retention policy。

### 3.2 V2 tables

`public.session_turns` 负责 turn metadata 和 V3.2 T0-T9 队列时间戳，`public.session_bodies` 负责 request/response delta 与 outbound body，`public.session_turn_logs` 负责短期环节状态。v3 的 canonical input 是按 `tenant_id + session_id + turn_no + request_id` 稳定排序的规范化 turn。旧 `gateway.*` 只作为 migration 513 之前的历史 schema 记录。

## 4. 修正决策（ADR）

### ADR-V3-001：旁路异步

语义分析只能通过 terminal event/outbox 或受控 backfill 触发，不同步阻塞 relay 请求。LLM、embedding、图服务失败只影响派生结果，不影响 canonical request/turn。

### ADR-V3-002：原始事实不可变

原始 request/response、turn、人工操作事件 append-only。摘要、标签、聚类成员和图关系均为带 `result_version` 的派生事实或投影，可作废但不可静默覆盖历史证据。

### ADR-V3-003：候选和事实分层

规则/模型产生 `candidate`；人工确认或达到明确自动门槛后才产生 `accepted`。查询默认返回当前有效事实，并提供 evidence、source、model_version、input_hash 和 freshness。

### ADR-V3-004：人工事实优先

人工标签、include/exclude、split/merge override 优先于模型结果。模型重跑不得删除 override；只有显式撤销事件才能使其失效。

### ADR-V3-005：租户与正文最小化

所有语义表携带 `tenant_id` 并启用 RLS；跨租户查询按认证主体确定 tenant，不能信任 query 参数覆盖。事件只携带引用和最小 metadata。

### ADR-V3-006：可降级、可重算

无 LLM 时使用规则摘要/既有字段；无 embedding 时使用 lexical/coarse key；无图服务时保留关系表；所有投影可从 canonical result/event 重建。

### ADR-V3-007：稳定 ID 与聚类版本分离

`project_id`/`topic_id` 是人工或受控实体的稳定 ID；`cluster_run_id` 是一次算法运行的临时结果。聚类重跑不能自动改变已确认项目 ID。
