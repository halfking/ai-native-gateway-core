## 3. 请求事件最小结构

```json
{
  "type": "request",
  "requestId": "r-1",
  "parentRequestId": "r-0",
  "requestType": "chat|title|summary|sensitive_word|unknown",
  "tenantId": "server-derived",
  "stage": "route_resolve",
  "retrySeq": 0,
  "retryReasonClass": null,
  "model": "model-name",
  "provider": "provider-name",
  "credentialId": "redacted-or-authorized-id",
  "occurredAt": "2026-08-14T00:00:00Z"
}
```

正文、API key、authorization、系统 prompt、未脱敏附件不得进入 SSE、日志或状态事件。

## 4. queue_snapshot 最小结构

> **2026-08-15（OBS-BE3）**：pipeline 层由 TARGET 升级为 CURRENT——`pipeline`（depth/waitingMsP50/waitingMsP95/inFlight/degraded）与 `sourceVersion` 已上线。字段全部 optional：dispatch 未启用/未接线时 `pipeline` 缺省；无样本时 waitingMsP50/P95 缺省（不是 0）。实现口径见 `admin/live_stream_sse.go` `LiveQueuePipelineStats`。

```json
{
  "type": "queue_snapshot",
  "occurredAt": "2026-08-14T00:00:00Z",
  "queues": {
    "pipeline": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0},
    "model": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0},
    "credential": {"depth": 0, "waitingMsP50": 0, "waitingMsP95": 0, "inFlight": 0}
  },
  "degraded": false,
  "sourceVersion": "queue-stats-v1"
}
```

如果当前实现无法提供某个统计量，必须返回 `null` 并带 `degraded=true`，不得填零冒充真实值。队列口径必须在实现前冻结：depth、等待时间窗口、in-flight 的 owner 和采样周期。

## 5. 节点操作语义

- `test-now` 是一次受控探测，不改变 provider/credential 的长期状态；结果至少包含 success、latency、error_code、observed_at。
- `enable` 当前操作粒度是 provider，而非单个 credential。文档、前端文案和审计事件必须明确“批量影响范围”。如果需要 credential 级操作，应另立 API，不复用该端点。
- 所有状态改变必须包含 operator、reason、correlation_id、idempotency key，并记录审计；当前 `node_operations.go` 的 TODO 在审计门禁前必须关闭。

## 6. 在线会话语义

- 在线索引来自 Redis，时间线当前主要来自 `request_logs_hot`；它只能称为“在线热请求时间线”。
- 要称为“完整会话时间线”，必须补齐 `public.sessions/session_turns/session_bodies` 读取、归档数据覆盖、tenant 过滤和正文权限控制。
- 跨租户或无权资源统一返回 not found 语义，不泄露资源存在性。
- 分页、排序和 freshness 必须由 API 响应明确声明；未完成聚合返回 `degraded/stale`，不得伪装 current。

## 7. 权限与安全契约

| 操作 | 要求 |
| --- | --- |
| live-stream/trace/timeline 读取 | 管理端认证 + tenant 上下文 |
| provider test-now | 管理操作 scope + 频率限制 |
| provider enable | 管理操作 scope + 二次确认 + 审计 |
| transitions 查询 | 请求可见范围授权 |

服务端不得信任 query/body 中的 tenant_id 覆盖认证主体。错误响应使用稳定 code，不返回 SQL、上游原文或内部堆栈。

## 8. 门禁

本契约从 `CURRENT-PARTIAL` 升级为 `CURRENT` 前，必须完成：

1. 路由测试和字段 snapshot；
2. SSE 重连、旧客户端兼容和未知字段测试；
3. provider 操作权限、限流、审计和批量影响范围测试；
4. online/timeline 的 tenant 负向和归档覆盖测试；
5. 修正并审计 510/511/513 migration 的 schema 目标、执行顺序、tenant/RLS、备份和真实 PG up/down；当前 513 为 CRITICAL 阻断；
6. 前端正式接线、浏览器交互、移动/桌面视口和控制台错误检查。

# V3.3-OBS 契约冻结（2026-08-15）

## 9. request_lifecycle / child_request SSE 事件

实现：`admin/live_stream_lifecycle.go`（OBS-BE2，commit a4a4a821）。

### 9.1 request_lifecycle

```jsonc
{
  "type": "request_lifecycle",
  "ts": "2026-08-15T12:00:00Z",
  "action": { /* 单事件=对象；聚合批量帧=数组（27号 §3 ≤500ms 聚合）*/ }
}
```

- `action` 对象 = 24号 §2 的一行动作事件：`request_id`/`seq`/`action`/`ts` 必填，`model`/`credential_id`/`error_kind`/`retry_seq`/`retry` optional。
- 发射器（`internal/liveactions`）的 `detail` map 在线上**摊平到事件顶层**（`queue_depth`、`ttfb_ms`、`from_credential_id` 等），不保留 `detail` 包装键。
- 动作词汇表 = 24号 §2 的 13 种（arrive…no_route）。`state_change` 是节点维度事件，**不走本通道**（走 `node_update`/`state_transition`），且从 lifecycle 回放/推送中排除。
- 实时推送：hub 以 250ms tick 轮询 Redis LIST `llmgw:live:actions`（有界 5000，LPUSH+LTRIM），cursor 推进 + 单帧聚合，端到端 ≤500ms；重复投递 at-least-once，前端按 `(request_id, seq)` 折叠。
- 回放：连接时 `initial_data` 之后 `LRANGE 0 199`（默认 200 条），按 `(ts, seq)` 升序，畸形条目跳过。
- 租户隔离：ActionEvent 无租户字段而 actions LIST 为全局——hub 用请求流维护 request_id→tenant 有界索引 + Redis 全局 detail 兜底；归属未知的动作只发 super_admin，绝不投给租户管理员。

### 9.2 child_request

```jsonc
{
  "type": "child_request",
  "ts": "2026-08-15T12:00:00Z",
  "parent_request_id": "r-0",
  "request": { /* 与 request 事件同构 */ }
}
```

- 广播路径对带 `parent_request_id` 的请求**额外**发帧（legacy `request` 帧保留）。
- `LiveRequest` 线上同时携带 snake_case 原键（`parent_request_id`/`request_type`）与 camelCase alias（`parentRequestId`/`requestType`）；alias 仅在值非空时出现（零值不冒充）。
- `requestType` 冻结词表：`chat | title | summary | sensitive_word | probe | unknown`。持久层词表（`main/title_gen/summary/sensitive_check/compression/probe`）经 `normalizeLiveRequestType` 归一后上线；`main`/空 → 字段缺省，`compression` 及未分类 → `unknown`。
- Redis payload（`liveRequestRedisPayload`）保留 parent/type，remote hub 经 `llmgw:live:events` pub/sub 重建不丢元数据。

### 9.3 已知缺口（显式记录，禁止静默补零）

- `request` 事件的 `stage`/`retrySeq`/`retryReasonClass` 无请求侧数据源（补齐需动热路径，被 23号 §2 禁止）；前端从动作时间线派生（FE1/FE2 已消费）。`stage` 仅当后端上报时渲染。
