## 2. 已修复问题（本次提交）

### A1. force_enable / clear_circuit 不重置进程内熔断器与 fpslot 冷却【严重】
- 现象：紧急修复返回 200，但路由热路径仍被内存态挡住：`executor.go` 每候选先 `Circuit.Allow()`（domains/credential/breaker.go），OPEN 要等 cooling；`router.filterHealthyNodes` 还会被 fpslot NodeState 的 300s 冷却过滤。最坏 5 分钟不生效。
- 根因：`admin/routing.go handleEmergencyRepair` 只写 DB 列。
- 修复：
  - `domains/credential/breaker.go`：新增 `Manager.Reset(providerID, credentialID)`（单凭据复位，不影响其他凭据）。
  - `admin/handler.go`：新增 `circuitResetter` / `credStateRecoverer` 钩子与 `SetCircuitResetter` / `SetCredStateRecoverer`。
  - `admin/routing.go`：新增 `resetInMemoryNodeState()`——force_enable 清（内存熔断 + fpslot NodeState（raw_model 为空时枚举全部绑定模型逐一清零）+ credentialstate 以探测成功语义恢复）；clear_circuit 清（内存熔断 + fpslot）。
  - `cmd/gateway/main.go`：装配 `SetCircuitResetter(cm)`、`SetCredStateRecoverer(stateManager)`。
- 验收：force_enable 返回后下一个路由周期（候选缓存 ≤30s 失效后）节点可被选中。

### A2. URSM v2 清理漏"整凭据"场景【中】
- 现象：`ClearStateForTenant` / `ApplyAdmin` 仅在 `req.RawModel != ""` 时执行；不带 raw_model 的整凭据 force_enable 漏清 URSM Redis（authoritative 模式下节点仍被 manual_hold/cooling 挡住）。
- 修复：tenant 查询不再依赖 raw_model；raw_model 为空时枚举该凭据全部绑定模型，逐模型 ApplyAdmin(ManualDisabled=false) + ClearStateForTenant。响应新增 `ursm_v2_models_covered`。

### A3. rate_limit 首败不触发主动自检【中】
- 现象：`domains/credentialstate/manager.go` 的 `probeImmediately` 集合含 network/timeout/upstream_down/overloaded/stream_timeout/transient，唯独不含 rate_limit（尽管 isTransient 含它）——上游 429（常为分钟级窗口）恢复要等 threshold=2 兜底，节点被排除时间被拉长，正是"上游可用但网关排除"的常见成因之一。
- 修复：`KindRateLimit` 加入 probeImmediately；首败即触发 active probe（退避链自动接管后续）。

### A4. 单节点超时默认 120s 与 FirstByteTimeout 180s 脱节【中】
- 现象：FirstByteTimeout 2026-08-04 已升到 180s，`llmgw_node_timeout_seconds` 默认仍 120s，且注释仍写"与 120s 对齐"；executor_chat.go 中 NodeTimeout 仅在更大时生效——120<180 恒不覆盖，node 层可能先于首字节超时截断长思考模型。
- 修复：默认值 120→180（hotconfig 与 Default 同步），注释更新并写明约束 `NodeTimeout ≥ FirstByteTimeout`。

### A5. resolve 无负缓存【低】
- 现象：未注册模型在正 TTL 窗口外每次请求都打 DB（singleflight 只防并发不防重复）。
- 修复：未命中（DB 正常返回空）以短负缓存（min(ttl/4, 30s)，下限 5s）缓存 passthrough；**DB 错误不负缓存**（基础设施故障≠真实的"模型不存在"）。

## 5. 路由流程核实摘要（作为基线存档）

客户端请求 → `streaming.ChatHandler` →（auto 魔数解析 `autoroute.Decider` / `resolve.Resolver` canonical→alias→raw→passthrough，缓存 120s+负缓存）→ `provider.GetCandidates`（`v_routable_credential_models`，30s candCache）→ `executors.Router.PlanCandidatesWithContext`（URSM 过滤→状态后端过滤→压力惩罚→fpslot 健康→计费轮次→tier 内 Bandit/P2C+并发能力加权→sticky/协议亲和→降级放行）→ `Executor.Execute`（fpslot Acquire→Circuit.Allow 半开槽→Limiter.AcquireAll→转发；失败分类→切下一候选；同 provider content_filter 短路；无候选→同步探测 hold）→ 成功副作用（sticky/Recorder/Bandit/NodeProbeHealthy/URSM.RecordRequest）。
负载均衡权重=凭据并发能力（`concurrency_limit_auto` 封顶手动值，clamp [1,1000]），符合"按供应商凭据并发能力加权"的要求。
