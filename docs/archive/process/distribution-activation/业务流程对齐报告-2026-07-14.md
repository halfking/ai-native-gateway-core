# 业务流程对齐报告 · 2026-07-14

## 结论

当前实现已经覆盖“License 创建/激活/查询、客户端本地升级/回滚、中心节点心跳和命令记录”这些技术能力，但还没有覆盖完整业务流程。后续交付标准必须从“接口存在”切换为“角色可以完成流程，状态可追踪，异常可恢复，审计可导出”。

## 流程对齐矩阵

## 必须统一的业务事实

1. Trial 默认期限为 15 天；配置值由 Authority 返回，所有 UI/CLI 不得硬编码另一期限。
2. Trial 请求必须包含 `email` 和 `agree=true`；没有同意不得签发。
3. 客户网关的 `/api/system/license/trial` 只是 Authority 代理，不负责签发，不保存私钥。
4. `/api/system/upgrade/status|check` 只是查询能力，不代表升级已经执行。
5. 中心 `IssueCommand` 目前只创建命令记录，不代表客户端已经收到、确认或执行。
6. heartbeat/request telemetry 不等价于用户授权的 runtime collector；遥测必须有独立 opt-in、allowlist、保留期和删除流程。

## 方案调整规则

- 方案文档中的“已实现”必须有代码路径、测试和可观察结果三项证据。
- 设计中的 endpoint 如果尚未注册，必须标记“设计目标”，不能写进当前契约清单。
- 每个业务流程必须有角色、状态、权限、输入输出、错误码、审计事件和回滚动作。
- 技术任务按业务流程拆垂直切片，不按“先把所有 API 写完”拆水平层。

## 下一步垂直切片

1. `FLOW-ACT-01`：Trial 条款同意、Authority 配置、审计事件和浏览器/CLI/Authority e2e。
2. `FLOW-OFFLINE-01`：离线请求文件下载、审批、响应导入和失败恢复。
3. `FLOW-UPGRADE-01`：单实例升级命令签名、队列、确认、执行、结果回写和幂等。
4. `FLOW-TELEMETRY-01`：opt-in、allowlist、runtime ingest、删除和告警。
5. `FLOW-RENEW-01`：续期、吊销、降级和通知状态机。
