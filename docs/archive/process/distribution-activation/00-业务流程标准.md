# 分发与激活业务流程标准

> 本文是 `docs/分发与激活/` 的业务标准入口。技术设计、API、数据库和 UI 必须先满足本文定义的业务流程，再选择实现方式。

## 1. 业务角色

| 角色 | 责任 | 不得做的事 |
|---|---|---|
| 客户管理员 | 安装、激活、授权采集、确认升级、回滚 | 不得执行任意远程命令 |
| 客户操作员 | 查看状态、处理告警、提交诊断 | 不得签发/吊销 License |
| License Authority | 签发、续期、吊销、验证 License | 不保存客户业务内容 |
| Release Manager | 上传、校验、发布、灰度、暂停版本 | 不得绕过签名校验发布 |
| 运维管理员 | 查看节点、审批危险命令、处理告警 | 不得无审批批量执行危险命令 |
| 审计员 | 查看不可变审计记录、导出证据 | 不得修改业务状态 |

## 2. 业务对象和状态

### 2.1 License

```text
CREATED -> ACTIVATED -> ACTIVE -> GRACE -> EXPIRED
                         |          |
                         +-------> REVOKED
```

业务规则：

- Trial 默认 15 天，实际值由 Authority 配置返回，客户端不得自行计算或延长。
- 同一邮箱只能领取一次 Trial；限制必须跨 Authority 实例生效。
- 激活必须绑定 instance、hardware fingerprint 和设备上限。
- 到期进入 Grace/Restricted，不能静默删除客户数据。
- 吊销即时阻断受保护能力，并留下可审计原因。

### 2.2 Release

```text
DRAFT -> VERIFIED -> PUBLISHED -> GRAYING -> FULL
             |          |           |
             +-------> REJECTED   +-> PAUSED -> ROLLED_BACK
```

只有 VERIFIED 版本可以发布。每个版本必须有不可变 artifact、SHA256、签名、兼容性、回滚目标和发布人。

### 2.3 Upgrade Command

```text
CREATED -> APPROVED -> DISPATCHED -> RECEIVED -> CONFIRMED -> RUNNING
   |          |           |             |           |
   +-------> REJECTED   EXPIRED       REJECTED      +-> SUCCEEDED
                                                    +-> FAILED -> ROLLED_BACK
```

命令规则：

- `command_id + instance_id` 幂等。
- 命令必须绑定 TTL、Release、目标实例、签名和审批记录。
- 客户端只执行白名单结构化命令，不执行 shell 字符串。
- 断线命令进入持久化队列；过期命令不得补执行。
- 失败达到阈值时自动暂停灰度，不自动扩大范围。

### 2.4 Telemetry

```text
NOT_CONFIGURED -> OPTED_IN -> REPORTING
       |             |
       +-----------> OPTED_OUT -> DELETE_PENDING -> DELETED
```

只允许采集资源、版本、聚合流量和错误分类；禁止 prompt、completion、文件内容、API Key、密码、原始 IP/MAC。Opt-out 必须停止新采集，并产生删除请求。

## 3. 四条标准业务流程

### 3.1 获取、安装和激活

1. 客户下载已签名 Release，查看版本、平台、校验值和隐私说明。
2. Installer 检查环境、安装并生成 instance identity。
3. 客户选择 Trial、Key 或 Offline；Trial 必须填写邮箱并明确同意条款。
4. Authority 校验请求、限流、签发/激活 License 并记录审计事件。
5. 客户端验证响应、写入本地授权状态、重新加载 License。
6. UI 显示 License 状态、到期时间、设备数和下一步动作。

失败必须返回稳定错误码和可操作提示，不能只显示内部错误字符串。

### 3.2 发布和升级

1. Release Manager 上传 artifact。
2. 服务端校验 SHA256、签名、兼容性和回滚包。
3. 发布到 canary，选择目标节点并记录 rollout。
4. 客户端收到通知或轮询补偿，验证命令后等待确认/维护窗口。
5. Installer 执行备份、替换、健康检查和结果回写。
6. 指标达标后扩散；失败则暂停并提供回滚。

### 3.3 运行监控和告警

1. 客户明确 opt-in 后，采集器按白名单周期采集。
2. 客户端队列限制大小、重试次数和保留时间。
3. Authority 验证 instance token/签名、时间戳、nonce 和 payload 大小。
4. 中心写入聚合指标，按规则触发告警。
5. 运维确认、处理、关闭告警，所有动作进入审计时间线。

### 3.4 续期、吊销、降级和回滚

1. 到期前按 30/7/1 天提醒客户。
2. 续期成功后重新签发并记录 License 版本。
3. 吊销必须有原因、操作者和审批记录，并在下一次验证立即生效。
4. 升级失败自动恢复最近一次 verified 版本，保留失败证据。
5. 降级只限制受保护能力，不删除业务数据、配置或审计记录。

## 4. 流程验收模板

每个流程必须记录：

| 项目 | 必填内容 |
|---|---|
| 起点 | 操作者、前置状态、输入 |
| 状态变化 | 状态机允许的 from/to |
| 权限 | 角色、审批、客户确认 |
| 数据 | 写入表、保留期、敏感字段处理 |
| 异常 | 错误码、重试、回滚、用户提示 |
| 证据 | request_id、command_id、audit_event、截图/日志 |
| 终点 | 成功条件和可观察结果 |

任何只完成 API、没有状态、审计、异常和用户可见结果的实现，不算业务流程完成。
