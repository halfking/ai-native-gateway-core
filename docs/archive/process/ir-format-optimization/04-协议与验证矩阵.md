# 协议与验证矩阵

## 1. 协议级支持矩阵

状态含义：`已支持`、`部分支持`、`规划`、`不在范围`。能力必须绑定 endpoint/model，不能从协议名称推断。

| 协议 | 请求 | 非流响应 | 流式 | 多模态 | Usage | 现状 |
|------|------|----------|------|--------|-------|------|
| OpenAI Chat | messages/tools | choices/message | SSE chunks | image，audio 部分缺失 | totals/cache/reasoning detail 部分 | 部分支持 |
| OpenAI Responses | ordered input items | ordered output items | typed SSE events | image/file 等未原生解析 | totals/detail 部分 | 部分支持，需重构 |
| Anthropic Messages | messages/system/tools | content blocks | Anthropic SSE | image 基础；document 不完整 | totals/cache | 部分支持 |
| Gemini generateContent | contents/parts | candidates | SSE GenerateContentResponse | image/audio/video/PDF | usageMetadata | 规划 |
| Ollama `/api/chat` | messages/tools/options | message/done | NDJSON | model-dependent images | eval counts | 规划 |

## 2. Compatibility Provider Profiles

| Provider | 推荐 Adapter | Profile 重点 | 禁止假设 |
|----------|--------------|--------------|----------|
| DeepSeek | OpenAI Chat 或 Anthropic compatibility | reasoning、cache hit/miss、strict tools、支持字段子集 | compatibility 不代表支持 image/document |
| GLM | OpenAI Chat | reasoning/usage/private metadata、model-specific vision | 不泛化 `image_config`/file 字段 |
| Qwen/DashScope | OpenAI Chat 或原生后续 adapter | model/region-specific media shape | 不把 audio_url/video_url/file_url 当全局标准 |
| MiniMax | OpenAI Chat 或 Anthropic compatibility | tool ID、response metadata、endpoint product | `audio_content` 不等于 chat audio 能力 |
| Gemini OpenAI compatibility | OpenAI Chat | compatibility 支持子集 | 不等同 native generateContent 全能力 |
| Ollama OpenAI compatibility | OpenAI Chat | installed model capability | 不等同 `/api/chat` NDJSON |

## 3. Content Mapping Matrix

| Canonical | OpenAI Chat | Responses | Anthropic | Gemini | Ollama Chat |
|-----------|-------------|-----------|-----------|--------|-------------|
| text | text/content string | input_text/output_text | text block | part.text | message.content |
| image URL/data | image_url | input_image | image source | inlineData/fileData | images(base64 only, model-dependent) |
| audio | input_audio | input_audio | unsupported in Messages | inlineData/fileData | adapter/model-specific，不默认 |
| video | unsupported | unsupported | unsupported | inlineData/fileData | unsupported by base chat shape |
| document/PDF | endpoint-specific file handling，不作为 chat block | input_file | document block | inlineData/fileData | unsupported by base chat shape |
| tool call | assistant.tool_calls | function_call item | tool_use | functionCall | message.tool_calls |
| tool result | tool role | function_call_output item | tool_result | functionResponse | tool message |
| reasoning | reasoning fields/model-specific | reasoning item | thinking block | model-specific thought metadata | message.thinking |

映射表只描述 wire shape，实际支持仍由 capability set 决定。

## 4. Usage 验证矩阵

| Provider | 必须保留 | 归一化注意点 |
|----------|----------|--------------|
| OpenAI | prompt/input、completion/output、cached、reasoning、audio/prediction detail、raw usage | details 通常已包含在 totals |
| Anthropic | input/output、cache creation/read、raw usage | image/PDF 通常计入 input，不合成独立收费 |
| Gemini | prompt/candidate/total/cached、modality detail arrays、raw usageMetadata | 不把 detail 再加到 total |
| DeepSeek | prompt/completion/total、cache hit/miss、reasoning detail | compatibility stream 的 final usage chunk |
| Ollama | prompt_eval_count、eval_count、durations | durations 是 telemetry，不自动视为供应商账单 |

同一 metric 集合若同时包含 aggregate 和已包含于 aggregate 的 detail，calculator 必须 fail closed；fixture 必须验证 billing error 被记录且 tenant wallet 未扣款。

## 5. Golden Fixture 场景

每个 adapter 至少覆盖：

1. 最小 text request/response。
2. system/instructions。
3. structured output。
4. 单 tool、多 tool、并行 tool。
5. tool-only response。
6. text+tool mixed response。
7. reasoning/thinking + tool。
8. stream usage terminal event。
9. provider error event。
10. unknown event/field 保留。
11. 每种支持 media 的 URL/data/file ID。
12. 超大小、非法 MIME、能力不满足。

## 6. 计费验证用例

| 用例 | 期望 |
|------|------|
| image detail included in input total | 只按选定 rate component 结算一次 |
| provider only returns aggregate tokens | 使用 aggregate rate；不凭空拆 modality |
| provider returns audio seconds rate | 按 second component，不换算为伪 token |
| usage estimate later reconciled | 保存两版来源，生成差异，不篡改历史快照 |
| duplicate completion callback | 幂等键阻止重复 debit |
| provider cost exists, tenant rate absent | 可记录成本，但租户结算按明确 fallback/reject policy |
| rate changes at midnight | 根据 request/rate effective timestamp 选择版本 |

## 8. 资料治理

- 每个 fixture 在 metadata 中记录文档 URL、抓取日期、API version 和 model。
- 每组 fixture 使用同目录 `_fixture_meta.json`，CI 校验必填字段 `source_url`、`captured_at`、`api_version`、`model`、`provider_profile`、`redaction_version`、`fixture_kind`。
- 无可访问一手资料的字段标为 `unverified`，不能进入 canonical 标准。
- compatibility 行为优先使用真实脱敏 capture 验证。
- 原厂文档变化触发 fixture review，不直接修改历史 charge snapshot。
