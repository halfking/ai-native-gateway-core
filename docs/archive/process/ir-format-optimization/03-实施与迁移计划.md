# 实施与迁移计划

## 1. 实施原则

- 小步上线，每阶段可独立回滚。
- 先修数据丢失和错误转换，再增加协议。
- 新旧链路双跑比对，不直接替换生产主路径。
- schema migration 与应用部署分离，遵循 expand -> backfill -> switch -> contract。
- 所有 capability 和 price 变更带版本，不覆盖历史计算依据。

## 2. Phase A：止损与基线（P0）

**目标**：修复现有错误，不扩大协议范围。

任务：

1. 修复 Extensions 方向，禁止 request unknown 进入 response。
2. 增加 nested field preservation，至少保留 `image_url.detail`。
3. 为现有 OpenAI Chat/Anthropic 四象限建立 golden fixtures。
4. 为 DeepSeek、GLM、Qwen、MiniMax compatibility profile 添加真实脱敏 fixture replay。
5. 记录 conversion path、loss report、provider profile 和 fixture version。
6. 对 catalog 中 runtime 未支持的 native protocol fail closed。
7. 兼容迁移 `TransportContext`：先新增 `RequestExtensions`/`ResponseExtensions`，旧 `Extensions` 保持只读；入口同时填充旧/新字段，响应仅读取新 response bag；观测一版后删除旧字段。
8. `IR_DIRECTIONAL_EXTENSIONS` 按 request 固化选择，in-flight 请求不在处理中途切换；关闭 flag 恢复旧 transport，但仍保留 request-to-response 泄漏防护。

验收：

- 同协议 round-trip 的已知字段零丢失。
- 跨协议每个不可映射字段都有 loss report。
- request extension 不出现在 response。
- 未注册 adapter 返回明确配置错误。

回滚：关闭 `IR_DIRECTIONAL_EXTENSIONS` flag，恢复旧 transport；不涉及 DB migration。

## 3. Phase B：Responses 原生 IR（P0）

**目标**：停止把 Responses item 错转为空 message。

任务：

1. 增加 `ProtocolOpenAIResponses` 和 endpoint-authoritative detection。
2. 实现 `ParseOpenAIResponses`，支持 message、function_call、function_call_output、item reference、input_image、input_file、reasoning/tool options。
3. 实现 Responses request serializer。
4. 将 `responses.go` 的 Chat 降级逻辑移到显式 compatibility adapter。
5. 实现有状态 Responses stream assembler。
6. 对 `previous_response_id` 做无损转发，不在网关持久化状态。
7. 固定协议优先级：endpoint > internal metadata > heuristic；endpoint/body 不匹配返回 400 `protocol_body_mismatch`，禁止自动切换到 Chat adapter。

验收：

- text-only、tool-only、mixed text+tool、多 tool、image/file item 契约测试通过。
- emitted SSE item indexes 和最终 `response.completed.output` 一致。
- compatibility 降级必须产生 loss report；strict 模式拒绝有损转换。

回滚：按租户/endpoint flag 回到旧 Responses bridge。

## 4. Phase C：Canonical Media 与能力路由（P1）

**目标**：统一 image/audio/video/document 表达和模型能力判断。

任务：

1. 引入 `ContentPart.Media`、`MediaPart`、`AssetRef`。
2. 迁移现有 `ImageSource`、`Documents`、`PDFDocument` 读取路径；先双写，后删除旧字段。
3. 增加 capability set 表或 JSONB 字段，并支持 offer override。
4. 从旧 modality/tags 生成初始能力，人工审核关键模型。
5. 路由改为集合包含判断，同时校验 MIME、大小、URL/file policy。
6. compressor 改读 canonical content；被省略 media 必须产生明确摘要，不静默删除。

建议 schema：

```sql
CREATE TABLE model_capabilities (
    canonical_id integer NOT NULL,
    direction text NOT NULL CHECK (direction IN ('input','output')),
    capability text NOT NULL,
    constraints jsonb NOT NULL DEFAULT '{}'::jsonb,
    source text NOT NULL,
    verified_at timestamptz,
    PRIMARY KEY (canonical_id, direction, capability)
);

CREATE TABLE offer_capability_overrides (
    credential_model_binding_id bigint NOT NULL,
    direction text NOT NULL,
    capability text NOT NULL,
    enabled boolean NOT NULL,
    constraints jsonb NOT NULL DEFAULT '{}'::jsonb,
    PRIMARY KEY (credential_model_binding_id, direction, capability)
);
```

验收：

- vision 请求不能进入 text-only offer。
- image+audio 请求只进入同时满足两种能力的 offer。
- `multimodal` 旧值不再参与精确 SQL equality 路由。
- 大 payload、非法 MIME、SSRF URL 被预检拒绝。

回滚：保留旧 modality 查询，通过 feature flag 切回。

## 5. Phase D：Usage 指标和可审计计费（P1）

**目标**：兼容 token/image/second/tile 等单位，不重复计费。

任务：

1. 引入 `UsageMetric` 和 provider usage normalizer。
2. 保存 raw usage JSON、normalized metrics、source 和 estimation version。
3. 新建 provider/tenant rate card 与 component 表。
4. 新建 immutable `request_charge_details`。
5. 供应商成本与租户 credits 使用独立 calculator。
6. Ledger 保持 `consume`，增加 request charge 关联和幂等约束。
7. 建立 invoice reconciliation job，比较 provider usage/cost 与账单。
8. calculator 对 aggregate/detail 冲突 fail closed；检测到可能重复计费时只记录 billing error，不扣 credits。

Phase D 明确采用 JSONB-only：第一版把 raw usage、normalized metrics 和 rate snapshots 写入 `request_charge_details`，不修改 `request_logs`/`request_logs_hot` 列。稳定运行并完成查询画像后，再用独立 RFC 决定是否物化高频维度。

后续 RFC 若决定改 `request_logs`，以下步骤全部为强制门禁：

1. 盘点父表、hot 表、所有分区和脱离表。
2. 停止依赖 `SELECT *`，先发布显式列 view/function。
3. drop dependent union view。
4. 以相同顺序 alter parent 和 hot。
5. 更新 telemetry INSERT/UPSERT。
6. 更新 promotion function 和 >7 天查询。
7. 重建 view 并执行 promotion dry run。
8. 验证旧分区查询。

验收：

- 已包含在 input total 的 image detail 不会重复收费。
- 相同 request 重放不会重复 debit。
- 任意 charge 可用快照重算得到同一结果。
- supplier cost 和 tenant credits 可分别对账。

回滚：新 calculator shadow-only；未切账前只记录不扣费。切账后按 calculation version 回到旧 calculator。

## 6. Phase E：Gemini 原生 Adapter（P1）

**目标**：支持 generateContent 和 streamGenerateContent，不依赖 OpenAI compatibility。

任务：

1. `contents[].parts[]`、`systemInstruction`、tools/toolConfig、generationConfig、cachedContent 解析。
2. `inlineData` 和 Gemini Files `fileData` 映射；第一阶段只透传客户端已上传且属于同一 Gemini provider 的 `fileUri`，网关不代理上传、不管理生命周期。
3. `usageMetadata` totals/detail 归一化。
4. `streamGenerateContent?alt=sse` decoder，保留 candidate/safety/function call。
5. API key/query/header auth 和 URL builder。
6. 根据 model capability 限制 MIME、inline size、File API 要求。

验收：文本、image、audio、video、PDF、function call、stream fixtures 和真实 canary 通过。

回滚：provider profile 切回 Gemini OpenAI compatibility endpoint。

## 7. Phase F：Ollama 原生 Adapter（P2）

**目标**：正确支持 `/api/chat` NDJSON。

任务：

1. 支持 chat 的 model/messages/tools/think/format/options/stream/keep_alive。
2. 映射 `messages[].images` base64。
3. 解析 message.content/thinking/tool_calls、done/done_reason。
4. 将 `prompt_eval_count`/`eval_count` 归一化为 usage。
5. durations 仅作为性能 telemetry；本地成本使用 deployment-scoped provider rate card，scope 绑定 cluster/provider deployment，metric 可选 input/output token 或 GPU second；租户 credits 仍使用独立 tenant rate card。

验收：stream true/false、vision model、tools、thinking 和终止对象测试通过。

回滚：切回 Ollama OpenAI compatibility endpoint。

## 8. 测试门禁

每阶段必须通过：

```bash
go test ./internal/ir/... -count=1
go test ./domains/transformation/... -count=1
go test ./domains/streaming/... -count=1
go test ./provider/... ./maas/... -count=1
go test ./internal/providercap/... ./internal/upstreamurl/... -count=1
go vet ./...
```

新增测试层：

| 层 | 内容 |
|----|------|
| Unit | parser/serializer/usage/calculator |
| Golden | 原厂脱敏 request/response/SSE/NDJSON fixtures |
| Property | parse->serialize->parse 语义不变，未知字段不串方向 |
| Contract | strict/best-effort loss policy、capability rejection |
| Replay | 生产脱敏 capture 回放，比较旧/新输出 |
| Canary | 每个原厂至少 text + tool + supported media |
| Billing | snapshot 重算、幂等、double-count 防护 |

## 9. 发布指标

- `ir_conversion_total{source,target,result}`
- `ir_loss_fields_total{source,target,field,action}`
- `protocol_adapter_errors_total{adapter,stage}`
- `capability_rejections_total{capability,provider}`
- `usage_metric_source_total{metric,source}`
- `billing_reconciliation_delta{provider,model}`
- `charge_idempotency_conflicts_total`

任何阶段出现转换错误率、loss rate、计费差异或 4xx 显著上升，自动停用新路径。
