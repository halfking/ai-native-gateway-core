## 2. 发现的关键问题

### 2.1 架构缺失

**Outbox 和传输层未实现**：

| 组件 | 状态 | 影响 |
|---|---|---|
| `outbox_events` 表 | ❌ 不存在 | 无法持久化事件 |
| OutboxWriter | ❌ 未实现 | 无法与事务同提交 |
| OutboxDispatcher | ❌ 未实现 | 无法投递到 ASM |
| HMAC 签名器 | ❌ 未实现 | 无法满足 ASM 安全要求 |
| DLQ 表 | ❌ 不存在 | 失败事件无处归档 |

### 2.2 字段映射问题

**10 个缺失字段**：

| 字段 | 数据来源 | 实施难度 |
|---|---|---|
| `turn_no` | `session_turns` 表或内存计数 | 中 |
| `correlation_id` | 需设计生成规则 | 低 |
| `idempotency_key` | 需设计生成规则 | 低 |
| `provider` | routing result | 中 |
| `status` | HTTP code → enum 转换 | 低 |
| `token_usage` | response 解析 | 中 |
| `latency_ms` | 记录 start time | 低 |
| `body_refs` | body storage ref 设计 | 高 |

**1 个违规字段**：
- `user_content` - 当前在 payload 中，违反契约（02-CROSS-REPO-EVENT-CONTRACT.md §3 禁止项）

### 2.3 事件发布位置

**当前发布点**：`cmd/gateway/main_pipeline.go:838`

**问题**：
1. 只在 `LLM_GATEWAY_USE_V2_PIPELINE=true` 时触发
2. 发布到内部 `analysis_events` 表，不是 outbox
3. 未与请求事务同提交（best-effort）
4. 无重试和 DLQ

### 风险

1. **ASM 不存在** - 文档提到 ai-session-manager 是独立项目，但未找到实际仓库
