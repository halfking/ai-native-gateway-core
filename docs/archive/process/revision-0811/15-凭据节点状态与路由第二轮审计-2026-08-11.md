## 3. 已修复缺陷（commit `d8c83b74`）

| # | 严重度 | 位置 | 缺陷 | 修复 |
|---|--------|------|------|------|
| 1 | **HIGH** | `credentialhealth/checker.go` `markDegraded` model_offers 镜像 | 镜像 UPDATE 子查询 `WHERE cmb.unavailable_at = $2`，`$2 = recoverAt (= now()+15min)`；但同一函数的 cmb 主 UPDATE 把 `unavailable_at` 设为 `now()`，**不是 recoverAt** → 子查询**永不命中**，镜像 UPDATE 恒为 0 行。结果是生产路由（读 cmb）已把凭据下线，但 `/api/routing/resolve`「测试路由」（读 model_offers 视图）仍显示可用——「admin UI 与生产路由 lock-step」承诺**静默落空**。 | 镜像改为按 `(credential_id, canonical_raw_name)` 匹配 cmb 主 UPDATE 命中的同一行，并传入与 `cmb.unavailable_at` 写入值完全一致的 `now` 时间戳（`$3`），使 JOIN 稳定。cmb 主 UPDATE 同步把 `unavailable_at = now()` 改为 `unavailable_at = $4` 以传同一 `now` 值。 |
| 2 | **HIGH** | `credentialhealth/checker.go` `RecoverExpired` model_offers 恢复 | 恢复 WHERE 用 `COALESCE(mo.unavailable_at + 30s, now()+1h) < now()`，因 `unavailable_at` 非空，等价于 `unavailable_at + 30s < now()`，即**降级后 30s 即恢复**。但 cmb 主路径按 `unavailable_recover_at`（= now+15min）恢复。由于 model_offers 有 `INSTEAD OF UPDATE` 触发器，恢复会写回 cmb（清 reason/at），**30s 的过早恢复会同时把 cmb 绑定重新放回路由池**，15min 冷却被实际绕过。 | 恢复条件改为 `COALESCE(mo.unavailable_recover_at, mo.unavailable_at + 30s) < now()`，与 cmb 主路径一致（视图已暴露 `unavailable_recover_at`）。 |
| 3 | **HIGH** | `autoroute/decision_v2.go` `DecideV2` 缓存重校验 | 缓存重校验路径只调 `ValidateCachedChoice`（仅查 DB `available` + `manual%` 原因），**未查内存 `OverrideStore`**。admin 通过 override ban 的模型，对已缓存会话会**持续命中至缓存驱逐**，bypass 了 ban。 | `ValidateCachedChoice` 通过后，额外查 `d.overrideStore.GetBans(task, prof)[cached.ChosenModel]`；命中则 `Invalidate` 并落到 reclassify（与「不再可用」同一路径）。 |
| 4 | MED | `credentialfpslot/node_state.go` `recoverIfCooldownExpired` | Go 侧 `recoverIfCooldownExpired` 在冷却到期时清零 `Disabled`/`FailureCount`/`SlideWindow`/`DisabledUntil`/`DisabledReason`，**漏清 `DisableCount`**；而 Lua `recordNodeOutcomeScript` 的冷却到期+成功分支显式置 `disable_count = 0`。两条路径分歧 → 通过 `IsUsable → recoverIfCooldownExpired` 的 Go 读路径在冷却到期后看到陈旧非零 `DisableCount`，破坏该字段「用于动态冷却调整」的设计语义，直到下一次 Lua 写入才纠正。 | `recoverIfCooldownExpired` 同步置 `n.DisableCount = 0`，与 Lua 转换一致。 |

## 5. 其余审查发现（未修复，已记录）

下列为本轮审查发现但因「设计决策/低风险/超出本轮范围」未在本次修复的问题，附定位与建议：

### A. Outbox 多实例领取缺事务保护（HIGH，上线前必修）— 承自 doc 14 §6-A
- **位置**：`internal/outbox/dispatcher.go:108-119`。
- **现状**：仍未接入 `cmd/gateway`，未上线，无生产影响。
- **建议**：claim-then-deliver（`UPDATE ... SET status='processing' ... RETURNING`），HTTP 投递后置。

### B. integrity 探测 SSE task ID 不一致（MED）— 承自 doc 14 §6-B
- **位置**：`bg/probe_queue.go:99` vs `bg/active_probe_emitter.go:240`。
- **影响**：integrity 探测 pending tile 永不折叠 + 重复 terminal tile。

### C. Outbox Writer nil-tx 静默丢弃（LOW）— 承自 doc 14 §6-D
- **位置**：`internal/outbox/writer.go:78`。

### D. 路由评分 price 维度退化为近常数（MED，新发现）
- **位置**：`autoroute/scoring_simplified.go:198/248`，`priceScore = (1000 - avgCost) / 10`。
- **影响**：`avgCost` 为 per-1M-token 单价（典型 0.1~60），`1000 - avgCost ≈ 940~1000` → priceScore ≈ 94~100，几乎所有付费模型 price 维度同分，近乎丧失区分力（与 legacy `scorePrice` 的 P75 ratio 归一化不一致）。
- **建议**：改用 cohort 归一化（P75 ratio）或明确断言单价单位。本报告未改（涉及评分口径设计决策）。

### E. `DecideV2` fallback-winner 判定用浮点三连等（MED，新发现）
- **位置**：`autoroute/recommend_v2.go:493-499`（`Composite==50 && PriceScore==50 && MatchScore<=30`）。
- **影响**：正常评分候选巧合命中该三元组会被误判为 fallback winner，翻转 `FallbackUsed`。
- **建议**：fallback 路径改用显式标记（专用 `Breakdown.Source` 或 sentinel `Composite=-1`）。

### F. `index.go` 混币种评分 TODO 仍 live（MED→HIGH 视生产而定，新发现）
- **位置**：`autoroute/index.go:380` TODO + `CostContext.HasMixedPrices`（声明但从未赋值）。
- **影响**：若同 cohort 混合 CNY/USD 单价，`scorePrice` 把两种币种当作可比，扭曲价格评分。
- **建议**：评分前按 billing_currency 归一化，或按币种分 cohort。

> 混币种问题若生产确有多币种凭据，应升级为 HIGH 并优先处理；本报告因未确认生产币种分布暂记 MED。
