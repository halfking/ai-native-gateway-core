## 5. 全域回归：`go test -race ./...`

- 首跑（@78da2a0e2）：200 包中 1 包失败——`domains/pipeline` `TestRequestPipeline_ParallelOneHookFailsCancelsOthers`（"expected slow hook to observe cancellation"，0.00s 失败）。
- **根因**（实现原生，非本会话引入）：`executeParallel`（pipeline.go:222-224）goroutine 入口有 `cancelCtx.Err() != nil` 早退守卫（`8c63881f5` Phase 0 原生）——若 fast-fail 的 cancel 在 slow hook goroutine 被调度前生效，slow hook 被直接跳过、永远观察不到取消。测试（同日引入）无启动同步，断言结果取决于调度时序：单测独跑绿、整包跑必红。
- **修复**（测试确定性化，不改实现语义——早退守卫是合法优化）：fast-fail hook 阻塞等待 slow hook 的 `slowStarted` channel 信号后再报错，钉死"**已启动的** hook 会被兄弟失败取消"这一真实契约。`-race -count=3` 绿。
- **复跑全量：200 包全绿，EXIT=0。**
- 已知环境噪声（doc 33 §7 备忘）：plugin-runtime 端口耗尽类偶发，本轮未出现。

## 7. 过程发现清单（本会话记录，待后续裁决/修复）

1. **run-migrations-strict.sh 与现代 psql 不兼容**：L100-102/L114 的 `psql -c "... :'var' ..."` 在 psql 17.10（容器内）与 18.4（本机）的 `-c` 路径均不做变量插值（stdin/`-f` 路径正常）——脚本在现代客户端上无法完成逐文件校验循环。修复建议：改用 stdin/heredoc 或 `-f` 传参。
2. **空库 bootstrap 亦坏**：`startup/002_work_types.sql:38` 的 `ALTER TABLE request_logs` 无表存在性守卫，`--bootstrap` 从真空库跑必挂（request_logs 建表在 quick-init 手工 SQL，不在链内）。
3. **EnsureSeedAdmin 契约错配**：硬编码建 `admin` 用户，而 local-deploy.sh verify 约定用 `LLM_GATEWAY_ADMIN_USER` 登录——两者不一致时 verify 必 401。
4. **verify_full metrics 步骤假阴性**：`curl … | grep -q '^# TYPE'` 在 `set -o pipefail` 下因 grep 提前退出触发 SIGPIPE（curl 23）。建议 `grep -m1` 前置落盘或去 pipefail。
5. **deploy-to-252.sh 静态 key 鉴权过时**（§4）；另含已退役环境假设（8780/llm-gateway-go.service/252 .env）。处置（删除/归档/重写）待裁决。
