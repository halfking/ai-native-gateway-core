## 三、关键流程设计变更

### 3.1 OmniFree资源请求流程（新增）

```
用户请求 model=auto
  ↓
AutoCombo路由器
  ↓
评估provider候选池
  ├─ 付费tier (有credential)
  ├─ 廉价tier (低成本provider)
  └─ 免费tier (free_resource_catalog) ← 新增
       ↓
    查询quota_tracker状态
       ↓
    429错误精细分类
    ├─ rate_limit → 等待Retry-After
    └─ quota_exhausted → 切换到下一个资源
       ↓
    多Key轮换 (credential_keys表)
       ↓
    返回成功响应
```

**核心改进**:
- 免费资源从0个provider扩展到523个model
- 429错误从粗粒度"限流"细化到rate_limit/quota_exhausted两类
- 单credential支持多Key自动轮换，提升免费tier可用性

### 3.2 会话管理v2数据流（优化）

```
HTTP请求
  ↓
SanitizeInputMiddleware (脱敏 → 占位符)
  ↓
SessionCompressor.Prepare
  ├─ Phase 0: session_id校验
  ├─ Phase 1: 读V2/V1状态
  ├─ Phase 2: delta-append (增量消息)
  ├─ Phase 3: tools缓存
  └─ Phase 4: 滑动窗口评估 → 摘要/裁剪
  ↓
上游请求
  ↓
responseInterceptor chain
  ├─ output_compliance (安全检查 - 在占位符阶段)
  └─ sanitize_restore (还原占位符 - 链末尾) ← 关键改进
  ↓
request_logs落库 (存脱敏body)
  ↓
异步生成
  ├─ auto-title (首轮成功后)
  └─ auto-summary (滚动门限触发)
  ↓
TurnsListView UI展示
  └─ 标题/摘要fallback (按task_id约束) ← 新增
```

**核心改进**:
- 确认脱敏→压缩→安全检查→还原的正确顺序
- 增加标题/摘要fallback机制，提升UI可读性
- Turns列表支持session分组 + 时间窗口过滤

### 3.3 多模态请求转换流程（增强）

```
用户上传multimodal请求 (image + text)
  ↓
MultimodalParser解析
  ↓
tier-based modality推断 ← 新增
  ├─ tier-1: 原生支持 (Gemini, Claude)
  ├─ tier-2: base64转换 (GPT-4V)
  └─ tier-3: 降级纯文本
  ↓
IR Adapter转换
  ├─ Gemini: CSV用base64-encode ← 修复
  ├─ Anthropic: content blocks标准化
  └─ OpenAI: url vs base64选择
  ↓
Per-provider circuit breaker ← 新增
  ├─ 成功: 计数器递增
  └─ 失败: 熔断器开启 → fallback其他provider
  ↓
上游provider
  ↓
IR反向转换 (统一返回OpenAI格式)
  ↓
持久化到session_bodies ← 修复数据丢失
```

**核心改进**:
- 修复IR转换后多模态数据丢失（1,590行修复）
- 增加per-provider熔断器，防止单点故障
- Gemini CSV场景专门base64编码支持

### 3.4 自动路由v6决策流程（升级中）

```
model=auto请求
  ↓
解析提示词特征
  ├─ 复杂度评分 (token count, nesting depth)
  ├─ 任务类型分类 (coding, reasoning, creative) ← v6新增
  └─ 工具调用检测
  ↓
路由矩阵查询
  ├─ v6分类器 (基于GPT-4o-mini预分类) ← 接入中
  ├─ v5 featured models (精选模型优先) ← 已上线
  └─ v4 fallback (传统规则路由)
  ↓
候选池排序
  ├─ ProviderProfile评分信号 ← 增强
  │   ├─ RateLimitMetrics (速率限制历史)
  │   ├─ AvailabilityWindow (可用性窗口)
  │   └─ EffLimit (有效并发限制) ← 修复上限约束
  ├─ 成本优先级
  └─ 延迟/质量权衡
  ↓
执行 + fallback链
```

**核心改进**:
- v6分类器接入（因回归暂时revert，待修复）
- ProviderProfile评分信号持久化，支持历史趋势分析
- EffLimit修复：不超过物理ConcurrencyLimit
