# 09 - 多模态与模型契约场景

本文件补充 S01-S16，覆盖附件可靠性、慢上传、供应商重试复用、会话压缩保真和模型名称分层。

## 执行约束

- 测试附件目录使用独立临时目录，不得污染生产目录。
- 测试必须记录供应商实际收到的 model 和附件 body。
- 每个请求都按 request_id 核对日志、逻辑附件记录和物理文件。
- 默认使用 strict 附件策略；专门的 fallback 场景显式切换 best-effort。
- 供应商 failover 时检查上传计数，要求同一附件只上传一次。

## 场景矩阵

| 编号 | 场景 | 核心断言 |
|---|---|---|
| S17 | OpenAI base64 image | 文件成功落盘，manifest 完整，详情可预览和下载 |
| S18 | Anthropic base64 image | 跨协议转换后图片块和附件引用不丢失 |
| S19 | Mixed attachments | image/audio/video/pdf/file 数量、顺序和 MIME 正确 |
| S20 | Slow client | body 未读完或客户端断开时不向供应商发送 |
| S21 | Slow/failing storage | strict 阻断并记录，临时文件清理，无半文件 |
| S22 | Provider retry | A 失败后 B 复用同一 manifest，不重复上传 |
| S23 | Session compression | 摘要和窗口裁剪后附件引用仍完整 |
| S24 | Streaming cancel | SSE、failover、取消后附件状态可追溯 |
| S25 | Client casing | 所有客户端大小写映射到同一小写标准模型名 |
| S26 | Vendor casing | 供应商原始模型名大小写保留并用于出站 |
| S27 | SQL equality | 匹配字段已标准化，SQL 不用 lower 兜底 |
| S28 | Discovery idempotency | 重复采集不污染 raw/standardized/canonical 关系 |

## 结果要求

测试报告不能只报告 HTTP 成功率。每个场景至少输出：

```text
request_id
attachment_count
uploaded_count
upload_attempts
physical_file_count
manifest_status
request_refs
outbound_refs
client_model
canonical_model
outbound_model
provider_received_model
```

任何出现以下情况均判定失败：

- 附件物理文件存在但没有逻辑记录；
- 逻辑记录为 uploaded 但文件不存在；
- 供应商重试导致重复上传；
- 压缩后附件引用减少；
- 客户端模型输出非小写标准名；
- 供应商收到小写标准名而不是供应商原始名；
- 新日志包含 data URI、base64 或临时文件路径。
