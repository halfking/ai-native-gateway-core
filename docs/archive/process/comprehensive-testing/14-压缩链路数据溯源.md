## 3. 完整性校验点

### 3.1 MsgHashes 完整性（可还原 tail）

`computeHashes` 对每个消息计算指纹，`MsgHashes` 持久化到 `outbound_msg_hashes`。验证方法：

```go
// 重算 hash 应与持久化一致
hashes := computeHashes(mustExtractMessages(outboundBody))
persisted := unmarshal(res.MsgHashes)
assertEqual(len(hashes), len(persisted))
for i := range hashes {
    assertEqual(hashes[i].Hash, persisted[i].Hash)
}
```

**可还原性**：`Lossiness=tail`（mechanical_trim / strip）时，被丢弃的中间内容可从 SessionCache L1/L2/L3 / `request_logs` 完整还原。

### 3.2 SummaryMarker 完整性（whole 不可还原标记）

- `injectSummaryMarker` 在摘要 body 的首条 assistant content 前加 `smm_v1` 前缀。
- 验证：`res.SummaryMarker != ""` ⇔ 出站 body 首条 assistant content 以 `smm_v1` 开头。
- **可还原性边界**：`Lossiness=whole`（LLM summary）时，被丢弃轮次的精确措辞**不可**还原，只能还原摘要本身。这是业务预期的信息衰减，需在验证中显式断言该边界，而非当作 bug。

### 3.3 C3 ResultMemo 完整性（可还原重放）

`memoKey` 包含 `(tenant, session, mode, protocol, ctxWindow, sha256(body))`，任一维度变化即 miss，杜绝跨租户/跨会话串用。

验证：
```go
// 同 body 重试 → hit
v1 := prepareWithBody(bodyA)
v2 := prepareWithBody(bodyA)   // memo hit，跳过 summary
assertEqual(v1.CompressedBody, v2.CompressedBody)
// 跨 session 不共享
vX := prepareWithBody(bodyA, otherSession)  // miss（key 含 session）
```

### 3.4 NeverWorse 防退化

`guard.go` 保证压缩结果不得大于输入。验证：

```go
out := compress(body)
assertTrue(len(out) <= len(body), "compression must never grow the body")
```

## 4. Preview vs Prepare（C7 dry-run）

| 维度 | `Preview` | `Prepare` |
|---|---|---|
| 副作用 | **无**（不写缓存、不调 LLM、不写 memo、不发指标） | 写 L1/L2、可调 LLM、写 memo、发指标 |
| 状态依赖 | state=nil（IDLE/RECENTLY 触发惰性） | 读真实 state |
| LLM 摘要 | **不执行**（成本），只报 `WouldTryLLMSummary` | 执行 |
| 结果语义 | 压缩收益**下界**（不含 LLM 摘要节省） | 实际收益 |
| 用途 | `POST /api/admin/compression/preview` | 在线主路径 |

**验证要点**：`Preview` 调用前后 DB/Redis 无新增写入；同一 body 的 `Preview` 结果确定性（多次调用一致）。

## 6. 已知风险与审计边界

| 风险 | 说明 | 处理 |
|---|---|---|
| LLM summary 不可精确断言 | 摘要文本不固定 | 只断言 `SummaryMarker` 注入 + `Lossiness=whole`，不断言摘要内容 |
| 多模态 content 数组 | `RawContent`（未提交的工作）可能影响 hash | 本次测试用纯文本 content，多模态留待 `bodies_writer` 工作合入后补充 |
| C3 memo 跨配置 | ctxWindow/mode 变化即 miss | 测试明确覆盖 key 维度隔离 |
| 生产数据不回放 | 只用 fixture 与合成数据 | 遵守 rule 11「诚实汇报」，不声称对生产数据做过验证 |
