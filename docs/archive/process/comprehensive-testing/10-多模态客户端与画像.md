# 10 - 多模态流程与客户端画像验证

本文件是 `09-多模态与模型契约场景.md` 的运维执行伴侣 ——
覆盖本轮 (2026-07-15) 新增的多模态测试基础设施 + 客户端画像 + 真实供应商
冒烟流程。

## 1. 测试目标

| 目标 | 验证手段 |
|---|---|
| 多模态请求 (image_url / image / input_audio / file) 经过网关后,内容块和顺序保持 | `multimodal_supplier.py` 解析 + `multimodal_client.py` 断言 |
| 客户端画像四要素 (tenant_id / client_profile / identity_hash / virtual_client_id) 完整捕获到 `request_logs` | `multimodal_client.py` S23-S24 + `request_context_attrs` 写入层 |
| 真实供应商多模态模型 (火山 GLM-4.6V / 智谱 GLM-4V / DeepSeek Janus / Moonshot Kimi-VL 等) 在低速率下流程跑通 | `multimodal_real_vendor.py` |

## 2. 工具链

### 2.1 multimodal_supplier.py

`docs/全方面测试/tools/multimodal_supplier.py` (替换 09-多模态与模型契约场景.md
中提到的「每条 image_url/audio block 都要被解析」需求)

- 监听端口 19280-19284 (5 个 mock_supplier 实例,每个一组 MM)
- 端点:
  - `POST /v1/chat/completions`  (OpenAI 兼容)
  - `POST /v1/messages`          (Anthropic Messages 兼容)
  - `GET  /v1/models`
  - `GET  /healthz`
  - `GET  /admin/requests?n=1`  (返回 ring buffer 50 条)
  - `GET  /admin/request?id=...`
  - `POST /admin/requests/clear`
- 对每个请求解析 content 数组,把每个 part 归一化成 `{type, ...}` 结构,包括:
  - `image_url` 的 url 长度 + 类别 (data / http / https)
  - `image` (Anthropic) 的 base64 data 长度 + sha256 前 16 字符
  - `input_audio` 的 data 长度
  - `file` 的 file_id
  - `text` 的 text 预览
- 抓取客户端指纹头: `X-Device-Seed / X-Machine-Id / X-Client-Profile / X-Runtime-* / X-OS-* / X-Tenant-Id / User-Agent / Authorization` (后 4 位掩码)

### 2.2 multimodal_client.py

`docs/全方面测试/tools/multimodal_client.py` (8 个 scenario 覆盖多模态 + 客户端画像)

```
$ python3 multimodal_client.py --gateway http://localhost:8781 \
                                --supplier http://127.0.0.1:19280 --all
```

8 个内置场景:

| # | 场景 | 端点 | 多模态块 |
|---|---|---|---|
| S17 | OpenAI 单 image_url | `/v1/chat/completions` | 1 text + 1 image_url |
| S18 | Anthropic 单 image 块 | `/v1/messages` | 1 text + 1 image (base64) |
| S19 | 多模态混合 | `/v1/chat/completions` | 1 text + 1 image_url + 1 input_audio + 1 file |
| S20 | 多张图片 | `/v1/chat/completions` | 1 text + 3 image_url (3 不同 URL) |
| S21 | 多轮带历史图片 | `/v1/chat/completions` | 3 turn 含 1 image_url |
| S22 | 流式 + 图片 | `/v1/chat/completions` (stream) | 1 text + 1 image_url, SSE chunks |
| S23 | 客户端画像 - 设备指纹 | `/v1/chat/completions` | 纯 text (验证 fingerprint 落库) |
| S24 | 客户端画像 - 租户标签 | `/v1/chat/completions` | 纯 text (验证 X-Tenant-Id 落库) |

每个场景断言:
- HTTP 状态 200
- supplier endpoint 匹配 (`/v1/chat/completions` 或 `/v1/messages`)
- supplier model 匹配 (例如 `loadtest-vision-alpha`)
- modality 计数 (text/image/audio/file 个数) 匹配预期
- image_url 长度 > 0 (说明 URL 透传)
- text 块 + image 块的 base64 长度合理 (Anthropic)

## 4. 客户端画像 (tenant + profile) 流程

网关的客户端画像管线 (3 层):

```
   Client request               router/handlers                background pipeline
   ──────────────               ────────────────                ──────────────────
   X-Device-Seed ─┐
   X-Machine-Id  ─┼─→  identity.BuildIdentity  ─→  request_context_attrs  ─→  client_profiles
   X-Runtime-Name─┤                                  (side table)            (aggregated)
   X-OS-Arch     ─┘                                       │
   X-Client-Profile                                     │
   X-Tenant-Id                                          ↓
                                          identity_hash (SHA-256)
                                          virtual_client_id (vc-<16hex>)
                                          virtual_ip (192.0.2.x)
                                          virtual_mac (02:xx:xx:xx:xx:xx)
```

### 4.1 验证步骤

```sql
-- 1. 发出 multimodal request 带 X-Client-Profile + X-Tenant-Id
curl -X POST http://localhost:8781/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-Client-Profile: roocode" \
  -H "X-Tenant-Id: my-tenant" \
  -H "X-Device-Seed: my-device-1" \
  -d '{"model":"glm-4.6v","messages":[{"role":"user","content":"hello"}]}'

-- 2. 验证 request_logs 落库
SELECT request_id, client_profile, tenant_id, identity_hash,
       virtual_client_id, virtual_ip
FROM request_logs_hot
WHERE request_id = '<X-Request-Id 上一步的>';

-- 3. 验证 request_context_attrs (per-request 细粒度画像)
SELECT attr_key, attr_value
FROM request_context_attrs
WHERE request_id = '<X-Request-Id>';

-- 4. 验证 client_profiles (aggregated 画像)
SELECT identity_hash, virtual_client_id, total_requests, total_sessions,
       preferred_models, avg_tokens_per_turn
FROM client_profiles
WHERE identity_hash = '<hash from step 2>';
```

## 5. 已知限制 (本轮测试发现)

1. **Anthropic Messages + base64 image 失败**: 网关的 attachment 存储在
   Anthropic 原生 base64 image 块上抛 `attachment_store_failed` 错。生产
   场景下用户通过 `/v1/messages` + base64 也会失败,改用 base64 + `image_url`
   的 OpenAI 格式 (S19) 即可。
2. **fingerprint 头不转发到上游**: 网关只为上游写 `X-Request-Id` /
   `X-Gw-Session-Id` / `X-Session-Id` / `X-Virtual-*`,其余客户端指纹头
   (X-Device-Seed / X-Machine-Id / X-Client-Profile / X-Runtime-* /
   X-OS-* / X-Tenant-Id) 都只写到 `request_logs` 和 `request_context_attrs`,
   不外发到供应商。S23/S24 的 supplier 端只断言 modality 计数。
3. **fp_slot 中间件改写 X-Device-Seed**: 网关会用自己的 `llmgw-cred<N>-fp<N>`
   覆盖客户端传入的 `X-Device-Seed`,用于 fp-slot 并发控制。客户端画像
   仍在 (但 fingerprint 不是字面等值)。

## 6. 验收标准

| 场景 | 期望 |
|---|---|
| S17 (OpenAI 单 image_url) | supplier 收到 text + image_url, url 长度 > 0 |
| S18 (Anthropic 单 image) | 失败,见 5.1 |
| S19 (混合) | supplier 收到 4 个 part (text/image/audio/file) |
| S20 (多图) | supplier 收到 3 个 image_url, 长度不同 |
| S21 (历史) | supplier 收到 3 条 message, 1 个含 image_url |
| S22 (流式) | HTTP 200 SSE, supplier 收到完整 image_url |
| S23 (设备指纹) | supplier 收到 model=loadtest-vision-alpha 的纯文本 |
| S24 (租户标签) | supplier 收到 model=loadtest-vision-alpha 的纯文本 |
| 真实供应商 | 6 选 1 跑, HTTP 200, 内容是图片描述, request_logs 含画像字段 |
