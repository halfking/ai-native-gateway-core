# 网关稳定性问题排查方案

## 问题描述

**现象**: 通过网关的请求变慢且偶发中断，但直连供应商正常且快

**可能原因**:
1. 会话压缩/缓存机制引入额外延迟
2. 用户限流/降级机制触发
3. 连接指纹/并发管理导致请求排队
4. 协议转换开销 (chat ↔ response ↔ anthropic)
5. 多模态数据解析/生成开销

---

## 5+1 维度测试场景

### D1: 会话压缩与缓存

**测试目标**: 验证会话压缩和缓存对延迟的影响

**变量**:
- `X-Gw-Compression: enabled/disabled`
- `X-Gw-Cache: hit/miss`

**场景**:
```
D1a: 压缩关闭 + 缓存关闭 → 基准延迟
D1b: 压缩开启 + 缓存关闭 → 压缩开销
D1c: 压缩关闭 + 缓存命中 → 预期最快
D1d: 压缩开启 + 缓存命中 → 综合影响
```

---

### D2: 用户限流降级

**测试目标**: 验证用户级别限流对请求的影响

**变量**:
- API Key 对应的租户限流配置
- 请求频率超过限制

**场景**:
```
D2a: 正常频率 → 基准
D2b: 超过 RPM 限制 → 429 降级
D2c: 超过 TPM 限制 → 429 降级
D2d: 超过并发限制 → 请求排队/拒绝
```

---

### D3: 连接指纹与并发管理

**测试目标**: 验证连接复用和指纹对吞吐的影响

**变量**:
- 连接指纹 (fingerprint) 开/关
- 并发连接数限制

**场景**:
```
D3a: 50 并发 + 无限制 → 最大吞吐
D3b: 50 并发 + 每供应商 10 连接 → 排队等待
D3c: 突发高并发 (100+) → 连接建立延迟
```

---

### D4: 协议转换稳定性

**测试目标**: 验证不同响应格式的协议转换

**变量**:
- `response_format: chat / response / anthropic`
- 流式/非流式

**场景**:
```
D4a: chat + 非流式 → 基准
D4b: chat + 流式 → SSE 处理
D4c: response + 非流式 → 格式转换
D4d: anthropic → 特殊格式解析
```

---

### D5: 多模态数据处理

**测试目标**: 验证多模态请求的处理

**变量**:
- 文本 (text)
- 图像 (image)
- 音频 (audio)

**场景**:
```
D5a: 纯文本 → 基准
D5b: 文本 + 图像 → 图片解析开销
D5c: 长上下文 (10K+ tokens) → 上下文累积
D5d: 多轮对话 (20+ 轮) → 会话状态累积
```

---

### D6: 综合压力测试

**目标**: 组合以上所有维度，验证整体稳定性

## 测试结果记录

### D6 综合压力测试结果

| 测试场景 | 并发 | 成功率 | P50延迟 | P95延迟 | P99延迟 |
|---------|------|--------|---------|---------|---------|
| baseline-healthy | 20x2RPS | 100% | 82ms | 150ms | 390ms |
| baseline-gzip | 20x2RPS + gzip | 100% | 88ms | 211ms | 405ms |
| baseline-sticky-nocache | 20x2RPS + sticky | 100% | 82ms | 129ms | 357ms |
| D6-chaos-mixed | 20x2RPS + 混合故障 | 100% | 78ms | 133ms | 390ms |

### 关键发现

1. **压缩开销**: gzip 压缩增加约 6-8ms P50 延迟
2. **故障容错**: 20% 供应商故障 (server_error/slow/quota) 下仍保持 100% 成功率
3. **会话复用**: sticky session 对延迟无明显影响
4. **稳定聚合**: 网关成功将多路不稳定供应商聚合成稳定输出
