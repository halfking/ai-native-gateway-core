# 11 - 请求错误分类与环境门禁（2026-07-18）

## 1. 目标

测试报告必须区分三类结果：

1. **网关行为错误**：路由、重试、熔断、状态恢复或响应契约不符合预期。
2. **供应商模拟错误**：Mock 按场景主动返回 429、5xx、超时、断流或格式错误。
3. **测试台错误**：数据库结构、扩展、端口、容量或脚本自身导致测试无效。

只有第 1 类可以直接归因于 Gateway。第 2 类必须验证 Gateway 是否按契约收敛；第 3 类必须阻断验收，不能用成功率掩盖环境失效。

## 2. 最近一周请求错误分类

| 分类 | 典型信号 | Gateway 期望动作 | 关联场景 |
|---|---|---|---|
| 客户端请求格式错误 | 无效 JSON、缺少 model、工具字段类型错误 | 4xx 快速失败，不污染供应商状态 | S10、S14、S17-S24 |
| 未知模型 | `invalid_model` / `model_not_found` | 400，不能降级为 503 no_candidate | S14 |
| 无候选节点 | `no_candidate` | 503，有限重试/探测，不死循环 | S13、S15 |
| 客户端认证/会话错误 | 401/403、错误 `X-Gw-Session-Id` | 归类 client，不熔断供应商 | S13、S14 |
| 网关限流 | Gateway 自身 token bucket / semaphore 拒绝 | 标记 `rate_limited`，不计入供应商失败率 | S07、S12 |
| 供应商 429 | RPM、配额或一次性额度耗尽 | 重试下一候选，保留 quota/rate-limit 原因 | S04、S06、S11、S16 |
| 供应商 5xx | 500/502/503、flaky | 记录 upstream 错误并降权/熔断 | S05、S06、S13、S15 |
| 供应商认证失败 | 401 或凭证不可解密 | 凭证 fatal，跳过该凭证，不误伤同供应商其它凭证 | S13、S15 |
| 网络波动 | connection refused、connect timeout、read timeout | 有界重试并切换候选，记录网络根因 | S06、S12、S15 |
| 空响应/探测超时 | `empty_response`、`probe_direct_timeout` | 短时 degraded，触发探测，不永久禁用节点 | S06、S12、S15 |
| 流式异常 | SSE 中途断开、缺 `[DONE]` | 标记 stream failure，切换候选或返回可识别错误 | S09、S12 |
| 工具调用错误 | tool input schema、tool call id、function_call_output 不匹配 | 归类 client/format，不把供应商节点标坏 | S17-S24 |
| 响应格式错误 | 非 JSON、choices 缺失、模型字段漂移 | 进入格式转换/校验失败路径，保留 request_id | S09、S10、S17-S24 |
| 数据库/状态存储错误 | schema mismatch、JSONB 参数类型、写入失败 | 记录 storage error，阻断依赖该数据的场景 | 全场景前置门禁 |

最近一周重点变更包括：`probe_direct_timeout`/`empty_response` 瞬时降级、429 统计统一、流式断开处理、MiniMax 工具调用格式校验、NVIDIA relay 模型字段映射和请求级 IR 日志。每次回归都必须检查这些错误不会被错误地归因到供应商健康状态。

## 3. 252 → 本地数据库同步门禁

### 3.1 必须满足

- 源端：252 的 `pg-252-pg17`，通过证书登录 `root@<env:HOST_252>`，SSH 端口 `${PORT_SSH_252}`。
- 目标端：本地 Docker 容器 `llm-gateway-pg`，PG17，使用绑定目录 `${LOCAL_PGDATA_PATH}`。
- `vector`、`citus`、`citus_columnar` 扩展必须能实际 `LOAD`，不能只存在于 `pg_extension` catalog。
- schema 对象计数和关键对象清单一致后，才允许执行 Gateway 场景。
- 完整同步前必须产生本地可恢复备份；备份失败时必须停止。

### 3.2 2026-07-18 实测结果

| 项目 | 252 | 本地 | 结论 |
|---|---:|---:|---|
| public tables | 273 | 271（同步预演后出现不完整表壳） | 未通过 |
| public columns | 4448 | 4382 | 未通过 |
| public indexes | 790 | 741 | 未通过 |
| public views | 35 | 35 | 仅此项一致 |
| public functions | 483 | 481 | 未通过 |
| RLS policies | 69 | 64 | 未通过 |
| triggers | 33 | 33 | 仅此项一致 |

实测证据：

- 252 可通过 `root@<env:HOST_252>:${PORT_SSH_252}` 证书连接，远端 PostgreSQL 为 17.10 x86_64。
- 本地 PostgreSQL 为 17.10 arm64。
- 本地原镜像 catalog 中存在 `vector 0.8.5`，但缺少 `vector.so`；换用本地 vector 镜像后，加载 `vector 0.8.3` 触发 `SIGILL`，日志为 `server process ... terminated by signal 4: Illegal instruction`。
- `pg-table-copy.sh --schema-only --dry-run` 正确阻断了继续同步。
- `sync-252-schema-only.sh` 预演曾创建不完整的 `session_bodies`、`session_turns`、`sessions` 分区表壳；脚本把部分 psql 错误误报为成功，必须在下一次同步前修复失败检测。

### 3.3 恢复条件

1. 构建或取得与本机 ARM CPU 兼容、且与 252 pgvector 主版本匹配的本地 PG17+Citus+pgvector 镜像。
2. 用新容器挂载同一数据目录后，执行 `LOAD 'vector'`，确认不会触发进程崩溃。
3. 人工确认并清理本次预演留下的不完整表壳，或从同步前备份恢复数据库。
4. 修复 `sync-252-schema-only.sh` 的错误码检查和序列依赖处理。
5. 重新执行 `pg-table-copy.sh`，通过 schema/object diff 后才执行 seed 和 Gateway 压测。

## 4. 验收规则

- 测试台门禁失败：报告状态为 `BLOCKED_ENVIRONMENT`，不计入 Gateway 通过率。
- Mock 返回预期故障：必须同时检查 Gateway 的状态分类、候选切换、日志和最终响应。
- 预期错误场景（S13/S14）不能按普通成功率判断，必须按错误码、响应状态和无死循环判断。
- 压测出现 P99 超阈值但成功率正常时，必须同时报告 CPU、连接数、Mock 容量和数据库等待，不能直接归因于代码。
- 所有结果文件必须带 commit、Gateway 版本、数据库 schema gate、Mock 数量和场景配置摘要。
