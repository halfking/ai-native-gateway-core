# S60: 跨环境网络模拟测试

> **安全边界**：公网入口只代理 `/healthz` 与 `/v1/*`。所有 `/admin/*` 控制接口仅允许从 252 本机访问，不得通过公网 Nginx 暴露。

**目标**: 验证网关在真实网络条件下（本地客户端 → 阿里云 252 服务器 → Mock 供应商集群）的稳定性与聚合能力。

**核心价值**: 将多个不稳定的供应商进行聚合，输出一个稳定的大模型服务。

---

## 前置条件

### 1. 部署 Mock Suppliers 到 252

```bash
# 在 252 服务器上执行
# 1. 安装 Python 3.11
dnf install python3.11 python3.11-pip -y
python3.11 -m pip install aiohttp==3.9.1

# 2. 创建目录并上传文件
mkdir -p /opt/mock-suppliers
# 上传 mock_supplier.py, mock_orchestrator.py

# 3. 启动 60 个实例；只绑定回环地址，由本机 nginx 访问
for i in $(seq 0 59); do
    port=$((19080 + i))
    group_idx=$((i / 5))
    instance=$((i % 5))
    group=$(printf "\\$(printf '%o' $((65 + group_idx)))")
    nohup python3.11 mock_supplier.py \
        --port $port --host 127.0.0.1 --group "$group" --instance $instance \
        > /tmp/mock_${group}${instance}.log 2>&1 &
done
```

> 不要使用 `--host 0.0.0.0`：这会绕过 Nginx 的访问控制，直接把供应商 API 和管理接口暴露到公网。

### 2. 配置 Nginx 负载均衡

上传 `deploy-252/s60-mock-suppliers.conf` 到 `/etc/nginx/conf.d/`，然后：

```bash
nginx -t && systemctl reload nginx
```

公网配置只允许 `/healthz` 和 `/v1/*`，并拒绝 `/admin`、`/admin/*`；管理操作必须在 252 本机通过 `127.0.0.1:19080-19139` 执行。不要把 19080-19139 或 19900 加入公网安全组。

### 3. DNS / Hosts 映射

本地测试需要将 `s60.itestu.cn` 指向 252 IP：

```bash
# /etc/hosts (macOS/Linux)
115.29.212.252  s60.itestu.cn
```

### 4. 验证部署

```bash
# 252 上验证
curl http://localhost:19900/healthz      # nginx 健康检查
curl http://localhost:19080/healthz       # 单个 mock supplier

# 本地验证
curl http://s60.itestu.cn/healthz
```

## 测试场景

### S60-1: 基础连通性测试

验证本地 → 252 → Mock 供应商的完整链路。

```bash
curl -X POST http://s60.itestu.cn/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"minimax-m3","messages":[{"role":"user","content":"hello"}],"max_tokens":10}'
```

**预期**: 返回 200 OK，响应包含 `[X/Y] mock-pong: hello`

### S60-2: 高并发压力测试

```bash
python3 << 'EOF'
import asyncio, aiohttp, time

async def run():
    async with aiohttp.ClientSession() as s:
        sem = asyncio.Semaphore(30)
        results = {"ok": 0, "err": 0}

        async def req(i):
            async with sem:
                try:
                    async with s.post(
                        "http://s60.itestu.cn/v1/chat/completions",
                        json={"model":"minimax-m3","messages":[{"role":"user","content":f"ping{i}"}],"max_tokens":10},
                        headers={"Authorization":"Bearer test-key","Content-Type":"application/json"},
                        timeout=aiohttp.ClientTimeout(total=20)
                    ) as r:
                        results["ok" if r.status==200 else "err"] += 1
                except: results["err"] += 1

        t0 = time.time()
        await asyncio.gather(*[req(i) for i in range(500)])
        print(f"500 reqs in {time.time()-t0:.2f}s, ok={results['ok']}, err={results['err']}")

asyncio.run(run())
EOF
```

**预期**: ≥99% 成功率，P99 延迟 <200ms

### S60-3: 供应商故障聚合测试

使用 `mock_orchestrator.py` 将部分供应商设为故障状态，验证 Gateway 的候选切换、错误分类、日志和最终响应。以下控制命令必须在 252 本机执行：

```bash
# 将 A 组全部设为故障状态
python3 mock_orchestrator.py set-group A server_error

# 将 B 组设为慢响应
python3 mock_orchestrator.py set-group B slow

# 故障场景结束后恢复
python3 mock_orchestrator.py reset-all
```

**预期**: 客户端仍能获得稳定响应；同时 Gateway 必须记录候选切换和供应商错误分类。

### S60-4: 环境门禁与结果记录

S60 结果必须记录以下字段；门禁失败时状态只能写 `BLOCKED_ENVIRONMENT`，不能计入网关成功率：

- Git commit、Gateway 版本和启动参数
- 数据库 schema/object gate、扩展 `LOAD` 检查和本地可恢复备份状态
- Mock 数量、端口范围、故障 profile、并发度和请求总数
- 成功率、错误分类、P50/P95/P99、CPU、连接数、Mock 容量和数据库等待
- 每个预期故障场景的 Gateway 状态分类、候选切换、日志和最终响应

本次 500 请求压测只验证了“本地客户端 → 252 Nginx → Mock 集群”链路；没有执行 Gateway、数据库 schema gate 或供应商故障聚合验证，因此不能将该结果表述为完整 Gateway 稳定性验收。

## 已知 Bug 修复

### Bug: Mock Supplier POST 无响应

**症状**: `curl -X POST http://localhost:19080/v1/chat/completions` 返回空响应（连接被关闭）

**根因**: `chat_completions` handler 中 `_do_chat_completions(request)` 的返回值未传递出去，导致 aiohttp 收到 None 并关闭连接。

**修复**:

```python
# 错误
await CONN_MGR.acquire()
try:
    await _do_chat_completions(request)  # 返回值被丢弃
finally:
    CONN_MGR.release()

# 正确
await CONN_MGR.acquire()
try:
    return await _do_chat_completions(request)  # 返回 Response 对象
finally:
    await CONN_MGR.release()
```

同时 `ConnectionManager.release()` 必须是 `async def`。
