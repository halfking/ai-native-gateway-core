# 15 - 缓存链路完整性验证

> **版本**: v1.0
> **日期**: 2026-08-08
> **相关**: [13-会话逻辑测试方案.md](13-会话逻辑测试方案.md)
> **核心源码**: `domains/hooks/compression/session_cache.go`、`domains/session/v2/`
> **目标**: 验证压缩会话状态在 **L1（内存）→ L2（Redis）→ L3（PostgreSQL）** 三层之间的数据一致性、可降级、可冷启动恢复。

---

## 1. 三层缓存架构

| 层 | 存储 | 键格式 | 容量/策略 | 出处写入 | 目标读取 |
|---|---|---|---|---|---|
| L1 | 内存 LRU | `tenantID:gwSessionID` | 字节预算 LRU | `SessionCache.Set` (L383) | `SessionCache.GetOrLoad` (L300) |
| L2 | Redis Hash | `compression:session:cache:v1:{tenant}:{sessID}` | `sessionCacheRedisTTL()` env | `saveToRedis` (L493) | `loadFromRedis` (L471) |
| L3 | PostgreSQL | `request_logs`（V1）/ `session_bodies`（V2） | 持久 | `SessionBodiesWriter` | `loadFromDB` (L502) / `TurnReader.LoadChain` (L64) |

### V2 独立缓存（`domains/session/v2/cache_v2.go`）

| 类型 | 作用 | 键 |
|---|---|---|
| `CompressionMetaCache`（L1 内存 LRU） | 存 `SessionStateV2`（CompressionMeta + GovernanceMeta，不含完整消息体） | `tenantID+sessionID` |
| `RedisGovernanceCache`（L2 Redis） | 仅 governance verdicts | 可配 |
| `SessionTurnsReader`（L3 pgxpool） | 从 `gateway.session_turns` 冷启动 | sessionID |

---

## 2. 缓存读取路径（降级链）

```
GetOrLoad(ctx, tenantID, gwSessionID)
    ├─ L1 内存命中 → 返回
    ├─ L1 miss → L2 Redis 命中 → 写回 L1 → 返回
    ├─ L2 miss → L3 DB（loadFromDB）→ 写回 L1/L2 → 返回
    └─ 全 miss → 新会话（空 state + 空 lastOutboundBody）
```

V2 读取路径（`SessionCompressor.shouldUseV2` 为 true 时优先）：

```
HasState(ctx, tenantID, sessionID)
    ├─ true → Builder.BuildLatestOutbound → lastOutboundBody（冷启动从 session_bodies 重建）
    └─ false/error → fallback V1（GetOrLoad）
```

---

## 3. 完整性校验字段

| 字段 | 作用 | 验证方法 |
|---|---|---|
| `SchemaVersion` | 版本门禁，防新旧混用 | 读回时断言 = 当前 `schemaVersion` |
| `LastOutboundHash` | **缓存完整性核心**（`sha256Hex(outboundBody)`） | 写后读回，断言 hash 一致 |
| `MsgCount` / `TokenEstimate` | 结构一致性 | 写后读回比对 |
| `SummaryMarker` | 摘要标记保留 | 写后读回比对 |
| `ToolsHash` | 工具缓存比对 | 写后读回比对 |

## 4. 验证场景

| 场景 | 触发 | 断言 |
|---|---|---|
| S14A V2 冷启动 | 空缓存 + `session_bodies` 有历史 | `LoadChain` 重建 body 与 `request_logs` 一致 |
| S14B L1→L2→L3 降级 | 逐层淘汰/失效 | 每层回退后数据最终一致 |
| S14C 缓存写回 | `Set` 后 | L1 命中 + L2 hash 一致 |
| S14D 失效 | `Invalidate` 后 | L1/L2 条目删除，下次回源 |
| S14E V1/V2 隔离 | `fromV2=true` | 不写 V1 缓存（防毒化，见 `updateCache` L667） |

### 4.1 V1/V2 隔离验证（关键）

`updateCache`（`session_compressor.go` L667）在 `fromV2=true` 时**跳过 V1 写回**，防止 V2 空 `SessionState` 毒化 V1 缓存。验证：

```go
// V2 读路径处理后，V1 缓存不应被写入
compressor.Prepare(ctx, body, tenant, sess, protocol, win, false) // fromV2=true
_, _, err := v1Cache.GetOrLoad(ctx, tenant, sess)
assertTrue(err == nil && state == nil) // V1 无污染
```

## 6. 已知边界

| 边界 | 说明 | 处理 |
|---|---|---|
| L1 字节预算淘汰 | 大会话可能提前淘汰 L1 | 测试用可控体积 fixture |
| V2 表迁移中 | `session_bodies` 可能非全部历史 | 冷启动验证用确定性 fixture |
| Redis 连接 | 测试需真实 Redis | 未连接时该场景标记 `BLOCKED_ENVIRONMENT` |
