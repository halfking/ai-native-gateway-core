## 252 同步流程

1. 先对 252 做只读 schema 快照：表、列、索引、`schema_migrations`、最近写入时间。
2. 确认当前 gateway 已停止写入或处于可控维护窗口。
3. 复制正向 SQL 到 252，执行并保存完整 `psql` 输出。
4. 执行 SQL 内置验证；失败时事务应回滚，不允许继续重启服务。
5. 重启 gateway 后发送一条测试租户请求。
6. 查询 `request_wal_hot`、`request_logs_hot`、`routing_decision_log_hot` 最近 5 分钟写入。
7. 失败时先执行 feature flag/服务回滚，再评估数据库回滚；不要删除 additive columns。

## 风险

- 正式脚本会创建缺失的 hot 表，前提是对应 parent 表存在；如果 parent 也缺失，验证会失败并回滚。
- down 脚本不删除 additive columns，保护已写入 telemetry；完整回滚应通过数据库快照或人工批准的专用 down migration。
- 本地 migration harness 仍会跳过部分生产分区迁移，不能用本地分区布局替代 252 schema 快照。
