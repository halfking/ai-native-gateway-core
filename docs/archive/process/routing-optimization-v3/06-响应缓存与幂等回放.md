# 响应缓存与幂等回放

> 解决"超时/取消后重试"和"请继续/请重试"场景，实现三层层叠缓存。

## 1. 场景分析

```
时序:
  T0: 客户端发送 R1 (requestID_1, 消息 M)
  T1: 网关转发到供应商
  T2: 供应商已接收并处理中
  T3: 客户端超时/取消
  T4: 供应商完成响应, 到达网关
  T5: 客户端发送 R2 (requestID_2, 相同消息 M)
  T6: 或客户端发送 "请继续"
```

**目标**: T5 时直接回放 T4 缓存的响应, 不重新路由。

## 2. 三层缓存架构

## 3. 回放判定逻辑

```go
func (h *ChatHandler) shouldReplay(ctx context.Context, req *Request, env *URSMEnvironment) (*Response, bool) {
    // Step 1: Request ID 去重
    entry := h.idempotentCache.Check(req.SessionID, req.RequestID)
    if entry != nil {
        if entry.Status == "completed" {
            return entry.Response, true
        }
        // in_progress: 返回 202 Pending
        return h.pendingResponse(req, entry.Token)
    }
    h.idempotentCache.MarkInProgress(req.SessionID, req.RequestID)

    // Step 2: Prompt Hash 缓存
    promptHash := hashPrompt(req.Messages)
    cached := h.sessionResponseCache.Get(req.SessionID, promptHash)
    if cached != nil && time.Since(cached.CreatedAt) < h.cfg.ResponseCacheTTL {
        binding := h.bindingMgr.Get(req.SessionID, req.StdModel)
        if binding != nil && binding.RawModel == cached.RawModel {
            // 缓存命中, 回放
            env.Binding.CacheHit = true
            return cached.Response, true
        }
        // 模型变了, 缓存不适用
        h.sessionResponseCache.Invalidate(req.SessionID, promptHash)
    }

    // Step 3: "请继续" 意图
    if h.isContinuationIntent(req) {
        pending := h.pendingStore.GetLatest(req.SessionID)
        if pending != nil && pending.Status == "completed" {
            // PendingStore 有完整响应
            return pending.Response, true
        }
    }

    return nil, false
}

func (h *ChatHandler) isContinuationIntent(req *Request) bool {
    // 检查最后一条用户消息
    lastMsg := req.LastUserMessage()
    if lastMsg == "" {
        return false
    }
    // 关键词匹配: 请继续, 继续, continue, 请重试, retry
    // 由 intent analysis hook 或插件判断
    // 返回 true 仅当:
    //   1. 会话中已有历史记录
    //   2. 消息短 (<50 chars)
    //   3. 上下文偏向延续意图
    return h.intentAnalyzer.IsContinue(lastMsg)
}
```

## 4. 缓存回放约束

| 约束 | 说明 |
|------|------|
| TTL 窗口 | 默认 5min, 可在插件配置中调整 |
| 模型一致性 | rawModel 必须相同 (不同供应商回复不同) |
| 完整响应 | 仅完整成功的响应可缓存, partial 不缓存 |
| 流式完整 | 所有 chunk 接收完毕后才缓存 |
| 客户端标记 | 回放时 X-Gw-Replay: true, 计费审计可归因 |
| 敏感信息 | 缓存不含凭据密钥, 仅响应体 |
| 幂等保证 | 同 promptHash 最多回放一次 |
| 容量限制 | 每会话最多缓存 10 条 (FIFO 淘汰) |

## 5. PendingStore 生命周期

```
Request → upstream
  → 客户端断开 → Cancel upstream context
  → PendingStore.MarkInProgress(sessionID, requestID)
  → 继续接收上游响应
  → 接收完成: PendingStore.Save(completed, body)

客户端重连:
  → GET /v1/sessions/{id}/pending-response?request_id=xxx
  → in_progress: 202 + Retry-After: 5
  → completed: 200 + body + X-Gw-Pending-Replay: true
  → failed: 200 + error_message

客户端发送新请求 (同 prompt):
  → handler.shouldReplay → Layer 2 缓存命中
  → 直接返回

客户端发送 "请继续":
  → handler.shouldReplay → intent 分析 → Layer 3
  → PendingStore.GetLatest → 返回
```
