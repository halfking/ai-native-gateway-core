# 资源门禁与等待语义

> FP Slot、Concurrency Slot 的独立管理、AcquireUntil 等待语义以及绑定感知的资源分配。

## 1. 资源模型

### 1.1 双维度分离

```go
// FP Slot: 限制同时连接的不同客户端身份数
//   - 粒度: (credentialID, model)
//   - 目的: 防止指纹识别/同 IP 并发过多
//   - 特征: 同一 session 复用 slot, pin 机制

// Concurrency Slot: 限制同时活跃的请求数
//   - 粒度: (credentialID)
//   - 目的: 防止凭据过载
//   - 特征: 每个活跃请求占用 1 个 slot
```

### 1.2 ResourceGate 接口

```go
type ResourceGate interface {
    AcquireFPSlot(ctx context.Context, credID int, model string, binding *SessionRouteBinding, deadline time.Time) (bool, error)
    ReleaseFPSlot(ctx context.Context, credID int, model string, sessionID string, requestID string) error

    AcquireConcSlot(ctx context.Context, credID int, binding *SessionRouteBinding, deadline time.Time) (bool, error)
    ReleaseConcSlot(ctx context.Context, credID int, sessionID string, requestID string) error
}
```

### 1.3 AcquireUntil 语义

```go
// AcquireUntil: 等待资源直到 deadline, 不立刻失败
//   行为:
//     资源可用 → 立即获取
//     资源占用 → 等待至 deadline
//     deadline 到 → 返回 false, 不超时
//   适用: 已绑定会话 (保持路由稳定)
//   不适: 未绑定会话 (切换到下一候选)
```

## 2. FP Slot 管理

### 2.1 Pin 机制

```go
// 同一 session 的同一 credential 复用同一 slot:
//   Key: ursm:fp_pin:{sessionID}:{credentialID}
//   Value: slotIndex
//   TTL: 1h (每次请求自动刷新)

// 获取流程:
func (m *FPSlotManager) AcquireFPSlot(ctx context.Context, credID int, model string, binding *SessionRouteBinding, deadline time.Time) (int, bool) {
    if binding != nil {
        return binding.FPSlotIndex, true    // 已绑定, 复用 slot
    }

    pinKey := fmt.Sprintf("ursm:fp_pin:%d", credID)
    if slotIndex, ok := redis.Get(pinKey); ok {
        return slotIndex, true              // Pin 复用
    }

    // 空闲槽分配
    slotKey := fmt.Sprintf("ursm:fp_slot:%d", credID)
    for i := 0; i < slotLimit; i++ {
        // Lua: SETNX slot:{credID}:{i} sessionID
        if acquired := redis.SetNX(slotKey, sessionID, ttl); acquired {
            redis.Set(pinKey, i, ttl)
            return i, true
        }
    }

    // 无空闲槽 + 已绑定 → wait
    if binding != nil && !deadline.IsZero() {
        return m.waitForSlot(ctx, credID, deadline)
    }

    // 无空闲槽 + 未绑定 → 降级
    return m.lruEvict(ctx, credID)
}
```

### 2.2 等待语义

```go
func (m *FPSlotManager) waitForSlot(ctx context.Context, credID int, deadline time.Time) (int, bool) {
    // 使用 Redis Pub/Sub + timeout:
    //   1. SUBSCRIBE urms:fp_slot_evict:{credID}
    //   2. 等待消息或 deadline
    //   3. 收到消息 → 尝试获取
    //   4. deadline 到 → 返回 false

    sub := m.redis.Subscribe(ctx, fmt.Sprintf("ursm:fp_slot_evict:%d", credID))
    defer sub.Close()

    ch := sub.Channel()
    for {
        select {
        case <-ch:
            // 有资源释放, 尝试获取
            if slot, ok := m.acquireInternal(ctx, credID); ok {
                return slot, true
            }
        case <-ctx.Done():
            return 0, false
        case <-time.After(time.Until(deadline)):
            return 0, false
        }
    }
}
```

### 2.3 LRU 抢占

```go
// 完全无空闲槽 + 无绑定 → LRU 抢占
//   1. 遍历所有 slot, 找 last_access 最早的
//   2. 更新 URSM 和 downstream:
//      - 旧 session 的 binding 标记 invalidated
//      - 通知旧 session (异步)
//   3. 分配给当前请求
//   约束: 仅未绑定会话可被抢占
```

## 3. Concurrency Slot 管理

### 3.1 全局计数

```go
// Key: ursm:conc_slot:{credentialID}
// Lua: GET → INCR → CMP → EXPIRE (原子操作)

// Redis Lua:
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local ttl = tonumber(ARGV[2])
local current = redis.call('GET', key)
if current and tonumber(current) >= limit then
    return 0  -- 超限
end
local new = redis.call('INCR', key)
redis.call('EXPIRE', key, ttl)
return new
```

### 3.2 会话计数

```go
// Key: ursm:conc_session:{credentialID}:{sessionID}
// TTL: 60s (每个 session 最多 1 个并发请求)
//   如果 session 已有并发请求, 排队等候或拒绝
```

### 3.3 释放

```go
func (m *ConcurrencySlotManager) Release(ctx context.Context, credID int, sessionID string, requestID string) error {
    // Lua: DECR + 通知 waiters
    local key = KEYS[1]
    local notifKey = KEYS[2]
    redis.call('DECR', key)
    redis.call('PUBLISH', notifKey, sessionID)
    return true
}
```

## 4. Provider Gate

```go
type ProviderGate struct {
    ProviderID      int
    FpSlotEnabled   bool
    ConcSlotEnabled bool
    AutoGate        bool     // 开关: 超过 N 模型 broken 时自动降低权重
    ModelBrokenCount int32   // 连续 broken 模型数
    Weight          float64  // [0, 1], 用于 P2C 加权
}

// AutoGate 逻辑:
//   模型 broken ≥ 3 → Weight *= 0.5
//   模型 broken ≥ 5 → Weight *= 0.2 (大部分流量避开)
//   模型全部恢复 → Weight *= 1.0 (慢恢复)

// Gate 检查:
func (g *ProviderGate) Allow(providerID int) bool {
    // 不阻塞请求, 仅降低权重
    // 除非 ManualDisabled
    return !g.ManualDisabled
}
```

## 5. 绑定感知的资源分配

### 5.1 等待 vs 跳过 决策

| 场景 | 已绑定 | 未绑定 |
|------|--------|--------|
| FP Slot 满 | AcquireUntil(deadline) | 尝试下一候选 |
| Concurrency 满 | AcquireUntil(deadline) | 尝试下一候选 |
| 断路器 Open | wait_or_reject(breaker) | 跳过该候选 |
| Provider Gate disabled | N/A (绑定已失效) | 跳过该候选 |

### 5.2 单候选中资源顺序

```go
// 顺序: Provider Gate → FP Slot → Concurrency → CB

// 这是因为:
//   1. Gate 检查最快 (内存)
//   2. FP 获取后 pin session, 不再变更
//   3. Concurrency 获取后请求保护, 再进入 CB
//   4. CB 检查 (内存) — 最后, 因为半开状态需要放行探测
```
