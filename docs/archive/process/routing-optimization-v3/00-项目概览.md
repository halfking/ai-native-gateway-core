# 路由优化 v3 — 统一路由状态管理系统 (URSM)

> 基于代码审计、全场景纸面推演与生产问题分析形成的完整设计方案。
> 2026-07-13

## 1. 项目背景

当前系统存在以下核心问题：

### 1.1 状态一致性
Router、ProbeV2、StateManager 各自更新状态，无统一协调。FpSlot 节点状态与 StateManager 存在重复。

### 1.2 5xx 立即降级
二次 5xx 就写入 DB 降级 (breaker threshold=2)，未等待探测确认。供应商瞬时闪断会被持久化为不可用。

### 1.3 生产场景漏洞
- 供应商超时后客户端取消 + "请继续" 请求 → 无响应缓存回放机制
- 流式响应已输出部分内容后断流 → 无安全拼接机制
- 超时 KindTimeout 可能来自客户端 context → 无法区分错误来源

### 1.4 与会话治理脱节
路由决策未暴露细粒度 Hook 点，会话治理、审计、成本优化等无法以插件形式接入。

## 2. 设计原则

| 编号 | 原则 | 说明 |
|------|------|------|
| P1 | 单一数据源 | 每种状态只有一个权威来源 |
| P2 | 原子更新 | 状态变更要么全成功要么全失败 |
| P3 | 稳定优先 | 未发生上游错误不得切换路由；厂商缓存优先 |
| P4 | 错误确认 | 瞬态错误需探测确认后方可持久降级 |
| P5 | 可观测 | 每个决策点通过 Hook 暴露，可追踪可回放 |
| P6 | 插件化 | 额外功能以插件形式扩展，不破坏核心不变量 |

## 3. 架构全景

```
Request
  │
  ├─ Layer 1: 身份与限流
  │   Auth → RPM/TPM → API Key Concurrent
  │   Hook: PhasePreRouting
  │
  ├─ Layer 2: 路由选择
  │   Binding Lookup → Candidate Load → Cost Score → Select
  │   Hook: PhaseRouting
  │
  ├─ Layer 3: 资源门禁
  │   Provider Gate → FP Slot → Concurrency → Circuit Breaker
  │   Hook: PhasePreUpstream
  │
  ├─ Layer 4: 上游执行
  │   Protocol Convert → Upstream Call
  │   Hook: PhasePostUpstream
  │
  └─ Layer 5: 后处理
      State Record → Binding Create/Update → Resource Release
      → 响应缓存 (新) → 幂等去重 (增强)
      Hook: PhasePostResponse
```

## 4. 核心概念

### 4.1 状态层级

```
Provider (enabled/manual_disabled)
  └─ Credential (active/auth_failed/quota_exhausted)
       └─ Model (active/probe_pending/broken_confirmed)
            └─ Node (available/circuit_open/consecutive_failure)
                 └─ Binding (strong/soft/reevaluating/invalidated)
```

### 4.2 资源双维度

| 维度 | 用途 | 粒度 | 超限行为 |
|------|------|------|----------|
| FP Slot | 限制同时连接的客户端身份数 | credential+model | 未绑定: 尝试下一候选；已绑定: wait-or-reject |
| Concurrency | 限制同时活跃的请求数 | credential | 同上 |

### 4.3 绑定级别

| 级别 | 触发条件 | 锁定范围 | 解绑条件 |
|------|----------|----------|----------|
| L1 强绑定 | prompt>2000 tokens 或 cached>0 | credential+provider+rawModel+fpSlot | 仅上游实际错误 |
| L2 软绑定 | 短请求无缓存 | credential+provider | 上游错误或成本劣化>阈值 |
| L3 无绑定 | 首次请求或绑定失效 | 无 | 每次重新选路 |

## 5. 关键改进

| 改进 | 现有缺陷 | 方案 |
|------|----------|------|
| 5xx 降级 | 2 次即写 DB | 半开失败 >=3 或滑动窗口确认才写 DB |
| 响应缓存 | 无跨 requestID 缓存 | 三层缓存: requestID→promptHash→PendingStore |
| 流式安全 | 断流可透明拼接 | 维护 response_started 标记，已输出禁止拼接 |
| 错误溯源 | KindTimeout 来源混乱 | 增加 error_origin=client/gateway/upstream |
| Hook 暴露 | 无细粒度 Hook | 25+ Hook 点，插件化架构 |
| 状态原子 | 多路径各自写 | StateRecorder Lua 原子写入 + 级联传播 |
