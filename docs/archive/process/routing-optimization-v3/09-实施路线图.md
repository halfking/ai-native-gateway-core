# 实施路线图

> 分阶段实施，每阶段可独立交付和验证。

## 1. 阶段划分

```
Phase 1: 5xx 分级降级 (P0, 2 周)
  - 修复最严重的生产问题
  - 影响: breaker.go, checker.go, writer.go, manager.go

Phase 2: 响应缓存 (P0, 2 周)
  - 修复超时/取消后重试问题
  - 影响: cache/session_response, handler.go, PendingStore

Phase 3: 智能绑定 (P1, 2 周)
  - 绑定系统的完整实现
  - 影响: domains/binding, router.go, ursm/*

Phase 4: 资源门禁增强 (P1, 2 周)
  - AcquireUntil 等待语义
  - 影响: slot manager, conc manager

Phase 5: 成本评分与 P2C (P1, 1 周)
  - CostScorer 完整实现
  - 影响: domains/costscorer, router.go

Phase 6: Hook 体系与插件化 (P2, 3 周)
  - 细粒度 Hook 点 + 插件接口
  - 影响: domains/hooks, 内置插件

Phase 7: 全场景集成测试 (P2, 2 周)
  - 27+ 场景的端到端测试
  - 影响: e2e/tests/

Phase 8: 可观测增强 (P2, 1 周)
  - 全面指标 + 审计 + 面板
  - 影响: metrics, admin API
```

## 2. Phase 1: 5xx 分级降级 (P0, 2 周)

### 2.1 改动清单

```go
// 1. Breaker 增强 (breaker.go)
//    - 新增 halfOpenFailures / halfOpenAttempts
//    - RecordFailure 增强: 半开下累加失败计数
//    - 新增 HalfOpenFailureCount() 方法

// 2. shouldWriteDBDegradation (writer.go / manager.go)
//    - 新增函数, 替换 shouldWriteCredentialStateOnConfirmedFailure
//    - IsImmediatePersist: Auth/Quota/ModelNotFound → true
//    - IsTransientFamily: 需要 halfOpenFailures >= 3 才写

// 3. HealthChecker 增强 (checker.go)
//    - 连续成功 3 次清除窗口失败记录
//    - 最小样本数: 5 → 10

// 4. DB 冷却策略调整
//    KindTransient: 30s → 60s (分级后降级已确认)
//    KindNetwork: 120s → 300s (需要更多确认)
```

### 2.2 验证

```
1. 单元测试:
   - 偶发 5xx x1: circuit open, 不写 DB
   - 偶发 5xx x2: circuit open, half-open fail x0, 不写 DB
   - 持续 5xx x5: half-open fail >=3, 写 DB
   - 恢复后 3 次成功: 清除窗口记录
   - Auth/Quota: 立即写 DB (不受新逻辑影响)

2. 集成测试:
   - 模拟供应商 5xx 后恢复, 验证 DB 降级延迟
   - 模拟授权失败, 验证立即写 DB

3. 回归测试:
   - 正常请求不受影响
   - 断路器半开探测正常
```

## 3. Phase 2: 响应缓存 (P0, 2 周)

### 3.1 改动清单

```go
// 1. SessionResponseCache (新增 cache/session_response/)
//    - Store/Get/Invalidate
//    - promptHash 计算 (Stabilize + SHA256)
//    - TTL 管理 (默认 5min)
//    - 容量控制 (每会话 10 条, FIFO)

// 2. IdempotentCache 增强 (domains/streaming/idempotent.go)
//    - 追加 PendingStore 状态查询
//    - completed 状态直接返回缓存

// 3. PendingStore 增强 (pending/pending.go)
//    - GetLatest(sessionID) 方法
//    - 取消后继续接收, TTL 缩短 30min

// 4. handler.go
//    - shouldReplay 入口
//    - isContinuationIntent 检测
//    - 回放标记 X-Gw-Replay: true
//    - request_logs 标记 replayed=true
```

### 3.2 验证

```
1. 单元测试:
   - 同 promptHash 命中缓存
   - 模型变更后缓存不命中
   - TTL 过期后缓存不命中
   - "请继续" 意图识别

2. 集成测试:
   - 请求 R1 → 供应商返回 → 缓存
   - 请求 R2 (同 prompt, 5s 内) → 缓存回放
   - 请求 R3 (5min 后) → 缓存过期, 正常路由

3. 回归测试:
   - IdempotentCache 原逻辑不受影响
   - PendingStore 原逻辑不受影响
```
