# 02 · 常用模型分级自检（2026-08-13，审计修订 2026-08-13）

需求补充：**针对常用模型，强化自检操作；其它模型可以减少自检的频度。**

## 常用模型判定

常用模型 = **静态精选 `routing_policy.featured_models` ∪ 用量 Top-N**（`request_logs_hot` 近窗口成功调用最多的 N 个模型）。与 daily-selfcheck 的 `featured→most_used` 分级一致，最贴合"常用"语义。

- 静态列表按租户范围限定（`probe.featured_tenant` 设置，默认 `'default'`），避免跨租户误判。
- 用量 Top-N 走 hot 表索引，ms 级；`probe.featured_usage_top_n=0` 即回退为纯静态精选（kill-switch）。
- 进程级单例 `bg.SetGlobalModelTier` + `globalIsFeaturedModel`，probe 各路径零侵入读取。
- 缓存由 `ModelTier` 每 10min 刷新一次，`atomic.Pointer[featuredSet]` 无锁读。

## 加强手段（常用模型）↔ 减弱手段（其它模型）

| 维度 | 常用模型 | 其它模型 | 配置 |
|---|---|---|---|
| 频率 | 专用深 ping（默认 15min；首轮 2min 错峰） | 健康态 watchdog ×倍（默认 ×4） | `probe.featured_cycle_seconds`(900) / `probe.nonfeatured_watchdog_multiplier`(4) |
| 深度 | chat-ping（Layer 4，计费 token） | 共识 `/v1/models` list（免费） | featuredCycle vs 共识环 |
| 队列优先级 | 高（默认 80，抢占式先执行） | 60 | `probe.featured_queue_priority`(80) |
| 失败回退 | 缩短（默认 ×0.5，更快重试恢复，下限 ≥5s 避免塌陷为 0） | 标准 7 步链 | `probe.featured_backoff_multiplier`(50%，Min=20) |

## 触发点

- **深 ping 周期**：`ModelProbeRunner.featuredCycleLoop`（`bg/model_probe.go`）。新模式（`LLM_GATEWAY_USE_NEW_PROBE_MODE=true`，默认）下用 `StartFeaturedOnly` 单独启动此周期（共识环不跑，避免与 NodeProbeWorker/CredentialSelfcheckWorker 重复写状态）。周期 2min 错峰 + 配置化 `interval`，Stop 通过 `ctx.Done()` 立即唤醒（无 2 分钟阻塞）。
- **非常用降频**（**审计修订**）：新模式下原 `applyResult` 路径不会运行，所以新加 `nonfeaturedWatchdogLoop` —— 30min 一轮、纯 SQL `UPDATE model_probe_state SET next_retry_at = next_retry_at + ($mult::int || ' seconds')::interval WHERE state='healthy_confirmed' AND NOT (raw_model IN 静态精选 OR Top-N 用量)`。零 HTTP 调用，仅时间戳推进，30min 一次。
- **队列优先级**：`NodeProbeWorker.submitViaQueue` 用 `FeaturedQueuePriority(model, 60)`（在入队时读设置，存在轻微漂移；priority 是 hint，非不变量）。
- **回退缩短**：`ProbeService.Run` 的 7 步 `backoff`，常用模型乘 `featured_backoff_multiplier`（带 ≥5s 下限防御性 floor）。

## 配置（probe.* 热加载）

| 设置 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `probe.featured_cycle_seconds` | 900（15min） | 60~86400 | 常用模型深 ping 周期（**非热加载**，需重启） |
| `probe.featured_usage_top_n` | 20 | 0~500 | 用量 Top-N 大小，0=仅静态精选（kill-switch） |
| `probe.featured_usage_window_hours` | 168（7d） | 1~2160 | 用量统计窗口 |
| `probe.featured_tenant` | 'default' | string | 静态精选列表查询的 tenant |
| `probe.nonfeatured_watchdog_multiplier` | 4 | 1~24 | 非常用健康态 watchdog 间隔倍率 |
| `probe.featured_backoff_multiplier` | 50（%） | 20~100 | 常用模型失败回退百分比 |
| `probe.featured_queue_priority` | 80 | 0~100 | 常用模型任务队列优先级 |

> 与既有 `probe.backoff_*` / `probe.broken_watchdog_hours` 不冲突；其它自检路径保留原行为。

## kill-switch / 回退

- `probe.featured_usage_top_n=0`：仅静态精选，关闭用量分级行为。
- `probe.featured_cycle_seconds` 调大即降低常用模型深 ping 频度（需重启）。
- `probe.nonfeatured_watchdog_multiplier=1`：非常用模型与常用同频（不降频）。
- `probe.featured_backoff_multiplier=100`：常用与非常用回退一致。
- 不改 routing 决策路径（`routing_policy.featured_models` 谓词读取不动），仅影响自检调度。

## 资源竞争

- 用量缓存 `atomic.Pointer[featuredSet]`（无锁读），单 goroutine ticker 刷新；prime 也加 10s 超时（防启动阻塞）。
- `ModelProbeRunner.done` 用 `sync.Once` 关闭，`StartFeaturedOnly`（无共识环）与 `Start`（有共识环）两种用法下 `Stop()` 均不死锁；`featuredCancel` 用 `atomic.Pointer` 解决 Start/Stop 重叠问题。
- 深 ping 保留 2s rate-limit（`featuredCycle` 内 `time.Sleep(2s)`，2 分钟错峰 sleep 改为 `select { ctx.Done / After }`）。

## 已知局限

- 新模式下其它模型不发起 HTTP 探测（仅时间戳扩展）；发现 regression 完全依赖 NodeProbeWorker 错误触发或 CredentialSelfcheckWorker 24h 扫。
- 与 `CredentialSelfcheckWorker` 的 Tier 1（featured）在常用模型上会有约 15min 重叠探查（计费 token 略增）；两者写不同审计表，状态机不冲突。
- `probe.featured_cycle_seconds` 标记 `HotReload:false`，运行中修改需重启（ticker 创建时绑定）。
