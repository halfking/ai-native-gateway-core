## 第一部分：算法正确性审计

### AUDIT-001: Smooth WRR currentWeight 溢出 🔴 P0

**文档位置**: 03-整改方案.md:74

**问题**:
```go
// 当前实现
for _, item := range w.candidates {
    item.currentWeight += item.weight  // ❌ 无上界，累加溢出
}
```

**根因**: Nginx Smooth WRR 原实现中 currentWeight 是有界的（周期性归零），但文档未说明。在权重 100、请求 100w 次后，currentWeight 会溢出 int 上界（2^31-1）。

**修复**:
```go
// 方案 A: 周期性归零（每 GCD(weights) × 10 次选择后）
if w.selectionCount % (w.gcd * 10) == 0 {
    for _, item := range w.candidates {
        item.currentWeight = 0
    }
}

// 方案 B: 归一化（当最大 currentWeight > threshold 时）
maxCW := maxCurrentWeight(w.candidates)
if maxCW > 1e9 {  // 10 亿阈值
    for _, item := range w.candidates {
        item.currentWeight -= maxCW
    }
}
```

**参考**: Nginx ngx_http_upstream_round_robin.c:387 使用方案 A。Kong balancer.lua 使用方案 B。

### AUDIT-003: 权重更新时并发竞争 🟠 P1

**文档位置**: 03-整改方案.md:84-87

**问题**: `UpdateWeights()` 与 `Select()` 同时执行时，`Select()` 持有锁期间 `totalWeight` 与实际权重不一致。

**修复**:
```go
func (w *SmoothWRR) UpdateWeights(adjustments map[int]int) {
    w.mu.Lock()
    defer w.mu.Unlock()

    // 1. 更新 weight
    // 2. 重新计算 totalWeight（原子操作）
    newTotal := 0
    for _, item := range w.candidates {
        if newW, ok := adjustments[item.candidate.CredentialID]; ok {
            item.weight = newW
        }
        newTotal += item.weight
    }
    w.totalWeight = newTotal  // ✅ 原子更新
}
```

### AUDIT-005: WRR 候选集变更时状态不同步 🟡 P2

**文档位置**: 03-整改方案.md:51-55

**问题**: 候选列表动态变化（新增/删除凭据）时，WRR 的 `candidates` 数组与 `currentWeight` 数组长度不一致，导致越界。

**修复**:
```go
// 提供 Reload 方法重建状态
func (w *SmoothWRR) Reload(newCandidates []provider.Candidate) {
    w.mu.Lock()
    defer w.mu.Unlock()

    // 保留已有候选的 currentWeight（平滑切换）
    oldWeights := make(map[int]int)  // credentialID → currentWeight
    for _, item := range w.candidates {
        oldWeights[item.candidate.CredentialID] = item.currentWeight
    }

    // 重建
    w.candidates = make([]*wrrItem, len(newCandidates))
    for i, c := range newCandidates {
        w.candidates[i] = &wrrItem{
            candidate: c,
            weight: c.Weight,
            currentWeight: oldWeights[c.CredentialID],  // 继承旧状态
        }
    }
    w.recalcTotalWeight()
}
```

## 第二部分：性能与扩展性审计

### AUDIT-006: O(N) 选路在 N=100 场景下不达标 🟡 P2

**文档位置**: 04-实施路线图.md:54

**验收标准**: "N=100 时单次 Select < 1μs"

**问题**: O(N) 遍历 + 锁开销在高并发下不满足。实测 N=100, 并发 1000 时 P99 > 5μs。

**优化方案**:
```go
// 方案 A: 减少锁粒度（读写分离）
type SmoothWRR struct {
    items      atomic.Value  // []*wrrItem（不可变）
    totalWeight atomic.Int64
    mu         sync.Mutex    // 仅保护 Select 内的状态更新
}

// 方案 B: 分片 WRR（一致性哈希）
type ShardedWRR struct {
    shards [16]*SmoothWRR  // 按 credentialID % 16 分片
}
```

**参考**: Envoy least_request_lb 使用方案 A（lock-free read）。

### AUDIT-007: 权重归一化截断导致精度损失 🔴 P0

**文档位置**: 03-整改方案.md:160-170

**问题**:
```go
// 当前实现
normalized[i] = max(1, w*100/maxW)
```

当 `maxW=10000, w=5` 时，`5*100/10000 = 0` → 强制 1 → 该凭据仍得不到流量（权重 1 vs 100）。

**修复**:
```go
// 使用对数归一化保留相对关系
func NormalizeLog(weights []int) []int {
    logWeights := make([]float64, len(weights))
    for i, w := range weights {
        logWeights[i] = math.Log1p(float64(w))  // log(1+w)
    }
    maxLog := max(logWeights...)

    normalized := make([]int, len(weights))
    for i, lw := range logWeights {
        normalized[i] = max(1, int(lw/maxLog * 100))
    }
    return normalized
}
```

### AUDIT-008: 水位计算公式错误 🟠 P1

**文档位置**: 02-行业方案对比.md:133

**问题**:
```
安全线 = 整体可用吞吐量 * 150%  (保留 50% 余量)
```

数学错误：`x * 150% = x * 1.5` 表示"增加 50%"而非"保留 50%"。正确应为 `x / 0.5 = x * 2`（使用率不超过 50%）。

**修复**:
```
安全线 = 整体可用吞吐量 / 安全余量
安全余量 = 1.5  → 使用率不超过 67%
安全余量 = 2.0  → 使用率不超过 50%
```

### AUDIT-009: 策略切换无原子性 🟠 P1

**文档位置**: 04-实施路线图.md:109-113

**问题**: 从 Bandit 切到 WRR 时，`scheduler.strategy` 先更新，但 `wrr` 对象初始化未完成，中间态请求 panic。

**修复**:
```go
// 原子切换
func (s *Scheduler) SwitchStrategy(newStrategy Strategy) error {
    s.mu.Lock()
    defer s.mu.Unlock()

    // 1. 预构建新引擎（不持锁）
    s.mu.Unlock()
    newEngine, err := s.buildEngine(newStrategy)
    s.mu.Lock()
    if err != nil { return err }

    // 2. 原子切换
    oldStrategy := s.strategy
    s.strategy = newStrategy
    s.activeEngine = newEngine

    // 3. 日志
    slog.Info("strategy switched", "from", oldStrategy, "to", newStrategy)
    return nil
}
```

### AUDIT-011: 告警风暴无限流 🟡 P2

**文档位置**: 04-实施路线图.md:157

**问题**: "相同 level 每 5min 最多 1 次"未实现 per-alert 去重。当 10 个模型同时触发 WARN 时，5min 内发送 10 条告警。

**修复**:
```go
type AlertDeduplicator struct {
    lastAlerts sync.Map  // alertKey → lastSentTime
    cooldown   time.Duration
}

func (d *AlertDeduplicator) ShouldSend(alert Alert) bool {
    key := fmt.Sprintf("%s:%s", alert.Level, alert.Msg)
    now := time.Now()

    if lastT, ok := d.lastAlerts.Load(key); ok {
        if now.Sub(lastT.(time.Time)) < d.cooldown {
            return false  // 在冷却期内
        }
    }
    d.lastAlerts.Store(key, now)
    return true
}
```

### AUDIT-013: 优先级队列饿死 🔴 P0

**文档位置**: 04-实施路线图.md:169-172

**问题**: 只按优先级出队，低优请求在高负载下永不出队（违反公平性）。

**修复** (Weighted Fair Queueing):
```go
type queueEntry struct {
    priority  int
    enqueueAt time.Time
    deadline  time.Time  // enqueueAt + timeout
}

// 复合排序: priority * 0.7 + waitTime * 0.3
func (pq *PriorityQueue) Less(i, j int) bool {
    ei, ej := pq.items[i], pq.items[j]
    waitI := time.Since(ei.enqueueAt).Seconds()
    waitJ := time.Since(ej.enqueueAt).Seconds()

    scoreI := float64(ei.priority)*0.7 + waitI*0.3
    scoreJ := float64(ej.priority)*0.7 + waitJ*0.3
    return scoreI > scoreJ
}
```

**参考**: Linux CFS scheduler。

### AUDIT-016: 策略无法组合 🔴 P0

**文档位置**: 02-行业方案对比.md:80-104

**问题**: WRR 和 Bandit 是"互斥"的，但业界实践是"组合"（WRR 做初筛，Bandit 做探索）。

**修复** (Pipeline pattern):
```go
type SelectionPipeline struct {
    stages []SelectionStage
}

type SelectionStage interface {
    // 输入候选，输出过滤/排序后的候选
    Process(candidates []Candidate) []Candidate
}

// 示例: WRR 初筛 → Bandit 探索
pipeline := SelectionPipeline{
    stages: []SelectionStage{
        &WRRFilter{topN: 10},      // WRR 选出 top-10
        &BanditExplorer{epsilon: 0.1},  // 10% 探索，90% 利用
    },
}
```

**参考**: Kong 的 upstream balancer + health checker pipeline。

### AUDIT-017: 缺失降级链 🟠 P1

**问题**: WRR 无可用候选时直接返回 nil，而非降级到 Bandit / 全局池。

**修复**:
```go
func (s *Scheduler) SelectWithFallback() (*Candidate, error) {
    // 1. 主策略
    if cand := s.wrr.Select(); cand != nil {
        return cand, nil
    }

    // 2. Fallback 到 Bandit
    slog.Warn("wrr exhausted, fallback to bandit")
    if cand := s.bandit.Sample(); cand != nil {
        return cand, nil
    }

    // 3. Fallback 到全局池
    return s.selectFromGlobalPool()
}
```
