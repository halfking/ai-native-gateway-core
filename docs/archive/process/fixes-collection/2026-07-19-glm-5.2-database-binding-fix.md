# GLM-5.2 Circuit Breaker 数据库绑定修复

## 问题描述

**时间**：2026-07-19 14:08
**现象**：`glm-5.2` 模型的 `credential_id=12` 从候选池中消失，无法路由

## 根本原因

**数据库配置缺失**：
1. `provider_models` 表中不存在 `glm-5.2` 的记录（provider_id=35 智谱）
2. `credential_model_bindings` 表中没有 `credential_id=12` 到 `glm-5.2` 的绑定
3. 导致 `model_offers` 视图中 `credential_id=12` 无法提供 `glm-5.2` 服务

## 修复方案

### 1. 插入模型定义

```sql
INSERT INTO provider_models (
  provider_id,
  canonical_raw_name,
  raw_model_name,
  outbound_model_name,
  last_seen_at
) VALUES (
  35,  -- 智谱 provider_id
  'glm-5.2',
  'glm-5.2',
  'glm-5.2',
  now()
)
ON CONFLICT (provider_id, raw_model_name)
DO UPDATE SET last_seen_at = now()
RETURNING id;  -- 返回 1601580
```

### 2. 绑定 credential

```sql
INSERT INTO credential_model_bindings (
  credential_id,
  provider_model_id,
  available,
  routing_tier
) VALUES (
  12,
  1601580,  -- glm-5.2 的 provider_model_id
  true,
  2
)
ON CONFLICT (credential_id, provider_model_id)
DO UPDATE SET available = true, routing_tier = 2
RETURNING id;  -- 返回 1583303
```
