# 客户端协议

## OpenAI Chat Completions

请求以 `messages[]` 表达对话。工具调用使用 assistant message 的
`tool_calls[]`，工具结果使用 `role=tool` 和 `tool_call_id`。图像通常是
`content[]` 中的 `image_url`，音频输入使用 `input_audio`，具体能力由模型声明决定。

代码入口：`internal/ir/parse_openai.go`、`internal/ir/serialize_openai.go`。

## OpenAI Responses

Responses 的 `input[]` 是有序 item，而不是 Chat 的 message 数组。文本使用
`input_text`/`output_text`，工具调用使用 `function_call`，工具结果使用
`function_call_output`，并通过 `call_id` 或 `previous_response_id` 关联。

代码入口：`domains/streaming/responses.go`。转换到 Chat 时必须保持：

| Responses item | Chat message |
|---|---|
| `function_call` | assistant `tool_calls[]` |
| `function_call_output` | `role=tool` + `tool_call_id` |
| 普通 role/content | 同 role 的 message |

不能把 Responses item 统一降级成 `role/content`，否则工具输出会变成孤儿。

## Anthropic Messages

system 位于顶层，消息 content 是 block 数组。工具调用是 `tool_use`，结果是
`tool_result`，标准字段是 `tool_use_id`。MiniMax 等兼容实现可能使用
`tool_call_id`，解析器必须兼容但序列化时绑定目标 provider。

代码入口：`internal/ir/parse_anthropic.go`、`internal/ir/serialize_anthropic.go`。

## Gemini generateContent

Gemini 使用 `contents[].parts[]`，assistant 对应 `role=model`，工具调用是
`functionCall`，工具结果是 `functionResponse`。多模态使用 `inlineData` 或
`fileData`，系统指令位于 `systemInstruction`。

代码入口：`internal/ir/parse_gemini.go`、`internal/ir/serialize_gemini.go`。

## 未知字段

OpenAI/Anthropic/Gemini parser 会把未知顶层字段放入 `Extensions`。恢复扩展字段不是
无条件行为：同协议同厂可以恢复，跨厂必须禁止；标准字段不能被 Extension 覆盖。
