# 现状确认与原厂对比

## 1. 对比方法

基于 `docs/格式转换/厂家数据格式/` 下载的原厂规范，逐字段对比当前代码实现。

**对比维度**：

- **原厂规范要求**：引用厂家数据格式目录下的规范文档
- **当前代码**：指向具体实现文件和行号
- **状态**：verified / partial / unsupported / unverified
- **证据**：测试文件路径或标注"待补 fixture"

**状态定义**：

- `verified`: 代码 + 测试 + 原厂规范三方一致
- `partial`: 主路径已实现，存在 endpoint/字段子集限制
- `unsupported`: 明确未实现
- `unverified`: 缺一手原厂资料或真实脱敏 fixture

## 11. 跨协议映射矩阵

| IR 块 | OpenAI Chat | OpenAI Responses | Anthropic | Gemini |
|---|---|---|---|---|
| text | string/content array | input_text | text block | part.text |
| image | image_url (URL/data URI) | input_image | image (url/base64/file) | inlineData/fileData |
| audio | input_audio | input_audio (endpoint-specific) | (provider-specific) | inlineData |
| video | (endpoint-specific) | (endpoint-specific) | (unsupported base) | inlineData |
| document | input_file | input_file | document block | inlineData/fileData |
| tool call | tool_calls array | function_call | tool_use block | functionCall |
| tool result | tool message (tool_call_id) | function_call_output | tool_result block (tool_use_id) | functionResponse |
| thinking | (reasoning item) | (reasoning item) | thinking block | thought part |

**映射规则**：

1. **文本**: 各协议基本一致，注意 string vs array 处理
2. **图片**: URL/base64/file 三种形态需按目标协议包裹
3. **工具 ID**: OpenAI `tool_call_id` ↔ Anthropic `tool_use_id` (MiniMax 例外使用 `tool_call_id`)
4. **思考**: Anthropic `thinking` ↔ Gemini `thought` ↔ OpenAI Responses `reasoning item`
5. **文档**: 各协议支持度不同，需按 model offer 判断
