# 多模态转换

## Canonical mapping

| IR block | OpenAI Chat/Responses | Anthropic | Gemini |
|---|---|---|---|
| text | string/content or input_text | text | part.text |
| image | image_url/input_image | image source | inlineData/fileData |
| audio | input_audio/input audio subset | provider/model specific | inlineData/fileData |
| video | endpoint/model specific | unsupported in base Messages | inlineData/fileData |
| document | input_file/file reference | document block | inlineData/fileData |
| tool call | assistant tool_calls/function_call | tool_use | functionCall |
| tool result | tool/function_call_output | tool_result | functionResponse |
| thinking | reasoning item/fields | thinking/redacted_thinking | thought |

## Source handling

- base64: 保留 MIME type 和未带 data URL 前缀的 payload；目标协议按规范包裹。
- URL/file URI: 不把 provider file URI 当公网 URL；IR 保留 `FileURI`/`FileID` 语义。
- MIME: 不能用默认 `image/png` 覆盖已知 MIME；缺失 MIME 时才使用目标协议允许的默认值。
- document: 必须保留 document source，不得因为不是 image 而转成普通文本占位符。
- unknown block: 原始 JSON 进入 `RawContent` 或 `Extensions`，并在 loss report 中记录。

## 工具和多模态混合

消息可以同时含文本、媒体和工具块。序列化器必须保持块顺序；工具调用和工具结果必须保留 ID 关联。Gemini native serializer 同时支持 IR 的 Anthropic `tool_use` block 和 OpenAI `Message.ToolCalls`，后者是本轮修复内容。

## 能力边界

能力由 model offer/profile 决定。OpenAI-compatible、Anthropic-compatible 只是格式入口，不自动获得 image/audio/video/document 全部能力。路由在能力不足时应 fail closed，而不是把媒体降级成丢失内容的文本。
