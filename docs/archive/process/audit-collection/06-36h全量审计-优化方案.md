## 三、优化方案

### 方案 A：文档治理（中优先级）

**问题**: 30.9% commit 包含文档变更。docs/ 目录 935 个文件需要索引和分类管理。

**措施**:
1. 建立 docs/INDEX.md 统一索引，所有文档在此注册
2. 设置"文档保质期"：实现完成后 7 天内必须合并/归档过期分析文档
3. 实施文档分类：`design/`（设计）、`report/`（报告）、`ops/`（运维）、`archive/`（归档）
4. handoff 文档执行后自动标记 `[EXECUTED]`，7 天未执行自动提醒

### 方案 B：回归测试体系（高优先级）

**问题**: 流式修复 16 次反复迭代无回归保护；P0 fix 无自动化门禁。

**措施**:
1. 为 streaming/ 子系统建立核心回归测试套件（10-15 个场景）
2. 每个 P0 fix 必须附带至少 1 个回归测试
3. 在 CI pipeline 中加入 `go test ./domains/streaming/...` 门禁
4. 覆盖率报告输出到 CI artifact，确保覆盖率不低于 80%

### 方案 C：Phase 1 代码集成（高优先级）

**问题**: Circuit Breaker、WRR、Unified Adapter 仍未接入生产路径。

**措施**:
1. 创建集成追踪 ticket：`phase1-integration` (3个模块 × 各自 wiring)
2. 为每个模块制定灰度开关（feature flag），先灰度再全量
3. WRR 调度器接入凭据选择路径
4. Circuit Breaker 接入 Gateway 中间件链

### 方案 D：版本管理规范化（中优先级）

**问题**: 三份 version 文件不同步，build_seq 重复/覆盖。

**措施**:
1. 统一版本 SSOT：只保留 VERSION 或 version.json（选一个）
2. 部署脚本只从 SSOT 读取版本号，禁止手动写入
3. 建立 build_seq 自动递增机制（pre-commit hook 或 CI step）

### 方案 E：Commit 质量控制（中优先级）

**问题**: 大 commit（32 文件，4448 行）违反 rule 01。

**措施**:
1. 大 commit（>10 文件或 >300 行 diff）必须拆分为逻辑子 commit
2. pre-push hook 检查 diff 行数，超限拒绝推送
3. 代码审查 checklist 增加 diff 规模项

### 方案 F：文档去重（低优先级）

**问题**: 衰减优化、价格优化、横向审计三份文档内容重叠。

**措施**:
1. 保留 docs/横向审计报告.md 为唯一 SSOT
2. 其他审计文档标记为交叉引用（`See also: docs/横向审计报告.md`）
3. 30 天后清理冗余文档到 `_archive/`
