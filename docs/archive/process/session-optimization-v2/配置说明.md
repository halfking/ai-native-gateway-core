# Sessions V2 配置说明

## 概述

Sessions V2 是会话存储的新架构，通过新的表体系（`sessions`、`session_turns`、`session_bodies`、`session_turn_logs`）来解决 `request_logs` 表的膨胀问题。

本文档说明如何通过 Feature Flag 控制 V2 的灰度发布。

## 配置方式

### 1. 数据库配置（推荐）

通过 `/api/admin/settings` API 动态修改配置，支持热重载，无需重启服务。

```bash
# 查看当前配置
curl -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  http://localhost:8781/api/admin/settings/sessions_v2.enabled

# 修改配置
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.enabled
```

### 2. 环境变量配置

通过环境变量设置，重启后生效：

```bash
export LLM_GATEWAY_SESSIONS_V2_ENABLED=true
export LLM_GATEWAY_SESSIONS_V2_SHADOW_WRITE=true
export LLM_GATEWAY_SESSIONS_V2_ROLLOUT_PERCENT=10
```

### 3. YAML 配置文件

在 `config.yml` 中配置：

```yaml
sessions_v2:
  enabled: true
  shadow_write: true
  rollout_percent: 10
```

**优先级**：数据库配置 > 环境变量 > 默认值

## 配置项详解

### 核心开关

#### `sessions_v2.enabled`
- **类型**: Boolean
- **默认值**: `false`
- **描述**: Sessions V2 总开关
- **危险级别**: Dangerous ⚠️
- **说明**: 关闭时完全使用 request_logs，开启后根据其他开关决定读写路由

#### `sessions_v2.shadow_write`
- **类型**: Boolean
- **默认值**: `false`
- **描述**: 启用副写模式
- **危险级别**: Warning
- **说明**: 同时写入 request_logs 和 V2 表，但仅从 request_logs 读取。用于验证 V2 表写入正确性
- **前置条件**: `enabled=true`

#### `sessions_v2.rollout_percent`
- **类型**: Integer (0-100)
- **默认值**: `0`
- **描述**: 灰度百分比
- **危险级别**: Dangerous ⚠️
- **说明**: V2 表的流量灰度百分比。0 表示不路由到 V2，100 表示全部路由到 V2。基于 session_id 哈希决定路由
- **前置条件**: `enabled=true`

### 读取控制

#### `sessions_v2.l3_read`
- **类型**: Boolean
- **默认值**: `false`
- **描述**: 启用从 V2 表读取（L3 缓存）
- **危险级别**: Dangerous ⚠️
- **说明**: 启用从 session_turns 读取会话数据作为 L3 缓存
- **前置条件**: `enabled=true`

#### `sessions_v2.dual_read`
- **类型**: Boolean
- **默认值**: `false`
- **描述**: 双读对账模式
- **危险级别**: Warning
- **说明**: 同时读取 request_logs 和 V2 表，对比结果差异并记录。用于验证 V2 读取正确性
- **前置条件**: `enabled=true` 且 `l3_read=true`
- **互斥**: 与 `primary_read` 互斥

#### `sessions_v2.primary_read`
- **类型**: Boolean
- **默认值**: `false`
- **描述**: V2 作为主读取源
- **危险级别**: Breaking 🚨
- **说明**: 将 V2 表作为主读取源，request_logs 作为降级备份
- **前置条件**: `enabled=true` 且 `l3_read=true`
- **互斥**: 与 `dual_read` 互斥

### 性能调优

#### `sessions_v2.write_timeout_ms`
- **类型**: Integer (100-5000)
- **默认值**: `500`
- **描述**: V2 写入超时时间（毫秒）
- **危险级别**: Safe
- **说明**: 写入 V2 表的超时时间。超时后不阻塞主流程，异步重试

#### `sessions_v2.read_timeout_ms`
- **类型**: Integer (50-3000)
- **默认值**: `300`
- **描述**: V2 读取超时时间（毫秒）
- **危险级别**: Safe
- **说明**: 从 V2 表读取的超时时间。超时后降级到 request_logs

#### `sessions_v2.compression_enabled`
- **类型**: Boolean
- **默认值**: `true`
- **描述**: 启用 V2 压缩检测
- **危险级别**: Safe
- **说明**: 检测客户端是否已压缩会话历史，标记 submit_mode 字段

#### `sessions_v2.turn_logs_retention_hours`
- **类型**: Integer (1-168)
- **默认值**: `24`
- **描述**: 环节日志保留时间（小时）
- **危险级别**: Safe
- **说明**: session_turn_logs 表中环节日志的保留时间，超时后自动清理

## 灰度发布流程

### Phase 1: 副写验证（Shadow Write）

```bash
# 1. 启用总开关和副写
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.enabled

curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.shadow_write

# 2. 观察副写指标
# 访问 /api/admin/sessions/v2/shadow_metrics
# 检查写入成功率、延迟等指标

# 3. 运行 1-3 天，确保无异常
```

**预期效果**：
- 所有会话同时写入 request_logs 和 V2 表
- 读取仍从 request_logs
- 对用户无影响

### Phase 2: 小流量灰度（10%）

```bash
# 1. 关闭副写，启用小流量灰度
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.shadow_write

curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": 10}' \
  http://localhost:8781/api/admin/settings/sessions_v2.rollout_percent

# 2. 启用 L3 读取
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.l3_read

# 3. 观察灰度流量
# 访问 /api/admin/sessions/v2/rollout_stats
```

**预期效果**：
- 10% 的会话写入 V2 表
- 90% 的会话继续写入 request_logs
- L3 缓存命中率逐步提升

### Phase 3: 双读对账

```bash
# 启用双读对账模式
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.dual_read

# 观察对账差异
# 访问 /api/admin/sessions/v2/dual_read_diff
```

**预期效果**：
- 同时从 request_logs 和 V2 表读取
- 记录差异并报警
- 确认数据一致性

### Phase 4: 逐步扩大灰度

```bash
# 逐步提升百分比: 10% -> 25% -> 50% -> 75% -> 100%
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": 50}' \
  http://localhost:8781/api/admin/settings/sessions_v2.rollout_percent
```

每个阶段运行 2-3 天，观察：
- 错误率
- 延迟
- 磁盘使用
- L3 命中率

### Phase 5: V2 作为主读取源

```bash
# 1. 关闭双读对账
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.dual_read

# 2. V2 作为主读取源
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": true}' \
  http://localhost:8781/api/admin/settings/sessions_v2.primary_read

# 3. 灰度提升到 100%
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": 100}' \
  http://localhost:8781/api/admin/settings/sessions_v2.rollout_percent
```

**预期效果**：
- V2 表作为主读取源
- request_logs 作为降级备份
- 完全迁移到 V2

## 回滚方案

### 快速回滚（紧急情况）

```bash
# 立即关闭 V2，回退到 request_logs
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.enabled
```

### 渐进式回滚

```bash
# 1. 降低灰度百分比
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": 10}' \
  http://localhost:8781/api/admin/settings/sessions_v2.rollout_percent

# 2. 关闭主读取
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.primary_read

# 3. 关闭 L3 读取
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.l3_read

# 4. 观察稳定后关闭总开关
curl -X PUT -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"value": false}' \
  http://localhost:8781/api/admin/settings/sessions_v2.enabled
```

## 监控指标

访问以下端点查看 V2 运行状态：

- `/api/admin/sessions/v2/status` - V2 整体状态
- `/api/admin/sessions/v2/shadow_metrics` - 副写指标
- `/api/admin/sessions/v2/rollout_stats` - 灰度统计
- `/api/admin/sessions/v2/l3_hit_rate` - L3 缓存命中率
- `/api/admin/sessions/v2/dual_read_diff` - 双读差异报告
- `/api/admin/sessions/v2/primary_read_stats` - 主读取统计
