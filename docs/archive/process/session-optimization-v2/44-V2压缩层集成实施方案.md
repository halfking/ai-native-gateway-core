# V2 压缩层集成实施方案

> **文档版本**: v1.0  
> **创建日期**: 2026-08-06  
> **文档性质**: 实施方案（Implementation Plan）  
> **关联审计**: [43-会话轮次表优化审计报告.md](./43-会话轮次表优化审计报告.md)

## 📋 执行摘要

本方案旨在将**会话压缩层**从 V1 架构（基于 `request_logs`）切换到 V2 架构（基于 `session_turns` + `session_bodies`），实现：

1. **动态拼接**：从增量 delta 重建完整会话上下文
2. **降低存储**：达成 60-80% 存储节省目标
3. **统一缓存**：废弃旧 `SessionCache`，使用 `SessionCacheV2`
4. **灰度切换**：通过 Feature Flag 安全切换

## 1. 架构设计

### 1.1 核心改造

#### 改造前（当前）

```
请求到达
  ↓
SessionCompressor.Prepare()
  ↓
SessionCache (旧缓存)
  ├─ L1: sync.Map
  ├─ L2: Redis session:sc:*
  └─ L3: request_logs (完整历史)
  ↓
压缩决策
  ↓
发送给 LLM
```

#### 改造后（目标）

```
请求到达
  ↓
SessionCompressor.Prepare()
  ↓
SessionCacheV2 (新缓存)
  ├─ L1: LRU (元数据)
  ├─ L2: Redis session:v2:*
  └─ L3: session_turns + session_bodies
  ↓
TurnReader.LoadChain() ← 动态拼接增量
  ↓
OutboundBuilder.Build() ← 重建完整上下文
  ↓
压缩决策（基于 V2 元数据）
  ↓
发送给 LLM
```

## 2. 详细设计

### 2.1 OutboundBuilder（新增）

#### 职责

从多轮 `request_delta` + `response_delta` 重建完整会话消息数组。

#### 接口设计

```go
// OutboundBuilder builds the complete outbound message array from incremental deltas.
type OutboundBuilder struct {
    reader *TurnReader
}

// BuildFromDeltas reconstructs the full session context from the last N turns.
//
// Parameters:
//   - ctx: context
//   - tenantID, sessionID: session identifier
//   - lastN: how many recent turns to load (0 = all)
//   - preserveCompression: if true, preserve compression markers (smm_v1:*)
//
// Returns:
//   - messages: the complete message array to forward to LLM
//   - meta: metadata about the reconstruction (token estimate, msg count, etc.)
//   - error: if any database or parsing error occurs
func (b *OutboundBuilder) BuildFromDeltas(
    ctx context.Context,
    tenantID, sessionID string,
    lastN int,
    preserveCompression bool,
) (messages []Message, meta *BuildMeta, err error)

// BuildMeta contains metadata about the reconstructed outbound body.
type BuildMeta struct {
    TotalTurns    int    // 重建使用的轮次数
    TotalMessages int    // 重建后的消息数
    TokenEstimate int    // token 估算
    HasCompression bool  // 是否包含压缩 marker
    LastTurnNo    int    // 最新轮次号
}
```

#### 实现逻辑

```go
func (b *OutboundBuilder) BuildFromDeltas(
    ctx context.Context,
    tenantID, sessionID string,
    lastN int,
    preserveCompression bool,
) ([]Message, *BuildMeta, error) {
    // Step 1: Load incremental deltas from session_bodies
    deltas, err := b.reader.LoadChain(ctx, tenantID, sessionID, lastN)
    if err != nil {
        return nil, nil, fmt.Errorf("load chain: %w", err)
    }

    // Step 2: Filter out compression markers if not preserving
    messages := deltas
    if !preserveCompression {
        messages = b.filterCompressionMarkers(deltas)
    }

    // Step 3: Build metadata
    meta := &BuildMeta{
        TotalMessages: len(messages),
        TokenEstimate: estimateTokens(messages),
        HasCompression: preserveCompression && b.hasCompressionMarker(deltas),
    }

    return messages, meta, nil
}

func (b *OutboundBuilder) filterCompressionMarkers(msgs []Message) []Message {
    var result []Message
    for _, msg := range msgs {
        if !strings.HasPrefix(msg.Content, compression.CompactionMarkerPrefix) {
            result = append(result, msg)
        }
    }
    return result
}
```

#### 依赖注入

#### Prepare 方法改造

```go
func (sc *SessionCompressor) Prepare(
    ctx context.Context,
    clientBody []byte,
    tenantID, gwSessionID, protocol string,
    contextWindow int,
    streamStarted bool,
) *PrepareResult {
    res := &PrepareResult{}

    if sc == nil || sc.deps.Disabled || gwSessionID == "" {
        return sc.fallbackResult(clientBody, res)
    }

    // ── Phase 0: Feature Flag 判断 ─────────────────────────────
    useV2 := settings.GetTenantBool(tenantID, "sessions_v2_compression_read", false)

    var lastOutboundBody []byte
    var compressionMeta CompressionMeta

    if useV2 && sc.deps.CacheV2 != nil && sc.deps.Builder != nil {
        // ── V2 路径：从增量拼接 ─────────────────────────────
        state, err := sc.deps.CacheV2.Get(ctx, tenantID, gwSessionID)
        if err != nil {
            slog.WarnContext(ctx, "v2 cache get failed, fallback to v1",
                "session", gwSessionID, "error", err)
            useV2 = false // fallback
        } else {
            // 从 V2 拼接完整上下文
            messages, meta, err := sc.deps.Builder.BuildFromDeltas(
                ctx, tenantID, gwSessionID,
                10, // last N turns
                true, // preserve compression markers
            )
            if err != nil {
                slog.WarnContext(ctx, "v2 build from deltas failed, fallback to v1",
                    "session", gwSessionID, "error", err)
                useV2 = false
            } else {
                lastOutboundBody, _ = json.Marshal(messages)
                compressionMeta = state.CompressionMeta
            }
        }
    }

    if !useV2 {
        // ── V1 路径：从旧缓存读取完整历史 ──────────────────
        state, _ := sc.deps.Cache.GetOrLoad(ctx, tenantID, gwSessionID)
        if state != nil {
            lastOutboundBody = []byte(state.LastOutboundHash) // 简化示例
        }
    }

    // ── Phase 1: 解析客户端消息 ────────────────────────────
    var clientMessages []Message
    if err := json.Unmarshal(clientBody, &clientMessages); err != nil {
        return sc.fallbackResult(clientBody, res)
    }

    // ── Phase 2: Delta 计算（BuildOutboundMessages）──────────
    outboundMessages := sc.buildOutbound(clientMessages, lastOutboundBody, &compressionMeta)

    // ── Phase 3: 压缩决策 ──────────────────────────────────
    if sc.shouldCompress(outboundMessages, contextWindow, &compressionMeta) {
        outboundMessages = sc.applyCompression(ctx, outboundMessages, &compressionMeta)
    }

    // ── Phase 4: 构造返回结果 ──────────────────────────────
    res.OutboundBody, _ = json.Marshal(outboundMessages)
    res.MsgCount = len(outboundMessages)
    res.CompressionStrategy = compressionMeta.Strategy

    return res
}
```

## 5. 风险与缓解

### 5.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **V2 读取性能回退** | 中 | 高 | 先做性能测试，确保 p99 < V1 * 1.2 |
| **增量拼接错误** | 低 | 高 | 100% 单元测试覆盖，集成测试验证 |
| **Redis 连接失败** | 中 | 中 | L2 降级到 L3，不影响功能 |
| **数据不一致** | 低 | 高 | 双读验证（V1/V2 对比） |

### 5.2 业务风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **用户体验下降** | 低 | 高 | 灰度切换，错误率超标立即回滚 |
| **存储成本未降** | 中 | 中 | V1/V2 双写期间成本上升，尽快切换到 V2 单写 |
| **回滚复杂度** | 低 | 中 | Feature Flag 秒级回滚，保留 V1 fallback |

## 6. 回滚预案

**触发条件**:
- 错误率 > 1%
- p99 延迟 > V1 * 2
- 数据一致性问题

**操作步骤**:

```bash
# Step 1: 关闭 Feature Flag
curl -X POST http://admin-api/settings \
  -d '{"key": "sessions_v2_compression_read", "value": false}'

# Step 2: 验证流量回到 V1
curl http://metrics-api/session_v2_compression_reads_total?version=v1

# Step 3: 通知团队
slack-notify "#incidents" "V2 compression rolled back due to [reason]"
```

**回滚时间**: < 5 分钟
