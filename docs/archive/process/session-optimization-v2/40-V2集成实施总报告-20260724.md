## 2. 关键设计决策与偏差

### 2.1 与现有架构的偏差（subagent 主动发现并修正）

| 偏差 | Plan 假设 | 实际代码 | 修正 |
| --- | --- | --- | --- |
| 编号 431 已被占用 | `431_session_v2_display_columns.sql` | `431_session_turns_add_attachment_columns.sql` 已存在 | 改用 **456**（commit `fbf1a38c`） |
| session_bodies 列已存在 | plan 重复列了 request_attachments/response_attachments | 430 migration 已建 | `ADD COLUMN IF NOT EXISTS` 幂等处理，down 跳过 |
| session_cache.go 注册点 | main.go 顶层 | `main_pipeline.go:buildV2DispatchPipeline`（生产 v1→v2 dispatch 入口） | 在真实生产入口注册，main.go 1695 行初始化序列未被污染 |
| owner_user 来源 | `session_dim.owner_user` JOIN | `session_dim` 无 `owner_user` 列 | 改用 `request_logs` 首条记录的 owner_user（语义合理：会话由首个请求者所有） |
| request_logs 列名 | `meta`、`status_code` | 无 `meta` 列，`success` 是 bool | 适配：submit_mode 默认 'full'，status_code 映射 success→200/0 |
| 路由文件路径 | `admin/routes.go` | 实际是 `admin/handler.go` | 在 handler.go 增量注册 |
| 前端 HTTP 客户端 | `axios` | 仓库用 `req<T>()` from `_core`（fetch 风格） | 全部改用 `req` |
| 主读切换（V2-P8） | 完整切路由 | plan 允许仅加 banner | 启动 banner 已加，路由切换留后续 PR（按 plan "按 plan 阶段切分"） |

### 2.2 安全 / 风险门禁

- ✅ 所有变更**全部在 feature flag 后面**（`sessions_v2.enabled && shadow_write`）
- ✅ V1 仍主读写，未触碰 V1 任何 reader/writer
- ✅ RLS owner filter 用 `RESTRICTIVE` 而非 `PERMISSIVE`（双条件 AND）
- ✅ Cursor 签名 HMAC + 绑定 tenant+session
- ✅ 附件 signed URL 5min TTL + Redis blacklist 撤销
- ✅ V2-P8 路由切换**未**做，保留 V1 read-only 兼容层条件

## 4. 运行模式与开关

### 4.1 默认行为（向后兼容）

- `sessions_v2.enabled = false`（默认）
- `sessions_v2.shadow_write = false`（默认）
- `SESSIONS_V2_PRIMARY_READ = false`（默认）
- **V1 仍主读写；V2 完全不参与**

### 4.2 灰度启用步骤

```bash
# 1) 启动期：开 V2 writers（shadow write，不影响主路径）
LLM_GATEWAY_SESSIONS_V2_ENABLED=true
LLM_GATEWAY_SESSIONS_V2_SHADOW_WRITE=true
LLM_GATEWAY_SESSIONS_V2_ROLLOUT_PERCENT=10  # 10% 灰度

# 2) 观察期（≥ 7 天）：监控指标
#   sessions_v2_write_success_total
#   sessions_v2_write_failure_total
#   sessions_v2_write_latency_seconds
#   sessions_v2_dual_read_diff_total

# 3) 切主读（满足 gate 后）
SESSIONS_V2_PRIMARY_READ=true  # 仅加 banner；路由切换在后续 PR

# 4) 观察期（≥ 7 天）：对比 p99/错误率/磁盘增长
```

### 4.3 回滚

```bash
# 紧急回滚 V2 writers
LLM_GATEWAY_SESSIONS_V2_ENABLED=false
# 热重载（curl -X POST http://localhost:8080/api/admin/reload-config）

# 完全回滚（如 V2 出现严重问题）
psql "$DB" -f sql/migrations/startup/457_session_v2_owner_filter.down.sql
psql "$DB" -f sql/migrations/startup/456_session_v2_display_columns.down.sql
```

## 5. 监控 / 告警 / Runbook

### 5.1 Prometheus 指标

```
sessions_v2_write_success_total       # V2 写成功计数
sessions_v2_write_failure_total       # V2 写失败计数
sessions_v2_write_latency_seconds     # V2 写延迟直方图
sessions_v2_cache_hit_total           # L0/L1/L2 命中
sessions_v2_cache_miss_total          # L0/L1/L2 未命中
sessions_v2_dual_read_diff_total      # V1/V2 差异计数
```

### 5.2 建议告警

```yaml
# V2 写失败率 > 1%
- alert: V2WriteFailureHigh
  expr: rate(sessions_v2_write_failure_total[5m]) > 0.01
  severity: warning

# V2 写 p99 > 100ms
- alert: V2WriteLatencyHigh
  expr: histogram_quantile(0.99, sessions_v2_write_latency_seconds) > 0.1
  severity: warning

# 双读差异 > 阈值
- alert: V2DualReadDiff
  expr: increase(sessions_v2_dual_read_diff_total[1h]) > 10
  severity: critical
```

### 5.3 排查 Runbook（要点）

1. **V2 写失败率高**：检查 `gateway.session_turns` 错误日志 + `error_message` 字段 + migration 456/457 是否应用
2. **L3 冷启动慢**：检查 `domains/hooks/compression/session_cache.go:turnReader` 是否注入 + `session_bodies` 索引 `idx_session_bodies_session (session_id, turn_no DESC)`
3. **双读差异**：用 `cmd/gateway/dual_read_validator.go` 的 `Compare()` 函数对账单会话
