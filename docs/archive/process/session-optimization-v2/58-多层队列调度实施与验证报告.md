## 3. 关键设计要点（已落地）

- **三层队列**：Tier-1 模型队列（含 auto 桶 + 每模型 FIFO drainer）→ Tier-2 凭据队列（按 `credentialID` 建制，因厂商限流账户级）→ Tier-3 统计（Prometheus + `/api/admin/dispatch/queues` 快照，纯观测）。
- **三种并发模式**：`concurrency`(信号量) / `rpm`(令牌桶) / `tpm`(token 令牌桶，发送前预估) / `disabled`(直通)。
- **四个独立执行器**（channel 解耦，单所有者不变量）：① Model Dispatcher / ② Credential Forwarder / ③ Failover Mover / ④ Stats（内联于指标+快照）。
- **线程安全**：队列=有界 channel；`QueuedRequest` 单所有者（无需 mutex）；`ResultCh` 单发（atomic 守卫）；Stats 非阻塞 send；`-race` 通过。
- **流式正确性**：队列只调解「选谁、何时发」；字节按现状直接流式回写；首字节前失败才切节点。
- **避免双重计数**：`AcquireAllNoCredLayer` 让 dispatch governor 独占凭据层并发/速率，Limiter 只管外层。
- **热路径可回退**：`dispatch_v2.enabled` 默认 ON，OFF 立即回退原同步候选循环（`executor.Execute` 旧路径完整保留）。

## 4. 已知 v1 限制（后续 phase）

1. **模型自动变更默认关闭**（`dispatch_v2.allow_model_change=false`）：`dispatchResolveModel` 暂返回请求模型本身、无备选；后续接入 `autoroute.Decider`/`Index.RecommendV2` 后开启。
2. **dispatch 转发路径是 legacy 循环的「聚焦子集」**：复用了 fp-slot/circuit/Limiter/key-rotator/executeOpenAI|executeAnthropic 与成功副作用（sticky/state/health/mnf/URSM）；**未复制** predictive-TTFB、session 黑名单、content_filter 同 provider 跳过、sync-retry 多轮、async-retry。这些保留在 OFF 回退路径。
3. **TPM token 预估**：v1 `estimatePromptTokens` 返回 0（未知），tpm governor 用保守固定成本 `defaultTokenEstimate=800`；后续接真实 tokenizer。
4. **同账户多 credential 的「账户组共享队列」**未实现（v1 按 credential 独立队列；见 [56] §4）。

> ⚠️ **上线建议**：dispatch 转发路径为 v1 新实现，虽复用核心原语且单测+race 通过，但生产流量下建议先在**单实例灰度**观察 `dispatch_*` 指标（队列深度/等待/overflow/failover）与成功率，再全量。如发现回归，`PUT /api/admin/settings` 设 `dispatch_v2.enabled=false` 或 `KILL_DISPATCH_V2=1` 即时回退到同步循环。

## 6. 审计与修正（2026-08-11 复审）

对实现做了一轮专项审计，发现并修正 3 个问题：

### 6.1 [BUG→已修] dispatch 错误未包装为 `*ExecuteError`，导致 HTTP 状态错乱
- **现象**：`executeViaDispatch` 直接返回 `dispatch.ErrNoRoute` 等裸 error。chat 路径（`handler.go:3878`）只在 `*ExecuteError.Exhausted` 时走 503 分支，裸 error 落到 `handler.go:4171` → **502 Bad Gateway**（而非 503），且 `isRetriableError` 不识别 → goal-retry 失效。
- **修正**：新增 `dispatchErrToExecuteError`，把 dispatch 结果映射为 `*ExecuteError{Exhausted:true, LastKind:...}`：`ErrNoRoute/ErrOverflow→KindConcurrent`（503+Retry-After，可重试）、`DeadlineExceeded→KindTimeout`、其余→`KindTransient`。新增 `executor_dispatch_test.go::TestDispatchErrMapping` 锁定该契约。

### 6.2 [BUG→已修] governor slot 在阻塞 `routeFailover` 期间仍被占用
- **现象**：`forwarder.attempt` 用 `defer gov.Release`，但 pre-firstbyte 失败时先调 `routeFailover`（满 failoverCh 时阻塞）再返回 → 阻塞期间并发槽未释放。在 **concurrency 模式**（DeepSeek/智谱/Kimi）下，失败突发会持续吃掉并发上限，恰好在最敏感的场景降低有效并发。
- **修正**：`forwardFunc` 返回后**立即** `gov.Release` + 递减 in-flight 指标，再分支到 `complete`/`routeFailover`。rpm/tpm 模式 Release 本就是 no-op，不受影响。

### 6.3 [回归→已修] dispatch RouteFunc 未尊重 session sticky，破坏 prompt-cache 亲和
- **现象**：dispatch 的 `RouteFunc` 给 `PlanCandidatesWithContext` 传 `stickyCredentialID=nil`，导致会话每轮可能换凭据 → 丢失 Anthropic/OpenAI prompt cache 命中与上下文连续性。
- **修正**：`dispatchCtx` 增加 `stickyCredID`，RouteFunc 在**首次尝试**（无已试凭据）时传入 sticky；sticky 凭据失败后自然进入 `TriedCredentials` 被排除，故障转移不受影响。

### 6.4 [次要，保留] detached `attempt` goroutine 未纳入 `p.wg`
- `Stop()` 不保证所有在途 `forwardFunc`（上游 HTTP 调用）结束——它们靠请求 ctx（HTTP server graceful shutdown）取消。非死锁、非泄漏（`complete` 非阻塞、`routeFailover` 有 stopCh 出口），优雅关停可覆盖。保留现状。
