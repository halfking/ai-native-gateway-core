> **来源**: V2 压缩路径审计的副产物（2026-08-07）
> **性质**: 独立技术债，**不属于** V2 压缩路径范围
> **状态**: 历史审计结论；幂等性问题已在后续提交修复并通过当前分支测试

## 背景

在为 V2 压缩路径补真 DB 集成测试时，本地用完整 migration 链跑
`go test ./domains/session/v2` 发现多个预先存在的失败。这些失败
与 V2 压缩读/写路径（outbound_body）无关，是 v2 包整体的测试
健康度问题，单独立项处理更合适。

## 发现的失败（本地 430+431+456 链上复现）

### 1. schema 漂移：attachment_count（已规避）

- **现象**: `TestTurnWriter_ListTurns_WithAttachments` 报
  `column "attachment_count" of relation "session_turns" does not exist`
- **根因**: 该列由 migration **431** 引入，只建 430 时缺失
- **影响**: 仅在 migration 链不完整的 DB 上失败；生产已跑全链则正常
- **当前处理**: V2 压缩 CI job 收窄到 `-run '_RealDB|_RoundTrip'`
  规避，注释已写明

### 2. 幂等性 bug：TestTurnWriter_Idempotency（已修复）

- **历史现象**: 即便跑全链 430+431+456，曾失败：
  `expected turn_no=2, actual=1`
- **修复**: `TurnWriter.AppendTurnInTx` 使用
  `ON CONFLICT (tenant_id, request_id, partition_date) DO NOTHING`，
  冲突后回读既有 `turn_no`；冲突路径同时做单调字段补全。
- **当前验证**: `go test -race -count=1 ./domains/session/v2/...` 通过，
  包含 `TestTurnWriter_Idempotency` 与
  `TestTurnWriterAppendTurnDuplicateReturnsExistingTurnNo`。
