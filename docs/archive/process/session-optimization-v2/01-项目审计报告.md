## 2. 原厂数据保护审计

### 2.1 审计目标
确认Sessions V2实现不会破坏不同原厂（Anthropic、OpenAI、Minimax、Gemini等）的数据格式。

### 2.2 架构层面保护

#### ✅ 数据存储层
```go
// session_bodies表存储原始JSONB
type BodiesRecord struct {
    RequestDelta  []Message  // 原始格式保留
    ResponseDelta []Message  // 原始格式保留
    OutboundBody  []Message  // 压缩后也保留原始
}
```

**保护机制**:
- ✅ 使用JSONB存储，保留原始结构
- ✅ 不修改message内容
- ✅ tool_calls等原厂特定字段完整保留

#### ✅ 增量提取层
```go
func extractRequestDelta(req *ProcessedRequest, submitMode string) []Message {
    // 只做消息级别的diff，不修改内容
    // 使用消息指纹匹配，不依赖原厂特定字段
}
```

**保护机制**:
- ✅ 只比较消息级别，不深入内容
- ✅ 使用通用字段（role, content）做指纹
- ✅ tool_calls等特殊字段完整保留

#### ✅ SubmitMode检测层
```go
// 检测逻辑不修改原始数据
func (d *SubmitModeDetector) Detect(ctx DetectionContext) SubmitMode {
    // 只读取，不修改
}
```

**保护机制**:
- ✅ 纯读取操作，零修改
- ✅ 检测工具调用时使用通用逻辑
- ✅ 支持所有原厂的tool格式

### 2.4 原厂数据流完整性

```
原厂请求
  ↓
Gateway接收（保留原始格式）
  ↓
DualWriter
  ├─ V1: 存储到request_logs（现有逻辑，已验证）
  └─ V2:
      ├─ 提取增量（不修改原始数据）
      ├─ 存储到session_bodies（JSONB完整保留）
      └─ 元数据到session_turns（不含敏感格式）
  ↓
返回给原厂（不受V2影响）
```

**保护验证**:
- ✅ V2只在V1成功后执行（副写）
- ✅ V2失败不影响响应
- ✅ 原始数据完整保留在V2表中

### 2.5 回填脚本原厂保护

```sql
-- 回填逻辑
INSERT INTO public.session_bodies (
    request_delta,  -- 直接从request_logs.request_body复制
    response_delta, -- 直接从request_logs.response_body复制
    outbound_body   -- 直接从request_logs.outbound_body复制
)
SELECT
    request_body,   -- 原始JSONB，不解析
    response_body,  -- 原始JSONB，不解析
    outbound_body   -- 原始JSONB，不解析
FROM request_logs
```

**保护机制**:
- ✅ 直接复制JSONB，不解析内容
- ✅ 不依赖特定原厂字段
- ✅ 所有原厂格式都能回填

### 2.6 审计结论

**✅ 原厂数据保护充分**:
1. 所有数据存储使用JSONB，保留原始结构
2. 增量提取只做消息级diff，不修改内容
3. 检测逻辑纯读取，零修改
4. V2失败不影响原厂响应
5. 回填脚本直接复制，不解析

**⚠️ 建议补充**:
1. 添加原厂兼容性测试（Minimax、Gemini等）
2. 在文档中明确说明原厂保护机制
3. 增加E2E测试覆盖多个原厂
