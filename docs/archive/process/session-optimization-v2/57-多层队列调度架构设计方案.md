## 1. 目标与动机

### 1.1 要解决的问题
1. **闪断路由**：现有 `Limiter.AcquireAll`（`domains/credential/limiter.go:376`）是 fail-fast——任一层满则阻塞最多 5s 后返回 error，executor 立即 `continue` 切下一凭据。突发流量在多凭据间反复横跳，且无「蓄峰」。
2. **并发模式单一**：现有只有 `concurrency_limit` + `rpm_limit` 两个并列字段，无「模式」概念，无法区分 DeepSeek/智谱/Kimi 的「并发数」与 OpenAI/Gemini 的「RPM」与 OpenAI/Anthropic/Azure 的「TPM」。
3. **故障转移不分级**：模型不可用与凭据不可用混在同一个候选循环里，模型自动变更不是一等公民。
4. **可观测性弱**：无队列深度、等待时长、切节点/切模型计数的实时视图。

### 1.2 设计目标
- **削峰**：超并发的请求进入凭据队列，按并发/速率平滑释放，**永不超过设定的上限**。
- **多模式**：`concurrency` / `rpm` / `tpm` / `disabled` 四种模式，按厂商语义选择。
- **分层故障转移**：凭据失败→切凭据；同模型凭据全失败→切模型；无路→拒绝（503+Retry-After）。
- **解耦执行器**：入队 / 派发 / 转发 / 故障转移 / 统计 分成独立执行器，channel 解耦，便于并发安全与可观测。
- **流式安全**：首字节前可切节点；首字节后只在同凭据内重试（沿用 executor 包内 `isResumable` 机制）。
- **热路径可回退**：feature-flag `dispatch_v2.enabled` + kill-switch，默认开启但可一键回到同步 `executor.Execute`。

## 2. 总体架构

```
            HTTP Handler / executor.Execute 入口
                      │ 构造 *QueuedRequest(qr)，带 ResultCh
                      ▼
        ┌──────────────────────────────────┐
        │ Tier-1  模型队列 modelQueue[model] │  (含 "auto" → 由派发器解析)
        └──────────────┬───────────────────┘
                       │ ① 模型派发执行器 (Model Dispatcher) 池
                       │   - auto→具体模型(ModelResolveFunc, 复用 autoroute)
                       │   - 模型不可路由 & 允许变更 → 移到另一模型队列
                       │   - 选凭据(RouteFunc, 复用 Router) → 入 Tier-2
                       ▼
        ┌──────────────────────────────────┐
        │ Tier-2  凭据队列 credQueue[credID] │  并发/速率门控在此
        └──────────────┬───────────────────┘
                       │ ② 凭据转发执行器 (Credential Forwarder)
                       │   - concurrency: worker 池=concurrency_limit
                       │   - rpm/tpm: 令牌桶 pacing
                       │   - 取出 qr → Limiter.AcquireAll(外层) →
                       │     ForwardFunc(=forwardOneCandidate) 直接流式回写客户端
                       │   - 成功→ResultCh；首字节前失败→送 ③
                       ▼
        ┌──────────────────────────────────┐
        │ ③ 故障转移执行器 (Failover Mover)  │
                       │ 全程镜像事件(非阻塞, 满即丢+计数)
                       ▼
        ┌──────────────────────────────────┐
        │ Tier-3  统计/显示 事件总线 (纯观测)│  ④ Stats Aggregator
        └──────────────────────────────────┘
```

### 2.1 三层队列职责
| 层 | 键 | 内容 | 由谁生产 | 由谁消费 |
|---|---|---|---|---|
| Tier-1 模型队列 | model 名（含 `auto`） | `*QueuedRequest` | 入口 Handler | ① Model Dispatcher |
| Tier-2 凭据队列 | credentialID | `*QueuedRequest` | ① | ② Credential Forwarder |
| Tier-3 统计总线 | — | 事件 `StatsEvent` | 全执行器 | ④ Stats Aggregator |

> **凭据队列按 credentialID 而非 (model,credentialID) 建制**：厂商限流是账户级（见 [56](./56-LLM厂商并发模式参考.md) §4），一个 credential ≈ 一个账户，其并发/速率上限跨模型共享。模型上下文随 `qr` 携带。

### 2.2 执行器与线程安全不变量
| 执行器 | 形态 | 写权限 |
|---|---|---|
| 入队(Handler) | 请求 goroutine | qr 初始字段 |
| ① Model Dispatcher | worker 池（hotconfig `llmgw_dispatch_dispatcher_workers`） | qr.ResolvedModel / TriedModels |
| ② Credential Forwarder | 每凭据：并发模式=worker 池(concurrency_limit)；rpm/tpm=pacing 单派发 | ResultCh 单发；in-flight atomic |
| ③ Failover Mover | worker 池 | qr.TriedCredentials / CredRetryCount |
| ④ Stats Aggregator | 单 goroutine | 仅自身聚合状态 |

**核心不变量**：
1. **单所有者**：任意时刻一个 `qr` 只被一个执行器持有（hand-off，非共享）。因此 `qr` 的可变字段无需 mutex——由「同一时刻唯一持有者」保证。
2. **ResultCh 单发**：`qr.ResultCh` 在请求生命周期内恰好被发送一次（成功/失败/拒绝）。
3. **有界队列**：Tier-1/Tier-2 全部为有界 channel；满即触发 overflow 策略（切凭据/切模型/拒绝），绝不无限堆积。
4. **Stats 不阻塞**：Stats 事件 send 用 `select { case ch <- ev: default: drop++ }`，满即丢弃并计数，永不阻塞热路径。
5. **ctx 取消贯穿**：`qr` 携带请求 ctx；客户端断开 → ctx.Done() → 当前持有者放弃 qr 并释放资源。

## 4. 新增包 `domains/dispatch/`

### 4.1 与 executors 解耦（避免循环依赖）
`executors` 将 import `dispatch`（提供回调）；故 `dispatch` **不得反向 import `executors`**。`dispatch` 通过回调接口获得能力：

```go
// dispatch 对外只认这些最小契约；executor 负责把 provider.Candidate / autoroute 适配进来。
type CredentialRef struct {            // dispatch 自有的最小凭据视图
    CredentialID, ProviderID int
    ConcurrencyMode string
    ConcurrencyLimit, RPMLimit, TPMLimit int
    MaxQueueDepth, MaxQueueWaitMS int
    Vendor string // 原厂/供应商，供 stats
}
type ForwardOutcome struct { BytesSent bool; Err error }   // BytesSent=是否已向客户端写出首字节
type RouteFunc      func(ctx, *QueuedRequest) ([]CredentialRef, error)
type ModelResolveFunc func(ctx, requestedModel string, tried []string) (resolved string, alternatives []string, err error)
type ForwardFunc     func(ctx, *QueuedRequest, CredentialRef) ForwardOutcome
```

### 4.2 文件清单
| 文件 | 职责 |
|---|---|
| `gate.go` | `dispatch_v2.enabled` 的 atomic 缓存 + 过渡回调（镜像 ratelimit/gate.go） |
| `config.go` | `LoadDispatchConfig(hotCfg)` + `clampInt`（镜像 node_failover.go:110） |
| `metrics.go` | Prometheus 指标（promauto，扁平 `dispatch_*` 命名） |
| `queued_request.go` | `QueuedRequest` / `StatsEvent` / failover 跟踪 |
| `governor.go` | 三模调速器：`concurrencyGovernor`/`rpmGovernor`/`tpmGovernor`，统一 `Governor.Acquire(ctx)` |
| `model_queue.go` / `cred_queue.go` | 有界 FIFO + 深度/等待指标 |
| `pipeline.go` | `Pipeline`：持有各队列+执行器；`Submit(ctx,qr) (*Result, error)`；kill-switch |
| `dispatcher.go` | ① Model Dispatcher worker 池 |
| `forwarder.go` | ② Credential Forwarder（每凭据 governor 节奏 drain） |
| `failover.go` | ③ Failover Mover（重试/切凭据/切模型/拒绝） |
| `stats.go` | ④ Stats Aggregator + 事件总线 + 内存快照 |
| `*_test.go` | governor 三模 / 有界队列 / failover 各分支 / stats 不阻塞 / ctx 取消 |

### 4.3 关键算法
- **concurrency governor**：`concurrency_limit` 个许可的加权信号量；`Acquire` 阻塞至有空位或 ctx/queueWait 到期。worker 池即转发并发数。
- **rpm governor**：令牌桶，每 `60/rpm_limit` 秒补 1 个令牌（上限 rpm_limit）；`Acquire` 取 1 令牌。
- **tpm governor**：令牌桶按 token 补充（`tpm_limit/60` token/s）；`Acquire(qr)` 取「发送前预估 prompt token 数」（由 `qr` 携带的预估值的令牌）。
- **overflow 策略**：Tier-2 满（达到 `max_queue_depth`）→ ① 不入该凭据，改试同模型下一凭据；同模型全满/全不可用 → 触发模型变更；Tier-1 也无路 → `ResultCh ← ErrNoRoute` → 503 + Retry-After。
- **首字节边界**：`ForwardOutcome.BytesSent`（由 `forwardOneCandidate` 据 `StreamOutcome.ChunkCount==0` 设定）。`BytesSent=true` 的失败 → **不切节点**，直接 `ResultCh ← err`（符合用户决策：首字节后不跨凭据切）。
- **重试预算**：同凭据重试 ≤ `Policy.RetryPerCredential`（默认 1），再切凭据；切凭据/切模型分别计入 `dispatch_failover_total{kind}`。

## 7. 风险与缓解
| 风险 | 缓解 |
|---|---|
| 热路径回归 | feature-flag 默认 ON + kill-switch；`forwardOneCandidate` 复用保证转发/流式语义不变；保留同步回退 |
| 队列延迟 | 容量可用时 fast-path 直发；`max_queue_wait_ms` 上界；每层 wait 指标 |
| 死锁/饥饿 | 全有界 channel + overflow；③ 独立池不被 ② 阻塞；单 FIFO 防倒置 |
| goroutine 泄漏 | `ResultCh` 单发；请求超时 + maxQueueWait 双兜底；ctx 取消贯穿 |
| 循环依赖 | `dispatch` 仅通过 `RouteFunc/ForwardFunc/ModelResolveFunc` 回调获得能力，不 import executors |

## 8. ADR 决策记录
- **ADR-Disp-001**：凭据队列按 `credentialID` 建制（不按 model+cred），因厂商限流账户级。同一账户多 credential 的「账户组共享」列为后续增强。
- **ADR-Disp-002**：dispatch 包不 import executors；以回调解耦，避免循环依赖。
- **ADR-Disp-003**：首字节后不跨凭据切换，沿用 executor 包内 `isResumable` 同凭据重试（`internal/streamretry` 当前未接线，不复用）。
- **ADR-Disp-004**：迁移 `479` 的 `.sql` 仅作 source-of-truth；真正生效靠 `db/db.go` 的 `ensure*` 启动钩子（仓库既有约定）。
- **ADR-Disp-005**：`dispatch_v2.enabled` 镜像 `ratelimit/gate.go`（DB Spec + atomic 缓存 + admin PUT 即时同步），默认 ON 但 DangerLevel=Breaking、带 kill-switch。
