## 1. 背景与目标

### 1.1 业务痛点

当前 LLM Gateway 的探测能力散落在 5+ 个独立 worker 中（`bg/credential_selfcheck.go`、`bg/node_probe.go`、`bg/probe_queue_worker.go`、`bg/active_probe_worker.go`、`bg/asset_health_probe.go`），每条路径各管一摊：

| 痛点 | 现象 | 损失 |
|---|---|---|
| **入口不收敛** | `NodeProbeWorker`、`ActiveProbeWorker` 都直接 `probeDirect` 调上游；新需求"自动探测供应商下所有节点"无法复用任何一条 | 加新探测入口 = 复制一份 worker |
| **去重不可见** | 同一节点可能被 4 个 worker 在 5s 内各跑一次，重复扣供应商 quota | 7/15 线上多次触发 NVIDIA/Claude 限流 |
| **去重窗口混乱** | `node_probe_state.next_retry_at`（30s~24h）、`probe_queue.expires_at`（300s）、`credential_probe_queue.dedup_key`（300s）三套窗口 | 错过去重窗口导致"模型短暂可用又 5xx"的振荡 |
| **没有自动/强制语义** | 24h 周期的 credential_selfcheck 与错误触发的 active_probe 走同一条通道 | 失败恢复路径被自动任务淹没 |
| **没有最近请求优化** | 5min 内已有真实请求成功的节点，又被自动周期任务再跑一次 | 每天 ~30K 次无意义探测 |
| **SSE 通道单一** | 仪表盘"实时请求流"通道只能看 request_logs，看不到探测队列动态 | 探测卡住无人发现 |

### 1.2 设计目标

建立**系统监测子系统**（`bg/systemmonitor/` + `admin/systemmonitor_handlers.go`），作为所有探测的唯一入口。满足六条硬约束：

1. **唯一入口**（rule 04 §1）：任何模块要做节点探测，必须通过 `SystemMonitor.Submit(task)`，不允许直接 `probeDirect` 调上游
2. **六种原子任务类型**：`direct_ping` / `gateway_ping` / `chat_minimal` / `chat_tool` / `chat_stream` / `http_ping`
3. **自动性语义**：`mandatory`（强制：手工 + 错误触发）vs `automatic`（自动：周期 + watchdog）
4. **5 分钟自动跳过**：自动任务执行前查 `request_logs` 5min 内同节点成功 → 跳过（强制任务永远跑）
5. **节点探测 30s dedup**：内存/Redis 30s TTL，避免同一节点重复探测（不消耗 quota）
6. **SSE 实时面板**：仪表盘"系统监测"独立 SSE 通道 `/api/admin/system-monitor/stream`，实时显示队列与执行

### 1.3 非目标

- 不重写现有 request_logs 写入路径，只新增 1 行同步 SET 写入 recent_success 缓存
- 不替换 `credential_probe_queue` 表（它仍负责错误触发后的审计/回查），只是新 SystemMonitor 同时往它和 `system_probe_runs` 双写
- 不引入新的外部依赖（Redis 已有 `fpSlotRedis`，PostgreSQL 已有 `system_probe_runs` 概念表 343 之后追加）

### 2.5 现状问题汇总

1. **入口分散**：6 个 worker 各自调上游，违反 rule 11 §13（反模式：修改 Openclaw 本体的精神——只通过插件/接口调用）
2. **去重窗口 3 套**：node_probe_state（30s~24h）、credential_probe_queue（300s）、self_check_runs（24h）——同一节点可能在 5s 内被 3 个 worker 各跑一次
3. **缺 5min 跳过**：自动周期任务无视最近请求成功历史，7/22 抓到 credential_selfcheck 在 30s 内对同一节点跑了 4 次的实例
4. **缺自动/强制语义**：NodeProbeWorker 强制任务和 CredentialSelfcheckWorker 自动任务走相同的 ttl 算法，无法差异化调度
5. **缺独立 SSE**：仪表盘看不到探测队列实时状态，只能 5s 轮询

## 3. Redis 队列 + 缓存设计

### 3.1 Redis Key 清单（统一命名空间 `llmgw:monitor:*`）

| Key | 类型 | TTL | 写入方 | 读取方 | 说明 |
|---|---|---|---|---|---|
| `llmgw:monitor:queue` | LIST | 永久（手动 LPOP） | SystemMonitor.Submit | Worker loop (BRPOP) | FIFO 任务队列，**全局集群唯一** |
| `llmgw:monitor:tasks:{id}` | HASH | 7d | SystemMonitor.Submit | Worker / REST GET | 任务完整定义（task_type/cred/model/automaticity/scheduled_at/max_attempts/...） |
| `llmgw:monitor:tasks:counter` | STRING | 永久 | SystemMonitor.Submit (INCR) | — | 任务 ID 自增计数器 |
| `llmgw:monitor:inflight:{cred}:{model}` | STRING | 30s | Worker claim 成功后 SETNX EX 30 | Worker claim 前 GET | 节点探测中 token（dedup，去除 30s 内重复探测） |
| `llmgw:monitor:node:recent_success:{cred}:{model}` | HASH | 300s | `middleware/request_log.go` 2xx 响应时 SET | Worker claim 前 HGETALL | 5min 内同节点最近请求成功标记（自动任务跳过判定） |
| `llmgw:monitor:running` | SET | 永久 | Worker claim 后 SADD, complete 后 SREM | SSE 广播 | 当前正在执行的 task_id 集合 |
| `llmgw:monitor:workers` | HASH | 90s | Worker 启动 SADD, 每 30s HSET heartbeat | 其它 Worker / REST | worker_id → last_heartbeat，多机去重 + 显示 |
| `llmgw:monitor:events` | Pub/Sub | — | SystemMonitor.Emit | SSE Hub | 任务状态变更（submitted/claimed/completed/skipped/failed） |
| `llmgw:monitor:metrics:{minute}` | HASH | 1h (cron) | SystemMonitor 完成时 INCRBY | Prometheus exporter | 每分钟聚合指标（queue_size/completed_total/skipped_total/...） |

### 3.2 FIFO 出队 Lua 脚本（核心）

确保"30s dedup + 自动任务 5min 跳过 + 多 worker 抢同一队列"三件事原子完成：

```lua
-- KEYS[1]=queue, KEYS[2]=inflight_tpl, KEYS[3]=recent_success_tpl
-- ARGV[1]=worker_id, ARGV[2]=inflight_ttl_sec
local raw = redis.call('LINDEX', KEYS[1], 0)
if not raw then return nil end
local task = cjson.decode(raw)

-- 30s dedup：探测中则把任务转队尾（FIFO 同节点避让）
local inflight_key = 'llmgw:monitor:inflight:' .. task.credential_id .. ':' .. task.raw_model
if redis.call('GET', inflight_key) then
  redis.call('RPOPLPUSH', KEYS[1], KEYS[1])  -- 队头转队尾
  return nil
end

-- scheduled_at 未到也转队尾（FIFO + 时间避让）
local now_ms = tonumber(redis.call('TIME')[1]) * 1000
if task.scheduled_at_ms and task.scheduled_at_ms > now_ms then
  redis.call('RPOPLPUSH', KEYS[1], KEYS[1])
  return nil
end

-- 抢占
redis.call('LSET', KEYS[1], 0, cjson.encode({worker_id=ARGV[1], claimed_at_ms=now_ms}))
redis.call('LPOP', KEYS[1])
redis.call('SET', inflight_key, ARGV[1], 'EX', tonumber(ARGV[2]))
redis.call('SADD', 'llmgw:monitor:running', task.id)
return task
```

### 3.3 Worker 心跳与多机并发控制

每个 gateway 实例启动时通过 `SET llmgw:monitor:workers:{worker_id}` HASH 字段 `started_at/host/cpu_count`，并启动 30s 心跳 loop。

并发上限 = `min(monitor_concurrency, sum(active_workers * per_worker_workers))`，其中：
- `monitor_concurrency`：从 `self_check_settings.monitor_concurrency` 读取（默认 5）
- `active_workers`：Redis 中 `last_heartbeat > now - 60s` 的 worker 数
- `per_worker_workers`：env `LLM_GATEWAY_MONITOR_WORKERS_PER_NODE`（默认 2）

任意 worker 在抢占任务前先查 `LLEN(llmgw:monitor:queue)`，如果 `in_flight_count + queue_size >= monitor_concurrency` 则放弃本轮 BRPOP（让其它 worker 消化）。

### 3.4 Fallback：Redis 不可达

参考 `bg/model_availability_reader.go` 已有 fallback 模式：

```go
if !r.Enabled() { return nil, nil }  // Redis 不可达时降级
```

SystemMonitor 启动时 `redisHealthCheck()`：
- 若 5s 内 Redis PING 失败 → log error + metric counter，**降级为本地内存 FIFO**（`chan Task`，容量 10000）+ 不持久化（重启丢任务）
- Redis 恢复后 → 自动切回 Redis 队列（双写一次 reconcile）

### 3.5 Pub/Sub 事件 schema（for SSE）

```
llmgw:monitor:events  channel
  envelope: { type, task_id, ts, payload }
  type ∈ { 'submitted', 'claimed', 'started', 'completed', 'skipped', 'failed', 'queue_full' }

submitted  payload: { task_type, credential_id, provider_id, raw_model, automaticity, source }
claimed    payload: { task_id, worker_id, host }
started    payload: { task_id, attempt, attempt_max }
completed  payload: { task_id, status, http_status, latency_ms, request_url }
skipped    payload: { task_id, skip_reason, recent_request_id }
failed     payload: { task_id, err_code, err_detail, next_retry_at }
queue_full payload: { queue_size, monitor_concurrency }
```

## 4. 任务类型与 executor 矩阵

### 4.1 六种 task_type

| task_type | 描述 | executor | 耗时 | 消耗 quota | priority |
|---|---|---|---|---|---|
| `direct_ping` | 直连上游 chat ping（解密凭据、POST /v1/chat/completions） | `ActiveProbeExecutor.Run`（已存在） | 5-30s | 是 | 50 |
| `gateway_ping` | 通过本网关 chat ping（用系统 API key） | `ActiveProbeExecutor.Run` + baseURL=本机 | 5-30s | 是 | 40 |
| `chat_minimal` | 最小 chat 探测（max_tokens=1，温度=0） | `ActiveProbeExecutor.Run` with `max_tokens=1` | 1-5s | 是 | 60 |
| `chat_tool` | chat + 单 tool_call（验证 tool 支持） | 新增 `RunCommandWithTool` | 5-15s | 是 | 30 |
| `chat_stream` | 流式 chat（验证 SSE 上游支持） | 新增 `RunCommandStream` | 5-15s | 是 | 20 |
| `http_ping` | **新增**：HEAD/GET 上游 base_url，仅网络层探测 | 新增 `runHTTPProbe` | 50-500ms | 否 | 90 |

### 4.2 自动性映射（automaticity 决策表）

| 入口（source） | task_type 默认 | automaticity |
|---|---|---|
| 仪表盘"开始全部任务" | direct_ping | mandatory |
| 仪表盘"自动探测凭据下所有节点" | direct_ping | mandatory |
| 仪表盘"自动探测供应商下所有节点" | direct_ping + http_ping（1:1 配对） | mandatory |
| 仪表盘"自动探测模型下所有供应商节点" | direct_ping | mandatory |
| `NodeProbeWorker.Submit` | direct_ping | mandatory |
| `ActiveProbeWorker.Submit` | direct_ping | mandatory |
| `CredentialSelfcheckWorker.cycleOnce` | chat_tool | automatic |
| `AssetHealthProbe.ProbeOnce` | http_ping | automatic |
| direct 失败 → http_ping 预检 fallback | http_ping | mandatory |
| 凭据 6h 无请求 → watchdog | http_ping | automatic |

### 4.3 5 分钟自动跳过规则

```
在 worker 抢占任务成功后、执行 RunCommand 之前：

if task.automaticity == 'automatic':
    recent = redis.HGETALL('llmgw:monitor:node:recent_success:' + cred + ':' + model)
    if recent and recent.http_status and 200 <= tonumber(recent.http_status) < 300:
        # 跳过：更新任务状态 + 写 audit + 续 30s inflight token
        redis.SET('llmgw:monitor:inflight:' + cred + ':' + model, 'skipped', 'EX', 30)
        queue.complete(task, status='skipped', reason='recent_request_success',
                       recent_request_id=recent.request_id, recent_request_at=recent.ts)
        audit.run(task, result='skipped', skip_reason='recent_request_success', recent_request_id=recent.request_id)
        sse.emit('skipped', {task_id, skip_reason, recent_request_id})
        return  # 不调用 executor

if task.automaticity == 'mandatory':
    pass  # 强制任务永远跑
```

### 4.4 入队扩缩（"开始全部任务"按钮防爆）

仪表盘触发"自动探测供应商下所有节点（provider=587）"时，先 expand：

```
expand(provider=587, scope='all_nodes'):
    1. SELECT credential_id, raw_model_name FROM credentials
       JOIN credential_model_bindings ON ... WHERE provider_id=587
       AND lifecycle_status='active' AND manual_disabled=FALSE
    2. for each (cred, model):
         SystemMonitor.Submit(task_type='direct_ping', automaticity='mandatory', ...)
    3. if len(tasks) > 200:
         sleep(100ms) every 200 tasks  # 让 worker 消化
         emit SSE 'queue_full' warning at queue_size >= monitor_concurrency
```

### 4.5 失败回退（backoff）

任务失败时（除 success/skipped/expired 之外的终态）：

```
backoff_attempt ∈ {1..7}: 5s, 30s, 60s, 5min, 1h, 2h, 24h
回退策略：
  - attempt < max_attempts: next_run_at = now + backoff[attempt], re-enqueue
  - attempt >= max_attempts: status='expired', 不再 enqueue
  - mandatory 任务的 max_attempts 由 Submit 时指定（默认 3）
  - automatic 任务的 max_attempts 写死 1（避免 watchdog 永远自循环）
```

每次入队时重新设置 `next_run_at`，回退时间到 → 自动被 Lua 脚本 `scheduled_at_ms` 检查放行。

## 5. SSE 总线 + Dashboard 设计

### 5.1 独立 SSE 通道

新建 `/api/admin/system-monitor/stream`（区别于现有 `/api/admin/live-stream`），物理隔离：

| 通道 | 路径 | 数据源 | 用途 |
|---|---|---|---|
| 实时请求流 | `/api/admin/live-stream` | `request_logs` + Redis Pub/Sub `request_stream:events` | 真实请求泳道（已存在） |
| **系统监测流** | `/api/admin/system-monitor/stream`（**新增**） | Redis Pub/Sub `llmgw:monitor:events` | 探测队列实时状态 |

实现要点（参考 `admin/live_stream_sse.go`）：
- 复用 `LiveStreamHub` 模式（多客户端 fan-out + per-client mutex + bounded broadcast channel）
- 单独 `type MonitorEnvelope struct { Type, Timestamp, Task, ... }`，不复用 LiveStreamEnvelope
- 鉴权走现有 `adminWrap(superAdmin)`，与其它 `/api/admin/*` 一致
- 初始 replay：连接建立时返回最近 50 个 task_id 状态（从 `llmgw:monitor:tasks:*` 取）

### 5.2 SSE envelope 事件类型

```go
type MonitorEnvelope struct {
    Type      string       `json:"type"`        // submitted/claimed/started/completed/skipped/failed/queue_full/heartbeat
    Timestamp time.Time    `json:"ts"`
    Task      *MonitorTask `json:"task,omitempty"`
    Stats     *MonitorStats `json:"stats,omitempty"` // for heartbeat

    // 跳过场景专用
    SkipReason       string `json:"skip_reason,omitempty"`
    RecentRequestID  string `json:"recent_request_id,omitempty"`
}

type MonitorTask struct {
    ID           int64  `json:"id"`
    TaskType     string `json:"task_type"`     // direct_ping/gateway_ping/chat_minimal/chat_tool/chat_stream/http_ping
    Automaticity string `json:"automaticity"`  // mandatory/automatic
    Status       string `json:"status"`        // ready/running/success/failed/expired/skipped
    Attempt      int    `json:"attempt"`
    MaxAttempts  int    `json:"max_attempts"`
    CredentialID int64  `json:"credential_id"`
    ProviderID   int64  `json:"provider_id"`
    RawModel     string `json:"raw_model"`
    Source       string `json:"source"`         // button/credential/periodic/error_fallback/watchdog
    WorkerID     string `json:"worker_id,omitempty"`
    StartedAt    *time.Time `json:"started_at,omitempty"`
    FinishedAt   *time.Time `json:"finished_at,omitempty"`
    LatencyMs    *int       `json:"latency_ms,omitempty"`
    HTTPStatus   *int       `json:"http_status,omitempty"`
    ErrCode      string     `json:"err_code,omitempty"`
}

type MonitorStats struct {
    QueueSize        int `json:"queue_size"`
    RunningSize      int `json:"running_size"`
    MonitorConcurrency int `json:"monitor_concurrency"`
    SkippedTotal1h   int `json:"skipped_total_1h"`
    CompletedTotal1h int `json:"completed_total_1h"`
    FailedTotal1h    int `json:"failed_total_1h"`
}
```

### 8.2 已知风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Redis Pub/Sub 消息丢失（至多 5%） | 中 | SSE 偶发缺事件 | REST 轮询作为兜底（5s/次，参见 `SelfCheckPanel.vue`） |

| 入队 1000+ 任务时 SSE backlog | 中 | 浏览器 EventSource buffer overflow | 单 client 限速 100 events/s + Last-Event-ID resume |
| system_probe_runs 分区表膨胀 | 低 | 磁盘占用 | 30d 滚动 cron（rule 33） |
| 自动跳过规则把"5min 内 401 但实际已修复"的节点永久跳过 | 低 | 节点未恢复但显示 healthy | mandatory 任务仍跑 + NodeProbeWorker 错误触发 mandatory 兜底 |
