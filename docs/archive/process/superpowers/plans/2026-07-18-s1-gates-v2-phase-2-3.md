# Session S1 Gate And V2 Phase 2.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining S1-AUTH/S1-RLS verification gates and wire Sessions V2 shadow writing behind the existing settings system without changing the S1 analytics read path.

**Architecture:** Keep S1 analytics on `session_summaries`/`session_dim` and preserve `AdminMiddleware` as the default fallback. Add the service JWT wrapper only to session analytics routes when the explicit service-auth flag is enabled. For V2, construct a settings-backed flag adapter and a V2 writer at Gateway startup, then register a non-blocking `telemetry.AddOnRequestLogPersisted` hook that converts terminal `RequestLogEntry` values into the V2 request model. V2 remains shadow-only and failure-tolerant until real-DB/RLS and staged rollout evidence exist.

**Tech Stack:** Go, `net/http`, pgx v5, PostgreSQL RLS, existing `settings.Registry`, existing telemetry persistence hooks, Prometheus metrics, GitHub Actions.

### Task 3: Build a settings-backed V2 flag adapter

**Files:**
- Create: `llm-gateway-go/domains/session/feature_flags.go`
- Test: `llm-gateway-go/domains/session/feature_flags_test.go`

- [ ] **Step 1: Define canonical keys and adapter behavior**

Use the registered dotted settings keys as the source of truth:

```go
const (
    FlagV2Enabled       = "sessions_v2.enabled"
    FlagV2ShadowWrite   = "sessions_v2.shadow_write"
    FlagV2RolloutPct    = "sessions_v2.rollout_percent"
)

type SettingsFeatureFlags struct{}

func (SettingsFeatureFlags) IsEnabled(flag string) bool {
    switch flag {
    case FlagV2Enabled:
        return settings.GetPlatformBool(FlagV2Enabled, false)
    case FlagV2ShadowWrite:
        return settings.GetPlatformBool(FlagV2ShadowWrite, false) &&
            settings.GetPlatformBool(FlagV2Enabled, false)
    default:
        return false
    }
}

func (SettingsFeatureFlags) IsEnabledForSession(sessionID, flag string) bool {
    if !SettingsFeatureFlags{}.IsEnabled(flag) {
        return false
    }
    return SettingsFeatureFlags{}.GetRolloutPercent(FlagV2RolloutPct) > 0
}

func (SettingsFeatureFlags) GetRolloutPercent(flag string) int {
    value := settings.GetPlatformInt(flag, 0)
    if value < 0 { return 0 }
    if value > 100 { return 100 }
    return value
}
```

The adapter must not introduce a second in-memory cache: existing settings helpers intentionally read the latest committed DB/env/default value for hot reload.

- [ ] **Step 2: Align `DualWriter` with the dotted keys**

Change `dual_writer.go` to use the constants from `feature_flags.go` rather than string literals. Preserve the current safety invariant: V1 is primary; V2 failures are logged/metricized and never returned as request failures.

- [ ] **Step 3: Test hot-reload semantics and defaults**

Use a fresh settings registry/backend in tests where possible. Assert that missing settings resolve to disabled/0, `enabled=false` suppresses shadow writes even when `shadow_write=true`, and rollout values clamp to `[0,100]`.


### Task 4: Adapt persisted request logs into V2 writes

**Files:**
- Create: `llm-gateway-go/domains/session/v2/request_log_adapter.go`
- Test: `llm-gateway-go/domains/session/v2/request_log_adapter_test.go`
- Modify: `llm-gateway-go/cmd/gateway/main.go` near telemetry hook registration

- [ ] **Step 1: Define conversion rules**

Convert only terminal rows (`request_status=success`, `failure`, or `rate_limited`) and ignore `in_progress` rows and request-log updates that do not contain a terminal state. Map:

- `RequestID`, `TenantID`, `GwSessionID`, model/provider/credential IDs, token counts, cost, latency, status, success, error kind, request/response/outbound JSON bodies, and timestamp.
- Decode JSON arrays into `[]v2.Message`; malformed optional bodies become empty slices and increment an adapter-error metric/log rather than blocking the request-log worker.
- Preserve attachment references without copying base64/body content.
- Use `RequestLogEntry` data already persisted; do not query `request_logs` again from the hook.

- [ ] **Step 2: Make the adapter nil-safe and bounded**

Return `(request *session.ProcessedRequest, ok bool, err error)` or an equivalent explicit result. Reject entries without tenant/session/request IDs. Never block on a request context or wait for another database operation inside the telemetry worker hook.

- [ ] **Step 3: Add conversion tests**

Cover success, failure, missing session, in-progress skip, malformed JSON, optional nil pointers, and tenant preservation. Tests must assert no sensitive raw body is logged on conversion failure.

- [ ] **Step 4: Register the shadow hook**

At Gateway startup, after `telemetryClient.SetDB` and after `dbConn` is known, construct the V2 writers from the same `*pgxpool.Pool`:

```go
turnWriter := v2.NewTurnWriter(dbConn.Pool())
bodiesWriter := v2.NewSessionBodiesWriter(dbConn.Pool())
aggregator := v2.NewSessionAggregator(dbConn.Pool())
logsWriter := v2.NewTurnLogsWriter(dbConn.Pool())
writerV2 := v2.NewSessionWriterV2(turnWriter, bodiesWriter, aggregator, logsWriter)
flags := session.SettingsFeatureFlags{}
shadowWriter := session.NewDualWriter(nil, writerV2, flags, sessionV2Metrics)
```

Do not pass a nil V1 writer to a path that invokes V1; instead add a dedicated shadow-write method or a small hook-specific writer that calls V2 only. The production hook must not duplicate the legacy request-log INSERT.

Register with `telemetryClient.AddOnRequestLogPersisted` and call V2 only when the settings-backed flags permit it. Log startup state as disabled by default.

- [ ] **Step 5: Test hook behavior with a fake V2 writer**

Assert that disabled flags and rollout 0 perform no V2 write, enabled flags write terminal rows, V2 errors do not propagate into telemetry, and in-progress rows are ignored.
