# Phase 2.2 实施方案 - 压力信号注入

**日期**: 2026-07-24  
**阶段**: Phase 2.2 - 压力信号注入到路由决策  
**状态**: 设计中

## 一、架构决策

### 1.1 注入位置选择

经过分析，有两个可能的注入点：

#### 方案 A: 在 URSM v2 内部注入（原计划）
**位置**: `domains/ursm/v2/manager.go` 的 `FilterAndScore()` 方法

**优点**:
- ✅ 集中管理，URSM v2 统一负责评分

**缺点**:
- ❌ URSM v2 需要依赖 FpSlots/Limiter（破坏独立性）
- ❌ URSM v2 是通用评分系统，不应耦合具体资源管理器
- ❌ 难以在 canary 模式下使用压力信号

#### 方案 B: 在 Router 层叠加（推荐）
**位置**: `domains/streaming/executors/router.go` 的 `PlanCandidates()` 方法

**优点**:
- ✅ Router 已经持有 FpSlots/Limiter 引用
- ✅ URSM v2 保持独立，不增加依赖
- ✅ 压力惩罚可独立开关（feature flag）
- ✅ canary 模式也能使用压力信号

**缺点**:
- ⚠️ Router 层逻辑略微增加

**决策**: 采用方案 B（Router 层叠加）

## 二、实施设计

### 2.1 压力惩罚函数

**位置**: `domains/streaming/executors/pressure.go`（新文件）

**函数签名**:
```go
// calculatePressurePenalty 计算压力惩罚系数（0-1 之间）
// 压力越高，惩罚越重，返回值越大
//
// 惩罚策略：
//   - 压力 < 0.5: 无惩罚（0%）
//   - 压力 0.5-0.8: 线性惩罚（0-30%）
//   - 压力 > 0.8: 指数惩罚（30-70%）
func calculatePressurePenalty(fpPressure, limiterPressure float64) float64
```

**实现**:
```go
func calculatePressurePenalty(fpPressure, limiterPressure float64) float64 {
    // 取两者最大值（最严重的压力）
    maxPressure := math.Max(fpPressure, limiterPressure)
    
    if maxPressure < 0.5 {
        // 低压力：无惩罚
        return 0
    } else if maxPressure < 0.8 {
        // 中压力：线性惩罚 0-30%
        return (maxPressure - 0.5) / 0.3 * 0.3
    } else {
        // 高压力：指数惩罚 30-70%
        excess := maxPressure - 0.8
        return 0.3 + excess / 0.2 * 0.4
    }
}
```

**惩罚表**:
| 压力 | 惩罚系数 | 说明 |
|------|----------|------|
| 0.3  | 0%       | 低压力，无惩罚 |
| 0.5  | 0%       | 临界点，开始惩罚 |
| 0.65 | 15%      | 中压力，轻度惩罚 |
| 0.8  | 30%      | 高压力临界点 |
| 0.9  | 50%      | 高压力，重度惩罚 |
| 1.0  | 70%      | 压力饱和，最大惩罚 |

### 2.2 Router 层集成

**位置**: `domains/streaming/executors/router.go`

#### 步骤 1: 添加压力查询辅助方法

```go
// getPressureSignals 获取候选节点的压力信号
func (r *Router) getPressureSignals(
    ctx context.Context,
    candidate provider.Candidate,
) (fpPressure, limiterPressure float64) {
    // FpSlots 压力
    if r.FpSlotsManager != nil && candidate.FpSlotLimit != nil && *candidate.FpSlotLimit > 0 {
        fpPressure, _ = r.FpSlotsManager.GetPressure(ctx, candidate.CredentialID, *candidate.FpSlotLimit)
    }
    
    // Limiter 压力
    if r.Limiter != nil {
        limiterPressure = r.Limiter.GetPressure(candidate.CredentialID, candidate.ProviderID, "")
    }
    
    return fpPressure, limiterPressure
}
```

#### 步骤 2: 在排序前应用压力惩罚

**位置**: `PlanCandidates()` 方法中，URSM v2 排序之后

```go
// URSM v2 authoritative 模式：使用 FilterAndScore 返回的顺序
```

#### 步骤 3: 实现 applyPressurePenalty

```go
// applyPressurePenalty 根据压力信号调整候选节点的权重
// 注意：这会修改 candidates 的 Weight 字段
func (r *Router) applyPressurePenalty(ctx context.Context, candidates []provider.Candidate) {
    for i := range candidates {
        // 获取压力信号
        fpPressure, limiterPressure := r.getPressureSignals(ctx, candidates[i])
        
        // 计算压力惩罚
        penalty := calculatePressurePenalty(fpPressure, limiterPressure)
        
        // 调整权重（降低高压力节点的权重）
        if penalty > 0 {
            originalWeight := candidates[i].Weight
            newWeight := int(float64(originalWeight) * (1 - penalty))
            if newWeight < 1 {
                newWeight = 1 // 保留最小权重 1
            }
            candidates[i].Weight = newWeight
            
            // 记录惩罚日志（仅在惩罚 > 10% 时）
            if penalty > 0.1 {
                slog.Debug("router: applied pressure penalty",
                    "credential_id", candidates[i].CredentialID,
                    "fp_pressure", fpPressure,
                    "limiter_pressure", limiterPressure,
                    "penalty", penalty,
                    "weight_before", originalWeight,
                    "weight_after", newWeight,
                )
            }
        }
    }
    
    // 重新排序（按调整后的权重）
    sortCandidatesByWeight(candidates)
}
```

```go
func TestCalculatePressurePenalty(t *testing.T) {
    tests := []struct {
        name             string
        fpPressure       float64
        limiterPressure  float64
        expectedPenalty  float64
        tolerance        float64
    }{
        {"no pressure", 0, 0, 0, 0.01},
        {"low pressure", 0.3, 0.2, 0, 0.01},
        {"threshold 0.5", 0.5, 0.4, 0, 0.01},
        {"medium pressure", 0.65, 0.6, 0.15, 0.02},
        {"high threshold 0.8", 0.8, 0.7, 0.30, 0.02},
        {"high pressure", 0.9, 0.85, 0.50, 0.02},
        {"max pressure", 1.0, 0.95, 0.70, 0.02},
        {"use max", 0.3, 0.9, 0.50, 0.02}, // 取最大值
    }
    
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            penalty := calculatePressurePenalty(tt.fpPressure, tt.limiterPressure)
            if math.Abs(penalty-tt.expectedPenalty) > tt.tolerance {
                t.Errorf("expected penalty ~%f, got %f", tt.expectedPenalty, penalty)
            }
        })
    }
}
```

## 五、性能影响分析

### 5.1 性能开销

| 操作 | 耗时 | 说明 |
|------|------|------|
| FpSlots 压力查询（缓存命中） | < 0.1ms | 内存读取 |
| FpSlots 压力查询（缓存未命中） | 5-10ms | Redis SCAN |
| Limiter 压力查询 | < 0.1ms | atomic 操作 |
| 压力惩罚计算 | < 0.01ms | 简单数学运算 |
| 权重调整 + 重排序 | < 0.1ms | 数组操作 |
| **总计（典型）** | **< 0.3ms** | **缓存命中场景** |
| **总计（最坏）** | **< 10ms** | **缓存未命中** |

**结论**: 性能影响可接受（< 1ms 大部分情况）

### 5.2 缓存命中率

- FpSlots 缓存 TTL: 5 秒
- 路由决策频率: ~100ms/次
- 预估缓存命中率: > 95%
