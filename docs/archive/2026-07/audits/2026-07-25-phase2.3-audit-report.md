## 二、问题详情与修复

### 2.1 问题 1: `ctx` 变量遮蔽（高严重程度）

**位置**: `domains/streaming/executors/router.go:159-163`

**问题描述**:
```go
// 原代码（有问题）
if r.PressureAwareEnabled && len(candidates) > 0 {
    ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
    defer cancel()  // 错误：defer 在 if 块内，但 cancel 会推迟到函数返回
    r.applyPressurePenalty(ctx, candidates)
}
```

**问题分析**:
- 内部的 `ctx, cancel` 遮蔽了外层函数作用域的同名变量
- `defer cancel()` 在 if 块内部定义，但会推迟到整个 `PlanCandidates` 函数返回
- 导致后续代码（line 167）重新声明 `ctx` 时产生变量遮蔽

**修复方案**:
```go
// 修复后
if r.PressureAwareEnabled && len(candidates) > 0 {
    pressureCtx, pressureCancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
    r.applyPressurePenalty(pressureCtx, candidates)
    pressureCancel()  // 立即调用，避免遮蔽外层 ctx
}
```

**修复效果**:
- ✅ 消除变量遮蔽
- ✅ 立即释放 context（避免延迟释放）
- ✅ 逻辑更清晰

### 2.2 问题 2: `Weight=0` 边界条件（中严重程度）

**位置**: `domains/streaming/executors/router.go:applyPressurePenalty`

**问题描述**:
```go
// 原代码（有问题）
if penalty > 0 {
    originalWeight := candidates[i].Weight
    newWeight := int(float64(originalWeight) * (1 - penalty))
    if newWeight < 1 {
        newWeight = 1 // 错误：originalWeight=0 时会被错误地提升为 1
    }
    candidates[i].Weight = newWeight
}
```

**问题分析**:
- 当 `originalWeight = 0` 时，`newWeight = 0 * (1 - penalty) = 0`
- 但 `newWeight < 1` 检查会将 0 错误地提升为 1
- 导致原本权重为 0 的候选被错误地分配权重

**修复方案**:
```go
// 修复后
if penalty > 0 {
    originalWeight := candidates[i].Weight
    // 原始权重为 0 时保持不变（不参与压力调整）
    if originalWeight <= 0 {
        continue
    }
    newWeight := int(float64(originalWeight) * (1 - penalty))
    if newWeight < 1 {
        newWeight = 1
    }
    candidates[i].Weight = newWeight
    // ... 日志记录 ...
}
```

**修复效果**:
- ✅ 保留 Weight=0 候选的原始语义
- ✅ 避免错误地分配权重
- ✅ 逻辑更清晰
