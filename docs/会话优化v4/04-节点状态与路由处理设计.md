## 1. 供应商节点状态（主题⑤）

### 1.1 状态数据模型（CURRENT，public.* schema）
- **路由可见状态**（均在 `public.*`）：`credential_model_bindings`（binding 可用性）+ `credential_health`（健康）+ `model_probe_state`（模型探测状态）+ `probe_revert_at`（延时回退时间戳）。
- 状态机：`healthy_confirmed → unhealthy → restoring → healthy_confirmed`（同步状态恢复链）。

### 1.2 统一自检队列（CURRENT，自检优化 01 号）
- **单一持久队列** `credential_probe_queue` + **单一执行拥有者** `ProbeService.Run`。
- 状态机：ready/running/(success|failed|expired|cancelled)；`FOR UPDATE SKIP LOCKED` + `lease_token` 原子 claim。
- dedup 部分唯一索引 `node_probe:{cred}:{model}` 覆盖 ready/running；活跃窗口内重 Submit 保留既有回退。
- 探测流程：Round1 direct（proxy-aware）→ 状态恢复（binding/health/observed 清 probe_revert_at）→ Round2 gateway（`X-LLM-Pin-Credential` 硬过滤）→ side-effects（circuit/cache/URSM/modelIQ/pg_notify）→ mirror node_probe_state（兼容桥）→ insert node_probe_runs（审计）。
- 回退链：node_probe 用 7 步 `NodeProbeBackoffChain`；integrity/selfcheck 用 5 步 `ActiveProbeBackoffChain`。
- kill-switch：`LLM_GATEWAY_PROBE_QUEUE_ENABLED=false` 回退 legacy `node_probe_state` 直跑。

### 1.3 常用模型分级自检（CURRENT，自检优化 02 号）
- 常用 = 静态精选 `routing_policy.featured_models` ∪ 用量 Top-N（`probe.featured_usage_top_n=20`）。
- 分级：深 ping 15min（首轮 2min 错峰）/ 非常用 watchdog ×4（30min 一轮纯 SQL 时间戳推进）/ 队列优先级 80 vs 60 / 失败回退 ×0.5（下限 ≥5s）。
- 配置：`probe.featured_cycle_seconds=900`（非热加载）/ `featured_usage_window_hours=168` / `featured_tenant='default'` / `featured_queue_priority=80` / `featured_backoff_multiplier=50`。
- kill-switch：`featured_usage_top_n=0` 回退纯静态。

### 1.4 分级故障转移（CURRENT，58 号）
- 链：同凭据重试 ≤1 → 切凭据 → 切模型（默认关）→ ErrNoRoute 503。
- 首字节边界：`Capture.ChunkCountersSnapshot() → ChunkCount==0`（首字节后可切换凭据；首字节后不可）。
- sticky 凭据首次尝试传入 `stickyCredID`（保留 prompt cache 亲和）。
- 指标：`dispatch_failover_total{kind}`；`/api/admin/dispatch/queues` 实时快照。

### 1.5 供应商耗尽长时保活（CURRENT-PARTIAL，修订0811 SR 轨）
- Phase 0/1 已实现：协议安全保活（serializedResponseWriter 串行写通道）、可恢复错误分类、连接内持续重试。
- **Phase 2（M3 durable）未实现**：EncryptWithAAD、durable_llm_tasks 表、PG 回源、CreateAndClaim/fencing、RecoveryWorker、三协议装配（详见 10 号实施计划）。

## 2. 路由处理（主题⑥）

### 2.1 实际接线基座（CURRENT，`ursm/v2` 三模式）
- **三模式基座**：`RoutingStateCoordinator` 实际由三件套构成——`routingstate.Coordinator` + `autoroute.Decider` + `ursm.v2.Manager`。
- `dispatch_v2.enabled`（默认 ON、Breaking、HotReload、admin PUT 即时）+ `KILL_DISPATCH_V2=1` kill-switch；OFF 完整回退 legacy 同步循环。
- 错误映射 `dispatchErrToExecuteError`：ErrNoRoute/ErrOverflow→KindConcurrent→503+Retry-After；DeadlineExceeded→KindTimeout；其余→KindTransient。

### 2.2 URSM 设计蓝本 vs 接线（版本裁决）
| 蓝本项（路由优化v3） | 状态 | 说明 |
|---|---|---|
| 5 层流水线 | CURRENT-PARTIAL | 决策/执行/观测层接线，状态层部分 |
| 状态层级 Provider→Credential→Model→Node→Binding | CURRENT | `ursm/v2` 状态层级 |
| error_origin 三分类（client/gateway/upstream） | CURRENT | 已接入错误链 |
| 成本评分公式 | CURRENT-PARTIAL | 五维评分部分接线；cost score 口径治理（修订0811 CO 轨）已推进 |
| 五维评分 + P2C 采样 | 纸面 | 未接线 |
| L1/L2/L3 智能绑定 | 纸面 | M3 后接入（修订0811 BND 轨） |
| 响应缓存回放 `X-Gw-Replay:true` | CURRENT-PARTIAL | 已实现；TTL 5min + 智能绑定部分纸面 |
| 分级降级 circuit open 30s→half-open | CURRENT | 已实现 |
| Hook 插件化 25+ | 纸面 | 未接线 |

### 2.3 修订0811 ROUTE/COST+BND 轨
- ROUTE：RT-1..RT-4（路由强化任务）——部分已并入 v2 dispatch；剩余见 10 号计划。
- COST：CO-1..CO-5（评分口径治理）——CO-5 摘要信封已交付（doc 24）；CO-3 对账待 M3。
- BND：BD-1..BD-2（智能绑定）——纸面，M3 后。
