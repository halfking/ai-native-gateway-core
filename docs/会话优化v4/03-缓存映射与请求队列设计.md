## 1. 轮次多级映射：会话三层数据（主题③）

> **老板 08-15 修正：缓存不是指 Redis 或内存，是指会话的三层数据**：
> ① **原始多轮会话** → ② **压缩后的多轮会话**（可为跨轮次合并）→ ③ **安全脱敏后的发送会话**。
> 主题③描述的是这三层数据如何在会话维度上映射/重建/降级，而非介质缓存。

### 1.1 三层数据形态
| 层 | 数据 | 存储 | 生成 | 消费 |
|---|---|---|---|---|
| ① 原始 | 未压缩多轮会话（增量 delta） | `public.session_bodies`（按月分区） | DualWriter 影子写 / SubmitModeDetector P0-P5 | 重建输入 |
| ② 压缩后 | 跨轮次合并的压缩会话（`[smm_v1:` marker） | `session_bodies` 增量 + `filterCompressionMarkers` 语义 | `SessionCompressor.Prepare`（smart_window / breaker / estimator） | ③ 的输入 |
| ③ 脱敏后 | 安全脱敏发送会话（含 prompt 注入检查 verdict） | 发送缓存（会话维度） | `SessionSanitizeManager`（映射表持久化 Redis TTL 30min，Hook 顺序 SanitizerInput(10)→上游→SanitizerOutput(50)） | 上游 LLM |

**映射/重建路径**：`tryLoadV2State → Builder.BuildLatestOutbound → BuildFromDeltas(10轮, preserve=true)`（原始→压缩）→ `SessionSanitizeManager`（压缩→脱敏）。失败逐级 fallback V1。

### 1.2 访问路径（CURRENT，非「缓存层」）
| 介质 | Key | TTL | 职责 |
|---|---|---|---|
| 内存 LRU 1024 会话 | CompressionMeta | - | 压缩元数据热点 |
| Redis Hash | `session:v2:{tenant}:{session}` / `session:sc:*:v1` | 30min | GovernanceMeta / 脱敏映射表，fail-open |
| `session_turns` | - | - | 冷启动 / Redis 降级回源 |

- L2 曾缺失 Redis 连接（43 号审计「cache_v2.go 未实现 Redis」）→ 59 号确认已闭合（`cache_v2_redis.go` 的 `RedisGovernanceCache`）。
- **两套访问体系已收敛**：旧 `session_cache.go`（V1 压缩访问）与新 `cache_v2.go`（V2 增量访问）——压缩读路径已走 V2（见 02 号），旧体系退为 fallback。

### 1.3 一致性（CURRENT-PARTIAL）
- 写路径：DualWriter 写 V1 + V2 → 失效/更新策略依赖 `turn_no` 幂等回读。
- 读路径：Compressor.Prepare() 按 flag 走 `CacheV2.Get → Builder.BuildFromDeltas(10轮, preserve=true)`，失败 fallback V1。
- **缺口**：
  1. **AlignmentMap 缺失**（见 02 号）——三层数据拼接时位置对齐无法验证。
  2. Redis fail-open 无指标（连接失败率未埋点，仅 slog）。
  3. 访问命中/未命中指标不完整（`CompressionMeta` 无 Prometheus counter）。

## 2. 请求队列（主题④）

### 2.1 Dispatch 三层队列（CURRENT，`dispatch_v2.enabled` 默认 ON）
| 层 | 队列 | 建制 | 说明 |
|---|---|---|---|
| Tier-1 | modelQueue | 按 model | 含 `auto` 桶（自动解析） |
| Tier-2 | credQueue | **按 credentialID** | ADR-Disp-001：厂商限流是账户级 |
| Tier-3 | Stats 事件总线 | 非阻塞 | 满即丢，不阻塞请求 |

- 三模调速器：`concurrency`（加权信号量）/ `rpm`（令牌桶 60/rpm）/ `tpm`（发送前预估）/ `disabled`。
- 不变量：单所有者（qr 无 mutex）、ResultCh 单发（atomic 守卫）、有界队列、ctx 取消贯穿、首字节后不切节点、`AcquireAllNoCredLayer` 避免双重计数、`KILL_DISPATCH_V2=1` 强制回退。
- `AcquireAllNoCredLayer`（limiter.go:474）：外层 global/pool/identity/key，凭据层由 governor 独占。

### 2.2 可配置容量（CURRENT）
- `credentials.concurrency_mode`（CHECK 四值）/ `tpm_limit` / `max_queue_depth` / `max_queue_wait_ms`。
- 迁移 479 + `ensureConcurrencyMode()` 启动钩子（DB Spec + atomic 缓存 + admin PUT 即时同步）。

### 2.3 队列可观测（CURRENT-PARTIAL，OBS）
- OBS-BE3（go-3 已实现）：pipeline queue snapshot——depth / 等待 p50p95 / inFlight / degraded 真实口径 + `sourceVersion`，**未启用整体缺省**。
- OBS-BE5（go-3 已实现）：probe queue tri-state API + SSE。
- 缺口：OBS-BE3 整体开关未开、OBS-BE2/BE4 队列观测剩余项、`/api/admin/dispatch/queues` 实时快照已有（57 号）。
