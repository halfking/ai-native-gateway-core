### 3. ✅ 修复 `/api/routing/resolve` API 500错误

**问题描述：**
- 请求 `https://llm.kxpms.cn/api/routing/resolve?model=claude-opus-4-8&persist_probe=1` 返回500错误

**根本原因：**
- `persist_probe=1` 参数触发将路由决策写入 `routing_decision_log_hot` 表
- 该表可能不存在（需要migration 346）或字段不匹配
- 写入失败导致整个API返回500

**修复文件：**
- `admin/routing_resolve_probe.go`

**修复策略：**
1. **降级错误处理**：将写入失败从阻断性错误降级为警告日志
2. **静默容错**：即使表不存在，API仍正常返回路由结果
3. **增强日志**：提供更详细的诊断信息（提示检查migration 346）
4. **缓存逻辑解耦**：无论写入成功与否，都执行缓存失效逻辑

**关键修改：**
```go
// 修改前：
if err != nil {
    slog.Error("...")
    return  // 阻断主流程
}
globalFunnelCache.invalidateModel(model)

// 修改后：
if err != nil {
    slog.Warn("resolve probe persist failed - likely missing table...", ...)
    // 不再return，继续执行
}
// 无论成功与否都刷新缓存
if globalFunnelCache != nil {
    globalFunnelCache.invalidateModel(model)
}
```

**兼容性：**
- 向后兼容：表不存在时API仍可用
- 向前兼容：migration 346运行后自动启用probe持久化

### 4. ✅ 修复非admin用户登录失败问题

**问题描述：**
- 创建了用户 `guest/Guest123`，但无法登录
- 只有 `admin` 用户能登录

**根本原因：**
登录逻辑缺陷：
1. 先尝试JWT认证（查询users表）
2. 如果JWT认证失败（用户不存在、密码错误、用户被禁用等），继续执行
3. 然后尝试legacy admin认证（硬编码用户名必须是"admin"）
4. 如果不是"admin"，直接返回401错误

**问题场景：**
- 用户`guest`输入正确密码 → JWT认证成功 → ✅ 能登录
- 用户`guest`输入错误密码 → JWT认证失败 → fallback到legacy admin → 用户名不是"admin" → ❌ 返回401

**修复文件：**
- `admin/auth.go`

**修复策略：**
改进认证流程，明确区分JWT用户和legacy admin：

```go
// 修改前的逻辑：
if (JWT认证成功) {
    return 成功
}
记录JWT失败日志
// 继续执行legacy admin检查
if (用户名不是"admin") {
    return 401
}

// 修改后的逻辑：
查询users表
if (用户存在于users表) {
    if (用户被禁用) return 403
    if (密码错误) return 401
    if (租户被禁用) return 403
    return 成功  // ← 明确return，不再fallback
}
// 只有用户不存在于users表时，才尝试legacy admin
if (用户名是"admin" && 密码匹配) {
    return 成功（legacy模式）
}
return 401
```

**改进点：**
1. **明确身份判断**：只要在users表中找到用户，就不再尝试legacy admin
2. **更详细的错误反馈**：
   - 用户被禁用：返回403 "User account is disabled"
   - 密码错误：返回401 "Invalid credentials"
   - 租户被禁用：返回403 "tenant is disabled"
3. **更好的审计日志**：记录失败原因（user_disabled, invalid_password, tenant_disabled）
