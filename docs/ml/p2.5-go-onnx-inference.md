## 2. 架构与数据流

```
autoroute.Decider.Decide
  └─ recommendWithOptimizer(cls, sigs, ...)          [仅optimizer!=nil时执行]
       └─ toMLRouteFeatures(cls, sigs, profile)      纯转换（复用ExtractStructuredFeatures）
       └─ optimizer.RecommendModel(cands, RoutingContext{Features: …})
            └─ RealOptimizer.RecommendModel
                 ├─ ModelRecommender.Recommend       规则引擎多目标排序（不变）
                 └─ MLReranker.Rerank                P2.5: ONNX推理→预测命中则提升到首位
                      └─ MLSelector.Predict          17命名输入→ONNX→label+probabilities
```

## 3. ONNX推理契约（训练端↔Go端）

由 `manifest.json` 固化（训练端 `export_model.py write_manifest` 自动生成）：

- **输入**（17个，按 manifest 顺序）：
  - 类别×10 → `string [1,1]`，空串/未知 → `"__missing__"`
  - 布尔×6 → `int64 [1,1]`，true=1/false=0（缺失=−1，决策时无缺失场景）
  - 数值×1（confidence）→ `float32 [1,1]`，负值编码为 NaN（图内中值填充）
- **输出**：
  - `label` → `string [1]`（预测的模型/provider名）
  - `probabilities` → `float32 [1, n_classes]`，列序 = `manifest.label_classes`
- **导出要点**：skl2onnx 必须 `options={"zipmap": False}`，否则概率输出是
  map 类型，onnxruntime_go 无法消费。

依赖版本锁定：`onnxruntime_go v1.36.0` ↔ ONNX Runtime **1.29.0** C API
（`libonnxruntime.dylib/.so/.dll`）。运行时通过
`ROUTING_ML_ORT_LIB_PATH` 或 `ONNXRUNTIME_SHARED_LIBRARY_PATH` 指定；
未指定时走 OS 默认搜索路径。

## 4. 关键设计决策

### 4.1 ML只重排序，不做最终决策
`MLReranker` 永不增删候选、不改分数：预测命中候选（精确→前缀两轮匹配，
忽略大小写）时把该候选**稳定提升到第一位**，否则保持规则引擎顺序。
原因：v1模型在合成数据上训练，真实数据准确率未验证；ML的角色是
"建议者"，规则引擎仍是"决策者"。这与planning doc"ML给建议，规则做
最终决策"的缓解策略一致。

### 4.2 五层降级链（ML永远不能破坏路由）
1. `ROUTING_OPT_ENABLED=false`（默认）→ 整个optimizer不存在，P2.5零开销
2. `ROUTING_ML_ENABLED=false`（默认）→ optimizer在但无ML
3. 共享库/模型/manifest缺失或init失败 → `attachMLReranker` Warn后跳过
4. 单次Predict失败 → Rerank内Warn，保持原序
5. `max(probability) < ROUTING_ML_MIN_CONFIDENCE`（默认0.6）→ 不干预

### 4.3 线程模型
onnxruntime_go的`AdvancedSession.Run`绑定预分配输入/输出张量，并发Run
有数据竞争 → `MLSelector.Predict`用互斥锁串行化。17特征小模型单次推理
<1ms，锁竞争不威胁hook的P99<10ms预算（`TestMLSelectorEndToEnd`断言
<50ms做粗防线）。若未来吞吐不足：每请求新建短生命周期session，或按
GOMAXPROCS建session池——阶段4 A/B后再评估。

### 4.4 路由热路径的特征成本
`toMLRouteFeatures`调用`ExtractStructuredFeatures`（含SHA256 content hash）。
仅当optimizer已接线才执行（早退在前），hash为µs级。与下游存储路径重复
计算一次，换取Decide结构零改动——阶段4做A/B时再统一为单次提取。

### 4.5 词汇表差异（已知限制）
- 训练数据`classifier ∈ {heuristic_v1, ml_v1}`，运行时`cls.Classifier ∈
  {heuristic, llm, default}`
- 训练数据`profile ∈ {balanced, cost, speed, quality}`，运行时Profile为
  `smart/speed_first/...`
两者都由ONNX OrdinalEncoder的`unknown_value=-1`优雅降级为"未知桶"，
功能不受损但损失信息量。**阶段4用真实导出数据重训前，需在训练端做
词汇表归一（按生产值分布导出）**，已列入p2.4文档§7交接清单。

### 4.6 测试fixture策略
43KB小模型（6树×深度6，合成数据）+ manifest 提交到
`routingopt/testdata/ml_fixture/`，由`ml-training/scripts/make_go_fixture.py`
一键复现。集成测试（`TestMLSelectorEndToEnd`）在ORT共享库不可用时
`t.Skip`——CI/无原生依赖环境保持全绿；本地设置
`ONNXRUNTIME_SHARED_LIBRARY_PATH`即可运行真实推理。

## 5. 部署指南

```bash
# 1. 训练并导出（ml-training/）
python -m src.train --data data/training.parquet
python -m src.export_model --run models/<run>    # 产出model.onnx + manifest.json

# 2. 部署模型文件（建议）+ 共享库
#    /opt/llm-gateway/ml/model.onnx + manifest.json
#    /opt/llm-gateway/ml/libonnxruntime.so（1.29.0）

# 3. 启动网关
export ROUTING_OPT_ENABLED=true                  # P2.2插件总开关
export ROUTING_ML_ENABLED=true                   # P2.5 ML重排序
export ROUTING_ML_MANIFEST_PATH=/opt/llm-gateway/ml/manifest.json
export ROUTING_ML_ORT_LIB_PATH=/opt/llm-gateway/ml/libonnxruntime.so
export ROUTING_ML_MIN_CONFIDENCE=0.6

# 4. 本地验证（Go测试）
export ONNXRUNTIME_SHARED_LIBRARY_PATH=/path/to/libonnxruntime.1.29.0.dylib
go test ./routingopt/ -run TestMLSelector -v
```

当前`attachMLReranker`仅在启动时构建一次。

## 6a. 阶段4增量（同日追加）

### A/B流量分配（实现P2.2遗留的ABTestEnabled/ABTestPercentage语义）
- `routingopt/ml_ab.go ABGate`：FNV-1a(sessionID|apiKeyID)确定性分桶，
  同一会话恒定同组；万分比精度，观测比例在目标±5%内（测试验证）
- 接线：`RealOptimizer.EvaluateAB`（可选接口，bridge类型断言）→
  control组请求完全跳过optimizer，字节级等价基线路由
- 开关：`ROUTING_OPT_AB_TEST_ENABLED` + `ROUTING_OPT_AB_TEST_PERCENTAGE`（P2.2已有）
- 观测：ABGate.Snapshot()进诊断端点（treatment/control计数与观测占比）

### 模型热更新
- `MLReranker.StartAutoReload`：轮询manifest+model的size+mtime签名
  （基线签名同步采样，避免竞态吞掉变更），变化→新session→原子SwapSelector
- 安全性：`MLSelector.lifeMu`（RWMutex）——Predict持RLock，换出Close持Lock，
  旧session在在途推理结束后才销毁；新加载失败保持当前模型服务
- 开关：`ROUTING_ML_RELOAD_SECONDS`（默认0=禁用；A/B生产建议30）

### ML运行统计与诊断端点
- `MLStats`：predictions/failures/low_confidence_skips/no_match_skips/boosts/avg_latency
- `GET /api/admin/routing-opt/ml`（super admin）：{enabled, manifest摘要,
  stats快照, ab_test快照}；ML关闭时返回原因。只读、无DB访问

### 词汇表归一（§4.5限制的前半修复）
- `ml-training/src/synthetic.py` 全部词汇表对齐Go运行时真实值：
  profile ∈ {smart, speed_first, cost_first}、classifier ∈ {v3_heuristic,
  llm, heuristic, default}、task_type/intent/domain/complexity/turn/
  language各枚举同步、context bucket去掉不存在于v1的"none"
- fixture已用新词汇表重训；Go测试输入同步更新
- 真实生产数据训练时天然一致（训练数据读的就是运行时写入值）
