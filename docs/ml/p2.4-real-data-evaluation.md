## 3. 根因分析

零数据是**双重原因叠加**，均为部署拓扑问题而非代码缺陷：

1. **生产无 AUTO 流量**：当前生产流量全部显式指定模型，`model=auto` 6 天内
   零请求。没有 auto 请求，decider 不触发，SelectionWriter 无行可写。
2. **245 预发为 traffic-only 角色**：canary 槽位单元模板硬编码
   `LLM_GATEWAY_RUNTIME_ROLE=traffic-only`，autoroute decider / SelectionWriter /
   SettleWorker / AffinityWorker 全部不装配（`cmd/gateway/main.go` 的
   `!bgDataPlaneOnly` 块），auto 请求静默回退 `autoFallbackModel()` 且不记录。
   245 日志中仅有一条 `data-lifecycle: hot cron table done (migrated:0)` 生命周期
   巡检行，零选择写入、零 auto 决策——与 2026-09-05/06 观察期结论一致。

## 4. 工具链健康验证（已闭环）

为确认"只缺数据、不缺管道"，将 `llm-gw-exporter` 交叉编译
（CGO_ENABLED=0 GOOS=linux GOAMD64）部署到 245 实测：

| 命令 | 结果 |
|---|---|
| `llm-gw-exporter configs` | ✅ 列出 3 条预置配置（balanced-high-quality-v1 / all-data-v1 / low-confidence-v1，均为 v1 schema，时间窗 2026-08-01→09-01） |
| `llm-gw-exporter list` | ✅ 正常（历史上从未执行过导出） |
| `llm-gw-exporter export --config all-data-v1` | ✅ 按预期在空集守卫处失败：`no records found in time range 2026-08-01 to 2026-09-01`（`training_exporter.go` 的边界检查正确工作，无部分产物残留） |

结论：**P2.2 导出管道 + P2.1 标注表 + P2.4 训练管道全部就绪，唯一缺口是
AUTO 路由从未接入生产流量。**

注意：预置配置时间窗（08-01→09-01）早于库内数据起点（09-01），真实导出前需
按下表更新 `training_export_configs` 的时间范围（或新增配置），否则即使有数据
也会命中空集守卫。

## 5. Go-live Runbook（数据到位后执行任务1）

前置触发（二选一）：
- A. 生产/预发出现 `model=auto` 真实流量（需 245 补 active 角色实例，或产品侧
  引导客户端使用 auto）；或
- B. 用网关冒烟 key 在 **154**（active 全模式）按节奏回放 auto 请求造数
  （`LLM_GATEWAY_API_KEY` 在 `.env`；245 无写入路径，造数必须打 154）。

数据达到 ≥1万行（观察用）/ ≥10万行（正式重训）后：

```bash
# 0. 确认数据量（任一环境 psql）
#    SELECT COUNT(*), MIN(ts), MAX(ts) FROM auto_route_selections WHERE feature_version='v1';
# 1. 更新导出配置时间窗覆盖数据区间（training_export_configs）

  --annotations data/annotations_real.csv --output-dir models/real-v1
# 6. 检查 models/real-v1/evaluation_report.md（判据：模型 test accuracy > rule_engine 基线；
#    基线取值来自 annotation_stats 视图或人工标注行本地计算）
# 7. ONNX 导出（zipmap=False 已内置）
python -m src.export_model --run models/real-v1
# 8. 本结论文档补"实测结果"章节，更新本文件状态为 ✅
```
