> ★ **为什么现在才写**：★ 2026-11-25 第 23 轮实测撞到**四例**量具面故障（★ 逐例登记在 §3 ★★）⇒ ★★ ⇒ ★ 它们此前全部被当成了「缺陷」或「回归」⇒ ★★ ⇒ ★ 教训不该再靠记忆 ⇒ **写进仓内、★ 变成规程**。

## 2. 环境前提（★ 缺一条就可能把量具故障读成缺陷 ★★）

### 2.1 PATH 必须显式补齐

★ **实测依据（★ 两例、★ 都是本机 macOS ＋ 默认 shell PATH ★★）**：

| 缺什么 | 症状 | 出处 |
|---|---|---|
| `/usr/local/bin`（★ `docker` ★） | `docker: command not found`（★ rc=127 ★★） | 2026-11-25 第 20 轮：★ `ursmcheck` 首遍红在 `pg-table-bloat-check.sh` / `ursm-snapshot-payload-bloat.sh` ★★ |
| `/Users/niuer/sdk/go/bin`（★ `go` ★） | `go: command not found` | 2026-11-25 第 23 轮：★ 空库新装烟测门第①遍红 ⇒ ★ 补 PATH 后第②遍 **PASS** ★★ |

★ **本机 `go` 与 `docker` 的真实位置**：
- `go` → `/Users/niuer/sdk/go/bin/go`（★ **不在** `/usr/local/go/bin` ★★）
- `docker` → `/usr/local/bin/docker`（★ Desktop 在跑、★ 但 PATH 不含它 ★★）

★ **标准写法（★ 每次读数都要带、★ 别依赖登录 shell 的 PATH ★★）**：

```bash
export PATH="/Users/niuer/sdk/go/bin:/usr/local/bin:$PATH"
go version && docker version --format '{{.Server.Version}}'
```

★ **判定**：★ 若 `go version` 或 `docker version` 失败 ⇒ ★ **不要开始读数** ⇒ ★ 那是量具不可用、★ 不是缺陷 ★★。

### 2.2 本地 psql 用「容器内 psql 包装器」

★ 本机 `psql` 不在 PATH、★ 而 census 的采集 SQL 需要真 psql ⇒ ★ **用包装器把 DSN 换成容器内 socket**（★ DSN 仍只走环境变量、★ 不进 argv ★★）：

```bash
cat > /tmp/psql-lgpg-wrapper.sh <<'EOF'
#!/bin/bash
shift
exec /usr/local/bin/docker exec -i llm-gateway-pg psql -U llm_gateway -d llm_gateway "$@"
EOF
chmod +x /tmp/psql-lgpg-wrapper.sh
```

★ ★ **注意**：★ 采集端的第一个参数是 DSN、★ 包装器要 `shift` 掉它（★ 不然 psql 会把 DSN 当成要打开的数据库 ★★）。

## 3. 量具故障的三种指纹（★ 「先看 stderr、★ 别只看 diff」★★）

| 指纹（★ 逐字 ★★） | 出处 | 真因 | 处置 |
|---|---|---|---|
| `docker: command not found`（rc=127） | 2026-11-25 第 20 轮 | ★ PATH 缺 `/usr/local/bin` | ★ 补 PATH 后重跑 ★★ |
| `go: command not found` | 2026-11-25 第 23 轮 | ★ PATH 缺 `/Users/niuer/sdk/go/bin` | ★ 补 PATH 后重跑（★ 同一道门两遍结论相反 ★★） |
| `ERROR:  canceling statement due to statement timeout` | 2026-11-25 第 23 轮（★ census 211 车道 ★★） | ★ 采集 SQL 自带 `SET statement_timeout='120s'` ⇒ ★ 生产库冷缓存下目录查询超时、★ **整段结果被丢弃** | ★ 复跑（★ 缓存已热 ★★）⇒ ★ 行数补齐、★ stderr 空 ⇒ ★ **那 1051 条「缺失」全是假的** ★★ |

★ ★ **纪律（★ 三条 ★★）**：
1. ★ **先看 stderr、★ 再看 diff**：★ 远程车道的 stderr 要单独留档（★ `verify-object-census-drift.sh` 落在 `/tmp/kx-census-drift-<env>.err` ★★）⇒ ★★ ⇒ ★ **stderr 非空 ⇒ diff 不可信**。
2. ★ **判「是不是我方回归」之前、★ 先做「纯上游树同条件对照」**：★ 在**纯上游树**上用**完全相同的 PATH** 跑同一个门 ⇒ ★ 若**同样红** ⇒ ★ **归因到执行环境、★ 不是改动面**。
3. ★ **「零红」有三种含义、★ 必须分开表述**：★ **真零红**（量具可用、★ 判据跑完、★ 无缺陷）／★ **量具不可用**（量具没跑起来、★ 本次**没有结论**）／★ **口径缺陷**（量具跑完了、★ 但判据本身量错了东西）⇒ ★★ ⇒ ★ 门脚本自己打的 `ABORT: 量具不可用 —— 本次没有结论` 要当**没有结论**读、★ 不是当 FAIL 读 ★★。

## 4. 标准姿势（★ 隔离 worktree ＋ 固定 SHA ★★）

★ **为什么必须隔离**：★ 主工作树随时可能被别的车道合并、★ checkout、★ 提交 ⇒ ★★ ⇒ **读数对象会变** ⇒ ★★ ⇒ ★ 隔离树 ＋ 固定 SHA ⇒ **读数对象与工作树彻底解耦** ⇒ ★★ ⇒ ★ ⇒ 【合并与读数不必串行】★ ★（★ 2026-11-25 第 23 轮实测：★ 合并动作**没有**让任何一次读数作废 ★★）。

```bash
# ① 读数前确认没有第二个「同种跑测」在跑（★ flock 互抢只发生在同种跑测之间 ★★）
pgrep -fl "go test ./scripts/ursmcheck" | grep -v "$$" | wc -l

# ② 建隔离树（★ detached at 固定 SHA ★★）
git worktree add --detach /tmp/gw-read-treeN <SHA>

# ③ 在隔离树里跑（★ PATH 必带 ★★）
cd /tmp/gw-read-treeN
export PATH="/Users/niuer/sdk/go/bin:/usr/local/bin:$PATH"
go test ./scripts/ursmcheck/ -count=1 -timeout 1800s

# ④ 清理
git worktree remove --force /tmp/gw-read-treeN
```

★ ★ **注意**：★ **不要**用 `git worktree add` 把隔离树放在**仓内**（★ 仓内树会污染 `git status` 与内容指纹 ★★）。

## 5. 冻结判据（★ 三层 ＋ 四项标志 ★★）

★ **「树没变」不是一个判据、★ 是三层**：★ **① HEAD 不变**（★ 别人合并会让 HEAD 变 ★★）｜★ **② `git status --porcelain` 前后逐字相同**（★ 版本控制系统自己说的「工作区与 HEAD 一致」★ ★ 比你自己遍历目录算哈希可靠 ★★）｜★ **③ 追踪文件的内容指纹前后相同**（★ `git ls-files -z | xargs -0 shasum | shasum` ★ ★ 只算 git 追踪的文件 ⇒ ★ 自然排除闸门自己的 untracked/ignored 产物 ★★）。

★ **读数必须打印这四项标志、★ 缺一项就不算数**：

```
HEAD_FROZEN=1
STATUS_IDENTICAL=1
STATUS_CLEAN=1
CONTENT_FROZEN_TRACKED=1
STATUS_AFTER_LINES=0
```

★ ★ **两条历史教训**：
- ★ **闸门自己会在工作区留痕**（★ `.ursmcheck-hollowout.lock` ★）⇒ ★ **全量指纹口径**会把量具自己的产物算成「树被改」⇒ ★ ⇒ ★ **要用追踪文件口径**。
- ★ **同一个判据在两次读数给出相反结论、★ 才是「判据量错了东西」的直接证据**；★ 单次红灯不是。

## 6. census 真库段的远程采集纪律（★ 只读 ＋ 口径同源 ★★）

### 6.1 采集 SQL 必须由工具生成

```bash
python3 scripts/audit/db-object-census.py census-sql > /tmp/census.sql
ssh <host> "docker exec -i acc-pg17 psql -U llm_gateway -d llm_gateway -tA -q" \
  < /tmp/census.sql | python3 scripts/audit/db-object-census.py verify \
    --env 211 --census scripts/audit/asset/db-object-census.tsv --from-stdin
```

★ ★ **为什么**：★ 手搓过一次采集 SQL ⇒ ★ 口径分叉 ⇒ ★ 252/211 各采到 **0 行**（★ 审计档 §5 有原文 ★★）。

### 6.2 同一 env 名下有多个候选库时、★ 必须先用 sha256 认领

★ **实测**：★ 本机有两个 PG 容器都当得起「本地」（★ `kx-citus`（★ 宿主端口 15433 ★★）与 `llm-gateway-pg`（★ 无宿主端口 ★★）★）⇒ ★ ★ 用错库 ⇒ 「本地车道红了 1909 条」是**伪命题**（★ 两条库**不是一条迁移血统**：★ 扩展属主 `kxuser` vs `llm_gateway` ★★）。

★ **认领办法（★ 逐字相同才算 ★★）**：

```bash
# 把现场行的 env 前缀归一为快照里的 env 名、★ 再重算 sha256
python3 - <<'PY'
import hashlib, io
rows = [l.rstrip("\n") for l in io.open("/tmp/live.tsv", encoding="utf-8") if not l.startswith("#")]
ren = ["local" + r[len("probe"):] for r in rows]
print(hashlib.sha256("\n".join(ren).encode()).hexdigest())
PY
# ★ 与快照头部登记的 sha256 逐字相同 ⇒ ★ 认领成功
```

★ ★ **纪律**：★ **认领靠 sha256 逐字相同、★ 不靠「看起来像」**。

### 6.3 语义漂移（★ 把「按日期滚动的对象」从漂移里分出来 ★★）

★ **形态**：★ `usage_facts_YYYYMMDD` / `ursm_node_snapshot_min_YYYYMMDD` / `mock_probe_history_YYYYMMDD` 这族对象**按天换名** ⇒ ★ 固定快照与现场比对**必然**报结构漂移 ⇒ ★★ ⇒ ★ **那是底账的年龄、★ 不是底账过期**。

★ **姊妹工具（★ 口径同源、★ 只加一层分类 ★★）**：`scripts/audit/verify-object-census-semantic-drift.py`
- ★ **diff 本身直接复用上游 `db-object-census.py` 的 `diff_env`** ⇒ ★★ ⇒ **不重写第二份 diff 口径**；
- ★ **滚动的判据不是「名字像日期」而是「这一族真的换过日期」**：★ 名字含日期戳 **且** 另一侧存在【同族但日期不同】的成员 ⇒ ★★ ⇒ ★ **豁免口径不会放过真正的删除/新增**；
- ★ 退出码：`0` ＝ 非滚动漂移为零（★ 底账仍是当下真事实 ★★）／`1` ＝ 有非滚动漂移（★ 底账已过期 ★★）／`2` ＝ 无法判定。

```bash
GUARD_DSN='<local dsn>' GUARD_PSQL=<psql 包装器> \
  python3 scripts/audit/verify-object-census-semantic-drift.py --env local
```
