# P2.2 Routing Optimization Plugin - Operations Manual

**版本**: v1.0  
**生成时间**: 2026-09-07  
**适用范围**: Staging/Production 环境运维

---

## 📖 **概述**

P2.2 路由优化插件通过机器学习增强 AUTO 路由决策，核心功能包括：

1. **PreClassify**: 加载用户历史偏好，增强任务分类信号
2. **RecommendModel**: 多目标优化（准确率/延迟/成本）+ ε-greedy 探索
3. **RecordFeedback**: 记录决策和反馈到 `routing_feedback_log` 表

**部署模式**:
- **Staging (Week 5-7)**: 10% A/B 测试，观察数据流和性能
- **Production (Week 8+)**: 100% 流量，持续优化

## 🚀 **启动与配置**

### **环境变量**

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `ROUTING_OPT_ENABLED` | `false` | 总开关，`true` 启用优化器 |
| `ROUTING_OPT_AB_TEST_ENABLED` | `false` | A/B 测试开关 |
| `ROUTING_OPT_AB_TEST_PERCENTAGE` | `0.0` | A/B 测试流量比例（0.0-1.0） |
| `ROUTING_OPT_MAX_PLUGIN_LATENCY_MS` | `10` | 插件超时（ms），超时降级到 baseline |
| `ROUTING_OPT_EXPLORATION_RATE` | `0.05` | ε-greedy 探索率（5% 随机采样） |
| `ROUTING_OPT_CLASSIFICATION_ENHANCEMENT` | `true` | PreClassify 增强开关 |
| `ROUTING_OPT_MODEL_RECOMMENDATION` | `true` | RecommendModel 重排开关 |
| `ROUTING_OPT_FEEDBACK_INTEGRATION` | `true` | RecordFeedback 记录开关 |
| `ROUTING_OPT_ADAPTIVE_LEARNING` | `false` | 自适应学习（Week 8+ 启用） |

### **启动流程**

#### **1. 验证数据库表**

```bash
# 连接到目标数据库
psql -h $DB_HOST -U $DB_USER -d $DB_NAME

# 验证必需表存在
\dt routing_feedback_log
\dt user_task_affinity
\dt routing_optimization_metrics

# 检查表结构（确认列完整）
\d routing_feedback_log
# 预期列: request_id, user_id, classified_task_type, recommended_provider, 
#         actual_provider, optimization_source, feedback_metadata, created_at
```

#### **2. 加载配置**

```bash
# Staging 环境
cd /path/to/llm-gateway-go-5
export $(grep -v '^#' deploy/staging-p2.2.env | grep -v '^$' | xargs)

# 验证关键配置
env | grep ROUTING_OPT
```

#### **3. 启动服务**

```bash
# 方式 1: 直接启动（开发/测试）
cd cmd/gateway
go build -o gateway .
./gateway 2>&1 | tee -a /var/log/gateway/gateway.log

# 方式 2: systemd（生产推荐）
sudo systemctl start llm-gateway
sudo systemctl status llm-gateway

# 验证启动日志
tail -f /var/log/gateway/gateway.log | grep -i "optimizer"
# 预期输出:
# [INFO] Routing optimization plugin enabled (A/B test: 10%)
# [INFO] Optimizer injected into Decider
```

### **关键指标**

#### **1. 性能指标**

```bash
# P95 请求延迟（Prometheus）
curl -s 'http://localhost:9090/api/v1/query?query=histogram_quantile(0.95,rate(http_request_duration_ms_bucket[5m]))' | jq '.data.result[0].value[1]'

  SELECT count(*) AS active_connections
  FROM pg_stat_activity
  WHERE application_name = 'gateway';
"

# 插件耗时分布（从日志提取）
grep "PreClassify.*latency_ms" /var/log/gateway/gateway.log | \
  awk '{print $NF}' | sort -n | \
  awk 'BEGIN {c=0; sum=0} {a[c++]=$1; sum+=$1} 
       END {print "P50:", a[int(c*0.5)], "P95:", a[int(c*0.95)], "P99:", a[int(c*0.99)]}'
```

#### **2. 数据流指标**

```sql
-- 每小时反馈记录数
SELECT 
  DATE_TRUNC('hour', created_at) AS hour,
  COUNT(*) AS feedback_count,
  COUNT(DISTINCT user_id) AS unique_users
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY hour
ORDER BY hour DESC;

-- 优化器命中率（A/B 测试组 vs 基线组）
SELECT 
  optimization_source,
  COUNT(*) AS count,
  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '1 hour'
GROUP BY optimization_source;

-- 推荐一致性（探索 vs 利用）
SELECT 
  CASE 
    WHEN recommended_provider = actual_provider THEN 'exploit'
    ELSE 'explore'
  END AS decision_type,
  COUNT(*) AS count
FROM routing_feedback_log
WHERE optimization_source = 'recommender'
  AND created_at > NOW() - INTERVAL '1 hour'
GROUP BY decision_type;
```

#### **3. 错误监控**

```bash
# 优化器相关错误
tail -f /var/log/gateway/gateway.log | grep -i "error\|panic" | grep -i "routingopt"

# 常见错误模式
grep -E "(timeout|degraded|connection.*failed)" /var/log/gateway/gateway.log | \
  grep -i routingopt | tail -n 50
```

## 🛠 **故障排查**

### **问题 1: routing_feedback_log 无数据写入**

**症状**: 查询表返回 0 行，或行数远低于预期（AUTO 请求数 × A/B 比例）

**诊断步骤**:

```bash
# 1. 确认优化器已启用
grep "Optimizer injected" /var/log/gateway/gateway.log
# 预期: [INFO] Optimizer injected into Decider

# 2. 检查 A/B 测试配置
env | grep ROUTING_OPT_AB_TEST
# 预期: ROUTING_OPT_AB_TEST_ENABLED=true, ROUTING_OPT_AB_TEST_PERCENTAGE=0.10

# 3. 检查 RecordFeedback 是否启用
env | grep ROUTING_OPT_FEEDBACK_INTEGRATION
# 预期: ROUTING_OPT_FEEDBACK_INTEGRATION=true

# 4. 查看 RecordFeedback 错误日志
grep "RecordFeedback" /var/log/gateway/gateway.log | grep -i error
# 常见错误: "duplicate key value violates unique constraint" (request_id 重复)
```

**解决方案**:
- 如果 `ROUTING_OPT_ENABLED=false`，设置为 `true` 并重启服务
- 如果 A/B 比例过低（如 0.01），发送更多测试请求（100 请求 → 1 条记录）
- 如果数据库连接失败，检查 `$DB_HOST` 和网络连通性
- 如果 `request_id` 冲突，检查 `routing/requestid.go` 的 ID 生成逻辑

---

### **问题 2: P95 延迟显著增加（>10%）**

**症状**: Prometheus 显示 P95 延迟从基线 150ms 增加到 >165ms

**诊断步骤**:

```bash
# 1. 测量插件各阶段耗时
grep "PreClassify.*latency_ms" /var/log/gateway/gateway.log | tail -n 1000 | \
  awk '{print $(NF-1)}' | sort -n | tail -n 50
# 如果 P99 > 10ms，说明 PreClassify 查询过慢

grep "RecommendModel.*latency_ms" /var/log/gateway/gateway.log | tail -n 1000 | \
  awk '{print $(NF-1)}' | sort -n | tail -n 50
# 如果 P99 > 5ms，说明重排算法耗时过高

# 2. 检查 DB 连接池状态
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  SELECT state, count(*) 
  FROM pg_stat_activity 
  WHERE application_name = 'gateway'
  GROUP BY state;
"
# 如果 'idle in transaction' > 5，可能存在连接泄漏

# 3. 检查 user_task_affinity 表索引
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  EXPLAIN ANALYZE 
  SELECT task_type, count 
  FROM user_task_affinity 
  WHERE user_id = 'test-user';
"
# 如果执行时间 > 5ms，添加索引: CREATE INDEX idx_user_task_affinity_user_id ON user_task_affinity(user_id);
```

**解决方案**:
- **临时降级**: 设置 `ROUTING_OPT_ENABLED=false` 并重启，确认延迟恢复
- **优化查询**: 为 `user_task_affinity.user_id` 添加索引
- **增加超时**: 设置 `ROUTING_OPT_MAX_PLUGIN_LATENCY_MS=20`，允许更长处理时间
- **启用 Redis 缓存**: Week 3 实现后，减少 DB 查询

---

### **问题 3: DB 连接数持续增长**

**症状**: `pg_stat_activity` 显示 Gateway 连接数从 20 增长到 50+

**诊断步骤**:

```bash
# 1. 检查连接状态分布
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  SELECT state, count(*) 
  FROM pg_stat_activity 
  WHERE application_name = 'gateway'
  GROUP BY state;
"
# 如果 'idle in transaction' 持续增长，说明事务未提交

# 2. 查看长时间未关闭的连接
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  SELECT pid, usename, state, query, NOW() - state_change AS duration
  FROM pg_stat_activity
  WHERE application_name = 'gateway'
    AND state != 'idle'
  ORDER BY duration DESC
  LIMIT 20;
"

# 3. 检查代码中的连接泄漏点
grep -r "db.Query\|db.Exec" routingopt/ | grep -v "defer.*Close"
# 查找未调用 rows.Close() 或 stmt.Close() 的地方
```

**解决方案**:
- **代码修复**: 确保所有 `db.Query()` 后调用 `defer rows.Close()`
- **连接池限制**: 设置 `DB_MAX_OPEN_CONNS=25` 防止无限增长
- **紧急重启**: `systemctl restart llm-gateway` 释放泄漏连接

---

### **问题 4: 任务分类异常（大量 'unknown' 类型）**

**症状**: `routing_feedback_log` 中 `classified_task_type='unknown'` 占比 >20%

**诊断步骤**:

```sql
-- 查看任务类型分布
SELECT 
  classified_task_type,
  COUNT(*) AS count,
  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY classified_task_type
ORDER BY count DESC;

-- 查看 'unknown' 类型的原始 prompt 样本
SELECT 
  request_id,
  feedback_metadata->>'original_prompt' AS prompt,
  feedback_metadata->>'classifier_confidence' AS confidence
FROM routing_feedback_log
WHERE classified_task_type = 'unknown'
  AND created_at > NOW() - INTERVAL '1 hour'
LIMIT 10;
```

**解决方案**:
- **分类器训练不足**: Week 2 引入人工标注，扩充训练集
- **置信度阈值过高**: 调整 `classifier.MinConfidence` 从 0.8 降低到 0.6
- **Prompt 预处理**: 检查 `routing/classifier.go` 中的文本清洗逻辑

## 🔄 **日常运维任务**

### **每日检查清单**

```bash
#!/bin/bash
# 保存为 /opt/scripts/p2.2-daily-check.sh

echo "=== P2.2 Routing Optimizer Daily Check ==="
echo "Date: $(date)"

# 1. 服务状态
echo -e "\n[1] Service Status"
systemctl is-active llm-gateway && echo "✅ Gateway running" || echo "❌ Gateway stopped"

# 2. 最近 1 小时错误日志
echo -e "\n[2] Recent Errors (last 1 hour)"
ERROR_COUNT=$(grep -c "ERROR.*routingopt" /var/log/gateway/gateway.log.$(date +%Y%m%d) || echo "0")
echo "Error count: $ERROR_COUNT"
if [ "$ERROR_COUNT" -gt 10 ]; then
  echo "⚠️  High error rate, check logs:"
  grep "ERROR.*routingopt" /var/log/gateway/gateway.log.$(date +%Y%m%d) | tail -n 10
fi

# 3. 反馈记录数
echo -e "\n[3] Feedback Records (last 1 hour)"
FEEDBACK_COUNT=$(psql -h $DB_HOST -U $DB_USER -d $DB_NAME -tAc "
  SELECT COUNT(*) FROM routing_feedback_log 
  WHERE created_at > NOW() - INTERVAL '1 hour';
")
echo "Feedback count: $FEEDBACK_COUNT"
if [ "$FEEDBACK_COUNT" -lt 10 ]; then
  echo "⚠️  Low feedback rate, check optimizer config"
fi

# 4. DB 连接数
echo -e "\n[4] Database Connections"
DB_CONNS=$(psql -h $DB_HOST -U $DB_USER -d $DB_NAME -tAc "
  SELECT count(*) FROM pg_stat_activity WHERE application_name='gateway';
")
echo "Active connections: $DB_CONNS"
if [ "$DB_CONNS" -gt 30 ]; then
  echo "⚠️  High connection count, check for leaks"
fi

# 5. P95 延迟（需要 Prometheus）
echo -e "\n[5] P95 Latency"
# 替换为实际 Prometheus 地址
P95=$(curl -s 'http://localhost:9090/api/v1/query?query=histogram_quantile(0.95,rate(http_request_duration_ms_bucket[1h]))' | \
  jq -r '.data.result[0].value[1]' 2>/dev/null || echo "N/A")
echo "P95 latency: ${P95}ms"

echo -e "\n=== Check Complete ==="
```

### **每周数据导出（人工标注准备）**

```bash
#!/bin/bash
# 保存为 /opt/scripts/p2.2-weekly-export.sh

EXPORT_DIR="/tmp/p2.2-exports"
mkdir -p $EXPORT_DIR

EXPORT_FILE="$EXPORT_DIR/feedback_$(date +%Y%m%d_%H%M%S).csv"

# 导出最近 7 天的反馈数据（用于人工标注）
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  COPY (
    SELECT 
      request_id,

    LIMIT 1000
  ) TO STDOUT WITH CSV HEADER
" > $EXPORT_FILE

echo "✅ Exported to: $EXPORT_FILE"
echo "Records: $(wc -l < $EXPORT_FILE)"
```

## 🚨 **应急预案**

### **场景 1: 生产环境延迟暴增**

**触发条件**: P95 延迟 > 200ms（基线 150ms + 33%）

**立即操作**:
```bash
# 1. 禁用优化器（1 分钟内完成）
export ROUTING_OPT_ENABLED=false
systemctl restart llm-gateway

# 2. 验证延迟恢复
curl -s 'http://localhost:9090/api/v1/query?query=http_request_duration_ms{quantile="0.95"}' | jq

# 3. 通知团队
echo "P2.2 optimizer disabled due to latency spike at $(date)" | \
  mail -s "[ALERT] P2.2 Optimizer Disabled" devops@company.com
```

**事后分析**:
- 查看事故时间段的插件耗时分布
- 检查 DB 慢查询日志 (`pg_stat_statements`)
- 验证是否为流量激增导致

---

### **场景 2: 数据库连接耗尽**

**触发条件**: `too many connections` 错误

**立即操作**:
```bash
# 1. 查看当前连接
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  SELECT count(*), application_name 
  FROM pg_stat_activity 
  GROUP BY application_name;
"

# 2. 杀死泄漏连接（谨慎操作）
psql -h $DB_HOST -U $DB_USER -d $DB_NAME -c "
  SELECT pg_terminate_backend(pid)
  FROM pg_stat_activity
  WHERE application_name = 'gateway'
    AND state = 'idle in transaction'
    AND NOW() - state_change > INTERVAL '5 minutes';
"

# 3. 重启服务
systemctl restart llm-gateway
```
