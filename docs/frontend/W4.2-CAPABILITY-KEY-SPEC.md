## 1. 功能概述

在API Key创建/编辑界面，增加**能力勾选**功能，实现类似灵果Policies的权限控制：

- 创建Key时，管理员勾选该Key允许使用的能力（audit/forensics/summary等）
- 后端在鉴权时检查Key的capabilities字段，拦截未授权的能力调用
- Key详情页显示已授权的能力列表

## 2. 后端数据结构

### 2.1 API Key表结构（迁移20261125000001）
```sql
ALTER TABLE api_keys ADD COLUMN capabilities JSONB DEFAULT '[]'::jsonb;
CREATE INDEX idx_api_keys_capabilities ON api_keys USING GIN (capabilities);
```

**capabilities字段格式**:
```json
["audit", "forensics", "summary", "cluster", "timeline", "dimensions"]
```

### 2.2 能力清单（internal/capability/capability.go）
```go
const (
    Audit       = "audit"       // 审计日志查询
    Forensics   = "forensics"   // 取证数据导出
    Summary     = "summary"     // 会话摘要生成
    Cluster     = "cluster"     // 会话聚类分析
    Timeline    = "timeline"    // 时间线视图
    Dimensions  = "dimensions"  // 多维分析
)
```

**能力说明**:
| 能力ID | 中文名 | 说明 | 对应端点示例 |
|--------|--------|------|--------------|
| `audit` | 审计日志 | 查询请求日志、操作记录 | `/api/admin/audit-logs` |
| `forensics` | 取证导出 | 导出完整请求响应、指纹数据 | `/api/admin/forensics/export` |
| `summary` | 会话摘要 | 生成会话摘要、关键点提取 | `/api/sessions/{id}/summary` |
| `cluster` | 会话聚类 | 按主题/用户聚类会话 | `/api/admin/session-analytics/clustering` |
| `timeline` | 时间线 | 会话时间轴、关联分析 | `/api/sessions/{id}/timeline` |
| `dimensions` | 多维分析 | 按模型/用户/项目的统计 | `/api/admin/session-analytics/dimensions` |

## 4. 前端UI设计建议

### 4.1 Key创建表单（新增能力勾选）
```vue
<template>
  <el-form :model="form" label-width="120px">
    <el-form-item label="Key名称">
      <el-input v-model="form.name" placeholder="如：营销部Key" />
    </el-form-item>

    <el-form-item label="所属租户">
      <el-select v-model="form.tenant_id">
        <el-option label="default" value="default" />
      </el-select>
    </el-form-item>

    <!-- 能力勾选 -->
    <el-form-item label="授权能力">
      <el-checkbox-group v-model="form.capabilities">
        <div v-for="group in capabilityGroups" :key="group.category">
          <div class="capability-group-title">{{ group.title }}</div>
          <el-checkbox 
            v-for="cap in group.items" 
            :key="cap.id" 
            :label="cap.id"
          >
            <span class="capability-label">{{ cap.name }}</span>
            <el-tooltip :content="cap.description" placement="top">
              <i class="el-icon-question" />
            </el-tooltip>
          </el-checkbox>
        </div>
      </el-checkbox-group>
    </el-form-item>

    <el-form-item>
      <el-button type="primary" @click="onSubmit">创建Key</el-button>
    </el-form-item>
  </el-form>
</template>

<script setup>
import { ref, onMounted } from 'vue'
import { getCapabilities, createApiKey } from '@/api/keys'

const form = ref({
  name: '',
  tenant_id: 'default',
  capabilities: []
})

const capabilityGroups = ref([])

onMounted(async () => {
  const data = await getCapabilities()
  // 按category分组
  capabilityGroups.value = groupByCategory(data.capabilities)
})

const groupByCategory = (capabilities) => {
  const groups = {
    security: { title: '安全能力', items: [] },
    analytics: { title: '分析能力', items: [] },
    export: { title: '导出能力', items: [] }
  }
  capabilities.forEach(cap => {
    groups[cap.category]?.items.push(cap)
  })
  return Object.values(groups).filter(g => g.items.length > 0)
}

const onSubmit = async () => {
  try {
    const result = await createApiKey(form.value)
    ElMessage.success('Key创建成功')
    // 显示生成的Key（仅此一次）
    showKeyDialog(result.key)
  } catch (error) {
    ElMessage.error('创建失败：' + error.message)
  }
}
</script>

<style scoped>
.capability-group-title {
  font-weight: bold;
  margin-top: 12px;
  margin-bottom: 8px;
  color: #303133;
}

.capability-label {
  margin-left: 4px;
}
</style>
```

### 4.3 Key列表（显示能力标签）
```vue
<template>
  <el-table :data="keys">
    <el-table-column prop="id" label="ID" width="80" />
    <el-table-column prop="name" label="Key名称" width="200" />

      </template>
    </el-table-column>

      <template #default="{ row }">

<script setup>
import { ref, onMounted } from 'vue'

  keys.value = await getApiKeys()
```

## 6. 权限验证流程

### 6.1 后端鉴权逻辑（已实现）
```
请求到达 → 提取API Key → 查询capabilities字段
                             ↓
                   检查端点所需能力（如forensics）
                             ↓
                   capabilities包含forensics？
                      ├─ 是 → 放行
                      └─ 否 → 403 Forbidden
```

### 6.2 前端处理403错误
```javascript
// utils/request.js
service.interceptors.response.use(
  response => response.data,
  error => {
    if (error.response?.status === 403) {
      const message = error.response.data?.message || '权限不足'
      if (message.includes('capability')) {
        ElMessage.error('该Key未授权此能力，请联系管理员')
      } else {
        ElMessage.error(message)
      }
    }
    return Promise.reject(error)
  }
)
```

## 9. 商业对齐：灵果Policies对比

| 灵果Policies | 本方案 | 说明 |
|--------------|--------|------|
| Policies配置 | capabilities字段 | 灵果用独立Policies表，我们简化为JSONB |
| 策略类型 | 能力ID | 灵果有deny/allow规则，我们v1只做allow白名单 |
| UI勾选框 | 同灵果 | 创建Key时勾选能力，体验一致 |
| 权限粒度 | 端点级 | 灵果到API级，我们v1到能力级（一组端点） |

**未来增强方向**:
- 细化到具体端点（如audit.read vs audit.write）
- deny规则（黑名单）
- 时间限制（某能力的有效期）
