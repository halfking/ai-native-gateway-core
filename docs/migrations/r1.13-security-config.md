# R1.13 安全检测引擎配置迁移指南

**版本**: R1.12 → R1.13  
**发布日期**: 2026-07-09  
**影响范围**: 安全检测模块配置  
**迁移难度**: ⭐⭐ (中等)

---

## 变更概览

### 新增功能

1. **安全检测引擎模块** (`security`)
   - 统一的安全检测入口，整合意图分析、威胁检测、响应策略
   - 新增 20 个配置项
   - 支持 observe/enforce 模式切换
   - 支持为意图分析和威胁检测分别配置 LLM 模型

2. **模块依赖管理**
   - 新增 `ModuleDependency` 结构体
   - 前端显示模块依赖状态
   - 依赖未满足时显示警告

3. **风险等级阈值**
   - 三级风险阈值：low (3)、medium (5)、high (7)
   - 支持分别配置三级响应动作

### 配置项对应关系

| 旧配置项 | 新配置项 | 变更说明 |
|---------|---------|---------|
| N/A | `security.enabled` | 新增：安全检测引擎总开关 |
| N/A | `security.mode` | 新增：observe/enforce 模式 |
| N/A | `security.llm.intent_model` | 新增：意图分析 LLM 模型 |
| N/A | `security.llm.threat_model` | 新增：威胁检测 LLM 模型 |
| `prompt_injection.enabled` | `security.threat.checks.prompt_inject` | 功能拆分：仍可独立使用 prompt_injection |
| `output_compliance.enabled` | `security.threat.checks.{data_leak,pii}` | 功能拆分：仍可独立使用 output_compliance |
| N/A | `security.threat.checks.jailbreak` | 新增：越狱攻击检测 |
| N/A | `security.threat.checks.persona_override` | 新增：角色劫持检测 |
| N/A | `security.response.*` | 新增：三级响应策略配置 |

### 不兼容变更

**无**。所有变更向后兼容，旧模块仍可独立使用。

## 迁移策略

### 策略 A：仅使用现有模块（无需迁移）

**适用场景**：满足当前安全需求，无需统一管理

**操作**：无需任何变更，继续使用 `prompt_injection`、`output_compliance`、`session_audit` 模块

**优点**：零迁移成本

**缺点**：无法使用统一配置、分级响应等新特性

---

### 策略 B：渐进式迁移（推荐）

**适用场景**：希望试用新功能，但不影响现有系统

**步骤**：

#### 1. 启用 security 模块

```bash
# 前端：/admin/modules，开启"安全检测引擎"
# 或通过 API：
PUT /api/admin/modules/security/toggle
{ "enabled": true }
```

#### 2. 确认依赖模块已启用

检查以下模块状态（必须全部启用）：
- ✅ `prompt_injection`
- ✅ `output_compliance`
- ✅ `session_audit`
- ⚠️ `session_inspector`（可选，提升意图分析准确率）

#### 3. 配置 security 模块（保持默认）

```yaml
# 基础配置
security.enabled: true
security.mode: observe  # 观察模式，不拦截

# LLM 模型（使用轻量模型降低成本）
security.llm.intent_model: gpt-4o-mini
security.llm.threat_model: gpt-4o-mini

# 意图分析
security.intent.enabled: true
security.intent.confidence_threshold: 0.7
security.intent.drift_threshold: 0.5

# 威胁检测（所有检测项启用）
security.threat.enabled: true
security.threat.severity_threshold: 7
security.threat.risk_level.low_threshold: 3
security.threat.risk_level.medium_threshold: 5
security.threat.checks.prompt_inject: true
security.threat.checks.jailbreak: true
security.threat.checks.data_leak: true
security.threat.checks.pii: true
security.threat.checks.persona_override: true

# 响应策略（保守策略）
security.response.low_risk: log
security.response.medium_risk: warn
security.response.high_risk: approval

# 审计联动
security.audit.enabled: true
security.audit.log_all: false
security.audit.sampling_rate: 1.0
```

#### 4. 并行运行 1-2 周

- security 模块运行在观察模式（observe）
- 旧模块继续正常工作
- 对比两者的检测结果，调整配置

#### 5. 查看审计日志

```sql
-- 查看 security 模块检测结果
SELECT * FROM security_audit_log 
WHERE tenant_id = 'your_tenant_id' 
  AND detected_at > NOW() - INTERVAL '7 days'
ORDER BY threat_severity DESC, detected_at DESC
LIMIT 100;

-- 统计威胁分布
SELECT threat_types, COUNT(*), AVG(threat_severity)
FROM security_audit_log
WHERE tenant_id = 'your_tenant_id'
  AND detected_at > NOW() - INTERVAL '7 days'
GROUP BY threat_types
ORDER BY COUNT(*) DESC;
```

#### 6. 调整阈值（可选）

根据审计日志分析误报率，调整阈值：

**如果误报率高（>5%）**：
```yaml
security.intent.confidence_threshold: 0.8  # 提高到 0.8
security.threat.risk_level.medium_threshold: 6  # 从 5 提高到 6
```

**如果漏报率高（>2%）**：
```yaml
security.intent.confidence_threshold: 0.6  # 降低到 0.6
security.threat.risk_level.low_threshold: 2  # 从 3 降低到 2
```

#### 7. 切换到强制模式（可选）

**前提条件**：
- 观察模式运行 ≥ 2 周
- 误报率 < 3%
- 已充分测试响应策略

**操作**：
```yaml
security.mode: enforce  # 从 observe 切换到 enforce
```

⚠️ **警告**：强制模式下，高风险请求将被直接阻断（403），请确保已充分测试。

#### 8. （可选）禁用旧模块

**仅在以下条件全部满足时执行**：
- security 模块已稳定运行 ≥ 1 个月
- 无任何误杀或漏报
- 团队已熟悉新配置

**操作**：
```bash
# 禁用旧模块（谨慎操作）
PUT /api/admin/modules/prompt_injection/toggle { "enabled": false }
PUT /api/admin/modules/output_compliance/toggle { "enabled": false }
```

⚠️ **注意**：`session_audit` 模块不应禁用，它提供审批流程能力。

### 策略 C：全量迁移（不推荐）

**适用场景**：新项目或测试环境

**风险**：⚠️⚠️⚠️ 高风险，可能误杀正常请求

**操作**：直接启用 security 模块并禁用旧模块

**不推荐原因**：
- security 模块配置接入尚未完成（P0 问题，配置不生效）
- 缺少生产环境验证数据
- 无回滚缓冲期

## 已知问题

### P0 - 配置项未实际生效

**问题描述**：
- 当前版本添加了 20 个配置项，但代码中仍使用硬编码值
- 用户在前端修改配置后不会生效

**影响**：
- 所有 `security.*` 配置项修改无效
- 只能使用默认值

**临时解决方案**：
- 接受默认配置（默认值经过合理设计）
- 等待 R1.14 修复

**修复计划**：
- 优先级：P0（阻断性问题）
- 预计修复版本：R1.14
- GitHub Issue: #待创建

### P1 - 部分依赖未强制校验

**问题描述**：
- 用户可以在 `prompt_injection.enabled=false` 时仍启用 `security.threat.checks.prompt_inject`
- 后端未校验依赖关系

**影响**：
- 依赖模块未启用时，对应检测项无法正常工作
- 前端已显示警告，但仍允许配置

**解决方案**：
- 前端已实现依赖警告（R1.13）
- 后端校验将在 R1.14 实现

## 回滚计划

### 场景 1：security 模块运行异常

**操作**：
```bash
# 禁用 security 模块
PUT /api/admin/modules/security/toggle { "enabled": false }
```

**影响**：无，旧模块继续工作

**恢复时间**：< 1 分钟

---

### 场景 2：误杀率过高

**操作**：
```yaml
# 切换回观察模式
security.mode: observe

# 或提高阈值
security.threat.risk_level.medium_threshold: 7  # 从 5 提高到 7
security.response.medium_risk: log  # 从 warn 降级到 log
```

**恢复时间**：< 5 分钟

---

### 场景 3：完全回滚到 R1.12

**操作**：
```bash
# 1. 禁用 security 模块
PUT /api/admin/modules/security/toggle { "enabled": false }

# 2. 清理审计日志（可选）
DELETE FROM security_audit_log WHERE detected_at < NOW() - INTERVAL '7 days';

# 3. （可选）降级代码
git checkout v1.12.x
docker-compose restart
```

**数据影响**：
- 审计日志保留（可选择清理）
- 配置项保留（下次升级时仍可用）

**恢复时间**：< 30 分钟

## 常见问题

### Q1: 迁移后需要修改应用代码吗？

**A**: 不需要。security 模块在网关层透明运行，应用无需任何修改。

---

### Q2: 旧模块和新模块可以同时运行吗？

**A**: 可以。建议渐进式迁移期间同时运行，对比检测结果。

---

### Q3: 如果 security 模块检测结果与旧模块不一致怎么办？

**A**: 
1. 检查依赖模块是否全部启用
2. 对比审计日志，分析差异原因
3. 调整阈值或检测项配置
4. 如果无法解决，禁用 security 模块并反馈给团队

---

### Q4: observe 模式和 enforce 模式有什么区别？

**A**:
- **observe 模式**：仅记录威胁，不阻断请求（所有威胁转换为 warn）
- **enforce 模式**：高风险威胁直接阻断（403）

推荐先用 observe 模式运行 1-2 周，充分测试后再切换到 enforce 模式。

---

### Q5: 配置修改后多久生效？

**A**: 所有配置项都支持热加载（`HotReload: true`），修改后立即生效，无需重启。

⚠️ **注意**：当前版本配置接入未完成（P0 问题），配置修改暂时不生效，将在 R1.14 修复。

---

### Q6: 误报率和漏报率如何统计？

**A**:
```sql
-- 误报率（人工标注）
SELECT 
  COUNT(*) FILTER (WHERE manual_label = 'false_positive') * 100.0 / COUNT(*) AS false_positive_rate
FROM security_audit_log
WHERE tenant_id = 'xxx' AND detected_at > NOW() - INTERVAL '7 days';

-- 威胁分布
SELECT threat_severity, COUNT(*)
FROM security_audit_log
WHERE tenant_id = 'xxx' AND detected_at > NOW() - INTERVAL '7 days'
GROUP BY threat_severity
ORDER BY threat_severity;
```
