## 1. 概述

### 1.1 什么是会话管理

会话管理是 LLM Gateway 的核心运营模块，负责对每一次 AI 对话会话进行全生命周期管理、监控、分析与治理。

**核心概念**：
- **会话 (Session)**: 同一身份在 5 分钟窗口内连续发起、共享上下文的一组 LLM 请求
- **会话 ID**: 唯一标识符，格式为 `gw_<uuid>`，例如 `gw_abc123`
- **双态视图**: 
  - **实时运营态**: Redis 热层数据，显示当前运行中的会话状态
  - **历史分析态**: PostgreSQL 冷层数据，用于分析和统计

### 1.2 三类角色的使用场景

| 角色 | 核心诉求 | 主要使用场景 |
|------|---------|-------------|
| **平台运营 / SRE** | 系统稳定、成本可控、故障可定位 | 实时会话监控、健康评分、成本分析、异常告警 |
| **租户管理员** | 安全合规、用量透明、审计可追溯 | 合规审批、用量成本归因、会话审计 |
| **产品 / 算法** | 理解用户行为、优化路由策略、提升体验 | 会话形态分布、用户意图、模型切换分析 |

### 1.3 功能模块导航

```
会话管理
├── 📊 分析中心 - 历史会话统计分析
├── 🟢 实时会话 - 运行中会话监控
├── 🔍 会话全景 - 单会话详细诊断
├── 🛡️ 合规审批 - 高风险会话审批
└── 💰 用量成本 - 成本归因分析
```

## 2. 分析中心

### 2.1 功能概述

分析中心提供会话历史数据的多维统计分析，包括：
- KPI 卡片：快速查看关键指标
- 时间序列：活动、成本、延迟、健康趋势
- 分布归因：模型、提供商、会话形态分析
- 热门会话：成本最高、最长、最多请求的会话

### 2.2 如何使用过滤器

**访问路径**: 导航栏 → 会话管理 → 分析中心

**过滤器选项**：

1. **日期范围** (必选)
   - 快捷选择：今天、昨天、最近 7 天、最近 30 天
   - 自定义范围：最大支持 90 天
   - 默认：最近 7 天

2. **模型过滤** (可选)
   - 支持多选
   - 示例：`gpt-4o`, `claude-sonnet-4`, `gemini-2.0-flash`

3. **提供商过滤** (可选)
   - 支持多选
   - 示例：`openai`, `anthropic`, `google`

4. **健康等级** (可选)
   - A（90-100分）：优秀
   - B（80-89分）：良好
   - C（70-79分）：一般
   - D（60-69分）：较差
   - F（<60分）：失败

5. **合规状态** (可选)
   - compliant：合规
   - flagged：已标记
   - blocked：已拦截
   - unknown：未检测

**过滤器联动**：修改任一过滤项后，所有图表和统计数据自动刷新。

**过滤器持久化**：过滤器状态会保存在浏览器，刷新页面后保持不变。

### 2.3 如何解读 KPI 卡片

页面顶部显示 7 张 KPI 卡片：

#### 2.3.1 总会话数
- **含义**: 当前过滤范围内的会话总数
- **对比**: 显示与上一周期的增减百分比
- **用途**: 快速了解活跃度变化

#### 2.3.2 总请求数
- **含义**: 所有会话的 LLM 请求总数
- **用途**: 评估系统负载

#### 2.3.3 总成本
- **含义**: 输入成本 + 输出成本总和（美元）
- **颜色提示**: 
  - 绿色：成本下降
  - 红色：成本上涨超过 20%
- **点击**: 跳转到成本趋势图

#### 2.3.4 平均会话成本
- **含义**: 总成本 / 总会话数
- **用途**: 评估单次对话的经济性
- **基准**: 一般在 $0.05-$0.50 之间

#### 2.3.5 平均延迟
- **含义**: 所有请求的平均响应时间（毫秒）
- **基准**: 
  - <500ms：优秀
  - 500-1000ms：良好
  - >1000ms：需优化

#### 2.3.6 合规率
- **含义**: (合规会话数 / 总会话数) × 100%
- **目标**: ≥ 98%
- **告警**: <95% 显示红色

#### 2.3.7 高质量率
- **含义**: (质量分 ≥ 80 的会话数 / 总会话数) × 100%
- **用途**: 评估整体服务质量

### 2.4 如何下钻分析

**三种下钻方式**：

#### 方式 1: 图表点击
- 点击柱状图/折线图上的任意数据点 → 显示该时间点的会话列表
- 示例：点击"7月1日"的柱子 → 查看当天所有会话

#### 方式 2: 会话列表点击
- 页面底部显示会话列表
- 点击任意会话行 → 打开该会话的全景图

#### 方式 3: 热门会话
- "成本最高 TOP 10" 表格
- 点击任意行 → 打开全景图，诊断成本异常原因

## 3. 实时会话监控

### 3.1 功能概述

实时会话模块显示当前正在运行的会话列表，提供：
- 会话状态机可视化（14 种状态）
- 凭证轮换诊断
- 远程停止/恢复操作
- SSE 实时推送（自动刷新）

### 3.2 如何查看运行中会话

**访问路径**: 导航栏 → 会话管理 → 实时会话

**列表字段说明**：

| 字段 | 含义 | 示例 |
|------|------|------|
| 会话 ID | 唯一标识 | `gw_abc123` |
| 状态 | 当前状态 | `running`, `waiting`, `stopped` |
| 开始时间 | 会话创建时间 | `2026-07-06 10:00:00` |
| 最后活动 | 最近一次请求时间 | `2026-07-06 10:05:30` |
| 请求数 | 已发送的请求数 | `8` |
| 当前凭证 | 正在使用的凭证 ID | `#1234` |
| 健康等级 | 实时健康评分 | `B (85分)` |

**状态图标**：
- 🟢 绿色：运行正常
- 🟡 黄色：等待中（排队/限流）
- 🔴 红色：异常（错误/停止）
- ⚪ 灰色：已完成

### 3.3 如何解读健康等级

**健康评分模型**: 100 分起扣制（Penalty Model）

**扣分规则**：

| 扣分类别 | 触发条件 | 扣分 | 示例 |
|---------|---------|-----|------|
| **错误** | 有错误请求 | 5-30 | 1 个错误扣 5 分，3 个扣 15 分 |
| **延迟** | 平均延迟 > 800ms | 5-20 | 1200ms 扣 10 分 |
| **成本** | 单请求成本 > $0.50 | 5-15 | $1.20 扣 10 分 |
| **合规** | 触发合规拦截 | 10-30 | PII 检测扣 10 分 |
| **放弃** | 用户中途取消 | 10 | 未完成对话扣 10 分 |

**等级划分**：

| 等级 | 分数范围 | 含义 | 颜色 |
|------|---------|------|------|
| A | 90-100 | 优秀 | 🟢 绿色 |
| B | 80-89 | 良好 | 🟦 蓝色 |
| C | 70-79 | 一般 | 🟡 黄色 |
| D | 60-69 | 较差 | 🟠 橙色 |
| F | <60 | 失败 | 🔴 红色 |

**结果分类 (Outcome)**：
- `completed`: 正常完成
- `error`: 错误终止
- `abandoned`: 用户放弃
- `unknown`: 未知状态

### 3.4 如何远程停止会话

**使用场景**：
- 会话陷入死循环
- 成本异常飙升
- 合规风险需紧急拦截

**操作步骤**：

1. 在实时会话列表中找到目标会话
2. 点击行末的"停止"按钮
3. 在弹出框中填写停止原因（必填）
   - 示例：`成本异常，单次请求超过$5`
4. 点击"确认停止"

**注意事项**：
- ⚠️ 危险操作：会立即中断客户端连接
- 📝 审计记录：所有停止操作记录到审计日志
- 🔐 权限要求：需要 `admin` 或 `super_admin` 权限
- ⏱️ 生效时间：<1 秒

**恢复会话**：
- 如果误停，可点击"恢复"按钮
- 会话会从停止前的状态继续

## 4. 会话全景图

### 4.1 功能概述

会话全景图提供单个会话的 360° 诊断视图，整合 9 大面板：

1. **摘要面板**: 基本信息、KPI 汇总
2. **健康诊断面板**: 健康分、扣分明细、优化建议
3. **时间线面板**: 请求序列、时间轴可视化
4. **逐步摘要面板**: 每次请求的摘要（AI 生成）
5. **模型切换面板**: 模型切换历史与原因
6. **成本流向面板**: 成本拆解（输入/输出/模型）
7. **标签建议面板**: 自动标签 + 手动标注
8. **凭证轮换面板**: 凭证切换历史（排查轮换问题）
9. **导出面板**: 导出完整数据为 JSON

### 4.2 如何打开全景图

**三种入口**：

1. **从分析中心**:
   - 分析中心 → 会话列表 → 点击任意会话行
   
2. **从实时会话**:
   - 实时会话 → 点击任意会话行

3. **直接访问**:
   - URL: `/admin/session-analytics/{gw_session_id}/panorama`

### 4.3 健康面板诊断导航

**面板布局**：

```
┌─────────────────────────────────────┐
│ 健康评分: 85 分 (B 级)              │
│ 结果: completed                     │
│ 错误率: 12.5% (1/8)                 │
│ 平均延迟: 850ms                     │
└─────────────────────────────────────┘

扣分明细:
• [-10分] 错误: 1 个错误请求
  → 点击跳转到时间线第 5 个请求
• [-5分] 延迟: 平均延迟 850ms > 800ms 阈值
  → 点击跳转到延迟分布图
```

**诊断闭环**：
- 每个扣分项都是**可点击链接**
- 点击后跳转到对应的诊断面板
- 示例：点击"错误"扣分 → 跳转到时间线面板，高亮显示错误请求

### 4.4 如何采纳优化建议

**建议类型**：

| 类别 | 示例 | 潜在节省 |
|------|------|---------|
| **模型降级** | `gpt-4o` → `gpt-4o-mini` | 50-80% 成本 |
| **启用缓存** | 重复上下文启用 prompt cache | 30-50% 成本 |
| **压缩策略** | 启用智能压缩 | 20-40% token |
| **并发优化** | 减少顺序调用，使用并行 | 30-50% 延迟 |

**采纳步骤**：

1. 在优化建议面板找到目标建议
2. 查看"潜在节省"列（token 和成本）
3. 点击"查看详情"了解具体方案
4. 点击"采纳"按钮
5. 系统自动应用配置更改
6. 下次同类会话自动生效

**撤销建议**：
- 如果效果不佳，可在设置中撤销
- 路径：设置 → 优化策略 → 已采纳建议

## 5. 合规审批

### 5.1 审批流程说明

**触发条件**：

会话在以下情况会进入待审批状态：

1. **PII 检测**: 检测到个人身份信息（姓名、身份证、手机号）
2. **敏感词命中**: 命中租户配置的敏感词库
3. **异常成本**: 单次请求成本超过租户阈值（如 $5）
4. **高风险操作**: 代码执行、文件访问等高风险工具调用

**审批状态**：

| 状态 | 含义 | 操作 |
|------|------|------|
| `pending` | 等待审批 | 需人工审批 |
| `approved` | 已批准 | 会话继续执行 |
| `rejected` | 已拒绝 | 会话终止 |
| `timeout` | 超时未处理 | 自动拒绝（可配置为自动批准）|

### 5.2 如何处理待审批

**访问路径**: 导航栏 → 会话管理 → 合规审批

**审批步骤**：

#### 5.2.1 批准审批

1. 点击待审批会话行，查看详情
2. 检查触发原因（PII / 敏感词 / 成本）
3. 查看请求内容预览（脱敏显示）
4. 如果确认无风险，点击"批准"
5. （可选）填写批准备注
6. 点击"确认批准"

**批准后**：
- 会话立即恢复执行
- LLM 请求自动发送
- 客户端收到响应

#### 5.2.2 拒绝审批

1. 如果确认有风险，点击"拒绝"
2. **必须填写拒绝原因**（用于审计）
   - 示例：`命中内部敏感项目代号，拒绝执行`
3. 点击"确认拒绝"

**拒绝后**：
- 会话立即终止
- 客户端收到错误响应：`403 Forbidden: Request rejected by compliance review`
- 拒绝记录永久保存

### 5.3 审批 SLA 监控

**查看路径**: 合规审批 → 统计面板

**关键指标**：

| 指标 | 定义 | 目标 |
|------|------|------|
| 待审批数量 | 当前 pending 状态的数量 | <10 |
| 平均等待时长 | 从创建到审批的平均时长 | <5 分钟 |
| 超时率 | 超时未处理的比例 | <5% |
| 拦截率 | 拒绝 / 总审批数 | 依业务而定 |

**告警**：
- 待审批积压 >50：发送钉钉/企微通知
- 超时率 >20%：触发 P1 告警

## 6. 用量成本

### 6.1 功能概述

用量成本模块提供多维成本归因分析，帮助：
- 了解成本构成（模型/提供商/用户意图）
- 识别成本异常
- 评估缓存和压缩的节省效果

### 6.2 如何查看成本归因

**访问路径**: 导航栏 → 会话管理 → 用量成本

**五维归因**：

#### 6.2.1 按模型归因

**显示内容**：
- 饼图：各模型占总成本的百分比
- 表格：每个模型的详细统计

| 模型 | 请求数 | 总成本 | 平均单价 | 总 Token | 错误率 |
|------|--------|--------|----------|----------|--------|
| gpt-4o | 1200 | $45.50 | $0.038 | 1,250,000 | 2.3% |
| claude-sonnet-4 | 800 | $32.00 | $0.040 | 900,000 | 1.5% |
| gemini-2.0-flash | 500 | $5.00 | $0.010 | 1,000,000 | 3.2% |

**优化建议**：
- 如果 `gpt-4o` 占比过高（>60%），考虑部分场景降级到 `gpt-4o-mini`

#### 6.2.2 按提供商归因

类似按模型，按 `openai`, `anthropic`, `google` 等提供商聚合。

**用途**：
- 评估提供商成本效率
- 识别单点依赖风险

#### 6.2.3 按用户意图归因

**意图分类**（自动检测）：
- `code_generation`: 代码生成
- `summarization`: 摘要总结
- `translation`: 翻译
- `qa`: 问答
- `creative_writing`: 创意写作
- `unknown`: 未识别

**示例图表**：

```
代码生成: $50.00 (40%)
摘要总结: $30.00 (24%)
问答: $25.00 (20%)
其他: $20.00 (16%)
```

**优化建议**：
- 代码生成场景可使用 `claude-sonnet-4`（性价比高）
- 摘要总结可使用 `gpt-4o-mini`（足够准确）

#### 6.2.4 按工作类型归因

**工作类型**（自动标注）：
- `chat`: 对话
- `completion`: 文本续写
- `embeddings`: 向量化
- `moderation`: 内容审核

### 6.3 如何解读同比环比

**同比**: 与上周期（上周/上月）的对比

**显示格式**：

```
本周成本: $125.50
上周成本: $98.30
环比: +27.7% ↑
```

**颜色提示**：
- 🟢 绿色下箭头：成本下降（好）
- 🔴 红色上箭头：成本上涨 >20%（需关注）
- ⚪ 灰色：变化 <5%（稳定）

**趋势分析**：
- 点击趋势图上的任意数据点 → 显示该时间点的详细归因
- 示例：7月1日成本飙升 → 点击查看当天模型分布，发现大量使用 `gpt-4o`

### 6.4 缓存经济学说明

**什么是缓存节省**：

LLM 提供商（如 OpenAI/Anthropic）支持 Prompt Caching：
- **Cache Write**: 首次发送长上下文，提供商缓存
- **Cache Read**: 后续请求复用缓存，价格减半（或免费）

**节省计算**：

```
节省 Token = 缓存读取 Token
节省成本 = 缓存读取 Token × (原价 - 缓存价) / 1M

示例:
- 缓存读取: 50,000 tokens
- 原价: $5.00/1M tokens
- 缓存价: $1.25/1M tokens
- 节省: 50,000 × ($5.00 - $1.25) / 1,000,000 = $0.1875
```

**查看路径**: 用量成本 → 缓存节省面板

**显示内容**：
- 缓存命中率：(缓存读取 / 总输入 token) × 100%
- 累计节省成本
- 建议：如何提高缓存命中率

## 7. FAQ

### 7.1 为什么我的会话健康分很低？

**排查步骤**：

1. 打开会话全景图
2. 查看健康诊断面板的扣分明细
3. 常见原因：
   - **错误扣分**: 检查时间线中的错误请求，查看错误信息
   - **延迟扣分**: 查看平均延迟，考虑切换更快的模型或提供商
   - **成本扣分**: 单次请求成本过高，考虑模型降级
   - **合规扣分**: 触发 PII 检测，检查输入内容

### 7.2 如何导出会话数据？

**方法 1: 单个会话**
1. 打开会话全景图
2. 点击右上角"导出"按钮
3. 选择格式：JSON / CSV
4. 下载文件

**方法 2: 批量导出**
1. 分析中心 → 会话列表
2. 勾选目标会话（支持多选）
3. 点击"批量导出"
4. 选择字段（基本信息/完整时间线/请求正文）
5. 下载 ZIP 文件

**注意**: 导出请求/响应正文需要 `super_admin` 权限

### 7.3 过滤器不生效怎么办？

**排查步骤**：

1. 检查日期范围是否合理（不能为空）
2. 清除浏览器缓存，刷新页面
3. 检查是否有租户权限限制
4. 查看浏览器控制台是否有错误

### 7.4 实时会话列表不更新？

**可能原因**：

1. **SSE 连接断开**: 刷新页面重新连接
2. **网络问题**: 检查网络连接
3. **权限不足**: 确认有 `admin` 权限
4. **后端未启用**: 联系管理员检查 `liveStreamHub` 是否启用

### 7.5 如何提高缓存命中率？

**优化建议**：

1. **保持上下文稳定**: 不要频繁修改系统提示词
2. **使用会话 ID**: 确保客户端正确传递 `session_id`
3. **合理分段**: 长文档分段处理，复用前文缓存
4. **避免随机性**: 减少时间戳等动态内容

### 7.6 审批超时后会怎样？

**默认行为**: 超时后自动拒绝

**可配置**:
1. 进入设置 → 合规审批 → 超时策略
2. 选择：
   - 自动拒绝（推荐，安全优先）
   - 自动批准（便利优先，风险自负）
3. 配置超时时长（默认 30 分钟）

### 7.7 如何理解"会话形态"？

**会话形态** = 请求数 + 持续时间的组合特征

**典型形态**：

| 形态 | 请求数 | 持续时间 | 特征 | 示例场景 |
|------|--------|----------|------|----------|
| 单次短对话 | 1 | <1min | 简单问答 | "今天天气怎么样" |
| 多轮短对话 | 2-5 | 1-5min | 连续追问 | "推荐餐厅 → 营业时间 → 预订方式" |
| 深度对话 | 6-20 | 5-30min | 复杂任务 | 代码调试、文档撰写 |
| 长会话 | 20+ | 30min+ | 持续协作 | 大型项目、教学辅导 |

**用途**: 识别用户使用模式，优化产品体验
