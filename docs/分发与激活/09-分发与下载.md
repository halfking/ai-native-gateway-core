## 四、版本与构建号管理

### 4.1 版本号规则

```
格式: v{MAJOR}.{MINOR}.{PATCH}-{BUILDNUM}
例:   v1.13.0-770   (MAJOR=1, MINOR=13, PATCH=0, BUILDNUM=770)

- MAJOR.MINOR.PATCH: 语义化版本
- BUILDNUM: 编译次数（CI 自动递增）
```

**`version.json`**（仓库根目录）：

## 五、CI / CD 流程

### 5.1 release 构建流水线

```
Git push (tag: v1.13.0)
        │
        ▼
CI 触发
        │
        ├─► bump-version.sh（自动 +1 build_seq）
        │
        ├─► go build -tags master -o kx-gateway-master
        │
        ├─► go build -tags customer -o kx-gateway-client
        │
        ├─► check-customer-binary.sh（验证不含 admin 路由）
        │
        ├─► cd web && pnpm build:master → dist-master/
        │
        ├─► cd web && pnpm build:customer → dist-customer/
        │
        ├─► docker build -t kx-llm-gateway-go:v1.13.0-770
        │
        ├─► docker save | gzip → images/*.tar.gz
        │
        ├─► pg_dump → db/dumps/llm_gateway_baseline.dump
        │
        ├─► 打包：
        │   ├─ release-master-v1.13.0.tar.gz   （内部用）
        │   └─ kx-gateway-go-v1.13.0-...tar.gz （对外发布）
        │
        ├─► sha256sum → SHA256SUMS
        │
        ├─► 推送到 registry.kxpms.cn
        │
        ├─► 上传到 download.kxpms.cn CDN
        │
        └─► 通知：邮件列表 / 站内公告 / GitHub release
```

### 5.2 release 验证清单（自动）

- [ ] master 二进制包含全部 admin 路由
- [ ] customer 二进制不含任何 admin 路由（grep + strings）
- [ ] customer 前端不含 `/ops/*` 菜单
- [ ] docker 镜像可启动且 `/healthz` 返回 200
- [ ] DB dump 可 restore 到空库
- [ ] install.sh 流程跑通
- [ ] offline 包完整（含 3 镜像 + DB dump + installer）

## 六、用户下载流程

### 6.1 在线用户

```
1. 访问 https://llm.kxpms.cn
2. 点击 [立即下载]
3. 选择平台（自动检测 + 提供手动选择）
4. 点击 [📦 下载离线包]
5. 文件下载到 ~/Downloads/
6. 解压：
   tar xzf kx-gateway-go-v1.13.0-linux-amd64-offline.tar.gz
7. 校验：
   sha256sum -c SHA256SUMS
8. 运行 ./install.sh
```

### 6.2 离线用户（完全断网）

```
1. 在联网电脑访问官网下载离线包 + 离线激活工具
2. 通过 U 盘 / 邮件 / 安全通道传输
3. 在隔离网电脑：
   tar xzf kx-gateway-go-v1.13.0-...tar.gz
   ./install.sh
4. 激活选择 [离线激活]
5. 在隔离网电脑生成 activation.req
6. 拷贝到联网电脑上传到 https://llm.kxpms.cn/offline-activation
7. 下载 activation.resp（实际为 license.dat）
8. 拷贝回隔离网电脑导入
```

## 八、发布策略

### 8.1 版本节奏

| 类型 | 频率 | 说明 |
|------|------|------|
| **MAJOR** | 6 个月 | 含重大变更，可能不向下兼容 |
| **MINOR** | 1 个月 | 新功能，向下兼容 |
| **PATCH** | 按需 | Bug 修复、安全补丁 |
| **LTS** | 季度发布 | 12 个月支持周期 |

### 8.2 向后兼容

- License 数据库 schema 加字段必须向后兼容
- API 新增字段/端点向前兼容
- 客户端可升级到最新 schema（无需重部署）

### 8.3 弃用流程

- 标记 DEPRECATED 的 API 至少保留 6 个月
- 文档标注迁移指南
- 弃用期满后下个 MAJOR 版本移除

## 九、关键决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 分发 CDN | CloudFlare / 阿里云 | 国内国外覆盖 |
| 下载包格式 | tar.gz + zip | 跨平台 |
| 试用版是否单独发布包？ | ❌ 不单独，全部版本都支持试用 | 简化分发 |
| 主控端如何发布？ | 内部 CI 产物，不上传 CDN | 物理隔离 |
| 离线激活工具 | 单独下载，不打包 | 安全 |
