## 一、方案概述

本方案实现从代码提交到用户下载的完整自动化流程，包括：

1. **构建打包**：基于 git commit 自动构建多平台二进制和 Docker 镜像
2. **测试验证**：在 245 预生产环境和本地 Docker 环境进行自动化测试
3. **版本管理**：版本记录的创建、发布、删除和状态管理
4. **文件分发**：自动上传到 files.kxpms.cn（Cloudreve）
5. **用户安装**：提供一键安装脚本和升级脚本

### 2.5 版本管理 API

#### 2.5.1 数据库 Schema

```sql
-- 版本表
CREATE TABLE IF NOT EXISTS releases (
    id BIGSERIAL PRIMARY KEY,
    version VARCHAR(50) NOT NULL,           -- 2.4.7
    build_seq INT NOT NULL,                 -- 1346
    git_sha VARCHAR(40) NOT NULL,           -- 3970dbc1
    build_date VARCHAR(20) NOT NULL,        -- 20260723
    status VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending/testing/released/archived
    release_notes TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    released_at TIMESTAMP,
    created_by VARCHAR(100),
    UNIQUE(version, build_seq)
);

-- 发布文件表
CREATE TABLE IF NOT EXISTS release_files (
    id BIGSERIAL PRIMARY KEY,
    release_id BIGINT REFERENCES releases(id) ON DELETE CASCADE,
    file_name VARCHAR(255) NOT NULL,
    file_type VARCHAR(50) NOT NULL,         -- binary/docker/installer
    os VARCHAR(50) NOT NULL,                -- linux/darwin/windows
    arch VARCHAR(50) NOT NULL,              -- amd64/arm64
    file_size BIGINT NOT NULL,
    sha256 VARCHAR(64) NOT NULL,
    download_url TEXT NOT NULL,
    cloudreve_path TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 测试结果表
CREATE TABLE IF NOT EXISTS release_tests (
    id BIGSERIAL PRIMARY KEY,
    release_id BIGINT REFERENCES releases(id) ON DELETE CASCADE,
    test_env VARCHAR(50) NOT NULL,          -- 245/local-docker/252-docker
    test_type VARCHAR(50) NOT NULL,         -- integration/e2e/smoke
    status VARCHAR(20) NOT NULL,            -- pass/fail/skip
    test_log TEXT,
    tested_at TIMESTAMP DEFAULT NOW()
);
```

## 四、关键技术点

### 4.1 版本号自动递增

```bash
# scripts/version/bump-build-seq.sh
#!/usr/bin/env bash
set -euo pipefail

VERSION_FILE="${1:-version.json}"

current_seq=$(jq -r '.build_seq' "$VERSION_FILE")
new_seq=$((current_seq + 1))

jq ".build_seq = $new_seq | .build_date = \"$(date +%Y%m%d)\"" "$VERSION_FILE" > "$VERSION_FILE.tmp"
mv "$VERSION_FILE.tmp" "$VERSION_FILE"

echo "Build sequence bumped: $current_seq -> $new_seq"
```

### 4.2 多平台编译

```bash
# scripts/build/build-backend.sh
#!/usr/bin/env bash
set -euo pipefail

PLATFORMS=(
    "linux/amd64"
    "linux/arm64"
    "darwin/amd64"
    "darwin/arm64"
)

for platform in "${PLATFORMS[@]}"; do
    IFS='/' read -r -a parts <<< "$platform"
    GOOS="${parts[0]}"
    GOARCH="${parts[1]}"
    
    output="build/llm-gateway-go-${VERSION}-${GOOS}-${GOARCH}"
    
    echo "Building for $GOOS/$GOARCH..."
    CGO_ENABLED=0 GOOS=$GOOS GOARCH=$GOARCH go build \
        -ldflags "-X main.Version=${VERSION} -X main.BuildSeq=${BUILD_SEQ}" \
        -o "$output" \
        ./cmd/gateway
    
    echo "✅ Built: $output"
done
```

### 4.3 Docker 多架构镜像

```bash
# scripts/build/build-docker.sh
#!/usr/bin/env bash
set -euo pipefail

# 构建多架构镜像
docker buildx build \
    --platform linux/amd64,linux/arm64 \
    --tag registry.kxpms.cn/kaixuan/llm-gateway-go:${VERSION}-${BUILD_SEQ} \
    --tag registry.kxpms.cn/kaixuan/llm-gateway-go:latest \
    --push \
    .

# 导出离线镜像
docker buildx build \
    --platform linux/amd64 \
    --tag llm-gateway-go:${VERSION}-${BUILD_SEQ}-amd64 \
    --load \
    .

docker save llm-gateway-go:${VERSION}-${BUILD_SEQ}-amd64 | \
    gzip > "build/images/llm-gateway-go-${VERSION}-${BUILD_SEQ}-amd64.tar.gz"
```

### 4.4 健康检查脚本

```bash
# scripts/deploy/health-check.sh
#!/usr/bin/env bash
set -euo pipefail

HOST="${1:-http://localhost:8781}"
MAX_RETRIES=30
RETRY_INTERVAL=2

echo "Checking health at $HOST/healthz..."

for i in $(seq 1 $MAX_RETRIES); do
    if curl -fsS "$HOST/healthz" | grep -q '"status":"ok"'; then
        echo "✅ Health check passed"
        exit 0
    fi
    echo "⏳ Attempt $i/$MAX_RETRIES failed, retrying in ${RETRY_INTERVAL}s..."
    sleep $RETRY_INTERVAL
done

echo "❌ Health check failed after $MAX_RETRIES attempts"
exit 1
```

## 五、风险与应对

### 5.1 风险清单

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 245 环境不稳定 | 测试失败 | 中 | 增加本地 Docker 测试作为备份 |
| Cloudreve 上传失败 | 无法分发 | 低 | 实现重试机制和备用上传方式 |
| 多平台编译失败 | 部分平台无法发布 | 低 | 交叉编译测试和 CI 环境验证 |
| 版本冲突 | 覆盖已发布版本 | 中 | 版本号唯一性约束和发布前检查 |

### 5.2 回滚策略

1. **构建失败**：保留上次成功构建的产物
2. **测试失败**：不创建版本记录，直接清理产物
3. **上传失败**：保留本地产物，稍后手动上传
4. **发布后发现问题**：更新版本状态为 "archived"，禁止下载
