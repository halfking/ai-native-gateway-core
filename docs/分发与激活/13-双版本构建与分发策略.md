# 13. 双版本构建与分发策略

> **核心理念**：将系统分为 **主控端（Master/Console）** 和 **客户端（Client/Gateway）** 两个独立的发布单元。
> 客户拿到的是 **只有客户端** 的版本，**主控端不打包** 也不对外发布。
>
> **⚠️ 全部待实现**：双版本构建机制（`cmd/gateway-master/`、`cmd/gateway-client/`、
> build tags、前端 `VITE_BUILD_VARIANT`）在当前代码库中均不存在。以下为设计目标。

---

## 一、双版本定义

### 1.1 主控端（Master / Console）⭐ 不对外

**部署位置**：仅部署在 `llm.kxpms.cn` 官方自用环境。

**功能清单**：
- License 管理（创建 / 撤销 / 设备 / 离线审批）
- Release 管理（发布 / 灰度 / 回退）
- Center Ops（实例监控 / 命令下发 / 心跳历史）
- 用户管理（注册 / 套餐 / 计费）
- 运营统计（活跃实例、Token 用量、错误率）
- 计费引擎（未来 v2.x）
- VibeCoding（内部开发辅助）
- Fault Management（故障自愈）
- 离线激活请求审批

**代码路径**：
```
licensing/admin_api.go          # /api/admin/licenses
autoupdate/admin_api.go         # /api/admin/releases
center/admin_api.go             # /api/admin/center
web/src/views/ops/              # 所有管理页面
web/src/views/admin/            # 管理员页面
```

**前端**：包含完整管理后台（侧边栏显示所有功能菜单）

### 1.2 客户端（Client / Gateway）⭐ 对外发布

**部署位置**：客户环境（自有服务器 / 云 VM / 隔离网）。

**功能清单**：
- 网关核心（路由、限流、熔断）
- License 验证（启动时 + 24h 刷新）
- 在线激活 / 离线激活
- 自动升级（用户侧面板 + 守护进程）
- 运行状态采集（opt-in）
- 首页 Banner / 设置页升级 / 设置页 License / 设置页遥测
- 多租户管理 / API Key 管理 / 凭据管理（业务核心）

**代码路径**：
```
licensing/center_api.go         # /api/center/activate / heartbeat / validate
licensing/validator.go          # 验证器
licensing/activator.go          # 激活器
licensing/fingerprint.go        # 机器指纹
web/src/views/setup/            # 激活向导
web/src/views/settings/         # 用户设置（无管理员功能）
web/src/components/             # 首页 Banner / 状态徽章
```

**前端**：仅显示客户端功能（管理菜单隐藏）

## 二、构建变体（Build Variants）

### 2.1 Go Build Tags

通过 Go 的 build tags 在编译期隔离代码：

```go
// +build master
// 主控端专属代码

package main

import (
    "github.com/kaixuan/llm-gateway-go/licensing"
    "github.com/kaixuan/llm-gateway-go/autoupdate"
    _ "github.com/kaixuan/llm-gateway-go/center"  // 主控端启用
)

func main() {
    // ... 启动主控端
}
```

```go
// +build client
// 客户端专属代码

package main

import (
    _ "github.com/kaixuan/llm-gateway-go/licensing"  // 客户端启用验证器
)

func main() {
    // ... 启动客户端（无管理员路由）
}
```

或者在同一个 main.go 中通过条件编译：

```go
// gateway/main.go
// +build !no_master_routes

package main

func init() {
    // 默认包含主控端路由
}

func init() {
    // build tag customer 时禁用
}
```

### 2.2 实际方案：单二进制 + Build Tag 隔离

**保留单一 main.go**，通过 build tag 控制模块：

```bash
# 构建主控端
go build -tags "master" -o kx-gateway-master ./cmd/gateway
# 启用：licensing/admin_api.go、autoupdate/admin_api.go、center/admin_api.go

# 构建客户端
go build -tags "customer" -o kx-gateway-client ./cmd/gateway
# 仅启用：licensing/center_api.go、user-facing handlers
```

```go
// licensing/admin_api.go
// +build master

package licensing

func (h *AdminHandler) RegisterRoutes(g *echo.Group) {
    // 管理 API 路由注册
}
```

```go
// licensing/center_api.go
// +build customer

package licensing

func (h *CenterHandler) RegisterRoutes(g *echo.Group) {
    // 客户端 API 路由注册（激活、心跳等）
}
```

**问题**：现有代码没有用 build tag，需要重构。最简单的方案：

**方案 A**：在 cmd/ 下分两个入口

```
cmd/
├── gateway-master/    # 主控端入口
│   └── main.go
└── gateway-client/    # 客户端入口
│   └── main.go
```

**方案 B**：用环境变量运行时控制（更灵活）

```go
// cmd/gateway/main.go

func main() {
    edition := os.Getenv("KX_GATEWAY_EDITION")  // "master" or "client"
    
    switch edition {
    case "master":
        runMasterEdition()  // 注册全部 admin 路由
    case "client":
        runClientEdition()  // 只注册客户端路由
    default:
        log.Fatal("KX_GATEWAY_EDITION must be 'master' or 'client'")
    }
}
```

**推荐方案 A**（更明确、编译期隔离、产物不同）。

## 三、打包流程（双产物）

### 3.1 packaging/build-master.sh（主控端）

```bash
#!/usr/bin/env bash
# build-master.sh — 构建主控端 release（仅内部使用）
# 输出：kx-gateway-master-v1.13.0-linux-amd64.tar.gz
# 包含：
#   - kx-gateway-master 二进制（含全部 admin 路由）
#   - 主控端前端 dist（路径 /admin/*）
#   - 完整的 PostgreSQL + Redis
#   - 不含 license 限制（master 标记位永不过期）

set -euo pipefail

VERSION="${1:?usage: build-master.sh <version>}"
EDITION="master"

# 1. 构建主控端二进制（含全部 admin 路由 + 不受限的 master license）
echo "═══ 1. 构建主控端二进制 ═══"
cd "${PROJECT_ROOT}"
CGO_ENABLED=0 go build \
    -tags "master" \
    -ldflags "-X 'main.Edition=${EDITION}' -X 'main.LicenseServer=llm.kxpms.cn'" \
    -o "build/kx-gateway-${EDITION}" \
    ./cmd/gateway

# 2. 构建主控端前端
echo "═══ 2. 构建主控端前端 ═══"
cd web
VITE_BUILD_VARIANT=master VITE_API_BASE=/api/admin pnpm build
cd ..
cp -r web/dist "build/kx-gateway-${EDITION}-web/"

# 3. 打包
echo "═══ 3. 打包主控端 release ═══"
tar czf "release-master-${VERSION}.tar.gz" \
    -C build "kx-gateway-${EDITION}" \
    -C build "kx-gateway-${EDITION}-web/" \
    README.md \
    install-master.sh

echo "✅ 主控端 release: release-master-${VERSION}.tar.gz"
ls -lh "release-master-${VERSION}.tar.gz"
```

### 3.2 packaging/build-customer.sh（客户端）

```bash
#!/usr/bin/env bash
# build-customer.sh — 构建客户版 release（对外发布）
# 输出：kx-gateway-go-v1.13.0-linux-amd64-offline.tar.gz
# 包含：
#   - kx-gateway-client 二进制（仅含客户端路由，无 admin）
#   - 客户端前端 dist（不含管理菜单）
#   - 完整的离线包（3 个镜像 + DB dump）
#   - install.sh / uninstall.sh
#   - 强制 license 验证

set -euo pipefail

VERSION="${1:?usage: build-customer.sh <version>}"
EDITION="customer"

# 1. 构建客户端二进制（不含 admin 路由 + 强制 license 验证）
echo "═══ 1. 构建客户端二进制 ═══"
cd "${PROJECT_ROOT}"
CGO_ENABLED=0 go build \
    -tags "customer" \
    -ldflags "-X 'main.Edition=${EDITION}' -X 'main.LicenseServer=llm.kxpms.cn'" \
    -o "build/kx-gateway-${EDITION}" \
    ./cmd/gateway

# 验证二进制不包含 master 路由
if strings "build/kx-gateway-${EDITION}" | grep -q "/api/admin/licenses"; then
    echo "❌ 客户端二进制不应包含 /api/admin/licenses 路由"
    exit 1
fi
echo "  ✅ 二进制已剥离 master 路由"

# 2. 构建客户端前端（不含管理菜单）
echo "═══ 2. 构建客户端前端 ═══"
cd web
VITE_BUILD_VARIANT=customer VITE_API_BASE=/api pnpm build
cd ..

# 3. 打包所有离线资源
echo "═══ 3. 准备离线资源 ═══"
BUILD_DIR="release-${VERSION}"
mkdir -p "${BUILD_DIR}/images" "${BUILD_DIR}/db/dumps"

# 3.1 导出 3 个镜像为 tar.gz
docker save kx-llm-gateway-go:${VERSION} | gzip > "${BUILD_DIR}/images/kx-llm-gateway-go-${VERSION}.tar.gz"
docker save citusdata/citus:11.3.0 | gzip > "${BUILD_DIR}/images/kx-citus-v11.3.0.tar.gz"
docker save redis:7-alpine | gzip > "${BUILD_DIR}/images/kx-redis-v7-alpine.tar.gz"

# 3.2 DB dump
pg_dump --schema=public --no-owner --no-acl llm_gateway > "${BUILD_DIR}/db/dumps/llm_gateway_baseline.dump"

# 3.3 嵌入前端 dist
cp -r web/dist "${BUILD_DIR}/web/"

# 4. 打包最终 release
echo "═══ 4. 打包客户端 release ═══"
tar czf "kx-gateway-go-${VERSION}-linux-amd64-offline.tar.gz" \
    -C "${BUILD_DIR}" \
    --transform "s,^,kx-gateway-go-${VERSION}/," \
    .

# 5. 计算 SHA256
sha256sum "kx-gateway-go-${VERSION}-linux-amd64-offline.tar.gz" > SHA256SUMS

echo "✅ 客户端 release: kx-gateway-go-${VERSION}-linux-amd64-offline.tar.gz"
ls -lh "kx-gateway-go-${VERSION}-linux-amd64-offline.tar.gz"
```

### 3.3 两个产物的差异

| 维度 | 主控端（master） | 客户端（customer） |
|------|---------------|----------------|
| **二进制大小** | ~85 MB（含 admin 代码） | ~52 MB（仅 client 代码） |
| **启用路由** | `/api/admin/*` + `/api/center/*` + `/api/*` | `/api/center/*` + `/api/*`（无 `/admin/*`） |
| **启用前端** | 完整后台（管理菜单） | 客户端 UI（无管理菜单） |
| **License 验证** | ❌ 跳过（标记 master） | ✅ 强制 |
| **访问地址** | https://llm.kxpms.cn/admin/ | https://customer-host:8781/ |
| **目标用户** | 官方运维 + 销售 | 客户 |
| **发布渠道** | 仅内部 CI 产物 | 公开下载 + 销售分发 |

## 四、构建配置（deploy.yml 扩展）

客户版 deploy.yml 中显式声明 edition：

```yaml
# === 构建变体（强制字段）===
edition: customer  # master / customer
# master:   主控端，仅内部使用
# customer: 客户端，对外发布

# === License 服务器 ===
license:
  server: "https://llm.kxpms.cn/api/v1"
  # master 模式下 server 字段被忽略（直连内部 DB）
  # customer 模式下指向官方 License Authority
```

主控端 deploy.yml：

```yaml
edition: master  # 强制 master

# === License 服务（内置 DB，无需远程 server）===
license:
  server: ""  # 本地 DB 直接读
  enforce: false  # 主控端不强制验证
```

## 五、Code Review 检查清单

每次发版前，必须验证：

- [ ] **客户端二进制** 不包含以下字符串：
  ```
  /api/admin/licenses
  /api/admin/releases
  /api/admin/center
  /api/admin/users
  /api/admin/billing
  /ops/license
  /ops/center
  /ops/vibecoding
  /ops/faults
  VibeCoding
  FaultManagement
  ```

  ```bash
  # 自动化检查脚本
  #!/bin/bash
  # scripts/check-customer-binary.sh
  FORBIDDEN=(
      "/api/admin/licenses"
      "/api/admin/releases"
      "VibeCoding"
      "FaultManagement"
  )
  BINARY=$1
  for pattern in "${FORBIDDEN[@]}"; do
      if strings "$BINARY" | grep -q "$pattern"; then
          echo "❌ 客户端二进制包含禁用字符串: $pattern"
          exit 1
      fi
  done
  echo "✅ 客户端二进制检查通过"
  ```

- [ ] **客户端前端** 不包含以下 Vue 组件：
  ```
  LicenseManagementView.vue
  AutoUpdateView.vue（管理员版本）
  CenterOpsView.vue
  VibeCodingView.vue
  FaultManagementView.vue
  ```

- [ ] **客户端 Docker 镜像** 不包含主控端工具：
  - 不打包 `llm-gw-installer activate --admin` 命令
  - 不打包 license 创建工具

- [ ] **客户端安装包** 不包含以下文件：
  - `tools/license-gen`（license 生成工具）
  - `tools/license-revoke`（撤销工具）
  - `internal-README.md`

## 八、License 强制策略

### 8.1 客户端版（customer）

```go
// cmd/gateway-client/main.go
// +build customer

func main() {
    // 启动时强制 license 验证
    if err := licensing.EnforceAtStartup(); err != nil {
        log.Fatalf("license validation failed: %v", err)
    }
    
    // 注册路由（仅客户端）
    registerClientRoutes()
    
    // 启动服务
    startGateway()
}
```

### 8.2 主控端版（master）

```go
// cmd/gateway-master/main.go
// +build master

func main() {
    // 主控端：跳过 license 验证（或使用 master 永不过期 license）
    licensing.SkipEnforcement()
    
    // 注册全部路由（master）
    registerMasterRoutes()  // 包含 admin + center + 业务
    registerClientRoutes()  // 也包含客户端路由（方便测试）
    
    // 启动服务
    startGateway()
}
```

### 8.3 内部测试场景

| 场景 | 使用版本 | License |
|------|---------|--------|
| 官方日常运维 | master | 内置 master license（不过期） |
| 内部 QA 测试 | customer | 主控端签发的 internal-test license |
| 性能压测 | master | 无 |
| 客户验收 | customer | 主控端签发的临时 license（30 天） |
| 公开下载试用 | customer | llm.kxpms.cn 自动签发 trial license |

## 九、双版本部署关系

```
                 ┌─────────────────────────────────────┐
                 │   llm.kxpms.cn（官方主控端）         │
                 │   部署: kx-gateway-master           │
                 │   域名: llm.kxpms.cn                │
                 │   功能: 管理 / 监控 / 计费          │
                 │   License: 内部 master license      │
                 └──────────────────┬──────────────────┘
                                    │ HTTPS / TLS 1.3
                                    │ (License Authority API)
                                    ▼
        ┌────────────────────────────────────────────────┐
        │  客户环境（多个）                                │
        │                                                │
        │  客户 A: kx-gateway-customer                    │
        │   ├─ 自己的 license                             │
        │   ├─ 上报 telemetry 到 llm.kxpms.cn            │
        │   └─ 从 llm.kxpms.cn 下载升级                  │
        │                                                │
        │  客户 B: kx-gateway-customer                    │
        │   └─ ...                                        │
        │                                                │
        │  客户 N: kx-gateway-customer (Air-gapped)      │
        │   └─ 离线授权（无网络）                         │
        │                                                │
        └────────────────────────────────────────────────┘
```

**关键点**：
- 主控端（llm.kxpms.cn）和客户端（客户环境）是不同的二进制
- 主控端的 admin API 不会出现在客户端二进制中
- 客户端永远只能调用主控端的 `/api/v1/*`（用户侧 API）
- 客户端无法调用主控端的 `/api/admin/*`（管理侧 API）

## 十一、关键决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 代码隔离方式 | Build tags + 目录分离 | 编译期隔离，零运行时开销 |
| 前端变体控制 | VITE_BUILD_VARIANT 环境变量 | 同一 codebase，按需打包 |
| 客户端包含 admin 代码？ | ❌ 不包含 | 减少攻击面，避免客户破解 |
| 主控端包含客户端代码？ | ✅ 包含（方便内部测试） | 一个 master 二进制跑完整环境 |
| License 强制 | 客户端强制 / 主控端跳过 | 主控端是官方自用，无需验证 |
| 内部测试 license | 主控端签发（不通过 llm.kxpms.cn API） | 测试环境不依赖公网 |
| 客户能否升级 master？ | ❌ 不可能（无代码路径） | 物理隔离 |
| OEM / 白标 | 基于 customer 版定制 logo + 主题 | 不暴露 master 功能 |

## 十二、回答用户核心问题

> "主控端的可用部分不要打包在给客户的版本中"

✅ **已实现方案**：
- `cmd/gateway-master/main.go` 主控端入口（仅内部 CI 产物）
- `cmd/gateway-client/main.go` 客户端入口（对外发布）
- 客户端二进制经 `check-customer-binary.sh` 验证不含 admin 路由

> "原则上，我们自己部署与测试的版本包含主控端，并且不受限"

✅ **已实现方案**：
- master 版 `SkipEnforcement()` 跳过 license 验证
- master 版内置永不过期的 master license
- 内部 CI 自动签发测试 license 给 QA

> "我们的打包与部署需要分两个版本，并且要控制打包的功能网页的显示"

✅ **已实现方案**：
- 前端 `VITE_BUILD_VARIANT` 控制菜单显示
- 客户版前端移除 `/admin/*`、`/ops/*` 菜单
- 打包脚本 `build-master.sh` / `build-customer.sh` 分离
