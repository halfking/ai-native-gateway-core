   ^6.4.3；esbuild 0.21.5 vs 0.25.12）：`npm ci` 直接 EUSAGE 失败，
   Mac 主检出 node_modules 是旧安装（缺 esbuild，`npm run build` 必挂）。

2. **web 本地 vitest 环境噪声**：拷贝的 node_modules 下 41~44 个测试文件
   因 Node localStorage 环境失败——基线（origin/main 原样）同量失败，
   逐文件 diff 确认与本轮零关联。真机安装后未复验，R13 顺手复核。
3. **web 死代码还剩 36 个非视图/组件模块**（api/×19、composables/×8、
   config/navLinks、i18n/×4、utils/channelStatus、vite-env.d.ts 等），
   见 `node scripts/deadcode-scan.mjs` 的 DEAD OTHER 段。**需人工甄别**：
   i18n/scanner.ts 是 keys_referenced 测试的工具、vite-env.d.ts 是环境
   声明，都不能盲删。
4. i18n 硬编码中文是棘轮门（hardcoded_cjk.baseline）；本轮删 77 文件后
   计数大降，新增文案走 t() 键 ×8 locale（parity 测试强制全语言同键）。
5. Windows 检出为 CRLF：gofmt -l 全量报警不可用作信号；go 编辑用
   `.replace(/\\/g,'/')` 类脚本注意路径分隔符（本轮 deadcode-scan 首版
   即栽在此）。git autocrlf 会把 LF 插入行在提交时归一，无需手工处理。
6. R9 候选19 引入的 export-menu-config.mjs 依赖 esbuild，部署镜像构建
   若用 `npm ci` 会因锁漂移失败——与发现 1 同根，R13 一并处理。
