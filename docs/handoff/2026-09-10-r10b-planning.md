### 1.2 RawDataLogger 可下线性

**结论：不可直接下线**。评估依据（来自 R8 范围核查）：

1. **落盘点**：通过 `RawDataLogger` 写入的字节会进入与 `AsyncRawDataLogger` 共享的 sink 文件队列（`internal/logging`），两套落盘点未做 namespace 隔离
2. **替代条件**：要下线 `RawDataLogger`，必须先实现独立的 sync sink（避免与 async 共享文件），否则会出现"切换路径但写入同一文件 → 解析失败"的回归
3. **当前调用方**（需 R11 进一步扫描）：
   - `internal/logging/raw_logger.go` 实现
   - `internal/proxy/...` 与 `internal/storage/lite/...` 中可能仍有调用（需 `grep -r RawDataLogger` 确认）
4. **不修改原因**：
   - 现有 `AsyncRawDataLogger` 已覆盖主要热路径
   - `RawDataLogger` 保留作为**同步落盘降级路径**，避免 async 队列阻塞时丢数据
   - 直接删除会导致运行时 panic（任何残留调用方都会触发 nil 引用）

**R11 候选路径**（仅当未来确实需要）：
- 方案 A：把 `RawDataLogger` 重命名为 `RawDataLoggerSync`，明确语义边界，保留实现
- 方案 B：实现 `RawDataLogger` → `AsyncRawDataLogger` 转发，所有同步调用改成异步（需要重审调用方是否会因异步化改变行为）
- 方案 C：保留现状（推荐 R11 前的默认）
