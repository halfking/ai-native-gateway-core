## FU-1 — `sql/migrations/domain/363_featured_models_standard.sql` (modified)

**Suggested title**: `fix(db): 363 featured-models split UPDATE`

**Body**:

```
Repo: llm-gateway-go
File:  sql/migrations/domain/363_featured_models_standard.sql
Branch: main
Audit context: docs/audit/2026-09-02-minimax-m3-load-balancing-dashboard-audit.md

Background
----------
The original migration tries to set two columns in a single UPDATE statement:
  UPDATE routing_policy
  SET featured_models = (SELECT ARRAY(...)),
      updated_at      = NOW()
  WHERE ...

Postgres rejects the scalar subquery in the same SET list as NOW() with:
  ERROR:  cannot use subquery in same UPDATE SET list as NOW()

Fix
---
Split into two UPDATE statements — first rewrite `featured_models` via the
array subquery, then a second UPDATE stamps `updated_at = NOW()` only when the
featured-models array actually changed. Diff is ~5 lines; behaviour is
identical.

Verification
-------------
Local dev DB (llm-gateway-pg @ 127.0.0.1:5432):
  before: featured_models lacked the 5 standard models on routing_policy.id=1
  after:  featured_models contains them; updated_at reflects last write

Acceptance
----------
- [ ] `psql -v ON_ERROR_STOP=1 -f sql/migrations/domain/363_featured_models_standard.sql` runs clean
- [ ] routing_policy.id=1 has the 5 standard models in featured_models
- [ ] updated_at bumped only when the array actually changed
```

## FU-4 — `scripts/deploy-local.sh` (modified, NOT in handoff §2)

**Suggested title**: `chore(local-dev): make deploy-local.sh self-contained (drop memora log-path coupling)`

**Body**:

```
Repo: llm-gateway-go
File:  scripts/deploy-local.sh
Branch: main

Background
----------
The original `deploy-local.sh` defaults `LOG_DIR` to
`$HOME/Downloads/kaixuan/memora/logs` — a path that only exists when the
`memora` start.sh layout is in place. Anyone running llm-gateway-go in
isolation ends up creating an empty `$HOME/Downloads/kaixuan/memora/logs`
folder they can't easily explain.

Fix
---
Switch the default to `$HOME/.cache/llm-gateway-go/logs` (XDG-style cache).
Operators can still override via `LLM_GATEWAY_LOG_DIR` / `LLM_GATEWAY_LOG_FILE`.

This drift was NOT listed in `docs/handoff/2026-09-02-minimax-m3-loadbalancing-closeout.md`
§2 (the handoff predates this drift). It was introduced by commit 2a5b3e868
(`chore(local-dev): align docker-compose + deploy-local + pg recreate with
canonical operator paths`) and the working-tree residue is the part that
wasn't actually committed.

Acceptance
----------
- [ ] Default `LOG_DIR` is `$HOME/.cache/llm-gateway-go/logs`
- [ ] Default `LOG_FILE` is `$LOG_DIR/llm-gateway-go.log`
- [ ] Override env vars still win
- [ ] `deploy-local.sh deploy` still works on a clean machine
```
