## 三、发现的问题

### F-1（P2，已修）resolveSessionID 反向映射歧义守卫缺失——注释承诺与实现不符
- **位置**：`admin/session_detail_v2.go` resolveSessionID 步骤 2。
- **问题**：注释承诺「只允许唯一解析（命中多行返回 error，禁止把 gw_session_id 隐式覆盖多个会话）」，实现却是子查询 `ORDER BY ts ASC LIMIT 1` 静默取最早请求的会话：① 承诺落空；② 同一 gw_session_id 跨多个会话时查询被悄悄路由到单个会话（跨会话数据混用，正是 §1.6 要防的）；③ 若 primary_request_id 恰非最早请求（首请求失败未建会话等场景）会误判 404。
- **修复**：改为 `SELECT DISTINCT s.session_id … IN (该 gw_session_id 的全部 request_id)`，Go 侧收集候选：恰好 1 个→返回；0 个→404；>1 个→500 显式点名歧义。新增契约测试 `TestSessionDetailV2_AmbiguousGwSessionIDRejected` 钉住。

### F-2（P2，已修）SessionPK 外泄 + 测试断言方向反了
- **位置**：`SessionV2.ID json:"id"` + 契约测试 255-263 行。
- **问题**：同一提交的代码注释、测试头注释均宣称「§1.5 SessionPK 永远不外泄」，但 `json:"id"` 让每个详情响应都带出数值主键；测试只断言「泄漏值必须是正数」——给泄漏背书而非拦截。
- **修复**：`ID` 改 `json:"-"`（Scan 保留、序列化剔除）；消费面核实（web/src 无引用、scripts/test_sessions_v2_api.sh 不读该字段、SessionV2 仅 detail 单文件使用）；测试翻转为断言缺失。

### F-3（P3，已修）ErrNoRows 字符串比较
`err.Error() != "no rows in result set"` ×2 → `errors.Is(err, pgx.ErrNoRows)`；`errSessionNotFound` 由 `fmt.Errorf` 改 `errors.New`。字符串比较在错误被包裹（如超时包装）时会把 miss 误判为 500。

### F-4（P3，已修）测试注释计数错误
`session_detail_v2_test.go` 头注释「期望两次 SQL 调用」实列 3 处 → 改三次。

### F-5（P3，已修）适配器 QueryRow 静默 nil
`sessionListV2Adapter.QueryRow` 在底层池无 QueryRow 方法时返回 nil（调用方 Scan 时空指针 panic 无线索）→ 改显式 panic 并指明缺失契约。
