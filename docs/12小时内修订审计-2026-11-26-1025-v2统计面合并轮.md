## 2. 逐项复核（疑点 → 证据 → 结论）

### 2.1 ✅ 投影与原始行共存同一张表 —— 双写隔离成立

- **疑点**：973 迁移让投影行（`chr(1)` 前缀键）与旧 writer 行共用 `request_metrics`，
  蓝绿过渡期（旧槽写原始键、新槽写投影键）**同一请求会出两行** ⇒ 谁不过滤谁双计。
- **证据**：
  - 旧 writer（`internal/metricsstore/writer.go`）**零生产调用点**——全仓
    `metricsstore.NewWriter` 仅出现在测试与 `.bak`；
    V2 读取面（`domains/metrics/*.go`）全部带 `source_fact_id IS NOT NULL` 或
    `fact_request_id` 过滤；逐读方核对：`query.go` 四个旧查询函数
    （`QuerySummary/QueryDailySummary/QueryProviderSummary/QuerySessionCount`）
    不过滤，但**同样零调用点**（仅 `migration_examples.go` 引用）⇒ 死代码面，无双计入口。
  - `request_metrics` 的其余读方（reconciliation / reportrollup / maas /
    account_activity / session_overview / period_compare）**逐文件核对全部带过滤**。
  - 旧入口 `/api/admin/stats`（`handleStats`）读的是 `stats_usage_daily` rollup，
    其数据源是 `usage_facts`——与投影行无关，无双计。
  - 集成测试 `projection_integration_test.go:140-156` 真库验证：旧 writer 行写入后
    V2 聚合读数不变（legacy=777 / projected=14，两键空间互不污染）。
- **结论**：隔离成立；`query.go` 四个函数是死代码（登记在案，不代删）。
