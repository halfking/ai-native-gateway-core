### 4.1 会话摘要原文回显脱敏收口（0400 轮遗留 #18，P2 隐私面）

**缺陷**：`parseSummaryResponse` 两条错误路径把 LLM 原始响应片段以 `%q` 回显进 error 文本——`starts with %q`（safePrefix(trimmed,20)）与 `extracted: %q`（safePrefix(jsonStr,100)）。`safePrefix` 只是 rune 截断**不脱敏**；worker 把 error 原样 `slog.Warn` 落盘 ⇒ 用户会话衍生内容（0400 轮探针实测 LEAK=true ×2）进生产日志。

**修法**（`domains/sessionsummary/summarizer.go`）：
- 「not look like JSON」路径：`starts with %q` → `prefix_class=%s`（新增 `firstRuneClass`：letter/digit/space/symbol/other **类别**，不回原字符；`describeResponseShape` 的 `first=%q` 单字符回显维持——单字符不足以重构内容，且是既有口径）
- 「unmarshal 失败」路径：`extracted: %q` → `extracted_shape: runes=%d first_key=len=%d`（新增 `extractedFirstKey`：只回键名**长度**，非 ASCII/含控制符/超 128 rune 的键名一律 `-`）
- 删除已无调用方的 `safePrefix`（防再被当作「脱敏」误用——它从来不是）

**防回归钉测**（`domains/sessionsummary/privacy_no_raw_echo_test.go`，4 用例）：
- `TestParseSummaryResponse_NotJSON_NoRawEcho`：含中文姓名 + 密钥样式串的非 JSON 响应 ⇒ error 文本不得含任何原文片段，且形态描述（runes=）必须在场
- `TestParseSummaryResponse_MalformedJSON_NoRawEcho`：`{` 开头但坏 JSON ⇒ extracted 原文不落盘、`extracted_shape` 在场
