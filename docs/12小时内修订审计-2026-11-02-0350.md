### 5.2 4xx 矩阵（本轮改动的核心）

`errorsx/classify_4xx_matrix_test.go` 把 `400..499` 的**每一格**钉成三类之一：

| 类 | 状态码 | 处置 |
|---|---|---|
| `wantByStatus` | 400 / 401 / 402 / 403 / **404** / 408 / 413 / **414** / 422 / 429 | 逐条断言等于登记值 |
| `protocol4xxStatuses` | 405 406 409 411 412 415 416 417 418 421 423 424 425 426 428 431 | 断言 == `KindUnsupportedFeature`（协议/能力族，终态语义不变） |
| `transientAllowlist` | 407 / 410 / 419 / 420 / 427 / 430 + 区段 `432..499` | 断言 == `KindTransient` **且理由非空**（逐条写明为什么不归请求侧） |

**门的三个性质**：

1. **闭集**：`400..499` 里任何既不在三张表内的状态码 ⇒ **门红**（「漏网的兜底」）。
2. **不腐化**：白名单里的状态码若后来被显式裁决了 ⇒ 门红（要求同步删条目并搬理由）。
3. **可执行**：请求侧族额外断言 `IsRetryable == false`（同节点盲重试必须关着）。

**变异臂（证明门有牙，容器内副本执行，活树未动）**：

| 变异 | 结果 |
|---|---|
| M1：把 `414` 从 `case` 里拿掉（模拟漏登记 4xx） | ✅ 门红：`4xx 状态码 414：... = "transient"，want "request_rejected"` |
| M2：把 `ClassifyError` 的 resp 分支改回 `ClassifyResponseStatus`（分叉复活） | ✅ 门红，**逐格**报出 400/405/406/408/409/411/412/413/414/415/416 … `两个分类器对同一状态码分叉了` |

### 5.3 4xx 矩阵的实测读数（改前 → 改后）

| 状态码 | 改前 | 改后 | 理由 |
|---|---|---|---|
| 400 / 413 / 422 | `request_rejected` | `request_rejected` | 并发会话第三轮已收 |
| **404** | `transient`（`IsRetryable=true`） | **`request_rejected`** | 211 生产证据：20 行/6 对/7 事件；`attempt_index` 1→2→3 且相隔 6s/11s ⇒ **同节点盲重试坐实**；三种正文形态全部确定性、绑定级失败，没有一个是节点临时抖动 |
| **414** | `transient`（`IsRetryable=true`） | **`request_rejected`** | 纯粹是「这次请求太长」，与节点健康无关 |
| 407 / 410 / 419 / 420 / 427 / 430 / 432..499 | `transient` | `transient`（**逐条登记理由**） | 无生产证据；410 另有 2026-08-05 日期决议 |

**404 的理由订正（重要）**：本轮初稿曾写「裸 404 的语义二义（既可能是模型不存在，也可能是端点路径错）⇒ 两者都言之成理 ⇒ 保持现状」。**并发会话的 211 生产证据推翻了它**：这两种读法**恰恰都排除 transient**——无论读作「模型不被该凭据提供」还是「端点路径错」，正确处置都在**绑定级**；二义性在于**归到哪个绑定级桶**，不在于**要不要按 transient 处理**。而 transient 恰恰是「节点临时故障」的语义 ⇒ 与实测（确定性、绑定级、盲重试坐实）**直接矛盾**。

**404 归请求侧带来的可观测行为变化（本轮实测到并记录）**：

| 观察点 | 改前 | 改后 | 判读 |
|---|---|---|---|
| 裸 404 的同节点上游调用次数 | 2（generic 梯子） | **1** | ✔ 盲重试消失——正是本轮要断的那一跳 |
| `domains/streaming/executors` 的 `TestExecuteOpenAIReqProbeModeMismatchRecordsWithoutFallback` | 断言 `calls == 2` | 断言 `calls == 1` | ★ 该用例**自己的注释**写着「非流式 responses 客户端不可安全回退 → **不重试**」，而断言却量的是 `calls == 2` ⇒ **注释与断言本就互相矛盾**：那一次从来不是模式回退（模式回退的条件要求 `ClientProtocol != "openai-responses" \|\| IsStream \|\| SuppressSuccessWrite`，本用例三条全不满足），而是 404 落 `KindTransient` ⇒ `IsRetryable=true` ⇒ generic 梯子的同节点重打。现在断言与注释终于一致 |

## 七、通用式（⇒ `LESSONS.md` §613）

- ★★★★ **「修了三个状态码」≠「兜底表有门」**：一张**默认返回最坏值**的表（`ClassifyResponseStatus` 的 `default: KindTransient`）里，每多一个未登记的成员就多一条静默通路 ⇒ **要么把表改成显式闭集，要么给它配矩阵门**（判据：任何「default ⇒ 最坏语义」的表都必须有一道逐格断言的门）。
- ★★★★ **「二义性」与「按什么语义处理」是两个问题**：本轮初稿用「裸 404 语义二义（模型不存在 vs 端点路径错）」为保留 transient 辩护，被 211 的生产证据推翻——两种读法**都排除 transient** ⇒ **二义性只影响归到哪个桶，不影响要不要按 transient 处理**（判据：为某个默认值辩护时，必须给出「这个默认值恰好对应哪一种读法」的正面理由；给不出 ⇒ 辩护不成立）。
- ★★★★ **「同一语义只修了一半」的检测面 = 同一族缺陷的**全部**调用点**：管理面的 NULL 扫描族修完了，热路径检测器的同一族（24 个可空列）原样留着 ⇒ 且后果更重（500 vs **静默失效**）⇒ 判据：修一族缺陷前，先把「同一语义」的全部读端点列出来（`grep` 扫描目标类型，不只扫出错的那些）。
- ★★★ **「终判不变」不等于「行为不变」**：alias 改变了**判空的时点**（提前判空 → `[DONE]` 处判空），终判（failover）没变 ⇒ 代码里写「does not change any empty/non-empty decision」是**假陈述** ⇒ 判据：涉及判据时点/顺序的改动，注释要写「**终判**」与「**时点**」两句。
- ★★★ **部署脚本的「修好了」要按**文档写的调用方式**验收**：`${BASH:-bash}` 继承调用方解释器 ⇒ 但文档写的 `bash scripts/deploy-211.sh` 自己就是 3.2 ⇒ 判据：改解释器/工具入口后，**按文档里那一行**实跑一遍，且失败时要给出**可执行的下一步**（本轮改为 `exit 78` + 指向 `~/sdk/bash5/bin/bash`）。
- ★★ **运维提示里的事实错误比没有提示更贵**：「211 引擎无部署锁」与事实相反 ⇒ 恰好把排查方向带偏（真有一把锁会卡 rc=75）⇒ 判据：提示文案里的每个事实断言都要能在代码里指到出处。
- ★★ **「门有牙」要靠变异臂证明**：本轮两道新门各做一次变异（M1 拿掉 414 / M2 改回旧口径）⇒ 门如期变红 ⇒ 才算落地；否则「门绿」只说明门没跑到。
