# 定价建议模型过滤功能实施文档

**日期**: 2026-11-19  
**需求**: 在定价建议中添加模型选择功能，支持多选模型进行定价  
**目标**: 可以选择一个或多个模型进行定价，也可以不选择对所有模型定价  

## 一、需求背景

在 https://llm.itestu.cn/operations/price-compare 的定价建议功能中，需要增加模型选择能力：

1. 可以选择多个模型（使用现有的 ModelPicker 组件）
2. 可以不选择任何模型（默认对所有模型定价）
3. 吸取跨平台现价中的模型过滤失误教训，明确传递 `canonical_ids` 数组

## 二、技术实现

### 2.1 前端修改

#### 文件：`web/src/views/operations/PricingSuggestionPanel.vue`

**主要变更**：

1. **引入依赖**
   - 添加 `ModelPicker` 组件
   - 引入 `listModels` API 用于获取模型列表

2. **新增状态变量**
   ```typescript
   const selectedModels = ref<string[]>([])  // 选中的模型名称（多选）
   const modelsCanonical = ref<ModelCanonical[]>([])  // 模型规范表
   const modelsLoading = ref(false)
   ```

3. **加载模型规范表**
   ```typescript
   async function loadModelsCanonical() {
     modelsLoading.value = true
     try {
       const res = await listModels({ status: 'active' })
       modelsCanonical.value = res.items || []
     } catch {
       modelsCanonical.value = []
     } finally {
       modelsLoading.value = false
     }
   }
   ```

4. **模型名称到ID的转换**
   ```typescript
   function getCanonicalIds(): number[] {
     if (selectedModels.value.length === 0) {
       return []  // 空数组 = 所有模型（后端默认行为）
     }
     const ids: number[] = []
     const selectedSet = new Set(selectedModels.value.map(m => m.toLowerCase()))
     for (const model of modelsCanonical.value) {
       if (selectedSet.has(model.canonical_name.toLowerCase())) {
         ids.push(model.id)
       }
     }
     return ids
   }
   ```

5. **请求体添加 canonical_ids**
   - 在 `preview()` 函数中添加 `canonical_ids: getCanonicalIds()`
   - 在 `applyAll()` 函数中添加 `canonical_ids: getCanonicalIds()`

6. **UI 组件**
   ```vue
   <div class="card filter-card model-filter-card">
     <div class="model-picker-wrapper">
       <ModelPicker
         v-model="selectedModels"
         mode="multi"
         :placeholder="t('priceCompare.suggestModelPlaceholder')"
         :title="t('priceCompare.suggestModelTitle')"
         compact
       />
     </div>
     <span class="hint-text">{{ t('priceCompare.suggestModelHint') }}</span>
   </div>
   ```

### 2.3 后端支持

后端已经支持 `canonical_ids` 参数（无需修改）：

- **文件**: `maas/pricing_suggestion_data.go`
- **函数**: `pricingSuggestionScope`
- **逻辑**:

  - 如果为空，返回所有有行情的模型

## 三、关键设计点

### 3.1 避免跨平台现价的失误

**问题回顾**：在跨平台现价功能中，模型过滤曾出现问题，导致过滤不准确。

**本次改进**：
1. **明确使用 canonical_ids**：不依赖模糊字符串匹配
2. **精确的 ID 映射**：通过 `listModels` API 获取完整的模型列表
3. **类型安全**：TypeScript 类型检查确保数据结构正确

### 3.2 用户体验设计

1. **默认行为保持不变**：不选择任何模型 = 对所有模型定价
2. **灵活性**：可以选择一个或多个模型
3. **紧凑模式**：使用 `compact` 模式的 ModelPicker，适合工具栏布局
4. **清晰提示**：提供明确的提示文案说明使用方式

### 3.3 数据流

```
用户选择模型
    ↓
selectedModels (模型名称数组)
    ↓
getCanonicalIds() (查询 modelsCanonical)
    ↓
canonical_ids (模型ID数组)
    ↓
POST /api/admin/market/pricing-suggestions
    ↓
后端 pricingSuggestionScope (查询 models_canonical)
    ↓
模型名称列表
    ↓
定价建议计算
```

## 四、测试要点

### 4.1 功能测试

| 场景 | 操作 | 预期结果 |
|------|------|---------|

**请求**: `POST /api/admin/market/pricing-suggestions`

**请求体示例**：
```json
{
  "strategy": "min",
  "platform_id": "",
  "dimension": "standard",
  "markup_pct": undefined,
  "min_delta_pct": 0,
```

1. **空选择** → `canonical_ids: []`
2. **单选** → `canonical_ids: [123]`

## 七、注意事项

1. **模型ID来源**：使用 `listModels({ status: 'active' })` 只获取活跃模型
2. **ID映射**：模型名称大小写不敏感的匹配
3. **空选择语义**：空数组明确表示"所有模型"，而不是"没有模型"
4. **紧凑模式**：ModelPicker 使用 `compact` 模式，显示为"已选 N"而不是展开所有 chips
