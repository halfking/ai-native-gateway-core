## 一、错误修复总结（三轮已完成）

### 1.1 第一轮：builtin.guard.tool_json_invalid 根修（已部署 211）

**错误形态**：
- 现象：211 大量 `builtin.guard.tool_json_invalid` 错误，客户端收到 `output_policy_blocked` 拦断
- 量级：24h 内持续出现，涉及 `/v1/responses` × `claude-sonnet-5` × `MiniMaxCode` 客户端

**根因分析**：
```
anthropic wire 语义（`{}` 占位符）在三处存在：
  ✓ IR 解析器内联注释（有排除逻辑但实现不完整）
  ✓ anthropic→chat 桥（!= "{}" 守卫，正确）
  ✗ anthropic→responses 桥（缺失！直接拼接 ⇒ 产出 `{}{...}` 非法 JSON）
```

**修复方案**（提交 `9381d13a4`）：
- 在 IR 解析器层统一处理：`arguments == "{}"` 时置空（占位符不进参数流）
- 选择解析器层的理由：这是 Anthropic **wire 级语义**，修在源头使全部消费方一致
- 保留非标准中继的真实半截参数形状（`input` 非 `{}`）

**门与验证**：
- 新增事故门：`TestStreamAnthropicSSEToResponses_ToolUse_EmptyInputPlaceholderNotArgs`（4 道断言）
- 变异验证：禁用占位符排除 ⇒ 全红；恢复 ⇒ 全绿
- 211 部署后验证：`tool_json_invalid` 错误归零 ✓

### 1.2 第二轮：context_budget_exceeded 根修（已部署 211）

**错误形态**：
- 现象：ZCode 报错 `input cannot fit the selected bucket budget`，`provider_code=context_budget_exceeded`
- TraceID: `824e8e19-089a-4cb7-8eb0-0597b6f83b2a`，model=`claude-sonnet-5`
- 实证：`actual=76792 limit=72000`，预算门 422 拒绝

**根因分析**：
```
预算计算逻辑缺陷：
  窗口 200k，max_tokens=128k（用户请求）
  预算门算法：inputBudget = window - max_tokens = 72k
  实际 prompt: 76792 tokens ⇒ 超限 ⇒ 422

错误假设：max_tokens 是「输出预留」应从输入预算扣除
正确语义：max_tokens 是输出**上界**，厂商不校验输入（OpenAI）
         或按自己规则校验（Anthropic: prompt ≤ window−max_tokens）
```

**修复方案**（提交 `199c20a00`）：
- `body.max_tokens` 按半窗封顶后并入输出预留（不从输入预算扣除）
- 输入预算 = 窗口 - 系统预留 - clamp(max_tokens, 半窗)
- 保留厂商原生语义差异：网关不替厂商做更严格的校验

**验证**：
- 事故形状（290KB×128k）复测：200 流式返回 ✓
- 判别形状（4KB×199000）：200 正常 ✓
- 211 部署后：`context_budget_exceeded` 错误归零 ✓

## 二、架构深度分析

### 2.1 问题根源：变化点未显式建模

三天三起生产事故的**共同根因**：

```
某一方的特有语义被复制（或漏复制）进通用路径
├─ tool_json_invalid：anthropic `{}` 占位符规则在 3 处内联（1 处缺失）
├─ context_budget：max_tokens 语义按单一假设执法（厂商实际语义不同）
└─ ir.anomaly 879条/35min：thinking/reasoning 字段差异逐字段 if-else
```

**设计违反**：
- **SRP 违反**：同一语义的多份拥有者（anthropic 占位符 × 3 处）
- **OCP 违反**：新厂商接入 = 改核心路径（每接一个新厂商就多一组散落条件）
- **隐式耦合**：厂商/智能体/供应商差异以「通用代码里的特判」形态存在

基于 211 日志复扫（35min / 26,269 行）识别 **6 个关键变化点**：

## 三、Slice 1 落地记录（tooldialect 抽象工厂）

### 3.1 设计：SRP + OCP + 抽象工厂

**核心抽象**（`internal/tooldialect` 新包）：

```go
// Dialect：一种上游 wire 方言的工具参数流语义（SRP：每个方言独占其全部参数流语义）
type Dialect interface {
    Name() string
    StartArguments(raw []byte) string          // ""=占位符
    MergeContinuation(start, buffered) (merged, ok)  // 终态校验
}

// 注册表式抽象工厂（OCP：新厂商 = 注册新方言，核心零改动）
func Register(protocol string, d Dialect)
func ForProtocol(protocol string) Dialect
```

**内置种子方言**：
```go
registry = map[string]Dialect{
    ProtocolAnthropicMessages: NewAnthropic(nil),  // 未装配即正确
}
```

### 3.2 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| **抽象层级** | 叶子包，零外部依赖 | 避免循环依赖；协议键与 `internal/ir` 字符串对齐 + 契约门守护 |
| **未注册协议** | 回落直通方言（中立） | fail-safe 到历史通用路径行为 |
| **种子方言** | 内置 anthropic + `json.Valid` 兜底 | 不经装配的单元测试也拿到占位符语义（事故教训：语义不能靠装配/下游假设） |
| **校验器注入** | `Validator` 函数式注入 | 生产装配覆盖为完整校验器；种子版保守但正确 |

### 3.3 消费方迁移（3 → 1）

```
消费方                              迁移前                          迁移后
────────────────────────────────────────────────────────────────────────────────
internal/ir/stream.go          内联 if arguments == "{}"        tooldialect.ForProtocol().StartArguments()
domains/streaming/              内联 != "{}" 守卫                toolArgsDialect.StartArguments()
  anthropic_bridge.go           直调 ValidateStreamingToolArgs   toolArgsDialect.MergeContinuation()
  (responses 桥缺失 ⇒ 事故)     ← 修复点
```

## 四、架构改进原则与路线图

### 4.1 核心原则

```
1. SRP（单一职责）：每个变化点一个显式抽象（接口），
   实现按「谁拥有语义」归包

2. OCP（开闭原则）：新厂商 = 新实现 + 注册，
   核心解析器/桥/守卫零改动

3. 抽象工厂：跨协议取用走注册表
   （ForProtocol / ForVendorFamily / ForClientFamily）

4. 渐进迁移：不做大爆炸重构，一片一片迁移，
   每片行为保持 + 既有测试全绿 + 新增契约门
```

### 4.2 Slice 2-6 路线图

| Slice | 变化点 | 接口 | 预期收益 |
|-------|--------|------|----------|
| **Slice 2** | reasoning 字段族 | `ReasoningDialect{Project, Restore}` | 消除 879 条/35min anomaly 噪声；语义化投影 |
| **Slice 3** | 供应商命名归一化 | `NormalizationStrategy` 注册表 | 消除 48 条归一歧义；单一权威源 |
