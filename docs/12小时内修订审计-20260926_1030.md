## 三、发现的问题

### P1（已修，本轮落地）：迁移 750 在有数据环境首启阻断 boot

- **提交**：ac007c2f8（R68 审计轮 P1 产物——审计正确发现了 pruning 问题，但修复方案自身带致命缺口）
- **根因**：`ensure_usage_facts_daily_partition` 初版用 `CREATE TABLE IF NOT EXISTS … PARTITION OF`。PG 在「父表挂 DEFAULT 分区」时新建具体分区，会先校验 DEFAULT 内无落入新边界的行；**有则报 `updated partition constraint for default partition would be violated by some row`**。
- **触发面**（数据来源与去处维）：
  1. **存量升级必踩**：252 共享 PG 的 usage_facts DEFAULT 分区持续接收 245/154/dev telemetry；部署新 build 后 `db.Open → ApplyMigrations → ensureUsageFactsDailyPartition`（db/db.go:1281）首次调用即失败 → 进程 no-DB 模式 + 部署自动回滚（db.go:143-146 注释所载行为）。
  2. **tick 路径间歇踩**：跨午夜停机后当日首行先落 DEFAULT，PartitionManager 24h tick 建当日分区同样失败；且该日**永远补不上**（行持续累积，约束校验持续拒绝），pruning 对该日失效。
- **为何前轮实证没拦住**：scratch 空库四通道（创建/共存/EXPLAIN/INSERT 路由）全部**先建分区后插数据**，未覆盖「数据先在 DEFAULT」的时序；真库回归同样在空库跑。
- **修复（move-then-attach，全步骤同事务）**：
  1. `pg_advisory_xact_lock(hashtext(名))` 串行化多入口（boot ensure/installer/升级通道/tick 可能在共享库并发）；
  2. `pg_inherits` 短路（已挂接即返回，锁前快路径 + 锁后复查）；
  3. `CREATE TABLE … (LIKE usage_facts INCLUDING DEFAULTS INCLUDING INDEXES)` 建承接表——fact_id 共享序列默认值随拷，父表 6 个分区索引（PK+537 四索引+749 前导）元数据级匹配，ATTACH 不现场重建索引；
  4. `LOCK TABLE usage_facts_default IN ACCESS EXCLUSIVE MODE` 挡搬移窗口内新写入路由进 DEFAULT（其余分区写不受影响）；
  5. `DELETE … WHERE occurred_at ∈ [start,end) RETURNING → INSERT` 把界内行搬入新表；
  6. `ALTER TABLE … ATTACH PARTITION`。失败整体回滚不留半成品。
- **代价说明**：ATTACH 仍会对 DEFAULT 做一次校验扫描（PG 无法凭空跳过），发生在每日一次的 boot/tick 低峰时点、5min 迁移期 statement_timeout 钉扎内；换 partition pruning 常态收益，值得。
- **改动面**：`sql/migrations/startup/750_usage_facts_daily_partition.sql`（函数重写+头注）、`db/db.go`（注释跟齐）、`db/db_750_ensure_realdb_test.go`（新增 DefaultOverlap 真库回归：3 行先落 DEFAULT→ensure 搬移挂接→DEFAULT 界内清零→父表视角守恒→幂等）、`sql/migrations/startup/migration_750_test.go`（新增 C1-C8 契约：advisory 锁/短路序/LIKE 索引拷贝/AE 锁先于搬移/搬移谓词=ATTACH 边界/禁一键 PARTITION OF 回归/down 只删函数/双通道登记）。
- **可原地修订依据**：750 提交于 09-26 06:20，晚于其的全部 build 记录为 2264（03:22），无部署消费记录；db-changelog 无 750 行（随下次部署登记新 SHA）。
- **验证**：本地 pg17 scratch（容器 ai-native-postgres，一次性库 lgw_750_audit_scratch，用后即删）：
  - `TestEnsureUsageFactsDailyPartition_RealDB` PASS（空库创建/幂等/盖章）
  - `TestEnsureUsageFactsDailyPartition_DefaultOverlap_RealDB` PASS（**P1 场景**）
  - `TestEnsureUsageFactsOccurredAtIndex_RealDB` PASS（749 在同库先应用，验证父表 6 索引全齐的生产形态下 LIKE 拷贝+ATTACH 匹配）

### 观察项（不修，记录在案）

- **O-1（da6b95627）**：Set 重构后 lite 路径 L1 写移出 B4 分片锁。核实结论：Set 写调用方新鲜状态，Invalidate 竞态交错结果=last-write-wins（新鲜态存活），与 Get 回填旧态的 B4 原命题不同，非缺陷；H2 装配点启用时如需「两层原子可见」再评估。
- **O-2（282ebf42a）**：mkdir 锁的 stale 接管存在极窄 TOCTOU（双 waiter 同时判 stale→一方 rm 掉另一方新锁）。触发需 60s 阈值+0.1s 内交错，后果=回到无防护旧行为（fail-open 设计已兜底），不改。
- **O-3（19eb31536）**：429 周期记忆是 worker 级全局粒度（非 per-credential）。若 429 来自某上游自身限流（非系统 key），下一周期压制其他凭据的 fallback 候选略保守——仅压制一个周期且自动清零，可接受。
