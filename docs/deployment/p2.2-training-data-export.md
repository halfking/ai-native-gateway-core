## 1. 概述

P2.2训练数据导出管道从`auto_route_selections`表导出结构化特征+标签，生成ML训练数据集（Parquet格式）。

### 核心能力

- ✅ **隐私合规**: 只导出15个结构化特征字段，不导出prompt/messages/response
- ✅ **质量过滤**: 支持置信度、reward、profile等多维度过滤
- ✅ **自动去重**: 基于content_hash或request_id去重
- ✅ **高效存储**: Parquet列式格式，Snappy压缩，节省存储和加载时间
- ✅ **可追溯**: 完整的导出执行记录和审计日志

### 架构图

```
┌─────────────────────────┐
│ auto_route_selections   │ (原始数据，只读15个特征字段)
└───────────┬─────────────┘
            │
            ↓ (CLI命令触发)
┌─────────────────────────┐
│ TrainingExporter        │ (exporter/training_exporter.go)
│  - queryRecords()       │ (PRIVACY: 白名单字段)
│  - filterRecords()      │ (质量过滤)
│  - dedupRecords()       │ (去重)
│  - writeParquetFile()   │ (写入Parquet)
└───────────┬─────────────┘
            │
            ↓
┌─────────────────────────────────────┐
│ training_export_configs (配置表)    │
│ training_exports (执行记录表)       │
└───────────┬─────────────────────────┘
            │
            ↓
┌──────────────────────────────────────┐
│ /data/exports/*.parquet (导出文件)   │
│ 或 s3://bucket/exports/*.parquet     │
└──────────────────────────────────────┘
```

## 2. 部署步骤

### 2.1 数据库Migration

Migration 663会在gateway启动时自动执行，无需手动操作。

验证migration已执行：

```bash
psql $DATABASE_URL -c "SELECT * FROM training_export_configs LIMIT 1;"
psql $DATABASE_URL -c "SELECT * FROM training_exports LIMIT 1;"
```

预期输出：应该能看到3个预定义的导出配置（balanced-high-quality-v1, all-data-v1, low-confidence-v1）。

### 2.2 编译CLI工具

```bash
cd /path/to/llm-gateway-go-5

# 编译llm-gw-exporter CLI
go build -o bin/llm-gw-exporter ./cmd/llm-gw-exporter

# 验证编译成功
./bin/llm-gw-exporter --help
```

### 2.3 配置环境变量

```bash
# 数据库连接字符串（必需）
export DATABASE_URL="postgresql://user:pass@localhost:5432/llm_gateway?sslmode=require"

# 可选：导出目录
export EXPORT_DIR="/data/exports"
mkdir -p $EXPORT_DIR
```

### 2.4 部署到生产环境

#### 方式1: 独立部署（推荐）

将CLI工具部署到独立的导出服务器或定时任务机器：

```bash
# 1. 复制二进制文件
scp bin/llm-gw-exporter export-server:/usr/local/bin/

# 2. 配置环境变量（在export-server上）
cat > /etc/llm-gw-exporter/config.env <<EOF
DATABASE_URL=postgresql://user:pass@db-host:5432/llm_gateway?sslmode=require
EXPORT_DIR=/data/exports
EOF

# 3. 设置定时任务（可选，每天凌晨2点导出）
crontab -e
# 添加：
# 0 2 * * * source /etc/llm-gw-exporter/config.env && /usr/local/bin/llm-gw-exporter export --config balanced-high-quality-v1 --output $EXPORT_DIR/$(date +\%Y-\%m-\%d)-v1.parquet >> /var/log/llm-gw-exporter.log 2>&1
```

#### 方式2: 与Gateway共同部署

如果导出频率较低，可以在gateway服务器上手动执行：

```bash
cd /path/to/llm-gateway-go-5
./bin/llm-gw-exporter export --config balanced-high-quality-v1 --output /data/exports/2026-09-06-v1.parquet
```

## 4. 导出配置管理

### 4.1 预定义配置

Migration 663已创建3个预定义配置：

| 配置名称 | 用途 | 过滤条件 |
|---------|------|---------|
| `balanced-high-quality-v1` | ML模型训练 | 置信度≥0.7，已结算，reward≥0.5，只包含balanced profile |
| `all-data-v1` | 数据分析和探索 | 无过滤 |
| `low-confidence-v1` | 人工标注优先级排序 | 置信度<0.7 |

### 4.2 创建自定义配置

直接插入数据库：

```sql
INSERT INTO training_export_configs (
  name, 
  description, 
  feature_version, 
  time_range_start, 
  time_range_end, 
  quality_filters, 
  dedup_strategy
) VALUES (
  'custom-experiment-2026-09',
  '自定义实验配置：高复杂度任务，置信度>0.8',
  'v1',
  '2026-09-01',
  '2026-09-30',
  '{
    "min_confidence": 0.8,
    "require_settled": true,
    "min_reward": 0.6,
    "complexity_bucket": "complex"
  }'::jsonb,
  'content_hash'
);
```

### 4.3 质量过滤选项

`quality_filters` JSONB字段支持以下选项：

```json
{
  "min_confidence": 0.7,          // 最低置信度（0.0-1.0）
  "max_confidence": 0.9,          // 最高置信度（用于筛选低置信度样本）
  "exclude_explore": true,        // 排除探索模式（classifier="explore_*"）
  "require_settled": true,        // 只导出已结算的行（reward不为null）
  "min_reward": 0.5,              // 最低reward（需要require_settled=true）
  "max_reward": 0.95,             // 最高reward
  "allowed_task_types": ["chat"], // 只导出特定task_type
  "allowed_profiles": ["balanced", "quality"] // 只导出特定profile
}
```

### 4.4 去重策略

`dedup_strategy` 字段支持：

- `content_hash`: 基于content_hash去重（**推荐**，去除完全重复的请求）
- `request_id`: 基于request_id去重（通常不需要，因为request_id本身唯一）
- `none`: 不去重（**谨慎使用**，可能导致训练数据偏差）

### 5.2 关键指标

- **成功率**: `completed_count / export_count > 0.95`（至少95%成功）
- **平均耗时**: `avg_duration_seconds < 180`（100万行应在3分钟内完成）
- **数据量增长**: 监控`total_rows_exported`是否符合预期增长趋势

### 5.3 告警规则（Prometheus/Alertmanager）

```yaml
# 添加到prometheus/alerts/training_export.yml

groups:
  - name: training_export
    interval: 5m
    rules:
      - alert: TrainingExportHighFailureRate
        expr: |
          (
            sum(rate(training_exports{status="failed"}[1h])) 
            / 
            sum(rate(training_exports[1h]))
          ) > 0.1
        for: 30m
        labels:
          severity: warning
        annotations:
          summary: "Training export failure rate > 10%"
          description: "{{ $value | humanizePercentage }} of exports failed in the last hour"

      - alert: TrainingExportSlowExecution
        expr: |
          avg(training_exports_duration_seconds) > 300
        for: 1h
        labels:
          severity: warning
        annotations:
          summary: "Training exports are slow"
          description: "Average export duration is {{ $value | humanizeDuration }}"

      - alert: TrainingExportNoRecentExports
        expr: |
          time() - max(training_exports_created_at) > 86400 * 2
        labels:
          severity: warning
        annotations:
          summary: "No training exports in 2 days"
          description: "Last export was {{ $value | humanizeDuration }} ago"
```

## 6. 故障排查

### 6.1 导出失败

**症状**: `llm-gw-exporter export` 返回错误。

**排查步骤**:

1. **检查数据库连接**:
   ```bash
   psql $DATABASE_URL -c "SELECT 1;"
   ```

2. **检查配置是否存在**:
   ```bash
   llm-gw-exporter configs | grep <config-name>
   ```

3. **检查数据范围**:
   ```sql
   SELECT COUNT(*), MIN(ts), MAX(ts)
   FROM auto_route_selections
   WHERE feature_version = 'v1'
     AND DATE(ts) >= '2026-08-01'
     AND DATE(ts) <= '2026-09-01';
   ```
   如果COUNT=0，说明时间范围内没有数据，调整配置的`time_range_start/end`。

4. **检查导出记录错误信息**:
   ```sql
   SELECT id, status, error_message, created_at
   FROM training_exports
   WHERE status = 'failed'
   ORDER BY created_at DESC
   LIMIT 5;
   ```

### 6.2 导出文件为空

**症状**: 导出成功但`row_count_deduped = 0`。

**原因**: 质量过滤条件过于严格，导致所有数据被过滤。

**解决方案**:

1. **检查过滤条件**:
   ```sql
   SELECT quality_filters
   FROM training_export_configs
   WHERE name = '<config-name>';
   ```

2. **放宽过滤条件**，例如降低`min_confidence`或移除`require_settled`。

3. **验证原始数据量**:
   ```sql
   SELECT COUNT(*)
   FROM auto_route_selections
   WHERE feature_version = 'v1'
     AND confidence >= 0.7  -- 你的min_confidence
     AND reward IS NOT NULL; -- 如果require_settled=true
   ```

### 6.3 导出速度慢

**症状**: 100万行导出超过5分钟。

**原因**: 数据库查询慢或磁盘IO慢。

**解决方案**:

1. **检查数据库索引**:
   ```sql
   -- 应该存在这些索引（由Migration 658创建）
   SELECT indexname FROM pg_indexes 
   WHERE tablename = 'auto_route_selections'
     AND indexname LIKE '%feature_version%';
   ```

2. **优化查询**（已在代码中优化，无需修改）:
   - 查询使用`DATE(ts) >= ... AND DATE(ts) <= ...`过滤
   - 只查询25个字段，不查询JSONB或TEXT大字段

3. **使用SSD存储**（如果导出到本地文件）。

### 6.4 隐私验证失败

**症状**: `llm-gw-exporter validate` 报告包含禁止字段。

**这是严重的隐私违规！立即停止使用该文件。**

**排查步骤**:

1. **检查代码版本**:
   ```bash
   git log --oneline -1 exporter/training_exporter.go
   # 应该是commit c1fd9f4c9或更新版本
   ```

2. **重新编译CLI**:
   ```bash
   go build -o bin/llm-gw-exporter ./cmd/llm-gw-exporter
   ```

3. **重新导出**并验证:
   ```bash
   llm-gw-exporter export --config <config-name> --output /tmp/test.parquet
   llm-gw-exporter validate /tmp/test.parquet
   ```

4. **如果仍然失败，联系开发团队**并提供：
   - 导出配置ID
   - validate命令输出
   - exporter版本号

## 7. 性能基准

### 7.1 预期性能

| 数据量 | 导出时间 | 文件大小 | 压缩比 |
|--------|---------|---------|--------|
| 10万行 | ~10秒 | 12 MB | ~8:1 |
| 100万行 | ~90秒 | 120 MB | ~8:1 |
| 1000万行 | ~15分钟 | 1.2 GB | ~8:1 |

**测试环境**: AWS RDS PostgreSQL (db.r5.xlarge), 4 vCPU, 32GB RAM, gp3 SSD。

### 7.2 性能调优

1. **并行度**: Parquet writer使用4个goroutine并行写入（hardcoded）。
2. **压缩**: Snappy压缩平衡了速度和压缩比，适合大批量导出。
3. **批量查询**: 使用单次查询获取所有数据，避免多次往返。

## 8. 安全和隐私

### 8.1 隐私保证

✅ **代码层面**:
- `queryRecords()` SQL查询白名单：只访问25个字段（15个特征+10个元数据/标签）
- `TrainingDataRecord` 结构体：编译时类型安全，无法添加敏感字段
- `ProhibitedFields()` 黑名单：9个禁止字段（prompt, messages, response等）

✅ **测试层面**:
- `TestTrainingExporterNoContentLeakage`: 集成测试，验证导出文件不包含敏感字段
- `TestParquetSchemaNoProhibitedFields`: 单元测试，验证schema定义合规
- `TestTrainingExporterQueryWhitelist`: 单元测试，验证SQL查询白名单

✅ **运维层面**:
- `llm-gw-exporter validate` 命令：每次导出后验证文件隐私合规
- 审计日志：所有导出记录在`training_exports`表，包含操作人员和时间

### 8.2 访问控制

- **数据库权限**: 导出服务只需要`auto_route_selections`的`SELECT`权限和`training_export_*`表的`INSERT/UPDATE`权限。
- **文件权限**: 导出文件应设置为`chmod 600`（只有owner可读写）。
- **S3权限**: 如果导出到S3，使用IAM角色限制访问（只允许ML训练账户读取）。

### 8.3 审计追踪

所有导出操作记录在`training_exports`表：

```sql
SELECT 
  e.id,
  c.name AS config_name,
  e.output_path,
  e.row_count_deduped,
  e.triggered_by,
  e.created_at
FROM training_exports e
JOIN training_export_configs c ON c.id = e.config_id
WHERE e.status = 'completed'
ORDER BY e.created_at DESC
LIMIT 20;
```

## 10. 常见问题（FAQ）

### Q1: 导出文件可以包含多少行？

A: 理论上无限制。实际测试过1000万行（~1.2GB），导出时间约15分钟。Parquet格式支持数十亿行。

### Q2: 可以增量导出吗（只导出新数据）？

A: 可以。创建新配置，设置`time_range_start`为上次导出的结束日期：

```sql
INSERT INTO training_export_configs (name, feature_version, time_range_start, time_range_end, ...)
VALUES ('incremental-2026-09-07', 'v1', '2026-09-07', '2026-09-08', ...);
```

### Q3: 导出会影响生产数据库性能吗？

A: 影响极小。导出是只读查询，使用索引，且通常在低峰时段（凌晨）执行。建议在从库（read replica）上执行导出。

### Q4: 如何导出到S3？

A: 目前需要先导出到本地，再上传到S3：

```bash
llm-gw-exporter export --config <config-name> --output /tmp/export.parquet
aws s3 cp /tmp/export.parquet s3://bucket/exports/2026-09-06.parquet
rm /tmp/export.parquet
```

后续可以实现S3直接写入（使用`s3.PutObject` API）。

### Q5: 导出的Parquet文件如何使用？

A: 可以用多种工具读取：

**Python (pandas)**:
```python
import pandas as pd
df = pd.read_parquet('/data/exports/2026-09-06-v1.parquet')
print(df.head())
```

**Python (pyarrow)**:
```python
import pyarrow.parquet as pq
table = pq.read_table('/data/exports/2026-09-06-v1.parquet')
df = table.to_pandas()
```

**Spark**:
```scala
val df = spark.read.parquet("/data/exports/2026-09-06-v1.parquet")
df.show()
```

**DuckDB**:
```sql
SELECT COUNT(*), chosen_model
FROM parquet_scan('/data/exports/2026-09-06-v1.parquet')
GROUP BY chosen_model;
```
