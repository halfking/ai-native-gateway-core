1. **数据流验证**: 确认 `routing_feedback_log` 正确记录优化器决策
2. **性能基准**: 测量插件对 P95 延迟和 DB 连接数的影响
3. **错误监控**: 检测生产路径中的异常和降级行为

## 📈 **观察重点（Week 5-7: Staging 阶段）**

### **1. 性能指标**

| 指标 | 基线（无优化器） | 目标（P2.2） | 测量方法 |
|------|-----------------|-------------|----------|
| P95 请求延迟 | 150ms | ≤158ms (+5%) | Prometheus `http_request_duration_ms{quantile="0.95"}` |
| DB 连接数 | 20 | ≤22 (+10%) | `SELECT count(*) FROM pg_stat_activity WHERE application_name='gateway'` |
| PreClassify P99 | N/A | ≤5ms | 日志聚合 `grep "PreClassify.*ms" | awk '{print $5}' | sort -n` |
| RecommendModel P99 | N/A | ≤3ms | 日志聚合 `grep "RecommendModel.*ms" | awk '{print $5}' | sort -n` |

### **2. 数据流质量**

```sql
-- 每小时反馈记录数（应约等于 AUTO 请求数 × 10%）
SELECT 
  DATE_TRUNC('hour', created_at) AS hour,
  COUNT(*) AS feedback_records,
  COUNT(DISTINCT user_id) AS active_users
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY hour
ORDER BY hour DESC;

-- 任务类型分布（验证 Classifier 输出合理性）
SELECT 
  classified_task_type,
  COUNT(*) AS count,
  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY classified_task_type
ORDER BY count DESC;

-- 推荐一致性（推荐 vs 实际，探索率应约 5%）
SELECT 
  CASE 
    WHEN recommended_provider = actual_provider THEN 'exploit'
    ELSE 'explore'
  END AS decision_type,
  COUNT(*) AS count
FROM routing_feedback_log
WHERE optimization_source = 'recommender'
  AND created_at > NOW() - INTERVAL '24 hours'
GROUP BY decision_type;
```

### **3. 错误监控**

```bash
# 检查优化器相关错误
grep -i "error\|panic\|timeout" /var/log/gateway/p2.2-staging.log | grep -i "routingopt\|optimizer"

# 常见错误签名:
# ❌ "PreClassify timeout exceeded 10ms" → 增加 MAX_PLUGIN_LATENCY_MS 或优化查询
# ❌ "DB connection pool exhausted" → 检查 user_task_affinity 查询是否泄漏连接
# ❌ "RecordFeedback insert failed" → 检查 routing_feedback_log 表约束
# ✅ "Optimizer degraded to baseline" → 预期行为（超时时降级）
```

## 🔧 **已知限制与 Week 2-3 改进计划**

### **当前限制（Week 1 实现）**

1. **用户亲和度未消费**: `LoadUserAffinity=false`，PreClassify 查询结果不影响分类
   - **影响**: 用户历史偏好不生效，当前仅测试查询性能
   - **修复**: Week 2 实现 `routingopt.Classifier` 扩展字段接入

2. **同步反馈写入**: 每请求一次 `INSERT INTO routing_feedback_log`
   - **影响**: 10% 流量下可承受，100% 时可能成为瓶颈
   - **修复**: Week 3 实现异步批量写入（内存队列 + 5s 批量刷盘）

3. **无 Redis 缓存**: 用户亲和度每次查询 DB
   - **影响**: 高频用户重复查询，增加 DB 负载
   - **修复**: Week 3 实现 Redis 缓存（TTL 1h 任务分布 + 6h provider 偏好）

### **Week 2-3 改进 Roadmap**

| 任务 | 优先级 | 预期收益 |
|------|-------|---------|
| Redis 亲和度缓存 | P0 | DB 查询减少 80%，PreClassify P99 ≤1ms |
| 异步批量反馈写入 | P0 | INSERT 延迟从同步 5ms → 异步 <0.1ms |
| Classifier 增强字段接入 | P1 | 用户亲和度生效，分类准确率 +5% |
| Grafana 仪表盘 | P2 | 实时观察指标，减少手动 SQL 查询 |

## 🎯 **Week 5-7 成功标准**

在进入 Week 8（生产 100% 流量）前，必须验证：

- ✅ **无 P0 错误**: 日志中无 routingopt 相关 panic 或持续错误

- ✅ **数据质量**: `routing_feedback_log` 记录完整，无缺失字段

## 📞 **故障排查**

### **问题: routing_feedback_log 无数据**

```bash
# 1. 检查优化器是否启用
grep "Optimizer injected" /var/log/gateway/p2.2-staging.log

# 2. 检查 A/B 测试是否命中（可能需要发送更多请求）
# 10% 命中率 → 100 请求应有 ~10 条记录

# 3. 检查数据库连接
psql -h staging-db-host -U gateway_user -d gateway_db -c "\dt routing_feedback_log"

# 4. 检查 RecordFeedback 错误
grep "RecordFeedback" /var/log/gateway/p2.2-staging.log | grep -i error
```

### **问题: P95 延迟显著增加（>10%）**

```bash
# 1. 测量 PreClassify 耗时分布
grep "PreClassify.*ms" /var/log/gateway/p2.2-staging.log | \
  awk '{print $(NF-1)}' | sort -n | tail -n 100

# 2. 检查 DB 连接池状态
psql -h staging-db-host -U gateway_user -d gateway_db -c "
  SELECT state, count(*) FROM pg_stat_activity 
  WHERE application_name='gateway' 
  GROUP BY state;
"

# 3. 临时禁用优化器（紧急降级）
export ROUTING_OPT_ENABLED=false
# 重启服务，确认延迟恢复
```
