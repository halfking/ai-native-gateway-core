**版本**: v1.0  
**生成时间**: 2026-09-07  
**目标**: Staging 环境 10% A/B 测试，验证优化器数据流与性能影响

---

## 📊 **部署目标**

1. **数据流验证**: 确认 `routing_feedback_log` 正确记录优化器决策
2. **性能基准**: 测量插件对 P95 延迟和 DB 连接数的影响
3. **错误监控**: 检测生产路径中的异常和降级行为
4. **人工标注准备**: 验证反馈数据质量，为 Week 2 人工标注提供数据源

```bash
# 查询 routing_feedback_log 表，确认有数据写入
psql -h staging-db-host -U gateway_user -d gateway_db -c "
  SELECT
    COUNT(*) AS total_records,
    COUNT(DISTINCT user_id) AS unique_users,
    COUNT(DISTINCT task_type) AS task_types,
    COUNT(*) FILTER (WHERE success) AS success_records
  FROM routing_feedback_log
  WHERE created_at > NOW() - INTERVAL '5 minutes';
"

# 预期输出:
# total_records ≈ AUTO 路由决策数（反馈记录所有被路由的决策；

#   异步批量写入按 100 条或 5s 刷盘 —— 计数前至少等待 5 秒。
# task_types: 包含 'reasoning', 'translation', 'creative_writing' 等
```

#### **4.3 验证 RecommendModel Hook**

```bash
# 查询 routing_feedback_log 中的推荐分布（表内无 optimization_source 列，
# A/B 门控观察走 Prometheus 指标：llmgw_routingopt_exploration_requests_total）
psql -h staging-db-host -U gateway_user -d gateway_db -c "
  SELECT
    predicted_provider,
    COUNT(*) AS count,
    ROUND(AVG(confidence)::numeric, 3) AS avg_confidence,
    ROUND(100.0 * COUNT(*) FILTER (WHERE success) / COUNT(*), 1) AS success_pct

  WHERE created_at > NOW() - INTERVAL '1 hour'
  GROUP BY predicted_provider
  ORDER BY count DESC;
"

# 预期输出:
# confidence 在 [0, 1] 区间；探索份额（ε-greedy 5%）看
# llmgw_routingopt_exploration_requests_total 增速是否 ≈ 总决策数 × 5%
```

## 📈 **观察重点（Week 5-7: Staging 阶段）**

### **1. 性能指标**

| 指标 | 基线（无优化器） | 目标（P2.2） | 测量方法 |
|------|-----------------|-------------|----------|
| P95 请求延迟 | 150ms | ≤158ms (+5%) | Prometheus `http_request_duration_ms{quantile="0.95"}` |
| DB 连接数 | 20 | ≤22 (+10%) | `SELECT count(*) FROM pg_stat_activity WHERE application_name='gateway'` |
| PreClassify P99 | N/A | ≤5ms | `/metrics` 直方图 `llmgw_routingopt_preclassify_ms`（10ms 处有目标刻度桶） |
| RecommendModel P99 | N/A | ≤3ms | `/metrics` 直方图 `llmgw_routingopt_recommend_ms`（10ms 处有目标刻度桶） |

### **2. 数据流质量**

```sql
-- 每小时反馈记录数（≈ AUTO 路由决策数；A/B 门控不减少记录行数）
SELECT 
  DATE_TRUNC('hour', created_at) AS hour,
  COUNT(*) AS feedback_records,
  COUNT(DISTINCT user_id) AS active_users
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY hour
ORDER BY hour DESC;

-- 任务类型分布（验证 Classifier 输出合理性）
SELECT 
  task_type,
  COUNT(*) AS count,
  ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY task_type
ORDER BY count DESC;

-- 预测质量（表内无 actual_provider 列；人工纠正后可比对
-- predicted_provider 与 ground truth correct_provider，与 Admin API
-- /api/admin/routing-opt/accuracy 的口径一致）
SELECT 
  task_type,
  COUNT(*) FILTER (WHERE has_human_correction) AS human_corrected,
  COUNT(*) FILTER (WHERE has_human_correction 
                     AND predicted_provider = correct_provider) AS human_agree,
  ROUND(100.0 * COUNT(*) FILTER (WHERE success) / COUNT(*), 1) AS success_pct
FROM routing_feedback_log
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY task_type
ORDER BY count DESC;
```

### **3. 错误监控**

```bash
# 检查优化器相关错误
grep -i "error\|panic\|timeout" /var/log/gateway/p2.2-staging.log | grep -i "routingopt\|optimizer"

# 常见错误签名（真实 slog 文案）:
# ❌ "optimizer.RecommendModel failed, keeping index order" → 推荐器报错，已保序降级
# ❌ "optimizer.RecordFeedback failed" → 反馈写入失败，检查 routing_feedback_log 表约束/连接
# ❌ "DB connection pool exhausted" → 检查 routing_user_affinity 查询是否泄漏连接
# ❌ "routingopt: batch feedback insert failed" → 批量刷盘失败，看 llmgw_routingopt_feedback_writes_total{result="error"}
# ❌ "routingopt: adaptive pass failed" / "routingopt: routing anomaly" → 自适应回路异常
# ✅ 插件超时不打日志 —— Hook 超时静默降级 baseline，观察 llmgw_routingopt_*_ms 直方图尾部
```

## 🔧 **已知限制与当前状态（2026-09-07 审计后更新）**

1. **用户亲和度未消费**: `LoadUserAffinity=false`，PreClassify 查询结果不影响分类
   - **影响**: 用户历史偏好不生效，当前仅测试查询性能
   - **修复**: Week 2 实现 `routingopt.Classifier` 增强 `EnhancedSignals` 字段接入
   - **说明**: Track A 的 Redis 亲和度缓存已接线并计数，但读路径在上述接入落地前保持休眠（`options.go` 中记录的 Week-2 门控决策）

2. **异步批量反馈写入（Track B，已实现）**: 内存队列 10 000 条，满 100 条或 5s 定时刷盘，`pgx.Batch` 单往返写入；队列满丢弃并计入 `llmgw_routingopt_feedback_writes_total{result="dropped"}`。回退开关 `Options.ControlledSyncFallback` 保持默认关闭

3. **Redis 亲和度缓存（Track A，已实现）**: TTL 1h（正）/ 30s（DB miss 负缓存），写后失效；由 `ROUTING_OPT_AFFINITY_CACHE=true` 装配启用（默认关闭，Redis 客户端不可用时自动跳过）

## 📞 **故障排查**

### **问题: routing_feedback_log 无数据**

```bash
# 1. 检查优化器是否启用
grep "routing optimizer enabled" /var/log/gateway/p2.2-staging.log

# 2. 确认等待了批量刷盘窗口（≥5s）后计数；
#    反馈记录所有 AUTO 路由决策（A/B 门控只影响推荐，不减少行数）

# 3. 检查数据库连接
psql -h staging-db-host -U gateway_user -d gateway_db -c "\dt routing_feedback_log"

# 4. 检查反馈写入错误（日志 + 指标）
grep "RecordFeedback failed\|batch feedback insert failed" /var/log/gateway/p2.2-staging.log
curl -s http://localhost:8080/metrics | grep 'feedback_writes_total{result="error"'
```

### **问题: P95 延迟显著增加（>10%）**

```bash
# 1. 测量 PreClassify 耗时分布（Prometheus 直方图，无逐请求日志）
curl -s http://localhost:8080/metrics | grep "llmgw_routingopt_preclassify_ms"

# 2. 检查 DB 连接池状态
psql -h staging-db-host -U gateway_user -d gateway_db -c "
  SELECT state, count(*) FROM pg_stat_activity 
  WHERE application_name='gateway' 
  GROUP BY state;
"

# 3. 临时禁用优化器（紧急降级）
export ROUTING_OPT_ENABLED=false
# 重启服务，确认延迟恢复
```
