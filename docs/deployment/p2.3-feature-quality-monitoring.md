# P2.3 Feature Quality Monitoring - Deployment Guide

**实施日期**: 2026-09-06  
**任务**: P2.3 - Monitor Feature Distribution and Deduplication Rate  
**优先级**: 高（无依赖，快速见效）

## 概述

P2.3监控系统为AUTO路由的ML训练数据质量提供实时可观测性，检测特征分布异常、去重率下降和特征提取失败等问题。

### 核心能力

1. **特征分布统计**: 每小时计算7个结构化特征的分布（语言、长度桶、复杂度等）
2. **去重率监控**: 基于content_hash检测重复请求，识别数据质量问题
3. **异常检测**: 自动告警特征集中（>90%）、低去重率（<50%）、高缺失率（>20%）
4. **可视化**: Grafana dashboard提供4个核心指标panel + 4个统计卡片

### 隐私保证

✅ **只访问结构化特征字段**（detected_language, prompt_length_bucket等）  
✅ **不查询prompt/messages/response或任何可逆内容**  
✅ **统计表只存储聚合计数**，不存储原始数据  
✅ **8个隐私测试覆盖**，CI自动验证

## 组件清单

### 1. 数据库 (Migration 662)
- **文件**: `sql/migrations/startup/662_feature_distribution_stats.sql`
- **内容**:
  - `feature_distribution_stats` 表：特征分布统计
  - `dedup_stats` 表：去重率统计
  - `feature_quality_metrics` 视图：特征填充率聚合

### 2. 后台Worker
- **文件**: `bg/feature_stats_worker.go`
- **功能**: 每小时计算统计并检测异常
- **测试**: `bg/feature_stats_worker_test.go` (3个测试用例)

### 3. Grafana Dashboard
- **文件**: `monitoring/grafana/dashboards/auto-route-feature-quality.json`
- **Panel清单**:
  1. Language Distribution (饼图)
  2. Prompt Length Bucket Distribution (柱状图)
  3. Deduplication Rate Trend (时序图，30天)
  4. Feature Fill Rate (表格，按填充率排序)
  5. Today's Dedup Rate (仪表盘)
  6. Total Samples (统计卡片)
  7. Unique Samples (统计卡片)
  8. Duplicate Samples (统计卡片)

### 4. Prometheus告警
- **文件**: `monitoring/prometheus/alerts/auto_route_feature_quality.yml`
- **规则清单**:
  1. `FeatureConcentration`: 特征值占比 >90%
  2. `HighDuplicationRate`: 去重率 >50%
  3. `LowFeatureFillRate`: 填充率 <80%
  4. `FeatureStatsWorkerDown`: Worker超过2小时未运行
  5. `FeatureExtractionFailureSpike`: NULL值突增（>2x 7天平均）
  6. `LanguageDistributionShift`: 语言分布偏移 >20%

## 部署步骤

### Step 1: 应用数据库Migration

```bash
# 方式1: 通过gateway启动自动应用（推荐）
./llm-gateway

# 方式2: 手动应用（生产环境）
psql -h <db_host> -U <db_user> -d llm_gateway < sql/migrations/startup/662_feature_distribution_stats.sql
```

**验证**:
```sql
-- 检查表是否创建
SELECT tablename FROM pg_tables WHERE tablename IN ('feature_distribution_stats', 'dedup_stats');

-- 检查视图是否创建
SELECT viewname FROM pg_views WHERE viewname = 'feature_quality_metrics';
```

### Step 2: 重启Gateway服务

Worker已集成到 `cmd/gateway/main.go`，重启后自动启动。

```bash
# 停止旧进程
pkill -f llm-gateway

# 启动新进程
./llm-gateway

# 验证worker启动日志
tail -f logs/gateway.log | grep "feature stats worker started"
```

**预期输出**:
```
2026-09-06T10:00:00Z INFO feature stats worker started interval=1h
```

### Step 3: 导入Grafana Dashboard

```bash
# 方式1: 通过Grafana UI导入
# 1. 登录Grafana → Dashboards → Import
# 2. 上传 monitoring/grafana/dashboards/auto-route-feature-quality.json
# 3. 选择PostgreSQL数据源
# 4. 点击Import

# 方式2: 通过API导入（自动化）
curl -X POST http://grafana.example.com/api/dashboards/db \
  -H "Authorization: Bearer <grafana_api_token>" \
  -H "Content-Type: application/json" \
  -d @monitoring/grafana/dashboards/auto-route-feature-quality.json
```

**验证**: 访问 `https://grafana.example.com/d/auto-route-feature-quality`

### Step 4: 配置Prometheus告警

```bash
# 1. 复制告警规则到Prometheus配置目录
cp monitoring/prometheus/alerts/auto_route_feature_quality.yml \
   /etc/prometheus/alerts/

# 2. 编辑prometheus.yml，添加规则文件
cat >> /etc/prometheus/prometheus.yml <<EOF
rule_files:
  - "alerts/auto_route_feature_quality.yml"
EOF

# 3. 重载Prometheus配置
curl -X POST http://prometheus.example.com:9090/-/reload
```

**验证**:
```bash
# 检查规则是否加载
curl http://prometheus.example.com:9090/api/v1/rules | jq '.data.groups[] | select(.name=="auto_route_feature_quality")'
```

## 监控与维护

### 关键指标

| 指标 | 正常范围 | 告警阈值 | 说明 |
|------|---------|---------|------|
| **去重率** | 10-40% | >50% | 重复请求过多 |
| **语言分布** | zh 50-70% | 单一语言 >90% | 流量异常集中 |
| **长度桶分布** | 均匀分布 | 单一桶 >90% | 可能的特征提取bug |
| **特征填充率** | >95% | <80% | 特征提取失败 |
| **Worker延迟** | <2小时 | >2小时 | Worker未运行 |

### 日常运维

#### 每日检查

1. 访问Grafana dashboard，确认数据更新
2. 检查Prometheus告警状态（无未处理告警）
3. 查看gateway日志，确认无worker错误

#### 每周检查

1. 回顾7天的去重率趋势，识别异常模式
2. 检查特征分布变化，与业务变化对比
3. 验证告警规则是否需要调整阈值

#### 故障排查

参考运维手册：`docs/runbooks/auto-route-structured-features.md`

常见问题：

**Q1: Dashboard显示"No Data"**
```bash
# 检查统计表是否有数据
psql -c "SELECT COUNT(*) FROM feature_distribution_stats WHERE stat_date = CURRENT_DATE;"

# 如果为0，检查worker是否运行
ps aux | grep llm-gateway
tail -100 logs/gateway.log | grep "feature stats"
```

**Q2: Worker计算失败**
```bash
# 查看错误日志
tail -500 logs/gateway.log | grep "feature.*failed"

# 常见原因：
# 1. 数据库连接中断 → 检查数据库连通性
# 2. auto_route_selections表无数据 → 等待正常流量写入
# 3. Migration未应用 → 手动应用migration 662
```

**Q3: 告警过于频繁**
```yaml
# 调整Prometheus告警阈值（编辑alerts/auto_route_feature_quality.yml）
- alert: FeatureConcentration
  expr: |
    max by (feature_name, feature_value) (
      feature_distribution_stats_percentage{feature_name!="detected_language"}
    ) > 95  # 从90调整到95
  for: 2h  # 从1h调整到2h
```

## 回滚计划

如果P2.3组件导致问题，按以下步骤回滚：

### 1. 停止Worker（不影响请求处理）

```go
// 临时禁用：编辑 cmd/gateway/main.go，注释掉这4行
// featureStatsWorker := bg.NewFeatureStatsWorker(dbConn.Pool(), 1*time.Hour)
// featureStatsWorker.Start(context.Background())
// defer featureStatsWorker.Stop()
// slog.Info("feature stats worker started", "interval", "1h")

// 重新编译并重启
go build -o llm-gateway ./cmd/gateway
./llm-gateway
```

### 2. 删除告警规则（可选）

```bash
# 移除告警文件
rm /etc/prometheus/alerts/auto_route_feature_quality.yml

# 重载Prometheus
curl -X POST http://prometheus.example.com:9090/-/reload
```

### 3. 删除统计表（谨慎，不可逆）

```sql
-- 只在确认不需要历史数据时执行
DROP TABLE IF EXISTS feature_distribution_stats CASCADE;
DROP TABLE IF EXISTS dedup_stats CASCADE;
DROP VIEW IF EXISTS feature_quality_metrics;
```

**注意**: Migration 662不会自动回滚，如需完全清理需手动删除表。

### C. 隐私合规声明

P2.3监控系统遵循以下隐私原则：

1. ✅ **最小化原则**: 只收集必要的结构化特征，不存储原始内容
2. ✅ **非可逆原则**: 所有特征为枚举/桶/哈希，无法反推原始prompt
3. ✅ **聚合原则**: 统计表只存储计数和百分比，不存储单条记录
4. ✅ **测试覆盖**: 8个隐私测试用例，CI自动验证
5. ✅ **审计追踪**: 详细的设计文档和审计报告可供审查
