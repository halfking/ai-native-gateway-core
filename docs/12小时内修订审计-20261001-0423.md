### 2.2 三路专项深审发现的问题（→ §三缺陷清单）

**A. jsoncol/R67-C 专项**：
- 契约失实（D1）：`encoding/json` 对 `UnmarshalTypeError` 是 save-error-then-continue——直接 Unmarshal 进 dst 会留下**部分填充**对象。真实受害位：`center.Command.Args map[string]string`（`store_pgx.go:274/304`），坏 args 会以部分参数形态经 ListPendingCommands **下发节点执行**；`session.Messages []Message` 部分会话以 200 返回（自洽假象比零值更危险）。原测试 `jsoncol_test.go:51-57` 只断言 bool 未钉 dst 状态。
- 数字失实：「15 处/vibecoding 10」实为 **16 处/vibecoding 11**（按调用点/旧 if 块/函数数三种口径都对不上 15）。
- Warn 无行标识：包文档声称「定位到具体行与列」，op 是静态串，列表端点出坏行时只能定位到列。
- 同族残留 ~50 位点未收口（详见 §五 P2-1）。

**B. errdiscard/R68 + R67-B 专项**：
- D2：`bg/model_tier.go` 两处 `else { Warn }`（Query 本身失败——DB 故障最常见形态）仍落到 `m.cur.Store(fs)`，把空集合全量替换上一份完整集合——D5 只修了 rows.Err 截断分支，同因不同支。
- D4：`admin/route_incidents.go` stats 端点——注释/文档/提交信息三处声称 503，`writeInternalErr` 实写 **500**；`recovered_24h` 全仓硬编码 0 无赋值点；`Limit:1`+len 把 active/recovering 封顶在 1——R68 刚「改诚实」的 payload 另一半仍是伪合法数字。
- ExportFromTx（R67-B 的 D4）全仓**零调用方**，P1 评级基于假想调用方，文档未披露（修法本身无害正确）。
- errdiscard 覆盖面：自称「同包」实为**同文件**（throwing 表在单文件 Walk 闭包内构建）；只认 `x.f(...)` selector 形态。

**C. streaming/分钟冲刷/routing 并发专项**：
- D3（高）：闭分钟 retire 有**迟到冲刷竞态**——请求在分钟 M 内完成，累加器 flush ticker（30s）于 M+1:00~M+1:30 才 upsert（增量加，会**重建**被 retire 刚删的悬空键）；下一轮 rollup since=M+1:00 永不再覆盖 M → 悬空键永生，英雄卡双计复发（窗口从 100% 收窄到迟到冲刷，粗略 ~30/60 相位占比）。测试 `a668fe99b` 是单连接串行事务，不覆盖此竞态。
- P1-1（中，未修）：DrainPending 非 survival 回归窗口——standalone 桥 + buffered gate + 整流无完整语义帧 + 尾部合法帧（空生成流 `data: [DONE]\n`+close）形态下：修复后 `gate_writer.go:143-145` 直接 return nil，该路径无人调 Finish()（仅 survival 协调器调）→ 客户端收不到终止帧但请求记 success——正是 `46acf0a1d` 根修症状的窄形态回归。`anthropic_bridge.go:165-166` 有 Finish 兜底，`stream.go`/`responses_bridge.go`×2/`native_responses_stream.go` 三处没有。drainable 预检在 survival 路径是承重的（防桥侧抢跑提交与协调器 discard 竞态），**不宜简单移除**——需 streaming Owner 在「executor 路径补 Finish」与「valid 尾帧走 WriteFrame 交门内裁决」间拍板。
- dims/error-drill 表跨分钟双计同族未修（retire 只接主表路径），跨分钟边界 turn 常态触发。

## 四、修复方案（本轮落地 7 项的设计依据）

1. **D1 fresh 解码**：解码进栈上 fresh，成功才整份赋值——失败时 dst 一个字节不动，契约从「声称」变「事实」；对 16 个调用点零行为回归（原先失败路径的 dst 本就被当零值用，现在真的保零/保原值）。
2. **D2 保旧集**：与 R67-B 截断分支同因同形（全量替换形态下任一段失败必须 keep-stale），补齐 Query-error 分支即闭环。
3. **D3 宽限重扫**：retire 下界取 `min(since, until-2min)`，外层 DELETE 与 NOT EXISTS 子查询共用同一 $1（子查询下界随外层一起放宽，视图仍产出的键由 NOT EXISTS 保护，不误删）——重建的悬空键最多存活一个 rollup tick。grace=2min 覆盖 flush(30s) 晚点 + 两次 tick 余量。
4. **D4 真实计数**：新增 `Store.CountByState`（COUNT(*)，无 limit 截顶、无整行拉取），stats 三键全实查（recovered_24h 按 updated_at 24h 窗）；503 与 ErrNoDatabase 分支同形。
5. **D5 诚实 partial**：已扫告警是真实子集，返回 partial + Warn 留痕，替代「零告警」的安心假象。
6. **D7 panic 安全**：defer 与既有显式 Close/Rollback 幂等共存（pgx Close 幂等、Commit 后 Rollback 返回 ErrTxClosed 被忽略），return 路径行为零变化，panic 路径句柄/行锁不再泄漏。
