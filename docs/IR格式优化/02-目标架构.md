# 目标架构

## 1. 分层

```text
HTTP Endpoint
  -> Client Protocol Adapter
  -> Canonical Request / Stream Event / Response
  -> Capability Validation + Loss Policy
  -> Upstream Protocol Adapter
  -> Usage Normalizer
  -> Cost Calculator + Credit Calculator
  -> Telemetry + Immutable Charge Detail
```

每层只解决一个问题：

| 层 | 责任 |
|----|------|
| Endpoint | 根据 URL/Header 确定客户端协议；heuristic 只做兜底 |
| Adapter | wire format、auth、URL、stream framing、usage extraction |
| IR | 保存可跨协议表达的语义和有序 item |
| Capability | 判断 model offer 是否能接受请求所需能力 |
| Loss Policy | 决定不可映射字段是 reject、drop+warn 还是 passthrough |
| Usage | 归一化原厂统计和估算值，不决定价格 |
| Rate Card | 把 usage metric 转换为供应商成本或租户 credits |
| Charge Detail | 保存计算输入、规则版本和结果，实现审计与幂等 |

协议选择优先级必须唯一：注册路由的 endpoint protocol > 显式内部 routing metadata > body heuristic。URL 已绑定 `/v1/responses` 时只允许 Responses body；body 看起来像 Chat 也返回 400 `protocol_body_mismatch`，不切换 adapter。heuristic 仅用于没有协议绑定的兼容入口。

## 2. Protocol Adapter

```go
type ProtocolAdapter interface {
    ID() ProtocolID
    ParseRequest(body []byte) (*CanonicalRequest, error)
    SerializeRequest(*CanonicalRequest, ProviderContext) ([]byte, LossReport, error)
    ParseResponse(body []byte) (*CanonicalResponse, error)
    SerializeResponse(*CanonicalResponse, ClientContext) ([]byte, LossReport, error)
    NewStreamDecoder(io.Reader) StreamDecoder
    NewStreamEncoder(io.Writer) StreamEncoder
    BuildURL(baseURL, model string, endpoint EndpointKind) (string, error)
    ApplyAuth(*http.Request, Credential) error
    NormalizeUsage(raw json.RawMessage) []UsageMetric
    ProbeDescriptor() ProbeDescriptor
}
```

首批 adapter：

| ID | 说明 |
|----|------|
| `openai-chat` | Chat Completions |
| `openai-responses` | Responses items + typed SSE |
| `anthropic-messages` | Messages + Anthropic SSE |
| `gemini-generate` | generateContent/streamGenerateContent |
| `ollama-chat` | `/api/chat` + NDJSON |

DeepSeek、GLM、Qwen、MiniMax 若使用 OpenAI/Anthropic compatibility endpoint，复用基础 adapter，并通过 `ProviderProfile` 声明差异；真正不同的原生 endpoint 才新增 adapter。

未知 protocol 必须报配置错误，禁止默认当成 OpenAI Chat。

`ProviderProfile` 包含 adapter ID、extension allowlist、capability overrides 和字段差异，不是散落的 vendor `if`。第一阶段以代码注册表实现；稳定后才评估数据库配置。

## 3. Canonical Request

```go
type CanonicalRequest struct {
    Model       string
    Items       []InputItem
    Instructions []ContentPart
    Tools       []ToolDefinition
    ToolChoice  ToolChoice
    Generation  GenerationOptions
    Stream      StreamOptions
    ClientMeta  map[string]json.RawMessage
    Extensions  DirectionalExtensions
}

type InputItem struct {
    Type      ItemType // message, function_call, function_result, item_ref
    Role      Role
    Content   []ContentPart
    Call      *FunctionCall
    Result    *FunctionResult
    Reference string
    ProviderAnnotations map[string]json.RawMessage
}
```

设计要求：

- `Items` 有序，能表达 Responses，不把 function item 强行塞进 message。
- Chat/Anthropic 可投影到 item 子集。
- 不可映射字段进入 provider namespace，不进入无方向的全局 bag。
- `GenerationOptions` 区分 canonical 参数与 provider raw 参数。

## 4. 统一内容与媒体

```go
type ContentPart struct {
    Type       ContentType // text, media, reasoning, refusal, tool_use, tool_result
    Text       string
    Media      *MediaPart
    Reasoning  *ReasoningPart
    ToolUse    *ToolUse
    ToolResult *ToolResult
    Cache      *CacheHint
    Annotations map[string]json.RawMessage
}

type MediaPart struct {
    Kind       MediaKind // image, audio, video, document
    MIMEType   string
    Source     AssetRef
    Filename   string
    Options    MediaOptions
}

type AssetRef struct {
    Kind   AssetRefKind // url, data, provider_file
    URL    string
    Data   string
    FileID string
}

type MediaOptions struct {
    Detail string // OpenAI image detail 等
    Start  *time.Duration
    End    *time.Duration
}
```

约束：

- PDF 表达为 `Kind=document` + `MIMEType=application/pdf`。
- `file` 不是内容模态；它是 asset transport，因此不作为 MediaKind。
- 大 base64 payload 不复制到多个 raw 字段。
- 第一阶段不代替客户端上传文件，只转换已有 URL/data/file ID。
- Adapter 必须校验 MIME、inline size、URL policy 和 file ID 所属 provider。

## 5. Directional Extensions 与 Loss Report

```go
type DirectionalExtensions struct {
    RequestUnknown  map[string]json.RawMessage
    ResponseUnknown map[string]json.RawMessage
    UpstreamHeaders http.Header
}

type LossReport struct {
    Dropped     []FieldLoss
    Approximated []FieldLoss
    Rejected    []FieldLoss
}
```

策略：

| 场景 | 默认 |
|------|------|
| 同协议同 provider | 保留标准字段和允许的 unknown 字段 |
| 同协议跨 provider | 只保留 profile allowlist 字段 |
| 跨协议可等价映射 | 转为 canonical 字段 |
| 跨协议近似映射 | 记录 `Approximated`，由租户策略决定是否允许 |
| 无等价语义 | 默认 reject；显式 best-effort 才 drop+warn |

禁止把请求 unknown 合并到响应。

`FieldLoss` 只保存字段类别、不可逆字段名摘要和原因，不保存字段值或原始字段名。日志需要样例时仅记录固定长度、类型化且经过密钥/PII 清洗的摘要。

IR converter 的方向边界由不同的类型保证：请求仅使用 `InternalRequest.Extensions`，响应仅使用 `InternalResponse.Extensions`；二者不能作为同一实例复用。Transport 层仍以 `RequestExtensions`/`ResponseExtensions` 维护 HTTP 生命周期内的方向隔离。

## 6. Capability Model

能力分为 canonical model 默认值与 model offer/credential override：

```go
type CapabilitySet struct {
    InputKinds      set[MediaKind]
    OutputKinds     set[MediaKind]
    Features        set[Feature]
    MIMEPatterns    []string
    MaxInlineBytes  int64
    SupportsURL     bool
    RequiresFileAPI bool
    Streaming       StreamFraming
}
```

`Feature` 包括 tools、parallel_tools、reasoning、structured_output、prompt_cache、system_instruction 等。

路由条件：

```text
request.required_input_kinds subset_of offer.input_kinds
request.required_features subset_of offer.features
all media MIME and size constraints satisfied
requested output kinds subset_of offer.output_kinds
```

旧 `models_canonical.modality` 保留一段迁移期，只作为 capability 派生展示值，不再参与精确路由。

能力不足在候选查询前完成。请求合法但没有任何 offer 满足能力时返回 422 `unsupported_model_capability`，响应包含缺失能力名和请求模型，不包含 provider 密钥或内部 URL。若模型存在但全部凭据暂时不可用，仍走现有 503/no-route 语义。Loss Policy 不能把必需输入能力降级为 drop；只有显式 best-effort 且媒体本身被声明 optional 时才能近似处理。

## 7. Streaming Model

```go
type StreamEvent struct {
    Type       EventType
    ResponseID string
    ItemID     string
    ItemIndex  int
    PartIndex  int
    Delta      *ContentDelta
    Usage      []UsageMetric
    Error      *StreamError
    Raw        json.RawMessage
}
```

原则：

- Adapter 负责 SSE、NDJSON 等 framing。
- canonical event 保存 item/part 生命周期。
- unknown event 保留 Raw，可按 client policy 转发或记录。
- Responses assembler 按 item ID 跟踪 added/delta/done，最终 output 与事件一致。
- tool-only、mixed text+tool、multiple tool calls 必须是首要测试场景。
- Anthropic usage 的 message_start/message_delta 累加规则由 Adapter 负责。

## 8. Usage Model

```go
type UsageMetric struct {
    Metric          UsageMetricName
    Direction       Direction
    Quantity        decimal.Decimal
    Unit            UsageUnit
    Modality        MediaKind
    Source          UsageSource // provider, gateway_estimate, invoice_reconcile
    IncludedInTotal bool
    ProviderPath    string
}
```

常用 metric：input_tokens、output_tokens、cache_read_tokens、cache_write_tokens、reasoning_tokens、image_tokens、image_count、image_tiles、audio_tokens、audio_seconds、video_tokens、video_seconds、document_tokens、document_pages。

规则：

- provider usage 为结算首选。
- estimate 仅在 provider 未返回时作为临时依据，并标记 estimation version。
- detail 若已包含在 input/output total 中，`IncludedInTotal=true`。
- 原始 usage JSON 必须留存，便于后续归一化升级和账单对账。
- calculator 在 rate selection 前执行一致性校验：同一收费维度同时命中 aggregate 与 `IncludedInTotal=true` detail 时 fail closed，不生成 charge；只有 rate component 显式选择 detail 且排除 aggregate 才允许按 detail 结算。

## 9. Rate Card 与结算

供应商成本和租户 credits 使用独立表，但共享 rate component 结构：

```text
provider_rate_cards / tenant_credit_rate_cards
  id, model/offer scope, region, currency, effective_from, effective_to,
  version, status

provider_rate_components / tenant_credit_rate_components
  rate_card_id, metric, direction, modality, unit, scale, rate,
  context_min/max, service_tier, cache_class
```

`scale` 表示每多少单位收费，例如每 1,000,000 token 或每 60 second。

请求完成后生成不可变 `request_charge_details`：

```text
request_id, tenant_id, provider_id, credential_id, canonical_id,
usage_snapshot JSONB, provider_rate_snapshot JSONB,
credit_rate_snapshot JSONB, cost_usd, credits_charged,
calculation_version, usage_source, created_at
```

Ledger 继续写一条 `consume`，通过 `ref_id=request_id` 关联 charge detail。幂等键覆盖 tenant/request/calculation version，重试不能重复扣费。

## 10. 安全与资源限制

- 设请求总大小、单 media、base64 decode 后大小和 media count 限制。
- 默认只允许 HTTPS URL；阻止 loopback、link-local、metadata service 和内网 SSRF。
- 不在日志记录 base64、signed URL、file token、tool arguments 中的敏感数据。
- MIME 不能只信声明，下载/解码后需检测 magic bytes。
- provider file ID 不可跨 provider 复用。
- LossReport 不包含原始敏感 payload。
