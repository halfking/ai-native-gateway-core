# Audit-09: Vendor Stripper 改动审计报告

**审计日期**: 2026-07-12  
**审计人**: AI Agent  
**Commit**: 20abff6c9

## 执行摘要

通过真实数据验证发现，vendor field strippers **错误地删除了 OpenAI 官方标准字段和计费关键字段**，导致：

1. **账单对账困难** - reasoning_tokens、cache tokens 等计费字段丢失
2. **客户端兼容性问题** - system_fingerprint、object 等标准字段丢失
3. **审计信息不完整** - usage detail、reasoning_content 等审计字段丢失

已修复全部 4 个 vendor strippers，测试全部通过。

---

|------|--------------|------|
| **DeepSeek** | `reasoning_tokens`, `prompt_cache_hit_tokens`, `system_fingerprint` | 账单对账失败、R1 计费错误 |

| **MiniMax** | `object`, `system_fingerprint`, `service_tier`, usage 详情 | OpenAI 兼容性破坏、计费字段丢失 |
| **Doubao** | `system_fingerprint` | 客户端兼容性问题 |

## 2. 根本原因

**错误假设**: "所有非标准 OpenAI 字段都是厂商私有字段，应该删除"

**实际情况**:
1. **OpenAI 标准字段扩展** - `system_fingerprint` (OpenAI 1.0+)、`object` (核心字段)
2. **Anthropic 风格 usage 扩展** - `prompt_tokens_details`、`completion_tokens_details` (业界标准)
3. **计费关键字段** - `reasoning_tokens` (DeepSeek R1)、`cache_read_tokens` (MiniMax/Anthropic)
4. **审计必须字段** - `reasoning_content`、service_tier

这些字段虽然不在 2020 年的 OpenAI spec 中，但已成为 **2024-2026 年的事实标准**。

## 6. 经验教训

### 6.1 设计原则违反

❌ **错误做法**: "凡是厂商响应中有的非标准字段，都删除"

✅ **正确做法**: "只删除明确的厂商私有字段，保留官方标准字段和计费关键字段"

### 6.2 判断标准

删除字段前，必须确认**不是**以下任何一种：

1. ✅ **OpenAI 官方字段** - `system_fingerprint`、`object`、`created`
2. ✅ **业界标准扩展** - `prompt_tokens_details`、`completion_tokens_details` (Anthropic 风格)
3. ✅ **计费关键字段** - `reasoning_tokens`、`cache_read_tokens`、`service_tier`
4. ✅ **审计必须字段** - `reasoning_content`、usage 详情
5. ✅ **通用追踪字段** - `request_id` (可选保留)

只有**明确是厂商私有内部字段**才删除，例如：
- `deepseek_request_id`
- `zhipu_request_id`
- `model_type` (内部模型版本)
- `web_search_results` (内部实现细节)

### 6.3 测试缺陷

**修复前测试问题**:
- ❌ 测试使用人工构造的假数据，未覆盖真实响应结构
- ❌ 测试只验证"字段被删除"，未验证"不应删除的字段被保留"

**修复后测试改进**:
- ✅ 使用真实生产数据构造测试用例
- ✅ 增加"保留字段验证"断言（`kept` 列表）
- ✅ 支持嵌套字段路径验证（`usage.reasoning_tokens`）

## 8. 附录

### 8.1 真实数据验证 SQL

```sql
-- DeepSeek R1 reasoning_tokens 验证
SELECT 
    response_body->>'id' as id,
    response_body->'usage'->>'reasoning_tokens' as reasoning_tokens,
    response_body->'usage'->>'prompt_cache_hit_tokens' as cache_hit,
    response_body->>'system_fingerprint' as fingerprint
FROM request_logs_hot
WHERE provider_id = 33  -- DeepSeek
  AND status = 'success'
  AND response_body ? 'usage'
LIMIT 10;

-- GLM-5 usage detail 验证
SELECT 
    response_body->>'id' as id,
    response_body->'usage'->'prompt_tokens_details' as prompt_detail,
    response_body->'usage'->'completion_tokens_details' as completion_detail,
    response_body->'choices'->0->'message'->>'reasoning_content' as reasoning
FROM request_logs_hot
WHERE provider_id = 32  -- GLM
  AND status = 'success'
  AND response_body->'usage' ? 'prompt_tokens_details'
LIMIT 10;

-- MiniMax M2 reasoning 验证
SELECT 
    response_body->>'id' as id,
    response_body->'usage'->>'total_characters' as chars,
    response_body->'usage'->>'cache_read_tokens' as cache,
    response_body->'choices'->0->'message'->>'reasoning' as reasoning
FROM request_logs_hot
WHERE provider_id = 14  -- MiniMax
  AND status = 'success'
  AND response_body->'usage' ? 'total_characters'
LIMIT 10;
```
