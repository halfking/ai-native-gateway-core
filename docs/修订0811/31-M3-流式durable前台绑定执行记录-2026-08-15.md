## 0. 与 doc 30（Wave B 移植）的撞车合并决策

本线与协作者移植线并行实现了流式 durable 前台的**同一范围**，main 侧先行合入了 gate 钩子（`BeforeSemanticCommit`，仅 buffered 首次语义提交时触发）与 coordinator 的 ctx 化 seam/Reschedule seam（未接线）。合并裁决（遵循 doc 25 §4/doc 28 §2 先例，main 为权威）：

- **gate 钩子统一为 main 的字段名 `BeforeSemanticCommit`，采用本线的触发语义**——按「状态推进且该状态字节即将上网」触发（覆盖 post-commit 的 content→tool_call 推进与 immediate 模式）。理由：§10.3 的 tool_call 档是重放硬阻断点，首个语义提交后才出现 tool call 的流若只覆盖首次提交，DB commit_state 将停在 content，重放安全语义失真。main 上无测试钉住旧窄语义，合并零破坏。
- **coordinator 的 durable `Reschedule` seam 保持未接线**：`store.Reschedule` 会清空租约，而 coordinator 睡醒后仍在连接内继续执行——接上会造成前台/worker 双持有。等待期崩溃的恢复由前台租约过期 → ClaimRunnable 重领覆盖（语义等价，延迟 = 租约期）。
- 移植线的 durable_* 指标族（worker 周期/gauge/lease-lost 双计数）与本线 binding 的 `lease_conflicts` 计数并存互补。

## 1. 产出

### 1.1 AttemptCommitGate write-ahead checkpoint 钩子（attempt_commit_gate.go）

- `GateOptions.BeforeSemanticCommit func(CommitState) error`（字段名沿 main，语义为本线版）：commit 状态推进且该状态字节即将上网（immediate 模式 / 已提交 attempt / buffered 语义提交，含 post-commit 的 content→tool_call）时**先**落 durable commit_state，失败即帧写失败——**DB 失败禁写网络**（doc 18 §11.3 原文语义）。
- 纯缓冲 metadata 不触发（首个语义提交的 checkpoint 按 rank 单调覆盖 metadata 档）；checkpoint 失败后本地 state 保持推进、Discard 拒绝——attempt 走 fail-closed（coordinator 聚合为 resume_blocked/fail_closed 终态，不透明重试"DB 结果未知"的输出）。
- 测试钉住：write-ahead 顺序（checkpoint 先于 wire 字节）、失败禁写+不提交+Discard 拒绝、immediate 模式 metadata 档也 checkpoint。

### 1.2 DurableStreamBinding 前台绑定（durable_stream.go，新增）

- **租约续租**：`Start/Stop` 半租约周期续租 goroutine；续租失败（ErrLeaseLost 计 lease_conflicts / DB 错误）即停——post-content 任务因 commit_state 门禁不可被 worker 重领，pre-content 可被重领，客户端侧流不受影响。
- **Checkpoint 适配**：gate 钩子 → `store.CheckpointCommitState`（携带 owner+token，detached 5s 有界 ctx）；**rank 去重**——重试 attempt 的 gate state 归零后再次推进 metadata 不会撞 SQL 的 rank 单调守卫（同 rank 重写会被误判 ErrLeaseLost）。
- **结算矩阵**（settleDurableStream，租约保持到结算写落地后再 Stop）：
  | 终局 | 结算 |
  |---|---|
  | 成功（有捕获正文） | CommitTerminal(completed, wire bytes, text/event-stream) |
  | 成功（无正文可存） | failed/`durable_result_unavailable`（不存"completed+空 body"的假结果） |
  | 客户端断连 · 未过语义检查点 | Reschedule(`client_disconnected_pre_content`) → worker 后台重执行，客户端可轮询——**durable 核心承诺** |
  | 客户端断连 · 已过检查点 | 停止续租弃置 → safety reaper（带 lease 护栏，doc 28）在租约到期后终态化 resume_safety_blocked（§10.3 禁自动重放） |
  | 前台终态失败 | CommitTerminal(failed, decision.Reason, LastKind) |
- **wire 捕获**：`durableWireCapture` tee（1 MiB 上限，溢出报 nil——绝不存截断的假 body；Header/WriteHeader/Flush 透传）。

### 1.3 接线

- `SurvivalCoordinator.BeforeSemanticCommit`（ctx 化，沿 main 字段名）seam → 每个 attempt 的 gate 钩子；binding 内部用 detached ctx（write-ahead 不被客户端断连取消）。
- `runSurvivalCoordinator` 增 binding 参数：tee 捕获 + `binding.Start()` 续租 + 循环结束后按矩阵结算（clientDisconnected 取 frozenCtx.Err()）。
- `maybeStartDurable` 增 `foreground` 参数：chat 端点（有 survival 分支）传 true——流式 durable 不再 501，改为 CreateAndClaim（不 Reschedule）返回 binding，前台持租约在连接内执行（§11.3 前台模式）；Messages/Responses 无 survival 分支，维持 fail-closed 501 直到其 coordinator 接线。流式重复任务（同 request_id 重试）回退连接内直行，不假 202。
- handler survival 分支条件扩展 `durableStream != nil`；防御性兜底：binding 存在却未进 survival 分支时 fail-closed 503（legacy 循环绝不在无 checkpoint 的情况下执行带可领取任务的请求）。
- `SetDurableExecution`/`ChatHandler.durableStore` 类型放宽为 `DurableForegroundStore`（*durable.Store 满足；cmd/gateway 装配无改动）。
