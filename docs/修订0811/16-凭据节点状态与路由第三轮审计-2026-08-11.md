## 3. 已修复缺陷

| # | 严重度 | 位置 | 缺陷 | 修复 |
|---|--------|------|------|------|
| **FIX1** | **HIGH** | `internal/outbox/dispatcher.go` `dispatchBatch` | `SELECT ... FOR UPDATE SKIP LOCKED` 经 `d.db.QueryContext` 执行（autocommit），行锁在 SELECT 语句结束即释放；`markSent`/`markFailed` 又是各自独立的 autocommit `ExecContext`。后果：**SKIP LOCKED 形同虚设**——两个 dispatcher 实例可同时领取并重复投递同一事件。crash 在 POST 成功后、markSent 前则事件留 pending 下轮重投（at-least-once 靠消费端 event_id 去重兜底，但并发重复投递无任何保护）。 | 重构为**每事件一个事务**：`dispatchOne` 内 `BeginTx → SELECT ... LIMIT 1 FOR UPDATE SKIP LOCKED → dispatch(HTTP) → markSent/markFailed(on tx) → Commit`。行锁覆盖整个投递窗口，SKIP LOCKED 真正生效。`markSent`/`markFailed` 改收 `execer` 接口（`*sql.DB` 与 `*sql.Tx` 均满足），在 tx 上执行。crash 语义不变（at-least-once）。 |
| **FIX2** | **HIGH** | `autoroute/override_store.go` `Reload` | 查询 `SELECT ... FROM routing_overrides WHERE ...` 无 `ORDER BY`，PostgreSQL 行序未定义。`GetPins`「按 pin 优先级顺序返回」依赖快照内切片顺序 → **pin 优先级跨 1min 重载非确定**：`{claude, gemini}` 的 pin 可能在下次刷新后翻转，winner 在两个模型间来回跳。 | 查询加 `ORDER BY id ASC`（pin 按创建顺序即优先级），重载顺序稳定。 |
| **FIX3** | MED | `internal/outbox/writer.go` `Write` | `w.tx == nil` 时静默 `return nil`（注释称「validation-only path，用于测试」）。但这是**持久化关键写入**：生产调用方若忘记传 tx，会看到「成功」而事件永不送达 ASM。 | 改为返回显式错误 `outbox.Writer.Write: no transaction provided (event_id=…)`，让 bug 在调用点暴露。现有 `TestWriter_Write_Defaults` 仅断言错误不含 "is required"，新错误信息不影响该测试。 |
| **FIX4** | LOW | `credentialhealth/checker.go:423` | SQL 注释写 `node_probe_state.raw_model_name`，但同句 `FROM model_probe_state mps`——注释引用了**不存在的表**（`node_probe_state` 是另一张表），误导后续编辑者。 | 注释改为 `model_probe_state.raw_model_name`，与 FROM 子句一致。 |
| **FIX5** | LOW | `credentialfpslot/node_state.go` 文件头 | 头部声明「DEPRECATED / Replaced by `domains/ursm/state.go`」，但 `domains/ursm/state.go` **从未存在**（实际只有 `domains/ursm/v2/`，且管的是 LRU/filter 评分，与本 NodeState 无关）。本 NodeState 仍是 `domains/streaming/executors/router.go` 请求热路径的**活生产类型**。误导性 DEPRECATED 标记会让维护者误以为可删。 | 改写头部为 NOTE：声明该目标文件不存在、本类型仍是生产权威、`domains/ursm/v2` 不替代它、在具体迁移落地前不要标 DEPRECATED。 |
