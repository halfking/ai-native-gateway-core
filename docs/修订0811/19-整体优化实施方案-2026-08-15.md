## 1. 统一业务流程（目标态）

```text
客户端请求
  ① 入口层：鉴权 / client 识别 / capabilities 协商 / request_id+session+task 标志冻结
  ② 脱敏层：SmartSaniGuard 占位符替换，真实值入 Redis（sanitize map）
  ③ 会话层：三层缓存读取（L1 LRU → L2 Redis 元数据 → L3 PG turns）
       滑动窗口评估 → LLM 摘要/机械裁剪（记录压缩起止 AlignmentMap/CutMarker）
  ④ 生存层：RetryOwner=survival 冻结
       durable 请求 → CreateAndClaim 加密快照落 PG
       每轮 attempt：重新解析候选 → ExecuteAttempt（attempt 内候选轮转）
       可恢复失败 → waiting_recovery（keepalive 注释保活 + 权威 recover_at 退避）
       首语义内容 → write-ahead checkpoint → AttemptCommitGate 提交真实连接
  ⑤ 路由层：候选评分 = 性能稳定性 × 成本 × IQ（MinStandardIQ 门禁 + 热门模型加权）
  ⑥ 多模态层：入站 base64 → 附件存储（hash 去重）；按 provider 能力出站 data-uri / 网关 URL
  ⑦ 响应层：协议 bridge（commit 后）→ output_compliance → 占位符还原（拦截器链末端）
  ⑧ 记录层：session turns（按轮次增量）+ request_logs 脱敏摘要（降采样）
       usage 如实/估算标记 → cost 落账 → 对账差异
  ⑨ 观测层：live stream（队列/节点/错误/生存等待泳道）+ transitions + survival 指标
```

流程规则：

1. 脱敏（②）先于 durable 快照切点（④）：快照必然含明文敏感值，强制 ciphertext+AAD 落库；密钥体系与 sanitize Phase-2 共用新 `EncryptWithAAD` API（单 keyring、双 AAD domain）。
2. 还原（⑦）永远在拦截器链末端；durable 重放后的响应必须重走 output_compliance → sanitize_restore 顺序契约。
3. request_logs 不再承载会话历史重建（历史由 ③ L3 turns 拼接），只保留审计摘要与降采样 body。
4. keepalive/状态帧不进 completion token、不进 capture、不进 turns 正文。

## 2. 数据结构与生命周期对齐

| 实体 | 存储 | 生命周期 | 责任轨 |
|---|---|---|---|
| Session / Turn | sessions_v2 + session_turns/bodies（增量） | 会话存续 + 保留策略；L1 LRU(1024/256MiB) → L2 Redis 30min → L3 PG | SC |
| 压缩窗口 | SessionState.AlignmentMap/CutMarker（L2）+ compression_meta | 每轮更新；ResultMemo 命中重放；跨层字段名一致 | SC |
| 脱敏映射 | Redis `session:{sid}:sanitize`（30min 刷新） | 与 SessionState TTL 同步、Invalidate 联动删除；v8 SanitizeMapRef 打通 | SC |
| 附件 | attachments 存储（hash 去重）+ request_logs.attachments | sent 后进入清理；lifecycle 扩展 OSS/S3/Cloudreve | MM |
| Durable 任务 | durable_llm_tasks（加密快照+结果+lease/fencing+commit_state） | running→waiting→retry→终态；双 reaper 兜底；终态后按读取窗口清理 | SR |
| 任务事件 | request_state_transitions 扩展（survival_* 枚举 + attempt 维度） | 与任务状态同事务/旁路异步写入；7 天保留 | SR/OBS |
| Attempt/CandidateOutcome | AttemptResult（内存）+ attempt transition 事件 | 每 attempt 独立记录全部候选 kind/scope/RetryAfter，不用 LastKind 代表任务 | SR |
| Usage/Cost | request_logs.usage_source + provider_cost_reconciliation | estimated 可被真实 usage 回填修正；月度对账 diff | COST |
| 生存指标 | Prometheus gateway_survival_* | 实时；backlog/projection lag/lease conflict 告警 | OBS |

生命周期冲突消解（本轮裁决）：

1. sanitize map 与 SessionState 独立 TTL → 统一为 SessionState 驱动：Invalidate/关闭会话时联动删 sanitize hash。
2. durable 快照保留窗口（deadline+读取窗口）与附件 TTL 联动：快照引用的附件延长至任务终态后。
3. request_logs_bodies 默认 7 天全量保留 → sessions_v2.enabled 时默认摘要模式（全量 body 转为显式开关），历史由 turns 拼接。
4. keepalive/status 帧不计 token、不进 capture/turns。

## 5. 全域验收

1. 稳定性：可恢复故障连接内恢复、durable 断连/重启恢复、无重复工具副作用（S30-S35 全绿）。
2. 会话：三层缓存命中率不降、脱敏还原零丢失、客户端可显式触发压缩。
3. 多模态：base64 不再重复上行、URL 模式 E2E 通过、不支持 URL 的 provider 自动回退。
4. 路由：IQ 低于阈值模型不被分配（租户开启时）、综合分权重可配且回归通过。
5. 成本：estimated 行可修正、月度对账 diff 可查、request_logs 体积增速显著下降。
6. 监控：live stream 生存等待/恢复泳道可见、survival 九指标齐全、告警就位。
7. 安全：新开关默认关闭；flag-off 行为与测试不变；RLS/加密 fail-closed。
8. `go test -race` 全仓通过（含 dispatch 修复）。
