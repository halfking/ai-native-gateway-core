## 3. 已修复缺陷

### FIX1 (§5-D) PriceScore cohort P75 归一化

**位置**：`autoroute/scoring_simplified.go` `ScoreSimplified` / `ScoreWithChannelQuality` / `ScoreWithAffinity`；`autoroute/recommend_v2.go` `RecommendV2WithHints`。

**缺陷**：旧公式 `priceScore := (1000 - avgCost) / 10`，per-1M-token 单价典型 0.1–60，输出钳制在 94–100，price 维度对排序几乎无贡献。doc 15 §5-D 已记录此 bug，但 doc 16 之前的修复未落地。

**修复**：
- 在 `ScoringBreakdown` 之外不引入新字段，只改公式语义。
- `ScoreSimplified` / `ScoreWithChannelQuality` / `ScoreWithAffinity` 三个评分函数签名从 `(c, task, avgPriceByCanonical map[int]float64, correction)` 改为 `(c, task, costCtx CostContext, correction)`，与 `scoring.go::scorePrice` 对齐。
- 新增共享 helper `scorePriceByCostContext(c, costCtx)`（公式 `clamp(100*(1.5 - blended/P75), 0, 100)`）+ `recommendCostContext(pool)`（cohort P75 计算，排除零价与不可用候选）。
- `RecommendV2WithHints` 调用 `recommendCostContext(candidatePool)` 一次，传入评分分支。

**回归测试**（`scoring_doc16_regression_test.go`）：
- `TestDoc16_PriceScore_P75Discrimination`：5 候选 [10, 50, 100, 150, 200] / 1M，P75=150；最便宜（ratio=0.0667）→ 100（钳制），最贵（ratio=1.33）→ 16.67，梯度 ≥40 点（旧公式 ≈1.5 点）。
- `TestDoc16_PriceScore_NoBaseline`：cohort P75=0（仅 free 候选）时退化为 80（中性），不丢失 free 优势。
- `TestDoc16_RecommendCostContext_ExcludesZero`：零价与 `UnavailableReason="manual"` 的候选不计入 P75。
- `TestDoc16_PriceScore_DiscriminationStrict`：跨真实价位 10–400/1M，PriceScore spread ≥ 50。
- `TestDoc16_PriceScore_FreeCandidateDominates`：free 候选始终拿 100；paid1 > paid3（最便宜的 paid > 最贵的 paid）。

**既有测试同步更新**（避免遗留旧公式断言）：`channel_quality_test.go::TestScoreWithChannelQuality_Formula`、`recommend_v2_test.go::TestScoreSimplified_IntentAndPriceWeighting`、`scoring_affinity_test.go`（所有 affinity 测试用 `affinityPriceCtx(prices)` helper 替代旧 map）、`recommend_v2_affinity_test.go`、`channel_quality_test.go::TestScoreSimplified_LegacyFormulaPreserved`（重命名为 `TestScoreSimplified_2DimFormula` 并反映 P75 归一化）。

### FIX2 (§5-E) isFallbackWinner 显式 IsFallback 标记

**位置**：`autoroute/scoring.go` `ScoringBreakdown`；`autoroute/recommend_v2.go` `isFallbackWinner` 与 3 处 fallback 路径构造。

**缺陷**：`isFallbackWinner` 用浮点三连等 `Composite==50 && PriceScore==50 && MatchScore<=30` 检测 48h 热门回退路径。注释声称"这种特征签名无法通过正常评分产生"，但 `avgCost=500/1M`（极贵模型）+ `MatchScore=0`（极端场景）确实能巧合命中三连等值，导致正常候选被误翻为 FallbackUsed，影响下游 metrics / observability。

**修复**：
- 在 `ScoringBreakdown` 加 `IsFallback bool`（`json:"is_fallback,omitempty"`）。成本：1 byte struct / 1 bit wire，新逻辑不影响其它维度。
- `isFallbackWinner` 简化为检查显式 `results[0].Breakdown.IsFallback` 字段（保持 `len(results) != 1` 的多/零候选守卫）。
- `RecommendV2WithHits` 三处 fallback 路径（available=0 / candidatePool=0 / MatchScore<30）构造 `ScoringBreakdown` 时统一设置 `IsFallback: true`。

**回归测试**：
- `decision_test.go::TestIsFallbackWinner` 重写：(a) sentinel 数值但 IsFallback=false → 不是 fallback；(b) sentinel + IsFallback=true → 是 fallback；(c) 多候选仍不是 fallback；(d) 空仍不是 fallback。覆盖原行为 + 新回归点。
- `scoring_doc16_regression_test.go::TestDoc16_IsFallback_FlagRequired`：独立于 decision_test 的 spec 测试，避免 decision_test 后续重构影响回归。
