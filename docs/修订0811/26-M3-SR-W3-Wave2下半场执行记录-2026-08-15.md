## 2. 切片明细

### 2.1 recovery worker（`domains/durabletask/worker.go`）

- `RecoveryWorker.Run`：claim 轮询（默认 5s）+ 双 Reaper 轮询（默认 30s）+ `ActiveTaskCounts` 刷 gauge。
- `executeClaimed` 全链路：解密快照（失败即 fail-closed 落 `permanent_failed`，reason=`snapshot_undecryptable`）→ 执行期续租 goroutine（`RenewLease` 失效即 `ErrLeaseLost`→cancel 执行 context 并丢弃结果——修正了实现中途发现的「只置位不取消」死锁）→ 结果映射 `Complete/Reschedule/Fail`，全部 fenced 写，`ErrLeaseLost` 一律丢弃不双写。
- `Executor` 接口 + `Execution{Outcome, Body, ReasonCode, RetryDelay, NextStatus}`；本片 `NoopExecutor` 占位：`waiting_recovery` 30s 回排，不丢任务不误终态。真实重放 executor 属 Wave 3。
- Reaper 产物经 `OutboxHandler` 回调转发（切片 3 投递器消费同一 outbox 表，另有自带轮询）。
- 发现并修复：续租丢失时必须 cancel 执行 context，否则阻塞型 executor 永不返回（测试实跑暴露）。

### 2.2 指标（`metrics/durable_metrics.go`，doc 18 §15 命名）

| 系列 | 类型 | 递增点 |
|---|---|---|
| `durable_tasks_active{tenant}` | Gauge | worker `ActiveTaskCounts` 快照；排空租户归零（防冻结旧值） |
| `durable_recovery_runs_total{outcome}` | Counter | claim 轮询：claimed/empty/error |
| `durable_pending_projections_total{status}` | Counter | outbox 投递成功（按终态） |
| `durable_pending_projection_errors_total{reason}` | Counter | decrypt/result_hash/project_cas/mark_delivered |
| `durable_lease_lost_total` | Counter | worker 全部 `ErrLeaseLost` 路径（`noteLeaseLost` 统一） |

与 doc 18 §15.1 的 `gateway_survival_*`（请求侧，SR-13 已建）并存：durable_* 是 worker/投影侧视角，series 数受租户数 × 1 约束（GW-00 基数规则，doc 18 §12 per-tenant cap）。

### 2.3 outbox 投递器（`domains/durabletask/outbox.go`）

- 流程：`ClaimOutbox` → durable-result 域解密（AAD=tenant/task/request_hash，`ClaimOutbox` 补 select `t.request_hash`、`o.attempt_count`）→ sha256 结果哈希校验 → `pending.ProjectCAS`（`Durable=true`，同 task 单调 `result_version`）→ `MarkOutboxDelivered`。
- 幂等三重保证：(task_id, result_version) 唯一约束（ON CONFLICT 收敛到原行）+ ProjectCAS Lua 守卫（被更新投影覆盖时仍标 delivered）+ delivered 行不可重认领。
- fail-closed：解密失败/哈希不匹配绝不写 PendingStore，`MarkOutboxFailed` 指数退避（5s 起、5min 封顶，位移限 16）重试，errors_total 可见。
- 终态映射：completed→`pending.StatusCompleted`+body；permanent_failed/expired/cancelled/resume_safety_blocked→`StatusFailed`+`<status>: <reason>` 错误消息。

### 2.4 请求加密接入口（`domains/durabletask/foreground.go` + `domains/streaming/durable_wiring.go`）

- `Foreground`：请求级生命周期句柄。`BeginForeground` = `CreateAndClaim`（owner=`gateway/<request_id>`，lease 90s、deadline 24h、结果 TTL +24h）；`Checkpoint/Complete/Fail/Reschedule/Renew(Now)` 封装；`Attach/ForegroundFromContext` 挂 context；`CommitStateFromString` 未知值不映射（上游按 content fail-closed）。
- streaming：`SurvivalCoordinator.DurableCheckpoint` seam 注入每个 per-attempt gate 的 `BeforeSemanticCommit`——语义字节 flush 前先落 PG 检查点，fencing 失效中止 flush。
- wiring（`runSurvivalCoordinator`）：请求进入构造 V1 快照（request_hash=sha256(body)、normalized body、endpoint、协议映射、session/tenant、tools）→ `BeginForeground` → lease 挂 context；30s 前台续租循环防长流式被 worker 抢占；终态映射 Complete（无捕获流式 body 时落状态 stub，Wave 3 补 gate 字节捕获）/ Fail(permanent_failed, decision.Reason)。begin 失败 fail-open（功能 opt-in，仅告警）。
- main.go：`LLM_GATEWAY_DURABLE_EXECUTION=true` 且 AES-GCM keyring 可用时 `SetDurableExecution`（默认关，零行为变化）。**注**：本片仅覆盖 survival 分支的流式请求；非 survival 常规路径与恢复重放执行器属 Wave 3。

### 2.5 真实 PG 集成测试（`domains/durabletask/pg_integration_test.go`）

- `go:build integration`，testcontainers `postgres:16-alpine` 单容器共享 + 每测试 TRUNCATE（append-only 触发器只拦 DELETE，TRUNCATE 安全）；直读生产迁移 `sql/migrations/startup/515_durable_llm_tasks.sql` 建表，保证测的就是部署 schema。
- 覆盖：并发 claim 恰一赢家 + 旧 token 全路径 `ErrLeaseLost` + 快照可解密；语义检查点过期任务不被 deadline reaper 回收、仅 unsafe reaper 终态化；未检查点过期任务正常 expired；outbox 唯一约束去重/delivered 不可重认领/failed 可重试不重复；权威计数 + 创建事件同事务。

## 4. 已知边界（诚实声明）

1. **重放执行器未实现**：NoopExecutor 仅保持任务存活（waiting_recovery 回排），恢复路径不产生新的上游 attempt——Wave 3 主体工作。
2. **流式结果字节未捕获**：前台 Complete 在无 ResponseBody 时落状态 stub（`note: streamed body not captured`），重连查询能得知完成但拿不到原文；Wave 3 需 gate 级字节捕获。
3. **终态映射粗粒度**：前台失败一律 permanent_failed；可恢复错误应 Reschedule 交 worker 重放，待 Wave 3 与执行器一起做。
4. **durable 接线仅 survival 分支**：常规（非 survival）请求路径未接 durable；`LLM_GATEWAY_DURABLE_EXECUTION` 默认关。
5. **worker/deliverer 尚未在 main.go 常驻启动**：组件就绪且可测，部署接线（含 `durable_enabled` 配置项化）随 Wave 3 一起。
