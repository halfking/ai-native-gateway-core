### 1.3 显式豁免与已知边缘（review 双轴结论）

1. **latent SQL bug 修复（flag-off 行为变化，豁免）**：原查询 `COALESCE(COALESCE(rb.request_body, rl.request_body), '')::text` 的空串字面量紧邻 jsonb 在**解析期**被强制转 jsonb 报错——estimated_original_tokens 历史上从未产出（被 `err == nil` 守卫静默吞掉）。修复为 `COALESCE(COALESCE(...)::text, '')` 后 flag-off 响应开始出现该字段（omitempty 增量）。定性：恢复设计意图的必要修复，非流式红线范畴；已在代码注释与本报告双记录。
2. **null 键语义差异（接受）**：SQL 侧 `?` 键存在即计入 summary_mode_rows，Go 侧把 `null` 键视为非信封。写入侧用非指针结构不会写出 `null` 键，实际不触发。
3. **顶层键理论碰撞（接受）**：合法请求 body 顶层恰含 `_gw_body_summary` 键且 flag-off 时会被误当信封解包。概率极低（写入侧 sha256 路径不可猜测），接受。
4. **标记文本进标题语料（接受）**：`[已摘要化: …]` 标记经 buildSummaryCorpus 进入标题/总结 LLM 语料。规格允许"适配展示"且已预期标题生成降级。
5. Standards 轴判断题（不阻塞）：compression_stats 错误吞噬为存量模式延续；SQL 子串断言测试较脆；信封结构镜像无编译期同步；同 body 双次解析纯效率问题；docs/design/timeout-retry-optimization/11 仍有 KeepaliveSender 示例残留（历史文档）。
