## 可能的问题和诊断

### 问题 1：canonical_ids 为空数组但应该有值
**症状**：选择了模型，但 Resolved canonical_ids 是 []

**可能原因**：
- 模型名称不匹配（大小写、空格、特殊字符）
- modelsCanonical 未正确加载

**诊断**：
```javascript
// 在控制台手动执行
console.log('Selected:', selectedModels.value)
console.log('Available:', modelsCanonical.value.map(m => m.canonical_name))
```

### 问题 2：后端返回了所有模型
**症状**：canonical_ids 有值，但 Response items 数量不对

**可能原因**：
- 后端未正确处理 canonical_ids 参数
- 传递的 ID 在数据库中不存在

**诊断**：
1. 检查请求体中的 canonical_ids
2. 在后端日志中查找相关错误
3. 直接查询数据库：
   ```sql
   SELECT id, canonical_name FROM models_canonical WHERE id = ANY(ARRAY[123, 456]);
   ```

### 问题 3：模型名称格式不匹配
**症状**：ModelPicker 返回的名称与 models_canonical 表中的不一致

**解决方案**：
- 检查 ModelPicker 返回的确切格式
- 可能需要添加名称规范化逻辑
- 或者改用 display_name 而不是 canonical_name

## 修复计划

根据测试结果，可能需要：

1. **如果 modelsCanonical 未加载**：
   - 检查 listModels API 调用
   - 添加加载状态提示
   - 在加载完成前禁用预览按钮

   - 添加名称规范化
   - 或改用其他字段匹配
   - 或在后端添加模糊匹配

3. **如果后端问题**：
   - 检查后端日志
   - 验证 SQL 查询
   - 确认数据库中的 ID 存在
