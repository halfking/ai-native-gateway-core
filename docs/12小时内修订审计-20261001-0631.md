### 4.1 bg panic 收口的结构性缺口（本轮只修 circuit_state_sync 一点）

- **~40 个 done 握手型循环 worker**（envelope_cleaner/handoff_*_trimmer/cost_reconciliation/integrity_fingerprint_drift/stats_minute_rollup/provider_profile_workers 等）因 run 体内 `defer close(w.done)` 结构上只能用 `bg.Go`——任何一次 panic 后**永久停摆到进程重启**（统计断流/清理停摆/告警引擎停摆）。留痕在位（slog+`llm_gateway_bg_goroutine_panics_total`），**但无告警规则消费该指标**。根修方向：done 所有权下沉 BaseWorker（设计变更）+ goroutine_panics 指标接告警（运维侧）。
