# PI（提示注入）智能体链审计

来源：`docs/audit/2026-11-17-PI智能体审计与完善-主档.md`（三轮审计 49 缺陷修 31；245 部署后验收又抓 3 条）。

## 核心判据：组件齐全 ≠ 链路能跑

判定标准是「**谁调用了它**」，不是「它写了吗」。第一轮审计发现整条链（收集器/分析器/worker/管理 API/判官）全部有实现、有单测、**零生产调用方**。

### 第一步：接线面普查（先于一切细节审计）

对链上每个组件，grep 它的**构造点**与**注入点**，两者都存在才算接线：

```bash
# 例：collector 构造了但没人 Set 进 detector ⇒ 数据面永远空
grep -rn "NewErrorCollector" --include="*.go" | grep -v _test
grep -rn "SetErrorCollector" --include="*.go" | grep -v _test
```

高频断线形态（本仓实测全部出现过）：
- 组件在 `if <某开关> { }` 块内装配，而该开关**默认关** ⇒ 生产整条不存在。
- worker 返回值被丢弃 ⇒ 无停机句柄，DB 关闭后仍在查询（goroutine 泄漏 + 关库后访问）。
- 管理 API 注册条件依赖「采集已开」⇒ 默认部署 404，运维无法区分「没开」与「开了但空」。
- ctx 用 `context.Background()` 且无 cancel ⇒ 永生 goroutine。

### 第二步：逐环验「真的会执行」（含 P0 高频缺陷表）

| 环节 | 已实测缺陷形态 | 判据 |
|---|---|---|
| 判官引擎配置查询 | 查询列在正典表**不存在** ⇒ 每次 PG 42703 ⇒ 判官从不产出 | 查询列清单 vs `\d 表` 逐列对拍 |
| 采集器入库 | 按字节切 UTF-8（`s[:10000]`）⇒ 中文落在切点 ⇒ PG 22021 ⇒ 整行丢 | 中文长文本实测入库；用 rune-safe 截断 |
| jsonb 绑定 | `[]byte` 直绑 ⇒ 简单协议下变 bytea ⇒ 22P02 | 统一 `string` + `NULLIF($N,'')::text::jsonb` |
| 分析客户端 | 空成功桩 `("",0,nil)` ⇒ 日志像在工作，实际零产出 | 未配置端点必须显式报错，不许静默成功 |
| LLM 回填枚举 | 自由文本写进 CHECK 列 ⇒ 23514 ⇒ 结论整条丢 | 归一函数 + 越界夹取后再写 |
| 领取队列 | 只读 SELECT → 无条件 UPDATE ⇒ 双处理器重复领 | `UPDATE … FOR UPDATE SKIP LOCKED … RETURNING` |
| 孤儿行 | 崩溃的 processing 行永久卡住 ⇒ 错误被吞 | reaper 要含「耗尽重试 → 终态 failed」独立分支 |
| 生命周期 | `Start` 注释说幂等但无守卫 ⇒ 重复起循环 | `atomic.Bool` CAS；handler 改批大小 = data race ⇒ 请求级走局部参数（`ProcessBatchN` 型） |
| 出站 HTTP | 默认跟随 30x ⇒ 端点校验只验初始 URL ⇒ SSRF 绕过 + key 泄漏 | `CheckRedirect: ErrUseLastResponse` |

### 第三步：安全面三查

1. **提示词注入**：攻击者原文进分析提示词？必须 `<untrusted_input>` 框架 + 指令在前数据在后 + 中和闭合标签（`neutraliseUntrustedText` 型）；**断言要落在产出物性质上**（闭合围栏只出现一次），不是「恰好用了某 API」。
2. **自放大递归**：分析端点打回网关自己 ⇒ 误报被收集→再分析→再误报。端点校验必须禁回环/私网（结构性消除）。
3. **管理面鉴权**：挂在 `/api/admin/` 前缀下的**精确路由**会绕过前缀中间件（ServeMux 最长模式派发）——每条路由自己带鉴权，缺失即拒绝注册（fail-closed）。错误响应不得回显 `err.Error()`（泄露表名/列名）。

### 第四步：部署后验收（部署成功 ≠ 验收通过）

- 把产物探针 SQL **拿到活库上求值**（不是读代码）。
- 规则集/种子数据有没有真的投递：查「全新安装通道」（installer 清单）与「存量升级通道」两本账，**「表在」不等于「表里有货」**。
- 管理 API 用「无 token 401 / 伪造 token 401 / 合法 token 200」三态探针。
- 界面层用浏览器验证（见 `maestro-browser-verification` 技能）。

## 元方法（每一条都被实战证伪过一次）

- **注释/配置也是交付物**：注释声称的性质（「幂等」「绕不过去」）要当缺陷候选核对，不是当验收依据。
- **修法写了 ≠ 修法生效了**：多轮自审计后的残留面，要用独立轮按「只看 HEAD 代码现状、不信主档自述」再扫一遍。
- **「断言不成立」先分辨「产品坏了」还是「量具问错了对象」**：换独立证据源（302 location / 截图 / 同环境其它用例 / 直连后端状态码），不要重跑。
- **登记不修要带理由与归属**：跨域裁决、需 owner 拍板、他人资产——写清「为什么这轮不动」。
