### N-2（P2，已修）750 分区边界随会话时区——1614 轮 O-3 裁决落地（迁移 751）
- **暴露面**（数据来源与去处维）：750 的 `start_ts/end_ts` 在 **DECLARE 初始化器**里做 `p_date::timestamptz`，随**会话时区**求值。tick 路径（PartitionManager，`partitionTZ` 上海日历派生，bg/partition_manager.go:964 已接入 `partitionUnit:"day"` spec）日期正确，但边界**转换**在 UTC 会话下产出 [00:00Z,24:00Z) = 上海日历 [+08 08:00) 起点的**错位 8h 窗口**；db.go boot ensure 传 `current_date` 亦随会话时区。252/245 会话均 +08 当前无害，但运维 UTC 会话手动调用 / 未来 DSN 显式 TimeZone=UTC 即触发（环境敏感时序炸弹）。
- **方案取舍**：694 先例证明 **body 内 SET LOCAL 不覆盖 DECLARE 初始化器**（初始器先于 body 执行，694 因此把月派生移出初始器）；751 采用其对偶——**函数级 GUC**（`ALTER FUNCTION ... SET timezone = 'Asia/Shanghai'`，proconfig 在函数入口生效、先于初始器、出口自动回滚），一行幂等 DDL，不动 750 canonical 函数体，无需三处复制函数体。
- **落地**：
  1. `sql/migrations/startup/751_usage_facts_partition_tz_pin.sql`（+ down：RESET）；
  2. 双通道登记：`installer/internal/dbinit/runner.go`（新装）+ `scripts/apply-db-revision-sequence.sh`（升级）；
  3. `db/db.go ensureUsageFactsDailyPartition`：boot 链先执行同一 ALTER 收敛存量库（幂等）+ 日期派生改 `(now() AT TIME ZONE 'Asia/Shanghai')::date`（与 tick 的 partitionTZ 同源，消除 current_date 会话时区依赖）+ 盖 751 章；
  4. 契约测试 `migration_751_test.go`（P1-P5：单 ALTER/无 SET LOCAL/无 body 重写/down 只 RESET/双通道登记顺序/Go 通道同语句/上海日期派生且禁 current_date 直传）；
  5. 真库测试 `db_751_tz_pin_realdb_test.go`：UTC 会话下 ensure → 解析 `pg_get_expr` 边界**时刻**与上海零点对齐断言（文本断言不可用：pg_get_expr 按会话时区渲染）+ 幂等二连 + 清理；
  6. `hasDailyPartition` 助手跟齐上海日历（消除 UTC 会话 16:00-24:00Z 窗口期按 UTC 日期找分区而错日）。
- **实证（本地 pg17 容器 ai-native-postgres，一次性 scratch `lgw_751_audit_scratch` 用后即删）**：
  - 750 三族真库测试（RealDB/DefaultOverlap/TZPin）全 PASS；
