### 1.3 关键启发

#### ✅ 直接借鉴
1. **多级fallback链**: 预计算top-3候选，失败时无缝降级
2. **动态权重**: 根据profile/时间/任务类型调整cost/quality/latency权重
3. **探索策略**: 加权随机选择，平衡exploitation vs exploration
4. **熔断保护**: provider连续失败后短期禁用

#### 🤔 需适配
5. **Free-tier优化**: OmniRoute聚合43个免费池，我们目前focus on付费provider
6. **区域感知**: OmniRoute强调低延迟，我们已有region字段但未充分利用
7. **流式优化**: 考虑为streaming请求单独优化模型选择

## 三、具体借鉴点

### 3.1 多级Fallback链

**OmniRoute做法**:
```typescript
// 伪代码
const fallbackChain = [
  primaryProvider,
  secondaryProvider,
  tertiaryProvider
];

for (const provider of fallbackChain) {
  if (provider.isHealthy() && provider.hasQuota()) {
    try {
      return await provider.call(request);
    } catch (error) {
      continue; // 尝试下一个
    }
  }
}
throw new Error("All providers failed");
```

**我们的实现** (P2.2设计):
```go
// routingopt/model_recommender.go

func (r *ModelRecommender) RecommendWithFallback(ctx context.Context, candidates []ModelCandidate) []ModelCandidate {
	// 1. 评分排序
	sorted := r.scoreAndSort(candidates)
	
	// 2. 预计算fallback链 (top-3)
	fallbackChain := sorted[:min(3, len(sorted))]
	
	// 3. 过滤不健康的provider
	healthy := []ModelCandidate{}
	for _, c := range fallbackChain {
		if r.isHealthy(ctx, c.Provider) {
			healthy = append(healthy, c)
		}
	}
	
	return healthy
}

func (r *ModelRecommender) isHealthy(ctx context.Context, provider string) bool {
	// 检查熔断器状态
	if r.circuitBreaker.IsOpen(provider) {
		return false
	}
	
	// 检查最近5分钟成功率
	recentStats := r.performanceTracker.GetRecent(ctx, provider, 5*time.Minute)
	if recentStats.SuccessRate < 0.8 {  // 成功率<80%
		return false
	}
	
	return true
}
```

### 3.2 动态权重调整

**OmniRoute做法**:
- 用户手动选择策略 (cost-optimized / latency-optimized / quality-first)
- 每个策略预设固定权重

**我们的改进** (P2.2设计):
```go
// routingopt/model_recommender.go

func (r *ModelRecommender) getDynamicWeights(context RoutingContext) Weights {
	w := Weights{Quality: 0.4, Cost: 0.3, Latency: 0.2, Availability: 0.1}
	
	// Profile调整 (类似OmniRoute策略)
	switch context.Profile {
	case "free":
		w.Cost = 0.5      // 类似cost-optimized
	case "premium":
		w.Quality = 0.6   // 类似quality-first
	}
	
	// 🆕 时间上下文 (OmniRoute未实现)
	if context.TimeContext.IsPeakHour {
		w.Cost += 0.1  // 高峰期更注重成本
		w.Quality -= 0.1
	}
	
	// 🆕 任务类型调整 (OmniRoute的task-specialized策略)
	switch context.TaskType {
	case autoroute.TaskReasoning:
		w.Quality = 0.6   // reasoning需要高质量
		w.Latency = 0.1
	case autoroute.TaskChat:
		w.Latency = 0.4   // chat优先低延迟 (类似latency-optimized)
		w.Quality = 0.3
	}
	
	// 🆕 用户历史偏好 (OmniRoute未实现)
	if context.UserPreference != nil {
		w = w.Blend(context.UserPreference.Weights, 0.2)  // 20%用户偏好权重
	}
	
	return w
}
```

### 3.3 探索vs利用 (Exploration vs Exploitation)

**OmniRoute做法**:
- `weighted-random` 策略: 加权随机选择
- 目的: 探索新provider，避免锁定次优选择

**我们的实现** (P2.2设计):
```go
// routingopt/model_recommender.go

func (r *ModelRecommender) RecommendModel(ctx context.Context, candidates []ModelCandidate, context RoutingContext) ([]ModelCandidate, error) {
	// 1. 正常评分排序
	scored := r.scoreAndSort(candidates)
	
	// 2. ε-greedy策略 (ε=5%, 可配置)
	if rand.Float64() < r.explorationRate {
		// 探索: 从top-5中随机选择
		top5 := scored[:min(5, len(scored))]
		randomIdx := rand.Intn(len(top5))
		
		// 将随机选择的移到首位
		scored[0], scored[randomIdx] = scored[randomIdx], scored[0]
		
		// 记录探索事件
		r.metrics.IncrementExplorationCount()
	}
	// else: 利用最佳选择
	
	return scored, nil
}
```

**优势对比**:
- OmniRoute: 简单加权随机
- 我们: ε-greedy策略，可控探索率，更符合学术界最佳实践

### 3.4 Provider健康检查

**OmniRoute做法**:
- 实时监控成功率、延迟、可用性
- Dashboard展示provider健康度

**我们的借鉴** (已有基础):
```go
// 已有: autoroute/channel_quality.go (部分实现)
// P2.2增强: 熔断器模式

type CircuitBreaker struct {
	states map[string]*CircuitState
	mu     sync.RWMutex
}

type CircuitState struct {
	Status        string    // closed / open / half-open
	FailureCount  int
	LastFailureAt time.Time
	OpenUntil     time.Time
}

func (cb *CircuitBreaker) RecordFailure(provider string) {
	cb.mu.Lock()
	defer cb.mu.Unlock()
	
	state := cb.getOrCreateState(provider)
	state.FailureCount++
	state.LastFailureAt = time.Now()
	
	// 连续失败5次 → 打开熔断器 (禁用provider 5分钟)
	if state.FailureCount >= 5 {
		state.Status = "open"
		state.OpenUntil = time.Now().Add(5 * time.Minute)
		log.Warn("circuit breaker opened", "provider", provider)
	}
}

func (cb *CircuitBreaker) IsOpen(provider string) bool {
	cb.mu.RLock()
	defer cb.mu.RUnlock()
	
	state, ok := cb.states[provider]
	if !ok {
		return false
	}
	
	if state.Status == "open" {
		if time.Now().After(state.OpenUntil) {
			// 尝试half-open (允许一次探测)
			state.Status = "half-open"
			state.FailureCount = 0
			return false
		}
		return true
	}
	
	return false
}
```

## 四、不适用的OmniRoute特性

### 4.1 Free-tier聚合
**OmniRoute**: 核心卖点是聚合43个免费池，每月~1.53B免费tokens

**结论**: 暂不借鉴，但可预留扩展点

### 4.2 压缩优化 (RTK + Caveman)
**OmniRoute**: 通过压缩节省15-95%的tokens  
**我们**: 已有streaming和token优化，压缩不在P2.2范围

**结论**: 独立特性，不纳入路由优化

### 4.3 290+ Provider聚合
**OmniRoute**: 支持290个AI提供商  
**我们**: 当前~10-20个主流provider，够用

**结论**: 扩展性已足够，不需要跟进
