## 🎯 核心改进

### 问题解决

**原问题**：
- `session_turns.cost_usd` 与 `credit_ledger.amount` 在不同代码路径
- 计费失败可能导致数据不一致

**解决方案**：
```
旧逻辑：ChargeRequestMultimodalWithMultiplier（同步，3-5ms）
  ├─ 计算积分 + 扣减钱包（DB事务）
  └─ 返回积分 → 写入telemetry

新逻辑：
  ├─ CalculateCredits（同步，1-2ms，内存操作）
  ├─ 写入telemetry（cost_usd和credits_charged同时写入）✅
  └─ DeductCredits（异步goroutine，失败自动重试）
```

### 技术亮点

1. **数据一致性**：cost_usd 和 credits_charged 在同一代码路径、同一次写入
2. **性能提升**：计费延迟降低 60-70%（3-5ms → 1-2ms）
3. **失败容忍**：扣减失败不影响请求完成，自动重试
4. **幂等性保证**：request_id级别锁，重复调用安全
5. **可观测性**：完整的监控指标和告警规则

### 1. 钱包余额延迟（1-5秒）

**现象**：积分立即记录，钱包异步更新  
**影响**：用户查询余额时可能看到"还没扣"  
**缓解**：P0-1预检使用预估成本，不受影响

### 2. 永久失败任务

**现象**：超过10次重试后标记为failed  
**影响**：需人工介入处理  
**缓解**：监控告警（failed_count > 100 → P2告警）
