## 🔧 技术细节速查

### Worker配置

**启动位置**: `cmd/gateway/main.go:3412-3425`

**配置参数**:
- 扫描间隔: 5分钟（硬编码）
- 批大小: 100（硬编码）
- 上下文: `context.Background()`
- 启动条件: `maasSvc != nil && maasSvc.Enabled()`

**工作原理**:
1. 每5分钟扫描一次`billing_retry_queue`
2. 筛选条件: `status='pending' AND next_retry_at <= NOW()`
3. 批量拉取100条任务
4. 对每条调用`maasSvc.DeductCredits()`
5. 成功 → `status='completed'`
6. 失败 → `attempts++`，计算下次重试时间（指数退避）
7. 达到`max_attempts` → `status='failed'`

### 重试策略

**退避算法**: 指数退避
- 第1次失败: 1分钟后重试
- 第2次失败: 2分钟后重试
- 第3次失败: 4分钟后重试
- ...
- 最多重试: 10次（`max_attempts=10`）

**幂等性保证**:
- 使用`request_id`作为唯一键
- 重复扣减会被`credit_ledger`的唯一约束拒绝
- Worker会正确处理"已扣减"的情况

### 数据库Schema

**核心表**: `billing_retry_queue`

**关键列**:
- `request_id`: 业务唯一键（NOT NULL）
- `status`: 'pending' | 'retrying' | 'completed' | 'failed'
- `attempts`: 已重试次数（默认0）
- `next_retry_at`: 下次重试时间（默认NOW()）

**核心索引**:
- `idx_billing_retry_queue_pending`: Worker扫描索引
  - 包含WHERE条件，只索引pending/retrying记录
  - 覆盖索引: (next_retry_at, status)

## 🚨 已知风险与缓解措施

### 风险1: Worker启动失败

**触发条件**: MaaS未正确配置或数据库连接失败

**症状**: 日志中没有"billing retry worker started"

**缓解措施**:
- 部署前检查: `grep "maas credits billing enabled" gateway.log`
- 部署后检查: `grep "billing retry worker started" gateway.log`
- 如果未启动: 检查数据库连接和MaaS配置

### 风险2: 一致性覆盖率下降

**触发条件**: 计算积分逻辑失败或telemetry写入失败

**症状**: `credits_charged` IS NULL 比例上升

**缓解措施**:
- 实时监控覆盖率
- P2告警: 覆盖率 < 95% (1小时)
- 回滚计划: 恢复旧逻辑

### 风险3: 重试队列积压

**触发条件**: Worker处理速度 < 任务生成速度

**症状**: `SELECT COUNT(*) FROM billing_retry_queue WHERE status='pending'` 持续增长

**缓解措施**:
- P3告警: 积压 > 1000
- 临时措施: 增加Worker实例或批大小
- 长期措施: 优化扣减性能
