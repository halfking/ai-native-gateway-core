### ✅ V21: DetectSessionDrift 死代码修复

**问题**: `DetectSessionDrift()` 已定义但从未调用，导致软任务漂移（chat→code 无工具）无法检测

**修复文件**: `autoroute/session_intent_cache.go`

**修复内容**:
1. 新增 `inferTaskFromSignals()` 函数，从信号推断任务类型
2. `shouldReclassify()` 中调用 `DetectSessionDrift(cached, inferredTask)`
3. 仅当 `inferredTask != ""` 时调用，避免纯文本提示的误判

**代码变更**:
```go
// 新增函数
func inferTaskFromSignals(sigs ClassificationSignals) TaskType {
    if sigs.HasImages {
        return TaskVision
    }
    if sigs.EstimatedTokens > 50_000 {
        return TaskLongContext
    }
    if sigs.ToolCount >= 3 && sigs.HasToolResults {
        return TaskAgent
    }
    if sigs.ToolCount > 0 {
        return TaskAgent // 轻量阈值用于漂移检测
    }
    return "" // 无强信号时禁用漂移检测
}

// shouldReclassify 中新增
inferredTask := inferTaskFromSignals(sigs)
if inferredTask != "" && DetectSessionDrift(cached, inferredTask) {
    return true
}
```

**测试结果**:
```bash

```

### ✅ V23: Circuit 写入延迟修复

**问题**: Auth/RateLimit 等错误需等待 Circuit OPEN 才写 DB，导致跨实例传播延迟 3×RTT

**修复文件**: `domains/streaming/executors/executor.go:2648-2674`

**修复内容**:
将 `KindAuth` 和 `KindAuthRevoked` 加入立即写入白名单（原仅 Quota 类）

**代码变更**:
```go
func (e *Executor) shouldWriteCredentialStateOnConfirmedFailure(...) bool {
    if !shouldWriteCredentialState(kind) {
        return false
    }
    // V23 fix: Auth/Quota 立即写，无需等 Circuit OPEN
    switch kind {
    case errorsx.KindQuota, errorsx.KindQuotaBalance, 
         errorsx.KindQuotaPeriodic, errorsx.KindQuotaPermanent,
         errorsx.KindAuth, errorsx.KindAuthRevoked:  // ← 新增
        return true
    }
    // 其他错误仍需 Circuit OPEN 确认
    if e.Circuit == nil {
        return true
    }
    b := e.Circuit.GetOrCreate(providerID, credentialID)
    state := b.State()
    return state == credential.StateOpen || state == credential.StateQuarantined
}
```

**测试结果**:
```bash
ok  	github.com/kaixuan/llm-gateway-go/domains/streaming/executors	3.881s
```

**影响**:
- Auth 失败立即写 DB → 30s 内跨实例传播（通过 candidate cache 失效）
- 原需 3 次失败 → Circuit OPEN → 写 DB，现首次失败即写

### ✅ V27: LiveFilter Prometheus 暴露

**问题**: V17 添加了 `liveFilterTotal` / `liveFilterFailed` 原子计数器，但未注册 Prometheus

**修复文件**: `autoroute/metrics.go`

**修复内容**:
1. 将 `int64` 原子计数器改为 `prometheus.Counter`
2. 新增 `registerLiveFilterMetrics()` 函数
3. `init()` 中调用注册
4. 移除未使用的 `sync/atomic` 导入
5. 删除 `LiveFilterStats()` 函数（不再需要）

**代码变更**:
```go
var (
    liveFilterTotal  prometheus.Counter
    liveFilterFailed prometheus.Counter
)

func registerLiveFilterMetrics() {
    liveFilterTotal = prometheus.NewCounter(
        prometheus.CounterOpts{
            Name: "llmgw_autoroute_live_filter_total",
            Help: "Total live availability filter operations.",
        },
    )
    liveFilterFailed = prometheus.NewCounter(
        prometheus.CounterOpts{
            Name: "llmgw_autoroute_live_filter_failed",
            Help: "Failed live filter operations (fell back to snapshot).",
        },
    )
    prometheus.MustRegister(liveFilterTotal, liveFilterFailed)
}

func init() {
    registerRoutingMetrics()
    registerLiveFilterMetrics()  // ← 新增
}
```

### ✅ V24: Pool.RecordSuccess 重置 drainingSince

**问题**: `drainingSince` 未在 Degraded→Active 转换时清零，可能导致池恢复后立即判定 grace period 过期

**修复文件**: `pool/pool.go:274-284`

**修复内容**:
使用 `CompareAndSwap` 确保原子转换并清零所有失败计数器

**代码变更**:
```go
// V24 fix: 原子状态转换 + 清零所有失败计数
if (currentState == PoolDegraded || currentState == PoolDraining) && n >= successThreshold {
    if p.state.CompareAndSwap(int32(PoolDegraded), int32(PoolActive)) ||
       p.state.CompareAndSwap(int32(PoolDraining), int32(PoolActive)) {
        p.successCount.Store(0)
        p.failCount.Store(0)
        p.drainingSince.Store(0)  // ← 确保清零
        slog.Info("pool recovered to active", ...)
    }
}
```

**测试结果**:

### ✅ V25: UnavailableReason 多原因累积

**问题**: 短路求值只返回首个失败原因，丢失完整故障链

**修复文件**: `provider/client.go:179-213`

**修复内容**:
改为累积所有原因，用 `"; "` 连接

**代码变更**:
```go
func (c *Candidate) UnavailableReason() string {
    var reasons []string
    
    if !c.Routable {
        if c.BlockReason != nil && *c.BlockReason != "" {
            reasons = append(reasons, "routing_blocked:"+*c.BlockReason)
        } else {
            reasons = append(reasons, "routing_blocked")
        }
    }
    if c.LifecycleStatus != "" && c.LifecycleStatus != "active" {
        reasons = append(reasons, "lifecycle:"+c.LifecycleStatus)
    }
    // ... (各状态检查，全部 append)
    
    if len(reasons) == 0 {
        return ""
    }
    return strings.Join(reasons, "; ")  // ← 多原因拼接
}
```

**输出示例**:
```
Before: "routing_blocked"
After:  "routing_blocked; quota:balance_exhausted; availability:cooling"
```

**测试结果**:
