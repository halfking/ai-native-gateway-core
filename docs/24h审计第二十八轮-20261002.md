## 二、本轮发现与修复落地（全部过验证门）

### A1（P1，实证修复）Responses 输入 known 输出承载型 item 同族绕过
- **发现（核心组对抗性复查+主会话亲读实锤）**：修复②只补了 reasoning，`sanitizeResponsesItem` 的 default 分支仍对已知输出承载型 item 整体 fail-open——`custom_tool_call_output`（明文 output，其兄弟 function_call_output 就在 3 行之上被处理）、`mcp_call`（arguments+output）、`web_search_call`（action.query）、`file_search_call`（queries[]/results[].text）；响应侧明确保留这些 item（ir/response_protocols.go:193），无状态回放必然以 input 形态回流。
- **修法**：input_protocols.go 补 4 个 case + 3 个专用 handler（custom_tool_call_output 走 sanitizeContent；mcp_call arguments 走 sanitizeToolValue+output 走 sanitizeContent；web_search_call action.query；file_search_call queries[]+results[].text）；sanitizeContentBlock 补 `refusal` 块型。
- **钉测承重教训（conventions §9 现行犯）**：初版钉测用 refs/占位符计数断言——变异验证（摘掉 custom_tool_call_output 分支）**仍然绿**，因为 `messageRef` 对未变更 item 也计数，计数断言钳不住"单类型退回 default"回归。重写为**每载体唯一敏感值+逐值 NotContains**，再变异 → 红，还原 → 绿。门本身写错与被测代码写错的比率再次 1:1。
- **变异验证**：input 侧摘分支→红/还原→绿；restore 侧摘 reasoning_text→红/还原→绿。
