## 1. 新表 DDL — request_context_attrs

```sql
-- Migration: request_context_attrs — 请求附属特性侧表
-- 一条请求一行，承载客户端/请求/会话扩展三类附属属性。
-- 与 request_logs 经 request_id 一对一关联，但 schema 独立演进。
-- 写入 best-effort，失败不阻塞主请求日志。
CREATE TABLE IF NOT EXISTS request_context_attrs (
    request_id       TEXT        NOT NULL,
    ts               TIMESTAMPTZ NOT NULL DEFAULT now(),
    tenant_id        TEXT        NOT NULL DEFAULT 'default',
    gw_session_id    TEXT,
    gw_task_id       TEXT,

    -- ─── 客户端信息 ───
    identity_hash      VARCHAR(64),   -- SHA-256，跨表主键（↔ client_profiles）
    virtual_client_id  VARCHAR(32),   -- "vc-" + hash[:16]
    virtual_ip         INET,          -- 10.x.x.x 派生 IP（出口伪装用）
    virtual_mac        VARCHAR(17),   -- 02:xx:xx:xx:xx:xx
    agent_name         VARCHAR(255),  -- claude-code/cursor/curl/...
    agent_type         VARCHAR(50),   -- web/cli/api/bot/mobile/unknown
    client_ip          INET,          -- 真实客户端 IP（X-Real-IP > XFF[0]）
    client_forwarded_for TEXT,        -- 完整 XFF 链
    api_key_fingerprint VARCHAR(16),  -- SHA-256(rawKey)[:16]
    api_key_id         BIGINT,
    application_id     BIGINT,
    application_code   TEXT,
    owner_user         TEXT,
    end_user_id        TEXT,
    customer_id        BIGINT,        -- application → customer 映射
    client_protocol    VARCHAR(50),   -- openai-chat/anthropic-messages/gemini-generate/openai-responses

    -- ─── 请求信息 ───
    is_retry         BOOLEAN DEFAULT FALSE,
    attempt_no       INT,             -- 网关 failover 轮次
    is_probe         BOOLEAN DEFAULT FALSE,
    origin_stage     VARCHAR(32),     -- self_check/node_probe/system_health/business/probe_*
    turn_no          INT,             -- 会话内轮次（best-effort）
    source_channel   VARCHAR(32),     -- web/api/mcp/agent
    client_request_id TEXT,           -- 客户端重试关联键

    -- ─── 会话扩展信息 ───
    project_id       TEXT,            -- X-Gw-Project-Id
    session_title    TEXT,            -- LLM 生成（投影自 session_titles/summaries）
    session_summary  TEXT,            -- LLM 生成
    task_id          TEXT,            -- = gw_task_id，冗余便于直查

    -- ─── 取证原材 ───
    fingerprint_raw  JSONB,           -- 原始指纹字段（DeviceSeed/MachineID/Runtime/OS/UA/Profile）

    CONSTRAINT request_context_attrs_pkey PRIMARY KEY (request_id)
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_rca_identity_hash  ON request_context_attrs(identity_hash);
CREATE INDEX IF NOT EXISTS idx_rca_session_turn   ON request_context_attrs(gw_session_id, turn_no);
CREATE INDEX IF NOT EXISTS idx_rca_tenant_ts      ON request_context_attrs(tenant_id, ts DESC);
CREATE INDEX IF NOT EXISTS idx_rca_customer       ON request_context_attrs(customer_id);
CREATE INDEX IF NOT EXISTS idx_rca_agent          ON request_context_attrs(agent_name);
CREATE INDEX IF NOT EXISTS idx_rca_probe          ON request_context_attrs(is_probe) WHERE is_probe = TRUE;
```

### 小 DDL（customer/project 维度）

```sql
-- applications 加 customer_id（账户=application，customer=所属客户/组织）
ALTER TABLE applications ADD COLUMN IF NOT EXISTS customer_id BIGINT;
-- session_dim 加 project_id（会话级项目维度）
ALTER TABLE session_dim ADD COLUMN IF NOT EXISTS project_id TEXT;
```

均 `IF NOT EXISTS`，可重入。

## 3. 写入站点（与 EmitRequestLogInsert 同位）

| 站点 | 文件:行 | 说明 |
|------|---------|------|
| 失败路径 | `request_log_pipeline.go:500 EmitFailure` | BuildFailureEntry 旁构造并 emit |
| 成功路径 | `handler.go:3298 recordInitialRequestLog` | 同上 |
| probe 路径 | `handler.go:3027 emitClientDisconnectProbe` | probe entry 旁构造 |
| **探针 worker** | `bg/active_probe_emitter.go` | **不写侧表**（见 §4.4 决策） |

每个站点：`entry.ApplyAttrsFromContext(ctx)` → `BuildContextAttrsEntry()` → `telemetryClient.EmitRequestContextAttrs(attrsEntry)`。

### 4.4 探针 worker（`active_probe_emitter.go`）不写侧表 — 设计决策

`bg/active_probe_emitter.go` 的 `Emit()` 入参只有 `credID/providerID/tenantID/rawModel/parentReqID/attempt/result`——
**没有 `*http.Request`，也无法用 `fillAttemptMeta`**（probe 是系统主动行为，无真实客户端 HTTP）。

强行给 probe 行填 client_ip/agent/customer/project 会得到错误的"幽灵客户端"语义。

**决策**：

1. probe 行**只**在 `request_logs` 落库 + `origin_stage='probe_*'` + `is_probe=true` 标记（已有）。
2. 触发 probe 的原始失败请求**已有**完整侧表行（含 client_ip/origin_stage=business）。分析时通过 `request_context_attrs.parent_request_id` 关联，或直接看源请求行。
3. 后续若 probe 演进到能携带原始 HTTP 上下文（如同步触发的 connect-timeout probe），可补 `EmitClientDisconnectProbe` 风格 emit。

## 4. 派生口径详解

### is_probe
```go
func isProbeOrigin(stage string) bool {
    switch stage {
    case "self_check", "node_probe", "system_health",
         "probe_direct", "probe_v2", "model_probe", "passive_probe", "manual":
        return true
    }
    return false
}
```

### turn_no（双口径）
- **best-effort 存储**：从 session 已知请求计数取（`session.TurnCount` 或等价），可能不准（并发）。
- **权威派生查询**（用于分析）：
```sql
SELECT request_id,
       ROW_NUMBER() OVER (PARTITION BY gw_session_id ORDER BY ts) AS turn_no
FROM request_context_attrs
WHERE gw_session_id = $1;
```

### attempt_no / is_retry
- attempt_no：网关 failover 时从候选执行上下文取（与 candidate_failure_logs.attempt_index 同口径，成功路径也记）。
- is_retry：客户端重试（同 client_request_id 多行）/ follow-up（FollowUpDepth>0）。

## 5. 252 验证 SQL

部署后用以下查询验证新字段正确落库（扩展自 `scripts/extract_session_test_data.sql`）：

```sql
-- 5.1 字段非空率（部署后 1 小时数据）
SELECT
    COUNT(*) AS total,
    COUNT(agent_name) FILTER (WHERE agent_name IS NOT NULL AND agent_name <> 'unknown') AS has_agent,
    COUNT(agent_type) FILTER (WHERE agent_type IS NOT NULL AND agent_type <> 'unknown') AS has_type,
    COUNT(client_protocol) AS has_protocol,
    COUNT(virtual_client_id) AS has_vcid,
    COUNT(customer_id) AS has_customer,
    COUNT(project_id) AS has_project,
    ROUND(100.0 * COUNT(identity_hash) / NULLIF(COUNT(*),0), 1) AS identity_pct
FROM request_context_attrs
WHERE ts > now() - interval '1 hour';

-- 5.2 侧表 ↔ request_logs 一致性（client_ip / origin_stage）
SELECT
    COUNT(*) FILTER (WHERE rca.client_ip::text IS DISTINCT FROM rl.client_ip::text) AS ip_mismatch,
    COUNT(*) FILTER (WHERE rca.origin_stage IS DISTINCT FROM rl.origin_stage) AS stage_mismatch,
    COUNT(*) AS checked
FROM request_context_attrs rca
JOIN request_logs rl ON rl.request_id = rca.request_id
WHERE rca.ts > now() - interval '30 minutes';

-- 5.3 按 identity_hash 聚合画像命中率（client_profiles 是否被填充）
SELECT
    COUNT(DISTINCT rca.identity_hash) AS distinct_identities,
    COUNT(DISTINCT cp.identity_hash) AS profiled_identities,
    ROUND(100.0 * COUNT(DISTINCT cp.identity_hash) / NULLIF(COUNT(DISTINCT rca.identity_hash),0), 1) AS profile_hit_pct
FROM request_context_attrs rca
LEFT JOIN client_profiles cp ON cp.identity_hash = rca.identity_hash
WHERE rca.ts > now() - interval '1 hour';

-- 5.4 agent 分布
SELECT agent_name, agent_type, COUNT(*) AS cnt
FROM request_context_attrs
WHERE ts > now() - interval '1 hour'
GROUP BY agent_name, agent_type
ORDER BY cnt DESC;
```

## 6. 实施阶段

| 阶段 | 内容 | 风险 |
|------|------|------|
| Phase 1 | 新表 DDL + 小 DDL | 低（新增表，IF NOT EXISTS） |
| Phase 2 | 提取层扩展 | 低（复用现有函数） |
| Phase 3 | 侧表写入层 | 中（触发热路径，best-effort 兜底） |
| Phase 4 | 请求性质维度 | 低（派生为主） |
| Phase 5 | 画像管线接通 | 中（事件总线 + 异步） |
| Phase 6 | 单测 + 252 验证 | — |

每阶段独立可验证，Phase 3 前 request_logs 不受影响。
