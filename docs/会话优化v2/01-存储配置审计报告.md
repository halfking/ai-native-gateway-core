# 存储配置审计报告

> 审计日期：2026-07-14
> 审计范围：`/admin/data-lifecycle` → 存储配置（StorageConfig）页面及相关后端
> 审计方法：源码静态分析 + 构建验证 + API 数据结构核对

## 1. 页面能力总览

`StorageConfig.vue`（`web/src/views/data-lifecycle/StorageConfig.vue`）提供以下功能区块：

| 区块 | 功能 | 后端端点 | 状态 |
|------|------|---------|------|
| 磁盘占用总览 | 实时磁盘使用率、附件文件数、附件总大小 | `GET /api/admin/attachments/filesystem/stats` | 可用 |
| 存储位置 | 查看/修改附件目录、路径测试 | `GET/PUT /api/admin/storage/config`、`POST .../test-path` | 可用（本地） |
| 目录迁移 | 修改目录后异步复制文件并切换 | `GET /api/admin/storage/migration-state` | 可用（本地） |
| 保留策略 | TTL 天数、单文件上限 | 同 storage/config | 可用 |
| 自动清理 | 磁盘水位告警、自动清理触发 | 同 storage/config + 后台 worker | 可用 |

**页面未展示的字段**：`storage_type`（local/oss/s3）、OSS 凭据、S3 凭据。
前端 `StorageConfig` interface 和 `StorageConfigUpdate` 请求体中
**不包含** `storage_type` / `oss_*` / `s3_*` 字段。

## 2. 后端 API 数据结构

### 2.1 响应体预留了 OSS/S3 字段

`admin/storage_config.go:35` 的 `StorageConfigResponse` 包含：

```go
StorageType           string // "local" | "oss" | "s3"
OSSEndpoint           string
OSSBucket             string
OSSAccessKeyID        string
OSSAccessKeySecret    string // 返回时脱敏
OSSBasePath           string
S3Endpoint            string
S3Region              string
S3Bucket              string
S3AccessKeyID         string
S3SecretAccessKey     string // 返回时脱敏
S3BasePath            string
S3UseSSL              bool
```

`storageConfigGet()` 会根据 `settings_kv` 中的 `storage.type` 读取 OSS/S3 配置并返回。

### 2.2 PUT 请求体也预留了对应字段

`StorageConfigUpdateRequest`（行 76）包含 `StorageType`、`OSSEndpoint` 等 `*string` / `*bool` 指针字段。

### 2.3 但 PUT handler 未处理 OSS/S3 字段

`storageConfigPut()`（行 251）只处理以下设置键：

- `storage.attachment_ttl_days`
- `storage.attachment_max_size_mb`
- `storage.disk_quota_percent`
- `storage.auto_cleanup_threshold`
- `storage.auto_cleanup_enabled`
- `storage.attachment_dir_override`（触发目录迁移）

**缺失**：`storage.type`、`storage.oss.*`、`storage.s3.*` 的写入逻辑。
即使前端发送 OSS 配置，后端也不会持久化。

## 3. 启动链路审计

### 3.1 生产启动路径（cmd/gateway/main.go:1145-1172）

```go
attachmentDir := os.Getenv("LLM_GATEWAY_ATTACHMENT_DIR")
if attachmentDir == "" {
    attachmentDir = "./data/attachments"
}
attachmentStorage, err := attachments.NewStorage(attachmentDir)
```

`NewStorage()` 固定创建 `LocalStorageBackend`，不读取 `storage.type` 设置。

### 3.2 预留但未接入的工厂方法

`domains/attachments/storage_config.go` 中存在：

- `LoadStorageConfigFromEnv()` — 从环境变量读取 `LLM_GATEWAY_STORAGE_TYPE`
- `NewStorageBackendFromConfig()` — 根据 `StorageConfig.Type` 创建对应后端
- `ValidateStorageConfig()` — 验证配置完整性

**这些函数在 main.go 中从未被调用**（grep 全仓零引用）。

### 3.3 接口热切换能力

`Storage` 结构体已支持 `SetBackend()` 热切换和 `NewStorageWithBackend()` 工厂，
但管理端没有触发后端切换的代码路径。

## 4. OSS/S3 编译验证

### 4.1 build tag 机制

| 后端 | 启用方式 | 实现文件 | stub 文件 |
|------|---------|---------|-----------|
| OSS | `-tags storage_oss` | `storage_backend_oss.go` | `storage_backend_oss_stub.go` |
| S3 | `-tags storage_s3` | `storage_backend_s3.go` | `storage_backend_s3_stub.go` |

默认构建（无 tag）使用 stub，返回 "not available" 错误。

### 4.2 带 tag 构建结果：编译失败

```bash
$ go test -tags storage_oss ./domains/attachments
# 编译错误：
# 1. OSSConfig 在 storage_backend.go 和 storage_backend_oss.go 中重复声明
# 2. *OSSStorageBackend 未实现 StorageBackend 接口
#    （Delete 签名：have Delete(string) error, want Delete(context.Context, string) error）
# 3. StorageMetadata 未定义（应为 FileMetadata）
# 4. config.Prefix 未定义（OSSConfig 无 Prefix 字段）

$ go test -tags storage_s3 ./domains/attachments
# 同类错误：
# 1. S3Config 重复声明
# 2. *S3StorageBackend 未实现 StorageBackend（缺少 Get/GetReader/SaveReader 等方法）
# 3. StorageMetadata 未定义
```

### 4.3 根因

OSS/S3 实现文件基于**旧版接口签名**编写（无 `context.Context` 参数、使用 `StorageMetadata` 而非 `FileMetadata`），
而 `storage_backend.go` 和 `storage_config.go` 后续演进时更新了接口定义，
但未同步更新 build-tag 实现文件。

### 4.4 修复清单

要让 OSS/S3 可编译，至少需要：

1. **消除类型重复声明**：将 `OSSConfig`/`S3Config` 移到 `storage_backend.go`，
   从 `storage_backend_oss.go`/`storage_backend_s3.go` 中删除。
2. **对齐 `StorageBackend` 接口**：所有方法添加 `context.Context` 首参，
   返回值匹配接口定义（`Get` 返回 `[]byte`，`GetReader` 返回 `io.ReadCloser` 等）。
3. **将 `StorageMetadata` 改为 `FileMetadata`**。
4. **对齐 `NewOSSStorageBackend` 签名**：当前 stub 接收 `*OSSConfig`，
   但 `storage_config.go:48` 传的是值类型 `OSSConfig`；需统一为指针或值。
5. **补充缺失方法**：`HealthCheck`、`GetBackendType`、`SaveReader` 等。

## 5. settings_kv 配置键

`settings/spec_storage.go` 中注册的存储相关 spec：

| Key | 类型 | 默认值 | 热重载 | 说明 |
|-----|------|--------|--------|------|
| `storage.attachment_dir_override` | string | "" | 否 | 覆盖附件目录 |
| `storage.attachment_ttl_days` | int | 30 | 是 | 保留天数 |
| `storage.attachment_max_size_mb` | int | 20 | 是 | 单文件上限 |
| `storage.disk_quota_percent` | int | 80 | 是 | 告警水位 |
| `storage.auto_cleanup_enabled` | bool | false | 是 | 自动清理开关 |
| `storage.auto_cleanup_threshold` | int | 85 | 是 | 清理触发水位 |

**注意**：`storage.type`、`storage.oss.*`、`storage.s3.*` 未在 spec 中注册，
意味着即使通过 SQL 手动写入 settings_kv，也不会出现在 spec 校验范围内。

## 6. 审计结论

| 维度 | 结论 |
|------|------|
| 本地存储管理 | 完整可用（配置、TTL、水位、清理、迁移） |
| OSS/S3 后端代码 | 存在但无法编译，接口签名过时 |
| OSS/S3 启动接入 | 未接入；main.go 硬编码本地存储 |
| OSS/S3 管理端 UI | API 预留字段，前端未展示，PUT 未处理 |

## 7. 追加风险审计

### 7.1 凭据与 URL 安全

- 响应体脱敏不等于安全存储；`settings_kv` 中的 OSS/S3 secret 必须加密存储，日志、trace、错误和审计导出不得出现明文。
- 附件 URL 若用于上游访问，必须是 HTTPS、不可枚举、可过期并可撤销的引用。管理端下载 URL 不能直接作为上游 URL。
- 任何根据客户端 HTTP URL 下载并转存的功能都必须做 scheme、host allowlist、DNS 解析和私网地址校验，避免 SSRF。
- 返回附件时应使用存储元数据中的 MIME，并设置 `Content-Disposition`、`X-Content-Type-Options: nosniff` 等响应安全头；不能仅按扩展名推断类型。

### 7.2 生命周期与一致性

- 当前本地路径、`request_logs.attachments` 和未来 OSS/S3 object 可能出现只删一侧的状态；删除必须使用可重试的 outbox/任务状态，并提供孤儿扫描。
- 热切换不能只替换进程内 backend。必须定义新旧后端的读写窗口、迁移校验、失败回滚、并发请求行为和重启后的持久状态。
- 附件 TTL 不能直接套用供应商文件 TTL。应分别记录 `stored_until`、`provider_reference_until` 和 `replayable`。

### 7.3 方案边界

本报告只证明当前代码中的本地存储与 OSS/S3 预留状态，不能证明 `files.kxpms.cn` 已存在或具备上游可达能力。
厂商字段、引用方式和模型限制见 [04-厂商标准与适配矩阵.md](./04-厂商标准与适配矩阵.md)。
