## 2. 协议适配与会话存储集成

### 2.1 多模态内容在会话中的存储策略

#### 存储原则

```
客户端请求 (任意协议)
  ↓
协议解析 (IR Converter)
  ↓
附件提取与存储 (Attachment Storage)
  ├─ 本地文件系统 (生产可用)
  ├─ OSS (待修复)
  └─ S3 (待修复)
  ↓
会话记录 (Session V2)
  ├─ session_turns (元数据 + attachment_refs)
  ├─ session_bodies (request_delta + response_delta)
  │   ├─ 原始协议消息（脱敏后）
  │   └─ 附件引用 (不含base64)
  └─ sessions (聚合统计)
  ↓
协议序列化 (IR → Provider)
  ├─ 根据目标厂商选择引用方式
  │   ├─ data: URI (base64)
  │   ├─ gateway URL (files.kxpms.cn)
  │   ├─ provider file URI (Gemini Files API等)
  │   └─ public HTTPS URL
  └─ 发送给上游
```

#### 会话V2附件字段设计

**session_turns表增强**:
```sql
ALTER TABLE gateway.session_turns ADD COLUMN IF NOT EXISTS
  attachment_count INTEGER DEFAULT 0,
  attachment_total_bytes BIGINT DEFAULT 0,
  multimodal_types TEXT[] DEFAULT '{}'; -- ['image', 'audio', 'document']
```

**session_bodies表附件引用**:
```sql
-- request_attachments和response_attachments已在现有schema中
-- 结构：[{object_key, mime_type, size_bytes, source_protocol}]
```

### 2.2 协议适配矩阵与存储

| 协议 | 多模态能力 | 会话存储策略 | 附件引用策略 |
|------|-----------|-------------|-------------|
| **OpenAI Chat/Responses** | image_url, input_audio, input_file | 存储消息增量 + 附件引用 | data URI / gateway URL / Files API |
| **Anthropic Messages** | image, document, thinking | 存储content blocks + 附件引用 | base64 / URL / Files API |
| **Gemini** | inlineData, fileData | 存储parts + file_uri映射 | Gemini Files API (优先) / inline data |
| **GLM** | image (OpenAI-like) | 存储消息 + private fields | data URI / URL (model-specific) |
| **MiniMax** | image (dual protocol) | 存储消息 + bot_setting | data URI / URL |
| **DeepSeek** | image (v3+) | 存储消息 + reasoning_content | data URI / URL |
| **Qwen** | image/audio/video | 存储消息 + DashScope fields | data URI / URL (endpoint-specific) |
| **Ollama** | image (model-dependent) | 存储消息 + options | data URI (本地模型) |
| **Doubao** | image (model-specific) | 存储消息 + plugins | data URI / URL |

### 2.3 附件生命周期管理

#### 写入流程
```go
// 1. 请求到达 → 协议解析
parsedRequest := ir.ParseRequest(rawRequest, protocol)

// 2. 提取附件
attachments := extractAttachments(parsedRequest)
for _, att := range attachments {
    // 存储到附件系统
    objectKey := attachmentStorage.Store(att.Data, att.MIME)

    // 替换消息中的base64为引用
    replaceWithReference(parsedRequest, att, objectKey)
}

// 3. 写入会话V2
sessionWriterV2.Write(ctx, &ProcessedRequest{
    RequestBody: parsedRequest.Messages, // 已脱敏
    RequestAttachments: extractAttachmentRefs(attachments),
    // ... 其他字段
})

// 4. 序列化到目标协议
targetRequest := ir.SerializeRequest(parsedRequest, targetProvider)
// 根据目标厂商能力选择引用方式
applyProviderAttachmentStrategy(targetRequest, targetProvider)
```

#### 读取流程
```go
// 1. 从会话V2读取
turn := sessionCache.GetTurn(ctx, requestID)
bodies := bodiesWriter.GetBodies(ctx, sessionID, turnNo)

// 2. 重建消息（附件为引用）
messages := bodies.RequestDelta

// 3. 根据需要加载附件
if needFullContent {
    for _, ref := range bodies.RequestAttachments {
        data := attachmentStorage.Load(ref.ObjectKey)
        injectAttachment(messages, ref, data)
    }
}
```

## 3. 原厂协议适配规则

### 3.1 协议边界

引用自 `docs/格式转换/03-原厂协议适配.md`:

| 原厂/家族 | 协议类型 | 工具能力 | 多模态能力 | 会话存储注意事项 |
|-----------|---------|---------|-----------|----------------|
| OpenAI | native/bridge | tool_calls | image/audio/file 子集 | 存储完整message结构 |
| Anthropic | native/bridge | tool_use/tool_result | image/document/thinking | 保留content blocks顺序 |
| Gemini | native | functionCall/Response | image/audio/video/document | 保存file_uri映射关系 |
| DeepSeek | OpenAI-compatible | OpenAI shape + reasoning | 不自动获得vision | 保留reasoning_content |
| GLM | OpenAI-compatible | OpenAI shape | model-specific | 保留web_search/retrieval |
| MiniMax | dual (OpenAI/Anthropic) | tool_call_id兼容 | model/endpoint specific | 保留bot_setting/plugins |
| Qwen | OpenAI-compatible | OpenAI-like | shape varies | 保留DashScope私有字段 |
| Ollama | OpenAI-compatible/native | OpenAI-like or native | model-dependent | 保留options/format |
| Doubao | OpenAI-compatible | OpenAI-like | model/endpoint specific | 保留plugins/bot_id |

### 3.2 多模态Canonical映射

引用自 `docs/格式转换/04-多模态转换.md`:

| IR Block | OpenAI | Anthropic | Gemini | 会话存储格式 |
|----------|--------|-----------|--------|-------------|
| text | string/input_text | text | part.text | 直接存储 |
| image | image_url/input_image | image source | inlineData/fileData | 引用 (object_key) |
| audio | input_audio | provider-specific | inlineData/fileData | 引用 (object_key) |
| video | endpoint-specific | unsupported | inlineData/fileData | 引用 (object_key) |
| document | input_file | document block | inlineData/fileData | 引用 (object_key) |
| tool call | tool_calls | tool_use | functionCall | 直接存储 |
| tool result | tool | tool_result | functionResponse | 直接存储 |
| thinking | reasoning/fields | thinking | thought | 直接存储 |

### 3.3 Source处理规则

引用自 `docs/格式转换/04-多模态转换.md`:

1. **base64**: 提取并存储，消息中保留引用
2. **URL/file URI**:
   - 公网URL: 根据目标厂商决定是否下载
   - Provider URI: 保留映射，不作为通用URL
   - Gateway URL: 存储object_key映射
3. **MIME**:
   - 保存declared_mime和sniffed_mime
   - 冲突时拒绝或隔离
4. **document**:
   - 必须保留document source
   - 不降级为文本占位符

### 5.2 厂商适配引用策略

引用自 `docs/会话优化v2/04-厂商标准与适配矩阵.md`:

```go
type AttachmentReferenceMode string

const (
    RefModeDataURI       AttachmentReferenceMode = "data"           // base64 data URI
    RefModeGatewayURL    AttachmentReferenceMode = "gateway_url"   // files.kxpms.cn
    RefModeProviderFile  AttachmentReferenceMode = "provider_file" // 厂商Files API
    RefModePublicURL     AttachmentReferenceMode = "public_url"    // 公网HTTPS URL
)

// 根据目标厂商选择引用方式
func SelectReferenceMode(targetProvider string, attachment *AttachmentRef) AttachmentReferenceMode {
    switch targetProvider {
    case "gemini":
        // Gemini优先使用Files API
        if attachment.ProviderFileID != "" {
            return RefModeProviderFile
        }
        return RefModeDataURI

    case "anthropic":
        // Anthropic支持base64和URL
        if attachment.SizeBytes > 5*1024*1024 { // >5MB
            return RefModeGatewayURL
        }
        return RefModeDataURI

    case "openai":
        // OpenAI支持URL和data URI
        if attachment.MIMEType == "image/png" || attachment.MIMEType == "image/jpeg" {
            return RefModeGatewayURL
        }
        return RefModeDataURI

    default:
        // 默认使用data URI (兼容性最好)
        return RefModeDataURI
    }
}
```

### 5.3 URL可达性约束

引用自 `docs/会话优化v2/04-厂商标准与适配矩阵.md`:

1. **Gateway URL要求**:
   - 必须从上游网络可达
   - 不依赖Cookie/内网DNS/登录态
   - 使用随机不可猜测的file ID
   - 支持HTTPS和正确的Content-Type

2. **签名URL**:
   - 需要鉴权时使用短时签名
   - TTL覆盖上游重试窗口
   - 不写入长期日志

3. **SSRF防护**:
   - 验证scheme、host allowlist
   - 验证响应MIME
   - 防止内网探测

## 6. 数据流完整链路

### 6.1 请求处理流程

```
1. 客户端请求到达
   ↓
2. 协议识别 (OpenAI/Anthropic/Gemini/...)
   ↓
3. IR解析 (internal/ir/parse_*.go)
   ├─ 提取消息
   ├─ 提取工具调用
   └─ 提取多模态内容
   ↓
4. 附件提取与存储
   ├─ 识别base64/URL/file URI
   ├─ 存储到AttachmentStorage
   ├─ 生成object_key
   └─ 替换消息中的引用
   ↓
5. 会话管理
   ├─ SessionCache查询上轮消息
   ├─ SubmitModeDetector检测提交模式
   ├─ 计算request_delta
   └─ 提取attachment_refs
   ↓
6. 双写机制 (DualWriter)
   ├─ V1Writer → request_logs (主写)
   │   └─ 包含脱敏后的消息
   └─ V2Writer → sessions + session_turns + session_bodies (副写)
       ├─ session_turns (元数据 + attachment_count)
       ├─ session_bodies (delta + attachment_refs)
       └─ sessions (异步聚合)
   ↓
7. 上游转换
   ├─ IR → 目标协议 (internal/ir/serialize_*.go)
   ├─ 根据目标厂商选择附件引用方式
   └─ 应用厂商特定Extensions
   ↓
8. 发送给上游
```

### 6.2 响应处理流程

```
1. 上游响应到达
   ↓
2. 协议解析 (internal/ir/parse_*_stream.go)
   ├─ 解析流式事件或完整响应
   ├─ 提取生成内容
   ├─ 提取工具调用
   └─ 提取多模态输出（如有）
   ↓
3. 附件提取（响应中的）
   ├─ 如音频输出、图片输出等
   └─ 存储并生成引用
   ↓
4. 会话V2写入
   ├─ 更新session_turns (completion_tokens等)
   ├─ 写入session_bodies (response_delta)
   └─ 更新sessions (异步聚合)
   ↓
5. 返回给客户端
   └─ 协议转换回客户端格式
```
