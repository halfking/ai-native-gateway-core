## 核心结论

### 1. 附件存储：本地目录 = 生产可用，OSS/S3 = 代码预留但不可编译

| 能力 | 状态 | 说明 |
|------|------|------|
| 本地文件系统存储 | **生产可用** | 启动时自动初始化，支持目录配置、TTL、自动清理、目录迁移 |
| 阿里云 OSS | **代码预留，无法编译** | `storage_oss` build tag 下类型冲突、接口签名不匹配 |
| AWS S3 / MinIO | **代码预留，无法编译** | `storage_s3` build tag 下同类编译错误 |

**关键事实**：即使运维在后台页面配置了 `storage_type=oss` 并填入 OSS 凭据，
运行时的附件存储后端**仍然是本地文件系统**。
`cmd/gateway/main.go:1157` 固定调用 `attachments.NewStorage(attachmentDir)`，
不会根据 `storage.type` 设置创建 OSS/S3 后端。

### 2. 多模态跨协议转换：Phase 1 修复已完成

OpenAI ↔ Anthropic 双向转换中的图片丢失/降级问题已修复并通过全量测试。
详见 [02-多模态能力审计报告.md](./02-多模态能力审计报告.md)。

### 3. 厂商适配：不能使用单一 URL 策略

各厂商对图片、音频、文档的字段、文件引用和可访问性要求不同。
`files.kxpms.cn` 可以作为网关存储和管理入口，但不能无条件作为所有上游的输入引用。
必须根据目标供应商和模型能力选择 data URL、可达 HTTPS URL、供应商 Files API 或拒绝请求。
详见 [04-厂商标准与适配矩阵.md](./04-厂商标准与适配矩阵.md)。
