## 3. 配置来源与优先级

### 3.1 Goal Retry 配置

**当前实际行为**（2026-07-23 前）：

```
启动时:
  1. 读取 LLM_GATEWAY_GOAL_COST_MODE 或推断模式
  2. 加载对应 preset
  3. 构造固定 ModeConfig
  4. 个别 env var 覆盖（MAX_RETRY 等）

运行时:
  1. streaming handler 直接读取 settings.Global
  2. 仅读取 goal.cost_mode，不读取其他 goal.* 配置
  3. 与启动配置来源分裂
```

**修正后行为**（2026-07-23）：

```
启动时:
  1. 仍推断默认 mode 作为 fallback
  2. 构造 resolver，不固化配置

运行时:
  1. 每个请求解析一次租户 goal.cost_mode
  2. 加载对应 preset
  3. 叠加租户级显式覆盖（goal.max_retry_count 等）
  4. 生成请求级不可变 policy
  5. retry loop 使用该 policy
```

### 3.2 配置优先级

```
1. 租户显式配置（settings 表，tenant scope）
   - goal.max_retry_count
   - goal.retry_total_timeout_seconds
   - goal.retry_on_error
   
2. Cost Mode Preset（由 goal.cost_mode 选择）
   - minimal: 2 retries, 40s
   - balanced: 3 retries, 50s
   - aggressive: 5 retries, 120s

3. 平台级默认（settings spec default）
   - goal.cost_mode = "minimal"
   
4. 硬编码 fallback（registry 不可用时）
   - minimal preset
```

## 4. 数据库 Schema 清单

```sql

gateway.sessions (
  session_id, tenant_id, client_id, state,

  session_id, turn_no, partition_date,

  has_request_delta, has_response_delta,
  has_request_attachments, has_response_attachments,

  session_id, turn_no, partition_date,
  tenant_id, request_delta, response_delta,

gateway.session_turn_logs (
  session_id, turn_no, partition_date,
  tenant_id, provider_id, credential_id,
  raw_model, latency_ms, error_message, created_at
)
```
