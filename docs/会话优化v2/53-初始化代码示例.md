## 4. 完整示例

```go
func initSessionCompressor(
    db *pgxpool.Pool,
    redisAddr string,
    disableCompression bool,
) *compression.SessionCompressor {
    
    // ── V1 Components (existing) ──────────────────────────────
    sessionCache := compression.NewSessionCache(db, redisAddr)
    
    compactionDeps := &compression.Dependencies{
        // ... existing compaction dependencies ...
    }
    
    // ── V2 Components (new) ───────────────────────────────────
    turnReader := v2.NewTurnReader(db)
    outboundBuilder := v2.NewOutboundBuilder(turnReader)
    sessionCacheV2 := v2.NewSessionCacheV2(db, redisAddr)
    
    // ── Create SessionCompressor ──────────────────────────────
    return compression.NewSessionCompressor(compression.SessionCompressorDeps{
        Cache:          sessionCache,      // V1 fallback
        CacheV2:        sessionCacheV2,    // V2 primary
        Builder:        outboundBuilder,   // V2 builder
        CompactionDeps: compactionDeps,
        Disabled:       disableCompression,
    })
}
```

## 5. 配置说明

### 环境变量

```bash
# Redis 地址
REDIS_ADDR=localhost:6379

# 禁用压缩（可选）
LLM_GATEWAY_SESSION_COMPRESSOR_DISABLE=false
```

### Feature Flag

V2 功能默认是**关闭**的，需要通过配置中心或数据库启用：

```sql
-- 在 settings 表中启用 V2
INSERT INTO settings (key, value, scope, tenant_id) 
VALUES ('sessions_v2_compression_read', 'true', 'tenant', 'default')
ON CONFLICT (key, tenant_id) 
DO UPDATE SET value = 'true';
```

或通过 API：

```bash
curl -X POST http://localhost:8080/api/admin/settings \
  -H "Content-Type: application/json" \
  -d '{
    "key": "sessions_v2_compression_read",
    "value": true,
    "tenant_id": "default"
  }'
```

## 6. 验证

### 检查日志

启用 V2 后，应该能看到以下日志：

```
INFO  session_compressor: using v2 cache session=gw_xxx tenant=default
INFO  session_compressor: v2 cache loaded successfully session=gw_xxx body_size=1234
```

如果 V2 失败，会看到 fallback 日志：

```
WARN  session_compressor: v2 cache failed, falling back to v1 session=gw_xxx
```

### 检查 Redis

V2 缓存使用的 key 格式：

```bash
redis-cli keys "session:v2:*"

# 示例输出：
# session:v2:default:gw_abc123
# session:v2:tenant-prod:gw_xyz789
```

## 7. 故障排查

### V2 未生效

**症状**: 日志中看不到 "using v2 cache"

**可能原因**:
1. Feature Flag 未启用
2. V2 组件未正确初始化
3. CacheV2 或 Builder 为 nil

**解决方法**:
```go
// 检查组件是否正确初始化
if compressor.deps.CacheV2 == nil {
    log.Fatal("CacheV2 is nil")
}
if compressor.deps.Builder == nil {
    log.Fatal("Builder is nil")
}
```

### V2 频繁 fallback

**症状**: 日志中频繁出现 "v2 cache failed, falling back to v1"

**可能原因**:
1. Redis 不可用
2. 数据库连接问题
3. session_turns 或 session_bodies 表数据不完整

**解决方法**:
1. 检查 Redis 连接
2. 检查数据库连接
3. 查看详细错误日志

## 8. 性能监控

### 添加 Prometheus 指标（可选）

```go
var (
    v2CacheHits = prometheus.NewCounter(prometheus.CounterOpts{
        Name: "session_compressor_v2_cache_hits_total",
        Help: "Total number of V2 cache hits",
    })
    
    v2CacheMisses = prometheus.NewCounter(prometheus.CounterOpts{
        Name: "session_compressor_v2_cache_misses_total",
        Help: "Total number of V2 cache misses",
    })
    
    v2Fallbacks = prometheus.NewCounter(prometheus.CounterOpts{
        Name: "session_compressor_v2_fallbacks_total",
        Help: "Total number of V2 fallbacks to V1",
    })
)

func init() {
    prometheus.MustRegister(v2CacheHits)
    prometheus.MustRegister(v2CacheMisses)
    prometheus.MustRegister(v2Fallbacks)
}
```
