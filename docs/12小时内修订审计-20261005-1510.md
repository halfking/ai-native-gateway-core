### L2.1 这不是设计取舍，是四轮审计的病根

### L2.2 改法

引入失败收集器，退出码语义不变：

| 情形 | 改前 | 改后 |
|---|---|---|
| 有 clobber 违规 | 立即 `exit 5`，其它失败看不见 | 全部报出，`exit 5` |
| 有任意其它失败 | 首个失败点 `exit 1` | 全部报出，`exit 1` |
| 全通过 | 0 | 0 |

**故意保留立即退出的两类**：

1. `scripts/apply-db-revision-sequence_test.sh:346`（提取 clobber 块失败）、
   `:355`（提取 chains 失败）、`:397`（提取 replays 失败）——
   锚点漂移意味着**后续判据全部不可信**，那是「观测手段坏了」，
   不是「被观测对象有问题」，两者处置方向相反。
2. 门自身的自测失败（`:87`、`:91` 等）——判据失效必须立刻停。

## 六、给下一轮的三条方法论提醒

1. **「门只报一条」≠「只有一条问题」，而且这条病根是可以直接修掉的。**
   本轮把 17 个 `exit 1` 改成收集后一次报出，并让端到端一次吐出 12 条。
   ⇒ 下轮若再遇到「只红一条」，先怀疑**观测手段的完整度**，而不是直接开修。

2. **负控必须在「旧行为的形状」上做，不是在「某个可疑 token」上做。**
   把 `return $found` 改成 `return 1` 也算变异，但它让 helper 恒失败，
   脚本在第一处**裸调用**下 `set -e` 静默死掉，新断言从未执行。
   **红 ≠ 负控有效**；要看红在哪一行、是不是被目标断言抓到的。
   ⇒ 变异要落在**循环体内**（旧代码正是那里 `return 1`）。

3. **裸调用 + `set -e` = 静默死。** 门里 `:77` 那处裸调用本轮实测会
   无输出地退出。本机已有先例：`make guards` 是采集失败不是门红、
   `bash` 不在 PATH 是假红、PowerShell `>` 产出 UTF-16LE 让 `git apply` 拒绝。
   ⇒ 同一族：**观测手段失败与被观测对象不合格，输出可以完全一样。**

4. **★ 负控必须落在被测判据覆盖的那条路径上——「变异成功」≠「变异命中目标」。**
   `hook.go` 有两个 `appendBacklog(`（`:181` semaphore_full、`:280` write_failed）。
   我按「第一个 `appendBacklog(`」注入 M-S1，打中的是 `:280`，
   **信号量判据根本没被触碰，测试照样全绿**。
   若就此收工，就会把绿灯写成「M-S1 已验证」——比「包编译不过就冒充阴性对照」
   更隐蔽，因为它连报错都没有。
   ⇒ 注入后**必须读一眼变异文件的目标行**，确认打中的是你以为的那一处；
   锚点用**语义**（先定位 `EnqueueMirrorFailure(..., "semaphore_full")`）
   而不是**字面首次出现**。
