### 2.2 档位划分建议

#### **Free 档位** (相对价格: 100)
- **模型**: minimax-m2系列基础版本
- **内部结算价**: 100 (基准)
- **对外定价**: 免费或极低价
- **用途**: 吸引新用户、验证概念、开发测试
- **利润策略**: 导流工具,不追求利润

#### **Basic 档位** (相对价格: 100-500)
- **模型**: minimax-m2-highspeed, claude-haiku系列
- **内部结算价**: 100-500
- **建议倍率**: 原厂价 × 1.2-1.3 (20-30% 毛利)
- **用途**: 日常轻量任务、高频简单场景
- **利润策略**: 小额高频,依靠规模盈利

#### **Standard 档位** (相对价格: 500-1500)
- **模型**: gpt-5.3-codex, claude-sonnet系列
- **内部结算价**: 500-1500  
- **建议倍率**: 原厂价 × 1.3-1.5 (30-50% 毛利)
- **用途**: 主力商业应用、内容创作、代码生成
- **利润策略**: 业务核心,平衡价格与能力

#### **Premium 档位** (相对价格: 1500+)
- **模型**: claude-opus系列, claude-fable-5
- **内部结算价**: 1500-4000
- **建议倍率**: 原厂价 × 1.5-1.8 (50-80% 毛利)
- **用途**: 高难度任务、企业级应用、关键决策
- **利润策略**: 高价值高毛利

#### **Enterprise 档位** (相对价格: 定制)
- **模型**: 按客户需求组合
- **内部结算价**: 定制方案
- **建议倍率**: 合同制,通常包含 SLA、专属支持
- **用途**: 大客户独家方案、批量预付
- **利润策略**: 锁定大客户,稳定现金流

## 四、内部结算价格实施方案

### 4.1 计算公式

```
内部结算价 = (模型原厂总价 / 基准模型总价) × 100
```

**示例**:
- `claude-opus-4-8`: ($5 + $25) / ($0.3 + $1.2) × 100 = **2000**
- `claude-haiku-4-5`: ($1 + $5) / ($0.3 + $1.2) × 100 = **400**

### 4.2 数据库映射

当前 `model_pricing` 表结构:
```sql
input_credits_per_1m  bigint NOT NULL,
output_credits_per_1m bigint NOT NULL,
tier                  varchar(16) NOT NULL  -- 档位
```

**建议映射规则**:
1. **Credits = 相对价格基数**
   - minimax-m3: input=20, output=80 (合计100)
   - claude-opus-4-8: input=333, output=1667 (合计2000)
   
2. **保持输入输出比例**
   - 原厂比例 = 输入价 / (输入价+输出价)
   - 内部输入credits = 总credits × 原厂比例
   - 内部输出credits = 总credits × (1 - 原厂比例)

3. **档位字段**
   - 按相对价格区间自动分档
   - 支持手动调整覆盖

## 五、风险与注意事项

### 5.1 价格波动风险
- ⚠️ **原厂降价**: 我们的定价可能滞后,导致失去竞争力
- ⚠️ **汇率波动**: 原厂价格多为USD,人民币定价需考虑汇率
- ⚠️ **促销活动**: 原厂临时促销我们无法同步

**缓解措施**:
1. 每月定期重新抓取原厂价格
2. 设置价格告警阈值 (原厂价变动>10%自动通知)
3. 保留快速调价的能力 (热配置,不依赖发版)

### 5.2 档位划分风险
- ⚠️ **用户降档**: 高端用户发现低档模型够用,迁移到低价
- ⚠️ **档位模糊**: 同一档位内模型能力差异大,用户困惑

**缓解措施**:
1. 能力维度也要可视化 (不只是价格)
2. 提供"最适合你"的推荐算法
3. 保留升档激励 (如高档模型赠送credits)

### 5.3 数据质量风险
- ⚠️ **快照陈旧**: 当前有5个厂商的快照被标记为 stale
- ⚠️ **解析失败**: 102条提案标记为 unusable 需人工审核
- ⚠️ **缺失供应商**: 部分重要供应商数据尚未采集

**缓解措施**:
1. 重新抓取陈旧快照
2. 人工审核 unusable 条目,改进解析规则
3. 建立供应商价格采集SOP

## 附录 B: 内部结算价格计算示例

### 示例1: Claude Opus 4-8

**原厂价格**:
- 输入: $5.00 per 1M tokens
- 输出: $25.00 per 1M tokens
- 总价: $30.00 per 1M tokens

**内部结算价计算**:
```
相对基准 = $30.00 / $1.50 × 100 = 2000
输入占比 = $5.00 / $30.00 = 16.67%
输出占比 = $25.00 / $30.00 = 83.33%

内部输入credits = 2000 × 16.67% = 333
内部输出credits = 2000 × 83.33% = 1667
```

**数据库记录**:
```sql
INSERT INTO model_pricing (
  model_canonical, 
  input_credits_per_1m, 
  output_credits_per_1m,
  tier
) VALUES (
  'claude-opus-4-8',
  333,
  1667,
  'premium'
);
```
