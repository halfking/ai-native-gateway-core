### Gemini native 丢失 OpenAI 风格工具调用

问题：`SerializeGemini` 原来只读取 `Message.Content` 中的 Anthropic `tool_use`/
`tool_result`，未处理 `Message.ToolCalls` 和 `Message.ToolCallID`。OpenAI Chat 或
Responses 经过 IR 后发送到 Gemini 时，function call 和结果会消失。

修正：

- `Message.ToolCalls` 转成 Gemini `functionCall`。
- `role=tool` + `ToolCallID` 转成 Gemini `functionResponse`。
- 保留工具名和 JSON arguments；非法 arguments 不伪造调用。
- 增加并行工具调用/工具结果模拟测试。

## 已确认但本轮不扩张

- provider-specific audio/video/document 能力必须按 model offer 验证，不能由兼容协议推断。
- Anthropic document block 当前保存为 RawContent，完整结构化 DocumentBlock 需要单独 fixture 和 serializer 审计。
- Usage modality 明细与 MaAS rate component 需要独立计费审计，不能在格式转换修复中顺手改动。
- Ollama native `/api/chat`、Qwen/DashScope 原生 endpoint 和 Doubao 聚合入口需要独立 provider profile 验收。
