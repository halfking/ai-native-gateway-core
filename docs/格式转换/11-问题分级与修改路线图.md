# 问题分级与修改路线图

## 1. 问题分级标准

| 等级 | 触发条件 | 处置 | 示例 |
|---|---|---|---|
| **P0** | 跨厂商数据丢失、工具 ID 不闭环、多模态静默降级、私有字段跨厂泄漏 | 必须立即修；阻塞晋级 | 图片降级为文本占位符、工具 result 孤儿、DeepSeek 字段泄漏到 OpenAI |
| **P1** | 单厂商字段子集缺失、流式事件个别类型未识别、纠错缺失 | 当迭代必修；非阻塞但需登记 | 缺少 GLM 多模态 fixture、未识别流式事件类型 |
| **P2** | 历史快照缺失、fixture 覆盖不全、文档与代码细微不一致 | 排期修复 | 旧格式兼容测试缺失、文档示例过时 |
| **P3** | 优化项、可读性、可观测性增强 | 视情况 | 日志格式优化、错误消息改进 |

## 4. 修改纪律（铁律）

### 4.1 不可妥协的边界

1. **不得删除 IR 中已声明的保留字段**
   - `Thinking`, `CacheControl`, `Documents`
   - `FrequencyPenalty`, `PresencePenalty`, `Logprobs`, `TopLogprobs`
   - `Seed`, `ResponseFormat`, `N`, `User`, `Metadata`
   - `Reasoning`, `Extensions`
   - 位置: `internal/ir/types.go`

2. **不得修改现有 parser/serializer 的公开签名**
   - `ParseOpenAIChatRequest(body []byte) (*InternalRequest, error)`
   - `ParseAnthropicRequest(body []byte) (*InternalRequest, error)`
   - `ParseGeminiRequest(body []byte) (*InternalRequest, error)`
   - `SerializeOpenAI(ir *InternalRequest, target TargetProvider) ([]byte, error)`
   - `SerializeAnthropic(ir *InternalRequest, target TargetProvider) ([]byte, error)`
   - `SerializeGemini(ir *InternalRequest) ([]byte, error)`

3. **不得改变现有 fixture 行为预期**（除非该 fixture 标记为 outdated）
   - 所有 `*_test.go` 中的 golden test 必须保持通过
   - 新增 fixture 不能破坏现有测试

4. **不得在格式转换修复中顺手改动 usage modality 计费**
   - 计费逻辑属独立模块，不在本任务范围

5. **新增能力必须走"IR + Extensions + 同厂同协议恢复"三件套**
   - 新增字段先在 IR 保留
   - 不可映射的字段进 Extensions
   - 恢复时检查 source/target protocol + provider catalog

6. **多模态：fail closed，不静默降级**
   - 不支持的 MIME 必须返回错误或 loss report
   - 不能把 image 转成 `[Image: ...]` 文本占位符
   - 不能把 document 转成普通 text

7. **工具 ID：闭环校验，孤儿 result 必须 fail**
   - `assistant tool_call_id` 必须与 `tool message tool_call_id` 一一对应
   - 孤儿 result 必须被 `validateToolCallIntegrity` 检测并拒绝

8. **私有字段：跨厂必须隔离，不得泄漏**
   - DeepSeek 私有字段不能发送给 OpenAI
   - GLM 私有字段不能发送给 Anthropic
   - Extensions 恢复必须检查 `source.provider == target.provider && source.protocol == target.protocol`
