# 模拟测试与发布门禁

## 最小 fixture 集

每个协议和 provider profile 至少需要：

1. text request/response。
2. system/instructions。
3. image base64、image URL/file URI。
4. audio、video、document（若 model capability 声明支持）。
5. 单工具、并行工具、工具结果和错误结果。
6. reasoning/thinking 与 text/tool 混合。
7. stream terminal usage、finish reason、未知事件。
8. 非法 MIME、超大 payload、能力不满足和 provider error。

## Go 验证命令

```text
go test ./internal/ir
go test ./domains/transformation
go test ./domains/streaming
go test ./...
go vet ./...
```

## Round-trip 规则

- 同协议：标准字段结构相等，允许 JSON key 顺序变化。
- 跨协议：比较 canonical IR，不比较 wire JSON；所有不可映射字段必须出现在 loss report。
- 工具：assistant call ID、function name、arguments、tool result ID 必须闭环。
- 多模态：MIME、source kind、payload/reference 和内容顺序必须保留。

## 发布门禁

- 新增 provider profile 必须有 parser/serializer 或明确声明复用哪个兼容协议。
- 未通过 fixture 的字段不能加入“原厂完整支持”清单。
- 生产日志出现工具 ID mismatch、媒体丢失或 unknown block drop 时阻断晋级。
- 真实 provider canary 只使用脱敏请求，记录 endpoint、model、API version、captured_at 和 redaction version。
