## 0. 为什么单独成篇

移动端高频交互六件套里，**标题**（06）、**按钮/行点击**（03 §3.3）、**滚动**（07、12）
已有契约；**下载、导入、全屏表格**三件此前**没有任何一篇覆盖**——而它们恰是
「桌面语义直接搬到手机上会静默失败」的重灾区：

- 下载：`blob + a[download]` 在桌面浏览器是标准做法，在 Android WebView 里
  **根本不触发**（见 §2.1），且**不报任何错**；
- 导入：`input[type=file]` 在 WebView 里依赖原生宿主配合，行为不一；
- 全屏表格：iPhone Safari/WKWebView **不支持元素级 Fullscreen API**（仅 `<video>`），
  按桌面思路调 `requestFullscreen()` 的代码在主要移动宿主上是死代码。

本篇给出这三件的**移动优先契约 + 三宿主统一降级链**（§6），并明确每条契约
在本仓的现状（§1）。

## 2. 平台事实（写契约的依据；证据分级：一手 = 本仓核到官方正文/实测，二手 = 未复核）

### 2.1 下载在 WebView 上是三档可用性，不是「要么行要么不行」

| 宿主 | `a[download]` + blob | http/https 附件 URL | 说明 |
| --- | --- | --- | --- |
| 桌面浏览器 | ✅ | ✅ | 现状九处封装的目标环境 |
| Android WebView（无宿主配合） | ❌ **静默失败** | ❌（默认无 DownloadListener 则无反应） | 二手：社区与 Capacitor issue 一致（`can only download HTTP/HTTPS URIs: blob:` 是典型报错）；Capacitor 壳是否已配 DownloadListener **未实测**（V-14） |
| iOS WKWebView | ❌（<iOS 14.5 无任何回调） | ⚠️ iOS 14.5+ 需实现 `WKDownloadDelegate` 全链 | 二手：WWDC "Explore WKWebView additions"（iOS 14.5 起 `WKDownload`）；本仓壳未实现该代理（未实测） |
| 移动浏览器（Safari/Chrome） | ⚠️ Safari 对 `a[download]` 支持历史混乱；blob 下载在新版可用但体验分叉 | ✅ | 二手 |

**结论**：不能指望单一通道覆盖三宿主——必须降级链（§3）。

### 2.2 Web Share API（Level 2）是移动端「导出」的原生通道

- `navigator.canShare({ files })` 特性检测 → `navigator.share({ files })` 唤起系统分享面；
  ★ R48-D1（2026-10-06）前置门：桌面指针宿主（`matchMedia('(hover: hover) and (pointer: fine)')`）
  直接跳过本臂——`canShare` 在 Windows Chrome/Edge 与 macOS Safari 的 HTTPS 部署下返回 `true`
  （原「桌面为 false」的前提不成立），不跳过会弹系统分享面而非落下载目录；
- Android Chrome 全量支持；iOS Safari **iOS 15 起**支持分享文件；
  需要 HTTPS + 用户手势；桌面 Chrome 不支持（二级来源：MDN `Navigator.share()`、
  web.dev《Integrate with the OS sharing UI with the Web Share API》——**二手**，
  接入实现时按 09 核验纪律复核到一手兼容表）。
- 对运维前端的意义：手机上「导出一份报告」的最自然去向往往不是「文件下载器」
  而是「发到微信/邮件/笔记」——分享面即下载面的移动等价物。

### 2.3 元素级 Fullscreen API 在 iPhone 上不存在

- iPhone Safari/WKWebView：`requestFullscreen()` 对任意元素**不可用**，仅 `<video>`
  可 `webkitEnterFullscreen()`；iPad 自 iPadOS 12 起支持（二级来源：Apple Developer
  Forums、video.js issue #7834——**二手**）。
- ⇒ **CSS 全屏覆盖层（fixed + 100dvh + inert 背景）是唯一可移植到全部移动宿主的
  全屏形态**。本仓 07 §4 的 FocusWorkspace 契约与 `RequestDetailFullscreenView`
  路由级形态都不依赖 Fullscreen API——**这个设计选择被平台事实证明为正确**，
  后续实现禁止改走 Fullscreen API 路线再配「iOS 特判」。
- 横屏锁定 `screen.orientation.lock()`：Android 需在全屏（fullscreen element）上下文
  中才生效，iOS Safari **不支持**——全屏表格**不得依赖横屏锁定**；需要横向空间时
  提示用户旋转，布局按 `orientation` 媒体查询自适应（二手，接入时复核）。

### 2.4 文件选择器：WebView 里 `input[type=file]` 依赖宿主，但 Capacitor 默认桥已实现

- Android WebView 需要 `WebChromeClient.onShowFileChooser`；Capacitor 的桥
  **默认实现了**该回调（官方桥代码），`input[type=file]` 可直接弹出系统选择器——
  **二手**（未在本仓壳实测），随 V-14 一并真机取证；
- iOS WKWebView 原生支持 `input[type=file]`（iOS 11+ 文件 App / 相册）；
- `accept` 过滤与 `capture`（直接唤相机）在移动端由系统 UI 兑现，桌面忽略——
  同一控件两宿主行为不同是**特性**不是 bug，文档里写清楚即可。

### 2.5 移动端宽表的主流答案（高星项目对标）

| 项目 | 做法 | 对本仓的意义 |
| --- | --- | --- |
| Ant Design Mobile（高星，React） | **不提供 Table 组件**——移动端列表就是 List/Card | 与本仓「compact 强制卡片」（03 §2.1）同向：卡片不是降级，是移动端一等形态 |
| Vant（高星，Vue） | 无 Table；Cell 承载行交互（16 §3.1 一手核对） | 行点击契约的依据 |
| 响应式表格六模式（Smashing Magazine 两部曲 / calmops 汇总，二手） | 横滚（sticky 首列/表头）/ 卡片化 / 列裁剪 / 堆叠 / 行展开 / 优先级列 | 本仓已取两档：**卡片**（默认）+ **横滚 sticky**（存量降级）；本篇补第三档：**全屏查看**（比较型宽表的移动出口，§5） |
| Ionic | `ion-card` 列表 + `ion-modal` 全屏表单 | 全屏承载用 modal/覆盖层，不用 Fullscreen API——与 2.3 结论一致 |

## 3. 下载 / 导出契约

**[已落地]**（2026-10-05 落地轮：`web/src/utils/exportFile.ts` 为唯一实现点，
九处调用点全部改造接入；D-5 源码门禁 `exportFile.gate.test.ts` 上线——
`createObjectURL` 只允许出现在 exportFile 及其单测，绕链即红。桌面臂零回归：
③四步与旧实现逐字节等价，全量 2342 例门禁绿。★ R48-D1：桌面零回归改由「桌面指针宿主跳过 ①」保证（canShare 在部分桌面浏览器为 true，见上）。
D-2/D-3/D-4 真机矩阵待 V-14 取证，未跑前不宣称。）

### 3.1 降级链（顺序固定，逐级尝试，全程用户可见）

```
① navigator.canShare({files}) 为真（移动浏览器/iOS 15+/Android Chrome）
   → navigator.share({ files: [File] }) 唤起系统分享面（含「存储到文件」）
② 壳环境（capabilities.platform ≠ 'web'，R3）且壳提供下载桥
   → 桥写文件到应用沙盒/下载目录（插件随壳发版，能力门四步取证，见 14 §3）
③ 兜底：blob + a[download]（桌面与新版移动浏览器）
④ 全部失败 → 如实报错（toast/inline，含「当前环境不支持下载」文案），禁止静默
```

规则：

1. **链条的选择在触发时判定，不在构建时判定**——同一按钮在桌面走 ③、在手机
   浏览器走 ①、在壳里走 ②，代码路径唯一。
2. **桌面零回归**：①的判定条件 = `canShare` **且非桌面指针宿主**（R48-D1 订正：仅靠 canShare 在 Windows Chrome/Edge、macOS Safari 的 HTTPS 部署会误入分享面），桌面回落 ③，
   现有九处封装改造后桌面行为逐字节不变（改造模式：把 `downloadSessionSummaryExport`
   的四步体抽成 `exportFile(name, blob, fallbackLabel)` 单一工具，九处调用点换函数名）。
3. **后端直链是正交通道**：凡后端能直接给 `Content-Disposition: attachment` 的
   http/https URL，优先走 URL（`window.open` / 壳的下载管理器），它比 blob 多活一层
   （Android WebView 配了 DownloadListener 即可用）。新增导出端点时在 API 设计层
   优先考虑直链。
4. **失败可见**是硬要求：降级链走到头仍失败，必须出错误提示——「按钮点了没反应」
   与 03 §3.3 的死按钮同罪。
5. **大文件导出**（对账/日志类）不允许在前端拼 blob：走后端异步任务 + 轮询/通知 +
   直链下载，与 13 §5「上传进度只报告有实测字节的阶段」对称。

### 3.2 验收

| # | 用例 | 通过判据 |
| --- | --- | --- |
| D-1 | 桌面 ≥1024 点导出 | 与现状行为一致（文件落下载目录），零回归 |
| D-2 | 移动浏览器（Chrome/Safari）点导出 | 出现系统分享面或下载确认，不静默 |
| D-3 | 壳内（Android WebView）点导出 | 文件可保存且可在系统「下载/文件」应用中找到（V-14 一并取证） |
| D-4 | 断网点导出 | 如实报错，不留半截文件 |
| D-5 | 源码门禁 | 新增导出按钮不得只写 `a[download]` 单通道——源码断言：凡新建下载工具函数必须含 `canShare` 分支或注释登记「桌面专用」理由 |

## 4. 导入 / 上传契约

**[部分落地]**（桌面可用、移动未验收）

1. **选择器形态统一走 `<input type="file">` 语义**：`el-upload` 内部即此；
   新增导入面不得自造拖拽唯一入口（移动端无拖拽）。`accept` 必须写具体类型
   （`.json,.csv`），移动端由系统过滤器兑现。
2. **大小上限前置声明**：前端在**选择后、上传前**校验大小并即时拒绝，
   不把 100MB 文件推上去再等 413；上限值与后端一致（同一常量源）。
3. **进度如实**（13 §5 既有契约，重申移动侧）：`input[type=file]` 没有
   真实字节流就不要伪造百分比——用「已选择 → 上传中 → 完成」三态 + 真实
   `progress` 事件（`XMLHttpRequest.upload.onprogress`）时才出数字。
4. **失败保留现场**：上传失败不清空已选文件与已填表单，重试不重选。
5. **相机/相册**：需要拍照导入的场景用 `capture` 属性唤起，不得只提供相册路径；
   纯文件场景**不加** `capture`（否则 Android 部分机型直接开相机）。
6. **验收**：

| # | 用例 | 通过判据 |
| --- | --- | --- |
| U-1 | 壳内（Android WebView）点「导入」 | 弹出系统文件选择器（Capacitor 桥默认 `onShowFileChooser`，V-14 取证）；取消不留脏状态 |
| U-2 | 移动浏览器选超大文件 | 选择后立即拒绝并提示上限，无网络请求发出（DevTools 断言） |
| U-3 | 上传中断网 | 错误可见、现场保留、重试成功后无重复提交（幂等由后端保证，前端不重发同批） |

## 5. 全屏表格模式契约

**[未落地]**（入口不存在；两种承载形态皆有先例/契约）

「全屏表格」= compact 下把比较型宽表（列多、需要横向对照）放进一个**独占视口的
查看容器**，桌面形态完全不动。

### 5.1 承载形态二选一（按数据量与复用度）

| 形态 | 适用 | 本仓先例/契约 | 退出 |
| --- | --- | --- | --- |
| **路由级全屏视图** | 独立详情深链、可分享/收藏 | `/request-detail/:requestId`（**已验证**） | 返回键/顶栏返回，路由历史天然正确 |
| **覆盖层全屏（FocusWorkspace）** | 页内宽表的临时全屏查看，退出还原 Tab/筛选/滚动/焦点 | 07 §4 契约（未实现；web-mobile/ 已用独立全屏覆盖层落地，17 §10） | Esc/系统返回/退出钮三入口等效，退出还原状态 |

选择规则：**需要 URL 的用路由级，需要还原现场状态的用覆盖层**；两者都不得用
Fullscreen API（§2.3）。

### 5.2 全屏容器内部契约

1. **入口**：宽表工具栏「全屏查看」钮（≥48px，图标 + 文案，compact 才渲染；
   medium+ 不渲染——桌面本来就看得到全表）。
2. **sticky 表头与首列**：全屏内横滚时表头与首列钉住（`position: sticky`，
   与 `DataTable` 包裹模式同一技法）；首列右缘与表头下缘要有持续阴影提示可滚方向。
3. **列宽不自适应压缩**：`min-width` 列宽保护沿用 `DataTable` 惯例，
   宁可横滚不可挤成「3 字符列」。
4. **滚动宿主登记**：全屏容器是唯一滚动宿主，登记进滚动恢复链（07 §1）；
   覆盖层形态退出时按 07 §4 还原外层滚动位置。
5. **背景 `inert`**（覆盖层形态）：背景产品事件屏蔽；降级为焦点门（旧 WebView）。
6. **横屏**：不做 `orientation.lock`（§2.3）；布局响应 `orientation` 媒体查询，
   横屏时自动利用宽度（比如 sticky 首列之外多显示两列）。可给一次性
   「旋转查看更多列」提示（`prefers-reduced-motion` 下不出动效）。
7. **编辑**：全屏模式默认**只读查看**；「全屏表格 + 行内编辑」需要单独立项
   （表单校验/脏表单守卫与 06 §5 覆盖层守卫叠加，复杂度不成比例）。

### 5.3 验收

| # | 用例 | 通过判据 |
| --- | --- | --- |
| T-1 | compact 宽表点「全屏查看」 | 容器独占视口（地址栏可让出），表头/首列 sticky 生效 |
| T-2 | 系统返回 / Esc / 退出钮 | 三入口等效；覆盖层形态退出后 Tab/筛选/滚动/焦点全部还原（07 §4） |
| T-3 | 320px 视口进全屏 | 无横向 body 滚动；表格横滚在容器内；标题不截断（06 §2 标题优先级链） |

| T-5 | `prefers-reduced-motion` | 进出动效取消，功能不变（12 §4） |

## 6. 三宿主统一矩阵（客户端规范与 web 端规范的统一落点）

**同一动作，三种宿主，一份契约**。能力差异由 **capabilities（R3 schema）** 驱动，
不由 UA 嗅探；壳能力必须过 14 §3 能力门四步取证后才允许使用。

| 动作 | 桌面浏览器 | 移动浏览器 | 壳（Capacitor） |
| --- | --- | --- | --- |
| 下载/导出 | blob `a[download]`（③） | 分享面优先（①）→ ③ | 壳桥（②）→ ③；后端直链全程可用 |
| 导入 | `input[type=file]` | 同左（系统选择器） | 同左（桥已实现 `onShowFileChooser`，V-14 取证） |
| 全屏表格 | 不适用（桌面看全表） | CSS 覆盖层/路由级 | 同左；**禁 Fullscreen API** |
| 分享 | 复制到剪贴板 | `navigator.share`（文本/URL） | 同左或壳分享插件（能力门取证后） |
| 打开外链 | 新标签 | 系统浏览器接管 | `allowNavigation` 白名单仲裁（04 §4） |

**统一规则**：

1. **判定源唯一**：宿主判定只读 `capabilities`（`platform` 字段），页面代码
   禁止 `navigator.userAgent` 分叉——UA 嗅探是 R11 已否决的形态在文件操作上的翻版。
2. **降级链是声明式的**：每个动作的通道顺序写在本篇矩阵里，实现落成
   `exportFile` / `pickFile` / `openFullscreenTable` 三个工具函数，
   页面不自行拼装通道。
