# 11 — 平台交互与导航状态

> 状态标记：**[已落地]** / **[部分落地]** / **[未落地]**。

## 1. 「接近原生」的判定

**[已落地] 判定标准，不是一句形容词**

一个交互算不算接近原生，用下面四条判。**缺一条就只是"做了个移动端样式"**：

| # | 判据 | 本仓状态 |
| --- | --- | --- |
| 1 | 返回键有**确定且可预测**的语义 | ✅ `BackDispatcher` 五级分派 |
| 2 | 覆盖层的关闭**只有一个所有者** | ✅ `OverlayRegistry` 唯一真源 |
| 3 | 页面标题**由当前层级决定**，不由全局变量决定 | ✅ `TitleResolver` 8 级 |
| 4 | 返回后**状态可恢复**（滚动位置、筛选、分页游标） | 🔶 部分（见 §5） |

**四条都过才叫接近原生。** 只有 1+2 而没有 3，会出现"弹层标题是上一页名字"；
只有 1 而没有 2，会出现"ESC 关掉的和返回键关掉的不是一个层"。

## 2. 一个导航所有者与导航意图

**[已落地]**

- 导航上下文的唯一真源是 `NavigationStore`（`lib/shell/hyper/context.ts`）
- 路由适配器由 `installHyper(router, opts)` 挂载，**幂等**
- `hyperActive === false` 时**不挂**适配器、**不写**持久化、**不绑** Esc

**导航意图与导航结果是两件事。** `BackDispatcher.request()` 只登记意图，
结果由 `afterEach` 在导航成功后唯一改写（`applyExternalPop`）。

> 这不是过度设计：改造前先改 store 再调路由，守卫拒绝时**页面没退但上下文以为退了**，
> 下次返回会跳层。见 [06 §4](./06-Hyper导航上下文.md)。

## 3. 返回仲裁与根页

**[已落地]** `lib/shell/hyper/back.ts`

| 级 | 处理 | 根页时的行为 |
| --- | --- | --- |
| 1 | 子层 consumer（浮层、下拉） | — |
| 2 | 覆盖层 top（先问守卫） | — |
| 3 | entry 前驱 | — |
| 4 | 路由登记的安全 fallback（`replace`） | 避免「首页→详情→首页」循环 |
| 5 | **交还系统** | Web 留在原地；**原生交还系统，不默认杀进程** |

**单飞**：并发返回请求只处理一次。

**根页不杀进程**：Android 上返回根页若杀进程，用户会丢失所有页面栈。
正确语义是"交还意图给系统"，由系统决定（通常退到后台）。

> **「无端口」返回 `'unsupported'` 而不是 `'navigated'`。**
> 把 no-op 报成 success，调用方会以为可以继续做后续动作。

## 4. 交互式返回事务

**[部分落地]**

可交互元素（输入框、抽屉、焦点态）应先消费返回，**再**考虑导航。当前实现只有两级：

| 情况 | 期望 | 当前 |
| --- | --- | --- |
| 输入框有焦点 | 失焦 | **[未落地]** |
| 下拉/浮层打开 | 关闭 | ✅ 子层 consumer |
| 弹层打开 | 关闭弹层 | ✅ 覆盖层 top |
| 都在上面 | 导航 | ✅ entry 前驱 |

**输入框失焦未实现。** 表现为：手机上点完输入框按返回，键盘收起但页面没退，
再按一次才退 —— 用户会觉得"要按两下"。

**落地建议**：在 `BackDispatcher` 的第 1 级之前加一条
"当前焦点元素是否可失焦"的 consumer，而不是在各处监听 `blur`。

## 5. 层与焦点

**[部分落地]**

| 项 | 状态 |
| --- | --- |
| 覆盖层登记 / 优先级 / 守卫 | ✅ `OverlayRegistry` |
| 打开时焦点移入层内 | **[未落地]** |
| 关闭后焦点归还原触发元素 | **[未落地]** |
| `prefers-reduced-motion` | ✅ `styles/hyper.css` |

**无障碍红线**：弹层打开后焦点**必须**进入层内，否则读屏用户停留在背景页；
关闭后必须归还原触发元素，否则键盘用户"焦点丢失"，要 Tab 半天才能回来。

**[未落地]标记是有意的** —— 在补齐前不要声称"无障碍合规"。

## 6. 双端差异（不可抹平）

**[未落地]** iOS 与 Android 的返回语义不同：

| 平台 | 返回 | 侧滑返回 |
| --- | --- | --- |
| iOS | 无系统返回键 | 边缘可取消侧滑 |
| Android | 系统返回键 / 预测返回 | 无边缘手势 |

**不能用同一套网页侧滑替代两者。** 参考仓明确保留这个差异，本仓继承。

当前只做了 Android（[04 §7 A-4](./04-Hybrid外壳.md)），
**iOS 侧未构建**，因此双端差异还只是契约。
