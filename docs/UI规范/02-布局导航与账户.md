## 1. 应用壳结构

**[已落地]** 壳层结构在 `src/App.vue`，无新增容器，改动只是把新组件接进既有结构：

```
App.vue
├── AppTopbar          既有。compact 下隐藏三个系统设置控件
├── V1DataFrozenBanner 既有。（存量令牌化欠账见 00 §9.6.4）
├── <RouterView />     既有页面树
```

**不新建外层容器。** 底栏用 `position: sticky; bottom: 0` 就地停靠；底部占位由
`styles/hyper.css` 在内容区补等量 padding，最后一条内容才不会被遮挡。

## 2. 四档窗口

**[已落地]** 断点真源是 `src/config/breakpoints.ts` 的 `BREAKPOINTS`，语义档映射在
`src/config/window-class.ts`，**全部由前者派生**：

| 档 | 范围 | 典型场景 |
| --- | --- | --- |
| `compact` | `< 768` | 手机竖屏、壳内 WebView |
| `medium` | `768 – 1023` | 折叠展开、平板竖横持、窄桌面 |
| `expanded` | `1024 – 1439` | 平板横屏、常规桌面 |
| `large` | `≥ 1440` | 大屏作业 |

**为什么不照搬参考仓的 600/960/1280**：本仓 `BREAKPOINTS.mobile` 已经是 `< 768`，
是 P0 响应式轮定下的既有形态。改档位等于推翻已有响应式结论，且会牵动全仓
两百余个 `.vue`/`.css` 的媒体查询（`responsive:check` 当前扫描 282 个文件、命中 112 处断点）。差异与代价见 [01 §4](./01-原则与断点.md)。

**已知 1px 差异**：恰好 768.0 CSS px 这一条线上，CSS 的 `max-width: 767.98px` 走移动兜底，
而 JS 的三条 `min-width` 媒体查询走 `medium`。这是分数边界的既有取舍，**不是 bug**，
详见 [01 §4](./01-原则与断点.md)。

## 3. 底部导航（仅 compact）

**[已落地]** `src/components/shell/AppBottomNav.vue`

| 项 | 值 | 理由 |
| --- | --- | --- |
| 渲染条件 | `v-if="isCompact"` | 桌面不渲染。用 `v-if` 而非 CSS 隐藏，"compact 下不存在底栏"才可被 `querySelector` 断言 |
| 席位数 | `MAX_PRIMARY = 3` + 「更多」= 4 席（上限 5） | 超出部分**不渲染、不做第二行**。5 席是触控可用性上限 |
| 触控高度 | `min-height: 44px` | WCAG 2.5.5 与 iOS 44pt 的共同基线 |
| z-index | `30` | 底栏 30 < 账户 Sheet 50 < 抽屉 100。顺序由 `gates.spec.ts` 的「弹层层级」门禁守住 |
| 数据来源 | `useAppNav().navPrimaryResolved` | **与顶栏同源**，权限过滤只有一份实现 |

> **为什么用 `v-if` 而不是 CSS 隐藏**：CSS 隐藏的节点仍在 DOM 里，测试能查到它、
> 读屏软件能聚焦它、点击事件还可能命中它。`v-if` 才让"这一形态不存在"成为可断言的事实。

> **席位顺序不要另算**。底栏与顶栏都消费 `navPrimaryResolved`，权限变化时两者必然同步。
> 若某处需要不同排序，应在 `useAppNav` 里加一个明确的派生，而不是在底栏里重新过滤。

## 4. 顶栏

### 4.1 large / expanded / medium

**[未改动]** 三档顶栏保持现状：品牌区、hamburger、主导航链接、主题/语言/用户三控件。
**桌面零回归红线**：≥1024 的顶栏 DOM、链接密度、控件顺序**不得改变**。

### 4.2 compact

**[已落地]** `styles/hyper.css` 在 `@media (max-width: 767.98px)` 内隐藏三个系统设置控件：

| 控件 | 选择器 | 去处 |
| --- | --- | --- |
| 主题切换 | `.theme-toggle` | 账户 Sheet |
| 语言选择 | `.language-selector` | 账户 Sheet |
| 用户菜单 | `.user-menu` | 账户 Sheet |

> ★ **这三个类名必须来自 `AppTopbar.vue` 真实渲染的子组件。**
> 第一版曾写成 `.app-topbar__lang` / `__theme` / `__user` —— 这三个类名在
> `AppTopbar.vue` 里**根本不存在**（它直接渲染 `ThemeToggle` / `LanguageSelector` /
> `UserMenuDropdown`，根类名是上表那三个）。规则完整、语法正确、构建通过、门禁全绿，
> **但完全没生效**，compact 顶栏照样堆着三个控件。
>
> 「CSS 规则打空」单文件 spec 抓不到，被测文件自己不会说自己没用上。
> 已加跨文件门禁 `gates.spec.ts`「hyper.css：不存在死选择器」，并经变异验证有牙。

**隐藏规则必须限定在 compact 媒体查询内**，桌面不受影响 —— 门禁会断言
`.theme-toggle` 之前最近的 `@media` 里含 `max-width: 767.98px`。

## 5. 账户面板

**[已落地]** `src/components/shell/AppAccountSheet.vue`。语言 / 主题 / 账户三类操作
在 compact 下从顶栏移到这里，**不是新增一套逻辑，是搬运**。

| 项 | 值 |
| --- | --- |
| 形态 | 自底向上 Sheet，`border-radius: 12px 12px 0 0`（圆角只在上沿） |
| z-index | `50`（高于底栏 30，低于抽屉 100） |
| 最大宽度 | `520px`（窄屏时自然铺满） |
| 行高 | `min-height: 48px` |
| 关闭按钮 | `min-width/min-height: 44px` |
| 遮罩类名 | `account-sheet__mask-backdrop` |
| 层登记 | 打开即 `OverlayRegistry.register`，`close()` **当场** `unregister` |

**两个曾经写错、已修的点**（详见 00 §9.2）：

- `watch` 缺 `immediate` → 初始 `modelValue=true` 时层永不登记，**系统返回穿透**。
- `close()` 只 emit、等父组件回传 prop → 留出「已死条目仍在栈里」的空窗。
  现在 `close()` 当场 unregister（幂等），不留空窗。

**遮罩类名必须符合仓库既有的 `*-backdrop` 约定**，否则触发 `theme.dark-skin` 门禁。
这是让门禁**因正确理由**通过，不是削弱门禁。

## 6. 权限与导航过滤

**[已落地]** 导航项的可见性统一由 `src/composables/useAppNav.ts` 的
`navPrimaryResolved` 决定，底栏与顶栏共用。**新增导航形态不得自己再过滤一遍** ——
两处过滤必然在某次权限变更后漂移，且漂移时没有任何报错。

## 9. 与参考仓 `nbjl3` 的实质差异

| # | 差异 | 代价 |
| --- | --- | --- |
| 1 | 断点 600/960/1280 → **768/1024/1440** | 沿用本仓 `BREAKPOINTS` 既有形态，避开两百余文件的媒体查询返工。参考仓在 768–960 区间是 medium，本仓是 compact |
| 2 | 侧栏阈值 960 → 沿用 `AppNavDrawer` 既有行为 | **[未改动]** 本专题没有动侧栏。若参考仓的常驻侧栏形态更合适，需单独立项 |
| 3 | 账户 Sheet 阈值 | 参考仓未定义具体值；本仓定义为 **compact 独占** |
| 4 | 账户面板内含内容 | 参考仓只列语言/主题/用户；本仓额外含「个人中心 / 服务健康 / 退出登录 / 管理入口」，因为本仓顶栏原本就有这些入口 |
| 5 | 顶栏 compact 隐藏项 | 参考仓未列具体选择器；本仓锁定为 `.theme-toggle` / `.language-selector` / `.user-menu` 三个并有门禁 |

## 10. 改这一篇的同轮义务

改断点、导航席位、列表模式或壳契约时，**同轮**更新：

1. 本篇对应小节
2. [00-需求与优化方案](./00-需求与优化方案.md) 的 F/N 条目与执行记录
3. `config/breakpoints.ts` 或 `config/window-class.ts`（唯一真源）
4. 跑 `pnpm responsive:check`、`pnpm ui:check:strict`、`pnpm element:check`

本仓无 `AGENTS.md`，故没有"规范 ↔ AGENTS 镜像"这一环。
