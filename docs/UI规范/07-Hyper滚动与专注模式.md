## 1. 布局模式与加载方式是两个独立维度

**[已落地]**

| 维度 | 取值 | 默认 |
| --- | --- | --- |
| 呈现形态 | `table` / `cards` | compact 强制 cards（见 [03 §2](./03-列表卡片与弹窗.md)） |
| 加载方式 | `continuous` / `paged` | 页面显式声明，不靠默认 |

「壳在平板/大屏仍可启用连续加载，但保留桌面表格密度」——**这是允许的**，
四个组合（表格/卡片 × 连续/分页）都合法。

**不用 `usePagination` 替代 `createHyperPages`**：前者是单页语义
（一个 page 指针 + total），后者是「已累积的 N 页 + 还能不能继续」，两者不能互相替代。

## 2. 连续加载：`createHyperPages`

**[已落地]** 状态机六态：

```
idle ⇄ loadingNext ⇄ refreshing
  ↓          ↓
failed    exhausted        （+ paused，由宿主控制）
```

### 2.1 revision 闸门（本模块唯一不能省的机制）

筛选 / 租户 / 排序变化时 `revision++`，**旧请求即使在之后到达也被拒绝写入**。

没有它会出现：切到租户 B 后，A 的慢响应回来把 A 的行追加进 B 的列表 ——
**跨租户数据泄露，且用户界面上看不到任何异常**。

每个请求带 `{ revision, page }` 快照；`commit` 时 revision 已变则整页丢弃。

**闸门是双层的**：`loadPage` 与 `commit` 各查一次。摘掉单层时另一层仍挡住
（变异验证 M1a / M1b 门**故意**保持绿），两层同摘才转红（M1c，4 例）。
这是**刻意的冗余**，不是重复劳动 —— 见 [05 §6](./05-落地清单.md) 关于「无牙 ≠ 未验证」。

### 2.2 单飞

同一页已有在途请求时**加入**它，而不是再发一次，也不是直接返回 `false`。
加入才能让重复调用与在途请求共享同一结果。

`inflight` 记录带 `token`，`finally` 只清理自己那一条 ——
`invalidate()` 清过 map 之后，旧请求落地若按 key 无条件 `delete`，
会删掉新请求的单飞记录，此后重复调用重复发请求。

### 2.3 去重

按 `rowKey` 稳定行 id 去重，后加载的同 id 行覆盖先加载的。
**依赖稳定排序键**（如 `created_at, id`）。

> **去重只能消重、不能补漏。** 数据频繁变化时页号可能跳过/重复。
> 要真正解决需要 cursor + snapshot/version 契约，**不伪造当前接口已有快照一致性**。

### 2.4 失败保旧

请求失败时**保留已加载行**（stale 态），不把列表清空。
`retry()` **重取失败的那一页**（`loadedPages + 1`），不跳页 ——
跳页会静默丢一整页数据。

`refresh()` 失败同样保留旧内容。刷新不清空列表，只有真正提交第 1 页时才替换。

### 2.5 内存预算

`evictAbove` 默认 **3000 行**（设计值，不是实测结论）。超过后清退最早的页，
保留游标（`evictedFromPage`）与 anchor，返回时补取。

**至少保留一页**：`evictAbove` 被配得比单页还小时，去掉这条保护会把 `pageRows` 删空、
`rows` 变成 `[]` —— 用户看到的是「加载完就没了」。门禁有用例钉住。

## 3. 尾部控件：`HyperLoadMore`

**[已落地]** 四条约束（缺一条就会在真机上出问题）：

| # | 约束 | 缺了会怎样 |
| --- | --- | --- |
| 1 | 只有有下一页且非 busy 才请求 | 「触发条件」写成 `isIntersecting` 等于每帧一次请求 |
| 2 | `root` 必须是 sentinel 的**祖先** | 传 `null` 退化成相对视口判断，自定义滚动宿主里屏外几百像素的 sentinel 被判为可见 |
| 3 | **单轮自动填屏最多 3 页** | 首屏不足一屏时 IO 连续命中，不设上限会一路打穿后端 |
| 4 | sentinel 滚出视口**顶部**不算接近底部 | 只看 `isIntersecting` 会把「已经滚过去了」当成「快到底了」 |

其它已落地行为：

- `rootMargin` 底边提前量 **240px**（规范值，可覆盖）
- **无 IntersectionObserver** → 降级为「继续加载」按钮，**不是永远不触发的空页**
- `exhausted` / `failed` → **不再观察**，停自动重试
- 手动加载或重试 → **重置自动填屏配额**（用户在主动推进，下一屏仍可自动填）
- 卸载 / 状态迁移 → **断开 observer**；「同一时刻只有一个活 observer」有门禁

> ### ★ 一个真实缺陷：`watch` 的 flush
>
> 状态从 `loadingNext` 回到 `idle` 时，若用默认的 `pre` flush，
> watcher 在 DOM 更新**之前**运行，sentinel 还没重新挂上，
> `setupObserver` 静默早退。
> **症状：列表加载完第一页后自动加载永久失效**，滚到底无反应、**无任何报错**。
>
> 现用 `flush: 'post'`，并把四个输入合并成**一个** watch
> （拆两个会让一次状态变化触发两次 `setupObserver`）。

> ### ★ 不可达守卫
>
> 模板里 `sentinel 存在 ⟺ autoTriggerEnabled`（那个 `v-if` 就是这条等价式的执行点），
> 所以 `setupObserver` 中两处 JS 守卫在当前模板下**可证明不可达**。
> 其中一处已删除，另一处保留并在注释里写明：只为防模板被改坏时
> 出现「偶发多发请求」这种极难定位的症状。

## 6. 虚拟化

**[未落地]** 规范给出的阶梯（**均为初始设计值，不是实测结论**）：

| 累积行数 | 动作 |
| --- | --- |
| ≤ 1,000 | 不虚拟化 |
| 1,000 | **开始**评估虚拟化 |
| > 3,000 | 进入窗口缓存 / 清退旧页（`evictAbove` 已在 3,000 生效） |

`evictAbove` 的 3000 默认值来自这个阶梯，**不是实测得出的安全上限**。

## 7. 下拉刷新

**[未落地]** 手势部分。**方法已就绪**：`createHyperPages.refresh()`
是保旧刷新（失败保留旧内容、不清空列表）。

**[部分落地]** 顶部局部刷新态在 `HyperLoadMore` 里是 `state === 'refreshing'`
的文案分支，但**没有任何页面接入**，也没有手势触发。
不要把「有文案分支」当成「下拉刷新已实现」。

## 8. 展示「已加载 X / 总计 Y」

**[部分落地]** `HyperLoadMore` 的 `exhausted` 分支显示「已全部加载 {count} 条」，
`loadedCount` 来自 `createHyperPages.loadedCount`。

**「总计 Y」未实现** —— 服务端 `total` 漂移时的更新时间标注也未实现。
