## 1. 手势争用规则

**[未落地] 契约**

一个手势可能同时被多个消费者想要。**必须显式仲裁，不得各自监听。**

| 优先级 | 消费者 | 理由 |
| --- | --- | --- |
| 1（最高） | **系统手势** | 系统返回 / 多任务手势不可被网页吞掉 |
| 2 | 覆盖层内部手势 | 用户在弹层里，意图属于弹层 |
| 3 | 内容滚动 | 列表/页面的原生滚动 |
| 4 | 边缘侧滑返回 | 系统手势未命中时才考虑 |
| 5（最低） | 下拉刷新 | 只有内容已滚到顶部且不 busy 才生效 |

**方向锁**：手势开始后锁定主轴方向，**不中途改判**。
横竖混判会让"斜着划"既不滚动也不触发，是最容易招致差评的手感缺陷。

**系统手势优先的具体含义**：
iOS 边缘侧滑、Android 屏幕边缘返回区，网页侧滑**必须让出**
（通常是把可触发宽度限制在 16–20pt 内，或完全禁用）。

## 2. 识别、跟手与中断

**[未落地] 契约**

| 要求 | 说明 |
| --- | --- |
| 跟手 | 手指移动 1px，界面移动 1px。**不缓动、不吸附到预设位置** |
| 松手才决定 | 松手时按速度 + 位置决定「完成」还是「取消」，**松手前不锁死** |
| 可取消 | 任何时刻可反向拖回原位。iOS 侧滑必须可取消 |
| 中断即复位 | 手势被系统打断（来电、通知、多任务）→ **立即回到中性态**，不留在半路 |
| 无 300ms 延迟 | 判定阈值用距离 + 速度，**不要用固定等待** |

> **「松手前不锁死」是可取消的前提。**
> 一旦过了阈值就播动画，用户想反悔也停不下来 —— 这在 iOS 上尤其明显。

## 3. 滚动与刷新手感

**[未落地] 契约**

| 场景 | 要求 |
| --- | --- |
| 列表滚动 | 原生滚动，**不做 JS 接管**（接管会丢 momentum 与滚动惯性） |
| 下拉刷新 | 只在 `scrollTop === 0` 时可触发；下拉超阈值时**背景不跟着下移**，只有刷新指示器动 |
| 忙时 | 正在加载时**禁用**下拉刷新（否则一次下拉发多次请求） |
| 横向 | 表格横滚在桌面保留；compact 强制卡片后**不再需要横滚**（见 [03 §2](./03-列表卡片与弹窗.md)） |

> **下拉刷新手势的忙态门必须存在。**
> `HyperLoadMore` 的 `loadingNext` / `refreshing` 已经提供这个状态，
> 但**尚无页面接入**。

## 4. 动效与减少动态效果（唯一已落地项）

**[已落地]** `src/styles/hyper.css`：

```css
@media (prefers-reduced-motion: reduce) { /* 关闭非必要动效 */ }
```

**这是无障碍要求，不是可选优化。** 前庭功能障碍用户对大幅位移与视差敏感。

**[未落地]** 前庭用户需要关掉的典型效果（本仓尚未实现任何一种）：

- 大幅位移 / 视差滚动
- 旋转与缩放动画
- 自动播放的循环动画
- 超过 300ms 的过渡（长过渡在移动端尤其难受）

**新增动效时的义务**：同时提供 `prefers-reduced-motion` 分支，
并**用系统设置实测一次**（不是只看代码里有没有那个媒体查询）。

## 5. 动效时长

**[未落地]** 参考值（不是本仓实测）：

| 场景 | 时长 |
| --- | --- |
| 状态反馈（按下、选中） | 100–150ms |
| 层进出 | 200–300ms |
| 页面转场 | 300ms 上限 |

**不做超过 300ms 的转场**：在低端 Android 上，多于 300ms 的动画会让用户觉得"卡"。
