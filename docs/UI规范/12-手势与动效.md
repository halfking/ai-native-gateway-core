## 1. 手势争用规则

**[部分落地]**：§1 里与「弹层 vs 内容滚动」这一格已实做并有门守护；
其余各格（系统返回、边缘侧滑、下拉刷新）仍是契约。

**已落地的那一格**：`AppDrawer` 的起手区域就是仲裁点本身 ——
bottom sheet **只允许从把手/头部起手**（`.app-drawer__grip` / `.app-drawer__header`），
`.app-drawer__body` 让给内容滚动；右侧面板整面可起手（面板内无横向滚动，无争用）。
系统手势让出带（`edgeInset`，默认 18px，规范给的是 16–20pt）内的起手**直接拒绝**，
不是「优先级降低」。

**仍未落地的**（仍被缺陷 2 阻塞的是**原生侧**那一部分）：

一个手势可能同时被多个消费者想要。**必须显式仲裁，不得各自监听。**

| 优先级 | 消费者 | 理由 |
| --- | --- | --- |
| 1（最高） | **系统手势** | 系统返回 / 多任务手势不可被网页吞掉 |
| 2 | 覆盖层内部手势 | 用户在弹层里，意图属于弹层 |
| 3 | 内容滚动 | 列表/页面的原生滚动 |
| 4 | 边缘侧滑返回 | 系统手势未命中时才考虑 |
| 5（最低） | 下拉刷新 | 只有内容已滚到顶部且不 busy 才生效 |

**方向锁**：手势开始后锁定主轴方向，**不中途改判**。
横竖混判会让"斜着划"既不滚动也不触发，是最容易招致差评的手感缺陷。
**已落地**：`dragDismiss` 用**起始斜率门槛**（默认 1.2）一次定轴，判完不再改判；
斜率不达标判为 `axis-mismatch` 并交还消费者。

**系统手势优先的具体含义**：
iOS 边缘侧滑、Android 屏幕边缘返回区，网页侧滑**必须让出**
（通常是把可触发宽度限制在 16–20pt 内，或完全禁用）。**已落地**（18px 让出带）。

### 1.1 行点击与行侧滑的分工（2026-10-05 落档；行侧滑本仓未实现）

手势争用表补两行（移植自参考仓 `007496e3`，按本仓现状改写）：

| 手势 | 触发条件 | 约束 | 可见等价物 |
| --- | --- | --- | --- |
| 行侧滑 | 非边缘区域、横向意图、非选字/输入/横滚表 | 同时只开一行；点外部收起；拖动后抑制误 click | 同一动作的显式按钮（不藏在「详情」里） |
| 行点击 | 无横向意图、非选字/输入/横滚表 | 侧滑后抑制的误 click 不得触发行点击 | chevron 指示器（[03 §3.3](./03-列表卡片与弹窗.md)）+ 行内无第二个导航控件 |

- **点行进详情是基线行为**，不是手势特权：它必须是一个真按钮（本仓 `CardList`
  的动态 `button`/`div` 已满足），键盘 `Enter`/`Space` 与读屏都能到达，
  且有 `:active` 即时反馈（**未落地**，03 §3.3 第 3 条）。侧滑**不得**成为任何
  列表的唯一操作入口——本仓未实现行侧滑，此条是**预置契约**：将来实现时
  每个侧滑动作必须有可见按钮等价物。
- **侧滑只承载行内写操作**（禁用、重导、归档），与 03 §3.3 第 6 条「写操作
  不挂整行」互补：整行点击是读向意图，写向意图要么独立按钮、要么侧滑 + 按钮等价物。
- **不可点行不参与手势仲裁**：静态行不应抢到 pointer 序列，否则用户会以为能操作。

## 2. 识别、跟手与中断

**[已落地]** `web/src/lib/shell/hyper/dragDismiss.ts`（纯状态机，无 DOM 依赖）+ `AppDrawer` 接线。

| 要求 | 说明 | 落地形态 |
| --- | --- | --- |
| 跟手 | 手指移动 1px，界面移动 1px。**不缓动、不吸附到预设位置** | `onProgress` 逐帧回调；跟手阶段 `transition: none !important` |
| 松手才决定 | 松手时按速度 + 位置决定「完成」还是「取消」，**松手前不锁死** | `onSettle` 只在 `end()` 调一次；`pastThreshold` 仅供 UI 提示 |
| 可取消 | 任何时刻可反向拖回原位 | 位置与速度都按 `closeDirection` 取符号，反向不触发关闭 |
| 中断即复位 | 手势被系统打断 → **立即回到中性态**，不留在半路 | `pointercancel` → `cancel()` → `onProgress(0)`，**不**触发关闭 |
| 无 300ms 延迟 | 判定阈值用距离 + 速度，**不要用固定等待** | 位置阈值 30% 面板尺寸 **或** 速度 800px/s，任一满足即关闭 |

> **「松手前不锁死」是可取消的前提。**
> 一旦过了阈值就播动画，用户想反悔也停不下来 —— 这在 iOS 上尤其明显。
> **已用变异 M3 钉住**：把「过阈值即 settle」改回去，`dragDismiss.test.ts` 立刻红。

**为什么写成纯状态机而不是 composable**：上面每一条都只跟几何与时间有关。
写成 `useDragDismiss(el)` 的话，方向锁与速度判定就只能在真机上手感验证，
而手感是最难回归的那一类。现在 20 条断言在无浏览器环境逐条覆盖。

## 3. 滚动与刷新手感

**[未落地] 契约**

| 场景 | 要求 |
| --- | --- |
| 列表滚动 | 原生滚动，**不做 JS 接管**（接管会丢 momentum 与滚动惯性） |
| 下拉刷新 | 只在 `scrollTop === 0` 时可触发；下拉超阈值时**背景不跟着下移**，只有刷新指示器动 |
| 忙时 | 正在加载时**禁用**下拉刷新（否则一次下拉发多次请求） |
| 横向 | 表格横滚在桌面保留；compact 强制卡片后**不再需要横滚**（见 [03 §2](./03-列表卡片与弹窗.md)） |

> **下拉刷新手势的忙态门必须存在。**
> `HyperLoadMore` 的 `loadingNext` / `refreshing` 已经提供这个状态，
> 但**尚无页面接入**。

## 4. 动效与减少动态效果（唯一已落地项）

**[已落地]** `src/styles/hyper.css`：

```css
@media (prefers-reduced-motion: reduce) { /* 关闭非必要动效 */ }
```

**这是无障碍要求，不是可选优化。** 前庭功能障碍用户对大幅位移与视差敏感。

**[未落地]** 前庭用户需要关掉的典型效果（本仓尚未实现任何一种）：

- 大幅位移 / 视差滚动
- 旋转与缩放动画
- 自动播放的循环动画
- 超过 300ms 的过渡（长过渡在移动端尤其难受）

**新增动效时的义务**：同时提供 `prefers-reduced-motion` 分支，
并**用系统设置实测一次**（不是只看代码里有没有那个媒体查询）。

## 5. 动效时长

**[未落地]** 参考值（不是本仓实测）：

| 场景 | 时长 |
| --- | --- |
| 状态反馈（按下、选中） | 100–150ms |
| 层进出 | 200–300ms |
| 页面转场 | 300ms 上限 |

**不做超过 300ms 的转场**：在低端 Android 上，多于 300ms 的动画会让用户觉得"卡"。

## 7. 路由与视图切换转场（2026-10-05 落档，compact 已实现）

**[已落地]**（`web/` 已登录主区，compact 档）· **[已落地]**（`web-mobile/` 全档，`page-fade`/`sheet`/`drawer`）
目标：**平滑、不闪动**。切档/换页/弹层三族转场的契约与依据。

### 7.1 分档：什么关系用什么转场（Material 3 同款取舍）

| 切换关系 | 转场 | 依据 |
| --- | --- | --- |
| 顶级目的地（底栏席位之间、同级路由） | **fade 160ms** | 顶级目的地无层级关系，slide 会暗示「可以滑过去」（Material 3：top-level 用 fade） |
| 层级进出（列表 → 详情、进全屏表格） | fade（现状）；slide 上移留作后续（transform-only，从 4% 位移起步） | 有从属关系才用方向性动效 |
| 弹层 / Sheet / Drawer | 既有专属转场（`AppDrawer` dragDismiss / `AppAccountSheet`） | 不并入路由转场 |
| 窗口档位切换（compact ↔ medium，resize） | **无转场** | 布局重排不加动画，媒体查询即时切换 |
| SPA 入口切换（R11 `/` ↔ `/m`）与壳交接 | **不做转场，只做防闪**（见 7.4） | `location.replace` 全量重载无法动画 |

### 7.2 硬规则（防闪动/卡顿的机制层）

1. **只动 `transform` / `opacity`**（GPU 合成）；出现 layout 属性（top/left/width/margin…）即违规——有门禁（`App.route-transition.spec.ts` 逐条断言 page-fade 规则内无禁动属性）。
2. **背景连续性**：`body` 背景统一 `var(--bg)`（路由间不同构不白闪）；`theme-init.js` 首帧定 `data-theme`（防主题 FOUC，既有）；壳 `windowBackground` 与主题同色（04 K-1 修复，防 WebView 首绘白帧）。**转场两侧任何一帧露白 = 缺陷**。
3. **`mode="out-in"` + 单根视图**：out-in 避免新旧两页同时在流内把容器撑高；多根 fragment 视图**降级为无动画**（Vue 仅 dev 告警，不崩）——不为此包裹 wrapper div（会改桌面 DOM 结构）。
4. **桌面零回归的实现形态**：Transition 的 `name` 由 `isCompact` 三元裁决——compact 用 `page-fade`，medium+ 用 **`page-none`（刻意不定义任何 CSS）**。Transition 无匹配样式时瞬时完成 ⇒ 桌面 DOM 与行为逐字节不变；`:key` 同理只在 compact 绑 `route.path`（桌面 `key=undefined` 维持「同组件不重挂」既有行为）。**不采用 v-if 双分支**：跨 768 断点会把当前页重挂一遍、丢页面内状态。
5. **`prefers-reduced-motion` 全关**（§4 契约延伸到路由转场，门禁有断言）。
6. **时长上限 250ms**：fade 160ms 为准（与 web-mobile 对齐）；超过 250ms 在弱机上的「跟手断档感」比无动画更差。
7. **guest 主区（登录/落地）不加转场**：桌面优先体系保持原貌，登记在案（门禁有断言「guest 区无 Transition」，防止后来者『顺手补全』）。

### 7.3 已实现状态与门禁

- `web/`：`App.vue` 已登录 `RouterView` → `v-slot` + `Transition`（2026-10-05），样式在 `App.vue` scoped 块（**刻意不进 `styles/hyper.css`**：死选择器门禁要求类名在 src/ 有实义引用，Transition 运行时生成的 `page-fade-enter-*` 类做不到，进 hyper.css 必打空——D6 同族坑）。
- 门禁 `App.route-transition.spec.ts` **7 例**：转场接线/键控/guest 无转场/禁动属性/时长/reduced-motion/page-none 不可被「补全」。
- `web-mobile/`：`HyperApp.vue` `page-fade`（160ms ease opacity + reduced-motion）、`AppSheet`/`AppDrawer` 专属转场（origin/main 实测）。
- **未真机验证**：低端 WebView 的实际帧率、转场与滚动恢复（06 §6）的竞态——进 15 §3 真机矩阵。

### 7.4 入口切换与壳交接：只做防闪，不做动画

R11 的 `/` ↔ `/m` 与壳引导页 → 远端 SPA 都是**全量重载**，重载边界没有 DOM 可言，
任何「转场」都只能是假象。防闪的三件事：

1. 两侧 SPA 的首帧背景一致（同一套 token，主题记忆键对齐）；
2. 壳 `windowBackground` = 主题背景色（已修，04 §7.2）；
3. 引导页 → 业务页交接时**引导页保持绘制直到 WebView 开始渲染新文档**（WebView 默认行为即是，不要在引导页 unload 前主动清屏）。

### 7.5 不采用 View Transitions API（登记为未来渐进增强）

`document.startViewTransition()` 同文档转场：Chrome/Edge 111+、Safari 18+，Firefox 未稳定。
本仓 N5 旧 WebView 目标（`safari15` cssTarget）下它**只能是渐进增强**，不能当基础机制；
且它按截图快照过渡，对长列表滚动位置的语义不如受控 Vue Transition 明确。
**结论：基础机制保持 CSS Transition；VTA 待 Firefox 稳定且最低 WebView 版本上移后重评。**
