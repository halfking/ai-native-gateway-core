> 状态标记：**[未落地]**。**本篇不含本仓的调研结论。**

## 0. 为什么这篇是空的（重要）

参考仓 `nbjl3` 的 09 是一份**带结论的调研**（官方文档核验、MiMo 型号、本地模型许可、
平台后台边界）。**本仓没有做过同等调研。**

把这篇写成"看起来像调研结论"的内容，等于**伪造证据**。
所以本文只做三件事：

1. 列清**必须核验**的项，以及每项的核验方法
2. 记录参考仓**已经核过**的结论，标明那是**它们的**结论、**未在本仓复核**
3. 给出资源目标与验收判据

**任何一条在填入实测数据前，都不得在其他文档里被引用为"已支持"。**

| # | 待核验 | 方法 | 阻塞什么 |

| V-4 | 真机（`4c308e2e` 已连接）上的 WebView 版本与行为 | 真机取证 | 与模拟器的差异 |

**V-1 是所有原生能力的总闸，现已取证（2026-10-04）——闸是关的，而且拆开看是两道门。**
① 「页面能不能留在 App 里」：修 `allowNavigation` 的写法即可（**已修**，实测复核两向通过）。
② 「留在 App 里之后桥还在不在」：**不在**。桥的注入被限定在 `appUrl` 的 origin，
   `http://localhost:5173` 上 `window.Capacitor` 为 `undefined`、已注册插件为 `null`。
   业务功能全可用、无崩溃、compact 判定正确，**唯独原生能力全无，且界面无任何提示**。

⇒ **第 ② 道门是架构级决策，产品不拍板就不应投入任何原生能力开发。**
三条路径与代价见 [04 §7.1](./04-Hybrid外壳.md)。

## 3. 核验纪律

| 规则 | 原因 |
| --- | --- |
| 每条结论必须附**取样日期** | 平台 API、插件版本、服务条款都会变 |
| 区分**实测证实**与**文档新查出** | 两者可信度不同，混写会让人误以为都验过 |
| 涉及**许可**的必须核到一手条款 | 转述容易丢掉限制条款 |
| 搜索不到 ≠ 不存在 | 只能说"未找到公开资料"，不能下否定结论 |
| 冲突时列出多个来源 | 单一来源不足以支撑能力承诺 |
