## 1. 从三个布尔值改为可区分的状态

只用 `loading / error / empty` **无法区分**首次读取、旧内容刷新与下一页失败，
三者的用户可做的事完全不同。

**[已落地]** `createHyperPages` 的六态：

| 状态 | 含义 | 用户可做的 | 尾部控件 |
| --- | --- | --- | --- |
| `idle` | 已就绪 | 滚动、继续加载 | sentinel / 按钮 |
| `loadingNext` | 正在取下一页 | 滚动已有项 | 忙态（无可点控件） |
| `refreshing` | 正在刷新已有 | 滚动、重读 | 忙态（无可点控件） |
| `failed` | 取数失败 | **看旧数据**、重试 | 失败文案 + 重试按钮 |
| `exhausted` | 没有更多 | 滚动到底 | 「已全部加载 N 条」 |
| `paused` | 宿主停止观察 | 手动继续 | 继续按钮 |

**关键差异在 `failed` 与 `exhausted` 都是「非空态」**：
`failed` 时用户**仍能读到已加载的旧数据**，不显示「暂无数据」。
把失败显示成空态，会让用户以为数据被删了。

## 2. 三态统一裁定

**[已落地]** `ResponsiveDataView`

```
loading → <AppSpinner />          两种形态都不渲染
empty   → <EmptyState />          两种形态都不渲染
else    → 表格 或 卡片
```

**三态在两种形态之外裁定**，这样切形态时不会出现「表格有骨架、卡片空白一片」。
`loading` 优先于 `empty`（门禁有用例）。

**[未落地]** 「无记录」与「筛选无结果」的分文案判定**在组件之外**，
由调用方决定 `emptyText`。批量场景必须分，否则用户以为数据没了。

## 3. 骨架、错误与延迟反馈

**[未落地]** 本仓没有骨架屏组件，也没有 150ms / 3s 的延迟分级。

参考值（**未在本仓实施**）：读取超过 **150ms** 显示骨架，快响应直接呈现结果；
超过 **3s** 在局部补充「正在加载，可返回」。

**[已落地]** 三条底线：

| 规则 | 实现 |
| --- | --- |
| 不先骨架→空白→数据连续跳三次 | 三态统一，不在中间态切布局 |
| 后台刷新不换回骨架 | `refreshing` 是**局部**状态，不遮全屏 |
| 金额位不填 `0.00` | 由 `CardList` 的 `primaryField` 交给调用方，本仓**未加门禁** |

**实际超时由 API client 决定，不能由文案定时器改成失败。**（未实现）

## 4. 查询隔离、取消与乱序

**[已落地] 本模块最重要的一节。**

### 4.1 revision 闸门

筛选 / 租户 / 排序变化时 `revision++`，**旧请求即使在之后到达也被拒绝写入**。

没有它：**切到租户 B 后，A 的慢响应回来把 A 的行追加进 B 的列表** ——
跨租户数据泄露，**且用户界面上看不到任何异常**。

每个请求带 `{ revision, page }` 快照；`commit` 时 revision 已变则整页丢弃。

**闸门是双层的**（`loadPage` + `commit` 各查一次）。单层摘除时门**故意**保持绿
（变异 M1a / M1b），两层同摘才转红（M1c，4 例）。

### 4.2 单飞与 token

同一页在途时**加入**而不是重发。`inflight` 记录带 `token`，
`finally` 只清理自己那一条 —— 否则 `invalidate()` 之后旧请求落地会删掉新请求的单飞记录。

### 4.3 取消的真实边界

`invalidate()` **清掉在途标记但不取消真实请求** —— 它回来时会被 revision 闸门丢弃。
**真要取消网络请求由 `fetchPage` 自行接 `AbortSignal`。**

这是刻意的：模块不该假装能取消它控制不了的东西。
**但这意味着会有"已取消"的请求继续消耗带宽** —— 接入时应在 `fetchPage` 里接 AbortSignal。

### 4.4 写操作的未知结果

**[未落地]** 提交/对账类操作若结果未知，**应查询操作结果，不自动重发写请求**。
本仓没有这套状态机。批量勾选必须区分「已加载行」与「全部筛选结果」，
**不能把手机当前缓存当全量**。

## 7. 接入检查项

新页面用连续加载时：

- [ ] `rowKey` 指向**稳定**字段（不要用数组下标或时间戳）
- [ ] `fetchPage` 接 `AbortSignal`（否则取消只丢结果不省流量）
- [ ] 查询条件变化调 `invalidate()` **或** `refresh()`，不要直接改参数
- [ ] `pageSize` 与后端限制一致（当前最大 100）
- [ ] **`createHyperPages` 的 `pageSize` 与 `fetchPage` 里发出的 `page_size` 同源**
      —— 两者是同一个数的**两处写法**，框架不保证一致，而**短页判据读的是配置里那个**
      （`result.rows.length < opts.pageSize`）。配置写 100、请求发 50 时，
      第 1 页回来的 50 行会被判成「短页」⇒ `hasMore = false` ⇒ 长列表**静默截断**。
      本条来自 10 §4.2.6 的变异台账（配置改 25 是一条当时未被咬住的变异）
- [ ] 失败态**不显示空态**
- [ ] **`fetchPage` 的 `catch` 必须 rethrow。** `createHyperPages` 靠它把 state 置成
      `failed`，而 `:empty` 的判据要靠 `failed` 挡住。吞掉的话 state 停在 `idle`，
      **UI 会撒谎**（没报错的失败比报错更糟）。写完 grep 一下 `catch` 块末尾有没有 `throw`。
- [ ] **`onMounted` 必须按档位分派，不能只调桌面那条 `load()`。** `displayEvents` 读的是
      `continuous.rows`（compact 分支），而它初始为空 ⇒ 只调 `load()` 的话，
      **compact 首屏会一直停在空态**，直到用户手动点「查询」。
      门禁要断「compact 首屏就有卡」，不是断「连续加载器存在」。
- [ ] **「正在加载更多」不能算成「正在加载」。** 忙碌判据只认首屏那个状态，
      不认追加那个 —— 否则点「加载更多」会把已加载的内容换成骨架（该保旧的不保旧了）。
      反过来首屏那次必须真的出忙碌态。两个方向都要断。
- [ ] **重试的测试必须让**非第 1 页**失败。** `retry()` 与「重新取第 1 页」在第 1 页失败时
      发出的请求逐字相同 ⇒ 只在第 1 页失败下测，两条接线永远分不开。
- [ ] 批量操作区分「已加载」与「全量」
- [ ] 跑 `pnpm color:check`（`CardList` / `HyperLoadMore` 的颜色必须用令牌）

**接口没有分页、只换呈现形态的页面**（本专题多数切片属于这一类），额外四条：

- [ ] **`title-key` 指向的行内字段必须逐行唯一。** `CardList` 的 `:key` 取的是 `titleKey`
      的**原始值**（取不到才回退 `idx-N`）⇒ 复合身份（`model + task_type` 之类）
      直接拿其中一个字段会**撞键**，表现是卡片内容串行。拼一个派生键（`model · task_type`）
      并让卡头用它 ⇒ 键与脸同源，也就不用 `titleFormat`。
      分隔符别用 `-`：模型名本身带连字符。
- [ ] **卡片的字段集与表格的列集必须一一对应** —— 表格没有的列，卡片也不许有
      （`by_model_task` 桌面不渲染 `avg_cost_usd`，卡片就不出）。
      卡片因换形态而多露出字段，比少露出更难发现。
- [ ] **表格与卡片共用同一份格式化与译名**（列名抽常量、格式化函数抽函数）。
      写两遍不会报错，只会在某次改口径时让一档对、另一档不对。
- [ ] **槽里放的是 `el-table` 而不是原生 `<table>` 时，`table-min-width` 无效** ——
      容器规则是 `:slotted(table)`，而 `el-table` 的根元素是 `<div class="el-table">`
      （已实测，见 §4.6.2 的 D12）。**这不构成阻塞**：compact 下 el-table 根本不渲染，
      非 compact 下它自带内部横向滚动。**别在代码注释里写「窄屏下限已设 0px」——
      那是假的**；要写就写「窄屏下限归 Element 自己管」。
- [ ] **固定像素下限的栅格要能在窄屏收缩**：`minmax(280px, 1fr)` 在 320px/360px 机上
      比容器宽（容器 = 视口 − 页面内边距 − 卡片内边距）⇒ 改 `minmax(min(280px, 100%), 1fr)`。
      容器够宽时 `min()` 取原值，**桌面逐字不变**。
- [ ] **`:empty` 谓词要用「实际喂给 `:rows` 的那个数组」。** 级联筛选页上这是最易错的一处：
      `:rows="filteredSessions"` 配 `:empty="isCompact && sessions.length === 0"` 时，
      「选中的项目下没有会话」会让 `:empty` 恒为 false ⇒ compact 下渲染出一个
      **空 `CardList`**（走 `v-else` 分支），而桌面对应位置是表格自带的 "No Data"
      ⇒ **两边形态不一致**。写完对着 `:rows` 抄一遍，**不要**对着原始数据源抄。
- [ ] **「表上有 loading 指令」不等于「该给容器传 `:loading`」。** 先问那个 loading 表现
      **在哪一层**：`v-loading` 指令是**覆盖层**（内容保留，桌面 el-table 仍在 DOM 里），
      容器 `:loading` 是**整块替换**（内容消失，桌面变成骨架）。对桌面的影响正好相反。
      本专题多数切片都**不传** `:loading`（桌面刷新时保留旧行）。⇒ 光 grep「容器没写这个
      prop」不够，它只证明没写、证明不了桌面没变；**另配一条行为门禁**：
      把请求 mock 成不 resolve，断言桌面表格仍在 DOM 里、遮罩确实挂着。
- [ ] **格式化 / 分档函数的每个阈值，fixture 要覆盖「左侧 / 右侧 / 中间带」三处。**
      中间带为空时，「阈值改一改」这条变异必然行为等价（本仓已中三次：
      `fmtMs` 1000→1500、`fmtUsd` 0.001→0.01、`getScoreColor` 80→90）。
      判定用的值也要覆盖 **0** 与**缺值**两端（`v == null` 与 `v` 在 0 上分道扬镳）。
- [ ] **别在源码里凭 `em()` 之类语义猜 Element 组件的 class 名。** 断言徽章类型时
      `find('.el-badge')` 拿到的是**外壳**，类型 class 挂在内层 `sup.el-badge__content` 上
      ⇒ 第一轮红的是判据不是产品。**dump 一遍真实 DOM 再写断言。**
- [ ] **`CardField` 配了 `tone` 就必须配 `type: 'metric' | 'badge'`。**
      `CardList.fieldTone` 开头就判 `type`，不是那两档就 `return undefined`
      ⇒ `data-tone` 属性**整个不渲染**、无任何报错。徽章形状另走 `metaKeys` 那一路，
      `type` 在 `fields` 里管的就是**状态色**。
- [ ] **卡片字段的「截断长度」要和它**对应那张桌面表**的那个数字一致。**
      同一页有两张表时，两个数字本来就可能不同（本专题实测 T1 是 18/20、T2 是 18/24），
      照抄另一张表会得到「同页同字段两个口径」而两边都不报错。
      判据**从桌面模板里取那个数字**再比对，别把字面量抄进断言。
- [ ] **`.table-wrap` 能不能整类删，看它除 `overflow` 外还带不带别的东西。**
      只带 `overflow-x` 的可以整类删（横滚交给容器）；**同时是视觉框**
      （`border` + `border-radius` + `background`）的**只能摘 `overflow`**
      —— 整类删会把桌面的圆角边框一起删掉，那是桌面视觉回归。
- [ ] **判「有某个属性」别只写「有这个属性的名字」。** `expect(css).toMatch(/border:/)`
      被 `border: none;` 照样匹配 ⇒ 判据是假牙，写成 `/border:\s*(?!none\b|0\b)\S/`。
- [ ] **同一个字段的两条性质（色 / 文本）要各断一条。** 断了 `data-tone` 没断译名，
      把 `format` 整个删掉照样绿。同理**逐 prop 断，别在整块标签上用「或」匹配**
      （`:(loading|empty)="…isCompact"` 会让 `:loading` 丢前置而 `:empty` 兜住）。
- [ ] **`.table-wrap` 若是视觉框且被保留，则本页**不传** `table-min-width`。**
      容器规则是 `:slotted(table)`，命中要求 `<table>` 是**直接子元素**；
      保留了一个 `div.table-wrap` 就不命中 ⇒ 传了是空操作（与 D12 同后果、不同成因）。
- [ ] **`CardList.text()` 只把 `null` / `undefined` 渲染成 `—`，空串 `''` 会渲染成空白。**
      桌面写 `x || '—'` 的那些列，卡片侧**必须补 `format`** 把空串也变成缺值
      （`format: (v) => (v ? String(v) : undefined)`），否则 compact 下会出现
      「桌面是破折号、卡片是空白」。fixture 里这几列要各放一行**空串**。
      ⚠️ **这一条与 10 §4.2.15 / §4.2.16 登记的那两处差异方向相反** ——
      那两处是「桌面空白 / 卡片 `—`」。不要把那两条当通则套用。
- [ ] **徽章类名不带语义 ⇒ 卡片 tone 必须从 CSS 的实际色值反查。**
      `xxxClass()` 只吐类名（`tos-ok` / `st-pending` …），tone 要按 `<style>` 里
      那一类的 `color: var(--x)` 决定。反直觉的两档实测：
      **`st-pending` 是 `--warning`**（待处理在桌面上就是黄底黄字，别按名字猜成 neutral）、
      **`st-running` 是 `--primary`**（`CardTone` 没有 primary 档 ⇒ 落 neutral，**不新造一档**）。
      ★ **门禁要去 `<style>` 抽色值交叉校验映射表**，不要把映射表自己抄一遍 ——
      改了徽章颜色忘了改映射（或反之）只有这样才会红（这是 D11 在页面级的补法）。
- [ ] **表头级批量操作在卡片形态没有对应物时，先确认它与某个按钮是否功能等价。**
      例：`FreeDiscoveryView` 的「全选」与下方「导入全部待导入」作用集合相同
      ⇒ compact 下不出全选**不是缺口**。把这条「等价」写进门禁，
      不要留给下一个人重新判断（判据：断「无 `thead`」+「等价按钮仍在且可点」）。
- [ ] **原生 `<table>` 切片要删掉自带 `overflow-x: auto` 的表格包裹 div**（连 `<style>` 规则一起），
      并按表的真实 `min-width` 决定 `table-min-width`：表**有** min-width 就传同值，
      没有才传 `0px`。★ 门禁要同时断「容器直接子元素是 `table`」与
      **「表的 CSS 里确实没有 min-width」**（后者是前者的前提，缺了它 `0px` 就是编的）。
