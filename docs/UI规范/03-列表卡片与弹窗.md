# 03 — 列表、卡片与弹窗

> 状态标记：**[已落地]** / **[部分落地]** / **[未落地]**。只描述本仓（`llm-gateway-go/web`）。

## 1. 列表：为什么分两种形态

**[已落地]** 本仓的列表数据有两种消费方式，它们是**两个独立维度**，不能互相替代：

| 维度 | 取值 | 谁负责 |
| --- | --- | --- |
| **呈现形态** | `table` / `cards` | `useDataViewMode` + `ResponsiveDataView` |
| **加载方式** | `paged` / `continuous` | `usePagination` / `createHyperPages` |

一个页面可以是「表格 + 连续加载」或「卡片 + 页码」，四种组合都合法。
参考仓把二者写在一起，容易被读成"要么表格分页、要么卡片连续"，**本仓明确拆开**。

**为什么不把 `DataTable` 改造进 `ResponsiveDataView`**：`DataTable.vue` 是**包裹模式**
（给存量手写 `<table>` 加横滚容器 + `min-width` 列宽保护），目前 **7 个视图**在用（`TenantsView` / `AnnotationStatsView` / `UsersView` /
`AnnotationView` / `RequestLogsView` / `AutoTuningView` / `TaskProfileView`）；
`ResponsiveDataView` 是**双模板**。强行合并会毁掉 `DataTable` 的零重构优势。
两者可嵌套使用。

## 2. 模式规则

### 2.1 档位规则

**[已落地]** `src/composables/useDataViewMode.ts`

| 档 | 默认 | 能否切换 | 是否写偏好 |
| --- | --- | --- | --- |
| `compact` (<768) | **卡片，强制** | 否（不渲染切换钮） | **否** |
| `medium` 及以上 | 表格 | 是：表格 ↔ 卡片 | 是，localStorage 跨页共用 |

**「compact 强制卡片」做在类型层，不是模板里 `v-if` 掉按钮。**
只隐藏按钮的话，调用方仍可能在别处调 `setMode('table')`，把横滚表格留在 320px 屏上 ——
那是规范明令禁止的降级。所以：

```ts
function setMode(next: DataViewMode): boolean {
  if (isCompact.value) return false   // ★ 直接 return，且不写存储
  ...
}
```

- 早退发生在**写存储之前**，所以 compact 下设过的模式不会带回桌面。
- `canSwitch` 驱动切换钮的 `v-if`，compact 下它**在 DOM 里不存在**（不是 CSS 隐藏）。

存储键：`llmgw_data_view_mode`（与本仓既有 `llmgw_*` 命名一致）。
存储不可用时（隐私模式 / 配额满）降级为**内存偏好**，功能不中断。

### 2.2 切换形态不重新打接口

**[已落地]** `ResponsiveDataView` **不发任何请求**。卡片与表格共用同一份 `rows`
与同一套字段政策。切换只换呈现。

这条有源码级门禁兜着：门禁扫描组件源码，命中 `fetch(` / `axios` / `XMLHttpRequest` /
`useQuery` / `useFetch` / `api.` 即报红。**若某页面在切换时 refetch，那是页面违反了约定，
应改页面，而不是放宽门禁。**

## 3. 组件用法

### 3.1 `ResponsiveDataView`（双模板，推荐新页面用）

```vue
<ResponsiveDataView
  :rows="rows"
  :title-key="name"
  :subtitle-keys="['provider', 'model']"
  :primary-field="{ key: 'cost', align: 'end' }"
  :fields="fields"
  :loading="loading"
  :empty="!rows.length"
  empty-text="还没有请求记录"
  @row-click="openDetail"
>
  <!-- 桌面表格：结构原样，不必为卡片改写 -->
  <template #table>
    <table class="data-table"><tbody>…</tbody></table>
  </template>
</ResponsiveDataView>
```

不提供 `#table` 插槽时只出卡片形态（适合 compact 独占页）。

### 3.2 `CardList`（描述驱动）

**[已落地]** `src/components/ui/CardList.vue`

| prop | 作用 |
| --- | --- |
| `rows` | 行数据（泛型 `T`） |
| `titleKey` | 卡片主体字段键（**必填**） |
| `titleFormat` | 卡头文本的格式化钩子 `(row) => string`（见下） |
| `subtitleKeys` / `metaKeys` | 副标题 / 元信息字段键数组 |
| `primaryField` | 主数值位（金额等），单字段 |
| `fields` | 其余键值对，声明式 |
| `clickable` / `clickableLabel` | 整卡可点（**仅当与「进入详情」同一意图**） |
| `loading` / `empty` / `emptyText` | 三态 |

**`titleFormat` 为什么必须存在**（2026-10-04 实测打出来的缺口）：`titleKey` 只给键，
卡头走**原始值**。以「时间」或「动作码」为主识别的列表于是会把
`2026-10-05T01:15:30.000Z`、`user.delete` 直接甩给用户 —— 本地化与译名都做不了。
`fields` 上的 `format` 救不了卡头：**它们渲染在卡的下方**。
返回 `null` / `''` 时回落到 `titleKey` 的原始值（不渲染空白卡头）；
`:key` **不走**这个钩子 —— 格式化后的标题可能重复或含时间戳，拿它当键会打乱列表复用。

**描述驱动的意义**：**未声明的键永不渲染**。这意味着新增一个敏感字段（如密钥片段、
手机号）不会因为"表格里有"就自动出现在卡片里 —— 卡片内容是显式授权的。

### 3.3 行点击是唯一必需的详情入口（compact 红线，2026-10-05 落档）

**[部分落地]** 契约自参考仓 03 §3.1（`007496e3`，2026-10-04）移植；本仓现状按条标注。

手机上的用户习惯是**点行看详情**，不会先去找一个「详情」按钮。规范因此规定：

1. **行 = 详情入口。** 有详情目的地的列表，行整体可点：`CardList` 传 `clickable`
   并监听 `@row-click`，且 `@row-click` 的行为与同页桌面侧的行点击交互**一致**
   （桌面行可点则同一意图，桌面行不可点则 compact 也不得凭空造出第二条导航）。
   **[已落地]** 本仓 8 个视图在用 `row-click`（`TenantsView` / `UsersView` / `DecisionsView` /
   `CompressionView` / `TenantDashboardView` / `AuditLogView` / `CredentialModelsPanel` /
   `ReconciliationReport`，2026-10-05 grep 实测）。
2. **禁止「详情按钮」作为唯一通路。** actions 区不得放「详情/查看」按钮来承担进入
   本行详情的唯一入口。跨实体跳转属于**另一个意图**，可以留在 actions 区，
   但它不是「进本行详情」的第二条路。
3. **可点必须看得见。** 可点行渲染右侧 chevron 指示器并有 `:active` 按压反馈；
   指示器与可点性是**同一个开关**的两个表现（依据：Vant Cell 把箭头与可点绑在
   同一个 `is-link` 上，见 [16 §3.1](./16-优秀项目对标与参考资料.md)）。
   **[已落地]** 2026-10-06 落地：`CardList` 的可点行渲染右侧 chevron 并有 `:active` 按压反馈，
   两者由**同一个 `clickable` 开关**驱动（9 条断言 + 8 条变异台账，见 10 §4.6.28）。
   〔原文保留〕2026-10-05 实测：`CardList.vue` 与 `hyper.css` 中 `:active` 零命中，
   `clickable` 行只有 `cursor` 语义，手机上看不出能点 —— 那是本轮登记的第一缺口。
4. **不可点就不许像可点。** 没有详情目的地的列表，行渲染为**非交互元素**：
   无 `cursor:pointer`、无 chevron、不进 Tab 序。
   **[已落地]** 本仓 `CardList` 用动态组件 `:is="clickable ? 'button' : 'div'"`
   ——静态行是 `div` 而非死按钮，并带 `aria-label`（`clickable` 默认 `false`）。
   参考仓的历史教训（无条件渲染 `<button>` ⇒ 7 处「按了没反应的死按钮」）
   在本仓组件设计时已规避。
5. **可点性可逐行不同。** 同一列表内部分行有详情、部分没有时，需要**逐行谓词**
   （只能收窄，不能凭空把行标成可点）。**[未落地]** 本仓 `clickable` 是整列表级
   布尔，无逐行 `navigable` ——按需扩展，不预建。
6. **写操作永远不挂在整行上。** 整行点击只承载「进详情」这一读向意图；
   禁用、揭示、重导等写操作走独立按钮（≥48px，R1）+ 确认，逻辑与桌面同一 API。

**门禁 [已落地]**：`web/src/components/ui/mobileListUx.spec.ts`（**7 条断言** + 变异台账
**10/10**，2026-10-06）。扫描 `<ResponsiveDataView>` 的全部调用点，凡 compact 下**没有入口**的，
必须登记，并写明理由：`NON_NAVIGABLE`（本无详情目的地）/ `KNOWN_GAP`（有详情目的地却无入口）。
登记表与实测集合**双向相等**；理由不得为空洞短句。

**块级「同一意图」判据（10 §4.6.38）**：作用域是**每个 `ResponsiveDataView` 块**
而不是文件 —— 同一文件可能有多个列表（`TenantDashboardView` 同时有「模型行」和
「详情里的请求行」两个不同实体，按文件比对会报假阳性）；比对的也是**目的地**
而不是函数名（`onCardClick` 转调 `viewSession` 算一致）。三条断言：

| 判据 | 拦什么 |
|---|---|
| 两种形态都在时，卡片处理函数必须就是表格那个、或 1 级转调它 | compact 与桌面指向不同意图 |
| 桌面表格行可点而卡片不可点 ⇒ 必须登记 | compact 静默丢掉该入口（LogsTab 同款，自动捕获） |
| `ASYMMETRY` 登记与实测双向相等 + 理由不得空洞 | 不对称被悄悄忘掉 |

当前 `ASYMMETRY` 登记唯一一条：`TenantDashboardView.vue:716`（卡片跳 `/request-logs`，
桌面页脚有同一目标的 `RouterLink`；桌面行是否也整行可点待裁决）。

⚠️ **原门禁描述与本仓实际形状不符，已按实测改写**：原写「扫 `CardList` 调用点 +
`#cards` 插槽两层」是照参考仓的形状写的；本仓 `web/src` 里 `#cards` 插槽**零消费者**，
卡片全部由 `ResponsiveDataView` 默认渲染，而本仓的行点击另有**第二套实现**
（桌面原生 `<tr class="row-click" @click>`，compact 下不存在）。门禁因此扫的是
`<ResponsiveDataView>` 调用点 + 插槽形态。

**首轮实测结论**（33 个调用点）：13 个 compact 无入口，其中 **11 个确属「无详情目的地」**，
**2 个是真缺口**（`ApprovalListView.vue:451`、`LogsTab.vue:289`）—— 详见 10 §4.6.35。

- `LogsTab.vue` **已修**（2026-10-06，10 §4.6.36）：canonical 跨实体入口从
  `#table` 移到 `#actions`，复用同一个 `ModelIdentityChip`，桌面零改动，已销账；
- `ApprovalListView.vue` **仍未修**，等用户裁决（桌面行是否整行可点 ——
  该行内有 ✕ 拒绝写操作，整行可点会抬高误触）。

⇒ `KNOWN_GAP` 是「已登记的不合格」，**不是合格**；门禁只保证它不被悄悄忘掉。

### 3.4 小屏（320px）字段展示地板

**[未落地]** compact 卡的可用宽度按 **320 CSS px** 设计，不按 390px——390px 只是
常见机型，320px 才是下限（iPhone SE 1 代 / 小窗 WebView）。本仓 `style.css`
**没有** `html/body { min-width: 320px }` 一类的文件级保证（2026-10-05 实测；
仅个别选择器有 360px 局部最小宽），落地时补。

| 位置 | 下限 | 说明 |
| --- | --- | --- |
| title / primary 值 | 15px（0.9375rem） | 主体识别名与主数值是卡片上最重要的可读文本 |
| subtitle / fields | 13px（0.8125rem） | 次要字段 |
| tag | 12px（0.75rem） | 状态色不单独承义，标签必须自带文字 |
| 行触控目标 | 44px 存量基线；**compact 新控件 ≥48px**（R1，本仓已修，见 10 §4.6.5） | 行已是详情主入口，不再停在 44px |

布局要求：

- 字段容器必须 `flex-wrap: wrap`：320px 下标签与值挤不下时**值换到下一行**，
  不截断、不溢出。
- title / subtitle / field-value 必须 `overflow-wrap: anywhere`：长请求 ID、长模型名、
  脱敏后仍长的账号串不得撑破窄屏。
- 一屏之内不做二次折叠；字段多于 3 行就说明这些字段属于详情页，删到 ≤3 行
  而不是加折叠开关。
- **禁止**用「横滑宽表」代替卡片。本仓 `DataTable` 包裹模式（横滚 + `min-width`
  列宽保护）是**存量降级**兜底，新列表页不得只交横滚（见 §2.1「compact 强制卡片」
  在类型层的实现）。

  **[门禁已落地]** `web/scripts/compact-card-coverage.mjs`（`pnpm card:coverage`，
  自检 `pnpm card:coverage:self-test`，2026-10-06）。它是一道**棘轮门**：
  存量基线与实测集合**双向相等** ——
  新增一个只交横滚的视图 ⇒ 红；基线里某条已补卡片形态 ⇒ 红（提示收基线）。
  存量本身**不判红**：03 §3.4 明确横滚是存量降级兜底。
  实测与台账见 10 §4.6.37。

## 4. 空态 / 加载 / 错误

**[已落地]** 三态由 `ResponsiveDataView` 在**两种形态之外**统一裁定：

```
loading  → <AppSpinner />            （两种形态都不渲染）
empty    → <EmptyState />            （两种形态都不渲染）
else     → 表格 或 卡片
```

这样切形态时不会出现「表格有骨架、卡片空白一片」的错位。
`empty` 与 `loading` 同时为真时 **`loading` 优先**（门禁有断言）。

**★ 例外：三态原本长在表格里的页面（2026-10-04，`AuditLogView` 打出来的）**

上面这条规则的前提是「桌面三态也在容器之外」。有的页面的 loading / empty 是
**表格内部的一行**（`<tr class="state-cell">`），桌面刷新时表头照常显示，
只是表内多一行字。这类页面若把三态交给容器，桌面刷新会变成
「整张表连 `<thead>` 一起消失」—— 肉眼可见的观感回退，且**不会报任何错**。

⇒ 这类页面的做法是：`:loading` / `:empty` 都带档位前置，
**只让 compact 走容器裁定**，桌面继续由表格自己出：

```
:loading="isCompact && busy"        // compact 才由容器出转圈
:empty="isCompact && !busy && rows.length === 0"
```

判断依据：**桌面刷新时表格在不在**。若原本桌面也不出表头（loading/empty 本来
就在容器之外），就不需要这个前置，按上面的通例接即可。

**★ 第二类例外：桌面在空态时把整块容器撤掉（2026-10-04，`TenantModelsView` 打出来的）**

有的页面的桌面空态是 `v-else-if="!rows.length"`，它把**整个列表卡片**（连标题带）
从 `v-else` 链里撤掉 —— 空态时容器压根不存在。这类页面**既不需要 `:empty`
也不需要 `:loading`**：容器挂在 `v-else` 分支里，无数据时根本不挂载，
两档共用页面自己的 `.empty`。

⇒ 三种形态的判据是同一句：**空态那一刻，那块东西在不在**。

| 形态 | 桌面空态 | 容器的 `:empty` / `:loading` |
| --- | --- | --- |
| 通例 | 三态在容器之外 | 照常传 |
| 例外一 | 空态是表内一行（`<tr class="state-cell">`），表还在 | 都带 `isCompact` 前置 |
| 例外二 | 空态把整块列表卡片撤掉，容器不挂载 | **都不传** |

**★ 第四种：空态在表格之外、但整块表壳不能空**（切片七/八）
这类页面桌面是「有行出表、没行出 `.empty`」。把 `v-if` 提到容器外的话，
空态下容器仍会渲染一个**带边框的空表壳** ⇒ `#table` 槽内**必须保留 `v-if`**，
并配一条反向约束（空态时 DOM 里一个 `<table>` 都不剩）。

**「无记录」与「筛选无结果」应分文案**，后者要给出清筛选入口。
本仓 `emptyText` 可覆盖默认文案，但**分文案的判定尚未在组件内实现**，
属于调用方责任（见 00 §9.4 未落地项）。

## 5. 弹窗与抽屉

### 5.1 单一真源：覆盖层只认 `OverlayRegistry`

**[已落地]** 覆盖层的唯一真源是 `src/lib/shell/hyper/overlay.ts` 的 `OverlayRegistry`。
`src/composables/useOverlayStack.ts` 已改为它的**门面**，不再维护独立栈。

> **为什么要合并**：改造前 ESC 依据 `useOverlayStack` 的栈关闭，
> 系统返回依据 `Hyper` 的 `OverlayRegistry` 关闭 —— 两个独立栈会关掉**不同的层**。
> 用户看到的是"按了返回没反应，再按一次弹窗突然全没了"。

弹层组件需登记**真实的关闭动作**（各加一行）：

```ts
// AppModal.vue / AppDrawer.vue
setOverlayLayerClose(overlayId, requestClose)
```

- 幂等 register / unregister。
- 订阅者异常隔离：一个订阅者抛错不影响其它层。
- `closeTop()` 有三条拒绝路径（无守卫 / 守卫拒绝 / 非顶层）。
- 支持 `upgrade()`：同 id 重入时升级元数据而不是压入新条目。

### 5.2 写操作弹窗

桌面保持对话框宽度，**不得因 Hyper 改造而变宽**。这是桌面零回归红线的一部分。
`dialog` 宽度有既有的 `ui:check:strict` 门禁守着。

### 5.3 详情抽屉

**[既有]** 存量视图用 `AppDrawer`（z-index 100）。抽屉与弹窗共用同一份
`OverlayRegistry`，所以返回键与 ESC 对它们的行为一致。
