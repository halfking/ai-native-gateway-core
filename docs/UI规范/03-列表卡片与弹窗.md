# 03 — 列表、卡片与弹窗

> 状态标记：**[已落地]** / **[部分落地]** / **[未落地]**。只描述本仓（`llm-gateway-go/web`）。

## 1. 列表：为什么分两种形态

**[已落地]** 本仓的列表数据有两种消费方式，它们是**两个独立维度**，不能互相替代：

| 维度 | 取值 | 谁负责 |
| --- | --- | --- |
| **呈现形态** | `table` / `cards` | `useDataViewMode` + `ResponsiveDataView` |
| **加载方式** | `paged` / `continuous` | `usePagination` / `createHyperPages` |

一个页面可以是「表格 + 连续加载」或「卡片 + 页码」，四种组合都合法。
参考仓把二者写在一起，容易被读成"要么表格分页、要么卡片连续"，**本仓明确拆开**。

**为什么不把 `DataTable` 改造进 `ResponsiveDataView`**：`DataTable.vue` 是**包裹模式**
（给存量手写 `<table>` 加横滚容器 + `min-width` 列宽保护），目前 **7 个视图**在用（`TenantsView` / `AnnotationStatsView` / `UsersView` /
`AnnotationView` / `RequestLogsView` / `AutoTuningView` / `TaskProfileView`）；
`ResponsiveDataView` 是**双模板**。强行合并会毁掉 `DataTable` 的零重构优势。
两者可嵌套使用。

## 2. 模式规则

### 2.1 档位规则

**[已落地]** `src/composables/useDataViewMode.ts`

| 档 | 默认 | 能否切换 | 是否写偏好 |
| --- | --- | --- | --- |
| `compact` (<768) | **卡片，强制** | 否（不渲染切换钮） | **否** |
| `medium` 及以上 | 表格 | 是：表格 ↔ 卡片 | 是，localStorage 跨页共用 |

**「compact 强制卡片」做在类型层，不是模板里 `v-if` 掉按钮。**
只隐藏按钮的话，调用方仍可能在别处调 `setMode('table')`，把横滚表格留在 320px 屏上 ——
那是规范明令禁止的降级。所以：

```ts
function setMode(next: DataViewMode): boolean {
  if (isCompact.value) return false   // ★ 直接 return，且不写存储
  ...
}
```

- 早退发生在**写存储之前**，所以 compact 下设过的模式不会带回桌面。
- `canSwitch` 驱动切换钮的 `v-if`，compact 下它**在 DOM 里不存在**（不是 CSS 隐藏）。

存储键：`llmgw_data_view_mode`（与本仓既有 `llmgw_*` 命名一致）。
存储不可用时（隐私模式 / 配额满）降级为**内存偏好**，功能不中断。

### 2.2 切换形态不重新打接口

**[已落地]** `ResponsiveDataView` **不发任何请求**。卡片与表格共用同一份 `rows`
与同一套字段政策。切换只换呈现。

这条有源码级门禁兜着：门禁扫描组件源码，命中 `fetch(` / `axios` / `XMLHttpRequest` /
`useQuery` / `useFetch` / `api.` 即报红。**若某页面在切换时 refetch，那是页面违反了约定，
应改页面，而不是放宽门禁。**

## 3. 组件用法

### 3.1 `ResponsiveDataView`（双模板，推荐新页面用）

```vue
<ResponsiveDataView
  :rows="rows"
  :title-key="name"
  :subtitle-keys="['provider', 'model']"
  :primary-field="{ key: 'cost', align: 'end' }"
  :fields="fields"
  :loading="loading"
  :empty="!rows.length"
  empty-text="还没有请求记录"
  @row-click="openDetail"
>
  <!-- 桌面表格：结构原样，不必为卡片改写 -->
  <template #table>
    <table class="data-table"><tbody>…</tbody></table>
  </template>
</ResponsiveDataView>
```

不提供 `#table` 插槽时只出卡片形态（适合 compact 独占页）。

### 3.2 `CardList`（描述驱动）

**[已落地]** `src/components/ui/CardList.vue`

| prop | 作用 |
| --- | --- |
| `rows` | 行数据（泛型 `T`） |
| `titleKey` | 卡片主体字段键（**必填**） |
| `titleFormat` | 卡头文本的格式化钩子 `(row) => string`（见下） |
| `subtitleKeys` / `metaKeys` | 副标题 / 元信息字段键数组 |
| `primaryField` | 主数值位（金额等），单字段 |
| `fields` | 其余键值对，声明式 |
| `clickable` / `clickableLabel` | 整卡可点（**仅当与「进入详情」同一意图**） |
| `loading` / `empty` / `emptyText` | 三态 |

**`titleFormat` 为什么必须存在**（2026-10-04 实测打出来的缺口）：`titleKey` 只给键，
卡头走**原始值**。以「时间」或「动作码」为主识别的列表于是会把
`2026-10-05T01:15:30.000Z`、`user.delete` 直接甩给用户 —— 本地化与译名都做不了。
`fields` 上的 `format` 救不了卡头：**它们渲染在卡的下方**。
返回 `null` / `''` 时回落到 `titleKey` 的原始值（不渲染空白卡头）；
`:key` **不走**这个钩子 —— 格式化后的标题可能重复或含时间戳，拿它当键会打乱列表复用。

**描述驱动的意义**：**未声明的键永不渲染**。这意味着新增一个敏感字段（如密钥片段、
手机号）不会因为"表格里有"就自动出现在卡片里 —— 卡片内容是显式授权的。

## 4. 空态 / 加载 / 错误

**[已落地]** 三态由 `ResponsiveDataView` 在**两种形态之外**统一裁定：

```
loading  → <AppSpinner />            （两种形态都不渲染）
empty    → <EmptyState />            （两种形态都不渲染）
else     → 表格 或 卡片
```

这样切形态时不会出现「表格有骨架、卡片空白一片」的错位。
`empty` 与 `loading` 同时为真时 **`loading` 优先**（门禁有断言）。

**★ 例外：三态原本长在表格里的页面（2026-10-04，`AuditLogView` 打出来的）**

上面这条规则的前提是「桌面三态也在容器之外」。有的页面的 loading / empty 是
**表格内部的一行**（`<tr class="state-cell">`），桌面刷新时表头照常显示，
只是表内多一行字。这类页面若把三态交给容器，桌面刷新会变成
「整张表连 `<thead>` 一起消失」—— 肉眼可见的观感回退，且**不会报任何错**。

⇒ 这类页面的做法是：`:loading` / `:empty` 都带档位前置，
**只让 compact 走容器裁定**，桌面继续由表格自己出：

```
:loading="isCompact && busy"        // compact 才由容器出转圈
:empty="isCompact && !busy && rows.length === 0"
```

判断依据：**桌面刷新时表格在不在**。若原本桌面也不出表头（loading/empty 本来
就在容器之外），就不需要这个前置，按上面的通例接即可。

**★ 第二类例外：桌面在空态时把整块容器撤掉（2026-10-04，`TenantModelsView` 打出来的）**

有的页面的桌面空态是 `v-else-if="!rows.length"`，它把**整个列表卡片**（连标题带）
从 `v-else` 链里撤掉 —— 空态时容器压根不存在。这类页面**既不需要 `:empty`
也不需要 `:loading`**：容器挂在 `v-else` 分支里，无数据时根本不挂载，
两档共用页面自己的 `.empty`。

⇒ 三种形态的判据是同一句：**空态那一刻，那块东西在不在**。

| 形态 | 桌面空态 | 容器的 `:empty` / `:loading` |
| --- | --- | --- |
| 通例 | 三态在容器之外 | 照常传 |
| 例外一 | 空态是表内一行（`<tr class="state-cell">`），表还在 | 都带 `isCompact` 前置 |
| 例外二 | 空态把整块列表卡片撤掉，容器不挂载 | **都不传** |

**★ 第四种：空态在表格之外、但整块表壳不能空**（切片七/八）
这类页面桌面是「有行出表、没行出 `.empty`」。把 `v-if` 提到容器外的话，
空态下容器仍会渲染一个**带边框的空表壳** ⇒ `#table` 槽内**必须保留 `v-if`**，
并配一条反向约束（空态时 DOM 里一个 `<table>` 都不剩）。

**「无记录」与「筛选无结果」应分文案**，后者要给出清筛选入口。
本仓 `emptyText` 可覆盖默认文案，但**分文案的判定尚未在组件内实现**，
属于调用方责任（见 00 §9.4 未落地项）。

## 5. 弹窗与抽屉

### 5.1 单一真源：覆盖层只认 `OverlayRegistry`

**[已落地]** 覆盖层的唯一真源是 `src/lib/shell/hyper/overlay.ts` 的 `OverlayRegistry`。
`src/composables/useOverlayStack.ts` 已改为它的**门面**，不再维护独立栈。

> **为什么要合并**：改造前 ESC 依据 `useOverlayStack` 的栈关闭，
> 系统返回依据 `Hyper` 的 `OverlayRegistry` 关闭 —— 两个独立栈会关掉**不同的层**。
> 用户看到的是"按了返回没反应，再按一次弹窗突然全没了"。

弹层组件需登记**真实的关闭动作**（各加一行）：

```ts
// AppModal.vue / AppDrawer.vue
setOverlayLayerClose(overlayId, requestClose)
```

- 幂等 register / unregister。
- 订阅者异常隔离：一个订阅者抛错不影响其它层。
- `closeTop()` 有三条拒绝路径（无守卫 / 守卫拒绝 / 非顶层）。
- 支持 `upgrade()`：同 id 重入时升级元数据而不是压入新条目。

### 5.2 写操作弹窗

桌面保持对话框宽度，**不得因 Hyper 改造而变宽**。这是桌面零回归红线的一部分。
`dialog` 宽度有既有的 `ui:check:strict` 门禁守着。

### 5.3 详情抽屉

**[既有]** 存量视图用 `AppDrawer`（z-index 100）。抽屉与弹窗共用同一份
`OverlayRegistry`，所以返回键与 ESC 对它们的行为一致。

## 7. 新增列表页的检查项

1. 用 `ResponsiveDataView` 而非裸 `<table>`（compact 不会被迫横滚）
2. 字段在 `fields` / `subtitleKeys` 里**显式声明**再依赖它渲染
3. 切换形态不 refetch
4. 加载方式选 `paged` 还是 `continuous` 明确写下来，不要靠默认
5. `empty` 与「筛选无结果」分文案
6. 跑 `pnpm color:check`（不要写 `var(--不存在的令牌, #字面值)`，见 00 §9.6）
