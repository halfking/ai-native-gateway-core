## 1. 原始需求与问题

原始需求四条：

1. 学习 `nbjl-3/docs/UI规范`，构建 llm-gateway-go 的移动端项目（Hyper 类型，可构建 Android）；
2. 后端与网页在 `llm-gateway-go` 目录内，网页按规划构建；
3. 学习 `nbjl-3` 的前端适配规范，完善 UI 规范文档；
4. 编写前端项目；先完善需求、形成优化方案，再执行。

**原需求不足以直接实施**，缺三处：①「Hyper 类型」在 nbjl3 是一整套运行时（导航上下文/滚动手势/专注/原生能力/任务），没说清本轮做到哪一层；②「网页按规划构建」指向不明——本仓已有一份 2026-09-12 的响应式方案且 P0–P5 已于 09-13 全部收口（见 §3.2），照它再做一遍是重复劳动；③「Android 可构建」没定义验收层级。

§2 补齐这些，§5–§7 给出方案与分期。

## 4. 四项前置决策（已拍板）

| 决策 | 选定 | 理由 | 被否方案与代价 |
| --- | --- | --- | --- |
| D1 工程形态 | **壳 + 复用 web 同一套 SPA**（nbjl3 同构）：`llm-gateway-client` 只建 Capacitor 壳，Hyper 运行时与 compact 组件加进 `web/src` | 单一业务事实源；权限/字段脱敏/103 路由不重复；桌面零回归可保证；后端零改动 | 否决「独立移动端 SPA」：会出现第二套业务前端，规范禁止页面副本；否决「只做壳不动 web」：交付不构成 Hyper |
| D2 断点体系 | **沿用现有 SSOT + 新增 window class 映射层**：`compact <768` / `medium 768–1023` / `expanded 1024–1439` / `large ≥1440` | 保住 `responsive:check` 白名单与 43 文件存量，零视觉回归 | 否决切 600/960/1280：改动面覆盖 95 视图、需重写审计白名单、回归风险高 |
| D3 Android 验收 | **实跑 `gradlew assembleDebug` 出 APK + 模拟器验证启动/引导页/远端加载** | 「可构建」需要构建证据，不能只交结构 | 否决只做结构校验：未证明依赖与 SDK 版本真能编译 |
| D4 规范落点 | **llm-gateway-go 新建 `docs/UI规范/` 专题**，按本仓现状重写 | 规范与被规范对象同仓，与门禁闭环；无需跨仓分叉 | 否决改 yatao/nbjl3：两产品差异需在正文分叉，且规范离开被规范对象 |

> D2 的映射表是**本仓与参考规范的已知差异**，必须在规范正文明示（见 `01-原则与断点.md` §2），不得让后来者以为 600/960/1280 可以直接照抄。

## 5. 优化方案

### 5.1 三层形态

```
┌─ 桌面浏览器 ≥1024 ────────────────┐  ┌─ compact WebView <768 ─────────────┐
│ 现状专业顶栏 + 高密度表 + 居中弹窗  │  │ Hyper 顶栏(返回/标题/更多)          │
│ （本轮零改动，红线）               │  │ + 底栏≤5席 + 抽屉 + 账户 Sheet       │
└───────────────────────────────────┘  │ + 卡片列表 + 连续加载 + 专注层       │
                                       └────────────────────────────────────┘
                                        ↑ 同一套 SPA，由 window class 分支
┌─ 原生壳 Capacitor ──────────────────────────────────────────────────────┐
│  图标/启动屏/网络豁免/插件位/进程                                        │
│    ↓ 冷启动：引导页 webDist/index.html（壳内唯一打包物，零 Vue）         │
│    ↓ 服务器地址 + GET /healthz + location.replace                        │
│  业务 SPA（web/ 构建产物）— Bearer + sessionStorage，与桌面同一套       │
└─────────────────────────────────────────────────────────────────────────┘
```

**壳内不打包 `web/dist`。** 改 Vue 组件 = 发 Web，不发商店包；改引导页 / `capacitor.config.ts` / 图标 = 必须 `npx cap sync` 再编原生。

### 5.2 分层与 SSOT

| 层 | 落点 | 责任 | 禁止 |
| --- | --- | --- | --- |
| 断点 SSOT | `web/src/config/window-class.ts`（新） | 四档语义 + 与 `breakpoints.ts` 的派生关系 | 组件内出现 px 判定 |
| 运行时 | `web/src/lib/shell/hyper.ts`（新） | 标题真源、导航上下文、返回仲裁、覆盖层登记、能力协商 | 页面自造导航栈、凭据、原生调用 |
| 壳组件 | `web/src/components/shell/`（扩） | 底栏、账户 Sheet、Hyper 顶栏 | compact 顶栏堆系统设置 |
| 列表 | `web/src/components/ui/`（扩） | `ResponsiveDataView` / `CardList` / `HyperLoadMore` / `FocusWorkspace` | compact 只横滚 |
| 原生壳 | `llm-gateway-client/` | 进程、图标、启动屏、引导页、桥 | 存 Token、打包业务 dist、第二套登录 UI |

#### 9.5.2 判据缺陷（比实现缺陷更值得记）

三条判据看起来在测东西，实际**恒真**或**与实现语义相反**：

1. **跨租户用例用了按「页号」索引的假数据源。** 切租户后重取第 1 页拿回的仍是旧租户的行，于是「只有 B 的行」这个断言**即使 revision 闸门完全失效也能通过**。
2. **retry 用例断言 `calls == [1,2,3]`**，即期望**跳过**失败的那一页 —— 这恰好是会静默丢一整页数据的错误行为。正确契约是 `[1,2,2]`。
3. **「refresh 失败保留旧数据」在按页号索引的数据源上根本无法构造**：那条路径上第 1 页永远成功，`refresh()` 返回 `true` 才是正确行为。

根因是同一个：**按页号索引的假数据源表达不了「同一页、不同次调用、不同结果」**。而单飞、重试、刷新、跨租户这四个语义**全部**依赖这个维度。已把它固化成 `seqFetcher`（按调用次序）与 `tenantFetcher`（按发出时刻的租户快照）两个替身，并在注释里写明什么场景必须用它们 —— 同一个 spec 里连续踩了三次才认出来。

- **双层防御（M1a/M1b、N7）**：revision 闸门在 `loadPage` 与 `commit` 各有一层，`setMode` 的 compact 早退与 `initial` 的 compact 判断各有一处。摘掉单层时另一层仍然挡住 ⇒ 门必然绿。已补「两层同摘」变异（M1c / N7b），分别转红 4 例与 3 例，证明这一对是**承重**的而非摆设。
- **不可达守卫（L3/L8/L14）**：`sentinel 在 DOM 中 ⟺ autoTriggerEnabled` —— 模板的 `v-if` 分支就是这条等价式的执行点。所以 `setupObserver` 里那三处 JS 守卫在当前模板下**可证明不可达**，真正承重的是模板分支。L8 那处已删除；L3/L14 保留但在代码注释里写明「当前模板下不可达，保留它只为防模板被改坏时症状难定位」。
- **锚点失效（L8 重跑）**：实现调整后锚点不存在，脚本如实报 INVALID 而不是伪装成通过。
- **fixture 在「两个阈值的中间带」里没有取值（切片十三 M25）**：`fmtUsd` 的毫单位阈值
  0.001 被挪到 0.01，若 fixture 的成本要么 0、要么 ≥0.01，**阈值怎么挪输出都一样** ⇒
  变异无牙。补一行落在 (0.001, 0.01) 的取值才红。
  与切片八 M10（`fmtMs` 阈值 1000 → 1500 缺中间带取值）是同一个坑，**连着两条切片各踩一次**
  ⇒ 写完格式化函数的门禁，回头逐个阈值检查「左右两侧有没有取值、中间带有没有取值」。
- **锚点落进注释（切片十四 M01/M07/M08）**：变异改的是**说明注释**，门禁读的是**剥掉注释后的代码**
  ⇒ 什么都没变却报 GREEN。处置是在写入后自检「剥注释后是否真的变了」，单列 `NOT_APPLIED`。
  ⚠️ **而那个自检自己第一次就没跑过** —— 写成了 Python 的 `str.replace(r"/*[\s\S]*?*/", "")`，
  但 `str.replace` 是**字面量**替换（JS 的 `String.replace(/re/g)` 才当正则），
  于是它永远不匹配、永远不报错。**一个永远不触发的检查不报任何错**，
  3 条注释命中就以 GREEN 的面目通过了第一轮。
  ⇒ **给变异脚本加任何自检/兜底/守卫之后，必须先拿一个「已知会命中」的输入证明它会触发**
  （`assert_stripper_works()` 用一个已知探针，不通过就中止整轮台账）。
  判别动作很便宜：喂一个已知输入，看它报不报。
- **「突变值恰好等于默认值」**（切片十五，三条无牙同族）：`days` 写死 30（默认就是 30）、
  `catch` 里不再 `data = null`（首屏本来就是 null）、`?? 0` 去掉（缺值行在另一张表上）。
  症状统一是「门没红」，但**病根是变异没制造出差异**，不是门弱。
  ⇒ 判别动作固定成一条：**突变值是否等于默认值**；是则先把系统驱动到别的态再断。
- **「缺陷是真的，严重程度是我编的」**（切片十四 D12）：我读码得出
  「`table-min-width` 对 el-table 无效」，**正确**；但接着推出
  「所以这 2 个候选做不了、需产品拍板」，**是过度声明**。
  实测（把 el-table 塞进槽里 dump 容器的直接子元素，并自证同一套代码在原生 `table` 时
  能取到 `["table"]`）显示：compact 下 el-table 压根不渲染、Element 自带内部滚动 ⇒
  **不构成阻塞**。⇒ **「机制成立」不等于「后果成立」**，
  两句之间那一步必须单独验，否则会把一个事实包装成一个假的产品决策点。
- **空杠杆（切片十三 M35，作废）**：给容器加 `allow-switch` 想让「compact 下不出切换钮」变红，
  但 `canSwitch = !isCompact` **本就 false**，传了也是空操作。
  这类变异要**先读组件语义**再写，否则会把「变异无效」误记成「门禁无牙」。
- **格式化器自带回落 ⇒ 调用点的显式兜底不可达（切片十六，2 条）**：`fmtDateTime24h`
  开头就是 `if (!iso) return '—'` ⇒ 桌面 `{{ v ? fmtDateTime24h(v) : '—' }}` 那个
  三元的右支**永远走不到**；卡片侧把三元去掉，门也不红（`undefined` 与 `—` 在
  `CardList` 里渲染逐字相同）。这与「突变值等于默认值」是**两种不同的行为等价**：
  那一族是**状态没被驱动到**，这一族是**这一行的另一支根本到不了**。
  判别动作：给某个值加显式兜底之前，先打开那个格式化函数**看它对缺值已经返回什么** ——
  **两处都写了同一个 `—` 的时候，删掉外层那个，输出不变**，这是可验证的、不是风格问题。
- **代理指标与它想代理的量不是一回事（切片十六）**：候选表里 `VibeCodingView` 那格
  「对话框 **27**」是 grep 计数，实测只有 **3 个 `AppModal` 且全在列表区之外**。
  ⇒ 与「行数是最弱的代理指标」同族，但更隐蔽：**每个复杂度维度都值得单独校准一次**，
  问「它到底在数什么」。基于错误信号做的排序，结论会反着来。
- **「门未红」的第一成因是「我根本没断那一条」（切片十七，7 条里占 6 条）**：
  逐条查因后发现 M13（只断空态**出现**、没断**说了什么**）、M25（没断某格是不是格式化后的串）、
  M28（漏了 T2 那一段的状态译名）、M44 / M47（fixture 从不出现「0 个可选项」，
  且没有任何断言读表头 checkbox 的 `checked`）—— **全是断言压根不存在**，
  不是实现绕过了断言。M01（`title-key` 换成会撞键的字段）则是
  **Vue 3 初次渲染既不报重复 key 警告、也不产生 DOM 差异**（与 D2 一致），
  最后靠一条**结构断言**（五处 `title-key` 统一 `id`）兜住。
  ⇒ **前六种成因都是「实现绕过了断言」，这一种是「断言不存在」——
  症状一样（门绿），处置完全相反：前者改实现或换变异，后者只能补断言。**
  判别动作极便宜：**把那一条的判据句子读出来，看它断言的到底是哪个节点、哪个属性；
  读不出来就是没断过。** 这次 7 条里有 6 条在「读判据」这一步就露馅了。
- **代理指标会虚高，且会虚高在你想避免的那个维度上（切片十六 + 十七）**：
  候选表里 `VibeCodingView` 的「对话框 27」实测 **0**（grep 数的是提到对话框的次数，
  不是与列表区的耦合面）；`AgentRegistryView` 的「对话框 25」同样 **0**；
  `FreeDiscoveryView` 的「定时器 2」是 **toast 自动消失**（6s/8s），不是轮询；
  「分页 12 / 14」与实测口径对不上（真分页只有两页，且是手写 `offset` 而非 `createHyperPages`）。
  ⇒ 排序表里每个「复杂度」格子都值得**单独校准一次**；
  **基于错信号做的排序，结论会反着来**（第十六、十七条各栽了一次）。
- **自证既要证明「会触发」，也要证明「不会误触发」（切片十六）**：
  上一条的「兜底检查从不触发」是**漏报**；换保守版剥注释器后，
  `assert_stripper_works()` 又对着 `` const t = `a//b` `` **报了假阳性**
  —— 「`//` 到行尾」那套正则把反引号串里的 `//` 当成注释起点。
  ⇒ 误伤比漏剥危险：漏剥至多让某条 grep 断言误绿，**误伤会让判据看见一份残缺源码**
  （「锚点落进注释」那类误判就是这么来的）。只做前半截的自证会变成一台
  专门制造假警报的机器 —— 它**看起来**比没有自证更可靠。
- **「我根本没断那一条」是占比最高的成因，且占比还在涨（切片十八：13 条无牙里 11 条）**。
  这一轮的 11 条逐条查因，**全部是断言不存在**，其中四类值得单列：
  - **同一个字段的两条性质，只断了一条**。`严重度` 字段断了 `data-tone`（色）却没断
    **文本**，把它的 `format` 整个删掉（卡片出裸枚举 `critical`）照样绿。
    ⇒ 断了一个字段的 `tone` 就要连它的**译名**一起断。
  - **判据写在整块标签上、且用的是「或」**。`expect(tag).toMatch(/:(loading|empty)="[^"]*isCompact/)`
    只要求 loading **或** empty 里有一个带前置 ⇒ 把 `:loading` 的前置去掉、
    同标签上的 `:empty` 还带着，绿。⇒ **逐 prop 抽出来断，别在整块上做「或」匹配**。
  - **分支只在「第 1 页失败」下验过**。`retry()` 与 `loadFirst()` 在第 1 页失败时
    发出的请求**逐字相同**（都是 `offset=0`）⇒ 把 `@retry` 接到 `loadFirst` 上输出不变。
    ⇒ **要让两者分得开，必须让非第 1 页失败**（本轮改成第 2 页失败、断重试仍打 `offset=50`）。
  - **某属性只被组件的「自动触发」那一路读，而门禁是直接发事件驱动**。
    `HyperLoadMore` 的 `hasMore` 只进 `canTrigger`，而门禁用 `$emit('load-more')`
    绕过它 ⇒ 改成源码级接线断言，并**在注释里写明它是接线断言不是行为断言**。
- **`CardField.tone` 在 `type` 不是 `metric`/`badge` 时被**静默丢弃**（切片十八查出的实现缺口）：
  `CardList.fieldTone` 开头是 `if (f.type !== 'metric' && f.type !== 'badge') return undefined`
  ⇒ 给了 `tone` 却忘了 `type`，`data-tone` 属性**整个不渲染**，没有任何报错。
  同页的 `严重度` 带了 `type: 'badge'`、`状态` 没带 —— **这种不对称本身就是「漏了」的证据**。
  ⇒ 给 `CardField` 配 `tone` 时，**`type` 不是可选的附属品**。
- **`ResponsiveDataView` 在 `loading` 时整个不渲染 `CardList`**（切片十八量具自身缺陷）：
  判据查的是 `.card-list__state`，实测忙碌标记是容器自己的 `.responsive-data-view__state`。
  ⇒ 「列表区在忙」有两个可能的位置，先 dump 再断。
- **门禁的装置自己会泄漏：`vi.clearAllMocks()` 只清调用记录、**不清实现****（切片十八）。
  一条用了 `mockRejectedValue`（非 `…Once`）的用例会把那个实现**永久**留给它后面的每一条
  ⇒ 本轮 11 条红里 8 条症状是「列表 0 张卡」，真因是**门禁自己的装置**。
  **症状与病因不同形**（0 张卡 = 「请求失败」也 = 「不出卡」），照症状改实现会把对的改坏。
  判别：**整组单独跑一遍**（跳过污染源就绿 ⇒ 是泄漏）；修法是 `beforeEach` 每条都装回基线实现，
  并**把「施害/受害」两条相邻用例写进门禁钉住它** —— 只写受害那条，它单独跑时永远绿。
- **「有某个词」不等于「有这个东西」**（切片十八）：`expect(cssBody).toMatch(/border:/)`
  被 `border: none;` 照样匹配 ⇒ 判据给的是**假牙**。要断「有宽度的边框」就写
  `/border:\s*(?!none\b|0\b)\S/`。与「突变值等于默认值」同族：**断言的存在形式让它空转**。
- **变异锚点不唯一 ⇒ 打到了**别的**同名规则**（切片十八 M45）：
  `.table-wrap` 的 `border: 1px solid var(--border);` 与 `.stat-card` 等 7 处逐字相同，
  `replace(…, 1)` 改的是**文件里第一处**（`.stat-card`）⇒ 被检验对象纹丝不动，门当然绿。
  处置：锚点带上规则名（`".table-wrap {\n  border: …"`）。
  **与「锚点落进注释」同族，都是「变异没打中它声称打中的东西」** ——
  脚本如实报 GREEN 是对的，错的是我读表时的结论。

另有 **P7 的教训**：`v-else` 改成 `v-if` 丢了表达式导致模板编译失败。**编译失败不算变异证据** —— 换成「让表格分支恒真」的单点变异后转红 3 例。

#### 9.5.4 顺带纠正的两处量具自身缺陷

- **源码断言只剥块注释不够**：`HyperLoadMore.vue` 的解释性 `//` 行注释里全是中文，被「无硬编码中文」门禁判成违规。已补行注释剥离（正则避开 `://` 以免截断 URL）。这与本仓既有教训一致：*源码断言前先剥全部注释*。
