## 0. 总览：三条数据流 + 两道红线

```
【行情流（单向下行，红线：绝不回流路由/计费）】
salesdecorate 采集（每日 01:00，wa-pg17）
  → scripts/market-price-sync.py（宿主 cron 02:30，docker exec psql 两侧访问）
  → 网关 940 表 market_price_reference（P1 原厂锚 + P2 市场最低 + fx 快照）
  → GET /api/admin/maas/market-price-overview（superAdmin 只读）
  → 定价页「行情对比」弹窗（市场最低 / 原厂锚 / 我方零售 / 溢价比）

【定价流（版本账，计费热路径照旧读 model_credit_rates）】
admin PUT model-rates / batch / batch-fill-global / reset / delete
  → maas.SyncPayAsYouGoPriceVersion（同步钩子，best-effort 不回滚计价）
  → 950+2 迁移 model_price_versions（(模型,模式,生效起点) PK + 现行期唯一索引）
  → GET model-price-history / model-price-changes + 定价页「历史」「订价变化」弹窗

【统计流（迟到行补统）】
request_logs_with_current_month（会话族视图，终态行可能迟到）
  → bg/stats_minute_rollup.go：游标臂 + 【近期闭分钟重扫臂】
    （[now-lag-span, now-lag] 整键替换幂等，lag=2min span=30min 可调）
  → request_stats_minute（看板/统计读面）
```

**两道红线**（940 迁移头注 + 2026-11-03 方案档 §4.4）：
1. 行情/营销价**禁止回流**路由与计费表——同步器写目标白名单 =
   `{market_price_reference, market_price_reference_sync}`，契约门
   `tests/market_price_sync_contract_test.sh`（含变异臂）钉死；
2. **NULL≠0**：无价 = 未知 ≠ 免费，所有价格链路保持 NULL 语义
   （autoroute AF-15 收窄 + 行情同步器 num() 同规）。

## 1. 请求统计对账（项1）

- **缺陷（已修）**：流式终态行在游标越过其分钟之后才落视图，单遍水位线
  永久漏统（生产实测单小时缺 30–50%）⇒ 重扫臂整键替换幂等补统。
- **对账工具**：`scripts/audit/request-stats-reconcile.sh`——四腿
  （client 面 / minute rollup / usage_ledger / request_wal）+ 成本链 +
  每分钟缺口 top10；验收判据 gap ≤ 2%。
- **验收记录**：修复后小时 gap=0；24h 聚合的残留为修复部署前的历史欠账
  （判据：看「修复后小时」，不看聚合窗）。
- **上下游口径**：client 面（A）与 usage_ledger（C）的差值 = ledger_only
  （预日志失败/压测遗留，须可解释）；成本链 cost_usd 全 0 = 绑定无单价
  （数据缺口，接行情整合 + 定价页录入）。

## 2. 内部定价版本化（项2）

- **模型**（迁移 952 `model_price_versions`）：
  PK(canonical_id, billing_mode, effective_from)；effective_to NULL = 现行期；
  部分唯一索引 ⇒ **同模型同模式至多一个现行价（库级强制不出现重复价格）**；
  billing_mode 闭集 pay_as_you_go | token_plan | booster_pack。
- **写侧语义**（maas/model_price_versions.go）：价格未变不开新期（防重复）；
  变化则原子「闭上一期 + 开新期」；行清空只闭期（空洞 = 全局默认价，如实）。
- **API/前端**：`GET model-price-history`（单模型期史）、
  `GET model-price-changes`（订价变化流）、`PUT model-price-mode`
  （token_plan/booster_pack 参考价期）；定价页行级「历史」+ 工具栏
  「订价变化」两弹窗。
- **边界**：计费热路径照旧读 model_credit_rates（零改动）；按模式计费分叉
  需独立裁决。

## 4. 营销策略（项4）

- **管理面**（superAdmin）：套餐/加油包 upsert+上下架（934 生效窗、
  bonus_credits、first_time_only）、优惠码停用、活动创建与状态机
  （benefit_value 形状校验：credits/gift={"credits":N}、discount={"percent":1..99}）。
- **兑现链**：gift 即时发积分（台账 note 标注）；discount 记零积分
  redemption，CreateOrder 单事务「锁 redemption → 折减 → 建单 → 回填
  order_id」（937 order_id 列首消费），QR 按折后金额生成。

  （独立 ledger 行 ref_type=order_bonus，逐条可对账）。
- **前端**：`/operations/marketing`（套餐/加油包/优惠码/活动四页签，
  super-only 菜单入口）。
- **支付边界**：支付通道（alipay/wechat）未配置、stub 二维码死链 —— 变现

## 6. 探测恢复感知（项6，最重缺陷）

- **根因双缺陷**（211 时间线取证）：①凭据探针模型不在套餐覆盖内 ⇒ 每小时
  探测永远 429-2056，凭据级挂起整天而套餐覆盖模型一直服务；②套餐配额
  扫描器每 5min 拿到厂商窗口读数却只对 balance_floor 原因行做恢复 ⇒
  probe-v2 挂起的行无人唤醒。
- **修复**：
  - **F-A 探针模型回退梯**（bg/credential_probe_v2.go）：配额族失败
    （402/429-配额/403-余额形态）⇒ fail-fast 分支对 ≤3 个备选 chat 绑定
    模型（排除主探针模型/嵌入/音频、last_direct_ok 优先）各试一发；
  - **F-B 证据门控 re-arm**（bg/balance_floor_guard.go）：用尽族挂起 +
    厂商窗口有容量（MaxUsedPercent<100）⇒ OnPlanCapacityAvailable →
    OnQuotaRecharged 快速凭据级探测（15min warnGate 节流）→ writeHealth
    翻 ok 全链闭环；
  - main.go legacy + authoritative 两条装配分支都接线。
- **生产实证**：F-B 触发 → 探测 → 回退梯 → 诚实 402（账号真没余额保持
  挂起是正确行为）；恢复的凭据自动翻 ready。
- **运维要点**：人工「强制恢复」按钮若走 force-recover 端点**不清
  quota_state**——对永久配额态要用 emergency-repair/force_enable 或
  reset-quota。
