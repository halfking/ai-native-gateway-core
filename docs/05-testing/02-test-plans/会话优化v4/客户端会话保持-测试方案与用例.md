## 1. 目标与范围

**目标**：为 v4 需求的全部功能点提供可执行、可追溯、分阶段门禁化的测试资产——三级队列与请求注册表、自愈调度（重试/换节点/换模型/预算）、客户端保活与思考帧回显、节点/凭据自愈（URSM/探测/36h 回看）、请求快照与重启语义、会话三级制品（FR-11）、首字节后流中断透明恢复（FR-12）、会话唯一成功持久化。

**范围内**：Go 后端单元/集成/混沌测试；契约 fixtures；管理端 API 只读投影断言；T12 混沌矩阵与 SLO 基线的执行方法；测试环境与初始数据的统一要求。

**范围外**（仅衔接，不在本册展开）：T9 前端 vitest 用例（`web/` 内既有 vitest + i18n:check 管道，见规格 T9）；T8 245 生产部署验收的现场步骤（本册提供其自动化底座与证据格式，现场执行以规格 T8 为准）；154 生产日志审计（T1，只读运维任务）。

### 3.2 新增夹具（随首个消费任务落地）

1. **脚本化 mock provider（`tests/lib/v4prov`，Go 包）**：在 LocalMockProviders 基础上支持按 (credential, model) 脚本编排逐次响应——固定错误码、`Retry-After` 头、首字节延迟、N 字节后连接重置（RST）、慢滴（chunk 间隔可配）、eof_without_done、空回复、tool-call/reasoning 帧、以及**请求指纹记录**（验证 L0 同节点重发与 prompt-cache 亲和时断言两次请求体一致）。OpenAI 与 Anthropic 双协议各一套。行为模式枚举与 SD-06 种子绑定（§5.4）。
2. **SSE 探针客户端（`tests/lib/v4sse`）**：以真实 HTTP 客户端消费流式端点，记录 (字节偏移, 时间戳, 帧类型) 时间线；提供断言器：任意 ≤N 秒窗口必有字节（心跳间隙）、注释帧/语义帧分类、最终 answer 与思考内容隔离校验、Zod 严格模式模拟（遇未知事件字段即失败，验证 L4/注释兜底）。
3. **journey/DB 断言器（`tests/lib/v4journey`）**：等待 request_logs_hot 出现终态行（轮询+超时），断言 `routing_attempts`、`error_kind`、t0–t9、`gw_session_id`、attempt 数、node_switched/model_switched/retry_scheduled 事件序列；journey 三源（内存/Redis/PG）一致性抽查。
4. **URSM 断言/种子工具（`tests/lib/v4ursm`）**：直接读写 `ursm:v2:node:t:{tenant}:{cred}:{model}` key（available/fail_streak/cool_until_ms/source_priority/遥测窗口）、sticky 与 intent key，供 L3 断言运行时真值与 §5 种子预置。
5. **fake clock / 时钟注入**：退避、心跳、holdback 窗口、RPM 翻转、TTL 类用例要求被测代码提供可注入 clock/sleeper（**实现侧前置改造**，各 T 任务验收项）；未注入前这类用例以真时间 + 缩小参数运行并标注不稳定风险。
6. **preflight 探针（`tests/chaos/probes/preflight.go`，亦供 L3 复用）**：环境就绪检查（§4.5）。

## 4. 测试环境要求

### 4.1 环境分层定义（E0–E5）

| 层 | 名称 | 用途 | 生命周期 | 资源建议 |
|---|---|---|---|---|
| E0 | 单测/契约环境 | L1/L2，无外部服务 | 每次构建 | CI runner 2C4G 即可 |
| E2 | 集成环境 | L3：真 PG+Redis、进程内 v4prov | 每次 CI nightly / 本地按需 | 4C8G、数据卷可丢弃 |
| E3 | 混沌环境 | L4：compose 全套（网关+PG+Redis+toxiproxy+3×v4prov+探针） | 矩阵运行期（约 2–3h，含 1h soak） | 8C16G（soak 与矩阵并行时 ≥8C） |
| E4 | 真实供应商环境 | L4b：真实低额度凭据抽查 | 上线前/周期性 | 共用 E2/E3 主机 + 出网 |
| E5 | 245 验收环境 | L5：生产部署验收 | T8 一次性 | 245 现有规格 |

> 版本对齐：E2/E3 的 PG 与 Redis 版本必须与部署环境（154/245 实际版本）对齐，以部署配置为准（参照 three-env-unified-verification.md 的环境核对项：pg 扩展 pg_trgm、分区预建等）；Go 版本以 `go.mod` 为准。禁止用与生产大版本不一致的本地默认镜像「凑合」。

### 4.4 隔离与卫生要求

1. **数据库**：E2/E3 使用独立库 `gwtest`（禁止指向任何共享/生产库）；跨用例可变数据一律以用例 ID 作后缀（如 `gw_session_id = 't4-IT-FO-01-s1'`）；种子 SQL 必须幂等（ON CONFLICT DO UPDATE）且提供 `seed_clean.sql` 反向清理。
2. **Redis**：L3 用例统一 key 前缀 `t4:`（测试内封装的客户端自动加前缀）；URSM 种子键在 teardown 显式 DEL；禁止 FLUSHALL/FLUSHDB 共享实例——E2/E3 必须是专用实例/db。
3. **文件与网络**：测试不读写仓库外路径；E4 之外禁止出网调用真实供应商。
4. **并发**：`go test -p` 并行下 PG 用例避免同表锁竞争——大表种子（SD-04 历史）仅由串行种子步骤装载一次，用例只读。
5. **敏感数据**：所有凭据为 fake key（`sk-t4-fake-*`）；真实 key 仅 E4 且仅经 env 注入，禁止出现在种子/日志/报告中。

### 4.5 环境就绪门禁（preflight）

L3/L4 运行前由 `tests/chaos/probes/preflight.go`（L3 复用）校验并输出 `TEST_PREFLIGHT.json`（沿用综合测试体系的结果契约命名）：

1. PG：连通、pg_trgm 扩展存在、migration ledger 处于最新、种子版本号一致；
2. Redis：连通、`EVAL "return 1"` 通过（Lua 可用）、pub/sub 收发通过、版本 ≥ 生产基线；

### 5.3 数据卫生与时间基准

1. **相对时间**：一切时间字段以 `now()` 相对生成（`now()-36h+1h`、`now()+15m`），禁止绝对时间戳；36h 回看用例的判定行用 `now()-35h`（命中）与 `now()-37h`（不命中）。
2. **幂等与重置**：种子可重复执行（upsert）；每个 IT 文件的 `TestMain` 做装种→跑→按需清理；跨文件共享的只读种子（SD-04/05）只在 preflight 阶段装载一次。
3. **时间缩放**：36h/15min/1h 等大窗口参数必须支持 `TEST_TIME_SCALE` 或独立热配置（实现侧要求），测试用缩放值；未支持前的用例标注「真时长，仅 nightly」。
4. **并行安全**：SD-01/02/03 的行带租户与用例组前缀；可变行（状态翻转）仅由持有它的用例操作。
5. **种子版本化**：`seed_version` 表 + preflight 校验，migration 或规格变更后种子必须同步升版，防止「种子漂移导致用例静默失效」。

### 9.3 CI 集成

| 流水线 | 触发 | 内容 | 硬门禁 |
|---|---|---|---|
| PR fast | 每次 push | `make test`（L1/L2，含 -race 关键包）+ `go vet ./...` + 契约 fixtures | 全绿必过；UT-CO 用例**禁止 skip** |
| nightly | 每日 | E2 preflight + L3 全量（含种子自检 IT-SM-04）+ IT-PR-01/05 | preflight 失败即 fail（不降级 skip）；失败阻塞次日合入并回流任务 |

### 9.4 报告与缺陷回流

- 单测/集成：CI 产物 + 每阶段 `reports/TEST_<阶段>_<日期>.md`（通过率、跳过清单及原因、失败用例→对应 T 任务编号）。
- 混沌：`reports/STABILITY_CHAOS_<日期>.md`（矩阵结果+SLO 基线+偏差清单，规格 T12 格式；含监控阈值表 P 级标注）。
- 验收：`reports/ACCEPTANCE_245_<日期>.md`（A1–A17 逐项：方法/证据/结论）。
- 环境与种子：preflight 产物 `TEST_PREFLIGHT.json` 与 `seed_version` 随报告归档，保证结果可复现。
- 缺陷回流规则：任何失败用例在 issue/任务标题携带用例编号（如 `IT-FO-03`），修复 PR 必须包含该用例的回归运行证据。

### 9.5 通过标准与退出准则

1. P0（UT-CO）与各阶段门禁用例全绿，无 skip（环境未配置导致的大面积 skip 视为未执行；preflight 失败视为 fail）。
2. 集成层关键验收映射用例（A1–A4/A7/A9/A10/A14/A15/A17 对应 IT）全绿；综合方案四场景（IT-FO-09～12）全绿。
3. 混沌矩阵 20 场景行为与 §14.1 预期一致；SLO 基线建立（含监控阈值表无 P1 级偏差）；1h 稳态无资源泄漏。
4. 覆盖率：新增包（nodestatecache/session/preprocess/requestpersistence/stream_recovery）语句覆盖 ≥80%，关键状态机分支（URSM lua、FR-12 阶梯、FR-11 复用四条件）行覆盖 100%（`make test-coverage` 产出核对）。
