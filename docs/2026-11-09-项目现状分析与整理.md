## 0. 一句话结论

llm-gateway-go 已经是一个**功能完整、生产在跑、工程纪律很强**的企业级 LLM 网关（427 个 Go 包 / 35 万行生产码 / 87 个顶层目录 / 35 个可执行程序 / 1415 个迁移文件 / 4165 份文档），
质量门禁体系（180 个 `ursmcheck` 门 + 188 个审计脚本 + 变异臂自检）是本仓最有价值的资产。

**当前的主要问题不是功能，而是「体量超过了组织能力」**：
① 仓库卫生有 2 处实打实的缺陷（27MB 二进制入库、三处重复 schema）；
② 关键事实源存在**多份且互不同步**（路由注册 291+155 两处、迁移台账只写不读、CI 配置在真实远端不执行、AGENTS.md 二次膨胀）；
③ 若干超千行文件与平铺目录开始削弱可维护性。

- 模型未登记 → `400 invalid_model`

### 3.3 存储与迁移

- **双模式**：`full`=PostgreSQL+Redis，`lite`=SQLite+File+Memory（`storage/interfaces.go:16-21`，ADR `docs/adr/2026-09-05-dual-mode-storage-package-layout.md`）。
  根包只放契约，实现拆 `storage/sqlite`（元数据 9 表）/ `storage/file`（大对象 bodies）/ `storage/lite`（进程内 KV）。
  等价性有门：`storage/factory/dual_mode_parity_test.go:18`。
- **迁移两条路径并存**：
  - A 安装期 SQL 文件：`installer/internal/dbinit/runner.go:20` 有序清单 **355 条**，经 `docker exec psql` 执行
  - B 运行期 Go DDL：`db/db.go:451` 串行调用 **82 个 `ensure*` 函数**（幂等自愈）
- **数据表**：`sql/objects/` 登记 286 表（含 16 个 `*_hot`、24 个月度分区、7 个归档 ⇒ 约 239 基表）+ 604 索引 / 260 约束 / 281 序列 / 119 RLS 策略 / 97 函数 / 52 视图。
- **热区三段式**：`*_hot` → `*_default`（8h 窗口，`bg/partition_manager.go:36`）→ 月分区 → 归档（18 条归档规格）。
- **一致性**：`storage/consistency.go` 处理 lite 跨介质孤儿（孤儿 body 只报不伪造，`ReconcileTurnArtifacts` vs `RepairTurnArtifacts`）；
  生产巡检 `bg/consistency_worker.go:112`（每日、仅空闲会话、单轮 500 上限）。
- **Redis 键族**：`rl:{rpm|tpm}:*` / `rpm:{provider:cred}` / `llmgw:ident:*` / `llmgw:health:cred:*` / `llmgw:dispatch:queue:v1:due` / `session:v2:*` / `llmgw:attack:*`。
  **MCP 网关不用 Redis**，走进程内令牌桶（`mcp/ratelimit.go:16`）。

### 3.4 管理面与前端

- **管理面**：`admin/` 821 个 .go（140,574 非测试行），私有 handler 561 + 导出 41。

- **构建不靠 Makefile**：主 `Dockerfile` 不构建前端；产物由部署脚本预构建后以磁盘目录进镜像（`Dockerfile.local-arm64:18`），

- **契约**：无 OpenAPI codegen、无 schema 校验（无 zod/ajv）；`contracts/` 仅 1 个文件，`tests/contract/` 仅 1 个文件。
