## §二、核实为健康的关键面

- **A2+B 改造与原公式逐字节兼容**：calculateLoadScore 6 维度权重 default 值未变（DefaultLoadScoreEnvWeights 返回与原 envFloat 默认值同值）；sticky/recency/balance/planquota 权重计算 `stickyPenalty*stickyWeight + ...` 顺序与精度一致。
- **Snapshot 接口扩展向后兼容**：StickyLoadView 多了 `Snapshot(ids)` 方法，**已实现**该接口的 `StickyLoadTracker` 自动满足；老 Stub（benchStickyLoad）同步补 Snapshot 实现。
- **hotTableOldestRowAge 失败语义**：返回 -1 表示查询失败（保持 last gauge value），不刷零，避免误报"表空了"。
- **R48 §一 F4 8 处双腿化**：`request_logs_with_current_month` 视图是 UNION ALL（hot + mother），与白名单 LEGIT 条目 ("sql/objects/views/request_logs_with_current_month.sql") 配对；admin 测试套 67s 全绿证明语义保持。

## §三、本轮事故与教训

1. **`mounted=true` 后 watch 不响应同值 setProps**：Vue 3 watch 默认 `deep: true` 但比较旧/新引用，深比较对 primitive string 不变就不触发。本轮 multi+string 钉桩因此用 `setProps('claude')`（不同值）强制触发 watcher。教训：future 钉桩必须用 `setProps` 制造真实差异，而非同值重设。
2. **router_scoring.calculateLoadScore 改签名是 breaking change**：5 个调用面（router.go:loadScore, strategy.go:p2cStrategy.Score, 测试 4 文件）全部同步更新。教训：参数重排要做 grep -r 周边 caller，不能只靠编译错（编译错能 catch 但命名含义变化 catch 不到）。
3. **snapshot 调用处** `stickySnapshot[id]` 返回 `StickyLoadInfo{}`（零值）而非 nil——这意味着即使 Info() 也不返回 nil；与 `safeValue` 设计一致（map 缺 key 时零值是合理默认）。教训：Go map 缺 key 用 nil-vs-zero-value 要分清语义；本场景 zero-value 即"无信号=惩罚 0"符合设计。
