## 2. ★★★ 本轮最值钱的一条：**三元分支的顺序决定「谁上屏」**

全仓错误文案的病根是一行：

```ts
error.value = e instanceof Error ? e.message : t('keys.loadFailed')
```

`.message` 在**第一分支** ⇒ 兜底只在「抛出的值**不是** `Error` 实例」时才触发
⇒ 正常路径（后端抛 `Error`）**永远走 `.message`** ⇒ 本地化兜底**结构性失效**。

⇒ **第 15 增量改写的 143 个键，在这条主路径上从来没上过屏。**

用户实际看到的是后端下发的**英文技术串**。实测后端 admin 侧：

| 读数 | 值 |
|---|---|
| `writeError(...)` 硬编码错误文案 | **1852 处** |
| 去重后 | **631 条** |
| 其中中文 | **33 条**（5.2%） |
| 英文 | **598 条**（94.8%） |

⇒ 本轮把「用户可见错误文案」收成**唯一出口**：

```
主文案（主体专属键：点名主体 + 恢复动作）  +  （原因：原始 detail）
```

★ 原始 detail **只作次要原因**，永不作主文案（impeccable：内部码不作主文案）。
★ 没有主体专属键时落**状态层**（`errors.byStatus.*` / `errors.network` / `errors.unknown`）——
  这 12 个键原是**死键**（`useApiError.ts` 的 `resolveApiError` 生产代码 0 调用），
  本轮把它们**复活**成「没有主体文案时的兜底层」。

## 4. 判据设计（4 条，全部可证伪）

新门 `web/scripts/i18n-error-outlet-guard.mjs`：

| 判据 | 内容 |
|---|---|
| **O1 裸用** | 源码里不得再出现 `<x> instanceof Error ? <x>.message : …` 且该表达式自己就是用户可见文案；登记在豁免表里的「原因槽 / 拼接原因」形态除外，**豁免必须自证仍然成立**（站点没了 ⇒ 判 `O1-exemption-stale`） |

| **O3 状态层合规** | `errors.byStatus.*` / `errors.network` / `errors.unknown` 必须**含恢复动作**且非裸失败短语（**复用 L1 门的同一把尺子**） |
| **O4 原因后缀** | `common.feedback.reasonSuffix` 必须 8 语种齐备且保留 `{reason}` |

★ 扫描器自己写的（不用一行正则）：① 兜底表达式里带括号 ⇒ 行级正则会吞掉收尾 `)`；
② 形状可能跨行。

**自证 13/13 全过**（含 S11/S12：扫描器自身的判别力）。

## 9. ★ 本轮明确没做（留给下一轮，别重复排查）

1. ★★ **后端下发文案本地化 / code 化** ——
   admin 侧 1852 处 `writeError(...)` 硬编码（去重 631 条，98% 英文）⇒
   本轮只能把原始 detail 当**次要原因**挂着；正解是后端给**机器可读 code**，
   前端按 code 翻译 ⇒ 那一族是「后端工程」，不是前端文案工程。
2. ★★ **`t(k)` 形态的键仍是引用集盲区**（全仓 1549 处非字面量 `t(...)`）——
   这些键不受「用户可见」硬闸保护。
3. ★★ **未登记槽位的跨语种一致性**（L1a 只用 zh-CN 触发）。
4. ★ **通用槽拆键的其余既有空态位键**（第 14 增量登记簿只管 23 个新增）。
5. ★ **「源码抄语言包」族**（632 处 / 107 文件）。
6. ★ **页面级硬编码中文**（4484 段 / 181 文件），含访客页 en 语种里混进的
   一处硬编码中文（「完整协议 ↗」）。
7. ★ **语言包死键**（ja-JP 294 / zh-TW 288 条 ⇒ 源码 0 引用 ⇒ 嵌套命名空间重构后遗留）。
8. ★ **字表完整正名单**（185 候选，`BIG5_TRAPS` 现有 5 字）。
9. ★ **移动端 8 语言**（现只有 en-US / zh-CN）。
10. ★ **远端运维菜单的中文**（maintain 后端下发 `label` 覆盖本地兜底）。

12. ★ **`scanner.ts` 的 6 形态采集**（让动态取键点可见）。
