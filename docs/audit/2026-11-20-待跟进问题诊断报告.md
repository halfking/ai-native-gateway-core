## 二、P2问题：插件注册失败

### 问题描述
- **频率**: 1次/启动
- **错误**: `approval provider "native" not found (available: [])`
- **严重性**: P2（中）

### 根因分析

**错误日志**：
```json
{
  "msg": "failed to initialize plugin registry",
  "error": "plugin registry not fully configured: approval provider not configured: authplugin: approval provider \"native\" not found (available: [])"
}
```

**分析**：
- 配置中指定了 approval provider "native"
- 但系统中没有注册任何 approval provider（`available: []`）
- 这导致插件注册失败

### 解决方案

#### 方案1：补充native provider实现（推荐）
如果确实需要审批功能，需要：
1. 实现native approval provider
2. 在系统启动时注册该provider

#### 方案2：修改配置（快速解决）
如果不需要审批功能：
1. 找到配置文件中的plugin配置
2. 移除或注释掉 approval provider 相关配置
3. 或者使用其他可用的provider

#### 建议
由于`available: []`表明系统中完全没有approval provider实现，建议：
- **短期**：修改配置，移除approval provider要求
- **长期**：如果需要审批功能，实现完整的provider

## 四、P3问题：存储配置警告

### 问题描述
- **频率**: 1次/启动
- **错误**: `storage_mode "full" requires a full_storage section in yaml`
- **严重性**: P3（低）

### 根因分析

**警告日志**：
```json
{
  "msg": "storage: full mode config validation failed (non-fatal, continuing legacy assembly)",
  "error": "storage_mode \"full\" requires a full_storage section in yaml"
}
```

**分析**：
- 配置文件中 `storage_mode` 设置为 "full"
- 但缺少 `full_storage` 配置段
- 系统降级使用遗留配置，功能正常但配置不一致

### 解决方案

#### 方案1：补充full_storage配置
在配置文件中添加：
```yaml
storage_mode: full
full_storage:
  postgres_url: ${LLM_GATEWAY_POSTGRES_URL}
  redis_url: ${LLM_GATEWAY_REDIS_URL}
```

#### 方案2：使用lite模式
如果不需要full模式：
```yaml
storage_mode: lite
lite_storage:
  data_dir: ./data
```

#### 方案3：删除storage_mode配置
使用默认配置即可

#### 建议
- 检查211的实际存储配置
- 根据实际情况补充完整的配置段
- 这是非致命警告，但应该修正以保持配置一致性
