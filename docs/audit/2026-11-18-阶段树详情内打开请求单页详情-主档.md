## 二、实现

### 2.1 路径**不另写一份**：复用仓内单一真源

```ts
import { requestDetailPath } from '../../utils/openRequestDetailPage'
const detailHref = computed(() => requestDetailPath(props.band.requestId))
```

★ 为什么必须复用：`requestDetailPath()` 与 `openRequestDetailPage()` **同模块** ⇒ 同一套
`encodeURIComponent` / router base / 命名路由回退逻辑。
若在阶段树里手写 `/request-detail/${id}` ⇒ **同一条规定写两份 ⇒ 必然漂移**
（上一轮 F1「紧凑图例字形漂移」的同型坑）。

### 2.2 用**真实 `<a>`**，不用 `<button>` + `window.open`

仓内既有形态是 `<button>` + `openRequestDetailPage()`（内部 `window.open(href,'_blank')`）。
本轮**刻意改用真实链接**，三条理由：

1. ★ `window.open` **可能被弹窗拦截器挡掉** ⇒ 返回 `false` 时用户**什么也没发生**、
   界面也**没有任何提示**（行级入口没有「链接」的位置，只能这么做）；
2. 真实链接**地址可见、可复制、可右键 / 中键 / ⌘点击打开** ⇒ 用户拿到的就是
   owner 描述的那个 URL 形态；
3. **语义正确** ⇒ 这是「跳到另一个页面」，不是「触发一个动作」。

> `openRequestDetailPage()` 的 `window.open` 形态**保留不动**（行级入口仍在用）。

### 2.3 其它三条纪律

| 纪律 | 做法 |
|---|---|
| **不顶掉现场** | `target="_blank"` ＋ `rel="noopener noreferrer"` ⇒ /live2 的现场不被顶掉；新标签拿不到 opener |
| **不冒泡** | 详情面板根节点已有 `@click.stop` ⇒ 点链接**不会**冒泡到请求行 ⇒ 不会「点一下就收起」（新增钉测钉住） |
| **无障碍名点名是哪一条** | `aria-label` 带 `{requestId}`（页面上可能同时有多条带）；可见文案「打开请求详情页」**点名目标**，不写「查看」「更多」 |

直链/刷新时**可能已滚出** ⇒ 该页**自己如实说明**「已滚出」，不冒充空详情。

## 六、通用式（本轮新增）

1. ★ **能力在 ≠ 入口在**：目标页、路由、路径拼装函数**全都早就存在**，
   缺的只是**从新界面到它的那个入口** ⇒ 接到新界面时，先在**全仓**搜一遍
   「这件事是不是已经有人做过」（本轮：`openRequestDetailPage` 有 4 处调用方，
   唯独阶段树一处没有）。
2. ★ **「跳页」用真链接，「动作」用按钮**：`<a href>` 的地址可见、可复制、可中键打开、
   不受弹窗拦截器影响 ⇒ 凡是「跳到另一个页面」都优先真链接；
   `window.open` 的形态只留给**行级**入口（那里没有链接的位置）。
3. ★ **新入口必须补「不冒泡」判据**：详情类浮层里塞链接后，最容易出的事故是
   「点链接 ⇒ 事件冒泡到父级 ⇒ 面板当场收起」⇒ **看起来像没点** ⇒ 必须有钉测钉住。
