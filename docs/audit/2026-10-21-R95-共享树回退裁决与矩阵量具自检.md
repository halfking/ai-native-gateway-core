## 2. ★★★ 矩阵脚本的两处量具缺陷（同源：跨基线复用的产物）

脚本：`scripts/audit/measure-factsource-cost-matrix.sh`

### 2.1 缺陷 1：worktree 已存在时**根本不更新**

```bash
if [ ! -d "$WT" ]; then git worktree add --detach "$WT" origin/main …; fi
say "  worktree = $WT @ $(git -C "$WT" rev-parse --short HEAD)"
```

⇒ 日志里「基线提交 = X」与「worktree @ Y」是**两个不同的提交**
⇒ **整份读数其实是从旧树算出来的**，而日志宣称新基线 ⇒ **没有任何一层会报警**。
（上次的读数侥幸无害，只因两次提交之间只差注释 —— ★ 那是运气，不是保证。）

**修法**：自检跑在读数之前 —— `git -C "$WT" rev-parse HEAD` 必须 == 宣称基线；
**不一致即 `exit 3` 拒绝出结论**，并给出两条修法（换 `WT` 路径 / `MATRIX_REFRESH_WT=1` 显式刷新）。

**实测**：
- worktree 在 `9eb30a0ec`、基线 `a06c24f16` ⇒ **exit 3** + 明确诊断（两个 SHA 都打出来 + 修法）；
- 加 `MATRIX_REFRESH_WT=1` ⇒ 刷新 ⇒ 自检显示「✓ 与基线一致」⇒ 继续往下跑。

### 2.2 缺陷 2：形态库也跨基线复用，且不校验

原先只要库存在就复用 ⇒ **旧形态算新读数**。

**修法**：建库时在库上写基线指纹（`COMMENT ON DATABASE … IS 'matrix-baseline:<sha>'`，**不动 schema 形态**）；
复用时比对，指纹不符 ⇒ **重建**。

**实测**：造一个指纹为 `matrix-baseline:deadbeef` 的库 ⇒ 守卫打印
「**[形态库] 基线指纹 ≠ 当前基线 ⇒ 重建**（旧指纹: matrix-baseline:deadbeef）」⇒ 旧库被 DROP ⇒ 重建并打上新指纹 ✓。

### 2.3 ★★ 同族通用式

> **「跨基线复用的产物」（worktree / 形态库 / 缓存 / 快照）必须带基线指纹，复用前校验；不符就重建，别将就。**
> ⇒ 且 ★ **不一致要变成【中止】（exit 3），不是一行需要人脑比对的日志。**

### 2.4 ⚠ 本轮自己踩的测试坑

第一次验证形态库守卫时，我用「**不存在的容器**」当替身 ⇒ `shape_exists` 直接为假 ⇒ **守卫分支根本没被走到** ⇒ 看起来像「守卫没生效」。
⇒ ⇒ ★★ **「用替代环境做测试」会改变被测路径** ⇒ ★ **测试替身必须走真实路径**（这次用真容器才验到）。

### 2.5 顺带一个新读数

当前树 `a06c24f16` 的矩阵 scope = **30 文件 / 92 函数 / 15 包**
（并行会话 R92 复算的 29/87/15 是 `b1276c952` 上的数 ⇒ **基线不同，不可直接引用**）
⇒ ★ **代价表的 scope 必须连基线一起发布**。
