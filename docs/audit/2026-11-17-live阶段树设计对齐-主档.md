## 二、取证：线上长什么样，设计是什么样

### 2.1 线上截图 vs 原型截图（部署前，154）

| 维度 | 线上 154（部署前） | 设计方案 |
|---|---|---|
| 行数 | **177 行**，绝大多数是 `error_kind=no_traffic_5min` 的**后端心跳** | 只有真实请求 |
| 阶段取值 | **全部为空**（只有节点名，没有值） | 每段有值（已通过 / N 处 / 候选数 / 模型名…） |
| 裸键 | 屏上直接出现 `liveStageTree.stage.first_by…` | 无裸键 |
| 错误 | `no_traffic_5min` **裸错误码**上屏 | 来源徽标 + `error_kind` + tooltip |
| 时间列 / 列头 / 图例 | **都没有** | 都有（设计第 8 轮） |
| 完整 / 紧凑双模式 | **没有** | 有（第 6 轮） |
| 最右错误列 | **没有** | 有（第 9 轮，右缘恒定） |
| 摘要行 | 只有状态 | 状态·错误·会话·模型链·供应商·排队·耗时·token·成本·可信度·缓存 |
| 全屏统计层 | 只有「请求数/成功率」两行 | KPI×16 + 周期统计 + 五维分类 + 口径说明（第 17 轮） |

### 2.2 根因（四类，逐条取证）

**根因①：后端心跳被当请求渲染。**
`web/src/composables/liveStreamStore.ts` 的 `liveStreamState.requests` 里混着 `type='idle_marker'` 的心跳帧（`status='idle'`、`error_kind='no_traffic_5min'`、`request_id` 形如 `idle-global-model-…`），而 `/live2` **从未过滤**。
⇒ 修：`isIdleMarker()` 判定 + 视图层 `realRequests`（过滤候选也只用真实请求，否则下拉里混进心跳模型）。

**根因②：线上 SSE 把动作明细摊平到顶层，前端只读嵌套 `detail` ⇒ 阶段取值全空。**
`admin/live_stream_lifecycle.go` 的 `flattenActionEvent` 先 `delete(m,"detail")` 再把 detail 的键拷到顶层。抓包实测动作帧**没有 detail 对象**（`mutations/decision/score/candidates/raw_model/ttfb_ms/status/attempt/tier` 全在顶层）。
而 `web/src/lib/liveStageTree.ts` 只读 `action.detail` ⇒ **每个阶段取值都是空**、审批拒绝判不出失败、注入命中判不出告警、最终模型退化成原始名。REST 回退 `/api/admin/request-actions` 才是嵌套形状。
⇒ 修：`actionDetail()` —— **嵌套 detail 优先 + 顶层平铺补齐**，两种形状都吃。

**根因③：裸 i18n 键上屏 + 裸错误码上屏。**
`t('liveStageTree.stage.' + s.key)` 是**动态键**，对 `first_byte` 取到不存在的 `liveStageTree.stage.first_byte` ⇒ 界面直接显示这串字符（仓内的 i18n 引用扫描器抓不到动态键 —— 这就是「动态键是引用扫描器盲区」的又一处实证）。
⇒ 修：所有阶段名改**逐字面量 `t()`**；错误码按 `error.kind.*` 逐条映射（15 种），未知码回落原始码（不编）。

**根因④：设计主档 §16.7 自认「生产端 `/live2` 的 Vue 实现仍未同步第 6/7/8/9 轮任何改造」** —— 版面层整体缺失。

### 2.3 ★ 机制原因：Maestro 资产里没有一条断言是「界面 == 设计方案」

上一轮加了 flow 12 与 `assert-stage-tree.mjs`，但它们验的是**行为与存在性**（入口可点、元素在、数据是活的、胶囊读数 == 带数）。
**没有一条断言是「界面长成设计那样」** ⇒ 于是「177 行心跳」「阶段值全空」「裸键上屏」「缺双模式/错误列/统计层」**全都是绿的**。
⇒ 本轮把设计方案里的**可观测事实**逐条写成断言（版面件齐、列头与带同宽、瓦片同一行、完成态不画 ✓、错误列右缘恒定、树宽 1400、胶囊带窗口…），
并把「紧凑模式」从「一个模式」升级成**一份独立的设计契约**（原型第 6/7/8/9 轮）。

### 3.3 紧凑模式（**整段重建**，原型的第 6/7/8/9 轮）

原型实测过的一版里，紧凑模式是**另一套版面**，不是完整模式的缩小版。本轮按原型重建：

| 契约 | 原型取值 | 本实现 |

| 小数字 | 瓦片内右下角 | 同 |

### 3.4 统计全屏层

分**两把尺**、各自标注、不混算：
- 主体＝**内存实时窗口**（与树同源）：KPI×16 + 周期统计（分钟桶）+ 分类统计 5 维 + 口径说明区；
- 折叠区＝**DB 直查** `StatsPanel`（与 `/live` 一致的那把尺）。
缓存命中率**不可跨口径合并**（OpenAI 包含口径 / Anthropic 并列口径）：两种口径并存时给 `null`（不混算），另报 covered/excluded 覆盖面。

### 3.5 i18n

8 语种补 **90 个新键**（mode/legend/header/clientType/session/window/newPill/band.queue/error.*（15 种错误码）/stats.kpi/trend/dim/notes/db），
改 `stats.readout` 格式、`value.meter`、`value.injection`，新增 `decision.warnShort` 与 `band.attempts`。
纪律：① 新键一律**逐字面量 `t()`**（动态键是引用扫描器盲区）；② 8 语种键集合平价；③ **en-US 值不得含汉字**；④ 各语种「值等于 en-US / 等于 zh-CN」的计数是**只许降不许升的棘轮**（`src/i18n/localeValueBaseline.json`）—— 本轮新增键在 8 语种逐个核对，无同值项。

## 四、与设计方案的**偏差登记**（有意为之，不是漏做）

| # | 设计原型 | 本实现 | 理由 |
|---|---|---|---|
| 1 | 阶段列序＝owner 初版列举序（鉴权→审批→注入→脱敏→压缩→路由→供应商） | **代码真实管线序**（鉴权→**脱敏**→**审批**→注入→路由→**压缩**→供应商） | 主档 §5.2 明定「阶段顺序＝代码真实管线顺序」；差异已在主档登记 |
| 2 | 紧凑瓦片角标用**单字**（网/供/它） | **来源色圆点**（名称与判据在 tooltip + 最右错误列） | 单字在 8 语种里既不可实现、又必然与 en-US/zh-CN 同值 ⇒ 撞 i18n 值棘轮；且整段文案会压到相邻瓦片上 |
| 3 | 紧凑模式**无列头** | 同（隐藏） | 原型 `body.mode-compact .stagehead{display:none}`：紧凑是「单行流水」不是「按列对照的表」 |
| 4 | 错误 tooltip 含 **HTTP 码** | 不含 | 生产 `reply` 动作的 `detail.status` 只有 `success`/`failure`，**不带 HTTP 码** ⇒ 拿不到就不编 |
| 5 | 摘要行含 **▤N 帧**（响应帧数） | 不含 | 实时流帧里**没有**帧数字段 ⇒ 未上报 ≠ 0，不显示 |
| 6 | 原型「压缩」格显示 `-22%` 压缩率 | 显示「已压缩 / 未压缩」 | 生产动作帧不带压缩率；只报**事实**（压没压） |
| 7 | 接收轨在原型里**绝对定位**按列对齐 | 与发送轨**同身份对齐**（首字节↔供应商列、还原↔脱敏列、计量↔审批列、回复↔鉴权列） | 沿用原型同一做法，但用 CSS Grid 实现（可维护、不错位） |

## 八、通用式（本轮沉淀）

1. **「功能打开」不等于「功能对」** —— 上轮把入口打开就收工，差异被 Maestro 资产**全绿放过**；
   ⇒ **入口存在的功能，必须有一份「界面 == 设计」的断言**。
2. **断言要问「界面 == 什么」** —— 「元素在不在」与「界面 == 设计方案」是两条独立断言；前者绿不代表后者绿。
3. **动态 i18n 键是扫描器盲区** —— `t('prefix.' + k)` 既抓不到引用、又会在键名错位时把**键字符串本身**印到屏幕上。
4. **同一条数据可能被上游摊平** —— 线上 SSE 把 detail 摊到顶层、前端只读嵌套 detail ⇒ **取值全空但页面不报错**；
   ⇒ **前端读动作帧必须同时吃两种形状**（嵌套优先 + 平铺补齐）。
5. **两种模式不是同一套版面的缩放** —— 紧凑模式是**另一份设计契约**；两套节点同时在场会**抢同一批网格列**。
6. **`v-html` 注入的 SVG 拿不到 scoped 属性** —— 选择器不匹配 ⇒ 退回浏览器默认（黑色填充、无描边）⇒ 画面上一坨黑块；
   ⇒ 必须 `:deep()`。**「图标不显示」先怀疑 scoped，而不是图标数据。**
7. **量具会老化** —— mock 的时间戳固定在启动时刻 ⇒ 跑久了全部掉出时间窗 ⇒ **被误判成产品缺陷**；
   ⇒ 「断言红」先问「是不是量具坏了」。
8. **量具也要分组** —— 「所有瓦片在同一行」是错的判据（每带一行）；正确判据是「**同一条带内**的瓦片同行」。
