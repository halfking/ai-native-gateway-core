## 2. ★ 机制实测：资产里写的「跑法」三处是错的

这一节是本轮最贵的产出 —— **没实跑过就写不出这些**。

### 2.1 YAML 头必须是 `url:`，不是 `appId:`

`maestro/cli/util/FileUtils.isWebFlow` 读 **`YamlConfig.getUrl`** ⇒ 只有头里写 `url:` 才会被判为
web flow、启用桌面 web 驱动（CLI 会打印「Web support is in Beta」）。

| 头 | 实际行为 |
|---|---|
| `appId: ${BASE_URL}` | 判成**移动端** flow ⇒ 去「安装」`http://127.0.0.1:8782` 这个包 |
| `url: ${BASE_URL}` | web flow ⇒ 桌面驱动 ⇒ `openLink` 与文本断言全部 COMPLETED |
| 两个都没有 | 报「Config Section Required」 |

⇒ **11 个 flow 的头全部要改**（`01..09` + `90` + `_shared/login`）。

### 2.2 CLI 没有 `--env-file`；`-e KEY=VALUE` 是唯一通道

`maestro test --help` 的真实选项里**没有 `--env-file`**；且 **shell 的环境变量不参与 flow 里 `${}` 的解析**
⇒ 口令只能靠 `-e` 逐个传 ⇒ **口令会进进程 argv**（`ps` 可见）。

⇒ 取舍（已写进 README）：口令**不落仓内任何文件**，由 `maestro/run-local.sh` 从**仓根 `.env.local`** 读
⇒ 拼 `-e` ⇒ 调 Maestro。代价只有「本机进程表里可见」，不进 git、不落盘。

### 2.3 ★★ 不要加 `-p web`

`-p web` 会把设备集过滤成「未连接的 web 设备」⇒ 报 `0 devices connected` /
「Device default was requested, but it is not connected」。
**正确用法**：不加 `-p`，让 Maestro 从 flow 内容自动判定 web（内部 `includeWeb`），
再 `--driver-host-port 9222` 连一个**自起的 CDP Chrome**：

```bash
nohup chromium --headless=new --remote-debugging-port=9222 \
  --user-data-dir=/tmp/kx-r176-chrome-profile2 --no-first-run --disable-gpu about:blank &
maestro test --driver-host-port 9222 --headless --no-ansi -e BASE_URL=... <flow.yaml>
```

★ **`--driver-host-port` 在 `maestro test --help` 里没列，但确实被接受**（实测可用）。

### 2.4 ★★ `evalScript` / `runScript` 跑在 **Maestro 侧 JS 沙箱**，不是页面里

实测：web 模式下 `runScript` 里写 `console.log(location.pathname)` ⇒
`TypeError: Cannot read property 'pathname' of undefined`
⇒ ⇒ **页面里没有 `location` / `performance`**。

⇒ ⇒ **flow 里的 `output.ms__<slug>` 实测值完全来自 `Date.now() - output.t0` 这一路（纯墙钟）**，
而且 `output.*` 存在 Maestro 的宿主引擎里 ⇒ **跨导航不丢**。
⇒ ⇒ **这条计时通道是真实可信的，不是假红**（这一点原本只是 README 里的推断，现已坐实）。

★ 顺带：`runScript` **必须是脚本文件路径**（内联多行代码报「Invalid File Path」）；
`runScript` 的 `console.log` 落在调试产物的 `commands.json` 的 `logMessages` 字段 ⇒ 机器可读。

### 2.5 ★ iOS 模拟器是死路

`--udid <iPhone 17 Pro fresh>` 能 `openLink` 成功、截图确认 **Safari 真的渲染出了目标文案**，
但 Maestro 的 iOS 驱动**暴露 0 个文本节点** ⇒ 文本断言全红 ⇒ **不可用模拟器代替桌面浏览器**。

## 4. ★★ 真缺陷一：访客面每页白等 10 秒

### 4.1 定位过程（每一步都有证据）

1. Maestro 报 `slow-check:/forbidden ... WARNED` ⇒ 「打开超过 2 秒」。
2. ★ **先用 CDP 探针把「页面慢」与「量具慢」分开**（自建 `probe-page.mjs`：注入新文档、
   `PerformanceObserver` 抓 longtask、轮询 `document.body.innerText`）：
   - `/forbidden`：**DOMContentLoaded 89.8ms、FCP 492ms、只有 1 个 68ms 的 longtask**
     ⇒ ⇒ **页面本体不慢**；
   - 但正文 10.1 秒后才出现 ⇒ **慢的是「等」**。
3. ★ 抓网络时间线，看到 **5.09s 处一次 `fetch('/index.html')` + 紧接着一次整页导航**
   ⇒ 先查「是不是页面自己重载了」。
4. ★ 回源码 ⇒ 命中 `web/src/router.ts` 的路由守卫：

```ts
if (!store.authHydrated) {
  ...
  const AUTH_HYDRATE_MAX_WAIT_MS = 10_000
  return new Promise<void>((resolve) => {
    const check = () => {
      if (store.authHydrated && store.userInfo && store.userInfo.id) { resolve() }   // ★ 这里
      else if (Date.now() - startedAt >= AUTH_HYDRATE_MAX_WAIT_MS) { resolve() }
      else { setTimeout(check, 30) }
    }
    check()
  })
}
```

★ **判据把「探测已 settle」写成了「拿到了用户」** ⇒ **访客永远没有 `userInfo`**
⇒ 一旦走进这个分支，**唯一出口就是 10 秒上限** ⇒ **每个访客页面都白等满 10 秒**。

★ 而登录态不受影响（登录后 `userInfo` 在位 ⇒ 立即放行）
⇒ ⇒ **这精确解释了「只有访客面慢、登录面全绿」这个观测**。

### 4.2 修法

- 判据改成**只看 `store.authHydrated`**（= 探测 settle）：
  `App.vue` 的 `onMounted` 在 `finally` 里 `markAuthHydrated()`，且 `setUserInfo(user)` 排在它**之前**
  ⇒ `authHydrated === true` 时已登录者的 `userInfo` 必然已在位 ⇒ `isAuthed()` 可直接用。
- 10 秒上限**保留**作死锁兜底（探测挂掉时仍会 fail-open）。
- ★ **判据与等待循环抽成独立模块** `web/src/router/authHydration.ts`（纯函数，可单测）
  —— 仓内纪律：「决策逻辑必须是可单测的纯函数」（同 `isMaintenanceEnvelopeCode` 的先例）。

### 4.3 复测（同一台机器、同一浏览器、同一网关）

| 路由 | 修前 | 修后 | 倍率 |
|---|---|---|---|
| `/forbidden` | **10131 ms** | **181 ms** | 56× |
| `/bootstrap` | **10108 ms** | **182 ms** | 55× |
| `/customer/update-activate` | **10116 ms** | **170 ms** | 59× |

⇒ ★ **全站 10 个 flow 的 slow-check 计数从 8 降到 0**（§6 最终读数）。

## 5. ★★ 真缺陷二：页面在自己打开 5 秒后整页重载（违反自家规范）

### 5.1 证据

网络时间线里 **5.09s 处的 `fetch('/index.html')` + 整页导航** ⇒ 指向
`web/src/composables/useDeploySeqUpdate.ts` 的部署序号自更新链：
`UPDATE_FIRST_CHECK_DELAY_MS = 5_000` ⇒ 首查在 5s ⇒ 序号变化 ⇒ `shouldAutoReload()` ⇒ `reloadImpl()`。

★ 而 `docs/UI规范/18 §4` 的明文判据是：

> 「自动应用必须满足：页面已静置一段时间 **且** 焦点不在输入控件 **且** 距上次交互超过阈值。
> 三者任一不满足就降级为提示条」

★ 而实现写的是：

```ts
msSinceInteraction: lastInteractionAt === 0 ? Number.POSITIVE_INFINITY : nowImpl() - lastInteractionAt
```

⇒ **「从未交互过」被当成「已静置 ∞」** ⇒ 首查必然满足 ⇒ **首查即整页重载**
⇒ ⇒ **违反自家规范**，且让「陈旧缓存的 index.html ⇒ 每次落地 5 秒后白重载一次」变成常态。

★ 顺带发现：**`scroll` 不算交互** ⇒ 正在读长页面的人会被判成「静置」⇒ 也会被自动重载。

### 5.2 修法

- 以**页面加载时刻**（`loadedAt`）为「距上次交互」的基准 ⇒ 首查（5s）时 `msSinceInteraction = 5s < 30s`
  ⇒ ⇒ **降级为提示条**（正是规范要的），**5 秒自重载消失**。
- `scroll` 加入交互事件集 ⇒ 正在滚动的人不会被重载。

### 5.3 变异臂（证明测试有牙齿）

| 变异 | 期望 | 实测 |
|---|---|---|
| 把 `msSinceInteraction` 改回 `Number.POSITIVE_INFINITY` | 新增的 2 条回归断言红 | ✔ **1 条红**（另 12 条绿） |
| 还原 | 全绿 | ✔ 13/13 |

### 7.2 ★ 第二轮（部署 2.5.8.2896 之后）14 处 —— 全是**断言文案**与真实渲染文本对不上

★ 第一轮的断言错大多能被肉眼看出来（标题全错、页签抄错）。
★ **第二轮的 14 处全是「文案基本对、但一个字符对不上」** ⇒ 这是 Maestro 断言最阴的一类错。

★★ **根因（实测坐实）**：Maestro 的 `visible:` 是**全匹配**，**不 trim**，
且取的是元素的 **`textContent`**（**不是** `innerText`）⇒
页面上真实渲染的文本只要带**前后空白 / 上下文前缀 / 徽标数字**，写「干净的短文案」就会红。

⇒ 修法统一：**两侧加 `.*` 的正则，只锚住稳定的那一段**。
★ 正则可用性有**阳性 + 阴性对照**的实测（不是「读文档得来的」）：

## 11. 通用式（写进 `LESSONS.md` **§500**）

1. ★★ **「资产里写的跑法」只能当假设，第一次实跑才是事实源** —— 本轮实测出 3 处 CLI 层面的错
   （`url:` 头 / 无 `--env-file` / `-p web` 会筛掉设备），每一条都足以让整套验证**跑不起来或跑歪**。
2. ★★ **判据要区分「事实成立」与「主体存在」** —— `authHydrated && userInfo.id` 把「探测完成」
   偷换成「拿到了用户」⇒ 访客永远不就绪 ⇒ **白等上限**。凡是「A 且 B」形式的判据，
   都要问一句：**B 在最常见的场景下成立吗？**
3. ★★ **「超时兜底」一旦成为常规路径，它就是缺陷** —— 10 秒上限本意是防死锁，却成了访客的默认等待。
   ⇒ **上线后必须看它被走到的频率**（实测：访客 100% 命中）。
4. ★★ **先分清「页面慢」与「量具慢」，再动手** —— CDP 探针 + 页面内时间线（DOMContentLoaded / FCP / longtask）
   比任何端到端计时都便宜，且能直接指认「慢的是渲染还是等待」。
5. ★★ **自家规范里已经写了判据时，实现要回到规范** —— 18 §4 的「距上次交互超过阈值」被实现成
   「静置 ∞」⇒ 规范就是判据的来源，**不必另发明**。
6. ★★ **抄注释 / 抄变量名当断言 ⇒ 必然红** —— 「成本归因」是 HTML 注释，「工作类型列表」是另一个页签的标题。
   ⇒ **断言只认「渲染出来的完整文本」**，且要回语言包核对（`web/src/locales/zh-CN/`）。
7. ★★ **Maestro 的 `${}` 只做字符串替换，动态路由必须喂真值** —— 新增 `resolve-ids.mjs` 从活网关取 ID。
8. ★★ **首轮基线要先分「资产错」与「产品缺陷」** —— 本轮 12 处资产错里，若不先分开，
   很容易把「断言写错」当成「页面坏了」去改产品代码。
9. ★★ **编辑正在运行的 bash 脚本会让 bash 增量重读而读歪** —— 本轮把 `run-local.sh` 改在运行中途，
   ⇒ 收尾阶段 bash 把文件读成了乱码命令（`command not found`）。
   ⇒ **要么等它跑完再改，要么改副本**。
10. ★★ **单测必须做变异臂** —— 本轮两处修复各配 1 条变异（改回旧行为 ⇒ 测试必须红），
    才敢说「这条测试守得住这个缺陷」。
