## 0. 结论摘要

| 维度 | 现状 | 判断 |
|---|---|---|
| 任务识别（启发式） | 仓内 240 例套件 accuracy/macro-F1 = **1.000** | 强；应继续做主路径 |
| 任务识别（LLM 兜底） | 生产 **未配置** `LLMGatewayAutoLLM*` ⇒ `DisabledCaller` | 低置信度（如 chat 0.1）永不升级 |
| 本地 Ollama（30） | `192.168.31.30:11434` 可达；`qwen2.5:7b` 分类 60 例 **acc 63.3% / F1 0.59 / p50 565ms** | 适合做**低置信度兜底**，不适合替代启发式 |
| 模型选择多样性 | 实测 top3 常是同一 canonical（如 3×`glm-5.2`） | 完成度风险：failover 假梯子 |
| 生产 auto 流量 | 7d 仅 **3** 条 auto（总请求 4.6 万） | 学习闭环几乎没有样本 |
| 事实表 | `auto_route_selections(_hot)` 写入正常；热表已有本轮探针 | settle/affinity 样本过少 |
| Ollama 供应商登记 | `providers.id=19` 曾指向 `.13`，已改 **`.30`** | 与「任务识别用 30」对齐 |

**三角均衡建议（本轮采纳）**：

1. **完成度**：启发式主判 + 低置信度（&lt;0.7）走 30 主机 `qwen2.5:7b`；候选池按**上游/模型**多样性约束（不仅凭据）。
2. **成本**：分类调用只打局域网 Ollama（$0）；业务模型继续 cost/quality 六维分；profile=`cost_first` 时提高价格维权重。
3. **效率**：分类超时 15s（冷加载）、热路径 p95≈1s；会话意图缓存命中则跳过重分类。

## 1. 现有链路（代码事实）

```text
model=auto
  → ClassificationSignals（正文只在内存）
  → HeuristicClassifier（主）
  → confidence < threshold ?
        是 → LLMFallbackClassifier（需 LLMGatewayAutoLLMEndpoint）
        否 → 采用启发式
  → RecommendV2 / 六维打分 + affinity 软重排
  → L2 凭据选择（tier / billing / P2C）
  → WriteAutoSelection → auto_route_selections(_hot)
  → settle → reward → affinity worker 回灌
```

关键文件：`autoroute/classifier*.go`、`decision*.go`、`recommend_v2.go`、
`domains/streaming/auto_route.go`、`telemetry/selection_writer.go`、
`cmd/gateway/main_types.go`（`buildAutoLLMCaller`）。

设计文档：`docs/auto-model-optimization/`（事实表唯一、只存元数据、ML 先结构化特征）。

## 5. 优化训练方案

### 5.1 数据边界（沿用仓内铁律）

- 训练集只来自 `auto_route_selections` + 人工标注元数据
- **禁止** prompt/messages/response 入训练集
- 特征：语言、长度桶、轮数桶、code/math/table/mm 标志、intent/domain、复杂度、敏感标志、`content_hash`

### 5.2 阶段

| 阶段 | 动作 | 验收 |
|---|---|---|
| A. 采数 | 打开 AutoLLM；`X-Gw-Test-Mode: mock` + token 对 240 套件全量决策头采集；另对真实业务开 auto 灰度 | 7d auto≥1000 或标注≥200 |
| B. 规则补洞 | 对 mismatch 只扩启发式词表（单一常量，见 R75 教训） | auto-testbench 不回退 |
| C. 结构化 ML | 逻辑回归/树模型，shadow 对比启发式 | macro-F1≥启发式 且 延迟 p95≤5ms |
| D. 本地 LLM 校准 | 用 mismatch 集微调/少样本提示；只服务 conf&lt;θ | 兜底集 F1≥0.75，p95≤2s |
| E. 路由层 | 多样性闸（distinct model/upstream≥2）；不健康主模型降权 | 单模型池率↓；低 conf 成功率↑ |

参考实现入口：`docs/auto-model-optimization/08-ml-training-pipeline.md`、
`cmd/auto-testbench -mode generate`、`annotation/`、`ml-training/`。

## 6. 自我优化流程改造

```text
线上 Decide
  → 写 selections（已有）
  → settle 补 success/latency/cost/reward（已有）
  → affinity 软重排（已有，样本不足）
新增：
  1) 每日任务：低置信度 × 失败 抽样 → 标注队列（只元数据）
  2) 周任务：auto-testbench 回归门 + Ollama autoclass-bench 门
  3) 棘轮：collapse_rate / distinct_model_rate / low_conf_success_rate 只降不升
  4) shadow：结构化模型与本地 LLM 并行写 shadow_* 列，不改赢家
  5) promote：shadow 连续 7d 不劣于基线才切主
```

与开源对齐的一点：**用阈值显式交易成本与质量**（RouteLLM），但阈值按任务类型分桶，而不是全局一个。
