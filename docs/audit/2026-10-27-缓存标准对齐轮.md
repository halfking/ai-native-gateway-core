## 二、原厂规格快照（2026-10-27 抓取）

### OpenAI（developers.openai.com/api/docs/guides/prompt-caching）
- 默认开启；请求参数：`prompt_cache_key`（<GPT-5.6 用于路由优化）、
  **`prompt_cache_options`** `{mode: implicit|explicit, ttl: "30m"|"12h", prewarm: bool}`
  （GPT-5.6+，Responses API）、**`prompt_cache_breakpoint`**（挂在内容块上，
  每请求最多 4 个写入 —— OpenAI 版的「检查点注入」）、旧参数
  `prompt_cache_retention`（`in_memory`|`24h`）。
- usage：`input_tokens_details.cached_tokens` + **`input_tokens_details.cache_write_tokens`**
  （含 `cache_write_tokens_details.ttl_30m_tokens/ttl_12h_tokens` 分档）。
- 计价：读 0.1×（GPT-6.1 Sol 0.05×）；写 1.25×（30m）/2.5×（12h）；最小可缓存前缀
  1024 tokens（GPT-5.6+）。`prompt_cache_retrieval_match` 在现行文档中**不存在**。

### Anthropic（platform.claude.com/docs/en/build-with-claude/prompt-caching）
- `cache_control: {type:"ephemeral", ttl:"5m"(默认,省略不发)|"1h"}`；可挂 tools /
  system / messages 块 / tool_result（thinking 块与空文本块不可挂）；块级断点上限 4；
  **请求体顶层 `cache_control`（自动缓存）**为现行特性；`max_tokens: 0` 预热。
- usage：`cache_creation_input_tokens`（=嵌套对象之和）、`cache_read_input_tokens`、
  嵌套 `cache_creation.{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}`。
- 计价：5m 写 1.25× / 1h 写 2× / 读 0.1×（新模型 0.025×~0.05×）；最小可缓存 512~4096。

### Gemini（ai.google.dev/gemini-api/docs/caching + /api/caching）
- 隐式缓存对 2.5+ 全模型默认开启（最小 2048/4096 tokens）；显式缓存 =
  `POST/GET/PATCH/DELETE /v1beta/cachedContents`（仅过期时间可改），请求经
  `cachedContent` 字段引用；响应 `usageMetadata.cachedContentTokenCount`。
  Interactions API 与 Gemini 4 Argon+ 不支持显式缓存。

### DeepSeek（api-docs.deepseek.com/guides/kv_cache + API 参考）
- 自动、无客户端旋钮；usage 同时发顶层 `prompt_cache_hit_tokens` /
  `prompt_cache_miss_tokens` **与** `prompt_tokens_details.cached_tokens`（两者恒等）。

## 八、通用式（本轮沉淀）

1. **自证夹具会锁死量具的拼写错误**：`input_token_details` 单数死键活了半年，
   是因为夹具断言的就是错拼形态——「测试绿」只证明「实现与夹具一致」，
   不证明「夹具与厂方一致」；对拍必须回到原厂文档。
2. **测试先行撞出真缺口**：ttl 往返测试首跑即红，暴露的不是 ttl 而是
   system 块整段检查点丢失（两条解析路径不对称）——单一字段的对拍值得为
   「路径覆盖完整性」付费。
3. **文档表格要先读表头再读格**：gemini.md 的 ❌ 是「必填=否」，不是
   「网关不支持」；按列语义误读去订正文档 = 制造新漂移。
