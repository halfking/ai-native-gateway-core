## 0. 一句话结论

**「仓内 DDL 不是产品表真源」这个前提被双重推翻**：

1. **分母错** —— §19.20.50 ④ 的「21 个产品表」清单里，3 个是**已退役的 v1 request_logs 族**、1 个**名字写错**、1 个**前缀截断** ⇒ 修正后 = **19 个真实产品对象**；

⇒ ⇒⇒ **⇒ 真正的真源问题被重新定义：不是「仓内 vs 生产」的对齐问题，而是「这个库里哪些对象属于本产品」的归属问题。**

## 6. 本轮自曝：量具的输入目录不能与并行写者共享

- 现象：同一段扫描代码**两次运行结果不同**（`route_incidents` 一次命中一次不命中）。
- 根因：扫描器 `ROOT` 指向**共享树** ⇒ 并行会话此刻正在那棵树上做 git 操作 ⇒ **事实源漂移**。
- 处置：① 改指**干净 detached worktree**（tracked = HEAD、工作区 0 项）；② 给提取器加**确定性自检**（同一输入跑两次，不一致 ⇒ 中止、拒绝给结论）；③ **重跑全部分段读数** ⇒ 与第一版**逐字相同** ⇒ 「第一版读数未被污染」得到确认 ✓。

## 7. 可复算命令

```bash
# 生产只读（252；relkind 必须 ::text）
ssh 252 'podman exec pg-252-pg17 psql -U llm_gateway -d llm_gateway -A -F"|" -t -c "
SELECT c.relname, c.relkind::text, COALESCE(pn.nspname||'"'"'.'"'"'||pc.relname, '"'"''"'"')
FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
LEFT JOIN pg_inherits inh ON inh.inhrelid=c.oid
LEFT JOIN pg_class pc ON pc.oid=inh.inhparent
LEFT JOIN pg_namespace pn ON pn.oid=pc.relnamespace
WHERE n.nspname='"'"'public'"'"' AND c.relkind IN ('"'"'r'"'"','"'"'p'"'"','"'"'v'"'"','"'"'m'"'"') ORDER BY 1;"'

# 生产只读（211 专属库）
ssh 211 'docker exec acc-pg17 psql -U llm_gateway -d llm_gateway -A -F"|" -t -c "<同上>"'

# 仓内扫描（★ 必须指向干净 worktree，且带确定性自检）

#   语句种类：CREATE TABLE / VIEW / MATERIALIZED VIEW；
```
