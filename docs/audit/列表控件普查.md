## 关于「没有控件」的 51 / 54 个

多数列表的维度不是时间也不是模型，而是状态、租户、凭据、任务类型。
给它们加日期/模型控件不会让查找更快，只会让工具栏变长。真正值得补的是
**本来就以时间或模型为主轴、却缺筛选器**的那几类（逐项判断，不批量加）。

## 名称列表里刻意不按名称排序的

审计门用的是启发式（看到名称列就点名），下面这些是**误报**，按名称排反而更差：

| 列表 | 原因 |
|---|---|
| `provider-detail/LogsTab` | 请求日志流，时间倒序才是正确默认 |
| `provider-detail/ProbeHistoryTab` | 探测历史，同上 |
| `provider-detail/ErrorDetailTab` | 错误明细，同上 |
| `ModelIntegrityView` | 事件流 + 漂移事件，同上 |
| `tenant/MaaSUsageView` | 用量流水，按时间看才有意义 |
| `UserProfileView` | 单条详情页，本就不是列表 |
| `StandardModelPricingView` | 排序发生在 `useModelCatalogFilters` 内部，会连带影响筛选/分组语义，需单独评估 |
