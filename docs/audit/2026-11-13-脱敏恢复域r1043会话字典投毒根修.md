### 1.3 三条根因链（r1043 D1/D2/D3，本地以生产快照规则逐字复现）

| # | 形状（逐字） | 旧行为 | 危害 |
|---|---|---|---|
| D1 标记投毒 | `SSH_USER="[REDACTED:account]"` | account_declaration 命中，**标记本身**铸成占位符值 | 还原器此后把标记当真值永久写回输出；标记成为会话词汇表永久成员 |
| D2 代码投毒 | `if 'SSH_USER=' in l or l.startswith('[ -n "$SSH_USER" ]'):`（值文法的引号臂捕获 `' in l or l.startswith('`）、`user=\$(docker`、`DB_USER=${DB_USER:-$(whoami)}` | 模型代码片段被当「账号」铸造；**输入侧把含引号的 span 挖走换占位符** | 模型收到的代码语法残缺（成对引号被吃掉一侧）；模型按残缺理解重写文件 ⇒ `bash -n` 从未再通过＝**「命令执行失败」本体** |
| D3 知名账号触发 | `SSH_USER="root"` / `USER=root` | root 占位符化 | 模型发现「有过滤器在改我的文件」⇒ 开始写修补代码 ⇒ 引爆 D1/D2 |

事故时间线：D3 触发 → 模型写 Python 修补脚本在 `[REDACTED:account]`/占位符文本上做字符串手术 →
D2 把修补代码本身铸成毒值（account:34/35/22）→ D1 把标记铸成毒值（account:6/36）→
回显这些占位符时还原器写回毒值/标记 → 文件被写坏 → bash -n 失败 → 模型二分排查 →
进一步改写 → 循环。用户看到的即「敏感信息没有恢复，命令执行失败」。

### 1.4 既有防线为什么没挡住（同族第五/六次复发）

r1030/r1042 已给「网关自产标记的**回声**」做过检测免疫（`detectionExemptSpans`：
花括号原形、带词退化、无词尾巴）——但只覆盖 `{SENSITIVE:…}` 族，**不覆盖
`[REDACTED:…]` 遮蔽标记**（r1038 起标记一律带类型，形状恰落在声明族值文法内）；
也不覆盖「值是代码片段」。§705 的结论（自己产的 token 被自己的规则命中是一类
结构性误报）在**遮蔽标记**与**值文法过宽**两个新面上再次应验。

## 二、修复（全部引擎级 ⇒ 对已发布规则快照 v2 立即生效，不动 DB）

| 修复 | 位置 | 语义 |
|---|---|---|
| F1 标记免疫 | `detector.go` 匹配循环（值级，**所有规则族**）+ `placeholder_loose.go` `redactedMaskValuePattern` | 值**恰好整个是**遮蔽标记（`[REDACTED]`/`[REDACTED:type]`，含声明文法 `]` 截断出的**前缀形态**，大小写不敏感）⇒ 豁免 + 台账 exempted。真实凭据不以 `[REDACTED` 开头，无误豁免面 |
| F2 账号字面量形状 | `r1043_account_literal.go` `accountLiteralPattern` + `accountValueIsExempt`（detector 接线） | account_declaration/account_assignment 的值必须是账号字面量（`[\p{L}\p{N}_.@-]{1,64}`，字母/数字开头）：代码片段/引号串散文/`$(…)`/`${…}` 豁免；`zhangsan_ops_2024`/`kaixuan.admin` 照常命中 |
| F3 知名账号豁免 | 同上 `wellKnownAccountLiterals`（封闭集） | root/admin/ubuntu/postgres/git 等**系统公开默认**不占位符化（判据族＝r1024「身份不是机密」/r1039 D7「示例值不是泄漏」）。**刻意不收** deploy/operator/ops（组织惯用名，r1024 与输出面钉测把它们钉在「必须检出」一侧） |
| F4 字典清洗 | `smart_sani_guard.go` 三处（输入字典载入 / restore `loadMap` / `sanitizeMapValues`） | 值恰好是标记的**存量**投毒条目在载入时丢弃（Redis 原字段不动——commit 只 HSET 幂等）；旧回声按未命中 fail-closed 遮蔽，不再写回毒值 |

设计取舍（写死在代码注释里）：
- 标记免疫放**值级**而非 span 级：span 级会把 `password=[REDACTED]真凭据` 的
  前缀匹配挖空 ⇒ 真凭据检测一起消失（`TestSedMaskWithProductionYAML` 钉住的既有
  行为，变异期实测撞过）。
- F2 只作用于 declaration/assignment 两 kind；credential_pair 的账号臂与密码臂是
  同一规则的两个捕获组，单独豁免会改变配对语义（登记不修）。

## 六、登记不修（裁决面）

1. **粘着标记后的真凭据文法可达性缺口**（§四第 1 行）——改值文法让裸 token 臂跨过
   `]` 续匹配会放大误报面，归 owner 裁决；
2. **credential_pair 账号臂**不适用 F2/F3（§二取舍）；
3. `{SENSITIVE:secret:16} → smm:[REDACTED:secret]` 一类「值里**嵌**标记」的复合形态
   不是 F1 的整值判据对象（可能是真实 DSN 结构），清洗只认「整个值是标记」；
4. deploy/operator/ops 等组织惯用账号维持检出（r1024 钉）；若 owner 认为它们也该
   豁免，在 `wellKnownAccountLiterals` 加一行即可（判据注释已写）；
5. 事故会话 `gw_ae47d6bb…` 的存量毒条目：部署 F4 后自动在载入侧被丢弃，Redis 原字段
   保留（无需清库）；如要物理清理可 `HDEL` 值为标记的字段（非必需）。
