## 2. 判据（唯一实现：`web/src/design/spacingScale.ts`，自证 **28/28**）

### 2.1 一条判据

> **`margin` / `padding` / `gap` 的静态长度值必须落在已声明的间距阶上。**

- **阶的事实源** = `web/src/style.css` 里 `--kx-space-*` 的**实际定义**（运行时解析，**绝不硬编码**）⇒ 改令牌 = 改判据。
- **不判**（单独计数，不算违规）：`auto` / `none` / `inherit` / `initial` / `unset` / `revert` /
  `%` / `em` / `vh` / `vw` / `calc()` / `env()` / 其它 `var()`（静态不可定值）、
  `var(--kx-space-*)`（**已经在消费令牌**，是阶的用法不是违反）、
  `0`（没有间距）、**负值**（负 margin = 抵消形状，不是节奏）、**≤ 3px**（发丝 / 光学微调）。
- **rem 判红**（根字号 16px ⇒ 可静态换算）；**em 不判**（相对语义是有意的）。
- ★ **豁免计数必须可见**（`facts.hairline` / `zero` / `negative` / `dynamic`）——
  「豁免命中数为 0」是危险信号，不是「干净」。

### 2.2 ★★ 判据的两条**硬错误**（不是棘轮指标）

| 硬错误 | 判什么 | 为什么不是棘轮 |
|---|---|---|
| **扫描器盲区** | 声明值里有**没被任何分量覆盖**的数值令牌 | 它判的是「**本门有没有盲区**」⇒ 盲区是**事实**，不是可谈的指标 |
| **豁免漂移** | 裁决簿登记了 N 条豁免，但命中 0 条 / 部分失效 | 裁决簿与代码漂移 ⇒ 门会「因为豁免而绿」但绿得没有依据 |

### 2.3 ★★★ 本轮抓到的判据缺陷（前导小数点）

`splitSpaceComponents` 的数字正则写成 `-?\d+(?:\.\d+)?` ⇒ **匹配不到前导小数点**：

```
`.35rem`  →  匹配到 `35rem`（`.` 落在区间之外）
             ① parseFloat('35rem') = 35 ⇒ px = 560（真值 5.6）
             ② 改写时只替换 `35rem` ⇒ 留下 `.64px`（5.6px 变成 0.64px）
```

★ 三道闸**全过**：

| 闸 | 为什么没拦住 |
|---|---|
| 闸① 声明总数不变 | 声明数确实没变 |
| 闸② 改写后离阶 = 0 | `0.64px` ≤ 3px ⇒ 落在**发丝豁免**里 |
| 闸③ 非间距内容逐字未变 | 那个 `.` 被当成「非间距内容」⇒ 逐字未变 |

⇒ ★★★ **闸③ 结构上挡不住「区间选错」**（它只保证区间之外逐字未变）。
⇒ ★★★ **聚合读数完全不变**（离阶 1711 → 1711、rem 198 → 198）⇒ **只有写入的文本被改坏**
⇒ ★★★ 这是「**门绿 ≠ 事实已改**」的一个教科书级实例。

**修法**（三条，缺一不可）：

1. **数字正则覆盖语言允许的全部写法**：`-?(?:\d+(?:\.\d+)?|\.\d+)`（含前导小数点）。
2. ★★★ **闸⑥ 令牌完整性**（新增，**独立于 px 换算**）：把声明值按分量切开后，
   **残留只允许「分隔符 + 具名值」** ⇒ 任何被漏掉的数值令牌都会以「残留里有数字 / 小数点 / 未知单位」暴露。
   ⇒ ★★ **这道闸为什么必须独立**：任何「用算出来的 px 再校验一遍」的复核都会**跟着一起错**
   ⇒ 它问的是「**文本**有没有被完整切分」。
3. ★★ **闸⑤ 比值闸**（新增）：收缩 / 放大超过 **2×** 的改写**必须**有裁决簿里的显式条目。

★ 闸⑥收紧后当场抓到 **4 处真实盲区**：`env(safe-area-inset-bottom, 0px)` ×2 与 `!important` ×2 ——
**全是合法 CSS，但扫描器读不懂 ⇒ 这 4 处此前完全没被门判过** ⇒ 补上 `env()` 与 `!important` 的解析后归零。

### 3.2 运行时尺 `web/scripts/design-spacing-scale-runtime-check.mjs`（第二把尺，自证 **14/14**）

| 维度 | 源码门 | 运行时尺 |
|---|---|---|
| 看什么 | 源码里**声明的** spacing | 浏览器里**渲染出来的**兄弟间隙（rect 实测） |
| 判据 | **绝对型**（离阶必须 0） | **趋势型**（相对基线只降不升） |
| 为什么 | 源码层豁免的是**写法/大小** | 运行时层合法存在源码层豁免的形态（`auto` / `%` / 发丝 / 派生对齐偏移）⇒ 运行时**不可能**要求「离阶 = 0」 |

★★ **运行时尺的主判据必须是【渲染出来的量】**：`getComputedStyle` 会把 `margin: 0 auto` 与 `%` 内边距
**解析成算出来的 px** ⇒ 那些值在运行时层**无法与「手写的魔法数」区分** ⇒ 拿它们当判据会造出成片假阳性。
⇒ 正解 = **rect 实测兄弟间隙**（含两侧 margin + 容器 gap + 边框），但要加三道限定：

1. **同一行/同一列**（另一轴的矩形区间必须重叠）—— 否则把「同列里隔了 700px 的两个区块」当成 700px 的「节奏间隙」
   （实测第一版把 `/examples` 的 **1221px / 1057px** 全算成间隙 ⇒ 读数毫无意义）。
2. **跳过 `space-between/around/evenly` 分布的容器** —— 那段距离是**自由空间**（对齐方式插入的），不是任何声明的间距
   （实测第一版把 `.page-header-right` 记成 **782px** 的间隙）。
3. **超过阶顶（64px）的算「布局距离」，只统计不判** —— `margin-left: auto` 把兄弟推到两端会产出 1187px / 546px 这类值。

### 3.3 ★★ 迁移器 `web/scripts/design-spacing-scale-migrate.mjs`（六道闸）

| 闸 | 判据 |

## 4. 裁决簿 `web/scripts/design-spacing-scale-decisions.json`

### 4.1 ★★ 平局为什么一律取下界（**实测依据**，不是拍脑袋）

平局档（恰好落在两档中间）有 8 个：6 / 10 / 14 / 20 / 28 / 36 / 44 / 56 px。
取上界还是下界，要看**这个属性在本仓本来就住在哪一档**（先例）：

| 属性 | 前态（HEAD，同一把尺）各档用量 | 主流档 |
|---|---|---|
| `margin-bottom` | 4px:75 · 8px:95 · **12px:165** · **16px:163** · 24px:23 · 32px:2 | **12 / 16** |
| `margin-top` | 4px:76 · 8px:72 · 12px:61 · 16px:44 · 24px:7 | 4 / 8 / 12 / 16 |
| `padding` | 4px:223 · 8px:471 · **12px:417** · **16px:253** · 24px:81 · 32px:30 | **8 / 12 / 16** |
| `gap` | 4px:189 · **8px:476** · **12px:238** · 16px:118 · 24px:12 | **8 / 12** |

⇒ 四个属性的主流档**都在 16px 及以下** ⇒ 平局取下界（20→16、28→24、36→32）**与仓内既有档位一致**；
⇒ ★★ 取上界（20→24）反而会把「组件内边距」推进一个只有 81 处的档位 ⇒ **层级会塌**。
⇒ 另有一条独立理由：本仓是**运维台**（表格 / 抽屉 / 弹层密集）⇒ 密度优先于松。

### 4.2 ★★★ 派生对齐偏移豁免（1 条）

```
key: components/detail/RequestProcessingFlowDiagram.vue|.waterfall-axis|margin|112px
```

- **112px = `.waterfall-row` 的 `grid-template-columns: 104px 1fr` + `gap: 8px`**
- ⇒ 轴刻度的左边界必须与泳道条的左边界重合 ⇒ 改成 64px 会**破坏对齐**
- ⇒ 它**不是档位**，是**推导结果** ⇒ 落在阶上反而会错
- ⇒ 豁免簿必须写「**为什么它不是档位**」，而不只是「放过它」

★ **豁免键不带行号**：`file|selector|property|raw`（★ 行号会漂移 ⇒ 行号错的门比没有门更坏）。

### 4.3 ★★★ rem 的三种落地方式

| 形态 | 落地 | 理由 |
|---|---|---|
| **发丝 rem**（换算后 ≤ 3px，如 `0.1rem` = 1.6px） | **等值**（`0.1rem` ⇒ `1.6px`，数值逐字不变） | 它是光学微调，**不表达档位** ⇒ ★★ 按就近阶会落到 4px 档 ⇒ **badge 内边距高 2.5 倍**（实测 5 处） |
| **在阶上的 rem**（如 `0.5rem` = 8px） | 只换写法，数值不变 | 数值已合规 |
| **离阶的 rem**（如 `1.25rem` = 20px） | 按平局规则落到 16px | 见 §4.1 |

★ **豁免说的是「值的大小」，rem 说的是「写法」** —— 两件事，不冲突。
