## §四 重点域逐条审计（双代理扫描 + 承重结论亲验）

### §4.1 脱敏/恢复域 —— P2 已修（本轮最重要交付）
**发现（P2）**：`/v1/images/generations`（images_generations.go）与 `/v1/videos/generations`
（videos_generations.go）**完全绕过 SmartSaniGuard**：
- 输入侧：`sanitizeEnvelope` 的 switch 没有 media 分支（default 找 messages 找不到 ⇒ 原样直通），
  两个 handler 也不挂中间件 ⇒ **prompt 明文出上游**；
- 响应侧：media 响应是非流式 JSON（{created, data[]}），既非 native Messages/Responses 形态也无
  choices ⇒ 即使过拦截链也只落在 maskUnrecognizedBody，从不还原；handler 直接写 respBody，根本不进链
  ⇒ **占位符出得去、原文回不来**。
- **为什么既有量具全绿**：5 序列化器还原矩阵/反射门只管 IR 参数还原轴；脱敏钉测全部经 ChatHandler
  入口构造 ⇒ 守卫在缺陷处没有牙。骨架端点（2026-10-08 Phase C）创建时守卫链尚未建成，此后无
  「端点×挂载点」对拍门 ⇒ 缺口存活 3 个月。

**实施**：
1. `security/sanitize/input_protocols.go`：sanitizeEnvelope 增 `/v1/images|/videos/generations` 分支
   （prompt 复用 completions 同款口径；字符串/数组两形态；非文本 token-id 直通）。
2. `security/sanitize/media_restore.go`（新）：`SanitizeRestoreInterceptor.RestoreMediaBody` —— 映射取
   请求 Context 的完整活字典（中间件 Wrap 尾部放入，已含 Redis 会话装载与本次新增）；复用
   `restoreNativeNestedValue` 通用树行走：已知占位符还原 / 未知标记打码 / 残余保留标记
   fail-closed（ErrMediaRestoreBlocked）。
3. `domains/streaming/images_generations.go` + `videos_generations.go`：`SetSanitizeGuard` 成对装配；
   鉴权后绑定租户（`WithAuthenticatedTenant`，与 chat 同契约——防攻击者预置租户映射）；2xx 响应过
   RestoreMediaBody，还原通道报错 ⇒ 502 `sanitize_restore_blocked`。
4. `cmd/gateway/goal_control.go`：installSmartSaniGuard 扩参接线两 handler；**还原拦截器构建失败时
   撤回输入中间件（SetSanitizeGuard(nil,nil)）**——「只脱敏不还原」的半装配比不装配更糟；
   `SanitizeGuardWired()` 探针只在两半都非 nil 时返回非 nil。

**门与验证**：
- 钉测 8 条：envelope 2（prompt 入洗+元数据不动 / 无 prompt 直通）+ restore 5（直通/还原/打码/截断
  fail-closed/键名标记 fail-closed）+ 端到端 2（上游收占位符+客户端收原文 / 伪造占位符被打码）。
- **变异验证**：禁用 envelope media 分支 ⇒ sanitize + streaming 两包当场红；还原 ⇒ 绿 ⇒ 门有牙。
- `go test ./security/sanitize/` ok 10.1s；`./domains/streaming/` ok 86.2s；`./cmd/gateway/` 装配序钉 ok。

**登记不修**：

  归 owner 裁决。
