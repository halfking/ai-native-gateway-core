## §1 起因：第 30 增量留下的那条待办 + 一条从来没人管过的禁令

第 30 增量（裸指标卡网格轮）在 `DESIGN.md` §6 的**三条**卡片禁令里处理了两条：
「不许用同尺寸卡片当页面骨架」与「不许用巨型数字 + 小标签当 hero 指标模板」。
★ **剩下的一条从来没有任何门管过**：

> - 卡片是懒容器；**卡片套卡片永远不对**。

而且它**不是**某个静态 CSS 扫描器能看见的东西：
`web/src/design/aiSmells.ts` 的 V1~V11 全是**静态 CSS 扫描**，
而「卡片套卡片」是一个**运行时结构属性**（一个盒子里面到底有没有卡）
⇒ ⇒ 与仓内既有运行时尺（icon-size / action-density / elevation / motion /
primary-clarity / primary-focus / semantic-color / spacing-scale / type-scale /
metric-skeleton）同族，**新开一道浏览器运行时尺**是正确落点。

## §2 事实源：这条禁令的措辞决定了判据落在哪一层

事实源有两处：

1. **impeccable `skill/reference/craft-floor.md:25`**（canonical 副本）：

★★ **本轮最关键的一次判据层级判断，来自这句话与前两条禁令的措辞差异**：

## §4 ★ 判据设计：为什么「底色 + 可见描边」必须**同时**在

### §4.1 三级定义

```
卡面 isSurface(el) =
    可见（不在隐藏子树、宽>0、高>0）
  ∧ 非交互控件（button / a / input / select / textarea / option / label）
  ∧ 非药丸（圆角 < 高的一半）—— 药丸是 chip，不是卡
  ∧ 圆角 > 0 —— 卡片是圆角的；页面外壳不是
  ∧ 四边内边距之和 ≥ 8px
  ∧ 有底色（background-color 非透明）                ★
  ∧ 四边都有**可见**描边（宽 ≥ 1px 且**色**非透明）   ★

外层「盒子」isContainer = 卡面 ∧ 宽 ≥ 120 ∧ 高 ≥ 48
内层「卡」  isCard      = 卡面 ∧ class 名含 `card` 词 ∧ 宽 ≥ 120 ∧ 高 ≥ 24
嵌套                     = 一张卡的**最近**盒子祖先存在
```

### §4.2 ★★ 「底色」与「可见描边」为什么必须同时成立

| 只看描边 | 只看底色 | **两个都看** |
| --- | --- | --- |
| `1px solid transparent` 的**占位描边**被当成描边 ⇒ 列表行被当成卡（§3.1） | 页面外壳（有底色、无描边）被当成盒子 ⇒ **整页每一张卡都成了「嵌套」** | ★ 卡片在运行时必须**同时**具备「面」与「边」，**拆掉任一它就不再是卡** |

⇒ ★★ **最后这条是本门最关键的设计**：它让**「只去掉描边、留下底色」这种半修法骗不过门**。
⇒ 而 §5.2 的修法正是**两面都拆**（去底色 + 去描边 + 去圆角）⇒ 门绿得干净。

### §4.3 ★ 内层为什么要「class 名含 `card` 词」

卡面之上还要仓内**自己的命名约定**命中（`.card` 全局类 + `*-card` 组件类）。
它把「同样有底有框的别的东西」分开：

| 元素 | 为什么不是卡 |
| --- | --- |
| `pre.code-block` | 有底有框，但它是**代码内容**，不是卡 |
| `div.kpi-chip` | 药丸，本来就被「非药丸」排除 |
| `button.link-card` | 名字里有 card，但它是**控件** ⇒ 被「非交互控件」排除 |
| `div.setting-item` | 是设置项，不是卡 |
| `div.card-toolbar` | 只有 `border-bottom` ⇒ 不是四边描边 ⇒ 不是卡面 |

★ **判据宁可窄不可宽**：class 名里没写 `card` 的东西，本门**不管**它
（★ 这条**已知的漏判面**记在 §8）。

### §4.4 ★ 为什么内层卡的高度下限是 24 而不是 48

第一版把「卡面」的高度下限设成 48px。★ **这会把真违规判绿**：

- `.reg-card`：`min-width: 220px` + `padding: 8px 8px` + `font-size: 12px` ⇒ **实测高约 37.6px**
- `.probe-card`：`padding: 8px 8px` + `font-size: 12px` ⇒ **实测高 37.6px 与 84px 两种**

⇒ 门第一次跑出来 `/admin/request-registry` 是 **0 对**、而独立的 v4 勘察是 **25 对**
⇒ ★★ **两条独立证据对不上时，先怀疑自己的量具**（★ 第 30 增量栽过同一类坑）。
⇒ 修法：把尺寸下限**分级** —— 外层盒子 ≥ 48（它要装得下一批卡），内层卡 ≥ 24（**矮卡也是卡**）。

### §4.5 ★ 硬闸与棘轮

- **硬闸**：任意一页出现 **1 对**「卡 ⊂ 盒」⇒ 判红（元素级禁令，无豁免）
- **棘轮**：逐页「嵌套对数」**只降不升**
- **基线不可用**（文件缺失 / 整册 `{}`）⇒ **在测量之前**就判红 ⇒ 「把基线删掉」不是后门

★ 与第 30 轮那扇门相比，本门**多一道闸**：`--update-baseline` 写回的值 = **`min(旧值, 实测值)`**
⇒ ★★ **重建基线这条路也放松不了棘轮**（★ 这条在 §7 被变异臂当场抓到过真 bug）。

## §9 通用式

1. ★ **限定语决定判据层级** —— 「当页面骨架」⇒ 页面级；「永远不对」⇒ **元素级**。
   ⇒ 读事实源时**先找限定语**，它直接决定判据落在哪一层
2. ★ **「描边宽度 ≥ 1px」不等于「有描边」** —— 必须**同时**验**描边色非透明**
   （占位描边 `1px solid transparent` 极常见）
3. ★ **一个元素要算「卡」，必须同时具备「面」（底色）与「边」（可见描边）**
   ⇒ 拆掉任一它就不再是卡 ⇒ ★ **门不会被「半修法」骗过**
4. ★ **只查一个信号 ⇒ 另一类东西必然被误判**：只看描边 ⇒ 列表行被当卡；只看底色 ⇒ 页面外壳被当盒子
5. ★ **尺寸下限要分级**：外层盒子要装得下一批卡（≥48），**内层卡可以很矮（≥24）**
   ⇒ 一刀切的高下限会**把真违规判绿**（`reg-card` 实测高 37.6px）
6. ★ **两条独立证据对不上时，先怀疑自己的量具** —— 门说 0、独立的勘察脚本说 25 ⇒ 是门错了
7. ★ **「0 命中」有两种读法**（真没有 / 没扫到）⇒ **判据放宽后必须立刻与另一把尺对拍**
8. ★ **打「最近的一对」会漏判** ⇒ 必须打**完整祖先链** ⇒ ★ 本轮正是靠它发现了 `el-tabs--border-card` 这一层
9. ★ **第三方库的 class 名里也会含 `card`**（`el-tabs--border-card`）
   ⇒ ★ 它在**视觉上确实是一张卡** ⇒ 这类东西要么改库用法，要么改判据，**不能靠"它只是库的名字"搪塞**
10. ★ **「只许降不许升」这种朴素实现，方向很容易写反** ⇒ ★ 必须是 **`min(old, now)`**
    ⇒ ★ **真仓变异臂是唯一能抓住它的手段**（本轮 M6 当场抓到）
11. ★ **基线不跟着修法一起降，棘轮就是形同虚设的** ⇒ 上限停在旧值 ⇒ 涨到旧值都不红
12. ★ **「修法」与「被修的病」要分开记账** —— 修了工具的 bug ≠ 降了基线；降了基线 ≠ 修了工具
13. ★ **import 一个模块会连带执行它的 CLI** ⇒ 运行时尺模块要有 `import.meta.url === argv[1]` 守卫
    ⇒ ★ 否则「复用判据」会变成「连带跑一遍全量浏览器」
14. ★ **判据里只要有一个正则，就必须让它被自证覆盖** ⇒ ★ 判据**从原始字段现算**，
    不让探针另算一份（否则两条实现会悄悄分叉，而正则一次都不会被测到）
15. ★ **改 JSON 前先做「原样往返自检」** ⇒ 登记册只允许**纯增量**的 diff（★ 本轮 diff = +7 行，零重排）
