## §4 ★ R2：写侧唯一的结构门对「拼接式 DML」失明（本轮最大的仓内改动）

### §4.1 缺陷

`internal/partguard` 是仓内**唯一**的写侧结构门（红线：「更新 / 删除只能在 hot 表」）。它的判据是**只扫字符串字面量**且要求表名紧跟 `UPDATE`：

```go
{"UPDATE", regexp.MustCompile(`(?i)UPDATE\s+(?:ONLY\s+)?(?:public\.)?([a-z_][a-z0-9_]*)`)},
```

⇒ 下面四种写法里的表名它**一个都看不见**：

```go
`UPDATE ` + tbl + ` SET …`                 // Go 字符串拼接
fmt.Sprintf("UPDATE %s SET …", tbl)         // 占位符
`DELETE FROM ` + tbl + ` WHERE …`
`TRUNCATE ` + tbl
```

### §4.2 ★★ 门头与门的能力，长期不一致

`scan.go` 的门头注释自 R78 起就写着：

> 这条红线**当前已经被 3 条生产路径违反** … `bg/partition_manager.go` 对分区父表 `stats_event_inbox` 直接 DELETE …

★ 而 `bg/partition_manager.go` 的那条 DELETE 是 `deleteTerminalRowsBatched(ctx, table, …)` —— **表名是形参** ⇒ **门看不见** ⇒ **登记簿里根本没有这一条** ⇒ **门一直是绿的**。
⇒ 也就是说：**注释是事实源，而门与注释不一致这件事没有任何机制会发现** —— 直到今天把门补上。

### §4.3 改造：三层归属（精确优先，窗口兜底）

新增 `internal/partguard/dynamic.go`：

| 层 | 判据 | 性质 | 覆盖 |
|---|---|---|---|
| **Tier 0** | `for … x := range []string{…}` 的**字面量**表名集合 | **精确** | turn_writer / session_aggregator / abandoned_turn / final_success_turn / test_helpers / minute_flush |
| **Tier 1** | 「表名由函数形参给」时，**同文件调用点的字面量实参** | **精确** | partition_manager（`stats_event_inbox`）、session_digest_backfill（`session_turns`） |
| **Tier A** | 同文件邻近 ±20 行字面量 | **保守超集**（仅在 0/1 层完全解析不出时兜底） | 兜底 |

★ 手法照仓内既有先例（`domains/session/v2/session_turns_dead_column_test.go` 已实现「拼接还原 + 占位符 + 邻近归属」三件套），不另创一套。

★ **三个设计要点，每一条都是被变异臂/实测逼出来的**：

1. **「解析成功且集合里没有父表」≠「解析不出来」** —— Tier A **不得**覆盖已判定的层。
   ★ M2 臂实测抓到：把 `{hot, parent}` 改成 `{hot}` 后，Tier A 仍从邻近注释里捞到 `session_turns` ⇒ 门照样绿 ⇒ **门对「把父表目标删掉」完全失明**。
2. **作用域跟着词法走** —— Tier 0 的标识符映射必须**按函数**建，不能按文件：`bg/partition_manager.go` 两个函数都叫 `table`（一个是 minute 表遍历变量，一个是 `stats_event_inbox` 的形参）⇒ 文件级映射会把两者混为一谈并**丢掉**真正的父表归属。
3. **保守归属会误伤** —— 纯窗口形态会把**注释里**提到的表名算进来（第一版把 `candidate_failure_logs` 误归属给 `deleteTerminalRowsBatched`）⇒ Tier 1 精确解析后该误报消失。

## §5 ★ R1：热路径 turn INSERT 的幂等检查去视图反连接

### §5.1 现状与代价

`domains/session/v2/turn_writer.go:599-604` 的热路径 INSERT 幂等检查：

```sql
WHERE NOT EXISTS (
    SELECT 1
    FROM public.session_turns_with_current_month
    WHERE tenant_id = $3::varchar AND request_id = $4
)
```

★ 该视图的 **hot 臂带一个相关反连接**（757 迁移；生产 `pg_get_viewdef` 逐字一致）：

```sql
FROM session_turns_hot hot
 WHERE NOT (EXISTS (SELECT 1 FROM session_turns archived
                    WHERE archived.tenant_id::text = hot.tenant_id::text
                      AND archived.request_id = hot.request_id))
UNION ALL … FROM session_turns;
```

### §5.2 252 生产规模实测（只读）

| 形态 | Planning | Execution | 计划结构 |
|---|---|---|---|
| 视图形态（现状） | **5.8 ~ 93 ms**（中位 ~67 ms） | 1.269 ms | `Nested Loop Anti Join` + **12** 处分区引用（反连接 6 + 父表臂 6） |
| 两臂直查（拟议） | **3.8 ~ 16 ms**（中位 ~4 ms） | 0.252 ms | 无反连接 + **6** 处分区引用 |

- ★ 读数是**区间**：机器有负载（load 49~69）⇒ 方差大 ⇒ 结论以「**系统性更高** + **结构差异**」表述，不写单点值。
- ★ **写路径每请求都重新规划**（`db/db.go:73` 的 `QueryExecModeSimpleProtocol` ⇒ 无计划缓存）⇒ 这是**每请求**成本，不是一次性成本。
- ★ 附带发现：父表 6 个分区里有 **4 个走 `Seq Scan`**（`Filter: ((tenant_id)::text = …)`）—— 唯一索引 `(tenant_id, request_id, partition_date)` **存在**但被 `::text` 转型挡住 ⇒ 这 4 个分区（空/小分区）代价低，但形态上是「有索引用不上」。
- ★ 在 **INSERT 上下文**里（`EXPLAIN` 不带 `ANALYZE` ⇒ 只规划不执行 ⇒ 仍是只读）对比：视图形态 28 行计划、两臂形态 21 行。

### §5.3 等价性（两个方向都走）

```
视图对键 K 的行集 = {hot 行 | K，且父表无 K} ∪ {父表行 | K}
两臂对键 K 的行集 = {hot 行 | K} ∪ {父表行 | K}
```

- ⇒ 视图行集 ⊆ 两臂行集；
- ⇒ 反证：若两臂有 K 而视图没有 ⇒ K 只能来自某个 hot 行 ⇒ 该 hot 行被反连接剔除 ⇒ **父表必有同键行** ⇒ 视图的父表臂会产出它 ⇒ 矛盾；
- ⇒ 两者对「K 是否存在」的答案**恒等** ⇒ 幂等检查口径不变。
- ★ 视图是 `security_invoker`（757）⇒ 视图与直读底表都在**调用者权限 / RLS** 下执行 ⇒ 可见行集一致 ⇒ 等价性**不受角色影响**。

### §5.4 对拍

- **252 生产（只读，50 个真实键）**：`disagreements=0 / only_view=0 / only_narrow=0`。
- **本地真库（111 个键，含只存在于父表的已晋级行）**：两边都说存在 111 / 0 / 0 ⇒ 通过。
- **真库写路径端到端**：`TestTurnWriterHostTagsRealDB`（用真实 writer 写入 + 读回 101 个位置参数）PASS ⇒ **改后的 SQL 真的可执行**。

- **落法**：新增**叶子包** `internal/sessionfamily`（`ExistsByKeySQL`），写路径改用它。
  ★★ **为什么不在 `db` 包**（原本的直觉落点）：`db` 的**测试**文件 import 了 `domains/hooks/observability/telemetry` ⇒ telemetry → dbdegradation → session → **session/v2** ⇒ 若 session/v2 再 import `db` ⇒ **测试期 import 环**（`go test ./db/` 直接报 `import cycle not allowed in test`）。⇒ 这类「写路径要用的族形片段」放叶子包，谁都能 import 且无环（与 `internal/internaltraffic` 的分层同款）。

## §7 自伤自愈：变异脚本把源文件截成 0 字节

- 现象：R1 变异脚本 A1 臂报 `AssertionError: A1 锚点缺失`，而 `turn_writer.go` 变成 **0 字节**。
- 真因：Python 的 `open(path, "w").write(inject(path))` —— **`open(..., "w")` 先截断**，`inject(path)` 才去读原文件 ⇒ 读到空 ⇒ 断言炸掉时文件已被清空。
- ★ 修法（按仓内纪律「**发现已落盘的损害 ⇒ 第一动作是回滚 + 确定性重放**，不是手工插回」）：
  1. `git checkout HEAD -- domains/session/v2/turn_writer.go`；
  2. 用**脚本**重放改动（import + `NOT EXISTS` 替换），保证与原改动逐字一致；
  3. `go build` + 守卫 + 变异臂复跑 ⇒ 全绿。
- ★ 脚本侧修法：**先算出内容，再打开文件**（`mutated = inject(path)` 前置于 `open(path,"w")`）。
- ★ 附带的同类坑：`str.replace` 默认改**第一个**匹配 ⇒ 锚点必须**带上下文且唯一**。
