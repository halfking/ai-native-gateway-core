## 四、量具坑（本轮新增）

1. **纯语句体行没有 PG 时间戳与 pid**：podman 前缀行分两种——`STATEMENT:`/`DETAIL:`
   头带 `PG时间戳 CST [pid]`，其后**语句体行只有 podman 前缀 + 原文**。按 pid 配对
   语句体会全部落空（本轮第一版提取器空手而归的原因）；正确规则=「遇到
   level 行（ERROR/LOG/STATEMENT/…）即条目边界，其余前缀行皆为体」。
2. **单行语句的文本在 duration 行本体上**：`execute S_N: SELECT ...` 形态（pgx
   预处理语句）的全文跟在 duration 行内，续行扫描永远看不到——家族指纹要在
   duration 行和续行两处找（B/D 两族第一轮漏计的原因）。
3. **并发执行的同文本语句体行逐行交错**（batch 8 worker 场景）：多行语句的
   提取必须容忍交错、以源码重建 SQL 为权威做 EXPLAIN（本轮 matched 族两次
   采样都被污染，最终用 throwaway Go test 打印 `candidateQuerySQL()` 内联参数）。
4. **`LOG:` 后是两个空格**：`\s?` 只吃一个，rest 带前导空格导致 `^duration:` 全落空
   （census 第一版慢查 0 条的原因）。
5. ssh 内联 heredoc 的 sed 转义不可靠（`\s?` 改写两次失败），跨机改脚本用
   python patch 或本地改完 scp。
