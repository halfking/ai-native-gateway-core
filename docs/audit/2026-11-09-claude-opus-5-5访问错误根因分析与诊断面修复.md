# 2026-11-09 claude-opus-5-5 访问错误：根因分析与诊断面修复

> 用户报告：通过 llm.itestu.cn 访问 claude-opus-5-5 总是错误，要求查 211 log、
> 判断是否请求数据转换错误或 token 桶状态错误，修复并部署验证。
> 本档记录最终核实的结论；此前几轮会话中的混乱结论（模型不存在 / 缺少绑定 /
> mock 补绑定等）全部被本轮真库证据推翻，见 §5 复盘。

## 1. 最终根因（真库 + 活体实验双重证据）

**不是请求数据转换错误，不是 token 桶状态错误，也不是路由配置错误。**

三层事实：

### 1.1 路由本身是通的
- 生产库 acc-pg17/llm_gateway：canonical `claude-opus-5-5`（id=3058962，active）
  有 3 个健康 apiclaude 节点（cred 31 `130dao-cache`、59 `nocahce-1x`、99036
  `calude-new-1x`，全部 ready/ok/closed）。
- 活体验证：小请求 / 90KB / 151KB / 302KB（重复内容）全部 200 成功。

### 1.2 失败定位在 apiclaude.cc 中继对「大体积 + 高熵」载荷的处理
| 上游载荷 | 结果 |
|---|---|
| 102B / 16.8KB / 90KB | 200 全量成功 |
| 171KB 唯一随机 ASCII（~49K token） | 200 接受 → 流中断（anthropic_empty_response，1 chunk） |
| 255KB / 273KB（含工具调用形态） | 同上流中断 |
| 302KB 重复 CJK（~10 万 token） | 200 全量成功（可缓存内容不受影响） |
| 用户真实会话 171,803B（11:05） | **1.3s 秒拒 400**（request_rejected） |

同网关给 minimax 发 893KB 正常 ⇒ 网关无大体量缺陷；瓶颈在 apiclaude 中继
（阈值介于 90KB 成功与 171KB 失败之间，且对不可缓存的唯一内容更糟）。

### 1.3 候选池只有 apiclaude 一家 ⇒ 无处 failover
用户「明明有多个节点」的其余节点全部被正当门控：
- evol（cred 10，绑定健康）：**provider manual_disabled=true（2026-07-26 手动禁用）**
- 速云U站 claude 系 key（38/39/71）：auth_failed（key 失效，需 owner 换 key）
- vapeur（cred 63）/ magpie（99025/99027/99031/99032）：suspended + 配额耗尽
- freellm 的 opus-5-5 族绑定到**另外的 canonical**（3433419 等），不参与本模型路由
