## §二、慢 SQL（>1s，1,879 条）

- **cancel 风暴 1,491（上轮 7.3 倍）逐条归因**：Top 受害=探针会话族——MAX(turn_no) ×607、session_turns advisory lock（sys:probe:credNN）×306、session_turns_hot INSERT ×55、bodies upsert ×22……探针请求在 per-session 串行锁上排队，顶部小时批（05:00/05:40/06:00 三次 ×4 击杀簇）拉长尾延迟 → 探针客户端 ctx 短熔断级联 cancel。**定性维持 R46：应用侧行为非 PG 故障**，但本轮实证其规模随负载尖峰放大 7 倍且与 DSM 失败（F3）同源放大——登记 §四 D2'。
- **30s 临界族新增击杀证据**（D2 族从"慢"升级为"开始死"）：bindings 候选（med 22.4s max 28.5s，击杀 ×7）、小时级 rollup（usage_facts dedup / fingerprint / session_key stats 各 ×4，整点簇发）、agg_src hot-only 版 max 29.96s 贴线。
- promote_request_logs max 58.8s 贴 60s SET LOCAL 预算（窗口 1 次击杀=预算语义正确生效，批 5000 行在当前负载下偏大——登记调优项）。
- REFRESH analytics_7d：完成 10 次 med 45.3s max 175s（pss max 178.9s）——180s pin 双刃：救活长刷新但也让 F5 的叠跑饿死可见。summary_7d med 3.7s 正常。
- 探针 MAX(turn_no) 本身 med 1.27s：2026_09 分区走复合索引、**旧分区臂 planner 误选 effective_session（tenant 前缀扫）**（复合索引各分区都在且 valid，EXPLAIN 实锤选错索引）——单条不致命，但探针高频 × 并行 Append 孵化 = DSM 压力主源。优化空间登记 D2'。
