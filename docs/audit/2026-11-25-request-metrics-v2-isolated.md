# 请求统计 V2 隔离验收

工作分支为 `codex/request-metrics-v2`，已对齐主干 `29727b3ba`。以下 PostgreSQL 实测基于 `29b3dfbd5` 上的同一投影代码和迁移字节。实验使用 PostgreSQL 17.10 夹具和从同源快照恢复的无网络 211 副本。生产切换需要单独确认。

## 投影与迁移

- 采用排序在 983/983b/983c 之后的 `983d_request_metrics_projection`。在自动枚举顺序中执行 preview 的 973，PostgreSQL 因 `public.request_metrics` 尚未创建而退出。211 原始两本台账没有 973、983d 或 988b 投递记录。
- 旧槽按旧表的全局最大 `(occurred_at, request_id)` 取水位。夹具在水位前插入一个晚到事实，同时修订水位上的事实，旧查询只读到下一条请求。按两候选的保留键写入新版行后，旧查询把新版行当成了旧水位。V2 因此使用独立的 `public.request_metrics_projection`，以 `(tenant_id, request_id, occurred_at)` 为主键，保留 983 的实际读写和回退路径。
- 回填按 `(fact_id, occurred_at)` 分批。持久队列记录事实变更及上下文、热会话维度变更。每次以事实版本、终态时间、事实 ID 确定胜出行。发布、队列确认及回填水位同事务提交，两槽用同一行锁仲裁。维度按同租户、同请求 ID 和距离请求时间最近的记录匹配，时间上限为 24 小时。此补数覆盖 `request_context_attrs` 和 `session_turns_hot` 的写入。
- 旧上下文表仍以请求 ID 为唯一键。跨租户同号的终态事实在 V2 中独立投影。历史维度来源如果已发生同号覆盖，单凭现存上下文无法恢复原归属，需核对来源覆盖。
- 上游 925、985–988 与两候选的历史字节不同。211 快照的指纹逐条匹配当前主干。旧候选 988b 的台账回填因此没有进入新投影迁移。

自然日按页面所用时区换算时间戳，查询窗口为 `[start,end)`。请求成功率保留成功条数和全部请求数，缓存请求率保留命中请求数和全部请求数，缓存 Token 率保留已知计量口径下的输入和命中 Token。成本只在相同原币计量内相加，通用统计可按币种列出原币金额及覆盖请求数。积分单独累计。运维端点可指定时间窗核对投影的最新版覆盖、供应商覆盖、会话关联覆盖、实测 Token 和币种覆盖。

## 验证记录

- 211 样本窗为北京时间 11 月 23 日关账日和 24 日对照日。迁移前两本台账摘要和采集时一致。运行真实部署迁移序列后，两本台账分别由 169 到 170 行、375 到 376 行。原有行逐字段对拍完全一致，925 和 985–988 均按已投递跳过且产物探针通过。第二次运行按指纹跳过 983d，对象与台账探针通过。
- 另一份同源恢复库走安装器。主干安装器先在 520 复现既有同义策略重名。候选接入已验证的历史安装器适配 `9c618fd6c`，保留原策略及晋升定义，避免重写历史 SQL。修复后安装器应用 983d，原有 169 条逻辑记录和 375 条投递记录逐字段不变。全新安装、第二次安装、部署接管及复跑烟测通过，接管时认领 373 条安装器凭证。
- PostgreSQL 夹具覆盖历史回填、跨租户同号、半开窗边界、迟到、追加版本、原地修订、晚到维度、64 位 Token、发布异常与重启、两槽锁竞争和两次回退 SQL。旧槽写入和旧水位读数单独断言。
- 合成延迟采样按一分钟默认轮询，120 条事实含 60 条突发。以首次观察到全部投影可见为上界，P95 为 60.15 秒。采样环境的结果用于验证链路，目标容量仍由实际负载验收。
- 日对账真实 PostgreSQL 夹具通过。WAL 在收件日归档，跨日终态按较新证据返回。旧报表、内部扣费、逐次发送、平台运维和供应商账单分别核对，同一报表的供应商账单使用外层事务的时间戳。
- 同源快照保有 WAL、终态事实和上下文。供应商逐次发送、账单及明细、合同费率、内部扣费和冲正证据为空，尚无法核对同一天的真实闭账金额。
- 两槽同时写入、失败重启和回退已由 PostgreSQL 夹具覆盖，流恢复的定向 Go 用例通过。完整的旧槽到新槽长流切换仍待隔离演练。

### 读性能与日汇总

211 副本回填 68,469 条事实，连续清空批次耗时 3 分 34 秒。1 日窗最新版覆盖 29,568 / 29,568，7 日及更长窗口覆盖 68,469 / 68,469。长窗共享相同样本，因为快照数据只有两个自然日。7 日窗会话关联 68,437 条，含供应商 32,466 条，实测或订正 Token 26,349 条，有币种证据 0 条。每个查询执行 20 次。

### 看板读路径复测

在相同的 90 日合成库上对拍本轮改动和 `bcb216dad`。通用汇总将模型与会话去重单独分组，其他度量可执行并行聚合。看板用分组集生成各维度分布，在按时段聚合前确定全窗前六个模型。通用汇总和完整看板的 Go JSON 逐字节匹配，长度分别为 1,103 字节和 2,201,204 字节。PostgreSQL 专项夹具覆盖了前六名并列、跨时段排名及其他模型桶的请求、Token、积分和金额。

| 90 日执行计划，默认 PostgreSQL 设置 | 基线 | 本轮 |
| --- | ---: | ---: |
| 通用汇总 | 2.744 s | 864 ms |
| 完整看板 | 7.488 s | 4.208 s |

同库按原负载夹具复测，每窗每读路径五次，最近名次 P95 为该组最大值。日历史 SQL 沿用基线，以下日历史读数仅记录本轮运行，不用于归因。尝试将历史报表的两个分位数合并排序，在服务使用的 JIT 关闭设置下用时由 7.527 秒升至 8.814 秒，完整 JSON 校验也有差异，已撤回该实验。

90 日历史的原响应约 45.7 MB。长窗完整读取仍超过 100 毫秒。较小的响应与可重算汇总分别影响传输时长和数据库执行时长，需要各自验收。

会话去重也在合成库上验证了按日压缩成员集合。以 `(tenant_id, session_id)` 分配唯一整数，日内每 64 个连续编号用一个位掩码保存，跨天按掩码编号做按位或后计位。476,040 条原始会话关联请求合成 92,966 个日掩码，90 日去重为 123,505 个会话。加入跨日、跨租户同号的迟到请求后为 123,507，将其中一个租户的最后两条请求修订到另一租户并重算受影响日后为 123,506，三次均与明细精确计数一致。单次执行对拍为原始复合键去重 1.678 秒、日掩码合并 13.6 毫秒，计时不含构建。SQL 使用临时表，尚未接入定时重算和报表读取。复跑见 `docs/audit/evidence/2026-11-25-request-metrics-v2-daily-memberships.sql`。

### 两槽长流与回退演练

从已通过迁移与追平验证的 211 隔离恢复库再复制演练库。旧槽使用主干 `29727b3ba`，新槽使用包含本轮查询改动的候选 `1e23979dd`，两者均是 Linux arm64 网关二进制。两个槽使用同一份演练库，由无外网容器内的本地反向代理切换，使用合成 key 和本地 OpenAI SSE 上游。此次照此验证网关行为，线上 Nginx 和 systemd 部署路径未运行。

旧槽在 53881 接住长流后，入口在北京时间 22:29:00 切至 53883。新槽就绪并完成一笔独立请求，随后向旧槽发送 SIGTERM。旧连接在 22:29:15 收到全部 16 个内容帧和一次 `[DONE]`。旧槽重新启动并通过就绪检查，22:29:33 将入口切回，回退请求返回 HTTP 200、一帧内容及一次 `[DONE]`。
