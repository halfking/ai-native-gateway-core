# 请求、会话统计与内外对账

**审计基线** `99149eb32`，2026-11-23。本文的现状结论来自当前代码、迁移和既有取证，未复跑生产查询，也未取得供应商账单。报表帮助本轮已更新。以下账本改造、历史回填和切换为实施规划。

## 一、审计结论

1. **当前日快照的供应商视角不能核定应付。** `usage_facts` 的写入入口只接受成功、失败、限流等网关终态，一次请求产生一个事实，事件 ID 中 attempt 固定为 0。它能回答网关记录了多少终态请求，重试、竞速和直连探测还需要逐次调用事实。请求被拒且未发上游的终态也可能出现在日快照供应商视角。 [终态映射](../../domains/stats/event.go#L107) · [落库](../../domains/stats/inbox_consumer.go#L506) · [日快照](../../domains/reportrollup/grain.go#L84)
2. **已有价格测算与月账单比对，缺少逐次费用证据。** 主流程按最终候选的价格和用量填 `CostUSD`。供应商月对账从热冷并读的 usage ledger 按 request ID 取最新记录，支持手工导入月账单。当前审计路径没有发现逐次保存供应商返回金额、同次价格快照和账单明细匹配的闭环。原始响应、观测日志和供应商月汇总可用于补证，覆盖率要分别验证。 [网关计价](../../domains/streaming/handler.go#L7785) · [测算入口](../../domains/streaming/usage.go#L530) · [月账单接口](../../admin/provider_cost_reconciliation.go#L51) · [月汇总查询](../../domains/providerprofile/pg_reconciliation_store.go#L284)
3. **上游发送已存在日志钩子，需补持久化事实。** 执行器在 transport 前记录 attempt 及供应商、凭据，故这一步只能证明准备发送。记录受供应商确认的调用、已发未获响应及提交状态不明的调用时，需要区分证据。后台直接 GET/POST 探测和定时配额任务使用独立链路，`node_probe_runs` 记录尝试结果，不能据此推算完整用量或金额。 [发送前动作](../../domains/streaming/executors/executor.go#L1136) · [HTTP 发送](../../domains/streaming/executors/executor_chat.go#L1492) · [独立探测 HTTP](../../bg/probe_http.go#L86) · [探测审计写入](../../bg/probe_service.go#L1291) · [周期配额探测](../../bg/periodic_quota_probe.go#L34)
4. **内部需以计费过账核对。** 主链按计费策略计算并请求扣费，成功后把实扣写到请求日志。部分读取用估算填补缺失，部分用零。现有 MaaS 三方核对提供扣费、小时用量和月账单的起点。现有报表快照用 `usage_facts.credits_charged` 乘报表快照换算价，需与实际扣费、冲正、调整和适用价格区分。 [请求扣费](../../domains/streaming/handler.go#L7810) · [积分估算回落](../../maas/credits_sql.go#L4) · [内部三方核对](../../maas/reconcile.go#L25) · [内部日快照](../../domains/reportrollup/grain.go#L142)
5. **会话统计存在不同窗口、分类和聚合单位。** 看板主卡与分钟趋势读面不同。会话面板按首请求入窗后汇总整个会话，跨窗活跃会话可能被漏掉，入选会话的窗口外流水也可能纳入。会话的探测识别还依赖归属、客户端和标题等规则。既有记录显示业务流量可能误剔除，同会话多天记录曾放大 JOIN。发布前须在目标版本分别复证。会话分析用 `internal_cost` 表示美元成本、`external_cost` 表示积分，历史模型维度还存在固定零。排行旧接口的 `total_cost` 把两个数值直接相加，统一口径要求按指定单位排序并单列。 [会话主聚合](../../admin/dashboardapi/session_overview.go#L439) · [会话探测范围](../../domains/analytics/session_probe_scope.go) · [排行查询](../../admin/session_analytics/queries.go) · [历史切片 SQL](../../sql/migrations/startup/981_session_analytics_foundation.sql#L180) · [994 后续变更](../../sql/migrations/startup/994_session_analytics_owner_key_and_close_path.sql) · [看板与会话取证](2026-11-23-看板与会话统计数据一致性取证与统计标准落地-主档.md) · [既有窗口修复方案](2026-11-23-会话统计口径修复方案.md)
6. **金额、缓存分母、缺数也会产生假差异。** 报表日 grain 用 `SUM(cost_amount)` 与 `MAX(cost_currency)`，没有按币种分组，存在混币数据时无法据此核账。日报快照的读面仍把输入、输出、缓存读和缓存写四项相加作为总 Token，缓存率使用缓存读 ÷（输入＋缓存读）。终态事实总 Token 是输入＋输出，部分会话视图另外统计命中请求数。输入是否已包含缓存取决于协议和字段。统计事实的部分列受零默认和写入映射影响，历史零值需要重新核对覆盖率。分组后取整的分差有既有取证。 [快照聚合](../../domains/reportrollup/grain.go#L115) · [快照总 Token 与缓存率](../../domains/reportrollup/grainreport.go#L585) · [终态总 Token](../../domains/stats/event.go#L163) · [报表设计](../reconciliation/design-report-rollup.md) · [对账复审](2026-11-17-对账模块统计口径复审-主档.md)

## 三、统一计算标准

常规报表使用显式 `[start,end)`，UTC 存储、所选 IANA 时区切日，返回实际区间、时区、数据水位、口径版本、租户权限范围和分子分母。客户端量按网关接收时间归窗，实际发送按发送时间归窗。入账时间和供应商账单周期独立保存。已经有固定 UTC 或上海物化日桶的报表继续按其固定口径标注，升级后通过显式参数对齐；月结按合同账期和账期时区。

| 指标 | 目标算法与边界 |
| --- | --- |
| 客户端总请求、已完成、进行中 | 总量按 `(tenant_id, request_id)` 去重。终态按成功、失败、限流、已终止取消互斥分类，进行中单列。未进入可信入站记录的量报告覆盖缺口。重试、换模和竞速只增加出站调用。 |
| 供应商发送数与状态 | 按不可变 `attempt_id` 去重，区分准备发送、证实发送、提交状态未知。实际送出的重试、竞速、平台任务全部计算。DNS/本地拒绝等已确认未发的调用在诊断漏斗单列。响应前取消或断线存在被供应商计费的可能，证据不足进入待核对。 |
| 活跃、新建、关闭会话、轮次 | 活跃是窗口中有客户端请求的规范会话去重，新建及关闭按首次请求和生命周期结束事件归窗。页面上的最近 24 小时活跃等独立指标标明窗口。无会话请求进未归属桶。轮次为镜像实体计数，冷热重叠或异步缺口单列。按天活跃会话不可相加为月活。 |
| 成功率、失败率及错误分类 | 成功率＝成功终态 ÷ 全部终态。失败、限流、取消按约定各有分项，合计与终态平衡。客户端和供应商分别计算；供应商成功以协议级结果及流终止状态判定。分母为零显示无数据。 |
| 输入、输出、总 Token | 归一化输入为完整输入，按协议把独立上报的缓存分量并入一次，子集保持原样。归一化输出包括已被协议计入的细分，另报缓存/推理/多模态分项。总量＝输入＋输出。供应商原始字段和供应商声明总量独立保存。估算值与上报值分开统计。 |
| 缓存读、写和命中率 | 分别求和。Token 命中率＝可比记录的缓存读合计 ÷ 同批记录的完整输入合计。请求命中率＝缓存读大于零的请求数 ÷ 同批有可比缓存统计的请求数。有效零计分母，未知或不支持单列。分子超出输入需标异常并保留原样。跨桶重算比率。 |
| 延迟、TTFT、P50/P95、健康和质量 | 延迟以声明时间点计算，平均保留样本数和合计，TTFT 限可观测流。分位数以原始时延或可合并分布重算。健康、质量、并发、压缩节省、风险和配置活跃量应在页内注明样本和独立分母，均与用量和扣费区分。 |
| 供应商测算成本 | 各调用按独立计费量×生效成本单价（含读写缓存、阶梯费率、每次费或其他合同单位）÷价格单位，并记录费率版本、价格证据、币种、精度和分项。计划价、估算价和缺价有独立状态。保留定点精度，按账单规则在界定层级舍入。 |
| 供应商返回金额 | 原始金额、币种、字段语义和来源证据。区分供应商返回的目录原价、结算价及未知语义。响应无金额保留 NULL，供应商账单金额、折扣、固定费、税、赠额和冲正分开对拍，由账单确认最终应付。 |
| 内部积分、内部金额 | 已过账消费、冲正及调整净额按租户、用户、应用、客户端分组，预扣和待入账单列。实际记账金额以按内部价格和规则写入的过账为准；只有积分时可展示冻结倍率折算的参考金额并标注。收款、充值和额度分配与消费单独统计。 |
| 金额差异与覆盖 | 比较量、币种、结算主体、账期和分摊范围须相同。输出测算与返回的差、测算与账单的差、未匹配账单与待证实发送。内部收入和供应商成本只在共同比较范围和相同结算币种下计算差额，跨币使用可审计的汇率和日期。 |

## 四、两条账与平台客户端

### 逐次上游调用和供应商账单

- 每次准备调用时生成 `attempt_id`，固定租户/平台归属、父请求或作业、模型、供应商账户、凭据代理 ID、尝试序号和路径。实际 transport 发出信号、响应、响应 ID、用量或异常以同键入 durable outbox。DNS/TLS 失败与已提交断线分别标识，无法确定提交状态时进入挂账。确保流式终帧、用量迟到、重启、队列重放、并行重试均可重建，不重新发供应商调用。
- 规范事实保留 token 原值和归一化用量，记完成状态、 usage 来源、费率/币种快照、测算金额及供应商返回金额。每一条费用证据支持审计版本，同一 attempt 只选一条有效版本供汇总。持久证据只存必要字段及受控引用。
- 复用 provider 月对账界面和导入骨架。将账单导入规范化为账户、币种、周期、单号、行号及调整类型。优先按供应商请求 ID 精确匹配，其次按供应商账户、模型、桶和计费项目对拍，模糊匹配只给候选。账单级固定项单列，重传同单不重算，差异需能回到来源和处理状态。

### 客户端入站请求和内部账

- 独立保留入站时点、唯一 request ID 及终态事件，沿用既有请求日志/WAL 但实证早拒、限流、取消、无会话、探测/内部回环是否覆盖，缺口从实际入口补齐。终态按租户+请求去重。扣费按同一请求幂等入账，不跟随尝试数增殖。
- 对齐额度桶、过账流水和月账单。先核请求级实际扣费及冲正，再校验按租户、用户、应用、客户端展开的净额。无扣费政策、网关拒绝、免单、待扣费、扣费失败及缺失必须能区分。
- 建立网关可信发起方分配的 **平台自动化运维客户端**，用稳定的系统标识，子类保留 health/probe、self-check、admin-test 和计划运维等。业务发起的模型调用继续继承真实客户端。混合工作流逐次保留父请求与发起者。未知流量单列待查，客户端传入的标题、User-Agent 或任意普通请求头不能取得平台身份。平台客户端计入平台用量和供应商账，在内部按平台成本中心列示且租户扣费为零。供应商账本应能按业务归属、平台归属、未归属三桶完整拆分，单独列出无调用的客户端请求及多调用请求。
- 一笔请求可以关联多次出站调用和多笔过账。请求级报表先按租户与请求聚合两条明细，再联结会话维度。供应商明细按 attempt 展开，过账明细按交易 ID 展开。账单匹配表单独保存匹配证据与分摊。只记录每种事实自身的金额，避免退款乘上重试数或账单固定费乘上请求数。

批次核对先锁定同一范围与账期。供应商发送数按业务、平台和未归属之和对拍。费用分别披露可测算金额、已返回金额、已匹配账单金额、账单独立调整及各自覆盖量。对账差额只在计量范围重合的行上计算，未知发送和缺价进入待核对明细。内部账从过账净额出发，匹配已出账汇总、未出账流水及调整，差额按迟到、冲正和待处理逐项解释。计数与 Token 使用整数对拍，金额容差按供应商合同的最小计费单位和舍入层级核定。

## 五、实施顺序与验收

| 阶段 | 交付与先后关系 | 可判定验收 |
| --- | --- | --- |
| 0 契约与基线 | A 盘点 transport/自动化，B 盘点入站/会话/计费，C 盘点报表、时区和访问。可并行做静态预检。集成负责人收敛字段、键、状态、价格规则与历史覆盖，锁定一组共同样例，再开始三线编码。 | 各入口标出记录点、覆盖、未知和最小补点；现有旧链输出与新标准映射完整。 |
| 1A 出站账 | 在流式/非流式执行器和运维 direct transport 接入逐次发送事实及价格、响应证据。数据库新增迁移由负责人协调。 | 单请求 A 失败/B 成功、竞速两条、断流和提前拒绝验证分开计数；重试重放不增加同一 attempt；运维不漏；显式零、NULL、计价单位覆盖。 |
| 1B 入站和内部账 | 补入口覆盖，联结会话维度、积分过账、冲正。应用唯一平台客户端及可信分类。与 A 约定请求桥和分类生命周期。 | 跨租户同名、跨日、无会话、冷热晋升、早拒、取消、延迟用量和 replay fixture；账单/汇总与流水按已定义的交易类型平衡。 |
| 1C 查询/UI 准备 | 按冻结的契约用 fixture 实现查询和导出字段，对照桌面帮助，补移动端入口和权限测试。A/B 完成后接入真实读面，保留清楚的旧值兼容和版本提示。 | 同窗口同范围下明细＝汇总＝导出；报表分段、币种筛选、缺失/延迟提示和隔离权限均可验证。 |
| 2 合并、迁移与影子 | 负责人合并 A/B/C，分配新迁移号并投递安装/增量双通道，保持已应用旧迁移字节。跑隔离空库新装及有历史和漂移的升级夹具。影子双写核对、分批按证据回填并公开覆盖起点。 | 新装与升级绿，分区提升/迟到 replay 不重复，核账可解释差或挂账。旧账在周期锁定后只走冲正或调整。 |
| 3 上线与账期复核 | 先影子再按权限切换报表查询；覆盖一个已关闭周期和一个开放周期。切换前由账务和系统负责人确认实际币种、账期、舍入、完整性阈值及差异处置。 | 幂等、缺失和匹配水位可观察；账单证据与应付对上、内部扣费与总账对上。回滚读面可切回旧版，已经记账的事实留存。 |

**最小验收样例**。一个业务请求两次调用，第一笔 HTTP 失败但产生 10 个输入 Token，第二笔流式成功，完整输入 100（缓存读 40）、输出 20。另有一个网关限流未出站请求，以及平台探测一个独立上游调用。预期客户端业务请求 2、业务成功率 1/2、业务上游发送 2、平台上游发送 1；按业务终态用量合计成功请求 120 Token，限流零上游用量。若失败尝试的 10 为经供应商确认，则出站业务输入合计 110，缓存率按有可比记录的分母计算。第二笔供应商测算 0.012 USD、返回 0.015 USD、内部扣费 12 积分应分别可查。属于前一日创建会话的成功请求仍计入今日窗口，今天的活跃会话计 1、新会话计 0。变体覆盖计价单位/币种、缓存写、多模态、未知送达、无计费率、重复账单、冲正、跨时区边界和平台身份冒用。

从仓库根目录运行 `bash docs/handoff/launch-request-session-reconciliation.sh --handoff` 可重新生成交接。用 `--preflight` 启动三条并行只读核对，启动实施协调会话用 `--implement`。模型默认 `gpt-6-luna`，可通过 `RECONCILIATION_CODEX_MODEL` 使用当前环境支持的低成本模型。脚本以本地替身验证了三路分派和失败退出码。 [handoff 启动脚本](../handoff/launch-request-session-reconciliation.sh)

## 六、本轮实施契约

| 事实 | 键与归窗 | 证据和写入归属 |
| --- | --- | --- |
| 客户端请求 | `(tenant_id, request_id)`，按网关接收时间归窗。`request_id` 由网关生成。 | 入站组件维护 WAL 和终态遥测；复用终态事实的版本及缓存、会话维度。租户和会话关联必须同时匹配租户与对应 ID。缺终态、缺用量和无会话分别暴露。 |
| 供应商调用 | `attempt_id`，每个独立传输一键。确认送达的调用按 `sent_at` 归窗，未证实送达按准备时间进入待查。 | 执行器和已接入的直连任务只写自己的 attempt。包含已证实发送、发送状态未知、已准备和已证实未发送。供应商回应证明送达，流结束证据决定调用终态。 |
| 已过账消费 | `credit_ledger` 的 `(tenant_id, id)`，按 `created_at` 归窗；`ref_type='request'` 和 `ref_id` 关联请求。 | 计费事务写实际积分，多额度池可生成多笔。重放在整个扣费事务上去重。无冻结的记账币种价格时，内部货币金额保留缺失。 |
| 会话 | `(tenant_id, gw_session_id)`。活跃由窗口内请求推出，新建和关闭各用自己的时钟。 | 复用 `session_dim` 和已验证请求关联。一个跨日会话可以今天活跃、今天未新建。 |

费率测算与供应商返回金额各自可空，金额保留定点精度。估算分币种，返回分币种和来源语义。缺币种的返回金额有计数且不参与分币种求和。无合同费率、账单样本或可信历史证据时保持缺数。平台自动化客户端标识为 `platform-automation`，只从网关可信身份或平台任务入口设置。

迁移 `982` 创建逐次调用表，使用仓内未占用的三位编号，按投递顺序追加。已有迁移文件的字节沿用。启用 `LLM_GATEWAY_RECONCILIATION_SHADOW_ENABLED=true` 可在已迁移的环境启动影子采集。报告为独立读取入口，现有报表查询仍可用于对照。

统一查询入口 `GET /api/admin/usage/request-reconciliation`。`start`、`end` 为 RFC3339，`timezone` 为 IANA 时区。`section` 支持 `requests`、`attempts`、`postings`、`sessions`，按以上各自时钟读同一区间。`format=csv` 和 JSON 使用同样的排序、窗口及分页参数 `limit`、`offset`，汇总覆盖整个所选窗口。租户管理员仅能读取本租户的请求、会话和已过账消费。供应商逐次证据仅对平台管理员开放。`read_at` 标记本次数据库读点，不能用于推断历史已补齐。
