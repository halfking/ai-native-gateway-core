# 请求、会话统计与内外对账

**审计基线** `99149eb32`，2026-11-23。本文的现状结论来自当前代码、迁移和既有取证，未复跑生产查询，也未取得供应商账单。报表帮助本轮已更新。以下账本改造、历史回填和切换为实施规划。

## 一、审计结论

1. **当前日快照的供应商视角不能核定应付。** `usage_facts` 的写入入口只接受成功、失败、限流等网关终态，一次请求产生一个事实，事件 ID 中 attempt 固定为 0。它能回答网关记录了多少终态请求，重试、竞速和直连探测还需要逐次调用事实。请求被拒且未发上游的终态也可能出现在日快照供应商视角。 [终态映射](../../domains/stats/event.go#L107) · [落库](../../domains/stats/inbox_consumer.go#L506) · [日快照](../../domains/reportrollup/grain.go#L84)
2. **已有价格测算与月账单比对，缺少逐次费用证据。** 主流程按最终候选的价格和用量填 `CostUSD`。供应商月对账从热冷并读的 usage ledger 按 request ID 取最新记录，支持手工导入月账单。当前审计路径没有发现逐次保存供应商返回金额、同次价格快照和账单明细匹配的闭环。原始响应、观测日志和供应商月汇总可用于补证，覆盖率要分别验证。 [网关计价](../../domains/streaming/handler.go#L7785) · [测算入口](../../domains/streaming/usage.go#L530) · [月账单接口](../../admin/provider_cost_reconciliation.go#L51) · [月汇总查询](../../domains/providerprofile/pg_reconciliation_store.go#L284)
3. **上游发送已存在日志钩子，需补持久化事实。** 执行器在 transport 前记录 attempt 及供应商、凭据，故这一步只能证明准备发送。记录受供应商确认的调用、已发未获响应及提交状态不明的调用时，需要区分证据。后台直接 GET/POST 探测和定时配额任务使用独立链路，`node_probe_runs` 记录尝试结果，不能据此推算完整用量或金额。 [发送前动作](../../domains/streaming/executors/executor.go#L1136) · [HTTP 发送](../../domains/streaming/executors/executor_chat.go#L1492) · [独立探测 HTTP](../../bg/probe_http.go#L86) · [探测审计写入](../../bg/probe_service.go#L1291) · [周期配额探测](../../bg/periodic_quota_probe.go#L34)
4. **内部需以计费过账核对。** 主链按计费策略计算并请求扣费，成功后把实扣写到请求日志。部分读取用估算填补缺失，部分用零。现有 MaaS 三方核对提供扣费、小时用量和月账单的起点。现有报表快照用 `usage_facts.credits_charged` 乘报表快照换算价，需与实际扣费、冲正、调整和适用价格区分。 [请求扣费](../../domains/streaming/handler.go#L7810) · [积分估算回落](../../maas/credits_sql.go#L4) · [内部三方核对](../../maas/reconcile.go#L25) · [内部日快照](../../domains/reportrollup/grain.go#L142)
5. **会话统计存在不同窗口、分类和聚合单位。** 看板主卡与分钟趋势读面不同。会话面板按首请求入窗后汇总整个会话，跨窗活跃会话可能被漏掉，入选会话的窗口外流水也可能纳入。会话的探测识别还依赖归属、客户端和标题等规则。既有记录显示业务流量可能误剔除，同会话多天记录曾放大 JOIN。发布前须在目标版本分别复证。会话分析用 `internal_cost` 表示美元成本、`external_cost` 表示积分，历史模型维度还存在固定零。排行旧接口的 `total_cost` 把两个数值直接相加，统一口径要求按指定单位排序并单列。 [会话主聚合](../../admin/dashboardapi/session_overview.go#L439) · [会话探测范围](../../domains/analytics/session_probe_scope.go) · [排行查询](../../admin/session_analytics/queries.go) · [历史切片 SQL](../../sql/migrations/startup/981_session_analytics_foundation.sql#L180) · [994 后续变更](../../sql/migrations/startup/994_session_analytics_owner_key_and_close_path.sql) · [看板与会话取证](2026-11-23-看板与会话统计数据一致性取证与统计标准落地-主档.md) · [既有窗口修复方案](2026-11-23-会话统计口径修复方案.md)
6. **金额、缓存分母、缺数也会产生假差异。** 报表日 grain 用 `SUM(cost_amount)` 与 `MAX(cost_currency)`，没有按币种分组，存在混币数据时无法据此核账。日报快照的读面仍把输入、输出、缓存读和缓存写四项相加作为总 Token，缓存率使用缓存读 ÷（输入＋缓存读）。终态事实总 Token 是输入＋输出，部分会话视图另外统计命中请求数。输入是否已包含缓存取决于协议和字段。统计事实的部分列受零默认和写入映射影响，历史零值需要重新核对覆盖率。分组后取整的分差有既有取证。 [快照聚合](../../domains/reportrollup/grain.go#L115) · [快照总 Token 与缓存率](../../domains/reportrollup/grainreport.go#L585) · [终态总 Token](../../domains/stats/event.go#L163) · [报表设计](../reconciliation/design-report-rollup.md) · [对账复审](2026-11-17-对账模块统计口径复审-主档.md)

## 三、统一计算标准

常规报表使用显式 `[start,end)`，UTC 存储、所选 IANA 时区切日，返回实际区间、时区、数据水位、口径版本、租户权限范围和分子分母。客户端量按网关接收时间归窗，实际发送按发送时间归窗。入账时间和供应商账单周期独立保存。已经有固定 UTC 或上海物化日桶的报表继续按其固定口径标注，升级后通过显式参数对齐；月结按合同账期和账期时区。

| 指标 | 目标算法与边界 |
| --- | --- |
| 客户端总请求、已完成、进行中 | 总量按 `(tenant_id, request_id)` 去重。终态按成功、失败、限流、已终止取消互斥分类，进行中单列。未进入可信入站记录的量报告覆盖缺口。重试、换模和竞速只增加出站调用。 |
| 供应商发送数与状态 | 按不可变 `attempt_id` 去重，区分准备发送、证实发送、提交状态未知。实际送出的重试、竞速、平台任务全部计算。DNS/本地拒绝等已确认未发的调用在诊断漏斗单列。响应前取消或断线存在被供应商计费的可能，证据不足进入待核对。 |
| 活跃、新建、关闭会话、轮次 | 活跃是窗口中有客户端请求的规范会话去重，新建及关闭按首次请求和生命周期结束事件归窗。页面上的最近 24 小时活跃等独立指标标明窗口。无会话请求进未归属桶。轮次为镜像实体计数，冷热重叠或异步缺口单列。按天活跃会话不可相加为月活。 |
| 成功率、失败率及错误分类 | 成功率＝成功终态 ÷ 全部终态。失败、限流、取消按约定各有分项，合计与终态平衡。客户端和供应商分别计算；供应商成功以协议级结果及流终止状态判定。分母为零显示无数据。 |
| 输入、输出、总 Token | 归一化输入为完整输入，按协议把独立上报的缓存分量并入一次，子集保持原样。归一化输出包括已被协议计入的细分，另报缓存/推理/多模态分项。总量＝输入＋输出。供应商原始字段和供应商声明总量独立保存。估算值与上报值分开统计。 |
| 缓存读、写和命中率 | 分别求和。Token 命中率＝可比记录的缓存读合计 ÷ 同批记录的完整输入合计。请求命中率＝缓存读大于零的请求数 ÷ 同批有可比缓存统计的请求数。有效零计分母，未知或不支持单列。分子超出输入需标异常并保留原样。跨桶重算比率。 |
| 延迟、TTFT、P50/P95、健康和质量 | 延迟以声明时间点计算，平均保留样本数和合计，TTFT 限可观测流。分位数以原始时延或可合并分布重算。健康、质量、并发、压缩节省、风险和配置活跃量应在页内注明样本和独立分母，均与用量和扣费区分。 |
| 供应商测算成本 | 各调用按独立计费量×生效成本单价（含读写缓存、阶梯费率、每次费或其他合同单位）÷价格单位，并记录费率版本、价格证据、币种、精度和分项。计划价、估算价和缺价有独立状态。保留定点精度，按账单规则在界定层级舍入。 |
| 供应商返回金额 | 原始金额、币种、字段语义和来源证据。区分供应商返回的目录原价、结算价及未知语义。响应无金额保留 NULL，供应商账单金额、折扣、固定费、税、赠额和冲正分开对拍，由账单确认最终应付。 |
| 内部积分、内部金额 | 已过账消费、冲正及调整净额按租户、用户、应用、客户端分组，预扣和待入账单列。实际记账金额以按内部价格和规则写入的过账为准；只有积分时可展示冻结倍率折算的参考金额并标注。收款、充值和额度分配与消费单独统计。 |
| 金额差异与覆盖 | 比较量、币种、结算主体、账期和分摊范围须相同。输出测算与返回的差、测算与账单的差、未匹配账单与待证实发送。内部收入和供应商成本只在共同比较范围和相同结算币种下计算差额，跨币使用可审计的汇率和日期。 |

## 四、两条账与平台客户端

### 逐次上游调用和供应商账单

- 每次准备调用时生成 `attempt_id`，固定租户/平台归属、父请求或作业、模型、供应商账户、凭据代理 ID、尝试序号和路径。实际 transport 发出信号、响应、响应 ID、用量或异常以同键入 durable outbox。DNS/TLS 失败与已提交断线分别标识，无法确定提交状态时进入挂账。确保流式终帧、用量迟到、重启、队列重放、并行重试均可重建，不重新发供应商调用。
- 规范事实保留 token 原值和归一化用量，记完成状态、 usage 来源、费率/币种快照、测算金额及供应商返回金额。每一条费用证据支持审计版本，同一 attempt 只选一条有效版本供汇总。持久证据只存必要字段及受控引用。
- 复用 provider 月对账界面和导入骨架。将账单导入规范化为账户、币种、周期、单号、行号及调整类型。优先按供应商请求 ID 精确匹配，其次按供应商账户、模型、桶和计费项目对拍，模糊匹配只给候选。账单级固定项单列，重传同单不重算，差异需能回到来源和处理状态。

### 客户端入站请求和内部账

- 独立保留入站时点、唯一 request ID 及终态事件，沿用既有请求日志/WAL 但实证早拒、限流、取消、无会话、探测/内部回环是否覆盖，缺口从实际入口补齐。终态按租户+请求去重。扣费按同一请求幂等入账，不跟随尝试数增殖。
- 对齐额度桶、过账流水和月账单。先核请求级实际扣费及冲正，再校验按租户、用户、应用、客户端展开的净额。无扣费政策、网关拒绝、免单、待扣费、扣费失败及缺失必须能区分。
- 建立网关可信发起方分配的 **平台自动化运维客户端**，用稳定的系统标识，子类保留 health/probe、self-check、admin-test 和计划运维等。业务发起的模型调用继续继承真实客户端。混合工作流逐次保留父请求与发起者。未知流量单列待查，客户端传入的标题、User-Agent 或任意普通请求头不能取得平台身份。平台客户端计入平台用量和供应商账，在内部按平台成本中心列示且租户扣费为零。供应商账本应能按业务归属、平台归属、未归属三桶完整拆分，单独列出无调用的客户端请求及多调用请求。
- 一笔请求可以关联多次出站调用和多笔过账。请求级报表先按租户与请求聚合两条明细，再联结会话维度。供应商明细按 attempt 展开，过账明细按交易 ID 展开。账单匹配表单独保存匹配证据与分摊。只记录每种事实自身的金额，避免退款乘上重试数或账单固定费乘上请求数。

批次核对先锁定同一范围与账期。供应商发送数按业务、平台和未归属之和对拍。费用分别披露可测算金额、已返回金额、已匹配账单金额、账单独立调整及各自覆盖量。对账差额只在计量范围重合的行上计算，未知发送和缺价进入待核对明细。内部账从过账净额出发，匹配已出账汇总、未出账流水及调整，差额按迟到、冲正和待处理逐项解释。计数与 Token 使用整数对拍，金额容差按供应商合同的最小计费单位和舍入层级核定。

**最小验收样例**。一个业务请求两次调用，第一笔 HTTP 失败但产生 10 个输入 Token，第二笔流式成功，完整输入 100（缓存读 40）、输出 20。另有一个网关限流未出站请求，以及平台探测一个独立上游调用。预期客户端业务请求 2、业务成功率 1/2、业务上游发送 2、平台上游发送 1；按业务终态用量合计成功请求 120 Token，限流零上游用量。若失败尝试的 10 为经供应商确认，则出站业务输入合计 110，缓存率按有可比记录的分母计算。第二笔供应商测算 0.012 USD、返回 0.015 USD、内部扣费 12 积分应分别可查。属于前一日创建会话的成功请求仍计入今日窗口，今天的活跃会话计 1、新会话计 0。变体覆盖计价单位/币种、缓存写、多模态、未知送达、无计费率、重复账单、冲正、跨时区边界和平台身份冒用。

从仓库根目录运行 `bash docs/handoff/launch-request-session-reconciliation.sh --handoff` 可重新生成交接。用 `--preflight` 启动三条并行只读核对，启动实施协调会话用 `--implement`。模型默认 `gpt-6-luna`，可通过 `RECONCILIATION_CODEX_MODEL` 使用当前环境支持的低成本模型。脚本以本地替身验证了三路分派和失败退出码。 [handoff 启动脚本](../handoff/launch-request-session-reconciliation.sh)

## 六、本轮实施契约

| 事实 | 键与归窗 | 证据和写入归属 |
| --- | --- | --- |
| 客户端请求 | `(tenant_id, request_id)`，按网关接收时间归窗。`request_id` 由网关生成。 | 入站组件维护 WAL 和终态遥测；复用终态事实的版本及缓存、会话维度。租户和会话关联必须同时匹配租户与对应 ID。缺终态、缺用量和无会话分别暴露。 |
| 供应商调用 | `attempt_id`，每次独立 HTTP 调用一键。确认发出的调用按 `sent_at` 归窗，未证实发出按准备时间进入待查。 | 执行器和已接入的直连任务只写自己的 attempt。发送依据是完整写出或收到上游响应，供应商是否接收以及流是否成功各用自己的证据。 |
| 已过账消费 | `credit_ledger` 的 `(tenant_id, id)`，按 `created_at` 归窗；`ref_type='request'` 和 `ref_id` 关联请求。 | 计费事务写实际积分，多额度池可生成多笔。重放在整个扣费事务上去重。无冻结的记账币种价格时，内部货币金额保留缺失。 |
| 会话 | `(tenant_id, gw_session_id)`。活跃由窗口内请求推出，新建和关闭各用自己的时钟。 | 复用 `session_dim` 和已验证请求关联。一个跨日会话可以今天活跃、今天未新建。 |

费率测算与供应商返回金额各自可空，金额保留定点精度。估算分币种，返回分币种和来源语义。缺币种的返回金额有计数且不参与分币种求和。无合同费率、账单样本或可信历史证据时保持缺数。平台自动化客户端标识为 `platform-automation`，只从网关可信身份或平台任务入口设置。

迁移 `982` 创建逐次调用表，使用仓内未占用的三位编号，按投递顺序追加。已有迁移文件的字节沿用。启用 `LLM_GATEWAY_RECONCILIATION_SHADOW_ENABLED=true` 可在已迁移的环境启动影子采集。报告为独立读取入口，现有报表查询仍可用于对照。

请求扣费的事务级重放幂等始终启用。平台自动化请求记录可信来源。启用 `LLM_GATEWAY_RECONCILIATION_PLATFORM_BILLING_ENABLED=true` 后，系统密钥且认证 owner 通过系统来源白名单的请求才豁免租户积分预检、月预算和扣费。平台计费和供应商影子采集各用独立开关，默认均关闭。

统一查询入口 `GET /api/admin/usage/request-reconciliation`。日对账传 `day=YYYY-MM-DD`，可用 `timezone` 指定 IANA 时区，省略时采用网关系统时区。`section` 支持 `requests`、`attempts`、`postings`、`sessions`、`coverage` 和 `internal`，按各自时钟查询同一日窗。`format=csv` 导出同一分页，`format=csv-summary` 导出该日汇总。租户管理员仅能读取自身请求、会话及内账。供应商逐次证据和覆盖查询仅对平台管理员开放。`read_at` 标记本次数据库读点。

请求按留存 WAL 中最早到达查窗口，窗口内重写的旧请求仍归原日。请求用量单列完整、部分和缺数。旧终态事实把缺失 Token 写成零的情况留空，逐次供应商证据保留明确返回的零。供应商测算按归属和币种汇总，供应商返回额还按金额语义拆分。

日对账使用当地日初至次日日初的左闭右开区间。已存月账和按月汇总可用 `month=YYYY-MM`，月窗口默认 `Asia/Shanghai`。需要自定义区间的请求、调用、积分流水及会话可传 RFC3339 的 `start` 和 `end`。真实账单金额按各单的账期、币种和结算账户核对。

如果当地时区跳过或重复月初零点，月报和账单导入统一取该月首个实际时刻。回归样例覆盖了两个相邻账期共享同一个跳时边界，以及月初零点重复的情形。

## 七、隔离验证与剩余范围

- 安装器空库烟测实际执行 `982`，部署通道契约检查通过，正本、安装器与离线升级副本 SHA-256 一致。隔离升级夹具在保留旧数据及列序差异的情况下重放 `982` 两次。通过安装器生成的完整数据库也成功执行了四类报表查询。
- 报表夹具验证两次业务上游发送、一次平台发送、一次送达未知、无上游的限流、跨日会话、跨窗口重写、跨租户同请求 ID 及拆分过账和冲正。真实 PostgreSQL 并发重放只扣一次。移动端 11 个入口的帮助和桌面共用定义通过组件测试，移动端生产构建通过。
- 出站覆盖 Chat、Anthropic、Gemini、Ollama、续流、上下文压缩及已接入的探测。供应商响应有公开字段证据时保存金额。OpenRouter 的 JSON 响应及 SSE 末帧使用 `usage.cost`，保留 USD 金额与账户扣款语义。 [OpenRouter 用量及扣款说明](https://openrouter.ai/blog/insights/cost-vs-quality-tradeoff-framework-for-agent-models/)
- 真实账期仍需合同费率、脱敏账单、历史覆盖核对和可写隔离历史库。音频及其他旁路供应商入口仍需核定覆盖。安装器全量 embed 门的 `055–058` 已知投递缺口留在 L22。生产影子采集、报表切换和平台免扣费开关尚未启用。

## 八、供应商账单明细与原始账期

迁移 `986` 增加账单正本和逐行明细。平台管理员使用 `POST /api/admin/provider-cost-reconciliation/invoices` 提交规范化明细。账单正本保存导入人、时间、规范化内容的 SHA-256、账户、对应凭据 ID 和原始账期边界。同一供应商、账户、币种、单号下，等价重传返回原单，修改内容返回冲突。更正使用单独的调整凭证。

`credential_ids` 由导入人按结算账户提供。系统验证每个 ID 有当前供应商归属，或有账期内该供应商的逐次事实支持。币种使用三字母代码，`stated_total` 和明细 `amount` 使用十进制字符串，明细签名金额逐项相加必须等于账单合计。`request_total` 代表一次调用的完整费用，必须带 `provider_request_id`。聚合费用可用 `usage_bucket` 录入，税、固定费、折扣、赠额、退款及其他调整有独立行类型。

可用以下脱敏样例演练导入形状。示例中的数字 ID 需要对应目标库中的供应商及凭据。

```json
{
  "provider_id": 17,
  "account_ref": "sample-account",
  "currency": "USD",
  "invoice_ref": "sample-2026-11-01",
  "day": "2026-11-01",
  "timezone": "Asia/Shanghai",
  "credential_ids": [117],
  "stated_total": "0.013",
  "lines": [
    {"line_ref": "1", "kind": "request_total", "provider_request_id": "sample-request", "amount": "0.015"},
    {"line_ref": "2", "kind": "discount", "amount": "-0.002"}
  ]
}
```

供应商提供日账单时传 `day`，提供月账单时传 `month`，并将 `timezone` 设为供应商原始账期时区。用 `GET ?provider_id=17&day=2026-11-01&timezone=Asia/Shanghai` 列出窗口完全匹配的日账单，用 `GET ?invoice_id=<UUID>` 查逐行结果。`month=2026-11` 继续用于按月查找已导入凭证。CSV 支持当页明细和全单汇总。匹配要求同供应商、归属凭据、账单原始窗口和供应商请求 ID。重复账单引用、多个调用候选、模型冲突、未确认发送、未找到调用和分桶行都留待核对。金额差异只对唯一匹配且同币种的证据计算，供应商返回额还须具有账户实扣语义。覆盖率以已观察记录为准。

隔离 PostgreSQL 夹具覆盖账单正本重传与冲突、凭据归属、月初与月末边界、跨供应商及跨账户排除、重复引用、同币种精确差额、显式零、税和折扣。真实合同价、厂商原始账单转换、分桶分摊和已关闭账期的正式核对仍须实际样本支持。

三阶段安装烟测在账单迁移初版通过，当时使用临时编号 `983`。最终版增加账户时间索引后，验证覆盖安装器单测、两条通道的依赖顺序和部署脚本契约。Docker 守护进程本轮后段失去响应，最终版账单夹具改用隔离 PGlite，通过同一套 Go 与 SQL 验收。最新版 Citus 全链烟测仍待复跑。 [PGlite 的 PostgreSQL 实现](https://pglite.dev/docs/about)

## 九、多模态出站补录

音频的原生转写、MiniMax 与 Whisper 转写、Chat 音频桥接及语音合成，与嵌入、图像和视频生成共用逐次记录器和现有影子开关。中途重试各有独立 `attempt_id`。可信系统密钥继承平台归属，无法确认业务或运维归属时保留未归属。

上游响应状态与协议终态分开记录。可识别的转写、语音及嵌入响应提供成功证据，媒体异步响应和缺终帧音频保留未定结果。可确认的 DNS、拨号及证书验证失败记为未发送，部分写入及证据不足的断线保留待核对。价格和账单缺项继续留空，按时长、图片、视频的合同计费单位仍待真实费率和账单确认。

## 十、多模态入站与跨日回放

影子开关开启时，已注册的嵌入、音频转写与合成、MCP、图像和视频路由在并发闸外写入请求 WAL。沿用网关生成的请求键，身份经校验后补记租户和应用，独立模态请求的会话留空。网关限流、供应商 HTTP 429、取消、MCP 协议错误和缺少转写终帧分别记录。平台来源来自可信系统密钥，按权限从租户查询中排除。路由前拒绝的纳入范围见第十四节。

客户端请求按接收时刻归日，供应商调用按已确认发送时刻归日。WAL 回放沿用最早接收时间，旧格式备份以其记录时间补证。终态先到且入站行尚未恢复时，多模态写入保留可重试错误。隔离夹具验证了日末接收、次日补录的请求仍归原日，日末准备但次日发出的供应商调用归次日。

## 十一、逐次调用证据的本地持久队列

影子模式复用 `LLM_GATEWAY_BACKUP_DIR` 下的 SQLite 文件保存准备、派发、实际写出、HTTP 响应、用量和终态。队列按配置的 PostgreSQL 主机、端口和数据库隔离，重启后使用同一标识接续。进程间串行投影，同一调用 ID 可幂等补录，只有 PostgreSQL 写入完成后才确认队列记录。格式或数据约束错误保留在队列供核查。初始化队列失败时继续直接写 PostgreSQL，并记录该实例缺少本地恢复能力。

本地测试覆盖重启、并发投影和发送时间及精确金额保真。隔离 PG 兼容夹具覆盖 PostgreSQL 已提交、队列确认前中断的回放，原调用 ID、供应商请求 ID、发送及终态时间保留。完整 Citus 烟测、真实历史覆盖率、合同样本与生产日对账仍待验证。

## 十二、每日覆盖与内账影子核对

平台管理员可用 `GET /api/admin/usage/request-reconciliation?section=coverage&day=YYYY-MM-DD` 查询每日覆盖，`format=csv-summary` 导出当日。入站请求按最早留存接收时刻计数，终态用量记录按最早留存发生时刻去重，积分流水按过账时间计数，已确认的供应商发送按发送时间计数。每项用自身分母，跨日入站与缺少留存入站分开列。缺测算金额、缺返回金额和返回额缺币种分别计数，显式零保留。历史供应商发送总数仍未知。

租户管理员可用 `section=internal&day=YYYY-MM-DD` 对拍自身毛扣费、含冲正的净积分和整小时用量桶。平台管理员须指定 `tenant_id`。边界小时桶单列，日查询仅核对整日可比的积分。现行 MaaS 月账仍以 UTC 自然月查找，`month=YYYY-MM&timezone=UTC` 仅在账期起止完全相同且账单状态为 `issued` 或 `paid` 时计算账单差额。

新增请求的扣费流水、余额和计费用量桶在同一事务提交，重放按实际过账记录合计。隔离夹具先让桶写入失败，确认余额和流水回滚，再重试确认一次扣费与一次桶增量。通过 Go 源码覆盖层测旧实现，同一测试在桶写入被拒后仍观察到旧实现返回扣费成功。本次验证使用 PGlite 单连接，Citus 最新版的跨连接账务验证仍待复跑。已有小时桶可能来自旧请求日志回填，差额作为审计线索，存量月账由其原账期归属保留。

## 十三、日对账入口与验证

桌面 `/admin/reconciliation` 提供自然日证据查询，默认选系统时区的上一日。可分别查看客户端请求、供应商尝试、会话、过账、覆盖和内账，并导出当天汇总及当前页明细。租户账单页仅提供已授权租户的日内账，移动 `/report-rollup` 增加可按日期查询的覆盖摘要。

隔离测试覆盖跨日接收与发送、23 和 25 小时自然日、被时区跳过的日期、日账单幂等重传、相邻日复用供应商请求 ID，以及同日终点排除。月账及跨日固定项留在原始账期。生产日对账仍需真实合同和账单样本、隔离历史库及独立授权。

桌面组件测试验证分页与导出沿用屏幕所选日期、时区和租户，租户切换作废在途请求。移动报表测试验证日证据查询独立于原有快照。Chrome 隔离页面在 320、768、1024 和 1440 px 验证了键盘可聚焦的明细滚动区域与精确金额显示。

## 十四、网关入口拒绝

影子模式下，生成和已接入的独立模态 POST 请求在全局鉴权拒绝时按服务器请求 ID 留下一条终态 WAL。生成请求在大请求预处理、密钥并发限制、异常检测或 V2 分派治理阶段被拒绝时也保留终态。已进入模态观察器的请求由原入口记录。桌面日对账和 CSV 可核对入口拒绝的数量与固定原因代码。

接收时间由请求 ID 中间件确定。入口拒绝的接收时间和终态一并写入，回放时沿用原时间。通过身份校验的业务拒绝归属实际租户，可信平台拒绝归属平台运维，平台全局请求查询中的未归属拒绝留空租户字段。代理在到达网关进程前拦下的请求由代理日志提供证据。

## 十五、客户端请求与编排子调用

影子模式记录音频后处理和文本加工入口的客户端请求。MCP 中的对应工具也使用原始 MCP 请求作为父请求。每次网关向聊天入口派发模型步骤前，迁移 984 对应的表登记一个短时有效的关联凭据。接收网关校验租户、密钥身份和归档前的请求体指纹后，以自身生成的 ID 单次领取。共享同一数据库的网关实例可以关联，原始凭据只在派发请求中携带，接收时从 HTTP 头移除，数据库存其摘要。

已确认的子请求从客户端请求计数中移出。只有子请求留存记录的会话从客户端会话查询中排除，有客户端请求证据的会话按原规则计数。供应商尝试和积分流水保留原执行请求 ID，同时显示父请求 ID。客户端请求按原接收时间归日，供应商发送和积分流水按各自实际事件时间归日。覆盖查询区分内部子请求接收数、已登记派发数与待关联派发数。

隔离夹具验证了同租户同一父请求下两次子调用跨午夜时的客户端请求数、会话数、发送数和积分流水，验证了不同租户、不同密钥、请求体不匹配、重复和过期领取。已知音频和文本模型步骤走网关环回时可关联。外部 ASM 委托、独立数据库的环回目标以及历史流量仍需相应证据，当前覆盖查询可显示已登记但未关联的网关派发。

## 十六、供应商日账单汇总行

平台管理员可在桌面对账页的「供应商日账单」按自然日和时区查找账单，查看核对结果并导出 CSV。日查询支持查看全部供应商。账单详情固定到原账单及账期，金额保持原币种和定点字符串。账单汇总及明细标记数据库读取时间，已保存的月账继续按原账期查询。

带有确切模型、覆盖该账单账户全部已列凭据和完整账期的请求总额，可以将账单行写为 `usage_bucket` 并附 `"usage_bucket":{"basis":"request_total","sent_attempts":2,"input_tokens":30,"output_tokens":5}`。模型写在行的 `model` 字段。可选 Token 数必须来自供应商与网关可比的归一化口径。只提供金额的历史汇总行和按单项计费量、阶梯或固定费用列出的行继续保留各自原值。

有重叠账单行、待确认发送、未知模型、笔数不符或已声明 Token 数无法核对时，汇总行进入待处理并给出具体原因。金额差额仅对同币种且该行全量具备可比证据的一侧计算。供应商返回的目录价、缺币种或语义不明的金额无法补足可比覆盖。逐笔请求号继续单独核对。通过汇总核对只说明账单范围与留存计量相符，最终应付取自对应账单。

隔离夹具验证原样保留旧账单、重复导入、跨自然日、跨凭据账户、重复计费范围、显式零和未知用量，以及只有一侧金额可比的输出。真实合同价格、供应商出账样本和最新 Citus 全链仍待验证。

上游缓存的 `origin/main` 已使用 `983` 投递请求指标。尚未发布的本地供应商账单迁移改用 `986`，其依赖迁移检查随账单汇总字段的编号 `987` 同步更新。

## 十七、供应商合同费率版本

平台管理员可用 `POST /api/admin/provider-cost-reconciliation/rates` 导入已核实的合同费率。用同路径 `GET` 并指定 `provider_id`、`credential_id`、`model` 可核查版本历史。合同必须明确供应商、凭据、发出的模型名、版本引用、币种、生效时间及收费计量。相同生效时刻的等价重传返回原版本，内容不同返回冲突。有效时间使用 UTC 瞬间，允许为同一范围追加新版本。

逐次账本用确认的发送时刻选择当时已导入、已生效的最近版本，按所选版本的结束时刻排除过期费率。实际发送跨日时按发送时刻选价。账本冻结该版本及条款，后续用量到达可补算，迟导入的费率不替历史调用补价。

费率组件可对确认发送、输入、输出、缓存读取和缓存写入计费。费用字段接受十进制字符串，组件写明价格对应的计量单位。合同如果定义了单次调用内的累进阶梯，按各阶梯实占数量乘价。输入包含缓存的协议可在 `subtract_from_input` 明确列出要扣除的分项。分项缺失或数量不一致时金额留空，明确的零保留。媒体计量见第十八节。套餐周期摊销和跨请求累积阶梯仍需真实合同证据。

报表及 CSV 区分供应商合同测算、历史未核实测算和供应商返回金额，日覆盖另列缺合同测算的发送。未核实的历史测算仅供追溯，账单差额使用同币种的合同测算。隔离夹具验证跨日切换、晚到用量、晚导入、等价重传、跨凭据隔离和查价失败时发送证据仍可落库。

## 十八、媒体逐次计量

逐次账本分别记录输入音频时长、供应商计费音频时长、输出音频时长、返回图片数和已完成视频时长。标准转写的输入时长与 `usage.seconds` 分列，MiniMax 的流式时长取终帧。语音合成只从结构和帧数可校验的 PCM WAV 输出测量时长。长度统一为可精确转换的整数微秒。 [OpenAI 转写响应](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) · [MiniMax 转写响应](https://platform.minimax.io/docs/api-reference/speech-to-text) · [PCM 格式](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex)

图片计数来自供应商返回的完整资源列表。视频计量使用现有兼容入口的已完成视频对象，待处理作业、截断流和无法确认媒介数量的响应保持缺失。用户请求的张数和秒数不作为测算证据。现有网关尚未连接异步视频回查。 [图片响应示例](https://developers.openai.com/api/docs/guides/image-generation) · [历史视频对象字段](https://developers.openai.com/api/reference/resources/videos/methods/retrieve)

尚未发布的 987 增加媒体账单汇总字段。供应商按账号、确切模型和原账期提供整组调用的总额时，可以在 `usage_bucket` 中声明 `generated_images`、`audio_input_duration_us`、`audio_billed_duration_us`、`audio_output_duration_us` 或 `video_output_duration_us`。张数用整数，时长用整数微秒。可选量的空值保留为未声明，显式零纳入核对。原始计量和计费用量口径各用自己的字段。

每项声明量都需要该账单范围内全部确认发送的相同单位证据。匹配失败时，桌面日报及 CSV 显示账单量、留存量和缺数或不一致状态，该行金额差额留空。隔离夹具覆盖部分缺数加显式零、计费与输入时长不同、1 微秒差异、下一自然日及其他凭据排除，以及等价重传和证据修改冲突。真实供应商账单转换仍需实际样本验证。

## 十九、每日影子对账快照

在授权的隔离库或只读证据库设置 `REQUEST_RECONCILIATION_SHADOW_DSN` 后，可从仓库根目录执行以下命令。

```sh
go run ./cmd/request-reconciliation-shadow -day 2026-11-23 -timezone Asia/Shanghai
```

命令在同一个只读、可重复读事务内复用现有日报查询。输出包括请求、发送、会话、过账、覆盖和内账汇总、各租户的流水与小时桶差额、与所选自然日完全同窗的供应商账单及核对汇总。可将标准输出保留为本次核对凭证。执行失败时退出码非零。相同日窗可再次采集，`read_at` 标出本次快照。日窗已过标记 `elapsed`，供应商关账仍由实际账单确认。

计数核对比较日报和覆盖面留存的入站、确认发送和请求过账笔数。两边都没有观察时标记 `no_observations`，历史真实供应商总量继续标记未知。内账差额按租户查看，避免不同租户的差额互相抵消。供应商仍在各自账单及币种内核对，跨日凭证留在原始账期。生产执行、关账样本验收及切换审批使用独立授权。

隔离 PGlite 夹具演练了开放日和已过日，后者读取四份同日样本，保留单个租户的积分差额。验证同时覆盖语句缓存开启和关闭时的账单导入、费率导入及逐次记录。关闭缓存时 JSON 参数以文本传给 PostgreSQL，未提供的费率快照保留 SQL NULL。

## 二十、历史用量覆盖与安装验证

每日覆盖读取旧用量台账的冷热合并视图。原始行数与按租户和请求去重的每日键数分别列出。用相同租户和请求键关联现存最早入站及终态用量，缺失和跨日接收分别计数。桌面、移动、CSV 和影子快照使用相同查询。日键数跨日相加时，同一个键可在不同日各出现一次。首尾日期表示首次和末次观察，日期之间的留存完整性仍需核验。

旧用量只能证明保存过相应的请求键。历史供应商总发送数仍未知，旧台账金额不写入逐次证据。隔离夹具在迁移前放入月度历史分区行和热表行，验证冷热重复、跨日出现、同名请求跨租户隔离，以及只有旧用量记录的日期。

空库烟测在初装和第二次运行后执行同一份 SQL 判据，核对对账迁移记账、媒体计量、供应商账单和历史读面。容器标识取自创建结果，后续操作使用该标识。

隔离 PGlite 中，完整迁移后判据通过，临时去掉一个账单媒体列后判据失败，随后回滚。容器同名和安装失败路径用命令替身验证了隔离。当前 Docker 守护进程不可用，完整 Citus 空库和实际历史库升级仍待运行。

## 二十一、日报默认读面与回退

网关有数据库连接且 `LLM_GATEWAY_RECONCILIATION_DAILY_DEFAULT_ENABLED=true` 时，已建权限接口会返回上一有效自然日和系统时区。平台报表进入页面后按该日加载桌面的证据覆盖或移动端的覆盖摘要。两端均提供历史快照入口，桌面的既有筛选链接直接打开历史快照。能力读取错误、超时或缺少该配置时，使用原有默认页面。

在已授权的环境完成影子验收后，可通过该开关切换默认读面。将其取消或设为 `false` 并使网关加载新配置后，下次进入页面恢复历史快照为默认，日证据仍可手动查询。权限沿用原接口。该开关只控制报表入口，与影子采集和平台免扣费分别生效。

媒体合同组件以对应账本字段作为 `meter`，按数值乘对应费率。时长可使用每秒 `1000000` 或每分钟 `60000000` 微秒作为价格单位。每次调用总额无法精确写成十进制时保留缺失，除非合同条款通过 `amount_scale` 给出小数位数，此时总额按四舍五入计算。日明细和 CSV 保留来源和计量，覆盖查询单列缺媒体数量或时长的发送。

## 二十二、移动端日对账明细

移动端 `/report-rollup` 可在同一天查看覆盖、客户端请求、供应商逐次调用、会话、积分过账、租户内账和同窗供应商账单。请求、调用、会话和积分以记录键展开。供应商账单显示匹配状态、可比金额和差额。租户内账必填租户，供应商账单按原结算账户和账期查询。

分页沿用日期、时区和租户，切换查询范围会取消在途请求。金额字符串保留服务器精度。超出浏览器安全整数范围的计数可在桌面 CSV 查验。移动说明同步当前读面。

## 二十三、HTTP 重试的失败用量与联测

传输层读取到完整的 5xx 响应体时，按当前发送的 attempt ID 写入可确认的用量和支持的返回金额。随后重试的响应归自己的 attempt ID。诊断仍使用原有 4 KiB 上限，读到截断或无法确认完整的内容时保留缺数。

隔离用例通过本机 HTTP 供应商替身、真实 SSE 执行器、SQLite 持久队列和日账单查询核对同一请求。失败发送记 10 个输入 Token，成功发送记 100 个输入 Token、20 个输出 Token 和 40 个缓存读 Token。两笔合同测算为 0.001 和 0.012 USD，同日两条样本账单都能关联。计费服务使用成功流的用量，同一请求扣费重放后八十八积分余额和单笔十二积分过账均可核对。样本价格和账单金额均为验收输入。

在 PGlite 隔离库运行通过。用 Go 覆盖层关闭失败用量回调后，输入合计从 110 降为 100，两条已关联的账单只剩一条能计算测算差额。恢复后回归和竞态测试通过。

在自己创建的空白 `reconciliation_transport_fixture_*` 库设置 `RECONCILIATION_TRANSPORT_TEST_DSN` 后，可运行 `go test ./domains/streaming/executors -run '^TestStreamingTransportRetryPreservesBothAttempts$' -count=1`。

## 二十四、HTTP 跳转逐次归账

日报按每一跳的发送时间和账期时区归日。供应商 HTTP 客户端每次调用底层传输接口时生成独立 attempt ID，记录本跳状态和返回的请求 ID。自动跟随的 3xx 记录为已发送，模型结果未知。客户端停止跟随时只记已调用传输的跳数。请求写入回调持有对应的 attempt ID，回调晚于下一跳开始时仍归原记录。

跨地址跳转保留可信租户、平台身份和网关请求 ID，供应商、凭据、模型及费率留空。同地址跳转中，鉴权或查询参数变化会清除凭据与费率，方法或路径变化会清除模型与费率。支持的供应商返回金额由最终响应的实际地址决定。

本机 HTTP 用例覆盖 307 保留请求体、停止跟随、跨地址跳转和延迟写回。用 Go 覆盖层恢复旧记录点时，跟随跳转用例由两笔降为一笔并失败。隔离库中的 5xx 重试、日账单匹配及单次扣费联测通过。

底层传输内部的重放证据见第二十八节。供应商真实账单和历史库对拍需要获得对应数据。

## 二十五、上下文压缩费用证据

上下文压缩发送仍关联原网关请求、租户和可信流量身份。重试保留压缩来源。OpenAI 兼容和 Anthropic 摘要响应由实际发送的 attempt ID 记录显式 Token、缓存量和支持的供应商返回金额。没有请求 ID 响应头时，使用完整 JSON 的 `id`。系统裁剪、读取中断或收到部分响应时，保留缺数。

完整 2xx 返回可用摘要时记录成功，完整但无可用摘要时记录失败。HTTP 拒绝保留实际状态。截断响应的摘要结果在账本中保留为未知，既有摘要解析和回退行为沿用原逻辑。

本机替身验证了 503 后重试的两笔压缩记录，以及响应头优先、完整响应金额、截断和 HTML 拒绝。隔离库日账联测中，失败发送仅靠 JSON 请求 ID 仍可匹配账单行。关闭压缩响应证据写入后，金额测试报错。

## 二十六、平台探针供应商费用

主动探针、凭据健康巡检、节点及兄弟端点探针、自检直连使用各自已解析的供应商 ID。每次 HTTP 发送使用平台专用客户端，跨地址跳转各记一笔，跳转目的地的供应商、凭据和模型按证据填写。无法确认的归属与合同测算保留缺失。

POST 探针在原读取路径中观察完整 JSON，记录显式用量、支持的供应商返回金额和请求 ID。正文 ID 仅用于响应头缺失时。读取提前结束、超出响应上限或正文传输失败时保留缺数。发送时间沿用日报的自然日边界。

隔离账单联测使用真实主动探针路径。收到响应的平台发送为 6 个输入、1 个输出 Token，夹具合同测算为 0.0007 USD，关联同日 0.001 USD 账单行。租户余额为 88，只有业务请求的一笔 12 积分过账。加入底层重放后的日报计数见第二十八节。

## 二十七、其余后台探针的供应商归属

定时和手工模型巡检、能力回填、模态验证和凭据轮询使用出站前已解析的供应商和凭据 ID。模态验证的结构与语义发送各记一笔，合同测算使用绑定的原始模型名，供应商请求沿用出站模型名。显式凭据与绑定冲突时，保留该发送已知的凭据，供应商和绑定模型按本次发送的证据填写。

本机替身覆盖四条工作路径共五笔发送。隔离库使用供应商 ID 17 和凭据 ID 1 验证模态待核实查询投递正确归属，未核实记录仍排在已过期记录前。平台供应商日账与租户过账联测复跑通过。

## 二十八、HTTP 传输内部重放

同一次 `RoundTrip` 在请求已有写入迹象后再次取得连接时，上一笔保留已有证据并以未知结果结束，后续发送获得独立的 attempt ID。只有连接取得信号的重试沿用原 ID。执行器、模态和平台探针应用相同规则。最后一笔接收最终响应、响应正文和供应商请求 ID。`transport_replay` 记录在来源前段，保留原调用类型供覆盖查询识别。

本地标准 HTTP/1.1 用例让服务器在读完第一个请求后断开长连接，第二次发送收到完整 503。服务器观察到两次请求，账本观察到两个写入，503 正文只归第二笔。本地 HTTP/2 用例在同一连接的首个流返回 `REFUSED_STREAM`，后续流独立记录并收到 200。模拟用例覆盖纯连接重试和已开始写入但未完成的情况。

隔离日报联测为 2 笔业务、2 笔平台发送，其中 3 笔留有用量和合同测算。平台首笔在供应商替身读完后断开，结果、请求 ID 与金额留空。第二笔匹配同日账单。租户余额为 88，只有业务请求的一笔 12 积分过账。

初版用本机故障注入令 HTTP/1.1 首次缓冲刷新写出零字节，服务端只收到一次请求，而 Go 回调仍报告两次成功写入，账本发送数因此多计一笔。修正后的判据见第二十九节。

## 二十九、HTTP/1.1 零字节刷新与发送证据

网关自建上游、身份连接池和自建节点探针传输对明文 HTTP/1.1 连接观察实际套接字写入。Go 的写入成功回调后，仍有缓冲数据时以对应刷新写入成功为证据。写入循环已经结束时，已写出字节且套接字无写入错误也能确认。归日时间取实际首次写出时间。

观测到零字节的换连接重试沿用原 attempt ID，部分写入或刷新失败保留未确认状态。TLS、HTTP/2 和未接入套接字观测的传输以可读的 HTTP 响应确认发送。缺少响应时保留写入迹象和未知状态，缺少连接与写入回调时无法拆分内部重放。

同一故障注入中，Go 仍给出两次成功回调，服务端收到一次，账本确认一次。可观测的直连 HTTP/1.1 只保留一行，连接不可观测时首行保留为未知。另一个夹具实际写出部分字节并返回错误，账本保持未确认。通过 Go 覆盖层改回使用本地回调确认发送后，两种故障用例均报错。此前两次真实发送的夹具仍记录两笔。

## 三十、自然日账单匹配的待确认与跨币种重叠

逐笔账单匹配同时检查同一供应商、凭据范围、原账期和请求 ID 下的确认发送与待确认记录。存在待确认记录时，已找到一笔确认发送的账单行也进入待核对，调用归属与可比较金额留空。多个确认候选继续显示为多笔调用候选。

完整费用行的重叠和请求 ID 覆盖按供应商、凭据和账期判断。两种币种的账单重复覆盖同一发送或汇总范围时，相关重叠行进入待核对。账单合计保留原币种，差额仅对同币种的可比较金额计算。不同凭据或相邻账期复用请求 ID 时按各自范围匹配。

隔离日报夹具验证了准备中和交付未知的候选、跨币种逐笔重复、跨币种汇总重叠及凭据和日窗隔离。通过 Go 覆盖层复跑旧匹配判据，待确认、逐笔重叠和汇总重叠用例均报错。恢复后对账、影子快照及重试过账联测通过。

## 三十一、小时桶从已过账扣费补缺

网关启动回填与信用桶适配器共用过账来源。按扣费流水时间归入 UTC 小时，冷热重复按租户和流水 ID 去重，拆分的扣费金额相加并按请求 ID 计一笔。冲正和调整仍进入日净过账，小时消费桶只累计毛扣费。缺少请求 ID 的小时无法核实请求数，保留待查。

回填只插入缺失且与现有桶无重叠的小时。既有桶和先提交的并发写入留存，历史差额继续在日内账中显示。窗口两端存在桶时仍查找中间缺失的已过账小时。在线扣费与回填都固定写入 UTC 小时，避免数据库会话处于半小时偏移时写出不同桶键。

隔离库以 `Asia/Kolkata` 会话时区验证在线扣费的 UTC 桶边界、拆分扣费重放、冷热去重、迟到过账、冲正和缺请求键。夹具的当日 13 积分实际扣费补成 1 笔，前一日请求日志未产生桶，已有 99 积分的桶及半小时偏移的旧桶保留供核对。覆盖层重新启用覆盖、改回请求日志来源或仅按桶键查重时，回归判据报错。

## 三十二、日内账的小时差异与证据缺口

自然日报在租户汇总前按 UTC 整小时核对过账毛扣费与用量桶。日报同时显示有差额的小时数、有扣费但缺桶的小时数、有非空桶但缺扣费流水的小时数，以及未对齐 UTC 整点的旧桶数。某些时区的日窗只覆盖边界桶的一部分，日报单独统计这些桶。

整小时桶金额只汇总日窗内对齐 UTC 整点的完整桶。未对齐的旧桶覆盖的小时暂停比较。两侧小时证据不齐、旧桶未对齐或日窗截断小时边界时，日报的桶与毛扣费总差额留空。各小时都有两侧证据但差额相互抵消时，日报可以显示总差额为零，差异小时数仍保留。冲正继续计入净过账。

隔离数据库联测同时覆盖两个小时差额相抵、缺桶与缺流水分别落于不同时段，以及跨两个 UTC 小时的旧偏移桶。桌面端和移动端使用相同的日报字段。

## 三十三、跨时区月界的自然日账单

供应商日报列表与影子快照都按所选时区的实际日窗起止时刻匹配账单。账单继续显示供应商原始日期、时区及月份，月账查询按供应商原始月份查找。

隔离夹具导入供应商在 `Pacific/Kiritimati` 记为 9 月 1 日的日账单及同月月账。`Pacific/Honolulu` 的 8 月 31 日与该日账的实际窗口相同。旧查询在日报列表漏掉了这笔账单。修复后日报和影子快照都只列出该日账，供应商 9 月的月度查询仍可查到两份凭证。

## 三十四、与上游统计迁移合并的预检

本地缓存的上游 `68fc91112` 已登记 `983_request_metrics`。临时目录合成时保留其安装序号 393，再追加对账迁移 984 至 988。官方生成器将对账迁移登记为 394 至 398。部署通道同样追加这五条迁移及各自的产物探针。沿用上游排除注释条目的解析规则后，两条通道共有 343 条，部署独有 25 条，安装器独有 63 条。

合成的四阶段烟测保留新装和增量后的日对账 schema 核对。所有写入阶段都传入创建时获得的容器 ID。部署通道的容器可用性检查据此改用容器运行状态，兼容原本传入的容器名。临时合成通过两份 shell 脚本的语法检查和 `installer/internal/dbinit` 全包测试。当前工作区尚未合并上游，真实 Citus 空库与有历史的数据库仍需分别验证。
