## 二、本轮发现的缺陷与修复

### P1：maas MarketPriceOverview Scan 列序错位（端点自 D7 起必 500）★ 值得单列
- **形态**：`marketPriceOverviewSQL` SELECT 列 26–29 = `[credits_per_1m_in(BIGINT), credits_per_1m_out(BIGINT), COALESCE(manual_in,bool), COALESCE(manual_out,bool)]`（值、值、旗、旗），`rows.Scan` 却写 `[&manualInFlag, &manualOutFlag, &manualIn, &manualOut]`（旗、旗、值、值）⇒ pgx `cannot scan int8 (OID 20) in binary format into *bool` ⇒ **每次调用必错**。
- **引入点**：`08af89b1f`（52nd 审计轮 D7，2026-11-10 20:09）新增 4 个 scan 变量时序错。**此后无人冒烟过该端点**——845ba1d3b（42703）/14bc988cb（s_cur NULL）两次线上冒烟都在 D7 之前；端点带 `s.Enabled()` 闸且管理页面低频 ⇒ 静默存活两天。
- **通用式**：★★★ 「Scan 参数序 ↔ SELECT 列序」没有机器看管 ⇒ 每一次增列（63466a646 加 14 列时人工对位）都是一次全量重排机会 ⇒ 修法 = 源码级序钉 `TestMarketPriceOverviewScanOrderMatchesSelect`（解析 SQL 常量与 Scan 块，断言尾四元组【值值旗旗】+ 列数==参数数；**永不 SKIP**）＋ **变异验证**（注入旧缺陷序 ⇒ 红，还原 ⇒ 绿）。加列型提交必须跑该钉。
- **修复**：Scan 改 `[&manualIn, &manualOut, &manualInFlag, &manualOutFlag]`；pgx 离线探针两向实证（int8→*bool、bool→*int64 均报错）。

### P2：sales withhold 变体判定双主（§690 同款，本轮收口）
- **形态**：150cf6d0b 的 `withholdNames` 注释声称「factored out so derivation and the sellable list can never drift apart」，但 **ListSellable 的内联变体计数没有删**（sales/service.go 双主并存）且已实质分叉：视图 949 的 price_confidence CASE 对**单边 NULL**（`in=NULL,out>0`）落 `ELSE 'trusted'` ⇒ 「trusted 行必有价」前提在视图层不成立 ⇒ 同一「trusted+单边 NULL 同名组」可售清单判 withhold（旧份把 NULL 当 (0,0) 计变体）而派生不 withhold（新份跳 NULL）——正是该函数声称要防的漂移。
- **修复**：`withholdGroups` 单源（返回扣下集合 + WithheldGroup 明细，同序同值），ListSellable/派生/成本漂移三消费方同源；quote_test 两处调用点迁移。行为变化仅限「trusted 宇宙存在 NULL 价行」场景——该场景下新行为与派生侧一致（NULL≠0 红线方向）。
