## 1. 架构确认：「统计表」指什么

异步清洗链路在代码中闭环成立：

```
stats_event_inbox（domains/stats/inbox_consumer.go，fencing token 事务内消费）
  → usage_facts 入库（insertUsageFactTx）
  → AFTER INSERT 触发器 enqueue_request_metrics_fact（迁移 973 建）入 pending 队列
  → Processor（cmd/gateway/main.go:4454 接线，pending/history 双游标投影）
  → request_metrics 投影表（投影行带 source_fact_id IS NOT NULL 标记，与旧 writer 原始行键空间隔离）
```

- V2 统计 API 的读面统一走 `domains/metrics/` 包，读 `request_metrics`。
- 每个读面都带 `request_metrics_projection_state`（`ready`/`updated_at`）与 `request_metrics_pending`（`pending_since`）水位 ⇒ backfill 未完成时**如实降级**（`degraded_reason="request_metrics_backfill"`），不假绿。
- 双写隔离经审计复核成立（见 `docs/12小时内修订审计-2026-11-26-1025-v2统计面合并轮.md` §2.1）：旧 writer（`internal/metricsstore/writer.go`）零生产调用点，V2 读面全部带投影行过滤。

## 4. 旧版残留排查：3 条尾巴与处置

### 尾巴① `/api/usage/tenants` 仍在用（tenants.ts:29，UsageTrendExplorer 租户筛选器消费）

- **核查**：后端 `admin/usage.go` `listTenants` 的数据源是 **`api_keys` 聚合列**（`total_requests`/`total_prompt_tokens+completion_tokens`/`total_cost_usd` 是 api_keys 上的冗余计数），不是原始请求表，也不是统计表。
- **裁决**：它是「租户清单」端点（给筛选器提供 tenant_id 枚举），**不属用量统计口径**，不在本次对齐范围内 ⇒ **保留不改**。若未来 api_keys 冗余计数退役，属另一笔改动。

### 尾巴② `getDashboardOverview` 死代码导出（usage.ts:162，打 v1 `/api/usage/dashboard`）

- **核查**：全前端（views/components/composables/api）零调用点；仅 `DashboardOverview` 接口与该函数互相引用。v1 `/api/usage/dashboard` 后端虽存在（usage.go case "dashboard"，读 `usage_ledger_with_current_month` 账本），但前端已无消费方。
- **处置**：**删除**该导出与配套接口（本轮执行，见 §6 改动面）。

### 尾巴③ 注释漂移（代码已切 V2、注释还写旧源）

- `web/src/views/UsersView.vue:5`：注释写「GET /api/admin/users/usage-summary（usage_facts × api_keys.owner_user）」，实际 `getUserUsageSummary` 打 `/api/admin/users/v2/usage-summary`，后端走 `request_metrics` 投影。
- `web/src/api/admin.ts:604–606`：段注释同样写旧口径。
- `web/src/components/UserDetailDrawer.vue:6`：注释写「GET /api/admin/users/{id}/stats（usage_facts × …）」，实际打 `/api/admin/users/v2/{id}/stats`。
- **处置**：三处注释订正到现役口径（本轮执行）。
