## §12.3 ★★ 门盲区：`i18n-key-parity` 为什么会 PASS

`i18n-key-parity` 比的是「各语种的键集合 vs 并集」⇒ 判据是**有没有缺**，不是**有没有多**。
⇒ 族 C 的 288 个键**在 7 个非源语种里连成一片** ⇒ 各语种集合差异 = 0 ⇒ **PASS**。
⇒ 也就是说：**「共有」在 parity 门眼里等于「一致」** ⇒ 孤儿键成片时，这道门完全看不见。

★ 这也是为什么上轮只修了 23 行复制块、没发现这 288 个 —— 上轮用的是「人工探测 + 逐键比对」，本轮把这件事**固化成常驻门**。

## §12.10 通用式（本轮沉淀）

1. **★ 「parity 门 PASS」≠「键集合对」** —— parity 判的是「有没有缺」，不是「有没有多」；
   ⇒ **「共有」在它眼里等于「一致」** ⇒ 孤儿键成片时它完全看不见。
   ⇒ 通用式：**「集合类门」天生看不见「多出来的那一份」** ⇒ 判「多」要有独立的门。
2. **★ 死键判据必须叠三条**：源语种没有 **且** 全仓 0 引用 **且** 不在动态键前缀下。
   少任何一条都会误删：少了第 1 条会把「源语言合法新增」当死键；少了第 2 条会删掉活键；少了第 3 条会删掉动态拼出来的键。
3. **★ 「0 引用」的前提是引用集做全** —— `t/tc/$t/i18n.t` + helper 展开 + **`te()` / `tm()` / `localeArray()`** + **模板字面量** + **变量根可还原**。
   ⇒ 实测：动态键前缀 34 个静态可判根 + 60 处变量形态；漏掉任何一类都会误判活键。
4. **★ 动态键的「根不可还原」要显式记成 unresolved**，不能静默放过 ⇒ 宁可漏报不误报（误报 = 删掉活键）。
5. **★ 「源语种缺键」的方向判断要靠事实源**：族 A 的判据是**后端枚举常量 + 它的使用点**（零使用点 ⇒ 该类型从不产生），
   而不是「哪个语种多」 ⇒ 语言包比事实源**多**的是幻觉，比事实源**少**的才是缺陷。
6. **★ 删键的顺序不能省**：自顶向下（子树全死 ⇒ 整块删，不留空壳）+ 字符串感知解析（值里可能有 `{` `}` `,`）+ **删后语法自检** + **行为等值断言**。
7. **★ 先验证、再落盘**：第一版「先写盘后断言」把坏文件写进了工作区；改成两阶段（内存里全删 + 全过语法自检 → 才统一写盘）后，同一个 bug 再出现时被拦在落盘之前。
8. **★ 真实语言包里的排版地雷有三类**：一行两个键 / 尾逗号单独占一行 / 标量值的尾部空白跨到下一行。
   ⇒ 每类都要有夹具钉住，否则改脚本时必踩。
9. **★ 「删死键」与「改文案」在指标上是分离的** ⇒ 死键清理**不动**引用集口径的棘轮（基线一条都不用重铸）⇒
   ⇒ **可以安全地独立做，不必等文案那一摊一起收**。
