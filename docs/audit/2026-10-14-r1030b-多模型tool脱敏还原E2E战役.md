## 二、网关缺陷两枚（已修，提交 ec9d2f3f0）

### D1 引号包裹 marker 还原失败 → 整流 output_policy_blocked

- 实测：MiniMax-M3 responses 腿（raw-logs 42cbe78a…），模型把 password 占位符
  加了一层引号回显：`"password": "{\"SENSITIVE:secret:1\"}"`（username 为干净
  形式，同响应两种命运）。
- 链路：loose 文法不接受花括号内侧引号 → 还原 miss → 输出合规按「非占位符的
  密码样值」拒 → 20 帧后整流 `output_policy_blocked`，客户端拿到
  response.failed，tool call 丢失。
- 修复（`security/sanitize/placeholder_loose.go` + `smart_sani_guard.go`）：
  - `trimSpanQuoteWrap`：span 解析容忍**首尾同现**的一层引号包裹
    （`"`/`'`/`\"`）。双边条件是关键——normalizePlaceholder 会丢空格，
    `{sensitive xyz stuff}` 本就解析成垃圾类型 marker，旧代码靠**单侧尾引号**
    挡住它的带引号兄弟（r1022 契约），单边 Trim 会把 r1022 改红（本轮实测过）。
  - 流式前缀扣留（validLoosePlaceholderPrefix）对到达侧引号**左右独立** Trim
    （`{\"SENSITIVE:secret:` 扣住、`{"abc` 放行）。
  - 超长释放阀：被扣前缀超 maxPlaceholderTailBytes 且 marker 词从未开始时
    原样释放（防引号跑列误遮）；marker 词已开始的超长仍 fail-closed。
- 判据 `r1030_quote_wrapped_marker_test.go` 六件套：**真实捕获帧序列回放**
  （判据纪律 6：不手写形状）+ 三拼写解析表 + 普通 JSON 反例（前提在场反向）+
  未映射 fail-closed 保持 + 引号跑列释放阀 + 前缀扣留判定表。
- 变异验证：M1 撤引号裁剪→解析表红；M3 撤释放阀→引号跑列红（第一版测试
  形态走不到阀门、假绿——重写为引号跑列后红）。

### D2 Responses input 同轮 [message, function_call] 拆成两条 assistant

- 实测：MiniMax-M3 responses 腿 turn2 出站历史是两条相邻 assistant（先 content
  后 tool_calls），模型读史错乱：要么散文模仿 tool（"[Tools: get_deploy_config"），
  要么叙述「我将执行步骤 2」后直接收尾——多轮 tool 循环断裂。
- 规范形状：AI-SDK/ZCode 回放历史时，同一轮 assistant 输出是相邻的
  [message item, function_call item]；chat 线格式的标准历史是**单条**
  assistant(content+tool_calls)。
- 修复（`internal/ir/parse_responses.go`）：function_call 紧跟 assistant 消息时
  并入该消息（连续 function_call 并行全并入）；跨 tool 结果/user 边界不并。
- 判据 `parse_responses_r1030_test.go` 四件套（含独立 function_call 不并、
  并行全并、合并后 SerializeOpenAI 单条 assistant）。变异 M2 红。
