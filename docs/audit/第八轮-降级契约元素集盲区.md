## 2. 本轮最实质的一条：两道门在失败时口径相反

同一个问题「`usage_ledger_with_current_month` 视图缺失（42P01）」，
两个消费点给出**相反**的答案：

| 门 | 位置 | 42P01 时 | 是否自报降级 |
|---|---|---|---|
| 观测面 / 页面直连 | `admin/keys.go:995-1001` | **fail-closed**：`500 usage query failed` | 是（HTTP 错误） |
| 认证面 / 实际闸门 | `domains/authentication/verifier.go:815-828` | **fail-open**：`spent = 0` ⇒ `0 >= budget` 为假 ⇒ **放行** | 否 |

```go
// domains/authentication/verifier.go:814
if isMissingUsageLedgerView(viewErr) {
    spent = 0                                   // ← 视图不存在 ⇒ 花费读作 0
    metrics.BudgetChecksTotal.WithLabelValues(metrics.BudgetOutcomeDegradedNoLedger).Inc()
    slog.Warn("key verifier: usage_ledger_with_current_month view missing; budget enforcement disabled ...")
} else {
    return viewErr
}
if spent >= *budget { return &BudgetExceededError{...} }
return nil                                       // ← 放行
```

`admin/keys.go:995` 的注释记着 R89-133 缺陷 B 的修法：「查询失败时 spent 保持零值会被下游当成
『没超预算』放行并回 200 —— DB 故障的语义是『不知道超没超』，不是『没超』」。
**认证面做的正是那条被判定为缺陷 B 的形状**，只是发生在内层闸门上。

三点必须说清楚，否则这条会被读成夸大：

1. 语义上它是**站得住的设计选择**（注释明写：迁移窗口内不要让每个请求都失败），
   目标原文也说过「降级是否语义正确往往站得住」。判据是
   **「该降级是否会被页面当成真值」** —— 这里就是：请求被放行，
   且产品面**没有任何一处**说「预算不可用」。
2. 它不是认证绕过，是**支出控制 fail-open**：预算闸门在这段时间内不生效。
3. 它**可观测**（`BudgetChecksTotal{outcome="degraded_no_ledger"}` + `slog.Warn`），
   只是不可见**于产品面**。所以定级是「降级诚实性缺口」，不是 P0。

**为什么前七轮没看见**：`domains/` 从来不在主门元素集内，而前七轮的
T1 全部工作都在 `admin/` 里。**这不是某个人漏看了，是边界画在了仓库内。**

`verifier.go:802-806` 的注释说两门读数曾分叉、并已把 SQL 对齐（DISTINCT ON）。
对齐的是**读取口径**，**失败口径**没对齐 —— 视图缺失时，一个说「不知道」，
一个说「没超」。

### 2.1 ⚠️ 本节自我纠正：我说大了一档（复核时才发现）

初稿把这条写成「页面被当成真值」。**复核后不成立**，必须改：

`admin/keys.go:995` 在任何查询错误时是 `500 usage query failed`，
它**没有**把 `spent` 读成 0 再回 200 —— 那个形状已经被 R89-133 修掉了。
所以页面侧不存在「没超预算」的谎。

再往前一步查前端：`budget-check` 端点**全仓前端零消费**
（`web/src` 里 `budget-check` / `budgetCheck` 无任何非测试引用），
`KeysView.vue:718`、`KeysView.vue:771`、`KeyDetailView.vue:596` 只显示
`budget_usd`（**上限**），从不显示 `spent_usd` / `remaining_usd`。

⇒ **页面上根本不存在预算消费展示**，也就没有任何页面在讲「预算未超」这个假话。
认证面的 fail-open 是**行为层**的降级（请求被放行、支出不被拦截），
不是展示层的谎。按目标原文的判据（「是否会被页面当成真值」），
它**不满足**该判据 —— 满足的是「产品面无任何信号」。

### 2.2 修正后的定性与最小修法

| 面 | 现状 | 判定 |
|---|---|---|
| 请求路径（`verifier.go`） | fail-open 放行；`metric{outcome=degraded_no_ledger}` + `slog.Warn` | **设计选择**，可观测，非谎 |
| 展示路径（`keys.go:988`） | 500 `usage query failed` | 诚实，但**把两种故障混成一种** |
| 页面 | 无预算消费展示 | 无谎可讲 |

真正缺的不是「加个降级标记」，而是**第二行的可诊断性**：
`usage_ledger_with_current_month` 缺失（可修复：补迁移 344）与
DB 真的挂了，现在返回**同一个 500 同一个文案**，运维无法从响应区分。

本仓已有现成约定可循：`aggregate_read_guard.go:20` 就是
「42P01 → 503 + `analytics_view_missing`（含视图名与迁移引导）」。
所以最小、且不改放行行为的修法是**让 `keys.go` 的预算端点复用该约定**：
42P01 → 503 + 视图名 + 迁移引导；其余错误维持 500 原语义。

⚠ 这**不**需要前端消费：它是给运维/排障的诊断信息，不是一个新的展示面。
真要在页面上提示「预算不可用」，那是**新功能**（要新增 spent/remaining 展示），
不属于降级诚实性修复，且需要 11 个 locale 的文案 —— 属另一个量级的事。

## 3. `credentialstate` 的第二数据源（T4 纪律的延伸）—— 已核

`domains/credentialstate/cache.go:139-146`：`isUndefinedTable(nodeErr)` 为真时
**跳过 node-probe 表**，回退 `getLegacyStateFromDB` —— 这是目标原文 T4
「凡引入第二数据源，逐条核覆盖集」约束下的**第二个**数据源，第一个是
`request_logs_with_current_month`（§13/§26 已核）。

- 可达性：`credentialstate.Manager` 仅在 URSM v2 `ModeAuthoritative` 下为 nil
  （`cmd/gateway/main.go:1547-1553`），off / canary / shadow 形态**照常装配**
  且是读权威 ⇒ 默认形态下**可达**。
- 触发条件：node 查询返回 42P01 **或** `pgx.ErrNoRows`（后者是常态：
  「尚未进入新探测管线的行」）。所以 legacy 路径**不是只在故障时**才走。

两源的**字段集不同、口径也不同**：

| | `node_probe_state`（主） | `model_probe_state`（legacy 回退） |
|---|---|---|
| 可用性信号 | `last_direct_ok` + `next_retry_at` | `state` 文本 |
| `Available` 初值 | **`true`**，再按 `last_direct_ok` 降级 | 零值 **`false`**，仅 `state` ∈ 4 词才置 true |
| 错误码 | `last_err_code` | **无对应列** ⇒ `LastError` 留空 |
| `LastUpdatedAt` | **`time.Now()`（读取时刻）** | `last_attempt_at`（**探测时刻**） |
| `Source` | `"node_probe_db"` | `"db"` |

三处口径差，按严重度排：

### 3.1 `Source` 写的值不在它自己声明的取值域里

```go
// domains/credentialstate/state.go:27
Source string `json:"source"` // request, probe_v2, model_probe, passive, manual
```
实际写入的是 `"node_probe_db"`（`cache.go:128`）与 `"db"`（`cache.go:200`）——
**两个都不在那 5 个值里**。且 `node_probe_db` 全仓只出现 1 次（就是它自己的写入点），
说明**没有任何消费者按该值分支**。

> 这是「字段有值 ≠ 值到达消费者」的同构形态：上一次是「注释里提到键名 ≠ 写了那个键」，
> 这次是「注释里声明了取值域 ≠ 写入的取值在域内 ≠ 有人按它分支」。
> 今天是死字段；谁按 `source` 写一个分支，谁就会静默落空。

### 3.2 legacy 的 4 个「健康」判定词，3 个不在 `HealthStatus` 的声明取值域里

`state.go:15` 声明 `healthy, warning, degraded, unreachable`，
而 legacy 路径把 `healthy_confirmed` / `probing` / `available` / `healthy` 判为可用。
其中 **`probing`（正在探测、尚未确认）被算作「可用」** —— 把「未确认」读成「已确认」，
方向是 fail-open。只在回退路径可达。

### 3.3 `LastUpdatedAt` 在主路径上是**读取时刻** —— 一条差一步就成活的缺陷

`cache.go:126` 写 `time.Now()`。而 `manager.go:782 GetStaleStates(staleTTL)`
（注释：「获取过期状态（**用于触发自动 ping**）」）正是按
`now.Sub(entry.State.LastUpdatedAt) > staleTTL` 判定过期。
读取即刷新时钟 ⇒ **node 来源的状态永远不会被判为过期**。

**但我没有把它记成活缺陷**：`GetStaleStates` 全仓 **0 个调用方**（只有定义处）。
判据：写「X 会导致 Y」之前先确认 Y 真在同一条控制流上。
所以它是一条**埋着的地雷**而不是现网缺陷：字段看着正常（非零、值合理），
语义在主路径上是错的，一旦有人把那个「用于触发自动 ping」的消费者接上，
过期检测会在 node 来源上**静默失效**。

> 与 §15.4 的 `loadDiscoveryStatus` 同族：消费者是死代码时，
> 上游的语义错误不会暴露，但也不会消失。

## 7. 一条元纪律（本轮新增）

**门是绿的，与门扫过哪些文件，是两件事。**

前七轮把这个盲区打了 5 次（弹层探针漏 `position:static`、读取清单漏 Go 字符串里的表名、
日期判据漏 `KxDatePicker`、降级门漏 42P01 一族、现在又漏 `domains/` 与裸 42P01），
每次都是**同一个动作**：把门扫过的集合当成全集。

所以可复用的做法不是「再检查一遍漏了什么」，而是
**每次写门时都问一句：我的元素集是怎么枚举出来的，那个枚举器覆盖全集吗**——
并且把这个枚举器本身**变成可执行的量具**，让它能在元素集变化时报红。

`--where <族>` 打印任一族的全仓 `file:line`，就是为下一轮省掉这 5 次。
