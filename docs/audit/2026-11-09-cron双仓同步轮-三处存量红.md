**契约来源**：`docs/06-deployment/04-runbooks/operations/REPO-MIRROR-POLICY.md`

`docs/audit/2026-11-02-双仓同步轮-探测启动检查闸门缺口.md` §6。

★ ★ **手段的现行契约 ≠ 字面指令**：`sync-to-github.sh` 的 filter-repo 全量改写
与「镜像保留原始历史」**互斥**，v2.0 起**退役为 `--dry-run` 诊断工具**
⇒ 推 github 走**树移植**：

```bash
TREE=$(git rev-parse origin/main^{tree})
SYNC=$(git commit-tree "$TREE" -p "$(git rev-parse github/main)" \
        -m "sync(codeup): verified gateway main <origin/main sha> —— 树移植自 codeup origin/main")
git push github "$SYNC:refs/heads/main"
```

**验收口径**（§10.1）：`origin/main^{tree}` == `github/main^{tree}`
且 `git diff --stat origin/main github/main` 为空，且 `git ls-remote` 对拍远端真值。

★ 推 github 前三道门（§10.3）：
1. `scan-secrets.sh --mode=normal --paths=. --tracked-only --baseline=…` ⇒ **BLOCK=0** ✅；
2. 审计守卫七包 + `guards-sync.sh` ⇒ ✅；
3. `tests/*.sh` 全量 ⇒ ✅（5 套红 = 既有环境红，已 A/B 实证）。

★ `.githooks/pre-push`（仅对 github 远端生效）默认用 **normal 模式**
⇒ 与 §10.3 第一道门同一口径。
