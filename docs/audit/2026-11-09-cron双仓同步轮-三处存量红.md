### 2.1 `internal/metricguard` 红：运行时长指标声明了却从不记录

**症状**：`mcp_gateway_uptime_seconds` 被 `internal/metricguard` 判为
「已声明但生产代码从不记录」。

**根因**：`mcp/metrics.go` 声明了该 Gauge，但**全仓没有任何 `Set` 调用**
⇒ 它在 `/metrics` 上永远是 0。

**★ 口径订正（实测，不是推断）**：
用 prometheus 客户端 v1.23.2 实测：

| 形态 | promauto 注册后、**未 Set** 时在 `/metrics` 上 |
|------|---------------------------------------------|
| 普通 `Gauge` | **存在，值为 0** |
| `GaugeVec`（没实例化过标签组合） | **ABSENT** |

⇒ 所以「只声明不 Set」对**普通 Gauge** 的真实后果是「**恒为 0**」
（面板上是一条永远平的线），**不是 metricguard 报错文案里写的「ABSENT」**。
本轮已把这条订正写进源码注释（`mcp/metrics.go` / `mcp/server.go` / `mcp/control.go`）
—— ★ 别让下一个读注释的人被那句报错文案带偏。

**修法（接线，不是写进 knownUnwired 兜底）**：
- `NewGateway` 落初值（进程一起来就带上真实起点）；
- `/health` 与 `/healthz` 两个健康端点各刷一次。
  ★ `/healthz` 是**公开探针端点**，部署里被周期性打的是它（`/health` 现在需要
  `mcp.topology` scope，是并行会话 `bde2baa59` 收进能力位的）⇒ 不刷它，
  值会停在最后一次 `/health` 的时刻。

**新增回归门**：`mcp/server_test.go:TestUptimeMetricTracksGatewayUptime`
—— 断言**取值会走**（构造时把 `startedAt` 挪到 1 小时前 ⇒ 期望 ≈3600 而不是 0）。
★ 断言「指标在不在」对普通 Gauge **恒真、没有牙**（它注册即存在）⇒ 那不是门。

**变异臂（2/2 检出）**：

### 3.1 canonical 读点三份产物：行号漂移

**根因**：`53d4e2abd`（11-09 运营审计轮）给 `bg/stats_minute_rollup.go` 加了

`scripts/audit/asset/canonical-read-point-{shapes.json,shapes.tsv}` 与

⇒ `TestTsvHollowoutReadersRejectEmptyRegistry` 红
（`读方在【基线】就红 ⇒ 不可判定`）。

**修法**：按快照文件清单机械重放提取器：

```bash
python3 scripts/audit/extract-canonical-read-point-shapes.py \
  --repo-root . --file-list <.json 的 source_files> \
  --out-shapes scripts/audit/asset/canonical-read-point-shapes.tsv \
  --out-points scripts/audit/asset/canonical-read-points.tsv \
  --json    scripts/audit/asset/canonical-read-point-shapes.json
```

**diff 规模**：12 insertions / 12 deletions，**逐条核对全是行号**
（283/332/352 → 323/372/392），shape_id / SQL 摘要 / 文件清单 / 计数**逐字未动**
⇒ 是「行号漂移」不是「产物语义变了」。
