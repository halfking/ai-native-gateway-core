## §10.0 本轮一句话结论

接线的**真正障碍不在视图**：视图里 125 段硬编码中文只是表层；底下压着
**① 语言包里的「同一批文案两处真值」已经漂移**（zh-TW 19/23、ja-JP 21/23 的键两份副本取值不同）、
**② vue-i18n 的 `t()` 根本不支持数组型消息**（会把键路径逐字符渲染上屏）、
**③ 静态扫描器不剥注释**（注释里的字面量 `t('…')` 会被当成真实引用）。
三件事都先修或先量，再接线。

## §10.2 接线：80 处替换，每处带「原文断言 + 命中次数断言」

**方法**：一次性 Python 脚本，逐条给出「旧串（逐字）→ 新串」+ **期望命中次数**；
任一条不满足即**当场中止**，不做「尽力而为」的半改状态。

**观测值**：RoutingPolicyView 30 处 / TenantModelPolicyPanel 29 处 / KeyApplicationsView 21 处 = **80 处，全中**。

### §10.2.1 顺带修掉的两处 collateral

1. **`FIELDS` 在 setup 期求值 ⇒ 运行时切语言不刷新参数列标签**
   - 原：`const FIELDS: {...}[] = [ { label: t('routing.algorithm_version') }, ... ]`（setup 期求值一次）
   - 改：`const FIELDS = computed(() => [...])`，模板 `v-for="f in FIELDS"` 自动解包
   - **A/B 实测**（worktree 起第二个 dev server，同一探针）：
     - 改前（HEAD）：切到德语后表头仍是「参数/当前值/新值」、参数列首格仍是「算法版本」
     - 改后：表头变「Parameter/Aktueller Wert/Neuer Wert」、参数列首格变「Algorithmus-Version」
2. **公式串写死中文**（`composite_score = 手工序号 + (归一化价格 × 10) + …`）
   ⇒ 改走 `routing.policy.formulaPrefix`（8 语种已译，占位符 `{price}/{session_load}/{failure_penalty}`）。

## §10.4 ★ 语言包的结构级缺陷：「一段块被复制进了错误的嵌套层」

### §10.4.1 发现路径

接 `routing.policy.*` 时发现：`policy.weights` 在 **zh-CN 只有 9 个键，其余 7 个语种 32 个**。
写探测器量全量范围 ⇒ **22 处分歧、7 个文件**，形态完全一致：

| 判据（跨语种结构分歧） | zh-CN | 其余 7 语种 |
|---|---|---|
| `routing.policy.weights` | 9 键 | **32 键** |
| `routing.dashboard.resolve.funnelStages` | 6 键 | 35 键 |
| `sessions.audit` / `sessions.audit.config` | 32 / 40 键 | 94 / 117 键 |
| `sessions.audit.management.*`（11 个路径） | **不存在** | 存在 |
| `dashboard.liveStream` / `nav.item` / `ops.fault` / … | — | — |

**根因**（以 en-US 为例）：`policy:` 块里 `weights: {` 之后，**有一段 23 行的 `policy` 级键的逐字副本**
（缩进 2 空格 vs 兄弟 6 空格）落在了 `weights` 内部 ⇒ 运行时 `policy.weights` 变成 32 键。
**zh-CN 是干净的**，7 个语种是坏的。

### §10.4.2 ★ 它不是「无害的冗余」—— 两份副本**已经漂移**

**方法**：把复制块里每个键的取值与正本（`policy` 级的同名键）逐字比对。

**观测值**（23 个键里取值已不同的个数）：

| 语种 | 已分叉 | 语种 | 已分叉 |
|---|---|---|---|
| ja-JP | **21 / 23** | es-ES | 3 / 23 |
| zh-TW | **19 / 23** | de-DE | 3 / 23 |
| en-US | 11 / 23 | fr-FR | 3 / 23 |
| | | ar-SA | 3 / 23 |

⇒ 「同一批文案两处真值」若不同步，**几个月后就是两份不同的文案同时在跑**。

### §10.4.3 修法与「行为等值」断言

**修法**：删掉复制块（7 语种 × 23 行 = 161 行）。
**判据不是缩进**（en-US 的 `policy:` 子键本来就用 2 空格，缩进不是层级的函数）⇒ **用字符串感知的括号深度**；
「正常组」也不按数量多数判定（复制块 23 条 > 正常 9 条，多数派是复制块）⇒ 按「含 9 个已知权重键名的组」判定。

**行为等值断言**（改文件前后各取一次运行时真值快照，逐字比对）：

```
✓ zh-CN  policy 键 27→26 | 删除 ["savingPolicy"] | 改值 [] | weights 键数 9→9 ✓
✓ zh-TW  policy 键 27→26 | 删除 ["savingPolicy"] | 改值 [] | weights 键数 32→9 ✓
（其余 6 语种同形）
✓ 8 个语种的 policy 运行时真值与改前逐字一致（仅计划内的死键删除）
```

⇒ **界面行为零变化**，只是不再有两份会漂移的文案。

### §10.4.4 顺带收敛的「死副本」（两处真值的另一半）

| 删掉的键 | 为什么是「两处真值」 | 裁决 |
|---|---|---|
| 扁平 `routing.savePolicy/saving/savingWeights/saveFeatured` | 仅 RoutingPolicyView 引用；页内 `routing.policy.*` 那份**已分叉**（de-DE 'Richtlinie speichern' vs 'Strategie speichern'；fr-FR 'Sauvegarder la politique' vs 'Enregistrer la stratégie'） | 收敛到**页内**命名空间（本页其余文案本来就在用它） |
| `routing.policy.savingPolicy` | 与 `policy.savePolicy` 同值的死副本（fr-FR 两者取值本就不同 ⇒ 它是「另一种措辞的死键」） | 删（**判据是「全仓 0 引用」，不是「取值一样吗」**） |
| `tenantModelPolicyPanel.softDeleteConfirm`（扁平） | 与结构化 `confirm.softDelete` 同义；**6/8 语种两份措辞已不同**（en-US 'Soft-delete policy X? (recoverable)' vs 'Confirm soft delete policy X? (Recoverable)'） | 保留**结构化**那份（符合文件自身 `dialog.*/error.*/audit.*` 惯例，且确认弹窗该是问句），删扁平那份 |

## §10.5 ★★ vue-i18n 9 的 `t()` **不支持数组型消息** —— 键路径会被逐字符渲染上屏

### §10.5.1 怎么发现的

接线时用了「数组型语言包键 `routing.policy.tableHeaders` + `v-for`」的写法（依据是 `src/i18n/scanner.ts` 里那句注释：
「Vue i18n 允许 `t('foo.bar')` 返回整个数组供 `v-for` 渲染」）。

**浏览器实测**：表头单元格内容 = `r` / `o` / `u` / `t` / `i` / `n` / `g` / `.` / `p` / `o` / `l` / `i` / `c` / `y` …
⇒ **渲染的是键路径字符串本身**。

**决定性实验**（仓内最小复现，vue-i18n 9.14.5）：
```
t("policy.tableHeaders") → "policy.tableHeaders" | typeof= string | isArray= false
t("policy.title")        → "Routing policy"
```
⇒ **量具的自述（代码注释）是错的**，而且它直接导致了一次上屏回归。

### §10.5.2 为什么现有门全都看不见

- `i18n-audit`（missing key）**看不见**：数组被 `collectLeafKeys` 当作**一个存在的键** ⇒ 0 missing，页面却是坏的
- `localeValueQuality` 的**值级指标也看不见**：`collectLeafValues` 只收字符串 ⇒ 数组**没有任何指标覆盖**
- ⇒ 缺的是「键存在」与「键能被 `t()` 取到」之间的那一位。

### §10.5.3 修法（分两种形态）

| 形态 | 修法 | 用在哪 |
|---|---|---|
| **短列表**（3~6 项表头） | 改成**标量键**（可被全部指标看见） | `routing.policy.table.{param,current,next}`（取值**直接拆自已译好的那个数组**，不引入新译文） |
| **长列表**（5~8 项步骤） | 新增 `i18n.ts` 的 **`localeArray(key)`**（从消息树直取，带 `en` 兜底、随语种反应） | `modulesView.integration.{feishu,wechat,dingtalk}Steps`、`landing.heroPoints`、`public.agreement.points` |

**顺带修掉的 4 处既存违规**（同一缺陷类，此前从未被发现）：
`ModulesView.vue` 3 处 + `OperationAgreementDialog.vue` 1 处 + `LandingView.vue` 1 处。

### §10.5.4 新增门：`scripts/i18n-array-key-guard.mjs`

**判据**：运行时遍历 8 语种全部模块找「值是数组」的键 ⇒ 与 `scanAll()` 的字面量引用求交集 ⇒ 交集即违规。
**自证 5/5**（会触发 ×2 / 不误触发 ×3：标量键、helper 取法、动态拼接键）。
**观测值**：修完后 **数组型键 17 个，被 `t()/tm()` 消费的 0 个 ⇒ PASS**。

### §10.5.5 ★ 数组长度平价（同族，量具顺手抓出来的）

**观测值**：`wechatSteps` / `dingtalkSteps` 的数组长度**在语种间不一致** ——
zh-CN / en-US = **4 项**，其余 6 语种 = **7 / 6 项**（其余 6 语种那份更贴合真实产品流程：含回调 URL、CorpID/AgentID、依赖模块）。

**裁决**：**源语言**（zh-CN/en-US）停在了旧版 ⇒ 把它们**向上对齐**到 7 / 6 项
（以 zh-TW 的繁中版与 ja-JP/de-DE 的结构为参照，逐条对译，不新造流程）。
修完后 8 语种长度一致：`feishuSteps`=5、`wechatSteps`=7、`dingtalkSteps`=6。

## §10.6 ★★ 静态扫描器**不剥注释** ⇒ 注释里的字面量调用会变成「幽灵引用」

**怎么发现的**：给 `localeArray` 写注释时顺手写了 `t('policy.tableHeaders')` 这样的例子 ⇒
`i18n-audit` 立刻报「**缺 4 个键**」：`policy.tableHeaders` / `policy.title` / `some.arrayKey` / `path`。
`key-parity` 同步红（各语种 missing-vs-union +4）。

**为什么既存的同类注释没红**：`walkFiles` 的 `skipDirs` 含 **`i18n` 目录** ⇒
`src/i18n/scanner.ts` 与 `src/i18n/localeKeyParity.ts` 里的 `t('path')` 从来没被扫到；
而 `src/i18n.ts`（**文件**，不是目录）**会被扫** ⇒ 我写在它里面的注释变成了真实引用。

**修法**：注释里写键名时用**不会匹配扫描正则**的形式（`t(<policy.tableHeaders>)`）。
**登记（未修）**：扫描器应当具备「剥注释」能力 —— 本轮只做了规避，**没有**改造 `scanner.ts`
（改造会移动引用集 ⇒ 需重铸多项基线），登记为下一轮项（见 §10.9）。

## §10.11 通用式（本轮沉淀，已写入 `LESSONS.md` §411）

1. **注释里的字面量调用会被静态扫描器当成真实引用** ⇒ 注释里写键名要用不会匹配正则的形式。
2. **「键存在」≠「键能被 `t()` 取到」** —— 数组型消息是 vue-i18n 9 的陷阱；而 missing-key 门完全看不见它。
3. **量具的「自述」（代码注释）也会骗人** ⇒ 前提要单独做实验钉住，并写成一条测试。
4. **跨语种「结构分歧」是独立于取值的一族缺陷** ⇒ 用「同一键路径在不同语种的子键数量是否一致」量，一次能抓出 22 处。
5. **「两处真值」一旦存在就会漂移** ⇒ 实测 23 键的复制块里，zh-TW 19 个、ja-JP 21 个取值已不同。
6. **删死键的判据该问「有没有人引用它」**，不是「取值一样吗」。
7. **接线前先问「这个键的语言包值已经是那个语言了吗」** ⇒ 否则「接线完成」对该语种不成立。
8. **自写解析器会静默吞异常** ⇒ 解析语言包结构一律用仓内运行时量具（`loadLocale`），别用正则。
9. **A/B 要同条件**（同探针、同视口、第二个端口）⇒ 数字才可比。
10. **引用集变了 ⇒ 原始数字不可比** ⇒ 基线人工重铸 + 理由写进 commit。
