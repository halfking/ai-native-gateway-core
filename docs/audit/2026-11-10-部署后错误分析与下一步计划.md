## 下一步优先级建议

### 🔴 P0：候选池健康修复（立即）

**问题**: 75% 错误是候选池为空
**建议**:
1. 检查 `credential_state_nodes` 表（handoff 文档指出该表 **0 行**）
2. 分析为何绑定被标记为不可用
3. 评估是否需要手动恢复部分绑定

**SQL 诊断查询**（建议在 211 上执行）:
```sql
-- 检查哪些模型完全无候选
SELECT 
    canonical_id,
    COUNT(*) FILTER (WHERE available) AS available_count,
    COUNT(*) AS total_count
FROM credential_model_bindings cmb
JOIN model_offers mo ON cmb.model_offer_id = mo.id
WHERE canonical_id IN ('deepseek-v4-flash', 'deepseek-v4-pro', 'glm-5.2', 'kimi-k3')
GROUP BY canonical_id;

-- 检查 credential_state_nodes 是否有数据
SELECT COUNT(*) FROM credential_state_nodes;

-- 检查探针失败的绑定
SELECT 
    credential_id,
    model_id,
    consecutive_failures,
    last_err_code,
    paused,
    available_at,
    unavailable_at
FROM node_probe_state
WHERE consecutive_failures >= 1000
ORDER BY consecutive_failures DESC
LIMIT 20;
```
