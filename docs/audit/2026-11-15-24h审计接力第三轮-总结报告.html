一、结论 / 根因

P1-1D-S4 双路由遮蔽 — 根因：POST /api/v1/plugins/{id}/activate 的 dedicated 单段路由按 Go ServeMux 最长模式优先恒胜出 catch-all 分发，792b0e373/939c89c82/35f27ab0d 三笔交付（supervisor 真实进程编排 + disabled 覆盖层 + 鉴权形态）只在多段畸形 URL 可达；lifecycle 路径从不更新 disabled ⇒ GET /api/v1/plugins 恒报 Enabled=true（UI 开关永不变化）。通用式：同路径双实现并存时交付面落在哪条由 mux 算法决定，不由提交者声明决定；handler 层测试全绿测不出接线漂移。修复：dedicated 路由统一委派 pluginapiHandler（幂等 activate）+ cmd/gateway 源码钉 ×2。
P1-2D-S1 停用被复活 — 根因：手动 deactivate 后 SocketPath 清空 → HealthLoop 连续 2 次失败 → tryRestart → sup.Restart(context.Background()) 把停用进程拉回，停用不持久。修复：HealthLoopConfig 新增 ShouldCheck 门（接 pluginapiHandler.IsDisabled），管理性停用豁免健康检查。
P2D-S2/S3/S6 + 幂等 — Start 无已在运行互斥（并发 activate 孤儿进程）；shadow 路径 request-scoped ctx 启动插件（请求返回即 SIGKILL，exec 探针实证 Z 状态）；eventbus run() 无 recover（订阅者 panic 炸穿网关）；activate 语义分裂（Restart 弹跳 vs Start 二次报错）→ SocketPathOf 非空跳过。
P2-2大 string prompt 422（第四案） — 根因：并行接力轮提交互相矛盾的两套测试（要求缩减成功 vs 把 interim 报错「wrap + reduce not yet implemented」钉为预期）⇒ main 带红测。裁决终态=缩减成功（fail-closed 于可缩减内容=会话砖化，r1051 族语义）：两个拒绝点改走 reduceStringGenerationField（流式摘录、prompt 保持 JSON string 原形）。
死面死面三连（24h 内再现） — autoroute/intent（唯一引用=自身 example_test）、security/multilayer（全仓零引用）、pkg/authplugin/native（零接线）：覆盖率声明属实（78.2%/86.1%）但「Production Ready/三层架构/FP Reduction 40-60%」为目标态写成成果（LLM 层全是 not-yet-implemented 占位符、multilayer「三层」实为单层）。处置：文档订正横幅 + multilayer 补 r1042 git-remote 豁免（拆接线日回归炸弹）+ authplugin UpdateUser 密码字段绕过复杂度校验已修（F-A1 第 N+1 处）。
生产ingress_capacity_exceeded 63 笔/4h 含公网真实用户 — 根因=2026-11-11 登记的 LargeIngress MaxConcurrent=4 默认（槽按请求全生命周期持有）「旋钮待 sizing」债变成用户可见 429。修复=部署引擎四点接线 LLM_GATEWAY_INGRESS_MAX_CONCURRENT + 三台 sizing（211=32/245=64/154=32）。

六、遗留风险（按影响排序）

  • P2SSE /api/v1/plugins/events 无鉴权 + ACAO\* + 无连接上限 — 暴露 plugin_id/pid/启停时序；EventSource 无法带 header 是其动机，改 query-token/cookie 属 Shell 客户端改造 → owner 裁决。
  • P2vendor 内自家子模块手工副本 24 文件（双重真相漂移陷阱）— go mod vendor 被 pre-existing test/f41_activation_validation.go 坏 import 卡死 → 先修 test/ 再重生成。
  • P2pluginapi 半启动态回滚缺口 — enable 成功但 manifest 缺失时 disabled 已删（list 显示 enabled、进程未启动）；boot 失败过的插件经 API 永远激活不了（500 循环）。
  • 裁决死面三连接线前置条件 — intent 若接线需先补齐 5 处语义退化或声明为替代语义；multilayer 与 sanitize 族归并 vs 替换裁决；authplugin 接线面另立轮。
  • 拓扑245→252 跨机房 DB 链路 — 32 并发下路由写超时（routing_database_error）；属部署拓扑约束，容量提升需本地只读副本或池化调优（owner）。
  • 环境基础镜像发布权 403 + 离线库坐标分裂 — registry-211 推送权缺失（与 11-15 轮同结论）；1.27.4 基础镜像靠 docker save|load 直落（本侧）+ 双目录落位（并行侧）双轨并存。
  • 测试mock-only 栈在 245 未闭环 — podman 4.9 短名→远端拉取 + localhost TLS 证书过期 + citus 镜像形态差异；需 podman 环境 variance 修复（--pull=never / 完全限定名已验证可行路径）或回退本地 docker 形态。
  • 观察130dao-cache 上游静默丢上下文（18-19h 突发 113 笔后自愈）— 检测器按设计改判失败；凭据运营复核面。
  • 观察request_stats_* DELETE 族 ~500ms×22/h — NOT EXISTS 表达式不吃索引；NOT EXISTS→GROUP BY 改写候选（下轮优化项）。
