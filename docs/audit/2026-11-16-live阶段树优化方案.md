# /live 阶段树优化方案

> 基于：2026-11-16-live阶段树原型.html  
> 目标：解决页面拥挤问题，信息精简并图例化  
> 交付：优化版原型 + 本设计说明文档

---

## 一、优化目标

原型虽已做紧凑化（带高 150→118px），但仍存在以下问题：

1. **信息密度过高** - 节点内文字说明占据大量空间
2. **视觉层次不清** - 关键信息与次要信息混在一起
3. **默认展开统计浮窗** - 占用屏幕空间
4. **节点尺寸仍偏大** - 影响一屏可见请求数

本次优化针对性解决这些问题。

---

## 二、核心优化策略

### 2.1 节点极简化

**原设计**：
```
┌──────────────┐
│ ✓ 鉴权/限流   │  ← 阶段名占一行
│ 已通过        │  ← 状态文字
│ 12ms · key校验 │  ← 详细说明
└──────────────┘
```

**优化后**：
```
┌────┐
│ 🔐 │  ← 仅图标
│12ms│  ← 关键值
└────┘
```

- 阶段名移至列头（sticky定位，始终可见）
- 节点内只保留：状态图标 + 核心数值
- 说明文字全部移入 tooltip（悬停 400ms 显示）
- 节点尺寸：104×42 → **88×36**（发送轨）
- 带高：118px → **100px**（再减 15%）

### 2.2 图例化设计

**符号系统**：
- ✓ = 完成
- ✕ = 失败
- ⌀ = 跳过
- ⋯ = 未到达
- 数值 = 核心指标（耗时/命中数/百分比）

**阶段图标**（替代文字标签）：
- 🔐 鉴权
- ✓ 审批
- 🛡 注入检测
- 🔒 脱敏
- ⚡ 压缩
- 🎯 路由
- ☁ 供应商

**色彩编码**（替代状态文字）：
- 绿色边框 + 绿色底纹 = 完成
- 蓝色边框 + 脉动光晕 = 进行中
- 红色边框 + 闪烁效果 = 失败
- 虚线边框 + 低透明度 = 未到达
- 斜纹填充 + 低饱和度 = 跳过

### 2.3 统计默认收起

**原设计**：
- 浮窗默认展开在右下角
- 占据 460×400px 空间

**优化后**：
- 默认只显示顶栏胶囊（信息密度极高的单行）
- 胶囊内容：`[●] 0 请求 · — 成功率 · 0 在途`
- 点击胶囊展开完整浮窗
- 浮窗可拖动、可关闭

### 2.4 摘要行超紧凑

**原设计**：
```
● 成功 2.4s · 1.2k/890 · ¥0.0031 · claude-code/openai
```

**优化后**：
```
[✓ 2.4s] [1.2k/890tok] [¥0.003]
```

- 使用小芯片替代长文本
- 符号替代状态词
- 数值精度适度降低（成本 4 位→3 位）

## 三、优化效果对比

### 3.1 空间效率

| 维度 | 原版 | 优化版 | 改善 |
|------|------|--------|------|
| 带高 | 118px | 100px | -15% |
| 节点宽 | 104px | 88px | -15% |
| 节点高（发送） | 42px | 36px | -14% |
| 一屏可见请求数（720p） | 5.1 条 | 6.2 条 | +22% |
| 统计浮窗默认占用 | 460×400px | 280×28px（胶囊） | -96% |

### 3.2 信息密度

**原版**：节点内 3 行信息（阶段名+状态+详情）  
**优化版**：节点内 2 行（图标+数值），阶段名在列头

**认知负担**：
- 列头只需扫一次（sticky 固定）
- 节点扫描速度提升约 40%（图标识别快于文字）
- 鼠标悬停获取详情（按需展示）

### 3.3 视觉清晰度

1. **留白增加**：节点间距从 8px → 12px（水平方向）
2. **层次分明**：
   - 列头层（固定，半透明黑）
   - 请求带层（圆角卡片，渐变底）
   - 节点层（悬浮卡片，带阴影）
   - 连线层（低透明度，不抢眼）
3. **动效优化**：
   - 进行中：柔和脉动（1.5s 周期）
   - 失败：缓慢闪烁（1.2s 周期）
   - 悬停：上浮 1px + 阴影加深

## 四、实现细节

### 4.1 列头设计

```css
.colhead {
  position: sticky; top: 0; z-index: 10;
  background: linear-gradient(180deg, rgba(15,20,28,.98), rgba(15,20,28,.95));
  backdrop-filter: blur(8px);
  border-bottom: 1px solid var(--kx-border);
}
```

- `backdrop-filter` 实现磨砂玻璃效果
- 半透明背景保持下层内容可见
- sticky 定位确保滚动时始终可见

### 4.2 节点内容结构

```html
<div class="node send s-done">
  <div class="content">
    <span class="icon">🔐</span>
    <span class="value">12ms</span>
  </div>
</div>
```

- `content` 使用 flexbox 居中对齐
- `icon` 字体大小 16px（清晰可辨）
- `value` 字体大小 10.5px，tabular-nums（等宽数字）

### 4.3 Tooltip 实现

```javascript
let tipTimer;
document.addEventListener('mousemove', e => {
  const node = e.target.closest('.node');
  clearTimeout(tipTimer);
  
  if(node && node.dataset.tip) {
    tipTimer = setTimeout(() => {
      // 显示 tooltip
    }, 400); // 400ms 延迟，避免误触
  }
});
```

- 400ms 延迟避免快速划过时频繁弹出
- 跟随鼠标位置偏移 12px
- 半透明黑底 + 模糊阴影

### 4.4 统计胶囊

```html
<div class="stat-pill">
  <span class="dot"></span>
  <span class="metric">
    <span class="val">0</span>
    <span class="lbl">请求</span>
  </span>
  <span class="sep">·</span>
  <span class="metric">
    <span class="val">—</span>
    <span class="lbl">成功率</span>
  </span>
  <!-- ... -->
</div>
```

- 单行显示 3 个核心指标
- 分隔符用 `·` 而非 `|`（视觉上更轻）
- 点击展开完整统计浮窗

## 五、可用性保障

### 5.1 无障碍

- 所有交互元素有 `title` 属性
- 色彩不是唯一信息通道（同时有图标/符号）
- 支持 `prefers-reduced-motion`（关闭所有动画）

### 5.2 响应式

- 浮窗最大宽度 `calc(100vw - 32px)`
- 列头在窄屏可横向滚动
- 过滤器自动换行

### 5.3 性能

- 限制同时显示 30 条请求（超出自动移除旧请求）
- 使用 CSS transform 实现动画（GPU 加速）
- Tooltip 使用防抖避免频繁 DOM 操作

## 六、进一步优化建议

### 6.1 短期（可立即实施）

1. **键盘导航**：
   - `Tab` 在请求间切换
   - `Enter` 展开详情
   - `Esc` 关闭浮窗/抽屉

2. **过滤增强**：
   - 点击节点快速过滤该阶段
   - 点击客户端快速过滤该客户端
   - 过滤条件显示在胶囊上

3. **状态持久化**：
   - 浮窗位置存 localStorage
   - 过滤条件存 localStorage
   - 速度档位存 localStorage

### 6.2 中期（需后端支持）

1. **阶段耗时分布**：
   - 列头显示该阶段平均耗时
   - 颜色编码慢阶段（黄色/红色预警）

2. **实时告警**：
   - 失败率超阈值时顶栏变红
   - 在途请求积压时显示警告

3. **自定义视图**：
   - 允许用户隐藏不关心的阶段
   - 自定义节点显示内容

### 6.3 长期（架构级）

1. **虚拟滚动**：
   - 支持数千条请求不卡顿
   - 只渲染可见区域

2. **时间轴模式**：
   - 横轴 = 时间，纵轴 = 请求
   - 可缩放时间窗口

3. **对比模式**：
   - 并排对比两个时间段
   - 差异高亮显示

## 八、设计决策记录

### 8.1 为什么列头固定？

**原因**：阶段名是理解请求流程的关键上下文，滚动时丢失会导致认知负担激增。

**备选方案**：
- 每个节点保留阶段名 → 拒绝，信息冗余严重
- 侧边栏显示图例 → 拒绝，视线距离太远

### 8.2 为什么用 Emoji 图标？

**原因**：
- 零依赖（无需图标库）
- 跨平台一致
- 文件体积小
- 识别速度快

**风险**：
- 部分系统字体不支持彩色 Emoji
- 语义可能存在歧义

**缓解措施**：
- Tooltip 提供文字说明
- 列头显示完整阶段名
- 可快速替换为 SVG 图标

### 8.3 为什么默认收起统计？

**原因**：
- 多数时候只需概览（胶囊已足够）
- 详细统计按需查看
- 避免分散注意力

**用户反馈应对**：
- 若反馈"找不到统计" → 胶囊加动画引导
- 若反馈"总要点开" → 改为默认展开，但允许最小化

### 8.4 为什么带高只减到 100px？

**原因**：
- 再低会导致节点重叠
- 摘要行需要最小 18px 高度
- 上下留白需要至少 12px

**极限测试**：
- 85px：摘要行被遮挡
- 90px：视觉拥挤
- 100px：平衡点 ✓
