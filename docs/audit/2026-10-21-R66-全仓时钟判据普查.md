## §0 一句话结论

**全仓 53 处时钟判据，其中 42 处（79%）是「兜底型上界」**（判「不能太慢」），
**只有 11 处是「判别型下界」**（判「不能太快」）+ 2 处双边。
⇒ ★★ **风险面比 handoff 预估的窄得多**，但**唯一一处「余量为零」的真缺陷被测出来了**：

`admin/distlock/lock_test.go` 的 follower-TTL 判据，

⇒ **余量按构造为零** ⇒ 实测 10 次的自然值 ∈ **[200.03ms, 201.64ms]**

⇒ 已修（下界改成「粗判意图」的 50ms，判别职责交给行为断言），
并落了一道**静态门**把这一类**变成可机械检出**（`internal/clockguard`）。

## §1 普查口径

- **扫描面**：全仓 `*_test.go`（排除 `.git` / `vendor` / `node_modules`）；
- **形态**：`elapsed / took / dur / duration / latency` 与数字阈值的比较；
- **剔除**：注释里出现的字样、散文中的 “took >30min”、以及**比值型**断言
  （`warm.dur > 3*cold.dur` —— 它对负载免疫，不属本族）；
- ⇒ **53 处**（原始 grep 命中 62 行，剔除 9 行非断言）。

### §1.1 分档（按阈值量级）

| 档 | 阈值 | 处数 | 性质 |
|---|---|---|---|
| A | ≤ 300ms | 16 | 亚秒，最容易贴边 |
| B | 300ms ~ 1s | 12 | 亚秒 |
| C | 1 ~ 5s | 13 | 秒级，宽松 |
| D | > 5s | 9 | 兜底 |

### §1.2 ★★ 分型（本轮最有价值的一步：**按「判别职责」而不是按阈值大小**）

| 型 | 判什么 | 处数 | 负载敏感性 |
|---|---|---|---|
| **兜底型上界** | 「不能太慢 / 不能挂死」 | 42 | 低（阈值通常 ≫ 自然值） |
| **判别型下界** | 「不能太快 / 确实等到了」 | 11 | ★ 取决于「下界凭什么保证」 |
| **双边** | 同时判「太快」与「太慢」 | 2 | ★ 至少一侧贴边 |

⇒ ★★★ **判别型下界的安全条件**（本轮的新结论）：

> **当下界所比较的自然值由「定时器 / ctx deadline」保证时，它是安全的** ——
> 定时器只会**晚**触发、不会早 ⇒ 下界恒成立。
> **当自然值是「从同一个时钟派生出来的读数」时，它就不安全** ——
> 例如用 Redis **PTTL**（毫秒分辨率）武装的过期看门狗，
> 再拿 `elapsed < 那个 TTL` 去比 ⇒ 余量 = 读数分辨率 ⇒ **趋于 0**。

⇒ ⇒ ★★ **这就是 distlock 那处的病根**。

## §2 ★★★★ 实测：唯一一处「余量为零」的真缺陷

### §2.1 机制

`admin/distlock/lock.go`：
- `:152` follower 拿的是 **`PTTL` 剩余量**（不是请求的 TTL）；
- `:167-168` `newFollowerHandle(…, remaining, …)` + `startRedisWatcher` ⇒
  看门狗定时器 = **remaining**（毫秒分辨率的读数）；
- 测试里下界写的是 **`elapsed < 200ms`**，而 200ms 正是**同一个 TTL 字面量**。

⇒ ⇒ **余量 = PTTL 读数与 TTL 的差** ⇒ 亚毫秒。

### §2.2 实测（10 次连跑，探针文件测完即删）

```
run 0: elapsed=200.712375ms   run 5: elapsed=200.796750ms
run 1: elapsed=201.004208ms   run 6: elapsed=200.785584ms
run 2: elapsed=200.105500ms   run 7: elapsed=201.635250ms
run 3: elapsed=201.136916ms   run 8: elapsed=200.571708ms
run 4: elapsed=200.139833ms   run 9: elapsed=200.034958ms
```

⇒ **最坏余量 0.03ms**（run 9：200.034958ms 对 200ms）⇒ 自然值的 **0.015%**。
⇒ ⇒ 任何让 PTTL 读数早一亚毫秒的扰动（另一个 Redis 版本、时钟粒度、
慢机器上的取整方向）⇒ **假红**（follower 行为完全正确，门却判它「等太短」）。

### §2.3 修法（判别职责归行为断言，时钟只做粗判 + 兜底）

- **它想表达的两件事**：
  1. 「它确实是等到 TTL 才放弃」⇒ **已由 `errors.Is(err, ErrTTLExpired)` 证明**
     （该错误只可能来自 TTL 定时器）⇒ **下界是冗余的**；
  2. 「它没有瞬间放弃」⇒ 用 **50ms** 表达（自然值 ≈200ms ⇒ **4× 余量**）。
- ⇒ 改动：`elapsed < 200ms` ⇒ `elapsed < 50ms`（上界 1500ms 不变），
  并把**实测的噪声底**写进注释（仓内既有的写法，见
  `scripts/ursmcheck/monitor_scheduling_semantics_test.go:155-169`）。
- ⇒ **判据没有被削弱**：行为断言（`ErrTTLExpired`）一字未动。

## §3 ★★ 新门：`internal/clockguard`（静态可检的「零余量下界」代理）

### §3.1 为什么这道门能机械化

「余量为零」在静态上等价于：**下界的字面量 == 同一个测试里被等待的时长字面量**。

⇒ 扫描器（`scan.go`，`go/ast`）：
1. 在每个测试函数里收集**等待时长**（`TTL:` / `Timeout:` / `Deadline:` / `Delay:` 等字段，
   以及 `time.Sleep(...)` / `SleepWithCtx(...)` / `context.WithTimeout(...)` 的实参）；
2. 收集**时钟下界**（`elapsed < 200*time.Millisecond` 形态）；
3. 两者**数值相等** ⇒ 零余量 ⇒ 报红。

### §3.2 门的三条判据

| 门 | 钉什么 |
|---|---|
| `TestNoClockAssertionHasAZeroMarginLowerBound` | 全仓不得出现零余量下界 |
| `TestScannerSkipsItsOwnPackage` | 扫描器不得把自己的夹具报出来 |
| `TestScannerIsNotSilent` | ★ 扫描到的测试文件数 < 50 ⇒ 显式红（防止「扫了个寂寞」） |

⇒ 扫描器**自证有牙**（`scan_self_test.go`）：正例（零余量 ⇒ 必须被报）、
反例（粗判下界 ⇒ 不得被报）、反例（不同的等待时长 / 非时钟比较 ⇒ 不得被报）。

### §3.3 变异验证

| 变异 | 期望 | 读数 |
|---|---|---|
| M1 把 distlock 的下界改回 `200ms` | 门红 | ★ **红**：`admin/distlock/lock_test.go:165 (TestRedisManager_FollowerTTLExpired): clock lower bound "200 * time.Millisecond" on "elapsed" equals the duration this same test waits for (TTL) ⇒ margin is ZERO by construction` |
| 还原 | 门绿 | ★ 绿（md5 逐字核对） |

## §4 ★★ 一处**被推翻**的怀疑（阴性结论也要当缺陷一样复核）

初看 `internal/streamretry/retry_test.go:339` 的 `elapsed < 5ms`（10ms 基准延迟）：
注释自己写着「with jitter, might be less」⇒ 怀疑抖动下限低于 5ms ⇒ 会假红。

⇒ ★★ **读实现推翻了这个怀疑**：`internal/streamretry/retry.go:249-252`
的抖动是 **±20%**（`jitter := delay * 0.2; jitterMs := jitter * (2*rand-1)`）
⇒ 10ms 基准的实际延迟 ∈ **[8ms, 12ms]** ⇒ **下界 5ms 有 3ms 余量** ⇒ **安全**。

⇒ ⇒ ★ 与 R61 那次一样：「按名/按形状的初判」必须回到**实现**去核。

## §5 ⚠ 诚实边界（本轮**没做完**的）

1. ⚠ **满载下的「全量」连跑实测本轮未完成**：
   原本的计划是「32 个忙循环 + 10 个包 × `-count=20`」，
   但 `admin` 单包 `-count=20` 就要 ~19 分钟 ⇒ **主动中止**。
   ⇒ ⇒ **本轮不声称「全仓所有包在满载下无假红」**。
2. ✅ **但「判别型」这一类的定点实测已完成**（宿主本底 load **68/16 核 = 超载 4.25×**）：
   判别型 11 处所在的 **7 个包各连跑 5 轮**
   （`admin/distlock` / `internal/probeutil` / `internal/streamretry` / `internal/dbx` /
   `domains/dispatch` / `domains/ursm/v2/migration` / `domains/streaming` 的双边判据单跑 **20 轮**）
   ⇒ ⇒ **全部全绿** ⇒ 与「安全条件」的推导一致：
   ★ **除 distlock 那处（余量按构造为 0）外，其余判别型判据在 4.25× 超载下未假红。**
   ⇒ ★★ **注意这与 distlock 那处并不矛盾**：那处的余量是 **0.03ms**，
   4.25× 超载**未必**能把 PTTL 读数推早一亚毫秒 ⇒ ⇒ **它要靠「余量为零」这个结构事实来暴露，
   不能靠「跑够多次就会红」来暴露** ⇒ ⇒ **这正是必须落静态门的原因。**
2. ⚠ **只有 1 处被改**。其余 10 处判别型下界**经读实现判定为安全**（依据：
   定时器/deadline 只晚不早 ⇒ 下界恒成立；或余量 4~5×），
   **未逐一实测** ⇒ 登记为「已分析、未实测」。
3. ⚠ **上界（兜底型 42 处）没有逐条量噪声底** —— 判据是「阈值 ≫ 自然值 ⇒ 宽松」，
   这是**结构性判断**，不是实测。
4. ⚠ **本轮只动测试面**（`admin/distlock/lock_test.go` 一处断言 + 新增 `internal/clockguard/`）
   ⇒ **对生产零影响**，部署风险为零。
