## 4. 判据定稿

### 4.1 accent 的四个落点

| 落点 | 判定 |
| --- | --- |
| `value` | 巨数字的计算色命中主色集 |
| `bg` | 卡底计算色命中**主色淡染集** |
| `border` | 四边描边任一命中主色集 |
| `shadow` | 阴影串里含主色 |

★ **主色淡染集 = token 精确匹配**：`--accent-soft` / `--primary-soft` / `--kx-primary-soft`
的**实测计算值**。★ `--bg-subtle` **不进**淡染族（★ 暗色模式下它是 `--kx-sidebar`，
按 token 名收会误报）⇒ 但它**浅色模式的计算值与淡染集同值** ⇒ **靠色值同值命中**。

### 4.2 色值解析要覆盖浏览器的实际输出形态

★ 实测有指标格的计算底色是 **`color(srgb …)`**（Chrome 对 `color-mix()` / 相对色的形态）
⇒ 旧版 `parseRgb` 只认 `rgb()` ⇒ **那些格子的底色对量具等于不存在**。

### 4.3 探针要收「所有后代自身的直接文本」

★ 旧口径只收**叶子元素**的 `innerText` ⇒ 值为「文本 + `<small>` 单位」的容器
（如 `mini-card__value`）自己有子元素 ⇒ 不是叶子 ⇒ **它的值整个消失** ⇒
量具看到的是「标签是巨数字」，量到的根本不是那个值。

★ 配套：**探针带版本号**（探针是跑在浏览器里的一段字符串 ⇒ 自证测不到它的 DOM 行为
⇒ 门读回版本号并与常量比对 ⇒ 改了探针却忘了改版本号 ⇒ 门立刻红）。
★★ **本轮探针回报口径变了（加了 `bodyTextLen` / `elementCount`）⇒ 版本号已 bump
到 `hero-metric-probe/2026-10-28-36-2`。**

### 4.4 ★ 「没量到」与「量到 0」必须分得开（★ 本轮当场抓到一个假红）

★ 本轮给门加第五道闸「空页面 ⇒ 判红」，第一版判据是 `totalCells === 0`
（★ 探针一个盒子都没看到）⇒ 真跑全量时**立刻报红**：`/admin/data-lifecycle/migration-state`。

★ 查证：那页**确实渲染了**（内容「存储迁移状态 / 空闲 / 刷新 / **暂无迁移记录**」，
元素 62 个、可见文本在）⇒ ★★ **它只是一个真空状态页，没有任何卡片状盒子** ⇒ **假红**。

★★★ **⇒ 根因：量具的「候选规则」本身就是一个【有偏的抽样框】⇒ 「0 个候选格」≠「页面没内容」。**

★ **修法（判据收窄）**：`totalCells === 0` **且** `bodyTextLen === 0` ⇒ 才判红。
★ ★★ **⇒ 这是「0 命中」的第八种读法：「量到了，但量具的抽样框不认这种页面」。**

★★★★ **但两道浏览器尺的「候选格」判定都是「有底色 或 四边描边」**
（`design-hero-metric-runtime-check.mjs` 与 `design-metric-skeleton-runtime-check.mjs` 同款）
⇒ ⇒ **拆掉底色与描边 ⇒ 这 4 格不再是候选格 ⇒ 从两把尺的分母里消失** ⇒

- ① **前后读数不可归因**：post-fix 的「0 处」里混着「它已经不是指标格了」这一层；

「门坏了」，第二读法是「靶点消失了」，★★ **第三读法（本例）是「靶点被我自己这道修法移出了分母」**。

#### 5.1.2 正解（★ 相对修法前只有一行实质差异）

★ `--card` = `var(--kx-surface)` = **#ffffff**（浅色模式）⇒ 中性表面色，与本页其它 `.card` 一致
⇒ ★ **不是**主色淡染（淡染集是 #eaf0ff）⇒ accent 落点归零。

**「盒子染了品牌色」**，不是「有盒子」。
