## 1. 四个问题的答案（一句话版）

1. **是什么**：ASM（ai-session-manager）的**会话分析 agent**——`session-analyzer` worker 从 `session_agent.work` 队列取会话，经 Pi Agent runner（`grounded-session.v1.yml` / `grounded-session-budget.v1.yml` 流程：prepare→extract→validate / +critique→refine）调 LLM 产出 title/intent/outcome/findings；每次**物理模型尝试**一个独立网关会话 `gw_asm_agent_<sha256(invocation,step,attempt)>`（`X-Gw-Task-Id: asm-session-agent-v1`），所以「一个分析」在网关侧表现为多条会话。
2. **来源于哪里**：211 上 `asm-session-agent-worker-1`（Go worker）＋ `asm-session-agent-runner-1`（Pi runner），runner 经**公网入口** `https://llm.itestu.cn/v1` 回调网关，用的 API key 是 **id=105 `sk-jybFTc1****`（owner_user=`[REDACTED:account]`，remark=`deploy-smoke-245-20260815-160010`「245 promotion authenticated smoke key」，`rate_limit_rpm=0` 无限流）**——2026-08-15 为 245 晋升冒烟铸造的部署凭据被挪作生产业务流量。11 月网关侧按来源 IP：172.21.0.9（freellmapi 容器，`FREELLMAPI_GATEWAY_URL=https://llm.itestu.cn`）26,667 次、172.21.0.8（asm runner）311 次，同 key。
3. **有无必要**：会话分析本身是产品功能（曾正常跑 minimax-m3）；但当前形态有四个真问题：**① 模型被钉死在 glm-5.3**（`AGENT_MODEL=glm-5.3`），而 glm-5.3 全库 14 条绑定**只剩 1 条可路由**（凭据 62 `zipu-max-account2`，智谱 coding 套餐）；**② 该凭据上游配额已耗尽**（429 code 1310「您已达到每周/每月使用上限，您的限额将在 2026-11-07 01:00:00 重置」）＋ 凭据 29 的 429「1分钟内最多请求30次，**包括失败次数**」；**③ worker 无全局熔断**：job 级退避（runner_unavailable 5min / agent_upstream_unavailable 1h）只推迟单个任务自己的下次尝试，1 秒 claim ticker 立刻去拉下一个任务 ⇒ 死模型期间整个队列被全速循环打网关（实测 60 次/分钟持续近 4 小时）；**④ 日预算阀被显式关闭**（`AGENT_DAILY_TOKENS=0`，`budget.go` 明写「A zero limit disables the daily cap」）。
4. **能否换 glm-5.3-flash**：**不能解本问题**。glm-5.3-flash 可路由的两条腿：凭据 62＝**同一智谱账号同一配额墙**（14:10 探针同文案 429 1310、同样 11-07 01:00 重置）；凭据 99023（freellm-unified，free 档）探针时好时坏（13:30/16:31 503「no configured provider key」，18:04 成功）。**健康替代是 minimax-m3**：11 月 2,444 次 99.2% 成功、独立供应商、已是 runner 注册首模型（`RUNNER_MODELS=minimax-m3,glm-5.3`）与 worker 代码默认（`env("AGENT_MODEL","minimax-m3")`）。
