## §2 ★ 中心产出：一道门的承诺是假的

### §2.1 决定性实验（★ 本轮唯一真正改变结论的一步）

`db/request_logs_view_schema.go` 的 `SessionFamilyLatestTurnPerSessionSQL` 里有一个内层闭包：

```go
leg := func(src string) string {
    return "(SELECT l.session_id, l.turn_no, " + SessionFamilyAPIKeyIDExpr + " AS api_key_id " +
        "FROM (SELECT session_id, max(turn_no) AS turn_no FROM " + src + " t " + ...
}
return "(" + leg("public.session_turns_hot") + " UNION ALL " + leg("public.session_turns") + ")"
```

★ 把它改成：

```go
return "(" + leg("public._request_logs_hot") + " UNION ALL " + leg("public.session_turns") + ")"
```

⇒ ★★★ **本工具整包绿**（它解析不出 `src`，分类仍是 unresolved）、
⇒ ★★★ **admin 的 v1 族全套门绿**（`TestNoLiveV1WriteOperations` / `TestNoLiveV1FunctionCalls` /
`admin/request_logs_indirect_readers_test.go` / `admin/request_logs_bodies_retirement_gate_test.go`
等，`go test ./admin/ -run 'RequestLogs|V1|Retirement|IndirectReader'` ⇒ **ok 68.033s**）、
⇒ ★★★ **例外台账仍是空的** ⇒ 而那份台账（`admin/session_family_sql_shape_test.go:356`）
自己写着：「★ 2026-10-20：**已清空**（基线 4 → 0）… ⇒ 例外表清空 ⇒ 本门变成**最锐**的那条：
『admin 生产代码里**一个** v1 引用都不许有』。将来谁再写回 `_request_logs` / 那两张包装视图，**本门立即红**。」

⇒ ⇒ ⇒ ★★★★ **那句话是假的**：不是「还没查」，是「**查不出来**」。

### §2.2 两个洞的精确刻画

| # | 洞 | 为什么看不见 | 谁能看见 |
|---|---|---|---|
| **洞 1** | `FROM public._request_logs_hot`（**带 schema 限定**） | `retiredV1ReadPattern` = `\b(?:from\|join)\s+(关系名)\b` ⇒ 关系名必须**紧跟**动词 ⇒ `public.` 打断它 | ★ 无 |
| **洞 1'** | `FROM ONLY _request_logs_hot` | 同上（`ONLY` 限定） | ★ 无 |
| **洞 2** | `"FROM " + "_request_logs_hot"`（**关系名在另一个字面量**） | 扫描器**逐行**扫源码；`FROM ` 与关系名被 `" + "` 隔开 ⇒ 不匹配 | ★ 无 |
| **洞 3** | 关系名由**形参**决定（`leg(src)`） | 工具解析不出 ⇒ unresolved 桶；门只统计「同一个字面量里的 from/join + 关系名」 | ★ 无（且 `admin` 那道门根本不认识 unresolved 桶这个概念） |

★ ★★ **洞 1 / 洞 2 之所以是真缺口而不是理论风险**：
**本仓自己的写法就是 `public.` 限定**（会话族源一律 `public.session_turns_hot`），

⇒ ★ 「按本仓惯例写出来的 v1 读点」**必然**逃过这两道门。

## §4 诚实边界

1. ★ **新门不是「解析器」**：它**不**解析形参的取值，而是**禁止**那些文件里出现 v1 关系名。
   ⇒ 它**保守**（可能漏掉「从别的文件传进来」的 v1 名）⇒ ⇒ **那条路仍需那个文件的门来管**。
   ★ 但**跨文件传参**本身在 Go 里需要一个显式的实参字面量 ⇒ **那个字面量所在文件**若在
   unresolved 桶里 ⇒ 被本门抓住；若不在 ⇒ 那条拼接点**解析得出来** ⇒ 由本工具的
   reads-v1 桶负责。⇒ **两条路合起来没有缺口**（前提：拼接点的关系名最终来自一个字面量）。
2. ★ **例外台账是空的** ⇒ 本门目前是「一条都不许有」；将来若确有正当引用，须具名并写理由。
3. ★ **`retiredV1OnlyRelationNames` 与 admin 侧 `retiredV1RelationNames` 是两份并列清单**
   （跨包共享 `package main` 的变量做不到）⇒ ★ **已知的轻微重复**，两处各自维护。
4. ★ **本轮没有做任何生产侧动作**：无 SQL、无发版、无 211/252 读写。
5. ★ **`db/request_logs_view_schema.go` 的 2 处仍落在 unresolved 桶**（工具解析不出形参）
   ⇒ ⇒ ★ **「unresolved 桶非空」本身不是缺陷**，但它意味着**那一类读点永远需要人读源码**。
