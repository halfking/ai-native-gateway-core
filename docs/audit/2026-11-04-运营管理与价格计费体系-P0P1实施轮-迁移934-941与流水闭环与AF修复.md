## 3. W2-T2/T3：流水闭环 + 单位口径

- **写入**：`writeLedgerWithBalanceDetail`（11 参）——七写点逐个过：consume×3（带五因子 detail + ownerUser）、subscribe/topup/adjust（走 legacy 包装 = 空三参，行形状与 935 前逐字节一致）、coupon（detail 带 coupon_id/code）、campaign redeem（**campaign_id 双写**）。
- **五因子 detail**：`{rate_in, rate_out, tokens{p,c,cr,cw}, discount, rate_multiplier}`（`ledgerDetailJSON`）——「我为什么被扣这些积分」可对到行。
- **owner 贯通**：`ChargeRequestMultimodalWithMultiplier` 加 `ownerUser` 形参（唯一生产调用点 handler.go 扣费处传 `keyOwner`，与 `api_key_owner_user` 遥测同源）⇒ 流水 owner 与请求归属永远一致。
- **两臂并读**：`ListLedger` 与 `ReconcileTripartite` C 侧改 `FROM credit_ledger_with_current_month`（935 扩列 + security_invoker）——AF-3 的读侧修复。
- **AF-1 修复**：`consumption_detail.go` 查询带出 `currency_display`；`TenantRevenueUSD` = credits×cents/100 折**账单币种元**，CNY 再除 `settings.CNYToUSDFX`（=7.2 记账锚点）；`GrossMarginUSD` 不再混币种。

**A/B 留档（口径修复的量化）**：currency=CNY、cents=0.01 时，旧口径 `TenantRevenueUSD` = credits×0.0001（把 CNY 分当美分）；新口径 = credits×0.01/100/7.2 = credits×0.00001389。**两者比 = 7.2×**——与设计档「假毛利偏大约 7.2 倍」逐字吻合。生产 buckets=266 行但流水 0 ⇒ 现网 `TenantRevenueUSD` 本就为 0 ⇒ 修复对现网读数零扰动（真库 A/B 在部署后 §5 复测）。
