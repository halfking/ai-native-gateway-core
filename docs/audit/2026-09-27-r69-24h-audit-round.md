### F1（P2）750 迁移预建通道时区缺陷 —— 函数级 SET 钉扎 + 上海日历预建

- **实锤**（D07 子代发现#1，主代理复核 750:57-58/115-116 + runner.go:288→296 成立）：750 文件自身的预建 SELECT 发生在 751 应用**之前**，且用会话时区 `current_date` + DECLARE 初始器 `p_date::timestamptz`——UTC 会话执行本文件时预建出边界错位 8h 的日分区；此后 boot/tick 按分区名幂等短路（pg_inherits 检查只看 relname），错位永不自愈，且与后续上海日历分区相邻日重叠、ATTACH 必报 overlap 事务回滚。installer compose 的 citus 服务未设 TZ，全新安装是真实触发面；751 的 ALTER 钉扎救不了 750 自己的预建调用。
- **修法**：750 函数定义直接带 `SET timezone = 'Asia/Shanghai'` 子句（proconfig 在函数入口生效、先于初始器，canonical 单文件自洽，不依赖 751 先行）；预建日期改 `(now() AT TIME ZONE 'Asia/Shanghai')::date`（与 db.go ensure / partition_manager tick 同源）。750 未部署消费（db-changelog 无行），原地修订有 1dfe88c08 先例。
- **钉桩**：migration_750_test.go 新增 C9（SET 子句存在 + 上海日历派生 ×2 + 禁 current_date）。
