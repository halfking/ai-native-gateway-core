## 经验教训

### 1. 配置管理

**教训**：双配置文件（/etc 和 /opt）导致不一致，部署脚本修改了后者但未同步前者

**最佳实践**：
- 确立单一 SSOT（/etc/llm-gateway-go/env）
- 部署时自动同步到运行时位置（/opt）
- 禁止手动修改运行时配置

### 2. 诊断方法论

**教训**：初次诊断时从运行进程读取到 211 DB，但未核对配置文件历史

**方法论**：实证三角验证
1. 配置文件内容（/etc + /opt）
2. 进程实际环境变量（/proc/{pid}/environ）
3. 实际连接测试（psql 验证）

### 3. 密码管理

**教训**：252 密码变更未同步到 245/154

**建议**：
- 密码变更时同步更新所有依赖方
- 使用密钥管理服务（Vault / AWS Secrets Manager）
- 部署前自动验证数据库连接

### 4. Base64 编码陷阱

**教训**：凭据密钥末尾 `=` padding 丢失导致解密失败

**防护**：
- 密钥复制时使用引号包裹
- 验证密钥长度（Base64 长度必须是 4 的倍数）
- 自动化测试检测密钥完整性

### 5. URL 特殊字符

**教训**：数据库密码中的 `@` 和 `#` 未编码导致解析失败

**规范**：
```
@ → %40
# → %23
$ → %24
& → %26
/ → %2F
: → %3A
```
