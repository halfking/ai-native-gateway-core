## 2. 词表设计（Phase B）

### 2.1 四支 token（唯一定义处：`web/src/style.css`）

| token | 浅色 | 暗色 | 语义 |
|---|---|---|---|
| `--kx-shadow-xs` | `0 1px 2px rgba(30,55,100,.06)` | `0 1px 2px rgba(0,0,0,.28)` | 贴面：选中态标签、探测标记 |
| `--kx-shadow-sm` | `0 8px 24px rgba(30,55,100,.06)` | `0 8px 24px rgba(0,0,0,.28)` | 浮起：弹层、下拉、吸顶条、品牌 logo |
| `--kx-shadow-md` | `0 16px 40px rgba(30,50,90,.10)` | `0 16px 40px rgba(0,0,0,.40)` | 覆盖：模态、对话框、用户菜单 |
| `--kx-shadow-md-left` | `-12px 0 32px rgba(30,50,90,.10)` | `-12px 0 32px rgba(0,0,0,.40)` | 侧向覆盖：右侧抽屉、侧向面板 |

三条设计决定：

1. **几何沿用仓内既有主流值**，不发明数值 ⇒ 视觉差异接近零，收益全在工程一致性。
2. **色相统一为蓝调黑**（现状纯黑阴影本身是 AI 痕迹）。
3. **alpha 只分两档**（浮起 `.06` / `.28`，覆盖 `.10` / `.40`）——
   级别之间的区分靠**锐度**（模糊半径）而不是浓度。
   加浓会让暗色主题糊成一片，级别就消失了。

### 2.2 令牌双轨（Phase A 读数，保留存档）

仓内另有 49 个旧阴影相关变量：**42 个可无损替换**，**7 个需处理**
（`--bg-subtle` 跨主题语义不同、`--bg-hover`、`--bg-secondary`、`--bg-tertiary`、
`--error-bg`、`--cyan`、`--border-muted`）。
这 7 个全是派生值（`color-mix`），且 `--bg-subtle` 浅色=primary-soft / 暗色=sidebar
⇒ **机械替换会改语义**，需产品/设计判断。**本轮未动。**

## 6. 门的三处盲区（本轮新发现，全部真实）

第 17 增量的 `aiSmells.ts` 在本轮暴露三处**假绿/漏判**：

### 6.1 V1 在全部 17 处 `var(--kx-shadow-*)` 元素上假绿

V1 要判「这层是不是抬升」⇒ 需要**偏移**；而偏移搬进 token 之后，
静态判据从 `var(...)` 里**取不到** ⇒ 合规元素在门上「不可见」。

**修法**：新增 `ELEVATION_TOKENS` 名单 + `isElevationToken()`，
「`--kx-shadow-*` 一律是抬升」写进代码，名单**只放一处**
（`aiSmells.ts` 导出，`elevation.ts` re-export）。

### 6.2 V7 硬偏移漏判

V7 的正则要求第 2 段**必须带 `px`** ⇒ `-1px 0 0 0 var(--accent)`
（零模糊 + 有偏移）漏判。
**修法**：逐层判；长度单位可省略。

### 6.3 V1 把「单边描边」当「闭合描边」

**修法**：`hasVisibleBorder` 改为只认**闭合**描边 ⇒ 4 处假阳性消除。

### 6.4 V7 只取块内第一条声明（真仓变异臂 M3 抓到）

同块第二条 `box-shadow` 完全看不见。
**修法**：抽出共享原语 `boxShadowDeclarations(body)`（返回 `{value, offset}[]`），
V7 与 `elevation.ts` **共用同一个遍历器** ⇒ 「块内所有 `box-shadow` 声明」只有一份口径。

⇒ `aiSmells.ts` 自证 **45 → 51/51**。
