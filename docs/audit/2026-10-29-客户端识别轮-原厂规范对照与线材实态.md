## §2 线材实态订正（firehose 实证）

**ZCode 3.x 是 Claude Code 分支版**：2MB 级 request（rid 9a7fbef3…，
UA `ZCode/3.16.3 ai/6.0.193 …`）body **完全没有 `metadata`**，工具名是
Claude Code 2.x 原名（`Agent`/`AskUserQuestion`/`Bash`/`CronCreate`/
`CronDelete`/`CronList`…），**没有 `zcode_*` 命名空间工具**。规范档的
「特征参数」章节（metadata 3 键 + zcode_* 工具）是 2026-09-21 老一代形态，
3.x 未复现 ⇒ body 标记对现役客户端永不命中，**UA 是唯一活信号**。

两个直接推论：① **不得按工具名识别**（分支共享同一工具集，按工具识别
会把 ZCode 误报成 claude-code 或反之）；② body 侧 metadata 规则保留作
向后兼容。`docs/client-formats/zcode.md` 已补订正块。

## §3 三处修复

1. **claude-cli + beta 旗标**：两张 UA 表补 `claude-cli` token；streaming
   链在 UA 未命中后增认 `Anthropic-Beta: claude-code-`（Anthropic 自家
   Claude Code 命名空间，普通 SDK 不带——旗标命中是有意的自我标识而非
   SDK 指纹）。
2. **识别链收敛**：检测逻辑进 `clienttype.DetectFromRequest`（优先级
   X-Gw-Client-Type → UA token → beta 旗标，与原 streaming 表一致）；
   `streaming/client_fingerprint.go` 与 `executors/executor.go` 两处改为
   薄委托。executors 的「行为一致镜像」副本**事实已漂移**（缺 ㊹ 的
   minimaxcode，缺 claude-cli = nativePairFor 兜底路径同盲）——「必须保持
   行为一致」的注释契约无任何执行机制 ⇒ 结构性收敛（一份实现）。
3. **`clienttype.HasToken` 双边界匹配**：前后字符均非小写字母数字才算
   命中。修形近词误报：`MiniMaxCoder/1.0` 不得命中 minimaxcode、
   `ZCodex/2.0` 不得命中 zcode（也不得抢在 codex 前）、`visualized/2.0`
   不得命中 zed。`/`、`-`、空格、串尾天然是边界。

## §7 通用式（详见 LESSONS §551）

1. 识别档案是快照，客户端会改版——判据要和生产 UA 分布定期对账（本轮
   第二例：claude-cli；第一例：MiniMaxCode）。
2. 「行为一致镜像副本」注释契约没有执行机制 = 漂移是时间问题——把检测
   收敛成一份实现，让「只改一张表」成为结构保证。
3. 分支共享形态（ZCode 3.x = Claude Code 工具集）意味着【按内容识别】
   在分支生态里系统性不可靠——识别锚点要选厂商独有信号（UA token /
   官方 beta 旗标）。
4. 形近词负臂是识别测试的必选项——裸 token 子串匹配的误报不命中正例
   也会命中形近词。
5. 验证矩阵的判定面是【出站 body】不是【HTTP 态】——上游故障窗里 503
   不妨碍识别差分取证（firehose 里 upstream_request 完整在场）。
