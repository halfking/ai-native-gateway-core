## 1. 为什么 `.tsv` 的那套搬不过来

★ `.tsv` 的掏空 = 「删掉数据行、留下列名行」⇒ ⇒ **文件仍然合法** ⇒ ⇒ 读方红是因为它「读到 0 行」。

★★ JSON **没有「列名行」这个概念** ⇒ ⇒ 「删几行」会留下**语法错误**的 JSON
⇒ ⇒ 读方红是因为**解析崩了** ⇒ ⇒ **那不是「读到 0 条」** ⇒ ⇒ **假红**。

⇒ ⇒ 所以必须有**格式感知的掏空变换**，★ 且变换本身必须满足两条不变式：

| 不变式 | 内容 | 作用 |
|---|---|---|
| ① 合法 | 掏空版仍是合法 JSON | 读方**不会**因解析失败而红 |
| ② 同形 | 每个**还存在**的节点**类型不变**、**没有凭空多出的键** | 读方**不会**因「字段没了」而崩 |

★ ⇒ 于是「读方红了」**只可能**解释成「它读到了 0 条 / 读不到真值」。

## 2. 掏空变换的两种模式（★ 为什么一种不够）

### 2.1 `entries`（★ 清单型）

| 节点 | 变换 |
|---|---|
| 数组 | `[]`（★ 数组的元素**就是**条目） |
| 映射（★ 值全是对象） | `{}`（★ **条目映射** ⇒ 条目清零） |
| 映射（★ 其他） | 逐键递归（★ **计数字典** ⇒ 逐项归零；**键集合保留**） |
| 数值 | `0` |
| 字符串 | **原样保留** |
| 布尔 | `false` |

★★ 「值全是对象 ⇒ 整个清零」这一条是本轮最关键的细节：
★ 若只掏**字段**不掏**条目** ⇒ 读方会撞上「条目在、字段空」⇒ ⇒ 红的原因是**字段缺失**
（★ 实测：`bg/data/model_baseline_prices.json` 若按「叶子归零」处理 ⇒ 红在 `source_url is required`
⇒ ⇒ **红因不对**）⇒ ⇒ 必须整条清零。

★★ 「字符串保留」同理由：★ 字符串是**元数据 / 标识**，不是「条目」⇒ ⇒ 清空它会让读方因
「字段是空的」而红 ⇒ ⇒ **红因不对**。

### 2.2 `unusable`（★ 上限型）

★ 整册替换成 `{}` / `[]` ⇒ ⇒ 「登记册拿不到真值」。

★★ **为什么需要它**：★ 上限型登记册（★ 棘轮：记录的是「**允许的最大值**」）的实测值**已经触底**
（★ 仓内 3 份全是 0）⇒ ⇒ 把上限归零是**空操作**⇒ ⇒ `entries` 模式对它**测不到任何东西**
⇒ ⇒ 承本线纪律「★ 掏空后仍绿的第一嫌疑是**探针无效**，不是门有洞」⇒ ⇒ 必须换成另一种形式。

⇒ ⇒ 顺带得到一条**类型学事实**：
★★ **「掏空 ⇒ 必红」这条判据，只对【清单型】登记册成立；**
★★ **对【上限型】登记册，它在结构上就不成立**（★ 放宽上限只会更宽松）⇒ ⇒ 必须用「真值被取走」这另一种形式。

## 3. 读方 harness：新增 `node` / `vitest` 两种形态

★ `runHollowReaderOverlay` 从 `{gotest, shell}` 扩到 `{gotest, shell, node, vitest}`。

### 3.1 cwd 的定法

★ `node` / `vitest` 臂的 cwd = **离脚本最近的、含 `package.json` 的祖先目录**
⇒ ⇒ `web/scripts/*.mjs` ⇒ cwd = `web/`（★ 与 `npm run` 的语义一致）。

★★ **为什么不能固定成仓根**：★ `web/scripts/color-baseline-stale.mjs` 用 `process.cwd()`
推算 `scripts/color-token-audit.mjs` 的位置 ⇒ ⇒ cwd 必须是 `web/` ⇒ ⇒ 否则读方「找不到文件」⇒ ⇒ **假红**。

★ 为什么用「最近的含 package.json 的祖先」而不是写死 `web/`：
★ 写死 `web/` ⇒ 仓里再加一个前端包（★ `web-mobile/` 已经是第二个）⇒ ⇒ 新的读方就会在错误的 cwd 里跑
⇒ ⇒ 判据依赖了当前目录布局 ⇒ ⇒ 「最近的含 package.json 的祖先」是**机械可算**的 ⇒ ⇒ 布局变了也不用改判据。

### 3.2 ★★ `go:embed` 读方 ⇒ 必须**重新编译**

★ `bg/data/model_baseline_prices.json` 的读方是 `//go:embed` 进二进制的 ⇒ ⇒ **掏空落盘后旧二进制里的内容不变**
⇒ ⇒ 读方会跑到「没被掏空」的内容 ⇒ ⇒ 分类误成「仍绿」⇒ ⇒ **假绿**。

★ ⇒ ⇒ 二进制缓存键必须带上**被掏空文件的指纹**（`contentKey`）⇒ ⇒ 掏空后**重新编译**⇒ ⇒ 嵌入内容跟着变。

★ ⇒ ⇒ **通用式：★★★ 凡读方把登记册【编译进产物】（★ `//go:embed` / 代码生成 / 打包），
★ ⇒ ⇒ 「掏空落盘」对它**不生效** ⇒ ⇒ 必须重编译 ⇒ ⇒ 缓存键必须带内容指纹 ⇒ ⇒ 否则就是假绿。**

### 3.3 ★★★ 「读方没跑起来」必须与「读方跑了并且绿」**可区分**

★★★ 负控臂的结论形态是「被改瞎的读方 ⇒ 分类 = `still-green`」。
★★ **风险**：★ 如果读方**根本没跑起来**（★ 路径写错 / vitest 二进制不在 / 包目录不存在）
⇒ ⇒ 退出码也会是 0 ⇒ ⇒ 分类同样判成 `still-green` ⇒ ⇒ 负控臂会报「门发现不了被改瞎的读方」
⇒ ⇒ **那是假警报**（★ 探针压根没跑）。

⇒ ⇒ 本轮给三种读方形态各加了一道**存在性前置检查**（★ node 脚本 / vitest 测试文件 / gotest 包目录）
⇒ ⇒ 并加门 `TestStructuredRegistryHarnessDistinguishesNotRunFromGreen` 钉住它。

★ ⇒ ⇒ **通用式：★★★ 阴性结论要当缺陷一样复核 ⇒ ⇒ 【阳性结论】（★ 「仍绿 ⇒ 读方被改瞎了」）也一样要复核
★ ⇒ ⇒ ⇒ 「跑不起来」与「跑了且绿」在退出码上不可区分 ⇒ ⇒ harness 必须把前者变成【错误】而不是【0】。**

## 6. 候选集：★ 文件名会漏收 ⇒ ⇒ 加一条「被已登记的读方按路径读取」

★ 原候选集 = **文件名关键词**（registry|baseline|inventory|ledger|manifest）⇒ ⇒ **漏收**「名字不像登记册」的登记册。

★★ **实测漏收**：`web/scripts/cjk-native-simplified-chars.json`（★ 简体残留门的 Big5 字表）⇒ ⇒ 名字里没有那 5 个关键词。

⇒ ⇒ 新增第二条候选来源：**被【普查表已登记的读方】按路径读取**的结构化文件。

★★ **为什么只扫「已登记的读方」而不是全仓**：★ 全仓扫实测得 **121** 个候选（★ compose / prometheus 规则 /
testdata / locale 文件……）⇒ ⇒ 绝大多数不是登记册 ⇒ ⇒ 表会变成噪音。
★ 而「已登记的读方」是**门** ⇒ ⇒ 它按路径读的结构化文件**就是**门的输入 ⇒ ⇒ 判据既精确又廉价
⇒ ⇒ 新登记册在**被登记为读方的那一刻**就会被自动纳入。

★★ **解析细节**：★ 字面量常是**片段**（★ `join(ROOT, 'scripts', 'xxx.json')` ⇒ ⇒ 字面量是 `xxx.json`）
⇒ ⇒ 用**路径后缀**撞仓内被追踪文件；★ **单词段字面量只在唯一命中时才算**（★ 否则 `package.json` 会拖进 3 个无关文件）。

## 7. 例外表机械段词表扩容（★ 与结构化侧**同源**）

| 机械断言 | 含义 | 用例 |
|---|---|---|
| `rows=0` | 该登记册当前 0 数据行 | 2 条 `.tsv` 例外 |
| `reader-green` | 读方在【基线】是绿的 | `cjk_var_sites.tsv` |
| `no-code-reader` | 仓内无代码引用者 | `appendix-a-tables.tsv` |
| ★★ `reader-red-on-missing` | ★ 读方在【登记册文件**不在**】时必须红 | ★ `cjk_var_sites.tsv` |
| ★★ `reader-red-on-hollow` | ★ 读方在【**掏空版**】下必须红 | ★ **结构化登记册全部 14 条** |

★★ `reader-red-on-missing` **比 `rows=0` 强**：`rows=0` 只说「它现在恰好是 0 行」（★ 明天长出一行就过期）；
★★ 这一条说「**文件本身是承重的**」（★ 文件一消失读方立刻红 ⇒ ⇒ 事实源丢了不会被静默放过）。

★ ⇒ ⇒ **两份表用**同一份词表** ⇒ ⇒ 两侧的「机械可核断言」不会各说各话。

## 8.1 ★★ 一条被实测踩到的预算陷阱

★ `go test ./scripts/ursmcheck/ -count=1`（★ **不带** `-timeout`）⇒ ⇒ 走 Go 的**默认 600 s**
⇒ ⇒ ★ 而这个包的**整包**运行（★ 掏空门 326 s ＋ 结构化门 135 s ＋ 其余约 100 个门文件）⇒ ⇒ **撞 600 s 超时**
⇒ ⇒ ★★ 退出码非 0 ⇒ ⇒ **「超时」与「结论被推翻」在退出码上不可区分**
⇒ ⇒ ★★ 与本线那条「★『跑过了』与『跑了 0 条』在退出码上不可区分」**同族**。

★ ⇒ ⇒ 修法：★ 复核命令**一律带显式 `-timeout`**（★ 本轮统一 `-timeout=1800s`）⇒ ⇒ 超时 ⇒ ⇒ 读数**明确标注「超时（不是结论被推翻）」**。

★ ⇒ ⇒ ★★ 另注：★ `scripts/ursmcheck` **不在** `Makefile` 的 `GUARD_PACKAGES` 里 ⇒ ⇒ CI 的 `-timeout=300s` / `-timeout=120s` **不覆盖它**
⇒ ⇒ ⇒ 它的超时预算**从来没人写死过** ⇒ ⇒ ⇒ **登记册必须自己写死**。
