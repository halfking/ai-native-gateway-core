### 3.3 P1 — 上游引入的真缺陷：元判据门 3 处「$变量紧跟全角字节」

对方提交 `6152cc5de` 新引入 `scripts/deploy-seamless-goacos_mutation_test.sh`，其中：

| 行 | 形态 | 后果 |
|---|---|---|
| `:100` | `（期望红字：$expect）` | bash 把全角 `）` 并进变量名 ⇒ `set -u` 下报 `bash: expect?: unbound variable` |
| `:102` | `（期望包含：$expect）` | 同上 |
| `:108` | `（退出码 $RC）` | 同上 |

★★ **要害**：这几行**恰恰是「断言失败时要打的红字」** ⇒ 断言不成立时，元门不是打出指定红字，而是炸成「未绑定的变量」⇒ **元门自己的「按指定红字红」契约被自己打断** ⇒ 消费方无法区分「断言不成立」与「脚本自己炸了」。

实测对照：

```
LC_ALL=en_US.UTF-8 bash -c 'set -u; expect=X; printf "%s" "$expect）y"'  ⇒ bash: expect?: unbound variable
LC_ALL=en_US.UTF-8 bash -c 'set -u; expect=X; printf "%s" "${expect}）y"' ⇒ X）y   ✅
LC_ALL=en_US.UTF-8 bash -c 'set -u; set -- Hello; printf "%s" "$1：x"'    ⇒ Hello：x  ✅（位置参数只吃数字 ⇒ 安全 ⇒ 不动）
```

**处置**：改 `${expect}` / `${RC}`；★ **顺带实测排除**了同文件的 `$1：` ⇒ **不改本来正确的写法**。
