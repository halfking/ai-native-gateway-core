## §3 紧凑模式的形态决策（为什么是单行而不是双轨）

候选形态有两个：

| 形态 | 带高 | 评价 |
|---|---|---|
| 双轨迷你树（发送轨在上、回程轨在下，各自压缩） | 118px → **90px**（-24%） | 省得不够；两轨各自瓦片宽度被压到读不出图标 |
| ★ **单行 11 段流水线**（发送 7 段 → 回程 4 段，段间短线 + 方向箭头） | 118px → **68 → 40px**（-66%） | ★ 采纳：更贴合「一屏多看几条 + 统一对齐」；用**段间短线 + 两端箭头**保住「往返」语义（发送向右 / 回程向左） |

紧凑模式瓦片 **28×28、无边框无底色**，每段三样东西，各占一角互不重叠：

| 位置 | 内容 | 作用 |
|---|---|---|
| 中上 | **语义图标** 15px（哪一步） | 阶段身份 |
| 右上 | **状态字形**（纯字形，不画实心圆）：进行中 `◐` / 失败 `✕` / 跳过 `⌀` / 告警 `⚠`；**完成与未到达无字形**（第 8 轮去勾勾 ⇒ 状态由**颜色**承载） | 现在怎么样（非颜色通道只保留少数几态） |
| 右下 | **小数字**（该阶段最关键的那个数） | 关键值，口径在 tooltip |
| 左下 | **路由标记**：每一跳一个小箭头 | 有几跳路由 / 每跳结果 |

**颜色即状态（第 8 轮）**：完成=**绿** / 出错=**红** / 跳过=**灰**＋斜纹 / 未执行=**靛紫** / 进行中=蓝 / 告警=琥珀。
★ 亮色下靛紫另提 opacity 并垫一层淡紫底 ⇒ 不与「跳过＝灰」混淆。

**行的右端**（第 7 + 8 轮加总）依次是：**状态 · 会话（◆ 首轮 / 第 N 轮）· 目标模型 · 完整路由 · 候选数 · ↻尝试次数 · token（入/缓存读/出）· 耗时** —— 全部**同一行**，不再另起摘要行。
例：`成功 │ ◆ 首轮 │ glm-5.3-flash │ 共享令牌池 │ ◲2 候选 │ ⇅ 4.5k ⛁ 4.4k → 1.0k │ ⏱ 2.0s`
★ 每条带**最前面**是**时间**（`00:41:45`），与客户端身份一起 sticky 吸左。

**最右的「错误列」（第 9 轮）**：出错时在带的**最右侧固定一列**显示 `GW 网关`＋`error_kind`，
**所有行的 chip 右缘恒等于同一个 x** ⇒ 眼睛一次**竖扫**就知道哪些行错了、错在网关还是供应商。
代价：紧凑树宽 1200 → **1400**（错误列 210 + 右留白 10 + 间距 12）；≤1023px 自动切卡片版面，错误列退回行内。
完整模式无独立列，改为在摘要行的来源徽标里追加 `error_kind`（同一口径）。

## §4 错误来源三分法（判据摊开，可核对）

来源**由词表推出，不手填**；判据写进 tooltip 与详情，全景面板另有「错误来源判据表」14 行。

| 归因来源 | 判据（error_kind） | 含义 |
|---|---|---|
| **GW 网关** | `auth_rejected` / `approval_required` / `prompt_injection_blocked` / `sanitize_error` / `compression_guard` / `no_route` / `circuit_open` / `gateway_concurrency_limit` | 网关自身的策略判定或自身故障 |
| **UP 供应商** | `upstream_rate_limited` / `upstream_5xx` / `upstream_timeout` / `connect_failed` | 上游返回或链路失败 |
| **OTH 其它** | `client_canceled` / `client_bad_request` | 客户端侧（取消 / 参数错） |

★ 「熔断打开」归**网关**（策略动作），但根因通常在上游 ⇒ 口径说明里写明，不让用户把策略动作误读成根因。
★ **限流不再等于「全部失败」**：上游 429（供应商）与网关并发闸 429（网关）按 errKind 分开归因。

## §5 内部多次路由的表达

生产锚点：`domains/dispatch/failover.go` `emitNodeSwitch` ⇒ `node_switch{from_credential_id, to_credential_id, reason, retry, retry_seq}`。

- 原型保留**尝试链**（`band.attempts`），**不覆盖** provider/节点；
- 最终 provider / cred 取**最后一次**；
- 最终成功的请求**仍保留中间失败的来源**（写在尝试链里），但整带**不挂**失败来源徽标 —— 否则会把「重试后成功」误读成「这条失败了」；
- 展示位置**四处**：① 瓦片左下角的**路由标记**（每一跳一个小箭头，跳数＝尝试数，颜色＝该跳结果）② 右侧行的**完整路由**（`共享令牌池 → 阿里云百炼`）③ 带级 chip「↻N 次尝试」/ 详情「路由全景」小节 ④ 全景面板「切换链 Top」。

实测样例：
```
#1 阿里云百炼 cred#128 · gemini-3-pro · 上游连接失败（来源：供应商）→ cred_retry
#2 … 成功
动作：node_switch{…reason:"cred_retry", retry:"true", retry_seq:"1"}
瓦片标记：▸▸（2 跳：红=失败跳，绿=成功跳）
右侧完整路由：阿里云百炼 → 内网直连
```

---

**性质**：本原型用于**设计评审**（模拟数据，内置模拟器），不是生产实时流。
**生产动作词与失败形态全部沿用生产口径**，未自造词汇。
**通用式（五轮沉淀）**：
① 「口径」标签是承诺——写「当前时间范围」就必须真的随时间走；
② 「同一行」是版面契约——状态/模型/路由/会话/token 是读一条请求的终点信息，另起一行就得来回对位；
③ 去边框会放大「元素相撞」的代价⇒ 必须同时给每个元素划出互不重叠的格位；
④ **状态色要成体系地选**——先数「已占用的色相」再选剩下的，且同一语义在全局只有一处颜色（瓦片/图例/徽标必须同色）；
⑤ **「去掉勾勾」不是删一个字符**——勾勾同时存在于瓦片角标、状态徽标、图例三处，只删一处会出现「图例与画面对不上」；
⑥ **「重叠」的根因常在写死的尺寸常量**——紧凑带高 40、展开逻辑却用完整模式的 118 ⇒ 带没长高就溢出 ⇒ 所有尺寸常量改**读当前模式**；
⑦ **半透明底色在「元素会长高」的场景里＝隐患**——可长高的层要**不透明底**；
⑧ **初始化时调用的函数如果不存在，症状是「整页空」而不是「报错」**——先看控制台有没有 `ReferenceError`，再怀疑数据；
⑨ **「在最右边显示 X」要先分清「想看到」还是「想一眼扫到」**——挂在内容流末尾 ⇒ 每行位置都不同；做成**固定一列** ⇒ 位置恒定，一次竖扫看完；代价（树宽 +200px）必须**明码标价**并量出内容的真实最宽值；
⑩ **列表要按「人怎么找」分层**——运营标注的（特色/精选）与统计出来的（热门）**分段分开**，混在一起就会「把标注当测量」；
⑪ **实时刷新会吃掉交互**——任何定时重画列表都要保住**滚动位置 + 焦点 + 正在点的那个元素**；
⑫ **「完整」的含义是「不藏」，不是「多」**——布局容量不够时**先换布局，别先砍指标**（被砍掉的指标会被读成「数据正常」）；
⑬ **两个「时间」控件必须各司其职**——「显示范围」与「统计范围」求交集看起来严谨，实际是让其中一个**形同虚设**；
⑭ **两套钱（收入 / 成本）不可共用一个数，换算必须在同币种内完成**——生产侧积分与美元不可直接相减；
⑮ **没有口径就不给数，并计数披露**——不给数且不说 ⇒ 读成「免费」；给数且不说口径 ⇒ 读成「精确」；
⑯ **独立维度比一个维度多出的是「交叉验证」**——用户 ↔ key 一对多 ⇒ 两个维度的请求数可以互相验账。
