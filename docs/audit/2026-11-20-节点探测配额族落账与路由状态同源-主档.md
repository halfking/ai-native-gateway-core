## 二、三个缺陷（全部在「探针面」）

### D1 ★ 探针的分类只看 err code，看不见上游响应体 ⇒ 配额裁决在探针侧不成立

`bg/probe_recovery_policy.go classifyProbeErrCode(code)`：只按 err code 映射
（`http_429 → rate_limit`、`http_5xx → upstream_down`…），**`http_403` 落到末尾返回 `""`（无策略）**。
★ 而 `errorsx.ClassifyErrorWithBody(403, {"code":"INSUFFICIENT_BALANCE"})` = `KindQuotaPermanent`（本轮实测确认）。

⇒ **同一把尺（`errorsx.ClassifyErrorWithBody`）在业务面有、在探针面没有。**

### D2 ★ 探针只写绑定面、不写凭据面 ⇒ 「节点正常」是探针自己造出来的

`bg/node_probe.go runOne` 失败分支 + `bg/probe_service.go applyOutcome` 失败分支
**只写**：`cmb.available` / `node_probe_state` / Redis 观测面。
**凭据面（`credentials.quota_state` / `availability_state` / `state_reason_code`）一个字不写。**

★ 仓内**已有**这套落账的现成实现：`bg/credential_probe_v2.go classifyProbeFailure`
（凭据级探针 v2 用它，写 `QuotaState` / `AvailabilityState='suspended'` / `StateReasonCode`，
并用 `errorsx.NextQuotaReset` 取周期族重置点）——**只是模型对探针（node probe）没接上它。**

⇒ 后果三连：
① 凭据面继续显示 ready/ok ⇒ **「节点正常」**；
② 用尽凭据对响应式余额复检探针**不可见** ⇒ 充值检测不到 ⇒ **卡死**；
③ 配额族没进配额策略 ⇒ 通用梯子对着一个余额已耗尽的节点反复空打。

### D3 ★ 绑定面的冷却时长与探针自己的下一跳是两个独立算出来的数 ⇒ 「5 分钟后复检」是假账

| 面 | 修复前 | 实测（凭据 56 / claude-sonnet-5-5，09:57） |
|---|---|---|
| 绑定面 `unavailable_recover_at` | `unavailableBindingHorizon` 恒 **5 分钟** | `09:50:11` ⇒ **已过期 7 分钟** |
| 探针面 `node_probe_state.next_retry_at` | 通用梯尾 6h × 常用模型 50% 折算 = **3 小时** | `11:50:11` ⇒ **还要等 ~2 小时** |

而 `bg/credential_recovery.go expiredCmbRecoverySQL` 的复检扫描以**探针行**为准
（`NOT EXISTS (node_probe_state … next_retry_at > now())`）
⇒ **冷却到期那一刻没有任何人来复检** ⇒ 绑定面写的恢复时间是**假的**，
实际恢复被推迟到探针自己的下一跳 ⇒ **owner 说的「更新延迟」**。

★ 通用式：★ **两个面各自算自己的时间 ⇒ 必有一个是假的；「承诺的恢复时间」必须由承诺的那一面兑现。**

## 三、本轮交付（三处修复 + 回归钉测）

### F1 ★ 探针的分类看上游响应体（`bg/probe_recovery_policy.go`）

- 新增 `classifyProbeOutcomeKind(errCode, httpStatus, responseBody)`：
  保留既有 code→kind 映射为基线；**仅当** HTTP 状态落在既有那张
  `quotaProbeHTTPStatuses`（402 / 403 / 429）时，才用
  `errorsx.ClassifyErrorWithBody(status, body)` 判一次，**命中配额族才采纳**。
- 新增 `isQuotaProbeKind(kind)`、`probeOutcomeKind(round)`。
- ★ 边界（刻意不扩大）：**纯鉴权 403（无配额体）不是配额族**（errorsx 判 auth）
  ⇒ 探针保持今天的行为，鉴权族另行设计（登记 L1）；**KindQuotaPeriodic 由
  `errorsx.NextQuotaReset` 取重置点**（与凭据级探针同一 helper ⇒ 两个面同点）。

### F2 ★ 配额族裁决**凭据级落账**（`bg/node_probe_write_through.go`）

- 新增 `quotaCredentialSQL(kind)`：`permanently_exhausted` / `balance_exhausted` /
  `periodic_exhausted` + `availability_state='suspended'` + `state_reason_code=<kind>`
  ⇒ **与业务面 / 凭据级探针 v2 的词表逐字一致**。
- 新增 `updateCredentialQuotaSurface(...)`：走 worker 既有的 `scheduleExec()` 缝
  （生产走 db、测试注入假 exec）。
- ★ 守卫：① 只写配额族；② **两次连续**配额族失败才落账（探针是合成流量，
  单次 403 不足以摘掉整个凭据的全部模型）；③ `lifecycle_status='active'` +
  `manual_disabled=FALSE` + `balance_floor` 豁免（与 `healthyCredentialSQL` /
  `domains/credential/writer.go` 同款守卫）。
- ★ **闭环收益**：凭据面一旦落账 ⇒ `bg/balance_quota_probe.go`（响应式余额复检探针）
  **看得见它** ⇒ 充值被检测到 ⇒ `RearmCredentialFailures` 回拉模型对失败行 ⇒
  绑定翻绿。**⇒ D2 造成的死循环被从根上断开。**

### F3 ★ 冷却时长与探针下一跳**同源**（一个数，两个面）

- 新增 `quotaVerdict{kind, recoverAt}` + `quotaVerdict.horizon()`：
  - permanent / balance（无重置点）⇒ **配额停放 horizon**（`probe.quota_exhausted_recheck_seconds`，默认 6h）；
  - periodic（有重置点）⇒ **重置点 + 60s**（与 `quotaResetAlignedBackoff` 的
    配额重置点对齐退避**同一个数**）。
- `updateBindingAvailability(..., verdict)`（**绑定面**的
  `unavailable_recover_at` 与 `unavailable_reason` 都由 verdict 决定）与
  `probeBackoffForDirectOutcomeKind(verdict, …)`（**探针面**的 `next_retry_at`）
  **都从 `verdict.horizon()` 取数** ⇒ **不可能再分叉** ⇒ 绑定面不再写「5 分钟」假账。
  ★ 绑定理由同步为 `probe_quota_<kind>` ⇒ 凭据级归因（与 `auto_credential_%` 同族）。
- 三条探针失败路径（**legacy tick `runOne` / 统一队列 `applyOutcome` /
  同步救援 `ProbeSync`**）全部改用 verdict 口径 ⇒ 没有一条路径能再写「5 分钟」假账。
- 配额族**不再走通用失败梯子**（通用梯子对一个余额耗尽的节点每轮注定失败
  ⇒ 211 实测：凭据 56 的 ~20 个模型对各连败 **175~489** 次，每 3 小时一轮空打）。
  恢复感知不降级：凭据级余额探针发现充值 → `RearmCredentialFailures` 立即回拉。
- 常用模型 50% 折算（featured multiplier）**排除配额族**（它是为「更快复验瞬时失败」
  存在的，对配额裁决只会把停放缩短）。
- ★ 同步救援路径（`ProbeSync`）**不写凭据配额面**：它不改 `node_probe_state`
  ⇒ 没有连败上下文 ⇒ 无法构成「两次连续」的佐证 ⇒ 佐证只认 tick/队列梯子。

### F4 ★ 凭据级归因的绑定，冷却到期也**不许**在凭据未 ready 时翻绿

`credentialhealth/checker.go cmbExpiredRecoverySQL`：F4 守卫原本只管
`auto_credential_%`（业务面写的凭据级归因）⇒ 探针新写的 `probe_quota%`
必须同款守卫，否则凭据被配额停用时绑定冷却到期被翻绿 ⇒ 又一次
「绑定面说可用、凭据面说不可用」的面间漂移。

★ 模式写作 `'probe_quota%'`（**不带**尾下划线）：探针配额族里
`errorsx.KindQuota` 的 reason 就是裸 `quota` ⇒ 绑定理由 = `probe_quota`（11 字符）
⇒ `'probe_quota_%'` 匹配不到它（SQL `LIKE` 里 `_` 是**单字符通配**，
该模式至少要 12 字符）⇒ 裸 quota 族会漏掉守卫。★ 通用式：
**LIKE 模式里的 `_` 是通配符，不是字面下划线** —— 词表边界要么用 `%` 收口，
要么显式确认最短样本长度。
