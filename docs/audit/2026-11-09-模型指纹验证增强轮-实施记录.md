# 模型指纹验证增强轮 — 实施记录（2026-11-09/10）

**目标**: 修复能力维度判定失效（MMLU 题库过简单 ⇒ 18 个高级模型恒 100 分），建立被动式模型指纹体系（被动为主、主动为辅）。
**状态**: ✅ 代码层完成（库级 API + 迁移 + 判定引擎），⏳ streaming 接线与部署待下轮。

---

## 一、根因（211 真库实证）

```
30 天窗口 model_iq_runs（status='success'，≥5 次）：
  claude-opus-5-5 / 4-8 / 4-7、sonnet-4-6/5、glm-5.3(+flash)、gpt-6-sol/terra/astra、
  grok-4.7、deepseek-v4.1-flash … 共 18 个模型全部 100.00%、stddev=0
唯一例外：MiniMax-M2.7（40-84%，stddev=11.3）⇒ 题库未全失效，但对高级模型天花板过低
```

**推导**：`ComputePeerParity` 的 Ratio = accuracy/Best 恒 = 1.0 ⇒ 同族降级（Opus→Haiku）
在能力维**完全不可见**。用户「模型智商不太正常」的体感与该盲区一致。

## 二、本轮交付（按依赖序）

### D1 权重应急配比（types.go）
- Capability 0.40→**0.15**（失效维度压低话语权）、Identity 0.30、Consistency 0.20、Reference 0.05、**Passive 0.30**（新维度）。

### D2 被动特征提取（passive.go，新文件 ~490 行）
- `ExtractPassiveFeatures`：从流式 chunk（复用 `StreamChunk.EmitAt` 时间戳）提取
  TTFT / ITT 序列 / 吞吐 / Token 计数 / OutputDensity / 格式位标（###/**/list/code）。
- `EvaluatePassive`：时序 60%（ITT JSD 50% + TTFT 25% + 吞吐 25%）+ Token 25% + 内容 15%；
  置信度 = min(1, 基线样本/100)。
- 异常常量：`passive_no_data` / `passive_itt_mismatch` / `passive_ttft_anomaly` / `passive_throughput_anomaly`。

### D3 JSD 核心（behavioral.go，新文件）
- `ComputeJSD`（对称 KL，[0,1] bit）——ITT 分布对比的数学底座；
  完整主动探针（8 探针 × 30 采样）留 W1-2（冷启动用，非关键路径）。

### D4 迁移 955（六面登记 + 契约门五件）
- `passive_model_fingerprints`： (tenant, credential, model) 唯一键；credential_id=0 保留给模型级聚合；
  ITT 分布 10ms 桶宽 jsonb（与 Go 侧逐字一致，契约门双向钉死）；时序列毫秒 real。
- 登记：embeddata 双副本（SHA 一致）/ go:embed / embeddedSQLFiles map / dbinit StartupFiles /
  apply-db-revision-sequence.sh files + ledger_artifact_probe / TSV 第 355 位 / db-changelog 第 7 面。
- 契约门 `migration_955_passive_model_fingerprints_test.go`：形态 / down / **桶宽 cross-pin** /
  字节一致 / 登记面覆盖。
- **字节修订一次**（prepared 未应用 ⇒ 合法，936/946 先例）：首版 statement_timeout 拍 60s 被
  heavy-DDL 预算门当场红（两条非 CONCURRENTLY CREATE INDEX ⇒ 761 先例 ≥10min），抬 10min。
- **隔离 PG17.11 真库验证**：up / 重放幂等 / down / 再应用四态全过。

### D5 Store 读写（store_passive.go，新文件）
- `UpsertPassiveBaseline` / `LoadPassiveBaseline`（实现 `PassiveBaselineSink` 接口，测试可注入替身）。
- jsonb 一律 string 绑定（bfbbb5618 教训：裸 []byte 落成 bytea hex 22P02）。
- 毫秒 real ⇄ time.Duration 边界换算收敛在文件内（msOrNil/msToDuration）。

### D6 采集器（passive_collector.go，新文件 ~560 行）
- `PassiveCollector.Add`（线程安全累积）/ `Flush`（与既有基线**加权合并**而非覆盖——
  低流量模型基线不再来回跳）。
- 合并规则：均值/分布按样本数加权；格式位标 OR 并集；样本数截断 cap=5000；
  **陈旧基线（>30 天）丢弃重建**；p50/p95 从合并分布近似（桶中点）。
- 单节点落库失败不阻断其余节点；窗口内存有界（ITT 2 万 / TTFT 4096）。

### D7 判定引擎第五维（verdict.go / types.go）
- `DimPassive = 1<<4` + `SubScores.Passive` + `ComputeOverall` 维度列表 + 权重 0.30。
- `scorePassive`：nil ⇒ 不计维（冷启动常态，非异常）；Confidence < **0.30**（基线 <30 样本）⇒
  不计维；过门 ⇒ 分数进综合分、异常透传。
- Evidence 扩展：`dimension_scores.passive` / `passive_measured`（★ 必须与分数一起读——
  0 分 + measured=false 是「没测」不是「极差」）/ `passive_itt_jsd` / 分项分数。
- 融合契约测试 `passive_verdict_test.go` 四条（nil 不计维 / 低置信不计维且异常不透传 /
  过门计维按权重合成 / 低分透传异常压 verdict）。

## 四、第二轮交付：被动闭环最后一跳（streaming 接线 + worker 装配，2026-11-10）

数据流（生产路径已通）：
```
SSE 文本增量 → PassiveTimingTracker.ObserveText（计时采样，永不中断流）
  → emitTelemetry usage 就绪点 → ExtractPassiveFromTracker → Worker.Submit → 内存累积
  → 5min 周期 Flush → 与 955 基线加权合并 → passive_model_fingerprints 落库
  → 下轮可信度扫描 LoadPassiveBaseline → EvaluatePassive → DimPassive 进综合分
```

| 件 | 文件 | 要点 |
|---|---|---|
| 追踪器+组合器 | `streaming/passive_timing_tracker.go` | ObserveText 内取时（≈增量到达）；样本有界 4096；组合器让 integrity 与被动追踪器并存于 capture 单一观察者槽，**中断裁决权归 integrity**（采样器永不改变流行为） |
| handler 完成 hook | `streaming/handler.go` | `SetPassiveTiming(factory, sink)` + `newStreamCapture` 组合 + `emitTelemetry` 采样点（`result.Candidate.CredentialID` / `evt.CanonicalName` / `keyInfo.TenantID`）；未接线 ⇒ 零开销旁路；audit 包仅加只读 `TextObserver()` 访问器 |
| bg worker | `bg/passive_baseline_worker.go` | 一体承担 factory+sink+周期 Flush（5min）；Stop 刷净残余窗口；flush 失败只告警不 panic；编译期断言锁两端接口 |
| main 装配 | `cmd/gateway/main.go` | `SetPassiveTiming(w, w)` + Start/defer Stop；`LLM_GATEWAY_PASSIVE_BASELINE=off` 关闭（关 ⇒ 不接线 ⇒ 热路径零变化） |

第二轮验证：`go build ./...` rc=0；streaming 接线测试 4 件 + modelcredibility + bg 全包（41s）全绿；vet/gofmt 干净。
实跑修掉：单增量流吞吐应缺省（lastAt==firstAt 时长为 0）——测试期望错非代码错。
