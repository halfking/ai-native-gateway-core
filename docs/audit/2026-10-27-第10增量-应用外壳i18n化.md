## 0. 一句话结论

**应用外壳此前有一整套「绕过 i18n 体系的第二份真值」** —— 品牌标题、导航项标签、运维菜单、登录弹窗，
全都以硬编码中文写在源码里；语言包里即使有对应词条也**改不到它们**。
本轮把 9 个新键 × 8 语种补齐、把 **64 段**中文兜底收进语言包、删掉 **15 处**死代码式「中文兜底」，
并新建一道门把「键藏在常量里」这个**会让引用集失明**的形态钉死。

## 1. 发现（按严重度排序）

### 1.1 ★★★★★ 品牌标题是第二份真值，语言包改不到它

`web/src/config/brand.ts` 导出的是**硬编码中文常量**：

```ts
export const SITE_TITLE = 'AI Native 组织核心网关'
export const SITE_TITLE_LINE_TWO = '组织核心网关'
```

它出现在 **5 个外壳组件**里：

| 消费点 | 位置 | 用途 |
|---|---|---|
| `App.vue` | `:aria-label` + 品牌第二行 | 访客壳品牌 |
| `components/shell/AppTopbar.vue` | `:title` + 品牌第二行 | 登录态顶栏品牌 |
| `components/LoginModal.vue` | 副标 | 登录弹窗副标 |
| `views/LandingView.vue` | `:brand` prop | 落地页品牌 |
| `views/lifecycle/UpdateActivateView.vue` | 页面副标 | 更新与激活页副标 |

⇒ 换语种时这 5 处**仍然是中文**，而且语言包里**没有任何一份可以改的文案**。
⇒ 同时 `app.ts` 里还有一个 `brand: 'AI-Native 组织网关'`（**0 引用**的死键），
两处品牌字符串的**拼写都不一样**（`AI Native` vs `AI-Native`、`组织核心网关` vs `组织网关`）。

### 1.2 ★★★★★ 导航项的 `label` 与语言包**并存**，而且**已经漂移**

`config/appNav.ts` 里每个菜单项都同时带 `label`（硬编码中文）与 `labelKey`：

```ts
{ path: '/maintain/ops/licenses', label: 'License管理', labelKey: 'nav.item.opsLicenses', ... }
//                                   ↑ 无空格          ↑ 语言包里是 'License 管理'（有空格）
```

⇒ **两份真值**（`label` 与语言包），而渲染时被 `navLabel(labelKey, fallback)` 优先取语言包 ⇒
`label` 是**死副本**，但它仍在漂移：实测 `appNav.ts` 的 `'License管理'` 与语言包的
`'License 管理'` **当场不一致**。
另有 2 处 `label` 的值是**英文**（`'Sensitive information rules'`、`'Agent Registry'`）——
在中文界面里也会上屏。

### 1.3 ★★★★ 运维中心本地兜底菜单 7 条硬编码中文

`config/edition.ts` 的 `LOCAL_OPS_MENU`（maintain 不可达时用的兜底）整块是硬编码中文，
而这些条目在语言包里**本来就有键**（`nav.item.ops*` / `nav.group.opsplatform`）。

### 1.4 ★★★★ 登录弹窗 8 条硬编码中文

`components/LoginModal.vue`：错误提示 3 条 + 「登录失败」兜底 + 标题「登录控制面」+ 提示 + 密码标签 +
提交按钮（「登录中…」/「登录」）+ logo 的 `alt="开轩启圭"`。
⇒ 弹窗是**每个用户都会看到**的第一屏，却是纯硬编码。

### 1.5 ★★★★ 15 处 `t(key, '中文兜底')` —— 兜底**全是死代码**

全仓 `t('key', '中文…')` 共 65 处（含误匹配的 `emit('error', …)` 7 处 ⇒ 真值 58 处）。
把每个键拿 8 个语言包逐一核对 ⇒ **58 处键在 8 语种全部存在** ⇒ **兜底一行都没执行过**。

⇒ 危害不在"多写了字"，而在**它把「缺键」伪装成「已翻译」**：
一旦某个语种漏了键，用户看到的是**中文**而不是键路径 ⇒ 缺键在生产上**没有任何信号**。
⇒ 本轮删掉外壳这 15 处兜底 ⇒ 缺键从此**显形为键路径**（可被 A/B 探针与人工发现）。

### 1.6 ★★★ `/examples#auto-config` 没有 `labelKey`

它是 `接入指南` 组里**唯一**没有 `labelKey` 的菜单项 ⇒ 语言包里没有它 ⇒ 只能显示硬编码中文「自动配置」。

### 1.7 ★★★ 「键藏在常量里」会让键**逃出用户可见硬闸的视野**（本轮自己踩了）

本轮一度把品牌标题写成：

```ts
export const SITE_TITLE_KEY = 'app.brand.siteTitle'
// 模板里：t(SITE_TITLE_KEY)
```

实测：i18n 引用集扫描器（`src/i18n/scanner.ts`）**只认字面量** ⇒
`app.brand.siteTitle` / `app.brand.siteTitleLineTwo` **没有进引用集**
（引用集增量：常量写法 **+11**（键少 2 个）vs 字面量写法 **+13**）
⇒ 这两个键被算成「未引用」⇒ **它们逃出了「用户可见简体残留 = 0」那道硬闸的视野**。

⇒ 这不是"我写错了"，而是**量具的形状**（只认字面量）撞上了"我以为的抽象"。
⇒ 修法二选一：让代码迁就量具（写字面量），或扩展量具（解析常量）。
本轮选了前者（字面量），并**新建一道门**把后者那条路也堵上（见 §3）。

## 3. 新门：`scripts/i18n-hidden-key-guard.mjs`

**规则**：i18n 键必须以**字面量**出现在调用点。藏在常量里的键对引用集扫描器不可见 ⇒
既不被「缺键」审计覆盖，也不被「用户可见」硬闸覆盖 ⇒ 静默失守。

**判据（窄口径，宁可漏也不误伤）**：
① 调用点形如 `t(IDENT)` / `$t(IDENT)` / `tc(IDENT)` / `i18n.t(IDENT)`，且 `IDENT` 是裸标识符；
② `IDENT` 必须能**解析**成字符串常量（同文件 `const`，或从**相对路径** import 的模块里的 `export const`）；
③ 该常量的值必须形如**点分 i18n 键**（`^[a-z][A-Za-z0-9]*(\.[A-Za-z0-9_]+)+$`）
⇒ 存储键（`'llmgw_device_name'`）、枚举值、URL 片段**不**命中。

**自证（8/8 全过，`--selftest`）**：
字面量调用判绿 / 动态变量判绿 / 存储键常量判绿 / 同文件键常量判红 / 跨模块 import 键常量判红 /
`$t`·`tc`·`i18n.t` 变体判红 / **注释里的 `t(CONST)` 判绿** / 模板串 `${}` 里的调用判红。

**注释剥离**：门的第一版把 `brand.ts` 里那段**说明文案**判成了违规 ⇒
补了**保留偏移量**的注释剥离器（字符串/模板串感知，模板串里 `${}` 是代码）。

**真仓变异臂**（把常量写法放回真实代码里）：

```
src/components/LoginModal.vue:126:47  SITE_TITLE_KEY → 'app.brand.siteTitle'
FAIL: 1 处 i18n 键藏在常量里 ⇒ 逃出「用户可见」硬闸的视野。   rc=1
（还原后）✅ 没有「藏在常量里的 i18n 键」—— PASS                 rc=0
```

更新与激活页标题行），**没有一处结构/版面/错误类差异**。

★ **探针本身踩了四个坑（都不是产品缺陷）**：
1. **就绪判据必须与「本轮改了哪一侧」无关** —— 第一版用「元素存在」当就绪 ⇒
   HEAD 侧在语言包还没加载完时就采到了 en-US 的兜底值（ja-JP 的用户名标签读成 `'Username'`）⇒ 造出一个**假差异**。
2. **`<html lang>` 不是就绪信号** —— 实测 `i18n.ts` 在 `ensureLocaleLoaded` **之前**就写了 lang
   （模块加载时同步调用）⇒ 它只说明「选了哪个语种」，不说明「装好了」。
   ⇒ 改用「页面出现该语种的**期望文案**」（期望值从语言包读出来，且选一个**两侧渲染相同**的元素当锚）。
3. **探针实参必须传给 `page.evaluate`** —— 第一版把期望值当成了 `waitFor` 的超时参数 ⇒
   浏览器侧永远收到 `undefined` ⇒ 就绪判据恒假 ⇒ 探针**静默超时**（不报错，最难查的一种）。
4. ★★ **视口宽度会改变「哪些元素存在」** —— 抽屉（`.app-nav-drawer`）只在**紧凑布局**（<1024px）下有；
   而顶栏分组触发器（`.app-topbar__group-trigger`）只在**桌面布局**（≥1024px）下有
   ⇒ 为修抽屉把视口统一改成 900px 之后，顶栏的就绪锚点**恒不存在** ⇒ 顶栏判据恒假
   ⇒ 修法：**按步骤切视口**（顶栏/更新页 1440px → 抽屉 900px → 切回 1440px）。
   ⇒ ★ 这就是「**判据的元素必须与被测面同在**」的实例：锚点选错一层布局，就读不到另一层。
