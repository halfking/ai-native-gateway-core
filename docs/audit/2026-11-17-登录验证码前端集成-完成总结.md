## 一、问题定位

### 用户报障
- **现象**：登录成功后，系统读取多个链接还是401，然后又退出登录状态
- **错误信息**：`"captcha required after repeated failed logins"`

### 根本原因
**用户根本没有成功登录**。真实流程是：
1. 用户多次登录失败（密码错误或其他原因）
2. 后端失败计数 >= 3次，触发验证码强制要求
3. 前端没有验证码UI，用户无法输入验证码
4. 登录请求被`verifyLoginCaptcha()`在line 478拦截，返回400
5. 用户看到"captcha required"错误，但无处输入验证码

**关键发现**：不是"登录成功后401"，而是"登录本身就失败了"。

### 2. 登录API升级（`auth.ts`）

#### 新增接口
```typescript
export interface CaptchaResponse {
  captcha_id: string
  image: string // data:image/png;base64,...
  expires_at: string
  required: boolean
  ttl_seconds: number
}

export function getCaptcha() {
  return req<CaptchaResponse>('GET', '/api/auth/captcha')
}
```

#### 登录接口改造
```typescript
export interface LoginRequest {
  username: string
  password: string
  captcha_id?: string
  captcha_code?: string
  remember_me?: boolean
}

export function login(params: LoginRequest) {
  return req<LoginResponse>('POST', '/api/auth/token', params)
}
```

**向后兼容**：参数从`(username, password)`改为`LoginRequest`对象，但后端仍接受旧格式。

## 三、后端支持（无需修改）

后端已有完整支持（`admin/auth_captcha.go`，2026-10-10实现）：

### 端点
- `GET /api/auth/captcha` - 签发验证码
  - 返回：`{captcha_id, image, expires_at, required, ttl_seconds}`
  - `required`字段告知前端是否强制要求
  
- `POST /api/auth/token` - 登录验证
  - 接受：`{username, password, captcha_id?, captcha_code?, remember_me?}`
  - 验证码验证在line 229（`verifyLoginCaptcha`）

### 自适应逻辑
- 失败次数 < 3：验证码可选（`required=false`）
- 失败次数 >= 3：验证码强制（`required=true`）
- 登录成功后清空失败计数（line 313 `clearLoginFailures`）

### 安全特性
- PNG位图渲染（不可OCR直读）
- 一次性验证（验证后立即删除）
- 5分钟TTL
- SHA256哈希存储（不存明文）
- 防枚举（最多3次尝试）

## 八、关键技术决策

### 1. 为什么不在所有情况都显示验证码？
**自适应设计**：正常用户不必被打扰，只有多次失败后才强制验证码。

### 2. 验证码何时消失？
- 登录成功后，失败计数清零
- 下次登录时如果失败次数 < 3，验证码自动隐藏

### 3. "保持登录"的作用？
- `remember_me=true`：持久cookie，关闭浏览器后仍保持登录
- `remember_me=false`：会话cookie，关闭浏览器即退出

### 4. 为什么用v-model而非@update？
- v-model语义更清晰（双向绑定）
- 与Element Plus等UI库保持一致
- 减少样板代码

## 九、已知限制

### 1. 验证码可用性
- 依赖后端`/api/auth/captcha`端点可用
- 如果后端不可达，验证码加载失败会静默降级（登录时才报错）

### 2. 浏览器兼容性
- 需要支持`<img src="data:image/png;base64,..."/>`
- 现代浏览器均支持，IE11可能需要polyfill

### 3. 无障碍访问
- 验证码图片有`alt`属性
- 但视障用户仍需辅助（未来可考虑音频验证码）
