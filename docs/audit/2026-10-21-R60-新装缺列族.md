### §9.2 ★★ C 类真缺陷：`fault` 的读方法把可空列扫进 `*string` ⇒ **生产上该接口必然 500**

**根因**（三处同形）：

- `fault_events` 的 `acked_by` / `resolved_by` 是**可空** `text`
  （权威 DDL：`sql/objects/tables/fault_events.sql`）；
- `fault.Event` 结构体对**时间戳**用 `*time.Time`（NULL ⇒ nil ⇒ `omitempty` 不输出），
  对**文本**却用 `string` ⇒ ⇒ **同一张表里两种 NULL 语义**；
- `fault.PgxStore` 的**三个**读方法把这两列扫进 `*string`
  ⇒ ⇒ `GetEvent` / `GetOpenEventsByRule` / `ListEvents` 一律报
  `cannot scan into dest[N] (col: acked_by|resolved_by): cannot scan NULL into *string`。

**生产影响（实测，不是推演）**：

| 证据 | 读数 |
|---|---|
| 生产 `public.fault_events` 行数 | **9** |
| 其中 `acked_by IS NULL` | **9 / 9（全部）** |
| 其中 `resolved_by IS NULL` | **9 / 9（全部）** |
| 列可空性（`information_schema`） | `acked_by nullable=YES`、`resolved_by nullable=YES` |
| 路由是否真的挂着 | ★ `cmd/gateway/main.go:7216` `faultHandler.RegisterRoutes(adminGroup.Group("/faults"))` ⇒ `GET /api/admin/faults/events` |
| 生产是否真的坏 | ⇒ **是**：该表只要有一行未确认/未解决，`ListEvents` 整条查询失败 ⇒ API 500 |

⇒ ⇒ ★★ **这不是「夹具形态」问题，是产品缺陷，而且现在就在生产上生效。**
⇒ ⇒ **修法**（本轮已落地）：三处 SELECT 的两个文本列改用 `COALESCE(..., 空串)`
⇒ 与时间戳的既有语义对齐（「缺省 ⇒ 空串 ⇒ JSON 里 `omitempty` 不输出」），
**不改 Go 结构体、不改 API 形状**。
⇒ 顺带发现：同表的 **UPDATE 臂本来就有这个保护**（`digest = CASE WHEN $12 <> '' ...` 那个形态），
⇒ ⇒ **INSERT 臂漏了** ⇒ ⇒ 这是「同一语义在两条路径上一致一不一致」的典型形态。

### §9.3 B 类两处（夹具形态比产品需求旧 / 测试数据不满足前置）

1. **`domains/session/v2` 的 `sessions` 夹具缺 `duration_ms`**：
   夹具手写的 `CREATE TABLE public.sessions (...)`（`claim_two_surface_realdb_test.go`）
   **没有** `duration_ms`，而 `upsertSessionSnapshot` 的 INSERT 臂要写它（迁移 706 声明的列）
   ⇒ ⇒ 产品 SQL 打在夹具上必 42703。
   ★ **形态与 R59 的 B1 完全同型**（夹具的列集比产品需求旧）⇒ ⇒ 已补列 ⇒ **2 条转绿**。
2. **`tests/integration` 的 `TurnRecord` 没设 `DigestJSON`**：
   `session_turns.digest` 是 `jsonb` 可空列，而 `AppendTurn` 把它按 `string(rec.DigestJSON)` 传
   ⇒ 空 digest = 空串 ⇒ PG 报 **22P02 invalid input syntax for type json** ⇒ **整条 INSERT 失败**。
   ⚠ **但这不是产品缺陷**：`TurnRecord.DigestJSON` 的注释已写明
   「生产侧不会踩到：唯一赋值点 `session_writer_v2.go` 的 digestJSON 来自 `sessiondigest.Marshal`，
   出错即 return，**永不为 nil**」⇒ ⇒ **是测试没满足这个被记录的前置**
   ⇒ ⇒ 修法：测试补一个最小合法 digest ⇒ **2 条转绿**。
   ⇒ ★ 顺带记一条**待属主确认的语义项**：INSERT 臂对空 digest 是「整条 turn 写不进去」，
   而 UPDATE 臂是「保留旧值」⇒ **两条路径的语义不一致**（本轮**未**改产品，只登记）。

### §9.4 vibecoding：软删除 vs 测试预期硬删除（**属主语义决策项**）

  ⇒ 若 store 层过滤 `status='deleted'`，API 行为就与测试预期一致（404）。
⇒ ⇒ **「已删除的项目，GetProject 该不该 404」是产品语义** ⇒ ⇒ **本轮不替属主选边**，登记为决策项。
