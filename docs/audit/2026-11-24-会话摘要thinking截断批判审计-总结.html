① 结论 / 根因

结论：211 生产 session_summary_worker 的高频解析失败由两个根因叠加造成，本轮全部修复并已上线 211；修复后 12 分钟活体窗口两类解析失败均归零。

  • 根因 A（主导，74%）——截断：摘要调用 max_tokens=600，上游 thinking 模型的 <think> 推理段把预算整段吃光，JSON 尚未输出即被截断（极端形态：整个响应只剩一个 {）。生产实测 111 次/6h。
  • 根因 B（26%）——think 前缀：响应以 <think>…</think> 开头，旧 extractJSON 不识别 ⇒ response does not look like JSON。39 次/6h（上一轮 c91f763fb 已修，本轮部署生效）。
  • 根因 C（连带）——重试放大：标题同步对无成功请求行的会话报 no rows ⇒ 已落库摘要的整个操作被判失败 ⇒ worker 对同一 event 无限重试，每轮重跑一次 LLM。

批判审计订正：上一轮修复只覆盖根因 B（39 次），未触及当时占比 74% 的根因 A——「只看日志前缀形态、没量化形态分布」是首修漏掉主导形态的方法论原因。

111（74%） JSON 截断 — unexpected end of JSON input（根因 A，本轮修）
