3. **`POST /results/{id}/apply` + `POST /results/{id}/revert`**（新，`admin/pi_analysis_fix_apply.go`）：
   - **白名单动作**：`disable_rule` / `adjust_severity` / `update_pattern`；LLM 自由形状 JSON 经归一化层（识别 4 种常见形状：规范单对象 / disable 列表 / rules 数组 / 顶层数组），白名单外的键忽略并计数上报。

   - **正则编译验证**：update_pattern 必须先过 Go regexp.Compile（RE2 = 运行时同一引擎）；severity clamp 1..10。
   - **并发双保险**：`UPDATE ... WHERE auto_applied = FALSE` 受影响行数 = 0 ⇒ 409。
   - **RefreshRules 接线**：应用/回滚后触发在役 detector 热刷新（`SetRuleRefresher` 注入；此前零生产调用方的死面第一次接上）。审计 slog 逐条留痕（action/rule/old/new）。

### 前端（`PIAnalysisView.vue` 详情对话框整段重写）
- **点击队列行即开详情**（不再只限 analyzed 行）；结果 tab 的「详情」按钮同入口。
- **四区结构**：
  1. **时间线**：入队 → 分析开始 → 分析完成 + 耗时；
  2. **前因 · 错误发生时**：优先级/状态/重试/错误指纹/会话/请求、错误消息、error_details、**触发输入（untrusted 警示框 + 攻击载荷样式）**、**命中规则卡片（规则名/严重度/pattern）**、检测层、策略快照；
  3. **分析 · 结论**：误报/置信度/严重度/影响范围/受影响用户/分类/分析模型、根本原因、analysis_details、similar_cases、LLM 原始响应（折叠）；

- 未分析时降级取 `/queue/{id}`（404 → queue 详情），前因区照常展示。
- **i18n 8 语种全量键**（`common.piAnalysis.detail.*` 约 65 键 × 8）：新增文案零硬编码中文（CJK 计数与基线一致 4647）；**棘轮撞值 9 处修正**（zh-TW×5 繁简同形、ja-JP×2 日中同形、de-DE/fr-FR×2 欧语同形）——修正后逐语种数值与基线逐字一致。

## 四、通用式（本轮沉淀）

1. **「列在 schema 里」≠「通道存在」**——auto_applied 三列躺了一个月，写面/读面/执行面全没有；判定标准是「谁调用它」，不是「它写了吗」。
2. **升级语言的破坏面会在「Scan NULL」这种角落爆**——json.RawMessage = jsontext.Value 后可空 JSONB 列全炸；真库数据（rule_adjustment=null）是最好的测试集。
3. **LLM 建议落地必须有「白名单 + 置信度门 + 旧值快照」三件套**——少任何一件，要么幻觉规则名写进库，要么改错了回不去。
4. **改规则的端点必须接线热刷新**——否则「数据库里规则变了、运行时还是旧的」，而且这种分叉要等下次重启才暴露。
5. **详情页要讲「前因」就得把前因列真的查出来**——列表查询不取的列，详情端点要自己取全；「点开只看到分析结论」等于只讲了故事的后半段。
6. **i18n 棘轮的撞值要用脚本精确定位**（对拍 en-US/zh-CN 逐键），肉眼扫 8 语种 × 65 键必漏；繁简同形、日中同形、欧语同形是三类高发。

## 五、遗留登记

- **L1**：`update_pattern` 动作允许 LLM 生成的正则写进规则表（有编译验证、无语义验证）——语义错误（过松/过紧）需人工复核；建议后续给 update_pattern 加「先 observe 再 enforce」的灰度开关。
- **L2**：`piDetectorCoreGlobal` 只覆盖 v2 pipeline 的 detector 实例；若未来出现第二个在役 detector，需在 refresher 里逐个刷新。
- **L3**：并发应用的窗口内，第二个请求拿 409 但前端未自动刷新列表（需手动刷新；低频场景登记不修）。
