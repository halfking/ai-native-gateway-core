## 3. 修法：破坏性门自带一次性空库（库要假、表名要真）

### 3.1 新增 `db/scratch_db_test.go`

| 入口 | 作用 |
|---|---|
| `scratchBaseDSN(t)` | 解析 `TEST_DATABASE_URL` / `TEST_DB_URL`；没有 ⇒ **显式 SKIP**（说明本次没跑） |
| `checkCreateDatabase(base)` | 预检 `rolcreatedb`；没有 ⇒ **显式 SKIP**（不是硬红） |
| `scratchDSNFor(t, base, policy)` | 用 `internal/testdb.Create` 派生一次性空库 + **空库自证**（`pg_tables` 必须为 0） |
| `scratchPool(t)` | 一次性库上的连接池 |
| `scratchDSN(pool)` | 从池反推 DSN（供需要第二条连接的门） |

**三条硬约束**（写在文件头，是本轮的判据核心）：

1. **绝不 fallback 到共享库** —— 拿不到一次性库就明说「本次没跑」，绝不改成「那就用共享库跑吧」
   （那正是本文件要消灭的行为）。
2. **空库自证** —— 夹具的出发点必须是「什么都没有」。
3. **回收** —— `internal/testdb` 在 `t.Cleanup` 里 `DROP DATABASE … WITH (FORCE)`。

### 3.2 迁移清单

| 文件 | 改法 |
|---|---|
| `db/r1039_request_logs_provider_id_column_test.go` | 3 个真库判据改用 `scratchPool(t)`（并删掉不再需要的 `pgxpool` import） |
| `db/startup_ddl_guards_realdb_test.go` | `newGuardEnv` 改用 `scratchPool(t)`；`env.dsn` 由 `scratchDSN(pool)` 反推 |
| `db/startup_ddl_guards_earlier_realdb_test.go` | 复用 `newGuardEnv` ⇒ 自动生效 |
| `db/db_745_ensure_realdb_test.go` | 2 个真库判据改用 `scratchPool(t)`；**补最小台账夹具**（`schema_migrations`） |
| `db/routing_analytics_source_gate_test.go` | `TestRoutingAnalyticsSourceGates_RealDB` 改为**自己派生空库**（`scratchDSNFor(t, base, scratchFail)`）⇒ 「靶子库要求空库」不再是由调用方承担的前提 |

### 3.3 ★★ 迁到空库后暴露的隐式依赖（这不是副作用，这是收益）

`db_745` 的门迁过去后立刻红：

⇒ ⇒ **搬到一个「更干净」的环境 ⇒ 原本被环境兜住的前置条件全部显形。**

## 5. 新增两道「守」

### 5.1 静态棘轮门 `db/db_package_isolation_gate_test.go`

规则（4 条）：

1. **不开库的文件不是污染源**（纯文本门手里的 `CREATE TABLE public.…` 是迁移脚本文本）。
2. 破坏性字面量集合 = `DROP TABLE/VIEW/MATERIALIZED VIEW/SCHEMA/FUNCTION/PROCEDURE`、`TRUNCATE`、
   `CREATE TABLE public.*`、`CREATE VIEW public.*`。
3. 含破坏性字面量 ⇒ 必须**隔离**（走 scratch helper **或** 自己 `CREATE DATABASE`）。
4. 含破坏性字面量 ⇒ **不得**从共享 DSN 变量直连（AST 追 `x := os.Getenv(<共享名>)` → `pgxpool.New/pgx.Connect(…, x)`）。

**量具自检**（`TestDbPackageIsolationScannerDetectsHistoricalPattern`）：
**正对照**（历史形态必须被命中）+ **负对照**（走 helper 的写法必须不被命中）。

**显式豁免**（3 条，带理由，且数量有上限 3）：

| 文件 | 理由 |
|---|---|
| `db_750_ensure_realdb_test.go` | 只 CREATE/DROP **自己建的探测分区**（net zero），且需要产品表 `usage_facts` 在场 ⇒ 不能进空 scratch 库 |

## 6. 本轮的三处自我订正

### 6.1 ★★★★ 量具事故 ×2：同一把尺子，两次读出假数

**事故 A（第一次）**：`relkind` 是 PG 的 `"char"` 类型，写 `c.relkind||' '||n.nspname` 报
`operator is not unique: "char" || unknown`（`relkind` 是 `"char"` 类型）⇒
而 stderr 被重定向进 `/dev/null` ⇒ **输出是空文件** ⇒ `comm`/`diff` 读出「**0 个差异**」。
★ 一个**假读数**差点被写成验收结论。
⇒ 加 `::text` cast 后回读行数（`iso=2436 / clean=2296`）才作数。

**事故 B（第二次，最后一次指纹）**：后台命令里**漏了 `export PGPASSWORD`** ⇒ psql 连不上 ⇒
指纹文件里躺着 **2 行错误文本**（`ERROR:` + `HINT:`）⇒ `diff` 读出「**2440 行差异**」
⇒ ★ 看起来像「形态库被彻底摧毁了」⇒ **其实是量具没连上。**
⇒ 加 `::text` cast 后回读行数（`iso=2436 / clean=2296`）才作数。
⇒ ★★ **两次都栽在同一件事上：「比较类读数的两端，先证明清单本身是对的」。**

### 6.3 ★★★ 订正我自己中途的推断：(A)/(B) **不是**污染源（见 §2.1）

### 6.4 ★★★ 尺子脚本自己的两次事故（写工具的人和用工具的人栽的是同一类）
