### §2.2 ★ 量具故障一：`relkind` 拼接歧义 ⇒ **SQL 报错被 `2>/dev/null` 吞掉**

第一版查询用 `n.nspname||'.'||c.relname||'|'||c.relkind`，在 PG 17 上：

```
ERROR:  operator is not unique: text || "char"
```

⇒ ★★ 而我把它和 `2>/dev/null` 写在同一条命令里 ⇒ **报错被吞** ⇒ 输出文件是**空的**
⇒ ★ **空文件看起来完全像「0 个关系」** ⇒ 我差点据此断言「生产里一个关系都没有」。
⇒ ⇒ **加 `::text` cast 后才拿到 721**。

⇒ ⇒ ★ **通用式**：**读数落成文件时，必须同时断言「非空」与「stderr 为空」** ——
★ **空结果文件是最危险的读数**，因为它同时是「真的 0」和「查询炸了」的形态。

### §2.3 ★ 量具故障二：`while read` **漏掉无换行的最后一条**

用 shell 循环逐条查「本仓迁移里有没有建它」时，Python 写出的清单**最后一行没有换行**
⇒ `while read -r` **静默跳过最后一条** ⇒ 98 条只处理了 97 条。
⇒ ★ 而且我的**统计口径自相矛盾**（`|—` 与 `|$` 两种写法）⇒ 得出「97 有来源 / 92 没来源」
这种**加起来大于总数**的读数（97+92=189 ≫ 98）⇒ ★ **正是这个自相矛盾把它暴露出来的**。

⇒ ⇒ ★ **通用式**：**逐条分类的读数必须自带「分桶之和 == 输入条数」的断言** ——
★ 本轮重写后断言 `25+66+9+9+98 == 207` 成立才继续。

### §2.4 ★ 量具故障三（协作补记 · 并行会话 R97 轮续实测）：**`grep` 命中被 `head` 截断 ⇒ 结论整个反向**

★ 2026-10-21 并行会话（R97 轮续）独立复核本节结论时，顺带报出**第三条同类量具故障**：
他们查 `model_offers` 时，第一次用 `grep -n model_offers sql/schema/01-schema.sql | head -3`
⇒ **只看到前 3 行命中**（全是 `CREATE FUNCTION`）⇒ ★★ **差点得出「`01-schema.sql` 里没有
`CREATE VIEW model_offers` ⇒ 对方的说法不成立」的假反例** ⇒ ⇒ **结论会整个反向**。

⇒ ⇒ ★★★ **通用式（第三次栽在同一族上）**：
1. ⭐⭐⭐⭐⭐ **★ `grep` 一个名字时，若命中被 `head` 截断 ⇒ 结论可能整个反向** ⇒
   ⇒ **要么 `grep` 特定的语句形态**（`grep -n "CREATE.*VIEW model_offers"`），
   ⇒ **要么别截断**（用 `-c` 计数、或把全部命中落到文件再看）。
2. ⭐⭐⭐⭐⭐ **★ 「没找到」这个结论，必须先证明「搜索面完整」** ⇒ ⇒
   **命中被截断** 与 **真的没有** 在输出上长得**一模一样**（都是「屏幕上没有那一行」）
   ⇒ ⇒ ★ **凡是要据此说「不存在」的地方，都要附上「我是怎么确认搜全了」的证据**
   （计数 + 形态 + 位置）。
3. ⭐⭐⭐⭐ **★ 本节前两条故障（`relkind` 拼接歧义被 `2>/dev/null` 吞掉 / `while read` 漏最后一条）
   与本条是同一族** ⇒ ⇒ **三条的共同形状 = 「失败/不完整」在输出上伪装成「干净的空结果」**
   ⇒ ⇒ **量具自检的通用形状 = 「断言结果非空 + 断言条数与期望一致」**。
4. ⭐⭐⭐⭐ **★ 这条对任何「按名提取清单」的提取器直接适用** ⇒ ⇒
   并行会话下一轮要建的「产品按名引用的关系集合」提取器，**必须带这一条自检**
   （★ 搜索面完整性的证明，不能只靠「grep 没命中」）。

★ **协作补记的原始上下文**：并行会话 R97 轮续（形态量具线续十三，落段 **`§19.20.68` / R98 轮（形态量具线 · 续十三）**）对
