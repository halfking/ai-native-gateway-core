## §0 结论

1. **浮层归属列修复**：旧实现 `RequestZoomPanel` 只挂在 `.live-topology__right`
   —— 点左栏请求，摘要浮层也弹在右栏。本轮引入 `zoomSide: 'left' | 'right'`
   （由布局层按面板传死，面板组件不知道自己在屏幕哪边），浮层跟着点击侧走：
   左栏点击锚左下、右栏点击锚右下（`side` 属性，互为镜像）。
2. **同病根的第二处（本轮最值钱的发现）**：DOM 归属修好后，无头 Chrome 实测
   桌面截图里**根本看不到浮层** —— 浮层 y=1552，视口只有 900。真因：
   grid 行是内容高，50 行/页的明细把左右两栏撑到 ~2000px，浮层锚在
   「整列底部」⇒ 点行后摘要弹在视口外 1000+px 处。**用户说的「摘要位置不对」
   其实一半是「摘要根本看不见」。** 修法：≥1024/≥1440 的
   `grid-template-rows: minmax(0, 1fr)` 把行收进视口，两栏列表回到组件
   设计好的内滚 + 分页形态（`.cp__list`/`.pp__list` 本来就是 overflow-y:auto，
   缺的只是容器高度约束）。
3. **手机端观察模式**（390 宽实测，无头 Chrome + CDP）：
   - 窄屏 `.live-topology` 从 `height:100%` 改自然流式（钉死 100% 会把栅格行
     压成等分三段 159px、列表 0 高 —— 外壳定高 + 行 auto + flex-basis:0 子项
     的连锁塌陷，实测抓到）；
   - 两个请求列表限高 70vh + 列表内滚动：**整页 4623px → 2191px**，
     拓扑与右栏不再被推到「永远划不到」的地方；
   - 聚合摘要（8 行）限高 176px 可滚 —— 此前它把请求明细挤到只剩一两行
     （明细才是面板主体；数据没删，滚动可见全部 8 行，与表头计数对得上账）；
   - ≤768 行高 44px、↗/⤢ 命中区加宽（触控目标，白名单断点）；
   - `TopologyCanvas` `height:100%` → `flex:1 1 auto`（配合行收口，
     路由决策时间线不再被挤出容器；窄屏退化行为不变，min-height 480 兜底）。

## §1 病根与证据链

- **DOM 层**：改前 `/dev/live-topology-preview` 上点 `.cp__item` 后
  `.live-topology__right .zoom` 存在、left 侧不存在 —— 浮层确实只挂右栏。
- **几何层**：改侧后 `zoom` rect y=1552 > 视口 900；`.live-topology__left`
  高 1994px（33 行明细全展开，无内滚）。
- **视觉层**：截图视觉分析确认「没有看到浮层」—— 与 DOM「存在」矛盾，
  正是 LESSONS §419「0 命中有两种读法」的布局版：**DOM 在场 ≠ 用户可见**。
- **外壳差异**：DEV 预览页（`meta.public`）走 `.guest-layout`（min-height:100vh
  可增长 → 高度链不定），生产 `/live` 走 `.app-layout`（100dvh + overflow:hidden
  → `.main-body` 定高）。**在访客外壳上验证已登录页面的几何是错的量具** ——
  本轮用 CDP 注入等价样式（定高 + overflow hidden）模拟已登录外壳复测，
  才得到生产行为的读数。

## §4 教训（本轮新形态）

1. **「位置不对」的一半是「根本看不见」**：用户报告的是「摘要显示位置」，
   DOM 归属修复后视觉验证仍不通过 —— 浮层在视口外 1000+px。**修完第一步
   必须做一次「用户视角」的视觉复核**（截图/几何双证），DOM 在场 ≠ 可见。
2. **在访客外壳上量已登录页面的几何 = 错误量具**：DEV 预览页是 public 路由
   → guest 布局（min-height 增长链），生产是 app 布局（定高链）。两者对
   `height:100%` 子树的解析完全不同。模拟外壳时必须复刻真实外壳的关键
   样式（定高 + overflow），否则修出来的 CSS 在生产是另一个行为。
3. **钉死高度 + flex-basis:0 子项 + grid 行 auto = 连锁塌陷**：窄屏把
   `.live-topology` 钉在 100% 后，栅格行塌成等分三段 159px、列表 0 高。
   窄屏要的是自然流式（页面滚动），桌面才钉满（配合行收口）。
4. **列表限高必须连同「谁吃空间」一起算**：限高 70vh 后聚合摘要（8 行）
   仍把明细挤到一两行 —— 次要信息（摘要/统计栏）也要可收缩（限高可滚），
   否则主体（明细）拿不到空间。
