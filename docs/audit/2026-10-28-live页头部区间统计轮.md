## 1. 为什么短窗口必须后端直查（而不是从实时流聚合）

- `stats_usage_daily` 是**纯日粒度**（无 hour 列）且 rollup 每小时重建 ⇒
  1h/5m 无法从日桶表如实得出；
- **实时流不可用作统计源**：Redis 快照每泳道只留 `LiveStreamLaneVisibleLimit=100`
  条、前端 `MAX_VISIBLE ≤200`，高峰期一分钟的流量就填满缓冲 ——
  从它聚合「1 小时」会系统性偏低，**把低估说成统计**；
- `request_logs` 有 `idx_request_logs_ts (ts DESC)` ⇒ 短窗口聚合走索引；
  归并口径与 live-stream SSE catch-up 查询**逐字同款**
  （credentials→providers / models_canonical / request_status CASE 表达式），
  不引入第二套真值。

### 2.1 本轮最值钱的一处：共享 SQL 片段的 Go 常量拼接会让量具失明

第一版把状态表达式抽成 Go 常量 `requestLogsStatusExpr` 再拼进两条 SQL
（`` ` + requestLogsStatusExpr + ` ``）——登记簿门当场红：
扫描器登记的读点**缺 `request_status:expr` 与 `success:base`**。
根因：canonical 读点扫描器走 go/ast，**只认 SQL 字面量文本，不解析 Go
标识符拼接** ⇒ 运行时真实引用的列从扫描结果里隐身。
修法：把表达式**逐字内联**进两条 SQL（扫描器视线 = 运行时真相），
单源纪律由契约测试钉住（`Contains(SQL, requestLogsStatusExpr)` ——
只改一处时钉子变红）。

   211 无此问题）；本地降级验证即用该环境完成。
4. **访客外壳 guest-header 在 390px 有横向溢出**（Download/License 等导航
   链接不换行）——**预存在**，与本轮无关（统计面板自身 366px 收在视口内）。

   明细两组仍联动过滤）。
