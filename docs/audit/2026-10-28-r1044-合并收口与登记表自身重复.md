## 四、★★★ 本轮最值钱的发现：一次**零冲突**合并造出的重复登记

### 4.1 现象

`git merge origin/main` 输出 **「Auto-merging web/src/components/ui/mobileListUx.spec.ts」、
零冲突、一次成功**。合并后该文件里：

```
158:  ['src/views/tenant/MaaSBillsView.vue', 125, '月账单内嵌表（title-key=period_ym）：…'],
167:  ['src/views/tenant/MaaSBillsView.vue', 125, '月账单内嵌表（账期聚合行），无账单详情页'],
```

⇒ ★ **同一个 (文件, 行号) 两条登记**，理由不同、来源不同（一边是 r1043 合并带进来的
「`eb6f6582d` 漏登记」，一边是上游 `a82ebec4f` 的「wip/07 合入漏带」）。
⇒ ★★ 两条**互不知情**：两边各自看自己的那一条都是对的。

### 4.2 为什么 git 合干净了，语义却没合干净

git 的自动合并判的是**行级冲突**。两侧的插入点相隔若干行、上下文不重叠 ⇒
⇒ **git 没有任何理由把这两行判成冲突** ⇒ 合干净。
⇒ ★★ **git 保证的是「行不冲突」，不是「同一实体不被登记两次」。**

### 4.3 ★★ 为什么那道门**一条断言都没拦住**

登记表类断言的通行做法是把登记集收进 `Set`：

```ts
const registered = new Set([...NON_NAVIGABLE, ...KNOWN_GAP].map(([f, l]) => key(f, l)))
```

★ `Set` **会去重** ⇒ 同一个 (文件, 行号) 登记两次时：

| 既有断言（7 条） | 为什么照样绿 |
|---|---|
| 登记表与实测集合**双向相等** | `registered.size` 不变 ⇒ `measured.size === registered.size` 成立 |
| 未登记 / 已不成立（集合差） | `unregistered` / `stale` 都是集合差 ⇒ 重复项不进任何一个差集 |
| 每条登记都必须写明理由 | 逐条遍历 ⇒ 同一条被跑两遍，两遍都合法 |
| `NON_NAVIGABLE` 的每一项… | 同上 |
| `KNOWN_GAP` 的每一项… | 同上 |
| `ASYMMETRY` 登记与实测双向相等 | `registered` 同样是 `Set` ⇒ 去重 |

⇒ ★★★ **重复登记对既有断言完全不可见。**
★★ 这不是「规约没覆盖」，是**判据的采集面**（`Set`）把要检的东西**吃掉**了 ——
与 r1043 的「台账不是水位」、r1042 的「额度/裁剪/记账三处口径不同单位」同族：
★★ **量具的形态决定了它能看见什么。**

### 4.4 为什么重复本身是缺陷（而不只是冗余）

① 两条理由会**各自漂移**（后来只改一条 ⇒ 登记理由与事实脱节）；
② 行号漂移时要改**两处**，漏改一处就留下一个「看似已登记、实则对不上」的幽灵；
③ 按行号查登记表会看到两条 ⇒ 「这条到底登记了几次」变成不确定问题；
④ **跨表重复**（同一行号既在 `NON_NAVIGABLE` 又在 `KNOWN_GAP`）会把
「已确认合格」与「不合格但已知」两个**互斥结论**同时挂在同一处。

### 4.5 修法

**① 收敛成一条**（保留信息量最大的一份，双方信息取并集）：

```ts
['src/views/tenant/MaaSBillsView.vue', 125,
  '月账单内嵌表（账期聚合行，title-key=period_ym）：/tenant/bills 无账单详情页，本视图无二级目的地'],
```

并在登记处的注释里**写明两侧来源与合并事实**（仓内惯例：登记处必须留下行号锚点与理由的来历）。

**② 补第 8 条断言**（覆盖 `NON_NAVIGABLE` + `KNOWN_GAP` + `ASYMMETRY` **三个登记表的并集**）：

```ts
it('登记表自身不得有重复的 (文件, 行号)', () => { … })
```

★ 判据用**多重集**（`Map<string, number>` 计数）而**不是** `Set` —— 这正是把
§4.3 那张表逐条反过来做一遍。
