### ★ C9：唯一坐实的真缺陷（生产可复现）

**缺陷**：`admin/data_lifecycle.go` 的分段 SQL 用
`(sz.total_size * a.total / NULLIF(g.rows_all, 0))::bigint` 产出 `size_bytes` / `size_human`。
会话族两腿都空时 `rows_all = 0` ⇒ 除以 NULL ⇒ **两列都是 NULL**。
而 handler 把它们扫进**非指针** `int64` / `string`（`dedupRow`）
⇒ pgx scan 报错 ⇒ 该行被跳过 ⇒ **`__ALL__` 行缺失** ⇒ 走 `!gotAll` 分支 ⇒ **端点 500**。

**实测复现**（生产 SQL 原文 + 事务内删空 + ROLLBACK）：

```
__ALL__|0|0|0|0|0|<NULL>|<NULL>|0
```

**可达态不是理论上的**：新装库、日志 TTL 清空后、日志族整体退役后。

**修法**：**在 SQL 侧**收口（不改成可空扫描）：`COALESCE(..., 0)` ——
0 行 ⇒ 摊派结果本就该是 0 字节，COALESCE 把「无行」翻译成 0，而不是让 NULL 穿透到 scan 变成 500。

**新门**（`admin/data_lifecycle_canonical_segments_test.go`）：
`TestDataLifecycleCanonicalSegmentsSurvivesEmptyFamily` ——
**判据与被测对象同层**：跑生产那条 SQL、扫生产那个**非指针** scan 形状，
删空写在**会 ROLLBACK 的事务**里 ⇒ 门无副作用、可指向任何库。

## §5 ★★ D2（新发现）：**注册启动链不可重跑** —— 第二遍 **52 条**失败

### 5.3 影响面（★ 为什么这条不能当「理论风险」）
