# 2026-11-23 用量趋势「Top 10 用户」名称显示原始 JSON + 六维点击跳转过滤失效——根因归档

> **范围**：`/admin/usage-trends` 的「Top 10 用户」卡片（① 显示名是原始 JSON 串、② 口径是按会话而非按用户），
> 以及六张排行卡片「点击 → `/admin/request-logs`」的跳转过滤（此前**只有 model 一维真正生效**）。
> **改动面**：后端 `admin/usage.go` + `admin/logs.go` + 两个新钉测文件。**零迁移 / 零 schema 变更 / 零前端改动**。

---

## 一、报障与现象

owner 报「Top 10 用户卡片名称显示成原始 JSON 串」+「点击排行卡片跳到请求列表后，看到的**不是**该维度的请求」。

### 1.1 现象取证（211 生产实测，2026-11-23）

**① 显示名**：`GET /api/admin/usage/top-rankings?...&users_limit=10` 返回 `top_users` 10 条，其中
**9 条 `name` 是原始 JSON 串**（`{"device_id":"50f0282d-…","account_uuid":"","session_id":"5d131116-…"}`），
1 条是 `anonymous`。

**② 跳转过滤**：`GET /api/logs?end_user_id=ZZZ_NOT_A_REAL_USER_12345`（一个**根本不存在**的值）
与传真值返回的 **100 条完全一样**，首条都是 `anonymous`
⇒ ⇒ 该参数**从未被后端消费**（过滤恒不生效 ⇒ 跳过去看到的是未筛选的全量）。

源码侧对拍：`admin/logs.go` 全仓只有 `model` 一个维度实现了 `queryString` 过滤，
其余五维（`client_model` / `end_user_id` / `api_key_prefix` / `application_code` / `task_type`）**0 处**。

## 二、根因

### 2.1 「显示成 JSON」的根因：`end_user_id` 存的是客户端上报的 `user` **原值**

`request_logs.end_user_id` 存的是**客户端上报的 `user` 字段原值**
（见 `domains/streaming/handler.go` 的 `resolveEndUser`，body-sniff 兜底）。现网实测形态分布（211）：

| 形态 | 行数 | 说明 |
|---|---:|---|
| `anonymous` | 379,142 | 兜底值 |
| `NULL` | 38,657 | 未上报 |
| `{"device_id":"…","account_uuid":"","session_id":"…"}` | 14,674 | **客户端把 `user` 报成了 JSON 对象** |
| `user-admin` / `auth0\|user_01J…` / … | 49 | 真正的纯 id |

排行侧当时直接 `GROUP BY rl.end_user_id` ⇒
① **显示**：整段 JSON 被当成「用户名」渲染；
② **口径**：那段 JSON 内含 `session_id` ⇒ 实际是**按会话分组**
⇒ 实测 14,674 行 JSON 只对应 **1 个 device_id**、**117 个 session_id**
⇒ 「Top 10 用户」里 9 条其实是**同一个设备的 9 个会话**。

⇒ **device_id 才是真实用户标识**（`account_uuid` 在现网恒空，不可依赖）。

### 2.2 「跳转过滤失效」的根因：五维参数后端**一个都没实现**

排行卡片会带维度参数跳到 `/admin/request-logs`，而后端只认 `model` ⇒
「点击进去可以看到详细的请求」此前**只有 1/6 成立**。

## 三、修法

### 3.1 共享一个「用户身份」表达式（跨文件契约）

新增常量 `userIdentityExpr`（`admin/logs.go`）：

```sql
COALESCE(
  NULLIF(CASE WHEN rl.end_user_id LIKE '{%'
              THEN substring(rl.end_user_id from '"device_id"\s*:\s*"([^"]*)"') END, ''),
  NULLIF(CASE WHEN rl.end_user_id LIKE '{%' THEN NULL ELSE rl.end_user_id END, ''),
  'unknown'
)
```

★ **排行侧（`admin/usage.go`）与过滤侧（`admin/logs.go`）必须共用同一个常量** ⇒
排行按它**分组**、显示名取它；过滤按它**等值匹配**
⇒ ⇒ 卡片上的 `request_count` 与点进去看到的条数**逐条对得上**。
★★ 两边各写一份表达式是这类修复最常见的假绿来源（改了一边忘了另一边 ⇒「卡片 14,674 / 点进去 0 条」）。

三个作用点：

1. **显示**：JSON 行取 `device_id`（可读）；
2. **口径**：同一 device_id 的多个 session 归为一组 ⇒ 回到「Top 10 用户」；
3. **兜底**：NULL / 空串 / JSON 里没有 device_id ⇒ 归 `'unknown'`，
   **过滤侧同口径** ⇒ 点击 `unknown` 也能查到这些行（否则卡片有它、点进去 0 条）。

★ 为什么用 `substring(... from ...)` 而不是 `::jsonb->>`：该列混着 `'anonymous'`/NULL/纯 id 等
**非法 JSON** 值 ⇒ `::jsonb` 会对它们抛错 ⇒ 整条查询 500。
`substring` 的正则形式对非 JSON 输入安全地返回 NULL；再由 `CASE` 包住 ⇒ 只在确实以 `'{'` 开头时才做正则提取（PG 的 `CASE` 是惰性的）。

### 3.2 五个维度补齐过滤（`admin/logs.go`）

抽成纯函数 `buildRankingDimensionFilterClauses(r, argIdx)`，`listLogs` 调用它：

| 维度 | 谓词 | 口径依据 |
|---|---|---|
| `client_model` | `rl.client_model = $n` | 排行侧取值 = 同一列 |
| `end_user_id` | `rl.end_user_id = $n OR <userIdentityExpr> = $n` | 腿①为**旧链接/直链**保留（修复前界面传的就是整段 JSON）；腿②与排行同口径 |
| `api_key_prefix` | `starts_with(rl.api_key_prefix, $n)` | ★ **前缀**匹配，见下 |
| `application_code` | `rl.application_code = $n` | 排行侧取值 = 同一列 |
| `task_type` | `rl.task_type = $n` | 排行侧取值 = 同一列 |

★ **`api_key_prefix` 为什么必须前缀匹配**（211 实测）：

```
ak.key_prefix = 'sk-pi-autollm-21'   （明文）
rl.api_key_prefix = 'sk-pi-autollm-21***'  （掩码值，掩码长度随前缀长度变）
⇒ 等值匹配命中 0 行（实测该 key 470 行 ⇒ 0）；前缀匹配命中 470 行
```

★ 为什么用 `starts_with` 而不是 `LIKE`：★ `LIKE` 把 `%`/`_` 当**通配符**，语义不是「前缀」
（传 `sk-%` 会匹配所有 key）⇒ `starts_with` 是字面前缀语义。

★ **五列在 native 源里都存在**：列表路径实际走 `logsSourceFromSQLWindowed`
（`session_turns_hot ∪ session_turns` LEFT JOIN details 两臂）⇒
`end_user_id`/`task_type` 来自 turns 臂，`client_model`/`api_key_prefix`/`application_code` 来自 details 臂，
五列全在 canonical 118 列契约里 ⇒ 不会 `column does not exist`。

## 四、钉测

### 4.1 静态门（`admin/logs_ranking_dimension_filters_test.go`，不依赖 DB）

| # | 断言 | 能在什么坏法下变红 |
|---|---|---|
| 1 | 五维的 `queryString(r, "<key>")` **且**谓词文本都在 | ① 参数被删；② **读了参数却没拼进 WHERE**（光断 `queryString` 抓不住） |
| 2 | `api_key_prefix` 走 `starts_with`、不走 `LIKE` | 退回等值（命中 0 行）/ 退回 LIKE（通配符语义） |
| 3 | `end_user_id` 谓词内嵌**共享的** `userIdentityExpr`、两条腿共用同一 `$n` | 两边漂移（卡片数 ≠ 列表条数） |
| 4 | `userIdentityExpr` 不用 `::jsonb`、含 `device_id` 提取、含 `'unknown'` 兜底、**逐字**出现在渲染后的谓词里 | 非法 JSON 抛错 500 / 兜底丢失 / 表达式被当成 Sprintf 格式串吃掉 `%` |
| 5 | `listLogs` 真的调用 `buildRankingDimensionFilterClauses` | 纯函数存在但端点没接（死代码） |
| 6 | `usage.go` 用 `queryTopN("users", userIdentityExpr, usersLimit)` 且**不自己抄**一份提取表达式 | 排行侧与过滤侧漂移 |

### 4.2 真库行为门（`admin/logs_ranking_dimension_filters_realdb_test.go`）

★ **直接调生产函数** `buildRankingDimensionFilterClauses` 拿谓词（不是在测试里重抄 SQL
—— 后者测的是「测试自己写的 SQL」，产品坏了测试照样绿）。

夹具的 `end_user_id` **同时**含六种形态：JSON（两个会话同一设备）/ anonymous / 纯 id / NULL / 空串 /
无 device_id 的 JSON。

★ 前缀补 `$1..$4` 四个**已占用**的占位符 ⇒ 复刻 `listLogs` 的生产编号上下文
（`$1/$2` = 分区键下界、`$3/$4` = ts 窗口、排行过滤从 `$5` 起）
⇒ ★ PG 的 `$n` 是**绝对位置**，少绑 4 个参数会直接 `42P18 could not determine data type of parameter`
—— ★ 这条是本门**第一次跑就抓到的真问题**（测试自己写错了编号，恰好证明了「生产编号形态必须被测」）。

核心不变式：**每一组的卡片行数 == 用该组名过滤得到的行数**。

## 六、通用式（本轮沉淀）

1. ★★ **「卡片上的数字」与「点进去看到的条数」是两个契约** ⇒ 排行侧与过滤侧**必须共用同一个表达式常量**。
   两边各写一份 ⇒ 改了一边忘了另一边就是「卡片 14,674 / 点进去 0 条」⇒ ⇒ 跨文件共享常量 + 真库门对拍**分组数 vs 过滤数**。
2. ★ **客户端上报的自由文本字段（`user`）不能直接当主键/显示名** ⇒ 先量形态分布（实测四类），
   再决定口径（`device_id`）⇒ 直接 `GROUP BY` 原值会把「按会话」误当「按用户」。
3. ★ **掩码值列不能等值匹配明文前缀** ⇒ 实测 `ak.key_prefix='sk-pi-autollm-21'` ↔ 库里 `'sk-pi-autollm-21***'`
   ⇒ 等值命中 0 行 ⇒ 必须前缀语义；且用 `starts_with` 而不是 `LIKE`（`LIKE` 的 `%`/`_` 是通配符，语义不是前缀）。
4. ★ **PG 的 `$n` 是绝对位置** ⇒ 测「后端拼出来的谓词」时必须复刻**已占用的前置占位符**上下文，
   否则测的是另一个编号形态 ⇒ 本门第一次跑就因 `42P18` 抓到了测试自身的编号错误。
5. ★ **过滤谓词构造抽成纯函数** ⇒ 真库门能直接调生产代码拿到谓词；
   在测试里重抄 SQL 测的是「测试自己写的 SQL」⇒ 产品坏了测试照样绿。

## 七、登记（遗留 / 待裁决）

- **L1**：`end_user_id` 的 JSON 形态里 `account_uuid` 现网**恒空** ⇒ 只能靠 `device_id`；
  若将来客户端开始上报 `account_uuid`，身份表达式需要重新定口径（当前会忽略它）。
- **L2**：`api_key_prefix` 走**前缀**匹配 ⇒ 若两个 key 的明文前缀互为前缀（短的是长的前缀），
  短前缀会同时命中两者的行（现网 `sk-pi-autollm-21` 与 `sk-pi-autollm-211` 这种形态存在潜在歧义，
  需按 `api_key_id` 才能精确区分）。
- **L3**：`unknown` 组的过滤依赖共享表达式 ⇒ 若将来排行侧给 NULL 组换个显示名（如「未标识」），
  过滤侧会同步失配 ⇒ **改显示名必须改共享常量，不能单边改**。
