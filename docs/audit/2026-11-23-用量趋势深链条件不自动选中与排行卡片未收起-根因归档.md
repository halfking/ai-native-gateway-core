## 一、报障与现象

owner 报：「用量趋势页，如果链接中指定了某个条件，则在页面的条件选择中自动选择相关的条件的下拉或选项，
并且在页面的列表中隐藏相关的列表，不用显示多余的数据。」

### 1.1 现象取证（211 现役，浏览器实点，2026-11-23）

| # | 深链 | 实测结果 | 判定 |
|---|---|---|---|
| ① | `?model=claude-opus-5-5` | 条件区出现徽标「模型 claude-opus-5-5 ✕」、**数据已过滤** ✔；但**「Top 5 模型」卡片没收起** ⇒ 顶着「Top 5」标题只剩 **1 行（13.5K）** | 缺陷 A：多余数据 |
| ② | `?end_user_id=anonymous` | 条件区**全是「全部」**；Top 10 用户仍是全站 **3 个用户**、Top 5 模型仍是 **5 个** ⇒ 图表/排行**完全没被过滤** | 缺陷 B：条件被完全忽略 |

★ **缺陷 B 比缺陷 A 更严重**：① 是「该收没收」，② 是「**URL 承诺的条件与页面呈现的数据不一致**」
⇒ 用户看到的是全站数据，却以为自己在看某个终端用户的用量 ⇒ **「界面显示的 ≠ 数据反映的」**。

### 1.2 入链来源盘点（前端实测）

全站只有两处会跳到本页带条件：

- `SaTop5Rankings.vue` → `?model=` / `?provider=`
- `SessionStatsRankings.vue` → `?model=`

⇒ ★ **既有入链只用到 2 个维度**，而页面内部六张排行卡片的**跳转出链**却用了 6 个维度
（`model` / `client_model` / `end_user_id` / `api_key_prefix` / `application_code` / `task_type`）
⇒ ⇒ **两页的维度词汇不闭环**（出链用六维、入链只有两维）⇒ 这是缺陷 B 的结构性来源。

## 二、根因（三处断点，分属三个位置）

### 2.1 断点①：深链钉住的维度，其对应排行卡片**没有被收起**

上一轮（Top10 卡片 + 六维跳转过滤那轮）owner 原话里已经写了「把对应维度的列表收起来」，
但**至今未实现、也没有钉测**——当时只钉了「条件区显示徽标」这前半句。

⇒ 「条件区有徽标」被当成「深链轮做完了」⇒ **后半句静默缺失**，没有任何测试会红。

### 2.2 断点②：用量趋势页**只认 4 个条件**（provider / tenant / apikey / model）

排行六维里的其余五个（`client_model` / `end_user_id` / `api_key_prefix` / `application_code` / `task_type`）
在本页**既没有选择器、也没有后端过滤**：

- **前端**：`RequestLogsView.vue` 那轮把五维加进了**请求日志页**的深链词汇，
  但**用量趋势页的 `usageTrendFilters` 结构体里没有它们** ⇒ 页面读不到、也不会发给后端；
- **后端**：`/api/admin/usage/*` 的排行与序列查询**没有任何这五维的谓词** ⇒ 就算前端发了也不生效。

⇒ ★★ **两头都缺** ⇒ 只修后端仍无效（页面不转发）、只修前端也无效（后端不消费）。

### 2.3 断点③：`syncQuery` **全量重建** query ⇒ 不认识的参数被悄悄抹掉

`UsageTrendExplorer.vue` 的 `syncQuery()` 每次都从零拼一个 `next` 对象再 `router.replace`。
凡是不在它白名单里的参数 ⇒ **一律消失**。

⇒ ★ 这就是 `?end_user_id=anonymous` **连 URL 都保不住**的机制：
页面一次 watch 触发 ⇒ `syncQuery` 把它抹掉 ⇒ 用户刷新、复制链接都会丢掉条件。

## 三、修法

### 3.1 口径拍板（owner 问卷：范围=all / 呈现=dropdown）

- **范围**：六张排行卡片的维度（model / client_model / end_user_id / api_key_prefix / application_code / task_type）
  ＋ 页面原有四个条件（provider / tenant / apikey / model）**全部认**；
  每个条件**真过滤数据**（不只是显示），且**收起对应排行卡片**。
- **呈现**：**有选择器的维度保留下拉框并自动选中该项**（显示友好名而非原始值），带 ✕ 解除；
  **无选择器的维度用只读徽标 chip + ✕**。

### 3.2 「收起哪张卡」的判据（唯一真相＝维度表）

`web/src/utils/usageTrendDeepLink.ts` 重写为**九维单一真相** `DIMENSION_SPECS`：

| 维度 | URL 参数 | 对应排行卡片 | 条件区形态 |
|---|---|---|---|
| provider | `provider` | —（页面不按这维排行） | picker |
| tenant | `tenant` | — | picker |
| apikey | `apikey` | Top 5 API Keys | picker |
| model | `model` | Top 5 模型 | picker |
| client | `client_model` | Top 5 客户端 | chip |
| user | `end_user_id` | Top 10 用户 | chip |
| project | `application_code` | Top 5 项目 | chip |
| task | `task_type` | Top 5 任务 | chip |
| apikeyPrefix | `api_key_prefix` | Top 5 API Keys | chip |

★ **两条边界**：

1. `provider` / `tenant` **没有对应卡片** ⇒ 收起**任何**卡片都不对 ⇒ 不收起；
2. `apikey` 与 `api_key_prefix` **同指 API Keys 卡** ⇒ 只列一次（`hiddenRankingArms` 去重）。

★ **为什么收起的判据是「维度当前有过滤值」而不是「维度在 URL 里」**：
卡片排的**就是这个维度** ⇒ 维度一旦有过滤值，这张卡必然退化成一行 ⇒ 顶着「Top 5」标题摆 1 行 = 多余数据。
其余卡片**保留**：它们是当前条件的**下钻拆解**（模型都被钉住了，「Top 5 客户端 / Top 10 用户」正是有价值的细分）。

### 4.3 ★ 本轮踩到的两个坑（都是门抓到的，不是想当然）

**① canonical 读点登记簿门红——根因是「我多写了一处字面量」**

整包 admin 门红：`admin/usage_trend_series.go` 读点**登记 3 条 / 扫描实测 4 条**。
根因：我在 `usageTrendSource` 的 switch 里**新增了一处 `return "request_logs_with_current_month"`** 字面量。

⇒ ★ **正解不是补登记**（补登记＝把「读点变多」合法化，而不是解释「为什么变多」）：
**把两个 case 合并**——`api_key / provider / 五维` 三条过滤理由不同、但**读面选择是同一个决定**
⇒ 合并成一个 case ⇒ 字面量出现次数回到 3 ⇒ **登记簿零漂移**，且分档语义仍由 `f.dims` 携带、与档位选择解耦。

★ **通用式**：读点登记簿这类「条数对拍」的门，**红的时候先问「是我的代码多写了一处，还是语义真的多了一处」**——
前者该合并、后者该补登记；**一律补登记会把代码膨胀固化成规范**。

**② i18n 键路径写错——漏了顶层命名空间前缀**

我在维度表里把 chip 维度的 labelKey 写成 `filter.deepLink.clientModel`，
而真实路径是 **`requests.list.filter.deepLink.clientModel`**（`requests` 是顶层命名空间，
`requests.ts` 被 index.ts 挂成 `requests` 命名空间）⇒ ★ **该键在 8 个语种全部不存在**
⇒ 页面 chip 标签渲染成原始键串 ⇒ **跨语种键存在性门 + 源语种可解析门双双变红**。

★ 这两条红**一开始被误当成「并行会话的改动」**：共享工作树里同时有并行会话对
`web/src/locales/zh-TW/nav.ts` 的在途改动（把繁体改成简体 ⇒ `sameAsSource` 棘轮 +108）。
⇒ ★ **归因方法**：在**隔离 worktree**（只带我的改动、不带并行会话的在途改动）里跑同一批门 ⇒
  - `localeValueQuality`（棘轮）**绿** ⇒ 那 2 条红**不是我的**（并行会话的 zh-TW 改动所致）；
  - `keys_referenced` + `localeKeyParity` **红** ⇒ 这 2 条**是我的**（键路径错）。

⇒ **通用式**：**共享工作树里出红，先在隔离树里复跑一遍再定责**——否则会把别人的红算到自己头上
（改错地方），或把自己的红推给别人（漏掉真缺陷）。

★ 修完顺手补了**两条新钉测**（防同类手滑复发）：
- ⑫ 每个维度的 labelKey 在**全部 8 个语种**都解析得到非空真值（★ bundle 形态必须与各语种 `index.ts` 的聚合形态**同构**，否则这条钉测自己就红）；
- ⑬ chip 维度的 labelKey 与**请求日志页实际使用的键同源**（读 `RequestLogsView.vue` 源码比对）。

★ **变异自证**：把 labelKey 改回 `filter.deepLink.clientModel` ⇒ ⑫⑬ **两条都红**（⑫ 报「ar-SA 解析不到」、⑬ 报「与请求日志页不同源」）⇒ 恢复后 13/13 绿。

## 六、通用式

1. ★★ **「深链钉住」这件事有前半句和后半句，只钉前半句＝后半句可以永远不存在**——
   上一轮把「条件区显示徽标」当成「深链轮做完了」，owner 原话里的「把对应维度的列表收起来」**至今无人实现、无人钉测**。
   ⇒ ⇒ **需求原文逐句拆成可判定的断言**，每句都要有自己的钉测；缺哪句，哪句就会静默缺失。
2. ★★ **两页共用维度词汇时，词汇必须闭环**——出链用了六维而入链只认两维 ⇒ 条件在页面之间**传不过去**。
   ⇒ ⇒ 凡是「A 页跳 B 页带条件」，**B 页必须认 A 页发的每一个参数**；参数名**逐字同名**（⇒ 可互贴链接），
   并用**跨文件契约钉测**把「同名」这件事钉住。
3. ★★ **「参数生效了吗」有两个断点：没发出去 / 发了没接住**——本页五维是**两头都缺**
   ⇒ 只修后端无效、只修前端也无效；**排查时先分清是「参数没被发出去」还是「参数发出去了但被忽略」**。
4. ★★ **「全量重建 query」是最隐蔽的参数丢失源**——凡是不在白名单里的参数都会被悄悄抹掉，
   用户刷新、复制链接都会丢条件 ⇒ ⇒ 深链参数**必须显式写回**。
5. ★ **汇总档只有部分维度** ⇒ 设了它没有的维度却留在汇总档 ⇒ 筛选被**静默忽略**
   ⇒ ⇒ 维度集合与数据档的维度集合**必须对齐**，不齐就**强制换档**。
6. ★ **读点登记簿这类「条数对拍」的门，红的时候先问「是我多写了一处，还是语义真的多了一处」**——
   前者该**合并**、后者才该**补登记**；一律补登记会把代码膨胀固化成规范。
7. ★ **共享工作树里出红，先在隔离树里复跑一遍再定责**——否则会把别人的红算到自己头上，
   或把自己的红推给别人（前者改错地方，后者漏掉真缺陷）。
8. ★ **i18n 键必须是完整路径**——漏一层顶层命名空间 ⇒ 8 个语种全缺 ⇒ 标签渲染成原始键串；
   ⇒ 用「8 语种逐个解析得到非空真值」的钉测钉住，比靠人眼可靠。
9. ★★ **「闸门通过」不等于「你的改动过了闸门」**——闸门**选包**与**基线对照**是两件事：
   `BASE_REF` 只参与基线对照，**选包**只看「工作区 + 暂存区 + 最后一笔提交」
   ⇒ ⇒ **每次上线前都要自己确认「我这次改的包到底进没进闸门」**（本轮 `./admin` 压根没被选中）。
10. ★ **「解除一个条件」必须四步自洽**：参数从 URL 消失 ⇄ 对应卡片重新出现 ⇄ 条件区徽标消失
    ⇄ 数据回到未筛选 ⇒ 少任何一步都是半吊子（本轮四条全部实测通过）。
