## 1. ④ 既有红之一：`test_fail_closed_call_sites`（定位锚指错对象）

- **现象**：`bash tests/deploy_web_surface_test.sh` 4 例中 1 FAIL。断言 `_bluegreen_abort` 出现在
  `if ! verify_public_web; then` 与 `if ! host_mark_verified` 之间。
- **根因**：断言的定位器是 `source.index('if ! verify_public_web; then')` = **文件里第一道门**。
  该测试写于 10-20（3462a8e09），当时全文件只有蓝绿一道门；10-27 的 legacy 门补齐
  （68833c967）在蓝绿路径**之前**插入两道 legacy 门 ⇒ 锚点指到 legacy 分支 ⇒ 假红。
- **定性**：legacy 门**不**调 `_bluegreen_abort` 是**有意的正确行为**——legacy 模式没有蓝绿
  候选态（`$old_version/$candidate_port` 未定义），fail-closed 形态 = 打印可粘贴回滚命令 +
  `exit 1`。生产行为没病，是**测试的锚与断言意图脱钩**。
- **修法**（`tests/deploy_web_surface_test.sh`）：改成**穷举**——解析出全部 `verify_public_web`
  门块（`if/fi` 深度计数，兼容门内嵌套 if），断言 ① 门数恰为 3（legacy canary / legacy host /
  蓝绿）；② 每道门块内必有 `_bluegreen_abort` 或 `exit 1`（fail-closed）；③ 至少一道用
  `_bluegreen_abort`（蓝绿门真正回滚上游）。比原断言覆盖更宽（legacy 门此前不在任何门的视野）。

## 2. ④ 既有红之二：`/state` 端点 503（定性：设计行为，文案缺失是真缺陷）

- **定性链**：`handleCredentialStateQuery` 503 ⟸ `stateManager == nil` ⟸ main.go:1705 只在
  **非** authoritative 模式创建 legacy credentialstate.Manager ⟸ `DefaultConfig().Mode =
  ModeAuthoritative`（ursm/v2/config.go:211）且 211 未设 `URSM_V2_MODE` ⟸ 211 数据面日志实证
  authoritative 生效（`router: URSM v2 authoritative view filtered out every candidate`）。
  ⇒ **503 = spec §10 Step 5 C-1 的设计行为**（v2 是唯一状态权威，legacy StateManager 有意不
  接线），恢复脚本早已正确降级 DB 直读。
- **真缺陷**：503 响应体只有 `state service not available`，不说原因 ⇒ 每个接手的人都要把
  上面这条链重查一遍（本轮就是这么来的）。修法（`admin/credential_state_handlers.go`）：
  nil → `credential live-state service not wired: legacy credentialstate is disabled by design
  in URSM v2 authoritative mode (read node_probe_state / /api/admin/probe endpoints instead)`；
  Enabled()=false → 另一条独立文案。部署后线上实测新文案生效。

## 3. ③ scan-secrets 解释器守卫：把「假绿」修掉之后，存量 WARN 显形

- **缺陷**（上轮已记「scan-secrets 假 0」，本轮落地修复）：sync-to-github.sh 自身用 bash5 跑，
  但 scan-secrets.sh 经 `#!/usr/bin/env bash` 落回 PATH 第一个 bash ⇒ macOS /bin/bash 3.2 下
  `declare -A` 报错后脚本**继续跑完并打印 findings 0** ⇒ strict 扫描形同虚设。
  ⇒ **上轮 dry-run「5 步 exit=0」的绿灯建立在这个假 0 上**（该轮审计档自己记了假 0，但没把
  5 步全绿与假 0 关联起来）。
- **双层修法**：① scan-secrets.sh 头部运行时守卫（`BASH_VERSINFO[0] < 4` ⇒ FATAL + exit 64，
  与 check-and-fix-missing-tables.sh 同款；bash≥4 零行为变化）；② sync-to-github.sh 同守卫 +
  两处调用改 `"$BASH" "$scanner"`（父解释器下传）。
- **守卫落地后的连锁**：strict 扫描**真跑** ⇒ 显形 **21 条一直存在的夹具 WARN**（CRED_ASSIGN）
  ⇒ 逐条人工定性（`sk-*-fixture` / `SUPERSECRET` 占位 / spec mock / 变量解析代码，无真实凭据）
  ⇒ baseline 补登 19 条 + **重钉 2 条**（ExamplesView 行号漂移 39/57→40/58，baseline 是
  `file:line:CATEGORY` 精确匹配）⇒ strict 全绿 ⇒ **dry-run 5 步 rc=0**（16165 文件 0 findings）。
- **顺带修**：`tests/deploy_sops_test.sh` 两处环境性红——①测试用 /bin/bash 调被测脚本，会测到
  守卫而不是被测行为 ⇒ BASH4 解析器（~/sdk/bash5 优先，deploy_local_reap_test.sh 同款）；
  ②macOS 无 GNU `timeout` ⇒ `timeout 30 cmd` rc=127 恒红（**stash A/B 实证 pristine HEAD 同红**
  ⇒ 非本轮引入）⇒ `run_bounded` 兜底。修后 22/22 全绿。

## 4. ③ REPO-MIRROR-POLICY v2.0 契约决断

**决断：树移植（commit-tree）是唯一实推通道；sync-to-github.sh（filter-repo）退役为
`--dry-run` 专用诊断工具；两者互斥。**（`docs/06-deployment/04-runbooks/operations/REPO-MIRROR-POLICY.md` §10）

  diff 空 + ls-remote 对拍；上轮已执行到 992d2f6ee）。
- filter-repo 只许 dry-run 的理由：实推 = force-push 重写历史 ⇒ 毁掉上述主张；且**全量改写
  完整性前提当前不满足**——退役 252 DB/SSH 口令只在 sops 加密的 `.env.252.enc` /

  复核）⇒ 不可恢复 ⇒ 私有替换表头已如实注明。**补齐属用户侧动作（需提供 sops/age 密钥）**。
- 文档同步：§1 表格的镜像 URL 从 v1.x 的 `SI-LLM-Gateway.git` 订正为
