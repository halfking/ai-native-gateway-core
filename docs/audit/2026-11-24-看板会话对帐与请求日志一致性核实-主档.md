## 五、重复计算逐项审计

### 5.1 ✅ 请求日志三臂：互斥，无重复

```sql
hot ∩ parent = 0 ；probe_hot ∩ parent = 0 ；hot ∩ probe_hot = 0
session_turns        451,730 行 / 451,730 个不同 request_id
session_turns_hot      2,916 行 /   2,916 个不同 request_id
session_turns_probe_hot 364,656 行 / 364,656 个不同 request_id
```
⇒ 三臂是**物理分表 + 按 `request_id` 车道互斥**，`UNION ALL`（`db/session_probe_arm_source.go:210`）不产生重复。

### 5.2 ✅ 会话宇宙：D2 去重有效

会话侧 **77,120 = 77,120**（请求数**完全相等**），token 逐字相等（4,609,767,459 / 51,387,729），费用差 **$0.0011**
⇒ `JOIN (SELECT DISTINCT ON (session_id, tenant_id) … ORDER BY partition_date DESC) s`（`domains/analytics/session_probe_scope.go:58-68`）**没有把 `sessions` 的按天分区行放大进统计**。

### 5.3 ✅ 看板英雄区：当前无同请求多行

`usage_facts` 实测「同 `request_id` 多行」= **0**；`session_turns` 同项 = **0**。
★ 机制上 `usage_facts` 的唯一键是 `(event_id, revision, occurred_at)`（`sql/migrations/startup/537_usage_facts.sql:47`），**不含 `request_id`** ⇒ 若同一请求以不同 `occurred_at` 再落一次，英雄区 `COUNT(*)` 会多计。
★ 仓内已自认此点：「usage_facts 一请求可多 revision，GROUP BY 去重」（`db/session_probe_arm_source.go:31`）——**对账侧按 `request_id` 聚合去重，看板侧没有**。
⇒ **判定：机制风险存在，当前无实例**（不记为现网缺陷，但应登记为待观察项）。

### 5.4 ❌ 会话与统计页「模型榜」：**确凿的重复计算**

`admin/dashboardapi/session_overview.go:658,668` 用 `unnest(ss.models_used)` 展开模型行，

| 请求数 | **77,120** | **118,727** | **+54.0%** |
| 模型行数 | — | 36,290 | — |

★ **状态订正（重要，两条分开说）**：
1. **复制语义在现役与 HEAD 都有** ⇒ **现网正在放大**：
   `git show HEAD:admin/dashboardapi/session_overview.go` 的 `queryModelUsage`（HEAD 坐标 `:666-668`）
