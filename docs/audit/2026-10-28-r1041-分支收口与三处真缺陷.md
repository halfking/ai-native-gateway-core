### 1. ★ P0：插件的 6 个 i18n 键被死键门误判成「共有死键」（活键被判死）

**现象**：合并 04 分支后，棘轮门 `i18n:shared-dead:check` **rc=1**：
「共有死键数 INCREASED by 6（ratchet violated）」。

**6 个键**：`plugin.hello.greeting` / `greetingDesc` / `times` / `enabled` /
`navSettings` / `title`。

**根因**：★ 插件的 i18n 键**不是源码字面量，而是数据文件里的**：

| 载体 | 形态 |
|---|---|
| `plugin-runtime/testdata/hello-plugin/plugin-manifest.json` | `settings_schema.properties.greeting.title_key = "plugin.hello.greeting"` |
| 同上 | `nav[].label_key = "plugin.hello.navSettings"` |
| 插件自带 `web/i18n.js` | `export default { 'zh-CN': { 'plugin.hello.title': '你好插件' } }` |
| 插件自带 `web/index.html` | `<h1 data-i18n="plugin.hello.title">Hello Plugin</h1>` |

⇒ 前端在**运行时**拿这些键去 `t()` ⇒ ★ **源码里根本没有这个字符串**
⇒ 死键门的采集面只 walk `web/src` 的 `.vue/.ts` ⇒ **永远看不见** ⇒ 误判死。

★★ **这与 r1038b 修过的「属性承载键」同族，但更隐蔽一层**：
上一轮修的是**源码里**的 `labelKey: '…'`；这一类是**JSON / HTML 数据文件里**的
`title_key: '…'` ⇒ ★ 连 `KEY_PROP_RE` 的扫描面都够不着（它只处理 `.vue/.ts` 源码）。

**修法**：★ **扩采集面**（把 `plugin-runtime/` 纳入引用集），★ **不是调高棘轮基线**
—— ★ 调高基线等于把活键登记成死键，下游的删除器会**真的把它们删掉**
⇒ ★ **门判错了要修门，不能改读数**。方向保守（多判活键 ⇒ 少判死 ⇒ 不会误删）。

**落地**：
- `web/scripts/i18n-dead-key-guard.mjs` 新增导出函数 `collectManifestRefKeys(text)`
  + 采集面扩到 `plugin-runtime/`（`.json` + `.js`）。
- ★ **自证 C 组 6 例**（C1 manifest 三种字段 / C2 `i18n.js` 单引号键 / C3 `data-i18n` /
  C4 **反向自证：manifest 提供的键一律不判死** / C5 **阴性对照：非键形态字符串不得被误收** /
  C6 真实 hello manifest 夹具）⇒ 自证 **19 → 25/25**。

### 2. ★ P0：本机 PG 缺 `pg_stat_statements` preload ⇒ ≥19 个门全是假绿

**现象**：跟踪数据库 log 时，`SELECT count(*) FROM pg_stat_statements` 直接报错：

```
ERROR:  pg_stat_statements must be loaded via "shared_preload_libraries"
```

**三重缺口（实测）**：

| 项 | 实测值 | 应有值 | 后果 |
|---|---|---|---|
| `shared_preload_libraries` | `'citus'` | `'citus,citus_columnar,pg_stat_statements'` | ★ 扩展虽已 `CREATE EXTENSION`，但 postmaster 未 preload ⇒ **每条查询都报错** |
| `log_min_duration_statement` | `-1` | `1000` | 慢查询日志关 |
| `logging_collector` | `off` | `on` | 即使开了阈值也只进 stderr，容器日志里查不到 |

**为什么严重**：★ 仓内 **≥19 个门**以 `pg_stat_statements` 为事实源
（`§143.77` / `§143.78` / `§143.79` / `§143.80` / `§143.81` / `§143.95` /
`§143.97` / `§143.98` / `§143.99` + `scripts/ursmcheck` 下的 `§143.19` /
`§143.21` / `§143.22` / `143.29` / `§143.30` / `§143.32` /
`index_reader_census` / `unused_index_report` 等）
⇒ ⇒ 它们在本机**恒 SKIP 或恒绿** ⇒ ★ 「慢 SQL」这个**整个类别不可观测**。

★★ **且仓内文档（`docs/06-deployment/02-database/local-pg-sync-from-252.md`）
写的期望值本来就是 `'citus,citus_columnar,pg_stat_statements'`**
⇒ ★★ **文档与实况漂移，而没有任何东西会报警**。

**修复（本机）**：直接写 `postgresql.auto.conf`（已备份 `.bak-r1041`）：

```
shared_preload_libraries = 'citus,citus_columnar,pg_stat_statements'
log_min_duration_statement = 1000
logging_collector = on
```

★ **用直接写 auto.conf 而非 `ALTER SYSTEM`**：逗号列表的引号在 `ALTER SYSTEM` 下是
**已知脚枪**（同上文档 §5 Q6 明载）。

**验证（全部实测）**：
- `SHOW shared_preload_libraries` ⇒ `citus,citus_columnar,pg_stat_statements` ✔
- `SELECT count(*) FROM pg_stat_statements` ⇒ **成功**（原先报错）✔
- 慢查询日志实测捕获：`LOG: duration: 1506.914 ms statement: SELECT pg_sleep(1.5);` ✔
- 唯一真连库依赖它的门 `TestSection14397TodayLegScansOnlyTodaysPartition` ⇒ **PASS**
  （输出含真实分区裁剪计划 ⇒ 设施完全生效）✔

**固化进仓内**：
- `installer/templates/compose.yml` + `installer/cmd/llm-gw-installer/embeddata/compose.yml`
  的 postgres 段加 `command: postgres -c shared_preload_libraries=… -c
  log_min_duration_statement=1000 -c logging_collector=on …`（★ 两份逐字一致）。
- ★ **新门** `scripts/ursmcheck/pg_slow_query_observability_test.go`：
  - **静态层**：生产 compose 必须带设施 + **两份副本必须逐字一致**（embeddata 那份是
    打进安装器的副本 ⇒ 漂移 = 模板改了但安装器没跟上）。
