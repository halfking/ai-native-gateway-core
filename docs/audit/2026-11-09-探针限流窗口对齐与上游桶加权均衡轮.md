## 2. 根因（两条）

**G-A 探针与业务抢限流窗**：业务侧 429 冷却已是 W1 节奏校准口径（默认 60s 窗口重灌），
但探针侧＝ladder 3m 固定档 + 绑定冷却 5min：
① 复检探针要等 3 分钟梯底才跑，绑定被多关 ~2 分钟（no_candidate 放大）；
② 探针 429 写的 5min 绑定冷却会**覆盖**业务侧 60s 冷却（探针写晚到 ⇒ recover_at 被覆写）；
③ 每次探测本身消耗紧桶 RPM（§631「1 分钟 30 次含失败次数」形态）。

**G-B 首跳无容量/压力维度**：firstHopLotteryWeights 有 sticky/recency/balance/
planQuota 四维惩罚 + recovery ramp，但没有限流压力维、没有容量份额维。

## 3. 修复

| # | 落点 | 内容 |
|---|---|---|
| A1 | bg/probe_recovery_policy.go | **rate 族探针梯对齐窗口**：首三跳 = `routing.rate.window_refill_seconds`（W1 旋钮，默认 60s）替换 3m 固定档；高位梯级（5m 封顶/sustained 1h）不动——窗口只定「最早有用时刻」。窗口=0（节奏校准关）⇒ 逐字节回 3m。 |
| A2 | bg/node_probe.go unavailableBindingHorizon | **rate 族绑定冷却 = 窗口**（60s）而非 5min——探针 429 与业务 429 同一窗口口径，不再把 60s 冷却覆盖拉长成 5min。窗口关 ⇒ 回 5min。sustained 档仍最高优先。 |
| B1 | executors/router_scoring.go | **首跳限流压力惩罚**：`LLM_GATEWAY_ROUTING_W_RATE_PRESSURE`（默认 0.20，env 同族）——penalty = 1−质量信号（RecentSuccessRate samples≥10 优先 → SuccessRate 回退 → 无信号中性 0），进 p 折算 ⇒ 429 闪断桶首跳份额缩、健康兄弟桶相对放大。置 0 逐字节一致。 |
| B2 | 同上 | **容量份额因子**：`LLM_GATEWAY_ROUTING_CAPACITY_SHARE`（默认开）——份额 ×= clamp(rpm_limit/队列最大 rpm, 0.1, 1)；无 rpm 信号的候选/队列全 1（零行为变化）；rpm_limit 从「只管准入限流」升级为「同时供数首跳份额」。 |

效果链：闪断桶份额缩 → 首跳更多落健康桶 → 紧桶 RPM 被业务挤占减少 → 探针 429 减少 →
绑定被钉 unavailable 的时间从 ~3-5min 降到 ~1min → no_candidate 收窄。
