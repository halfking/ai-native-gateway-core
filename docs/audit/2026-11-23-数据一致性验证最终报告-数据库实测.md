## 五、会话统计的真实偏差（唯一需要修的模块）

### 5.1 三条宇宙规则各自的剔除量

| 桶 | 会话数 | 请求数 | 费用（USD） |
| --- | --- | --- | --- |
| 1-无归属用户 | 1,062 | 1,202 | 0.08 |
| 2-人工标记探测 | 10,592 | 12,364 | **5,145.16** |
| 3-模式判定探测 | 5,687 | 5,946 | **1,876.67** |
| **剔除合计** | **17,341** | **19,512** | **7,021.91** |
| KEEP-保留 | 22,107 | 58,176 | 1,551.40 |

### 5.2 决定性证据：被剔的全是业务流量

把被剔除会话的窗口内请求，按请求日志的 `origin_stage` 分类：

| 剔除原因 | 请求数 | 费用（USD） | 其中 `origin_stage='business'` | 占比 |
| --- | --- | --- | --- | --- |
| 人工标记探测 | 12,364 | 5,145.16 | 12,364 | **100%** |
| 模式判定探测 | 5,946 | 1,876.67 | 5,946 | **100%** |
| 无归属用户 | 1,202 | 0.08 | 1,202 | **100%** |

⇒ 被会话侧剔掉的 19,512 笔请求、**$7,021.91**，**没有一笔是探测**，全部是真实业务流量。
⇒ **这是会话统计低于看板的首要原因（占看板费用 79%）。**

### 5.3 次因：跨窗会话（18 个）

窗口内实际有请求、但首次请求早于窗口的会话只有 **18 个**，漏算 **3,191 笔 / $281.38（占 3.2%）**。

> ⚠️ **订正**：早前报告称「漏算约 13% 费用，因跨窗会话被排除」——**方向对、量级错**。实测跨窗会话只占 3.2%，主因是探测剔除（79%）。按旧结论去改后端聚合逻辑会改错方向。

## 八、遗留与建议

### 8.1 待 owner 决策（需改后端，本轮未动）

**P1｜会话宇宙探测剔除过宽**（会话统计低于看板 79%）
- 现状：`session_analytics_is_probe(...)` + `is_probe` 把 17,341 个真实业务会话判成探测。
- 影响面：会话统计、会话分析物化视图（981/994）、会话宇宙所有下游消费者。
- 风险：改动会同时影响会话分析的多个页面，**不是低风险**；建议先在只读副本上验证剔除规则的误判率，再分批收窄。

**P2｜跨窗会话整体排除**（占 3.2%）
- 现状：`first_request_at >= NOW() - N days` 把 18 个窗口内仍活跃的会话整个排除。
- 修法：改为按窗口内请求聚合（`session_turns` 侧），而非按会话首请求过滤。

### 8.2 无需改代码的口径提示（已落地）

- 统计标准正文已把「先对齐探测口径」「再对齐成熟度（对账是 T+1）」写成自查步骤。
- 会话统计页的用户可见说明已订正，用户不会再被误导到「跨窗会话」这个错误方向。

## 附录 A：复现用的 SQL

### A.1 事实表逐日对拍（看板 vs 对账）

```sql
SELECT d.d::date AS day,
       uf.req AS uf_req, uf.cost AS uf_cost,
       rs.req AS rs_req, rs.cost AS rs_cost,
       (uf.req - rs.req) AS d_req,
       ROUND((uf.cost - rs.cost)::numeric,4) AS d_cost
FROM (SELECT generate_series(DATE '2026-11-17', DATE '2026-11-23', '1 day')::timestamptz AS d) d
JOIN LATERAL (SELECT COUNT(*) req, ROUND(COALESCE(SUM(cost_amount),0),4) cost FROM usage_facts
              WHERE occurred_at >= d.d AND occurred_at < d.d + INTERVAL '1 day') uf ON true
JOIN LATERAL (SELECT SUM(request_count) req, ROUND(SUM(estimated_cost_cents)/100.0,4) cost FROM report_snapshots
              WHERE scope='daily_total' AND report_date = d.d::date) rs ON true
ORDER BY 1;
```

### A.2 会话宇宙（原样取自 `admin/dashboardapi/session_overview.go`）

```sql
SELECT COUNT(*) AS sessions, COALESCE(SUM(ss.request_count),0) AS req,
       ROUND(COALESCE(SUM(ss.total_cost_usd),0),4) AS cost
FROM (SELECT * FROM session_summaries WHERE first_request_at >= NOW() - INTERVAL '7 days') ss
JOIN (
  SELECT DISTINCT ON (session_id, tenant_id)
    session_id, tenant_id, is_probe, owner_user, client_type, title
  FROM sessions ORDER BY session_id, tenant_id, partition_date DESC
) s ON s.session_id = ss.session_key AND s.tenant_id = ss.tenant_id
LEFT JOIN session_dim sd ON sd.session_key = ss.session_key AND sd.tenant_id = ss.tenant_id
WHERE NULLIF(COALESCE(s.owner_user, sd.api_key_owner_user), '') IS NOT NULL
  AND NOT COALESCE(s.is_probe, false)
  AND NOT session_analytics_is_probe(COALESCE(s.owner_user, sd.api_key_owner_user), s.client_type, s.title);
```

## 附录 B：环境与方法

- **数据库**：`acc-pg17` 容器 / `llm_gateway` 库（211 生产）；连接方式 `ssh 192.168.31.211 "docker exec -i acc-pg17 psql -U llm_gateway -d llm_gateway"`（`llmgw-211` 别名的 mesh 中继不可达）。
