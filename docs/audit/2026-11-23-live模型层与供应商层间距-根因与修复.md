## 0. 诉求

owner 反馈（附图）：`/live` 页面模型层（模型卡片）与供应商层（供应商节点）**挤在一起**，
要求「将供应商与模型的间距再放大一倍」。

前十一轮已按「调 `ROW_RATIO` 比例」的方式反复试过（model 0.72→0.86→0.78→0.82→0.76、
provider 0.95→0.88→0.94→0.97），owner 每轮仍反馈「间隔还是太小」。

---

## 1. ★ 实测取证（CDP 实测，**非推算**）

用 CDP 驱动生产页 `/live`，读取 DOM 实测：

```
视口 900px → 画布 480px｜模型层 4 张（底边 423）｜供应商层 4 张（顶边 423）｜净间距 0px
视口 846px → 画布 480px｜模型层 4 张（底边 423）｜供应商层 4 张（顶边 423）｜净间距 0px
视口1200px → 画布 503px｜模型层 3 张（底边 441）｜供应商层 4 张（顶边 445）｜净间距  4px
```

**⇒ 生产实际净间距是 0~4px，不是前几轮推算的 45px / 96px。**

高度链实测（1440×900 视口）：

| 层级 | 高度 | 说明 |
|---|---|---|
| `.main-body` | 790px | flex 拉伸，`height` **属性仍是 auto** |
| `.live-topology` | 742px | `height:100%` **百分比解析失败** ⇒ 退回 auto |
| `.live-topology__stage` | **320px** | 栅格行只拿到下限 |
| `.topo-canvas` | 480px | 靠 `min-height:480px` 撑出 ⇒ **溢出被裁 160px** |

`rowY` 实测：`{client:36, model:394, provider:451}`
⇒ 模型底边 `394+28=422`，供应商顶边 `451-28=423` ⇒ **净间距 1px**。

---

## 2. 根因（两层，互相叠加）

### ① 画布被容器裁掉 160px
- `.live-topology__body` 的栅格行是 `minmax(min(320px, 50vh), 1fr)`；
- `1fr` **吃不满** —— 父 `.live-topology` 的 `height:100%` 因父 `.main-body` 的
  `height` 属性是 `auto`（实际高度由 flex 拉伸得到）⇒ **百分比高度解析失败**
  ⇒ `.live-topology` 高度 = 内容高 ⇒ 栅格容器高度 = 内容高 ⇒ 行只拿到下限 320px；
- 画布 `min-height:480px` 撑出 480px，被 stage 列的 320px **裁掉 160px**
  ⇒ 拓扑图底部永远看不见。

### ② 层间距用**比例**定位 ⇒ 在 480px 画布里被压成 1px
- `ROW_RATIO.model=0.82 / provider=0.94` ⇒ 差值仅 `0.12 × 480 = 58px`，
  而两个节点各占 56px（半高 28px）⇒ **净间距 = 58 − 56 = 2px**（实测 1px）。
- ★ **比例方案的病根**：层间距随画布高度线性缩放，而画布高度是**被容器压住的**，
  不是视口高度 ⇒ 调比例调不出可见间距。

> ⇒ 前十一轮「在 846px 画布下有 45px / 96px 净间距」的**全部推算作废**：
> **846px 这个画布高度在生产上从没出现过**（实际 480px）。

---

## 3. 修法

### ① 层间距改为**固定像素**（`ROW_GAP = 72`）
- 供应端层贴底（`providerY = height − NODE_H/2 − BOTTOM_PAD`）；
- 模型层固定在其上方（`modelY = providerY − NODE_H − ROW_GAP`）；
- ⇒ **任何画布高度下净间距恒为 72px**（视觉设计量不该随高度缩放）；
- 网关核心大方块下边界改用「**模型层顶边**」（原为供应端顶边）⇒ 不再压进模型层。

### ② 栅格行下限 320px → 560px（≥ 画布 `min-height:480px`）
- 画布完整可见，不再被裁 160px；
- 空间不足时仍由 `.main-body` 滚动兜底（沿用该处既有的「宁可滚，不可塌」纪律）。

### ③ CDP 探针从**占位假绿**落地为真实断言
- 此前 `assert-live-gateway-core.mjs` 是 exit 2「量具失效」的占位版、**0 条断言**，
  runner 却把它当门 ⇒ 「CDP 验证: PASS」曾是**假证据**；
- 现改为：多视口实测卡片**边缘到边缘**净间距 + 断言
  ①「净间距在各视口间**恒定**（极差 ≤20px）」⇒ 直接守住「不是比例」这个契约
  ②「净间距 ≥ 60px」③「画布高度 ≥ 480（未被裁）」④「大方块不压模型层」。

## 3.5 ★ 顺带抓到的第二个缺陷：Maestro Flow 判据与账号**不配套**（量具红）

`run-live-gateway-core.sh` 跑 Flow 时**必然红**（红在 `_shared/login.yaml` 判据②）：

| 项 | 值 | 来源 |
|---|---|---|
| runner 默认 `ADMIN_USER` | `demoadmin` | runner 第 24 行 |
| `demoadmin` 的 display_name | **演示管理员** | 生产库 `users` 表实测 |
| runner 默认 `ADMIN_DISPLAY_NAME` | **系统管理员** | runner 第 26 行（**错**） |
| 「系统管理员」是谁的 | `admin` 种子账号 | `admin/users.go:247` |

- 共享登录流判据②③ = 「顶栏出现 `${ADMIN_DISPLAY_NAME}`」，而顶栏 `.user-menu__name`
  渲染的**就是该账号自己的 display_name** ⇒ 登录 demoadmin 却断言「系统管理员」
  ⇒ **必然红** ⇒ **量具红，不是产品红**。
- `_shared/login.yaml` 头注其实早已写明「「系统管理员」只是 admin 种子账号的
  display_name ⇒ 用 demoadmin 跑登录，判据②③必红 ⇒ 默认值放调用侧」，
  **但调用侧的默认值一直没改** ⇒ ★ 参数化做了一半：变量化了，默认值却仍配旧账号。
- 生产口令-账号配对实测（2026-11-23）：
  `demoadmin/Demo@admin123` → **200**；`admin/Demo@admin123` → **401**
  （env 的 admin 口令未生效，后端按 `users` 表记录校验）；`maestro_test/*` → **401**。
- 另测：`.user-menu__name` 在**窄视口**（756×469）下被响应式 CSS 隐藏 ⇒
  `innerText` 里没有它 ⇒ 判据依赖视口宽度（Flow 的 `--screen-size 1440x900` 满足）。

**修法**：runner 默认 `ADMIN_DISPLAY_NAME` 改为 **演示管理员**（与默认账号配套），
并在注释里写明「必须与 ADMIN_USER 配套 + 生产实测的口令-账号配对表」。

## 5. 通用式（可复用）

1. ★ **「比例」只在分母稳定时才有意义** —— 布局按比例算，但**渲染容器的高度
   不等于你以为的那个高度**（这里被 flex + 百分比失效压到 480px）⇒
   比例差被压成 1px。**先量容器实际高度，再谈比例。**
2. ★ **视觉设计量（层间距）应当是常量**，不是「画布高度的函数」——
   画布变高多出来的空间不会变成层间距，只会变成空白。
3. ★ **「元素看不见」先量高度链**（本次 5 级容器逐级实测定位到 320px vs 480px），
   不要先怀疑数据或样式规则。
4. ★ **占位脚本当门 = 假证据**：`exit 2` 的「量具失效」是诚实的，
   但 runner 若把它当 PASS 就等于没测 —— 判据必须区分「没测」与「测过且通过」。
5. ★ **参数化 ≠ 参数化完成**：把硬编码的显示名变成 `${ADMIN_DISPLAY_NAME}` 之后，
   **默认值必须与实际部署的真实值配套** —— 否则只是把「硬编码的红」换成了
   「默认值的红」，而红的**位置**（判据②）看起来一模一样 ⇒ 极易误判成产品缺陷。
   判据的**被测对象**与**断言值**必须是同一个实体（这里的实体＝登录账号）。

## 6. 登记

- **L1** 本轮只改 `/live` 拓扑层定位与栅格行下限；行下限 560px 会让
  统计面板占用更多视口高度，**窄屏（<1024px）仍走单列流式布局**，未受影响。
- **L2** `ROW_GAP=72` 为常量；若将来节点高度 `NODE_H` 大幅上调，
  需重算「模型层顶边 vs gateway box 净空」（480px 画布下净空仅 220px）。
- **L3** `maestro/tools/assert-live-gateway-core.mjs` 现为**真实断言**，
  可作为后续回归的守门人；但它依赖 9222 端口的 Chrome（`--remote-debugging-port`），
  CI 需自备。
- **L4** `.live-topology` 的 `height:100%` 仍因父级 `height:auto` 而失效；
  本轮用「行下限 ≥ 画布 min-height」绕过，**未改全局 `.main-body` 布局**
  （改它影响所有页面，风险外溢）。
- **L5** 生产终验结论待部署完成后补入本档。
