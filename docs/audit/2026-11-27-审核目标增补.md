## 二、本周新增的审核目标（从提交与实测反推）

### 戊 ★ 目标五：「同一改动、两条车道、两个 SHA」是常态 ⇒ 收敛判据必须是 patch-id，不是文件名 ★

本轮实测：并行车道把 `codex/opencode-gateway-ledger` 的 `6dfd06ad29` cherry-pick 成 main 上的
`ec949dd8a3`（commit message 自证 cherry-picked），我方同一时刻把原分支 merge 进了 main。
两笔在 `git log` 里是**两条独立记录**，但 patch-id 逐字相同 ⇒ 内容零重复落地。
**判据**：合并前 `git show <c> | git patch-id --stable` 对拍；相同 ⇒ 任取其一，删冗余引用。

### 己 ★ 目标六：「临时目录入库」必须当场拦截 ⇒ `tmp/` 不是投递面 ★

本周 `b10fea0298` 把 30 个中间态文件（含重复的 DEPLOYMENT/FINAL/COMPLETION 三连报
＋一次性部署脚本）直接提交进仓根 `tmp/`。实测：仓内无任何门/脚本读 `tmp/`；
脚本绕过投递通道直连单库执行迁移（绕过编号门与事务包裹守卫）。
**处置**：收编进 evidence 目录并带 INDEX 声明「不要复用其中脚本」。
**新增目标**：任何一次性部署/验证脚本若要留存，必须进 `scripts/` 或 evidence 目录并写明用途，
不得以 `tmp/` 入库。

### 庚 ★ 目标七：跨仓工作树（`.codex/worktrees`）与 `.scratch` 的孤儿目录要有台账 ★

本轮实测：`/Users/niuer/.codex/worktrees/` 下 9 个目录，其中 8 个只剩 marker 文件（死目录）、
1 个（`s5-evidence`，315M）持有 **132 笔未推送的 docs 提交** —— 已先推送保全到
`github.com:halfking/ai-native-workspace.git` 的 `codex/s5-evidence-archive-20261127` 分支再删除。
**新增目标**：清理前必查「目录是否持有未推送提交」（`git rev-list --count origin/main..HEAD`）；
有则先保全再删。
