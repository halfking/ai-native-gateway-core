## 三、本轮修复：迁移 863 —— ensure_handoff_logs_partition 存储形态自适应

### 根因（211 实测证据链）

1. 211 llm_gateway 库 = mac mini pg18 dump→acc-pg17 restore 血缘，无 pgcolumnar：
   `handoff_logs_2026_10/_11` 以 **heap** 形态挂在父表下（pg_inherits 实测 3 子，
   含 default），`ursm_node_snapshot_min` 是普通表（830 从未应用）。
2. 714 版 ensure 函数要求挂载子表 `am='columnar'` 否则 P0001 → 211 每次
   boot/24h tick 报两条 `partition_manager: ensure partition failed`。
3. 未来月份走 `CREATE ... USING columnar` 在无 pgcolumnar 环境必失败 → 新行
   只能落 default 分区（月度组织退化）；promote 内部 PERFORM 同函数 → 同因
   失败 → hot 永不促升（211 现网 hot=0 行，无实害、潜伏）。promote 本身
   INSERT/DELETE 单语句原子（535 契约实测复核），失败不丢数据。
4. `ursm_node_snapshot_min` 42P17：db.go boot 路径自 830 起就有 shape-first
   探测（非分区即 Info 跳过），**bg 24h tick 没有同款探测**——两条路径契约
   不一致（r1021「两路径政策必须一致」同族），非分区环境每天报错。

### 修复

- **迁移 863**（`sql/migrations/startup/863_handoff_partition_am_aware.sql` +
  down）：挂对父表即合法（columnar 只是优化，错父表仍 raise）；创建路径探测
  `pg_am` 有 columnar 才 `USING columnar`，否则建 heap（4 个分区级索引照建）；
  714 时区钉扎语义原样保留；文件尾自证 DO（旧 raise 文本不在场+columnar 路径
  在场）。down 恢复 714 体。
- **bg tick 形状探测**（`bg/partition_manager.go`）：`archiveSpec` 新增
  `parentTable`；`ensureSpecEligible` 先探 `to_regclass(...).relkind='p'`，
  非分区父表 Info 跳过（对齐 db.go 口径）；`NewPartitionManager` 参数窄接口化
  `partitionDB`（生产传 pgxpool 不变；聚合器仅对真池构造，pgxmock 判据路径
  nil 无害——`TestPartitionManagerIncludesErrorAggregator` 改 typed-nil pool
  保持旧契约）。
- 同步：installer 五点（embeddata 副本/main.go embed+map/dbinit runner/TSV
  258→259）+ 通道腿登记（**位置硬约束：必须在 714 之后**，intentional chain
  `534→714→863` 终态项 863）。

  不合格 / 无 parentTable→直接合格 / 正向腿（探测被消费+ensure 恰 2 次）/

## 五、慢 SQL 观测落地（211 acc-pg17，reload-only）

- 问题：切主 211 后网关主库在本机 acc-pg17，但该库慢 SQL 日志未开
  （-1），pg_stat_statements 未 preload——「找慢 SQL」没有量具。
- 实施：`ALTER SYSTEM SET log_min_duration_statement='500ms'` +
  `pg_reload_conf()`（仅 reload，不重启容器；acc 项目共用集群，零中断）。
- 验证：`pg_sleep(0.6)` 探针语句在日志中呈现为 `duration: ~600 ms`
  慢条目（详见 §七实测输出）。
- 边界：500ms 阈值偏保守，后续可按噪声量调至 1s；DSM/连接数等重参不动。
