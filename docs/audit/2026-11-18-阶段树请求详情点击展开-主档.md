## 一、现象与定性

### 1.1 现象

在 `/live2`（请求阶段树）页点任意一条请求带 ⇒ **什么也没发生**（没有详情面板、没有展开、没有任何反馈）。

### 1.2 设计侧：原型里这段是有的

设计原型 `docs/audit/2026-11-16-live阶段树原型.html` 里有完整的详情实现：

- `bandDetailHTML(band)`（原型第 1654 行）＝ 渲染「请求详情」两栏五段：
  **模型解析链**／**回复侧指标**／**模型身份与可信度**（左栏）
  ＋ **阶段明细（发送轨 + 接收轨）**／**模拟 liveactions**（右栏）；
- `toggleBandDetail(band)`（原型第 1736 行）＝ **手风琴**：同时只展开一条，
  展开时带高随之变长（`band.el.style.height = BAND_H + detailHeight`），
  并且用 `bandHeight()`（读当前模式）避免紧凑模式下详情与下一条带重叠（设计规则 18）。

### 1.3 实现侧：线上这段**从来没做过**

`web/src/views/LiveStageTreeView.vue` 渲染请求带时只传了一堆展示用 prop，
**没有任何点击入口、没有展开态、没有详情组件** ⇒ 设计与实现之间缺了整块。

> ★ **通用式：设计原型里有 ≠ 线上有** —— 原型是**形态证据**，不是**功能证据**；
> 「按原型实现了版面」很容易被读成「按原型实现了功能」，
> 而**可点的交互**恰恰是版面对齐时最容易整体漏掉的那一类（因为它不在 DOM 结构里）。

## 二、实现（三层）

### 2.1 ① 共享文案层 `web/src/lib/liveStageTreeLabels.ts`（新）

把**阶段名 / 状态名 / 错误码释义 / 客户端类型 / 模型来源 / 阶段值 / 状态推导**收敛成**一份**：

- 请求带（`StageTreeBand.vue`）与请求详情面板（`StageTreeBandDetail.vue`）**都从这里取**；
- 请求带原有的 switch 改成**委托**（函数体一行，模板与 DOM **零变化** ⇒ 既有钉测不受影响）；
- ★ **为什么必须先做这一层**：上一轮的 F1 缺陷（紧凑模式图例字形漂移）根因就是
  「**同一条规定写了两份** ⇒ 必然漂移」；详情面板要重复用到阶段名/错误码/状态推导，
  若各写一份 ⇒ 下一轮新增错误码时就会「带里显示了、详情里没有」。

### 2.2 ② 详情面板组件 `web/src/components/live-stage-tree/StageTreeBandDetail.vue`（新）

五分区（按原型的内容，**只做线上真有的数据**）：

| 分区 | 内容 | 数据来源 |
|---|---|---|
| 模型解析链 | 客户端请求模型 / auto 选型（任务类型 + 决策置信度）/ 解析方式 / 最终匹配模型（含取值来源）/ 模型切换 / 上游出站（模型 @ 供应商） | `band.model` |
| 回复侧指标 | 输入·输出·合计 token / 缓存读 token / 缓存命中率 / 响应帧数 / 首字节·总耗时 / 排队时长 / 出站尝试次数 / 成本 | `band` |
| 模型身份与可信度 | 声称模型 / 上游自报模型 / 凭据 / 供应商 / 指纹可信度 | `band` ＋ 页面层算好的可信度 chip |
| 阶段明细 | 11 段（发送轨 7 + 接收轨 4）逐段：状态字形 · 名称 · 值 · 补充说明 · 耗时 | `band.stages` |
| 会话与错误 | 会话标识 / 会话轮次 / 是否探测请求 /（有失败时）错误来源 · 错误类型 · 失败阶段 | `band` ＋ 视图层会话轮次 |

三条纪律（沿用本仓既有）：

1. **诚实**：拿不到的值一律显示「—」，**不拿 0 冒充**（未测量 ≠ 0）；
2. **不编**：原型里的「模拟 liveactions」「打开右侧抽屉」两块，线上**既无这份数据、也无那个抽屉**
   ⇒ 本组件**不做**它们（做不了就承认做不了，别画一个假的）；
3. **字形随模式**：阶段字形取自唯一真源 `lib/stageTreeGlyphs.ts`
   ⇒ 紧凑模式下**不出现 ✓**（设计规则 15：紧凑模式全页 ✓ 计数 = 0）。

### 2.3 ③ 接线（手风琴 + 无障碍）

- 请求带 root（`<article class="band">`）可点：`@click` ＋ **Enter/Space 键盘可达** ＋ `role="button"`
  ＋ `tabindex="0"` ＋ `aria-expanded`；
- 视图层只存**一个** `expandedRequestId` ⇒ **手风琴是结构上成立的**
  （不是靠两条规则去互斥）；点第二条 ⇒ 第一条自动收起；再点同一条 ⇒ 收起；
- 详情面板经**插槽**注入被点开的那一条 ⇒ **默认态的 DOM 与改造前逐字一致**
  （既有设计钉测 32 条不受影响）；
- 详情内部 `@click.stop` ⇒ 点详情**不会**冒泡到请求行 ⇒ 不会「点一下就收起」；
- 顶栏加一行**可发现性提示**（弱化样式）：告诉用户「点行可看详情」。

### 2.4 8 语种文案

`liveStageTree.detail.*` 新增 **35 个键**（title / hint / sections 5 / field 28），
8 个语言包文件**纯插入**（各 +42 行、0 删除，既有键一字未动），**键形状与键序 8 语种完全一致**。

## 六、通用式（本轮新增）

1. ★ **设计原型里有 ≠ 线上有**：原型是**形态证据**，不是**功能证据**；
   「按原型对齐了版面」很容易被读成「按原型实现了功能」，而**可点的交互**是版面对齐时最容易整体漏掉的
   那一类（它不在 DOM 结构里，只在事件里）⇒ 上线前必须**按原型逐个交互点对拍**。
2. ★ **同一条规定写两份 ⇒ 必然漂移**（上一轮 F1 的教训）：要新增一个**用到同一批映射**的界面，
   先把映射收敛成**单一真源**（本轮：`lib/liveStageTreeLabels.ts`），再写新界面。
3. ★ **手风琴用「只存一个 id」实现**，不要用「集合 + 两条互斥规则」⇒ 前者结构上成立，后者迟早漏。
4. ★ **诚实性与不编**：原型里有、但线上**没有数据/没有功能**的两块（模拟 liveactions / 右侧抽屉）
   ⇒ **不做**，而不是画一个假的；没上报的值显示「—」，不拿 0 冒充。
5. ★ **交互断言放页面内 CDP**：动态 testid 选不中时，Maestro flow 侧别硬凑断言，
   与「浮层交互」同分工放页面内（点真元素、读真 DOM）。
6. ★ **新增界面默认态必须与改造前逐字一致**（详情经插槽注入、未展开不渲染）
   ⇒ 既有的 32 条设计钉测不受影响 ⇒ **新功能不会偷偷改掉旧版面**。
7. ★ **量具自己有 bug 时，先读当前态再决定动作次数**：本轮「再点同一条 ⇒ 收起（可逆）」首跑是**红**的，
   但根因在探针自己——上一步的手风琴往返已经把「第一条是否展开」翻过了，
   探针再无脑点一次等于「**展开**」⇒ **量的不是产品，是上一步留下的状态**。
   ⇒ 修法＝**先读当前态（`openBefore`）再决定点几次**，并把前置条件写进断言 detail。
   ⇒ 同理：`v-if` 会重建 DOM ⇒ **每步重新查询节点**，缓存的旧引用会变 detached ⇒ 恒假绿/假红。
8. ★ **「全 401」先查自己的取凭据路径，再怀疑产品**：`GET /api/keys/{id}`（列表/详情）**不返回明文**，
   明文只在 `GET /api/keys/{id}/reveal` ⇒ 我把「列表接口」当成了「明文接口」⇒ 4 笔 401 是**我的错**，
   不是网关拒绝新 key。★ 假红会把「我方取证错」伪装成「产品缺陷」。
9. ★ **有界留存 ≠ 读数窗口**：「近 5 分钟」是**过滤标签**，不是**留存承诺**。
   实测：完成 16s 的成功请求**仍在**带列表里，3–4 分钟前的三笔成功请求**已不在**（虽仍在读数窗口内）；
   且 **ingress 前置拒绝（401）根本不产生带**（pre-routing 短路 ⇒ 无阶段动作）。
   ⇒ 线上取证/回归**必须在有请求在途时取**，否则只会得到「没评估到」。
10. ★ **「没评估到」≠「评估为失败」**：探针改成**三态**（0 通过／1 失败／**2 量具失效**），
    窗口内 0 条真实请求时记 `skipped` ⇒ **量具失效不冒充产品红**（复核者不会误读）。
