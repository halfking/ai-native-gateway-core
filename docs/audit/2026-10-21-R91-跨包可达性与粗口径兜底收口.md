## 4. 修法：全局调用图（跨包可达）

| 改动 | 内容 |
|---|---|
| `r91CrossRef` / `r89PkgFunc.cross` | 记录**跨包**调用边（同包走 `calls`） |
| `r91BuildGlobal` | 把所有包的包索引拼成一张**全局**图（节点 = **包目录 + 函数名**） |
| `r91Propagate` / `r91Flow` | 沿**反向边**做不动点传播：汇总要**从后继流回前驱** |
| `r91LegDSNNames` / `r91LegOpensPG` / `r91LegCallsGate` | 腿的三项全局判定 |
| `r88AnalyzeLegs` | 守卫判定**拆成两半**：**内联判定限同包** ＋ **声明闸门调用走全局** |
| `r88CollectFuncs` | ★ 同包内**调用本包声明的闸门**（`Gate()` 这种写法）也记为「调用了闸门」⇒ 跨包链接得上 |

### 4.1 ★★ 三条传播规则（判据的核心）

| 性质 | 同包边 | 跨包边 | 理由 |
|---|---|---|---|
| `reachDSN`（读到了哪些事实源名） | 传 | **传** | ⇒ 跨包消费必须看得见（漏放方向） |
| `reachOpenPG`（开不开 PG） | 传 | **传** | ⇒ 同上 |
| `reachGate`（调用了**声明**闸门） | 传 | **传** | ⇒ 「声明名单」是**函数级承诺**，与包无关 |
| `guarded`（**体内写了判定**） | 判 | **不判** | ⇒★ 静态上分不清「闸门」与「核对落点」 |

⇒⇒ ★★ 最后一行是本轮**最关键**的安全判据：
`internal/testguard.RequireDatabaseMatchesDSN` 的**体内**就有目标库判定证据
⇒⇒ 若把它跨包传播 ⇒⇒ DSN 指产品库时它照样通过 ⇒⇒ 破坏性 SQL 照样落在产品库上
⇒⇒ ⇒ ⇒ 真腿会被误判成「有守卫」⇒⇒ **漏放**。

### 4.2 ★★ 顺手收掉「包级粗口径兜底」

★ R87 轮引入 `GuardFunctions` 名单正是为了摆脱「这个包**做过**目标库判定 ⇒ 它的函数都是闸门」
这种**包级粗口径**；但**兜底没删干净**：

```go
if len(facts.declaredGuards) > 0 { guarded = facts.declaredGuards[fun.Sel.Name] } else { guarded = facts.hasCheck }
```

⇒⇒ ★★ 那个 `else` 分支把「包级事实」当成了「函数级承诺」
⇒⇒ 仓内 **18 个包**有判定证据却没声明名单 ⇒⇒ 跨包调用进它们一律被当成闸门调用
⇒⇒ ⇒ **漏放**。本轮**只保留声明名单**（实测：主门读数**零变化** ⇒ 纯 soundness 修正）。

⇒⇒ ★ 这 18 个包同时也是「守卫口径收口」清单的一部分 ⇒⇒ **两件事合并到同一处根因**。

## 5. ★★★ 本轮自己踩的四个坑（两个是**实现**错，两个是**夹具**错）

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | ★★ **传播方向反了** | 第一版把「自己的汇总**推给后继**」⇒⇒ 调用者**拿不到**被调用者读到的 DSN 名 ⇒⇒ 跨包消费判不出来 ⇒ R90 夹具 ⑲ 当场变红 | 改成沿**反向边**回流（`reach(X) = 自身 ∪ ⋃ reach(后继)`） |
| 2 | ★★ **同包闸门调用没被记为闸门** | `callsGate` 只在**限定名调用**上设置 ⇒ 同包内 `Gate()` 这种写法不算 ⇒⇒ 跨包链式闸门（腿 → P.helper → Q.Helper → `Q.Gate()`）中间那环**接不上** | 同包调用本包**声明**的闸门也记为闸门调用（**不改变**同包读数：闸门自身的内联证据本来已覆盖） |
| 3 | ★ **R87 自检的索引建得太早** | 索引建在夹具 ⑨⑩ 写入**之前** ⇒⇒ 全局图里没有 fx9/fx10 ⇒⇒ 判据查「全局图里有没有这个节点」⇒⇒ 节点缺失 ⇒ **夹具恒绿** | 索引 + 全局图改成**所有夹具写完之后**才建（与 R88 夹具同款纪律） |
| 4 | ★★ **夹具的 import 路径与目录布局不匹配** | 夹具在 `fx20/otherpkg`，import 却写 `example.com/x/otherpkg` ⇒⇒ 跨包边指向**不存在的包** ⇒⇒ 边接不上 ⇒ 读数与被测形态无关 | import 路径与目录布局对齐（`example.com/x/fxNN/otherpkg`）⇒ 并在夹具门里写明这条纪律 |

⇒⇒ ★ 与 R90 轮那条「夹具的**载体形态**必须与被测判据同款」**同族**：
第 4 条是它的**跨包版** —— **夹具的「import 路径」也必须与「目录布局」同款**。

⇒⇒ ★★ 另有一处**自己写出来的设计错误**：拆「同包边 / 跨包边」两段传播时，
我在**跨包**那一段把 `withGate` 写成了 `false` ⇒⇒ 声明闸门的承诺没能跨包传
⇒⇒ 夹具 ㉗ 当场变红 ⇒⇒ 改回 `true`。
