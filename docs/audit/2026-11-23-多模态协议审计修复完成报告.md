## 修复详情

### P1-A: Thinking 块静默丢失（高危）

#### 问题描述
- `serialize_openai.go` 的 `serializeOpenAIMessageContent` 缺少 `case "thinking"`
- `serialize_responses.go` 的 `buildResponsesContent` 缺少 `case "thinking"`
- 导致 Anthropic thinking 块文本转 OpenAI/Responses 时整段消失且无 loss 事件
- 仅 signature 和 redacted_thinking 有上报，thinking 文本本身静默蒸发

#### 修复内容

**internal/ir/serialize_openai.go**:
```go
// serializeOpenAIMessageContent 的 switch 添加：
case "thinking":
    // Anthropic thinking blocks have no OpenAI Chat equivalent.
    // The block is skipped; loss is reported in reportSerializeOpenAILosses.

// reportSerializeOpenAILosses 添加：
if block.Type == "thinking" && block.Thinking != nil && block.Thinking.Thinking != "" {
    ReportProtocolLoss(
        "unknown",
        fieldPathMessageContent(i, j, "thinking"),
        ifaceNonEmpty(src, ProtocolAnthropicMessages),
        ProtocolOpenAIChat,
        "loss",
        "Anthropic thinking block cannot be expressed on OpenAI Chat Completions; block dropped",
        map[string]any{"message_index": i, "content_index": j, "text_length": len(block.Thinking.Thinking)},
    )
}
```

**internal/ir/serialize_responses.go**:
```go
// buildResponsesContent 的 switch 添加：
case "thinking":
    // Anthropic thinking blocks have no Responses equivalent.
    // The block is skipped; loss is reported in reportSerializeResponsesLosses.

// reportSerializeResponsesLosses 添加：
if block.Type == "thinking" && block.Thinking != nil && block.Thinking.Thinking != "" {
    ReportProtocolLoss(
        "unknown",
        fieldPathMessageContent(i, j, "thinking"),
        ifaceNonEmpty(src, ProtocolAnthropicMessages),
        ProtocolOpenAIResponses,
        "loss",
        "Anthropic thinking block cannot be expressed on Responses API; block dropped",
        map[string]any{"message_index": i, "content_index": j, "text_length": len(block.Thinking.Thinking)},
    )
}
```

#### 验证
- 现有 `TestAnomaly_AnthropicThinkingSig_LostOnOpenAITarget` 继续通过
- thinking.signature 上报路径已有覆盖
- thinking 文本上报路径新增（审计发现此前缺失）

### P1-B: file_id-only 内容静默丢失（高危）

#### 问题描述
- `irImageToGeminiPart` 对 file_id-only 图片（uri=="" && FileID!=""）返回 nil
- `irDocumentToGeminiPart` 对 file_id-only 文档（Type=="file_id" && URL==""）返回 nil
- 调用方跳过 nil 返回，块静默消失且无 loss 上报
- OpenAI 线对同场景有显式上报（serialize_openai.go:1049）形成**双标**

#### 修复内容

**internal/ir/serialize_gemini.go** 在 `reportSerializeGeminiLosses` 添加：

```go
// P1-B (2026-11-23): file_id-only images cannot be expressed on Gemini.
if block.Type == "image" && block.Image != nil {
    uri := block.Image.URL
    if block.Image.FileURI != "" {
        uri = block.Image.FileURI
    }
    if uri == "" && block.Image.FileID != "" {
        ReportProtocolLoss(
            "unknown",
            fieldPathMessageContent(i, j, "image.file_id"),
            ifaceNonEmpty(src, ProtocolOpenAIChat),
            ProtocolGeminiGenerate,
            "loss",
            "file_id image reference cannot be resolved to Gemini fileUri; block dropped",
            map[string]any{"message_index": i, "content_index": j, "file_id": block.Image.FileID},
        )
    }
}

// P1-B (2026-11-23): file_id-only documents cannot be expressed on Gemini.
if block.Type == "document" && block.Document != nil && block.Document.Source != nil {
    if block.Document.Source.Type == "file_id" && block.Document.Source.URL == "" {
        ReportProtocolLoss(
            "unknown",
            fieldPathMessageContent(i, j, "document.file_id"),
            ifaceNonEmpty(src, ProtocolOpenAIChat),
            ProtocolGeminiGenerate,
            "loss",
            "file_id document reference cannot be resolved to Gemini fileUri; block dropped",
            map[string]any{"message_index": i, "content_index": j, "file_id": block.Document.Source.FileID},
        )
    }
}
```

#### 对齐口径
- 与 `serialize_openai.go:1049` 的 file_id 图片上报形成同族
- 与 `serialize_openai.go:1069` 的 file_id 文档上报形成同族
- 消除了 OpenAI 线显式上报、Gemini 线静默跳过的双标

### P2-A: 413 错误文案失真

#### 问题描述
- `domains/streaming/handler.go:75` 定义 `maxBodySize = 100_000_000`（100 MB）
- 但 `:3085-3094` 错误文案写 "exceeds 32 MiB limit"
- 两处 Gemini handler 写 "exceeds gateway limit"（过于笼统）

#### 修复内容

**domains/streaming/handler.go** 3 处：
```go
// 行 3088/3092/3095
- "request body exceeds 32 MiB limit"
+ "request body exceeds 100 MB limit"
```

**domains/streaming/handler_gemini.go** 2 处（行 501、730）：
```go
- message = "request body exceeds gateway limit"
+ message = "request body exceeds 100 MB limit"
```

#### 对齐原则
- 文案与常量保持一致（100_000_000 bytes ≈ 100 MB）
- 使用用户友好单位（MB 而非字节数）
- 明确具体限制值（而非笼统的"超限"）
