# 2026-10-15 —— 停更横幅成因答疑 + 按处理队列首开连接反馈与自动重连（r1032）

> 用户报告两件事：
> ① 每次打开网关页面都出现「流量数据已停更：本页数字只反映停写之前」横幅，问原因、
>   是否为 request_log / session_turns 双写关闭后产生的问题；
> ② 总览页实时请求流的「按处理队列」第一次打开时不会自动连接实时流，要切到
>   按凭据等其它维度再切回来才可以；要求自动检查修正并显示「正在连接实时流」。

## 一、横幅：设计行为，不是故障（问题 ① 的答案）

- 代码链：`admin/v1_freeze_notice.go`（单一告示源）→ `/api/admin/v1-data-horizon` →
  `web/src/composables/useV1DataHorizon.ts` → `web/src/components/shell/V1DataFrozenBanner.vue`。
- 触发条件：`settings.RequestLogsWriteEnabled()` 读到**显式 false** 且来源是 DB/env
  （不是默认回落）。生产共享 PG（252）实测：
  `storage.request_logs_write_enabled=false`（2026-10-13 20:18 S4 停写翻转写入），
  与用户贴出的 frozen 文案逐字对应。
- **是停写（S4 翻转）的直接后果，且是有意设计**：审计 §9.73.7 ③-4 裁决
  「接受冻结 + UI 标注」——silently_frozen 档读点接口照常 200、结果非空、无任何
  错误信号，平台级横幅是让这件事可见的唯一载体。写门重新打开（键置 true）横幅
  即消失；在 v1 表 DROP 之前它会一直在。
- 实时流（SSE）**不在**停写影响范围内：`EmitRequestLog` 的 `onEmitted` 钩子
  （in_progress 投影，`cmd/gateway/main_livestream.go` 转发器）在 DB 写入门控
  **之前**触发；S4 门只拦 `persistRequestLog` 的 PG 落库腿。本地 2639 实测：
  停写环境下首开 1s 内已连接、节点数据正常到达。
- 顺带发现（未修）：本地部署根迁移到 `~/kaixuan/llm-gateway-go` 后换了全新空库，
  settings_kv 无停写键 ⇒ 本地横幅显示的是「无法确认」而非「已停更」三态里的
  unconfirmed 态——恰好验证了 §9.79.8 三态设计的判别力。

## 二、按处理队列首开：两个结构性缺口（问题 ② 的根因）

复现环境：本地 2639（42aa2d4e）。本地首开连接本身正常（已连接 1s 内出现，
nodes 2s 内到达）——「不连接」在数据面更忙的生产才可见，由三个缺口叠加：

1. **队列视图零连接反馈**：连接状态药丸只在页面顶部工具栏；`groupBy` 的默认值
   就是 `'queue'`（liveStreamPreferences defaults）——每个新会话首开都落在队列
   视图，而队列数据区里没有任何「正在连接/已断开」的呈现。SSE 建连窗口 +
   模型范围加载窗口叠加时，整个视图看起来是死的。
2. **EventSource 致命错误无自愈路径**：HTTP 层错误（401/403/404/上游 5xx）使
   readyState=2，浏览器**不再自动重连**（自动重连只覆盖网络瞬断）；
   liveStreamStore 记为 'closed' 后唯一恢复路径是卸载/重挂组件——用户发现的
   「切维度再切回」正是一次重挂载。
3. **模型范围（featured ∪ top-models 72h）单次重试**：生产 top-models 在
   MV REFRESH 争用下 10s 打满 500（f1b027645 实测 EXPLAIN：旧 JOIN 52s/0 行；
   该修复已在 main 但生产 2634-f280c9dc 尚未部署）。单次 3s 重试撞在同一争用
   窗口上，重挂载又成了唯一恢复路径。

## 三、修复（全部前端，本仓库 web/）

1. `LiveRequestStreamV2.vue`：
   - 队列面板区顶部渲染连接状态条（`.live-queue-connect`，role=status）：
     connecting/reconnecting/idle →「正在连接实时流，连接后本区数据自动刷新…」；
     closed →「实时流连接已断开，正在自动重连…」；unsupported → 明确提示。
     open → 状态条消失。
   - `watch(connection)`：进入 'closed' 后有界指数退避自动重连（5s 起 ×2，
     封顶 30s；任何状态迁移先撤旧排定；'open' 复位计数；卸载清理定时器）。
     'reconnecting' 是浏览器自身重连窗口，**不**叠加自家重连。
2. `QueuePerspectivePanel.vue`：空 scope 重试 3s 单次 → 3s/9s/20s 三档递进
   （避开 10s 预算端点的失败节奏；scope 非空即停火；次数有界，不循环压测）。
3. i18n：`dashboard.liveStream.queueStream{Connecting,Closed,Unsupported}` 三键
   × 8 语种（parity 门全绿）。
