# 2026-10-28 live 页选路层表达轮 + 当天汇总轮（含批判式审计修正）

> 会话 goal：live 页补齐「内部直连模型 / auto 按任务选模」的表达；缓存→脱敏→压缩
> 三层数据处理完整呈现；路由与节点状态作为基础服务单独放一侧；后续追加「当天
> （模型×供应商）即时汇总、可折叠、显示更多动态信息」。
> 本轮经历**两段**：第一段实现 + 浏览器验证；第二段对第一段做批判式审计，
> 证实 4 项缺陷并全部修正，再叠加新需求落地。

## 1. 结论

- `/live` 网关大方块从「三带 9 格」改为「四带 11 格 + 基础服务侧条」：
  - 主线（进站链）：**缓存 → 脱敏 →（插件）→ 模型选择 → 压缩** → ⬇派发
    （★ 压缩在模型选择**之后**——批判式审计修正，见 §3-A）；
  - 选路扇出带：模型选择的三个**出口分解**（auto 按任务 / 内部直连 / 指定），
    是「模型选择」格的明细注解带，不占主链串行位、不带派发箭头；
  - 存储转发带、出·响应链维持原三带版语义；
  - 基础服务侧条（右侧竖条）：路由管理、节点状态管理。
- 后端 SSE `LiveRequest` 新增 4 个 additive 字段：`client_model` / `is_auto_request`
  / `task_type` / `token_band`，全部来自 telemetry 既有持久化投影，零新采集。
- 新端点 ×2（均 admin 权限、200+degraded 契约）：
  - `GET /api/admin/topology/provider-kinds`：providers.code/kind 两列投影，
    供「内部直连」判定（kind='local'）；
  - `GET /api/admin/topology/models-today`：模型当天聚合（stats_usage_daily
    `provider_model` 维度在 canonical_id 上再聚合），与 providers-today 同表同口径。
- 左栏 `ProviderTodayRail` 升级为 `TodaySummaryRail`：供应商 + 模型两组当天汇总，
  各组可折叠（折叠后组头合计仍在）、行内显示 请求/成功率/占比条/token/缓存，
  点行联动图过滤（select-provider / select-model）。

## 2. 可行性核查（第一段的三个关键事实）

1. auto 选模：线上只有最终 canonical 名，但 `request_logs` 早已持久化
   `is_auto_request/task_type/auto_decision`（`telemetry/client.go:350-352`）；
   handler 在 route_resolved 动作里也带 `auto/auto_task_type/auto_confidence`
   detail（`handler.go:3714-3741`）。**数据在线，只是 SSE 没带出来**。
2. 内部直连 = `providers.kind='local'`（本地托管供应商，内网直连无真实 key，
   `admin/local_provider.go` 契约）；`/api/providers` 本就返回 kind。
3. 压缩打点在 `token_band`（below/preliminary/forced，
   `telemetry/client.go:400`，SessionCompressor 写入）。

## 3. 批判式审计：证实的 4 项缺陷与修正

### A. 主线顺序排反（真实缺陷，违反组件立身原则）

第一段把主线排成 `缓存 → 脱敏 → 压缩 → 模型选择`。实测后端管线：
`handler.go:4025` 注释明写 SessionCompressor.Prepare "**Runs AFTER candidate
resolution** so we know the target model's context window"——**压缩发生在
候选解析之后**（要先知道目标模型的上下文窗口才能决定触发线）。
修正：主线改为 `缓存 → 脱敏 → 模型选择 → 压缩`；派发箭头回进站链末尾
（扇出带只是模型选择的注解，不是主链一步）。判据同步钉死带内顺序与
「扇出带不含派发箭头」两条。

### B. `requestedModel` 是死字段（声明了没人消费）

第一段在 `PanelEntry` 加了 `requestedModel/isAuto/taskType`，但只接了两个
面板行的 auto chip；`requestedModel` 全仓 0 消费。修正：接入
`RequestDetailView.modelValue()`——auto 请求显示 `auto → 最终模型`，
别名请求显示 `别名 → 标准名`，其余只显示最终名。并写明语义注解：
auto 请求的 client_model 在后端已被改写为选中模型，**「要的是 auto」由
isAuto 表达，不能靠 requestedModel==='auto' 反推**。

### C. `/api/providers` 权限错配（非 default 租户恒「未测量」）

`/api/providers` 走 `ProviderConsoleMiddleware`（super_admin / **default 租户**
tenant_admin，`provider_access.go:76-89`），而 `/live` 是任意租户管理员可进
⇒ 非 default 租户打开页面时 provider-kinds 403，直连分桶**恒为「未测量」**
且页面会静默吞掉。修正：新增 `GET /api/admin/topology/provider-kinds`
（admin 权限，与 plugins 端点同级），只投影 code/kind 两列不泄敏感字段；
DB 不可用 → 200 + degraded（前端渲染「未测量」）。前端切到新端点，
回退 providers.ts 的死声明。顺带修：测试注入需要窄接口，按
topologyStatsDB 同款范式给 Handler 加 `topologyProviderKindsDB`。

### D. 预览夹具没有新功能的数据（浏览器验证的是空读数）

第一段的 CDP 验证里 `auto=0 / direct=0 / compress=0`——三张新卡全部 0，
「结构在位」验证过但「数据通路」没验证过（**0 有两种读法**）。修正：
预览夹具补 auto/直连/token_band 数据；provider-kinds 在 DEV 页用 fetch 拦截
回夹具 JSON（只拦这一个端点、卸载还原、不进生产代码分支）。重测读数：
auto=5（chat×2·code×2·reasoning×1）/ direct=5 / explicit=28 /
compress=11 / modelSelect=38，三分桶守恒 5+5+28=38 ✓，直连徽标上卡 ✓。

## 4. 当天汇总（第二轮追加需求）

- 后端 `models-today`：`stats_usage_daily` 已有 `provider_model` 维度
  （rollup 逐 (provider,credential,canonical,raw_model) 落桶）⇒ 本端点在
  canonical_id 上再聚合：**同一标准模型跨供应商/凭据/别名合并一行**（与
  拓扑图模型列的 canonical 口径一致，否则「图上 5 个模型、栏里 8 行」对不上）。
  canonical_id=0 的 passthrough 行回落 raw_model_name（与 modelKeyOf 同口径）。
  share 分母 = 全量 requests（不是可见行和）；截断显式标注 `truncated`。
- 前端 `TodaySummaryRail`：两组独立加载/独立降级（Promise.allSettled 语义，
  一组挂不拖垮另一组）；默认供应商组展开、模型组收起；折叠态组头合计
  （请求 · token · 缓存）仍可见；行内 `请求 成功率 / 占比条 / token · 缓存 N`
  （缓存=cache_read+cache_write；**没有缓存量就不显示「缓存 —」**，假零禁令）；
  点行 toggle 图过滤。60s 轮询、水位与 degraded 是一级信息（沿用 2026-10-16
  「统计不可用 ≠ 当天 0 请求」不变量）。
- 语言包：rail 组 `requests/tokens` 两个死键删除，`title` 换新语义，
  净增 4 键/语种（providerGroup/modelGroup/toggle/cache）；8 语种 141 键
  独立复核一致、占位符零失配。

## 6. 本轮明确没做 / 遗留风险

- **providers-today 组没有模型细分的交叉行**：需要的是「模型×供应商」二元
  交叉，provider_model 维度天然带 provider_id，可加 `?by=provider` 展开——
  本轮只做了 canonical 合并行（与图口径一致优先）。
- **models-today 水位取可见行 watermark 最大值**：截断时（>500 行）低流量
  行的水位可能被高流量行盖住，语义上仍是「数据不会新于此水位」，可接受。
- **压缩格口径是 token_band 非空**：`compression_meta` 里的多路压缩
  （title/summary 环回）不在这一格的读数里。
- **DEV 夹具的 fetch 拦截**只覆盖 provider-kinds 一个端点；models/providers
  -today 在预览页会真打后端（dev server 下 404 → 两组显式降级横幅，
  不影响选路层验证）。
- 批判式审计未覆盖：真实租户下（非 default）的端到端截图验证（无凭据）。
