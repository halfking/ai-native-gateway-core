## 〇、结论（先读这一节）

1. ★★★ **owner 的报障属实，且比描述更具体**：线上简易模式 `/dashboard` 渲染的是
   `SimpleAccessListView`（**只有一张接入清单表**），页面上**没有任何统计数字、没有系统状态、
   没有快捷操作**（除「刷新」「签发网关密钥」两个按钮外）。2026-11-17 05:50 浏览器实页取证：
   标题「接入清单」，副标题「一行一个客户端接入」，下面直接是一张 7 列的表。

2. ★★★ **这不是「漏做」，是 v2 设计稿只兑现了一半**：v2 稿 §四 的首页明确写了
   「KPI 收成页头一行小字」+ 右栏两块面板（供应商健康 / 接一个上游），
   但实现只落了左栏那张清单。v2 自己的风险表 **G1** 就登记过这件事：
   「首页换成清单后，『今天花了多少』变弱」—— 本轮处置的正是 G1。

3. ★★★★ **取证过程中另发现四处线上真缺陷**（都与「初级用户看不懂」直接相关）：

   | # | 缺陷 | 证据 | 本轮处置 |
   |---|---|---|---|
   | **D1** | **211 上的前端产物是旧的**：线上服务的入口 chunk `index-CIvqE3-E.js` 里**有** `SimpleAccessListView`、**没有** `ProvidersModeView`/`SimpleProvidersView` ⇒ 上一轮「部署」发的是**一棵不含 `eb49441c3` 的树**构建的产物 ⇒ **简易模式的供应商页在线上根本不可达**（`/providers` 一律渲染专家面） | 线上 chunk 内容 + 211 上 `/opt/kaixuan/data/llm-gateway/web/a/dist/index.html` 的 entry 同名 ⇒ rsync 到位了，**但构建用的树是旧的** | 本轮用 `deploy-211.sh` 走「部署机侧构建 → 随 tar 上树 → 种子进槽 → 绑定挂载」的正规流程；并在部署后**逐字校验线上 chunk 含新代码**（见 §六） |
   | **D2** | **7 个 i18n 键在全部 8 个语种里都不存在**：`common.status.healthy` / `common.status.warning` / `common.status.unknown` / `common.credentials` / `common.autoFilled` / `common.protocol` / `common.copy` ⇒ 简易模式供应商页与签发页**把键名当文案显示**（字面量 `common.status.healthy`） | `node scripts/i18n-audit.mjs --missing-only`（改动前：7 missing） | 8 语种补齐 ⇒ 审计 **7 → 0 missing** |
   | **D3** | **死路由**：`SimpleKeysView` 的「返回清单」推 `/simple/access-list`，**这条路由从未注册** ⇒ 点「返回」落空 | `grep simple/access-list web/src/` 只有推送点、没有路由行 | 改推 `/dashboard`（简易模式的真实首页） |
   | **D4** | **快捷操作跳死链 + 静默截断**（第四轮 Maestro 实跑撞出，详见 §7.3 / §7.6.3）：① 第 3 个快捷操作跳 `/usage`，而**这条路由从来没有注册**（`router.ts` 无、appNav 真源无）⇒ 点了就是 vue-router 的 no-match 空白页；成因是 `simpleNav.ts` 与台账生成器两份**同源同错**的清单互相掩盖；② 上游健康明细按严重度排序只留前 12 行，被切掉的几乎全是「可用」的 ⇒ 徽标写「19 个上游可用」而列表只有 3 行「可用」，且**截断无任何披露** ⇒ 用户只会判定「这页数据坏了」 | Maestro 实跑（r10）+ 线上 chunk 逐字校验 + 页面内 CDP 对拍（总数 61 / 显示 12 / 隐藏 49） | ① 落点改 `/request-logs`，三份清单同步，并加**三条守卫 + 三条变异自证**（§7.5）；② 模型层新增 `hidden`、面板披露截断、8 语种新键 + 4 条钉测（§7.6.3） |

4. ★★ **性能缺陷（顺手修掉）**：旧实现对**每一个密钥**发一次 `/api/usage/{id}/models`
   ⇒ 线上 208 个密钥 = **208 个请求**才能画出「当前模型」列。
   本轮改为 **3 个请求**（board 一次 + providers 一次 + keys 一次），
   「当前模型」改用 board 自带的 `pies.clients` / `pies.models`（同一张聚合表一并返回）。

5. ★★ **magpie 的借鉴与不照搬**（详见 §三）：magpie **没有首页/仪表盘**，
   它让用户「打开就在上次那页」，首页是一张 Agents 清单。
   ⇒ 我们**不能照搬它的 IA**（我们是多租户网关，统计/预算/对账/审计是商业价值本身），
   但**必须借它的表达层**：状态点 + 口径写在数字旁 + 空状态写「怎么办」+
   **引导 checklist 的勾选状态由真实系统状态推导、完成后自动消失**。

6. ★★★★ **最终状态（2026-11-17 12:33 观测，含第五轮 + 并行车合并后再部署）**：总览页
   `https://llm.itestu.cn/dashboard` 已上线并通过**部署后**的双重验证 ——
   ① **线上版本身份 `53658ecc`（干净 sha，无 `-dirty`）**，`build_seq` 3087，
   槽 b @8783 接管、旧槽 a 已停可回滚，**登录冒烟 OK**；
   ② **页面内 CDP 对拍 24/24 全绿**（含「读不到 ≠ 0」「统计口径与 board API 同页同刻逐字一致」
   「三个面板确实存在」「截断必须披露」「**点下一页后首行与页码都变**」）；
   ③ **Maestro 全量 flow 全绿**（r12：91 步 / 87 COMPLETED + 4 WARNED，WARNED 集合与 r11 逐项相同）——
   登录 → 切简易模式 → 五个区块 → **两个分页列表 + 分页栏** → 六张统计卡 →
   四个快捷操作逐个点并验证落点 → 刷新 → 切回专家面不回归。
   逐条证据见 §7.6（第四轮）、§7.7（第五轮）、§7.7.5.1（合并并行车后再部署）。

7. ★★★★ **第五轮（owner 反馈「接入清单太长」）的核心结论**：
   **总览页的第一张表有 118 行、折叠里还有 91 行** ⇒ 与「5 秒读懂」的总目标**直接冲突**。
   修＝**两个分页列表**（「最近在用」按 `last_used_at` / 「用得最多」按累计 `total_requests`），
   折叠区的停用清单**也分页**；排序与分页落成**纯函数**（可单测），并列按「累计请求数 → id」稳定兜底，
   页码**钳制**到最后一页。
   ★ 口径纪律：**列表＝累计口径、统计卡＝今日口径**，两处口径各自贴着自己的数字并在副标题写明。
   ★ 部署前的**本地预览**当场抓到两个「单测/typecheck 看不见」的真错
   （多余的 `</template>`；模板 ref 自动解包导致**翻页静默失效**）⇒ 详见 §7.7。

## 三、学习 magpie：借什么、不借什么

**magpie 侧取证**：`~/workspace/ai/magpie`（本轮用源码级证据复核，见附录 A）

| magpie 的事实 | 出处 | 我们的处置 |
|---|---|---|
| **没有首页/仪表盘**。导航 10 项无 home/overview/dashboard；窗口还会**恢复上次停留的页面** | `internal/gui/assets/index.html:69-85`、`start.js:7-25` | **不照搬 IA**。我们是多租户网关，「今天花了多少 / 有没有人在用 / 上游健不健康」是用户必须看到的东西 |
| **首屏 = Agents 清单**（一行一个客户端 + 行内选模型），没有请求量/费用/错误率 | `index.html:117`、`docs/reference.md:7-13` | **保留 v2 的清单化主体**（v2 稿 B1），但把统计补在上面 |
| **引导 checklist 的勾选状态由真实系统状态推导**，完成后引导卡自动消失 | `app.js:1717-1743`（`guideShown()` 读 `state.served` / `state.agents[].wired`）、`:1740`（`return null`） | ★ **直接借用**：本轮「三步接入」的三步由真实状态算出（可用上游数 / 已签发密钥数 / 已被调用的密钥数），三步全完成即消失 |
| **口径必须写在数字旁边** | `assets/plugins/usage/client.js:43`「Gateway calls only; session-log calls are in Requests. Local rejections are excluded from totals.」 | ★ **直接借用**：每张统计卡都带口径行（「今日口径」/「当前生效」）；状态条的数字也标口径 |

| **数字等宽（tabular-nums）+ 定高，刷新时不跳动** | `app.css:1266` | ★ 借用：状态条与统计卡的数量用 `font-variant-numeric: tabular-nums` |

## 四、设计：简易总览页长什么样

**一屏的四个问题，按「结论 → 数字 → 行动 → 对象」排**（顺序不是审美，是读屏成本）：

```
┌ 总览 ──────────────────────────────── 工作模式·简易 │ 刷新 │ 签发网关密钥 ┐
│ ● 状态条：一句话结论 + 关键数字 + 异常清单                              │
├ 统计卡行（6 张）：今日请求 · 成功率 · Token 用量 · 今日花费 · 活跃密钥 · 可用模型 │
├ 常用操作（4 个）：接一个上游 · 签发网关密钥 · 查看用量 · 打开对话        │
├ 三步接入（仅未完成时出现，完成即消失）                                  │
├ 两栏 ─────────────────────────────────────────────────────────────────┤
│ 接入清单（表格 + 「已禁用/未使用」折叠带计数） │ 上游健康（分级 + 计数）  │
│                                                │ 最常用的模型（今日 Top5） │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.1 状态条的判据（纯函数，可单测）

| 状态 | 触发条件 | 页面文案（zh-CN） |
|---|---|---|
| `blocked` | **确实**一个能用的上游都没有 | 「现在还不能正常用」+「还没有可用的上游，先接一个上游才能转发请求」 |
| `warn` | 有上游不可达/告警 · 自检最近一次失败 · 自检超过 7 天没跑 · 统计读不到 · **上游状态读不到** | 「有需要处理的地方」+ 逐条列出 |
| `ok` | 以上都没有 | 「系统运行正常」+「今日 16,201 笔请求 · 成功率 96.0% · 21 个上游可用」 |

★ **「读不到」≠「用不了」**：上游健康读不到（403/接口失败）判 **`warn` + `confident=false`**，
**不是** `blocked`。把「不知道」渲染成「不能用」会让用户去修一个没坏的组件。
（对应 magpie 的绿点语义：不知道 ≠ 正常。）

### 4.2 统计卡的口径与降级

| 卡 | 值 | 口径行 | 降级时 |
|---|---|---|---|
| 今日请求 | 16,201 | 今日口径 | **「暂不可用」**（不是 0） |
| 成功率 | 96.0% | 今日口径 | 同上；色调按 ≥99% 绿 / ≥90% 黄 / <90% 红 |
| Token 用量 | 740.4M | 今日口径 | 同上 |
| 今日花费 | $2,665.18 | 今日口径 | 同上 |
| 活跃密钥 | 118 / 208 | 当前生效 | 同上 |
| 可用模型 | 21 | 当前生效 | 同上 |

★ 看板 `summary` 整体降级（`degraded_summary` / `summary_missing_view`）时
**六张卡全部显示「暂不可用」** —— 「读不到」渲染成 0 就是静默错账。

### 4.3 常用操作的动作区预算

`design-action-density` 门的判据是「**一个动作区里最坏情况下可见动作 ≤ 4**」。
⇒ 页头动作区 2 个（刷新 / 签发网关密钥，唯一的主色），
常用操作区 4 个（全为次级样式），**各自独立成区**，不叠加。

### 7.4 工具链结论：Maestro 2.11.0 **web 驱动不支持 evalScript**（实测取证）

★ 这是本轮最大的工具链发现：**它让第一版 flow 的 82 步断言全部失效而不报任何错**。

| 能力 | 实测结果 | 取证方式 |
|---|---|---|
| `evalScript`（web 驱动） | **no-op**：命令报 COMPLETED，但页面一字未变 | 连续三步（改 `document.title` / 写 `localStorage` / 插探针 div）全部 COMPLETED；截图无探针、`screen-hierarchy` 无探针 |
| `${output.x = ...}` | 只在 **JVM 侧**（Maestro 自己的 JS 引擎）求值 ⇒ **拿不到 DOM** | `${output.modeAfterLogin = document.querySelector(...)}` 报 `TypeError: Cannot read property 'querySelector' of undefined`；纯算术 `1+1` 绿 |
| `assertVisible: { text }` | ✔ 可用，**秒级**；但**只匹配可见文本**，且是**元素完整文本相等**（**不是子串包含**） | `text: "登录"` 绿；而 `text: "下一步该做什么"`（元素完整文本是整句「系统现在能不能用、今天跑了多少、下一步该做什么」）**红** |
| `text` 的匹配范围 | `aria-label` / `title` **不参与** | `tapOn "切到专家模式"`（= aria-label）⇒ Element not found |
| `assertVisible: { id }` | ✔ 秒级，但**只匹配 HTML 的 `id` 属性**，**不匹配 `data-testid`** | `id: "login-username"` 绿；`tapOn id: work-mode-switch`（纯 `data-testid`）⇒ **Element not found** |
| `assertVisible: { css }` | ✔ 能用，但**极慢**：单条实测 **2 分 23 秒** | probe 实测 |
| `assertNotVisible: { css }` | ✘ **直接挂住**（无超时上限） | 探针卡在该步 3 分钟无返回 |
| `css` + `text` **组合** | ✘ 不可用（组合断言 FAILED） | probe 实测 |
| `launchApp: { clearState: true }` | 会**清 cookie**（下一轮登录弹窗重新出现） | 连续两轮实跑对比 |
| **`openLink`** | ★★ **会清 localStorage**（cookie 保留）⇒ 工作模式这类「本机选择」**每次整页导航后都退回默认** | 切换到简易模式后 `openLink /dashboard` ⇒ 落地**专家面仪表盘**；同一页用 CDP `Page.navigate` 导航则保持简易模式 |
| `--driver-host-port 9222` | 对 web 驱动**无效**：web 驱动自己起 Chrome（独立 profile 与调试端口） | 并发 `curl :9222/json/list` 全程只看到 `about:blank`，从未出现 Maestro 的页面 |

★ 根因（javap 实证）：`javap -p maestro.drivers.CdpWebDriver` 的方法表里
**根本没有 `evaluateScript`**（只有私有 `executeJS`，供驱动内部用）⇒
命令被 Maestro 的分发层吞掉，照样报 COMPLETED。

★ **「报 COMPLETED 但什么都没做」是最危险的一种失败**：它让一条**从未执行过**的断言
  看起来通过了 —— 第一版 flow 里 82 步断言有 30+ 步依赖 `${output.*}`，
  在这个驱动下**全部拿不到数据**（不是「红」，是「静默空转」）。

★ ★★ **一次必须分清的区分：产品有没有坏？**
  实测过程中一度怀疑「切到简易模式后整页重载会退回专家面」＝产品 bug。
  ★ 用 CDP 在**真实页面**里逐拍取证（`maestro/tools/cdp-client.mjs`）：
  | 时刻 | localStorage | 按钮 | 首页 |
  |---|---|---|---|
  | 复位后 | `expert` | 专家模式 | 专家面 |
  | 点击切换后 | **`simple`** | 简易模式 | **总览页** |
  | **整页重载后** | **`simple`** | 简易模式 | **总览页** |
  | SPA 内跳转后 | `simple` | 简易模式 | 总览页 |
  ⇒ ★★ **产品侧完全正常**：写入、重载保持、投影切换全部正确。
  ⇒ 该现象是 **Maestro 的 `openLink` 清掉了 localStorage**（cookie 不清 ⇒ 登录态还在、
    但本机选择没了）⇒ **不是产品缺陷** ⇒ 不改产品代码去迎合测试。
  ★★ 顺带纠正一个中途的**误判**：截图证明 Maestro 的坐标点击**确实生效了**

    断言的失败信息、没看截图。★ 通用式：**断言失败时先看截图与页面状态，
    再下「哪个环节没生效」的结论**；否则会把「判据写错」误判成「功能坏了」。
  ⇒ 修法落在**测试侧**：把「切到简易模式」做成**幂等子流程**

    每次需要总览页就跑一次 ⇒ 与 openLink 的清理行为无关，恒成立。

### 7.5.1 为可测性补的锚点：`work-mode-switch`

★ 事实：工作模式切换按钮是**全站唯一**的切换入口，但它**没有 HTML `id`**，
  只有 `class="work-mode-switch"` 与 `data-work-mode="expert|simple"`。
★ 而 Maestro web 驱动：`css` 断言极慢（2 分 23 秒/条）、`assertNotVisible: {css}` 挂住、
  `text` 只认可见文本 ⇒ 唯一定位手段就是**可见文本**。
★ 但它的可见文本是「专家模式 / 简易模式」——**随模式变化**，用它当定位键，
  就分不清「点到了按钮」与「按钮已经是这个状态」；用它当判据，又会被
  按钮自身的 `aria-label`（`切到专家模式`）文本干扰。

⇒ 本轮给按钮补 `data-testid="work-mode-switch"`：
- **不改变任何行为**（纯属性增量，无逻辑改动）；
- 让测试可以「按稳定锚点点它」，再用**总览页独有的副标题**（「下一步该做什么」）
  判定模式**真的**切了 —— 判据与被测对象**不同源**，不会被自身文案骗。

★ 通用式：**当一个控件的可见文本同时承担「定位键」与「状态指示」两种角色时，
  它就不是可用的测试锚点**；此时该做的是**补一个不随状态变化的锚点**，
  而不是让测试去猜「点之前它长什么样」。

#### 7.7.6 通用式

1. ★ **「上面做得再好，也会被下面一张长表抵消掉」** —— 概览页的目标是「5 秒读懂」，
   那么**任何超过一屏的区块都会把前面所有努力抵消**；表本身不是问题，**表的长度**才是。
   ⇒ 验收清单里要有「最长区块多少行」这一项，不能只验收「有没有这一块」。
2. ★ **「长表换个地方放」不算修** —— 折叠区里的 91 行同样要分页；
   只把 118 行挪进折叠，用户「展开」时照样被淹没。
3. ★ **排序与分页必须落成纯函数** —— 否则「并列怎么排」「页码越界怎么办」只能靠人肉点，
   而这两处恰恰是最容易出现**静默错误**的地方（行在两页间跳 / 渲染出空页）。
4. ★ **并列必须稳定**（累计请求数 → id 兜底）⇒ 否则翻页时用户会看到「刚才那行不见了」，
   这是**分页最伤信任的一种表现**。
5. ★ **页码要钳制到最后一页** ⇒ 空页会被读成「这一页没数据」，而不是「你已经翻到最后了」。
6. ★ **口径必须写在副标题里** —— 同一页出现「今日」与「累计」两套数字却没交代，读者会自己挑一个信；
   本轮把「累计口径」写进面板副标题，把「今日口径」留在统计卡副标签，**两处口径各自贴着自己的数字**。
7. ★★ **类型检查绿 ≠ 模板能编译；单测绿 ≠ 交互有效** —— 本地跑一次救两个错：
   多余的 `</template>`（`vue-tsc` 放过）、模板 ref 自动解包导致翻页静默失效。
   ⇒ **部署前的本地预览是硬步骤，不是可选步骤**。
8. ★ **「点了没反应」和「点了跳错地方」在日志里都很安静** —— 这两个都只能靠
   「真的点一下 + 看页面状态」发现 ⇒ 断言必须包含**行为**（点下一页后首行变了），
   不能只断言**元素存在**（元素在但功能坏掉时依然存在）。
