### 1.2 ★★ 连带发现一：这道门会被自己的规则**永久卡死**

`scripts/ursmcheck/tracked_binary_artifact_gate_test.go`（A14 轮，2026-11-03 引入）有两条**代理式恒绿护栏**：

2. `TestTrackedBinaryBaselineIsNotEmpty`：`基线为空 ⇒ 门判红`

⇒ ★★ **本轮把仓清干净后，这两条会必然误报**（仓里真的一个编译产物都没有了 ⇒ 「干净」被判成「坏了」）
⇒ ⇒ **照原计划只做 `git rm --cached` 就会把 CI 弄红**。

### 1.3 ★★ 连带发现二：扫描源**漏检**（提交前放行）

原实现用 `git ls-files` 取**文件名**（索引），却用 `HEAD:%s` 取**内容**（HEAD 树）
⇒ ⇒ 两棵树不一致 ⇒ 一个 `git add` 进来、**尚未提交**的二进制在 `HEAD:` 下查不到
⇒ ⇒ `git cat-file` 回 `missing` ⇒ **被静默跳过** ⇒ **门在最该拦的那一刻放行**；等提交完再跑才红，而那时二进制**已经进了历史**。

**实证**（本轮实跑）：

```
HEAD:cmd/llm-gw-annotator/planted-macho.bin  →  missing          ← 旧口径：静默跳过
:cmd/llm-gw-annotator/planted-macho.bin      →  blob 21          ← 新口径：命中
```

**处置**：内容也取索引（`:path` = stage 0 的 blob）⇒ 文件名与内容**同源**。
CI 上索引 == HEAD ⇒ **行为不变**（等价）。

**负控**（把缺陷重新造出来）：

```
$ git add cmd/llm-gw-annotator/planted-macho.bin
$ go test ./scripts/ursmcheck/ -run TestNoNewTrackedBinaryArtifacts
--- FAIL: TestNoNewTrackedBinaryArtifacts
    ★★ 仓内出现**未登记**的编译产物二进制 … [cmd/llm-gw-annotator/planted-macho.bin]
```

⇒ ★ **门确实抓到了未提交的二进制** ⇒ 处置后比处置前**更严**。

### 1.4 未做（明确登记）

- **历史未瘦身**：两个 blob 仍在 `.git` 历史里。彻底瘦身需 `git filter-repo`（**改写历史 SHA**）
  ⇒ ★ 须与协作方约定窗口 ⇒ 本轮**不做**。
