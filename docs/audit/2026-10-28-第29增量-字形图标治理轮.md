## §1 起因：第 28 增量的顺藤摸瓜

第 28 增量做「图标必须有尺寸」时，发现 `@element-plus/icons-vue` 渲染的裸 `<svg>` 没有内在尺寸
⇒ 尺寸全靠 CSS 兜 ⇒ 兜底逐处写 ⇒ 漏一处就塌成 0×0。

本轮顺着「图标位」这件事继续查，撞上一个更大的事实：

> **DESIGN.md §6「图标」明令「不许用 emoji / Unicode 字形冒充图标系统」**
> （原文点名 `StatCard` 的 `icon` 参数即此病），
> **而仓内有两套门都看不见它**。

- 源码侧：`aiSmells.ts` 的 **V3（`detectGlyphIcons`）** 只扫**元素字面量**
  （`<button>` / `<a>` / class 含图标语义词）⇒ **emoji 藏在数据数组里时它完全失明**。
- 语言包侧：**根本没有门** ⇒ 8 个语言包的值里的 emoji 从来没有被任何一道门看过。

## §3 判据设计：三次收窄（★ 本轮最值钱的一段）

### §3.1 第一版：「语言包值含 emoji 即判红」⇒ ★★ 越权

★ 我按这个口径落盘清理了 **518 处**（104 个文件）。
★ ★★ 落盘**之后**回头核对仓内**既有口径**，发现它比事实源**宽**：

> `aiSmells.ts` 的 `glyphCandidates` 明写：
> ★ 「**图标位**（元素里只有这个字形）」才算违规；
> ★ 「**字形 + 文本 = 文字标记，不是图标位**」；
> ★ 仓内 **172 处**「文本以字形开头」（`★` 作危险标记前缀等）被明确记为
> ★ **既有惯例、判绿**，不是待清的存量。

⇒ ★★ 对照实测：518 处**全部**是「字形 + 文本」，**图标位 0 处**
⇒ ⇒ ⇒ ★★★ **我的清理全是越权** ⇒ ★★ **全部回滚**（`git checkout -- web/src/locales/`）。

> ★★★ **通式：判据比事实源宽 ⇒ 批量落地就是在改无辜的代码。**
> ★★ 而批量落地**不可逆** ⇒ ★★ **落盘前必须先对着事实源核口径**
> （★ 本轮代价：一次回滚 + 一次重做 + 一次清理脚本的删除）

### §3.2 第二版：口径与仓内一致 ⇒ 门变成「防回归闸」

★ 门口径改为「**图标位** = 去掉字形后不剩任何文字」
⇒ ★ 与 `aiSmells.ts` 的 V3 同源 ⇒ ★ 当前读数 **0**
⇒ ★★ 它的价值是**防回归**：防止有人把 `icon: '📋'` 写进语言包
（★ 那正是本轮真缺陷的语言包版）。

### §3.3 第三版：★ 清理函数的字符集必须与判定同源

★ `stripGlyphIcons` 第一版用宽口径正则
`/[\p{Extended_Pictographic}\p{Emoji_Presentation}\uFE0F\u20E3]/gu`
⇒ ★★ **`↔`(U+2194) 也是 `Extended_Pictographic`** ⇒ ⇒ 协议互转的箭头会被一起删掉。

★ 是 vitest 用例 `stripGlyphIcons('Anthropic ↔ OpenAI {n}')` 抓到的。

> ★★★ **如果当初没有回滚那 518 处清理，语义箭头就已经被删掉了。**
> ⇒ ★★ 「先查清口径再落盘」救了真缺陷 —— ★★ **不是运气**。

★ 修法：清理逐字符走 `isGlyphIconChar`（已排除流程箭头与排印符号）。
