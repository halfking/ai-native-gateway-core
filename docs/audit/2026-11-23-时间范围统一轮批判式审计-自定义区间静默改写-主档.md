# 2026-11-23 时间范围统一轮——批判式审计：自定义区间被静默改写（根因 + 修复）

> **一句话**：全站统计页面统一了时间范围**控件**，但**控件允许选自定义历史区间、后端却只认天数**——
> 前端把用户选的区间压成「跨度天数」，后端把天数解释成「相对今天的滚动窗口」。
> ⇒ **用户选 2026-09-01 ~ 2026-09-10，实际拿到的是「最近 10 天」**。
> 这是**静默错误答案**（界面显示 A、数据是 B），不是量具问题，也不是「没有时间范围控件」。
>
> 本轮取证 → 定案 → 修复 → 实测闭环，并把「预设走 days / 自定义走 start+end」的口径固化到前后端契约与钉测。

## 二、取证（可复现）

### 2.1 现象：参数被静默忽略

本地真实网关（8782）+ 真实种子数据：

```bash
GET /api/admin/work-types/stats?start_date=2026-09-01&end_date=2026-09-10
→ HTTP 200
→ 响应 window="24h"     ← 参数被忽略，回落默认窗口
```

对比：

```
?days=10                    → window="10d"    （正常）
?start=...&end=...          → window="24h"    （★ 被静默忽略）
（不传）                    → window="24h"
```

### 2.2 根因定位（两条链）

**链条一：后端把 `days` 解释成「相对现在」的滚动窗口**

```go
// admin/work_types.go（改前）
windowInterval := fmt.Sprintf("NOW() - INTERVAL '%d hours'", int(windowDur.Hours()))
// ⇒ days=N 恒等于「最近 N×24 小时」，无法表达任何历史区间
```

**链条二：前端把自定义区间压成天数**

```ts
// web/src/composables/useSpanDaysRange.ts（改前）
function applyRange(range: KxDateRange) {
  const span = rangeSpanDays(range)
  if (span >= 1) days.value = span   // ★ 自定义区间 → 只剩「跨度天数」
}
```

**两条链条相乘 = 静默错误答案。**

### 2.3 影响面（全站普查）

| 形态 | 页面数 | 说明 |
|---|---|---|
| `useSpanDaysRange` + 后端只收 days | 15 | 自定义区间被压成天数（**静默改写**） |
| `useSpanDaysRange` + 后端**已**收 start/end | 4 | board / usage-enhanced / usage-provider-* ⇒ **后端能力被前端扔掉** |
| `useRangeDays`（本轮新增） | 4 | board×2、work-types、routing-dashboard ⇒ 自定义区间原样透传 |

★ 后端**已有**真实区间能力的面（`admin/board_time_range.go:boardTimeRangeFromRequest` 收 `start`/`end`、
`admin/usage.go:resolveUsageTimeRange` 是通用解析器、`web/src/api/board.ts` 早就有 `start`/`end` 参数）
——**能力一直在，只是前端没传**。这是本轮最反直觉、也最该修的一点。

## 三、修复

### 3.1 后端：统一区间解析（新增 `admin/stats_time_range.go`）

```go
parseStatsTimeRange(r, defaultDays) → statsTimeRange{Start, End, Days, Hours, Custom, StartDate, EndDate}
```

- **`start` + `end`** ⇒ 真实区间（`Custom=true`），`[start, end)` 半开、end 日全天计入；
- **`days`** ⇒ 旧行为**逐字保留**（`NOW() - INTERVAL '{hours} hours'`，零参数）；
- **半截区间 / 越界 / 非法值** ⇒ **400 报错**（不静默回落、不静默夹紧）。

三个设计取舍：

1. **days 分支保持零参数** ⇒ 端点内其它占位符（tenant 片段）编号不变 ⇒ 改造面与回归风险最小；
   且 `NOW()` 在库里求值，客户端时钟不参与（改成 `INTERVAL '1 day' * $1` 会在 DST 时区差 1 小时）。
2. **复用 `settings.SystemDayRangeUtc`** ⇒ 不新造轮子，且天然带 `end >= start` 校验。
   ★ 自拼 `ParseSystemDate(...).UTC()` 会在 UTC+8 下把区间起点显示成**前一天**（单测抓到）。
3. **跨度天数不再 `+1`** ⇒ `End` 已是「end 日 +1 天零点」（独占端），再 `+1` 会把 10 天算成 11 天。

### 3.2 后端：端点接入

| 端点 | 改动 |
|---|---|
| `/api/admin/work-types/stats` | 收 `start`/`end`；自定义区间时谓词参数化（tenant 占位符顺延 `$3`） |
| `/api/admin/auto-route/analytics/matrix` | 收 `start`/`end`；**自定义区间绕开物化视图**（MV 只覆盖固定窗口） |
| `/api/admin/auto-route/analytics/flow` | 同上（L12 + L23 两段查询） |
| `/api/admin/auto-route/analytics/funnel` | 同上（RDL 精确 / `_request_logs` 近似 / 混合补齐 三条查询同窗）；**自定义区间不入缓存**（缓存键只带天数档位 ⇒ 两个历史区间会撞同一把键 ⇒ 串数据） |

### 3.3 前端：两个 composable 分工（诚实性约定）

```ts
useSpanDaysRange(days, buckets)   // 端点只收 days
  // ⚠️ 自定义区间语义 = 「跨度天数」⇒ 调用方必须用 KxDateRangePicker 的
  //    presetsOnly 禁掉自定义入口，否则界面显示的区间 ≠ 数据窗口。

useRangeDays(days, buckets)       // 端点收 start/end
  // 预设 ⇒ customRange=null（走 days 快路：后端缓存键 / MV 选择 / 索引扫描不受影响）
  // 自定义 ⇒ customRange 原样保留 start/end（不再被压成天数）
```

★ **为什么预设仍走 days**：预设解析出的区间本身就是「相对今天」的窗口，与 days 语义天然一致 ⇒
两者结果相同，走 days 不损失任何东西；**只有用户手选的历史区间两者才分叉** ⇒ 只在自定义时透传。

### 3.4 前端：组件加 `presetsOnly`（第二道防线）

`KxDateRangePicker.vue` 新增 `presetsOnly` prop ⇒ 隐藏自定义起止输入与「应用」按钮。
供「端点确实只收 days」的页面使用：**宁可不给自定义入口，也不给一个会被悄悄改写的区间**。

### 3.5 前端：页面接入

| 页面 | 改动 |
|---|---|
| `BoardOperationalView.vue` | `useRangeDays` + 透传 `start`/`end`；**下钻链接一并带上**（否则「看板选历史区间 → 下钻页变回最近 N 天」） |
| `BoardOperationalListView.vue` | 同上 + 支持从 URL 读 `start`/`end` |
| `WorkTypesView.vue` | 同上；`api-work-types.ts` 的 `getWorkTypeStats` 支持 `{days}` \| `{start,end}` |
| `RoutingDashboardView.vue` | 同上；`api-autoroute.ts` 新增 `AnalyticsRange`；**matrix/flow/funnel 三端点共用同一区间参数**（否则页面内两块数据口径不一致） |

## 六、通用式（可复用的教训）

1. ★ **「控件统一」不等于「语义统一」**：统一了输入控件，但没统一「输入如何被解释」。
   审计必须验证的不变量是「**界面显示的区间 = 数据反映的区间**」，不是「有没有控件」。
2. ★ **静默回落比报错更危险**：参数被忽略时端点返回 200 + 合理数据，用户无从察觉。
   ⇒ 区间类参数**要么生效、要么明确报错**，绝不静默回落默认窗口。
3. ★ **后端已有能力要先查清再改前端**：本轮最贵的发现是「`start`/`end` 早就通了，是前端压成了天数」——
   改前端比改后端便宜一个数量级。
4. ★ **多端点同窗是一致性底线**：matrix/flow/funnel 共用一个时间选择器 ⇒ 必须共用同一区间参数，
   否则同一页面上半屏是自定义区间、下半屏是「最近 N 天」。
5. ★ **共享工作树上禁止 `git checkout -- .` / `git clean -fd`**：本轮误删了自己在途的 4 个文件
   （后端 2 改 + 2 新），靠隔离 worktree + patch 导出才救回。⇒ 在途改动必须先导出 patch，
   或全程只在隔离 worktree 操作。
