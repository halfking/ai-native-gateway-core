## 一、审计结果

### 发现的问题

#### P1 - 验证码前端完全缺失（高优先级）
**问题**：前端登录表单没有验证码输入，导致多次登录失败后用户完全无法登录。

**影响**：
- 用户体验极差
- 本次验证过程中真实遇到此问题
- 需要重启容器才能清除失败计数

**状态**：✅ **已修正**

#### P2 - 认证提供者配置硬编码（中优先级）
**问题**：虽然架构支持 Native 和 Casdoor 两种提供者，但实际硬编码为 "native"，无法通过配置切换。

**影响**：
- 无法使用 Casdoor 认证
- 需要修改代码并重新编译

**状态**：✅ **已修正**

#### P3 - 配置管理界面缺失（低优先级）
**问题**：没有管理界面让管理员选择认证提供者和配置参数。

**状态**：📋 **待后续实现**

## 三、修正方案摘要

### 3.1 前端验证码支持

**实现**：
- ✅ 创建 `CaptchaInput.vue` 组件
- 📋 修改 `LoginModal.vue` 集成验证码
- 📋 修改 `auth.ts` 添加 `getCaptcha()` API
- 📋 修改 `login()` 函数支持验证码参数
- 📋 添加 8 语种 i18n 文案

**流程**：
1. 用户正常登录（无验证码）
2. 多次失败后后端返回 `captcha_required` 错误
3. 前端自动显示验证码并调用 `/api/auth/captcha`
4. 用户输入验证码后重新提交
5. 验证码错误时自动刷新

### 3.2 认证提供者配置

**实现**：
- 📋 修改 `cmd/gateway/main.go` 从环境变量读取配置
- 📋 添加 Casdoor 配置结构（如需要）
- 📋 添加配置验证逻辑

**环境变量**：
```bash
LLM_GATEWAY_AUTH_PROVIDER=native|casdoor  # 默认 native

# Casdoor 配置（当 AUTH_PROVIDER=casdoor 时）
LLM_GATEWAY_CASDOOR_ENDPOINT=https://...
LLM_GATEWAY_CASDOOR_CLIENT_ID=xxx
LLM_GATEWAY_CASDOOR_CLIENT_SECRET=xxx
LLM_GATEWAY_CASDOOR_ORGANIZATION=org
LLM_GATEWAY_CASDOOR_APPLICATION=app
```
