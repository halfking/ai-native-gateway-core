## 🎯 任务识别流程

### 当前实现（两层）

```
请求 → [第一层] 启发式分类器（本地规则）
          ↓ 置信度 < 阈值
        [第二层] LLM分类器（远程调用）
          ↓
        任务类型（chat/code/reasoning等）
          ↓
        模型选择
```

**代码位置**：
- `autoroute/classifier.go` - 启发式分类器
- `autoroute/classifier_llm.go` - LLM分类器（第二层）
- `autoroute/decision.go` - 决策器

### 优化方向（三层）

```
请求 → [第一层] 启发式（本地规则，置信度≥0.85直接返回）
          ↓
        [第二层] 本地轻量模型（置信度0.5-0.85，降低远程调用）
          ↓
        [第三层] 远程精确模型（置信度<0.5，复杂任务）
          ↓
        任务类型 → 模型选择
```

**收益**：
- 降低LLM调用频率 50-70%
- 降低分类延迟 30-50%
- 提高中等置信度场景准确率

## 🎓 技术要点

### PI分析层集成（任务识别特殊类型）

**概念**：将"识别任务意图及类型"本身作为一个特殊任务类型，使用auto模式处理。

**实现思路**：
```go
// PI分析的任务识别也用auto模式
type PITaskRecognizer struct {
    AutoDecider *autoroute.Decider  // 复用auto决策器
}

// 识别错误的任务意图
func (r *PITaskRecognizer) RecognizeErrorIntent(ctx context.Context, errorContext ErrorContext) (Intent, error) {
    // 1. 将错误上下文转换为分类信号
    signals := convertErrorToSignals(errorContext)
    
    // 2. 使用auto分类器识别错误类型
    decision := r.AutoDecider.Decide(ctx, signals, ...)
    
    // 3. 映射到修复意图
    intent := mapTaskToIntent(decision.TaskType)
    
    return intent, nil
}
```

**优势**：
- 复用成熟的任务识别基础设施
- 本地+远程模型协作自动生效
- 统一的监控和优化路径
