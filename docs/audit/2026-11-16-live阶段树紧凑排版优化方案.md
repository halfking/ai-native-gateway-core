# /live 阶段树紧凑排版优化方案

> 基于：2026-11-16-live阶段树原型.html  
> 目标：保持完整信息和专业风格，仅优化节点内文字排版  
> 原则：不删减信息，不改变交互，不偏离视觉风格

---

## 一、问题诊断

根据反馈，原版设计的优点全部保留：
- ✅ 完整的节点信息展示（阶段名+状态+详情）
- ✅ 统计浮窗的详细程度和交互方式  
- ✅ 整体的视觉风格和色彩体系
- ✅ 列头固定显示阶段名称

唯一问题：**节点内的文字信息排版有点拥挤**

---

## 二、优化策略

### 2.1 节点内部排版优化（核心改进）

**当前结构**（发送轨节点 104×42px）：
```
┌────────────────┐
│ ✓ 鉴权/限流     │  ← n-top: 9.5px, gap:4px
│ 已通过          │  ← n-title: 11.5px, 行高1.25
│ 12ms·key已校验  │  ← n-meta: 9.5px (当前被隐藏)
└────────────────┘
```

**优化后**（保持 104×42px）：
```
┌────────────────┐
│ ✓ 鉴权/限流     │  ← 字号不变，但间距优化
│                 │  ← 增加垂直留白
│ 已通过 12ms     │  ← 状态+关键值合并一行
└────────────────┘
```

**具体调整**：
1. **n-top 行间距**：gap: 4px → 5px（图标与文字稍微拉开）
2. **n-title 行高**：line-height: 1.25 → 1.3（增加呼吸感）
3. **n-title + n-meta 合并**：状态值与关键数据放同一行，用空格分隔
4. **内边距微调**：padding: 3px 7px → 4px 8px（四周稍微放松）

### 2.2 请求带间距优化

**当前**：请求带之间紧贴，border-bottom 分隔  
**优化**：带之间增加 4px margin-bottom，用真实间距替代视觉分隔

### 2.3 列头视觉优化

**当前**：stagehead 纯背景色  
**优化**：加轻微渐变和阴影，增强层次感但不抢眼

### 2.4 摘要行精简

**当前**：多个 chip 平铺
```
● 成功 2.4s · 1.2k/890 · ¥0.0031 · claude-code/openai · 缓存命中 42%
```

**优化**：保持所有信息，但紧凑排版
```
✓ 2.4s | 1.2k/890tok | ¥0.003 | claude→gpt-6 | cache 42%
```
- 用竖线分隔替代圆点（视觉上更轻）
- 缩短单位词（token→tok）
- 成本精度 4位→3位（足够）

## 四、JavaScript 节点渲染优化

### 4.1 nodeHTML 函数调整

保持函数签名不变，只调整内部HTML结构：

```javascript
function nodeHTML(key, name, cls, state, x, y, compact, extra, tipOv){
  const glyph='<i class="gl">'+GLYPH[state.s]+'</i>';
  const tip=tipOv || (name+' · '+(state.v||'—')+(state.d?' · '+state.d:''));
  
  if(compact){
    // 接收轨保持原样
    return '<div class="node '+cls+' s-'+state.s+'" data-key="'+key+'" style="left:'+x+'px;top:'+y+'px"'
      +' data-tip="'+esc(tip)+'">'
      +'<div class="n-title">'+glyph+'<span>'+esc(name)+'</span><b>'+esc(state.v||'—')+'</b></div>'
      +'<div class="n-bar"></div></div>';
  }
  
  // 发送轨：状态值与详情合并
  const mainVal = state.v || '—';
  const detail = state.d ? '<span class="detail">'+esc(state.d)+'</span>' : '';
  
  return '<div class="node '+cls+' s-'+state.s+'" data-key="'+key+'" style="left:'+x+'px;top:'+y+'px"'
    +' data-tip="'+esc(tip)+'">'
    +'<div class="n-top">'+glyph+esc(name)+(extra||'')+'</div>'
    +'<div class="n-title">'+esc(mainVal)+detail+'</div>'
    +'<div class="n-bar"></div></div>';
}
```

### 4.2 摘要行生成优化

```javascript
// 原版使用多个 chip，优化为更紧凑的单行
function summaryHTML(band){
  const dur = band.latency ? fmtDur(band.latency) : '—';
  const icon = band.result==='success' ? '✓' : (band.result==='failure' ? '✕' : '◐');
  const badge = band.result==='success' ? 'ok' : (band.result==='failure' ? 'bad' : 'run');
  
  let parts = [];
  parts.push('<span class="badge '+badge+'">'+icon+' '+dur+'</span>');
  
  if(band.tokensIn || band.tokensOut){
    parts.push('<span class="chip">'+band.tokensIn+'/'+band.tokensOut+'tok</span>');
  }
  
  if(band.cost){
    parts.push('<span class="chip">¥'+band.cost.toFixed(3)+'</span>');
  }
  
  // 模型解析链（仅在有切换或auto时显示）
  if(band.isAuto || band.clientModel !== band.model){
    const chain = band.clientModel + (band.clientModel!==band.model ? ' → '+band.model : '');
    parts.push('<span class="chip model">'+esc(chain)+'</span>');
  }
  
  // 缓存命中率（有数据时才显示）
  const cr = cacheRate(band);
  if(cr && cr.pct !== null){
    parts.push('<span class="chip hit">cache '+cr.pct+'%</span>');
  }
  
  return '<div class="summary">'+parts.join('<span class="sep">|</span>')+'</div>';
}
```
