## 4. 判据定稿

### 4.1 三级判据

**① 指标格（metric cell）** = 一个「表面」盒子（有底色 **或** 四边**可见**描边），同时满足：

- a. **巨数字**：存在文本叶子，字号 **≥ 24px**（仓内 `--kx-text-2xl`，即「巨数字」的规范档）**且内容含数字**；
- b. **小标签**：存在另一个文本叶子，字号 **≤ 14px** **且严格小于巨数字字号**
  （★ 14px 是 `--kx-text-md` 档；★ 第一版写的 13px **漏掉了这一档** ⇒ 被 M2 臂抓出来，详见 §8.3）；
- c. **不是商品卡**：格内**没有交互控件**（`button` / `.el-button` / `a[href]` / `[role=button]` / `input` / `select` / `textarea`）；
- d. **不是货币计价**：巨数字带 `¥ $ € £ ₤` ⇒ 商品标价 / 货币金额，不是 hero 指标；
- e. **不是药丸**（圆角 ≥ 高度的一半）、**不是隐藏子树**、**不是一个整段页面**（宽度 ≤ 400px：24px 的数字摆在 660px 宽的区块里是「页面章节」，不是「指标卡」）。

**② 装饰性强调色** = 巨数字的**计算色**命中「装饰性主色集」
{`--accent`, `--accent-h`, `--kx-primary`, `--kx-primary-hover`, `--el-color-primary`} 的**实测计算值**
（每通道容差 2），**且**不命中语义色集 {`--success`, `--warning`, `--danger`}。

**③ 页面级硬闸**：同一父容器下 **≥ 3 个**指标格，且其中 **≥ 2 个**的巨数字带装饰性强调色 ⇒ 判红。

### 4.2 两条关键取舍（★ 都各有代价，写明）

**取舍一：accent 必须用 token 精确匹配，不能用颜色空间阈值**（§3.1）。
⇒ 代价：**色值被改写**（例如 `color-mix` 混出来的中间色）**匹配不上** ⇒ 那是已知盲面。

**取舍二：排除项要两条并用**（CTA + 货币）。
⇒ 只用 CTA 那条会有**视角依赖**：`pricing-card` 的「立即购买」按钮带 `v-if="!isAdminTenantView"`，
管理员视角下按钮**不渲染** ⇒ 只靠 CTA 那条，管理员视角会把它误判成指标墙。
⇒ 补一条与视角无关的货币排除 ⇒ 两条并用才稳。
⇒ 代价：**一条「以货币计量、且被主色染、且 ≥3 格并排」的指标墙会被漏掉**（判据宁可窄，不可宽）。

### 4.3 门槛（≥3 格 / ≥2 格）不是拍脑袋定的

★ 第 30 增量已经认定：控制台里「表格 / 筛选区上方的**抬头摘要条**」是**合法存量**（1 组，4~6 张）。
⇒ 本轮的门槛必须与这条存量对齐：

- **≥ 3 格**：两格不算「并排」；
- **≥ 2 格染主色**：**单点强调不判红**（`/admin/usage` 的「综合节省率」是 5 格里唯一的主色数字 ⇒ 合法），
  **整片染主色才判红**（`/pricing` 7/7 ⇒ 违规）。
