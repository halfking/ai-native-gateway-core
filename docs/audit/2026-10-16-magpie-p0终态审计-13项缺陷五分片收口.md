## 二、修复与判据（先红后绿 + 变异验证）

每个分片：同层红测先行（修前确认红）→ 最小修复 → 变异验证（cp 备份恢复，
禁 git checkout/stash/reset）→ 包全量复绿。

- **survival**：`context.WithTimeoutCause` 派生 attempt deadline（fake Now 与真
  wall-clock 解耦；父 deadline 优先且不渲染 synthetic terminal）；`SurvivalDeadline`
  显式贯穿 upstreamContext/dispatchExecutionContext（detached 保 deadline 免客户端
  cancel）；durable `deadline_exceeded && !ContentCommitted` → ReleaseToWorker；
  `ExecuteError.RetryAfterSeconds`/tracker `RetryAfterSeconds` fold 进
  CandidateOutcome。变异：撤 deadline ctx（阻塞测试超时红）、撤 durable 交接
  （resched=0 红）、撤 RetryAfter fold（candidate 0s 红）。
- **reqprobe**：`LearnedKey{ProviderID, OutboundModel, ActualWire}` 贯穿
  Store/Memory/Redis/Fingerprint/Coordinator 缓存（invalid 键 fail-open 不学习）；
  `actualOutboundWire` 按**运行时端点**（native→responses/anthropic/否则 chat）映射，
  学习查询与记录点全部切换；空快照不缓存（正缓存保留，跨实例靠 Store 收敛）。
  变异：换回声明协议（chat 丢 stream_options 红）、恢复空缓存（异步学习不可见红）。
- **nodehealth**：adapter 顶部算 `ModelScopedRejection(ErrorDetail)`，完整过滤
  credential-wide effects（breaker+SetCredentialUnavailable），保留
  binding/URSM/cache/probe；legacy UpdateOnFailure 同门禁；真实 OutcomeReducer
  三连失败判据（前提：六个 effect 在场）。SurvivalAttempt 恢复 quotaHeld 快速返回
  与 probeOne 单飞，恢复后**不递归 Execute**（返回可聚合 transient 交协调器下一轮）。
  变异：撤过滤（breaker 被创建红）、恢复 `!SurvivalAttempt` 门（quotaHeld 丢失红）。
- **observe**：LOG_GLOB 走 python 逐行解析 RFC3339 time 只计窗口内；journal unit
  for+case 去重（bash3.2 兼容）。变异：去时间过滤红、去去重红。
- **continuation**：见 commit `060ace467` 详情——error 帧三站点契约、预算/计量、
  usage banking、role 抑制、n>1 禁续、64KiB 上限、max_tokens 保守禁续、EOF body
  先关；附 sse buffer-full 修复+独立回归。五方向变异全红。

## 四、过程记录（量具教训）

1. **限流/网络中断下的代理收口**：5 路审计代理中 3 路两次被提供方限流打断；
   恢复靠「保留 worktree 现场＋新代理接手现状审查」而不是重做；一次全局网络
   故障后 4 个修复代理阵亡，改为主会话直接接手分片收口。
2. **审计代理的 finding 也要复现**：reqprobe 分片代理留下的实现把 Chat 线学习
   整体禁用（过宽）、一条集成测试用 `reasoning_effort` 作量具（会被其它方言
   裁剪器删掉，假绿）——接管后改为线格式骨架精确过滤 + `stream_options` 量具，
   红测立刻暴露出「实际端点 vs 声明协议」这一层真正的根因。
3. **隔离 worktree 的量具陷阱**：首轮「基线测试」实际跑在共享主 checkout
   （cd 未切换），结果作废重跑——审计证据必须绑定 worktree 路径。
4. **红测意外抓出第三方缺陷**：prefix 上限红测在基线同样红，追出
   sse.LineReader 的 buffer-full 缺陷——红测的「意外红」要查因，不能只让它变绿。
