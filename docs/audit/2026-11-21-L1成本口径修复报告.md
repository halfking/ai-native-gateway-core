## 一、问题描述

根据审计报告（docs/audit/2026-11-20-会话分析系统前端实施报告.md §五 L1），后端API存在跨单位成本相加问题：

```
后端 total_cost = internal_cost(美元) + external_cost(积分)
```

**影响**：
- 排序依据混合口径，数据语义不清晰
- 前端虽然有兜底方案（从trends.cost分别求和），但API契约不够明确
- 用户无法从API直接获取分离的成本数据

**优先级判定**：
- 前端已兜底 ⇒ 非阻塞性
- 数据质量问题 ⇒ P1优先级
- API契约优化 ⇒ 建议近期处理

---

## 二、解决方案

### 2.1 方案选择

经过评估，采用**保守方案B（向后兼容）**：

| 方案 | 优点 | 缺点 | 决策 |
|-----|------|------|------|
| 方案A：完全重构 | 彻底解决问题 | 破坏性变更，需前后端同步 | ❌ 不采用 |
| **方案B：保持兼容** | 向后兼容，渐进式改进 | 保留冗余字段 | ✅ **采用** |
| 方案C：最小改动 | 改动最小 | 问题未彻底解决 | ❌ 不采用 |

### 2.2 实施策略

**保留原有字段**：
- `total_cost` - 保留用于排序和向后兼容
- 添加注释说明跨单位相加的语义

**新增分离字段**：
- `internal_cost` - 内部成本（美元）
- `external_cost` - 外部成本（积分）
- 对于OverviewSummary，同时添加增长率字段

## 五、API契约变更

### 5.1 响应格式变更

**变更类型**: 非破坏性扩展（additive change）

**示例 - OverviewSummary**：
```json
{
  "summary": {
    "total_sessions": 12345,
    "total_cost": 1234.56,              // 保留（美元+积分混合）
    "total_cost_growth": 15.5,          // 保留
    "internal_cost": 789.12,            // 新增（纯美元）
    "internal_cost_growth": 12.3,       // 新增
    "external_cost": 445.44,            // 新增（纯积分）
```

**向后兼容性**：

- ✅ 排序功能保持不变（仍使用`total_cost`）
