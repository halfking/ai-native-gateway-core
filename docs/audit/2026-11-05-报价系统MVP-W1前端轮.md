## §2 实施中的行为决议（对齐后端与红线）

1. **withheld 展示面**：`sellable.withheld` 以告警条 + 计数呈现（同名多价整组
   withhold 不进可售表——视图测试断言 `model-b` 不在表内文本）。
2. **C3 是门不是分（前端不越权阻断）**：置信档逐行如实展示（trusted=绿、
   其余=警示色），但前端不做提交拦截——提交准入由服务端 `SubmitQuote` 的
   C3 门裁决（前端拦截只会造成「两把尺」）。
3. **分享 token 一次性**：创建响应携带明文 token ⇒ 立即拼 `/public/quote/{token}`
   复制进剪贴板并提示「只出现一次（明文不落库）」；后续清单条目类型上就
   没有该字段（`token?:`），测试断言 `listed.items[0]?.token === undefined`。
4. **无独立红线评估端点**（诚实边界）：红线判定在 `submit` 动作内由服务端
   执行（决议 B「只审例外」）；前端以 submit 返回状态
   （approved=政策内自动放行 / pending_approval=触发）+ `/approvals` 的
   trigger_reasons 快照呈现触发结果，不造 version 级评估端点的假客户端。
5. **菜单门控**：菜单项不设 super——供给登记的写权限是 super-only（POST
   走 `h.superAdmin` 包装），需求 claim/报价动作带 owner 语义（A-11 先例）；
   前端不重复角色模型，服务端是唯一裁决点。
