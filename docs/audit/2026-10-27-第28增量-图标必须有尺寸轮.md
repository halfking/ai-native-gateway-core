## §1 主题：控件渲染成空方块，比没有这个控件更糟

★ 勘察（第 27 增量收尾后）：操作员首屏（仪表盘 `/`）的页头右侧，有一个**空圆角方块**——
既没有图标，也没有文字，只有 `title="刷新数据"`。

```
  API Key      模型      整站数据      ▢      ← 最右那个是空的
```

★ 而它是**刷新数据的唯一入口**（页面上没有别的刷新控件）⇒ 用户看到一个不动的方框，
只能靠鼠标悬停才知道那是什么 ⇒ ★★ 这是 `polish.md` §3 分诊里的**第 1~2 级**
（"broken or blocked tasks / inaccessible paths"），**不是**第 4 级的视觉不一致。

★★ **本轮最值钱的一处认识**：这个洞**不是**「某处 CSS 写漏了」，而是
**「设计系统里压根没有『图标尺寸』这回事」** ——
`@element-plus/icons-vue` 渲染的**裸 `<svg>` 没有 width/height 属性** ⇒ 没有内在尺寸 ⇒
尺寸**完全靠 CSS 兜**；而兜底此前是**逐处**写的（每个父元素各写各的）⇒ **漏一处 ⇒ 塌成 0×0**。

⇒ ★ 这正是 `polish.md` §1 点名的 **"missing token: the system needs a reusable value"**。

## §2 勘察：两路图标 · 174 处裸图标 · 为什么源码判据太宽

### 2.1 两路图标，只有一路有内在尺寸

| 路 | 写法 | 内在尺寸 | 实测 |

★ 两路都靠 CSS 兜 ⇒ **同一个坑**。

### 2.2 ★ 为什么「裸图标」不能当判据

★ 直觉写法：「凡是没有 `<el-icon>` 包裹的 element-plus 图标 ⇒ 判红」。
★ **实测这个判据太宽**：174 处里**绝大多数是正常的**（父级有尺寸规则）⇒ ⇒
按它做门 ⇒ **把 174 处全判红** ⇒ ⇒ **判据宁可窄，不可宽**。

★ ⇒ 真正能下判决的只有一件事：**它渲染出来到底有没有尺寸** ⇒ ★ **必须是运行时尺**。

### 2.3 ★★ 覆盖面的盲区：既有运行时尺**不含首页**

⇒ ★ **没有 `/`（仪表盘首页）** ⇒ ⇒ 而 0×0 图标恰恰长在首页页头
⇒ ⇒ **首页此前无人看守**。

## §3 量具：为什么只能是运行时尺（★ 以及量具自己被抓出的两处缺陷）

### 3.1 两层结构（照抄仓内既有尺的形状）

★ 判定层吃**纯描述符**（不碰 DOM）⇒ `--selftest` 不需要浏览器；
浏览器探针只负责「把 DOM 翻译成描述符」⇒ 两层口径不会各说各话。

### 3.2 ★★ 量具自身的两处缺陷（都是被抓住的，不是想出来的）

| # | 缺陷 | 怎么抓到的 | 修法 |
|---|---|---|---|
| **M1** | 判定写成「**任一边** > 0 就放过」⇒ **`0×10`（宽为 0）被漏判** | ★ **本工具自己的 `--selftest`**（S-IS4） | 改成「**两边都** > 0 才算看得见」 |
| **M2** | 探针**没有「隐藏子树」这一条** ⇒ 还没打开的下拉菜单里的图标被判红 | ★ 实测 `/request-logs` 报了 1 处，复核发现是**假阳性** | 探针加 `inHiddenSubtree()`（祖先链上有 `display:none`/`visibility:hidden`/`opacity:0` ⇒ 它的 0×0 是**应该的**） |

★ **M2 是本轮最该记的一条**：★ 「0×0 ⇒ 看不见」这个判据**默认是错的** ——
**看不见**有两种：**「本该看不见」**（隐藏子树）与**「本该看得见却塌了」**（真缺陷）。
★ 不区分 ⇒ 门第一天就会假红 ⇒ ★ **假红比假绿更费人**：假绿可以靠变异臂抓出来，假红会让人去「修」无辜的代码。

### 3.3 ★★★ 顺带补上那一族的老坑：基线没了 ≠ 通过

★ 仓内 `design-spacing-scale-runtime-baseline.json` 的普查条目记过：
「**基线缺失 ⇒ 读方退出码 0** ⇒ 消息说『不是通过』而**退出码说『通过』**」。

★ ⇒ 本工具**故意**加了两道门禁：
`baselineUsable`（基线存在且数值有限）+ `pagesMatchBaseline`（量到的页面集与基线一致）
⇒ 退出码 = `findings || regressions || !usable || !pagesMatch ? 1 : 0`
⇒ ⇒ ★ **「把基线删掉」不再是让门变绿的后门**。

## §4 修法：系统级兜底（missing token），不是逐处补丁

```css
/* 令牌（主题无关的令牌区） */
--kx-icon-size: 1em;

/* 兜底规则（浏览器表面区） */
:where(svg:not([width]):not([height])) {
  width: var(--kx-icon-size);
  height: var(--kx-icon-size);
}
```

★ ★★ **为什么用 `:where()`**：它的**特异性恒为 0** ⇒ 这是**兜底**语义 ⇒
**任何既有规则**（`.journey-trigger svg { width: 15px }` 之类）都压得住它
⇒ ⇒ ★★ **本条只影响当前是 0×0 的那些**，不改动任何已经正常的图标
（实测：修前 34 个图标里只有 3 个是 0×0；修后其余 31 个**尺寸一字未变**）。

★ **为什么值是 `1em`**：跟着所在文字的大小走 ⇒ 图标与它的标签同一视觉重量
（★ element-plus 自己的口径也是 `.el-icon svg { width: 1em; height: 1em }`）。
★ 主题无关 ⇒ 落在主题无关的令牌区。

## §9 通用式（已写入 `LESSONS.md` §477）

1. **★ 「看不见」有两种：「本该看不见」与「本该看得见却塌了」** ⇒ ★ 判「看不见」时**必须先排除隐藏子树**，
   否则门第一天就假红（★ 假红比假绿更费人：假绿靠变异臂抓，假红会让人去「修」无辜的代码）。
2. **★ 量具自己也要被量**：★ 本工具的第一版有**两处**缺陷，**一处**被自己的 `--selftest` 抓住
   （「任一边 > 0 就放过」漏判 `0×10`），**一处**被实测复核抓住（隐藏子树假阳性）。
3. **★ 判据宁可窄，不可宽**：「裸 element-plus 图标」实测 **174 处** ⇒ 绝大多数正常 ⇒ 不能当判据；
   ★ 能下判决的只有「**它渲染出来到底有没有尺寸**」。
4. **★ 找根因要落到【设计系统】那一层**：★ 本轮的病不是「某处 CSS 写漏了」，
   而是「**设计系统里没有『图标尺寸』这回事**」⇒ ⇒ 修法是**令牌 + 兜底规则**，不是逐处补丁。
5. **★ 兜底规则用 `:where()`**：特异性恒为 0 ⇒ **任何既有规则都压得住它** ⇒
   ★ 兜底只影响「本该兜住却没兜住」的 ⇒ ★ 改完其余图标尺寸**一字未变**（实测 31/31）。
6. **★ 「把基线删掉」不许是让门变绿的后门**：★ 基线不可用 / 页面集不匹配 ⇒ **必须判红**。
7. **★ 覆盖面的盲区要显式核对**：★ 既有运行时尺的页面清单**不含首页** ⇒
   ★ 而缺陷恰恰长在首页 ⇒ ★ **加新尺时要把「页面清单」当判据的一部分来核**。
8. **★ 变异臂要有一条「撤掉修法」**：★ A1（撤掉兜底规则）直接测「门能不能看见原来那个 bug」，
   ⇒ 比「注入一个新缺陷」更强（★ 后者只证明门认得新形状，前者证明门认得**这个**形状）。
9. **★ 负向臂要证明「豁免是活分支」**：A3 往隐藏子树里注入图标 ⇒ 门**不许**报红
   ⇒ ⇒ 否则那条豁免就是永不触发的死代码（★ 而死掉的豁免会让人误以为「隐藏图标是安全的」）。
10. **★ 「还原校验」要拿【还原后】与【原始】比**：★ 臂脚本若在 `apply()` **之后**才取 md5 ⇒ 拿到的是**变异后**的 md5
    ⇒ ⇒ 拿它跟「还原后」比 ⇒ **恒不相等** ⇒ ⇒ ★ 那行「md5 不一致」看着像失败，**其实它本来就不可能相等**
    ⇒ ⇒ ⇒ **还原校验形同虚设** ⇒ ★ 正确做法：从内存里的**原文**算 md5。
