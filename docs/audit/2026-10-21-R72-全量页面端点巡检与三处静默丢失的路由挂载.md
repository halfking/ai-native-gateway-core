## 七、新门：`internal/routemount`（把「合并期静默丢失」变成可检事实）

- `internal/routemount/scan.go`：AST 扫描器。规则 =
  **「任何注册 HTTP 路由的函数，必须在非测试代码里有调用点」**。
  - 只收**非测试文件**里的候选（测试夹具的 `httptest` 注册不是生产接线）。
  - `main` / `init` 除外（运行时调用，不存在「调用点」）。
  - **调用点只在 `_test.go` 里** ⇒ 同样算孤儿（`go test` 里挂载 ≠ 生产挂载）。
  - ★ **显式停用标记**：`routemount: disabled — <理由>`（必须带理由，≥8 字符；
    标记只在函数文档注释或函数体内注释里）。带标记者不算发现，但**每次运行都会打印出来**。
- `internal/routemount/scan_self_test.go`：扫描器自证（孤儿必报 / 有调用点不报 /
  只在测试里被调用仍报 / 非路由函数不报 / 带理由的标记被认 / **无理由的标记不算数**）。
- `internal/routemount/guard_test.go`：仓内闸门（扫全仓，非测试调用点缺失即红）。

### 10.1 key 到手后的执行通道（已实测备好，**未创建任何凭据**）

- 创建凭据：`POST /api/providers/{provider_id}/credentials`，体 `{"api_key":"…","label":"…"}`
  ⇒ 空体实测返回 `{"error":{"detail":"api_key required"}}`（**无副作用**，契约已确认）。

  xai=30、anthropic=2、openai=20、xiaomi=1（小米/mimo）—— base_url 与 protocol 均已配好。
- 发现模型：`POST /api/providers/{pid}/credentials/{cid}/refresh-models`（探上游 `/v1/models`）
  → `POST /api/providers/{pid}/credentials/{cid}/models`（把 raw model 绑到 canonical id）。

### 10.2 ★★ 但必须先说清一件事：**「贴个 key」不足以让点名模型可路由**（实测，非推理）

- 点名模型在 `provider_models` 里**只绑在两个 audit-local 假 provider**（2453/2454）上：
  `claude-sonnet-5-5 / gpt-5.6-luna / grok-4.6` → 2454；`deepseek-v4-flash / glm-5.2` → 2453。
- **真实 provider 侧**：`provider_models` 里 minimax/zhipu 各只有 **1 条**行，且都是 ASR
  （`minimax→asr-1.0`、`zhipu→glm-asr`）⇒ 聊天模型**一条都没有**
  ⇒ deepseek/xai/anthropic/openai/xiaomi **零行**。
- `models_canonical` 里 8 个点名模型**都在**（canonical 身份齐全，缺的是 provider 侧绑定）。
- ⇒ 所以「加 key ⇒ 点名模型可路由」这条链**缺一环**：真实 provider 必须**声明这些 raw model name**。
- ⇒ 且这些名字**本身很可能不是真实上游模型名**（它们是审计夹具里的名字）：
  真实 DeepSeek 是 `deepseek-chat`/`deepseek-reasoner`，xAI 是 `grok-4`/`grok-3`，
  Anthropic 是 `claude-sonnet-4-5` 一类 ⇒ **上游 `/v1/models` 里大概率查无此名**。
- ⇒ **key 到手后的正确做法**（而不是硬造绑定）：
  ① 加凭据 ⇒ ② `refresh-models` 让网关**自己发现上游真实模型清单** ⇒
  ③ 用**上游实际存在**的模型名跑 `ping` / `say OK.` 多轮并验证落库 ⇒
  ④ 把「用户点名模型 → 上游实际模型 / 上游无此名」逐条对照报出。
  ★ **不做的事**：不把 audit 夹具的假模型名硬绑到真实 provider 上
  （那会让路由指向一个上游不认的名字 ⇒ 必然失败，且会污染 `models_canonical` 的语义）。
