## §1 边界是怎么闭上的

### §1.1 工具（本仓早就有）

| 工具 | 位置 | 作用 |
|---|---|---|
| 逐路由渲染扫描 | `web/scripts/ui-sweep.mjs` | 71 个路由逐个开页，查 P0/P1/横向溢出/空壳 |
| dev 代理 | `web/vite.config.ts` `server.proxy` | `/api` → 网关；`/maintain-api` → `:8082` |
| 凭据注入 | `GATEWAY_DEV_AUTH_TOKEN` | 由**代理在服务端**注入 `Authorization: Bearer`（★ 浏览器侧不持凭据） |

### §1.2 ★ 必须先过的那道「激活旁路」（否则量具落空）

本机网关实例**从未完成激活** ⇒ 应用把**所有路由**重定向到 `/bootstrap`（激活向导）：

```
$ curl -s http://localhost:5793/api/system/bootstrap/status
{"activated":true,"registered":true,"admin_bootstrap_required":false}   # ← 开了旁路之后
```

⇒ **不开旁路时的扫描读数是「全部一致」的假象**：71 条路由**全都**报
「文本 344 字 / 可见块 1 / bodyWidth 1440 > rootWidth 1392」———
★ 那不是「每页都正常」，★ 是**每页都渲染了同一个坏掉的壳**。

> ★★ **通用式：全量扫描的读数「全部一模一样」时，先怀疑量具落空，再看结论。**
> ★★ 判据：读数的**方差**为 0 ⇒ 测的不是被测对象。⇒ 修好旁路后读数立刻分化
> （`/admin/subscription-tiers` 518 字 / `/examples` 2798 字 / …）。

### §1.3 复现命令（凭据只走环境变量，不落仓）

```bash
# ① 起 dev（代理指向本机网关 + 激活旁路 + 凭据注入）
GATEWAY_API_TARGET=http://127.0.0.1:8782 \
GATEWAY_ASSUME_ACTIVATED=1 \
GATEWAY_DEV_AUTH_TOKEN=<本机 super_admin JWT> \
  pnpm exec vite --port 5793 --strictPort

# ② 扫
BASE_URL=http://localhost:5793 GATEWAY_DEV_AUTH_TOKEN=<同上> \
  node scripts/ui-sweep.mjs --json reports/ui-sweep-postfix.json
```

> ★ 前置：本地网关的 admin 凭据由容器环境提供（`LLMGW_GATEWAY_ADMIN_USER` / `LLMGW_GATEWAY_ADMIN_PASSWORD`），
> 登录端点是 `POST /api/auth/token`（★ 验证码在未达失败阈值前**可选**），★ 成功即下发 HttpOnly `llmgw_session`。
> ★ ⚠ `vite.config.ts` 里那条「本地 8782 的 ADMIN_PASSWORD 为空 → 登录不可用」的注释**已过期**（实测可登录）。

## §5 复盘：这一轮真正学到的东西

★ **「读数全部一致」是量具落空的信号，不是「没有现象」的证据。**
★ 若只看「71 条路由 0 P0」就宣布「内页面全部正常」，那会是**一次假绿**——
★ 因为每一页当时渲染的都是同一个 `/bootstrap` 壳。
★ ⇒ 门禁的判据除了「有没有红」，还要问「**读数有没有分化**」。

★ **验证「补了内边距/描边」这类改动有没有撑破布局，唯一像样的办法是 A/B**：
★ 只看「修复后有没有 P0」是不够的（溢出未必被判成 P0），
★ 要**逐路由对拍修复前后的 `bodyWidth`/`rootWidth`/`textLen`**。
