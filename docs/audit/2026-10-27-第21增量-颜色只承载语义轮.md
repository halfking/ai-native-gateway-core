## 1. 为什么是这一轮

### 1.1 病：颜色在撒谎

仓内明文：

- `DESIGN.md` §视觉世界：「状态用最小的颜色量表达、**每个元素都承担信息职责**」
- impeccable `skill/reference/colorize.md`：
  「**Decoration without a relationship to hierarchy, state, content, or the visual world is not a color strategy.**」
  「**Let the strongest color own a deliberate region or role instead of scattering tiny accents.**」
- impeccable `skill/reference/operate.md`：
  「Accent color used for primary actions, current selection, and **state indicators** only, **not decoration**.」

而真仓 `web/src/components/LiveRequestStreamV2.vue` 的 CSS **注释自己承认了**：

```css
/* 2026-07-24: 视觉分组 - 让相邻的功能簇有清晰的区隔 */
/* 2026-07-24: 不同功能簇使用不同色调做软区分 */
.control-group.control-group--mode {
  background: color-mix(in srgb, var(--success) 14%, var(--bg-subtle));
}
/* 2026-07-24: 多维过滤器使用警告色，与维度/模式/请求类型组区分。 */
.filter-group {
  background: color-mix(in srgb, var(--warning) 18%, var(--bg-subtle));
```

⇒ **选色的理由是「跟旁边不一样」，不是「这是什么状态」。**

| 分组 | 被涂的颜色 | 用户会读成 |
|---|---|---|
| 按处理队列 / 按凭据 / 按供应商 / 按模型 | `--accent` 蓝 | 「这是主色区域」（它不是） |
| **小 / 大**（显示模式切换） | **`--success` 绿** | 「模式成功了」（它不是成功） |
| 业务 / 探测 | `--accent` 蓝 | 同上 |
| **筛选**（筛选控件组） | **`--warning` 橙** | 「筛选出问题了」（它不是警告） |

⇒ 截图取证见 `§7`。浅色主题下工具栏一排四组分别是**蓝 / 绿 / 蓝 / 橙** —— 一眼看过去像「有三个不同状态」，实际一个状态都没有。

### 1.2 选主题时排除的两条路（不要重试）

| 候选 | 排除理由（实测） |
|---|---|
| **空容器**（有面无内容） | 运行时探针在 9 个页面上量得 **0 个** ⇒ 该族不存在 |
| **同屏字面重复句** | 大头是**表格数据值**（`/models`：`active`×53、`unknown`×21、`multimodal`×20）⇒ 那不是冗余文案，是数据 ⇒ 该判据会大量假阳性 |

⇒ 顺带发现一个**真实但判不准**的现象：落地页 `/` 的实时请求流 tab 上，
`dashboard.liveStream.emptyConnecting`（「正在连接实时流，连接后**自动加载**…」）与
`dashboard.liveStream.queueStreamConnecting`（「正在连接实时流，连接后**本区数据自动刷新**…」）
是**同屏近义重复**（不是字面重复 ⇒ 探针抓不到）⇒ 登记为遗留项（见 `§9`）。

## 2. 判据（唯一实现：`web/src/design/semanticColor.ts`）

### 2.1 一条判据

> **承载「一组控件」的容器，底色/边框色必须中性。**
> —— 颜色预算属于「被选中的那一个」自己；容器只是「分组」，不是「状态」。

### 2.2 形态（穷举）

| 维度 | 形态 | 计数 |
|---|---|---|
| **控件组容器** | 直接子元素里有 ≥2 个**可交互控件** | 标签 11 种（`button` / `el-button` / `el-radio` / `el-radio-button` / `el-checkbox` / `el-checkbox-button` / `el-segmented` / `el-switch` / `el-tab-pane` / `input` / `a`）+ 语义角色 8 种（`button` / `tab` / `radio` / `switch` / `checkbox` / `menuitem` / `menuitemradio` / `option`） |
| **着色属性** | `background` / `background-color` / `border` / `border-color` / `border-top` / `border-bottom` / `border-left` / `border-right` / `border-block` / `border-inline` / `border-*-color` ×4 | 14 种 |
| **裸颜色令牌** | `--accent` `--primary` `--success` `--warning` `--danger` `--error` `--info`（含 `--kx-` 别名） | 7 类 |

★ **不含** `outline` / `box-shadow` / `color`：
- `outline` = **焦点环**（键盘可达性），是「状态指示」的正当用法；
- `color` = 文字色，不是底色（底色是「这块区域处于某状态」的主战场）。

★ **语义底色令牌不算「现场混入」**：`--success-bg` / `--warning-bd` / `--danger-bg` / `--accent-soft` 等
（`src/style.css` 的「语义: 状态色 + 透明背景」段）**正是本门要引导写法使用的通道**。

### 2.3 豁免

| 豁免 | 判据（形状，不是白名单） | 实测命中 |
|---|---|---|
| ① **状态载体** | 容器**自身**带状态词（静态类名或 `:class` 动态绑定键命中 `active` / `selected` / `error` / `danger` / `warning` / `success` / `loading` / `disabled` / `checked` / `current` / `failed` / `invalid`）⇒ 它在表达自己的状态 | **6** |
| ② **登记豁免** | 人工判定 + witness（指向事实源） | **2** |

★ 豁免 ① 的 6 处（逐条看过）：

| 位置 | 声明 | 为什么合法 |
|---|---|---|
| `components/detail/SessionTurnsSyncPane.vue:584/585` `.turn-card.active` | `border-color` / `background` ← `--accent` | 卡片**自己**就是「被选中的那一项」⇒ 主色 = 当前选择（`operate.md` 允许） |
| `components/live-topology/ClientRequestPanel.vue:304` `.cp__row.is-active` | `border-color` ← `--kx-primary` | 同上 |
| `components/live-topology/ProviderResponsePanel.vue:214` `.pp__row.is-active` | `border-color` ← `--kx-primary` | 同上 |

★ 豁免 ② 的 2 条（`web/scripts/design-semantic-color-exemptions.json`）：

| 位置 | 颜色 | witness |
|---|---|---|
| `views/FreePoolView.vue` `.verification-code-box` | 绿 | 模板 `v-if="m.verificationCode"` ⇒ **容器在场即是状态**（验证码已生成） |
| `views/SanitizeRulesView.vue` `.rollback-confirm` | 橙 | 模板 `v-if="rollbackOpen"` + 组内 `.btn.danger` ⇒ 破坏性操作的**警示态** |

⇒ ★ **没有用「条件渲染 ⇒ 豁免」这种形状豁免** —— 那会太松（任何 `v-if` 容器都被放行）；
本轮把它做成**登记豁免 + witness**，witness 指到 `v-if` 那一行。

## 6. ★ 本轮抓到的真缺陷（都不是本轮引入的）

### 6.1 ★★★ 运行时尺第一版把「有没有面」当成了「什么颜色」

第一版判「同父的控件组容器背景色必须一致」⇒ 实跑 `/routing-v2` 报出：

```
✘ /routing-v2 [light] 同父分组容器配色不一致：seg-tabs(rgb(234,240,255)) ≠ nav-chips(transparent)
```

逐条判：`.seg-tabs` 是**分段控件**（本来就是一条带轨道的面），`.nav-chips` 是**链接行**（本来就没有面）
⇒ 两者背景不同是**形态差异**，不是「颜色在做区分」⇒ **假红**。

★ 修法：判据收窄成「**只比对不透明的背景**」（`transparent` = 没有面 ⇒ 不参与）。
★ 这也印证了「**门红 ≠ 门对**」—— 红是待判的线索，不是判决。

### 6.2 ★★★ 变异臂第一版：靶点落在**死 CSS** 上

第一版臂注入 `.control-group.control-group--dimension { … }`，而那个修饰类在模板里**已被本轮删掉**
⇒ 那条 CSS 不落到任何元素上 ⇒ paints nothing ⇒ 门**不**判红是**对的** ⇒ 臂失败。

★ **臂没通过时，先问靶点，再问门**（§419「三臂全绿时先问靶点」的镜像版）。
⇒ 重做后的臂同时注入**模板 + CSS**，让着色真的落到元素上；并补一条**阴性臂**（死 CSS ⇒ rc=0）。

### 6.3 ★★ 豁免簿的路径口径与门不一致 ⇒ 一条都命不中

豁免簿写 `src/views/FreePoolView.vue`，而门里的 `file` 是**相对 `web/src`** 的 `views/FreePoolView.vue`
⇒ 读数显示「登记豁免 0」⇒ 看起来像「没有需要豁免的」，实际是**路径口径不一致**。
★ 这类「读数为 0 但含义不是 0」的问题，只能靠**把读数的含义写进指标名**来防。

### 6.4 ★★ 自证里我把「文件计数」当成了「行号」

变异臂的输出断言写成 `/LiveRequestStreamV2\.vue\s+\((\d+)\)/` ⇒ 抓到的是 `--list` 输出里的
`LiveRequestStreamV2.vue  (1)` —— 那个 `(1)` 是**文件内命中数**，不是行号
⇒ **断言恒真**（第一次跑就「通过」了）⇒ 改成 `/^\s+(\d+)\s+(\.[^\n]*)$/m` 后才真的在验行号
（实测命中行 687）。

★ 这就是 §419「断言恒真比恒假更隐蔽」的又一次现场复现。
