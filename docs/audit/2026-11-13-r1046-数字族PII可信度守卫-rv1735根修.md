## §三 根因定案

**「形状像 PII」≠「是 PII」，且规则语义有三层载体，修复只落在其中一层：**

| 载体 | bank_card 形态 | 生产是否生效 |
|---|---|---|
| `configs/sensitive_patterns.yaml` | r1039 修后（IIN+长度） | 仅空库种子，不覆盖已有快照 |
| 内置 fallback（detector.go） | 另一套宽松形状（`4\d{12,15}` 13-16 位，无 Luhn） | 无快照无 YAML 时 |
| **DB 规则快照血统（v1→v2）** | **r1039 修前旧正则（任意 16-19 位）** | **是（sanitize_rule_head→v2）** |

与 §694「视图基线以最后一个改它的迁移为准」、r1043「同一语义多载体」同族——**修了 YAML 不等于修了生产**。

## §四 修复（引擎级 ⇒ 对已发布快照 v2 即刻生效，不动 DB）

`security/sanitize/r1046_credit_card_credibility.go`，接入点＝`detector.go` 匹配循环（与 r1042 git-remote
豁免、r1043 标记免疫同层），对**所有规则来源**（fallback / YAML / 快照）同口径：

1. **credit_card**：`credibleCardCandidate` —— 剥分隔符后需 ①纯数字 ②长度 15-19
   ③IIN 前缀族（Visa 4 / MC 51-55 / AmEx 34,37→恰 15 / Discover 6011,65 / UnionPay 62 / JCB 35→16-19）
   ④**Luhn 校验和通过**。
2. **id_card**：`credibleIDCardCandidate` —— 恰 18 位 + GB/T 2260 省级前缀表 + 真实出生日期
   （1800-2099，含闰二月）；**刻意不做 MOD 11-2 校验码校验**（匿名化改码的结构合法 ID 继续遮蔽，
   隐私面合理默认——与快照 pii.id_card 的世纪约束同宽）。
3. **phone / id_card / credit_card 共同**：`standaloneDigitRun` 嵌入豁免 —— 匹配片段任一侧紧贴数字
   ⇒ 是更长数字串的子串 ⇒ 豁免（对带 `\b` 的严格规则是恒真空操作，只收掉 legacy 无边界规则的子串命中）。
   真手机号/身份证/卡号被数字直接粘住可忽略，Chrome 命令行/时间戳/字节数互相粘连是常态。

**取舍（写死）**：不以已知 IIN 开头 / 长度不符 / Luhn 不过 / 无日期结构的数字串**不再**被判为 PII——
时间戳、纳秒 tick、Chrome 进程参数 ID、字节数、流水号全部出局（550 例误遮蔽的全部来源）；
真值（含四位分组形态、X 校验位身份证、19 位 UnionPay）钉测钉住不放宽。自定义规则若把
type=credit_card 用于内部固定格式账号会被一并收窄——内部号请用 custom/account 类型承载。
