## §二 本轮修复（P1×1 + P2×1 + 钉桩×3 + 测试×6）

### F1（P2）Gemini stop_reason 透传修复 — anthropic A#2 同款三步法

- **实锤**：Gemini 流式终止原因在原实现下被 `mapGeminiFinishReason`（parse_gemini_stream.go:265）单向折叠为 OpenAI 归一化值：
  - RECITATION / SAFETY / BLOCKLIST / PROHIBITED_CONTENT / SPII → `content_filter`
  - MALFORMED_FUNCTION_CALL → `tool_calls`
  - 后果：Gemini→Gemini 直通时，wire 上只能产出"content_filter / tool_calls"等无差别值，丢失 Gemini 客户端识别具体阻断原因的能力。Anthropic A#2（audit-r2 2026-09-08）已用同样的"原生 StopReason 优先"模式修复 Anthropic→Anthropic 透传（stream.go:1038-1044），Gemini 一直没接。
- **修法（三步）**：
  1. **parse 填原生槽**：`parse_gemini_stream.go:228-232` 在 `mapGeminiFinishReason` 之前先 `chunk.StopReason = cand.FinishReason`，与 audit-r2 A#2 注释同款；
  2. **serialize 优先原生**：`stream.go` SerializeGemini 当 `SourceProtocol == ProtocolGeminiGenerate && StopReason != ""` 时透传原生值，否则走 `mapOpenAIFinishReasonToGemini(FinishReason)` 跨协议路径；
  3. **SourceProtocol 守卫**：防 Anthropic→Gemini 跨协议时把 anthropic 原生值（end_turn 等）泄漏到 Gemini 客户端（Gemini 不识别 end_turn 会拒收）。
- **钉桩**：`internal/ir/gemini_stream_test.go` 新增 3 测试：
  - `TestParseGeminiStreamChunk_StopReasonNativePassthrough`：5 原生值双面覆盖（StopReason 原生 + FinishReason 归一化）
  - `TestSerializeGemini_StopReasonNativePassthrough`：2 有损归一化项（RECITATION 不被折叠为 SAFETY；MALFORMED_FUNCTION_CALL 不被折叠为 STOP）+ 反向断言禁值不出现
  - `TestSerializeGemini_StopReasonSourceProtocolGuard`：Anthropic→Gemini 路径，end_turn 不出现在 wire 上，回退到 STOP
  - `TestSerializeGemini_CrossProtocolStillMapsFinishReason`：OpenAI→Gemini 路径回归，stop→STOP 不被打破
  - 既有 `TestParseGeminiStreamChunk_FinishReasons` 扩展：每案新增 StopReason 原生值断言

### F2（P1）usage_facts 按日分区函数 + ensureSpecs 接线 — 迁移 750

- **实锤**：R67 §四 P2 登记项，R66 48h §二 2.3 复核（"usage_facts 仅 DEFAULT 单分区 + 4 个二级索引全部非 occurred_at 前导；无分区函数则 partition pruning 不可用"）。R67 749 仅补索引，本轮 750 补分区函数与 24h tick 接线。
- **DEFAULT 共存设计**：PG 17 允许 DEFAULT 分区与具体 RANGE 分区共存（scratch 真库验证），具体 RANGE 优先匹配 + 越界落 DEFAULT + WHERE 范围查询仅扫命中分区。**不脱附 DEFAULT**——保历史数据可见、避免 DETACH PARTITION 大锁 + 行重路由复杂度；TTL 由 owner 拍板后另立迁移处理（旧 DEFAULT 数据按存储策略 v2.1 表 5 推算 7-90 天区间）。
- **三臂投递（744/745/746/749 先例）**：
  1. **canonical SQL**（`sql/migrations/startup/750_usage_facts_daily_partition.sql`）：`ensure_usage_facts_daily_partition(p_date DATE)` 函数 + 首次预建 `current_date` + `current_date + 1`；
  2. **down SQL**：`DROP FUNCTION IF EXISTS ensure_usage_facts_daily_partition(DATE)`（不删已建日分区，无应用查询方依赖）；
  3. **Go ensure**（`db/db.go` `ensureUsageFactsDailyPartition`）：先 SELECT 调用（autocommit，不经单事务）+ stamp 750 号章；
- **partition_manager 接线**（`bg/partition_manager.go`）：
  - archiveSpec 新增 `partitionUnit string` 字段（"" / "month" 走 `AddDate(0, offset, 0)` 月分区历史约定；"day" 走 `AddDate(0, 0, offset)` 日分区，R68 接入）；
  - ensureNextMonthPartitions 分支按 partitionUnit 派生 targetBoundary + dateLabel，同源 Asia/Shanghai 日历钉扎（防 UTC 会话在 +08 0-8h 把次日误建为今日，与 687/694 月分区钉扎同源）；
  - ensureSpecs 加 `ensure_usage_facts_daily_partition`，argExpr="$1::date" partitionUnit="day"；
- **scratch PG17 四通道实证**（`ai-native-postgres` 容器端口 15433，临时库 scratch_r68）：
  1. **分区创建**：537 + 749 + 750 顺序应用，3 分区同存（usage_facts_default + usage_facts_20260926 + usage_facts_20260927）；
  2. **DEFAULT 共存**：pg_inherits 查询确认 usage_facts_default 仍挂；
  3. **partition pruning**：EXPLAIN 对今日/历史日/1小时近窗三形态分别"Subplans Removed: 2"，新索引 `usage_facts_20260926_occurred_at_idx` 走今日单分区（0.016ms），`usage_facts_default_occurred_at_idx` 走历史单分区；
  4. **INSERT 路由**：今日 timestamp→今日分区（旧日 2020-01-01→DEFAULT），函数二次调用 NOTICE "relation already exists, skipping" 幂等；
- **测试**：
  - `bg/partition_manager_test.go` `TestEnsureSpecsCoversAllPartitionedTables`：expected map 加 `ensure_usage_facts_daily_partition: false // Migration 750`；
  - `db/db_750_ensure_realdb_test.go` 新增（TEST_DATABASE_URL 门控）：5 钉桩（首次 ensure 创建今日/次日+DEFAULT 仍挂、二次 ensure 幂等分区数不变、schema_migrations 盖 750 号章）
