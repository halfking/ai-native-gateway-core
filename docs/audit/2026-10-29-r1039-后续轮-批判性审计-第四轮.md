## 3. ★★ 本轮最值钱的一处发现：**静态自检判绿，行为是坏的**

### 3.1 形态

第三轮把共享部署库的 `lock.sh` 的 flock 分支修好之后，本轮按纪律先写了一个
**静态自检**（grep 有没有裸的 `exec {VAR}<>`、`bash -n` 过不过）再落盘。
静态自检**判绿**。

★☆ 但真跑起来是：

```
/tmp/deploy-lib-patched/lock.sh: line 160: exec: 200: not found
```

### 3.2 真因（★ 词法分析先于参数展开）

补丁里那行是：

```bash
eval "exec \${fixed}<>\"\${path}\""     # ← 错
```

★☆ **bash 的词法分析先于参数展开** ⇒ `${fixed}` 在 eval 里被切成
「**命令名** `${fixed}`」＋「重定向 `<>`」⇒ ⇒ `exec` 去找一个叫 `200` 的**命令**
⇒ ⇒ `exec: 200: not found`。
⇒ ★☆ 正确的形状必须是 `exec 200<>file`（**数字紧贴重定向符**）⇒ ⇒ 那个数字必须是
**字面量** ⇒ ⇒ **fd 号必须在 eval 之前就展开掉**：

```bash
eval "exec ${fixed}<>\"\${path}\""       # ← 对：${fixed} 在【外层双引号】里就展开
```

### 3.3 ⇒ 由此得到的两条纪律

1. ★★ **静态判据（grep / `bash -n`）对「fd 分配」这一族是恒绿的** ⇒
   ⇒ **判据必须能【跑起来】才算数** ⇒ ⇒ 落盘前的自检里必须有**行为自检**
   （本轮据此给补丁器加了 4 条行为判据：flock 分支真的拿到锁 / 持有者元数据真的写进去了 /
   目录形态干净 rc=75 且不撞致命路径 / 第二个持有者拿不到）。
2. ★★ **「脚本能解析」与「脚本按你要的方式执行」是两件事** ⇒ ⇒ 门要验**行为**，
   不是验**形状**。（★ 同族：`bash -n` 也只查语法，查不出 `exec` 把数字当命令名。）

### 3.4 ★★ 更一般的教训：**eval 是「先展开还是先切词」的陷阱**

★☆ 只要用 `eval` 拼一条**要重新解析**的命令，**拼进去的常量必须在外层就变成字面量**；
凡是「拼进去再展开」的量（`${var}`），都会在 eval 的词法阶段变成**命令名**。
⇒ 判据：★ **凡是 eval 里出现「重定向 + 数字」这种形状，那个数字不能在 eval 里展开。**

### A.1 新增 fd 分配原语（插在 `lock_ensure_local_dir` 之后）

```bash
LOCK_FD_LOCAL=200
LOCK_FD_BUILD=201
LOCK_FD_PROBE=202

lock_bash_ge() {
  [[ -n "${BASH_VERSINFO[0]:-}" ]] || return 1
  (( BASH_VERSINFO[0] > $1 )) && return 0
  (( BASH_VERSINFO[0] == $1 && BASH_VERSINFO[1] >= $2 ))
}

lock_open_fd() {
  local var="$1" fixed="$2" path="$3"
  if lock_bash_ge 4 1; then
    eval "exec {${var}}<>\"\${path}\"" || return 1
  else
    eval "${var}=\${fixed}"
    # ★★ fd 号必须在 eval **之前**就变成字面数字（★ 见 §3.2）
    eval "exec ${fixed}<>\"\${path}\"" || return 1
  fi
  return 0
}
```

★ ★★ **`exec ${fixed}<>` 里的 `${fixed}` 必须在【外层双引号】里就展开**（★ 不是 `\${fixed}`）
