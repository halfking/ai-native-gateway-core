## §4 期望集反解的三个坑（★ 全部本轮真踩过）

### §4.1 坑一：注释里也有 `CREATE INDEX`

★ 迁移文件的说明段里大量出现 `CREATE INDEX` 字样 ⇒ ★ **必须先剥 `--` 行注释再解析**
⇒ ★★ **否则期望集会被说明文字污染 ⇒ 几百条假缺口。**

### §4.2 坑二：中间产物索引（★ 判据必须是【结构】不是【名字】）

★ 迁移 902 建 `stats_event_dedup_pkey_include_tmp`（★ `CREATE INDEX CONCURRENTLY`），
★★ **紧接着** `ALTER TABLE … ADD CONSTRAINT … USING INDEX <它>` ⇒ ★★ PG 把它**改名**成
`stats_event_dedup_pkey` ⇒ ⇒ ★★ **`_tmp` 这个名字在库里【根本不存在】**。

⇒ ★★★ **判据不是「名字带 `_tmp`」，★ 而是【同一个文件里它是否被 `USING INDEX` 引用】**
⇒ ⇒ ★★ **结构判据 ⇒ ★ 改名规则变了也不会被骗。**

### §4.3 坑三：后来的迁移会删掉早期的索引

★ 全仓 581 份启动迁移 ⇒ ★ 建出 **886** 个索引 ⇒ ★ 另有 **93** 个 `DROP INDEX`
⇒ ★★ 其中 **34** 个是「建过又删掉」⇒ ⇒ ★★ **期望集必须是【建了 ∧ 没被删】的差集**
⇒ ⇒ ★★ 否则 34 条永远是假缺口。

★ ★★ **反解口径（★ 工具与门各写一遍、★ 互证）**：
`881`… 精确读数：**581 迁移文件 → 886 建出 → 减 1 中间产物 → 减 34 建了又删 ⇒ 852 期望**。

### §4.4 ★★ 第四个坑（本轮第一版工具自己踩的，★ 写在最前面）

★★★ ★ **PG 17 的 `pg_get_indexdef()` 会【换行】**（★ 长的索引表达式被 pretty-print 折行）
⇒ ★★ 直接 dump 出来的 TSV 里混进**残行**（★ 实测：14 行字段数 ≠ 正常值）
⇒ ⇒ ★★ **任何行式 TSV 消费者都会静默读错** ⇒ ⇒ ★★ 所以采集 SQL 里
★★ **每个文本字段都被 `replace(replace(…, E'\n',' '), E'\t',' ')` 折成单行**。

⇒ ★★★ **通用式：★★ 「量具自己坏了 ⇒ 后面所有读数都是假的」**
⇒ ★★ 所以本轮把「坏行必被拒」写成了一道**门**（★ `TestDbObjectCensusRejectsMalformedRows`）。

### §4.5 ★★ 第五个坑（★ 同族：★ 靠名字前缀判「表在不在」）

★ 第一版工具用「有没有 `<table>_` 前缀的关系」判分区父表是否存在

## §7 诚实边界（★ 八条）

1. ★★ **对生产的写入 = 0**：★ 全程只读 `SELECT` ＋ `EXPLAIN`（★ **不带 ANALYZE** ⇒ 不执行）
   ＋ `pg_class`/`pg_index`/`pg_inherits`/`pg_extension` 元数据查询。★ **没有** `CREATE INDEX`、
   ★ **没有** `ANALYZE`、★ **没有**改任何配置。
2. ★★ **`EXPLAIN` 一律不带 ANALYZE**：★ ⇒ 计划形态可信，★ **但没有真实耗时**。
   ★ 本轮**未**在 211 上跑 `EXPLAIN ANALYZE`（★ 那会真扫 91,663 行 ＋ 128MB `shared_buffers`）。
3. ★★ **绝对耗时不可移植**：★ 「形态可移植、绝对值不可移植」（★ R156 轮的结论）
   ⇒ ★ 本轮引用 R154 的 40.4 秒与仓内注释的 205,708 ms **都是别处的读数**，
   ★ ★★ **本轮没有在 211 上复测绝对值** ⇒ ★★ **211 上的绝对耗时尚未实测**。
4. ★★ **期望集是【反解】出来的**：★ ⇒ 它等于「仓内迁移声明的索引」，
   ★ **不等于**「产品真正需要的索引」⇒ ★★ **仓内没声明的索引，本台账看不见**。
5. ★★ **`retired` 判据是【表不在了】**：★ ⇒ 一个「表还在但索引被刻意删掉」的情形
   ⇒ ★★ 会被判成 `missing` ⇒ ★★ **可能高估缺口**（★ 43 条三环境同缺里 ★ **可能混着这类**）。
6. ★★ **底账是快照**：★ ⇒ 采集时刻之后的对象变化不在其中 ⇒ ★★ **会过期**
   ⇒ ★★ 所以每环境带 sha256 ⇒ ★★ 「快照过期」机器可判（★ 与 R160 同款做法）。
7. ★★ **分区子索引的父链靠 `pg_inherits`**：★ ⇒ ★ 若某环境的分区结构与仓内不同，
   ★ ⇒ 子索引数会不同（★ 本轮实测：252 与本地各 5~6 个子索引，★ 211 为 0）。
8. ★★ **本轮没有做端到端 API 验证**：★ ⇒ 「211 的 `?model=` 真的 500@30s」是
   ★★ **【计划形态 + 仓内明文硬依赖】推出的**，★ **不是本轮在 211 上打出来的 HTTP 实证**。
