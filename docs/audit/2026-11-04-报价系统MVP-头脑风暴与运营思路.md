## §1 本轮的三个判断（先说结论）

**判断一：报价系统 MVP 的三根数据柱子在网关侧全部是空的或极薄的，所以 MVP 不能做成"自动比价引擎"，必须做成"引导式工作台 + 数据置信门"。**

**判断二：冷启动不需要覆盖率。27 个真价足够开出第一张真报价单；系统上线验收 = 一张真实客户询价走完全链，而不是功能清单全勾。**（直接针对 salesdecorate「链路通了但没人走」的教训。）

**判断三："卖得怎样、利润如何"在 MVP 期间只能报漏斗（报价→审批→发送→成交）与报价毛利，不能报实收毛利——因为 `default` 租户按设计不计费、流水至今 0 行。这是边界不是缺陷，管理层看板必须显式标注。**

## §3 头脑风暴：运营思路

### 3.1 冷启动：先有一张真单，再有系统

salesdecorate 的教训（第 42 增量）：供给卡 7 张、报价单 1 张（还是 draft），加成率全部恰好 20.0000（全局默认值，不是算出来的）——**"链路通了但没人走"比"链路没通"更贵**。报价系统的上线验收不能是"六个功能都做了"，而是：

- **W0 上线前置动作（半天，人工）**：把 27 个真价行登记进供给池（补容量/SLA/有效期）；红线数值定值；找**一个真实客户询价**（哪怕是最友好的那个）建需求卡。第一张单走完 → 系统才算上线。
- **预填率目标**：销售从"选模型"到"可发送的报价单"≤ 5 次点击。成本分解、毛利测算、红线判定、客户版渲染全部自动；销售只填**客户、量、折扣意向**三件事。
- **"能卖什么"清单 = 可信供给清单**：默认只展示 C3 可信档的行。销售看到的每一行都必须是**可报的**——把"不知道进价"的行挡在工作台之外，而不是让销售撞上再退回。

### 3.2 三条角色动线（对应骨架的系统目标）

**销售的一天**：新建/领取需求卡（客户、场景、预估月用量、预算、决策窗口）→ 选模型包（只能从可信供给清单选）→ 看成本分解与毛利 → 触红线走审批 / 不触直接生成客户版链接 → 发给客户 → 回填结果（won/lost + 丢单原因：价格 / SLA / 无货 / 其他）。
**资源团队的一天**：维护供给池（真价行补容量/SLA/有效期；缺价行发起采购询价）→ **缺货清单 = 需求池里"报不出来"的模型**，天然就是采购优先级 → 有效期临期告警。
**管理层的一天**：漏斗四数（报价数 / 审批数 / 发送数 / 成交数）＋ 报价毛利分布 ＋ 丢单原因分布；"实收毛利"一栏显式标"待租户计费激活"（见 3.6）。

### 3.3 毛利红线与审批的现实版

- **红线是分层配置，不是全局数**：MVP 两维（模型档：标准/长尾 × 客户档：新客/续客），例如标准×新客 ≥30%、长尾×新客 ≥50%。**具体数值待裁决**（§8-1）；配置进 `settings_kv`，**红线本身的变更要审计**。
- **触线 ≠ 拒绝**：触线 = 必须走审批，审批通过照样发。红线管的是"不能**自动**发布"，不是"不能低价"——低价换战略客户的门要开着，只是要留痕。
- **审批链 MVP 一级**（super 或运营负责人），每步落审计。版本锁定见 3.5。

### 3.4 版本化与失效：价格漂移要传导到报价单上

- 报价单发出即**锁版本**：快照五价坐标系（P1–P5）＋ FX 汇率 ＋ C3 档位 ＋ 毛利。改价 = **新版本 + 重新审批**，原版本永久可追溯（骨架"版本化"原则的落地）。
- **FX 单源**：快照里的汇率必须复用 `CNYToUSDFX`（与 AF-1 毛利口径同源），**工作台不得自算第二把汇率**——否则"报价毛利"与"对账毛利"从第一天就分叉。
- **成本漂移提醒**：上游成本变动超过阈值（建议 10%，待裁决）⇒ 未成交的活报价单标"成本已漂移，建议重报"。MVP 形态 = 提醒不自动撤（第 42 增量 §7"报价单自动失效"用途的最小版）。
- **有效期必填**：报价单默认 14 天有效（待裁决），到期未成交自动关单进历史。

### 3.5 内外隔离：渲染隔离，不是显示隐藏

- **客户版** = 服务端单独渲染模板，从版本快照**只取销售价列**——成本、毛利、供应商身份**物理不进响应体**（不是 CSS `display:none`，不是前端条件渲染）。
- **内控版**（含审批链与成本）仅内部角色可达；如外泄 = 毛利策略泄露，客户版页面带水印（报价单号 + 时间）。
- **分享链接**：128bit token、库存 hash、默认 14 天 TTL、可撤销、每次访问记审计（时间/IP/UA）。只读、无登录（客户摩擦最小）——**这是新增公开面**，实施时须过公开面安全审查（与 §8-3 裁决联动）。
- **数据最小化**：客户联系方式仅销售本人 + super 可见；供应商联系人仅资源团队 + super 可见（骨架"权限审计"原则 + 第 42 增量"供应商联系人永不外泄"）。

### 3.6 实收毛利的诚实边界

`default` 租户跳过计费是**按设计的**（租户体系未启用前的保护门），生产流量全是 default ⇒ `credit_ledger_hot` 0 行。推论：

- MVP 的闭环验收 = **到"成交 + 开通完成"为止**；"用量 → 实收毛利"这段飞轮在租户计费激活之前是断的。
- 管理层看板 MVP 只报**报价毛利**（算术口径与 AF-1 相同：经 `CNYToUSDFX`），实收侧显式标"待激活"。**禁止**为了出数而给 default 租户放开计费——那是另一个独立裁决（影响全量生产请求）。
- 报价毛利 vs 实收毛利的对齐是 W3 任务，前置条件 = 真实租户开通 + 计费激活（见 §8-2）。

### 3.7 数据飞轮：报价系统的运营本质

```
供给池(有货+可信价) ──→ 报价(成本分解+毛利+红线) ──→ 客户版分享
        ↑                                                  │
        │                                          成交/丢单回填
        │                                                  ↓
 修正定价与红线 ←── 对账(报价毛利 vs 实收毛利) ←── 开通(租户+套餐+零售价) ←─┘
```

关键设计：**成交不改价**。报价成交后，零售价落库必须走人工审核（建租户 → 订套餐 → 写 `model_credit_rates`/`tenant_model_rates`），沿用"营销手工价禁自动回流"的既有裁决——报价系统提出价，既有通道落价。

## §4 MVP 功能逐条落法（对骨架六件）

| 骨架 | 落法 | MVP 边界 |
|---|---|---|
| 1 供给池 | `VIEW`（投影 `credential_model_bindings` 真价行 + 迁移 941 供应商七列）＋ `sales_supply_annotations` 登记表（容量/SLA/有效期/联系人，人工维护） | SLA/容量是**人工登记字段**，不自动测；后续可挂 selfcheck 数据 |
| 2 需求池 | `sales_demand_cards` 极简六字段（客户/场景/月用量/预算/窗口/状态） | 不建 CRM；一需求 → 多报价版本 |
| 3 报价工作台 | 成本分解（P3×量）→ 毛利测算 → 红线判定 → 审批/直发 → 版本锁定；三档一键报价（保守/标准/激进 = 成本×档位系数，档位待裁决） | 每行带 C3 置信标签；无可信成本不许出正式单 |
| 4 分享传播 | 客户版 token 链接（TTL/撤销/审计）＋ 内控版页面 ＋ 打印样式兜底 PDF | 服务端 PDF 生成放 W2 |
| 5 历史记录 | 版本不可变 ＋ 成交价回填 ＋ 审批链可查 ＋ 状态迁移审计 | 丢单原因作为一字段强制回填 |
| 6 权限审计 | sales / ops(资源) / super 三角色；全部状态迁移与链接访问落审计表 | 数据最小化见 3.5 |

## §5 数据模型 sketch（建议迁移号 942–948，实施轮定稿）

- `sales_demand_cards`（需求卡）
- `sales_supply_annotations`（供给登记面：binding 引用 + 容量/SLA/有效期/供应商联系人）
- `sales_quotes`（报价单头：客户、状态、当前版本指针）
- `sales_quote_versions`（**不可变**版本：五价坐标系 jsonb + FX + C3 档 + 毛利 + 有效期）
- `sales_quote_items`（行：模型、量、销售价、成本、毛利、置信档）
- `sales_quote_approvals`（审批链：触发原因/审批人/结论/耗时）
- `sales_quote_shares` ＋ `sales_quote_share_access_log`（token hash/TTL/撤销 + 访问审计）
- 状态机：`draft → pending_approval → approved → sent → won | lost | expired | superseded`

**RLS 决策（显式登记）**：本组表是**自营内部运营表**（主体是我们自己的销售组织），不是租户可见数据 ⇒ **不挂 `tenant_isolation_*` RLS**，与第 43 增量 §9 ④"每张新租户可见的表必须带策略"的适用域区分（同 940 市场三表的平台级定位）；角色闸在应用层。实施轮按该判据复核一遍。

**实施轮硬约束清单（沿用第 43 增量 §9）**：孤儿路由门（新页面一律挂 `/operations/*`）· i18n 8 语种全键 ＋ 双棘轮 · 间距尺 · 迁移六面登记 ＋ `docs/db-changelog.md` · `pg_policies` 台账口径核对。

## §6 治理红线接合表（全部继承，零修改）

| 既有裁决 | 在报价系统里的体现 |
|---|---|
| 对账只记账不改价 | 成交不自动写零售价；走人工审核落价 |
| NULL ≠ 0 | 无进价 ≠ 进价为 0；C3 四档显式承载 |
| 币种未知拒绝，不默认 USD | 成本行币种未知 ⇒ 不可信档，不出正式单 |
| C3 是门不是分 | 可信档是工作台准入条件 |
| 整组 withhold（同名多价） | 供给池投影沿用既有 withhold 口径，被 withhold 的不进可信清单 |
| 基准价不进金额计算 | P4 只做锚定参考展示，成本分解只用 P3 |
| 营销手工价禁自动回流 | 报价 → 零售价走既有导入通道 |
| FX 单源 | 报价快照用 `CNYToUSDFX`，禁第二把汇率 |

## §7 分期路线图

- **W0（上线前置，人工半天）**：27 真价行登记 + 容量/SLA/有效期补齐；红线数值定值；第一个真实需求卡建档。
- **W1（MVP）**：供给池（VIEW+登记表）/ 需求池 / 工作台（成本分解→毛利→红线审批→版本锁）/ 客户版链接（token+TTL+撤销+审计）。
- **W2**：服务端 PDF 导出；管理层漏斗看板；成本漂移失效提醒；**940 同步器**（salesdecorate `price_observation` → `market_price_reference`，按第 42 增量三步法设计）——同步器通了 P2 才活，三档报价才能按市场位势校准。
- **W3**：成交→开通联动（人工审核清单）；实收毛利对齐（前置 = 租户计费激活）；报价单自动失效 SLA。
- **明确不做（MVP）**：多级审批流、CRM 全套、自动定价算法、电子签章、移动端原生、跨仓写入 salesdecorate。

## §8 待裁决

1. **红线数值与分层**：两维四档的具体百分比（建议标准×新客 30%、长尾×新客 50% 起步，续客各降 5pp）。
2. **成交落价通道**：人工审核走既有导入（建议）vs 半自动提案单。
3. **分享链接是否公开无登录**（建议：是，带 TTL+撤销+访问审计；否则需客户账号体系，MVP 承不起）。
4. **供应商联系人可见角色**（建议：仅资源团队 + super）。
5. **三档报价系数**（建议 MVP 先 激进 1.3× / 标准 1.6× / 保守 2.0× 成本加成；P2 同步后按市场位势校准）。
6. **宿主仓**：网关 `/operations/*`（建议：钱与供给的 SSOT 都在这边，/operations 菜单与鉴权已就绪）vs salesdecorate。
7. **成本漂移阈值**（建议 10%）与报价默认有效期（建议 14 天）。
8. **default 租户计费激活的时机**（独立大裁决：影响全量生产请求的扣费；报价系统 W3 的前置条件，不阻塞 W1/W2）。
