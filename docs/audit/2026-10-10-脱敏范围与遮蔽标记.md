# 脱敏范围事故：地址被遮蔽 + 遮蔽标记不可辨识（2026-10-10）

## 一句话

`server_ip` / `internal_ip` 规则把**运维上下文**当成机密脱敏，把一条可复制执行的
命令改坏；同时客户端只看到一个裸的 `[REDACTED]`，无从判断遮掉的是什么。两件事
同源：把「哪些字节算敏感」和「遮蔽后如何自证」混成了一个没有出口的判定。

## 复现

用户报告的原始症状：

```
export https_proxy=http://[REDACTED]:7890 http_proxy=http://[REDACTED]:7890
```

`security/sanitize` 在输入侧直接命中这两处 `127.0.0.1`：

```
IN : export https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890
OUT: export https_proxy=http://{SENSITIVE:server_ip:1}:7890 http_proxy=http://{SENSITIVE:server_ip:2}:7890
```

生产配置（`configs/sensitive_patterns.yaml`，走 YAML 加载的 detector）同样命中，
且额外吃掉了 `address` 规则误伤的整段中文地址：

```
公司地址北京市海淀区西北旺东路10号院  ->  {SENSITIVE:custom:1}院
```

## 根因

两条 IP 规则同时承担了两个**性质不同**的职责，这是问题的真正来源：

| 职责 | 出现位置 | 地址该不该命中 |
|---|---|---|
| A. 替换请求文本中的敏感值 | 输入侧中间件、输出文本脱敏 | **不该**。地址是运维上下文，不是机密 |
| B. 判定模型是否在向外传输 | 输出侧 tool 参数防外传守卫 | **该**。公网地址 = 外传目的地 |

规则只有一条，作用域只有一个，于是 A 的误伤和 B 的必要性被绑死：
要么继续遮蔽 proxy 地址，要么拆掉防外传底线。154 生产事故
（`r1008_survival_fail_closed_regression_test.go`）之后加的
`Test154PublicIPToolCallStillBlocks` 锁的是 B，但它锁不住 A —— A 一直在
无谓地破坏运维命令，没人给它写判据。

标记的问题是另一件事：遮蔽侧只知道「这里被遮了」，不知道「遮的是什么」。
类型信息在检测阶段是存在的（`SensitiveFragment.Type`），在还原失败的兜底路径上
被丢掉了，于是退化成裸 `[REDACTED]`。

## 修复

### 1. 引入 `DetectionScope`，把两个职责拆开

`security/sanitize/detector.go`：

```go
type DetectionScope int

const (
    ScopeRedact DetectionScope = iota  // 默认：不含地址类规则
    ScopeEgress                         // 额外匹配地址类规则
)
```

- `Detect()` = `DetectScope(..., ScopeRedact)`，输入侧与输出文本脱敏走这条。
- `detectEgress()`（`output_sensitive.go`）显式请求 `ScopeEgress`，只有
  tool 参数防外传守卫用它。

分类按**类型**判定而不是给每条规则打标志，这样 YAML 加载的 detector 与内置
fallback 在这个决定上不会各自漂移 —— 两者共用 `scopedType()`。

净效果：地址退出脱敏范围；防外传底线原封不动，且今后任何一方调整都不会
静默地带动另一方。

### 2. 遮蔽标记带上类型

新增 `RedactionMarker(typ)`，产出 `[REDACTED:phone]` / `[REDACTED:secret]`。

类型名是**规则的名字**，不是它匹配到的值，因此不构成泄漏。类型解析不出来的
两处（`maskDegenerateMarkerSpans` 的退化回显、超长未闭合占位符尾巴）保持裸
`[REDACTED]` —— 那两个位置的字节从未被解析出类型，编一个就是猜测。

精确阶段（`sanitizer.go` 的 `PlaceholderPattern`）与容错阶段（loose）行为
不同：前者能拿到类型因而带类型，后者只做归一化不保留类型，因而是裸标记。

## 回归门

`security/sanitize/r1010_scope_split_test.go`，两个方向都有断言：

| 测试 | 锁住什么 |
|---|---|
| `TestAddressShapedTextIsNotRedacted` | 用户报告的那条命令 + 同族运维文本，fallback 与 configured 双跑 |
| `TestRealSecretsAreStillRedacted` | 「删掉 IP」不能被实现成「删掉一切」 |
| `TestScopeEgressStillBlocksPublicAddress` | 公网地址进 tool 参数仍然 fail-closed |
| `TestEgressGuardStillIgnoresPrivateAddresses` | r1008 的另一半：环回/私网不阻断 |
| `TestRedactionMarkerNamesTheType` | 标记带类型；未知类型回退裸标记 |

变异验证（三个方向各自都能被抓住）：

| 变异 | 结果 |
|---|---|
| 撤销 scope 拆分（egress == redact） | `TestAddressShaped*` 红 |
| 去掉类型（全部裸标记） | `TestRedactionMarkerNamesTheType` 红 |
| 防外传守卫改回普通 `Detect` | `TestScopeEgress*` + `Test154PublicIP*` 红 |

## 影响面

`security/sanitize`、`domains/streaming`、`proxy`、`settings`、
`plugin-runtime`、`domains/sessionaudit` 全绿。

被更新的既有断言，都是同一条契约的旧读数，不是放宽：

- `TestReplayedAssistantAndToolSecretsDoNotLeaveGateway` — 地址移出必遮列表，
  同时新增「地址必须原样通过」的反向断言。
- `TestOperationalRulesFromDefaultsAndProductionConfig` — 地址样本从「必遮」
  挪进「必须不变」清单，防止被悄悄改回去。
- `TestTwoGatewayRoundTrip` / `TestSanitizeHopSurvivesMarkerOnlyIntermediate` —
  这两个测的是**网关套网关的占位符传递**，不是脱敏范围。原本靠一个裸 host
  地址来铸造占位符；地址不再脱敏后改用凭据铸造，被测契约本身未变。
- `TestOutputSensitiveMasksNewValuesAndRestoresKnownValues` —
  `password=` / `username=` 仍遮蔽，`host=` 不再遮蔽。

## 未变的部分

- 手机号、身份证、邮箱、银行卡、密码、API key、JWT、云厂商 AK、Bearer、
  私钥块、连接串中的账号密码：全部照旧脱敏，且带类型标记。
- 防外传硬阻断（公网地址 + tool 参数）：照旧 fail-closed。
- r1008 事故的两条回归门：照旧通过。
