## 三、第一批：126 处怎么改的

### 3.1 方法：只替换「含破折号的那一段」

改写脚本对每条都带**严格断言**：

- 目标片段在该行**恰好出现一次**（`count != 1` 直接中止并打印原文）；
- 替换后的片段里**不再有破折号**（含 `\u2014` 转义形态）。

⇒ 好处：diff 一屏可逐条复核，**语义漂移面最小**（每条只动破折号附近那几个字）。

### 3.2 改写口径（承上一轮的表）

## 四、★★ 「桶读数 0」不等于「干净」

第一批改完、门报 0 之后，**手工**扫了一遍 `web-mobile/src/i18n/en-US.ts`：

```
产品文案里的 em-dash（未被判据命中）: 48
注释里的 em-dash（不是产品文案）      : 29
```

⇒ 门说干净，手工数出 48 处同一副骨架的破折号。根因在判据：

```js
const EM_DASH = /\p{L}\s*—\s*\p{L}/u   // ← 要求破折号左侧【紧邻一个字母】
```

⇒ 左侧是 `)` / `"` / `}` / `**` 的形态**全部漏判**，例如：

```
'Result truncated (the server returns at most 500 bindings) — the totals below are incomplete.'
                                                              ↑ 左侧是 ")" ⇒ 漏判
```

⇒ ⇒ ★★★★ **通用式：★ 「命中集合」是判据的函数，不是数据的性质** ——
★★ **门的读数为 0，不等于「没有违规」，只等于「没有命中这条判据」**。
★★ ⇒ **判据收窄时必须手工扫一遍数据**，否则「清零」是假的。

## 五、判据怎么放宽才不误伤（4 个版本，逐个量过）

| 版本 | 形态 | 问题（实测） |
|---|---|---|
| v0 原判据 | 左侧紧邻字母 | 漏 `)` / `"` / `}` / `**`（48 处） |
| v1 放宽收尾符 + lookbehind 排除数字结尾 | 左侧 = 字母 + 收尾符 | 漏「数字结尾」（`at 5000 — over-limit…`）与「右括号与前面的词**不相邻**」（`it at 0) — do not read`） |
| v2 只留字母 + 要求右侧两个 token | 左侧紧邻字母 | 漏「右侧单个词」（`Loading — retry.`）与「右侧以引号开头」（`— "enabled" here…`） |
| **v3 最终形态** | 见下 | — |

### v3 的三个条件（同时成立才算违规）

1. 破折号**左侧紧邻**一个「字母 / 数字 / 右括号 / 右花括号 / 引号 / 星号」
   —— ★ **不要求它与前面的词相邻**（`it at 0) — do not read` 也要抓住）；
2. 破折号**右侧是空格 + 一个以字母开头的词**（可带 `"` `'` `*` 开头）；
3. ★ **但右侧首 token 形如 `P99` / `L50`（字母+数字）⇒ 判作「区间标签」，放过**
   —— `P50 — P99` 是范围连接号，不是「两个分句」，不是 AI 腔。

### 为什么第 3 条必须要有

`P50 — P99` 在 UI 文案里是**合法的破折号用法**（范围连接号）。
没有这条豁免，判据会把合法写法判红 ⇒ 逼人把对的写法改坏。
⇒ 用「右侧首 token 形如 `P99`」来识别区间，是**启发式**（诚实边界见 §十）。

### ★ 改判据的纪律

- 每改一版，**重新量全仓 12 个桶**（本轮实测：只有 `web-mobile/en-US` 有命中，其余 11 个桶零新增）；
- **逐条复核新命中的原文**（本轮 46 + 11 = 57 条逐条看过）；
- ★ 量到 v1 与 v3 在同一批数据上命中数**完全相同**（180 行；「v1 命中而 v3 不命中」= 0）
  ⇒ 这个收窄**不损失任何真实命中**，只是挡掉区间误伤。
