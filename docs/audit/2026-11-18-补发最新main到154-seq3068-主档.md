⇒ 下一轮它必然假红。★ **通用式：同一族的判据要一次改到底**——

### 6.4 结构性修法（与 ⑦ 同构：基准＝发布单元/部署树，与场景无关）

| # | 新判据 | 覆盖的风险 |
|---|---|---|
| ① | **台账自洽**：`diff(上一版 base, 上一版 tag)` 文件数 == tag 记的 `files=` | tag 指错提交 / 记错文件数（seq 3067 的真错就属此类） |

| ③ | **内容超集**：新版相对上一版**没删任何文件**（`diff --name-status` 无 `D`） | 上一版交付过的内容被悄悄丢掉 |
| ④ | **可回滚**：上一版的**线上 release 目录仍在** | 「可回滚」只是文档里的说法 |
| ⑤ | **PI 域**：只作**报告**（上一版发布面内 PI 域改动几处） | — |

★ **退役的闸门不留在仓里当负债**：旧 `leak_of()`（按「并行车文件清单」判泄漏）**整段删除**，

★ **通用式（本轮最重要的一条）：把旧判据直接删掉 ＝ 把真错一起放过。**
假红的正确处置不是「删掉这条判据」，而是「**换成一条能覆盖同一风险、但基准正确的判据**」——
否则下一次「tag 指错提交」就会在新判据的盲区里溜过去（seq 3067 真吃过这个亏）。

### 6.5 量具自身的第三个坑（顺手记下）

- 首跑 3068 采集器时，**冻结树里跑的是旧版判据**：⑦ 的改造只在分支（提交 `7f34aae9f`），

## 八、通用式（本轮新增）

1. ★ **上游会在你的发版窗口里前进** ⇒ 「部署最新 main」是**持续收敛的动词**；
   判据 ＝ 「owner 说最新 main 时，main 是否还是发版那一刻的 main」（本轮补发即由此而来）。
2. ★ **同一族假红要一次改到底**：⑦ 改了、⑧ 留着 ⇒ 下一轮 ⑧ 必然假红 ⇒
   判据改造要**按「判据族」扫干净**，而不是按「这次报红的那一条」改。
3. ★ **把旧判据删掉 ＝ 把真错一起放过**：旧判据假红时，正确处置是**换成基准正确的新判据**，
   不是「这条不需要了」（否则新判据的盲区会吃掉下一个真错）。
4. ★ **退役的闸门不留在仓里当负债**：无消费者的判据函数**整段删**（`leak_of`）。
5. ★ **部署树工作区会被部署链自己改脏**：`VERSION` / `version.json` / `web/public/version.json` /
   `web/public/menu-config.json`（构建戳）四处 ⇒ 判据必须走 **git 对象**（`git show HEAD:path`），
   不能读工作区文件（否则每次部署后都会「莫名其妙多出 4 处改动」）。
6. ★ **隔离 worktree 里跑回归会缺 `.env.local`**（`REGRESS_EXIT=2`，口令只从**仓根** `.env.local` 读）
   ⇒ 要么在带凭据的树里跑，**要么核对那棵树的 `maestro/` 资产与发布树一致**（本轮：共享树 HEAD ＝
   `ef1578122`，`maestro/` 与发布树 **零差异**）。
7. ★ **证明「拦截器没拦」要三层齐**：规则侧（这条内容**确实**命中）+ 线上（**真的没被拦**）
   ＋ 仓内（**测试真的钉住了这个行为**）；缺第一层就退化成「规则根本没命中」，缺第三层就退化成「碰巧没拦」。
8. ★ **造流量 ≠ 造成功流量**：采集器用 `glm-4.5-flash` 造「在途」流量，而该模型在 154 上**候选面为空**
   ⇒ 那几笔请求**以 503 收尾** ⇒ 断言钉的是「**失败请求**的在途」⇒ 登记 L20（造流量改用 `auto`）。

## 十、L20 修复（造流量模型改 `auto`）＋ 全绿证据归档

### 10.1 问题回顾（为什么「造流量 ≠ 造成功流量」是证据质量问题）

- 采集器造流量写死 `glm-4.5-flash`；该模型在 154 上**候选面为空**（实测 `/v1/chat/completions` ⇒ **503 `no_candidates`**）
  ⇒ 那 4 笔「在途流量」**以 503 收尾** ⇒ 阶段树记录的是「**失败请求**的在途」；
- 断言仍然通过（阶段树确实记录了这些请求）⇒ **量具没错、结论没错**，但**证据偏弱**：
  它钉的是「失败请求也会出现在实时阶段树里」，而不是「**成功**请求的在途」。

### 10.2 修法（两处，都不是「换个字符串」）

1. **模型改 `auto`**（实测 200 真作答），并保留 `STAGE_TREE_TRAFFIC_MODEL` 覆盖口
   ⇒ 换机器/换模型面时**不必改脚本**（写死的模型是负债：它把「这台机上有没有候选面」焊进了量具）；
2. **采集器自报造流量实况**：每笔请求的 HTTP 码落文件，断言跑完后汇总打印，并写进 ⑫/⑬ 两行 verdict
   ⇒ **「造的是不是成功流量」从此在证据里看得见**，不再靠推断。

### 10.3 重跑结果（**15/15 全绿**，退出码 0）

- 断言轮 1：行为层 rc=0／设计层 **rc=2（量具失效：窗口内无在途请求）** ⇒ 采集器按「断言与造流量**成对**」纪律
  **再造一轮** ⇒ 断言轮 2 行为层 rc=0／设计层 rc=0；
- **造流量实况：模型 `auto` ⇒ HTTP 200 200 200 200**（4 笔全部成功流量）；
- ⑭ 临时密钥 id=237 已删（回读 **404** / 旧密钥 **401**）；⑮ 紧凑图例 `✓` 计数＝**0**、完整模式对照 ✓＝36。
