## 一、§11.6 EOF-without-DONE 翻转（修复质量 P1→P0）

### §11.6 stream.go:1150+ 处（a1b17b224）

- **问题**（事前）：2026-05 commit "treat eof_without_done after commit as benign upstream non-compliance" 把 HTTP 200 + committed SSE chunks + EOF（无 [DONE]）走 benign success 路径——审计 success=true、断路器静默、凭据健康不受影响。**§11.6 综合测试计划明令禁止**：HTTP 200 空响应或 SSE 无 [DONE] 不向客户端返回伪成功，必须切换或返回结构化错误。
- **修复**（主代理复核：✅ 路径闭合）：
  1. `outcome.Interrupted=true` + `Kind=errorsx.KindUpstreamDown` + `Reason="eof_without_done"`
  2. **wire 先 error envelope**（OpenAI 错误帧 `data: {"error":{"type":"upstream_incomplete","message":"upstream closed the stream without sending [DONE]","code":"eof_without_done"}}`），客户端 SDK 能 pattern-match 到失败
  3. **再合成 `data: [DONE]\n\n`** —— OpenAI 兼容解析器仍能 finalize（防止某些客户端 block forever）
  4. `Resumable=false`（已 commit 不可双发重复字节），`ChunkCount=chunkCount`（供 SQL 过滤 `chunk_count > 0 AND failure_detail_code='eof_without_done'`）
  5. `RecordStreamSynthesizedDone()` 指标仍触发（wire 上确实注入了合成 terminator）
- **钉桩**：`TestStreamChatWithPendingCapture_Section11_6_PseudoSuccessGuard`（a1b17b224: 钉 wire 顺序 + HTTP 200 不改写 + executor Kind + 没有 silent 200）
- **健康面**：未 commit 字节的 EOF 仍走既有 Resumable=true + ChunkCount=0 failover 路径（与 §11.6 兼容）
- **部署跟进**：真实供应商验收仍需在 154/245 上跑故障注入脚本（本机 mock 不模拟此协议违例），登记 R55 §遗留
