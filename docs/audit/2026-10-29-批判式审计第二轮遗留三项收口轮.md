### 1.3 ★★ 自我批判审计发现的两个真实缺陷（已修）

#### 缺陷 A：「域外不可达」只是一句注释登记，不是门

对拍域是**枚举出来的**，而 $5 的生产值域来自 `detectRequestModality`。
alternativesSQL 的 $5 块是**闭世界**：请求值落在三条臂之外 ⇒ 整个 AND 不成立
⇒ **建议列表静默变空**（不是 4xx、不是日志）。而 Go 判据 `ModalityAccepts` 的
default 臂对未知请求值判 `registered == requested || registered == "multimodal"`
⇒ 对 (multimodal, 未知值) 判 **true**。
⇒ **两边在域外语义相反**；域内一致（现有门锁着）≠ 域外一致。
⇒ 只要 detect 将来扩一个值域（例如为文档输入新增 "document"），**三道锁步门
全部照样绿**，而生产上该模态的建议列表会整条消失。

**修法**：新增 `TestAlternativesSQL_DetectModalityDomainClosed`，两条互补判据：
- ① **行为判据**：真实调用 `detectRequestModality`（不复制它的逻辑）跑 10 组
  代表性 body（空/坏 JSON/纯文本/Responses 纯文本/OpenAI 图/Anthropic 图/
  Gemini 图/音频/视频/混模），断言产出落在「alternativesSQL 有臂的请求值 ∪ 全放行值」内；
- ② **穷举判据**：detect 的**返回常量集合**（源码里全部 `return modalityX`）
  必须 ⊆ 允许集 ⇒ detect 新增一条返回路径（哪怕代表性 body 覆盖不到）也当场红。
  ①漏「形态」、②漏「路径」，两条合起来才是闭合。

**真文件变异臂**：给 `modality_detect.go` 加 `modalityDocument` 返回 ⇒ 门红且
点名 `"document"（modalityDocument）` ⇒ 还原 ⇒ md5 一致（a4792503…）。

#### 缺陷 B：对拍分母硬编码 ⇒「缩小分母 + 改判据 ⇒ 零漂移假绿」

实测（探针脚本）：把 video 从对拍域删掉、**同时**把 SQL 联合臂的 video 删掉
⇒ 对拍零漂移 ⇒ 门全绿，而生产上 video 请求的建议列表会静默变空。
⇒ 分母若写死，「改门」和「改判据」可以在同一次提交里合谋。

**修法**：登记侧对拍域改为**从事实源派生**——`models_canonical.modality` 的
CHECK 约束（迁移 451 及其后续修订，取仓内最后一份 `ADD CONSTRAINT` 定义）。
- 事实源**新增**值 ⇒ 门要求扩域（否则该值上的漂移检不出）；
- 事实源被**改小** ⇒ 门红（分母残缺，fail-closed）；
- 事实源**读不到** ⇒ 门红（不许退回硬编码域）。

**实现归属**：`tests/testutil/modality_value_domain.go`（仓内既有的共享测试辅助
包，与 §411「同一口径只能有一份实现」一致）—— provider 侧与 streaming 侧
**共用同一份派生**；函数自己向上查找仓根（provider 在一级子目录、streaming 在
两级 ⇒ 调用方各算各的根是静默失败源）。

**真文件变异臂**：改迁移 451 的 CHECK（去掉 'video' / 去掉 'multimodal'）⇒
两包的门都红并点名「事实源被改小了」；把迁移文件藏起来 ⇒ 门红（fail-closed）。

#### 附带修正：provider 侧门的「声明 > 事实」

provider 锁步门头注释一直写着「登记侧 = CHECK 值域 …/embedding」，而
`registeredSet` 里**独缺 embedding** ⇒ 声明 > 事实。已补齐（请求侧仍不含
embedding ⇒ 头部登记的 (multimodal, embedding) 分歧不在对拍域内，不受影响），
并给变异臂测试（262 行那处）同步同一登记域，避免「主测试域」与「变异臂域」分叉。

### 1.4 对拍域的事实依据

- **请求侧**：$5 生产值域 = findModelAlternatives 两个调用点——零候选臂
  `requestModality ← resolveCandidatesForRequest → detectRequestModality`
  （text/vision/audio/video）∪ 诊断臂 `mismatch.RequestedModality`（⊆ detect
  值域）∪ OmniFree（同样 detect）⇒ 值域 = {""} ∪ detect。对拍域比生产值域宽
  （multimodal/image 也纳入：三份表达在这两格逐格一致，属防御性冗余）。
- **登记侧**：DB CHECK 派生 = {text, vision, audio, video, multimodal, embedding} ∪ {""}。

  登记不改，与 provider 锁步门头的登记同族。

## 2. 遗留②：部署引擎三道身份闸的非生产 --via 实测

### 2.1 为什么还要做

第二轮修了两处部署脚本缺陷（§1.1 显式号被 git 覆盖 / §1.2 --via 转发前门缺失）
并加了**抽取式**行为门（9 断言/3 变异臂）——但「真实 --via 流程在链路上每一跳的
号值」从未被端到端跑过。§6 明说「上线时机由运维决定，任何变更都需先在非生产
验证引擎路径」。本轮补上这道**集成**验证。

### 2.2 隔离手段（本机零副作用）

- 部署树 = 临时目录里的**真引擎副本** + 假前端产物（T1 无 .git / T2 git 检出）；
- `ssh`/`scp` PATH 垫片拦截：记录完整远端命令后**在本机执行**（远端 = 另一个
  临时目录模拟目标机）；目标机语境 = 垫片再放 `uname`（报 Linux，越过 macOS
  本机守卫）与 `docker`（拒绝连接 ⇒ 引擎在身份闸之后、任何容器动作之前
  fail-closed 终止）；
- 锁钉进隔离 `LOCK_TMP_ROOT`；前端构建用引擎自带逃生舱 `DD_SKIP_WEB_BUILD=1`
  跳过，新鲜度门由假 dist（无 src 目录 ⇒ 判新鲜）真实通过。

### 2.4 harness 自身踩的坑（都修在 harness 里）

1. **ssh 垫片的环境泄漏**：第一版垫片把部署机全部 env 带进「远端」⇒
   `LLM_GATEWAY_ROOT` 泄漏 ⇒ 目标机的 `DD_REPO_ROOT/.git` 判定失真 ⇒
   B4/C3/M1/M2 四条断言集体假红。修法：垫片用 `env -i` 模拟真实 ssh（DD_*
   只靠命令行随行——这正是引擎转发清单的设计）。
2. **`$var` 紧跟全角括号**（第二轮 §1.4 第 3 条坑的现场复踩）：`$GIT_SHA）`
   在 UTF-8 locale 下把 `）` 并进变量名 ⇒ `未绑定的变量`。修法：全角括号前的
   `$var` 一律 `${var}`。
3. **变异靶点选错树**：M1 的变异落在 T2 而场景跑 T1 ⇒ 变异从未生效；M2 的
   断言用全等匹配漏了变异后合法产生的 `-dirty` 后缀。修法：mutate 显式传
   目标树；断言按前缀匹配并写明理由。
4. **恒真断言**（初稿 M6 拿同一个路径跟自己比 ⇒ 恒真）：改为「启动时记录 md5
   ⇒ 结束时比对」，并做了负控验证（基准改错 ⇒ 变红）。

## 6. 本轮的自伤与修法（★ 记下来给下一轮）

★ **变异还原用 `git checkout --` ⇒ 把同文件里自己的未提交改动一起还原了**
（本轮：alternativesSQL 的注释块被连带还原，md5 从 b11dcaed… 退回 443f1390…）。
⇒ 已手工复原（md5 校验一致）。
⇒ ★ **修法**：真文件变异臂的还原必须用 **cp 备份/还原**（或 `git stash push
单文件`——但本仓纪律禁 stash），**不许用 `git checkout --`**（它还原的是 HEAD，
不是「变异前的状态」）。
⇒ ★ **更稳的次序**：先把本文件的**全部**改动做完并记录 md5，再做变异臂；
还原后**必须比对 md5**（本轮正是靠 md5 才发现自伤）。
