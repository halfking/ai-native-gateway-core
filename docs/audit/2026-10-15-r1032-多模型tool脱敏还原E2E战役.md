## 二、缺陷一（r1032）：tool-only 空参数 Responses 流被 commit 门整流吞掉

- **现象**：claude-sonnet-5 responses 腿（/v1/responses 流式）200 + 只有
  `: keep-alive`，**零事件帧**（无 response.created）。本地复现最小请求
  63ms 速败同形。
- **根因链**（raw-logs 279e4627…）：
  1. claude-sonnet-5 在 vapeur 的 native-responses 能力行缺失/否定 →
     客户端 Responses 请求落到 **chat 上游腿**（api.vapeur.ai/v1/chat/
     completions），响应需经 `StreamOpenAIToResponsesSSE` 桥回 Responses SSE；
  2. 上游完整回 tool_calls（chatcmpl 帧：name=get_time、args=""、finish）；
  3. 客户端帧全部经 `wrapAttemptWriter` 的 **AttemptCommitGate（buffered
     默认开）**：`response.created`/`output_item.added`/`content_part.added`
     都是 **AttemptMetadata**（可丢弃、不触发 commit）；
  4. 该工具调用 arguments 为空串（`{}`/无参工具）→ 桥不发
     `function_call_arguments.delta`（ToolCall 类，会 commit）；
     `output_item.done`/`response.completed` 是 Terminal 类，但桥的
     `finishAttempt` 先问 `MayWriteTerminal()`——**未 commit 即 return**，
     终态帧根本不写给门；
  5. 结果：整条流在门 buffer 里从未 commit，客户端零字节，audit 记
     success=true、stream_chunks=1。带参数的调用不受影响（arguments.delta
     → ToolCall → commit），这就是 r1030b 该腿 PASS 而「无参首调用」全灭的
     差异。
- **修复**（`domains/streaming/stream_frame_classifier.go`）：
  `response.output_item.added` 按 item.type 分流——`function_call`/
  `custom_tool_call`/`local_shell_call` 判 **FrameClassToolCall**（与 chat
  方言的 tool_calls-delta、anthropic 的 tool_use content_block_start 判例对
  齐：工具 item 的宣告时刻就是模型对工具调用的 commit），其余 item 保持
  AttemptMetadata。
- **判据**：`domains/streaming/r1032_claude_chat_to_responses_repro_test.go`
  —— 真实捕获帧序列回放（隔离桥、断言 created/function_call/completed 全
  落网）+ 分类器双向钉子（tool item→ToolCall、message/reasoning item→
  Metadata）。变异：M1 撤分流→双红；M2 过宽（恒 ToolCall）→分类器反方向红。
  streaming 全包 152s 绿。

## 三、缺陷二（r1032d）：`USER=$USER` 形态把整条 tool lane 零 issues 阻断

- **现象**：grok-4.6 chat 腿多轮会话第 2+ 轮，上游参数帧完整（raw-logs
  9bd6ccf5/506f8a80：host=10.24.7.91 + 正确占位符），**客户端只收到工具名，
  arguments 被掏成 `delta:{}` 空壳**、finish 帧消失、[DONE] 在——多轮工具
  循环断裂。
- **取证路径**（可复用）：客户端 dump（harness DUMP_RAW）↔ raw-logs 按
  request_id 解码 upstream_request/upstream_response 三段对帧；gateway 日志
  grep `blocked stream lane` 拿 lane/label/lane_bytes——**lane_bytes=270 与
  「还原前」参数串逐字节相等**（还原后=245），锁定守卫检查的是还原前文本。
- **根因**：`outputSensitiveChecker.unsafeToolValue` 的外传判定循环消费
  `detectEgress`（ScopeEgress）返回的**全部**片段，而 ScopeEgress 不过滤
  规则类型；r1024 给 YAML account 规则拓宽的 label 集
  （`user(?:name|_name)?`、`[a-z0-9_]*_user`）命中普通 shell 命令里的
  `USER=$USER` / `USER=$(whoami)`，抽出 account 片段 `$(whoami)`——用户名
  token 既不可路由、又不在 isNonExfiltrationFragment 豁免表 → unsafe →
  CheckField 返回 **Blocked=true 且 Issues=[]**（与生产日志 issues=0 同形）
  → `releaseCheckedFrames` 判 lane 阻断。round 1 的命令恰好无 `user=` 形态
  所以过——这就是「第 2+ 轮才炸」的表象来源（模型第二轮起爱写
  `echo USER=$(whoami)`）。
- **单层复现**：`CheckField("__tool_json@run_ssh_command", <还原前参数>)`
  用内置检测器 PASS、用生产 YAML 检测器 **BLOCKED（issues=0）**——判据纪律
  第 2 条再次实证：地址/规则类判据必须用生产 YAML 检测器。
- **修复**（`security/sanitize/output_sensitive.go`）：外传判定循环跳过
  `TypeAccount` 片段——与 r1024「身份不是凭据」同一条原理的输出侧延伸：
  用户名形状的 token 不是外传目的地。**第一版收得过宽**（只认地址族片段）
  被 r1017（公网 user@host 靠 email 片段拦）与 r1028（真凭据样值靠 secret
  片段拦）两条既有契约打回，收窄为仅豁免 account 族。
- **判据**：`security/sanitize/r1032d_egress_account_not_destination_test.go`
  —— 捕获参数原样回放不阻断 + 两个前提在场钉子（公网 IP 目的地仍拦、
  非占位符明文密码仍拦）。变异 M3（撤豁免）红。另
  `r1032_grok_chat_args_drop_test.go`（拦截器直驱三轮全还）与
  `r1032c_chain_replay_test.go`（生产同构三拦截器链回放：guard→restore→
  compliance，扣留帧在终态统一释放、参数还原落网）作为层内判据。
  sanitize 全包绿（r1017/r1028/r1020/r1024 等既有契约全保）。

## 六、方法论增量（判据纪律第 11 条候选）

**「客户端收到什么」与「上游发了什么」必须按 request_id 配对取证，且
客户端侧 dump 的解析器要与 dump 格式同构**：本轮两次量具自伤——dump 校验
脚本要求行首 `data: `（dump 存的是裸 payload）得出「零参数」假结论；
首轮 harness `[DONE]` 早退漏刷 buffer 得出「零轮」假败。修复判据前先修
量具，否则缺陷定性会错层。
