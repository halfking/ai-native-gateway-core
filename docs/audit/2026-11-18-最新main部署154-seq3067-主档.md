## 六、三个辨析：**真错 / 假红 / 量具 bug**（本轮最有价值的部分）

★ 上轮的经验是「红清单一致 ≠ 数值一致」；本轮多了一层：**红本身要分类**。

### 6.1 真错（我方）：durable tag 指到了**前一个提交**

- 现象：采集器 ③「身份三方一致」判红，提示 `部署树 commit=a9e185d78（前缀匹配=0）`；
- 归因：tag 是在**分支工作树**里建的，而该工作树的 HEAD 停在上一个提交 `a9e185d78`，
  **实际发布树是 `1562862ba`** ⇒ tag 指错 ⇒ 证据链指向历史快照；
- 处置：`git tag -f -a deploy-154/seq3067-1562862b … 1562862ba` ⇒ ③ 即绿。
- ★ **通用式：tag 必须在「发布的那棵树」上建，或显式指定 commit** ⇒ 否则「发布面 = 树」这件事会被悄悄破坏。

### 6.2 假红（验收工具的判据**场景化写死**）：采集器 ⑦

- 旧判据把两件事**写死**了：① 「并行车在途文件（`admin/pi_analysis_handler.go`、`web/public/menu-config.json`）不得出现在发布单元里」；
  ② 「`domains/promptinjection` 的差异数必须 = 0」；
- 那两条**只在「发我方分支、并发车改动仍在途」时成立**；本轮发布单元 ＝ **origin/main**（并发车的 PI 工作已正式上线）
  ⇒ 「泄漏」「PI 差异」按定义就是发布单元**自己的一部分** ⇒ 旧判据**必然假红**；
- ★ **更危险的是：假红会掩护真错** —— 6.1 的 tag 指错，恰好被旧判据的红**盖住**，
  若只把 ⑦ 当成「老判据写死的」放过，就会把真错一起放过；
- 结构性修法（基准＝**发布单元/部署树**，与场景无关）：
  ① **tag 指向的 commit 必须 == 部署树 HEAD**（＝实际部署的那棵树）；
  ② **零真泄漏**：**线上 release 的 menu-config 内容**（去构建戳）必须 == **部署树**的同一文件内容
  （「线上有、部署树没有」才算泄漏）；
  ③ **PI 域**只作**报告**，不再写死为 0；
- ★ **通用式：判据的基准必须是「发布单元」，不是「谁还在途」** —— 后者会随并行车合流而失效；
  **且任何写死的 0 都要问一句「它依赖哪个前提」**。

### 6.3 量具 bug（我的冒烟脚本）：`.env.local` 的引号没去掉

- 现象：公网登录**间歇性 401**（第一次 401、第二次 200、第三次 401、第四次起全 200 ⇒ 看着像「双后端不一致」）；
- 排除项：目标机 env 与本地 `.env.local` 的**凭据指纹完全一致**（用户 sha `8c6976e5b541` / 口令 sha `6033c90d4ec6`）⇒ **口令没变**；
  旧实例在 13:25:37 已停 ⇒ **不是「新旧实例交替」**；
- 决定性证据：**服务端日志的 `request_bytes`** —— 401 那次 **53**、成功那次 **51** ⇒ **差 2 字节**；
- 根因：我的脚本 `env[k]=v` 没去引号，而 `.env.local` 的口令带引号 ⇒ **多带了 2 个字符**；
- 处置：解析改为 `v.strip().strip('"').strip("'")` ⇒ 12/12 连续 200。
- ★ **通用式：「间歇性 401」先看**服务端日志里的 `request_bytes`/`error.kind`**（比猜双活/缓存快一个量级）**；
  ★ **差 2 字节 ⇒ 一定是「多了两个字符」** ⇒ 去查解析，不要去查架构。

1. ★ **部署前先把闸门跑一遍（只读）**：上轮被闸门拦下是在**切符号链接之前**（无半部署），

   **顺序不能反**（台账语义＝这串字节真的跑过）。
3. ★ **重放前必须量数据侧**：本轮用整表内容哈希（`count + md5(string_agg(row_to_json))`）对拍 ⇒ 逐字节零变化
   ⇒ 才敢更新台账；**「幂等」是文件属性，「数据没变」要实测**。
4. ★ **判据的基准必须是「发布单元」**（不是「谁还在途」）⇒ 假红会**掩护**真错（6.2）。
5. ★ **tag 必须建在发布的那棵树上**（否则证据链指向历史快照，6.1）。
6. ★ **间歇性 401 先看服务端 `request_bytes`**（差 2 字节 ⇒ 多两个字符 ⇒ 查解析，别查架构，6.3）。
