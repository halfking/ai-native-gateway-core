## 3. F2（高）：我引入的切流锁，会把偶发互踩变成必然卡死

### 3.1 缺陷本体（实测复现）

上一轮的切流锁有两条获取路径：**flock**（Linux 有 `flock` 时）与 **mkdir 回退**（macOS 默认）。

★ **flock 路径没有这个问题**（进程退出即自动释放）；★ **mkdir 回退有**：
进程被 SIGKILL / 机器重启 ⇒ 锁目录**留在原地** ⇒ 而上一轮的实现**只有一条出路：rc=75 拒绝**。

实测（2026-10-28，本机）：

```
造一个「持有者 pid 已死」的残锁 ⇒ dl_acquire_switch_lock ⇒ rc=75
再试一次（= 模拟后续每一次部署）  ⇒ rc=75
⇒ ★ 永久卡死，且仓内没有任何命令能解开
```

⇒ **新机制把「偶发互踩」换成了「必然卡死」**——这比它防的问题更糟
（互踩只坏一次部署；卡死让**之后所有部署都坏**）。
★ 而且上一轮审计档里那句「残锁元数据里有 pid ⇒ 运维核对后手工删除」是**纯声名**：
仓内**没有任何命令**能删它（共享部署库的 `unlock-local.sh` 管的是它自己的锁路径，不是我的）。

### 3.2 修法：两处，都落在仓内

**① 残锁接管**（`scripts/deploy-local-lib.sh`）：
争用时读持有者元数据的 pid ⇒ **pid 已死 ⇒ 判定残锁 ⇒ 接管**（并大声告警）；
**pid 还活着 ⇒ 仍然拒绝**（那是真的有人在切流）。
⇒ 口径与共享部署库 `lock.sh` **一致**：**只看 pid 存活，不按年龄判**
（部署可能正在长时间跑，按年龄清锁会打断别人）。

**② 仓内真恢复命令**（`scripts/deploy-local.sh`）：
新增动作 `recover-switch-lock` ⇒ `dl_recover_switch_lock`：
- 持有者**还活着** ⇒ **拒绝**（不打断正在跑的部署）；
- 持有者**已死** ⇒ 清掉；
- 没有锁 ⇒ 幂等成功。
⇒ 注册在**三处**（usage / 参数白名单 / case 分派）—— 三处都缺，判据就红。

### 3.3 判据（`tests/deploy_switch_lock_contract_test.sh`，8 条不变量）

| # | 不变量 |
|---|---|
| I1 | 锁路径**机器级**（逐字等于 `${LOCK_TMP_ROOT}/kx-llm-gateway-switch.lock`，且换 cwd 再算一次必须一样） |
| I2 | 争用**快速失败**（rc 75）+ 打印持有者元数据 + 提示可恢复 |
| I3 | 释放后可再次获取 |
| I4 | 持锁窗口**覆盖候选起跑**（源码行号顺序） |
| I5 | 释放点在**切流完成之后**（源码行号顺序） |
| I6 | **失败路径（trap）也释放** |
| **I7** | **残锁（持有者已死）必须被接管**（rc 0 + 告警 + 元数据改写），**不得**把部署路径永久卡死 |
| **I8** | **活着的持有者仍然被拒**（rc 75）且其元数据**未被破坏**（接管逻辑不得把互斥拆了） |

## 9. F8（中）：本轮扩写契约测试时引入了新的 SIGPIPE 面

### 9.1 缺陷本体

本轮把 `tests/deploy_switch_lock_contract_test.sh` 从 4 条不变量扩到 8 条时，


★ **`head -1` 会提前退出** ⇒ 上游 `grep` 在写第二行时可能收到 **SIGPIPE（141）**
⇒ ⇒ 本仓脚本用 `set -euo pipefail` ⇒ **管道退出码非零 ⇒ 整个判据脚本中止**
⇒ ⇒ 而且它是**内容依赖**的：`deploy-local.sh` 里有**两处** `Usage:` 时，
判据会**随机地**中止 ⇒ ⇒ **判据自己变成了不确定的**。

★ **这道门是怎么抓到的**：`scripts/ursmcheck/pipefail_race_ledger_test.go`
（SIGPIPE 竞态面台账门）—— 它用静态普查工具
`scripts/audit/measure-pipefail-race-surface.py` 给出候选集，
要求「候选集 ↔ 台账」**键集完全一致**（主键 = `(file, fingerprint, occ)`）。
⇒ 本轮新增的这条形态 ⇒ **新候选点** ⇒ **台账里没有** ⇒ 门红。

### 9.2 归属：确凿是本轮引入的

pristine 上同一个文件是 **97 行**、**没有**这条管道 ⇒ 门在 pristine **PASS**；
本轮改写后 ⇒ 门 **FAIL** ⇒ ⇒ **确为本轮引入**。

### 9.3 修法：改代码，不改台账

★ **两条出路**：① 在台账里登记该候选点并写裁决（如 `benign-value`）；
② ★★ **把那条管道改掉**，让候选**根本不存在**。

⇒ **取 ②**：`grep -m1 -n 'Usage: deploy-local.sh' "$deploy_script"`
⇒ 语义等价（都取第一处匹配）、**无竞态**。
⇒ 同理修掉同文件里另一处 `grep -nF … | head -1 | cut -d: -f1`（助手函数 `line_of`）。
⇒ （第三处 `| tail -1` **保留**：`tail` 读全量、**不提前退出** ⇒ 上游 `grep` 不会收到 SIGPIPE。）

⇒ **实测**：重跑普查工具 ⇒ 候选集 **363 → 362**（去掉的正是这一条）
