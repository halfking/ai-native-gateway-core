## 二、问题根源

### 2.1 核心问题: **统计口径不一致**

**看板**: 统计**7天窗口内**的所有业务请求
```sql
SELECT SUM(cost_amount) FROM usage_facts
WHERE occurred_at >= NOW() - INTERVAL '7 days'
  AND traffic_class = 'business';
-- 结果: $9,899.22
```

**会话统计**: 读取`session_summaries`表,但`session_summaries`存储的是**会话全生命周期累计值**
```sql
SELECT SUM(total_cost_usd) FROM session_summaries
WHERE first_request_at >= NOW() - INTERVAL '7 days';
-- 结果: $8,577.79 (仅包含first_request_at在窗口内的会话)
```

### 2.2 举例说明

**会话 `gw_c6b0559e...`**:
- 生命周期: 2026-11-15 23:24 ~ 2026-11-17 02:32 (跨度约27小时)
- **全部请求**: 810条 / $354.61
- **7天窗口内**: 759条 / $340.56 (从2026-11-16 08:47开始)
- **窗口外**: 51条 / $14.05 (2026-11-16 08:47之前)

**session_summaries存储**: 810条 / $354.61 (全部)
**7天窗口查询**: 只看`first_request_at`,会包含这个会话的全部810条

**问题**: 应该只统计759条(窗口内),但实际统计了810条(全部)

### 2.3 为什么会少?

会话统计只统计了`first_request_at >= 7天前`的会话。
- 如果会话首请求在8天前,即使它在7天内还有活跃请求,也会被**整个排除**
- 这导致漏算了部分跨窗口会话的窗口内请求

**数据对比**:
```
request_logs(7天窗口,有session): 81,226请求 / $9,899.22
session_summaries(first_request_at>=7天前): 74,495请求 / $8,577.79
差异: 6,731请求 / $1,321.43
```

## 三、正确的统计口径

### 3.1 看板口径(正确)

统计**7天窗口内**的所有业务请求,无论这些请求属于哪个会话
```sql
SELECT COUNT(*), SUM(cost_amount)
FROM usage_facts
WHERE occurred_at >= NOW() - INTERVAL '7 days'
  AND traffic_class = 'business';
```

### 3.2 会话统计应该采用的口径

**按7天窗口聚合request_logs**,而不是读session_summaries:
```sql
SELECT 
    COUNT(DISTINCT gw_session_id) AS sessions,
    COUNT(*) AS requests,
    SUM(cost_usd) AS cost
FROM request_logs_with_current_month
WHERE ts >= NOW() - INTERVAL '7 days'
  AND origin_stage = 'business'
  AND gw_session_id IS NOT NULL
  [+ 宇宙过滤条件]
```

**验证结果** (211生产实测):
```
无过滤: 36,497会话 / 81,226请求 / $9,899.22 ✅ 与看板一致
```

## 四、修复方案

### 方案A: 修改会话统计后端查询 (推荐)

**修改位置**: `admin/dashboardapi/session_overview.go`

**当前实现** (错误):
```go
// 读取session_summaries表(存储全生命周期累计)
SELECT SUM(total_cost_usd), SUM(request_count)
FROM session_summaries
WHERE first_request_at >= NOW() - INTERVAL '7 days'
  [+ 宇宙过滤]
```

**修复后** (正确):
```go
// 直接聚合7天窗口内的request_logs
SELECT 
    COUNT(DISTINCT gw_session_id) AS sessions,
    COUNT(*) AS requests,
    SUM(cost_usd) AS cost
FROM request_logs_with_current_month
WHERE ts >= NOW() - INTERVAL '7 days'
  AND origin_stage = 'business'
  AND gw_session_id IS NOT NULL
  [+ JOIN sessions做宇宙过滤]
```

**优点**:
- 与看板口径完全一致
- 数据准确,无漏算

**缺点**:
- 查询性能可能较慢(需要聚合request_logs)
- 需要重写查询逻辑

### 方案B: 前端添加明确说明 (临时方案)

在会话统计页面添加说明:
> **统计说明**: 本页面统计的是首次请求在近N天内的会话的全部请求。
> 如需查看近N天内的所有请求费用,请查看"看板"页面。

**优点**: 实施简单
**缺点**: 用户体验差,数据口径不直观

### 7.1 核心结论

1. ✅ **看板与请求日志**: 完全一致 ($9,899.22)
