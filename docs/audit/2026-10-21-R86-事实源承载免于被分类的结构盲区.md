## 1. 盲区现场

`scripts/ursmcheck/pg_test_env_registry_test.go`：

```go
// -r71-update 分支（498-513 行）
if _, ok := ds[name]; ok {
    continue // 事实源承载的 dsn 类，不进登记册
}
// 判据 ① 差集完备（515-531 行）
for name, files := range used {
    if _, ok := ds[name]; ok {
        continue          // ★★ 事实源承载 ⇒ 既不进登记册、也不被分类
    }
```

而登记册**头部**早就写好了分类学：

```
#   dsn           整体 DSN，通用值可用        ⇒ 事实源必须导出
#   dsn_exclusive 整体 DSN，但必须专用值      ⇒ 事实源必须不导出
```

⇒ **分类学是对的**，只是它对「由别处承载的条目」从不生效。
⇒ R85 轮那条 `GATEWAY_CANONICAL_TEST_DSN` 是**手工读文件**才发现的 ⇒ 这不是手滑，是**盲区**。

### ③ 里必须分清的两个概念

- **读形态守卫 vs 改指**：
  `cfg.ConnConfig.Database = name` 是**把连接改指到自建库** ⇒ **好形态**（自带隔离，
  事实源的 DSN 只是引导连接）⇒ **不是错配**。
  只有**读取**库名（`current_database()` / 读 `cfg.ConnConfig.Database` 去比较）才是守卫。
  ⇒ ★★ 第一版把「赋值」当「守卫」⇒ **11 条候选里 9 条是假阳性**。
- **自建库排除**：`CREATE DATABASE` ⇒ 自带隔离 ⇒ 排除。

⇒ 与 R63 轮「按名命中多半是假阳性」**同族**，只是这次发生在**守卫层**。
⇒ ★ **一次判据修正，多挖出一例真缺陷**（`TEST_SESSION_SETTINGS_DATABASE_URL` 那条腿第一版没浮出来）。
