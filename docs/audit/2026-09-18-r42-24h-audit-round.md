## §三、本轮事故与教训（如实记录）

**psql 外层事务包装迁移文件 → BEGIN/COMMIT 嵌套失效，改名被永久提交。** §四的全新装序列模拟把现有表 RENAME 后期望 ROLLBACK 恢复，但 516/520 文件自带 BEGIN/COMMIT，把外层事务切成 autocommit 段——RENAME 在首个显式 BEGIN 之前已 autocommit 落盘。损害：6 表改名 + durable 四表被 IF NOT EXISTS 重建为空表（attachments 因 723 守卫 NOTICE 跳过而短暂缺失）。**恢复**：确认新旧表全为空（本机 durable/attachments 零数据）→ 新表改名让位 → r42bak_* 六表改回原名 → DROP r42new_*（先查 pg_depend 无视图依赖）→ healthz ready + RLS 标志逐表核对 + 723 在场路径幂等重跑。事后库内 r42% 残留为零。**教训入册**：①批量验证迁移时先 grep 文件头 BEGIN——自带事务的迁移文件绝不能包进外层事务，要么裸跑要么用 scratch database；②IF NOT EXISTS 的"幂等"只对建表语句成立，对"外层包装事务"是假幂等；③本次 723 守卫在真实事故中经受了实测（表缺席 → NOTICE skip 而非 42P01）。
