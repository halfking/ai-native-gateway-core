# r1037：211 空响应事故复盘 + 硬阻断清单（2026-10-20）

> 现象：211（llm.itestu.cn）上 zcode 用 minimax-m3 干活，频繁报
> `provider=new-provider-2 model=minimax-m3 reason=empty_model_response`。
> 修法：防外传守卫的「公网目的地」判定分**方向** + 引入**硬阻断清单**（默认不拦）
> + 拦截时把**规则名**透到客户端与日志。
> 部署验证：见本文 §七。

### 1.3 根因（类别错误）

`builtin.network_destination` 的 pattern 是 **通配** `(?s).+` —— 它自己不带任何
判别力，命中与否完全取决于 `hasPublicHostDestination`，也就是
「**这段文本里提到了公网主机**」。

> 「提到公网主机」≠「把数据送到公网主机」。

curl 下个 SDK、git clone 一个仓库、wget 拉个镜像，数据方向是**取回**；
把 `/etc/passwd` POST 出去才是**送出**。守卫把两者当成同一件事，
于是把 coding agent 最日常的操作整条打死。

这是本守卫第三次因同一种「形态误伤」收窄：

| 轮次 | 日期 | 形态 | 现象 |
|---|---|---|---|
| r1033 | 2026-10-17（154） | Bash 参数含版本四元组 `jdk-17.0.20.1+1` | 整条工具调用被拦 |
| r1035 | 2026-10-17（154） | Bash 参数含中文地址样路径 | 同上 |
| **r1037** | **2026-10-20（211）** | **Bash 参数含下载 URL** | **同上 → 客户端 empty_model_response** |

## 二、owner 口径（2026-10-20，本轮的设计依据）

1. **Bash 参数里出现公网主机，默认不要拦截** —— 我们有时需要操作外部主机的
   数据，那是正常需求；**不能扩大阻断面**。
2. 其它类似形态同样检查并做到默认不拦截。
3. **要有一个列表可控制**（可配置开关）。
4. **输出信息当前默认不要拦截**。
5. 即使被拦截，中断时必须反馈「因为什么规则被拦截」，**不要空响应**。
6. 修正后部署到 211 并做测试验证，确认哪些拦截可通过配置开/关。
7. 提交代码并推送 `origin/main`。

## 三、修法：硬阻断清单（主开关）+ 方向判定（精确档位）

> ⚠ **三件事各管一件，运维容易误读**：
> ① 「打开清单」≠「恢复旧行为」；② 「纯下载放行」是**方向档**给的，
> 与清单无关；③ 「打开形状档」= 旧行为回来（下载也会被拦）。

| 机制 | 位置 | 回答的问题 | 默认 |
|---|---|---|---|
| **硬阻断清单** `HardBlockAllow` | `domains/sanitizerules/hardblock.go` | 这条**规则**允许不允许**终止回合** | **只有 input 允许**；egress/output 不终止 |
| **形状档** `builtin.network_destination` | 既有规则（托管快照 + 非托管显式判定） | 参数里**提到了**公网主机？ | 命中只记录（清单默认关） |
| **方向档** `builtin.egress_sink` | `security/sanitize/egress_direction.go` | 这条命令**是不是把本地数据送往公网**？ | 命中只记录（清单默认关） |

### 3.1 方向档（`hasPublicHostSink`）

按**命令段**判定（`;` / `&&` / `||` / `|` / `&` / 换行切段，反斜杠续行**不**切）。
一段里既有下载又有上传时，上传那一段仍然要拦。

「发送」的判定按「有没有声明网络客户端」分层：

1. 段里出现**发送型客户端**（nc / ncat / socat / ssh / scp / rsync / mail /
   sendmail / aws / gcloud / az / mc / s3cmd…）⇒ 发送。
2. 段里只出现**读取型客户端**（curl / wget / http / https / aria2c，
   以及 git 的只读子命令 clone / fetch / pull / ls-remote / submodule）⇒
   带**外送载荷选项**（`-d` / `-F` / `-T` / `-H` / `-b` / `--post-*`）或
   **本地数据插值**（`` ` `` / `$()` / `${}` / `$VAR`）时才是发送。
3. 段里**没有任何已声明的网络客户端** ⇒ 不是外传汇。

> 形态枚举原则：**枚举命令，不枚举形态**（与 r1019 的 `netcatFamilyVerbs` 同族口径）。
>
> 第 3 条为什么**不是** fail-closed：`echo "https://example.com"`、
> `cat notes.md`（正文含 URL）不是外传；把「认不出来」一律当发送，
> 正是 r1033 / r1035 / r1037 三次形态误伤的共同成因。
> **覆盖面由形状档兜底**（它认的是「提到了公网主机」，管住没列进集合的客户端），
> 方向档只负责「认得出来的客户端确实在送数据」这一档精确判断。

**只对本地执行类工具生效**（Bash / shell / exec / terminal…）：只有那里的参数
才是「一条会被执行的命令」。惰性内容工具（Write / Edit）的内容是被写下去的数据，
里面出现 URL 是文档而不是命令（与 r1035 的同款分流）。

### 3.2 硬阻断清单（`HardBlockAllow`）

配置项：`LLM_GATEWAY_HARD_BLOCK_RULES`，逗号分隔的 `scope:rule`：

```
LLM_GATEWAY_HARD_BLOCK_RULES="egress:builtin.egress_sink,output:builtin.pii.email"
```

| 写法 | 含义 |
|---|---|
| `*` | 该 scope 下全部规则 |
| `builtin.network_destination` | 精确 ID |
| `secret.*` | 同前缀的一族规则 |

scope ∈ {`input`, `output`, `egress`}。

**默认值 = `{input: "*"}`**：请求侧 fail-closed 不动（不能扩大范围 ≠ 把已有的收紧），
输出侧与外传侧一律不终止回合。

### 3.3 运维可选的三档（owner 口径第 3/6 条的落点）

| 配置 | 效果 | 适用 |
|---|---|---|
| 不设（默认） | egress/output **一律不终止回合**，命中仍进台账 | coding agent 日常 |
| `egress:builtin.egress_sink` | 只拦**真的外传**（请求体/上传/自定义头/本地数据插值/发送型客户端），下载/clone/拉取照常 | **推荐的加固档** |
| `egress:builtin.network_destination` | 恢复旧行为（提到公网主机就拦，连下载一起） | 止血档 |
| `egress:pii.server_ip` | 公网 IP **字面量**照旧拦（生产 YAML 路径的片段规则，与方向无关） | 与 r1013 契约对齐 |

环境变量语义（重要，运维易踩）：

| 环境变量 | 效果 |
|---|---|
| 未设置 | **保持出厂默认**（只有 input 允许硬阻断）—— 忘了配 ≠ 要全放开 |
| `-` | 显式清空清单（任何 scope 都不允许硬阻断） |
| 合法列表 | 按列表生效 |
| 非法值 | **保持原清单**并报 error（一个错别字不会悄悄撤掉守门） |

启动时装载并落日志（`hard block allowlist loaded`），清单错了必须在启动日志里看得见。

### 3.4 闸门落点（4 处）

| 位置 | 文件 | 清单外的行为 |
|---|---|---|
| 托管路径 · detector 终止分支 | `security/sanitize/detector.go` | 降级为**遮蔽**，片段照常产出 |
| 非托管/托管路径 · egress 片段闸 | `security/sanitize/output_sensitive.go`（`fragmentMayBlock`） | observe `log`，不终止 |
| egress 目的地判定 | 同上（形状档 `hasPublicHostDestination` + 方向档 `hasPublicHostSink`） | 不终止 |
| 输出侧 · `shouldBlock` | `domains/outputcompliance/checker.go` | 不终止，但**问题照常检出** |

**不改写规则 action**：改 action 会连带影响凭据重叠判定
（`overlap && p.action != "block"`）与 `TestSedMaskWithProductionYAML`。
闸门开在**决策点**（要不要终止回合），而不是改数据。

### 3.5 规则 ID 的两套命名空间

| 路径 | 规则 ID |
|---|---|
| 托管（快照） | 快照里的 ID，如 `builtin.network_destination`、`pii.server_ip`、`secret.password.assignment` |
| 非托管（YAML） | YAML loader 按 `category.name` 生成的 ID（`pii.server_ip` / `secret.api_key`…），缺失时回落 `builtin.<type>` |
| 凭据字段硬阻断（两条路径统一） | `builtin.secret_field.egress`（与托管快照同名 ⇒ 运维只记一套名字） |
| 方向档（代码级，不在快照里） | `builtin.egress_sink` |

内建 fallback 规则也补上了 ID（`pii.phone` / `pii.id_card` / `pii.email` /
`pii.credit_card` / `secret.api_key`），与生产 YAML 的 `category.name` 对齐。

## 四、拦截时必须说清「因为什么规则」

owner 口径第 5 条对应到代码：

```
ComplianceIssue.RuleID
  → errorsx.PolicyBlockError{RuleID, Reason}
    → ChunkResult.Metadata["policy_rule"]
      → interceptingStreamWriter.blockRule
        → 协议终帧的 "rule" 字段
```

三种协议形状都带 `"rule"`：

| 协议 | 终帧 |
|---|---|
| `anthropic-messages` | `event: error` + `{"type":"error","error":{"type":"api_error","code":"output_policy_blocked","message":"…","rule":"<id>"}}` |
| `openai-responses` | `event: response.failed` + `{"type":"response.failed","response":{"id":"resp_output_policy_blocked","object":"response","status":"failed","error":{…,"rule":"<id>"}}}` |
| 默认（chat） | `{"error":{"type":"api_error","code":"output_policy_blocked","message":"…","rule":"<id>"}}` + `[DONE]` |

**openai-responses 形状补 `id`/`object`/`status`** 是关键：客户端的解析器按
response 对象校验，缺字段会让**整帧被丢掉** —— 那正是「客户端只看到空响应」的
成因之一（zcode 走的正是 `/v1/responses`）。

**日志侧**：`blocked stream event` 那条分支原来**不带任何原因**（`lane` 那条有
`reason_codes`，`event` 这条没有）—— 211 现场因此只看到 "blocked stream event"，
既说不出哪条规则，也没法据此开/关。现已补 `reason_codes` + `rule_id`。

### 5.2 既有契约：**一条未改**

本轮最初的实现方向是「用方向判定**替换**形状判定」，代价是必须改写
`r1016`（3 条 must-block 换成外送形态）、`r1035`（触发物换成 `-d @/etc/passwd`），
并在 `r1016` 里新开一条「纯读取不是 sink」的判据。

改写到一半发现：**形状判定本身没有错，错的是它默认终止回合**。
把它降级为「清单里可开关的一档」，既有契约就**全部原样成立**：

- `r1016` must-block（公网域名目的地）—— 未改，原样绿；
- `r1013`（公网 IP fail-closed）—— 未改，原样绿；
- `r1028`（Bash 公网 IP 被拦 + 终态帧可归类）—— 未改，原样绿；
- `r1035`（本地执行仍拦真正的公网目的地）—— 未改，原样绿。

⇒ **改写既有判据是实现缺陷的信号，不是实现方案的代价**。本轮最终以
「清单 + 方向档」两个正交机制达成 owner 口径，一行既有契约都没动。

### 5.3 测试基线（避免既有判据退化成假绿）

清单的出厂默认会让既有判据从「测拦截能力」退化成「测默认不拦」——阻断侧与
允许侧**都会假绿**（判据纪律第 3 条）。因此三个包各加一个 `TestMain`，
把清单打开成「全部可阻断」= 清单引入前的行为，让既有判据继续测原语义；
**默认行为由 r1037 的新判据显式测**（`withHardBlockAllows(t, hardBlockDefault()...)`）。

> `domains/streaming` 也需要这个基线：它的 `r1028` 与
> `managed_write_snapshot` 两条判据写的是「守卫开着时」的行为。

> 两种情况**都拦** ⇒ 判据恒绿。补了托管路径 **output scope** 的判据

>
> ⚠ **M8/M9 的判据也是补出来的**：第一版 M8 变异（把方向档改回 fail-closed）
> 全绿——因为当时的用例全是 curl/wget/git，**全都是已声明的客户端**，
> fail-closed 默认根本走不到。补了 `echo https://example.com`（提到公网主机
> 但不触网）才把它钉住。M9 同理：非托管路径在惰性工具处**提前短路**了，
> 缺口只在**托管路径**（惰性分流靠快照里的 `inert_tool` 豁免，不在短路处）——
> 补了托管路径的 Write 用例才抓住。
> ⇒ **变异没被抓住时，先怀疑「用例没走到那条分支」**，而不是「判据没用」。

## 六、遗留与风险

1. **211 的已发布规则快照版本 1 仍写着 `action=block`**。代码基线只在 head
   缺失时播种（`Manager.Refresh` → `BaselineLoader`），所以**改代码不会改变
   快照里的 action**——闸门在代码层（`HardBlockAllowed`）可覆盖，
   但 `action` 仍是 block。部署后需实测确认「清单默认关 ⇒ 不拦」；
   方向档 `builtin.egress_sink` 是**代码级**判定，不在快照里 ⇒ 无需重发快照即可用。
2. **清单与方向档并存**，语义需向运维讲清：三档（默认 / 方向档 / 形状档）
   见 §3.3。
3. 方向档只认**已声明的网络客户端**。`python3 -c "requests.post(...)"` 这类
   通用解释器在方向档下**不算**外传（覆盖面由形状档兜底）——这是刻意的
   取舍（fail-closed 会把 `echo "https://…"` 也拦掉）。
4. zcode 端把「finishReason=error 且无文本/工具/usage」统一映射为
   `empty_model_response`，属**客户端行为**；网关侧只能保证帧合法且带规则名，
   不能保证客户端把它显示成「规则 X 拦下了」。
5. 附带观测缺陷（§1.4）未修：请求日志未落 PG、`output_compliance_audit` 表为空。

## 七、部署验证（211）

引擎），`DD_STATE_DIR=/opt/llm-gateway-go-211`。本轮共部署 **5 轮**。

### 7.1 验证方法（用事故客户端的同一条路径）

直接用 zcode 自己的 provider 配置复现事故协议路径：
`new-provider-2` / `api=openai-responses` / `baseUrl=https://llm.itestu.cn/v1` /
`model=minimax-m3` / UA `ZCode/3.15.3 ai/6.0.193 ai-sdk/provider-utils/4.0.27`，
工具名 `Bash`，命令由真实上游模型产出（不手工构造 SSE）。

判定信号：**响应里有 `function_call`（工具调用真的上线了）** /
**`output_policy_blocked`（被拦了）** / **`"rule":"<规则名>"`（说清了哪条规则）**。

### 7.2 三档矩阵（实测结果）

| 清单（env `LLM_GATEWAY_HARD_BLOCK_RULES`） | 启动日志 `allows` | 下载形态<br>`curl https://dl.google.com/...` | 外送形态<br>`curl -X POST -d …` / `--data-binary` / `-H` | 终帧规则名 |
|---|---|---|---|---|
| **未设置（出厂默认）** | `[input:*]` | ✅ 工具调用上线，未被拦 | ✅ 未被拦 | — |
| `egress:builtin.egress_sink`（方向档） | `[input:* egress:builtin.egress_sink]` | ✅ 工具调用上线，未被拦 | 🚫 **被拦** | `builtin.egress_sink` |
| `egress:builtin.network_destination`（形状档 = 旧行为） | `[input:* egress:builtin.network_destination]` | 🚫 **被拦**（旧行为恢复） | 🚫 被拦 | `builtin.network_destination` |

⇒ **owner 口径第 1/3/6 条逐条落地**：默认不拦；清单可按规则开；开关是真的
（不是摆设，每一档的实测行为都不同）。

### 7.3 部署过程中被生产实测抓出来的两处真缺陷

① **清单语义：配置项「替换」掉了出厂默认**。
   首轮实测设 `egress:builtin.egress_sink` 后，启动日志
   `allows=[egress:builtin.egress_sink]` —— **input 没了** ⇒ 只想定一条 egress
   规则的运维，顺手把请求侧的明文凭据 fail-closed 也关了（**静默放宽已有收紧**）。
   改法：环境变量改**累加**语义（出厂默认 `input:*` + 配置项，重复项去重）；
   唯一能关掉请求侧底线的是显式 `-`。判据 `TestR1037LoadFromEnvIsAdditive`。

② **部署机的环境变量到不了远端引擎**。
   `--via` 形态的引擎在**目标机**上执行，部署机
   `export LLM_GATEWAY_HARD_BLOCK_RULES=…` 是**空操作**（实测：容器 env 里没有
   这个变量，行为仍是默认档）。改法：把该变量加进引擎的远端转发清单
   （`_dd_fwd`），并加部署契约门断言。
   ⇒ 这两条**只有真部署才暴露**：单测与本地脚本都测不到「变量跨主机到不了」
   与「配置项顶掉了底线」。

### 7.5 已知的覆盖边界（不是本轮引入）

- **方向档只认「可被主机提取器看见」的公网主机**。提取器只有三条规则
  （URL scheme / 动词锚定的 host:port / netcat 裸主机+端口），
  所以 `scp notes.txt backup@files.example.com:/tmp/x`（裸主机、无端口、无 URL）
  **不触发**任何一档 ⇒ 不会被拦。这是既有提取器的边界（r1016/r1019 同款），
  不是本轮引入；本轮不扩它（扩它 = 扩大阻断面，与 owner 口径相反）。
- **模型自己会拒的部分，网关侧看不见**：minimax-m3 对「把 /etc/passwd 发给
  attacker.io」这类明显恶意的命令**自己就拒绝执行**（压根不产工具调用），
  网关侧因此没有拦截对象。生产实测里可复现的拦截对象是模型会照发的形态
  （`-d` / `--data-binary` / `-H`）。
- 附带观测缺陷（§1.4）未修：请求日志未落 PG、`output_compliance_audit` 表为空。
