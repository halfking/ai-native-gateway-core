## 📋 验证结果判定标准

### ✅ 验证通过（全部满足）
1. 部署前（< 12:50）的记录：`error_kind IN ('request_rejected', 'transient')`
2. 部署后（≥ 12:50）的记录：`error_kind = 'upstream_quota_permanent'`
3. 最近 24 小时无新的 `transient` 误归因
4. 活体测试：`error_kind = 'upstream_quota_permanent'`
5. 活体测试：`upstream_status_code = 400`，`client_status_code = 502` 或 `429`

### ⚠️ 部分通过
- 有少量 `transient` 记录，但时间戳在修复部署前
- 或者时间窗口内数据较少，样本不足

### ❌ 验证失败
- 部署后仍有 `transient` / `request_rejected` 记录
- 活体测试归因错误

## 🔧 故障排查

### SSH 连接失败
```
Error: Connection closed by 198.18.2.202 port 22
```

**解决方法**：
1. 检查 netbird 是否运行：`netbird status`
2. 尝试使用内网直连（去掉 `--via-mesh`）
3. 在 211 机器上本地执行：
   ```bash
   ssh 211-mesh
   cd /root/llm-gateway-go
   ./scripts/f3-verification-suite.sh
   ```

### SQL 查询超时
```
Error: query timeout
```

**解决方法**：
1. 缩小时间窗口（修改 SQL 文件中的时间范围）
2. 添加 `LIMIT` 限制返回行数
3. 在 211 机器上本地执行（减少网络延迟）

### 活体测试失败
```
Error: 401 Unauthorized
```

**解决方法**：
1. 检查 API key 是否有效：`echo $LLM_GATEWAY_TEST_KEY`
2. 检查 key 是否过期（从管理后台查看）
3. 使用 `--skip-live-test` 跳过活体测试
