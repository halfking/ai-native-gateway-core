## 二、copy-quality 为什么**可以**扩到源码面（先量再落盘）

## 三、★ 新门：Vue 3 的普通属性不做插值

### 3.1 形态

```html
<span title="$t('common.close')">   →  title 的值就是字符串 "$t('common.close')"
<span :title="$t('common.close')">  →  绑定形式才求值
```

实测（`@vue/compiler-dom` 3.5.43）：

```js
compile('<div title="$t(\'common.close\')">hi</div>', { mode: 'module' })
// ⇒ { title: "$t('common.close')" }      ← 静态字符串，不是表达式
```

**编译不报错、vue-tsc 不报错、运行时也不报错** —— 只有用户看得见：
tooltip / placeholder 变成字面量 `$t('…')`，而且它**比原文长得多**，还会撑宽版面。

同族：Vue 3 也**移除了属性里的 mustache 插值** ⇒ `text="{{ x }}"` 同样渲染成字面量。

### 3.2 为什么之前没有门

- `keys_referenced` / `localeKeyParity`：只管「键在不在」。
- `callSiteParams.bindingKind`：**按变量名**判「静默吞错的变量有没有消费者」，
  不是通用的「普通属性里放 i18n 调用」判据。

⇒ 上一轮在模板里插了 **563 个 `$t()`**，任何一处落进普通属性都会静默把键路径显示给用户，
而**没有门会报**。

### 3.3 ★ 门首跑抓到 2 处真缺陷（不是假阳性）

`web/src/views/AgentRegistryView.vue` 的**邻居列表**（上下游）：

```html
<span class="kind-tag kind-{{ n.kind }}">{{ n.kind }}</span>   ← Vue 3 不插值
```

而**同文件 421 行**用的是正确写法：

```html
<span class="kind-tag" :class="'kind-' + a.kind">{{ kindLabel(a.kind) }}</span>
```

并且 648–650 行确实有三条按 kind 区分的配色规则：

```css
.kind-llm_endpoint { background: color-mix(in srgb, var(--accent) 18%, transparent); color: var(--accent-h); }
.kind-mcp_server   { background: var(--success-bd); color: var(--success); }
.kind-agent        { background: var(--warning-bd); color: var(--warning); }
```

⇒ **主列表的徽章是按 kind 上色的，邻居列表的徽章从来都是同一个默认色**
（`.kind-tag` 本身只有 padding/圆角，没有背景色）。用户看到的是「同一个列表里两种颜色」。

**修法**：与 421 行同款 —— `class="kind-tag" :class="'kind-' + n.kind"`。

### 3.4 门的判据纪律

| 纪律 | 做法 |
|---|---|
| 只看 `<template>` 块 | `<script>` 里的字符串不是模板 |
| **先剥 HTML 注释** | 仓内的修复说明注释里会原样写出被修的那段（`text="{{ tabErrors.pricing }}"`），不剥就会把注释当缺陷 |
| 绑定/指令放行 | `:x` / `@x` / `#x` / `v-x` 的值会被求值 |
| 非空下限 | 扫过的属性数必须 > 3000 —— 「一个属性都没扫到」也是绿的（假绿） |
| 双向自证 | 10 条夹具：会触发 3 条、不误触发 7 条 |

## 四、等级量表：为什么要**搬进语言包**而不是换个词

copy-quality 在 `web/src/types/quality-api.ts` 报出空洞词「卓越」（DESIGN.md §7 禁用词表）。
若只换词（卓越 → 最优）能过门，但有三个问题被留下：

1. 等级文案在源码里是**硬编码中文** ⇒ **7 个非中文语种显示中文徽章**；
2. 源码字面量 + 语言包 = **两个真值源**；
3. 换词只解决**这一个词**，解决不了「量表没有本地化」。

⇒ 做法与上一轮的 `headlineState` 同款：**字母是稳定 code，文案是语言包里的词**。

- 语言包：`common.terms.qualityGrade.{s,a,b,c,d}`（5 key × 8 语种 = 40 条译文）
- 取词：`web/src/utils/qualityGradeLabel.ts`（键名写成**字面量** ⇒ 静态扫描器看得见 ⇒
  「8 个语种都有这个键」仍然有门在管）
- 调用点：`ProvidersView.vue`（徽章 tooltip）、`provider-detail/QualityTab.vue`（徽章旁文字）

### 4.1 8 语取值与两条硬约束

| | zh-CN | zh-TW | en-US | ja-JP | de-DE | es-ES | fr-FR | ar-SA |

| S | 最优 | 最優 | Best | 最優 | Optimal | Óptimo | Optimal | الأفضل |
| A | 优秀 | 優秀 | Excellent | 優秀 | Sehr gut | Excelente | Très bon | ممتاز |

### 6.4 棘轮基线的设计

## 七、量具口径的一处澄清

中文棘轮门数的是「**注释剥离后**的 CJK **连续段**数」，不是字数。

本轮 −4 的构成（逐文件对拍 HEAD vs 工作树）：

```
  -5     12 →     7  src/types/quality-api.ts      ← 等级表 5 个标签（每段 1 段）
  +1      6 →     7  src/views/DispatchWaterfallPreview.vue  ← 一句话被逗号拆成两段
  合计 delta -4
```

⇒ **把一句话拆成两段，计数会涨**。这不是缺陷，是口径：门数的是「段」不是「字」。
（也说明「让句子更可读」的改写有时会让棘轮计数 +1 —— 棘轮留了余量即可。）

   与 **after-en-US 逐字同款**；而 after-zh-CN 的 `/live` **没有**这一条裁切。
2. 「逐字折行」是 CJK 现象（字符被一个一个竖排），历史基线 **0 条**。
3. 报告的顶层字段只有 `{base, at, results}` —— **不记语种** ⇒ 只能靠签名反推。

⇒ ★★ **后果**：直接拿历史基线跟 zh-CN 对拍，会看到
`textLen 合计 103,206 → 85,569（−17,637，0.83×）`，
**这是跨语种伪影，不是回归** —— 中文本来就比英文紧凑。
⇒ ★★ **若把它当回归去追，会追一个不存在的回归**（这正是「先判量具、再判数据」）。

⚠ **顺带暴露报告格式的缺陷**：跑同一趟扫了两种语种，报告里**没有语种字段** ⇒
事后无法自证是哪一趟。`UI_SWEEP_LOCALE` 已经存在 ⇒ **报告应该把 locale 写进去**（下一轮的活）。

⇒ ★★ **已修（2026-10-25 稍后）**：主报告与弹层报告的顶层都加了 `locale` 字段，
控制台头部也打「语种：」。实测：`UI_SWEEP_LOCALE=zh-CN` ⇒ 报告 `locale='zh-CN'`；
不带该变量 ⇒ `locale='(default)'`（控制台写明「默认：跟浏览器 navigator.language」）。
⇒ ★ **价值**：事后拿到两份报告，**能自证它们是不是同一门语言** ⇒ 跨语种的差值不会再被当成回归。
⇒ ★ **通用式**：★ **报告必须自陈口径**（语种 / 时间窗 / 分母 / 扫描根）——
★ 否则「两份报告的差」只能靠签名反推，**而签名反推是有可能反推错的**。

## 补充.3 ★★ 量具自己的三处缺陷（本轮修）

### (a) 折行判据不认竖排 ⇒ CJK 语种每趟都挂假 P1

`/live` 的 3 个车道标签**每次扫 CJK 语种都会出现** ⇒ 真回归会被噪声淹没。
修法：探针排除 `writing-mode: vertical-* / sideways-*`（竖排是排版意图）。

### (b) ★★ selftest 的计数断言恒真 ⇒ 「不得误报」的反向对照全是装饰

原判据：`ok = actual[k] >= want`。于是 **`expect: 0` 变成「≥ 0」= 恒真** ——
所有「不得误报逐字折行 / 不得误报裁切」的反向对照夹具**永远是绿的**，等于没有对照。

修法：`expect: 0` 取**相等**；`expect > 0` 仍取「≥」（一处真 bug 常在同页复现多行/多列，
探针 8 处封顶，拿相等去卡会把「报得更多」误判成探针失灵）。

### (c) ★★ 夹具可以「悄悄不再命中签名」⇒ 夹具会变成装饰品

本轮实测的坑：新写的竖排夹具用 `font-size:14px` ⇒ 实测 `clientH=80`，
**没过 `h > 90` 的阈值** ⇒ 压根没命中几何签名 ⇒
**把 writing-mode 排除去掉，变异体仍然全绿**（第一次跑出来就是这样）。
⇒ 夹具「绿」证明不了「门有牙」，只证明「夹具没触发」。

修法（两条）：
1. 探针新增 `sigHits`：**命中几何签名的元素**，逐个带排除原因（`scrollable` / `vertical-writing`）；
2. selftest 新增 `sigHit` 判据：**每条夹具自己声明命中了几个签名元素**
   （期望 0 取相等、期望 >0 取「≥」）⇒ 夹具不再命中签名时**当场红**。

## 补充.7 ★ 顺带抓到的一道「半绿不绿」—— 是在**我自己的测试**里

新写的 `qualityGradeLabel.test.ts` 里把语种写成 `'en-US'` ⇒ vue-tsc 报
`TS2322: Type '"en-US"' is not assignable to type '"zh-CN" | "en"'`。

根因值得记：**`'en-US'` 是 locale 的「目录名」，运行时码是 `'en'`**
（`i18n.ts` 里 `STATIC_LOCALES = { 'zh-CN': zhCN, 'en': enUS }`，参考码 → 当前码的映射写在文件头）。
⇒ `'en-US'` 这个语种**根本不存在** ⇒ 断言是靠 `fallbackLocale: 'en'` **蒙对**的
⇒ **测试是绿的，但绿的理由是错的**。

修法：改用真实运行时码 `'en'`，并加一道守卫
`expect(i18n.global.te('common.terms.qualityGrade.s')).toBe(true)`
—— 证明「这个语种的消息**真的加载了**」，而不是 fallback 兜的。
变异验证：把码改回 `'en-US'` ⇒ **测试红**（`expected false to be true`）。
