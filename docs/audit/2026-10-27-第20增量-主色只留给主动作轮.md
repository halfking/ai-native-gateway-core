## 1. 为什么是这一轮

### 1.1 病：主色被重复消费，焦点被稀释

impeccable 规范里三条原话（`skill/reference/`）：

| 出处 | 原话 |
|---|---|
| `operate.md` | **Accent color used for primary actions, current selection, and state indicators only, not decoration.**（`rule:product-color-accent-only`） |
| `distill.md` | **Clear hierarchy: ONE primary action, few secondary actions, everything else tertiary or hidden** / **Clear next action: ONE obvious next action, not five competing ones** |
| `colorize.md` | **Keep the primary action easy to find; do not spend its color on decoration.** / **Let the strongest color own a deliberate region or role instead of scattering tiny accents.** |

仓内明文也写着同一件事（`DESIGN.md` §视觉世界）：

> 状态用最小的颜色量表达、**每个元素都承担信息职责**。

⇒ 53 个蓝底按钮把「新增模型」稀释到看不见。

## 2. 判据（唯一实现：`web/src/design/primaryFocus.ts`）

### 2.1 一条判据

> **实心主色不得落在「数据行」内。**

### 2.2 实心主色的形态（穷举，2 种）

| 形态 | 写法 | 非实心的变体（必须排除） |
|---|---|---|
| `element-plus-primary` | `<el-button type="primary">` | `link`（文字链）/ `text`（文字按钮）/ `plain`（描边） |
| `own-btn-primary` | `<button class="btn btn-primary …">` | — |

★ **自证当场抓到**：`link` 是**裸布尔属性**（没有 `=`、没有引号）⇒ 朴素的属性正则看不见它
⇒ 文字链被当成实心 ⇒ 修法：写正规的属性分词 `parseAttrs`，区分「有值 / 裸属性 / 显式假值 / 属性不存在」四种状态。

### 2.3 数据行的形态（穷举，5 种）

| 形态 | 判据 |
|---|---|
| `table-cell` | 祖先含 `<td>` / `<th>` |
| `element-table-column` | 祖先含 `<el-table-column>` |
| `row-slot` | 祖先含 `<template #x="{ row }">`（作用域变量名 `row`/`item`/`record`/`entry`） |
| `list-item` | 祖先含 `<li>` / `<tr>` |
| `v-for-block` | 祖先含带 `v-for` 的**块级**元素 ⇒ **刻意区域卡候选** |

★ 第 3 种（行 slot）是实测补的：`ui/ResponsiveDataView` 把「一行」交给父组件渲染，
父组件的 slot 内容**既没有 `v-for` 也没有 `<td>` 祖先** ⇒ 只认前两种会整族漏网。

### 2.4 豁免

| 豁免 | 判据 | 读数 |
|---|---|---|
| ① 焦点区域 | 祖先含 `el-dialog` / `el-drawer` / `<AppModal>` / `<AppDrawer>` / `role="dialog"` / `aria-modal="true"` / 类名 `app-modal` / `app-drawer` / `modal-panel` | **29** |
| ② 刻意区域卡 | 形态 = `v-for-block` **且**该视图内没有别的实心主色与之竞争 | **5** |

★ 豁免 ② 的第二个条件有实测支撑：`views/FreePoolView.vue` 同屏有 **9 个**非焦点区实心主色
⇒ 此时卡片里的主色不再是「这个区域的角色」⇒ 判红。

### 2.5 竞争主色怎么算

「竞争主色」= 同文件里**既不在重复容器内、又不在焦点区域内**的实心主色。
裁决（`decideRowLevel`，纯函数，自证与真扫描共用）：

```
焦点区域          ⇒ 豁免
数据行            ⇒ 违规
刻意区域卡 + 0 竞争 ⇒ 豁免
其余              ⇒ 违规
```

## 6. ★ 本轮抓到的真缺陷（都不是本轮引入的）

### 6.1 ★★★ `maskSource` 的「等长」承诺是假的 ⇒ **所有复用它的门行号都错**

`web/src/i18n/hardcodedCjk.ts` 的注释写着：

> 下面所有替换都**等长**（非换行字符一律替换成空格），因此偏移量在整条链路上不变

**实测 `views/FreeDiscoveryView.vue`：长度 51173 → 58358（+7185）、行数 1501 → 1648**
⇒ 门把 **615 行的按钮报成 761 行**。

**根因**：`maskHtmlCommentsOutside` 逐段拼接「保护区之外的文本」时，**保护区重叠**：

- 该文件的 `<style>` 标签**落在 `<script>` 内容区间内**（script 内容 24→19960，`<style>` 开在 12768）
- ⇒ `cur` 已推进到 19960，再来一个 `s=12775` 的区间时 `s > cur` 不成立
- ⇒ 中间那段**被跳过一次又拼一次** ⇒ 内容重复 ⇒ 偏移全漂

**影响面**：全仓 **3 个**文件长度不一致（`CorrelationsView.vue` +3894 / `FreeDiscoveryView.vue` +7185 /
`ModelIntegrityView.vue` +9810）⇒ 所有复用 `maskSource` 的门（copyClarity / copy-clarity /
internalJargon / primaryFocus）**在这 3 个文件上报的行号都是错的**。

**修法**（两处）：
1. `maskHtmlCommentsOutside` 先**合并重叠 / 相邻的保护区**再逐段处理，并保证游标单调不减；
2. 新增回归门 `src/i18n/hardcodedCjk.maskInvariance.test.ts`（全仓等长 + 针对性回归 + 只动注释不动代码）。

**修后**：全仓 **1473 个文件 0 例外**；`i18n:cjk:check` 读数 **4484 = 基线（未动）**。

### 6.2 ★★★ 「同签名兄弟组」在源码层**分不开** ⇒ 实测假阳性 73 处 / 23 文件

我先在源码层补了第 5 种重复容器形态（「多个长得一样的兄弟容器，各带一个实心主色」），
想用它覆盖 §5.2 那一族。**实测假阳性 73 处 / 23 文件**：
`ProxyView.vue`(7) / `BootstrapWizardView.vue`(6) / `PromptInjectionSettingsView.vue`(5) /
`FormatAnomaliesView.vue`(4) …… 全部是「**不同的区块**恰好长得像」。

★ 原因：「5 段同款代码示例」与「5 个长得一样的区块」在**源码结构上完全一样** ⇒
⇒ ★★ **判据宁可窄，不可宽** ⇒ 撤掉源码层的这一形态，**交给运行时尺**（DOM 才分得开）。

### 6.3 ★★ 焦点区域豁免名单**过期** ⇒ 豁免分支是死的

我按老印象写 `el-dialog` / `el-drawer`，而仓内 **2026-09-13 起**把弹层壳收敛成了
`ui/AppModal` / `ui/AppDrawer` ⇒ 豁免**一次都没命中**（读数 `focusRegionSolidPrimary: 0` 暴露了它）。
★ 修后读数 **29**。
★ 教训：**「豁免命中数 = 0」是危险信号**，不是「干净」。

### 6.4 ★★ 【标签名 ≠ 类名】⇒ 运行时层原本一个焦点区域都认不出

源码层看到 `<AppModal>`（标签名 `appmodal`）；运行时看到 `<div class="modal-overlay app-modal">`。
⇒ 两层必须各自认「标签名 + 类名 + 语义角色」三条，且名单一致。

### 6.5 ★★ 运行时尺原本会把「没量到」写成「通过」

三页测到 0 个实心主色（数据没到 / 状态没进到）⇒ 工具改成显式打「⚠ 该族未被覆盖」。

## 10. 通用式

见 `LESSONS.md` **§458**（11 条形态），要点：

1. 「同一个主色按钮渲染出 N 个」才是用户看到的病 ⇒ 源码门按**声明位**判、运行时门按**渲染位**判
2. 形态表要穷举**同一形状的所有实现写法**（link/text/plain 三个非实心变体）
3. **豁免名单会过期** ⇒ 豁免命中数为 0 是危险信号
4. **【标签名 ≠ 类名】** ⇒ 搬观测层时，形态的命名方式也要一起搬
5. 「刻意区域」是**视觉判断** ⇒ 压缩成可算的近似，或显式登记 + 附证人
6. **两把尺的作用域不同** ⇒ 结论要写清「谁在什么作用域上说的」，以运行时尺为最终裁决
7. 源码层原理上看不见「同签名兄弟组」⇒ 交给运行时尺（实测源码层假阳性 73 处）
8. ★★ **复用量具前先量它的不变量** —— 注释里的承诺不算证据；**行号错的门比没有门更坏**
9. 「量具挂起」是**读不到**，不是**读到了 0**
10. 负向臂要证明**豁免是活分支**（豁免计数必须 +1）
11. 自证要覆盖判据的每个分支，且每个正向用例都要有反向对照
