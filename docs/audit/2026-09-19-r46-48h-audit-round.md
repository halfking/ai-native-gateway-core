## §三、本轮事故与教训

**"三选一裁决要靠实测，不靠论辩"**。affinity 盲窗连续三轮顺延的根因是三个选项都只有定性权衡（JOIN 视图怕慢、迁移嫌重、维持不甘）。本轮先跑 EXPLAIN ANALYZE：字面首选方案（JOIN 视图）7 秒且**视图含 session_turns 段语义直接不可用**——这个否决证据纸面推演永远得不到；NOT EXISTS 变体 110ms 一测定案。教训入册：**带性能权衡的遗留裁决，第一步永远是真库 EXPLAIN，权衡材料必须是测量值**。

**"端点存在 ≠ 端点能用"——部署冒烟是 admin 内嵌 SQL 的唯一真门**。R44 的"SQL 模板免检"教训针对 scripts/ 下的 .sql 文件；本轮证明同样的债在 admin handler 内嵌 SQL 里更深：F9 的 4 组 500 级预存缺陷（verdict 42803×3、回放 `$1::uuid` 对探测 id、ErrNoRows 裸 `==` 永假、双形态 id 无匹配）全部是**端点交付以来第一次被真实执行**暴露的——单元测试打桩绕过了 DB，门禁跑不到 handler 内嵌 SQL 的真实语义。教训入册：admin 新端点的验收必须含"登录→真实调用→200"的部署冒烟（本轮已把三端点纳入冒烟清单），并评估落 checker。

**部署 tag 碰撞陷阱**。同一 build_seq（version.json 未 bump）连续多次 deploy-local 时，镜像 tag 不变，容器可能继续挂在旧镜像上（本轮 00:43 容器跑的镜像与 00:51 tag 指向不一致，冒烟结果一度与代码矛盾，排查耗费数轮）。教训：**反复部署验证时必须 bump version.json build_seq 强制新 tag，并用 `docker inspect .Image` 对账容器镜像 ID 与 tag**。

**读面纪律的"剩余半径"**。R44 重写了两份分析 SQL、R45 修正了读面 NULL 投影，但本轮 D07 仍抓到 3 处 admin 端点裸读母表/hot 表——纪律的传播半径止步于"被审计过的文件"。教训：读面纪律需要**机制化收口**（§五#11：`FROM request_logs\b` 裸读 grep 守卫测试纳入 checker，白名单豁免）。另注：本轮 F3/F9 修正了子代理的一个笼统建议——"切 `request_logs_with_current_month`" 对依赖 `model_chosen/strategy_used/auto_profile` 列的查询**不可用**（turns 段把这些列投影为 NULL），正确读面是 request_logs 侧双腿视图 `..._without_request_class_due_at`；读面纪律要连同**列依赖**一起判断。

## §五、遗留登记

1. **P2 | 评分热路径性能专项**（D05 P2-1 + D01 P3-7 合并）：`Info()` 每凭据 O(n) 持锁扫描 × 每请求 P2C+抽签约数十次调用、6-8 个权重 env 热路径重读——结构性优化（增量窗口计数器/单次评分共享快照/权重启动期解析）需基准对照，登记专项不改。
2. **P3 | 首跳抽签不折边际成本**（D01 P3-8）：cost 仅进 composite（影响 failover 序），有意排除的口径需在设计文档写明或补齐折算——待产品确认。

4. **P3 | blended 价格 ≤0 记 0 惩罚**（D01 P3-9）：价格异常（负单价）被视作免费而非异常信号。
5. **P3 | IRTransformer（MM-1a）全仓无生产接线**（D03）：附件 base64 落盘去重对线上流量未生效，MM-1b outbound 渲染预留——台账记录分阶段状态。
6. **P3 | Gemini 入向附件不入提取/存储/审计链**（D03）：handler_gemini 无 attachmentExtractor 调用（OpenAI/Anthropic 已覆盖）——需 ExtractFromGeminiBody 或等 MM-1b 统一走 IR。
