## 二、普查方法：「地址族判定点」怎么定义、怎么测

### 2.1 口径

「某类型算不算地址族」在仓内不是一个问题，而是**三个问题**，必须分开：

| 问题 | 判据的**轴** | 谁在问 |
|---|---|---|
| ① 这个**声明类型**算不算地址族？ | 类型**名** | 脱敏面豁免 / 合规面只检出 |
| ② 这个声明类型**该映射成什么**托管类型？ | 类型**名** → 类型**名** | legacy 导入 / 合规面导出 |
| ③ 这个**规则名**（内置 YAML 的 `patterns:` 键）算不算？ | 规则**名** | 内置基线装载 |

★ 前两个必须同源（同一份 SSOT + 同一个规范化入口）；第三个是**另一个问题**
（YAML 词表封闭、且 `address` 在 YAML 里指的是**中文邮政地址**，与 SSOT 里的
`address`（**网络**地址）**同词异义** —— 见 §六）。

### 2.2 量具（不是文本 grep，是 AST）

新工具 `cmd/tools/address_family_decision_audit`：

* 用 `go/parser` + `go/ast` 扫全仓非 vendor 的 `.go` 文件；
* 认领五种形态：
  * `membership-call` —— 调 `sanitizerules.IsAddressFamilyType`；
  * `canonical-call` —— 调 `sanitizerules.LegacyPIIRule`（规范化入口）；
  * `list-call` —— 调 `sanitizerules.AddressFamilyTypes`；
  * `type-list` —— **自己写了一份类型名的集合**（复合字面量）；
  * `type-switch` —— **自己写了一份按类型分支的 switch**；
* ★ **量具里那 9 个类型名是故意的副本**：若量具用 SSOT 的导出函数去找「谁写了名单」，
  抄件与原件长得一样就分不出来 ⇒ 副本与 SSOT 的一致性由另一道门把住
  （`TestAddressFamilyTypeNameCopyMatchesTheSSOT`）。

★ **为什么用 AST 而不是 grep**：`grep '"ip"'` 会把 `center/types.go` 的 JSON 字段名
`ip_address`、遥测禁收键 `hostname`、admin 响应的 map 键一起算进来 ⇒ 噪声淹没信号。
AST 能分清「复合字面量里的字符串」「switch 分支里的字符串」与「随便一个字符串」。

## 四、D1（真缺陷）：第三面已经漂移

### 4.1 形态

`domains/outputcompliance/managed_rules.go` 的 `Checker.RuleConfig()` 持有一份**自己的类型映射**：

```go
switch typ {
case "bank_card":            typ = "credit_card"
case "ip", "ip_address", "ipv6": typ = "server_ip"
case "phone", …, "custom":   // 原样
default:                     typ = "custom"   // ★ 未知的地址族声明落进这里
}
action := "mask"
if isAddressPIIType(typ) { action = "log" }
```

而 SSOT 那份（`domains/sanitizerules/legacy_baseline.go` 的 `LegacyPIIRule`）在 r1038b 补了
`case "domain", "hostname", "address": typ = "server_ip"` ⇒ **两份已经不一样**。

### 4.2 实测（r1040 修复前的探针读数）

| 声明类型 | 合规面导出（旧） | legacy 导入（SSOT） | 是否一致 |
|---|---|---|---|
| `ip` / `ip_address` / `ipv6` | (server_ip, log) | (server_ip, log) | ✅ |
| **`domain`** | **(custom, mask)** | **(server_ip, log)** | ❌ **相反** |
| **`hostname`** | **(custom, mask)** | **(server_ip, log)** | ❌ **相反** |
| **`address`** | **(custom, mask)** | **(server_ip, log)** | ❌ **相反** |
| `server_ip` / `internal_ip` | (server_ip / internal_ip, log) | 同 | ✅ |
| `url` / `custom` / `secret` / `email` … | (custom, mask) | 同 | ✅ |

★ **后果**：`pii_patterns` 里的一行 `pattern_type='domain'`（运维写的**声明类型**）——
走 legacy 导入路径 ⇒ 只记录不遮蔽（合用户口径）；走合规面导出路径 ⇒ **照遮蔽**。
**同一行 DB 规则，走哪条路决定它遮不遮域名。**

★ 这正是 r1038b 的 D1（两份名单漂移 ⇒ 同一类型在两个面相反待遇）**在新位置上复发**：
r1038b 修好了 `detector.go` 与 `checker.go` 两份名单，**没发现 `managed_rules.go` 里还有第三份映射**。

### 4.3 修法（删副本，不是补第二份）

```go
// 修复前：本包自己抄一份 switch。
// 修复后：与 legacy 导入调**同一个**构造器（同一张 pii_patterns 表的同一种行）。
cfg.Rules = append(cfg.Rules, sanitizerules.LegacyPIIRule(id, p.PatternName, p.PatternType, p.RegexPattern, p.Enabled))
```

★ 「给第二份 switch 也补上 domain」是**错法**：那还是两份，下一轮照样漂。

## 五、三道门（本轮新增）

### 5.1 门 A：清单 ↔ 实测双向对拍（`cmd/tools/address_family_decision_audit/manifest_test.go`）

形态**照抄** `cmd/tools/sql_source_indirection_audit`（**事实源漂移**线的样板，见 §七）：

| 断言 | 内容 |
|---|---|
| ① 实测有、清单无 | 红：**新判定面无人判定** |
| ② 清单有、实测无 | 红：判定过期（面被删/改名/挪位） |
| ③ 分类/理由为空 | 红：空理由的登记等于没有登记 |
| ④ **核心**：生产代码（**非测试、非量具、非 SSOT 包**）里的 `type-list` / `type-switch` | 红 ⇒ **「所有地址族判定点必须调 SSOT」** |
| ⑤ 全仓**只有一份**地址族名单 | 红（>1 即红） |
| ⑥ 量具副本 == SSOT 名单 | 红 |
| ⑦ 防空过假绿：实测面数非 0，且至少各有一个 membership/canonical-call | 红 |

分类词表：`ssot-bound` / `definition-site` / `reverse-assertion` / `measuring-instrument` /
`not-a-decision` / `reviewed-exception`。

★ **诚实边界**：`not-a-decision`（误报）是**人的判断** —— AST 分不出「DB 列名 `hostname`」
与「规则类型 `hostname`」⇒ 这一类登记的价值是**留痕**，不是自动判定。

### 5.2 门 B：行为对拍（`domains/outputcompliance/r1040_address_family_canonical_parity_test.go`）

* 同一批**声明类型**，两条路径必须给出**同样的 `(type, action)`**；
* 声明为地址族 ⇒ 导出成 `action=log`（**只记录不遮蔽**）；
* 反向对照：`url` / `custom` / `secret` / `account` / `email` / `phone` / `credit_card` / `id_card`
  ⇒ 必须 `action=mask`（**凭据类不许被顺手放宽成安全后门**）。

### 5.3 门 C：内置 YAML 词表对拍（`security/sanitize/r1040_builtin_pattern_address_family_test.go`）

* YAML 里凡是**名字**属于地址族的规则，其类型**必须**也是地址族；
* YAML 里出现**未登记**的地址族名字 ⇒ 红（将来有人加一条 `ip:` 规则 ⇒ 它会落进
  `TypeCustom` ⇒ 脱敏面开始遮蔽 ip ⇒ 本门在**加载期**就红）；
* 登记在册的**例外**：YAML 的 `address` = **中文邮政地址**（r1036 冻结项）⇒ 必须 `custom`（照遮）。

★ 这道门**当场抓到了自己**：初版登记簿只写了 `address` 与 `server_ip` ⇒ 门立刻报出
YAML 里还有一条 `server_ipv6`（`pii.server_ipv6`，类型 `server_ip`）⇒ 补登记后绿。
（这就是「门归零后要立刻看它有没有牙齿」的最小实例。）

## 六、★ 一处**同词异义**（写在这里，别在别处改一半）

同一个词 `address` 在两个体系里指**两件事**：

| 体系 | `address` 指什么 | 类型 | 结果 |

⇒ 将来谁想「顺手统一一下」，会先撞到这道门。

## 八、属主裁决备忘：`pii.address`（对应目标 ② · 本轮**未动那条正则**）

> 现状：`configs/sensitive_patterns.yaml:47` 与 `domains/approval/sensitive_detector.go:73`
> 各有一份**同字面量**的正则副本：
> `[^\s]{2,}[省市区县镇乡村路街道巷弄号栋单元室]\s*[\d\-号栋单元室]+`

### 8.1 两边并排

| | r1036 的**冻结理由**（2026-10-20，154 生产取证） | r1038 / r1038b 的**建议**（也是本轮的建议） |
|---|---|---|
| **主张** | **不改**。冻结 | **改**：只从**前导**字符类去掉「号」，**后置**保留 |
| **理由 1** | 修复只处理「custom 内含精确类型子片段」，**不重新解释地址规则的其他命中**（`TestR1036NonAddressLabelWithoutPreciseTypeUnchanged` 断言「订单号 20241012」→ `{SENSITIVE:custom:1}`） | 那条「不重新解释」的边界**正是要重新解释的地方** ⇒ 改它等于**推翻 r1036 的边界**（须 owner 明知） |
| **理由 2** | 用户当年的「地址」指**网络地址**（示例里的 proxy host 与其并列的域名、ip），**不是**中文邮政地址 | 同 ⇒ 用户口径**不覆盖**中文邮政地址 ⇒ 这一族**不该由本轮代裁** |
| **理由 3** | 改它会**缩小 PII 覆盖面**，属**安全姿态变更** | 改的是**运营编号**（工号 / 订单号 / 任务号 / 房间号）——它们**不是 PII**；真地址（`建国路88号` / `文三路100号`）**仍命中**（后置类里有「号」） |
| **实测面** | —— | 245 生产：`pii.address` **7 天命中 90,091 次**，误伤面即上述运营编号族；真地址应遮 |
| **与 r1036 的冲突点** | —— | r1036 反对的是删掉**后置**的「号」（那会让真地址整体失效）；**本建议只动前导** ⇒ **两者不冲突** |

### 8.2 若裁决「改」，本轮已核过的落地面（**裁决前不动**）

* **两份副本**要同改：`configs/sensitive_patterns.yaml:47` ＋ `domains/approval/sensitive_detector.go:73`
  （只改一处 ⇒ 两个面口径分裂）；
* 建议字面量：`[^\s]{2,}[省市区县镇乡村路街道巷弄栋单元室]\s*[\d\-号栋单元室]+`
  （前导去「号」、后置保留）；
* **既有门不会挡**：`r1036_label_suffix_address_test.go` 的 `addressSpecificChars`
  = `省市区县镇乡村路街道巷弄`（**不含**「号」）⇒ 改前导不触门；
* **本轮新增的门 C**（§5.3）把 YAML 的 `address` 登记成**必须保持 `custom`** 的例外
  ⇒ 若裁决「改」，**必须同步改门 C 的登记**（否则门会红 ⇒ 这是有意的：让改动必须显式）。

### 8.3 本轮态度

**裁决前不动那条正则。** 本轮只把它**并排放给 owner**（本档 §八 ＋ 交付时的问卷）。

★ **问卷结果（诚实记账）**：交付时的问卷在 **60 秒内未收到回复** ⇒ **系统自动选择了推荐项**
