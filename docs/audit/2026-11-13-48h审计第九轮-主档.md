### § 4.2  关键差异分析

#### 差异 1：market_compare.go

**stash 版本**：
```go
if err != nil {
    // 降级可见性（2026-11-13 12h 修订审计轮补：此前静默吞成空 map，前端把
    // 「API 失败」显示成「0 覆盖」——误导排查方向）。主件（评分行）已到手，
    // summary 失败不构成 5xx 的理由，降级 + WARN 留痕。
    slog.Warn("admin/market/compare: summary query failed (degrading to empty summary)", "error", err)
} else {
    defer sumRows.Close()
    for sumRows.Next() { ... }
    if err := sumRows.Err(); err != nil {
        slog.Warn("admin/market/compare: summary rows error (degrading to partial summary)", "error", err)
    }
}
```

**HEAD 版本**（5b4120b2b rowsguard 修复）：
```go
if err == nil {
    defer sumRows.Close()
    for sumRows.Next() { ... }
    if serr := sumRows.Err(); serr != nil {
        writeJSON(w, http.StatusOK, map[string]any{
            "available": false,
            "reason":    "summary rows iteration failed",
            "error":     serr.Error(),
        })
        return
    }
}
```

**差异本质**：
- stash：query 失败降级 + WARN，迭代失败也降级 + WARN
- HEAD：query 失败静默降级（summary 空 map），迭代失败 fail-closed

**裁决建议**：stash 版本更详细（区分两类失败+留痕），但需 owner 裁决是否 fail-closed。

#### 差异 2：credential_rollup_refresher.go

**stash 版本关键删除**：
```go
// 删除的内容：
const credRollupLockKey = "llmgw:credential-total-requests-rollup"

// refreshOnce 中删除的内容：
if _, err := tx.Exec(rctx, `SELECT pg_advisory_xact_lock(hashtextextended($1, 0))`, credRollupLockKey); err != nil {
    r.logFailure(err, started)
    return fmt.Errorf("credential rollup refresher: advisory lock: %w", err)
}
```

**删除原因**（stash 注释）：
> 跨实例互斥（2026-11-13 12h 修订审计轮补）：245+154 共用 252 库 ⇒ 无锁时
> 双实例各自全表聚合（17.3s×N/30m）。锁必须**先于**聚合 SQL 取；另一实例
> 持锁时本事务在此等待（受上方 rctx 超时约束，不会无限挂住）。

**影响评估**：
- 删除锁 ⇒ 245+154 双实例无互斥 ⇒ 每 30m 至少两次 17.3s 全表聚合
- 保留锁 ⇒ 跨实例串行 ⇒ 每 30m 一次 17.3s 聚合

**裁决建议**：**高优先级**，涉及 245+154 共用 252 库的并发控制策略，需 owner 明确裁决：
1. 若删除锁，是否有其他机制（如错开调度相位）避免同时聚合？
2. 若保留锁，是否需要调整超时避免死锁？
