# /live 网关核心布局优化 · 设计方案（四案对比稿）

> 轮次：2026-11-20（设计轮，**零产品代码改动**——本轮只交付设计稿供挑选；**二轮修订已并入**，见 §七）
> 原型：`docs/audit/2026-11-20-live网关核心布局-四案对比原型.html`（自包含，浏览器直接打开；顶部可切换「现状 / A / B / C / D」，勾选「纵向全览对比」可五案同屏）
> owner 需求（一轮）：优化页面中央「网关核心」的呈现——在能表达清楚流程的前提下**更紧凑**，让下方节点与模型有足够显示空间；仍分**入/出**两个主方向；逻辑重新整理、流程化说明；字体与色系可调；不同模块用不同**外框或图标**；先出几稿供挑选。目标：**直观、完整、有序**。
> owner 反馈（二轮，2026-11-20）：**A**＝流程要从上到下简要写明＋基础服务放右侧；**C**＝要流程性更强；**D**＝存储转发与异步事件移到右侧、贯穿全局。（B 未提反馈，维持一轮终版。）

## 一、现状取证（为什么挤）

现状版本 = `GatewayCoreBox.vue` 2026-10-28 选路层版（四带纵排 + 基础服务侧条）。
在 DEV 夹具预览页（`/dev/live-topology-preview`，与生产同组件同布局函数）实测：

| 量 | 值 | 说明 |
|---|---|---|
| 网关核心高度 | **320px** | `GATEWAY_BOX_MAX_H = 320`（liveTopologyLayout.ts:140）长期**顶格** |
| 四带结构 | 头 26px + 进站链 / 选路扇出 / 存储转发 / 出站链 四带 | 每格双行（名称+计数上下排）+ 左侧竖排带标 18px |
| 供应端行 / 模型行 | 画布 0.85 / 0.95 比例位 | 两行**贴底**：620px 画布里净距仅 ~20px，视口 940 时供应端行已在折叠线下方 |
| 外框语言 | 实线（主链）/ 虚线（旁路）两种 | 模块**类型**（处理/扇出/存储/观测/基础服务）无外框区分 |
| 图标 | 仅存储带一个 `<Coin/>` | 其余模块无图标，全靠文字 |
| 流向表达 | 入/出两链都读 L→R | 「出」的回流方向与「入」同向，**环读语义断了**（响应应回到客户端一侧） |

结论：核心问题不是信息太多，而是 **320px 的四带双行结构把纵向空间吃光** + 流向/模块类型缺乏非文字编码。

## 二、设计目标（对齐 owner 口径）

1. **紧凑**：核心区高度显著下降，让供应端/模型行上移并获得呼吸空间；
2. **流程化**：入/出两个主方向清晰，且互相构成一个**环**（请求进 → 派发 → 响应回）；
3. **外框/图标分型**：不同类模块用不同外框族与图标（用户点名）；
4. **字体与色系**：数字走等宽（IBM Plex Mono，tabular-nums），四色语义系（见 §3.1）；
5. **完整**：现有 11 个模块 + 插件 chip + 队列深度 + 选路扇出（含 auto 任务分布）**一个不减**；计数/失败红/未测量标注等诚实性语义全保留；
6. **有序**：阅读动线单一，不产生「这是串行还是并行」的歧义（扇出≠串行步骤的既有结论不回退）。

## 三、四案共用的设计语言

### 3.1 色系（四语义族，全部来自仓内 kx tokens，零新色）

| 族 | token | 用途 |
|---|---|---|
| 入 | `--kx-primary`（蓝 #5b8cff） | 请求链主链芯片/线/计数 |
| 出 | `--kx-success`（绿 #3ecf8e） | 响应链 |
| 存 | `--kx-warning`（amber） | 存储转发（斜纹底继承现行） |
| 支撑 | `--kx-violet` 系（#9d8cff，本稿新增的第 4 语义色） | 基础服务（路由/节点状态）+ 内部直连扇出口 |

### 3.2 图标（内联 SVG 线性描边 1.5px，12–14px）

仓规（DESIGN.md §6 / glyphIconCore）禁 Unicode 字形与 emoji 冒充图标 ⇒ 全部 SVG：
缓存=闪电、脱敏=盾、模型选择=靶心、压缩=向心箭头、队列=三条杠、写入=笔、文件=夹、
任务识别=扫描框、错误记录=三角叹号、探测=雷达、路由=分叉曲线、节点状态=脉搏线、插件=插头、auto=环针。
（实施轮可优先映射 element-plus 既有图标，缺的自画 SVG 组件，规格同上。）

### 3.3 外框五族（「外框即语义」）

| 外框 | 语义 |
|---|---|
| 实线圆角框 | 主链处理模块（缓存/脱敏/模型选择/压缩/输出合规） |
| 药丸（整圆角+淡底） | 选路扇出出口（auto/直连/指定）——并行出口，非串行步骤 |
| 斜纹底+amber 边 | 存储转发（队列/写入/文件） |
| 虚线框 | 旁路观测（任务识别/错误记录/探测）——继承现行虚线=旁路语义 |
| 括号（左侧粗竖线+无整框） | 基础服务（路由/节点状态）——支撑件，不在链上 |

### 3.4 字级

标题 13px/700；带名 11px/600+字距；芯片名 12px；计数 11px mono tabular；微字（任务分布）10px mono。

### 3.5 保留的现行行为（实施轮不动）

点模块格=过滤聚焦（选中环形描边）、命中脉冲 470ms、失败转红、`没有数据就是 0`、直连未测量标注、插件 chip 按方向落带、`prefers-reduced-motion` 全部动效降级。

## 四、四案

### 方案 A · 对向双轨（主推）

**结构（二轮修订后）**：三列——**左列「流程速览」**（①客户端请求↓ → ②入站处理→ → ③派发供应端↓ → ④供应端处理· → ⑤返回·出站↑ → ⑥回客户端↑，从上到下简要写明全程）；**中列双轨主体**——入轨（蓝，L→R）在上、出轨（绿，R→L 视觉回流）在下，右端汇于「派发⬇ / 返回⬆」连接柱（与下方供应端层交换方向），中间「存·转发桥」（队列+写入⇄文件），「模型选择」芯片正下方垂挂扇出三药丸；**右列「基础服务」全高侧栏**（路由管理/节点状态，紫色括号标签）。

- 高度 **178px（-142px）**；供应端/模型行上移 ~100px。
- 直观点：①→⑥ 流程速览一眼读全程；入/出对向 + 右端连接柱 = 一个**顺时针环**，出方向第一次有了与入相反的视觉流向。
- 完整点：全部模块单行芯片化（图标+名+计数一行读完），信息零删减。
- 风险/取舍：出轨 R→L 阅读习惯需要半秒适应（已加「← 出·响应链」方向标）；窄屏（<900px）芯片需横向滚动或两行折行；三列对宽度最敏感（<1100px 时流程速览列可收成图标窄条）。
- 迁移面：`GatewayCoreBox.vue` 模板重排（带结构从 4 带变「速览列+双轨+侧栏」），`liveTopologyLayout.ts` 的 `GATEWAY_LANES`/`GATEWAY_BOX_MAX_H`（320→~190）联动改。

### 方案 B · 环线总线（最紧凑）

**结构**：一条 U 形闭环总线——左外腿（蓝）自顶部客户端进入 → 上横线入段 5 站点（缓存/脱敏/插件/模型选择/压缩）→ 右竖腿下行 → 右下角「派发⬇」出框到供应端；「返回⬆」自供应端入框 → 下横线出段 4 站点（输出合规/任务识别/错误记录/探测，R→L）→ 左内腿（绿）上行回客户端。存储=右腿上的 amber **换乘支线**（分支圆点+队列/写入⇄文件）；扇出=模型选择站下方两行块（药丸行+任务分布微字）；基础服务括号挂左下角。

- 高度 **158px（-162px）**；供应端/模型行上移 ~132px，为四案之最。
- 直观点：眼随线走，「一次请求的完整旅程」一条线讲完；站点=圆徽+图标+计数角标，地铁图心智。
- 完整点：站点标签在徽下方，信息同量但**字更小**（10.5px）。
- 风险/取舍：密度高时（插件多、任务分布长）中带最先挤（本轮评审已实测过一版拥挤，靠两行扇出块+出段下移解决）；「存储是支线」弱化了它在数据链路上的地位；站点+标签的纵向占位对画布高度敏感。
- 迁移面：组件重写幅度最大（站点定位用百分比，`computeGatewayBox` 的 lanes 模型要换成站点坐标模型）。

### 方案 C · 分组瓦片（分型最强 · 二轮流程强化）

**结构（二轮修订后）**：**完整流程缎带**——①入口治理 ▸ ②选路·压缩 ▸ ③存储转发·贯穿 ▸ ⬇派发供应端 ▸ 供应端处理 ▸ ⬆供应端返回 ▸ ④出口·观测 ▸ ↩回客户端（└基础服务）——把「派发/供应端/返回/回客户端」四个原本缺位的全程节点补进主轴；下面四个**异形外框分组**并排，**组间▸▸粗箭头**衔接；①②组内补**串行小箭头**（缓存→脱敏→插件、模型选择→压缩——真实串行才画，扇出仍无箭头）；③组内用 ⇄；基础服务括号列挂最右；底部外框图例行。

- 高度 **186px（-134px）**。
- 直观点：**外框即类型**（「不同模块不同外框」在此案最彻底）；缎带=完整主轴，顺序感不再只靠编号；增删模块只动所在组。
- 风险/取舍：仍是「分组」而非「连续流向线」——流程感强于 v1、弱于 A/B 的轨道/总线；四组并排对宽度敏感（<1100px 需换行成 2×2）。
- 迁移面：与 A 同级，但类型外框可以单独先落到现行结构（渐进路径友好）。

### 方案 D · 紧凑改良 + 右侧贯穿轨（最稳）

**结构（二轮修订后）**：**主线只剩三带**——进·请求链（缓存→脱敏→插件→模型选择→压缩→⬇派发）／选·模型去向（auto/直连/指定药丸，行尾带基础服务括号标签）／出·响应链（⬆供应端返回→输出合规→↑回客户端，二轮起**回流向也有了**）；**右侧「存储·异步」贯穿竖轨**（全高、左缘两段式竖脊：上段 amber=存储转发「队列/写入⇄文件」，下段绿=异步观测事件「任务识别/错误记录/探测」——存储转发与异步事件不再占主行，作为贯穿支撑挂在右侧）。

- 高度 **204px（-116px）**；主线带宽比 v1 多出整条存储带的空间。
- 直观点：主线一眼读完「进→选→出」；右轨把「贯穿性关注点」（存储/异步观测）从主流程里拿出来，语义正好——它们本来就不是串行步骤。
- 风险/取舍：右轨条目字号偏小（10.5px）；-116px 的收益中等。
- 迁移面：小——带结构仍是「横向带 + 右侧列」的现行骨架（四带变三带+右轨），`GatewayCoreBox.test.ts` 的带级断言改映射即可。

## 五、四案对比（二轮修订后）

| 维度 | 现状 | A 对向双轨 | B 环线总线 | C 分组瓦片 | D 紧凑改良+右轨 |
|---|---|---|---|---|---|
| 核心区高 | 320px | **178px** | **158px** | 186px | 204px |
| 供应端/模型行获得空间 | — | +100px | **+132px** | +90px | +58px |
| 流程环读（入→出闭环） | ✗（同向两链） | **◎ 速览列①→⑥+对向车道** | **◎ 一条线走完** | ◎ 缎带补全程节点+组间箭头 | △ 主线三带+↑回客户端 |

| 存储/异步的语义位 | 中间一条带 | 中间桥 | amber 支线 | ③组·贯穿标注 | **◎ 右侧贯穿竖轨** |
| 模块类型辨识（外框/图标） | 2 种外框 | 5 族外框+图标 | 站点形制+图标 | **◎ 5 族外框最彻底** | 5 族外框+图标 |

## 八、本轮过程登记（一轮）

- **评审迭代**：首版经三轮视觉 QA 打回——①「游离红色椭圆」根因是原型 CSS 单字母类名 `.d`（方案 D 根类）与 `.hdot.d`（供应端危险点）**撞选择器**（已根修：四案根类改 `gA/gB/gC/gD`，顺手发现现行 mock 里 `class="d"` 详情 span 同样中招）；② B 案中带「扇出/存储/出段」三层贴挤（12px 间隙）⇒ 扇出改两行块+出段下移（间隙 155px）；③ B 案出段左腿向下出框（回流方向错）⇒ 改双左腿闭环（蓝入腿 x10 / 绿出腿 x30，均回顶部客户端侧）。终版四案经 DOM 级（越界/重叠/锚定）与视觉级双通道复验通过。
- **量具**：截图/几何量取走仓内 `maestro/tools/cdp-client.mjs`（CDP 直驱 headless Chrome，1440×940@2x）。
- **未动产品代码**：`web/src/**` 零改动；本稿全部落在 `docs/audit/`。
- **遗留**：①「内部直连」紫族色 `#9d8cff` 为本稿新增语义色，实施轮需进 design tokens（`style.css` dark/light 两块）；② B 案若中选，插件多时（>3 个 chip）需定义折叠策略；③ 全案在 light 主题下的对比度复验留实施轮（本稿只做了 dark）。
