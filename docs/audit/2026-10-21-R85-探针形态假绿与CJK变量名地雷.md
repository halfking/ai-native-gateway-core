
## 4. ③ L3 分支补 `COUNT(*)` 闸（同一个错误只修了一半）

### 4.1 缺口

`scripts/252-monitor/pg17-emergency-cleanup.sh` 的 **L3** 分支对 `casdoor/kaixuan/crm/kxmemory` 四库用


### 4.2 修法（已落地，形态**刻意对齐 L1**，不发明新形态）

① **分区排除闸**：分区生命周期不归本脚本（TRUNCATE 一个已 ATTACH 的分区会静默丢掉该范围的行，之后该范围 INSERT 直接报 `no partition of relation found`）⇒ 跳过并留痕。

## 5. ★★★★★ 意外收获：**bash 把非 ASCII 字节并进变量名** ⇒ 仓级地雷

### 5.1 现象与机制

我给自己的探针门写完第一版后，**`fail` 子用例红**，红因是 `$_rc`「未绑定的变量」—— 而 xtrace 明确显示 `_rc=1` **在 190 行已被赋值** ⇒ **量具与被测对象不在同一层** ⇒ 深挖后得到真因：

```bash
$ bash -c 'set -u; v=1; echo "X$v中Y"'
bash: v?: 未绑定的变量          # exit 127
$ bash -c 'v=1; echo "X$v中Y"'
X??Y                          # 值与那个汉字**一起被吞掉**（静默失真）
$ bash -c 'set -u; v=1; echo "X${v}中Y"'
X1中Y                          # 花括号形式安全
```

**机制**：bash 解析 `$` 之后的**变量名**时，把后随的**非 ASCII 字节**也算进名字里 ⇒ 变量名变成 `v中` ⇒ 这个名字**从来没人定义过** ⇒

- `set -u` ⇒ 报「未绑定的变量」并**中止脚本**（exit 127）
- 无 `set -u` ⇒ 展开成空串 ⇒ **原值与那个字符一起消失**

★ **bash 3.2 与 5.3 行为一致**（两版各测一遍）⇒ 不是某个 bash 版本的怪癖。

### 5.2 爆炸半径（两把独立尺子全量对拍）

| 口径 | 读数 |
|---|---|
| 裸 `$VAR` 紧跟非 ASCII（**代码点**，排除整行注释与单引号区段） | **52 处 / 33 文件** |
| 其中落在 **`set -u` 脚本**里（⇒ **硬崩**，脚本当场退出） | **49 处 / 30 文件** |
| 无 `set -u`（⇒ **静默丢值**） | 3 处 |

★ **两把尺子（Go 门内置扫描器 / 独立 Python 扫描器）全量对拍：差异 0**（一度差 1 文件 2 处，追下去发现是 Python 的读数取自**我修那 2 处之前**的快照 ⇒ **陈旧读数**，不是量具分歧）。

★ **仓里已有一处同类局部守卫**：`sql/schema/integration_gate_test.go::TestGateDoesNotRequireHostPsql` 里的
`\$[A-Za-z_][A-Za-z0-9_]*[^\x00-\x7f]` 正则 —— 但它**只覆盖那一个脚本**。

★ **最刺眼的几个**（都在 `set -u` 脚本里 ⇒ 一走到那行就死，且**死的往往正是失败/告警分支**）：

## 7. ★ 两次**自造量具缺陷**的复盘（本轮真正的学费）

### 7.1 判据**自证** ⇒ 门在那一格没有牙（M2 首轮 GREEN）

第一版 `nomatch` 子用例的标记词是 `no tests to run` ⇒ 而第 ⑥ 步脚本会把 go test 的输出**原样 `tail -12` 转述**出来 ⇒ **标记词照样出现在 stdout 里** ⇒ **无论脚本有没有真的检测到 no-tests-to-run，门都绿** ⇒ ⇒ 判据自证。

★ **修法**：标记词必须用**脚本独有的诊断措辞**（改成「目标测试名没匹配到任何测试」）⇒ 并加一条**自检断言**：标记词**不得**出现在假 go 的输出里（否则同类漏洞复发）。

### 7.2 红在**错的步骤**上 ⇒ 门空转（第二道探针门首轮红）

### 15.4 ★★★★ 修 `admin` 之前那 2 条红，指向一条**产品级**缺陷（不是测试问题）

**第 1 轮实测（档 B）新增 3 条红**，其中 2 条在 `admin`，原文：

```
admin_500_column_contract_realdb_test.go:179: seed isolated schema: ERROR: function columnar_insert_only_parents() does not exist (SQLSTATE 42883)
session_retirement_http_test.go:97: ERROR: function columnar_insert_only_parents() does not exist (SQLSTATE 42883)
```

★ 注意第一条是 **PASS → FAIL**（档 A 它是 PASS）⇒ ⇒ ★★ **同一道门在两种口径下走的是两条不同的分支**
（档 A 没有 `TEST_ADMIN_500_DSN` ⇒ 走 `LLM_GATEWAY_DATABASE_URL`；档 B 有它 ⇒ 走「隔离 schema」分支）。

**根因（逐条实跑定位，不是推理）**：

1. 在隔离 schema 里逐句执行那条 seed ⇒ **每一句 `CREATE TABLE` 都报同一个 42883** ⇒
   ⇒ ★★★ **`CONTEXT: PL/pgSQL function public.fn_enforce_columnar_event_trigger() line 15 at FOREACH over array`**；
2. 该库有**库级 EVENT TRIGGER** `enforce_columnar_trigger` → `public.fn_enforce_columnar_event_trigger()`；
3. 它的函数体里是 **不加限定名**地调用 `columnar_insert_only_parents()`（该函数**就在 `public`**）；
4. ⇒ ⇒ ★★★★ **event trigger 的函数体按【会话当时的 `search_path`】解析名字**
   ⇒ ⇒ **凡是 `search_path` 不含 `public` 的会话 ⇒ 任何 `CREATE TABLE` 都 42883**；
5. ⇒ 顺带解释了第一条：`LIKE public.session_dim INCLUDING DEFAULTS` 复制进来的 DEFAULT 表达式也变成不可解析。

★ **我自己的假设被实测否掉了**：先判「本地 citus 镜像没有 `columnar` AM ⇒ 环境红」⇒ ★ **实测 `pg_am` 里 `columnar` = 1、`pg_proc` 里 `columnar_insert_only_parents` = 1** ⇒ ⇒ **不是环境缺件，是 `search_path`**。

★★ **仓内早就有人踩过并写下来了**（⇒ ⇒ **这是「已知、被局部绕过、但没根治」的缺陷**）：

| 位置 | 原文 |
|---|---|
| `domains/reportrollup/grainreport_e2e_test.go:209` | 「注意是**追加**而不是覆盖原 search_path：本库装了 citus_columnar…**把 search_path 收窄成只有 scratch schema 会让函数解析失败，建表直接 42883**」 |
| `tools/benchreport/main.go:65` | 「…**columnar_insert_only_parents()**，收窄 search_path 会让建表直接 42883」 |
| `internal/testschema/testschema.go:98` | ★ **公共样板**：`search_path = name + ",public,pg_catalog"` |

⇒ ⇒ ★★★★ **⇒ 也就是说：知道的人都在【自己那一处】追加 `public`（绕过），而根因在产品侧没动**
⇒ ⇒ ⇒ **本轮实测：`admin/` 那两处隔离 schema 就是「忘了追加」⇒ ⇒ 两个测试门红。**

**修法（测试侧，已落地）**：照 `internal/testschema` 的样板改成 `schema + ",public,pg_catalog"`
（`public` 排在隔离 schema **之后** ⇒ **裸名仍优先命中隔离 schema ⇒ 隔离性不受影响**）
⇒ ⇒ ✅ **两条红同时转绿**（`TestInspectorStatsRecycledTodayRealDB` PASS / `TestSessionRetirementHTTPRealDB` PASS ＋ 3 个子角色全 PASS）。

⚠ **诚实边界（产品侧根因未修）**：**event trigger 的函数体仍然是不加限定名的调用**
⇒ ⇒ **任何人再把 `search_path` 收窄到不含 `public`，仍会 42883** ⇒ ⇒ ⇒ **产品级修法属属主决策（P9）**。
