## §4 主修复一：bodies promote 活锁根修（批 500 + 预算 150s）

### §4.1 现象与证据（全部 252 实测）

- 积压：hot 表 10,860 行 / 311MB，`ts < now()-8h` 者 10,765 行，最老 **10-28 21:21**（33h）；
- 杀面：promote 调用 50 次 statement-timeout（`SET LOCAL 60s` 生效形态）+ 6 次
  user-request（Go timeoutCtx 60s 先到）= **每 tick 必死**；
- 重量：队头 5000 行（default 批 `lifecycle.promote_batch_size` 无 KV 行 → 取
  `promoteBatchSize=5000`）的 jsonb 五列 `pg_column_size` 合计 **169MB**
  （均值 34KB/行、max 506KB）；
- **知识丢失链**：R16 fact 85 明载 v1 链批=500（「TOAST 重行防爆量」）⇒ 890 删
  v1 链（R72f/R107 spec 注释预言过「真要保留这组旋钮，正确做法是**改指向会话族
  bodies 链**」）⇒ 614 的会话族 promote 落 default 分支拿 5000。

### §4.2 终态根因与修法

**根因 = 单批物理成本 > 双侧预算**：5000×34KB TOAST 拷贝 + 叶子 7 条索引写放大，
慢宿主（4 核 / load 15-17 / 页写 ~8ms）上单批 6~15 分钟量级，60s（09-22 轮按当时
负载定的值）必死 ⇒ 整批回滚 ⇒ 每 tick 重试同一批 = 活锁。

**修法（代码，`bg/partition_manager.go` + `settings/spec_lifecycle.go`）**：
- `resolvePromoteConfig` 新增 `case "session_bodies_hot"`：保留期语义与 default
  完全一致，只换批 → 专用键 `lifecycle.session_bodies_hot_promote_batch_size`
  （默认 **500**，min 50 / max 50000，HotReload；spec 的 Default 与读方 fallback
  逐字对齐 = R72f 原则）；
- 单批预算 `promoteBatchBudget = 150s`（Go ctx 与 SET LOCAL 同值；周期
  promoteCycleTimeout 5min→10min）；
- 钉子 `TestResolvePromoteConfigSessionBodiesHotBatch`（500 落点 + 不泄漏到
  generic 路径）。

**即时缓解（部署前先止血，已生效）**：252 settings_kv 写
`lifecycle.promote_batch_size=500`（已注册键、每次调用直读 DB 无缓存）→ 手动
superuser 排水 22 批 × 500 行（**每批 18~24s**）⇒ **积压清零（drainable=0）**。
新二进制落地后 bodies 用专用键（同为 500），全局键可回 5000（留给对账轮）。

### §4.3 两次错误假设（本轮最贵的一课，如实记）

1. **假设一「批太大，收 500 即愈」**——不成立：批 500 实测仍 182s（>60s）。
   500 只是成本分母，物理成本仍超预算 ⇒ 需要预算抬升配合。
2. **假设二「叶子零索引是结构缺陷（立 925 heal）」**——**假缺陷，已撤销**：
   「六叶零实体索引」的读数来自**我自己的坏查询**——用 `pg_inherits(inhparent =
   叶子表)` 数索引，而索引附着关系记在**父索引**下（`inhparent = 父索引`），
   该 join 恒空 ⇒ 三个环境全报 0。基于它立了迁移 925、在 252 的 9GB 叶上建了
   **与既有 canonical 唯一索引重复的冗余索引**（ATTACH 报「another index already
   attached」才暴露）。撤销动作：925 文件+五处登记全撤（manifest 回 325 条），
   252 六叶 + 本地四叶的冗余索引全数 DROP（`my_dups_left=0`）。
   **通用式**：★ 数「一张表的索引」必须走 `pg_indexes` 或 `pg_index.indrelid`；
   ★ 「ATTACH 报已附着」是数据库在替你的量具纠错——听到就停，不要绕；
   ★ 假缺陷的修复会真伤生产（9GB 热写路径上的双份唯一索引维护）。
   （925 号未推送过 ⇒ 编号自然回到空闲池。）
