## 四、主修：迁移 951 —— armor_judgments (created_at) 前导索引

**缺陷本体**（bg/audit_trimmer.go，armorBatchSize=5000 × armorMaxBatchesPerTick=20，24h tick + boot 初始 trim，retention 90d）：

```sql
DELETE FROM armor_judgments WHERE ctid IN (
  SELECT ctid FROM armor_judgments WHERE created_at < NOW() - $1::interval LIMIT 5000)
```

表上唯一含 created_at 的索引 `idx_armor_judgments_tenant_time (tenant_id, created_at DESC)` 前导是 tenant_id ⇒ trim 谓词无边界可落 ⇒ 每批整条索引顺扫。
**量化**：471,648 行 / 155MB；quiet EXPLAIN ANALYZE **3,689ms/批**（Index Scan idx_armor_judgments_tenant_time，read=3,219 buffers，90 天外行≈0 时每批白扫证明空集）；pss 累计 calls=52 mean 13.2s + calls=13 mean 18.2s；窗内 ≥10s 慢查 5 条（max 19.1s）。每 tick 至少 20 批 × 3.7s ≈ 74s 纯浪费；表龄跨过 90 天后从「白扫」变「扫完再删」，成本曲线只升不降——非 canary 语义（882 对照），是真 TTL 路径的内在缺陷。
**修复**：`CREATE INDEX IF NOT EXISTS idx_armor_judgments_created_at ON public.armor_judgments (created_at)`（878 款 lock guard：SET LOCAL lock_timeout='60s' + statement_timeout='10min'；down=同名 DROP）。
