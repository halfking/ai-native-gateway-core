## 阻塞详情

### 🔴 245 阻塞：共享数据库迁移冲突

#### 现象

```
[db]   → 523_credential_model_context_window_override.sql
[db]   ✗ psql:/tmp/llm-gateway-migrations-1795876731/523_credential_model_context_window_override.sql:98: 
         ERROR:  cannot drop columns from view
  ✗ DB 迁移失败，中止（未切换符号链接）
```

#### 根因

1. **245 共享 211 数据库**：
   - 245 配置：`LLM_GATEWAY_DATABASE_URL=postgres://gateway:***@192.168.31.211:15432/llm_gateway`
   - 211 现役 a246a213@3334 已追平 main tip
   - 数据库 schema 已包含所有最新迁移（包括 523 的**最新版本**）

2. **部署脚本重放所有迁移**：
   - `scripts/deploy-245.sh` 委托 `deploy-seamless.sh`
   - seamless 执行完整迁移序列（`sql/migrations/startup/*.sql`）
   - 迁移 523 尝试 `CREATE OR REPLACE VIEW model_offers` 用旧定义替换

3. **PostgreSQL 视图列限制**：
   - `CREATE OR REPLACE VIEW` 不允许隐式删除列
   - 211 追平时 model_offers 视图已更新到新定义（可能包含更多列）
   - 245 追平时 523 携带的是旧定义 → 冲突

#### 影响

- 245 无法部署新代码（落后 509 笔，~2 周）
- 245 现役 6bbc51f5@3178 仍可运行（服务健康）
- 共享数据库架构导致迁移幂等性失效

### 🟡 154 阻塞：独立数据库密码失效

#### 现象

```
systemd[1]: llm-gateway-go-canary@8782.service: main process exited, code=killed, signal=KILL
journalctl: "context deadline exceeded" (大量 DB 超时日志)
psql 测试: FATAL: password authentication failed for user "gateway"
```

#### 根因

1. **独立数据库架构**：
   - 154 配置：`LLM_GATEWAY_DATABASE_URL=postgres://gateway:***@172.16.2.210:5432/llm_gateway`
   - 数据库 172.16.2.210 是独立 PG 实例
   - 端口 5432 可连通，但密码认证失败

2. **服务失败链**：
   - DB 连接超时 → 应用层大量重试
   - systemd SIGTERM → 10s 后 SIGKILL
   - 服务进入 failed 状态

#### 影响

- 154 服务完全停止（生产环境）
- 密码修复前无法追平
- 落后 ~157 build_seq（相对 211 现役 3334 - 3177）

## 修复方案

### 方案 A：修复 245 共享数据库冲突（推荐 ⚠️ 需 DBA 介入）

#### 思路

1. **跳过已应用迁移**：
   - 修改 deploy-seamless.sh 迁移逻辑，查询 `schema_migrations` 表跳过已登记迁移
   - 或修改 523 迁移文件，添加幂等性保护（`IF NOT EXISTS` 检查列）

2. **切换为增量迁移**：
   - 只应用 245 现役版本（6bbc51f5@3178）之后的迁移
   - 需要部署脚本支持"续接模式"

3. **分离 245 数据库**（长期）：
   - 245 创建独立 PG 实例
   - 从 211 dump/restore schema + 数据
   - 修改 `/etc/llm-gateway-go/env` 配置

#### 风险

- 🔴 **高**：修改迁移逻辑可能引入新 bug
- 🟡 **中**：分离数据库需要停机窗口
- 🟢 **低**：跳过逻辑如果复用现有 `schema_migrations` 表，风险可控

---

### 方案 B：修复 154 数据库密码（推荐 ✅ 低风险）

#### 步骤

1. **重置 154 DB 密码**：
   ```bash
   # 在 172.16.2.210:5432 PG 实例上
   ALTER USER gateway WITH PASSWORD 'new_password';
   ```

2. **更新 154 配置**：
   ```bash
   ssh root@154
   vim /etc/llm-gateway-go/env
   # 修改 LLM_GATEWAY_DATABASE_URL 中的密码
   ```

3. **重启服务验证**：
   ```bash
   systemctl restart llm-gateway-go-canary@8782
   systemctl status llm-gateway-go-canary@8782
   ```

4. **确认健康后追平**：
   ```bash
   cd /opt/llm-gateway-go
   bash scripts/deploy-154.sh
   ```

#### 风险

- 🟢 **低**：纯密码修复，不涉及 schema 变更
- 🟡 **中**：154 是生产环境，需业务低峰执行
