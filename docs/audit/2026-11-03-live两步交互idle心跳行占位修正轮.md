## 1. 结论（一句话）

**线上 211（v2.5.9 #2944，前端树 `81360f8d9`）对真实请求的两步交互完好
（双视口 18 项断言全绿）；被打破的是 11-02 `7c3632e7c` 引入的 idle 心跳行——
后端 `idle_marker` 本是「泳道安静」瓦片，却被渲染成可点请求行：
点行弹灰态摘要、「查看全景」被 `onOpenPage` 守卫吞掉、行尾 ↗ 也不存在，
低流量时段整页（实测 75 行）都是这种死入口 ⇒ owner 体感＝「点击逻辑坏了」。
修法＝两面板把心跳收敛为一条非交互灰态指示条，请求行只留真实请求。**

## 3. 根因定性

- 后端 `admin/live_stream_sse.go` 的 `idle_marker`：每分钟对安静泳道注入、
  Redis 常驻、delta 同通道下发 —— 设计语义是「泳道空闲**瓦片**」（注释原文：
  "The frontend uses this to decide which lanes need idle tiles"）。
- `7c3632e7c`（11-02）把它渲染进两个请求面板的可点行里：灰态样式 + 延迟/
  token 显「—」+ `idleLane` 标签，同时给 ↗ 加 `v-if="!isIdleMarker"`、
  `onOpenPage` 加 idle 守卫。**方向对（心跳不再当错误开详情），层级错
  （心跳进了「点行＝两步交互第一步」的契约面）**。
- 时序闭环：此前 5 轮「两步交互坏了」的复核全部无缺陷（旧 JS/缓存），
  因为当时每次部署面板里只有真实请求行；2944 上线后第一夜（低流量时段）
  心跳行占满面板，owner 第一次真正点到死入口 ⇒ 本轮投诉。
- **为什么之前没被门抓住**：行为量具（verify_live_two_step_interaction.mjs）
  的靶点（首行/第 24 行）不区分行形态，量具写成时窗口里只有真实行；
  vitest 面板组也没有「心跳不能渲染成行」的判据（7c3632e7c 只带了
  `liveStreamIdle.test.ts` 的形状判定）。

## 4. 修法

1. **`ClientRequestPanel.vue` / `ProviderResponsePanel.vue`（镜像）**：
   - `realRequests` / `realResponses` computed：`isIdleMarker` 过滤；
     行列表、分页（`PANEL_PAGE_SIZE`）、表头计数、翻页越界回退、
     `useNewArrivals` 入场动画全部只看真实请求（心跳不再借「新到达」
     反复触发入场）。
   - 新增**非交互灰态指示条**（`client-idle-strip` / `provider-idle-strip`）：
     复用既有键 `liveTopology.panel.idleLane`（空闲）与
     `liveTopology.panel.idleLaneHint`（tooltip），泳道名去重（左栏按
     `client` 易读名、右栏按 `provider`）最多 4 个 + `+N`，带最新心跳时刻；
     虚线描边（与探测行「不是普通请求」的家族语义同源），无任何 click 绑定。
     **不新增语言包键** ⇒ 不碰 8 语种 key-parity / same-as-source 棘轮。
   - 行级 idle 分支（`statusClass` 的 idle 档、↗ 的 `v-if` 等）**保留不动**
     —— 过滤在上游做完，它们退居防御。
2. **量具 `verify_live_two_step_interaction.mjs`**：
   - 新增 `X1`（`.cp__row.is-idle,.pp__row.is-idle` 必须为 0）与
     `X2`（有心跳信号时指示条必须可见且无 button）——先于真实行门跑，
     心跳占行本身就是被抓的回归，不能被「无流量」截走。
   - 新增 `waitRealRows`（以「↗ 按钮存在」定义真实行，与产品判据同源）；
     窗口内无真实请求行 ⇒ **throw ⇒ exit 3 不可判定**（不是红），
     消息点名「窗口无业务流量」；**用 throw 不用 `die()`**：
     `process.exit` 会跳过视口 `finally` 的 Chrome/profile 清理
     （AGENTS「门被中止时 finally 没跑」教训家族）。
   - `L1b/R1b` 的中部行只在真实行里挑（旧版挑到心跳行 ⇒ L1b/L2/L3 三连假红）；
     `openFreshLive` 与 R3 右栏轮询同步改真实行口径。
3. **vitest（`RequestPanels.test.ts` +5 例）**：心跳不渲染成行（双面板）、
   计数/分页同源过滤、指示条去重+无 button+不产生点击事件、纯心跳时空态
   +指示条、心跳混入不挤掉两步出口（zoom/select/open-page 照常 emit）。
