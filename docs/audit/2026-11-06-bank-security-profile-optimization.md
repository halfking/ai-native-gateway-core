# 银行侧安全接入优化方案（Bank Security Profile）

> 文档日期：2026-11-06  
> 适用仓库：`llm-gateway-go`  
> 场景：融联智云 / 融联金融云 — 银行私有化大模型安全接入（替代跳板机 / 桌面云形态）  
> 对照口径：金规〔2024〕24号《银行保险机构数据安全管理办法》、等保三级、生成式 AI 安全基本要求  
> 状态：方案定稿，待按任务拆解分期落地

---

## 1. 背景与目标

银行侧需要「类似跳板机 / 桌面云的安全效果」，但不想沿用传统形态。正确落点是：

**统一大模型安全接入网关（AI Gateway）**

- 人与 Agent 只连网关，境内外真实 Token 落在融联侧加密机 / 密钥仓
- 用户侧永远拿不到明文 Key
- 调用经审计、脱敏、限流、出境策略
- 部门 / 人员租户与密钥域隔离
- **开发运维不碰业务数据**（只见指标与审计元数据，不见对话与投研正文）

本方案在现有 `llm-gateway-go` 能力上增加 **Bank Security Profile**，以配置开关分期启用硬合规能力，避免推倒重做路由 / 计费 / 会话治理。

### 1.1 成功标准

| 编号 | 标准 | 验收方式 |
|------|------|----------|
| S1 | 运维角色无法读取会话正文 / turn dump | 角色权限单测 + 管理面接口集成测 |
| S2 | 境外模型调用必须过 DLP + 审批 / 白名单 | 路由集成测 + 审计落库 |
| S3 | Bank profile 下 armor / guardian 可 enforce 阻断 | 注入 / 敏感出域用例可拦 |
| S4 | 上游 Key 可对接 HSM/KMS，进程不长期持根密钥 | 适配层单测 + 融联联调 |
| S5 | 敏感操作日志可导出到行内 SOC，留存策略可配 | 导出探针 + 配置验收 |

## 2. 现状盘点（已具备）

| 能力域 | 现状 | 位置 / 备注 |
|--------|------|-------------|
| 租户隔离 | PG RLS + `tenant_admin` 范围；会话 owner 校验 | 数据面 / 管理面 |
| 凭证加密 | 上游 Key AES-GCM / Fernet 落库；`secretmask` 防摘要泄 Key | 进程内 keyring |
| 内容安全 | `security/sanitize`（含 egress）、`outputcompliance`、`promptinjection` | 已接线或可接线 |
| 高危确认 | `approval` / `interception` | 可复用到出境 / 工具调用 |
| Armor | 已挂 `cmd/gateway`，**v1 默认 observe-only，不阻断** | 需 Bank profile 强制 |
| Guardian | 包内有 block / rewrite，**未见完整挂进 gateway 主路径** | P0 接线 |
| 可观测 | 会话审计、OTel / Prometheus、`modelcredibility` | 缺 SOC 导出形态 |
| 路由 | 成本 / 质量两层路由强 | **缺 residency 合规标签** |
| 角色 | `super_admin` / `tenant_admin` / 用户 | **无 ops 盲视角色** |

结论：底座可讲故事；银行 / 融联硬合规差在 **运维盲视、出境闸、防护可强制、密钥外置、分级策略、Agent/MCP 一等公民、SOC 对接**。

## 4. 总体方案：Bank Security Profile

### 4.1 设计原则

1. **开关化**：`bank_security_profile.enabled=true`（或等价环境 / 租户策略）一次性打开银行硬约束默认值，租户可加严不可轻易放松。
2. **不重写主干**：保留现有两层路由、会话治理、计费；只加合规闸与角色边界。
3. **管理面 ≠ 数据面**：运维密钥只能解配置 / 指标；内容解密密钥与运维角色互斥。
4. **默认可审计**：每次策略命中（拦 / 放 / 改写 / 出境）写审计事件，字段不含明文正文（或仅脱敏摘要）。

### 4.2 Profile 默认行为（启用后）

- 管理面：`ops_readonly` 可见指标、配置元数据、审计元数据；**禁止**会话正文、turn dump、明文 Key
- 数据面：armor / guardian **enforce**（可按规则 observe→warn→block）
- 路由：模型必须带 `residency`；`overseas` 必须过 DLP + 审批 / 白名单
- 密钥：优先走 KMS/HSM provider；禁止在日志 / 提示 / Agent 配置落明文 Key
- 审计：默认导出脱敏事件；留存 TTL 按数据分级覆盖产品默认值

### 4.3 逻辑架构（文字）

```
[投研人员 / 部门 Agent / 公共 Agent]
        │  零信任接入
        ▼
┌────────────────── 私有化安全网关（llm-gateway-go）──────────────────┐
│ 身份(人/Agent) → 分级/脱敏 → 注入检测(enforce) → 出境闸 → 路由      │
│                              │                                      │
│              ┌───────────────┴───────────────┐                      │
│              ▼                               ▼                      │
│         境内模型目录                    境外模型目录(+审批)           │
│              │                               │                      │
│              └────────── MCP 工具闸 ─────────┘                      │
│  会话正文加密存储 │ 审计元数据 │ 指标                                 │
└───────────────┬───────────────────┬─────────────────────────────────┘
                │                   │
                ▼                   ▼
         融联 HSM/KMS          行内 SOC / SIEM
                │
                ▼
      开发运维面（ops_readonly）：只见指标/配置/审计元数据
```

## 6. 任务拆解

> 优先级：P0 阻塞银行演示 / 过审；P1 融联联调与规模化；P2 持续合规。  
> 每条任务含：目标、范围、验收、依赖、建议 Owner 角色。

### 6.1 P0 — 必须先做

#### T-P0-01 新增 `ops_readonly` 角色与权限矩阵

- **目标**：开发运维不碰业务数据
- **范围**：
  - 角色枚举增加 `ops_readonly`（及可选 `ops_admin` 仅限基础设施，仍无正文）
  - 管理 API：会话列表 / 详情 / turn dump / 导出 对 ops 角色返回 403 或仅元数据
  - `super_admin` 在 Bank profile 下默认关闭「明文正文」或二次审批 + 全量审计
- **验收**：
  - 单测覆盖角色矩阵
  - 集成测：ops token 调会话正文接口失败；指标 / 健康检查成功
- **依赖**：无
- **建议路径**：`internal/auth` / admin API / RBAC 中间件

#### T-P0-02 会话正文字段级加密（或加密工作区）

- **目标**：即使 DB/备份泄露或超管误操作，正文默认不可读
- **范围**：
  - 会话消息 / turn 内容信封加密；密钥与上游 Key 密钥域分离
  - 解密仅数据面请求路径与「业务授权角色」；ops 密钥环不含内容密钥
  - 迁移：存量明文双写 / 后台回填策略（可分期）
- **验收**：DB 直查密文；授权用户经 API 可读；ops 不可解密
- **依赖**：T-P0-01（角色边界先定）
- **建议路径**：`internal/session` 存储层 + keyring 命名空间

#### T-P0-03 审计 / 管理接口默认脱敏摘要

- **目标**：审计可查「发生了什么」而不是「说了什么」
- **范围**：
  - 审计事件字段：租户、主体、模型、residency、策略命中、决策、哈希 / 长度；正文改为可选且默认关
  - Admin UI / API 默认摘要视图
- **验收**：抽样审计记录无完整 prompt/completion；打开全文需显式权限 + 审计
- **依赖**：T-P0-01
- **建议路径**：audit writer + admin session handlers

#### T-P0-04 模型目录 `residency` 标签

- **目标**：境内外受控路由
- **范围**：
  - 模型 / provider 元数据增加 `residency`: `domestic` | `overseas` | `unknown`
  - `unknown` 在 Bank profile 下禁止路由
  - 管理面可维护；变更进审计
- **验收**：境外模型打标正确；未打标模型请求被拒并记审计
- **依赖**：无
- **建议路径**：模型注册表 / admin registry / 路由前置校验

#### T-P0-05 境外调用合规闸（DLP + 审批 / 白名单）

- **目标**：敏感不出境，出境可审
- **范围**：
  - 路由前：若目标 `overseas`，强制跑 sanitize/egress + 分级结果
  - 策略：敏感级及以上默认拒绝；白名单租户 / 场景可放行；或走现有 `approval`/`interception`
  - 命中策略写审计（含决策原因码）
- **验收**：含客户信息样本出境被拦；白名单场景可放行且有审计
- **依赖**：T-P0-04；复用 sanitize / approval
- **建议路径**：router guard middleware

#### T-P0-06 Armor / Guardian 在 Bank profile 下 enforce

- **目标**：防护从观察变为可强制
- **范围**：
  - Bank profile：armor 允许 block（取消「v1 永不 block」在 profile 下的行为）
  - 将 `guardian` 挂入 gateway 数据面主路径（请求入 / 响应出）
  - 租户策略：`observe` | `warn` | `enforce`，Bank 默认 `enforce`
- **验收**：注入样本 / 敏感出域样本在 enforce 下 4xx/拒绝体；observe 仅审计
- **依赖**：Profile 开关骨架
- **建议路径**：`security/armor`、`security/guardian`、`cmd/gateway` 接线

#### T-P0-07 Bank Security Profile 配置开关与文档

- **目标**：一键（或单配置）启用上述默认硬约束
- **范围**：
  - 配置结构、环境变量、租户覆盖规则
  - `docs/` 运维说明：开启影响、回滚、与融联部署参数
  - 特性开关与回归清单
- **验收**：测试环境打开 profile 后 T-P0-01/04/05/06 行为符合默认；关闭后不破坏现网默认路径
- **依赖**：与各 P0 任务并行，最后联调
- **建议路径**：config + `docs/06-deployment` / `docs/audit`

### 6.2 P1 — 融联联调与规模化

#### T-P1-01 密钥外置 HSM/KMS Provider

- **目标**：对接融联金融特殊设备 / KMS
- **范围**：抽象 `SecretBackend`（env keyring | KMS | HSM）；轮换与短时解包；网关不落根密钥
- **验收**：切换 backend 后上游调用正常；轮换演练；进程内存无长期根密钥（设计评审 + 测试桩）
- **依赖**：融联接口规格
- **建议路径**：`internal/crypto` / keyring

#### T-P1-02 管理面与数据面密钥分离落地

- **目标**：运维拿得到宿主机也无法解业务正文 / 上游 Key
- **范围**：密钥命名空间、权限绑定角色、启动身份拆分
- **验收**：威胁模型评审通过；渗透式配置误用用例失败
- **依赖**：T-P1-01、T-P0-02

#### T-P1-03 数据分级引擎（敏感 / 重要 / 核心）

- **目标**：金规口径标签驱动路由、留存、是否落全文
- **范围**：请求打级；与 sanitize 规则对齐；分级结果进入路由与 TTL
- **验收**：样本分级稳定；核心数据默认禁出境、全文留存策略生效
- **依赖**：T-P0-05

#### T-P1-04 Agent 一等公民身份

- **目标**：Agent 不用借用人员账号
- **范围**：Agent 服务账号、客户端档案、短时凭证、可吊销
- **验收**：Agent 调用带独立主体进审计；吊销后立即失效
- **依赖**：现有 identity / clientprofile

#### T-P1-05 MCP / 工具调用 ACL 与高危确认

- **目标**：工具边界可控
- **范围**：工具级 ACL、参数校验、频率限制；高危动作复用 interception
- **验收**：未授权工具 403；高危工具待确认；回传再脱敏
- **依赖**：T-P1-04；MCP 网关里程碑

#### T-P1-06 模型准入目录与熔断

- **目标**：供应链可控
- **范围**：准入状态、版本变更复测标记、一键熔断切流
- **验收**：未准入模型不可路由；熔断后流量切到备用境内模型
- **依赖**：T-P0-04、modelcredibility

---

### 6.3 P2 — 过审与运营

#### T-P2-01 审计导出 SIEM（CEF / Syslog / Kafka）

- **目标**：对接行内 SOC
- **范围**：导出适配器、字段映射、脱敏、重试与背压
- **验收**：测试 collector 收到完整决策事件；无正文泄露
- **依赖**：T-P0-03

#### T-P2-02 留存策略对齐银行年限

- **目标**：敏感 ≥1 年、核心 ≥3 年；防篡改存证可选
- **范围**：分级 TTL、归档存储、哈希链或 WORM 对接点
- **验收**：配置与金规表一致；过期删除演练有记录
- **依赖**：T-P1-03

#### T-P2-03 异常调用告警与抗滥用加强

- **目标**：配额打满、注入峰值、出境拒绝激增可告警
- **范围**：告警规则、通知渠道、与现有 Prometheus 对齐
- **验收**：故障注入可触发告警工单 / webhook
- **依赖**：T-P2-01（可选并行）

#### T-P2-04 过审材料包

- **目标**：招标 / 行方评审可直接用
- **范围**：架构图、数据流、密钥、角色矩阵、日志字段、留存、应急切换 Runbook
- **验收**：内部预审一次无结构性缺口
- **依赖**：Phase 1–2 主体完成

## 7. 非目标（本阶段不做）

- 为银行单独重写路由算法或计费引擎
- 做成传统 VDI / 跳板机 / 桌面云
- 在网关内实现完整行内 IdP（对接即可）
- 替换现有多租户 RLS 模型

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 正文加密迁移影响性能 | 延迟 / CPU | 异步回填；仅热点字段加密；基准测试 |
| enforce 误杀业务 | 可用性 | 先 shadow 一周对比；租户灰度；快速回滚开关 |
| 融联 HSM 接口延期 | P1 阻塞 | 先完成 Provider 抽象 + 软件 KMS 桩 |
| super_admin 例外口子 | 合规失败 | Bank profile 默认收紧 + 每次解密强审计 |
