部署 211 时撞出的上游阻塞缺陷

A14 · 已修 · 影响三台

现象

部署在 DB 阶段 FATAL 中止：994 … 本轮按指纹认账但其产物缺失 ⇒ f。
切流前中止 ⇒ 线上无中断。

台账一旦有 994 行，211/154/245 每次部署都会必然失败。

根因

探针用 information_schema.columns 查物化视图的列，而 PG 的 information_schema 只含表/视图，不含 MV ⇒ 恒得 0 行 ⇒ 探针恒假。

真库实测：information_schema 0 行 / pg_attribute 18 列且 end_user_count 存在 ⇒ 产物早已齐全，是探针在撒谎。

修法与验收

MV 的列改走 pg_catalog（pg_attribute+pg_class+pg_namespace）；session_dim 是真表 ⇒ 保持不动。

验收＝探针取值本身：修复前实测 f ⇒ 修复后实测 t（不采信「脚本说 OK」）。
