# 供应商返回自动调策：全链审计 + 「网关智能体」必要性裁决（2026-10-14）

> 用户目标拆解：① 对「供应商报错自动甄别→调策」任务做审计；② 修正发现的问题；
③ 自动根据供应商返回调整策略并**记录复用**，提高成功率；④ 裁决「是否需要增加一个
网关智能体来自动处理网关错误信息」，学习一个方案后继续。
> 结论先行：**①②③已闭环（r1020→r1028 八轮修复 + 五层策略引擎），④裁决为
「不需要热路径 LLM 智能体」**——确定性策略引擎更快、更便宜、可判据化；智能体
的正确位置在**离线**（异常台账的模式挖掘），不在请求路径。本轮在活网关实测
复用链生效（见 §三）。

## 一、审计：网关已有的「供应商返回→调策→记录→复用」五层架构

| 层 | 实现 | 触发时机 | 实例 |
|---|---|---|---|
| L0 参数预检 | `internal/paramguard` + `reasoncap` 能力表 | 出站前静态钳制 | grok-4.6 `reasoning_effort:xhigh`→钳到 high（r1026b，400 报错原文实证） |
| L1 方言适配 | `internal/paramreg`（RejectedBy/翻译）+ `transformation.AdaptChatParamsToResponsesWire`（r1027） | 出站前按目标线格式改写/裁剪 | `thinking`→`reasoning.effort` 翻译；`logprobs` 系 native responses 腿删除；`stream_options` 三泄漏口守卫（r1026/r1026b） |
| L2 错误分类 | `errorsx/classify.go`（25+ ErrorKind × 双分类器同臂） | 上游响应到达 | json-word 契约 400→client_bug 止住节点冷却级联（r1027）；`Operation not allowed`→unsupported_feature 快速转移 |
| L3 反应层 + 学习 | `internal/reqprobe`：Diagnose（点名正则+方向甄别）→ StripParams（wireKeyAliases）→ 免费重试 → 24h 滑窗学习 | 上游 4xx 点名后 | Bedrock `output_config.effort` 三断链修复（r1027）；多轮剥参上限 3（P7）；学习后 `applying learned param strips` 前置剥参 |
| L4 动作策略 | `errorsx/action_policy.go` DecideNextAction（commit-state 感知） | 每次失败后 | retry_same_node / switch_node / wait_recovery / fail_terminal 按已提交状态投影 |

**记录面**：Redis db2 `llmgw:reqanom:records`（管理面 request-anomalies 表格，
含 occurrences/recovered_count/resolved/param/suggest_mode）——即用户所指
「格式错误的表」。**复用面**：同 (provider,raw_model) 24h 内免再探直接前置剥参。

1. **无需新增修复**：r1027/r1028 之后，已实测的供应商拒绝形态全部有主

   一次性验证，而是常驻行为。

## 四、裁决：网关智能体（LLM agent）**无必要**，方案=确定性策略引擎

| 维度 | 热路径 LLM 智能体 | 现行确定性引擎（已落地） |
|---|---|---|
| 延迟 | +1~5s（每次错误多一轮模型调用） | 毫秒级（正则+查表+免费重试） |
| 成本 | 每错误一次 LLM 计费 | 零增量（最多多一次上游调用） |
| 可预测性 | 不可判据化（模型输出漂移会破坏语义） | 全链有单测+变异验证（r1027 三套判据） |
| 复用 | 需外部记忆注入 | 24h 滑窗自动学习 + 台账常驻 |
| 失败模式 | 智能体幻觉→错误剥参/错误换向 | 保守 fail-open，误伤面已审计 |

**「学习一个方案」的答案**：本仓 2026-10-14 已落地的 reqprobe 五层方案就是
业界标准做法（错误分类→定向恢复→记录→学习复用），与 LLM 网关领域通行的
「provider adapter + retry policy」架构同构，不需要引入运行时智能体。

**智能体的正确位置（登记，不在本轮实施）**：对格式错误表中 `upstream_error`
（供人工分类桶，当前 #31 一条）做**离线**模式挖掘——批量聚类新错误文案、
提议新词表条目/别名，经维护者审核后进 diagnose 词表。这是「agent 辅助运营」
而非「agent 在网关里」，不引入热路径不确定性；待 owner 需要时另立轮次。
