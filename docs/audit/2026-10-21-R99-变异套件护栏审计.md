## 2. 自查：我方门 B 的护栏现状

⇒ ⇒ R98 轮的门 B（`scripts/ursmcheck/pipefail_race_tool_mutation_test.go`）里，变异施加处已有两道护栏：

| 护栏 | 作用 | 强度 |
|---|---|---|
| **锚点唯一性** | `strings.Count(src, m.old) != 1` ⇒ `t.Fatalf` | ★★★ 强（锚点改到别处会立刻失败） |
| **锚点唯一性自检测试** | `TestPipefailRaceToolMutationAnchorsStayUnique` | ★★★ 强（量具措辞变了会红） |

⇒ ⇒ ★★★ **但是**：这两道护栏都只回答「**改到的是不是我以为的地方**」
⇒ ⇒ ⇒ **没有一道回答「**改了吗**」**
⇒ ⇒ ⇒ ⇒ **缺口就在这里**。

### 2.1 ★★ 缺口实测（不靠推理）

⇒ ⇒ 构造一条 `old == new` 的变异（其余完全正常）：

```go
src := "AAA"
old, nw := "AAA", "AAA"   // ← 变异写错：old 与 new 逐字相同
n := strings.Count(src, old)          // ⇒ 1（锚点护栏通过）
mutated := strings.Replace(src, old, nw, 1)
fmt.Printf("anchor_hits=%d  mutated==original? %v\n", n, mutated == src)
// ⇒ 实测输出：anchor_hits=1  mutated==original? true
```

⇒ ⇒ ★★★★ **⇒ 「锚点命中 1 次」这道护栏在 `old == new` 时照样放行**
⇒ ⇒ ⇒ **⇒ 变异**没有发生**，而门会绿**
⇒ ⇒ ⇒ **⇒ 这不是「风险」，是「已经存在的静默失效」**（当前 5 条变异的 `old`/`new` 确实不同 ⇒ **尚未触发**）。

⇒ ⇒ ★★ **注意与 peer 的差别（口径要写清）**：
- **peer 的形态**：变异**脚本**用 `sed` + `\t` ⇒ 替换串与原串**不等价于预期**，但文件**确实被写过**（只是内容没变）
- **我的形态**：变异定义本身 `old == new` ⇒ `strings.Replace` 是**恒等替换** ⇒ 文件**根本没被改**
- ⇒ ⇒ ★ **两者是同一个失效家族：「变异没真的发生 ⇒ 门绿」**，只是**上游成因**不同。

## 3. 修法：把护栏做成**可判定的纯逻辑**

⇒ ⇒ ★★★ **关键设计约束**：护栏若只存在于 `t.Fatalf` 分支里 ⇒ 要测它就只能靠「子测试失败」
⇒ ⇒ ⇒ **而子测试失败会连带把父测试标红** ⇒ ⇒ **那条测试永远红** ⇒ ⇒ **恒红门**
⇒ ⇒ ⇒ ⇒ **⇒ 所以：护栏必须是「可返回错误的纯函数」** ⇒ ⇒ ⇒ **它的「有牙」才能被【正面判定】**。

⇒ ⇒ 落地形态：

```go
// r98ApplyMuts：施加变异 + 全部护栏 ⇒ 返回 (新源码, 错误)
//   护栏①：锚点必须恰好命中 1 次
//   护栏②（★ 本轮新增）：替换后必须与替换前不同 ⇒ 否则「变异没有真正发生」
func r98ApplyMuts(src string, muts []r98Mut) (string, error)
```

⇒ ⇒ `r98MutateTool` 退化为「调用它 + 出错就 Fatal」⇒ ⇒ **原 5 条变异的调用点一字未改**
⇒ ⇒ ⇒ ★ **零行为变化**（门 B 的 7 条断言语义完全不变）。

### 3.1 新增测试：`TestPipefailRaceToolMutationSelfCheckHasTeeth`（门 B 第 8 条）

⇒ ⇒ **它测的是【护栏自己】，不是量具** ⇒ ⇒ 三条断言：

| # | 断言 | 形态 |
|---|---|---|
| ① **阳性** | `old == new` 的假变异 ⇒ **必须被拒绝**（返回错误 + 空源码） | ⇒ 缺护栏时**必红** |
| ② **阴性** | 一条**真的会改**的变异 ⇒ **必须被接受**（输出确实变了） | ⇒ 护栏不是「逢变异必杀」 |
| ③ **锚点** | 命中多次的锚点 ⇒ **必须被拒绝** | ⇒ 护栏① 也有牙 |

⇒ ⇒ ★★ **断言形态的选择很关键**：断言① 若写成「变异后门抓到了它」⇒
⇒ ⇒ **在 `old == new` 时永远不可能发生**（工具没被改 ⇒ 它当然通过）⇒ ⇒ **恒绿门**
⇒ ⇒ ⇒ **所以必须断言「护栏在施加时拒绝了它」** ⇒ ⇒ ⇒ ★ **判别形态必须与被测形态同构**。

## 4. 变异验证：护栏自己必须有牙

⇒ ⇒ ★★ **两次变异都必须是【断言红】，不能是【编译红】**（R65 轮教训：**编译红 ≠ 断言红**）

| 变异 | 做法 | 结果 |
|---|---|---|
| **M1'** | 把 `if src == before` 改成 `if src == before && len(m.name) > 1000` ⇒ 自检永不触发 | ★ **断言红**：报「护栏没有牙：假变异被静默接受」 |
| **M2'** | 把 `if src == before` 改成 `if src != before \|\| src == before` ⇒ 护栏变成「逢变异必杀」 | ★ **断言红**：报「阴性对照失败：真变异被拒了」 |

⇒ ⇒ ★★ **第一次试错**：M1 直接写 `if false {` ⇒ **编译红**（`declared and not used: before`）
⇒ ⇒ ⇒ ⇒ **那条读数作废**（编译红说明不了断言有牙）⇒ ⇒ 改用 `&& len(m.name) > 1000` ⇒ **编译干净** ⇒ 重测。

⇒ ⇒ ★ **还原核对**：两次变异后把文件还原 ⇒ **md5 逐字一致**（`de6533ff5d62f94dcc8a5ada25c5d61a`）
⇒ ⇒ ⇒ **还原校验必须校验【被改的那个路径】**（R65 轮教训：拷到仓库根目录 ⇒ 源文件从未还原 ⇒ 读数作废）

⇒ ⇒ ★★ **还原后复跑**：门 B **8 条全绿**（`ok 23.158s`）。

## 6. 诚实边界

1. ★ **本轮的缺口在护栏层面，当前 5 条变异并未触发它**（它们的 `old`/`new` 确实不同）
   ⇒ ⇒ 本轮是**补一道缺失的护栏**，**不是**「修一个正在发生的故障」⇒ ⇒ **收益当前不可观测 ⇒ 不夸大**。
2. ★ **护栏自检测的是「护栏拒绝假变异」**，**不是**「假变异会让门红」
   ⇒ ⇒ 因为后者在 `old == new` 时**永远不可能发生** ⇒ ⇒ 断言必须落在「护栏拒绝」这一侧。
3. ★ **peer 的具体踩坑（BSD `sed` 不解释 `\t`）对我不适用**（我走 Go 的 `strings.Replace`）
   ⇒ ⇒ 本轮落地的是**通用形态**（「变异可能没真的发生」），**不是**复现 peer 的那个成因。
4. ★ **变异自检与 peer 的 md5 自检强度不同**：md5 只能证明「变了」；
   ⇒ ⇒ 本轮的做法是**在施加时**就断言「变了」⇒ ⇒ 不存在「先写错、后才发现」的空窗。
5. ★ **本轮只动了门 B 一个文件** ⇒ ⇒ 量具、台账、门 A 的语义**一字未改** ⇒ ⇒ **零回归面**。
6. ★ **并行会话 R95 轮·段 B 的产品库名台账（`4eadc06a3`）与本轮无交集**
   ⇒ ⇒ 本轮**未触碰** `scripts/ursmcheck/product_db_name_ledger.tsv` 与 `product_db_name_ledger_test.go`。
