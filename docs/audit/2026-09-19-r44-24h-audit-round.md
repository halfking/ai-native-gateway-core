## §三、本轮事故与教训

**"SQL 模板免检"陷阱（本轮最重要教训）。** 两个分析 SQL 是窗口内本地会话交付的（cc013e68d/5815184f2），交付时未在真库实跑——`providers.name` 这种**一执行就 42703** 的硬失败、和"只查母表"这种**数字系统性偏小 13.6%** 的软失败，都在本轮真库首跑时当场暴露。Go 侧有 build/test 三门兜底，SQL 模板的等价门就是"真库 psql -f 实跑"。教训入册：**任何入库的 .sql 模板（含 scripts/analysis、scripts/audit），commit 前必须在本地真库实跑一遍**——与迁移三纪律 #1 同源，只是对象从迁移扩展到分析模板。已回注 D07 域文档。

**子代理的"契约权威性"自觉上报值得信任并复用。** D11 子代理发现自己派发词（"低于阈值回退"）与 commit message（"全继承 LLM 契约"）存在两种解读时，没有擅自定级而是并列证据上报。亲读裁决按意图基线（Jev 调研的"置信度门"定式）+ 放大面（intentCache 会话级粘滞）定为 P2 修复，且修在 decider 层而非 classifier 层——修错层会把低置信误计为熔断失败打开熔断。子代理找线索、主代理定裁决与层面的分工再次验证。
