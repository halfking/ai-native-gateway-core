## § ④ 新发现：第四类归因＝「rename detection 吃掉上游新增文件」

现象：合并后上游的 sql/migrations/startup/055-058 与 embeddata/055-058 在工作树里消失。

根因（实测）：
1. git ls-tree $(git merge-base HEAD origin/main) sql/migrations/startup/ → 无 055-058
   ⇒ 它们是上游在 base 之后【新增】的
2. 但 git 的 rename detection 把上游【新增】的 055_teams_table.sql 误判成
   「我方 1000_teams_table.sql 的改名」
3. ⇒ 上游那四个文件的内容被【合并进】我方那四个文件，而不是作为新文件落地
4. ⇒ 随后 git rm 掉 1000-1003（判定为退役）⇒ 上游的 055-058 随合并一起消失

⇒ 通用式：「合并后清理某一族文件」这个动作本身可能是【合并引入的删除】
⇒ 清理后必须逐个 ls 确认【上游那棵树】里那族还在
