# 211 统计 V2 与离线升级复审

复审基线为发布分支 `3f26861c2`，211 的已验收版本为 `6f099525`、构建 3274、槽 a。发布、账期还原和稳定窗口的原始读数见[发布验收](2026-11-25-211-statistics-v2-rollout.md)。本轮仅在本地验证修复。

## 发现与修复

- 旧离线包按数字编号收集、执行迁移，依赖字母后缀的资产未全部收进包，973 会先于创建表和扩展列的 983、983b。新包从安装器启动清单按原顺序收集 408 件 SQL。安装器校验清单和文件后复用增量迁移及台账判断，遇到空台账立即停止。三份 973 正向资产的 SHA-256 仍为 `287647400087da6ec2512da3acc0c51d2f1e7f4d8b43a3c7d51ceb4f76e92adf`，本轮没有 SQL 差异。
- 旧 Compose 执行器加载镜像后只执行 `restart`，现有容器仍使用旧镜像。新包记录镜像 ID，安装器核验加载结果和实际运行容器，只重建网关服务。切换失败恢复旧镜像、`.env` 和 `app/VERSION`。已提交的数据库增量保留，由台账控制重跑。新包需要支持 `installer-startup` 的安装器。
- 稳定窗口里两次 V2 会话总览 500 有明确的 `context canceled` 原因。同窗口热门模型也有一次 500，原日志未记录其错误原因。两条读路径现在都用 499 记录客户端取消，并保留服务器超时和数据库错误的原有处理。

## 复核边界

- 用合成二进制和镜像输入运行实际打包脚本。压缩包内 408 件迁移的顺序与安装器清单逐项一致，410 个文件及整包的 SHA-256 均复核。安装器回归用命令替身验证了从读取压缩包、迁移分发到镜像切换和健康失败回退的流程。
- 本轮 Docker Desktop socket 的 `_ping` 与容器查询均超时。211 同源隔离库原始备份与历史台账保留，发布修复仍需在 Docker 恢复后跑真实镜像、历史库、重复升级和失败退回。此前安装器直升与部署通道交接的原始核验见[发布验收](2026-11-25-211-statistics-v2-rollout.md)。
- 最新已查主干 `490524452` 的[裁决记录](../2026-11-25-待owner裁决清单.md)明确两条旧 V2 分支暂不合入。本轮审计以已经在 211 验收的 973 分支为基础。后续如获整合授权，保留 973，避免把同源投影 983d 一并送入迁移通道。
