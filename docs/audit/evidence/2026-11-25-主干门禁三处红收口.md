## 三、红②：监控脚本「量具不可用」被写成 shell 级崩溃

### 3.1 根因

- 两个脚本用 `date -Is`（**GNU coreutils 专有**）取时间戳 ⇒ BSD/macOS 的 `date` 报 `invalid argument 's' for -I`。
- 更要紧的是：`$PSQL_CMD` 的默认形态是 `docker exec ... psql ...`；本机没有 `docker` 时，bash 直接打印 `docker: command not found` ⇒ 被契约门的 `shellFatal` 正则判成「脚本崩在 shell 层」。
  ★ 退出码其实是 3（契约内的「量具不可用」），**但那行 shell 级报错签名会把它伪装成崩溃** —— cron 里读起来就是「脚本崩了」。

### 3.2 修法（照抄**同目录既有标准形态**，不新发明）

- 本目录另两个脚本（`pg17-pg-availability-check.sh` / `pg17-onconflict-constraint-check.sh`）**早就有**同一问题的标准修法，本轮直接沿用其形态：
  - `now_iso() { date +%Y-%m-%dT%H:%M:%S%z; }`（GNU/BSD 通用）
  - `check_toolchain()` 量具预检：取 `PSQL_CMD` 的**首词**，`command -v` 找不到就 `exit 3` 并**说人话**
- 落点：`scripts/252-monitor/pg-table-bloat-check.sh`、`scripts/252-monitor/ursm-snapshot-payload-bloat.sh`。

### 3.3 实跑读数（按契约门的环境变量实跑）

```
$ env LC_ALL=C LANG=C LLMGW_PG17_CONF=/nonexistent/pg17.conf PG17_CONTAINER=definitely-not-a-container bash ../252-monitor/pg-table-bloat-check.sh
2026-11-25T04:44:15+0800 ABORT: 量具不可用 —— 找不到 'docker'（PSQL_CMD 的第一个词）。本次不出结论。
2026-11-25T04:44:15+0800    在 252 上它由 docker 提供的 PG17 容器执行；本机没有 docker 就跑不了，属正常。
EXIT=3
```
（另一个脚本逐字同形。）

⇒ 退出码 3 ∈ 契约 {0,1,3}；输出无 `command not found` 等 shell 致命签名；「量具不可用」说清了是哪件量具不可用。

## 四、红③：会话 WAL 回放用例停留在旧生产契约

## 七、第 6 处（复跑新暴露）：rowsguard —— 4 处 rows 循环缺迭代终检（静默截断）

### 7.1 现象与归因

```
--- FAIL: TestEveryRowsLoopIsGuarded
    unguarded rows loop: admin/analytics_queries.go:403        (queryCrossErrors, recv=rows)
    unguarded rows loop: admin/usage.go:1756                   (usageTopRankings, recv=rows)
    unguarded rows loop: cmd/user-admin-tool/main.go:70        (listUsers, recv=rows)
    unguarded rows loop: domains/errorplaybook/logcontext.go:85 (Gather, recv=sampleRows)
```

- 对拍树实测：`origin/main` 上**同样 4 处**、逐字一致 ⇒ **主干存量红**。
- 缺陷面：迭代中断（连接断开 / 服务端错误）时 `rows.Next()` 会**提前返回 false** ⇒ 不看 `rows.Err()` 就会把**半截结果**当成完整结果交出去（silent truncation）—— 看板少了几行、日志分析材料少几条样本、运维 CLI 打印半截用户表却退出码 0。

### 7.2 修法（补终检，**不加豁免**）

| 落点 | 处置 |
|------|------|
| `admin/analytics_queries.go`（`queryCrossErrors`） | 循环后补 `if err := rows.Err(); err != nil { return nil, false }` ⇒ 与本文件另两处循环逐字一致 |
| `admin/usage.go`（`usageTopRankings` · TopAPIKeys 臂） | 循环后补终检；失败口径与本函数其它分支一致（`slog.Warn` ＋ `Degraded=true` ＋ `DegradedReason`）⇒ 不静默少几行 |
| `cmd/user-admin-tool/main.go`（`listUsers`） | 循环后补 `rows.Err()` ⇒ `log.Fatalf` 退出 ⇒ 不再「打印半截用户表、退出码 0」（与同函数扫描失败口径一致） |
| `domains/errorplaybook/logcontext.go`（`Gather` · 消息样本臂） | 循环后补终检；口径与「样本查询失败不致命」一致（样本是补充材料、分布已完整），但**不静默** ⇒ 把「样本读取中断：样本内容不完整」写进材料 |

> ★ 为什么**不**走豁免表：豁免表只用于「one-shot/main 包、不在 R66 口径内」这一类**语义待裁决**站点；这 4 处都能直接补终检（改动 2–8 行）⇒ 补终检比豁免更保守（不扩大豁免面），也更符合该门「防的是完全没人看 `Err()`」的设计意图。
