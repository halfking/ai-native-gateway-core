## 子代理审计发现（本会话关键产出）

两个并行 Explore 子代理审计 `5486952e8` 前身提交 + 远程 nodeProbeLock 实现，发现：

1. **P0 批量路径绕锁**：`healthCheckAllNodesInner` 的 `BatchUpdateNodes`
   快速路径（PgStore 单事务）在 per-node 锁外执行——全局探活 apply 后释放
   锁，单节点探活在间隙内落库新状态，批量事务随后用旧快照覆盖之，失败计数
   丢失。测试只覆盖 fake store 的降级路径，从未触达该快速路径。
2. **P0 读-改-写不原子**（重建守门测试后暴露）：三个单节点路径的 `GetNode`
   在 `nodeProbeLock` 外执行。并发各自读到 CF=0 → 锁内各写 CF=1，N 次失败
   只记 1 次。锁只保护了写，没保护读。
3. **锁泄漏**：`HealthCheckSubscriptionNow` 错误路径 `continue` 跳过 Unlock。
4. **#6 缺口**：`swapProbeOne` / `healthCheckAllNodesInner` 无 pwd-decrypt
   过滤，密文密码探测触发 407 + 静默消耗失败计数。

## 最终状态（合并后 main 的实现）

| 修复 | 实现 |
|---|---|
| #3 并发写竞态 | `nodeProbeLock`（sync.Map[nodeID]*sync.Mutex）；**四个入口的 GetNode→skip→probe→apply→UpdateNode→cache→record 全序列在锁内**；全局路径锁内取新鲜快照后原子落库+写缓存，锁外批量阶段删除 |
| #6 统一跳过闸门 | `shouldSkipForHealthCheck`（skipReason: status/undialable/password_decrypt_failed）；HealthCheckNode / HealthCheckSubscriptionNow / swapProbeOne / healthCheckAllNodesInner 四处共用；pwd-decrypt 统一 IncPasswordDecryptFailed + 计入 Skipped |
| #9 transactional refresh | `PgStore.RefreshSubscriptionAndMetadata`（远程 `b8d686267`） |
| #10 Start 不持锁跨 DB | 远程 `30293f256` |
| #11 swap tick ctx | 单次 tick 独立 30s timeout，Stop 即时取消 in-flight 探测 |

| BatchUpdateNodes | manager 不再调用（锁内逐节点取新鲜快照替代）；方法保留为公共 API，零生产调用方 |

## 教训

- **审计报告必须由守门测试背书**：远程并行修复落了 nodeProbeLock，但"锁只
  保护写不保护读"——只有重建并发守门测试（-race + 精确计数断言）才暴露
  读-改-写缺口。光看代码"有锁"不等于"原子"
- **fake store 模型决定测试有效性**：测试桩自带全局锁会掩盖被测代码的竞态；
  桩必须模拟真实语义（快照隔离 + 无锁落库 + per-node 并发观测）
- **并行会话同仓工作**：远程与本会话同窗口修同一批缺陷，先 fetch 比对再
  适配补齐（而非盲目 rebase/revert），最终以合并后代码为准逐项核对
