### 7.2 部署轮新发现并修复的 4 处 deploy-lib Windows 缺陷（SSOT `~/workspace/ai-native-tools/deploy-lib`，已同步 252）

本机此前从未成功跑过 245/154 部署链（deploy-lib/envs 两个仓外 SSOT 缺失）。
从 252 拉回 SSOT 后暴露 4 处 Windows-only 缺陷，逐个修掉：

| # | 缺陷 | 机制 | 修法 |
|---|------|------|------|
| D1 | `ssh_run` 在 set -e 下静默死 | `output=$(ssh ...)` 赋值状态=替换状态 ⇒ attempt-1 的 mux-reset rc=255 直接杀死脚本（Linux 首连即成 ⇒ SSOT 未暴露） | `\|\| exit_code=$?` + 循环头 `exit_code=0` 复位 |
| D2 | `ssh_run_pipe` 永不重试 | stderr 被 `>/dev/null 2>&1` 丢弃 ⇒ classify 看不到 "Connection reset" 关键字 ⇒ 一律 fail | stderr 落临时文件供分类 |
| D3 | 重试时 stdin 已被消费 | 第 1 次 ssh 吃掉 heredoc ⇒ 远端 `bash -s` 读空脚本静默 exit 0 ⇒ **锁假成功** | stdin 缓冲到临时文件，每次重试整流重放 |
| D4 | bundle sha256 校验恒失败 | Windows sha256sum 默认**二进制模式**（` *name`），Linux 是文本模式（`  name`）；verify 前置 grep 只认后者 | 前置 grep 兼容 `(  \| \*)$bin_name$` 两种合法格式 |

（D1/D3 修复后手工验证：mux-reset 进重试、远端锁真实创建；D4 修复后
`sha256sum -c --strict` 远端 0 非 OK。三处均同步 252 的 SSOT——Linux 成功路径零行为变化。）

## 8. 本轮通用式（LESSONS §569）

1. ★★★★★ **bot 的「go build ✓」必须用本机重测**——它建立在其工作区未提交的包上
   （幽灵 import 直接进 main）。
2. ★★★★ **量具的路径口径在 Windows 必须归一**（Go `filepath.ToSlash` /
   TS `replace(/\\/g,'/')`）：正斜杠字面量 vs `Rel/join` 产物在 Windows 上
   **永不相等** ⇒ 门全瞎（本轮 7 处同族：Go 门 2 + scanner 2 + vitest 门 5）。
3. ★★★★ **Windows 的 exec 链路有两层隐藏转换**：argv 经 CreateProcess 字符串往返
   （复杂脚本必须落盘执行）；env 值经 MSYS 链路被 C 转义吃掉（钉子路径必须正斜杠）。
4. ★★★ **Windows 上 `Path.home()` 走 USERPROFILE 不走 HOME**——凡是「用 env 钉
   home」的测试必须同时钉 USERPROFILE/APPDATA/XDG_CONFIG_HOME，否则测试写穿到
   真实用户配置（本轮实测泄漏）。
5. ★★★ **python3 在 Windows 不可信**（shim 脚本 + Store stub 双劫持 LookPath）——
   解释器必须真跑 `--version` 验明正身，缺位时显式 SKIP 而非假红。
6. ★★★ **「同一生产告警」要在真库 A/B 下判决**：modelbinding 的旧序/新序在
   credential 19 上各跑一遍（旧=错 / 新=对），比读代码更硬。
7. ★★ **修共享判据先枚举消费方**的镜像版：**修测试夹具先找唯一入口**
   （callTurnDetail 单点开 consent，而不是 9 个用例各贴一遍）。
