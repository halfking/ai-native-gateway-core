## 二、核实为健康的面

- **F1 核心（成功终态 outcome 回填）健康**：ReportRoutingOutcome 门（handler.go:6190）只要求 IsAutoRequest——成功路径经 5657 传播后确实发射；DB 侧 UPDATE 全 COALESCE（client.go:1963-1968），INSERT 首行（handler.go:7006 applyAutoRouteFields）写入的 task_type/auto_decision 不会被成功 UPDATE 抹掉——settle/accuracy 的 SQL 口径（bg/auto_route_settle_worker.go:284、bg/auto_index_refresher.go:553）不受 #1 的内存丢失影响。
- **失败路径 TaskType 来源清晰**：BuildFailureEntry→applyAutoRouteFields（request_log_pipeline.go:1020→493-495），源头 SetAutoDecision（756-762，wire.TaskType 由 relay 解析 model=auto 时生成）。
- **具体模型影子轮不污染 auto outcome/orphan**：IsAutoRequest=false → 不调 ReportRoutingOutcome（无 orphan 计数）；也不进 settle（selections 只由 auto 决策产生）。
- **影子轮防自链**：model=auto 影子轮置 logCtx.IsAutoRequest → shouldSkipAutoTitleGeneration/Summary（handler.go:6290-6292, 6317-6319）阻断 title/summary 链式自触发。
- **回放契约**：所有合成 body 的小写 "auto"（mode_hook.go:772、goal_specs 默认值），无大小写混用绕过。
- **窗口内数据管道三缺陷基线/ML-ONNX/新 RFC 零接触**：diff 名单（上述 5 文件）与 autoroute/routingopt/ml-training/modeliqdata/bg 无交集。
