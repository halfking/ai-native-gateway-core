## 二、核实为健康的面

- **影子轮落库链（主代理线索 1）完整可 JOIN**：buildFollowUpRequest 设头（response_interceptor_helpers.go:226-243）→ 回环 `h.ServeHTTP`（不穿 origin 中间件，头不被覆盖，handler.go:1665-1673）→ 入口读入 logCtx（handler.go:1726-1731）→ 三处落库点均应用 `applyParentCorrelationFields`：初始行 recordInitialRequestLog（handler.go:6997）、终态 buildEntry（request_log_pipeline.go:1024）、成功终态 upsert 再应用（handler.go:5642，2026-08-15 修复防止 ON CONFLICT 用 NULL 覆盖）→ `request_logs_hot.parent_request_id/origin_actor` 列（telemetry/client.go:1175,1341,1394）。session_turns 侧同样落：mirror 转换 `ParentRequestID/OriginActor`（internal/sessionv2mirror/hook.go:264、s1a_fields.go:112）→ `session_turns_hot` 列（domains/session/v2/turn_writer.go:316,342）。SQL `child.parent_request_id = parent.request_id` 可 JOIN。
- **requestID 变量来源（主代理线索 3）确为本次客户端请求**：两处调用点都在 `serveWithExecutor` 内，其 `requestID := logCtx.RequestID`（handler.go:1993），logCtx 由 `serveHTTPInner` 以入口 requestID 构造（handler.go:1694-1708，`NewRequestLogContext` 拷贝赋值 request_log_pipeline.go:359-366）；窗口内无对 logCtx.RequestID 的再赋值。且与 `interceptReq.RequestID`（handler.go:5116）同源。空串不可能（1694-1698 保底 generateRequestID）；即便为空 buildFollowUpRequest:238 优雅省略头。影子轮自身 request_id 为新生成（合成请求不带 X-Request-Id），父子不撞键。
- **goal_continue/goal_model_switch 影子轮不会被 isInternalAutoEntry 吞**：body 携带具体模型名（buildContinueMessage 用已解析的 ClientModel/modelOverride，mode_hook.go:753-766），不触发 model="auto" 分支（handler.go:2786），IsAutoRequest 恒 false → 镜像保留，符合方案18 §3.2。
- **不打 X-Gw-Is-Auto 未引发 executor 续跑裁剪误伤**：continue-trim 豁免虽只认 X-Gw-Is-Auto 头（executors/executor.go:2115-2116），但 `IsContinuationOrRetry` 是「≤32 rune + 归一化后整串精确等于关键词」（node_failover.go:120-148），续跑提示 "请继续下一步"/"Please continue with the next step" 均不等于任何关键词 → 不会被 trimOneMessageFromBody 裁掉（node_failover.go:129 注释还点名 "请继续下一步" 是保护对象）。
- **auto 路由反馈不被影子轮污染（主线场景）**：`ReportRoutingOutcome` 门控在 `entry.IsAutoRequest`（handler.go:6190-6192），goal_continue/goal_model_switch 轮 IsAutoRequest 为空 → 不进 P2.2 反馈流。仅发现 #1 的 audit-auto 边界例外（该轮本就是真 auto 路由请求，语义可辩护）。
- **JSONB 免疫 / 序列化器 / 未知字段保真 / anomaly**：窗口改动未新增任何 JSONB 写入点与序列化器分支；follow-up body 为 bytes 透传；R30 两条健康面基准未被触碰。
- **钉桩测试在位**：TestInjectFollowUpPassesParentRequestID（seam 透传）、TestFollowUpSourceActorMapping（映射锁定）（response_interceptor_helpers_test.go:311-381）。
