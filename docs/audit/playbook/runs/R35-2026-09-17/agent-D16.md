## 二、核实为健康的面

- **影子轮打标数据闭环（来源/去处明确）**：X-Gw-Source-Actor/X-Gw-Parent-Request-Id 由 buildFollowUpRequest 写入（response_interceptor_helpers.go:235-240）→ handler 入口读入 logCtx（handler.go:1726-1731）→ applyParentCorrelationFields 持久化（request_log_pipeline.go:472-481）→ request_logs.parent_request_id/origin_actor，影子轮可递归 JOIN 父链（嵌套时 parent=上一层影子轮自身 request_id，handler.go:5185 传当前请求的 requestID）。actor 枚举 goal-continue/goal-model-switch/goal-audit/goal-followup 与既有 auto-title 命名空间无 'goal-' 前缀碰撞（全仓 grep 无其他 goal- actor 字符串）。
- **不打 X-Gw-Is-Auto 的决策成立**：handler.go:1718-1720 仅在 header=true 时置 IsAutoRequest；goal 影子轮不带头 → 不进 isInternalAutoEntry 镜像排除（sessionv2mirror 消费该标记），符合提交声称的 GLOBAL_G2 保护。
- **影子轮再判定链有界（三问之"清理"）**：goal_continue/goal_model_switch 影子轮响应会再次进入 decideAndContinue（mode_hook.go:241/599 只跳过 "audit" 前缀）——预算经 AtomicAutoContinue 对影子轮生效（同一 goal_sessions 行，tryAtomicContinue→AtomicAutoContinue 有 max 上限）；轮换经 AtomicModelSwitch 有 maxSwitch 上限；深度经 context 递增且 injectFollowUpRequest:120-129 在 depth≥effectiveMaxFollowUpDepth（默认 15，boot 不变量可上调，goal_control.go:429-452）截断，另有每会话 50 上限（helpers.go:90-95）。**ContinueAttempt 不被影子轮累计**：合成请求无 X-Gw-Capabilities → ClientSignalAllowed=false（handler.go:5131）→ tryBuildClientSignal 返回 nil → 走 legacy 自调用，不触碰 ClaimContinueAttempt；advisory（Path 1.5）在影子轮上同样被 ClientSignalAllowed=false 抑制，不会影子轮再发 advisory。
- **advisory 不消耗预算**：tryBuildAdvisoryToolSignal（mode_hook.go:561-584）无 ClaimContinueAttempt/AtomicAutoContinue 调用，attempt 仅回显当前值；goal_test.go:515-560 断言 AtomicAutoContinue 计数为 0、payload 无 hint、advisory=true。
- **advisory 不触发 legacy 自调用**：ClientSignalKind 非空时 handler 走 SSE frame / 响应头分支，else-if 结构保证不进 injectFollowUpRequest（handler.go:5172-5186 流式、5203-5212 非流式）；且 advisory 结果的 InjectFollowUp 本身为空。ClientSignalAttempts 仅被 chain.go:101/203 透传，handler 无任何把它当已消费 attempt 的逻辑——回传值是纯信息展示。
- **advisory 抑制分支**：give-up（decision.giveUp）与 sub-agents pending 均抑制（mode_hook.go:358、562），测试六分支覆盖（goal_test.go:515-634）。
- **audit 影子轮无二次审计环**：audit follow-up 影子轮回流时 goal hook 按 "audit" 前缀跳过（mode_hook.go:241/599），audit hook 因 UpdateSessionAudit 已写入（audit_hook.go:110-113 audit_result 非空跳过）不再触发。
- **goal_run_actions 无悬挂 pending 行**：无生产写入方（见发现 5）。
