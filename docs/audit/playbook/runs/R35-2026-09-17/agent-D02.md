## 二、核实为健康的面

- **advisory 帧契约逐字段与文档一致**（问题 1）：代码 payload（mode_hook.go:569-578）13 键 = `type,version,reason,advisory,finish_reason,request_id,session_id,attempt,max_attempts,tokens_used,context_window,sub_agents_pending`，与 `docs/GOAL_CLIENT_SIGNALS.md:62-67` advisory 变体示例的键集合完全相同；无未声明字段、无缺失字段；`hint` 正确缺席（goal_test.go:548-549 断言）；数值均为 JSON 整数与文档一致。handler 侧 `renderClientSignalFrame`（stream_recovery.go:915-924）原样透传 payload，不再编解码。
- **mode 门两路径一致**（问题 2）：正式 gw-continue 门 `mode ∈ {"",auto,continue,both}`（mode_hook.go:496）与 advisory 门（mode_hook.go:566）集合完全相同；`handoff` 双双抑制。`ClientSignalAllowed` 同源：非流式 handler.go:5131 `ClientSignalRequested(r)` → 流式 handler.go:5157 透传 → mode_hook.go:624 重建 req；handler 还有第二道独立闸 `clientSignalKindAllowed`（durable_contract.go:186-195，gw-continue 再验 `ClientSignalRequested`）。
- **advisory 不触发任何 follow-up dispatch / 预算**（问题 4）：流式 handler.go:5172-5186 与非流式 handler.go:5203-5211 均为 `if 帧渲染 {…} else if len(InjectFollowUp)>0 {dispatch}`——ClientSignalKind 非空走帧分支，advisory 结果 InjectFollowUp 为空，dispatch 不可达；`injectFollowUpRequest` 对空 body 在计数器自增前早退（response_interceptor_helpers.go:114-117），`ClientSignalAttempts` 全仓仅赋值/合并（chain.go:101,203）无消费方；goal_test.go:554-563 断言 `AtomicAutoContinue`/`ClaimContinueAttempt`/`ContinueAttempt` 三者均未移动。
- **finish_reason="tool_calls" 在 goal hook 可达的两条活跃上游链路均精确产出**（问题 3）：openai-chat 上游 verbatim（internal/ir/response.go:403；流式 stream.go:323,394）；anthropic 上游经 `mapAnthropicFinishReason`/`mapAnthropicFinishReasonToOpenAI` "tool_use"→"tool_calls"（response.go:1108-1123 非＋stream.go:629,1222-1237 流），无 "tool_use" 别名泄漏到 hook 看到的 OpenAI 形态 body（executor_anthropic.go:205,243 经 IR→SerializeOpenAIResponse）；流式 capture 的 `upstream_finish_reason` 记录的是归一化后的 IR 值（audit/stream.go:92-127），`reassembleFinishReason` 原样返回。
- **非流式 trailer 通道预声明**：`Trailer: X-Gw-Client-Signal[-Payload-B64]` 在 executor 提交 header 前声明（handler.go:2889-2894），5204-5205 的 post-body Set 是合法 trailer 而非无效 header。
- **影子轮打标头链路闭环**：`buildFollowUpRequest` 设 `X-Gw-Source-Actor/X-Gw-Parent-Request-Id`（response_interceptor_helpers.go:231-244），handler 入口 handler.go:1726-1731 读入 `logCtx.ParentRequestID/OriginActor`（复用 auto-title 落库链）；`X-Gw-Is-Auto` 正确缺席（response_interceptor_helpers.go:184-189 注释 + goal 侧测试 response_interceptor_helpers_test.go:349-381 断言）；action→actor 映射有钉桩（:330-343）。dispatch seam 增加 `parentRequestID` 参数后全部三处调用点已同步（handler.go:5185,5211 + helpers）。
