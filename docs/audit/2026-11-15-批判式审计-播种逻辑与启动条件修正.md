## 二、问题①：跨窗 limit 播种缺失

### 根因分析

**原实现**（7511df49e）：
```go
g.minutePeak = make(map[int]int)
g.minuteRejected = make(map[int]int)
g.minuteLimit = make(map[int]int)  // ← 重置为空 map
for id, inFlight := range g.used {
    if inFlight > 0 {
        g.minutePeak[id] = inFlight
        // limit 播种注释存在但实现缺失——从刚 make 的空 map 取值恒为 0
    }
}
```

**触发场景**：长请求跨窗口（请求持续时间 > 60s）
- 窗口 T1：key 10 请求到达，`used[10]=1`，`minuteLimit[10]=5`
- 窗口切换：`SnapshotAndResetMinute()` 执行
  - 样本1：`{KeyID:10, InFlight:1, Peak:1, Limit:5}` ✓
  - 重置：`minuteLimit = make(...)`，旧值丢失
  - 播种：`minutePeak[10]=1` ✓，但 `minuteLimit[10]` 未播种
- 窗口 T2：请求继续持有
  - `used[10]=1`（仍在飞），`minutePeak[10]=1`（播种的），`minuteLimit[10]=0`（未播种）
  - 样本2：`{KeyID:10, InFlight:0, Peak:1, Limit:0}` ✗
  - **自相矛盾**：peak>0 意味着有帽在执法，但 limit=0 表示无帽

**影响**：
- 观测数据不可信（peak 与 limit 不匹配）
- 运维用观测数据推断「key 是否受帽约束」会误判
- DB 表会积累 `peak_in_flight>0 AND concurrent_limit=0` 的脏行

### 修复

```go
// 重置前保存旧 limit（播种需要）
oldLimit := g.minuteLimit
g.minutePeak = make(map[int]int)
g.minuteRejected = make(map[int]int)
g.minuteLimit = make(map[int]int)
for id, inFlight := range g.used {
    if inFlight > 0 {
        g.minutePeak[id] = inFlight
        // 从重置前的旧值继承（同一 key 的帽不会中途变化）
        if limit := oldLimit[id]; limit > 0 {
            g.minuteLimit[id] = limit
        }
    }
}
```

**测试加强**：`TestKeyConcurrentGate_MinuteStatsAccounting` 第三窗口检查加
`s.Limit <= 0` 断言——修复前红，修复后绿。

## 三、问题②：writer 启动条件过严

### 根因分析

**原条件**（7511df49e）：
```go
if keyVerifier != nil && keyVerifier.Enabled() && dbConn != nil {
    // 启动 KeyConcurrencyStatsWriter
}
```

**问题**：`keyVerifier.Enabled()` 在 lite 模式返回 false
- lite 模式 = 有 DB 但无 apikey 表（开发/测试环境常见形态）
- 这种形态下：
  - 并发闸**仍在执法**（内存 key 的 `ConfiguredConcurrent` 有值就执行）
  - 但观测写入**完全不启动**（条件不满足）
  - 结果：有并发限制活动，但观测数据黑洞

**对照其他组件**：
- RPM 限流器：`keyVerifier.Enabled()` 门槛合理（无 key 表就没有 RPM 限流）
- 并发观测：执法发生在进程内存（与 key 表脱钩），有 DB 就应该写观测

### 修复

```go
// 启动条件 = 有 DB（观测写入不依赖 keyVerifier.Enabled，lite 模式下
// 内存 key 的并发执法与观测仍有意义——批判式审计轮修正条件过严问题）。
if dbConn != nil {
    // 启动 KeyConcurrencyStatsWriter
}
```

**影响面**：
- lite 模式现在也写观测（正确行为）
- 仍保留表缺席自愈（迁移 965 未部署前 WARN 不停 worker）
