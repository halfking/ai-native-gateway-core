### 3.2 第一次尝试的坑(留档给下一轮)

直接跑原脚本 → 在 `ursm_node_snapshot_min` 的 UPDATE 处超时。表里 2083 万行,**无 canonical_name 索引**,且 EXECUTE 包裹在同一个 DO 块里没有 SAVEPOINT 隔离,**单点失败回滚整段事务**。

第二次成功执行加了 `-c 'SET statement_timeout = 0;'`,整个脚本跑完 90 秒左右,所有验证 V1-V8 全绿。

**结论**:`ursm_node_snapshot_min` 在 dedup-cleanup 里是无 SAVEPOINT 的,**任何长事务跨过它都有风险**。下一轮 R51 必修:
1. 给 ursm_node_snapshot_min 加 `CREATE INDEX CONCURRENTLY ... ON ursm_node_snapshot_min USING btree (lower(canonical_name));`(已有 snapshot_ts 索引思路同款)。
2. dedup-cleanup 脚本里给每个 EXECUTE 包 SAVEPOINT,任一失败不回滚整段。
