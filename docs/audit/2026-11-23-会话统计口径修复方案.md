# 会话统计口径修复方案

## 问题描述

**当前问题**: 会话统计的费用($8,577.79) ≠ 看板费用($9,899.22),差13.4%

**根本原因**: 统计口径错误
- 看板: 统计7天窗口内的所有业务请求
- 会话统计: 读取`session_summaries`表(存储会话全生命周期累计值),仅过滤`first_request_at >= 7天前`
- 问题: 会话首请求在8天前但7天内仍活跃的会话,其窗口内请求被**整个排除**

---

## 修复方案

### 位置
`admin/dashboardapi/session_overview.go` - `querySessionSummaryAggregates()`

### 修复方案A: 直接聚合request_logs (推荐)

```go
func (h *SessionOverviewHandler) querySessionSummaryAggregates(ctx context.Context, params QueryParams, win sessionWindow) (*sessionSummaryAggregates, error) {
    buildQuery := func(withUniverse bool) (string, []interface{}) {
        where := []string{}
        args := []interface{}{}
        argIdx := 1

        // 时间谓词: 请求时间在窗口内
        where = append(where, "ts >= NOW() - INTERVAL '$1 days'")
        args = append(args, params.Days)
        argIdx++
        
        // 租户过滤
        if params.TenantID != "" {
            where = append(where, fmt.Sprintf("tenant_id = $%d", argIdx))
            args = append(args, params.TenantID)
            argIdx++
        }
        
        // 只统计业务流量
        where = append(where, "origin_stage = 'business'")
        
        // 只统计有session_id的请求
        where = append(where, "gw_session_id IS NOT NULL")
        
        baseWhere := joinStrings(where, " AND ")
        
        var fromClause string
        if withUniverse {
            // 宇宙过滤: 需要JOIN sessions表判断探测
            fromClause = `
                FROM request_logs_with_current_month rl
                JOIN (
                    SELECT DISTINCT ON (session_id, tenant_id)
                        session_id, tenant_id, is_probe, owner_user, client_type, title
                    FROM sessions
                    ORDER BY session_id, tenant_id, partition_date DESC
                ) s ON s.session_id = rl.gw_session_id AND s.tenant_id = rl.tenant_id
                LEFT JOIN session_dim sd ON sd.session_key = rl.gw_session_id AND sd.tenant_id = rl.tenant_id
                WHERE ` + baseWhere + `
                  AND NULLIF(COALESCE(s.owner_user, sd.api_key_owner_user), '') IS NOT NULL
                  AND NOT COALESCE(s.is_probe, false)
                  AND NOT session_analytics_is_probe(
                      COALESCE(s.owner_user, sd.api_key_owner_user), s.client_type, s.title)
            `
        } else {
            fromClause = "FROM request_logs_with_current_month rl WHERE " + baseWhere
        }

        query := `
            SELECT
                COUNT(DISTINCT rl.gw_session_id) as total,
                COUNT(DISTINCT rl.gw_session_id) FILTER (WHERE rl.ts >= NOW() - INTERVAL '24 hours') as active,
                -- 健康度分布需要从session_summaries JOIN获取
                -- 或者从request_logs无法直接获取,需要另外查询
                COALESCE(SUM(rl.cost_usd), 0) as total_cost,
                COUNT(*) as total_requests,
                COALESCE(AVG(rl.latency_ms), 0) as avg_latency
        ` + fromClause
        
        return query, args
    }
    
    // ... 执行查询
}
```

**优点**:
- 与看板口径完全一致 (都统计窗口内请求)
- 数据准确,无漏算

**缺点**:
- 健康度/合规度等字段在request_logs中不存在,需要额外JOIN session_summaries
- 查询性能可能较慢(需测试)

### 修复方案B: 修正session_summaries的使用方式

**思路**: 仍使用session_summaries,但只统计**窗口内完全包含**的会话

```go
// 只统计 first_request_at >= 窗口开始 AND last_request_at < 窗口结束 的会话
WHERE first_request_at >= NOW() - INTERVAL '7 days'
  AND last_request_at < NOW()
```

**问题**: 仍然不准确
- 会话可能跨越窗口边界
- session_summaries存储的是累计值,无法拆分窗口内外

### 修复方案C: 混合方案 (推荐)

```go
// 核心KPI(请求数/费用)从request_logs聚合
// 健康度/合规度从session_summaries JOIN获取

WITH window_sessions AS (
    -- 7天窗口内所有活跃的session
    SELECT DISTINCT gw_session_id
    FROM request_logs_with_current_month
    WHERE ts >= NOW() - INTERVAL '7 days'
      AND origin_stage = 'business'
      AND gw_session_id IS NOT NULL
),
window_metrics AS (
    -- 窗口内请求聚合
    SELECT 
        COUNT(DISTINCT r.gw_session_id) AS total_sessions,
        COUNT(*) AS total_requests,
        SUM(r.cost_usd) AS total_cost,
        AVG(r.latency_ms) AS avg_latency
    FROM request_logs_with_current_month r
    JOIN window_sessions ws ON r.gw_session_id = ws.gw_session_id
    WHERE r.ts >= NOW() - INTERVAL '7 days'
      AND r.origin_stage = 'business'
      [+ 宇宙过滤]
),
session_quality AS (
    -- 健康度/合规度从session_summaries获取
    SELECT 
        COUNT(*) FILTER (WHERE ss.health_grade = 'A') as health_a,
        COUNT(*) FILTER (WHERE ss.health_grade = 'B') as health_b,
        ...
        COUNT(*) FILTER (WHERE ss.compliance_status = 'compliant') as compliant,
        ...
    FROM session_summaries ss
    JOIN window_sessions ws ON ss.session_key = ws.gw_session_id
)
SELECT 
    wm.*,
    sq.*
FROM window_metrics wm, session_quality sq;
```

**优点**:
- 费用/请求数准确 (从request_logs)
- 健康度/合规度可用 (从session_summaries)
- 性能可控 (window_sessions先过滤)

## 性能考虑

### 当前性能 (session_summaries)
```
查询耗时: ~880ms
扫描行数: 36,475个会话 (WHERE first_request_at >= 7天前)
```

### 修复后性能 (request_logs)
```
预估耗时: ~1,500ms (需实测)
扫描行数: ~81,000个请求 (WHERE ts >= 7天前)
```

**优化方案**:
1. 在`request_logs_with_current_month`上添加索引: `(ts, origin_stage, gw_session_id)`
2. 使用物化视图缓存窗口聚合结果(每15分钟刷新)
3. 前端缓存60秒(已有)
