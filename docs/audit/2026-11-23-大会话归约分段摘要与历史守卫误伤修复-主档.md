## 二、历史守卫误伤修复

### 2.1 根因

**此前行为**：`HistoryGuard` 只看正则匹配，不走输入面的候选过滤链（`DetectScope`）：
- 只要消息解码文本里含「tokens」「keyboard」「email」等词 ⇒ 整条省略
- 而输入面的真实判据是「候选过滤链」：正则 + 字段选择器 + 叶子值判定 + 范围判定

**211 真实数据对照**（三份真实大请求体拷贝到临时目录 × 线上现行 59 条规则）：
- 7.3MB/8226 条：被守卫省略 735（8.9%）→ 修复后 38（0.5%）
- 7.9MB/3999 条（2026-11-22 超时事故的那场 ZCode 会话）：2285（57.1%）→ 151（3.8%）
- 16.7MB/3276 条：745（22.7%）→ 44（1.3%）

**★ 最严重案例**：7.9MB 会话里 57.1% 的历史被误丢——用户的工具调用结果、助手的完整回复，只要含「tokens left」「keyboard shortcuts」就整条不给模型看 ⇒ 模型失去上下文连贯性。

### 2.2 修法

**核心设计**：守卫以输入面同一份检测主体为准，字段规则维持原行为。

**实现**（`security/sanitize/history_guard.go` + `detector.go`）：
1. **快路径不变**：先看正则（regex-only 规则 + 其它规则的正则部分），未命中直接放行 ⇒ 热路径零开销。
2. **快路径说可能命中后复核**：把已解码文本交给输入面同一份检测主体（`detectPatterns`，从 `DetectScope` 机械抽取）。
3. **字段规则维持原行为**：键名选择器（`$.tool[*].input.password` 等）+ 任意值 ⇒ 守卫直接省略，不复核——输入面对它们按字段上下文 + 叶子值判定，整条消息的解码文本复现不了这个上下文。
4. **复核有 1MB 上限**：超限保守省略（大消息的文本解码成本高，且大消息本身就可能被摘要功能省略）。
5. **复核前按规则必含字面量逐条预筛**：每条规则若有 required literals（如 `email` 规则的 `@`），先 `strings.Contains` 预筛；未命中跳过该规则的正则匹配。7.9MB 会话实测：逐条预筛前 3.7s，预筛后 2.7s。
6. **策略 key 带版本号 2**：`sha256(策略键 + "v2" + 消息字节)` ⇒ 策略一变旧判决自然失效。

**抽取 `detectPatterns` 是纯机械搬移**（diff 仅新增 11 行、零删除）：
```go

func detectPatterns(text string, patterns []*CompiledPattern) (bool, string, string) {
    // ... 原 DetectScope 主体 ...
}

// history_guard.go (调用方)

    text := string(decoded)
    if len(text) > 1<<20 { // 1MB 上限
```

## 三、分段抽取式摘要

### 3.1 设计

**目标**：给超大会话归约时保留历史精华，让模型看到首/中/尾代表性内容，而不是因为历史太长直接全丢。

**方法**：抽取式（extractive），不是 LLM 生成式（abstractive）：
- **抽取式**：从原文按分数挑行，零额外成本、可复现、不丢信息
- **LLM 生成式**（未采用）：更省 token 但多一次调用且可能丢信息

**pipeline**（`internal/sessioncontext/digest.go`）：
```
原始历史消息
  ↓ 切段（默认 64KB）
  ↓ 每段抽取式摘要（稀有词占比 + 数字/路径/标识符信号 + 人类消息开头句 + 角色权重）
  ↓ 合并保留树结构、按需求比例自顶向下分预算并给每段保底一行
  ↓ 段摘要按内容哈希缓存（下一轮只有新段需要算）
  ↓ 输出：<=16KB 的代表性历史摘要
```

### 3.2 实现细节

**1. 切段**（默认 64KB）
- 按原始字节切，不按消息边界 ⇒ 超大单消息会被切成多段
- 段边界对齐消息边界（尽量不切碎一条消息）

**2. 每段抽取式摘要**（`scoreMessageForDigest`）

**评分维度**：
- **稀有词占比**：TF-IDF 思想，出现次数少的词更有信息量
- **数字信号**：含数字的行（统计数据、版本号、ID）权重 +0.5
- **路径/标识符信号**：含 `/` 或 `_` 的行（文件路径、变量名）权重 +0.3
- **人类消息开头句**：user 消息的前 2 句权重 ×1.5（用户意图集中在开头）
- **角色权重**：user 2.5 / assistant 1.5 / tool_result 0.35（工具结果冗长但信息密度低）

**排序规则**（先按类别再按分数）：
1. 人类消息（user）的行
2. 助手消息（assistant）的行
3. 工具结果（tool_result）的行

**去冗余**（Jaccard 相似度 ≥0.9）：
- 只去掉近乎逐字重复的行
- 阈值取 0.9 而非 0.5~0.8 ⇒ 避免把用户第二次提的要求当成第一次的重复丢掉

**每条消息至多 2 行**：
- 防止单条消息占用过多预算
- 超大消息（>64KB）只留省略标记 `[large message omitted, N bytes]`

**3. 合并保留树结构**（`mergeSegmentDigests`）

**按需求比例自顶向下分预算**：
- 每段按其需求（段内消息总行数）占比分配预算
- 每段保底一行 ⇒ 保证首/中/尾都有名额
- 段内再按分数填预算

**为什么不按分数直接填预算**：按分数填会让内容同构的一段包揽名额，其它段被挤出 ⇒ 失去首/中/尾的代表性。

**4. 段摘要缓存**（`digestCache`）

**缓存键**：`sha256(段内容字节)` ⇒ 下一轮只有新段需要算，旧段直接命中缓存。

**缓存管理**：
- 进程内有界缓存（131072 条、分片、FIFO）
- 只缓存成功的摘要结果
- 缓存不含会话明文（只存摘要结果）

### 3.3 配置与装配

**环境变量**（`cmd/gateway/session_digest_init.go`）：
- `LLM_GATEWAY_SESSION_DIGEST`：默认 `on`；`off`/`0`/`false`/`no`/`disabled` 关闭
- `LLM_GATEWAY_SESSION_DIGEST_SEGMENT_BYTES`：默认 65536（64KB）
- `LLM_GATEWAY_SESSION_DIGEST_BUDGET_BYTES`：默认 16384（16KB）

**接入点**（`domains/streaming/handler.go`）：
- `prepareHistoryGuard` 注入 `WithDigest` 到请求 ctx
- `sessioncontext.Reduce` 在 ctx 里找到 `WithDigest` 即启用摘要

**指标**（`metrics/session_context_reduce_metrics.go`）：
- `session_context_digest_segments_total{cache="hit"|"miss"}`：段缓存命中/未命中次数
- `session_context_digest_bytes`：摘要输出字节数（应 ≤ 预算）
- `session_context_reduce_omitted_total`：被守卫省略的历史条数（新增，此前线上看不见）

- 7.9MB 会话（冷启动 0.9s）加摘要后 ≈2.7s（含守卫复核）

## 七、登记

**L1** 热缓存的真实命中率取决于客户端是否逐字节重发历史（缓存标记移动、工具结果裁剪都会让少数消息字节变化）⇒ 以线上指标 `history_guard_memo_*` 与 `session_context_digest_segments_total{cache="hit"}` 为准。

**L2** 守卫修复改变的是「哪些历史消息被保留」：模型会看到更多历史——以前因 tokens/keyboard/token count 这类词被误丢的那些；电话/邮箱/身份证号、带敏感键名的工具参数、真实凭据仍然照旧省略。代价是冷路径第一轮更慢（7.9MB 会话约 2.7s）；如线上出现异常可回滚到 6076df408 之前的版本。

**L3** 摘要功能默认开启、带 env 开关 `LLM_GATEWAY_SESSION_DIGEST=off` 可关闭；关闭时归约输出与此前逐字节相同。

**L4** 去冗余阈值取 0.9（只去近乎逐字重复的行）——0.5~0.8 会把用户第二次提的要求当成第一次的重复丢掉。

**L5** 合并用「按需求比例分预算 + 每段保底一行」的树形分配——按分数直接填预算会让内容同构的一段包揽名额。

**L6** 211 暂存空目录存量 318,201 个（第一遍清理前）——代码修复只管新产生的，存量由清理脚本处理。

**L7** 第二遍清理待 SSH 访问 211 后执行（1,321 个目录）。

**L8** 部署、验证、第二遍清理均被 SSH 连接失败阻塞。

**L9** 候选被永久性原因（额度耗尽/停用/未登记）挡空时是否把 503 换成 4xx——上一轮遗留，本轮未动。
