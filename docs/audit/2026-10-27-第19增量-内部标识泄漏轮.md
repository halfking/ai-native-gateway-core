## 2. 判据（唯一实现：`web/src/i18n/internalJargon.ts`）

### 2.1 J1 —— 形状：只认 snake_case

```ts
export const JARGON_ID_RE = /\b[a-z][a-z0-9]*(?:_[a-z0-9]+)+\b/g
```

★ 为什么只认 snake_case：
- snake_case 在**任何语言的正常散文里几乎都不出现** ⇒ 它本身就是「机器内部名」的形状标记；
- ⇒ 规则在 8 个语种间**天然一致**（第 12 增量的教训：规则在语种间不一致 ⇒ 门就不是门）。

★ **点分小写路径规则被实测否掉**：`e.g.` / `api.example.com` / `mail.tm` 全被抓进来
⇒ **76 个标识符 / 726 条命中，绝大多数是假阳性** ⇒ **判据宁可窄，不可宽**。
⇒ 而点分路径里真正该管的部分（`cmb.billing_mode`）**本来就含下划线段** ⇒ 点分规则是多余的。

★ 事后复核（值层面）：全 8 语种语言包里的点分小写串**只出现在注释与对象键里**，值层面 0 条 ⇒ 盲区当前未被利用。

### 2.2 J2 —— 不是整串

该标识符**不是**整个值（整串即标识符 = 界面上的标签 / 列名 / 枚举值 ⇒ 不判）。

### 2.3 J3 —— 不是「用户对照的代码」

被 `<code>…</code>` / 反引号 / 引号（`「」『』“”‘’«»„“‹›`）包裹 ⇒ 不判
（用户在逐字对照代码或字段名 ⇒ 那正是他要找的东西）。

### 2.4 J3b —— 模板插值

`{...}` 内的标识符是**与代码绑定的占位符名**（如 `{session_load}` / `{failure_penalty}`）⇒ 不判。
★ 判它红 = 要求人改占位符名 = **直接改坏功能**。与第 12 增量「点名具体目标只认引号 / 模板插值 / 箭头」同源。

### 2.5 J4 —— 豁免簿

未登记 ⇒ 判红（**漏网即红**）。

### 2.6 J5 —— 反向自证（豁免不能靠「文件改了」继续挂着）

`payload-field` / `ui-visible-term` 两类豁免必须附 **witness**（界面上真的展示它的地方），
门会核对该文件里**仍然存在**该标识符 ⇒ 豁免过期必须重新裁决。

## 6. ★ 本轮抓到的真缺陷（都是「改写引入的」，不是原有缺陷）

### 6.1 语义窄化 —— 8 个语种同时错（本轮最值钱的一处）

`routingAudit.subtitle` 原句是「**每次变更**均会记录…」（en-US：`Every change to the routing_overrides table is recorded…`）。
★ 改写者把表名换成人话时，中文原句尾句里的「**封禁**」被误当成同义替换 ⇒ 产出「每次**封禁**变更」。

★ 而事实是：
- `routing_overrides.mode` 的 CHECK 约束：`mode = ANY (ARRAY['pin','ban'])`（`sql/schema/01-schema.sql:15017`）；
- 审计查询**没有 mode 过滤**（`admin/routing_overrides.go:373`）⇒ 页面上 pin 与 ban **都**会出现。

⇒ **窄化 = 事实错误**，8 语种全改回「每次变更」口径（表名换成人话，如 zh-CN「每次**路由覆盖**变更」、
en-US「Every **routing override** change」）。

★ 通用式：**「去掉内部标识」的改写，最容易改掉的是【量词与范围】** ⇒ 改完要去事实源问「这句的范围还对吗」。

### 6.2 事实性幻觉 —— 语言包比事实源多

zh-CN 的 `trace.empty.hint3` 被改写成「已完成的请求：追踪数据已持久化（**含完整请求与响应正文**）」。
★ 而 `internal/trace/builder.go:247-248` 只写 `response_body_len` 与 `response_body_sha256`，
`internal/trace/trace_test.go:119` **明确断言** `response_body` **不**在事件里；请求正文更不在 trace 里 ⇒ **幻觉**。

⇒ 改回「已完成的请求：追踪数据已持久化到请求日志（JSONB）」。

### 6.3 es-ES / fr-FR / ar-SA 的冗余括号

`taskProfile.action.applyConfirm`：把 `task_type_tier_config` 换成「(configuración de niveles)」后与前半句语义重复。
⇒ 其余 5 语种的同类改写都是**直接删掉括号** ⇒ 三语种同样删括号，跨语种结构对齐。

### 6.4 ar-SA 的双数一致性与悬空代词

- `models.noRecommend`：「مجموعة」是阴性 ⇒ 双数应为 `كلتاهما`、谓语应答双数 `فارغتان`；「و مجموعة」应连写为 `ومجموعة`。
- `providerDetail.models.resetNodeProbeTitle`：原句「استخدمه」的先行词是表名 `node_probe_state`；
  标识符被去掉后先行词消失 ⇒ **悬空代词** ⇒ 改「استخدم هذه الخطوة عندما」。

### 6.5 ★ 批量改写脚本自己写坏了一个文件

修正脚本第一版用 `\bkey\s*:\s*(['"])(.*?)\2` 取值 ⇒ 在 **`l\'auteur`** 处提前截断 ⇒ 抓到半截值
⇒ 重新序列化时把 `\'` **二次转义**成 `\\'` ⇒ **产出语法错误文件**（`fr-FR/routingAudit.ts`）。

★ 门当场报 `SyntaxError: Unexpected identifier 'auteur'` ⇒ **这就是「落盘后立刻跑门」的价值**。
⇒ 修法：按**原始文本**做片段替换，**绝不重新序列化整串**；取值时手工处理反斜杠转义。

★ 配套：纪律反过来抓到了我自己 —— 第一版脚本被我写成「片段式旧值」，
结果 5 处报错「当前值 ≠ 期望旧值」⇒ **纪律比人可靠**。

## 7. 运行时核对（第二把尺）与它踩到的三个坑

`web/scripts/i18n-jargon-runtime-check.mjs`（无头 Chrome + CDP；无 Chrome 时打印 ⏭ SKIP「**未测量**」，绝不伪装成通过）。

判据 4 条：**R1** 屏上无未登记内部标识 · **R2** 屏上无 i18n 键路径（缺键必须显形为键路径）·
**R3** 控制台无错误 · **R4** 改写后的文案确实上屏。

### 7.1 坑一：不能用 innerText 判 R1（★ 假阳性 13/13）

第一版扫 `document.body.innerText` ⇒ 报出 13 个「屏上内部标识」。逐条判：
- **9 个全在 `<code>` 里**（`RoutingPolicyView.vue:35-38` 的策略字段名 —— 源码门 J3 **本就豁免**）；
- **4 个在 `<td class="mono">` 里**（任务类型键 `code_audit` / `function_call` / `intent_classification` / `long_context`
  —— 一格一个标识符 ⇒ J2「整串即标识符」形态）。

★★ 根因：**浏览器解析完标签后 innerText 里只剩裸文字，标签没了** ⇒ 源码门的【上下文感知】在运行时**全部失效**。
⇒ 修法：**逐 DOM 文本节点**判（复用**同一个** `detectInternalJargon` ⇒ 同一份口径），
并额外识别 `<code>/<pre>/<kbd>/<samp>` 祖先（J3 的运行时形态）；J2 的运行时粒度也必须是文本节点。

### 7.2 坑二：换语种会被 app 自己覆盖

第二版报「6 处该上屏却没上屏」，取证发现：**期望值是阿拉伯语、屏上是中文** ⇒ 换语种根本没生效。

★★ 根因：语种在**模块加载时**读 localStorage；而 `usePersistedValue`（LP8）在**页面卸载时**
（`pagehide` / `beforeunload` flush）把内存里的语种**写回** localStorage ⇒ 设的值在导航瞬间被冲掉。
⇒ 修法：在**同源静态资源页**（`/favicon.svg`，那里没有 app JS ⇒ 没有 flush）上写 localStorage 再导航；
并且**核对 `<html lang>` 与请求语种一致**，不一致就**报页面错误、不判该行**。

### 7.3 坑三：R4 的占位符匹配

「删掉占位符再整体包含」会留下双空格（`已清除 {n} 条` ⇒ `已清除  条`）而屏上是 `已清除 12 条` ⇒ 子串必然失配。
★ 这条是**自证当场抓出来的** ⇒ 改成按占位符**切段**、每段都要在屏上（少于 4 字的段视作弱证据）。

### 7.4 终读数

**28 次判定（7 页 × 4 语种）· 屏上内部标识 0 · 屏上键路径 0 · 该上屏却没上屏 0 · console 错误 0**
⇒ ★ 逐行核实 `<html lang>`：zh-CN→zh-CN / en-US→en / ja-JP→ja / ar-SA→ar，各 7 页，0 页面错误
⇒ ★★ 「全绿」有两种读法（扫到了没发现 vs 根本没扫到那一段）⇒ **阴性结论也要当缺陷一样复核**。
