## 0. 一句话

impeccable 要求空状态**区分** first use / no results / filters / permissions / failure 五种状态；
本仓把 **4 个通用空态键**跨语义共用在 **24 处调用点**上 ⇒ 用户看到「没有数据」时无法判断是

## 2. 设计：状态种类进**结构**，不只进措辞

### 2.1 五种状态（impeccable 的 5 类）

| kind | 含义 | 本轮落地处 |
|---|---|---|
| `FirstUse` | 首次使用：还没创建过任何东西 | 用户画像 3 张表 / VibeCoding 项目列表 |
| `NoResult` | 无结果：查过了，确实没有 | 看板 6 处 / 用量表 / 3 张图表 / 大字段表 |
| `Filtered` | 筛选后为空：有数据但被筛掉了 | 凭据热力图 / VibeCoding 会话与审查 |
| `Failed` | 失败/未知：服务端没给 ⇒ **不能说成「没有」** | 错误汇总缺失（`errors === null`） |
| `NoPermission` | 无权限 | 本轮未用到（词表保留） |

### 2.2 ★ 键名带 kind ⇒ 「可区分」这件事可复核

```
dashboard.board.emptyNoResultProviders    ← 无结果 · 供应商
dashboard.board.emptyNoResultDrill         ← 无结果 · 错误下钻
sessions.userProfile.emptyFirstUseTopTasks ← 首次使用 · 热门任务
ops.vibecoding.emptyFilteredSessions       ← 筛选后为空 · 会话
sessions.stats.emptyFailedErrorSummary     ← 失败/未知 · 错误汇总
common.empty.noResult                      ← 跨页面兜底
```

⇒ 复核时**先看结构、再看措辞**；反过来只看措辞，差异会被下一次改写抹平。

### 2.3 ★★ kind 只能由「页面已经掌握的事实」决定

逐个读 24 处调用点的状态变量，三处实证：

1. **VibeCodingView 的会话列表谓词是 `filteredSessions`** ⇒ 空 = **筛选后为空**，
   **不是**「没有会话」⇒ 原文案把「你还没开始」和「你的筛选条件太窄」讲成了同一件事。
2. **SessionStatsSignals 的两个分支是两件事**：
   `errors` 有值但计数为 0 ⇒「当前周期无错误记录」= **好状态**；
   `errors` 为 `null` ⇒ 服务端**没返回**错误汇总 = **未知** ⇒ 原文案用 `dashboard.noData`
   「该时段暂无数据」⇒ **把「不知道」讲成「知道」**
   （与 `ProviderUsageExplorer` 里那段既有注释「降级时说『暂无数据』等于把不知道讲成知道」同根）。
3. **BlobManager 页没有时间筛选器** ⇒ 空态**不写时间范围**（不编造页面不知道的事实）。

## 4. 新门 `web/scripts/i18n-empty-state-guard.mjs`

### 4.1 ★★ 为什么这道门测的是**结构**，不是措辞

本仓已有的语言包侧清晰文案门（L3）判的是「**值整句等于通用空状态短语**」。
⇒ 「暂时没有内容可显示」**不是**通用短语 ⇒ **L3 判绿**；
⇒ 但它**没有区分** 5 种状态 ⇒ **它恰恰是本轮要治的病** ⇒ **门是绿的，界面在混同状态**。

⇒ **「门绿」只说明「门测的那件事成立」——测的不是要的 ⇒ 绿是假绿**（§424 形态一）。

⇒ 本门与 L3 **分工**：L3 管措辞，本门管结构。

### 4.2 六条判据（全部可证伪）

| # | 判据 | 挡住的回归 |
|---|---|---|
| ① | 退役键**源码 0 引用**（只认真取键调用） | 「为了省事」再引一次通用键 |
| ② | 退役键**8 语种语言包里都不存在** | 键还在包里，等着被接回去 |
| ③ | 登记键**8 语种齐备** | 半边落地 |
| ④ | 登记键**键名末段带 kind 标记** | 差异退化成措辞差异 |
| ⑤ | 登记键的值**不是通用空状态短语**（复用 `LOCALE_GENERIC_EMPTY`） | 措辞退化 |
| ⑥ | 同语种内登记键的值**互不相同** | 不同页面说同一句话 |
| ⑦ | 登记键**源码引用数 ≥ 1** | 登记簿变成死键的新家 |

### 4.3 ★ 引用集口径：只用「真取键调用」

死键门的 `collectStaticRefKeys()` 刻意**保守**（所有点分字面量都算引用 ⇒ 少删键）——
在**死键**方向是优点，在「**这个键被用了吗**」这个问题上是错的：
★ **注释里提到一个键名、测试里断言一个键名，都会被算成「在用」**。

⇒ 实测（本轮）：注释里写 `dashboard.board.empty`（讲旧版行为）、
测试里写 `expect(used.has('hyper.list.empty')).toBe(false)`（断言它**不该**出现）
—— 都被算成「引用」⇒ 门误报 3 处。
⇒ 本门自建 `collectCallSiteRefKeys()`（只认 `t/te/tm/TE/localeArray/i18n.t` 的**紧邻字面量**调用）。

★ 这是**把判据对准被问的那件事**，不是放宽判据。
