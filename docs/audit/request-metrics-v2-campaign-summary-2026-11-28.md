## 七、经验教训

### 7.1 配置管理

**问题**：245 有两个配置文件（/etc 和 /opt），部署脚本修改了后者但未同步前者  
**教训**：配置 SSOT 必须单一，避免多源不一致  
**建议**：/etc 作为 SSOT，/opt 通过符号链接或部署时复制

### 7.2 诊断方法论

**问题**：初次诊断时从运行进程读取到 211 DB，但未核对配置文件历史  
**教训**：环境变量可能被动态覆盖，必须交叉验证配置源  
**方法**：实证三角 — 配置文件 + 进程环境 + 实际连接测试

### 7.3 密码管理

**问题**：252 密码变更未同步到 245/154  
**教训**：共享数据库的密码管理需要中心化同步机制  
**建议**：使用密钥管理服务（如 Vault）或部署前自动同步验证

### 7.4 Base64 编码陷阱

**问题**：凭据密钥末尾 `=` padding 丢失  
**教训**：Base64 字符串复制粘贴时容易截断 padding  
**验证**：密钥长度必须是 4 的倍数，末尾 `=` 是合法字符

### 7.5 URL 特殊字符

**问题**：密码中的 `@` 和 `#` 未编码导致解析失败  
**教训**：数据库 URL 中的密码必须 URL 编码  
**规范**：
```
@ → %40
# → %23
$ → %24
& → %26
```
