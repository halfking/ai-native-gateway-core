## 1. 项①：两份 SQL 抄本 → 只有一份

### 1.1 病根（不是「忘了改」，是**结构**允许它漂）

上轮把五份表达做成了「改一份忘另一份会当场红」的三道锁步门，但**抄本仍是抄本** ⇒ 第五份、第六份照旧各自漂。本轮把**结构**改掉：

```
provider/modality_accept.go（新增·唯一实现）
  ├─ ModalityAccepts(registered, requested)          ← ③ Go 判据
  └─ ModalityAcceptArmsSQL(placeholder)              ← ①② SQL 形态的唯一片段
        ↑ 由它渲染：① provider.candidateQuerySQLBase（$3）
                     ② domains/streaming.alternativesSQL（$5）
```

### 1.2 ★★ 拼接形态对 `sql_comment_syntax_test.go` 的要求：**实测出来的，不是想出来的**

候选形态有两种：把片段**拼**进主 SQL，或用占位符 **Replace**。仓内既有先例是 `/*MODALITY_VERDICT_GATE*/` 的 Replace。**为什么必须是 Replace**：

* **provider 侧那道词法门**（`provider/sql_comment_syntax_test.go`）按「行尾单个反引号 = 块开头」＋「块内第一个反引号 = 块结尾」配对 ⇒ 一行里出现**两个**反引号（`... AND (` + frag + ` `）时，它在**第一个**反引号处就把块关掉 ⇒ ★★ **拼接之后的那一半 SQL 整段不再被扫** ⇒ 那一段里的 `//` 注释对门**完全隐形**。
  ⇒ 实测夹具见 `provider/sql_comment_syntax_test.go` 的 `TestSQLCommentScanner_SeesPastConcatenation`（旧实现 0 命中 / 新实现 1 命中）。
* ⇒ 因此：**主 SQL 保持一个完整 raw string**，片段用占位符 + `strings.Replace` 替换。

### 1.3 ★★ 顺带量出**权威门**（repo-wide AST 门）的盲区，并修掉

仓内另有 `internal/sqlguard/sql_literal_guard_test.go`（repo-wide，AST 扫描）。本轮实测它的**覆盖边界**：

* 它用 **AST** ⇒ `+` 拼接的两半是两个 `BasicLit` ⇒ **AST 本身**不会在拼接点失明；
* ★ 但它**认 SQL 的方式是「形状」**（字面量第一个有效行必须以语句关键字开头）⇒ ★★ **被拆开的后半段**，它自己的第一个有效行不是语句关键字 ⇒ **不被认成 SQL** ⇒ ★★ 后半段里的 `//` 注释**看不见**。
* ⇒ 实测：把门修成「**一组拼接里，第一片像 SQL ⇒ 整组都按 SQL 扫**」（修之前：自证夹具 0 命中；修之后：1 命中）。
* ⇒ ★ 修的过程里**撞到一次假阳性**：第一版用「任意一片像 SQL」⇒ 把 `internal/dbx` 的**测试夹具**（整段 Go 源码当字符串塞进 raw string，里面嵌着 SQL）里的 Go 注释误判成 SQL 注释 ⇒ ★⇒ 判据改成「**第一片**像 SQL」⇒ 假阳性消失，真实覆盖不丢。
* ⇒ ★ 边界写进门里（`TestSQLLiteralGuard_CoverageBoundary`）：本门只覆盖 **SQL 语句形态**的字面量；★ **SQL 表达式片段**（本轮的模态接受臂唯一片段）**不在**它的范围内 ⇒ 它的覆盖归 provider 侧那道**词法**门（扫整个包的所有 raw string，不问形状）⇒ ★★ **两道门必须同时存在**。

## 2. 项②：default 臂收窄为精确相等

* **事实依据**：①的兜底臂本来就是 `COALESCE(mc.modality,'text') = $P`（**精确**）；③此前是 `registered == requested || registered == "multimodal"`（**宽**）⇒ ⇒ 在 (multimodal, 未知请求值) 这格**语义相反**。
* **收窄后**：③ = 精确 ⇒ ①②③ 在**全部**格上同义 ⇒ ★ **域外分歧注销**（上轮登记的那条作废）。
* ★ **收窄不是审美**：兜底精确臂是**承重**的 —— `/v1/embeddings` 靠它命中登记为 `embedding` 的行；放宽成「multimodal 也接」⇒ **嵌入请求会被路由到 chat 型多模态模型** ⇒ 那是功能事故。
* ★ **调用方核对**：`ModalityAccepts` 的调用方只有诊断路径（`provider/modality_mismatch.go`）与发布表派生 ⇒ **没有任何调用方依赖「multimodal 通配」**（实测 grep 全仓）。
* ★ **发布表（第五份表达）改为派生**：`supportedModalitiesFor` 现在由 `provider.ModalityAccepts` 过滤请求词表得出 ⇒ 删掉手写表。
  * ★ 形状变化**只有一处**：登记为 `embedding` 的模型现在也发布 `embedding`（此前只发 `[text]`）⇒ 那是**修好了**（此前是**少报**）。
  * ★ 派生后，原来的「表 vs 判据」交叉检查变成**恒真** ⇒ ★ 按「恒真断言要主动做负控」拆成两条有牙的断言：黄金表（含「天真的表会算错」的格）+ **换输入必须换输出**的负控。

## 3. 项③：读方「环境失败 vs 判据失败」分离

### 3.1 病

`web/scripts/design-icon-size-runtime-check.mjs` 在**浏览器驱动失败**时以 `exit 2` 退出 —— 而 exit 2 在该工具里是「自证失败」的码 ⇒ 仓内 Go 侧掏空门把它判成「**红了，但红因不对**」⇒ ★★ **随机误判「门没牙」**。

★ 实测（本轮端到端）：

| 形态 | 掏空门的行为 |
|---|---|
| 旧（exit 2，无探针） | **FAIL**：`读方在【基线】就红 ⇒ ⇒ 不可判定 ⇒ ★ 先把读方修绿。` ← ★ **假指责**（读方没坏，是环境坏了） |
| 新（exit 3 ＋ 探针） | **SKIP**：`★ 读方没量到（环境不可用）⇒ ⇒ 本条本轮不可判定 ⇒ ⇒ 跳过（★ 不是「门没牙」，也不是「读方坏了」）` |

★ 复现方式：`CHROME_PATH=/bin/echo`（路径存在但不是浏览器 ⇒ 驱动必然失败）。

### 3.2 三处改动（读方侧 ＋ 门侧）

1. ★ **icon-size 读方补上「基线不可用 ⇒ 在测量之前就判红」的早退**（两个兄弟读方早有，icon-size 没有）⇒ ★★ **掏空态从 87s 变成 0.03s**（不碰浏览器）⇒ ★★ **随机误判的根因被移除**（掏空态压根不需要浏览器）。
2. ★ **环境失败改走 exit 3 ＋ 探针 token `[ICON-SIZE-NOT-MEASURED]`**（三个兄弟读方同款统一）⇒ 门侧新增「环境不可用 ⇒ 不可判定 ⇒ 跳过」这一等分类（`structuredIsEnvUnavailable`）。
3. ★ **顺带修掉一个真缺陷**：icon-size 的 `--update-baseline` 写回值**直接写实测值** ⇒ 一次误操作就能把**上限型**棘轮放松 ⇒ 改为「只许降不许升」（与两个兄弟读方同款）。

★ 门侧判据是**两条取或**（退出码 3 **或** 输出里有探针 token）⇒ 读方换退出码也不怕；★ 分类器自带**负控**（`TestStructuredIsEnvUnavailable`）：正常判据红 / 自证失败（exit 2）/ 绿 / 崩溃但 exit 1 ⇒ 四档都**不得**被判成环境失败。
