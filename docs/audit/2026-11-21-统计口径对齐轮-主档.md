## 二、本轮三个真缺口（实测定案，不是推断）

### 缺口 1：request-logs 的「包含探测」是**盲的**（修 = 探测臂）

`/api/logs` 后端早有 `include_probe=1` / `lane` 参数（2026-11-02 探测隔离轮），
但：
- **前端从未发送**（RequestLogsView.vue 全文无 lane/include_probe 引用）⇒ 页面永远
  业务口径；
- 更深一层：include 模式只是**摘掉业务两臂上的 stage 过滤**，而迁移 928 物理隔离后
  当前探测落在 `session_turns_probe_hot`（25 列窄表），业务两臂里根本没有探测行
  ⇒ 即使发了 `include_probe=1`，总请求也**永远小于供应商对账**（probe 部分 ~14.5k/日，
  ≈50%，不是边缘差）。

**修法**（`db/session_probe_arm_source.go` + `admin/logs.go`）：
- 三臂 UNION：业务两臂（hot ∪ parent）∪ 探测臂（probe_hot 按**同一份 118 列
  canonical 投影**展开，逐列类型对齐——业务臂 jsonb 的列出 `NULL::jsonb`，
  `::numeric(14,8)` / `::character varying(255)` 转型逐列镜像；
  `attachment_count` 出字面量 `0`（扫描结构体非指针 int，NULL 必炸））；
- 探测臂费用列经 **usage_facts 按 request_id 聚合**（`traffic_class <> 'business'`，
  GROUP BY 去重 revision）LEFT JOIN 挂回 ⇒ 包含探测的 COUNT/tokens/cost/credits
  与 board include_probes（usage_facts 全量）同真源；
- **无重复计数**：同一 request_id 只落一条车道（探测臂只挂 probe_hot 行；
  隔离前历史 marker 行的费用在业务两臂自带 `session_turns.cost_usd`）；
- 响应新增 `traffic_lane`（business/all/probe_history），前端徽标跟随响应值。

**真库验证**（本地 PG17，迁移 928 试应用 + 种子行）：三臂 UNION 的
COUNT/SUM(cost)/SUM(tokens) 与 usage_facts 同窗聚合**逐字相等**（1/0.0123/150 双向）。

**request-logs 前端**（`RequestLogsView.vue`）：筛选条头部加「包含探测」开关
（data-testid=`logs-probe-scope`，持久化 `llmgw_logs_probe_scope`），统计概览条
同徽标；i18n 8 语种（`requests.list.probeScope.*`）。

**与 live2 的对齐口径**：live2 主车道只下发业务 tile（probe tile 独立键空间，
`?probe=1` 才订）⇒ live2 实时统计 = 业务口径 = board 缺省英雄区，两者只差取数周期
（live2 内存滚动窗 vs board usage_facts 日窗）——**该对齐已成立，本轮只登记**。
board include 模式停用 SSE 业务增量合并是 2026-11-20 轮已有的行为。

### 缺口 2：dashboard 会话统计含探测未排除（修 = 会话宇宙对齐 + 对齐指标行）

`/api/admin/dashboard/session-overview` 直读 `session_summaries`（无探测排除），
而 981 实测该表 ~80% 是探测/自检会话；`/admin/session-analytics` 的物化视图
排除它们 ⇒ 两边「会话总数」差一个数量级级别，窗口语义也不同（滚动 NOW()-N 天 vs
上海日历日桶）。

**修法**（`admin/dashboardapi/session_overview_alignment.go` + 六条腿改造）：
1. **会话宇宙对齐**：缺省给全部 session_summaries 腿套上与 994 物化视图**逐字
   同构**的宇宙（JOIN sessions + LEFT JOIN session_dim + owner 双源键非空 +
   `NOT is_probe` + `NOT session_analytics_is_probe(owner, client_type, title)`）。
   片段收敛到 `domains/analytics/session_probe_scope.go`（迁移 SQL 由
   `session_probe_scope_contract_test.go` 做归一化文本对拍——两份拷贝各改一半的
   漂移被门咬住）。`include_probes=1` 回历史全量；依赖缺失（未迁移环境）逐腿
   自动降级全量 + `probe_scope=degraded_included`（降级可见）。
2. **对齐指标行（即时查询 + 缓存定时刷新两级并存）**：响应新增 `aligned` 块，
   读 `user_session_aggregates` + `model_usage_aggregates`（15 分钟刷新的缓存面），
   SQL 从 admin/session_analytics **逐字迁到 `domains/analytics/aligned_source.go`
   单一真源**（session_analytics 反向委托）⇒ 看板对齐行与会话分析总览页数字
   **构造相等**，不是「再算一遍碰巧相等」。窗口=上海日历日（与物化视图日桶同尺，
   刻意不用 settings.SystemDayRangeUtc——那是系统时区，非 +08 部署机错位一天）；
   days 预设自动折算 `[today-(N-1), today]`，与会话分析前端预设同折算。
   物化视图缺失 ⇒ `aligned_source=unavailable`、对齐块缺席。
3. **单位纪律**：aligned 块 internal_cost_usd（美元）与 external_credits（积分）
   分列，禁止相加（framework §3.2）；顺带给 OverviewSummary 补了 internal/external
   单列输出（跨单位 total_cost 保留为既有契约）。
4. R87 门（合并腿钉测）按 ss. 别名形态更新——**同覆盖**（24 条聚合表达式 + 别名
   集合断言不变），段数 7→8（新增对齐腿）。
