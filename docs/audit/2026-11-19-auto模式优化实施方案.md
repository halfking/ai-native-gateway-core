## 二、待实施的优化项

### 2.1 任务识别的本地+远程模型协作（核心优化）

**当前状态**：
- 任务识别分两层：启发式分类器（本地规则）+ LLM分类器（远程调用）
- LLM分类器在启发式置信度低于阈值时触发
- 代码位置：`autoroute/classifier_llm.go`

**优化方案**：

```go
// 任务识别流程优化
type TaskRecognitionPipeline struct {
    // 第一层：本地快速分类（基于规则和模式匹配）
    LocalClassifier *HeuristicClassifier
    
    // 第二层：本地轻量模型（可选，用于中等置信度场景）
    LocalLightModel *LocalModelClassifier  // 新增
    
    // 第三层：远程精确模型（用于复杂任务）
    RemotePreciseModel *LLMFallbackClassifier
}

// 决策流程
func (p *TaskRecognitionPipeline) Classify(ctx context.Context, sigs ClassificationSignals) (*Classification, error) {
    // 1. 本地规则分类
    result1 := p.LocalClassifier.Classify(ctx, sigs)
    if result1.Confidence >= 0.85 {
        return result1, nil  // 高置信度，直接返回
    }
    
    // 2. 本地轻量模型（新增）
    if p.LocalLightModel != nil && result1.Confidence < 0.85 && result1.Confidence >= 0.5 {
        result2 := p.LocalLightModel.Classify(ctx, sigs)
        if result2.Confidence >= 0.75 {
            return result2, nil  // 中等置信度提升，返回
        }
    }
    
    // 3. 远程精确模型（仅在必要时）
    if result1.Confidence < 0.5 {
        return p.RemotePreciseModel.Classify(ctx, sigs)
    }
    
    return result1, nil  // 降级使用本地结果
}
```

**实施步骤**：
1. 设计本地轻量模型接口
2. 评估可用的本地模型（如TinyBERT、DistilBERT等）
3. 实现 `LocalModelClassifier`
4. 添加配置开关，支持逐步灰度
5. 监控三层分类器的命中率和准确率

### 2.2 模型指派流程透明化

**目标**：让每个auto请求的决策过程可追溯

**实施**：
1. 在响应头 `X-Gw-Auto-Decision` 中增加字段：
   ```json
   {
     "chosen_model": "glm-5.1",
     "task_type": "chat",
     "classifier": "heuristic",  // or "local_model" or "llm"
     "confidence": 0.92,
     "candidates_count": 5,
     "reselect_happened": false,
     "fallback_used": false,
     "decision_time_ms": 12
   }
   ```

2. 在 `auto_route_selections` 表中增加列：
   - `classifier_type` (heuristic/local_model/llm)
   - `reselect_chain` (JSONB，记录重选过程)
   - `decision_latency_ms`

### 2.3 PI分析层与auto模式集成

**场景**：auto请求失败时，PI分析层自动分析根因并提供修复建议

**实施**：
1. auto请求失败时触发PI分析
2. PI分析识别失败原因（凭据问题/模型不可用/配额耗尽等）
3. 自动应用修复（如果有可用的修复动作）
4. 记录到 `pi_analysis_queue` 表

## 七、风险和缓解

### 7.1 风险清单

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| 换模导致成本增加 | 中 | 中 | 监控fallback比例，设置成本告警 |
| 零候选重选失败 | 高 | 低 | 保留宽退路池（32个模型） |
| 任务分类错误 | 中 | 中 | 监控分类准确率，持续优化规则 |
| LLM分类器调用失败 | 中 | 低 | 降级到启发式结果 |
| 会话粘性过强 | 低 | 低 | 重校验机制已实现 |

### 7.2 应急预案

**场景1：auto请求成功率突然下降**
```bash
# 1. 查看最近的失败请求
# 2. 检查是否是某个模型的问题
# 3. 如果是，临时禁用该模型
# 4. 如果是整体问题，热关闭换模开关
```

**场景2：决策延迟过高**
```bash
# 1. 检查LLM分类器调用频率
# 2. 如果过高，提高启发式分类器的置信度阈值
# 3. 或临时禁用LLM分类器
```

## 八、后续优化方向

### 8.1 短期（1-2周）

1. **实现本地轻量模型分类器**
   - 选型：TinyBERT / DistilBERT / 自训练小模型
   - 目标：中等置信度场景不调用远程LLM
   - 预期收益：降低分类延迟50%，降低成本70%

2. **优化任务分类规则**
   - 收集分类错误案例
   - 分析特征模式
   - 更新启发式规则

3. **增强可观测性**
   - Grafana dashboard for auto模式
   - 实时监控成功率、延迟、分类准确率
   - 告警规则配置

### 8.2 中期（1-2月）

1. **A/B测试框架**
   - 支持不同分类策略的对比
   - 支持不同退路池大小的对比
   - 收集用户反馈

2. **自适应退路池**
   - 根据实时可用性动态调整退路池
   - 学习用户偏好（如果某个模型经常被人工覆盖，降低其优先级）

3. **多维度评分优化**
   - 当前主要基于成功率和延迟
   - 增加：用户满意度、成本效率、模型能力匹配度

### 8.3 长期（3-6月）

1. **强化学习优化**
   - 从真实流量学习最优路由策略
   - 个性化推荐（不同用户/租户的偏好）

2. **预测性路由**
   - 预测模型即将不可用（基于历史模式）
   - 提前切换，减少失败率

3. **与magpie的功能对齐**
   - `auto/<model>` 语义（同模型跨供应商）
   - patience轮次机制
   - 更细粒度的rest策略
