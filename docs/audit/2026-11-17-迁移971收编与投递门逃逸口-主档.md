## 一、取证：问题不是「忘了登记」，是「**登记这件事不会变红**」

### 1.1 事实链（逐点量的，非推测）

| # | 事实 | 取证方式 |
|---|---|---|
| ① | 迁移落在 `sql/migrations/domain/641_pi_error_analysis_system.sql` | `git show --stat 0e62d88da` |
| ② | **`sql/migrations/domain/` 是死文件区**：该目录 **95 个 `*.sql` 文件（含 `.down.sql`），无一件**登记进 installer `StartupFiles` 或 deploy 通道 `files=(...)` 数组 | 逐文件比对（见 §1.2） |
| ③ | 本仓两道投递门**都扫不到它** | 读门禁源码（见 §1.3） |
| ④ | 原件**非幂等**：9 个裸 `CREATE INDEX` + 1 个裸 `CREATE TRIGGER` | 通读 SQL |
| ⑤ | deploy 通道**会重放内容变化过的已应用文件** | `apply-db-revision-sequence.sh` 的指纹台账逻辑 |
| ⑥ | PI 错误分析代码**无任何生产调用方**（Phase 1 未接线） | `grep ErrorCollector\|ErrorAnalyzer` 全仓 |

★ 改动后该目录剩 **93** 个 `*.sql`（最大编号 **640**），逃逸口由 §2.4 的门焊死。

★ 同仓先例：`db/migrations/README.md` 已用同样口径把该目录标为
「**冻结的历史通道，禁止新增与手工执行**」「没有执行器接线」，纪律是
「新的 schema 变更一律走 `sql/migrations/startup/` 编号通道」。

### 1.3 两道门为什么没抓住（**本轮最重要的发现**）

| 门 | 位置 | 扫描范围 | 为什么看不见 641 |
|---|---|---|---|
| 三通道覆盖门 | `internal/sqlguard/migration_delivery_channel_coverage_test.go` | **只扫 `sql/migrations/startup/`** | 641 在 `domain/` ⇒ 根本不在扫描面里 |
| embed 强制门 | `installer/cmd/llm-gw-installer/migration_embed_sync_gate_test.go` | 只对 **≥849** 的 canonical 件要求 embed 副本 | 641 < 849 ⇒ 即使搬进 `startup/` 也**不在覆盖内** |

★ ⇒ **`domain/` 是一个门禁盲区**：把迁移放进去，等于同时躲开「部署通道登记」
与「embed 副本」两维 ⇒ CI 全绿而迁移永不落地。
这与 AGENTS.md 记过的两次同型事故同源（966 只登记未投递、968 DDL 写在死通道）。

### 1.4 为什么非幂等是**真雷**（不是洁癖）

deploy 通道的台账是**内容指纹**（`public.gateway_db_revision_sequences`）：

- 指纹一致 ⇒ 跳过（`already applied`）；
- **指纹变化 ⇒ 重放**（`content replay`）。

⇒ 一旦有人给这条迁移「加固」内容（加注释、加 SET LOCAL），sha 变化 ⇒ 重放 ⇒
裸 `CREATE INDEX` 撞 `42P07`、裸 `CREATE TRIGGER` 撞 `42710` ⇒
`psql_stream` 带 `ON_ERROR_STOP=1` ⇒ **通道失败 ⇒ 部署 die**（切流前，旧槽继续服务）。

## 二、修法

### 2.1 收编 + **改号 971**（而不是沿用 641）

| 编号 | ≥849（embed 强制门覆盖） | = maxNum（三通道覆盖门近邻窗口 `maxNum-19..maxNum`） | 门保护 |
|---|---|---|---|
| 641 | ✗ | ✗（远离 970） | **无** |
| **971** | ✓ | ✓ | **双门接管** |

★ ⇒ 改号不是为了「显得新」，而是**为了让门能管住它**：
今后任何漏登记 / 漏 embed / 漏账本，都会在 CI 里变红。

### 2.2 幂等化（逐项可点名）

- 9 个索引 ⇒ 一律 `CREATE INDEX IF NOT EXISTS`
- 触发器 ⇒ 先 `DROP TRIGGER IF EXISTS` 再 `CREATE TRIGGER`
- 视图 / 2 个函数 ⇒ `CREATE OR REPLACE`
- 台账自登记 ⇒ `ON CONFLICT (version) DO UPDATE`
- 全部对象 ⇒ `public.` 限定；文件 ⇒ `BEGIN; SET LOCAL lock_timeout='5s';
  SET LOCAL statement_timeout='10min'; … COMMIT;`

### 2.3 七点登记（逐点核对）

| # | 点位 | 落点 |
|---|---|---|
| ① | canonical | `sql/migrations/startup/971_pi_error_analysis_system.sql`（+ `.down.sql`） |
| ② | embeddata 副本 | `installer/cmd/llm-gw-installer/embeddata/startup/971_*.sql`（**字节级相同**） |
| ③ | `go:embed` + var | `installer/cmd/llm-gw-installer/main.go` |
| ④ | `embeddedSQLFiles` map | 同上 |
| ⑤ | dbinit `StartupFiles` | `installer/internal/dbinit/runner.go` |
| ⑥ | deploy 通道 `files=(...)` + `ledger_artifact_probe` | `scripts/apply-db-revision-sequence.sh` |
| ⑦ | 台账 | `sql/schema/installed_startup_migrations.tsv`(371) + **`docs/db-changelog.md`**（sha `018a4b7b…`） |

★ 第 ⑦ 点的 `docs/db-changelog.md` 是**权威 sha 台账**
（`scripts/verify-migration-checksums.sh` 与 `internal/sqlguard` 的 sha 门都读它），
漏了它 ⇒ 门判 `MISMATCH` ⇒ CI 失败。

### 2.4 新增守门测试

`internal/sqlguard/migration_971_delivery_six_points_test.go`（4 条）：

1. **七点齐备性** —— 逐点断言（含 embed 副本逐字节、deploy 数组**数组块内**匹配、

## 四、通用式

1. ★★ **「把文件放进错目录」的代价不是「没生效」，是「没生效而且 CI 不告诉你」** ——
   本仓的投递门按**目录**划扫描面（`startup/` vs `domain/`），
   ⇒ 错目录 = 同时躲开两维检查 ⇒ 「静默」是**设计出来的**，
   不是执行者的疏忽。**⇒ 判据必须覆盖「文件落在哪」，而不只是「文件写了什么」。**
2. ★★ **「编号」也是门覆盖面的一部分** ——
   embed 强制门只管 ≥849、三通道覆盖门只管近邻窗口 ⇒
   **一个低于门槛的编号，等于一件「无人看管」的资产**。
   ⇒ 新迁移的编号必须**落在门的覆盖面内**，否则「登记对不对」全靠人记。
3. ★★ **非幂等件放进「会重放」的通道＝定时炸弹** ——
   指纹台账在内容变化时会**重放**已应用文件 ⇒ 非幂等 DDL 会在**未来某次无关的改动后**
   才炸（当天的部署是绿的，几周后有人「加固」一行注释就部署 die）。
   ⇒ **投递通道上的每条迁移都必须幂等**（实测二次执行零报错，是最低验收线）。
4. ★ **实测优先于拍脑袋** —— 门禁要求「量的是哪个环境哪张表、量出多少」；
   本轮量出 99ms / 85ms / 1163ms 三个数，比任何论证都有说服力，
   而且**最坏形态**（50 万存量 + 索引全缺）那一测才真正回答了「10min 够不够」。
5. ★ **收编别人的迁移不是「改别人的代码」，是「把它放进有执行器的通道」** ——
   本轮保留了原 SQL 的**全部语义**（表结构、约束、视图、触发器、函数逐字保留），
   只加幂等包装与登记点 ⇒ **双方语义都保住**，且原件的意图（Phase 1 基础设施）
   第一次真正可执行。
6. ★ **「功能未接线」与「schema 未落地」是两件事** ——
   本件在改动前处于「代码在、schema 从未建、且无人调用」的三重静止态：
   **不报错、不告警、也不可用**。⇒ 这类状态只有靠**跨层对拍**（代码引用的表 ↔ 迁移建的表）
   才抓得到 ⇒ 本轮为此加了一条门。
