## §二 生产三层链路实证（「检查逻辑」的正面交付）

auto 请求的意图理解 → 任务类型 → 模型匹配 → 路由全链（`cmd/gateway/main.go:6063-6170` 装配，亲验）：

| 层 | 维度 | 实现 | 证据 |
|---|---|---|---|
| **Layer 1 规则启发式**（速度≈0 成本） | μs 级纯内存 | `HeuristicClassifier.Classify`：6 通道硬覆盖（vision/强编码/审计/意图分类/规划/长上下文）→ tool 分派 → **24 条结构正则**（patterns.go:92-340）→ 关键词（zh+en，多通道加权）→ `codeOutputNegated` 否定守卫（classifier.go:640-644 亲验）→ winner + **dominance bonus**（≥0.8 时 +0.05 上限 0.95，classifier.go:655-659 亲验，把清晰胜者顶过 LLM 阈值避免无谓 LLM 调用＝成本层的一部分） | classifier.go / patterns.go / task_types_ext.go |
| **Layer 2 会话粘性**（准确/零边际成本） | 内存+Redis 双层 | `SessionIntentCache`（session_intent_cache.go：会话级 task/model/profile 粘性 + 50 次命中漂移检测 `shouldReclassify`）；分类结果另有 `classification_cache.go` 请求哈希 TTL/LRU；装配点 main.go:6106-6114（fpSlotRedis 存在时挂 Redis 版） | decision.go 会话缓存 consult/reclassify |
| **Layer 3 LLM 兜底**（准确/有成本） | 低置信才升级 | `Decider.classify`（decision.go:999-1048 亲验）：heuristic 置信 < `effectiveLLMThreshold()`（TuningStore 动态读，decision.go:380-384）→ LLM fallback（`NewLLMFallbackClassifierWithCaller`，HTTP caller + 熔断 + 指标三件套，main_types.go:229-247）→ 失败 fail-open 保 heuristic；R44 门（decision.go:1038-1046）拒低置信外部结论替换本地 winner；Jev 分类器可选占位同一槽（main_types.go:261-274） | http_llm_caller.go / classifier_llm.go / classifier_jev.go |
| **匹配到模型** | 准确/成本再平衡 | 任务类型 → `Index.Recommend`（index.go，5 分钟滚动 credential_model_index 快照热路径）→ Profile 权重（profile.go：smart/speed_first/cost_first 八维权重＝速度/成本的运营面表达）→ candidate 打分（scoring*.go）→ task profile overlay + admin task→model 覆盖（override_store.go） | index.go / profile.go / scoring.go |
| **运行时调参** | 不重启改语义 | `TuningStore`（tuning_params 表，5 分钟刷新 + admin 即时重载）：关键词/阈值/权重运行时覆盖（classifier.go:384-428），LLM 阈值同源 | tuning_store.go |
| **影子学习** | 准确性演进 | `EmbeddingClassifier`（余弦近心 + EMA 质心更新，shadow 1% 采样，feature flag `AutoEmbeddingRoute` + ANAIYSIS env 三件套，main.go:6118-6149） | embedding_classifier.go |

**三层平衡的现行实测形态**：85-95% 请求 Layer 1 零成本收敛（dominance bonus 专门为「少打 LLM」设计）；会话内重复形状 Layer 2 直接粘住；只有真歧义且配置了 LLM 端点才付费升级。**生产 211 实测（本轮 docker env 取证）：`LLMGatewayAutoLLM*`/Jev/ANALYSIS 三组 env 均未设 ⇒ Layer 3 装配为 `DisabledCaller`（main_types.go:236-238）+ 影子分类器不挂 ⇒ 现网实际运行 Layer 1+2，Layer 3 槽位在但惰性（fail-open no-op）**。这是运营旋钮不是缺陷——启用需要选型+计费裁决（与 r1047 判官后端同形状，归 owner），旋钮已在 §五 补披露。
