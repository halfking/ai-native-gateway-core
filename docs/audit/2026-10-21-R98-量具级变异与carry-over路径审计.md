## 2. 发现 1（真缺陷）★ 级联第 4 级是**不可达的死分支** ⇒ 「不许自动重锚」从未落地

### 2.1 文档原文（R97 审计档 `§5.3'`）

| 级 | 情形 | 动作 |
|----|------|------|
| 1 | 主键 `(file,fp,occ)` 精确命中 | 直接沿用 |
| 2 | 同 `(file,fp)` 组内**行号未变** | 沿用（行号是更强的锚） |
| 3 | 同 `(file,fp)` 组内**组内行数未变** | 按序重锚（附注「顺序重锚」） |
| **4** | 同 `(file,fp)` 组但**组内行数变了** | **pending**（occ 位移 ⇒ 无法安全重锚 ⇒ **不许自动重锚**） |
| 5 | 同 `(file,line)` 有旧行但**指纹变了** | **口径漂移 ⇒ pending**（原 evidence 保留，**不许自动重判**） |
| 6 | 其它 | 新增（自动初稿） |

### 2.2 代码原文（R97 量具 `build_ledger`）

```python
old = None
...
if (path, fp, o) in old_by_key:        # 第 1 级
    old, status = old_by_key[(path, fp, o)], "exact"
elif grp:
    ...
    else:
        status = "shift"                # ← 第 4 级的**入口**
...
if old is not None:                    # ★★ old 在 shift 情形下恒为 None
    ...
    elif status == "shift":             # ←★★ 第 4 级的**动作写在这里 ⇒ 不可达**
        v = "pending"
```

⇒ ⇒ **`status == "shift"` 时 `old` 恒为 `None`** ⇒ `if old is not None:` 为假
⇒ ⇒ **`elif status == "shift":` 永远进不去** ⇒ ⇒ **`stats["shift"]` 恒为 0**
⇒ ⇒ **量具自己都报不出「第 4 级没生效」这件事**。

### 2.3 还有第二重：第 1 级会**抢先**

组大小变了（例如 3 行变 2 行）时，旧组的 occ 仍是 `1..3` ⇒ `(path,fp,1)`、`(path,fp,2)` **照样命中**
⇒ ⇒ 所谓第 4 级**根本没机会被判定**。

⇒ ⇒ **两种真实形态**：

| 形态 | 旧 | 实际行为 | 设计要求 |
|------|----|---------|---------|
| 组变多（2→3） | 2 行 | 前 2 行 exact 沿用；**新增行走第 6 级 ⇒ 自动初稿** | 新增行 **pending** |
| 组变少（3→2） | 3 行 | 前 2 行 exact 沿用；**旧第 3 行的裁决静默消失**（若该 `(file,line)` 仍在，连「上游已消失」都不报） | **pending** |

### 2.4 实测（合成夹具，组 2→3）

**修前**：

```
⇒ 台账写入 …：共 3 行（沿用人工裁决 2 / 重锚 0 / **新增 1** / **因口径漂移或位移作废 0** / **待裁决 0**）
   line=5 occ=3 usage=value verdict=**benign-value**  reason=取值用：管道退出码被命令替换丢弃
```

⇒ ★★ 受影响行拿到的是**自动初稿的终值 `benign-value`**，`reason` 也是自动初稿的措辞
⇒ ⇒ **人工裁决被静默顶替**（且因为 `usage=value` 的自动初稿是**终值**，**连 pending 都不会产生**）
⇒ ⇒ `作废 0` ⇒ **零信号**。

**修后**：

```
⇒ 台账写入 …：共 3 行（沿用人工裁决 2 / **重锚 2** / 新增 0 / **因口径漂移或位移作废 1** / **待裁决 1**）
   line=5 occ=3 usage=value verdict=**pending**  reason=★ 同形组行数变化 ⇒ occ 位移 ⇒ **无法安全重锚** ⇒ 需人工重裁（原证据保留供重裁参考）
```

### 2.5 危险方向（为什么这值得修）

- `usage=value` / `usage=bare` 两桶的自动初稿是**终值**（`benign-value` / `benign-bare`）
  ⇒ ⇒ 上游一旦在同形组里插删一行，受影响的行会**直接拿到终值**，**没有 pending、没有告警**。
- ⇒ ⇒ 若那一行原先的人工裁决是 `risk-*` ⇒ **risk 被静默降级成 benign** ——
  这正是 R97 轮明文写着要防的那件事（「★ **不许把 risk 降级**」）。

### 2.6 定级

**真缺陷（文档–实现不一致）**。修法是**零语义风险**的：它只把 R97 自己声明的行为补进代码。

## 7. 我自己犯的三个错（都被当场抓到）

### 7.1 ★★ 前缀匹配 ⇒ **假读数 236 行**（真值 37 行）

第一版统计「台账里有多少行是机器初稿」时用了 `reason.startswith(初稿措辞)`
⇒ ⇒ 得 **236 / 354** ⇒ ⇒ **假读数**（把 201 行「人工润色过的同源措辞」也算成了机器初稿）
⇒ ⇒ 改成**逐字相等**后 = **37 行**（18 `benign-value` + 19 `benign-bare`）。

⇒ ⇒ ★ **通用式：★ 前缀匹配会把「人工润色过的同源措辞」误判成「机器原样」**
⇒ ⇒ ★ **计数类结论必须和口径一起发布**（口径 = 「逐字相等」还是「前缀相同」，差 6 倍）。

### 7.2 ★★★ 变异写错了语义 ⇒ **门抓到了，但抓的理由是错的**

第一版 M1/M2 写成 `v = av[0]`。而 `av, ar, ae = auto_verdict(s0)` ⇒ **`av` 本身就是裁决值**（不是元组）
⇒ ⇒ `av[0]` 取到的是**裁决值的首字符 `"b"`**。

⇒ ⇒ 门确实红了 ⇒ ⇒ 但红的原因是「裁决值成了垃圾 `"b"`」，**不是**我声称的「自动初稿的终值顶替人工裁决」
⇒ ⇒ ★★ **「门红」不等于「机制对」**。

⇒ ⇒ 修法（三条同时上）：
① 变异改成 `v = av`（语义精确）；
② **每条变异测试先验「产出正是预期的那个坏值」**，再验「不变量被抓」
⇒ ⇒ 于是「变异套件自己」也有牙（防「变异到别的地方」）；
③ 断言要能**区分「非法裁决值」与「合法但不是 pending」** ⇒ ⇒ 报错才指得准方向。

⇒ ⇒ ★ **通用式：★ 变异测试要断言「坏成什么样」，而不只断言「红了」**
⇒ ⇒ ★ **门红只说明「判据抓到了变化」，不说明「变化是预期的那种」**。

### 7.3 探针把「工具拒绝写出」当成「工具失败」

`LedgerBleed` 触发时工具 **exit 3 且不写台账**（这是**正确行为**）
⇒ ⇒ 我的探针去读没写出的文件 ⇒ 解析崩了 ⇒ ⇒ 探针必须区分「工具报错」与「工具设计上拒绝」。

⇒ ⇒ ★ **通用式：★ 「非零退出」有两种含义：「出错了」与「按设计拒绝了」⇒ 探针要分开报**。
