## 2. 判据侧漏放（核心）：「自建 ⇒ 删它安全」的**位置盲区**

### 2.1 机理

R87 轮的排除规则（`r87SelfCreatedObjects`）返回**名字集合、无位置**：

```go
if self[tg] { skip = true }   // 「这个文件建过它 ⇒ 删它安全」
```

⇒⇒ **「先 DROP 后 CREATE」的形态被误判成安全**
⇒⇒ 而此时 DROP 删掉的是**落点上已存在的那个对象**（产品表）
⇒⇒ **漏放方向（数据事故级）**。

### 2.2 影响面

**28 个文件 / 48 条**语句处于该形态，含产品表：
`route_incidents` / `request_logs` / `request_logs_hot` / `credentials` / `providers` /
`model_offers` / `model_aliases` / `credential_model_bindings` / `provider_models` 等。

### 2.3 决定性实验

位置敏感化后，主门读数：

| 口径 | 候选 | 登记 | 未登记 | 腐化 |
|---|---:|---:|---:|---:|
| 旧（只问「建不建」） | 5 | 5 | 0 | 0 |
| 新（位置敏感） | **9** | 5 | **4** | 0 |

### 2.4 修法

`scripts/ursmcheck/destructive_target_guard_test.go`：

```go
// 新增：对象名 → 最早 CREATE 的字节偏移
func r87SelfCreatePositions(f *ast.File, fset *token.FileSet, consts map[string]string) map[string]int
```

- 与破坏性语句**同款实参解析**（拼接 / const 都能解析）
- 跳过 `r87IsStringInspection` / `r87IsMessageCall` / `r87IsAssertionCarrier` 调用

```go
// r87AnalyzeFile 的排除条件
if self[tg] {
    if cp, ok := createPos[tg]; !ok || cp <= s.pos {
        skip = true
    }
}
```

- 「**建在前**」才排除；「**建在后就**」不排除 ⇒ 进入候选
- ★ 找不到 CREATE 位置时**仍然排除**（保守方向不变）
- ★ **位置单位一致**：两侧都是 `fset.Position(a.Pos()).Offset`（已核）

## 8. ★★ 本轮四次量具故障（都是「读数被自己骗」）

1. ★ `grep -E '^\s*--- FAIL'` ⇒ **BSD grep 不支持 `\s`** ⇒ 匹配失败被读成「没有失败项」。
2. ★ `c.relname||'|'||c.relkind` ⇒ `relkind` 是 **`"char"`** ⇒ `text || "char"` **运算符歧义报错**
   ⇒ 又被 `2>/dev/null` **吞掉** ⇒ **空输出被读成「库里没表」**。
3. ★★ **没清场就观测** ⇒ 两段对照实验**用了同一个库** ⇒ ② 读到 ① 的残留
   ⇒ 与 ② 日志里的 SKIP **直接矛盾** ⇒ ⇒ **同一个坑在同一会话里犯了两次**（M22b 修过一次，M23 没修）
   ⇒ ⇒ **判据要自带清场，不能靠记忆**。
4. ★★ **`git checkout <file>` 还原变异** ⇒ **连自己未提交的改动一起撤掉了**
   （`internal/testdb` 的 `GuardFunctions` 声明没了）⇒ ⇒ ⇒ **还原必须用备份副本**。

⚠ 另：**「通过了」不等于「跑过了」** ⇒ `t.Skip` 也算 pass ⇒ 必须看 `-v`。
