## 一、为什么是这一轮

第 9、10 增量把「外壳」与「引用集盲区」收干净了；第 11 增量转向**文案质量本身**。

impeccable `clarify.md`（94 行）给了三条可判的判据：

| 判据 | 原文要求 | 本轮实现 |
|---|---|---|
| **R1 错误三问** | 错误要回答「什么失败 / 为什么 / 怎么恢复」 | `ruleError()` |
| **R2 别用手势** | 动作/导航用「动词+宾语」，不用「点这里」 | `ruleGesture()` |
| **R3 空状态要能区分** | 区分首次 / 无结果 / 筛选后 / 无权限 / 失败 | `ruleEmpty()` |

**关键判断**：这不是 i18n 门，是**清晰文案门**。它扫的是**源码侧**（界面层），语言包内容由既有 `copy-quality-audit` 管。

### 2.3 ★ 判据是**位置驱动**，不是内容驱动

「文案里有『失败』两个字」≠「这是错误文案」—— 状态词映射、枚举标签、表单校验提示都会误伤。

⇒ **错误位置**（文案落在这里才判 R1）：
1. 兜底形状：`X.message || …` / `instanceof Error ? … : …`
2. 错误槽位：赋值目标逐段含 `err/error/msg/message/fail`，且整串不含 `filter/label/type/status/code` 等
3. 报错调用：`alert` / `notify*` / `ElMessage.error` / `*Err(` / `emit('error')`
4. `throw` / `new Error(`

⇒ **排除**：日志语境（`console.*` / `logger.*` / `log.*`）、标签语境（`label:` / `cls:` / `tooltip:`）。

### 2.4 ★ 提取本身就是判据的一部分

Vue 必须**分层提取**：

| 层 | 提取方式 |
|---|---|
| `<script>` | JS 字面量（单/双引号/模板串） |
| `<template>` 静态属性 | **纯文本**（不是 JS 表达式） |
| `<template>` 绑定属性 | 内嵌 JS 字面量 |
| `<template>` **文本节点** | 纯文本（★ 模板文本不是字符串字面量，只抽字面量的提取器对模板完全失明） |

## 三、★ 本轮最重要的发现：区间配对盲区

### 3.1 现象

门在接线完成后归零（148 → 0）。按纪律做**真仓变异臂**（把违规注入回真实源码看门是否红）⇒ **三臂全绿**。

第一反应是「门没牙」。真因在更前面一层：

- 靶点①落在**注释行** ⇒ 门会剥注释 ⇒ 注释放违规永远红不了
- 靶点②落在**已被 `$t()` 取代的位置** ⇒ 不再是字面量
- 靶点③的模板文本**与相邻段落连成一段** ⇒ 「整句等于黑名单」判据不成立

而**真正的盲区在门自己身上**：

```ts
// 修复前
const close = masked.indexOf('</template>', start)   // ❌ 第一个闭合标签
```

Vue 模板大量使用 `<template v-if>` / `<template v-for>` 作为分组标签，各有各的 `</template>`。
⇒ 顶层 `<template>` 的区间在**第一个嵌套 template 结束处**就截断。

**实测**（`src/views/RoutingDashboardView.vue`）：

| 项 | 值 |
|---|---|
| 顶层 `<template>` | 974 行 |
| 第一个嵌套 `<template v-if>` | 991 行 |
| 修复前区间结束 | **994 行** |
| 真实模板结束 | 1683 行 |
| ⇒ **从未被扫描的行** | **995 ~ 1683** |

⇒ 修复（改用**深度计数**：开标签 +1 / 闭标签 −1，深度归零才是结束）后：

| 读数 | 值 |
|---|---|
| 修复前门读数 | **0 命中** |
| 修复后门读数 | **7 命中** |
| ⇒ **此前一直被判绿的真违规** | **7 处** |

**同族修法**：`scriptRanges` 同样用 `indexOf('</script>')`，而 `.vue` 允许 **`<script setup>` + `<script>` 两个块**
（`views/admin/UsageTrendExplorer.vue` 就是）⇒ 两个块被合并成一段 ⇒ 第二个块的语句上下文判错。⇒ 一并改为深度配对。

## 五、文案改写口径

| 类别 | 判据 | 改法 | 例 |
|---|---|---|---|
| R2 手势 | 「点击 X」是手，不是动作 | 换「动词+宾语」 | 点击 ↻ 刷新 → **按刷新键**重新拉取一次<br>点击详情查看 → **打开详情**可查看本次请求<br>点击上方变体按钮查看 → **选择上方的变体**，可查看…<br>点击行跳转 → **选择任意一行**，可跳转到…<br>点击下方按钮弹出 → **在下方确认协议后**，会弹出… |
| R3 通用空状态 | 「暂无」没点名缺的是什么 | 点名**哪张表** + **时间范围** | 暂无 → **这段时间没有客户成本记录** / **这段时间没有模型成本记录** |
| R1 错误 | 只说「失败了」 | 补**恢复动作** | 加载失败 → **没能加载出来，请重试**（第 1 轮 16 键改值） |

⇒ 「同一句话不许两份」：客户成本 / 模型成本是**两张表** ⇒ 两个键，不共用一个「暂无」。
