## 三、★★★ 发现 ①：「行数自检」是**同源自证** ⇒ 实测假绿

### 3.1 R83 轮那扇门的**守门人**长什么样

R83 轮发现「`registry_rows()` 的 `printf` 漏了 `\n` ⇒ 15 行被拼成 1 行 ⇒ ③/④ 两个循环
**只检查了登记册的第一行** ⇒ 门在基线上是绿的、但 90% 是瞎的。⇒ 修法 = 加一条**行数自检**：

```bash
registry_rows_read=$(registry_rows | awk 'END{print NR+0}')                      # 读册子读到了几条
registry_rows_data=$(awk -F'\t' '!/^#/ && NF>=2 {n++} END{print n+0}' "$file")   # 数据行有几条
if [[ "$registry_rows_read" != "$registry_rows_data" ]]; then gate_fail …; fi
```

★ **问题正写在这两行里**：两个计数用的是**同一个谓词**（`!/^#/ && NF>=2`）——
`registry_rows()` 内部的 awk 与这里的 awk 是**同一段谓词的两份拷贝**。

⇒ ⇒ **同源自证**：过滤器一旦被收窄（**两份一起收窄**），读册子与参考计数会**同时**少读
⇒ ⇒ 计数**仍然相等** ⇒ ⇒ 自检**看不见** ⇒ ⇒ ③/④ **已经不再检查那几行**，而门**是绿的**。

★ 这正是 LESSONS `§235` 那条已经写下的通用式（「双口径互证」若**同源** ⇒ 它**恒真**，不是互证」）
—— ★ **R83 轮在写这条自检时，把同一个错误又犯了一遍**（不是「同源自证」而是「同源**计数**」）。

### 3.2 ★★★★ 实测复现（三步，每步都可复算）

**实验树**：`git worktree add --detach /tmp/r84-exp origin/main`（纯净副本，不含本轮任何改动）。

| 步骤 | 变异 | 期望 | **实测** |
|---|---|---|---|
| **对照** | 只把 395c 的投递腿 `none` → `channel`（该文件**不在** `files=()` 里） | 门红 | ✅ **红**：「声明 canonical/395c… 走通道腿，但它不在 scripts/apply-db-revision-sequence.sh 的 files=() 里 ⇒ 升级库拿不到」 |
| **假绿** | **①** 把「读册子」与「数数据行」两处过滤器**同时**收窄（排除 395c）<br>**②** 同上把 395c 的投递腿改成 `channel` | 门红 | ★★ **绿**：「apply-db-revision-sequence contract passed」<br>★★ **Go 门也绿**：「ok … 0.547s」 |
| **修复后** | 同上两条复合变异（门已修） | 门红 | ✅ **红**：「登记册读取的行数（14）与数据行数（15）不一致 ⇒ 读册子的口径坏了（行分隔符丢了？过滤器被收窄了？）」 |

⇒ ⇒ ★★★ **结论**：**①②各自单做**都抓不到它（①不红、②红），**合起来才绿**
⇒ ⇒ ⇒ **只做单点变异的集合【天然看不见】复合盲区**（本轮的 M21/M22 就是为这条而生）。
⇒ ⇒ ⇒ 而 R83 轮那条「行数自检」**恰恰是为了防这一族而加的**，却因为**同源**而对它**完全失明**。

★ **危害面**：假绿的那一轮里，登记册宣称 `canonical/395c_canonical_raw_name_unprefix.sql`
走通道腿，而通道**没有**这个文件 ⇒ 升级库**永远拿不到**这条迁移 ⇒
**这正是 R82/R83 两轮立项要抓的那一类缺陷本身**（「升级库与新装库都拿不到，而没有任何一道门会红」）。

### 3.3 修法：参考计数必须与读册子的口径**独立**

```bash
registry_reference_rows() {
  local total comments blanks
  total=$(awk 'END{print NR+0}' "$nonplain_registry")                       # 总行数
  comments=$(grep -c '^[[:space:]]*#' "$nonplain_registry" || true)        # 注释行
  blanks=$(grep -c '^[[:space:]]*$' "$nonplain_registry" || true)          # 空行
  echo $(( total - comments - blanks ))                                   # 数据行数
}
```

⇒ ★ **为什么是「三个不同的工具」而不是「另一个 awk」**：
另一个 awk 也会**复制同一个谓词** ⇒ 变异同时改两处时仍然同源 ⇒ 假绿照样成立
⇒ ⇒ **谓词必须写在不同的地方**。

⚠ **诚实边界**：这个「独立」是**结构独立**（不同工具、不同谓词），
**不是**「统计独立」—— 三者都在描述同一份文件的同一批行。
若有人**同时**改「读册子的过滤器」与「三个工具的口径」（例如把 `grep -c '^[[:space:]]*#'`
改成 `'^#'`），仍然会同源。⇒ 该边界已显式登记（见 §十一 遗留 1）。

## 四、★★★ 发现 ②：bash 侧读册子的**注释口径**与 Go 侧**分叉**

⇒ Go 侧（`migration_nonplain_delivery_gate_test.go`）是：
`strings.TrimSpace(line)` 之后判「以 `#` 开头」或「为空」⇒ **跳过**。
⇒ R83 轮的 bash 侧是：`!/^#/ && NF>=2` ⇒ **不剥前导空白**。

⇒ ⇒ ★★ **实测**（一行 `   # 带前导空白的注释行<TAB>第二段含制表符`）：

| 口径 | 结果 |
|---|---|
| 旧 bash（R83 轮） | ⇒ **当数据行处理** ⇒ 键 = `   # 带前导空白的注释行` ⇒ ② 会拿它去查目录 ⇒ 报「登记册陈旧（键的宇宙前缀也非法）」这种**看不懂的假红** |
| Go（TrimSpace） | ⇒ **跳过** |
| 新 bash（R84 轮） | ⇒ **跳过** ✔ 与 Go 一致 |

⇒ ⇒ 修法 = 两侧**逐字对齐**（先剥首尾空白，再判注释/空行）。
⇒ ⇒ **M24** 把这条钉住（**期望绿**的用例：证明「对齐」真的生效）。

## 五、★★ 发现 ③：bash 侧**没有列数门** ⇒ 两道门对「形状」的判断不一致

⇒ R83 轮把「列数必须恰好 4 列」**只**放在 Go 侧。
⇒ ⇒ bash 侧读到列数不对的行时，会把「第 3 列」当成**效果落点**、把「第 4 列」当成**理由**
⇒ ⇒ ④ 会报「效果落点 … 语法非法」这种**看不懂的错**；
⇒ ⇒ 而 Go 侧报的是「列数是 3」⇒ ⇒ **两道门对同一份册子的形状判断不一致**。

⇒ ⇒ 修法 = bash 侧也核列数（并逐行报行号与列数）⇒ 两边一致、报错可读（**M23**）。

## 六、★★ 发现 ④⑤：harness 自身的两处缺口（选题⑥ ＋ 方法学）

### 6.1 「变异落地」自检只查 md5 ⇒ 查不出「变了但形状不对」

⇒ R83 轮第一版的 M11/M13 就是这么漏过去的：`\1` 反向引用在 `re.sub` 的 **lambda** 里不生效
⇒ 落地的是**字面量 `"\1"`** ⇒ **md5 变了、但形状不是要的** ⇒ 那两条变异是**假通过**。
⇒ ⇒ R83 轮已经修好了 M11/M13 本身（改用 `mutate_clear_field`），**但缺口本身还在**：
`run_mutation` 仍然只比 md5。

⇒ ⇒ **修法**：新增 `assert_contains` / `assert_tsv_field` —— 变异落地后**把目标内容读回来核对**
⇒ ⇒ ★ 通用式：★ **「md5 变了」≠「变异是想要的那个」** ⇒ 落地判据必须能表达【形状】。

⇒ ⇒ ★★★★ **★ 而这条修法在【补上后的第一轮】就立刻证明了自己的价值** ——
本轮把断言补到 M7/M8/M9/M10/M11/M12/M13/M19 上之后，**M12 当场报「红但不是对的理由」**：

| 步骤 | 读数 |
|---|---|
| M12 的旧锚点 | `^canonical/2026-07-13-…\.sql\tnone\t` ⇒ 只匹配到「键<TAB>投递腿<TAB>」⇒ ⇒ **旧的效果落点被留在后面** ⇒ ⇒ 那一行变成 **5 列**（不是 4 列） |
| 门实际报的红 | 「登记册读取的行数（14）与数据行数（15）不一致」＋「**第 71 行的列数是 5**」⇒ ⇒ ★ **红是对的**（那一行确实畸形）⇒ ⇒ **但不是 M12 想测的那条判据** |
| 根因 | ★ **变异「落地了」但「形状不是要的」** ⇒ ⇒ **这正是 R83 轮登记的那个缺口本身** |
| 修法 | ① 锚点**吃掉整个旧的效果落点字段**（`[^\t]*`）⇒ 保持 4 列 ⇒ 变异变忠实<br>② 补 `assert_tsv_field` ⇒ ★⇒ **「形状不对」从此变成可归因的诊断，而不是一个「理由不对」的谜** |

⇒ ⇒ ★★★ **⇒ 这是一次「守门人的守门人当场抓住自己人」的实例**：
★ 新加的**列数门**（本轮的修复③）抓出了**一条老变异**（M12）的**形状不对**
⇒ ⇒ ⇒ ★★ **而如果没有那条新列数门，M12 就会「红」在**别的地方**（或者更糟：红在错的地方被当成通过）**
⇒ ⇒ ⇒ ⇒ **两处修复互相加固** —— ★ 这也是「同一个洞要【正反两侧】都看」的一个具体例证。

### 6.1bis ★★ 第四处 harness 缺陷：**锚点会随实现漂移** ⇒ ★ 这次是 harness 自己抓到的

⇒ R84 轮把 `registry_rows()` 从「单行 awk」改写成「多行 awk」（注释口径对齐 ＋ 只输出 4 列的行）
⇒ ⇒ **M20 的旧锚点不复存在** ⇒ ⇒ `mutate_text` 报「anchor found 0 times」

⇒ ⇒ ★★★ **这条是 harness 的「变异必须真的落地」守卫在替本轮挡住了一次自欺**：
★ 若 harness 只比 md5（更早的形态）⇒ 这条会变成**假通过**（变异没落地 ⇒ 门当然绿 ⇒ 记成「红」）
⇒ ⇒ ⇒ ★★ **⇒ 「落地守卫」不是多余的严格** —— ★ **它是「锚点漂移」的唯一探测器**。
⇒ ⇒ 修法 = 锚点跟着实现走（改成多行 awk 里那行 `printf`）＋ 补 `assert_contains`。

## 九、★★ 选题①普查：全仓「把结构化输入读成多条记录」的地方

### 9.1 方法：从「静态找哪里写了行数断言」换成「**把输入掏空，看门的表现**」

⇒ R83 轮 §19.25.14 选题 ① 建议：「普查仓内**所有**『用换行/分隔符把结构化输入读成多条记录』的地方

## 十二、诚实边界

1. ⚠ **「独立参考计数」是结构独立，不是统计独立** —— 三者都在描述同一份文件的同一批行；
   若有人**同时**改「读册子的过滤器」与「三个工具的口径」，仍会同源。
2. ⚠ **M22 是复合变异** ⇒ 它检验的是「这一族盲区被堵住」，
   **不是**「任何复合变异都能被抓住」。
3. ⚠ **选题①普查只覆盖了 10 份登记册**（仓内 `.tsv` 共 28 份）⇒
   未纳入的那 18 份**没有**被逐份掏空验证 ⇒ **不声称「全仓无此洞」**。
4. ⚠ **阴性结论 ⑥⑦ 只对「今天现盘」成立** ⇒ 现盘一变（新增四位数前缀件 / 新增只由显式脚本退役的对象），
   结论即失效 ⇒ 届时由**门如实报错**提醒（不靠人记得这两条）。
5. ⚠ **对生产的写入 = 0**；未写 SQL 迁移、未改注册点 ⇒ 迁移水位 / 投递形态 / 生产行为**逐字不变**。
