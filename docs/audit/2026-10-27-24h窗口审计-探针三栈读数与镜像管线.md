### 1.4 model 级 liveness 叠加的收益评估（先量收益再动 ⇒ 结论：不引入）

- **无附着面**：model 探针栈 7 天 0 run、model_probe_state 无两模型任何行
  ⇒ 叠加判据没有可作用的现存探针流。
- **无可防事故**：窗口内全部翻红为 timeout 驱动的真实不可用，reasoning-only 形态
  （inconclusive）从未翻转健康 ⇒ liveness 叠加可防的翻红数 = **0**。
- **语义边界已由 c8d11d9ce 固化**：`credentialProbeHasOutput`（deliverability）与
  `credentialProbeHasLivenessEvidence`（仅 credential 探针叠加）成对分层，
  node/model/active 探针走 deliverability 是 2026-10-27 审计轮定下的界线；
  model 级再叠加 liveness 会重新打开「reasoning-only = 空回答判活」的回归门
  （正是上一轮 bg 4 红的根因）。
- ⇒ **决策：不在 model 级引入 liveness 叠加**。理由与读数如上；若未来 model 栈
  真正活跃且出现「真实流量成功 ∩ 探针红」样本，再按数据重开评估。

## §3 ③ github 镜像管线复核（bash≥4 执行 + 契约修正）

### 3.1 管线真相（与 goal 前提的重大出入）

- **现行同步契约已换成「树移植」**（AGENTS.md 027799a06，2026-10-26 文档化）：
  `git commit-tree origin/main^{tree} -p github/main -m "sync(codeup): …"`，
  验收 = 两仓 main 的 tree SHA 相同；github 镜像**保留原始历史**（26791 笔）。
  今晨 04:30 已由并行会话执行过一次（mirror tip 引用 origin 87a8aedd）。
- **sync-to-github.sh（filter-repo 全量改写）与树移植互斥**：它会 force-push 重写
  历史 ⇒ 毁掉「保留原始历史」这条镜像价值 ⇒ **只做 --dry-run 验证，不做实推**。
- **管线自身断点（本轮实锤）**：`scripts/scan-secrets.private.replacements`
  （设计为未跟踪 + .gitignore:209）在本机**全部检出都不存在** ⇒ 任何环境跑
  sync-to-github.sh 都会死在 Step 2 —— 管线坏的不是 bash 版本一件事。
