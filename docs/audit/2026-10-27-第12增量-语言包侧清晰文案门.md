## 1. 为什么要做语言包侧

第 11 增量清的是**源码侧**的硬编码中文。语言包侧另有两族问题，用户直接看得见：

1. **手势代替动作**：`点击复制`（点的是屏幕上的哪里？）、`Cliquez sur une ligne pour…`。
   impeccable `clarify.md` 的判据是**动作/导航用「动词+宾语」而非手势**。
2. **通用空状态**：`暂无` / `No data` / `Keine Daten` —— 没点名缺的是什么。
   判据是**空状态要能区分**（首次 / 无结果 / 筛选后 / 无权限 / 失败）。

★ 语言包侧与源码侧的**关键差异**：源码侧的位置信号是**语句上下文**；语言包侧的位置信号只能是**键路径**。

## 2. 判据设计

### 2.1 L2「别用手势」

- 位置：全语种全键（不限位置）。
- 规则：出现本语种**手势词** ⇒ 手势词**后面**必须**点名具体目标**。
- ★ **「点名具体目标」只认三类**：**引号内容**（`「」『』""«»`）/ **模板插值**（`${…}`）/ **箭头**（`→` `>`）。
- ★★ **裸拉丁词不算** —— 否则拉丁语种天然不判红（实测 en-US 仅 3 处且 2 处假阳性、fr-FR **0 处**），
  ⇒ **规则在语种间不一致 ⇒ 门就不是门**。
- ★ **手势词的「目标在前后」在语种间会翻转**：
  ja-JP 的 `「+ 認証情報」をクリックして追加`（目标在**前**）判红，
  zh-CN 的 `点击「+ 凭据」添加`（目标在**后**）判绿
  ⇒ 门只认「手势词**后面**点名」⇒ 改写要**按语种调整语序**，不能逐字直译。

### 2.2 L3「通用空状态」

- 位置：**空状态位** = 键路径**末段以** `empty` / `noData` / `noRecord` / `noResult` / `noItems` / `nothing` **开头**。
- ★★ **只认「开头」不认「整段相等」** —— 否则 `emptyHint` / `emptyTitle` / `noResults` / `noDataText`
  这一族（**同样是空状态位，却带后缀**）会整族落在门的视野之外（实测 **47 个键**）。
  ⇒ 这是本轮**变异臂发现并修掉的盲区**（§5）。
- 规则：值**整句等于**本语种的通用空状态短语 ⇒ 红。
- ★ **术语位不是空状态位**（`common.terms.noData` = 「无数据」是合法词条）⇒ **位置规则，零豁免**（不是白名单）。

### 2.3 L1「错误三问」—— **本轮不设硬闸**

语言包侧的**键路径不区分「错误陈述」与「计数摘要」**：
`providerDetail.models.refreshSummaryFailed` = 「失败 {n}」是**计数摘要**不是错误陈述。
⇒ 假阳性高 ⇒ **列人工清单**（仓内纪律：★ 门看不见的放人工清单，同第 9 增量对接口层中文的处理）。
★ 盘点结论：zh-CN 裸词表候选 515，其中 **398 是标签型**（`common.status.failed` = 「失败」是状态名）
⇒ 裸词表在语言包侧假阳性极高，**位置信号必须是键路径**。

## 3. 判据实现中踩到的 6 个真缺陷（建门阶段自证抓到的）

| # | 缺陷 | 现象 | 修法 |
|---|---|---|---|
| 1 | `namesTarget()` 的前导剥离把 `→` 当标点剥掉 | 「点击 → 下钻」被误判红 | 剥离时**不吃箭头** |
| 2 | `allLocaleValues()` 返回 **Map**，按普通对象取 | `per[locale]` 全 `undefined` ⇒ **全仓 0 命中（假绿）** | 按 Map 取 ★（「0 命中有两种读法」又一例） |
| 3 | en 词表含 `press` | 「Press Enter」（**键盘**）被误判红 | `press` 移出词表（指针手势只认 click/tap） |

| 6 | fr/es 词表**缺词边界** | `toucher` 命中「touchera」前缀（法语误报） | es/fr 补 `(?<![\w-])…(?![\w-])` |

## 4. ★★ 两次误删事故（本轮最值钱的产出）

### 4.1 事故一：分类脚本用**字面量 grep** 判「0 引用」⇒ 活键被判死

- 现象：源码里**根本没有** `providers.credential.empty` 这个完整字符串：

  ```ts
  // src/views/ProvidersView.vue:35
  const pm = (k: string, params?: Record<string,unknown>): string =>
    t(`providers.${k}` as never, params as never)
  // src/views/ProvidersView.vue:1465
  {{ pm('credential.empty') }}
  ```

  ⇒ `grep -rn "providers.credential.empty" src` **必然 0 命中** ⇒ 活键被判死。
- 暴露者：★ **`i18n-audit` 事后报出「2 missing i18n key(s)」** ⇒ **那道门救了这轮**。
- ★★ **而仓内的两道门本来就是对的**：
  `src/i18n/scanner.ts` 的 `scanAll()` 与 `scripts/i18n-dead-key-guard.mjs` 的 `collectStaticRefKeys()`
  **都能正确还原 `pm()` 形态** ⇒ ★ **错的不是仓内的门，是我临时写的分类脚本。**
- 处置：恢复 2 个键（8 语种）并改写（它们确实违规），改用**扫描器引用集**重判。
- ⇒ **通用式：判「这个键有没有人用」必须用【与事实源同源的量具】；临时 grep 只能找线索，不能下判决。**
  ⇒ **配套：删活键不可逆 ⇒ 判决前【三口径对拍】** —— ① `scanAll()` ② 仓内死键门 `collectStaticRefKeys()` ③ 全仓字面量。
  本轮 33 个死键三口径一致判死；唯一的「字面量命中」是**本轮新文件里的一句注释**（注释不是引用）。

### 4.2 事故二：「拿不到期望值」⇒ **安全阀整个空转** ⇒ 删掉 7 个活键

- 第一版删除脚本的校验设计：「★ 删之前确认**该行的值 == 门报告里该语种该键的值**，不一致就跳过」。
- ★★★★ **但「门报告」不是全量真值**：某个键在某个语种**本来就没违规** ⇒ 门对它没有读数
  ⇒ 期望值 = `undefined` ⇒ ★★ **校验分支整个被跳过**（`expectVal !== undefined` 守卫）⇒ 删的时候不设防。
- ★★ 再叠加第二个缺陷：**定位用「中间段正则先命中谁」** ——
  `providers.credential.empty` 的中间段 `credential:` 会先命中文件里**更早**的同名块
  ⇒ 叶键 `empty:` 落到**另一个父路径**下 ⇒ ★★★ **删掉了 `providers.list.empty`（活键）**。
- 实测影响面：`providers.list.empty` / `sessions.list.emptyHint` × 4 个语种 = **7 个活键被误删**。
- ⇒ **通用式一：校验基准必须来自【被改对象自身】（loader 实测值），不能来自【另一份报告】。**
- ⇒ **通用式二：「定位」必须做【结构化校验】** —— 本轮正解：**brace 深度扫描**算出每一行的**完整键路径**
  ⇒ 只有「路径逐段等于目标键」且「该值在文件里唯一匹配」才允许删。
  ★ 效果实证：删除 3 个死键时，路径校验**正确跳过了 3 处同名不同路径的误命中**
  （`common.ts` 的 `feedback.noResults` vs `catalogPanel.ts` 的 `noResults`）。
- ⇒ ★★★ **通用式三（本轮最贵的一条）：发现已落盘的损害后，第一动作是【回滚 + 确定性重放】，不是【手工插回】。**
  - `git checkout HEAD -- web/src/locales/` ⇒ 重放改写 ⇒ 用**带路径校验**的脚本重删。
  - ⇒ 最终读数：**8 语种 removed 精确 = 33 个死键、added = 0、误删 = 0、漏删 = 0、键数逐语种一致 = 9447。**

## 10. 通用式（同步写入 `LESSONS.md` §421）

1. ★★★ **判死键的量具必须与事实源同源** —— 临时 grep 只能找线索，不能下判决；删活键不可逆 ⇒ **三口径对拍**才敢删。
2. ★★★ **「拿不到期望值」会让安全阀整个空转** —— 校验基准必须来自被改对象自身，不是另一份报告。
