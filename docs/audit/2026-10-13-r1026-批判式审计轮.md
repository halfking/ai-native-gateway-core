## F. 审计发现的两个真缺陷（已修复 + 判据化）

### D1：native Responses 透传腿仍泄漏 stream_options（r1026 守卫的第三缺口）

- **取证**：raw-logs 2026-10-13T19:36:12——responses 客户端体带
  stream_options，`upstream_request` 原文保留该字段 → vapeur 400 →
  客户端收到 `response.failed provider_unavailable`（无 response.completed，
  探边首轮 grep 模式没匹配到，第二轮才显形）。
- **根因**：/v1/responses 的原生透传腿（executor_chat native 分支）直接
  使用 `params.ResponsesBodyBytes`（客户端原文，responses.go:396），
  **不经 IR 序列化**——r1026 的 pass1/pass2 守卫都看不到它。durable 快照
  回放（snapshot.NormalizedBody）同路。
- **修复**：native 分支 choke point（executor_chat.go，sourceBody 选定后）
  调 `transformation.StripStreamOptions`（新 helper，sanitizer.go）。
  与 extensions_restore 守卫同形同因：stream_options 是 openai-chat 线格式
  专属参数。
- **判据**：`r1026b_native_strip_test.go`——executeOpenAI 同层驱动 native
  腿 + httptest 假上游，回放 raw-logs 捕获原文；前提在场
  （ResponsesBodyBytes 必含 stream_options）；过裁剪守卫（input/model 保留）。
  **变异验证的坑（判据纪律第 9 条候选）**：第一版变异的 perl 正则括号未
  转义 → 变异是**无操作** → 测试绿被误读为「判据无效」。用 dbg 复现
  （出站体含 stream_options）+ 转义修正后真变异 → 判据红在正确断言。
  **变异脚本必须先验证变异确实落盘**（grep 改动行）再读测试结果。
- **一致性补齐（同轮）**：reactive 重试腿（chat 腿被「requires the
  responses api」拒后换 /v1/responses，executor_chat.go）对 responses 客户端
  直接用 ResponsesBodyBytes 原文重试——与 native 分支同源不同治，绕过
  strip choke point。已补同款 strip（当下无实证流量走此路，纯一致性
  修复）；判据 `TestR1026BReactiveRetryStripsStreamOptions`（chat 拒 →
  重试腿顶层键 JSON 判定），真变异（落盘确认后）红。

### D2：reasoncap 表 grok-4.6 行无实证地登记 xhigh → 钳制空转 → 上游 400

- **取证**：raw-logs 19:36:16/26/43 三连（客户端 ZCode chat 腿显式发
  `reasoning_effort:"xhigh"`，top-level keys 实证）→ 网关转换成
  `reasoning:{effort:xhigh}` → vapeur grok-4.6-1 后端 400 "Supported
  values are: 'none', 'low', 'medium', and 'high'"，单候选整请求失败。
- **根因**：`internal/reasoncap/reasoning_defaults.go` 的 grok-4.6 行
  Efforts 含 "xhigh"（注释「supports low, medium, high, xhigh」无任何
  实证出处）→ paramguard.fixReasoningEffort 按表放行。
- **修复**：按上游明示能力集订正表行（xhigh 出列、none 入列——两者都有
  400 报错原文实证）。paramguard.ClampEffort 自动就近把 xhigh 钳到 high
  并记 paramledger（响应回显还原链已有）。方言门不动：Grok 能力有意图
  不匹配 DialectOpenAIChat（跨供应商误改防护），泛 chat 中转
  （DialectUnknown）按教义 fail-open 不钳——测试注释已钉。
- **判据**：`r1026b_grok46_xhigh_clamp_test.go`（两载体钳到 high +
  前提在场含表项钉子）+ 更新两条建立在旧错误假设上的过时断言
  （guard_reported_test.go 的 normalize-only 两例 → normalize+clamp 双报告；
  clamp 报告 Original=客户端原值 x-high 是既有还原链语义，grok-4 测试注释
  早已写明）+ reasoncap 的 grok_4_6_test.go 过时期望集订正。
  变异：表行回潮 xhigh → 前提钉子红。
- **连带**：/v1/models 若向客户端广播 effort 能力（ZCode 据此选 xhigh），
  表订正后新会话将不再收到 xhigh 选项；存量已发请求由钳制兜底。
