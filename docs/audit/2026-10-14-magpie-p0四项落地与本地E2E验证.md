## 二、本地 E2E（2608，真实请求路径，可控 mock 上游）

**环境构造**（本轮新建，后续轮次可复用）：
- mock 上游 `/tmp/p0_mock_server.py`（aiohttp :19080，模式由 messages[0] 前缀选择：
  NORMAL/CUT/STRICT400/QUOTA429/MODEL404；请求落痕 /tmp/p0_mock_hits.log）。
- DB seed（llm-gateway-pg@5432）：provider 9010 → 127.0.0.1:19080，
  credential 9010 + binding + provider_models(canonical_id 链) + node_probe_state。
- API key id=2（HMAC(SECRET_KEY) 直插 api_keys，application_id=8——
  **application_id=0 不在 applications 表会被 keystore 内联 JOIN 丢弃，全员 401**）。
- 凭据密文用 `secret.FernetKeyFromSecret(SECRET_KEY, LLM_GATEWAY_CREDENTIAL_ENCRYPTION_KEY)`
  生成 v1:legacy envelope（仓内临时工具 go run 生成后删除）——**run/*.env 里
  explicit key 优先于 SECRET_KEY 派生，只按 SECRET_KEY 加密会 unknown format**。

**七个场景实测**（全部通过）：

1. **基线**：MODE_NORMAL 流式 200，echo 全文 + [DONE]，单上游 hit。
2. **P0-3 断流续问**：MODE_CUT 第一腿发 "one two three" 后断连（无 [DONE]）→
   **61ms 后 mock 收到第二请求，messages 尾部 = assistant "one two three"（prefill
   前提在场）** → 客户端收 "one two three"+" four five six"+stop+[DONE]，
   无重复 role 帧、单终态。
3. **P0-1 骨架字段（reqprobe 抢先）**：reasoning_effort 被拒 → reqprobe 反应式
   剔除重试（既有机制，3ms 内恢复）——paramrefusal 是第二道兜底。
4. **P0-1 paramrefusal 本尊**：pydantic 形态 422（extra_forbidden +
   loc:["body","service_tier"]）→ **`paramrefusal retry` 日志在场**
   （named_param=service_tier, wire=openai-completions）→ 剔除重试成功；
   **第二次执行仅 1 个上游 hit（记忆发前主动剔除）**。
5. **P0-4a reset 对齐**：429 "usage quota exceeded, will reset at +10min" →
   **`circuit quota cooling aligned to upstream reset`（cooling=599344ms≈10min，
   未钳制，单次失败即 OPEN）** → 冷却期内后续请求 **0.13s 快速失败、零上游
   命中**（不锤上游，probeOne 式有界行为）。
6. **P0-4b 模型级隔离**：404 "The model 'mock-p0-e2e' does not exist" →
   走既有 KindModelNotFound→binding-scoped 通道（reducer 不发凭据熔断效应，
   我的接线臂兜的是误分类侧）→ **紧随其后的同凭据正常请求 0.31s 恢复 + [DONE]
   + 命中上游——凭据未被连坐**。
7. **热键双向实测**（借 P0-3 kill 键验证 settings_kv 热通道，与
   survival.interactive_deadline_seconds 同一 GetPlatformBool 机制）：
   settings_kv 置 `survival.stream_continuation_enabled=false` → MODE_CUT
   **1 个上游 hit、无 prefill 续问**（回到 legacy 截断形态）；翻回 true →
   续问恢复（user+assistant 双 hit、单终态）。全程零重部署。

**注**：429 body 写 "rate limited" 时分类为 rate_limit（非 quota 族），按设计
不对齐 resetsAt（rate 族走既有指数冷却）——quota 词形（usage quota exceeded）
才进对齐分支，与文档「quota 类冷却对齐」一致。
