## §3 改法：**A 的语义 + B 的机制**

订正给的两个选项：

* **A（推荐）**：v1 臂检测分「基线时点 / 部署时点」两个时点；
* **B**：给 5 个基线形态 fallback 体加**机器可读声明标记**，按声明豁免。

⇒ 本轮取 **A 的语义 + B 的机制**：

1. **声明是机器可读的**（沿用仓内既有 `dbinit:` 惯例，例 `dbinit:no-transaction`）：

   ```sql
   -- dbinit:baseline-v1-fallback —— 本文件是**基线形态**的 v1 fallback 体：…
   -- dbinit:baseline-v1-fallback-switch: 883_session_family_cost_view_metrics.sql —— …
   ```

2. **部署形态不是假设，是读出来的** ⇒ 豁免**可证伪**。
   声明只拿到一张空白支票；还要过**三道腿**（缺一即红）：

   | 腿 | 内容 | 变异 M1/M2/M3 的可证伪性 |
   |---|---|---|
   | A | 切换迁移**存在**且**在启动链**里 | 把它从 TSV 摘掉 ⇒ 红 |
   | B | 切换迁移**排在 v1 退役迁移之前**（退役迁移是**推导**出来的，不写死 `890_...`） | 把它挪到 890 之后 ⇒ 红 |
   | C | 切换迁移的**体里没有 v1 臂**（它的 `CREATE OR REPLACE VIEW` 体覆盖源文件的体） | 把迁移体改脏 ⇒ 红 |

   ★ 退役迁移的**推导判据**：`DROP TABLE` + 同时引用**两代拼写**（带 `_` 与不带 `_` 的 v1 基表名）
   ⇒ 唯一命中 `890`（只删其中一张的 562/687/765/829/836 都不满足）。

3. **反向腿**（防「声明泛滥」）：
   * 声明**过期**（源文件已无 v1 臂）⇒ 红（该退休的退休）；
   * **未声明却含 v1 臂** ⇒ 算**部署形态** ⇒ 红（这是 M3 的实测结果）。

4. **豁免台账双向严格相等**：声明集合 == 测试内显式登记册（5 条 view→switch 映射），
   两边任一边多/少都红 ⇒ 台账不漂。
