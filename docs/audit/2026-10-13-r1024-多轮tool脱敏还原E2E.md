# r1024 —— 多轮 tool 调用 × 脱敏还原 E2E：五缺陷收口

> 会话目标（用户 /goal 摘要）：经网关对特色模型（minimax / z.ai / vapeur ai）
> 逐模型发起多轮带 tools 的请求（~5 轮，/goal 提示词 = 拉主分支合并 / 24h 审计），
> 跟踪请求 log，修正问题，部署验证；重点是参数收发与转换——**脱敏介入后，
> 客户端必须能拿到 tools 参数里可用的真实值（IP/用户/密码），拿到占位符即无法操作**。
> 本地 2595→2600 四轮部署验证，全矩阵 PASS。

## 一、测试台（可复跑）

harness：`/tmp/gwtool_e2e/tool_roundtrip_e2e.py`（python3 无依赖，SSE 流式解析）。

- 工具集：`get_deploy_config`（返回含敏感值的 env dump：server_ip/ssh_user/
  ssh_password/db_*/ops_phone/ops_email）→ `run_ssh_command(host,username,
  password,command)` → `write_env_file(path,content)`。
- 判据（任一失败即 FAIL）：
  - A. 每轮 HTTP 200 且 SSE 可组装；
  - B. 客户端可见字节里**零** `{SENSITIVE:*}` 占位符泄漏（还原完整）；
  - C. `tool_calls[].function.arguments` 是合法 JSON（r1022 类结构损伤回归）；
  - D. `run_ssh_command` 收到的 host/username/password 与注入真值**逐字相等**
    （可操作判据：拿不到真值=无法操作）；
  - E. ≥2 轮 tool 往返（多轮性）。
- 会话：`X-Gw-Session-Id` 贯穿全程（占位符映射是会话级 Redis Hash）；
  钉扎：`X-LLMGW-Preferred-Credential` + `X-LLMGW-Admin-Token`；
  思考档位：chat 腿 `reasoning_effort:"medium"`、responses 腿 `reasoning:{effort:"medium"}`。
- 提示词即用户给的两条运维指令（merge/audit），加了「先拿配置再发远程命令、
  禁止编造占位值」的串行约束（见 §五-4）。

## 二、缺陷与修复（按发现顺序）

### 1. 身份字段硬阻断（r1024 主缺陷，output_policy_blocked）

- **现象**：MiniMax-M3 第 2 轮（tool 结果回传后）整流 `output_policy_blocked`，
  chunk_count=0，客户端零内容。
- **根因**（raw-logs 复现 + 单测隔离）：上游回显
  `"password":"{SENSITIVE:secret:1}","username":"deploy"`。密码是占位符（放行），
  但 `credentialField` 把 `username/user_name/account/login` 等身份字段与密码族
  一视同仁——「凭据键 + 非占位符值→硬阻断」。裸用户名（"deploy"）不命中任何
  输入检测规则、**结构性不可能以占位符形态出现**，于是任何带 username 的
  SSH 类工具调用必被掐断。
- **修复**（`security/sanitize/input_tools.go` + `output_sensitive.go`）：
  `credentialField` 拆为 `secretCredentialField`（密码族：password/passwd/pwd/
  secret/token/api_key/apikey/access_key/authorization/密码/口令——保留硬阻断）
  与 `identityField`（身份族——不再触发阻断，仍走检测器+外传目的地检查）。
  **畸形形状契约不随族分流**：任何凭据字段（含身份族）下的非字符串形状
  （number/bool/map）仍 fail-closed（`TestCriticalUnsupportedCredentialShapesFailClosed`
  不回退——map/number 两处保持全集）。
- **理由**：身份不是凭据。r1020 的底线是「模型写出的明文**密码**整条拦」，
  用户名是登录身份，误伤面是全部 SSH/部署类 agent 工具。

### 2. YAML account 规则漏检 `*_user` 形态（r1024 输入侧缺口）

- **现象**：tool 结果散文 `ssh_user=deploy` 明文出网关（上游可见），
  模型回显明文 username 后又撞缺陷 1。
- **修复**（`configs/sensitive_patterns.yaml`）：account 正则 label 集补
  `user(?:name|_name)?` 与 `[a-z0-9_]*_user`。用户名进 `{SENSITIVE:account:N}`
  占位符闭环后，出向是占位符、回程可还原（实测 upstream_request 出现
  `{SENSITIVE:account:1/2}`）。

### 3. `X-LLMGW-Preferred-Credential` 钉扎静默失效（布线缺陷）

- **现象**：钉扎 62 的请求被自由路由到 nvidia 19 / vapeur 63——E2E 归因失真
  （此缺陷直接导致缺陷 4 被发现）。
- **根因**：`ChatHandler.SetAdminAPIKey` 全仓无人调用，`h.adminAPIKey` 恒空 →
  handler.go 的钉扎提取永远走 `adminAPIKey == "" → return nil`。
- **修复**（`cmd/gateway/main.go`）：chatHandler 构造后接
  `chatHandler.SetAdminAPIKey(cfg.AdminAPIKey)`（与 /metrics 的
  AdminTokenMiddleware 同源）。安全性不变：钉扎仍需 X-LLMGW-Admin-Token
  常量时间比对通过才生效。

### 4. openai-responses 供应商的 tool 历史被散文折叠（多轮工具失效）

- **现象**（钉扎修复后归因到 vapeur 才复现）：glm-5.3→vapeur chat 腿第 2 轮，
  上游收到的历史是 `[调用工具 get_deploy_config ...]`/`[工具结果 ...]` 散文——
  模型于是用散文模仿工具调用，客户端拿不到结构化 tool_calls。
- **根因**：`IsToolUseCapable` 协议启发式只认 openai-completions/
  anthropic-messages；vapeur（catalog_code 空、protocol=openai-responses）
  落到折叠分支。
- **修复**（`domains/transformation/sanitizer.go`）：协议启发式补
  `openai-responses`（Responses 线格式原生携带工具块）。全仓仅 vapeur 用该协议。

### 5. 无 `event:` 行的 Responses SSE 终态误判（假失败 + 探针连坐）

- **现象**：grok-4.6（vapeur，responses 腿）完整收到 `response.completed` 后，
  上游正常关连接被当成 `native_responses_read_error` 流中断——客户端在完整
  响应之后又收到 `response.failed`；且失败计入凭据健康（3 连败停节点 →
  no_candidate 连坐，实测 grok/claude 先后被打停）。
- **根因**（`domains/streaming/native_responses_stream.go`）：终态判定只看
  SSE `event:` 行名字；vapeur 只发 `data:{"type":"response.completed",...}`，
  `event.Name` 恒空 → terminal 永不置位（已有的 RST 容错分支进不去）。
- **修复**：`finishNativeResponsesEvent` 在无 `event:` 行时从 payload `type`
  回填 Name——终态判定/帧分类/capture 语义与带 event: 行的上游对齐。
  判据：终态后断连=干净结束；**终态前断连仍中断**（前提在场配对）。

### 6. 客户端把 chat 嵌套形 tools 发到 /v1/responses（网关容错增强）

- **现象**：出向体 responses 形但 tools 是 `{"type":"function","function":{...}}`
  嵌套形 → vapeur 400（以 502 信封回）→ 3 次注定失败重试 + 凭据连坐。
  （本轮先由 harness 自身 bug 复现，随后按「转换而非拒绝」原则网关侧收口。）
- **修复**（`domains/transformation/responses_tools_normalize.go`）：
  native responses 出站前 `NormalizeResponsesTools` 把嵌套形归一化为平铺形
  （name/description/parameters/strict 提升；已是平铺形原字节返回；
  无 name 的畸形嵌套不动）。与 paramreg「翻译而非拒绝」教义同向。

### 7. 模型自造占位拼写撞密码族阻断（r1024b）

- **现象**：MiniMax-M3 在拿到配置前并行发出
  `"password":"PLACEHOLDER"`（下次 `"USE_DEPLOY_PASSWORD"`）的早产 ssh 调用，
  密码族非占位符→整流掐断，同轮合法的 `get_deploy_config` 陪葬。
- **修复**（`security/sanitize/input_tools.go`）：`isPlaceholderCredentialValue`
  三路判据——①字面量集（PLACEHOLDER/TODO/<...> 等）；②**自指涉**：值包含
  凭据关键词（password/token/... → USE_DEPLOY_PASSWORD、PASSWORD_HERE、
  ${password} 都是字段引用而非机密）；③模板包裹形（`<...>`/`${...}`/`{...}`/`$x`/`%s`）。
  模型自造词每次不同，字面量集挡不住，自指涉判据才跟得上。
- **已知边界（如实登记）**：真实密码恰含 "password" 字样（"Password1!"）会被
  判占位放行——该值仍只回会话属主（客户端），不构成第三方泄漏；触网外传由
  目的地检查另行把守。普通明文（"hunter2"/"Xk9#mZ2pQ8"）照拦。

## 三、判据与变异验证

- `security/sanitize/r1024_identity_tool_fields_test.go`：
  - A 事故原样回放（命令+私网 host+密码占位符+明文 username）不阻断；
  - B 身份/密码字段矩阵（含畸形形状、占位拼写、未收录拼写）；
  - C YAML account 规则覆盖 `ssh_user=/db_user=/user=/username=`（生产 YAML
    检测器，内置 fallback 写这类判据是假绿——判据纪律第 2 条）。
  - 变异：撤身份拆分→矩阵红；撤 YAML 补丁→C 红；撤自指涉判据→
    USE_DEPLOY_PASSWORD 红。
- `domains/streaming/r1024_native_responses_nameless_terminal_test.go`：
  真实线帧形状（无 event: 行）终态后断连=干净；终态前断连仍中断；Name 回填
  单元。变异：禁回填→终态误判红。
- `domains/transformation/responses_tools_normalize_test.go`：嵌套→平铺
  （strict/parameters 保真）、平铺原字节、畸形不动。

## 五、方法论增量

1. **钉扎头先验证生效再归因**：本轮首小时「glm-5.3 折叠」误判的根源是
   钉扎静默失效、请求被路由到 nvidia/vapeur——供应商级结论必须先证钉扎
   （看 upstream_http_attempt 的 provider/credential）。
2. **占位拼写不可枚举，可判据化**：模型自造词每次不同（PLACEHOLDER →
   USE_DEPLOY_PASSWORD），字面量集第一天就过时；「值自指涉字段名」是结构
   判据，跟得上自造词。方向与 r1020 形态枚举禁区相反：枚举的是「定义上
   不构成泄漏」的引用形态，不是「长得像无害」的形状。
3. **终态判定要与线格式双形态对齐**：SSE 的 event 名有 `event:` 行与
   `data.type` 两个权威位置，只认前者的一半供应商（vapeur）全部误判。
4. **E2E 提示词要显式禁止编造占位值**：不禁止时模型会早产并行调用，
   自造 host 触发安全契约（正确拦截），把「安全行为」混进「功能验证」
   的失败集里污染结论。

## 六、遗留（登记不修）

- `password_restored`（还原后的真实密码）在 sanitize 输出守卫视角仍是
  「非占位符凭据值」——现链序（守卫在还原前）不触发；若未来有人把守卫
  挪到还原后，会重新打断还原闭环。判据矩阵里已有 `{"password":"Xk9#mZ2pQ8"}`
  → blocked=true 钉住该契约，挪动前必读。
- 模型自造公网 IP 的早产调用仍整流拦（r1013 契约），客户端会看到流中断
  而非部分结果——若未来要「只丢弃单条 tool call」，需协议级手术，另立轮次。
- 散文里 JSON 转义形态的占位符还原（r1022 修的是 JSON 参数 lane；模型把
  markers 写进散文且带转义时还原兜底为遮蔽）——折叠修复后该形态出现率大降，
  未见新复现，留观。
