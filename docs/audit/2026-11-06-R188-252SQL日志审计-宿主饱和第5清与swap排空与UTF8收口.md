## §七 量具坑（本轮新增）

1. **本机 Bash spawn ENOENT 全程不可用** ⇒ 全部取证改走 `world.run`（execFile 直spawn，绕开 /bin/zsh）；半程后 Bash 自愈，两通道并存。
2. 稀疏洞：`ls -ls`（块数）≠ `ls -l`（表观）；逐字节 first/last non-zero offset 是跨文件连续性证明的正典。
3. PG 头锚定 `] LEVEL:` ——`: ERROR:` 锚点假空（第一次错误普查全军覆没的根因）。
4. TS 模板串里的 `${var}` 会吞 shell 变量引用（awk `$3`、`$L`）——world.run 载体上写远程脚本要么转义要么拼接。
5. ssh heredoc 三层引号剥层：参数计数正则 `[\$]` 静默失配 ⇒ 「params_left 0」假象；重脚本一律本地 Write + scp（第二次应验）。
6. pss 查询必须 `-d llm_gateway`（扩展只装在该库，缺省 postgres 库报 relation 不存在——差点误登「pss 消失」假异常）。
7. **会话 CWD 是空壳**（syncfield/llm-gateway-go-4 仅 .zcode/）：git 沿父目录上溯到 ai-native-tools 外层仓会给出**另一个仓**的 main/origin —— 网关真仓在 `llm-gateway/llm-gateway-go`，一切 git 操作前先 `rev-parse --git-dir` 验身。
8. parser CAP=20000 截断的日志语句重放 EXPLAIN 会失真（matched 形状语法错）⇒ 重放一律取**仓内源 SQL**（grep .go 常量）而非日志重组文本（R187 坑 #3 的延伸）。
9. 双解析实例同写一个输出文件=交错损坏（ssh 慢 spawn 造成的重复 launch）；重启前必须 pgrep 全量清理。
