## 二、三个真修复（转换/数据格式族）

### F1 孤儿 tool_result 整请求拒绝 → 降级放行（internal/ir/serialize_anthropic.go）

- 事故：claude-sonnet-5（request 75777ea4…，11:54）——ZCode 会话压缩删掉 assistant
  tool_use、留下 **80 个孤儿 tool_result**（tool_use_id 全为 call_1）⇒
  `validateAnthropicToolCallIntegrity` fail-closed ⇒ `tool_call validation failed` ⇒
  **0 候选即终态** ⇒ 客户端重放同败 ⇒ 会话砖化（r1048「trim 吞 user」同族灾难形态）。
- 修复：校验失败时先 `downgradeOrphanedToolResults`（孤儿转 `[orphaned tool result <id>]`
  文本块，内容保留、2000 字符封顶）→ 重验通过则放行 + anomaly 留痕
  （tool_result_orphan_downgrade）→ 仍失败（结构性坏）才拒绝。
- 首版缺陷实录：降级结果只写回局部变量、`out["messages"]` 仍指旧切片——**出站体原样带孤儿**，
  改判后的钉测当场抓住（测试先行的价值）。
- 既有契约改判 ×3（OrphanedToolResult/PartialOrphans/MultipleOrphans）：从「拒绝+错误信息」
  翻转为「降级放行+内容保留断言」（r1046 带注释改判先例）。

### F2 tool 消息缺 tool_call_id 整请求拒绝 → 配对回填/降级（internal/ir/parse_openai.go）

- 事故：glm-5.3-flash（10:37 一簇 5+ 笔，ZCode 会话重放）——`messages[N] tool role requires
  tool_call_id` ⇒ 同协议直传格式门（protocolformat.ValidateOpenAIChatRequest）fail-closed
  ⇒ 会话砖化。
- 修复：`repairChatToolCallIDs` 在 parse 层（直传/跨协议转换两路都受益）：
  ① 缺 id 的 tool 消息按顺序回填最近 assistant tool_calls 中未消费的 id（显式 id 先出队）；
  ② 无可配对 call 时降级为 user 文本（`[tool result without tool_call_id]` 标注+内容保留）。
  留痕走 reportClientShapeFix（ir.anomaly 可见）。
- 钉测 ×3（顺序回填/显式消费/孤儿降级+格式门复验）。

### F3 智谱 trial 配额误分类 request_rejected → quota_permanent（errorsx/classify.go）

- 事故：glm-5.3-flash-trial 大量（15+ 笔/2h）——`"ZCode has no active limited quota for
  GLM-5.3-Flash-Trial"`（HTTP 400 invalid_request_error）。这是**账号级配额裁决**，但状态门
  （402/403/429）不含 400 ⇒ 落 KindRequestRejected（归因错族：请求侧参数错误）。
- 修复：`noActiveQuotaRe` 单列并接进两个分类器（400 也归 quota_permanent）——**不整体放开
  budgetExceededRe 到 400**（其他 quota 词在 400 上误命中会误冷却凭据；本模式措辞专属配额
  缺失，误报面可忽略）。两分类器同门（不分叉纪律）。
- 钉测 ×1（原形态+无 limited 变体）。
