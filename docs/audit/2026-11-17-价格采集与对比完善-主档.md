## 三、salesdecorate 能力调研与移植判定

调研（只读）结论 —— 可移植资产与**不可照搬**的部分：

**已移植**
1. **三段式架构**：Python 采集器 + Go 报表/服务（与本仓现有形态一致）。
2. **五元价格坐标系**：每百万 token 的 `input / output / cache_hit` 三元组（**cache_hit 是本轮新增的关键维度**，源侧 49.7% 的观测有值，此前网关侧一个列都没有）。
3. **阶梯（tier）维度**：上下文阶梯 / Priority / Flex 等 **258 个取值**，此前在采集侧被压平成最小值。
4. **别名映射**（`model` + `model_alias`）⇒ 多个源 key 归一到同一 canonical。
5. **对比算法**：原厂溢价率、MaaS 最低价相对溢价、中位数/spread/vsMin、**cheapest 染色**（原厂不参与极值）。
6. **同比/环比窗口**（±15 / ±45 天）—— 本轮未移植，登记在 §七。
7. **证据逐字可回溯**的校验纪律（`internal/validate`）⇒ 本轮以「台账自带读数 + 门禁有牙」的形式继承。

**判定为「不可照搬」并给出修法**
| salesdecorate 做法 | 本轮判定 | 理由 |
|---|---|---|
| `canonical_key` 优先取**展示名**（带厂商前缀）⇒ 跨平台漏配 | **这是根因**，本轮改为「剥命名空间 + 四趟解析」 | 展示名不是身份 |
| 按「可比类别白名单」丢弃非文本模型 | **不照搬** | 网关自己也服务 embedding/rerank（211 实测 19 个相关 canonical）⇒ 只在**未解析**时按 kind + 名称形态拒绝 |
| 只解析入价（tier A 18 源） | 不照搬 | 本轮取**全部** scope（tier B 也在采集面有数据），但**多 scope 只进 970 明细、不进 940 地板** |
| 促销价与常规价混算地板 | **不照搬** | 促销进地板＝把「最便宜的常规价」错报成「市场价」 |

## 四、缺陷清单（F1–F9）

### F1（P1）部署漂移：平台现价表恒空，而台账显示正常

- **现象**：970 表 0 行；台账落地 1084 行、无报错。
- **根因**：宿主 cron 副本与仓库副本靠人工拷贝，实测 md5 不同 ⇒ cron 跑的是**没有 970 写入段**的旧脚本。
- **修法**：新增 `scripts/deploy-market-price-sync.sh` —— 幂等安装 + **sha256 对拍自证**（不是「我拷过去了」，是「两边指纹相同」）+ 旧副本备份。
- **配套**：台账 `detail.script_sha256` 写入本次运行的脚本指纹 ⇒ 运维从台账即可看出「跑的是哪个版本」。
- **验证**：211 上安装后 `sha256sum` 与仓库逐字节一致；台账行 12 的 detail 含指纹。

### F2（P1）身份断层：行情价与评分面「同一个模型」对不上

- **现象**：解析率 24.3%；两个名字空间交集仅 12.5% ⇒ 绝大多数「我方价 vs 市场地板」**没有地板可比**。
- **根因**：源侧 `canonical_key` 带 `vendor:` 命名空间前缀（`openai:-gpt-4o`），网关侧是裸名。
- **修法**（`scripts/market-price-sync.py`）：
  - `strip_namespace` / `resolve_canonical` **四趟**解析：原样精确 → 剥前缀精确 → 原样归一 → 剥前缀归一。
    ★ **原样精确优先于剥前缀**（网关自己有 10 个 Ollama 风格名 `qwen2.5:7b` / `claude-opus-5-5:high`，一律先剥会误命中）。
  - 映射灌进源侧 SQL 的 `res` CTE ⇒ **同名合并在 SQL 侧一次算对**（地板取 min、平台数 `count(DISTINCT platform_id)` 精确、归属平台按组内全局最小重选）。
    ★ 合并是必须项而非优化：211 实测 165 个多 key 合并组涉 **43.3%** 的观测。
- **验证**：见 §二.3 修后列。

### F3（P1）旧口径的「歧义 NULL-out」把刚写好的新行也置空

- **现象**：旧语句在同一 `canonical_id` 出现两行时把**两行都**置空 —— 而那正是本轮要修的漂移形态（新行=网关名、旧行=源 key 名并存）⇒ **修复被自身抵消**。
- **修法**：改为**身份漂移自愈** —— upsert **之前**先删旧口径漂移行（判据：① `canonical_id` 非空但名字 ≠ 该 id 的网关名；② `canonical_id` 为空且名字匹配 `:-` 形态），残留行由迁移 974 清理。
- **门禁**：契约门 C7 **改判**（原「歧义回退 NULL」被判定为缺陷本身）⇒ 门改为钉「身份漂移自愈 + 不得再有 `canonical_id=NULL`」；C20b 变异臂改为**行为级**断言（文本门抓不到行为变异）。

### F4（P1）阶梯价与缓存价在采集侧被压平 / 直接丢失

- **现象**：970 的 PK 不含 tier ⇒ 阶梯价互相覆盖；`cache_hit` 列**一个都没有**。
- **根因**：源侧 `price_observation.tier`（258 个取值）与 `cache_hit_price`（49.7% 有值）从未进过网关侧。
- **修法**：迁移 974 加 4 列（`tier` / `model_kind` / `cache_hit_per_1m` / `cny_cache_hit_per_1m`）且 PK 改 tier 感知；同步器同步带出。
- **验证**：211 上 970 落地 **2771 行**，其中带 tier **866 行**、带缓存命中价 **1253 行**。

### F5（P1）970 的表键粒度 ≠ 源侧观测键 ⇒ 首次真跑即 23505

- **现象**（**真库首次写入 970 就暴露**，单测全绿也抓不到）：
  ```
  ERROR: duplicate key value violates unique constraint "market_price_platform_quotes_pkey"
  DETAIL: Key (dimension, canonical_name, platform_id, tier)=(standard, deepseek-v4-flash-0731, bailian, 忙时 08:00-22:00)
  ```
- **根因**：源侧观测键含 `region`（salesdecorate 的 ingest 去重键与 `price_hash` 同款 ⇒ 官方口径），而 970 的键不含它。实测该模型该档位有 **5 个 region**：中国大陆/全球 **3.000000**、美国/日本/新加坡 **3.208000** CNY ⇒ **价差 7%**。
  ★ 970 此前恒为 0 行 ⇒ **这条写入路径从未在生产跑过** ⇒ 单测与 dry-run 都测不到。
- **修法**：
  - 迁移 976：加 `source_region` 列，主键并入 `source_region` 与 `currency`（`currency` 列本就 `NOT NULL DEFAULT ''`；211 实测同 (platform, model, tier, region) 的多币种行数 = **0** ⇒ 并入不产生额外行数，但挡住未来形态）。
  - 同步器：**表键 = 源侧观测键的投影**；同键多行（别名收敛的产物）按**地板口径确定性择优**（CNY 价低者优先 ⇒ 与 940 地板同源；NULL 价排在已知价之后），**折叠数写进台账**（`platform_quote_collapsed`）⇒ 不静默丢行。
  - ★ 原有 `region` 列语义**不变**（= 网关平台登记表的 domestic/overseas，用于 A-17 双地板判定）⇒ 两个语义不混用。
- **验证**：211 真跑落地 2771 行（源 2932 ⇒ 折叠 161），无冲突。

### F6（P1）决策面与候选面判据不一致 ⇒ auto 选中「候选面必然滤空」的模型

> F6 是上一轮 auto 模式根修的同型缺陷：**键一样、闸不一样**，症状与键错位一模一样，但修法完全不同。

- **现象**：`canonical_id` 有值、状态闸全通过，但 `models_canonical.released_at` 过期 ⇒ 决策面说「能用」、路由面说「不能用」。
- **量化**：决策池 1017 个模型里 **194 个（19%）**「决策面活、候选面死」⇒ 命中死模型是高频事件不是偶发。
- **修法**（上一轮已落地，本轮只做回归确认）：决策侧实时过滤补齐候选面的三道闸（canonical disabled / model lifecycle / broken_confirmed 探针对）。
- **本轮通用式**：**候选面与决策面必须同闸** —— 同键还不够，键一样、闸不一样时症状与键错位一模一样。

### F7（P2）`model_kind` 在同一次运行里有**两个来源**

- **现象**（复核时发现）：源侧 `price_observation.model_kind`（观测快照）与 `model.model_kind`（canonical 分类）在 **6341/19181 行不一致** ⇒ 970 明细写的是观测快照值，而「非模型拒绝门」与「同名合并取最高可比类别」用的是 canonical 值 ⇒ **同一个模型在同一份产物里有两个类别**。
- **修法**：统一到 **canonical 分类**（`m.model_kind` 优先，`o.model_kind` 仅兜底）。Python 侧以 `resolved_map` 为单点真值（与本脚本既有原则一致：「解析只在一个地方实现」）。
- **门禁**：A15 **行为门**（跑真 `main()`、抓真生成的 INSERT、逐条读列值）+ **变异臂**（退回观测快照值 ⇒ 门当场红）。

### F8（P2）非模型标签污染

- **现象**：源侧把上下文阶梯标签 / 图片分辨率档当成了模型名（`128k<token≤256k` / `720p` / `480p`）。
- **修法**：**只在未解析时**按 kind + 名称形态拒绝（≤ ≥ < > 阶梯标签 / 纯数字符号），已解析到网关 canonical 的一律保留；拒绝族 `not_a_model` **可计数**（211 实测 95 行）。
- **门禁**：C19 + A13/A13b。

### F9（P2）部署脚本的「备份」其实没备份

- **现象**：`scp remote:/root/x /root/x.prev` —— scp 的第二个参数是**本地**路径 ⇒ 写的是本机的 `/root` ⇒ 必然失败；脚本用 `|| echo 跳过备份` **吞掉了错误** ⇒ **看起来备份了，其实没有**。
- **修法**：远端备份用 `ssh cp`（同机回滚）+ 本地备份用 `mktemp`（跨机回滚），且**备份失败即报错退出**（备份不是可选步骤）。
- **验证**：211 上 `cp -p` 后 `.prev` 存在且 sha256 与主文件一致。

## 五、**撤回**一条自己先前的结论（量具错误）

> 本轮中途曾依据「按 `', '` 裸切 dump 出来的 SQL 文本」判定
> 「970 明细的 `model_kind` 有脏值（`32k)` / `256]` / `123K+12K` / URL 片段）」，
> 并据此准备改取数优先级。

**该结论是量具错误，已撤回。** 复核方式：改用**按 SQL 字面量语义解析**（尊重单引号转义）重解析同一份 dump：

- 2932 条 970 INSERT，**arity 全部正确**（0 条错位）；
- `model_kind` 只有 **10 个干净类别**，计数与源侧分布逐项吻合（2118/534/70/53/46/44/32/20/10/5）；
- 那些「脏值」是 **tier 值里的逗号**（如 `输入长度[0,32K),输入长度[32K,128K)`）被裸切错位后的碎片。

⇒ 通用式：**审计里的每个数字都必须是可复现的断言**；裸切文本得到的「异常值」先怀疑量具，再怀疑代码。

> 附带修正：F7（`model_kind` 双来源）是复核时**另发现**的真问题 —— 它与「脏值」无关，但同样属于「同一个东西两套口径」。

### 7.2 ★ 门自身的缺陷（本轮修掉的一处「假红」）

契约门 C4/C11/C12 在同步器长到 **70983 字节**后**同时假红**（判据在脚本里都存在，`grep -c` 逐条可数）。

- **根因**：门用 `printf '%s' "${BODY}" | grep -q "PATTERN"` 做全部文本判定。被测文件**大于管道缓冲区（64KB）**时，grep 一命中就提前退出 ⇒ printf 收 `SIGPIPE`（141）⇒ 脚本带 `set -o pipefail` ⇒ **整条管道被判为失败**。

## 八·六、F10：定价建议把「全局基准兜底」当成了「当前零售价」（假偏离 100 倍起）

### 8.6.1 现象（线上实测，部署后验收时抓到的）

部署 `f6f99545` 后，`POST /api/admin/market/pricing-suggestions`（strategy=min）返回：

```
aion-2.0      current_cny_in=0.0492  suggested_cny_in=5.342719  delta_pct_in= 10759.18%
aion-3.0      current_cny_in=0.0492  suggested_cny_in=20.035197 delta_pct_in= 40621.94%
claude-fable-5 current_cny_in=0.0492 suggested_cny_in=33.391995 delta_pct_in= 67769.90%
                                              delta_pct_out=135639.81%
```

**「当前零售价 0.0492 CNY」对任何模型都不成立** ⇒ 幅度是**假偏离**。

### 8.6.2 取证（211 真库 + 线上响应统计）

| 读数 | 值 | 含义 |
|---|---|---|
| 375 个模型的 `current_credits_in/out` | **全部 = 492 / 1230** | 正是**全局基准**：`base_credits_per_1m=600 × global_discount=0.82 = 492`；输出轴 `1500 × 0.82 = 1230` |
| 现价 == 全局基准的行数 | **375 / 375 = 100%** | **整块现价栏没有一个模型是真价** |
| `delta_pct_in` 中位数 | **+3904.3%** | 典型行就是**几十倍假偏离** |
| `delta_pct_in` 最大值 | **+407119.5%** | 四十万倍 |
| `delta_pct_in > 1000%` 的行数 | **280 / 375** | |
| `applicable=true` 的行数 | **347** | ★ **这 347 行处于「一键执行」可达状态** |

### 8.6.3 根因

`loadPricingSuggestionCurrent` 用 `pickCreditRateFlagged(manual, val, global)` 取「有效价」。
该函数（`maas/market_price_reference.go:234`）的语义是
「**手工价优先，否则全局基准**」⇒ **模型没有存储价时返回全局基准**。

而**全局基准不是这个模型的价** —— 它是「所有模型统一兜底」。
把它塞进「当前零售价」栏，再与市场价相比 ⇒ 假偏离。

★ 更严重的是**连带污染**：① 阈值过滤（`min_delta_pct`）按这个假偏离筛 ⇒
「只动明显偏离的」会把**几乎所有模型**捞进来；② 347 行 `applicable=true` ⇒
**若真按当时的建议一键执行，会把 347 个模型的零售价写成市场地板价** ⇒ 定价整体打崩。
⇒ 本轮「未在生产真实执行一键执行」这个克制，事后看是**躲过了一次生产事故**。

### 8.6.4 修法（口径，不是补丁）

| 位置 | 改动 |
|---|---|
| `pricingSuggestionCurrentPrices` | 新增 `InExplicit` / `OutExplicit`：该轴的价**是这个模型自己的**吗 |
| `pricingSuggestionRateIsOwn` | 判据 = **存储值存在且 > 0**（与 `pickCreditRate` 取存储值的判据**逐字同源**）⇒ 存了 0 视作未设 |
| `pricingSuggestionCurrentPricesFor` | 装载映射抽成纯函数：有效价照旧回落全局基准，但**显式性单独标记** |
| `pricingSuggestionApplyCurrent` | 现价栏**只写自有价**；没有 ⇒ 四个字段全留 nil（前端显示「—」）⇒ **兜底值无法进现价栏** |
| `PricingSuggestionRow.CurrentBasis` | 新增 `explicit` / `partial` / `none`，供审计与前端区分「有价」「仅一轴」「没价」 |
| `pricingSuggestionDecision` | 可执行性判定抽成纯函数：**无自有现价 + 有阈值 ⇒ 不参与**（没有偏离可比）；**无自有现价 + 无阈值 ⇒ 仍可执行**（首次定价是主场景） |

⇒ 结果口径：**现价栏只认模型自有价**；没有就显示「—」、幅度不产出、
不参与保守阈值过滤；**但仍可作为「首次定价」被一键执行**。

### 8.6.6 通用式（新增）

- **「兜底值」不能冒充「业务值」** —— 兜底是「没查到时的替身」，把它展示成「就是这个模型的价格」，
  就是在**编造事实**；且**兜底值一旦进入比较，就会批量产生假信号**（本次 375/375 全中）。
- **同一个取数函数，语义可能与调用点的意图不一致** —— `pickCreditRateFlagged` 在计费面是对的
  （"有效价"），在「现价对比」面就是错的（"这个模型的价"）⇒ **调用点必须声明自己要哪种语义**，
  不能靠函数名猜。
- **「有效值」与「归属值」要分开携带** —— 有效值可以回落全局基准，但**必须同时带上「这是不是它自己的」**，
  否则下游无法区分「查到了」与「没查到」。
- **假信号会顺着闸门放大** —— 假偏离不仅显示错，还会污染阈值过滤、把不可执行变可执行 ⇒
  **量一个指标前，先确认它的输入是不是真的**。
- **修口径不能把真信号一起修没** —— 门里必须有一条对照：**有自有价时幅度照算**（本次 6.8%）。

## 八·七、F11：跨平台现价明细把**别的模型**的价格混进来（浏览器级验收抓到的第二个真实缺陷）

### 8.7.1 现象（浏览器实页 + API 对拍）

在 `/operations/price-compare` 的「跨平台现价」页签里点 glm-5.3 的「查看现价」，
页面给出的「最便宜」是 **OpenRouter ¥0.2665 / ¥0.5236**；
而同页模型目录里 glm-5.3 的「市场最低」写的是 **¥0.4668 / ¥9.35** —— **自相矛盾**。

API 对拍（`?model=glm-5.3`）：

| 读数 | 值 |
|---|---|
| 返回总行数 | **43** |
| 其中 `canonical_name = glm-5.3` | **17** |
| **混入的其它模型** | **26** 行：`glm-5.3-flash`(15) / `glm-5.3-flashx`(3) / `glm-5.3-prime`(2) / `glm-5.3-fast`(1) / `zhipu/glm-5.3`(1) / `zhipu/glm-5.3-flash`(1) / `zhipu/glm-5.3-flashx`(1) / `glm-5.3-flashx-legal`(1) / **`glm-5.3-flash`（含零宽空格 U+200B）**(1) |
| 940 综合地板（真值） | `market_min_cny_in/out = 0.466820 / 9.349759`，`market_min_platform_count = 4` |
| 970 该模型的真实最小（非原厂） | `0.466820 / 9.349759`（**与 940 一致**） |

⇒ **940 与 970 是对的**；错的是**读面**：明细 SQL 把同族变体的价混了进来。

### 8.7.2 根因

`admin/market_model_platforms.go` 的明细 SQL 带一条「同族便利匹配」：

```sql
WHERE dimension = $1
  AND ($2 = '' OR lower(canonical_name) = lower($2)
       OR canonical_name ILIKE '%' || $2 || '%')   -- ★ 元凶
```

⇒ 任何**名字里含** `glm-5.3` 的模型都被当成 glm-5.3 的行情。

### 8.7.3 影响（不止"多几行"）

1. **跨模型价格被当成同一模型的行情** —— 运营看到「glm-5.3 在 OpenRouter 只要 ¥0.2665」，
   实际那是 **glm-5.3-flash** 的价 ⇒ **据此定价会亏本**。
2. **「最便宜」标记挂到别的模型行上**（实测：同族行 ¥0.2665 抢走了本模型 ¥0.4668 的徽章）。
3. **平台数被灌水**（43 行 vs 17 行）⇒ 与目录的「可比平台数」口径打架。
4. **与目录自相矛盾**（目录 ¥0.4668 vs 明细 ¥0.2665）⇒ 运营无法判断哪个是真的。
5. ★ 附带发现：源侧存在**带零宽空格（U+200B）的模型名**（`glm-5.3-flash`）
   ⇒ 即便将来做同族视图，这种名字也会被再次漏掉 ⇒ 登记为数据卫生问题（见 §九）。

### 8.7.4 修法（把"便利"变成"显式"）

| 位置 | 改动 |
|---|---|
| `marketPlatformQuotesSQL` | **默认精确匹配**：`($2 = '' OR lower(canonical_name) = lower($2))`（**删掉 ILIKE**） |
| `marketPlatformQuotesFamilySQL`（新） | 同族视图独立 SQL：`scope=family` 时才用，且 `ORDER BY (lower(canonical_name) = lower($2)) DESC` ⇒ **本模型行排前** |
| handler | 解析 `scope` 参数（只认 `family`，其余一律回落精确匹配）；响应回带 `scope` |
| 前端 `ModelPlatformCompare.vue` | 新增「匹配范围」开关（仅本模型 / 含同族变体）；**同族视图显示「模型」列**并给族行打「同族」标签；**「最便宜」只在本模型内计算**（`isSelectedModel`） |
| `web/src/api/market.ts` | `getAdminMarketModelPlatforms(..., scope)` |

⇒ 默认口径：**只查本模型自己**；同族变体是**用户显式选择**的结果，且**必须可分辨**。

### 8.7.5 验证

| 门 | 结果 | 有牙证据 |
|---|---|---|
| Go `admin/market_model_platforms_scope_test.go`（4 个） | 绿 | 契约门断言**默认 SQL 不得含 `ILIKE/LIKE/~`**；行为门断言 scope 路由与 `scope` 回带 |
| 前端 `ModelPlatformCompare.test.ts`（2 个） | 绿 | 断言默认不带 scope、默认视图不显示「模型」列、**「最便宜」不得落到 glm-5.3-flash 行** |
| 变异臂 M4：把 ILIKE 放回默认 SQL | 红 | 契约门 `默认明细 SQL 含模糊匹配` ⇒ 变红 |

### 8.7.6 通用式（新增）

- **"顺手带上同族"是典型的隐性口径污染** —— 用户查 A 模型，看到的是 A + A-变体的混合行，
  而表格**没有任何列**能说明哪行属于谁 ⇒ 读者必然把族行的价当成 A 的价。
  ⇒ 「同族/模糊」这类便利查询，必须**显式开启** + **每行自带身份** + **标记算法按主体分组**。
- **聚合标记必须在"主体"内部计算** —— 「最便宜」是**该模型**的最便宜，不是**这一批行**的最便宜。
- **自相矛盾是发现口径错配的最强信号** —— 目录说 ¥0.4668、明细说 ¥0.2665，
  两个读数对拍即暴露了「不是模型价，是别的模型的价」。
- **数据卫生也要看不可见字符** —— 零宽空格让「精确匹配」也会漏；本轮未修（登记在 §九），
  但它提醒：**字符串键的身份必须防不可见字符污染**。

## 八·八、F12：行情概览端点对**任何调用方**都 500（浏览器验收抓到的第三个真实缺陷）

### 8.8.1 现象（浏览器实页 + 容器日志）

- `/operations/market-prices` 页面顶部常驻红条：**「加载失败（服务端返回错误，详见浏览器控制台）」**；
- 该页的摘要区读的正是 `GET /api/admin/maas/market-price-overview` ⇒ Network 面板：**500**；
- 容器日志（`llm-gateway-211-a`）逐字：

  ```
  "msg":"admin handler internal error","caller":"maas_handlers.go:1016",
  "err":"can't scan into dest[24] (col: s_cur): cannot scan NULL into *string"
  ```

- **同源同病**：`/operations/price-compare` 的「定价参考」页签读的是同一个端点 ⇒ 那个页签也一直是死的。

### 8.8.2 取证（211 生产真库，只读）

| 事实 | 读数 |
|---|---|
| `market_price_reference` 的字符串列 | **全部 NOT NULL**（`vendor_list_currency` / `vendor_vendor` / `*_platform_id` 等）⇒ SELECT 里**唯一可空字符串**就是 LATERAL 出来的 `s_cur`（dest[24]） |
| 已解析模型（`canonical_id IS NOT NULL`） | **375** |
| 其中在 `credential_model_bindings` 里**没有带价绑定**的 | **353（94%）** ⇒ `LEFT JOIN LATERAL` 无行 ⇒ `s_cur` 为 NULL |
| overview 前 50 行里 `s_cur IS NULL` 的行 | **41** ⇒ 第一次扫描就整体失败（该端点是「整体返回 error」，不是逐行跳过） |

⇒ **不是"数据脏了"，而是"没有数据"这种常态触发的**：绝大多数已解析模型根本没有供应商绑定价。

### 8.8.3 根因（★ 这是**回归**，不是新洞）

1. `14bc988cb`（2026-11-10 前后）**修过同一列**：当时的 SQL 形态是 `min(b.currency)`，修法 `COALESCE(min(b.currency), '')`；
2. `08af89b1f`（D7，2026-11-10）重写 LATERAL 子查询（改成 `GROUP BY bb.currency` + `is_cny` 优先）时**把那个 COALESCE 丢了**；
3. 既有契约门 `TestMarketPriceOverviewScanOrderMatchesSelect` 只钉**列数/列序** ⇒ 对「列变 NULL」**完全不可见**（同源自证的典型：它证明的是"数量对得上"，不是"值不会炸"）。

### 8.8.4 修法

- **SQL 侧** `COALESCE(s.s_cur, '')`（`''` = 币种**未知**，不是 0）；Go 侧 `r.SupplierCur == "CNY"` 判据随之不成立 ⇒ 不产出位势比（NULL≠0）；
- **列序不动**（`s_in=22 / s_out=23 / s_cur=24`）⇒ 既有列序门继续有效；
- **顺带钉死同族的第二个 NULL 陷阱**：`COALESCE((bb.currency = 'CNY'), FALSE) AS is_cny`
  ——`(NULL='CNY')` 的结果是 **NULL 而不是 FALSE**，而 Postgres 的 `ORDER BY is_cny DESC` 默认 **NULLS FIRST**
  ⇒ 「币种未知」的组会排在**真 CNY 组前面**。当前生产库 NULL 币种绑定实测为 0（今天不发作），但它与 500 同族 ⇒ 一并钉死。

### 8.8.5 验证（行为门 + 契约门 + 变异臂成对）

| 门 | 结果 | 有牙证据 |
|---|---|---|
| 源码契约门 `maas/market_price_reference_null_safety_test.go`（2 个） | 绿 | **不变量门**（不是形状锁）：允许 (a) SQL COALESCE + 裸 `*string` 扫、(b) SQL 原样 NULL + Go 侧 NULL 安全容器；只禁「原样 NULL + 裸 `*string`」这一种 |
| **真库行为门** `maas/market_price_reference_realdb_test.go`（1 个） | 绿（211 生产库，**只读 SELECT**） | 跑**生产函数本体** `Service.MarketPriceOverview` ⇒ 真库读数：**200 行 / 币种未知 182 行 / 带币种 18 行**；并断言「币种未知 ⇒ 不产出 market_position」 |
| 变异臂 **M5**：摘掉 `COALESCE(s.s_cur, '')` | **红** | **两道门同时红**，真库腿复现**生产同款报错原文**：`can't scan into dest[24] (col: s_cur): cannot scan NULL into *string` |
| 变异臂 **M6**：`is_cny` 退回 `(bb.currency='CNY')` | **红** | 契约门红 |
| 既有列序门 `TestMarketPriceOverviewScanOrderMatchesSelect` | 绿 | 列序未漂（SQL 列数 == Scan 参数数） |

> 真库腿未设 `TEST_DATABASE_URL` 时**静默 Skip** ⇒ Skip ≠ 通过；
> 配套的源码门不需要真库、永远在跑（两者缺一，结论都不成立）。

### 8.8.6 通用式（新增）

- **"没有数据"是常态，不是异常** —— 读面必须扛得住「该维度缺失」：`LEFT JOIN LATERAL` 无行 ⇒ **整组三列都是 NULL**，
  其中只要有一列是字符串且扫进裸 `*string`，整条列表就全灭。
- **历史修复会被后续重构吞掉** —— 同一个洞修过一次仍会复发 ⇒ 门要钉**不变量**（「扫进裸字符串的那一列绝不能是 NULL」），
  而不是钉「当时那行代码」；本轮的门正因如此，M5 才能精确复现生产报错。
- **列序门 ≠ NULL 安全门** —— 前者证明"数量/顺序对得上"，后者证明"值不会炸"；**缺一不可**。
- **真库门要能复现生产报错原文** —— 只有跑**生产函数本体**（而不是拼一条等价的 SQL）才能做到。

### 8.8.7 ★ 一次「量具伪影」的登记（差点改出一个不存在的缺陷）

- 我用 `curl` 探 `https://llm.itestu.cn/operations/market-prices` ⇒ **401 `invalid_key`** ⇒ 一度判成
  「深链坏了，鉴权放行名单漏了 `/operations/`」⇒ 差点去改鉴权门。

  `/operations/market-prices` `/live2` `/help` **全部 200**（返回 SPA 外壳）⇒ **没有缺陷**。

  （与上一轮「gofmt 读数过期」同族：**错的量具比没量具危险**）。

## 十、通用式（本轮沉淀）

1. **审计里的每个数字都是可复现的断言** —— 本轮据此**撤回**了一条自己先前的「脏值」结论（量具错误，见 §五）。
2. **守卫自己也要被审计** —— 契约门在「被测对象 > 64KB」时假红（SIGPIPE + pipefail），门一直绿只是因为文件恰好小。
3. **「首次在生产跑到的路径」才是真测** —— 970 写入路径此前从未在生产跑过（表恒 0 行）⇒ 单测与 dry-run 全绿也测不到 PK 粒度错误（F5）。
4. **表键粒度必须与事实源的观测键对齐** —— 少一个维度（region）就撞主键，或静默丢掉 7% 的价差。
5. **同一个东西只能有一套口径** —— `model_kind` 在一次运行里两个来源（F7），与 F6「键一样、闸不一样」同型。
6. **台账版本号是全局共享的** —— 拟用 972/973 时撞上 `model_offers_update_trigger` ⇒ 改号到 974/975/976。
7. **继承红要逐条量化归因（HEAD-only worktree 对照）**，并**明确说出本轮是否修、为什么** —— 越界改他人特性文件与放着不管同样不可接受，中间态是「量化 + 登记 + 给出修法」。
8. **不静默丢行**：折叠数、拒绝族、身份读数全部写进台账 ⇒ 任何一次口径变化都能在台账上看见。
9. **兜底值不能冒充业务值**（F10）—— 全局基准是「没查到时的替身」，把它展示成「就是这个模型的价」就是编造事实；
   而且兜底值一旦进入比较，就会**批量产生假信号**（本次 375/375 全中，中位假偏离 +3904%）。
10. **有效值与归属值要分开携带**（F10）—— 取数函数可以回落兜底，但必须同时回答「这是不是它自己的」；
    调用点必须**声明自己要哪种语义**，不能靠函数名猜（`pickCreditRateFlagged` 在计费面对、在对比面就错）。
11. **「顺手带上同族」是隐性口径污染**（F11）—— 便利查询必须**显式开启** + **每行自带身份** +
    **标记算法按主体分组**；否则读者必然把族行的价当成主体的价（本次据此定价会亏本）。
12. ★ **两处假数据都是「自己写的代码」在「自己没测过的路径」上暴露的** ——
    F10 出在**部署后验收**（线上 API 第一次真跑），F11 出在**浏览器级验收**（第一次真看页面）。
    ⇒ **验收的深度决定缺陷的暴露时机**：API 级验收过了，不代表页面级就干净。
13. ★ **第三个缺陷（F12）出在「读第二个页面」** —— price-compare 验得再细也不会碰到 market-prices；
    而 market-prices 的摘要区一打开就是 500。⇒ **需求里点名的每一个页面都要真读一遍**，
    不是"验完主页面就算"。
14. **「没有数据」是常态，不是异常**（F12）—— `LEFT JOIN LATERAL` 无行 ⇒ 整组三列全 NULL；
    其中任何一列是字符串且扫进裸 `*string` ⇒ **整条列表全灭**（不是那行缺值）。
15. **历史修复会被后续重构吞掉**（F12）—— 同一列修过一次（14bc988cb）仍会复发（08af89b1f 丢了 COALESCE）
    ⇒ 门要钉**不变量**（「扫进裸字符串的那一列绝不能是 NULL」），而不是钉当时那行代码。
