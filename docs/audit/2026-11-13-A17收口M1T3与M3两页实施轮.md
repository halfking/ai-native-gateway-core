### 2.4 给运营的裁决材料（★ 本轮不改代码；采纳才立项）

1. **判别力结论**：现口径在本轮这对真实数据上**必发假警报**（两库同时、且增量可逐行归因为新增
   无价绑定）；「非 empty 口径」（suspect_symmetric+unknown_currency）对 churn 免疫且成员稳定。
   empty 单类（4090→4092 / 1964→1980）几乎纯绑定流入信号，作为「定价覆盖率缺口」另有
   thin_coverage 族可表达。
2. **采纳「非 empty 口径」的工程代价**：961 台账现只存 `trusted_count/non_trusted_count/unknown_currency`
   ⇒ day-1 的 empty/suspect 拆分**在 11:10 +08 的下一轮覆盖 smp 后即永久不可考**。若采纳，需一个
   新迁移给 `market_scoring_runs` 加 `suspect_count`（或 `empty_count`）列（幂等；旧行回填 NULL，
   告警 SQL 对 NULL 基线沉默）+ `bg/market_scoring.go` 写列 + 告警判据改口径 + 钉测。
3. **若维持现口径**：告警的价值=「绑定数流入的粗指示器」，不是置信度退化信号——建议至少在
   告警 detail 文案里去掉「C3 置信度退化」语义（改「绑定集流入」），避免值班误读。
4. **复核点**：本档 §2.2 的 day-2 是 02:0x 的只读仿真。11:10 +08（211）/03:10 +08（245/154）真跑后，
   台账真值若与仿真偏差大，说明 02:0x→跑点之间绑定/价格又变了（正常），**裁决仍以
   suspect+unknown 类的稳定性为准**（该类两库两日 9/9，扰动概率低）。
