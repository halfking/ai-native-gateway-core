## 2. 量具自身的四处缺陷（本轮全部带自检）

### 2.1 大小写：白名单里没有 `ElMessage`

```
VISIBLE = … 'message\s*\.\s*(error|warning)' …   // 小写 m
```

实测（views 下全部 471 个 catch 块，逐块取块内文本匹配）：

| 形态 | 被错判为「静默」处数 |
|---|---|
| `ElMessage.error(...)` | 23 |
| `setError(...)`（ProxyView） | 9 |
| `setTabError(...)`（ProbeHealthDetailView） | 1 |

第一版把「调用即产生用户可见输出」与「只写了个 error 状态」混成一个白名单，
这是根因：前者的可见性由**调用点自己**保证，后者的可见性取决于**模板**。
两者混在一起，就既会误报（`ElMessage` 没被认出来），又会漏报
（`setError` 被认成可见，但它有没有消费者是另一回事）。

### 2.2 早退让遍历漏掉嵌套 catch

把分类写成 `if (自证可见) { 计数++; return }` 之后，catch 块总数从 **471 掉到 469** ——
`return` 跳过了 `ts.forEachChild`，嵌套的 catch 再也数不到。

危险的不是少 2 个，而是**它长得像「数据变了」**：报告里总数变小，
默认解读是「这轮清理掉了两个 catch」，而不是「量具瞎了」。

修法：`countCatches()` 用一个没有任何早退的独立递归数一遍，
两个数字必须相等，不等就 `exit 3`。现在恒为 471 == 471。

### 2.3 无语句边界的窗口

解析「`setError` 写到哪个 ref」时用 `[\s\S]{0,400}?` 惰性匹配，
解析「哪个 computed 派生自它」时用 `[\s\S]{0,160}?`。后者从
`const loading = computed(` 出发，窗口跨过下一行吃到了
`const error = computed(() => errorByTab…)` —— 于是解析出 `loading`，
真正的 `error` 因为起点被消耗而丢失。

后果：把 `ProxyView`（422 行确有 `<div v-if="error" class="error-banner">`）
报成「模板里没有消费者」。**量具的假阳性比它要抓的缺陷更吵。**

修法：窗口截到下一条 `const|let|var|function` 声明之前。

### 2.4 状态名认得太宽 → 又一批假阳性

`\w*[Ee]rror\w*\(` 会把 `formatCredentialError(...)`（纯格式化函数）
和 `Error(`（构造/类型）当成「被写入的状态」，报出「模板里没有消费者」
这种查下去根本不存在的结论。收紧为：`(ref).value = …` 的 ref 名
+ 符合 `^set[A-Z]` 命名约定的调用。

模板侧的识别同样补了两处漏掉的形态：
- 经 i18n 参数传进插值：`{{ t('…', { err: statsError }) }}`
  （第一版只认「紧跟花括号」那一种，把 `AgentRegistryView` 误报成没有消费者）
- **引号里的花括号**：`attr="{{ x }}"` 不参与插值，是字面量

## 34. 缺陷：一处「安全更新」级别的假话

`UpdateActivateView.vue` 两个加载函数原来只把值置 null：

同一句假话出现**两次**：表格 `v-else-if="records.length === 0"` 渲染
「暂无合规记录」；`recordsTotal = 0` 让分页文案渲染「共 0 条」。

修法：新增 `recordsError`；模板新增 `v-else-if="recordsError"` 取代空态；
分页整块收进 `v-if="!recordsError"`。

> **只加横幅是不完整修法**：留着 `records.length === 0` 那一格，页面会同时说
> 「加载失败」和「没有命中记录」，而「没有命中」是会被当真结论引用的那句。
> 判据 ① 专门断言那句话在失败时**不出现**。

## 52. P2 RequestLogsView.loadKeys —— 外面那层 try/catch 是死代码

```js
async function loadKeys() {
  try { keys.value = await getKeys() } catch { keys.value = [] }   // 内层已吞
}
// 调用处：
try { await loadKeys() } catch (e) { console.error('Failed to load keys:', e); keys.value = [] }  // ← 永不触发
```

外层那层读起来像「loadKeys 可能抛出」的保护，实际因为内层已吞而**永不执行**——
诊断信息就埋在这一段死代码里。死代码伪装成守卫，是量具盲区在源码侧的同构问题。

**也不能复用 `filterOptionsError`**：`loadCredentialOptions` 开头会把它清零，
而它在 `loadKeys` **之后**执行 ⇒ 写进去必被抹掉。两个下拉各有各的失败，
所以新增独立的 `keysFilterError` 与第二个 `.filter-error`。

## 53. P3 ChatView.refreshAvailableModels —— 清空之后下拉不是空的

模型 `<select>` 里有一条**硬编码**的「自动路由 (auto)」（`ChatComposer.vue:47`）。
所以 `popularModels.value = []` 之后下拉**仍然有一个选项**，
读起来就是「网关只提供自动路由」—— 而用户据此发出去的请求走了完全不同的链路。

⇒ 与前几处不同：这里的假话不是「没有」，是「只有一个」。判据锚在
「那条说明必须挂在专属节点上」，不是全页含有这句话（防恒绿）。

## 54. P4 TurnsListView.loadChildOps —— 空数组是 truthy，失败被缓存成「确实为空」

```js
if (childOpsMap.value[sessionId] || childOpsLoading.value[sessionId]) return   // 入口早退
...
} catch {
  childOpsMap.value = { ...childOpsMap.value, [sessionId]: [] }                // 失败写 []
}
```

`[]` 是 truthy ⇒ 一次失败之后这一项**永久**命中早退，展开再多次也不重试。
「取不到」被缓存成了「取到了，是空的」，两个错误合成一个**永久的**假。

修法：失败**不进 map**（键缺席才是「还没取到」），原因单独存 `childOpsError`，
卡片上渲染 `child-ops-error` 标记（否则「什么都不渲染」读起来就是「没有子请求」）。

判据 P4-② 直接钉这条：`toHaveBeenCalledTimes(2)` —— 端点恢复后必须**真的**再发一次。

## 60. Q1 BootstrapWizardView.loadStatus —— 一个 null 造出三处后果

原来是 `catch { status.value = null }`。这个 null 在模板与逻辑里分三路：

| # | 位置 | 后果 |
|---|---|---|
| ① | `status?.center_online ? '在线（可自动注册）' : '离线（不阻塞激活）'` | 本地 status 取不到时，页面拿一句**安慰话**覆盖未知的量，还明说「不阻塞」 |
| ② | `status?.message \|\| '可以登录本地后台开始使用。…'` | 兜底文案在没有数据时断言「已就绪」 |
| ③ | `onMounted` 的 `if (status.value?.activated)` | 未知 ⇒ 当成未激活 ⇒ 把一台**已激活**的机器领进完整激活流程 |

③ 最重，而且**页面上没有一句是错的**——它只是把人带去了错误的下一步。
⇒ 判据 ③ 守的是**状态机**（`step` 停在 0、指纹端点根本没被叫过），
不是某一句话。只会断言文案的人会漏掉它。

修法：`statusError` ref + 两处模板三态 + `onMounted` 早退。

判据 5 例，`wizardStatusUnknownVsNotActivated.silentcatch.test.ts`；
反向对照 4/4（R1 抽赋值、R2 撤三态标签、R3 撤早退、R4 撤结束页三态）。

## 61. 写判据时踩的一处，值一整节：桩挂在了没人 import 的模块上

`BootstrapWizardView` 在 `src/views/bootstrap/`，它 import 的是 `'../../api/bootstrap'`。
我照抄了**视图的**说明符写 `vi.mock('../../api/bootstrap', …)`，而判据本身在
`src/views/` —— 那个说明符解析到**仓库根下的 `api/`**，**没有任何模块 import 它**。

后果是本轮最隐蔽的一种：**桩静默不生效，真模块照常加载**。
报错长得像「桩返回了错的东西」：

```
expected 'Failed to parse URL from /api/system/…' to be 'status 503'
```

实际上 `statusMock` 从头到尾没被调用过。

**这不是「报错」告诉你的**。它既不报 unknown export，也不报解析失败。
唯一的发现途径是那条报错本身指向 `/api/system/bootstrap/status` ——
如果当时我把它当成「后端返回了这个字符串」，就会去改一个根本没坏的东西。

⇒ 两条可直接复用的做法：
① **桩的说明符必须相对判据自己解析，不是相对被测视图**；
② **每条正向对照都断言「桩确实被调用了**」（④ 断言 `fingerprintMock`
被调用，正是它暴露了这个问题）。

## 63. 量具修正：错误态按「右值」识别（本批真正的产出）
