## 二、P1-D：Fit 路径媒体标记缺失修复 ✅

### 2.1 问题描述

**审计发现**: Fit 路径（fit.go:18-91）无 r1052 媒体标记——被裁媒体历史静默消失，与 Reduce「不无声消失」合同不一致。

**根因**: 
- Reduce 路径通过 `file.go:272-274` 添加 `[media omitted from bounded context]` 标记
- Fit 路径只生成文本摘要，被移除的含媒体消息无任何痕迹
- 两条路径语义不对齐：同样是"归约"，一个标记、一个不标记

### 2.2 修复实施

#### 2.2.1 导入 bytes 包

```go
// internal/sessioncontext/fit.go:4-12
import (
	"bytes"  // 新增：用于媒体探测
	"crypto/sha256"
	"encoding/json"
	"errors"
	"fmt"
	"strings"
	"unicode"
	"unicode/utf8"
)
```

#### 2.2.2 检查被移除消息是否含媒体

```go
// internal/sessioncontext/fit.go:83-91（在 prefix 生成后）
// P1-D (2026-11-23): r1052 media marking for Fit path.
// When old messages containing media are removed, append explicit marker
// so media doesn't silently disappear (matching Reduce's contract).
for _, msg := range old {
	if fitHasMedia(msg) {
		prefix += "[media omitted from bounded context]\n"
		break
	}
}
```

**设计要点**:
- 只需检查 `old` 切片（被移除的消息）
- 一旦发现任何媒体，添加标记并 break（不需要计数）
- 标记文本与 `file.go:273` 完全一致

#### 2.2.3 新增 fitHasMedia 辅助函数

```go
// internal/sessioncontext/fit.go:252-274
// fitHasMedia checks whether a raw message contains media fields (r1052).
// Uses the same probe list as file.go's mediaMarkerOmitted to ensure
// consistent media detection across Reduce and Fit paths.
func fitHasMedia(raw []byte) bool {
	// Same probe list as file.go:mediaMarkerProbe (r1052)
	probes := [][]byte{
		[]byte(`"image_url"`), []byte(`"input_image"`), []byte(`"input_audio"`),
		[]byte(`"audio_url"`), []byte(`"video_url"`), []byte(`"input_video"`),
		[]byte(`"inlineData"`), []byte(`"inline_data"`), []byte(`"fileData"`),
		[]byte(`"file_data"`), []byte(`"encrypted_content"`), []byte(`"image"`),
		[]byte(`"audio"`), []byte(`"video"`),
	}
	for _, probe := range probes {
		if bytes.Contains(raw, probe) {
			return true
		}
	}
	return false
}
```

**实现原理**:
- 探测列表与 `file.go:491-497` 的 `mediaMarkerProbe` 保持一致
- 采用字节级探测（deliberate crude probing）
- 只决定「是否添加标记」，不做闸门判定
