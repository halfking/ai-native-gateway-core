## 一、取证链（归档件是钥匙）

- 发射点＝`domains/streaming/large_ingress.go:170`：>256KB 请求走 LargeIngress
  归档；>1MiB（ContextBytes 默认）触发 `sessioncontext.Reduce` 收敛；Reduce
  失败（非超时/取消/策略/JSON 类）⇒ 422「bounded context」。**入口拒绝不进
  request_wal**——WAL 零行，取证面是 `_request_logs`（error_kind）+ 容器日志
  （http_request 422）+ **session-archive 归档件**（raw.json=原始请求全文）。
- 定位：12:34:24+08 的 422/688ms（client_request_id=7718f89a 与报障逐字吻合）；
  归档件 `gw_staging_7ccb2ae4…/large-v1/requests/254340c9…/raw.json`
  **1,365,000B**：149 条消息（4 条 170-333KB 的巨型 user 消息，内含
  `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}`——
  ZCode「Tool result media from Read」截图），tools 仅 140KB。
- **本地真身重放**（真实归档件 + 仓内真实 Reduce）：`err=ErrProtectedContext`
  先红复现；插桩定位＝`fileMetadata` 在 333KB 巨型消息的媒体块上直接拒绝。
- 活体三档对照（211，临时 key id=253）：312B 带图＝路由层 vision 400（另一码
  事）；170KB 带图（<256KB 不走归档）同上；**1.8MB 带图＝422 原样复现**。

## 二、根因＝三处媒体 fail-closed（改写层制造入口自己都不会放的形状·第三案）

| 位置 | 触发 | 旧行为 |
|---|---|---|
| `fileMetadata`（metadata.go） | >64KB 巨型消息内媒体型块（type=image_url 等）或消息级媒体字段 | `ErrProtectedContext` ⇒ 整个 Reduce 失败 |
| `Reduce` 元数据循环（file.go） | ≤64KB 消息含媒体 ⇒ `contextbudget.UpperBound` Uncountable | 直接失败 ⇒ 同上 |
| `objectExcerpt` | 块内超大非字符串字段（base64 媒体对象 >64KB） | `ErrProtectedContext` ⇒ 同上 |

**砖化机制**（与 r1048/r1051 同族）：ZCode 全量历史带截图 ⇒ 每笔请求 >1MiB ⇒
入口 422「split the protected input」——客户端**无法**split 历史里的截图，
重试必败，会话砖化。报错文案把「网关缩减器的结构缺陷」甩锅成「用户输入非法」。

## 三、设计冲突的裁决：无声消失 vs 整请求拒绝 → **显式省略**

仓内既有钉测 `TestReduceCannotSilentlyRemoveUncountedHistoricalMedia` 钉的
正是旧行为（「媒体不可无声消失」＝必须报错）。本轮改判：

- **拒绝不可行**已在生产实证（会话砖化、owner 三连报障）；
- **无声删除**违背旧钉测意图（模型不知道少了一张图 ⇒ 幻觉风险）；
- ⇒ **显式省略**：缩减成功 + 媒体不入缩减体 + 账目恒在——
  ① `objectExcerptMedia` 结构性媒体感知（媒体型 type + 媒体字段键 ⇒ 块级
  `[media omitted from bounded context]` 标记，不读载荷）；
  ② **聚合计数进摘要头**（`[media omitted from bounded context: N
  media-bearing message(s)]`）——best-16 摘要逐出也不丢账（真身调试实证：
  149 候选竞争下块级标记会被逐出，聚合头不会）；
  ③ ≤64KB 消息按字节探针（`mediaMarkerProbe`，只决定是否记账，不做门）。

## 四、修复清单

1. `metadata.go fileMetadata`：媒体型块打桩 `{"type":…,"gw_media_omitted":true}`
   （保留类型丢数据，role+工具链元数据不受影响）；消息级媒体字段打桩。
2. `file.go Reduce` 元数据循环：UpperBound 的 Uncountable 降级为继续
   （结构错误 InvalidRequest 族仍失败）——媒体计量归 contextbudget dispatch 面。
3. `file.go objectExcerpt`：超大非字符串字段跳过+标记（不再 ErrProtectedContext）。
4. 钉测 3+1：媒体历史缩减（>1MiB、媒体在中部非保护区、断言无 base64 泄漏+
   标记在场+最新 user 幸存）/ 巨型媒体消息（>64KB 内嵌 340KB 媒体）/ 受保护区
   溢出仍拒（预算等式不动）/ 旧钉测改判（显式省略语义）。
5. 变异（编译通过的无声删除+恢复拒绝）：3 测红→还原绿；**真实归档件重放**：
   1,365,000B→160,652B、4 消息（3 保护+1 摘要）、聚合标记在场。
