## 确认并修复的问题（P1×3 + P2×3 + P3×1）

### P1-1 跨身份数据泄露（前端）

模块级 singleton（requests/snapshot/queue/nodes/actions/lastEventAt）在登出、
重新登录、租户切换时从不清理；新身份首帧前甚至永久显示旧用户数据——
后端空 replay 时根本不发 initial_data，没有任何帧会覆盖旧状态。
修复：`store.ts` 的 `setUserInfo`（user/tenant 变化）、`clearJwt`/`clearApiKey`
（值变化时）经 cycle-free 全局回调调 `liveStreamStore.resetLiveStreamIdentity()`：
fence 旧 EventSource（generation+1）→ 完整清空全部租户域状态 → 仍有 consumer
则重开连接。`resetStream()` 补齐 queue/nodes/lastEventAt/initialDataReceived/
redis 健康/paused/needsFullRefresh。

### P1-2 重连代际交付状态失真（前端）

`lastEventAt` 跨 EventSource 代际保留：fatal 重连后新连接一 `open`，旧时间戳
就让加载标记提前消失、旧 queue/nodes 顶着「已交付」的名义继续显示。
修复：引入 `initialDataReceived`（每代际 `openConnection` 复位，只有
`initial_data` 帧——含显式空回放——才置位）；组件/面板全部改读该信号。

### P1-3 多实例共享库遮蔽 data-horizon（后端）

原判据比较「本机 lastBusinessActivity vs 全局 MAX(session_turns_hot.ts)」。
154/245 共享 PostgreSQL，任一实例的新行都能让全局 MAX 恒新鲜，另一实例
镜像全灭也不告警；Redis fan-out 让 lastActivity 也成了集群信号。
修复：身份 canary。每实例从本机 `onPersisted`（session mirror hook 之前）
按 UTC 分钟最多记 1 条、保留 10 分钟的「应产生 turn 的终态业务 request_id」
环；端点用 `request_id = ANY($1)` 一次往返查
`session_turns_hot UNION session_turns` 双腿（两表均有 request_id 索引），
成熟（>5min）且缺失即 stale。其它实例的任何新行都不能替代本机 request_id。
资格判定抽为 `sessionv2mirror.EligibleForTurnMirrorPolicy`（终态/探针合成/
内部回环三道策略门与 PersistHook 同源；运行期 shadow 开关**故意**不豁免——
关写入开关正是该告示要报告的状态）。canary 起点用 persisted-hook 时钟而非
`EventAt`（长请求终态到达时事件时间可能已超容忍窗，立即误报）。

### P2-1 health 旁路帧误撤加载（前端，并入 P1-2 修复）

`handleEnvelope` 把任何 JSON 帧（health/lifecycle）都标成「已收首帧」，
QueuePanel 在 queue envelope 未到时就显示「队列数据未接入」。
修复：只有 `initial_data` 置 `initialDataReceived`。

### P2-2 空 initial_data 不发送（后端）

`len(items) > 0` 才发首帧 → 空身份无权威清空信号（P1-1 的放大器）。
修复：恒发 initial_data；DB 读失败时不发（保持 loading + EventSource 重试），
不冒充「权威空回放」。快照零值同样权威（`Summary.Total==0` 不再跳过）。

### P2-3 空 nodes/queue 无法清旧值（协议）

`omitempty` 让权威空数组在 wire 上缺席，前端无法区分「无意见」与「清空」。
修复：`queue_present` / `nodes_present` 显式位；客户端 presence 为真时按
`?? null/[]` 权威赋值，无标志的非空载荷保持向后兼容。

### P2-4 fatal 重连只挂在总览组件（前端）

RequestRegistry / RequestJourneyDetail 直接 acquire，401/5xx 后永久 closed
且状态药丸仍可能显示已连接。修复：有界退避（5s×2 封顶 30s）下沉到
liveStreamStore——`onerror(readyState=2)` 排定、任何状态迁移先撤排定、
`open` 复位计数、final release 清 timer；组件里的旧 watcher 删除。

### P3-1 release 非幂等

重复 release 会把 refCount 减成负、关掉第二个 consumer 正在用的连接。
修复：release 闭包加 `released` 守卫。
