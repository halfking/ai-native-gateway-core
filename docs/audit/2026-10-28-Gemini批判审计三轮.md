## 二、本轮实锤两处真缺陷（都已修 + 真机复验）

### 缺陷 A（P0，跨会话集成）：`openai-chat` 词表分叉断掉 Gemini→原生上游

- **真机现象**：provider 翻成 `gemini-generate` 后，Gemini 原生入站请求 503
  `gemini executor: client protocol "openai-chat" not yet wired`（All 0 candidates）。
- **根因**：`domains/streaming/handler.go:4428` 用 `ir.DetectProtocol(body)` 填
  `ExecParams.ClientProtocol`，OpenAI Chat 线体检出 **`"openai-chat"`**（Gemini 入站
  的合成体也是它）；而 executor_gemini/executor_ollama 的 client-wire 白名单只认
  legacy 兜底值 **`"openai-completions"`**（IR==nil 时代的词）。catalog 层自己的
  别名表（protocol_normalize.go:40）与 connection_registry_wiring 一直把两者当
  同义词——**三处词表，executor 用了窄的那份**。
- **为什么测试全绿**：两个执行器的既有测试**全部**用 `"openai-completions"` 写——
  测试词表与生产词表分叉，测试绿而生产断。executor_gemini 的注释甚至写着
  「dispatcher 会检出 openai-completions」——**注释的假设就是错的**。
- **波及面**：gemini-generate 上游（**活路径**，无 flag 门）；ollama-native 上游
  （潜伏，FF_OLLAMA_NATIVE 默认关）。
- **修法**：`canonicalInboundWire()`（executor_gemini.go，openai-chat →
  openai-completions，与 catalog 别名表对齐），四处接线：gemini finalize 门 +
  clientWire()、ollama finalize 门 + clientWire()。
- **复验**：真机 Gemini 入站 fileData 音频 → 原生上游收到 **`{"fileData":{"fileUri":
  …,"mimeType":"audio/wav"}}` 原生形态**（完整 IR 往返保真）；流式 200；视频 fileData 同。

### 缺陷 B（P2）：`video_url` 在 Anthropic 边界未拒

- R148 让 parse_openai 把 `video_url` 解析成「保 Type + RawContent」的块；Anthropic
  序列化器的 default 分支会把它**原样发到 Anthropic 线上**——而 Anthropic Messages
  没有 video_url 块类型 ⇒ 上游 400 ⇒ 错误记账归到凭据/节点（2026-09-09 gemini
  dispatch 同族病理）。**仓内旧转换器**（chat_to_anthropic.go:445）一直把 video_url
  列在拒绝表里——两份实现口径分叉，IR 版是窄的。
- 修法：`validateAnthropicMedia` 拒绝表补 `video_url`（对齐旧转换器），在边界诚实
  拒绝而非让上游 400。

## 六、遗留风险（如实记）

1. **`session_turns_hot.host` 列缺失**（真机日志 `SQLSTATE 42703`，V2 shadow write
   失败）——本地库 schema 漂移，与本轮无关，但**会吃掉本地环境的 V2 写入**。
2. **首次流式失败把凭据打进熔断**（`circuit failure pending confirmation` →
   `db_empty`）——mock 抖动触发的既有熔断行为，真实上游短抖时同样会发生；恢复要
   等冷却或人工重置（恢复脚本在 `scripts/credential-health-recover.sh`）。
3. **Responses 方言的 URI-only 音频仍是「整块跳过」**（buildResponsesInputAudio 无
   URI 表达，跳过未上报损失——Responses 侧损失上报点缺失，OpenAI 侧有）。
4. Gemini 入站的 `alt=sse` **总是**得到 SSE 形态（厂方默认无 alt=sse 时是分块 JSON
   数组）——既有行为，原生客户端如按 JSON 数组解析会不兼容；未改。
