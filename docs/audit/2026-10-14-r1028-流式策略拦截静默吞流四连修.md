## 二、机制（为什么「成功」与「客户端零内容」同时成立）

output compliance 流式持帧：所有带可见文本/tool-args 的帧 `SuppressChunk`
持有（跨帧 regex 契约），直到终态帧或 finish() 的 FlushStreamPending 释放。
lane 检查（r1013 契约：Bash 参数含公网 IP 字面量——Bash 不在 r1020 惰性
工具集）命中时释放失败 → 整条流被扣住丢弃 + 客户端只拿到 trusted terminal。
四条独立缺陷让这次合法的策略拦截**呈现为不可名状的事故**：

1. **survival 分支从未接线 R25-V**（handler.go）：goal-retry 循环自 R25-V
   （2026-09）起就把 `interceptingStreamWriter.blocked` 打标成
   `outputGovernanceTerminal` → 失败审计 + 跳过成功 telemetry；survival
   分支的 writer 困在 if 块作用域里无人消费 → **audit 记 success=true**。
2. **block 决策点零日志**：stream_compliance.go 的 lane/event/comment 三处
   block 与 mandatory 重写拒绝全部无 slog → 网关侧无从归因。
3. **chat 终态帧无 code**：`{"type":"api_error","message":…}`——agent 客户端
   无法归类 → `reason=unknown`；responses 腿本有 code，chat 腿缺失。
4. **DrainPending 死断言**（六处桥）：`w.(*GateWriter)` 在
   wrapAttemptWriter 返回外层包装（survival 复用 coordinator gate 的全部
   路径）时恒失败 → R-vapeur3 的 [DONE] 排水在 survival 路径是死代码 →
   持帧释放推迟到 finish()（成功请求的迟到整批交付 = 日志里 finish 落后
   outcome 12s 的观测解释）。

## 五、登记不修（owner 拍板域）

1. **r1013 契约本身**：模型在 Bash 参数里写公网 IP 字面量（含版本号样四
   元组、用户自有服务器 IP 的回显）仍整轮阻断。修复只让阻断**可见、可
   归类、可审计**。若 owner 认为「会话请求侧出现过的 IP 应豁免」（r1024
   restored-values 同原理、来源改请求侧），需在 guard（mandatory，
   排还原之前）加会话级豁免通道——涉及外传防线语义，另立轮次。
2. chain.go 的持帧者类型断言（`interceptor.(StreamPendingFlusher)`）对装饰
   器不鲁棒：任何包装层都会让释放载荷被静默丢弃（本地复现实证）。当前
   生产链无包装层，暂不动；给持帧者加装饰器前必读 chain.go:196 注释。
3. slog 侧「audit: request completed success:true」行在治理阻断时仍会打
   （来自 audit hook sink 的另一事件源）；权威判定以 session_turns_hot 行
   为准。口径混淆已在此记录。

## 六、判据纪律增量（第 10 条）

**自建 HTTP 夹具的「通过」可能是空洞的**：流式响应的最终 wire 字符串无法
区分「逐帧透传」与「持帧后终态一次性释放」——本缺陷复现两度假绿（第一
版终态断言、第一版持帧行为断言），都是靠给 writer 链加逐帧探针后才现形。
流式判据要么断言**时序**（分批读取），要么在链的中间层加计数/日志探针。
