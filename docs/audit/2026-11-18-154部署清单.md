### ★ 为什么 3060 的基点是「上一版在役树」而不是 `origin/main`

3060 动手时 `origin/main` 已在并行车手里（`48ae5917d`）⇒ 拿 main 发版＝**替并行车发版**。
⇒ 3060 ＝ **`8ab0d2e56`（3051 的部署树）＋ cherry-pick 本轮 F1 修复** ⇒ **只加修复、不含并行车、不回滚**。

## 六、只凭本仓即可复核的命令

```bash
# ① 三版部署的身份（不依赖任何 /private/tmp 目录）
git show -s --format="%H  %s" \
  deploy-154/seq3050-6840a7be^{commit} deploy-154/seq3051-8ab0d2e56^{commit} \
  deploy-154/seq3060-2083bbe09^{commit}

# ①b 「当前在役」不要写死：**自动取 seq 最大的 deploy-154 tag**（★ 写死会永远指向旧发布）
git tag -l 'deploy-154/seq*' | sed -n 's/.*seq\([0-9]\{1,\}\).*/\1 &/p' | sort -rn | head -1
#   ⇒ 3060 deploy-154/seq3060-2083bbe09

# ①c 标签消息里带机器可解析的「基点 / cherry-pick 列表 / 改动文件数」（★ 一行一个 key）
git tag -l --format='%(contents)' deploy-154/seq3060-2083bbe09 | grep -E '^(base|cherry-picks|files)='
#   base=8ab0d2e56
#   cherry-picks=4c0c41026,2083bbe09
#   files=10

# ② 当前在役版相对其【基点】的改动面（★ 用 base，不要用 TAG^）
git diff --stat 8ab0d2e56 deploy-154/seq3060-2083bbe09^{commit}
git diff --name-only 8ab0d2e56 deploy-154/seq3060-2083bbe09^{commit} | wc -l    # ⇒ 10

# ③ 3051 → 3060 的差异面（应＝F1 修复：字形单一真源 + 图例/瓦片 + 钉测 + 验收资产）
git diff --name-only deploy-154/seq3051-8ab0d2e56^{commit} deploy-154/seq3060-2083bbe09^{commit}

# ④ 并行车零泄漏（输出为空 ⇒ 零泄漏）
git diff --name-only 8ab0d2e56 deploy-154/seq3060-2083bbe09^{commit} \
  -- domains/promptinjection admin/pi_analysis_handler.go
#   menu-config.json 要比【内容】（去 exported_at 构建戳）⇒ 见 §五

# ⑤ 线上身份（与 ① 的 git_sha 对拍）
curl -s https://llm.kxpms.cn/healthz
ssh -o BatchMode=yes -p 25022 root@47.97.111.154 "cat /opt/llm-gateway-go/current/version.json"

# ⑥ 一条命令跑完整 15 条证据（SSH/healthz/i18n/vitest/bundle/可追溯/合并/F1/浏览器面）
bash maestro/verify-stage-tree-evidence.sh --with-browser
```

★ **⚠ `TAG^` 不是基点**：部署树是 `base → cherry1 → cherry2 → cherry3`，
`TAG^` 指的是**上一笔 cherry-pick** ⇒ 会算成「10 个文件」冒充「25 个文件」⇒ **看起来 PASS、其实是错的**。
⇒ 基点一律用标签消息里的 `base=` 或本文件的基点列。

★ **⚠「在役是哪一版」不要写死**：本文件第一版把 tag 写死成 `seq3051`，
3060 上线后**采集器就会去验旧发布** ⇒ 证据链指向历史快照而不是现状。
⇒ **动态取 seq 最大的 tag**（命令 ①b）。

★ **为什么要有这份清单**：部署源原本只存在于 `/private/tmp/deploy-frozen-*`（系统清理会抹掉），
而三个部署 SHA **一度没有任何 ref 指向** ⇒ `git gc` 后可能被剪掉 ⇒ 「可追溯」不可靠。
⇒ 现在 **tag（durable ref）＋ 本清单（仓内文件）** 双锚定，复核者不需要任何临时目录。
