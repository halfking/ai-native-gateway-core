## 4. Category B — 14 date-suffixed snapshot canonicals

```sql
-- Find ALL active canonicals that have a YYMMDD or YYYYMMDD date suffix in canonical_name
SELECT id, canonical_name, family, status, source
FROM models_canonical
WHERE status='active'
  AND canonical_name ~ '-(20[0-9]{6}|[0-9]{6})$'
ORDER BY canonical_name;

-- For each, list its shared-alias overlaps with another active canonical
WITH snapshot_ids AS (
  SELECT id FROM models_canonical
  WHERE status='active'
    AND canonical_name ~ '-(20[0-9]{6}|[0-9]{6})$'
)
SELECT s.id AS snapshot_id, mc1.canonical_name AS snapshot_name,
       ma.raw_name AS shared_raw, COUNT(DISTINCT ma2.canonical_id) AS shared_with_count,
       array_agg(DISTINCT mc2.canonical_name) AS shared_with_names
FROM snapshot_ids s
JOIN models_canonical mc1 ON mc1.id=s.id
JOIN model_aliases ma  ON ma.canonical_id=s.id AND ma.status='active'
JOIN model_aliases ma2 ON ma2.raw_name=ma.raw_name AND ma2.canonical_id<>s.id AND ma2.status='active'
JOIN models_canonical mc2 ON mc2.id=ma2.canonical_id AND mc2.status='active'
GROUP BY s.id, mc1.canonical_name, ma.raw_name
ORDER BY snapshot_name;
```

If the 14 names from local appear on 252 too (with active status), re-run the
audit doc §Phase 2 SQL on 252. The SQL is schema-agnostic (only references
canonical_id / canonical_name / provider_models / model_aliases).
