## §2 闸门失效的机制（可复现）

### 2.1 闸门长什么样

`scripts/deploy-lib.legacy/db-changelog.sh` 的 `_deploy_migration_checksum_reconcile()`：

```bash
while IFS='|' read -r ver description; do
  ... 解析 canonical 文件 → 算本地 SHA-256 → 查 llm_gateway_migration_checksums ...
  缺行 / 文件名不符 / 校验和不符 ⇒ _db_err + return 1   # fail closed
done < <( ssh ... psql "SELECT version || '|' || description FROM schema_migrations ..." )
```

调用方：`deploy-seamless.sh:1087`（第 6.5 步，**切换符号链接之前**）→
`deploy-154.sh` → `deploy-seamless.sh deploy 154` ⇒ ★ **这就是生产 154 的发布路径**。

### 2.2 ★ 为什么它只跑了 1 轮

★ **循环体内的 ssh 把 while 的 stdin 管道读空了。**

- 循环的输入是**进程替换**（`< <(...)`）⇒ 那是一条**管道**；
- 循环体内要读远端账本，用的是 `scripts/deploy-lib.legacy/ssh-retry.sh` 的
  `ssh_run()`，它**用命令替换捕获远端输出**：
  ```bash
  output=$(ssh ... "$host" "$script" 2>&1)
  ```
  ⇒ 命令替换**不改变 stdin** ⇒ ssh 的 stdin **就是**外层 while 的那条管道
  ⇒ ssh 把它读空（转发给远端，远端不读也不要紧，**本地管道已被抽干**）
  ⇒ while 的下一次 `read` 直接命中 EOF ⇒ **循环结束**。

实测证据（`bash -x` 跟踪生产同一份脚本与同一台目标机）：

```
+ base=412_rca_ts_index.sql
+ checksum=89e938ee...
+ row='412_rca_ts_index.sql|89e938ee...'
+ [[ 412_rca_ts_index.sql != ... ]]
+ [[ 89e938ee... != ... ]]
+ IFS='|'
+ read -r ver description        ← EOF
+ echo RECONCILE_EXIT=0
```

⇒ **只判了 412 一个版本**（而 412 的指纹恰好是对的 ⇒ 闸门永远绿）。

| # | 我犯的错 | 现象 | 判定 |
|---|---|---|---|
| 1 | 用 `ssh 154`（**含空格的字符串**）当 `ssh_cmd` | `"$ssh_cmd"` 被当成**单个参数** ⇒ ssh 把 `"ssh 154"` 当主机名 ⇒ 返回 0 行 | ★ **我的量具坏了**（生产里 `SSH_CMD="remote_ssh"` 是**函数名**，不是字符串）⇒ 差点得出「闸门被跳过」的假结论 |

## §5 官方补录载具（`scripts/repair-252-migration-ledger.sh`）的三道闸

R75 轮实测该载具**跑不到「补录」这一步**，卡在三处（本轮修了两处，第三处待裁决）：

### 5.1 ★ 已修：canonical 单候选兜底缺失（仓内已改）

- 现象：生产 837/838/839 的 `description` **是空串**（2026-10-07 12:48~12:50 应用）
  ⇒ repair 的 `canonical_for` 要求「单候选时 description 也必须逐字相等」
  ⇒ 判「无法解析为唯一 canonical 文件」⇒ **官方载具修不了它们**。
- 修法：与**部署侧同款**的单候选兜底（`db-changelog.sh` 里本来就有：
  `if [[ -z "$f" && ${#candidates[@]} -eq 1 ]]; then f=${candidates[0]}; fi`）。
- ★ 修的过程中**自己踩了第二个坑**：`while IFS= read -r candidate` 循环**结束时
  EOF 会把循环变量置空** ⇒ 循环后读 `$candidate` 得到空串
  ⇒ 首候选必须在**循环内**捕获（`first="$candidate"`）。
  ⇒ 这条已被本轮自检抓住（§5.2）。

### 5.2 ★ 已修：首候选捕获（仓内已改）+ 自检

- 自检方式：★ **不手抄函数** —— 用 awk 从仓内脚本**原样抽出** `load_candidates` /
  `canonical_for` 两个函数体，在 **bash 5.3 容器**里 eval（★ macOS 自带 bash 3.2
  没有 `declare -A`，本机跑不动）后喂 fixture 断言：
  - 837/838/839（description 空）⇒ 必须解析到唯一文件 ✔
  - 840（两个候选 + description 空）⇒ **必须拒绝猜** ✔

## §8 通用式（本轮新增，进 LESSONS）

1. ★★ **「闸门是绿的」和「闸门跑过了」是两件事** —— 用 `bash -x` 看它**实际迭代了几轮**，
   比读它的返回值可靠得多。
2. ★★ **循环体里任何会读 stdin 的命令（ssh / curl / docker）都会吃掉 while 的管道**
   ⇒ ⇒ 判据：`while read` 的数据源**必须是文件**，或者循环体里的命令一律
   `< /dev/null`。
3. ★★ **`while IFS= read -r x` 循环结束后 `$x` 是空串**（EOF 会清空循环变量）
   ⇒ ⇒ 需要「最后一个/第一个元素」时**在循环内捕获**。
4. ★★ **量具跑不出数时，先量量具** —— 本轮两次「读数错误」都导出过**方向相反**的结论。
5. ★★ **基线对比必须用「基线自己的路由集」** —— 现场另找的路由清单可能与之几乎不相交。
6. ★★ **落前基线没留「环境底噪」对照 ⇒ 后置对比只能说「没退化」，不能说「变快了」**。
