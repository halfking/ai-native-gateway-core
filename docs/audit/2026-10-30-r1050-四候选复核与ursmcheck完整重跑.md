## 三、候选 C：`<tr>` 直挂 `<table>` —— 前一轮的「复现不出」结论是错的

### 3.1 ★★ 前一轮结论错在哪

我此前（同一会话的前半段）写的是：

> 候选C：Vite 警告在当前 HEAD 复现不出（stash A/B 已证基线也无），结论改记为「上游已消失」

得到「零错误」⇒ 判「无此警告」。

### 3.2 ★★★ 但**零错误有两种读法**：扫到了没发现 vs 根本没扫到

**反向验证（证明量具失明）**：
```js
compileTemplate({ source: '<table><tr><td>x</td></tr></table>', onError(e){ console.log('CAUGHT:', e.code, e.message) } })
// → 零错误输出
```
⇒ ★★ **同一个量具连人工构造的确定缺陷都抓不到** ⇒ 「零错误」**不是「没缺陷」，是「量具瞎」**。
（根因：`compileTemplate` 的浏览器端解析器对 `element-permitted-content` 这类**警告级**问题默认不报，
  只在 `onWarn` 通道里；而 Vue 运行时用 `innerHTML` 挂载，压根不走 HTML 解析器的 permitted-content 校验 ⇒
  **这条警告压根不在 Vue 的通道里**，我拿 Vue 编译器去量它，量错了对象。）

★ 这正是本仓纪律「**静态门、独立尺、运行期探针必须互相抓**」的现实版：
★ **「我用的工具没报错」≠「事实不存在」** —— ★★ 尤其当**工具与事实不在同一条通道上**时。

### 3.3 ★★★ 用能自证的量具重查 ⇒ 缺陷确实在

**量具**：栈式标签配对扫描（开标签入栈 / 闭标签出栈 / 自闭合不入栈），
判定「`<tr>` 的父节点是 `<table>`」。
**先自证**（正例 / 负例都要对）：
```

NEGATIVE defect : 1   （<table><tr><td>x</td></tr></table>）
nested table    : 1   （内层 table 的 tr 确为缺陷 ⇒ 命中）
```

**全仓扫描（299 个 `.vue`）命中 5 处，全在 `RequestLogsView.vue`**：
```

line 186 | <tr> | stack: div>div>div>div>table
line 191 | <tr> | stack: div>div>div>div>table
line 196 | <tr> | stack: div>div>div>div>table
line 201 | <tr> | stack: div>div>div>div>table
```

### 3.4 ★★ 真正的危害不是「lint 报警」，是**浏览器会悄悄改写语义**

实测（jsdom，与浏览器同源的 HTML 解析器）：
```
<table><tr><td>x</td></tr></table>       → table.children = [TBODY]   ← 解析器隐式插入 <tbody>
<table><thead>…</thead><tbody>…</tbody></table> → table.children = [THEAD, TBODY]
```
⇒ ★★ **浏览器会自动补一个隐式 `<tbody>`，把作者写的结构改掉**；
⇒ ★ 而 Vue 的编译期模板走 `innerHTML` 挂载，**拿不到这个容错** ⇒
  ★★ **同一份模板在「编译期语义」与「运行期 DOM 形状」上可以不一致** —— 这才是这条警告的实质。

### 3.5 ★★ 定位到的那张表不是我看错的那张

★ 我第一次用 grep 行号定位，**看的是 1550 行那张表**（`<table class="data-table request-log-table">`），
  那张是**合法的**（`<thead>` → `<tbody>` → `<tr>`）；
★ 真正有缺陷的是 **1335–1361 行**那张「会话缓存机制 / 压缩策略说明」表：
