## 0. 摘要（一页读懂）

### 0.1 三句话结论

1. **技术上可行，而且路径比预想的短**：`salesdecorate` 已经把「原厂刊例价 + 25 个 MaaS 平台价 + 1230 个模型的每日行情」攒齐了（`price_observation` 3744 行，最新 `run_date=2026-11-03`）；而网关侧要跟它对比的「供应商实付价」虽然**质量极差**（2328 条绑定里只有 **177 条有价**，其中 **141 条是 0/0 空价**、**9 条是占位价形状**，真正像真价的只有 **27 条**），而**有正价的 36 条绑定里，88.9%（32/36）能对上** `salesdecorate` 的模型目录。⇒ **「比价 → 评分 → 路由参数」的链路在第一批就能跑通，不需要先补全全量目录。**

2. **但「直接拿市场价当路由权重」是错的**，因为三件事：① 市场比价的分母是「跨供应商同模型的刊例价」，路由竞争的是「同模型不同凭据」；② **方向相反**——市场比价「我们买得便宜」是**加分**，路由成本「我们花得多」是**减分**，直接相加会把语义搞反；③ **87.6% 的有价绑定是周期性套餐**（`token_plan` 155/177），钱已经付了，边际成本≈0，不该因为「市场价比我贵」被降权。⇒ **正确形态是「新增一个可选维度、权重默认 0、与现有 `CostWeight`/`IQWeight` 同族」**，而不是改现有成本分。

3. **真正的第一优先级不是路由，是数据质量与商业闭环**。实测已经能量出两个硬结论：
   - **我们在 Anthropic 系买贵了**：`claude-opus-4-8` 供应商实付输入 **$10/1M**，而原厂刊例是 **$5/1M** ⇒ **输入价 2.00 倍**；`claude-fable-5` 是 **1.50 倍**（这两条已超 `supplier_price_drift` 的 1.5× 阈值）。同一模型市场侧（`deepinfra`）折人民币后输入只要 **$4.64/1M** ⇒ **我们比市场贵 2.16 倍**。
   - **商业侧几乎是空的**：`salesdecorate` 有 3744 行行情，但**供给卡只有 7 张、报价单只有 1 张**（还是 `draft` 的测试单）。⇒ 行情→报价→成单的链路**通了但没人走**。

## 1. 两个仓库的定位（先把边界划清）

| | `llm-gateway-go`（本仓） | `salesdecorate` |
|---|---|---|
| 角色 | **执行/计费层**：请求进来 → 选供应商 → 记账 → 出账单 | **行情/报价层**：去市场把价格和打法采集下来 → 算账 → 出报价单 |
| 关键资产 | 2328 条供应商绑定、1217 个 canonical 模型、路由与计费 | 25 个平台行情、3744 条价格观测、7 张供给卡、1 张报价单 |
| 写入者 | 运维（`admin/pricing.go` 导入 CSV）、工具提案 | 采集器（每日 01:00）+ 运营（供给卡/报价单手工录入） |
| 运行形态 | 在线服务（请求热路径） | 离线/准实时（每日采集 + 后台 API + 前端） |

**边界原则（本方案的第一条设计约束）**：

- **行情层 → 网关：单向自动同步**（原厂刊例价、MaaS 最低价）。理由：采集是机器事实，网关消费它。
- **商业层（供给卡的人工定价/报价单）→ 网关：禁止自动同步**。理由：本仓既有纪律明写「**对账只记账不改价**」「**机器不该替运营改账**」「**钱永不消失**」——营销手工定的价若能直接改路由，等于让一次报价误操作变成流量倾斜。
- **网关 → 行情层：反向只回「我方实付价」这一条**，用于算「采购折扣率」；不回路由决策、不回客户价。

### 2.4 两套目录能对上多少？（接合可行性实测）

把两个库的模型目录都拉下来，本地做归一后求交（归一：NFKC、去厂商前缀 `vendor:-`、`.`/`_`/空格 → `-`、压连字符、去零宽字符）：

```
网关 models_canonical        1217 条 → 归一后 1215 个 key（自身几乎无重）
salesdecorate model          1218 条 → 归一后 1053 个 key（★ 自身有 165 个归一后撞车）
精确交集                     361 个 key  = 网关全量的 29.7%
交集里「同 key 对应多个原始写法」的        141 个  ← 两侧都有脏变体
```

**但全量 29.7% 不是决策依据**——决策依据是「有价绑定」：

```

```

⇒ **结论：不需要先统一两个仓的全部模型目录**。第一批（88.9% 的有价模型）直接可跑；剩下的靠 `model_alias` 表 + 归一函数增量补，别做一次性大清洗。

## 4. 核心机制：市场参考价 → 供应商评分 → 路由参数

### 4.1 五价坐标系（先把名字定死，避免后面口径漂移）

| # | 名称 | 定义 | 存储位置 | 现在有吗 |
|---|---|---|---|---|
| **P1** | **原厂刊例价**（vendor list price） | 模型厂商自己公布的、按量标价 | 网关 `models_canonical.baseline_*`；行情 `salesdecorate` 的 `is_vendor` 平台观测 | 网关 16 个模型 / 行情 14 个平台 |
| **P2** | **市场最低价**（market floor） | 非原厂 MaaS 平台上该模型的最低标准按量价 | **无**（需建） | ❌ |
| **P3** | **供应商实付价**（我方采购价） | 我方实际支付 | `credential_model_bindings.unit_price_*` | ✅ 但 141 空价 + 9 占位 |
| **P4** | **内部核算价 / 基准价**（本仓既有概念） | 内部合理性下限，**只告警不参与金额计算** | `models_canonical.baseline_*`（= P1 的网关侧副本） | ✅ |
| **P5** | **客户零售价** | 客户实际付 | `model_credit_rates`（积分）＋ `cents_per_credit` | ✅ 但只有报表级毛利 |

**命名纪律（避免踩既有坑）**：**P1 与 P4 不是两个东西**——P4 是 P1 在网关库的副本（826 的注释明写 `baseline_price_vendor` 是「基准价所引用的厂商，**不是实际被计费的供应商**」）。本方案里 **P1 是「市场侧的事实」**，**P4 是「网关侧的内部账」**，两者必须分别记账、分别记出处，不能合列。

### 4.2 供应商竞争力评分：拆三个子分数，不合成一个

**为什么必须拆开**（这是本方案最重要的设计判断）：

- 三个子分数的**语义不同**：C1 答「我们采购议价多深」（对内，对采购）；C2 答「我们相对市场最优者什么位势」（对内对竞争 ＋ 对外对销售）；C3 答「这条价**是不是真的**」（数据质量）。
- **失效模式不同**：C1 缺原厂价、C2 缺市场观测、C3 缺价 —— 三种缺失各自独立，必须能分别 fail-open。
- **责任人不同**：C1 归采购、C2 归市场/销售、C3 归数据治理。
- **符号不同**：C1/C2 **越大越好**（我们更便宜）；而路由里的成本惩罚 **越大越差**。⇒ **合成一个数必然要在接入时手工翻符号** ⇒ 一旦有人翻错，就是「买得便宜的供应商被降权」。**拆开就不可能翻错。**

#### C1 · 采购折扣率 `discount_vs_vendor`

```
discount_vs_vendor = 1 − (supplier_blended / vendor_list_blended)
```

- 分母：**P1 原厂刊例价**（同币种，或先按 `settings.CNYScoreFX()` 折算）。
- 分子：**P3 供应商实付价**，`blended = in + out`（与既有 `blendedCost` 同口径，`router.go:1549`）。
- **NULL 语义（关键）**：`NULL` = 拿不到原厂价（未知）；`0` = 正好等于原厂价。**两者不可合并**——这正是 826 的既有纪律（`baseline_input_price_per_1m IS NULL` ≠ `= 0`），且 `propose-baseline-prices` 的 `sigNum` 也专门保持 nil/0 可区分。
- 读数含义：`claude-opus-4-8` 当前 **−100%**（输入侧 `1 − 10/5 = −1`），即**我们付的输入价比原厂贵一倍**。

#### C2 · 市场位势 `market_position`

```
market_position = market_min_blended / supplier_blended      （>1 = 我们比最便宜的更便宜）
```

- 分母：**P2 市场最低价**（**必须排除我方自己的平台**，否则自己和自己比）。
- **必须同时留两个口径**：只比「输出价」会被输入输出比例不同的模型误导；用 blended 与既有 `blendedCost` 对齐。
- **必须记「最低价来自哪个平台」**（`market_min_platform_id`）——单一来源时该分**降级为参考而非判据**（§2.5 的诚实边界）。

#### C3 · 价格置信度 `price_confidence`（**门，不是分**）

C1/C2 都以 P3 为分子。**P3 不可信时，C1/C2 的数字没有意义。** 故 C3 是**前置门**：

| C3 档 | 判据（实测口径） | 处理 |
|---|---|---|
| `trusted` | 正价 ＋ 输入≠输出 ＋ 币种已知 ＋ `pricing_source` ∈ {imported, manual, scraped, catalog} | C1/C2 正常产出 |
| `suspect_symmetric` | 正价但 `in == out`（实测 **9** 条，且 9 条**都还 routable**） | **不产出 C1/C2**；进人工复核队列 |
| `empty` | `in == out == 0`（实测 **141** 条） | **不产出 C1/C2**；本仓既有裁决即「无价」而非「免费」 |
| `unknown_currency` | 币种缺失 | 拒绝（沿用 `propose-supplier-prices` 的「币种未知不默认 USD」） |

> C3 的判据**直接复用**本仓既有健康门 `offer_price_looks_like_placeholder`（`bg/routing_health_checks.go:1001`）的形状与措辞（它已经区分了「正价对称」与「0/0」两个**需要相反修法**的群体）—— **不新造判据**。

### 4.3 路由接入：新增一个**可选维度**（权重默认 0）

#### 为什么不改现有成本分

现有成本分是**队列内相对**的：`scorePrice` 的分母是候选池 P75（`autoroute/scoring.go:243-260`），`computeCostContext`（`autoroute/index.go:328-356`）算 P75 时**排除零价候选**（免得免费模型把基线拉到 0），并把 CNY 折 USD。⇒ 它能回答「这些候选里谁更便宜」，**不能**回答「我们全都比市场贵 2 倍吗」。后者正是营销与采购要知道的。

#### 新维度：`MarketAdvantage`

```
market_advantage_score = 100 × clamp( 1 − (supplier_blended / market_ref_blended) , 0 , 1 )
```

- 分母：**P2 市场参考价**（blended，同币种）。
- **与 `scorePrice` 同族**：0..100，越大越好（我们相对市场越便宜）。
- **符号天然正确**：市场参考价是固定分母 ⇒ 「我们比市场便宜」⇒ 分数高 ⇒ 在 composite 里**加**它就是加分。**不需要手工翻符号**（这是拆分子分数的第二个好处）。

#### 接入点（精确）

| 层 | 文件 | 改动 |
|---|---|---|
| 索引 SQL | `autoroute/index.go` `refreshIndexSQL`（:535+） | 投影 `market_ref_in_per_1m` / `market_ref_out_per_1m` / `market_ref_platform_id` / `market_ref_run_date` |
| 索引刷新 | `bg/auto_index_refresher.go:623+` | 与上同步（★ 派生台账必须**按提交树**生成，见 §9.3） |
| 候选结构 | `autoroute/scoring.go` `Candidate`（:16-81） | 加 `MarketRefInPer1M` / `MarketRefOutPer1M` / `MarketRefRunDate` |
| 队列上下文 | `autoroute/scoring.go` `CostContext`（:146-159） | 加 `MarketRefBlended`（**逐候选**，不是池级 ⇒ 不进 `CostContext`，直接放 `Candidate`） |
| 评分 | `autoroute/scoring.go` `scorePrice` 旁 | 新增 `scoreMarketAdvantage(c Candidate) float64`，**与 `scorePrice` 并列**（不改 `scorePrice` 本身） |
| 权重 | `autoroute/profile.go:67-85` 三档 profile | 新增 `MarketAdvantageWeight`，**三档全部默认 0** |
| v2 主链 | `autoroute/scoring_v2.go:52-68` | `FinalScore = IntentMatch*0.4 + Price*0.2 + ChannelQuality*0.3 + Reliability*0.1 + correction` ⇒ **加一项 `MarketAdvantage*w`**，默认 `w=0` ⇒ 逐字节不变 |

| 执行层 | `domains/streaming/executors/router.go` `p2cOrder`（:1497-1547） | 10% 成本带闸门（:1518）**不改**；竞争力分不参与该带（它是**带**不是**点**） |

#### 两条不可越过的实现纪律

1. **默认权重 0 ⇒ 未接线时行为逐字节不变**。这是本仓既有 `CostWeight`/`IQWeight`/`OutlierWeight`/`CacheAffinityWeight` 的形状（`router_scoring.go:187-195` 注释：「Guarded so the default (weights zero / off) hot path stays byte-identical to the pre-RT-2 composite」）。**任何新维度不满足这条 ⇒ 不许合。**
2. **无信号即中性**：C1/C2/C3 任一缺失 ⇒ 该维度贡献 **0**，**不得**折算成「未知即最差」或「未知即最好」。特别是 C3=`empty`/`suspect_symmetric` 时 ⇒ 中性，**不许**当免费（这正是 §2.2 那条不自洽要修的地方）。

### 4.4 治理红线（继承本仓既有裁决，不新造）

| 红线 | 出处 | 在本方案里的体现 |
|---|---|---|
| **基准价只做「合理性下限」告警，不参与金额计算** | `bg/baseline_price_not_in_billing_test.go:11`（2026-10-07 人裁决）＋ 静态门（:68-80 禁 `baseline_*` 进 `CalcCost`/`cost_usd`/`cost_cents`/`total_cost`） | ★ **新维度只进候选排序，不进任何金额计算** ⇒ 不触发该门。**但「路由排序算不算金额计算」需要 owner 显式澄清**（§10.1） |

### 5.2 同步链路（严格单向 + 三步法）

```

   │  · 归一 canonical（§2.4 的归一函数）

   │  · P1：取 is_vendor 平台中 vendor 与模型厂商一致者的最新价；无 ⇒ NULL
   │  · P2：取非原厂、非我方平台的最低价；记录 platform_count
   │  · 冲突 ⇒ **整组 withhold**，进 conflicts
   ▼
market_reference.csv（人审 diff）
   ▼
admin 导入通道（同 pricingImport 形状：offer_id/keyed upsert + 逐行回报 updated/failed）
   ▼
market_price_reference  →  每日重算  →  supplier_market_position
```

**同步器的判据要求（照抄本仓既有工具的形状）**：

- **必填参数**：`-source-dsn`（或 `-source-url`）、`-run-date`、`-fx-rate`（**不默认**）、`-out`。
- **拒绝族**（每个族一个明确原因，禁止静默跳过）：`model_alias_unresolved` / `no_vendor_price` / `conditional_price` / `conflict_same_canonical` / `currency_unknown` / `stale_source`（`run_date` 超过 N 天）。
- **绝不**在同步器里做「取第一条」「取数值最小的那条当原厂价」这类隐式决策。

### 5.3 路由接入的**实施顺序**（不可颠倒）

1. 先落表（①②③）＋ 同步器 ＋ 评分器，**但不接线到路由**。
2. **影子模式**：每请求算出 `market_advantage_score` 但**不改顺序**，只落日志/指标；对比两套排序的差异分布。
3. 差异分布稳定后，**显式打开**权重（从 0.05 起步），并设置**回滚开关**（env，秒级生效）。
4. 任一阶段出现「排序变化导致成功率/延迟劣化」⇒ 权重回 0，**不需要发版**。

### 6.2 三条产品线（把内部能力变成对外价值）

#### 产品线 A · 面向客户（租户）：「算得清的账单 + 看得懂的价格」

**现状痛点**（实测）：客户看到的是**积分**价目（`model_credit_rates`），换算靠 `maas_settings.cents_per_credit`（默认 0.1 分/积分）⇒ 客户无法直接和公开的 MaaS 报价比较，也无法独立核算账单。

**方案**：
1. **双口径价目表**：积分（计费口径，用于对账）＋ **人民币/美元每百万 token**（理解口径，用于比较）。后端已有 `cents_per_credit` 桥；前端 `web/src/views/tenant/MaaSPricingView.vue`（329 行）与 `StandardModelPricingView.vue`（836 行）是落点。
2. **客户可见的市场参考价**：在价目表上给出「市场公开价区间」与「我们的价格」并列（数据来自本方案的 P2）⇒ **透明即信任**，且这正是差异化卖点（我们公开比价，多数聚合平台不公开）。
3. **预算护栏接上「预计月耗」**：仓内已有 `domains/hooks/goal/cost_presets.go:57-59` 的 `MonthlyTokenLimit` / `SessionTokenBudget` / `CostAlertThreshold`（**注意：它是 token 预算，不是钱**；`CostAlertThreshold` 是 0..1 的比例阈值，默认 0.85）⇒ 补一个「按当前用量速率外推的月末预计消耗（人民币）」。

#### 产品线 B · 面向销售：从「7 张卡」到「可批量生成的 SKU」

**现状痛点**（实测）：供给卡 7 张、报价单 1 张（`draft`）、毛利全是同一个 20.0000。

**方案**：
1. **行情 → 供给卡一键化**：复用已有的 `/api/v1/supply-cards/vendor-discount`（选原厂平台 ＋ 折扣 ＋ 加成 ⇒ 一键建卡），但**新增一路从「我方实付价」建卡**（而非从原厂刊例价）⇒ **成本口径与网关统一**，消除 §2.3 的双轨成本。
2. **分层加成策略**：把 20% 的全局默认，换成**按模型族 × 客户等级 × 承诺档**的策略表（例如：原生 API 直连 25%、聚合渠道 15%、批量异步 8%、承诺 SLA 的加 5%）。加成策略是**配置对象**，不是硬编码。
3. **一键报价**：输入「模型 ＋ 月用量 ＋ 承诺量」⇒ 出 3 档报价（直采 / 聚合 / 自营池），每档标明成本、毛利、证据（`evidence` 字段已存在）⇒ **报价单带着证据走**，这是 `salesdecorate` 数据模型已经支持、但没被用起来的。

#### 产品线 C · 面向平台：把「采购折扣率」变成对外价值

**核心洞察**：**「我们同时掌握 14 个原厂的刊例价 ＋ 25 个 MaaS 平台的行情 ＋ 我们自己的实付价」本身就是产品能力**——它让「你按 X 买、我按 Y 卖」的价差**可证明**，而不是拍脑袋。

- 对外话术有据可依：报价单里的成本行附 `evidence`（页面快照 + 原文摘录）+ `source_url` ⇒ 客户尽调时能自证。
- 对内护城河：知道自己的采购折扣率（C1）＝ 知道真实毛利上限；只知道零售价 ＝ 不知道自己在亏还是在赚。

## 7. 更多用途（本方案不止路由）

按「见效快 × 风险低」排序（前 4 项建议 P1 阶段就做）：

1. **采购谈判的反向筹码**：每日行情能看出「整个市场在降价，只有这家没降」⇒ 带数据去谈，而不是等账单变贵才发现。
2. **新供应商准入评估**：新报价进来先与市场参考价比 —— 高于市场最低价 30% 以上的**要求说明**。这是把 §4.1 的 P2 变成一道**准入闸门**。
3. **价格异动预警（我方被涨价的提前量）**：供应商涨价前，市场通常先动 ⇒ `price_change`（已有 41 条）＋ `alert_level` 可做提前 1–7 天的预判。
4. **模型清单决策**：一个模型该不该上（可路由）＝ 有行情 ＋ 有渠道 ＋ 有折扣；市场价格在跌 ⇒ 别把新流量导过去；原厂在降价 ⇒ 等一等再谈。这直接喂给 `domains/freediscovery` 与 `routing_policy.featured_models`。
5. **「市场最优价保证」的营销机制**：若我方报价高于市场公开最低价，平台自动下调报价 ⇒ 行情系统从「成本工具」升级为「营销武器」。⚠ 需要先做 §9 的对等条款与人工闸门（§7 第 5 条）。
6. **财务三方对账**：`maas/reconcile.go:23` `ReconcileTripartite` 已有三方对账骨架（A 消费桶 / B 月度账单 / C 积分流水）⇒ 可扩成四方（加「供应商实付」与「市场参考」）。
7. **路由的成本置信度护栏**（§2.2）：让「没填价」的绑定不再被 autoroute 当成「最便宜」。
8. **多目标路由的第五目标**：现有 `routingopt/recommender.go:172-199` 是 质量0.4/成本0.3/延迟0.2/可用性0.1 ⇒ 可加「客户侧成本」（我们给客户的价 × 用量），用于「内部省成本 vs 让客户便宜」的显式策略选择。
9. **报价单自动失效**：行情变 ⇒ 报价单里的成本行过期 ⇒ `quote_item` 加 `cost_ref_run_date`，过期即提示重算（避免用旧成本报新价）。
10. **模型降价传导 SLA**：市场降价 → 我方零售价下调的时延承诺（如 7 天内跟进）⇒ 可对外承诺，量化内部执行力。

## 9. 风险、边界与「明确不做的事」

### 9.1 数据风险

| 风险 | 现状 | 对策 |
|---|---|---|
| **市场价是「观测」不是「现状」** | `price_observation` 每日累积、历史不删（设计如此） | 参考价必须带 `source_run_date`；超过 N 天降级为「陈旧」；评分里陈旧价不参与路由 |
| **市场最低价是单点来源** | §2.5 实测：4 个模型各只有 1 个平台 | `market_min_platform_count` 硬指标（≥3），否则 C2 降级 |
| **两仓命名不一致** | 归一后交集 29.7%（全量）/ 88.9%（有价） | 先跑有价那批；脏变体走 `model_alias`，**不做一次性全量清洗** |
| **行情层自身有脏行** | `salesdecorate` 归一后 165 处自撞；已有 `claude-opus-5-/-claude-opus-4.8` 这类合并行，**且已污染供给卡** | 同步器侧也执行「整组 withhold」；★ 并把 §2.3 的 `SC-…-007` 作为**已发生的真实污染案例**登记 |
| **FX 漂移** | 记账 7.2（`CNYToUSDFX`），路由 `CNYScoreFX()` 进程启动冻结 | 参考价落库时**同时存原币与 CNY 与 fx_rate**；评分时用落库快照的 fx_rate，不依赖运行时汇率 |

### 9.2 治理风险

- **本方案要推翻/澄清一条既有裁决**（§10.1）。按本仓惯例，这类事**必须显式记录**，不能默默做（`bg/baseline_price_not_in_billing_test.go` 的存在本身就是这个惯例的证据）。
- **不让营销的手工价改路由**（§1 边界原则）。这是本方案最容易被好心破坏的一条。

### 9.3 工程风险

- **派生台账必须按「提交树」生成**（既有教训：按共享工作树生成的行号类产物在自己的提交树里对不上 ⇒ 提交后门必红，且极难归因）。
- **派生产物一律从 SSOT 重新生成，不手改产物**（既有纪律）。本方案新增的 3 张表与 1 个同步器都属于此类。
- **门要有牙**：每个新门都要做**变异臂**（CONTROL 绿 / 变异体红 / 还原 md5 逐字一致），否则「门绿」只说明门没跑到。

### 9.4 明确不做（避免范围蔓延）

- ❌ **不做**「自动改价」：任何自动把市场价写进零售价/报价单的机制，都必须先有人工闸门。
- ❌ **不做**「用市场最低价直接当路由权重」：见 §4.3，方向与分母都错。
- ❌ **不做**一次性全量模型目录清洗：先跑有价那批。
- ❌ **不做**把 `models_canonical.input_price_cny`（历史 CNY 展示列）复活成核算口径：826 已明令不可与 USD 混用。
- ❌ **不做**复活 `domains/approval/cost_estimator.go` 那张写死的价格表：它生产未接线，是陷阱。
