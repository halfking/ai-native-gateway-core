## 三、问题详细分析

### 问题1: JSON解析失败 ★已修复

**严重性**: P0 - 高  
**频率**: 12次  
**状态**: ✅ 已修复

#### 根因
- **位置**: `internal/ir/stream.go:264`
- **错误**: `cannot unmarshal number into Go struct field .error.code of type string`
- **原因**: 错误结构体的 `Code` 字段定义为 `string` 类型，但上游返回的错误响应中 `code` 是数字 `400`

#### 实际错误响应
```json
{"error":{"message":"Invalid request","type":"invalid_request_error","code":400}}
```

#### 影响
- 12次请求的错误响应无法正确解析
- 客户端无法获得详细的错误信息
- 日志中出现大量解析失败警告

#### 修复方案
创建 `FlexibleString` 类型，可以同时接受字符串和数字：

```go
// FlexibleString 是一个可以接受字符串或数字的类型，用于处理不同供应商返回的
// error.code 字段类型不一致的问题。某些供应商返回数字（如 400），某些返回字符串。
type FlexibleString string

func (fs *FlexibleString) UnmarshalJSON(data []byte) error {
	// 尝试解析为字符串
	var s string
	if err := json.Unmarshal(data, &s); err == nil {
		*fs = FlexibleString(s)
		return nil
	}
	
	// 尝试解析为数字
	var n json.Number
	if err := json.Unmarshal(data, &n); err == nil {
		*fs = FlexibleString(n.String())
		return nil
	}
	
	// 其他数值类型的兜底处理
	...
}
```

#### 验证结果
- ✅ 编译通过
- ✅ 所有existing测试通过（internal/ir包）
- ✅ 修复验证：旧实现失败，新实现成功解析 `code:400`
- ✅ 兼容性：仍然支持字符串类型的code
