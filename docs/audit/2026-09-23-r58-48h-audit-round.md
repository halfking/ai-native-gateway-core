## 一、chunk_buffer 三验证 → 裁决不接线，删除（Handoff-B 批次 2 收口）

三验证（handoff 硬约束：验证先行裁决接入形态）**全部不通过**：

1. **s8_burst 主张证伪**。模块头自述"s8_burst_stress 2000 reqs @ c50 无缓冲
   封顶 ~600 req/s（4 核），需缓冲达 ≥900"——但 (a) `tests/stress/scripts/
   scenarios.json` 的 s8_burst_stress 是 **`"stream": false`**，非流式压测根本
   不经过 SSE Flush 热路径，基准锚点张冠李戴；(b) 本仓最新实跑
   （tests/stress/results/report.json，2026-09-23T00:30）**871 req/s、100%
   成功、p95 TTFB 107ms，未接线缓冲**，"~600 封顶"被直接否证（疑似走样自
   CAPACITY_HANDOVER.md GOMAXPROCS=4 行的 673.9 rps——mock loopback 非流式）；
   (c) 头注释"Production tests (2026-08-29)"无出处。CAPACITY_HANDOVER.md 自
   述 Handoff-B 七项"都没有接到生产 cmd/gateway"、数字是未验证折算。
2. **TTFT 主张与实现不符**。idle-flush 是惰性检查（只在下一次 Write 时判
   `time.Since(lastFlushAt) > 50ms`），**无后台定时器**；首块写入后若无后续
   写入，字节滞留至下一写入/显式 Flush/Close——"50ms 存活上限"实为"下一次
   写入前的无界延迟"（chunk_buffer_test.go 的 TestChunkBuffer_IdleFlushFires
   注释自证）。补定时器需破坏"struct 单 goroutine 持有、非线程安全"不变量。
3. **终端帧及时性接线上价过高**。现行 40 处语义 Flush 配对（stream.go:740
   per-chunk 配对、stream.go:871/1158/1231 终端帧配对、anthropic_stream 16
   处、responses_stream 5 处）承载 R27/R28/§11.6 契约；接线必须拆除 per-chunk
   配对，且与两个机制互斥——ConnectionMonitor（interval 1s/idleTimeout 10s，
   靠 socket 级 Write/Flush 触发 Touch()，缓冲吞写→假性失活断流）、
   AttemptCommitGate 帧级 commit/discard 分类（"每次 Write=完整帧"前提，
   8KiB 高水位会切开帧中间）。

**处置**：接入形态不存在（前提证伪 + 组件自身语义缺陷），删除
`domains/streaming/executors/chunk_buffer.go` + 测试（符号零外部引用实锤；
git 历史可找回）。
