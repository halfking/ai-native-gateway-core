## 一、发现与处置（3 项全部收口）

### R53-F1（P1，R51-F15 顺延）reqprobe/ctxLen 免费重试计入 Governor 计量

- **问题**：reqprobe 参数剔除/模式回退两次免费重试（`probeRetry` 抵消 attempt++ 且跳过退避）与 ctxLen 恢复重试（`ctxLenRecoveryRetry` 同机制）在凭据 attempt 内自旋，不重新过 dispatch Governor Acquire——一次准入最多 4 次上游 HTTP 调用（首发+剔除+回退+压缩重发），RPM/TPM 桶按 1 次计入，限流计量失真、雪崩防护预算被绕过（R52 D04 报告实证计数）。
- **裁决**：不采纳「免费重试消耗 retry budget」方向——probe 重试是确定性修正，消耗预算会让 maxRetries=0 的 dispatch 流量直接 failover、reqprobe 学习闭环永不触发，属语义回归。采「按次补记 Governor 用量」：计量归计量、准入归准入。
- **修复**（四层接线 + 闭集豁免）：
  1. `domains/dispatch/governor.go` 新增可选能力接口 `ExtraCallRecorder`（`RecordExtraCall`）：rpm/tpm governor 实现为**债务式扣减**（tokens 直落负值、钳在 `-limit`）——确定性修正不被 pace，但超额让下一次准入按补充时长等价等待；concurrency governor **刻意不实现**（其 in-flight 槽位全程持到准入结束，重试已被覆盖）。
  2. `forwarder.go acquire()` 准入成功后经 `extraCallMeterFor(gov, qr)`（能力断言，无能力者 nil）装配 `qr.OnExtraUpstreamCall`——捕获的是**本次准入的 governor 实例**（ApplyPolicy 换装不影响在途请求，与既有注释语义一致）。
  3. `ExecParams.ExtraUpstreamCall` 由 `forwardForDispatch` 从 qr 透传；legacy（非 dispatch）路径无准入无 meter，nil 安全。
  4. 四个触发点补记：executor_chat 模式回退 / 参数剔除 / ctxLen 恢复，executor_anthropic ctxLen 恢复（`meterExtraUpstreamCall` nil-safe helper）。
  5. 可观测：`dispatch_extra_upstream_calls_total{mode}`（rpm/tpm 闭集标签）。
- **钉桩**：governor 层 4 测（rpm 补记后 Acquire 实际等待 / 双 governor 债务钳制 / concurrency·noop 无能力 / meter 工厂发现）；executor 环级 2 测（参数剔除与 ctxLen 恢复各 meter 恰 1 次且免费语义不变——成功路径上游调用数不变）。
- **已知边界**：Redis enforce backend 的分布式 governor 未实现该能力（需要新 Lua 计费脚本，本轮不做）——能力断言 miss → meter nil → 计量缺口维持现状，登记 §遗留。

### R53-F2（P1，R51-F13 顺延）BaseWorker 自愈重构：panic 后退避重启 + restarts 指标

- **问题**：BaseWorker 的 recover 只兜住进程崩溃（2026-09-09 引入），worker goroutine 随后永久退出——单次 panic（坏 JSON、下标越界）即该 worker 静默停摆到进程重启，约 20+ 嵌入 worker 全部暴露于此面。
- **修复**（`bg/base_worker.go` 重构为监督循环）：
  1. `supervise`：`runOnce`（recover → panicked 布尔）+ panic 后指数退避（1s、2s、4s…封顶 60s，移位溢出为负时同样取封顶）后**同一 ctx 重启**；runFn **正常 return 视为有意退出**，监督循环随之终止不重启。
  2. **done 语义收敛**：done 恰在监督循环退出点 close 一次（`closeDone` 幂等）；`NotifyStopped` 转兼容 no-op——原契约下 runFn panic 路径先 close done 会导致 Stop 提前返回 + 监督循环二次 close panic，必须收权。既有 runFn 的 `defer NotifyStopped()` 全部继续编译、语义审查通过。
  3. 退避睡眠期间 Stop 立即解阻塞（select ctx.Done）。
  4. 可观测：`Restarts()` 访问器 + `llm_gateway_bg_worker_restarts_total{worker}`（worker 名为编译期字面量闭集 ~25 值，低基数）。某 worker 该指标持续增长 = 反复 panic 需要真修，不是退避能兜的。
- **钉桩**：×3（两次 panic 后第三次健康长跑，Restarts()==2 / 正常 return 不重启且 done 已闭 / 退避睡眠中 Stop 一秒内返回）；既有 8 测（含并发 Start/Stop 50 goroutine race）全绿，R52 worker panic 族测试（per-worker `...Recovered` 包装层）不受影响。
