# 100MB会话接入与桶预算实施验证

日期：2026-11-09（Asia/Shanghai）。实施基线0863c20c9；对应[已确认方案](../design/2026-11-09-large-request-session-budget-feasibility.md)。本轮为代码实施、本地测试、修正和提交推送，不包含生产部署。原始资料和测试均为合成数据，没有向真实供应商发送客户会话。

## 1. 已实现的运行链

```text
可信请求头鉴权 / 租户核验 / 预处理并发与磁盘余量准入
  → 100000000 bytes 实际读取硬限 / 本地不可覆盖RAW和ref.json
  → 有界JSON索引 / 巨型字符串流式摘录 / 保护任务及工具依赖
  → 原有可逆脱敏 / 多层缓存 / 压缩
  → 每次具体桶最终协议适配 / 有界Fit / 输入与字节校验
  → 供应商（重试、换桶、摘要和续问均覆盖）
  → 客户端响应按实际写出字节流式归档
```

生产main默认装配新入口在V2 dispatch和streamretry之外，防止它们先读取RAW。原始请求留在文件中；业务处理、队列、日志正文和重试快照只持有≤1MiB工作集及归档引用。预处理完成即释放4并发配额，不占用整个SSE生命周期；LLM执行继续使用既有Governor/队列限额。

预算取`min(500000, floor(窗口×0.5), 可选输入上限, 窗口−输出/思考预留−安全余量)`；另设8MiB最终JSON资源策略。500K是tokens，不是500KB。目录未知窗口拒绝；上游明确报出更小窗口后，在当前请求/当前桶内立即取更小值，不能把该窗口带到其它桶。新模式不把容量不匹配记成节点健康失败，允许换桶，最终不能满足时HTTP422；已发200的SSE使用协议终态错误。

当前没有模型专用精确tokenizer，采用**完整JSON的UTF8字节＋结构/framing余量保守上界**。它会比真实tokenizer更早压缩或拒绝，不能称为精确token数。媒体、隐式远端历史、encrypted_content等没有可信外部token上界时拒绝；不能通过删掉未计数历史媒体绕过检查。Counter接口保留供后续适配已验证模型。

## 2. 文件、上下文与缓存

- RAW与ref.json：0700目录、0600文件，64KiB复制缓冲，校验长度/SHA256，原子不可覆盖提交。每请求独立记录，避免同会话并发覆写；不属于可淘汰HotZone缓存。
- 会话归属：沿用body优先于header的sessionid.Resolve。归档先使用服务器随机staging会话，校验最终会话的key/tenant并原子认领后，才经不可覆盖Rebind提交；403/503保留临时可恢复记录。无所有权服务时改用新系统ID，不能直接信任客户端目录。多个同优先级ID别名在一次校验后固定，正文与header同步；保留recent-session复用。
- 归档目录：`LLM_GATEWAY_SESSION_RAW_DIR`；缺省为日志文件同级的`session-archive`，未配置日志文件时为`data/session-archive`。运行环境须给该目录持久卷。第一版保证同宿主目录重开恢复，不保证跨主机复制。
- 大对象：词法扫描不物化巨大字符串；按JSON原始字节range读取。256KiB小体缓冲、≤1MiB工作集；单条最新任务/必要工具参数无法放入时拒绝，不能静默截断。
- 摘录前安全：完整源消息进行有界流式JSON解码并扫描当前租户的固定规则版本。可遮蔽的旧消息整条省略并记录`sensitive_history_omitted`，block仍拒绝403；保留JSON字段语境，私有guard规则的首尾锚点扩大为保守超集。规则源64KiB容量、最多8份编译缓存；普通文本与嵌套转义展开两份完整视图均检查，防止裁剪丢失PEM/口令识别边界。工具限定在此门中保守放宽，因此可能多省略历史。AST推导必要字面量，以固定32KiB缓冲和128B重叠做保守预筛；只有完整流无必要字面量时才跳过原正则，未知语法仍运行原正则，Unicode SimpleFold包含ſ/K等完整变体。
- 上下文：保护system/developer、最初任务、最新人类任务和按ID闭包保留的活动工具链；旧历史使用关键词命中窗口、头尾摘录与已有压缩链。中文bigram、Unicode转义及代码/路径/数字覆盖于质量样本。摘录是有损处理，不声明任意100MB都能无损处理。
- 响应：io.Pipe施加磁盘背压，不排队完整响应；保留Flush及FlushError。`<request_id>-response`是客户端响应的可恢复记录，归档引用进入小型compression_meta，原文和本地绝对路径不进入数据库元数据。
- 冷缓存：严格ctx下Redis先Lua检查长度再取固定字段，禁止HGETALL先取后验；memo先STRLEN再GET；本地旧快照先打开inode做Stat再LimitReader；SQL先选最新行，再CASE限制逻辑正文；历史链SQL先LIMIT并累计≤1MiB。超限不能退回旧无界分支。
- 元数据：深拷贝前检查总容量；巨型消息元数据共享256KiB结构与标量预算、请求链接元数据≤1MiB；修复已有L1条目更新绕过总字节淘汰的问题。

RAW当前按原始业务字节保存，**未新增压缩帧或静态加密**。仓内原有gzip/zstd会话存储仍兼容；本次不把它们当作100MB事实源的随机访问实现。磁盘512MiB安全余量外，还预留一个最大请求；容量不足503，不回退RAW常驻内存。不自动删除RAW；保留期/租户配额需由运行维护策略管理。

## 5. 实跑发现并修复

1. Anthropic工具结果和Responses无role工具输出可能留下结果而删掉调用：改为按工具ID闭包，并独立保护最新人类任务。
2. 字符串分片取消检查按按位整除会长时间不触发：改为每个有界块检查。
3. 无换行长文本命中关键词却取到行首：改为命中位置附近窗口；增加中文关键词片段。
4. 元数据只限制标量、空对象树可绕过：递归构造前扣结构预算，并限制请求级链接元数据。
5. 4xx恢复后仍按旧目录窗口验算：新增请求内、桶内发现窗口状态。
6. Messages/Responses独立分支把预算错误当供应商503：统一typed422及协议SSE终态。
7. 正文session优先级与归档目录不一致：同源Resolve＋安全Rebind。
8. 外层writer不透传读期限：Logging/Prometheus补Unwrap，取消时关闭不支持期限的reader。
9. 响应归档writer吞Flush错误：透传FlushError，保持已有断连识别。
10. 旧缓存先整包取回再检查：Redis/文件/SQL/L1深拷贝全部增加取前门；L1更新也执行总量淘汰。
11. 入口提前拒绝绕过业务失败记录：新增无正文读取的初始事实与终态记录。
12. 私钥/跨行口令的中部摘录失去脱敏边界：增加完整源安全筛选，命中整条旧历史省略；补齐真实托管规则基线，修复字段通配规则误删所有安全事实和叶首尾锚点漏检。
13. 归档先于session owner校验：改为服务器staging，认领/校验成功后再Rebind；补无authority随机ID和同优先级别名固定。
14. 安全筛选全量正则过慢导致100MB四并发超时：增加可证明保守的AST必要字面量预筛、Unicode折叠与跨块负控，并分别报告修前失败/修后资源矩阵；处理超时改为503。
15. 全仓结构门误认JSON返回字节丢弃和reflect.MapIter为SQL游标：实现改为检查期望字节、校验随机ID长度和Go map Seq2遍历，没有放宽门禁或登记豁免。
