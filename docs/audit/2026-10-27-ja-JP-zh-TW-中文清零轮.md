## 3. 本轮新发现的盲区（都已固化成门或登记）

### 3.1 ★★★ 「工单口径 = 同键路径逐字相同」会把「值放错键位置」的键**整体漏掉**

- 工单生成口径：`引用集 ∩ (值 === zh-CN 同键路径的值) ∩ (源值含汉字)`。
- `freePool.signup` 在 zh-TW 里装的是 `acquisition.signup` 的值 ⇒ **与 zh-CN 同键路径的值不同** ⇒ 不满足「逐字相同」⇒ **结构上进不了工单**。
- 而它又是**用户可见**的简体中文 ⇒ 两个 worker 都不可能修它。
- ⇒ **通用式：「与源语言逐字相同」是「没翻」的判据；「值放错了位置」会伪装成「已经翻过了」。**
  ⇒ 判「没翻」不能只看值，还要看**同键路径上其它语种是不是都有本地化文本**。

### 3.2 ★★★ CJK 原生语种被两个指标**双重豁免**

- `cjkInNonCjkLocaleAllKeys` 把 ja-JP / zh-TW 整体豁免（`CJK_NATIVE_LOCALES`，理由是「日文/繁中用汉字是正常的」）。
- `sameAsSource` 只判「与 zh-CN 逐字相同」⇒ **部分**残留（值已改过、但还留着简体字）两条都看不见。
- ⇒ 新门 `i18n-cjk-native-simplified-guard.mjs` 专治这个盲区（详见 §4）。

### 3.3 ★★ 量具事故：**CJK 字面量区间写歪一个码位 ⇒ 区间跨过代理对区 ⇒ emoji / 韩文全被误判成汉字**

- 我在临时脚本里写 `/[㐀-䶿一-鿿豈-﫿]/`，其中 `豈` 的真实码位是 **U+8C48**（本意 U+F900）⇒ 区间变成 **U+8C48–U+FAFF**。
- 而 **U+D83D（高代理）= 55357 落在 35912–64255 之间** ⇒ 非 `u` 模式下**所有 emoji 代理对**、乃至韩文 U+C740 全部被误判成「汉字」。
- ⇒ 结论：**CJK 字符类必须用转义写法**（仓内权威写法见 `web/src/i18n/localeValueQuality.ts:89`：`/[\u4e00-\u9fff\u3400-\u4dbf]/`），并在门里自带 17 例自检（emoji / 韩文 / 假名 / ASCII 全部不得命中）。
- ⇒ 新门的 S17 就是这条的常驻守卫。

### 3.4 ★★ A/B 装置事故：**vite 端口被占 ⇒ 静默换端口 ⇒ 探针打在旧 server 上**

- 现象：工作区侧 10 个路由 `scanned` **恒为 50**、`textLen` 恒为 125；HEAD 侧 74~3708。
- 第一直觉「我的改动把路由打挂了」⇒ 被 `pnpm run build`（✓ 通过）证伪 ⇒ **先判量具、再判数据**。
- 真因：我的 `pkill -f "vite --port 578"` **没杀掉旧进程**（命令行实际是 `node ./node_modules/.bin/../vite/bin/vite.js`，pattern 没匹配上）⇒ 新 server 启动时打印 `Port 5780 is in use, trying another one... → Local: http://127.0.0.1:5782/`，**探针仍在打旧 server**；旧 server 的 `node_modules/.vite` 依赖预打包缓存**被 worktree 那份覆盖**（worktree 的 `node_modules` 是符号链接 ⇒ 共享同一份缓存）⇒ chunk hash 对不上 ⇒ 路由懒加载 404 ⇒ 只剩外壳。
- 处置：① 按 **PID** 精确 kill（`ps -eo pid,command | grep "[v]ite"`）；② `--strictPort` 让端口被占就**直接报错退出**而不是静默换端口；③ worktree 用独立 `cacheDir`（`/tmp/headwt/web/vite.ab.config.ts`）隔离依赖缓存。
- ⚠ 另一个坑：仓内 `official-portal` 有一个 vite preview 占 8083 ⇒ **不属于本轮，一律不动**。

### 3.5 ★ worker 把**输入工单覆盖成了自己的「保留清单」**

- 两个 worker 都把 `/tmp/worklist_{ja-JP,zh-TW}.json` 改写成了自己的保留清单（108 / 585 条，正好等于它们各自报的保留数）⇒ **原始范围定义被销毁**。
- 处置：从 **HEAD** 重建（`/tmp/mk_worklist_head.mjs`）⇒ 796 / 1225，与初版条数逐条吻合 ⇒ 才得以对拍「有没有漏做」。

## 4. 新门 `i18n-cjk-native-simplified-guard.mjs`

```
node scripts/i18n-cjk-native-simplified-guard.mjs              # 对比 baseline，超限则 exit 1
node scripts/i18n-cjk-native-simplified-guard.mjs --json       # 输出 JSON
node scripts/i18n-cjk-native-simplified-guard.mjs --selftest   # 自证（20 例）
node scripts/i18n-cjk-native-simplified-guard.mjs --update-baseline
node scripts/gen-cjk-native-simplified-chars.mjs               # 重生成字表（需 iconv）
```

### 4.1 判据

- **简体专用字 ≈ 「Big5 转不出来的汉字」**（繁体有、简体/日文新字体形没有）。
  ★ 仓内**没有任何** S/T 转换依赖（本机也没有 opencc / opencc-js）⇒ 用 Big5 当判据。
  ★ Big5 对 **zh-TW** 是精确的；对 **ja-JP** 会连**合法日文新字体**（実/処/録/続/検/総…）一起命中 ⇒ 再减去 `japaneseOk` 子集。
- **字表是入仓的数据资产**（`scripts/data/cjk-native-simplified-chars.json`，`notBig5` 453 字 + `japaneseOk` 110 字）
  ⇒ **门本身不依赖 iconv** ⇒ Windows / CI 都能跑。
- **ja-JP 的豁免表是自推导的**：`japaneseOk` = `notBig5` 中在 ja-JP「已本地化值（值 ≠ zh-CN 同键路径的值）」里出现过的字。
  ⇒ **自我修正**：将来真译出 時点（点 既是简体「點」的简形、也是日文常用字），点会自动进豁免表。
  ⇒ **保守方向**：宁可漏报不误报。
- ★★★ **★ 但这个「自推导」有个致命反例：本轮实测它把自己的缺陷洗白了。**
  「授权 / 联系 / 请求 / 一键 / 运维平台 / 编排」这些**漏进 ja-JP 的简体片段**，正好因为「出现在已翻译值里」而被豁免
  ⇒ **门永远看不见它们** ⇒ ★ **第一版豁免表（110 字）⇒ 门报「用户可见残留 0」是假的。**
  ⇒ 修法：**豁免表 = （已本地化值里出现过的字）**减去**一份人工审定的「这些不是日文正字」清单**
  （`权维编联请键运` —— 日文对应形是 `権/維/編/連/請/鍵/運`，本表里已有）⇒ 豁免表 110 → **103**。
  ⇒ ★ **⇒ 通用式：★ 「豁免表」若由「数据本身」推导 ⇒ 它会把该数据里的缺陷一并豁免 ⇒ 豁免表必须有【人工审定的负名单】。**

### 4.2 两个指标

| 指标 | 含义 | 判据 | 当前值 |
|---|---|---|---|
| `referenced` | **被源码引用 ⇒ 用户可见** | **硬闸 0** | ja-JP **0** / zh-TW **0** |
| `unreferenced` | 未被引用 ⇒ 潜伏 | **棘轮**（只许降不许升） | ja-JP **337** / zh-TW 320 |

⚠ **ja-JP 的未引用基线由 328 调高到 337**（**人工显式**改 JSON，理由写在 baseline 的 `baselineRaiseReason` 里）：
这是**检测器变准**，不是残留变多 —— 豁免表剔掉 7 个「错洗白」的简体字 ⇒ +12；再修掉 3 处「本地化值里的简体片段」⇒ −3 ⇒ 328 + 12 − 3 = **337**。

未引用残留的归属：大部分是「**所有语种共有但 0 引用的叶子键**」（§412 登记的 3716 个那一族）⇒ 属产品词汇取舍，**待裁决**，本轮不动。

### 4.3 自证与变异台

- **自证 20/20 通过**（`--selftest`）：含 ① 简体→抓到 ② 繁体→不抓 ③ 合法日文新字体→不抓 ④ emoji/韩文/假名/ASCII→不抓 ⑤ 占位符不影响判定 ⑥ referenced/unreferenced 分流 ⑦ 字表结构合法 ⑧ **真实字表**跑本轮修掉的 `注册 Key` ⇒ 抓到「册」 ⑨ 真实字表跑 `実装` ⇒ 不抓。
  ★ 自证抓到过**我自己夹具写错**（期望值把 `这` 写进了一句里没有的字；把 `注` 当成简体专用字——实际 `注` 在 Big5 里也有，是繁简共用字）⇒ 修正为「只抓 `册`」。
- **变异台 3 臂全绿**（每臂跑完从备份还原并 **md5 逐字节校验**）：

| 臂 | 注入 | 期望 | 实测 |
|---|---|---|---|
| M1 | ja-JP **被引用**值改成简体 | 红（硬闸） | `referenced 0 → 1`，exit=1 ✅ |
| M2 | zh-TW **未引用**值改成简体 | 红（棘轮） | `unreferenced 320 → 321`，exit=1 ✅ |
| M3 | ja-JP 被引用值改成合法日文新字体 | 绿（不误报） | exit=0 ✅ |
