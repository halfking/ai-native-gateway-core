# 插件式架构与微前端实现审计与规划（2026-11-25 审计轮）

> 范围：`plugin-runtime/`（Go 侧插件运行时）＋ `web/src/lib/shell/hyper/`（前端微壳）
> ＋ `plugin-runtime/nav_api.go`（动态菜单注入）。本文是对**现有代码**的总结与
> 差距规划，不是新设计。

## 一、现状总结（对照代码，逐条可核）

### 1. 后端插件运行时（plugin-runtime/，~9,800 行主包 + 4 个子包）

**manifest 体系（manifest.go / types.go / manifest_verify.go）**
- manifest v1/v2/v3 三级契约：`schema_version` 3 起走严格解码
  （`DisallowUnknownFields` ⇒ 未知字段当场报错，防止「配了却静默丢失」，
  `manifest.go:23`）；v2 强制 SemVer + `gateway-plugin-v2` 契约。
- Ed25519 签名验证（`manifest_verify.go`），`plugins.yml` 批量登记
  （`plugins_yml.go`）。
- 夹具即门：`testdata/manifest-v3-example.json` 被 Go 测试
  （`TestManifestV3ExampleFixtureIsLoadable`）与前端跨语言契约门
  （`web/src/lib/shell/hyper/gates.spec.ts`）**两侧共同消费** ——
  夹具漂移任何一侧先红。本轮已把其 `label_key` 修正到 `nav.*` 命名空间。

**安全三件套（capability.go / sandbox.go / boundary_test.go）**
- capability 注册表 + 三入口鉴权（ADR `2026-09-04-plugin-runtime-v2`）：
  `Required(method, path)` 路由表把每个 canonical 端点映射到能力位，
  插件越权访问当场拒绝（fail closed）。
- nav 校验（`nav_validate.go`）：页面路径受控词表（禁 `..`/前导 `/`），
  label_key 必须点分 i18n 键、order 有界 ±10000、页数 ≤64 ——
  防菜单注入与排序操纵。
- 目录边界断言（`boundary_test.go`）+ sandbox policy
  （`sandbox_policy.go`）。

**生命周期（supervisor/ controller/ reconciler/）**
- Supervisor：安装 staging + 原子切 current（installer.go），
  Upgrade 失败自动回滚 + Uninstall 内存清理。
- controller/：进程级管控（proc_unix / proc_windows 双平台）、
  health 心跳、reconciler 预算（reconciler_budget.go）。
- reconciler/：状态机 552 行，收敛插件期望态与实际态。

**通信（ipc/ handshake.go apiproxy.go proxy.go）**
- unix-socket HTTP 协议 + HMAC 双向认证 + nonce 防重放
  （nonce_cache.go）+ context_token 会话令牌。
- apiproxy：body 代理路径（受 capability 门约束）。

**数据面（db_registry.go + DB_REGISTRY_README.md）**
- 插件 DB 访问注册表：不是「给插件一个 DSN」而是登记式受控访问。

### 2. 前端微壳（web/src/lib/shell/hyper/，~2,000 行）

- **门面装配顺序固定**（index.ts）：`capabilities → scope → 恢复历史 →
  路由适配器 → 返回端口 → 全局键盘`；**任一步失败降级不抛错**
  （「Hyper 是增强层，挂掉不能让控制台打不开」）。
- 动态菜单注入：`GET /api/v1/plugin-nav`（nav_api.go）→
  `usePluginNav` → `mergeRemotePluginNav` 落进匹配的静态分组
  （找不到匹配则合成 `plugins` 组）；插件**不能**挤掉运维导航
  （merge 步骤在 opsPlatform override 之后）。
- 菜单可见性三把尺统一走 `canShowNavItem`：角色（super/platformOps/
  providerConsole/tenantOnly/hideForTenant）＋ 路径级隐藏清单
  （navHidden.ts，本轮 `/live2` 挂入）＋ 探测型闸门（opsPlatform/
  piAnalysis）。

### 3. 插件菜单的跨语言契约（本轮收口）

`gates.spec.ts` 的「manifest label_key → 8 locale」门覆盖了
Go 校验（形状）与前端 t()（存在性）之间没人管的那一环：
插件作者改 key 名，任何一侧都不会红 —— 只有这道中间门抓。
真源是 **manifest JSON 本身**（不是 Go 字面量，避免把单测脚手架
`nav.plugin.title` 之类的假键吸进来造成永久红）。

## 二、差距与规划（按优先级）

### P1（建议下一轮做）

1. **v3 严格解码的回滚面**：schema_version 3 的
   `DisallowUnknownFields` 对**存量 v2 插件**是破坏性变更
   （v2 manifest 里多带一个字段即拒载）。规划：加载失败时回读
   schema_version 并区分「未知字段」与「契约不匹配」两类错误文案，
   给运维一个可行动的迁移提示（`manifest.go` 已有基础，缺 UI 呈现）。
2. **插件 settings 写通道审计**：`settings_api.go` 存在但缺
   「插件只能写自己 namespace」的门（对照 capability 三入口的
   既有纪律）。加一道 registry 门：写键必须以 `plugin.<id>.` 开头。

### P2（登记待做）

3. **hyper 壳的降级可观测性**：index.ts 的「任一步失败降级」目前
   只在不抛错层面保证，缺一个 `hyper.degraded(reason)` 上报点
   （接入 telemetry），否则壳静默降级成裸 Vue 应用时无迹可查。
4. **iframe 微前端与超壳导航协议**：`PluginMount.vue` 与 hyper 的
   back/title 端口尚未打通（插件页内返回不会联动壳的历史栈）。
   规划：postMessage 协议 v1（`hyper:navigate-back` / `hyper:set-title`），
   由 capabilities.ts 统一分发。

### P3（远期）

5. **插件热升级的会话排空**：Supervisor.Upgrade 目前直接换进程，
   在途请求由 HTTP 层超时兜底。规划：升级前向插件发
   `on_deactivate`（已声明但未实现调用），给一个 drain 窗口。
6. **plugin-runtime/config 独立 go.mod 的版本对拍**：子模块
   （config/ ipc/）与主模块共享 types 时靠复制，缺一处
   「契约类型一致性」对拍门（可行做法：小夹具两侧编译）。
