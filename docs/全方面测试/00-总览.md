# 00 - 全方面测试总览

> 这个文档是 **2026-07-12 incident response** 之后整合的版本。
> 所有可执行工具都已落在 `tools/`，场景在 `scenarios/`。

## 测试目标（与 03-测试场景定义.md 一致，简版）

1. 验证 Gateway 在高并发下的路由、故障转移、熔断恢复能力
2. 覆盖 15+ 种故障模式
3. 验证多维度路由决策：成本、延迟、并发、指纹 Slot、健康状态
4. 验证 TokenPlan/CodePlan 配额耗尽自动切换
5. 验证 Sticky Session
6. **验证无可用节点时的错误处理 (S13)**
7. **验证模型不存在时的快速失败 (S14)**
8. **验证跨组故障迁移能力 (S15)**
9. **验证充值后快速恢复 < 5 秒 (S16)**

## 数据流

1. `data/seed.sql` 把 60 个 provider + 120 个 credential + 15 个 model 注入测试 DB（id 9010-9099）
2. `tools/start_suppliers.sh` 启动 60 个 `mock_supplier.py` 进程
3. `mock_orchestrator.py` 通过 HTTP `/admin/state` 控制每个 mock 状态
4. `loadtest.py` 是 N-client 持续并发客户端；调用 gateway
5. 结果 JSON 写到 `results/S{XX}.json`
6. `tools/validation_report.py` 聚合成 Markdown 报告

## 模块旁路（kill-switch）

2026-07-12 incident response 中新增 —— 通过环境变量旁路 3 个高风险模块（详细在 08-kill-switch.md）：

| 开关 | 关闭模块 | 位置 |
|---|---|---|
| `KILL_SESSION_COMPRESSION=1` | compression hook | `settings/feature_switches.go` |
| `KILL_SESSION_CACHE=1` | session_cache (L1+L2+L3) | `domains/hooks/compression/session_cache.go` |
| `KILL_CIRCUIT_DEGRADATION=1` | circuit breaker | `domains/streaming/executors/executor.go` |
| `KILL_FP_SLOT=1` | fingerprint prefilter | 同上 |
| `KILL_RATE_LIMITER=1` | RPM/TPM token bucket | ratelimit middleware |
