## 1. 三套脱敏体系对比

| 体系 | 目的 | 出处 | 去向 | 可逆性 | 核心函数 |
|---|---|---|---|---|---|
| `safety.ContentFilter` | 请求/响应内容安全检测 | request/response body | 拦截响应 / `"***"` 掩码 | **不可逆**（单向） | `CheckRequest` (L57) / `CheckResponse` (L85) / `check` (L96) / `sanitize` (L245) |
| `caveman` | 保护代码块/公式/结构不被压缩破坏 | 消息 content 字段 | body 中 placeholder | **可逆**（extract→restore 成对） | `extractPreservedBlocks` (L38) / `restorePreservedBlocks` (L146) |
| `secretmask` | 摘要输入脱敏（密钥不进 prompt） | 压缩前 conversation text | `[REDACTED]` | **不可逆**（单向） | `MaskSecrets` (L57) |

## 2. safety.ContentFilter 验证

### 2.1 数据流

```
CheckRequest(ctx, req)
    └─ check(content)                       # keyword + regex 并行
         ├─ hits = keywordMatcher + regexMatcher
         ├─ applyRulesWithRules(rules, content, hits)   # 决策
         │    ├─ Action=Block    → 拦截（终态）
         │    ├─ Action=Sanitize → sanitize(content, hits) → "***"（Medium 及以上）
         │    └─ Action=Allow    → 放行
         └─ CheckResult { Action, SanitizedContent, Hits }
```

### 2.2 内置规则（`safety/rules.go`）

| 规则 | 类型 | 命中动作 |
|---|---|---|
| OpenAI / Anthropic API Key | regex | Block |
| JWT / AWS / 私钥 | regex | Block |
| 身份证 / 手机号 | regex | Sanitize |
| 邮箱 | regex | Warn |
| SQL 注入 | regex | Block |
| 敏感词 | keyword | Block |

### 2.3 验证场景

| 场景 | 输入 | 断言 |
|---|---|---|
| S15A | content 含 `sk-...` | `Action=Block`，请求被拦截 |
| S15B | content 含手机号 | `Action=Sanitize`，`SanitizedContent` 含 `"***"` 且不含原号码 |
| S15E | response 含敏感段 | `CheckResponse` 返回 Block/Sanitize |

**可逆性边界断言**：`safety` 掩码是**单向**的，`"***"` 无法还原为原文。验证中明确断言「还原不可能」，而非试图还原。

## 3. caveman 可逆验证（压缩保护）

### 3.1 数据流

```
Compress(body)
    └─ 每条消息 compressTextPart()
         ├─ extractPreservedBlocks(text, opts)
         │    ├─ frontmatter → fenced code → 13 种保护模式 → 用户自定义
         │    └─ → (处理后文本, []PreservedBlock)   # placeholder=\u0000OMNI_CAVEMAN_r<hex>_<n>\u0000
         ├─（压缩/摘要处理处理后文本）
         └─ restorePreservedBlocks(处理后文本, blocks)   # 按序替换回原文
```

### 3.2 验证场景（S15C）——可逆性核心

```go
// 原样往返：extract → restore 必须得到原文
blocks := []PreservedBlock{...}
processed, blocks := extractPreservedBlocks(original, opts)
restored := restorePreservedBlocks(processed, blocks)
assertEqual(restored, original)   // 无损往返
```

覆盖的保护模式：
- fenced code block（``` go ... ```）
- math_inline / math_block（`$...$` / `$$...$$`）
- latex
- markdown 标题 / 表格
- typst
- inline_code / 链接 / URL
- 环境变量 / 版本号 / 函数调用 / 文件路径 / 错误信息

**关键验证点**：压缩/摘要作用在「处理后文本」上，placeholder 内容（`\u0000...`）**不参与压缩语义**，restore 后原文完整保留。

## 4. secretmask 验证（摘要输入脱敏）

### 4.1 数据流

```
conversation_text.go: extractConversationText(body, protocol)
    └─ MaskSecrets(conversation) → [REDACTED]
         └─ summarizer.Summarize(ctx, dim, maskedConversation)
```

### 4.2 验证场景（S15D）

```go
masked := MaskSecrets(conversationWithKeys)

```

**可逆性边界**：`secretmask` 是**单向**的，`[REDACTED]` 无法还原为原文。这是安全设计，验证中明确断言。

## 5. 脱敏可逆性矩阵

| 处理 | 还原方法 | 是否可还原 | 验证断言 |
|---|---|---|---|
| caveman placeholder | `restorePreservedBlocks` | **可还原** | restore 后 == 原文 |
| media prune（`[Earlier image/audio removed...]`） | 无（信息已丢） | 不可还原（业务预期） | 断言占位符存在 |
| lite 压缩（`[image: png]`） | 无 | 不可还原（占位符语义） | 断言占位符存在 |
| safety `"***"` | 无 | 不可还原（安全设计） | 断言不泄露原文 |
| secretmask `[REDACTED]` | 无 | 不可还原（安全设计） | 断言不泄露密钥 |

## 6. 已知边界

| 边界 | 说明 | 处理 |
|---|---|---|
| safety 是黑盒 | 掩码实现依赖命中位置 | 只断言 `"***"` 存在且原文消失 |
| caveman 自定义模式 | 用户可加自定义保护模式 | 测试覆盖内置 13 种 + 1 自定义 |
| 多模态 content 数组 | `RawContent`（未提交工作） | 本次用纯文本 content 验证 |
