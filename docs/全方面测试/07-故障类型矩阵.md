## 客户端视角的故障体验

```
client request
   │
   ▼
gateway (route → resolve candidate)
   │
   ├─ credential 1 → mock_supplier:19080 (A/0)
   │     ├─ state=healthy → 200 OK
   │     ├─ state=slow → 200 OK + 2-4s
   │     ├─ state=flaky → 30% 500/502/503
   │     ├─ state=server_error → 500
   │     ├─ state=auth → 401
   │     ├─ state=quota_429 → 429 (after quota exhausted)
   │     └─ state=broken_stream → 200 SSE + cut after 5 chunks
   │
   └─ gateway 收到 5xx/429/timeout → 候选链下一个
```

### 测试环境已知 schema drift

r112 测试栈的 PG 来自 252 生产同步，但 gateway 代码版本更新，存在以下漂移：

| 漂移项 | 日志模式 | 影响 | 状态 |
|---|---|---|---|
| `request_logs.trace_events` 列不存在 | `WARN trace.FlushToPG: UPDATE failed` | trace 事件不落库，不影响业务请求 | ⚠️ 需 migration |
| `credential_model_index.complexity_ceiling` 列不存在 | `WARN auto_route listener: refresh failed` | 内存索引刷新失败，fallback 到旧路由 | ⚠️ 需 migration |
| `task_default_routing` 表不存在 | `WARN default routing store reload failed` | per-tenant 路由默认值降级 | ⚠️ 需 migration |
| `routeincident` JSON insert | `WARN routeincident transition gave up` | probe 事件 JSON 格式匹配 `_notified_at` 旧 schema | ⚠️ 代码或 migration 修复 |
