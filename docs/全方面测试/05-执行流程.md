### ⚠️ Shell 兼容：必须用 bash 显式调用

`scenarios/run_all.sh` 第 68 行用了 `declare -A`（关联数组），这是 bash 4+ 特性，zsh 不支持。
在 macOS 默认 zsh 环境下直接 `./run_all.sh` 会报 `declare: -A: invalid option` 并退出。

```bash
# ✅ 正确：显式 bash
bash docs/全方面测试/scenarios/run_all.sh --gateway http://127.0.0.1:8793 --fast

# ❌ 错误：zsh 调用（macOS 默认）
docs/全方面测试/scenarios/run_all.sh --gateway http://127.0.0.1:8793 --fast
# → declare: -A: invalid option
```

或者用 shebang 重写：脚本已经是 `#!/bin/bash` 但 zsh 会忽略 shebang 用 zsh 解释，
所以必须 `bash <script>` 强制。

## 报告生成流程

```
run_all.sh 执行
  ├─ 16 个 S{XX}_*.sh → results/S{XX}_*.json
  └─ validation_report.py → results/REPORT.md

REPORT.md 内容：
  - 总通过率 + 通过数 / 失败数
  - 各场景表格（含 succ_pct / p99 / 阈值）
  - 失败场景详细
  - 故障模式覆盖矩阵
```

## kill-switch 验证循环

```bash
# Step 1: 跑 baseline (全 enable)，记录基线
$DOCS/scenarios/run_all.sh --skip-scenarios "S11"  # 5 min

# Step 2: 关 fp_slot 在 154 网关
ssh root@154 'systemctl edit llm-gateway-go'
# 加 Environment="KILL_FP_SLOT=1"
ssh root@154 'systemctl restart llm-gateway-go'
sleep 30  # 给 gateway 30s 启动

# Step 3: 跑 S01 + S13 + S15 (3 min)
$DOCS/scenarios/S01_baseline.sh
$DOCS/scenarios/S13_no_candidate.sh
$DOCS/scenarios/S15_cross_group_failover.sh

# Step 4: 对比与基线
diff <(jq '.metrics.success_rate' results/REPORT.md) /dev/stdin  # 简化对比

# Step 5: 灰度
# 假设：S01 成功率无明显下降 (≥ baseline × 0.95)
#   → 可继续开 KILL_CIRCUIT_DEGRADATION
#   → 重复 step 3

# Step 6: 回滚
ssh root@154 'systemctl edit llm-gateway-go'
# 删除全部 Environment= 行
ssh root@154 'systemctl restart llm-gateway-go'
```

## 与 docs/全方面测试/执行提示词.md 的关系

- `执行提示词.md` 是原始 prompt — 用 `k6`、`hey`、`wrk` 等工具
- `05-执行流程.md` (本文) 是更新版 — 用 `mock_supplier.py` + `mock_orchestrator.py` + `loadtest.py` 自建测试台
- 两者数据准备（`seed.sql`）一致；mock 模型名也一致（`loadtest-*`）
- 主要差异：原版依赖 `kx-citus-pg17:13.3.0-arm64` 容器；新版既可用它，也可用任何 PostgreSQL 17（已验证本地 llm-gateway-pg 工作）

## 故障排查速查

| 现象 | 原因 / 解决 |
|---|---|
| `start_suppliers.sh: 未绑定的变量 CASE_BASE_GROUPS_X` | 旧版本残留脚本；新版本使用 GROUP_NAMES 而非 GROUPS |
| `connection refused on port 19080` | mock_supplier 没起；`./tools/start_suppliers.sh` |
| `model_disabled` 阻断了路由 | 跑前 `psql -c "UPDATE providers SET manual_disabled=false WHERE id BETWEEN 9010 AND 9069;"` |
| S01 总是 0% succ | 网关没起 / 端口不对 / api_keys 不在 DB |
| supplier 报告 healthy 但业务 503 | 检查 api_keys 是否包含 hash 但用户传的是 prefix；看 `api_keys.key_prefix` 匹配 |
| 结果 SUMMARY 列空 | run_all.sh 完成后跑 validation_report.py |
