# S60: 跨环境网络模拟测试

**目标**: 验证网关在真实网络条件下（本地客户端 → 阿里云 252 服务器 → Mock 供应商集群）的稳定性与聚合能力。

**核心价值**: 将多个不稳定的供应商进行聚合，输出一个稳定的大模型服务。

---

## 架构

```
┌─────────────────────┐      公网       ┌──────────────────────────────┐
│   本地 (macOS)       │ ──────────────→ │  阿里云 252 (115.29.212.252) │
│                      │   ~20-100ms    │                              │
│  loadtest.py        │ ←────────────── │  nginx:80 (s60.itestu.cn)   │
│  (aiohttp 压测)      │   HTTP 响应     │       ↓ upstream             │
│                      │                 │  127.0.0.1:19900             │
└─────────────────────┘                 │       ↓                       │
                                        │  nginx (least_conn)           │
                                        │       ↓                       │
                                        │  60× mock_supplier           │
                                        │  (ports 19080-19139)          │
                                        │  12 groups × 5 instances      │
                                        └──────────────────────────────┘
```

## 前置条件

### 1. 部署 Mock Suppliers 到 252

```bash
# 在 252 服务器上执行
# 1. 安装 Python 3.11
dnf install python3.11 -y
pip3.11 install aiohttp==3.9.1

# 2. 创建目录并上传文件
mkdir -p /opt/mock-suppliers
# 上传 mock_supplier.py, mock_orchestrator.py

# 3. 启动 60 个实例
for i in $(seq 0 59); do
    port=$((19080 + i))
    group_idx=$((i / 5))
    instance=$((i % 5))
    group=$(printf "\\$(printf '%o' $((65 + group_idx)))")
    nohup python3.11 mock_supplier.py \
        --port $port --host 0.0.0.0 --group "$group" --instance $instance \
        > /tmp/mock_${group}${instance}.log 2>&1 &
done
```

### 2. 配置 Nginx 负载均衡

上传 `deploy-252/s60-mock-suppliers.conf` 到 `/etc/nginx/conf.d/`，然后：

```bash
nginx -t && systemctl reload nginx
```

### 3. DNS / Hosts 映射

本地测试需要将 `s60.itestu.cn` 指向 252 IP：

```bash

```

### 4. 验证部署

## 测试场景

### S60-1: 基础连通性测试

验证本地 → 252 → Mock 供应商的完整链路。

```bash
curl -X POST http://s60.itestu.cn/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"minimax-m3","messages":[{"role":"user","content":"hello"}],"max_tokens":10}'
```

**预期**: 返回 200 OK，响应包含 `[X/Y] mock-pong: hello`

### S60-2: 高并发压力测试

```bash
python3 << 'EOF'
import asyncio, aiohttp, time

async def run():
    async with aiohttp.ClientSession() as s:
        sem = asyncio.Semaphore(30)
        results = {"ok": 0, "err": 0}

        async def req(i):
            async with sem:
                try:
                    async with s.post(
                        "http://s60.itestu.cn/v1/chat/completions",
                        json={"model":"minimax-m3","messages":[{"role":"user","content":f"ping{i}"}],"max_tokens":10},
                        headers={"Authorization":"Bearer test-key","Content-Type":"application/json"},
                        timeout=aiohttp.ClientTimeout(total=20)
                    ) as r:
                        results["ok" if r.status==200 else "err"] += 1
                except: results["err"] += 1

        t0 = time.time()
        await asyncio.gather(*[req(i) for i in range(500)])
        print(f"500 reqs in {time.time()-t0:.2f}s, ok={results['ok']}, err={results['err']}")

asyncio.run(run())
EOF
```

**预期**: ≥99% 成功率，P99 延迟 <200ms

### S60-3: 供应商故障聚合测试

使用 `mock_orchestrator.py` 将部分供应商设为故障状态，验证网关仍能稳定输出。

```bash
# 将 A 组全部设为故障状态
python3 mock_orchestrator.py set-group-state A server_error

# 将 B 组设为慢响应
python3 mock_orchestrator.py set-group-state B slow
```

**预期**: 客户端仍能获得稳定响应（网关自动跳过故障供应商）

## 已知 Bug 修复

### Bug: Mock Supplier POST 无响应

**症状**: `curl -X POST http://localhost:19080/v1/chat/completions` 返回空响应（连接被关闭）

**根因**: `chat_completions` handler 中 `_do_chat_completions(request)` 的返回值未传递出去，导致 aiohttp 收到 None 并关闭连接。

**修复**:

```python
# 错误
await CONN_MGR.acquire()
try:
    await _do_chat_completions(request)  # 返回值被丢弃
finally:
    CONN_MGR.release()

# 正确
await CONN_MGR.acquire()
try:
    return await _do_chat_completions(request)  # 返回 Response 对象
finally:
    await CONN_MGR.release()
```

同时 `ConnectionManager.release()` 必须是 `async def`。
