# 06 - 验收标准（严格执行版，2026-08-06）

## 状态门禁

| 状态 | 含义 | 发布验收 |
|---|---|---|
| `PASS` | 所有检查通过且有当前 run 证据 | 可计入通过 |
| `FAIL` | 网关行为或测试断言失败 | 阻断 |
| `BLOCKED_ENVIRONMENT` | 数据库/schema/mock/metrics/隔离前置不满足 | 阻断，不计为网关失败 |
| `INVALID` | 缺结果、旧格式无法迁移或 JSON 损坏 | 阻断 |
| `SKIPPED` | 能力未实现或显式跳过 | 默认阻断；仅非发布报告可 `--allow-skipped` |

脚本退出码为 0 不是验收依据；最终以 `validation_report.py` 对 manifest 中当前 run 的结果判定为准。

## 通用指标

| 指标 | 功能基线 | 并发/可靠性 | 性能基线 |
|---|---:|---:|---:|
| HTTP 业务成功 | ≥99% | steady ≥95%，burst ≥95% | 非流 ≥99%，流 ≥95% |
| P95 | 按场景 gate | 记录并比较 | 记录并比较 |
| P99 | 按场景 gate | 记录并比较 | 记录并比较 |
| 流完成率 | S09/P01 ≥95% | R01 持续采集 | P01 ≥95% |
| SSE JSON 解析失败 | 0 | 0 | 0 |
| TTFB P95/P99 | S09 记录 | 记录 | 流式阶段记录 |
| 资源指标 | 不得伪造 | `/metrics` 或外部采集 | 缺失标记未采集 |

`202 Accepted` 是异步控制响应，不计为 `200 OK`；S13/S14 等预期失败场景使用错误分类、错误码、响应时延和无上游证据进行验收。

## 专项硬门禁

### C01 并发阶梯

- steady 阶段完成且成功率 ≥99%。
- burst 阶段完成且成功率 ≥95%。
- 必须记录总请求、吞吐、P50/P95/P99、HTTP 状态和错误分类。
- 如要宣称容量上限，必须同时提供 Gateway CPU/RSS/goroutine/FD、DB pool、Redis latency 采样；缺少则只能报告“负载行为已验证”。

### P01 性能基线

- 非流式成功率 ≥99%，流式成功率 ≥95%。
- 流式请求必须有可解析 SSE chunk 和 `[DONE]`；`stream_parse_failed > 0` 直接失败。
- 必须输出非流式与流式 P50/P95/P99、TTFB P50/P95/P99 和吞吐。
- 任何性能回归比较必须绑定同一环境、commit、模型和请求参数。

### R01 可靠性

- 长稳阶段健康探针无失败；探针失败、Gateway panic、进程退出直接失败。
- 故障阶段必须有请求结果和错误分类；故障移除后必须恢复 mock 状态。
- 结果必须记录故障 profile、持续时间、恢复动作和清理状态。
- 未执行 PostgreSQL/Redis 重启、连接池耗尽或 Gateway 重启恢复时，不得宣称依赖故障恢复已验证。

## 当前功能场景注意事项

- S17：pending 必须实际创建，owner 恢复正文完整，跨租户访问非枚举失败；只有 404 探测不能通过。
- S18：必须调用实际 system-health probe，验证 NULL fallback/status；仅 healthz 存活不能通过。
- S19：必须使用不同 tenant fixture；两把 `tenant_id=default` key 不构成租户隔离证据。
- S20/S22/S23：TODO、WARN、历史 `/tmp` 日志不能作为 PASS；必须关联当前 run/request ID 的 DB/log evidence。
- S21：分支会话未实现，结果必须为合法 `SKIPPED`，不可计入完整通过。

## 运行与报告

```bash
bash docs/全方面测试/scenarios/run_all.sh --suite all
python3 docs/全方面测试/tools/validation_report.py \
  --results docs/全方面测试/results/runs/<run_id> \
  --manifest docs/全方面测试/results/runs/<run_id>/manifest.json \
  --format json
```
