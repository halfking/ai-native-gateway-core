# 验收标准

## 全局指标

| 指标 | 最低要求 | 目标值 | 测量方式 |
|------|---------|-------|---------|
| 总成功率 | > 99% | 100% | 成功请求 / 总请求 |
| 总错误数 | < 1% | 0 | 客户端统计 |
| P50 延迟 | < 800ms | < 300ms | loadtest-v2.py 输出 |
| P95 延迟 | < 2000ms | < 1000ms | loadtest-v2.py 输出 |
| P99 延迟 | < 5000ms | < 2000ms | loadtest-v2.py 输出 |
| 最大吞吐 | > 150 req/s | > 250 req/s | 总请求 / 总耗时 |
| Gateway 错误日志 | < 10 条 ERROR | 0 | gateway-test.log |
| Mock 供应商分布 | 可用供应商均匀分布 | 匹配画像权重 | distribution 统计 |
| 流完成率 | > 95% | 100% | SSE [DONE] 标记检查 |

## 路由决策验证

| 决策维度 | 验证方式 | 预期行为 |
|---------|---------|---------|
| Tier 优先级 | tier=1 优先于 tier=2/3/9 | A/B/C/H/I 优先 |
| 成本优化 | TokenPlan/CodePlan (cost≈0) 优先 | C/D 组优先于 A/B |
| 延迟惩罚 | 慢供应商 (G 组 2-4s) 被降权 | G 组流量 < 5% |
| 健康过滤 | circuit_state=open 不路由 | 熔断供应商无流量 |
| 指纹 Slot | fp_slot_limit 限制并发指纹数 | H 组活跃客户端 ≤ 3 |
| 并发 Slot | concurrency_limit 限制并发请求 | I 组并发 ≤ 20 |
| Sticky 会话 | 同一 session 路由到同一供应商 | 准确率 > 85% |
| 高峰 fallback | tier=3 在高负载时被启用 | K 组收到流量 |
| 配额感知 | 配额耗尽后切走 | C 组耗尽 → D/A/B |
| 配额恢复 | 窗口重置后恢复 | C 组重新收到流量 |

## 失败条件 (测试中止)

以下条件触发测试中止:

1. Gateway 进程崩溃 (PID 消失)
2. 数据库连接丢失
3. 超过 50% 的 Mock 供应商不可用
4. 连续 3 个场景成功率 < 90%
5. Gateway 日志中出现 panic
6. 磁盘空间不足
