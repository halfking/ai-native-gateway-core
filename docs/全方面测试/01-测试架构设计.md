## 核心组件

### 1. Mock 供应商服务 (server-v3.py)

- 60 个实例, 12 组画像, 端口 19080-19139
- 15 种故障模式 (healthy/slow/rate_limited/quota_exceeded/auth_error/server_error/timeout/connection_refused/broken_stream/flaky/tool_error/data_format_error/context_length_exceeded/invalid_request/rate_limit_burst)
- 真实并发限制 + 排队机制
- Token 配额消耗与周期性恢复
- RPM 滑动窗口限流
- 可配置延迟分布 (uniform/bimodal/slow_start)
- 动态状态切换 API (/admin/state GET+POST)
- 画像系统: 按组批量配置并发/配额/延迟/成功率

### 2. 压力测试客户端 (loadtest-v2.py)

- 100-150 并发客户端, 基于 aiohttp 连接池
- 20+ 独立 API Key, 加权分配
- 多轮会话模拟 (session 池 + 复用率控制)
- Session ID 注入 (X-Gw-Session-Id)
- 可配置 Prompt 大小 (short 10-30t / medium 100-300t / long 1000-3000t)
- 流式 (SSE) 和非流式请求
- TTFB 和完整延迟采集
- 粘性路由准确率统计
- Mock 身份识别与分布统计
- JSON 结果持久化

### 3. Mock 编排器 (mock-orchestrator-v2.py)

- 组级健康矩阵查看
- 组级批量状态设置/重置
- 动态并发控制
- 动态配额控制
- 组级启用/禁用 (DB)

### 4. 数据库

- 12 组供应商配置, 每组 5 实例
- 15 个 mock 模型 (不重名避免路由到真实供应商)
- 60 个凭证, 每个凭证 2-4 个模型绑定
- v_routable_credential_models 视图提供完整路由候选

## 数据流

```
客户端请求
  │
  ▼
Gateway 接收
  │
  ├─ API Key 验证 → 解析租户
  ├─ 模型匹配 → 从 v_routable 获取候选
  ├─ 路由决策:
  │   ├─ tier 排序 (1→2→3→9)
  │   ├─ 成本排序 (PAYG 价格 / plan 摊销)
  │   ├─ 延迟惩罚
  │   ├─ 健康状态过滤 (circuit_state / availability)
  │   ├─ 指纹 slot 检查
  │   └─ 并发 slot 检查
  ├─ 发起上游请求
  │   ├─ 成功 → 返回响应
  │   ├─ 429 → 重试下一候选
  │   ├─ 500 → 重试 (最多 N 次)
  │   ├─ 401 → credential fatal → 跳过
  │   ├─ 超时 → 重试下一候选
  │   └─ 流中断 → 重试下一候选
  └─ 记录路由决策 → metrics
```
