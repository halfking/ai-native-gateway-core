### 3.1 实战必填环境变量（2026-08-05 经验补全）

`02-测试环境部署.md` 之前未明确以下几项，本地实测补全：

```bash
# 1) v2 URSM 必依赖 Redis（缺失则 /v1/chat panic: StickyStore is nil）
export LLM_GATEWAY_REDIS_ADDR=localhost:6379

# 2) CORS fail-closed（缺失则 main 直接 panic："CORS origins must be explicitly configured"）
export LLM_GATEWAY_CORS_ORIGINS='*'

# 3) 静态 API key（留空 → AuthMiddleware 静态校验 bypass，
#    KeyVerifier 仍走 DB 校验 sk-loadtest-01..08 这类 sk-* key）
export LLM_GATEWAY_API_KEY=''

# 4) 必须与 seed.sql 中 -v gateway_secret=... 一致（HMAC 计算 key_hash）
export LLM_GATEWAY_SECRET_KEY='local-test-secret-key-2026'

# 5) admin 端（/healthz/full, /metrics 等）独立 token
export LLM_GATEWAY_ADMIN_API_KEY='sk-test-admin-key-do-not-use-in-prod'

# 6) DB 连接（容器 llm-gateway-pg 已固定此密码）
export LLM_GATEWAY_DATABASE_URL='postgres://llm_gateway:llm_gateway_db_pass_2026_secure@localhost:5432/llm_gateway?sslmode=disable'

# 7) 凭证加密 key（32 字节零 base64；与生产 KID='k1' 配合）
export LLM_GATEWAY_CREDENTIAL_ENCRYPTION_KEY='AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA='
```

### 3.3 seed.sql 序列同步（idempotent 前置）

`api_keys` 主键序列与历史数据可能不同步，导致 seed.sql 报 `duplicate key value violates "api_keys_pkey"`：

```bash
PGPASSWORD='llm_gateway_db_pass_2026_secure' psql -h localhost -U llm_gateway -d llm_gateway -c \
  "SELECT setval('api_keys_id_seq', (SELECT MAX(id) FROM api_keys), true);"
# 然后再跑 seed.sql
```

### 3.4 编译修复记录

- `domains/stats/body_size_tracker.go` 历史已引入 `maxUpdateScriptSrc` (Lua 字符串)，
  但仍有 2 处调用了已不存在的 `maxUpdateScript.Source`，导致 `go build` 失败。
- 修复：第 118 行、132 行 `maxUpdateScript.Source` → `maxUpdateScriptSrc`
- 修复后 `go build -o ./bin/llm-gateway-go ./cmd/gateway` 成功（约 60MB binary）

### 3.5 完整启动脚本（推荐写法）

```bash
# /tmp/gateway-test.env
cat > /tmp/gateway-test.env <<EOF

LLM_GATEWAY_DATABASE_URL=postgres://llm_gateway:llm_gateway_db_pass_2026_secure@localhost:5432/llm_gateway?sslmode=disable
LLM_GATEWAY_SECRET_KEY=local-test-secret-key-2026
LLM_GATEWAY_CREDENTIAL_ENCRYPTION_KEY=AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=

LLM_GATEWAY_CORS_ORIGINS=*
LLM_GATEWAY_REDIS_ADDR=localhost:6379
LLM_GATEWAY_ENV=local
LLM_GATEWAY_CENTER_URL=http://127.0.0.1:9999
TRANSPORT_LAYER_IR_ENABLED=false

# 修 api_keys 序列 + 注入
PGPASSWORD='llm_gateway_db_pass_2026_secure' psql -h localhost -U llm_gateway -d llm_gateway \
  -c "SELECT setval('api_keys_id_seq', (SELECT MAX(id) FROM api_keys), true);"
PGPASSWORD='llm_gateway_db_pass_2026_secure' psql -h localhost -U llm_gateway -d llm_gateway \
  -v loadtest_host=127.0.0.1 -v gateway_secret=local-test-secret-key-2026 \
  -f docs/全方面测试/data/seed.sql

set -a; source /tmp/gateway-test.env; set +a
```

## 7. 故障级 kill-switch (2026-07-12 incident response)

## 9. 故障排查速查

| 现象 | 排查 |
|---|---|
| 端口 19080 已占用 | `lsof -i :19080` + `pkill -f mock_supplier.py` |
| DB 连接失败 | 确认 `llm-gateway-pg` 容器在跑：`docker ps` |
| mock_supplier.py 启动失败 | 检查 `/tmp/lab-suppliers/A-0.log` + 检查 `python3 -c "import aiohttp"` |
| gateway 崩溃 | 看 `/tmp/gateway-test.log` + 试 `KILL_*=1` 旁路 |
| 所有 401 from gateway | 检查 api_keys prefix 是否匹配 + `Authorization: Bearer sk-loadtest-01-hash-...` |
| 端口超时 | 确认 nginx → gateway upstream 配的是 `127.0.0.1:8781`（不是 8082 等） |
