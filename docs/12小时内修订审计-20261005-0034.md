### L5 — bloat 巡检的 0/3 语义

- 根因：`rc=$?` 抓了退出码却**从不使用**，改用「嗅输出」判失效；而 SQL 自带三道阈值过滤，**没有超阈表时输出本就应该为空**，于是「查询成功且结果为空」与「查询失败」被压成同一个 `exit 3`。该提交自己主张要区分 0/3，却把它破坏了。
- 修法：判据改为**先看退出码、再看输出形状**——`rc≠0` 或输出含 psql 报错特征 ⇒ exit 3；`rc=0` 且输出解析不出记录 ⇒ 全空 = 没有超阈表（exit 0）、有内容但解析不出 = 格式漂移（exit 3）。同时删掉被抢先的 `[ -eq 0 ] && exit 0` 死代码。
- 验证（四路对照 + 负控）：

| 桩场景 | 期望 | 实跑 |
|---|---|---|
| 成功 + 零行（治理完成后的常态） | 0 | **0** ✅ |
| 成功 + 有超阈表 | 1 | 1 ✅ |
| psql 失败 | 3 | 3 ✅ |
| 成功 + 输出不可解析 | 3 | 3 ✅ |

  **负控**：`git stash` 回退到修改前，同一个 `empty` 桩 ⇒ **exit 3**（即修复前每天的假告警）；恢复后 ⇒ 0。

### L6 — assets 心跳的 NULL 逃逸

- 根因：`assets.last_seen_at` 在 `deploy/sql/schemas/baseline/01-schema.sql:5673` 是**可空、无 DEFAULT、无 NOT NULL** 的裸声明。门控半②写作 `last_seen_at < now() - …`，对 NULL 行求值为 NULL（不是 true）；半①在业务字段未变时为 false ⇒ **两半都不成立 ⇒ 该行永远不会被更新**，`last_seen_at` 永远停在 NULL。而读方（:746）用 `COALESCE(last_seen_at, registered_at)` 判 stale ⇒ 一个活着的资产因 `registered_at` 已超 6h 被 `bg/asset_health_probe` 判成 degraded。
- 这是「省掉无效重写」省过头的样子：**NULL 行不是「无需重写」，而是「永远写不进去」**。
- 修法：半②改为 `COALESCE(public.assets.last_seen_at, '-infinity'::timestamptz) < now() - ($12 * interval '1 second')`，第一跳就把 NULL 行救出来，此后走正常的 5 分钟窗口。
- **门同步升格（不是放宽）**：既有契约门 `TestUpsertSQLHeartbeatWindowGuard` 原本断言「含有裸比较」，被 COALESCE 打断。改为断言「含有 COALESCE 到 `-infinity` 的比较」**且**「与 `$12 * interval '1 second'` 比较」——意图未变（仍锚在 last_seen_at 与 now() 的比较上），同时把 NULL 这条逃逸路径钉死。

## 五、825 撞号：**我先判错，后改号**（本轮最有价值的一次自我推翻）

### 5.1 我第一遍的判断（错的）

初审时我核实过「编号是不是排序键」，结论是**不是**：`installer/internal/dbinit/runner.go:31` 的 `StartupFiles` 是显式有序字面量清单（不是 glob 后按数字前缀排序），`scripts/apply-db-revision-sequence.sh` 同为显式路径清单，全仓在这两处 `git grep 'sort\.|%03d|strconv.Atoi'` 零命中。基于此我写下「**决定不改号**，理由：改号零运行时收益，却要动 `bg/` 契约门 3 处常量 + 变异脚本 9 个靶点」。

这个推理**只对了一半**：它对「执行顺序」成立，但对「**身份**」不成立。

### 5.2 第三路子审计推翻了我

子审计报了一个 P0，我**自己复核坐实**：

- `db/db.go:764` 与 `db/db.go:1719` **两处都**往 `schema_migrations` 写：
  - `VALUES ('825', 'modality graded verification: …')`
  - `VALUES ('825', 'ursm_node_snapshot_min converted to daily RANGE partitions; MANUAL migration …')`
  - 两处都是 `ON CONFLICT (version) DO NOTHING` ⇒ **抢同一个主键**，先跑者赢、另一条**静默丢弃**，825 的描述取决于哪条 ensure 先跑。

**教训**：我用来推翻风险的证据（「编号不派生顺序」）与风险的真正机制（「编号是主键」）**不是同一件事**。用前者论证后者，属于**换了判据还沿用旧结论**。这与 224 号那次的教训同型：判据必须与被检查对象对齐。
