### §10.6 本轮新增的可复用经验（**待并入 `LESSONS.md` / `AGENTS.md`**）

> `LESSONS.md` 本轮正被并行会话编辑（`git status` 显示 modified），为避免同文件并发写，
> 本节先记在 handoff 里，由该会话或下一轮合并进 `LESSONS.md`。

1. **「量具自身有竞态」与「断言写错」的分诊特征：失败项会不会漂移。**
   同一道门复跑若干次，**失败项在多条断言间漂移** ⇒ 竞态（管道/时钟/共享状态）；
   **稳定地红同一条** ⇒ 断言或实现真错。本轮那道门复跑 5 次红 1 次、再 10 次红 1 次，
   且两次红的**不是同一条**（configs 种子 / GO 基础镜像）⇒ 锁定竞态方向。
   ⇒ 通用式：**判「门坏了」之前，先看它坏得稳不稳。**
2. **`set -o pipefail` + `printf "$big" | grep -q` = 随机假红。**
   `grep -q` 命中即退出 ⇒ 上游 `printf` 还在写 ⇒ 收 **SIGPIPE(141)** ⇒ pipefail 把
   整条管道判成非零。实测 52KB 正文单条断言 60 次里 141 出现 **1 次**。
   ⇒ 修法：改 **here-string**（`grep ... <<<"$X"`，命令退出码取 grep 的），
     或把内容落临时文件再 grep。⇒ 判别动作：**任何 `pipefail` 脚本里的
     `X | grep -q`，若 X 可能 > 管道缓冲（64KB），就是潜在随机红。**
3. **「门全绿」这句话本身要有证据。** 上一轮写下的「既有门 110 条仍全绿」是**假陈述**
   （单次全绿 ≠ 门可靠）。⇒ 报告门的状态要给**复跑次数**与**失败项是否漂移**。
4. **locale 的真值是「运行时求值」，不是「文件文本」。**
   JS 对象字面量里**重复键后者覆盖前者** ⇒ 文件里残留的中文可能**根本不生效**。
   实测 `en-US/routing.ts` 的 `queryFailed` 出现 4 次，运行时生效的是英文那个；
   文件行数口径 588 vs 运行时口径 389 ⇒ **按文本统计会把早已被覆盖的中文算成缺陷**。
   ⇒ 任何 locale 统计必须 **vm 求值后取运行时值**（本轮 `localeValueQuality.ts` 即如此）。
5. **门里重复调重活 ⇒ 门自己变成计时敏感门。** 本轮新门在 4 条断言里各调一次
   `measureAll()`（每次扫完 `src/**` + 加载 8 个语种）⇒ 默认 20s 超时必红。
   ⇒ 修法：① 重活**带缓存**只算一次 ② 显式给 describe 设 `timeout` ③ 缓存要配
   `clearXxx()` 且**写明「缓存不会因文件变化自动失效」**。
6. **变异验证必须先证明「变异真的动了指标」。** 本轮 M2 选了 ar-SA 的
   `workTypes.savedOk` —— 它**本来就是中文** ⇒ 变异是**语义空操作** ⇒ 门当然绿。
   ⇒ 通用式：变异后**立刻复测指标**确认它动了，再看门红不红；否则「门没抓住」
   与「变异无效」无法区分。⇒ 更进一步：**变异要挑「当前值与目标形态不同」的那一条**。

### §11.3.1 一件必须写下来的事：**测试全绿 ≠ 类型能过**

首轮 `vue-tsc --noEmit` 报了一个错，位置是**本轮自己新增的文件**：

```

```

根因：自证用例 P4 要喂一个**非字符串**值（`{ 'k': ['b'] }`）去测「该语种不参与比较」的
防御分支，而 `probe` 的入参类型写的是 `Record<string, LocaleValues>`（`LocaleValues`
规定值必须是 `string`）⇒ **P4 这条自证自己编不过**。

⇒ ★ **vitest 只做转译（esbuild），不做类型检查** ⇒ 一条自证用例可以「逻辑上想测
防御分支、类型上却编不过」，而 **vitest 依然 5/5 全绿**（因为 vitest 也不查类型）。
真正抓住它的是 `vue-tsc`。⇒ 而 `verify.sh --web`（CI 走的那条）**先 typecheck 再 test**
⇒ 若没单独跑类型检查，这个错会**在 CI 上炸**，而本地全绿。
⇒ 本轮因此补了一条**定向**类型检查（只查 `localePlaceholderParity.ts` 这条依赖链，
秒级），不必每次等 13 分钟的全量 `vue-tsc`：

```
cd web && npx tsc --noEmit --target es2022 --module esnext --moduleResolution bundler \
  --allowImportingTsExtensions --verbatimModuleSyntax --strict --skipLibCheck \
  src/i18n/localePlaceholderParity.ts
# 修后 exit 0
```

### §11.6 本轮新增的可复用经验（**待并入 `LESSONS.md` / `AGENTS.md`**）

> `LESSONS.md` 仍可能被并行会话编辑 ⇒ 本节先记在 handoff 里。

1. **「把某件事交给别人一并提交」= 把交付押在别人的推送时点上。**
   R53 的判断（两个 211 门文件与引擎重命名是同一原子变更）**在技术上是对的**，
   但它让「竞态修复已在 main 上」这个**状态陈述**变成了假陈述 ⇒ 审计时刻实测
   main 上仍有 30 处 racy 形态。
   ⇒ ★ 通用式：**「代码在别人的工作区里」不等于「代码在 main 上」。**
   状态陈述必须用**远端可复核的读数**（`git show origin/main:<file> | grep -c`），
   不能用「我改过了 / 我交给谁了」代替。
2. **「以某个语种为参照」这条规则本身要先验证参照方是对的。**
   本轮族2 里**恰恰是参照方（en-US）+ 另一语种（zh-CN）缺参数**。
   ⇒ ★ 通用式：**凡是以「A 为真值」的判据，先问「A 一定对吗」。**
   判别动作：拿**调用点**（`t('key', {…})` 实际传了什么）去裁定，而不是投票。
   ⇒ 推论：**「跨语种平不平」是比「谁等于谁」更稳的判据形式**——它不预设谁对，
     只把「不一致」暴露出来，把「谁对」留给有依据的一方裁定。
3. **找「有 N 个语种不一致」这类缺陷时，先分清「哪一侧是多数」和「哪一侧是对的」。**
   本轮族1 是 2:6（en-US/zh-CN 对），族2 是 2:6（en-US/zh-CN 错）⇒
   **两个族的多数方向相反** ⇒ 「按多数对齐」会把其中一个修反。
   ⇒ ★ 判别动作：**每个族都要单独找它的外部依据（调用点），不许套用统一规则。**
4. **判据「不越界 / 不一致 / 为 0」型，必须配「非空下限」。**
   本轮新门的 M3/M4 变异证明了这一点：把提取器改坏、把比较逻辑整体失效，
   **硬闸 0 那条仍然全绿**（前者没有不一致可看，后者比都没比）⇒
   真正抓住它们的是**「非空下限」那条**（比较键数 ≥ 5000 / 含占位符键数 ≥ 500）。
   ⇒ ★ 通用式：**任何「不得存在 X」的门，都要另配一条「确实量到了足够多的东西」的断言。**
   ⇒ 这与 AGENTS.md 判据纪律第 20 条（几何类「不越界」会被「什么都没画」同时满足）
     是**同一个形态的另一个面**：「没坏」的门对「没做」永远绿。
5. **「死代码里的缺陷」要不要修？先问「它死得多彻底」。**
   族1 的键全仓零引用 ⇒ 修它的**用户收益是 0**。但**平价门若只管被引用的键，
   这类缺陷就永远抓不到** ⇒ 命名空间一旦复活，缺陷就等着。
   ⇒ ★ 通用式：**门选「键范围」时要分开两个问题**：
   「哪些键值得度量（范围）」与「哪些键值得修（收益）」。
   本轮的做法是**门管全范围、修只修能自证的**。
6. **顺着一条缺陷往下挖，常常挖到比它更大的东西，但更大的那个要单独登记。**
   本轮族1（占位符被吞）往下挖挖出「激活页硬编码中文」——那是**另一个根因**
   （页面不走 i18n），**不是占位符问题**。⇒ 本轮修占位符、把「激活页不跟 i18n」
   登记为遗留，**不把两件事混成一件**（混了就会声称「修了激活页」，而实际只改了
   几行 locale 文件）。
7. **★「vitest 全绿」不等于「类型能过」—— 新增 TS 文件必须单独跑类型检查。**
   本轮新文件里有一条自证用例（P4：喂非字符串值去测防御分支），**类型上编不过**
   （`probe` 入参写的是 `Record<string, LocaleValues>`，值必须是 `string`）。
   而 **vitest 只转译不查类型** ⇒ 这条用例「逻辑上想测防御分支、类型上却编不过」，
   **vitest 依然 5/5 全绿**。真正抓住它的是 `vue-tsc`（TS2322）。
   ⇒ ★ 通用式：**判据的「有牙」要分两层验**——
     「逻辑上会不会红」由测试验，**「代码能不能编过」由类型检查验**。
     只做前一层 ⇒ 会出现「门全绿但 CI 挂在 typecheck 上」的交付物。
   ⇒ ★ 配套（省时间）：**不必每次等全量 `vue-tsc`（本机 load ~500 时实测 13m37s）**，
     先跑**定向 tsc**（只查新文件这条依赖链，秒级）定位与验证：
     `npx tsc --noEmit --target es2022 --module esnext --moduleResolution bundler
      --allowImportingTsExtensions --verbatimModuleSyntax --strict --skipLibCheck <file>`。
   ⇒ ★ 推论：**自证用例本身也是代码**。它写错了（类型/语法/前提）不会让门变红，
     只会让门「测不到它想测的东西」⇒ 自证用例的**类型正确性**也要验。

### §12.4 本轮新增的三条判据纪律（**都是自己踩到并当场修掉的**）

> 现按 rule 66（同一模式跨 **3 个不同工作日**复现才晋级）正式晋级为 **AGENTS.md §35(a)**。

写一句解释「这里没用 DISTINCT ON」的注释就会误报，而写注释的人为了让门绿去改注释
⇒ 下一个人写注释就重新踩。
⇒ 已加 `stripSQLComments`（剥行注释/块注释，**单引号字符串内原样保留**），
模式类判据一律扫**剥掉注释后的代码位**；
并补了**防假阳性自证**（注释里的 `DISTINCT ON` 不得进代码位）
**＋ 保留真缺陷仍被抓的自证**（真代码位里的 `DISTINCT ON` 仍必须红）——
**只补前者会退化成「什么都抓不到」的恒绿门**。

**纪律二：两个**极性相反**的判定函数直连 ⇒ 守卫永远不生效，而守卫自己的判据全绿。**

项 1 的 S4 停写门里有两个函数：
`recordedCostComparability` 回答「**还能不能判定**」，`SkipWhen` 回答的是「**要不要跳过**」——
极性相反。我第一版**直连**二者，写成「不可判定 ⇒ 不跳过」，
守卫于是**永远不生效**（照旧发 SQL），而**判定函数本身的判据仍然全绿**
（它确实正确地返回了 comparable=false）。
⇒ 这条缺陷**只有**一条腿能抓住：**「守卫生效时，那条 SQL 确实没发出去」**。
本轮用的量具是「同一个**连不上的池**、同一条检查，只切换停写门」：
写门开着时错误来自 `query recorded_cost_is_negative: ...`（它发了 SQL），
停写生效时错误**不**来自那里（它根本没发 SQL）。
⇒ **通用式：任何「守卫/门/短路」类机制，都必须有一条腿直接断言「副作用没发生」**；
只断言「判定函数返回了正确的值」的门，会在守卫接反时**全绿**。
