**本轮踩到的量具坑（如实登记，不计入回归）**：
1. `CGO_ENABLED=0` 跑全量测试 ⇒ lite/SQLite 族一片红（`CGO_ENABLED=1` 复跑全绿）——**量具坏了，不是回归**；
2. 252 的容器运行时是 **podman**（`docker` 是包装）且全量 `docker logs` 会被超时打断 ⇒ 读到的是**截断读数**，
   曾一度把「读不到」当成「没有慢查询」；正解是**有界读**（`tail -c` + 直接读 `ctr.log`）+ `grep -a`；
3. `grep` 报「匹配到二进制文件」⇒ podman json-file 里有二进制字节；
4. `git worktree add` + `checkout` 22,170 个文件时把 `git status` 打成进度刷屏（须加 `--porcelain`/静默）；
5. `cmd | tail; echo $?` 取到的是 **`tail` 的退出码**而不是被测命令的 ⇒ 探针自身写错，
   导致一度以为 `ui-audit.mjs --strict` 失败；改用 `PIPESTATUS`/不接管道后在 pristine 树上实测 **exit 0**。
6. **★ A/B 两条 SQL 的「冷热缓存顺序混淆」**（2026-10-20 订正，见 §8.1 第 6 条）：
   先跑的那条是**冷**的（buffer 未命中、并行 worker 刚起），后跑的那条是**暖**的
   ⇒ 我把 **1789 ms → 739 ms** 读成了「−59%、每天省 27 分钟」，并把这套数字复制进了
   **代码注释 / 门禁理由 / 审计档 / handoff / AGENTS.md 五处**。
   复核方用**交错重复**证伪；我自测确认：交错 ABAB ×6 ⇒ 中位 −11%、最小值 −1.9%，
   **组内极差 > 组间差**；逐节点 EXPLAIN 比对 ⇒ 两形态行数/buffers 几乎相同，
   **「双扫」机理不存在**。⇒ **A/B 必须交错重复测并报分布；「先跑的那条」不是基线。**
