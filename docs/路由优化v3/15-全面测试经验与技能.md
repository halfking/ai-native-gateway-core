# 路由优化 v3 全面测试经验与技能

> 目标：把 154/252 故障经验转成可重复的本地、集成、staging、生产只读测试方法。
> 本文不替代 `docs/architecture/phase2-r112-local-test-plan.md`，专门补充 URSM、降级、日志可靠性和真实故障回归。

## 1. 测试分层

| 层级 | 环境 | 目标 | 是否允许写生产 |
|------|------|------|----------------|
| L0 | Go 单测 | 分类器、状态门槛、纯逻辑 | 否 |

## 2. P0 回归矩阵

| 场景 | 输入 | 期望 | 证据 |
|------|------|------|------|
| ModelNotFound | mock 返回 400/404 model not found | 只冷却 `(credential, model)`，不污染同 credential 其他模型 | `credential_model_bindings` |
| ModelNotFound failover | A 返回 MNF，B 成功 | 客户端只收到 B 成功响应 | response + attempt trace |
| Client cancel | 客户端主动断开 | 不写供应商降级状态 | request log/error origin |
| Transient x1/x2 | 上游短暂 5xx | 只走 breaker，不立即持久化 | breaker state |
| FailureLogger nil | 依赖未注入 | 请求不失败，但日志明确告警 | gateway log |
| Failure log insert fail | PG 拒写 | 请求不失败，出现 insert failed | gateway log + alert |
| Staleness quiet | 无近期 request_logs | 不告警 | alert ring |
| Staleness active | 近期有请求，无新 failure row | 触发一次告警，按 cooldown 去重 | log/webhook |
| Staleness recovery | failure row 恢复写入 | 后续 tick 不再告警 | alert ring |

## 3. 本地 L1 流程

```bash
# 依赖已存在时只重建网关，不删除 PG/Redis/mock
docker compose -f docker-compose.local-r112.yml build gateway
docker rm -f r112_gateway 2>/dev/null || true
docker compose -f docker-compose.local-r112.yml up -d --no-deps gateway

# 基础门
curl -fsS http://127.0.0.1:8781/healthz
curl -fsS http://127.0.0.1:8781/metrics | grep '^# TYPE'

# 认证门
curl -fsS -X POST http://127.0.0.1:8781/api/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<local-only-password>"}'

# mock 上游真实转发
curl -fsS -X POST http://127.0.0.1:8781/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer local-mock' \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"local audit"}],"stream":false}'
```

本地判定必须同时检查：HTTP 结果、容器日志、`request_logs`、`candidate_failure_logs`、`routing_audit_log`。只看 HTTP 200 不算通过。

## 4. 真实故障回放

### 4.1 MNF 回放

Mock upstream 增加一个固定返回：

```json
{"error":{"type":"not_found_error","code":"5","message":"model is not found"}}
```

验证：

1. 请求 `glm-5.2` 到 credential A。
2. 确认 `model_probe_runs_hot` 记录 `routing_404`。
3. 确认 `credential_model_bindings.available=false`、reason 为 `auto_model_not_found`。
4. 确认同 credential 的其他 model 仍可路由。
5. 确认候选 B 成功时客户端不看到 A 的内部错误。

### 4.2 流断 EOF

Mock upstream 返回若干 SSE chunk 后直接关闭连接，不发送 `[DONE]`。

验证：

- `stream_interrupted=true`、`failure_detail_code=eof_without_done`。
- 已经向客户端输出内容时禁止透明拼接。
- 连续失败达到 breaker 门槛后才进入持久化状态。
- 不把客户端取消误判成 upstream failure。

### 4.3 探测超时

让 probe endpoint 延迟超过 probe timeout，分别测试：请求 context 取消、探测 context 超时、applyResult DB 超时。

验证：三者的 `error_origin` 不混淆；探测失败不会覆盖最后一个健康状态；重试有上限和退避。

## 6. 经验与技能

### 6.1 先验证数据面事实

- 先确认进程、监听端口、实际 binary、日志 fd、数据库连接，再解释业务日志。
- 154 是 systemd 主机部署；252 可能无 active gateway，必须先确认启动方式。
- 时间窗口统一使用 `+08`，数据库 `timestamptz` 查询不得混用本地无时区字符串。

### 6.2 日志与数据库必须交叉验证

- `http_request` 没有 credential 维度，必须结合 `LOAD_SCORE_V2`、`upstream_failure`、`model_not_found` 等事件。
- `request_logs` 为最后一次尝试，不能替代 candidate failure 明细。
- failure log 的 `max(ts)` 只能和最近请求活动联合判断，空闲网关不能误报。

### 6.3 失败分类不允许凭名字推断

- `model_not_found` 必须通过 HTTP status + provider body 双重确认。
- `eof_without_done` 需要区分 benign missing sentinel 与真实截断流。
- `context canceled` 必须携带 error origin，否则不能用于供应商降级。

### 6.4 测试闭环

1. 先写能失败的最小测试。
2. 复现后只改一个变量。
3. 先跑定向测试，再跑全量测试。
4. 本地请求必须检查持久化结果和日志。
5. 生产只读验证完成后才允许部署。
6. 部署后验证失败，优先关闭 feature flag 或回滚 binary。

## 7. 阻断门

- `go test ./...`、`go build ./...`、`go vet ./...` 全通过。
- 本地 health、auth、metrics、mock chat 全通过。
- 数据库启动日志不得出现 `postgres disabled`。
- 本地请求日志能持久化，不能有 `mkdir data: permission denied`。
- MNF 只影响模型绑定，不得污染 credential-wide 状态。
- staleness quiet/active/recovery 三态测试通过。
- 生产部署前确认当前 binary、service、端口、回滚 binary 和数据库 migration 状态。

## 8. 当前已知本地环境风险

- compose 文件使用固定 `r112_*` container name，多个 compose project 并行执行会冲突；处理方式是复用依赖并使用 `--no-deps`，禁止随意删除共享依赖。
- 本地镜像是 `linux/amd64`，Apple Silicon 会触发 emulation warning，性能数据不可用于生产基线。
- 本地部分历史 migration 被脚本跳过，启动日志中的非关键对象缺失需单独记录，不得把该环境当作生产 schema 等价物。
