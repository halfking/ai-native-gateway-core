# 冷却状态测试场景

## 概述

本文档描述了 LLM Gateway 中供应商/凭证冷却状态的测试场景，验证：
1. 冷却状态下前端返回正确的错误信息
2. 自动探测机制在冷却期满后恢复正常
3. 多处状态同步更新（credentials, credential_model_bindings, model_offers）

## 测试场景

### S11: 供应商冷却状态测试

**目标**: 验证供应商进入冷却状态时，客户端收到正确错误信息，自动探测恢复后正常路由

**前置条件**:
- Gateway 运行在 localhost:8082
- 至少 50 个 Mock vendor 运行
- 数据库连接正常

**测试步骤**:
1. 将 C 组供应商设置为 `rate_limited` 状态
2. 发送 5 个请求验证错误信息
3. 等待 10 秒（自动探测恢复）
4. 发送负载测试验证恢复后路由

**预期结果**:
- 冷却状态下返回 HTTP 503，错误信息包含 "No available provider"
- 恢复后请求成功率 100%

**验证点**:
```bash
# 检查冷却状态
psql -d llm_gateway -c "
SELECT c.id, c.provider_id, c.availability_state, c.quota_state,
       c.availability_recover_at
FROM credentials c
WHERE c.provider_id IN (
    SELECT id FROM providers WHERE code LIKE 'loadtest%'
)
LIMIT 10;
"
```

### S12: 凭证冷却状态测试

**目标**: 验证单个凭证进入冷却状态时，错误信息正确返回，自动探测恢复后状态同步更新

**前置条件**:
- 同 S11

**测试步骤**:
1. 为 C 组设置低配额（500 tokens）
2. 高并发请求触发凭证冷却
3. 检查冷却状态
4. 等待 15 秒（自动探测恢复）
5. 验证恢复后路由

**预期结果**:
- 凭证冷却状态正确设置
- 恢复后状态同步更新到 credential_model_bindings 和 model_offers

**验证点**:
```bash
# 检查凭证冷却状态
psql -d llm_gateway -c "
SELECT c.id, c.availability_state, c.availability_recover_at,
       c.quota_state, c.circuit_state
FROM credentials c
WHERE c.id = (
    SELECT MIN(id) FROM credentials
    WHERE provider_id IN (
        SELECT id FROM providers WHERE code LIKE 'loadtest%'
    )
);
"

# 检查绑定状态同步
psql -d llm_gateway -c "
SELECT cmb.credential_id, cmb.available, cmb.unavailable_reason,
       cmb.unavailable_recover_at
FROM credential_model_bindings cmb
WHERE cmb.credential_id = (
    SELECT MIN(id) FROM credentials
    WHERE provider_id IN (
        SELECT id FROM providers WHERE code LIKE 'loadtest%'
    )
)
LIMIT 5;
"
```

## 错误信息格式

### 冷却状态错误响应

```json
{
    "error": {
        "message": "No available provider for model 'loadtest-mini-alpha'. All 3 candidates failed.",
        "type": "server_error",
        "code": "model_not_found",
        "param": null,
        "stage": "execution",
        "kind": "rate_limit",
        "attempts": 3,
        "tried": 3,
        "retryable": false
    },
    "request_id": "req_xxx"
}
```

### 关键字段说明

| 字段 | 说明 |
|------|------|
| `type` | 固定为 "server_error" |
| `code` | 错误代码，冷却状态为 "model_not_found" |
| `kind` | 具体错误类型，如 "rate_limit", "cooling", "unreachable" |
| `stage` | 错误发生阶段，"execution" 表示执行阶段 |
| `retryable` | 是否可重试，冷却状态下通常为 false |

## 自动探测机制

### 恢复条件

1. **availability_recover_at** 已过期
2. **lifecycle_status** = 'active'
3. **manual_disabled** = false
4. 无 **broken_confirmed** 的模型探测状态

### 恢复频率

- 默认每 60 秒检查一次
- 可通过环境变量 `LLM_GATEWAY_MNF_COOL_MINUTES` 调整 mnf_cooling 恢复时间

### 状态同步流程

```
凭证冷却 → credential_model_bindings unavailable → model_offers unavailable
    ↓
自动探测恢复 → credential ready → cmb available → model_offers available
```

## 故障排查

### 问题：冷却状态未恢复

**检查**:
```bash
# 检查 availability_recover_at 是否设置
psql -d llm_gateway -c "
SELECT id, availability_state, availability_recover_at,
       EXTRACT(EPOCH FROM (availability_recover_at - now())) as seconds_until_recover
FROM credentials
WHERE availability_state = 'cooling';
"
```

**解决方案**:
- 如果 `availability_recover_at` 为 NULL，检查写入逻辑
- 如果时间未到，等待恢复
- 手动恢复：`UPDATE credentials SET availability_state = 'ready', availability_recover_at = NULL WHERE id = xxx;`

### 问题：状态未同步到 cmb/model_offers

**检查**:
```bash
# 检查 cmb 状态
psql -d llm_gateway -c "
SELECT cmb.*, c.availability_state
FROM credential_model_bindings cmb
JOIN credentials c ON c.id = cmb.credential_id
WHERE c.id = xxx;
"
```

**解决方案**:
- 手动同步：`UPDATE credential_model_bindings SET available = TRUE, unavailable_reason = NULL WHERE credential_id = xxx;`
- 检查 mnf_cooling 恢复逻辑是否正常运行
