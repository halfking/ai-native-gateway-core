# Mobile Gateway Operations Gap Matrix

This matrix is the implementation source of truth for the cross-repository mobile operations goal. Existing functionality is reused; new work is limited to the gaps below.

| Domain | Existing mobile/API coverage | Gap to close | Authorization/data contract |
|---|---|---|---|
| Mobile node access | `llm-gateway-client` had one stored server origin and static host presets; `web-mobile` account sheet had no node entry | Implement multi-node profile manager, signed QR import, fingerprint confirmation, node-specific health, account-settings deep link, and exact dynamic navigation guard | No tokens in profile/QR; remote origin gets no Capacitor bridge; HTTPS in release |
| System health | `SystemMonitorView.vue` covers probe-worker health and completed probe runs; `DashboardOpsView.vue` covers operational aggregates; `HomeView.vue` now polls the live queue | Keep existing health views and expose live pending/active/completed queue counts and update state on the overview | Existing admin authorization; stale/degraded/missing source is not “healthy” or zero |
| Live request queue | `RequestJourneyView.vue` and `RequestJourneyDetailView.vue` call `/api/admin/request-journeys/queues`; filters include lifecycle/view | Expose queue counts and refresh time in system overview; keep the queue page as the detailed view | Existing queue has bounded/local-or-shared observation semantics; expose degradation/scope labels |
| Routing | `RoutingCheckView.vue`, `RouteMatrixView.vue`, `RoutingAuditView.vue`, `RouteFlowView.vue`, `RoutingLogView.vue`, and `RoutingOverridesView.vue` exist | Add model picker to relevant model filters; add a clear route-policy entry from the status/overview surface; audit any missing mobile routing-policy mutation/detail | Respect route-by-route role differences; do not infer permission from URL prefix |
| Models | `ModelsView.vue`, `ModelPoliciesView.vue`, `ModelPolicyAuditView.vue`, model API `fetchAvailableModels()` exist | Add a mobile searchable/grouped selector matching desktop `ModelPicker` semantics and reuse it in matching filters | Canonical model identifier remains unlocalized; model catalog API is source of truth |
| Tenant list/details | `TenantsView.vue`, `TenantDetailView.vue`, `api/tenants.ts`; GET/PATCH tenant endpoints; detail reports summary, daily stats, users, and keys | Add confirmed enable/disable using existing PATCH; expose available usage dimensions and distinguish unavailable aggregates from zero | Super-admin tenant endpoints; `default` cannot be disabled; stats can return 504; cost/credits and time-zone sources differ |
| User directory/actions | `admin/users.go` has GET/PUT user APIs and `enabled` field; tenant detail lists users | Add confirmed user enable/disable and a searchable user usage page | Tenant admins can only mutate users in their own tenant; server remains authority; localize 403/409 errors and refresh after action |
| User usage | `api/userUsageStats.ts` wraps `/api/admin/users/usage-summary` and `/api/admin/users/{id}/stats` | Add searchable user usage list/detail with date range, model/app/key dimensions, and recent request links | Preserve summary caps/truncation and omitted/degraded states from API module |
| API keys | `KeysView.vue` lists request/token/cost totals and enables/disables keys via `api/keys.ts`; tenant detail lists keys | Add key status action in tenant detail and useful usage drill-through; do not duplicate the main key workflow | Existing key tenant-scope checks; reveal remains explicit and uncached |
| Cost reconciliation | Go backend exposes `/api/admin/provider-cost-reconciliation` and bill import; no corresponding mobile route/view | Add a mobile reconciliation page for provider bill totals and gateway costs; label supplier cost separately from customer charge | Super-admin route; provider bill import is a write and requires explicit confirmation; retain UTC month boundaries |
| Requests | `RequestLogsView.vue`, `RequestDetailView.vue`, request journey list/detail, and request APIs exist | Add a shared drill-through/filter surface from tenant/user/key/model views; ensure details expose route/model/status/timing/tokens/cost where available | Existing request body access and redaction rules remain authoritative; body fetch is explicit |
| Sessions/multi-turn | `SessionAnalyticsView.vue`, `SessionAuditView.vue`, `TurnsView.vue`, and session context APIs exist | Link a session from its requests and a request from each turn; show per-turn and session aggregates without replacing existing analytics/audit flows | Session endpoints have distinct tenant/role guards; session IDs are encoded in links |
| Locale coverage | The mobile SPA contains complete `zh-CN.ts` and `en-US.ts`; eight desktop locale files do not cover all mobile keys | Expose only fully covered mobile locales and provide complete page/state coverage, date/number/currency formatting, and responsive English/Chinese layouts; keep the local node manager's independent eight-language selector | Build checks enforce key parity and every literal mobile translation key in the two supported locales |

## Implementation decisions

1. Do not recreate functionality already present in the mobile SPA or Go API.
2. Reuse user `PUT /api/users/{id}` with `{ "enabled": false|true }` and tenant `PATCH /api/admin/tenants/{code}` with `{ "status": "disabled"|"active" }`; do not add parallel mutation endpoints.
3. Keep API key enable/disable in the existing key API, with a smaller action in tenant detail only for context.
4. Build user analytics on the existing `userUsageStats.ts` API before adding any new aggregate query.
5. Use the existing provider-cost reconciliation API for supplier invoices. Customer usage/charge comparisons are a separate data series and must not be represented as the same accounting quantity.
6. The NetBird service adds the configured gateway peer to a pre-created dedicated gateway group and manages only a narrowly scoped gateway-access policy. The mobile-admin peer group and membership remain administered in NetBird so scanning a QR cannot grant a new phone network authority.
