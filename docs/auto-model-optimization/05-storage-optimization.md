# 数据存储优化方案

## 1. 唯一事实来源

AUTO 路由选择、决策快照和结算结果只以现有 `auto_route_selections` 为事实表。旧草案中的 `auto_request_logs`、`auto_task_classifications`、`auto_task_features`、`auto_model_metrics`、独立反馈事实表均不再作为并行存储设计。

允许在事实表中记录请求/会话/租户等 ID、路由决策、模型 ID、成功率、延迟、成本、奖励和结构化特征；不允许记录 prompt、messages、response、summary、会话历史、关键词原文、嵌入向量或任何可逆内容特征。

## 2. 热 8 小时 + 月分区 + all view

- **热窗口**：最近 8 小时，服务于结算、近期监控和待分析样本查询。
- **月分区**：`auto_route_selections` 依据 `partition_date` 按月分区；月分区是历史存储布局，不是新的事实表。
- **统一 all view**：提供 `auto_route_selections_all`（migration 656）作为跨热窗口与历史分区的统一读取入口。view 只做 `UNION ALL`/父表透传，不复制行、不保存内容。
- **默认分区**：继续作为月分区未及时创建时的写入保护；它不是长期热存储替代品。

所有查询应优先通过事实表父表或 all view，并带时间范围；不要求业务代码自行拼接分区。

## 3. 结构化特征

特征必须是不可逆、低敏感、可版本化的字段，例如：语言枚举、长度桶、上下文长度桶、代码/数学/表格标记、轮数桶、延迟/成本敏感标记、特征版本和 hash。不要保存关键词列表、截断文本、摘要、原始 token 或 embedding。

## 4. 标注与训练数据

人工标注和训练导出均从 `auto_route_selections` 派生，只复制行 ID、决策元数据、结构化特征及标注元数据。标注队列是工作队列/派生索引，不是第二事实源；完成后的标签必须能关联回事实行。

## 5. 保留和查询

- 热窗口：8 小时，重点用于实时结算和诊断。
- 月分区：按合规和训练需要保留；具体月份与清理周期由运维策略配置，不在此承诺永久保留。
- 聚合统计：可按日/月派生，删除明细前须确保仍可审计的指标已落入受控聚合。
- 备份：只备份元数据、结构化特征和必要的标签/模型版本，不备份正文。

## 6. 成本口径

存储成本取决于实际请求量、字段宽度、索引、分区保留和云厂商价格。文档不再给出未经测量的固定美元金额或“99%+”节省结论；上线前用生产样本测量行宽、增长率、索引占用和保留周期。
