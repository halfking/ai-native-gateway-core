# ML 模型训练管道

## 初期模型策略

初期不以原始 prompt/messages/response/summary 或文本编码器为训练输入。训练数据只来自 `auto_route_selections` 与已审核人工标签，输入是版本化的结构化特征：语言枚举、长度/上下文长度/轮数桶、代码/数学/表格/多媒体标志、意图/领域枚举、复杂度桶、延迟/成本敏感标志，以及必要的缺失值标记。

首期优先选择可解释、易部署的结构化特征模型，例如逻辑回归、线性分类器、朴素贝叶斯或小型梯度提升/树模型。规则引擎仍是冷启动和失败回退路径。只有在结构化特征模型的离线/线上 shadow 结果证明不足时，才另行评审文本模型；这不属于首期交付前提。

## 数据来源与边界

```text
auto_route_selections（唯一事实表）
  + 已审核标签（selection_id 关联）
  -> 结构化特征导出
  -> 训练/验证/测试切分
  -> 模型评估
  -> shadow 灰度
```

导出集必须包含 dataset version、feature schema version、标签来源、时间范围、质量门槛和事实行 ID。不得导出或复制 prompt、messages、response、summary、关键词原文、截断正文、embedding 或可逆特征。

## 训练与评估

- 按时间切分，避免同一请求/会话泄漏到多个集合。
- 对类别不平衡报告 macro-F1、每类召回率、混淆矩阵和校准误差，不只看 accuracy。
- 以人工审核标签为主评估集；用户覆盖、重试、错误和 reward 作为辅助信号，不自动视为黄金标签。
- 评估必须同时比较规则基线、结构化模型和（如启用）免费池 shadow 结果。
- 质量、延迟、内存和成本门槛均为待实测门槛，不承诺固定准确率或推理时间。

## 模型注册与发布

模型版本记录应关联 dataset/schema version、训练时间、特征顺序、类别映射、评估指标和回滚版本。发布顺序为离线验证 -> shadow -> 小流量灰度 -> 扩大流量；任何回归都回退到规则/基础排序。ONNX 只是可选的部署格式，不能改变数据边界。

## 增量训练

按固定时间窗或新增已审核标签数量触发。每次训练保留可复现的数据快照和配置，禁止在线学习直接修改生产模型。训练日志只记录聚合指标和版本信息，不记录正文或可逆样本内容。
