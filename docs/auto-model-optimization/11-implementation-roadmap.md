# AUTO 模型优化实施路线图

## 交付原则

本路线图只描述文档批准的实施顺序，不代表生产 Go/SQL 已修改。唯一事实表是现有 `auto_route_selections`；存储采用最近 8 小时热窗口、按月分区和统一 all view。全流程不持久化 prompt、messages、response、summary 或可逆内容特征。

## 阶段一：事实链路与结构化特征

- [ ] 对照现有 migration 和 writer，确认 `auto_route_selections` 字段、结算与月分区状态。
- [ ] 确认热 8 小时查询路径和 all view 语义，避免创建平行事实表。
- [ ] 定义 feature schema：枚举、桶、布尔值、版本和不可逆 hash。
- [ ] 建立规则基线、指标和脱敏审查。
- [ ] 验收：写入/结算可追踪，查询不依赖正文，结构化特征 schema 可版本化。

## 阶段二：人工标注与数据集

- [ ] 从事实表派生标注队列，只传递 selection ID、路由元数据、结构化特征和标注元数据。
- [ ] 低置信度、分歧、异常 reward、用户覆盖/重试/错误及分层抽样触发标注。
- [ ] 使用双标/抽检和审核状态形成高质量标签。
- [ ] 验收：标注系统不复制正文，标签可回溯到事实行，训练导出具备 dataset/schema version。

## 阶段三：结构化特征模型

- [ ] 训练规则可解释的线性/树模型，建立时间切分的离线评估。
- [ ] 比较规则基线、结构化模型和免费池 shadow 的质量、延迟、错误率与成本。
- [ ] 先 shadow，随后小流量灰度；模型失败或低置信度回退规则。
- [ ] 验收：按 macro-F1、每类召回、校准、P95、资源和回退率设实测门槛，不预设未经验证的准确率。

## 阶段四：免费池与低价后备

- [ ] 运行时同步供应商官方免费资格、价格和限流状态，记录配置版本和复核时间。
- [ ] 免费池默认 shadow，不作为容量或永久免费承诺。
- [ ] 配置预算可控的低价直连后备，以及本地规则/模型最终降级。
- [ ] 验收：配额/价格变化可熔断，免费池异常不影响主链路，月成本由真实账单测量。

## 阶段五：发布与运营

- [ ] 模型包校验 feature schema、类别映射和版本后再加载。
- [ ] 建立灰度、回滚、数据保留、指标告警和月度供应商复核。
- [ ] 监控事实表增长、热窗口、月分区、all view 查询、settle 延迟、reward、模型质量和预算。
- [ ] 验收：无平行事实表、无正文落盘、可审计可回滚。

## 风险

| 风险 | 应对 |
|---|---|
| 供应商免费池或价格变化 | 动态基准、官方复核、shadow、低价直连后备 |
| 标签偏差 | 双标、抽检、时间切分、审核门槛 |
| 特征泄露 | 固定 schema、不可逆字段审查、日志和缓存检查 |
| 模型回归 | 规则基线、灰度、原子切换与快速回滚 |
| 分区遗漏 | 默认分区保护、月度预创建和 all view 统一读取 |
