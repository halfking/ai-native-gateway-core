## P1风险1: 429处理机制统一

### 🎯 问题描述

**现状冲突**:
- **旧机制**: `ratebackoff.go` 对绑定级429执行**固定3分钟冷却**
- **新机制**: Token桶方案要求**1分钟探测 + 渐进恢复**
- **冲突**: 时序重叠，旧机制会阻止新机制的探测

### ✅ 解决方案

#### 方案A: 统一到RateLimitHandler（推荐）

**设计**:
```
┌─────────────────────────────────────────────┐
│     RateLimitHandler (新的统一入口)          │
│  - 接管所有429/并发错误处理                 │
│  - 废弃ratebackoff.go的3分钟冷却            │
│  - 实现渐进探测 + 批次限流                  │
└─────────────────────────────────────────────┘
          │
          ├─→ ProbeScheduler (探测调度)
          │    ├─ 1min初始探测
          │    ├─ 10%→25%→50%→75%→100%渐进
          │    └─ 批次限流（同provider最多3个桶同时探测）
          │
          └─→ BucketStateManager (状态管理)
               ├─ AVAILABLE (正常)
               ├─ RATE_LIMITED (限流中，流量=0%)
               ├─ PROBING (探测中，流量=10%→100%)
               └─ RECOVERING (恢复中，流量<100%)
```

**迁移步骤**:
1. **Phase 1**: 新旧并行
   - RateLimitHandler优先处理429
   - ratebackoff.go只处理非429的速率问题
   - 通过feature flag控制

2. **Phase 2**: 全量切换
   - 观察1周，确认新机制稳定
   - 关闭旧机制
   - 删除ratebackoff.go中的429处理代码

3. **Phase 3**: 清理
   - 移除feature flag
   - 更新文档

**关键代码位置**:
- 修改: `domains/streaming/executors/ratebackoff.go:ObserveWithPace()`
- 新增: `internal/routing/ratelimit_handler.go`
- 配置: `ENABLE_NEW_RATELIMIT_HANDLER=true` (环境变量)

**兼容性保证**:
- ✅ 保留旧表和字段
- ✅ 渐进迁移，支持回滚
- ✅ 不影响现有断路器逻辑

## P1风险2: 探测协同机制

### 🎯 问题描述

**场景**: 上游真限流时（如OpenAI账户级429）
- 同provider的100个桶**同时探测失败**
- 全部进入更长探测间隔（1min→2min→4min）
- **恢复延迟**: 从预期1分钟延长到5-10分钟

### ✅ 解决方案

#### 方案: 分层探测 + 成功触发机制

**设计原理**:
```
同一Provider下的桶 = 共享限流命运
├─ 限流时：一个桶探测 = 代表全体探测
├─ 恢复时：一个桶成功 = 通知全体加速
└─ 避免：100个桶同时探测 = 浪费配额
```

**具体实现**:

#### 1. 探测代表选举
```go
type ProbeCoordinator struct {
    providerBuckets map[string][]*TokenBucket  // provider_id → 桶列表
    probeLeaders    map[string]*TokenBucket    // provider_id → 当前探测代表
    mu              sync.RWMutex
}

// 为每个provider选举一个探测代表
func (pc *ProbeCoordinator) SelectProbeLeader(providerID string) *TokenBucket {
    buckets := pc.providerBuckets[providerID]
    
    // 优先级：
    // 1. 历史成功率最高的桶
    // 2. 最近使用的桶（热桶）
    // 3. 随机选择（避免饥饿）
    
    sort.Slice(buckets, func(i, j int) bool {
        return buckets[i].SuccessRate() > buckets[j].SuccessRate()
    })
    
    return buckets[0]  // Top桶作为代表
}
```

#### 2. 成功触发广播
```go
// 探测代表成功后，触发同provider其他桶加速恢复
func (pc *ProbeCoordinator) OnProbeSuccess(bucket *TokenBucket) {
    providerID := bucket.ProviderID
    
    // 广播给同provider的其他桶
    for _, otherBucket := range pc.providerBuckets[providerID] {
        if otherBucket.ID == bucket.ID {
            continue
        }
        
        if otherBucket.State == StateRateLimited {
            // 加速恢复：直接进入PROBING状态，从10%开始
            otherBucket.TransitionTo(StateProbing, 0.10)
            log.Info("加速恢复", "bucket", otherBucket.ID, "trigger_by", bucket.ID)
        }
    }
}
```

#### 3. 批次限流
```go
// 同一时刻，同一provider最多3个桶在探测
func (pc *ProbeCoordinator) CanProbe(bucket *TokenBucket) bool {
    providerID := bucket.ProviderID
    currentProbing := 0
    
    for _, b := range pc.providerBuckets[providerID] {
        if b.State == StateProbing {
            currentProbing++
        }
    }
    
    const MaxConcurrentProbes = 3
    return currentProbing < MaxConcurrentProbes
}
```

**时序图**:
```
时刻T0: OpenAI账户级429
├─ 100个桶全部进入RATE_LIMITED状态
│
时刻T0+1min: 探测代表开始
├─ Bucket#1 (代表) → 发起10%流量探测
├─ Bucket#2-100 → 等待
│
时刻T0+1min+5s: 代表探测成功
├─ Bucket#1 → 25%流量
├─ 触发广播 → Bucket#2, #3 立即进入PROBING(10%)
├─ Bucket#4-100 → 继续等待
│
时刻T0+2min: 全量恢复
├─ Bucket#1-3 → 全部达到100%
└─ 逐批唤醒Bucket#4-100
```

**关键参数**:
- `MaxConcurrentProbes`: 同provider同时探测桶数上限 = **3**
- `ProbeInterval`: 代表探测间隔 = **1分钟**
- `BroadcastDelay`: 成功广播延迟 = **5秒**（避免惊群）

## P1风险3: 桶懒加载和LRU淘汰

### 🎯 问题描述

**内存爆炸风险**:
- 1 provider × 100 credentials × 500 models = **50,000个桶**
- 每桶2KB（状态+指标+历史） = **100MB基础**
- 包含历史窗口 = **500MB+**

### ✅ 解决方案

#### 方案: 懒加载 + 两级LRU + 定期清理

**架构**:
```
┌────────────────────────────────────────────┐
│      TokenBucketManager                    │
│  ┌──────────────────────────────────────┐ │
│  │   Hot Buckets (常驻内存)             │ │
│  │   - 最近1小时使用过的桶              │ │
│  │   - 上限: 5000个桶 ≈ 10MB            │ │
│  │   - LRU淘汰到Warm层                  │ │
│  └──────────────────────────────────────┘ │
│  ┌──────────────────────────────────────┐ │
│  │   Warm Buckets (压缩存储)            │ │
│  │   - 最近24小时使用过的桶             │ │
│  │   - 上限: 20000个桶 ≈ 20MB           │ │
│  │   - 只保留核心指标，历史压缩         │ │
│  │   - LRU淘汰到数据库                  │ │
│  └──────────────────────────────────────┘ │
│  ┌──────────────────────────────────────┐ │
│  │   Cold Buckets (数据库)              │ │
│  │   - 超过24小时未使用的桶             │ │
│  │   - 定期清理（7天无活动→删除）       │ │
│  └──────────────────────────────────────┘ │
└────────────────────────────────────────────┘
```

**详细设计**:

#### 1. 懒加载
```go
func (m *TokenBucketManager) GetBucket(key BucketKey) *TokenBucket {
    // 1. 检查Hot层
    if bucket, ok := m.hotBuckets.Get(key); ok {
        return bucket
    }
    
    // 2. 检查Warm层
    if bucket, ok := m.warmBuckets.Get(key); ok {
        // 升温到Hot层
        m.hotBuckets.Add(key, bucket)
        return bucket
    }
    
    // 3. 从数据库加载
    bucket := m.loadFromDB(key)
    if bucket != nil {
        m.hotBuckets.Add(key, bucket)
        return bucket
    }
    
    // 4. 首次创建（懒加载的核心）
    bucket = m.createNewBucket(key)
    m.hotBuckets.Add(key, bucket)
    return bucket
}
```

#### 2. 两级LRU实现
```go
type LRUCache struct {
    capacity int
    items    map[BucketKey]*list.Element
    evictList *list.List
    mu       sync.RWMutex
    
    onEvict func(key BucketKey, bucket *TokenBucket)  // 淘汰回调
}

// Hot → Warm淘汰
hotLRU := NewLRUCache(5000, func(key, bucket) {
    warmLRU.Add(key, bucket.Compress())  // 压缩后降级
})

// Warm → DB淘汰
warmLRU := NewLRUCache(20000, func(key, bucket) {
    db.SaveBucket(bucket)  // 持久化
})
```

#### 3. 桶压缩策略
```go
type TokenBucket struct {
    // === 核心状态（不压缩） ===
    Key       BucketKey
    State     BucketState
    CurrentCapacity float64
    
    // === 指标（可压缩） ===
    Metrics   *BucketMetrics
    History   *RequestHistory  // 可压缩
}

// 压缩：只保留聚合指标，丢弃详细历史
func (b *TokenBucket) Compress() *TokenBucket {
    return &TokenBucket{
        Key:     b.Key,
        State:   b.State,
        CurrentCapacity: b.CurrentCapacity,
        Metrics: &BucketMetrics{
            SuccessRate: b.Metrics.SuccessRate,
            AvgLatency:  b.Metrics.AvgLatency,
            // 丢弃：详细的请求历史、逐分钟统计
        },
        History: nil,  // Warm层不保留详细历史
    }
}
```

#### 4. 定期清理任务
```go
// 每小时执行一次
func (m *TokenBucketManager) CleanupTask() {
    ticker := time.NewTicker(1 * time.Hour)
    
    for range ticker.C {
        now := time.Now()
        
        // 清理策略：
        // 1. Warm层：超过24小时未访问 → 数据库
        m.warmBuckets.ForEach(func(key, bucket) {
            if now.Sub(bucket.LastAccessTime) > 24*time.Hour {
                m.warmBuckets.Remove(key)
                db.SaveBucket(bucket)
            }
        })
        
        // 2. 数据库：超过7天无活动 → 删除
        db.DeleteInactiveBuckets(7 * 24 * time.Hour)
        
        // 3. 内存指标上报
        m.reportMemoryMetrics()
    }
}
```

**内存预算**:
| 层级 | 容量 | 单桶大小 | 总内存 |
|------|------|----------|--------|
| Hot  | 5,000桶 | 2KB | 10MB |
| Warm | 20,000桶 | 1KB | 20MB |
| **总计** | **25,000桶** | - | **30MB** |

**性能指标**:
- Hot层命中率目标: **>95%**（常用桶）
- Warm层命中率目标: **>3%**（偶尔使用）
- DB加载延迟: **<10ms**

## P1风险4: 分布式状态同步

### 🎯 问题描述

**多实例场景**:
- 3个网关实例同时运行
- 桶状态在各实例独立维护
- **问题**:
  1. 探测调度重复（3个实例同时探测同一个桶）
  2. 状态不一致（实例A认为可用，实例B认为限流中）
  3. 资源浪费（重复探测消耗配额）

### ✅ 解决方案

#### 短期方案: 进程内状态 + 定期同步（适用Stage 1-3）

**设计**:
```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  Instance A │  │  Instance B │  │  Instance C │
│  ┌────────┐ │  │  ┌────────┐ │  │  ┌────────┐ │
│  │ Buckets│ │  │  │ Buckets│ │  │  │ Buckets│ │
│  └────────┘ │  │  └────────┘ │  │  └────────┘ │
│      ↓      │  │      ↓      │  │      ↓      │
│  每30秒同步  │  │  每30秒同步  │  │  每30秒同步  │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┴────────────────┘
                        ↓
              ┌──────────────────┐
              │  PostgreSQL DB   │
              │  token_buckets   │
              │  - state         │
              │  - last_probe_at │
              │  - success_rate  │
              └──────────────────┘
```

**实现**:
```go
type BucketStateSyncer struct {
    db        *sql.DB
    localMgr  *TokenBucketManager
    interval  time.Duration  // 30秒
}

func (s *BucketStateSyncer) Start() {
    ticker := time.NewTicker(s.interval)
    
    for range ticker.C {
        // 1. 推送本地变更到DB
        s.pushLocalChanges()
        
        // 2. 从DB拉取其他实例的更新
        s.pullRemoteChanges()
    }
}

func (s *BucketStateSyncer) pushLocalChanges() {
    dirtyBuckets := s.localMgr.GetDirtyBuckets()  // 标记为"已变更"的桶
    
    for _, bucket := range dirtyBuckets {
        query := `
            INSERT INTO token_buckets (bucket_id, state, last_probe_at, success_rate, updated_at, instance_id)
            VALUES ($1, $2, $3, $4, $5, $6)
            ON CONFLICT (bucket_id) DO UPDATE SET
                state = EXCLUDED.state,
                last_probe_at = EXCLUDED.last_probe_at,
                success_rate = EXCLUDED.success_rate,
                updated_at = EXCLUDED.updated_at,
                instance_id = EXCLUDED.instance_id
            WHERE token_buckets.updated_at < EXCLUDED.updated_at  -- 只更新更新的状态
        `
        db.Exec(query, bucket.ID, bucket.State, bucket.LastProbeAt, 
                bucket.SuccessRate(), time.Now(), s.instanceID)
    }
    
    s.localMgr.ClearDirtyFlags()
}

func (s *BucketStateSyncer) pullRemoteChanges() {
    // 只拉取其他实例的最新更新
    query := `
        SELECT bucket_id, state, last_probe_at, success_rate, updated_at
        FROM token_buckets
        WHERE updated_at > $1 AND instance_id != $2
        ORDER BY updated_at DESC
        LIMIT 1000
    `
    rows := db.Query(query, s.lastSyncTime, s.instanceID)
    
    for rows.Next() {
        var bucketID, state string
        var lastProbeAt, successRate, updatedAt time.Time
        rows.Scan(&bucketID, &state, &lastProbeAt, &successRate, &updatedAt)
        
        // 更新本地状态（如果远程更新）
        bucket := s.localMgr.GetBucket(BucketKey(bucketID))
        if bucket.UpdatedAt.Before(updatedAt) {
            bucket.State = BucketState(state)
            bucket.LastProbeAt = lastProbeAt
            bucket.UpdatedAt = updatedAt
        }
    }
    
    s.lastSyncTime = time.Now()
}
```

**探测去重**:
```go
// 探测前检查：是否其他实例刚探测过
func (s *BucketStateSyncer) ShouldProbe(bucket *TokenBucket) bool {
    // 从DB查询最近探测时间
    var lastProbeAt time.Time
    query := `SELECT last_probe_at FROM token_buckets WHERE bucket_id = $1`
    db.QueryRow(query, bucket.ID).Scan(&lastProbeAt)
    
    // 如果任意实例在过去30秒内探测过，跳过
    if time.Since(lastProbeAt) < 30*time.Second {
        return false
    }
    
    return true
}
```

**容忍度**:
- ✅ 最多30秒状态延迟（可接受）
- ✅ 探测去重（避免浪费配额）
- ⚠️ 可能出现短暂不一致（如实例A限流，实例B尚未同步）

#### 长期方案: Redis共享状态（适用Stage 4+）

**设计**:
```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  Instance A │  │  Instance B │  │  Instance C │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┴────────────────┘
                        ↓
              ┌──────────────────┐
              │   Redis Cluster  │
              │  ┌─────────────┐ │
              │  │ Bucket State│ │  <-- 实时共享
              │  ├─────────────┤ │
              │  │ Probe Locks │ │  <-- 分布式锁
              │  ├─────────────┤ │
              │  │   Metrics   │ │  <-- 实时指标
              │  └─────────────┘ │
              └──────────────────┘
                        ↓
              PostgreSQL (持久化备份)
```

**核心特性**:
1. **实时状态共享**: 所有实例读写同一份Redis状态
2. **分布式锁**: 探测前获取锁，避免重复探测
3. **Pub/Sub广播**: 状态变更立即广播到所有实例

**实现示例**:
```go
// 探测前获取分布式锁
func (m *TokenBucketManager) ProbeWithLock(bucket *TokenBucket) error {
    lockKey := fmt.Sprintf("probe_lock:%s", bucket.ID)
    lock := redis.SetNX(lockKey, m.instanceID, 60*time.Second)
    
    if !lock {
        return ErrProbeInProgress  // 其他实例正在探测
    }
    defer redis.Del(lockKey)
    
    // 执行探测
    result := m.executeProbe(bucket)
    
    // 更新Redis状态
    redis.HSet(fmt.Sprintf("bucket:%s", bucket.ID), map[string]interface{}{
        "state": result.NewState,
        "last_probe_at": time.Now().Unix(),
        "success_rate": result.SuccessRate,
    })
    
    // 广播状态变更
    redis.Publish("bucket_state_changes", bucket.ID)
    
    return nil
}

// 订阅状态变更
func (m *TokenBucketManager) SubscribeStateChanges() {
    pubsub := redis.Subscribe("bucket_state_changes")
    
    for msg := range pubsub.Channel() {
        bucketID := msg.Payload
        
        // 从Redis拉取最新状态
        state := redis.HGetAll(fmt.Sprintf("bucket:%s", bucketID))
        
        // 更新本地缓存
        bucket := m.GetBucket(BucketKey(bucketID))
        bucket.State = BucketState(state["state"])
        bucket.LastProbeAt = time.Unix(state["last_probe_at"], 0)
    }
}
```

**迁移路径**:
1. **Stage 1-3**: 使用PostgreSQL定期同步
2. **Stage 4**: 引入Redis，双写（PG + Redis）
3. **Stage 5**: 完全切换到Redis，PG仅作备份

## 补充设计1: 数据库Schema

### 新增表

#### 1. token_buckets（Token桶状态表）

## 补充设计3: 错误处理策略

### 错误分类

#### 1. 可恢复错误（Retriable）
| 错误类型 | HTTP状态 | 特征关键词 | 处理策略 |
|---------|---------|-----------|----------|
| **速率限制** | 429 | "rate limit", "too many requests" | 触发RateLimitHandler，进入RATE_LIMITED状态 |
| **服务繁忙** | 503 | "overloaded", "capacity" | 重试，降低桶capacity到50% |
| **临时超时** | 504 | "timeout", "deadline" | 重试，记录延迟指标 |
| **并发超限** | 429 | "concurrent", "parallel" | 限流，避免并发探测 |

#### 2. 不可恢复错误（Non-Retriable）
| 错误类型 | HTTP状态 | 特征关键词 | 处理策略 |
|---------|---------|-----------|----------|
| **认证失败** | 401/403 | "invalid key", "unauthorized" | 标记桶为DISABLED，告警 |
| **模型不存在** | 404 | "not found", "model" | 标记桶为DISABLED |
| **参数错误** | 400 | "invalid parameter" | 不重试，返回客户端 |
| **余额不足** | 402/429 | "insufficient balance", "quota exceeded" | 标记凭据不可用，切换凭据 |

#### 3. 不确定错误（Uncertain）
| 错误类型 | HTTP状态 | 处理策略 |
|---------|---------|---------|
| **5xx通用错误** | 500-599 | 重试1次，失败后降低质量分数 |
| **网络错误** | - | 重试1次，记录连接问题 |
| **未知错误** | - | 保守处理，记录详细日志 |

### 错误处理流程

```go
func (h *RateLimitHandler) HandleError(err error, bucket *TokenBucket, ctx *RequestContext) error {
    errorType := h.classifyError(err)
    
    switch errorType {
    case ErrorTypeRateLimit:
        return h.handleRateLimit(err, bucket, ctx)
        
    case ErrorTypeTemporary:
        return h.handleTemporaryError(err, bucket, ctx)
        
    case ErrorTypePermanent:
        return h.handlePermanentError(err, bucket, ctx)
        
    case ErrorTypeUncertain:
        return h.handleUncertainError(err, bucket, ctx)
    }
}

func (h *RateLimitHandler) handleRateLimit(err error, bucket *TokenBucket, ctx *RequestContext) error {
    // 1. 解析限流时长（如果响应中包含Retry-After）
    retryAfter := h.parseRetryAfter(err)
    if retryAfter == 0 {
        retryAfter = 60 * time.Second  // 默认1分钟
    }
    
    // 2. 更新桶状态
    bucket.TransitionTo(StateRateLimited, 0.0)
    bucket.RateLimitUntil = time.Now().Add(retryAfter)
    bucket.RateLimitReason = err.Error()
    
    // 3. 调度探测
    h.probeScheduler.Schedule(bucket, retryAfter)
    
    // 4. 记录指标
    metrics.RecordRateLimit(bucket.ID, retryAfter.Seconds())
    
    // 5. 尝试切换桶（如果有其他可用桶）
    return ErrShouldFallback
}

func (h *RateLimitHandler) handlePermanentError(err error, bucket *TokenBucket, ctx *RequestContext) error {
    // 1. 禁用桶
    bucket.TransitionTo(StateDisabled, 0.0)
    
    // 2. 告警
    alerts.Send(AlertBucketDisabled, map[string]interface{}{
        "bucket_id": bucket.ID,
        "reason": err.Error(),
        "credential_id": bucket.CredentialID,
    })
    
    // 3. 不重试，直接返回错误
    return err
}
```

### 重试策略

#### 指数退避
```go
type RetryPolicy struct {
    MaxRetries int
    BaseDelay  time.Duration
    MaxDelay   time.Duration
    Jitter     float64
}

func (p *RetryPolicy) NextDelay(attempt int) time.Duration {
    if attempt >= p.MaxRetries {
        return 0  // 不再重试
    }
    
    // 指数退避: 1s → 2s → 4s → 8s
    delay := p.BaseDelay * time.Duration(1<<attempt)
    if delay > p.MaxDelay {
        delay = p.MaxDelay
    }
    
    // 添加随机抖动（避免惊群）
    if p.Jitter > 0 {
        jitter := time.Duration(float64(delay) * p.Jitter * (rand.Float64() - 0.5))
        delay += jitter
    }
    
    return delay
}

// 使用示例
policy := &RetryPolicy{
    MaxRetries: 3,
    BaseDelay:  1 * time.Second,
    MaxDelay:   10 * time.Second,
    Jitter:     0.3,  // ±15%随机抖动
}
```

```go
// 降级决策树
func (r *BucketRouter) SelectFallbackBucket(failedBucket *TokenBucket, req *Request) (*TokenBucket, error) {
    // 1. 同凭据下的其他桶
    sameCred := r.findBuckets(SameCredential(failedBucket.CredentialID), Available())
    if len(sameCred) > 0 {
        return r.selectBest(sameCred), nil
    }
    
    // 2. 同供应商下的其他凭据
    sameProv := r.findBuckets(SameProvider(failedBucket.ProviderID), Available())
    if len(sameProv) > 0 {
        return r.selectBest(sameProv), nil
    }
    
    // 3. 跨供应商降级（如Anthropic→OpenAI）
    crossProv := r.findBuckets(Compatible(req.ModelCapability), Available())
    if len(crossProv) > 0 {
        return r.selectBest(crossProv), nil
    }
    
    // 4. 无可用桶
    return nil, ErrNoAvailableBucket
}
```
