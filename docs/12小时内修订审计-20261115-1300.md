### P1（已修复落地）

1. **pkg/authplugin/casdoor/auth_provider.go:96** — `GetOAuthToken(username, password)` 调用错误  
   - **根因**: SDK该函数签名是OAuth2授权码模式 `GetOAuthToken(code, state)`——用户名被当授权码、密码被当state传给 `/api/login/oauth2_access_token` 的code兑换端点，**Casdoor密码登录必然失败**（且所有认证失败被吞成 `ErrInvalidCredentials`，无日志）  
   - **修复**: 改调 `GetOAuthTokenByPassword(username, password)` (Resource Owner Password Credentials Grant)  
   - **前提**: Casdoor应用配置需勾选 `password` grant type  
   - **影响**: phase3 Casdoor集成在任何环境无法工作（包括已手工建表的252）

2. **migrations/036_add_auth_id_mapping.sql** — 撞号死文件，无投递通道  
   - **根因**: phase3把迁移放顶层 `migrations/036_*`（无执行通道：不在deploy pending-scanner、不在installer清单、不在boot ensure自愈链），唯一执行方式=文档里的手工psql

### P2（遗留，需owner决策）

3. **domains/streaming/routing_errors.go 分类器字串匹配脆弱** (eea844247)  
   - canceled→499、circuit open→503、42P01→schema_error三臂均靠 `strings.Contains` 匹配，未用 `errors.Is(ctx.DeadlineExceeded)` / `errors.Is(ErrCandidatesCircuitOpen)`  
   - 自定义包装类型若 `Error()` 不含字串即漏网回 `routing_database_error` 兜底（误归因）  
   - **建议**: 补 `errors.Is` 判据

   - 半开探测者若经 `waitForRetry` 的ctx cancel路径返回（client.go:2205附近），**不调RecordFailure** → halfOpen恒true且openUntil已过 → AllowProbe永拒 → 全员永久秒败503（直至进程重启）  
   - **建议**: 统一探测失败路径走RecordFailure

5. **plugin-runtime/reconciler/reconciler.go 成功即Reset使退避计数失真** (c94842b7f)  
   - `executeAction` 里 Restart/Start返回nil即Reset（reconciler.go:432-436, 444-448）——start API成功≠插件健康  
   - 慢崩溃环（每次start成功、数分钟后崩）RetryCount永停在1，MaxRetries=10不可达；仅剩crashTracker 1h窗闸兜底，崩溃频率 <1次/6min时**永不禁用**，退避终态名存实亡  
   - **建议**: Reset改为"持续健康N分钟后再清"

6. **domains/promptinjection/detector.go LLM判官fail-open** (f3249a3c4)  
   - LLM调用失败仅 `slog.Warn` 后继续用规则分（detector.go:227-243）——**安全判官默认静默放行**（无开关、无降级计数指标）  
   - **成本无控制**: policy开启LLM检测时，每次Detect（经hooks/promptinjection进请求路径）必调一次LLM，无输入去重/采样/缓存（hash算了只用于落库）  
   - **超时**: `http.Client{Timeout: 30s}` 硬编码，串行在请求路径最多加30s尾延迟  
   - **建议**: fail-closed模式开关 + 采样率配置 + 超时可配置

7. **domains/promptinjection/detector.go 判官可被元注入** (f3249a3c4)  
   - `buildLLMDetectionPrompt` 将原始输入裸嵌 `---` 分隔内，无转义——攻击者可直接对判官做元注入让 `is_injection=false`  
   - **建议**: prompt注入转义或使用结构化输入（JSON schema）
