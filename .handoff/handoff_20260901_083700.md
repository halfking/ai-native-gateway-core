完成 P2-D（数据准确性监控）的实现：

  通道淹没。

## 3. 设计要点（Key Design Decisions）

### 3.1 双阈值（pct AND abs）

单看百分比会被小 bucket 噪声淹没：4 行 bucket 多 1 行就是 25%。
因此 `MVDriftAlertPct = 5.0` 与 `MVDriftAlertAbs = 100` 必须**同时**超过才
计为 breach。

### 3.2 In-process 与 cron 的差异化阈值

| 路径 | 运行频率 | Breach 阈值 | Abs 阈值 |
|------|----------|-------------|----------|
| In-process | 每 10 分钟（144 次/天） | >= 3 buckets | >= 1000 req |
| Cron | 每天 1 次 | >= 1 bucket | >= 100 req |

In-process 阈值更严苛以避免 IM 风暴；cron 阈值更宽松以保留单个
tail-bucket 异常的信号能力。两个阈值都是常量，逻辑都在
`bg/mv_consistency.go` 和 `scripts/monitoring/verify-mv-consistency.sh`
的注释里清晰标注。

### 3.3 冷却（cooldown）与升级（escalation）

`shouldFireDriftAlert` 的二阶门控（`bg/materialized_view_refresher.go`）：

- **升级**：breach_count 比上一周期增长 → 立即告警（哪怕在冷却期）。
- **稳态**：breach_count 不变但距上次告警 ≥ 30 min → 重新告警一次。
- **静默**：稳态 + 冷却期内 → 不告警，但仍写入指标。

30 min 冷却是 admin 端 `mvFreshnessBudget`（15 min）的 2 倍，确保持续
breach 每 30 min 必触达 IM 一次。

### 3.4 共享 IM 通道

drift 告警与 refresh-failure 告警共享 `gLarkCh`（同一个 webhook、同一个
IM 群），但使用**不同的 notification.Message ID** 与标题前缀（"⚠️ 物化视图
数据一致性告警 (P2-D)"），便于在 IM 客户端按标题分类过滤。

## 4. Prometheus 指标清单

| 指标 | 类型 | 标签 | 含义 |
|------|------|------|------|
| `routing_analytics_mv_drift_pct` | gauge | `view` | 单次检查中最大的 pct 漂移 |
| `routing_analytics_mv_drift_abs` | gauge | `view` | 单次检查中最大的绝对漂移 |
| `routing_analytics_mv_breach_count` | gauge | `view` | 超过双阈值的 bucket 数 |
| `routing_analytics_mv_consistency_last_unix` | gauge | `view` | 上次成功检查的 unix 时间戳 |
| `routing_analytics_mv_consistency_errors_total` | counter | `view`, `reason` | 检查失败计数 |

`view` 标签是闭枚举：`routing_analytics_7d` 或 `routing_audit_summary_7d`。
`init()` 在包加载时预注册两个 view 的零值序列，避免 `/metrics` 首次
scrape 时缺数据。

`TestMaterializedViewRefresher_ShouldFireDriftAlert`）：

1. `nil_callback_never_fires` — 未接 callback 时绝不告警
2. `below_floors_never_fires` — breaches < 3 或 abs < 1000 时不告警
3. `first_breach_fires_immediately` — 首次 breach（lastDriftAlert 为零值）
   立即告警
4. `escalating_fires_within_cooldown` — 升级场景下即使在冷却期也告警
5. `steady_state_within_cooldown_does_not_fire` — 稳态 + 冷却期内不告警
6. `steady_state_past_cooldown_refires` — 稳态但冷却已过重新告警
7. `exactly_at_cooldown_fires` — 边界 `>=` 行为
8. `just_below_cooldown_does_not_fire` — 差 1ns 不告警（防 thrash）
