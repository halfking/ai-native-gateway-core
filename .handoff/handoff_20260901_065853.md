```go
// 每个刷新周期（10分钟）尝试拿 Redis 锁
if handle := r.acquireDistLock(ctx); handle != nil {
    defer handle.Release(ctx)
    if handle.IsLeader() {
        // 赢家：执行刷新，跳过 PG advisory lock（useAdvisoryLock=false）
        r.refreshView(ctx, "routing_analytics_7d", false)
        r.refreshView(ctx, "routing_audit_summary_7d", false)
    } else {
        // 输家（follower）：直接返回，不刷新
        return
    }
} else {
    // Redis 不可用/未配置：走原有的 PG advisory lock 路径（useAdvisoryLock=true）
    r.refreshView(ctx, "routing_analytics_7d", true)
    r.refreshView(ctx, "routing_audit_summary_7d", true)
}
```

## 技术设计要点

### 令牌桶（Token Bucket）协调机制

**原理**：
- 每个刷新周期（10 分钟）发放一个"令牌"
- 多实例竞争 Redis 锁（`SETNX + TTL`），赢家拿到令牌执行刷新
- 输家（follower）立即返回，不排队等待（非阻塞）
- 锁自动续约（distlock 内部每 TTL/3 续约一次）
- 进程崩溃时锁自动过期（TTL=6分钟），无需手动清理

**两层锁设计**：
1. **Redis 锁（首选）**：
   - 跨任意数量实例协调（不依赖 PostgreSQL）
   - 自愈能力强（TTL 自动过期）
   - 使用现有 `fpSlotRedis` 连接，零额外成本
   
2. **PostgreSQL advisory lock（兜底）**：
   - Redis 不可用/未配置时自动启用
   - 与升级前行为完全一致
   - 单数据库协调（canary + prod 共享 DB）

**降级路径**：
```
Redis 可用且 Acquire 成功 → Redis 分布式锁
    ↓ 失败（网络问题/未配置/disabled）
PostgreSQL advisory lock（原有机制）
```

### 与现有系统集成

**复用组件**：
- `admin/distlock`：已验证的 Redis 锁实现（用于 title-gen per-session lock）
- `fpSlotRedis`：session/pending-response 缓存用的 Redis 连接
- `gLarkCh`：飞书通知通道（P1-B 失败告警）

**兼容性保证**：
- `SetDistLock(nil)` 或 `mgr.Enabled() == false`：透明降级，与原有行为一致
- 不调用 `SetDistLock()`：仍走 PG advisory lock，完全向后兼容
- 现有测试套件全部通过，无破坏性修改

## 已知限制和改进方向

### 当前限制
1. **锁 TTL 静态配置**：`mvRefreshDistLockTTL = 6*time.Minute`，如果后续调大 `RefreshTimeout`（当前 5 分钟），需要同步调大 TTL
2. **无主动健康检查**：依赖 distlock 的续约机制，进程假死可能导致锁占用直到 TTL 过期
3. **无 Prometheus 指标**：Redis 锁本身的成功/失败、续约次数等未暴露（distlock 包有指标，但未在 refresher 层聚合）

### P2 改进方向（非阻塞）
1. **添加告警规则**（可选）：
   - `llmgw_analytics_refresh_total{result="failed"}` 持续 > 阈值
   - `distlock_acquire_total{scope="mv_refresh",outcome="failed"}` 异常飙升
   
2. **视图刷新频率优化**（Phase 2）：
   - 当前固定 10 分钟一次全量刷新
   - 可考虑增量刷新（只刷新最近 1 小时的新数据）
   - 或基于数据变化率动态调整刷新间隔
   
3. **多视图并行刷新**（Phase 3）：
   - 当前 `routing_analytics_7d` 和 `routing_audit_summary_7d` 串行刷新
   - 可改为并行（两个独立的 goroutine + 各自的 token）
