## 技术债务与观察项

### 1. 物化视图刷新器的增强机会

虽然 P1-B 已完成基础告警，但还有改进空间：

**当前实现的限制**:
- `failureCount` 是全局计数，不区分具体视图
- 如果 `routing_analytics_7d` 失败 1 次，`routing_audit_summary_7d` 失败 1 次，不会触发告警
- 但应该分别跟踪每个视图的失败次数

**建议改进**（可作为 P3 任务）:
```go
// 将 failureCount 改为 map，分别跟踪每个视图
failureCount map[string]int  // viewName -> count
```

### 2. Prometheus 指标缺失

当前只有日志和 Lark 告警，缺少 Prometheus 指标：

**建议添加**（可作为 P3 任务）:
```go
var (
    mvRefreshDurationSeconds = promauto.NewHistogramVec(...)  // 刷新耗时
    mvRefreshErrorsTotal = promauto.NewCounterVec(...)        // 失败次数
    mvRefreshSkippedTotal = promauto.NewCounterVec(...)       // 跳过次数（锁竞争）
    mvRefreshSuccessTimestamp = promauto.NewGaugeVec(...)     // 最后成功时间
)
```

### 3. sessionv2mirror 持续 WARN

**现象**: 245/154 持续刷 `sessionv2mirror: V2 shadow write failed` WARN  
**原因**: `request_logs_bodies ON CONFLICT` 无唯一约束（SQLSTATE 42P10）  
**归属**: 并行会话的 session v2 mirror 工作，不属于本次任务域  
**建议**: 提醒对应会话处理
