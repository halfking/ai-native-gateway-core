### 1. 核心集成（commit: `51d05bddf`）

#### `scripts/pg-table-copy.sh`：新增 PHASE 8.5

在 PHASE 8 VERIFICATION 末尾、SUMMARY 之前新增独立子段，无条件 fork `apply-routing-mv-fixup.sh`。整体位于 `if ! $DRY_RUN` 块之外，**dry-run 也能打印计划但不会触发 fixup**。

**Skip 条件（按顺序判定）**：
1. `DRY_RUN=true` → `[DRY-RUN] Would apply routing-mv fixup to $TGT_CONTAINER (skipped)`
2. `DATA_ONLY=true` → `skip: --data-only mode (fixup is a schema operation)`
3. `! TGT_IS_LOCAL_DOCKER` → `skip: target is not a local docker container (fixup is local-only)`
4. 全部不命中 → 通过 `PG_FIXUP_CONTAINER/USER/PASS/DB` env 注入参数 fork fixup 子进程

**关键设计**：
- 新增 `FIXUP_FAILED` 标志（与 `SCHEMA_IMPORT_FAILED`、`DATA_IMPORT_FAILED` 并列），通过 SUMMARY 阶段的 `|| $FIXUP_FAILED` 统一 fail-fast。
- 新增 `--fixup-script <path>` flag 允许 CI 或自定义部署覆盖默认路径。
- 凭据仅通过命令前缀 env vars（`PG_FIXUP_PASS=... bash fixup.sh`）传给子进程，**不污染父 shell** — 经 mock 测试验证父 shell 的 `PG_FIXUP_PASS` 子进程退出后仍为空。
