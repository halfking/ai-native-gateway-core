# 路由总览页数据说明

这一页回答「一笔请求为什么被派给某个模型」：把选路过程拆开给你看。

## 核心概念

- **候选**＝按条件筛出来可以接这笔请求的凭据。
- **可路由**＝候选里当前真正能用的那部分（健康、未被禁用、未在冷却期）。
- **决策记录**＝每一次真实请求的选路结果流水。

## 统计口径

- 「可路由数」按当前时刻判定：同一候选一分钟前可用、一分钟后进入冷却，数字随之变化。
- 决策明细按「层级」列出候选顺序：排在前面的优先接单；前面的失败时按顺序向后回退。
- 「回退」＝首选候选失败后换下一个候选接手；一次请求最多只有一条最终成功记录。

## 页签说明

- 实时决策：发起一次试算，看「如果现在来一笔请求会怎么选」。
- 凭据监控 / 探测健康：上游凭据的可用性详情。
- 自动运营：系统自动调参与分析工具。

## 数字对不上时怎么自查

1. 试算结果与实际记录不同：试算是「当下推演」，实际决策发生在过去；冷却状态、临时禁用都会让两者不同。
2. 决策条数与请求记录页对不上：决策页只记选路事件；没有进入选路的请求（如被前置拦截）不会出现在这里。
3. 「可路由 = 0」但请求仍成功：说明系统走了跨供应商回退或备用通道，可在决策明细里看到回退链。
4. 时间差：冷却解除、凭据恢复都是分钟级变化，两端查询时间差几分钟结果就不同。
