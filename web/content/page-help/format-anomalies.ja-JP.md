# 形式異常ページのデータ説明

このページでは、2種類の「おかしい」状況を確認します。上流から返された**形式**が突然変更された、またはリクエストが**エラー**になった場合です。目的は、ユーザーより先にサプライヤー側の変化を検知することです。

## 2つのデータソース（2つのタブ）

- **レスポンス形式の異常**：上流のレスポンス構造が想定どおりでない場合（フィールドの欠落、型の変更、Tokenの抽出失敗など）。
- **リクエストエラー**：リクエスト自体が失敗した場合（タイムアウト、拒否、パラメータ誤りなど）。

ページ上部のバッジの数字＝2つのデータソースの「未解決」件数**の合計**。一覧ページの「未解決」フィルターと同じ基準です。

## 「未解決／解決済み」の判定基準

- 新たに検知された異常はデフォルトで「未解決」。人による確認と対応完了後に「解決済み」になります。
- 「解決済み」は自動的に消えることを意味せず、人による確認済みの状態です。「確認済み」と「未確認」を区別するために使用します。

## 数字が一致しない場合のセルフチェック

1. バッジの件数と一覧の件数が一致しない場合：まずフィルター（「未解決のみ」が選択されているか、時間範囲）を確認してください。
2. サプライヤーの改修により、同じ種類の異常がまとめて発生することがあります：「異常タイプ」でグループ化し、同じ種類の異常は通常同じ原因です。
3. プローブトラフィックと実トラフィックの双方から記録が生成される可能性があります：影響を判断する前に、異常がどちらのトラフィックから発生했かを確認してください。
4. 異常が自動的に復旧した場合（サプライヤーが以前の状態に戻した場合）、「解決済み」とは自動的には表示されません。人による確認が必要です。これは意図的な設計であり、見過ごされやすい変更を検知できるようにするためです。
