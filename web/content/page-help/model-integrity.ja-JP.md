# モデル完全性監視ページのデータ説明

このページでは、「上流から配信された回答が完全か、こっそり置換されていないか」を監視します。置換、切り詰め、空の応答、重複、フィンガープリントのドリフトはいずれも完全性の異常として扱います。

## 2つのタブ

- **完全性イベント**：異常ごとに1件を記録します（種類、重大度、対象のモデル／プロバイダー、解決済みかどうか）。
- **フィンガープリントのドリフト**：同じモデルの「行動フィンガープリント」が時間とともにどう変化したかを示します。ドリフトが大きい場合は、上流側がこっそり実装を変更したことを示唆します。

## 集計基準の説明

- イベント総数 / 未解決 / 重大イベントは、選択した集計ウィンドウに基づいて算出します。ウィンドウは変更できます。
- 「重大」＝回答の正確性または安全に影響を及ぼす異常（例：モデルの置換）。「切り詰め／空の応答」は通常は中程度です。
- フィンガープリントのドリフトは**相対ベースライン**との比較です。ベースラインを更新すると、過去のドリフト判定は再計算されます。

## 数字が合わない場合のセルフチェック

1. イベント数が形式異常ページと異なる場合：2つのページ，关注する異常の種類が異なります（このページは「回答の完全性」、形式異常ページは「応答形式」を対象としており、共通点guided 있지만一致するわけではありません）。
2. 「未解決」が減らない場合：人による確認と対応が必要です。形式異常ページと同様、自動回復だけでは自動的に事案をクローズできません。
3. フィンガープリントが突然すべてドリフトした場合：まず、直前にベースラインを更新したか、集計ウィンドウを切り替えたかを確認します。その上で、上流側 collectively が実装を変更した可能性を疑います。
