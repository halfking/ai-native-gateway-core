# 请求阶段树页数据说明

这一页把一笔请求的「一生」拆成十个阶段，按时间轴排开，出问题时能立刻看到卡在哪一步。

## 十个阶段（按发生顺序）

鉴权/限流 → 脱敏 → 审批 → 注入检测 → 路由 → 压缩 → 供应商/令牌池 → 首字节 → 脱敏回填 → 计量/回复。

- 发送轨（左→右）是请求出去的过程；接收轨（右→左）是答案回来的过程。
- 一笔请求不一定走全部阶段：没触发审批的请求，「审批」阶段显示「不适用」。

## 七种阶段状态

未到达 / 进行中 / 已完成 / 不适用 / 失败 / 有告警 / 未测量。

- 「失败」＝这一步把请求拦下来了（例如注入检测命中、审批拒绝）。
- 「有告警」＝放行了但记录了可疑点。
- 「未测量」＝该阶段没有计时数据，不代表失败。

## 阶段耗时

- 每个阶段的横条长度代表它花了多久；「首字节」到「回复」是模型生成答案的时间，通常最长。
- 总耗时 ≠ 各阶段简单相加：有的阶段并行发生。

## 数字对不上时怎么自查

1. 「进行中」的请求阶段时长还在涨，完成后数字才固定。
2. 找不到某笔请求先查过滤器：页面只显示当前过滤与时间窗内的请求。
3. 「未测量」阶段多说明该请求走了旧版流水格式（早期数据），属历史数据形态，不是系统故障。
4. 失败请求以「失败阶段」为准：定位问题时先看第一个「失败」的阶段，它之后的阶段通常不会执行。
