# 請求階段樹頁資料說明

這一頁把一筆請求的「一生」拆成十個階段，按時間軸排開，出問題時能立刻看到卡在哪一步。

## 十個階段（按發生順序）

鑑權/限流 → 脫敏 → 審批 → 注入檢測 → 路由 → 壓縮 → 供應商/令牌池 → 首位元組 → 脫敏回填 → 計量/回覆。

- 傳送軌（左→右）是請求出去的過程；接收軌（右→左）是答案回來的過程。
- 一筆請求不一定走全部階段：沒觸發審批的請求，「審批」階段顯示「不適用」。

## 七種階段狀態

未到達 / 進行中 / 已完成 / 不適用 / 失敗 / 有告警 / 未測量。

- 「失敗」＝這一步把請求攔下來了（例如注入檢測命中、審批拒絕）。
- 「有告警」＝放行了但記錄了可疑點。
- 「未測量」＝該階段沒有計時資料，不代表失敗。

## 階段耗時

- 每個階段的橫條長度代表它花了多久；「首位元組」到「回覆」是模型生成答案的時間，通常最長。
- 總耗時 ≠ 各階段簡單相加：有的階段並行發生。

## 數字對不上時怎麼自查

1. 「進行中」的請求階段時長還在漲，完成後數字才固定。
2. 找不到某筆請求先查過濾器：頁面只顯示當前過濾與時間窗內的請求。
3. 「未測量」階段多說明該請求走了舊版流水格式（早期資料），屬歷史資料形態，不是系統故障。
4. 失敗請求以「失敗階段」為準：定位問題時先看第一個「失敗」的階段，它之後的階段通常不會執行。
