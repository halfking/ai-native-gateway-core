# 会话分析总览页数据说明

这一页回答「大家怎么在用」：会话有多少、平均多长、花在哪些任务上、趋势如何。

## 核心指标卡

| 卡片 | 含义 | 算法 |
| --- | --- | --- |
| 会话总数 | 时间段内的对话数量 | 去重计数：一个会话算一次，不论它含多少轮 |
| 平均 Token 数 | 每个会话平均消耗的文字量 | 全部会话的 Token 总量 ÷ 会话总数 |
| 平均会话时长 | 每个会话平均持续多久 | 各会话首末时间差求平均 |
| 平均轮次 | 每个会话平均几问几答 | 全部轮次数 ÷ 会话总数 |
| 内部成本（美元） | 平台支付给上游的美元成本 | 按上游定价逐笔累加 |
| 外部成本（积分） | 向租户收账的积分 | 按平台定价逐笔累加 |

**内部成本与外部成本不合计**：美元与积分是两种单位，加起来没有业务含义。页面顶部的趋势图也分别按两种单位展示。

## 趋势与排名

- 趋势图按天聚合（世界标准时 UTC 切日），展示会话数或成本的逐日变化。
- 「较上一周期」＝当前窗口与等长的上一窗口相比的百分比变化。
- 排行页（人员/智能体/模型）按所选指标排序；“花费”排序使用后端兼容字段 `total_cost`，其值是美元内部成本与积分外部成本的原始数值相加，没有汇率换算。列表可能仍以美元样式显示该值，因此它不是金额、不能跨币种比较；请分别查看内部成本（USD）和外部成本（积分）。

## 数据新鲜度

这一页读的是系统定时汇总的「聚合快照」，不是逐笔明细。快照有新鲜度预算（约 90 分钟）；超期时页面显示「聚合数据正在刷新」横幅并拒绝返回过期数字——这是保护机制，不是故障。

## 数字对不上时怎么自查

1. 时间范围：本页与请求记录页窗口不同，数字必然不同；先对齐时间。
2. 快照延迟：最近的请求可能还没进聚合快照，等刷新后再对。
3. 口径差异：本页按「会话」聚合，请求记录页按「单次调用」展开，条数天然不等。
4. 去重规则：会话数按会话去重，同会话多轮不重复计；轮次数才是逐轮计数。
