# プロバイダー一覧ページのデータ説明

このページでは、接続済みの上流「プロバイダー」（OpenAI、Claudeなどのモデルサービス）と、各プロバイダーに紐づく認証情報・モデルを管理します。

## 2つのステータスの違い

- **システム健全性**：認証情報単位の可用性（正常／警告／到達不能／不明）。プローブと実際のトラフィックで発生した失敗記録に基づきます。
- **ルーティング可否**：このプロバイダーが現在**ルート選択に参加するか**（利用可能／利用不可／モデルなし／手動無効化）。プロバイダーが健全でも、手動で無効化されている場合があります。この場合はトラフィックを受け取りませんが、健全性データは更新され続けます。

## モデルと認証情報の関係

- 1つのプロバイダーに複数の認証情報を設定でき、各認証情報を複数モデルで利用できます。いずれかの認証情報に問題があっても、影響を受けるのは、その認証情報が対応するモデルだけです。
- 「モデルなし」＝プロバイダーは接続済みですが、利用可能なモデルがまだ1つも設定されていません。そのため当然、トラフィックは受け取りません。

## 並び替えと絞り込み

- 既定では健全性の順に並び替えます。可用性の絞り込み（ルーティング可能／ルーティング不可）は独立したスイッチであり、互いに影響せず、表示する行だけが変わります。

## 数字が合わない場合の確認方法

1. 健全なのにトラフィックがない場合：まず「ルーティング可否」を確認します。手動で無効化されたプロバイダーはルート選択に参加しません。
2. モデル数が実際に選択できる数と一致しない場合：モデル一覧は認証情報の可用性で絞り込まれるため、すべての認証情報がオフラインになると、モデルが一時的に選択肢から消えます。
3. 保存したばかりの認証情報が「チェック中」と表示される場合：保存後、システムが自動的に健全性チェックを実行します。結果が出るまで一時的なステータスが表示されます。
4. リフレッシュ後も絞り込み条件が残る場合：ページは前回の絞り込み条件を保持します。別のユーザーが使用する場合は、先に絞り込み条件を解除してください。
