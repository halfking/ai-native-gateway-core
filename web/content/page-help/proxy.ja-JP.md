# 代理管理ページのデータ説明

このページでは、ゲートウェイが上流へのアクセス時に使用する「プロキシ出口」を管理します。サブスクリプションの入手元、ノードプール、現在使用している出口です。

## 3つのタブ

- **ステータス概要**：概要カード（サブスクリプション数、ノード総数、接続可能/正常数）+ 現在選択中の出口 + 自動切替状態。
- **サブスクリプション管理**：プロキシのサブスクリプションソース（ノードを一括インポートするリンク）。「地域ブラックリスト」を設定して出口を絞り込めます。
- **ノード管理**：ノードごとの手動登録と保守。

## 重要な判定基準

- **接続可能**＝現在、接続を確立できるノード；**正常**＝連続してプローブが正常だったノード。繰り返し失敗するノードは、接続可能でも正常には数えません。
- **自動切替**：現在の出口で連続して失敗が発生し、しきい値に達すると、自動的に次のノードへ切り替わります。「連続失敗回数」はリアルタイムに加算され、成功するとゼロに戻ります。
- 「直近のアクティブプローブ」は、システムが独自に実施した接続性チェックの時刻であり、業務リクエストの時刻ではありません。

## 数字が一致しない場合の確認方法

1. ノード総数 ≠ 接続可能数：正常です。総数は登録台数、接続可能数は現在の接続可能台数です。
2. 切替後も業務が失敗する場合：切替にはチェック周期があり、数秒で完了します。失敗が続く場合は、「連続失敗回数」がまだ増加しているか確認してください。
3. サブスクリプション更新後もノード数が変わらない場合：サブスクリプションソースの内容が同じである可能性があります。個数ではなく、更新前後のノードのフィンガープリントを比較してください。
4. ブラックリストの地域が効かない場合：地域コードは、ノードが報告した地域値と完全一致する必要があります（大小文字を区別します）。記載方法を誤ってもエラーにはなりませんが、フィルタリングもされません。
