# 格式異常頁資料說明

這一頁盯著兩類「不對勁」：上游返回的**格式**突然變了、或請求**出錯**了。目標是先於使用者發現供應商側的變化。

## 兩個資料來源（兩頁籤）

- **響應格式異常**：上游回答的結構不符合預期（欄位缺失、型別變了、提取 Token 失敗等）。
- **請求錯誤**：請求本身失敗（超時、被拒、引數錯等）。

頁面頂部徽標數字＝兩個資料來源的「未解決」條數**之和**，與列表頁的「未解決」篩選同口徑。

## 「未解決 / 已解決」怎麼算

- 新檢測到的異常預設「未解決」；人工確認處理過後標「已解決」。
- 「解決」不代表自動消失，是人工確認過的狀態——用於區分「看過」和「沒看過」。

## 數字對不上時怎麼自查

1. 徽標數與列表數不一致：先確認篩選器（是否勾了「僅未解決」、時間範圍）。
2. 供應商改版會造成一批同類異常同時出現：按「異常型別」分組看，同一型別的一批通常是一個原因。
3. 探測流量與真實流量都可能觸發記錄：判定影響面前先區分異常來自哪類流量。
4. 異常自動恢復（供應商改回）不會自動標「已解決」：仍需人工確認，這是刻意設計，防止靜默變化被忽略。
