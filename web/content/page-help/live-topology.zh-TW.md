# 實時拓撲頁資料說明

這一頁是閘道器的「實時交通圖」：哪些節點線上、請求正在從哪裡流向哪裡。

## 圖上的元素

- **節點**＝一個可承接請求的服務點（接入端節點、供應端節點）。
- **鏈路**＝兩節點之間的連線；線的粗細/數量代表流量大小。
- 一筆請求從「使用者側」進入，經閘道器選路，從某條「供應端鏈路」出去拿到答案。

## 節點狀態

- 線上/離線來自節點的實時心跳；Redis 異常時健康狀態會降級顯示為「未知」——這是採集通道的問題，不代表節點真的不可用。
- 「內部直連」徽標＝該供應端節點由平臺直連維護，不走第三方代理。

## 實時性說明

- 頁面透過長連線推送更新，正常情況下秒級重新整理。
- 短暫斷線時頁面會自動重連；斷線期間的請求不丟，只是畫面延遲補齊。
- 「已隱藏 N 條經無效節點的請求」＝被判定經過無效節點的請求預設不顯示在鏈路上，需要時可以開啟顯示開關。

## 數字對不上時怎麼自查

1. 實時畫面是「此刻」的快照，與統計頁「過去某段時間」的累計沒有直接可比性；對賬要用請求記錄頁。
2. 鏈路上的數字是滾動視窗內經過的請求數，視窗隨時間滑動，數字會自然回落。
3. 看到請求停留在某條鏈路不動，先看它的狀態標籤：進行中/已完成/失敗分別表示不同階段。
4. 節點全部顯示「未知」：多半是訊息通道故障，重新整理頁面或稍等重連即可恢復。
