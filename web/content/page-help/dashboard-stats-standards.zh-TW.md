# 看板與會話統計的統計標準

「看板」和「會話與統計」是同一批模型呼叫流水在**兩套口徑**下的兩種彙總。這一頁把兩頁每個數字的演算法、資料來源、時間視窗寫清楚，並給出兩頁數字為什麼對不上的逐項對照——用於對齊資料、自查偏差。

> 實測口徑：2026-11-23 02:27（Asia/Shanghai）生產環境實測 + 生產庫唯讀對拍。

## 兩頁是什麼關係

| | 看板 | 會話與統計 |
| --- | --- | --- |
| 統計實體 | 一筆模型呼叫算一條（**請求級**） | 一個會話算一條，取該會話的**累計值**（**會話級**） |
| 真源 | 請求級事實表 `usage_facts`（Redis 快取基線 + 即時增量） | 會話彙總表 `session_summaries`（即時查詢）+ 物化視圖（快取面） |
| 時間視窗 | 系統時區日曆日：今天-(N-1) 日零點 → 此刻 | 面板＝滾動 N 天（首次請求落在最近 N 天內）；對齊行＝上海日曆日整天 |
| 探測流量 | 依請求級事實表的流量分類剔除 | 依會話側的「會話宇宙」規則剔除 |

**結論先說**：兩頁的數字**本來就不該相等**——實體不同（請求 vs 會話）、視窗不同、剔除規則不同。跨頁比較必須先對齊這三項，不能直接相減。

## 看板：每個數字怎麼來的

| 卡片／模組 | 演算法 | 說明 |
| --- | --- | --- |
| 總請求數 | 視窗內終態請求筆數 | 只含成功／失敗／限流等終態紀錄，不含未完成的串流 |
| 成功率 | 成功筆數 ÷ 總筆數 | 狀態為成功的請求佔比 |
| 總 Token | 每筆輸入字量 + 輸出字量分別累加 | 快取命中的字量依各上游口徑計入 |
| 總費用 | 每筆費用累加（美元） | 美元是付給上游供應商的成本口徑 |
| 總積分 | 平臺向租戶計費的積分數 | ★ 見下方「積分卡」 |
| 平均延遲 | 每筆延遲累加 ÷ 總筆數 | 毫秒 |
| 活躍模型／活躍供應商 | 視窗內有實際流量的去重計數 | 不是「平臺可用總數」 |
| 活躍金鑰 | 目前處於啟用狀態的金鑰數量 | **配置口徑，與時間範圍無關** |
| 錯誤數 | 優先依失敗原因分佈逐類累加；無該分佈時用「總請求 × (1 − 成功率)」推算 | 推算值與真實值可能差幾筆 |
| 餅圖（模型／供應商／租戶／客戶端…） | 依維度分組累加請求／Token／費用 | 來自分鐘統計表，與上方卡片不是同一個真源 |
| 用量趨勢圖 | 依時間桶累加請求／Token／費用／積分 | 同樣來自分鐘統計表 |

### 時間視窗怎麼算

- 「今天」＝系統時區（預設 Asia/Shanghai）今日零點 → 此刻；「近 7 天」＝6 天前的零點 → 此刻；「近 30 天」同理。**起點是日曆日零點，終點是當下時刻**，不是整日。
- 自訂區間依所選兩天彙總，含末日整天。
- 頁面每 10 秒自動重新整理；即時通道線上時新完成的請求會即時累加。

### 積分卡（口徑特殊，務必注意）

積分卡顯示的值**不是視窗內的積分消耗**：請求級事實表的積分欄目前恆為 0（實測全表 298,037 列全為 0），頁面顯示的實際是「基線快照之後的即時增量」。因此：

- 切換「今天／近 7 天／近 30 天」，積分卡的數字**完全一樣**（實測三者同為 86,925）。
- 同一頁的用量趨勢圖另有積分合計（分鐘統計表口徑，近 7 天 1,767,183），與積分卡不是同一個數。

需要可信的積分帳目時，請以「用量成本」「對賬報表」頁為準，不要用看板積分卡做時間序列比較。

## 會話與統計：每個數字怎麼來的

| 模組 | 演算法 | 說明 |
| --- | --- | --- |
| 總會話數 | 視窗內首次請求時間落窗的會話筆數 | 會話級計數，不等於請求數 |
| 活躍／新／已關閉會話 | 依會話的最後／首次請求時間是否落在最近 24 小時內劃分 | 與主視窗無關的 24 小時口徑 |
| 總費用（美元） | 各會話累計費用求和 | 一個會話的**全部**費用記在會話列上 |
| 總請求數 | 各會話累計請求數求和 | 同樣取會話累計值，不是視窗內發生的請求數 |
| 輸入費用／輸出費用 | 各會話的輸入／輸出費用分別求和 | 兩者相加＝總費用 |
| 平均會話費用／單請求費用 | 總費用 ÷ 會話數（÷ 請求數） | 分母是會話累計值 |
| 成功率／快取率（對齊行） | 請求級視圖的成功筆數 ÷ 請求總數 | 只有請求級口徑才有這兩項 |
| 會話分析對齊指標行 | 物化視圖會話級彙總 | 每 15 分鐘更新一次；視窗＝上海日曆日整天 |
| Top5 使用者／Top5 供應商 | 會話分析排行端點（使用者／模型／供應商／任務） | 供應商由 SQL 按 `model_usage_aggregates.provider` 聚合（**不是**由模型名稱前綴推導），**含費用**、可依費用排序；Top5 四維在「會話分析 → 使用者」頁呈現 |
| 輪次對拍 | 會話請求數 vs 輪次數 | 差值超過 10% 時頁面會給出提示條 |

### 會話宇宙（哪些會話被算、哪些沒算）

會話側只統計同時滿足以下三條的會話：

1. 在會話表裡登記過的會話；
2. 有歸屬使用者（依使用者鍵或金鑰歸屬鍵取其一，都為空則不計）；
3. 不是探測會話：既不是人工標記的探測位，也不是依「使用者／客戶端類型／標題」模式判定的自我檢查、部署閘門、測試、驗證類會話。

### 為什麼這裡的費用比看板少

會話宇宙的第三條規則會把**一部分真實業務會話**判成探測而剔除。2026-11-23 生產庫實測（同一 7 天視窗）：

- 被會話側剔除的 15,898 個會話，其主請求在請求級事實表裡 **100% 屬於業務流量**，合計 $6,452.73；
- 同一視窗，請求級事實表裡真正標為探測的流量合計只有 **$1.81**。

也就是說：兩頁雖然都聲稱「排除探測」，但**剔除的不是同一批請求**。這是會話與統計費用明顯低於看板的首要原因。

## 兩頁數字對照（2026-11-23 實測，7 天視窗）

| 指標 | 看板 | 會話與統計（面板） | 會話與統計（對齊行） |
| --- | --- | --- | --- |
| 統計實體 | 請求 | 會話 + 會話累計請求 | 會話／請求 |
| 請求數 | 65,774 | 72,098 | — |
| 費用（美元） | 8,013.93 | 2,717.62 | 2,468.73（內部成本） |
| 積分 | 86,925（與視窗無關） | — | 0 |
| Token | 3,245,804,009 | — | — |
| 成功率 | 95.31% | — | 94.64% |
| 會話數 | — | 19,235 | 17,390 |

差異來源，逐項對上：

- **請求數 72,098 > 65,774**：會話側的請求數是「被選中會話的累計請求數」，跨窗會話的窗後請求也整段計入；同時會話表存在重複列（實測同一會話鍵最多 30 列重複），彙總時被一併累加。
- **費用 2,717.62 < 8,013.93**：會話宇宙把上面那 $6,452.73 的業務流量判成探測剔除了；此外看板還統計了**沒有歸屬會話**的呼叫（直連 API、腳本呼叫），實測這部分約佔看板費用的兩成。
- **積分 0 vs 86,925**：會話側與請求級事實表的積分欄目前都沒有可信存量，頁面上的積分來自即時增量。
- **成功率 95.31% vs 94.64%**：請求級口徑對請求級口徑，但一個依 `usage_facts`、一個依請求日誌物化視圖，視窗也不同。

## 數字對不上時怎麼自查

1. **先對齊視窗**：看板＝日曆日零點起；會話與統計面板＝滾動 N 天；對齊行＝上海日曆日整天。同一預設下三者仍不是同一個視窗。
2. **再對齊實體**：請求數對請求數、費用對費用；不要拿「會話數」和「請求數」比。
3. **看降級標記**：卡片出現「降級／不可信／未算出」時，那幾個 0 不代表沒有流量。
4. **看探測開關**：看板上的「排除探測／含探測」只切英雄區彙總；分佈圖與趨勢圖一律是業務口徑。
5. **「今天」檔位曾失敗（2026-11-23 已修）**：會話與統計的「今天」檔位先前因資料庫側連接索引缺失而穩定 30 秒逾時（2026-11-23 已補索引，查詢耗時由 121.8 秒降到 0.19 秒）。若頁面仍顯示該檔位失敗，代表索引又被清掉了，請讓值班同學檢查 `idx_session_dim_session_key` 是否在位。

## 已知限制（2026-11-23 實測）

1. **會話側的費用與請求數偏高（重複計數，2026-11-23 已在 `main` 修復）**：「會話與統計」的費用與請求數來自會話級彙總，而 `sessions` 表是**按天分割的會話歷史表**（同一會話每天續一行），統計的連接未按會話去重 ⇒ 同一會話被累計多次。2026-11-23 生產庫實測（同 7 天視窗，**修復前口徑**）：會話側報出的費用比按會話去重後高約 **61%**、請求數高約 **36%**（最貴的那個會話被累計了 3 次）。**該重複計數已修復**：會話宇宙連接改為按 `(session_id, tenant_id)` 去重（`DISTINCT ON`），三個物化視圖隨遷移 994 同步更新 ⇒ 上述 61%／36% 屬**修復前**測量值。**仍然存在的已知限制是 D1（探測剔除過寬，與本條正交）**；**看板（請求級）的數字自始不受影響** ⇒ 比較費用時以看板為準。
2. 看板積分卡不隨時間範圍變化（見上）。
3. 看板趨勢圖（分鐘統計表）與上方卡片（請求級事實表）在 30 天視窗實測相差約 13.8%（160,451 vs 140,969 筆）。
4. 探測剔除在兩側不是同一批流量（見上）。
