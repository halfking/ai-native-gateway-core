# 模型完整性監控頁資料說明

這一頁盯著「上游交付的答案是否完整、是否被偷換」：替換、截斷、空回覆、重複、指紋漂移都算完整性異常。

## 兩個頁籤

- **完整性事件**：每條異常一條記錄（型別、嚴重度、涉事模型/供應商、是否已解決）。
- **指紋漂移**：同一模型的「行為指紋」隨時間的變化——漂移大說明上游悄悄換了實現。

## 口徑說明

- 事件總數 / 未解決 / 嚴重事件按所選統計視窗計；視窗可改。
- 「嚴重」＝影響答案正確性或安全的異常（如模型替換）；「截斷/空響應」通常為中等。
- 指紋漂移是**相對基線**的比較：基線更新後歷史漂移結論會重算。

## 數字對不上時怎麼自查

1. 事件數與格式異常頁不同：兩頁關注的異常型別不同（本頁管「答案完整性」，那邊管「響應格式」），有交叉但不重合。
2. 「未解決」降不下去：需要人工確認處理；與格式異常頁一樣，自動恢復不自動銷案。
3. 指紋突然全部漂移：先查是不是剛更新過基線或切換了統計視窗，再懷疑上游集體改版。
