# モデル信頼性ページのデータ説明

このページでは、上流が低スペックモデルをハイスペックモデルに偽って提供していないかを検査します。一般に「水増し／性能劣化qwired」と呼ばれる問題です。4つの指標をクロスチェックし、結論を得出できない場合は、正直に「証拠不足」と表示します。「問題がなかった」として扱うことはありません。

## 4つの判定結果

| 判定 | 意味 |
| --- | --- |
| 検証済み | 複数の証拠が一致しており、モデルは申告どおりの仕様です |
| 疑いあり | 疑わしい兆候はありますが、断定するには証拠が不足しています。再確認を推奨します |
| 水増し | 実際に提供された構成が、申告された構成より低いことを示す強い証拠があります |
| 証拠不足 | 証拠が少なすぎて判定できません（**問題がなかったことを意味しません**） |

## 4つの評価基準

上流の自己申告、同モデルの能力比較、リクエスト署名が変動していないか、外部ベースラインによる校正です。

## 判定基準

- 「判定済みノード」は「モデル × サプライヤー」の組み合わせごとに数えます。同じモデルでも、サプライヤーが異なれば個別に判定します。
- 結論は**直近のテスト結果**を基準とします。「全量テスト」は全対象を再実行し、過去の判定結果を上書きします。

## 数字が合わない場合のセルフチェック

1. 「疑いあり」が多いのに業務に異常がない場合：疑いありは問題を断定uded 아니라、再確認を促す表示です。整合性監視ページのフィンガープリントの変動も合わせて確認してください。
2. テスト直後に「証拠不足」になった場合：この組み合わせの直近のトラフィックが少なすぎて、サンプリングが不足しています。実際のトラフィックが発生してから再テストしてください。
3. サプライヤーのバックエンドの能力と一致しない場合：4つの評価基準のうち「能力比較」は、このプラットフォームで実測したトラフィックに依存しています。人気のないモデルでは、 Naturally証拠も少なくなる傾向があります。
