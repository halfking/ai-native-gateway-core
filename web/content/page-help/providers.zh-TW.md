# 供應商列表頁資料說明

這一頁管理接入的上游「供應商」（OpenAI、Claude 等模型服務），以及每家供應商下的憑據與模型。

## 兩套狀態的區別

- **系統健康**：憑據層面的可用性（正常/警告/不可達/未知），來自探測與真實流量的失敗記錄。
- **可路由性**：這家供應商當前**是否參與選路**（可用/不可用/無模型/手動禁用）。一家供應商可能健康但被手動禁用——此時它不接流量，但健康資料仍在更新。

## 模型與憑據的關係

- 一家供應商掛多條憑據、供多個模型；任一憑據出問題隻影響它承載的模型。
- 「無模型」＝供應商接上了但還沒配置任何可用模型，自然不會接到流量。

## 排序與篩選

- 預設按健康狀況排，可用性篩選（可路由/不可路由）是獨立開關，兩者互不影響、只決定顯示哪些行。

## 數字對不上時怎麼自查

1. 健康但沒流量：先查「可路由性」——被手動禁用的供應商不參與選路。
2. 模型數與實際可選不符：模型列表按憑據可用性過濾，憑據全下線時模型會暫時從可選項消失。
3. 剛儲存的憑據顯示「探測中」：系統儲存後會自動發起一次健康檢測，結果出來前顯示過渡狀態。
4. 重新整理後篩選被記住：頁面會保留上次的篩選條件，換人使用時先清空篩選。
