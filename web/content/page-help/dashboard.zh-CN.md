# 总览页数据说明

这一页是整个网关的「仪表盘」，把一段时间的用量、费用、健康状态汇总在一屏。

## 数据从哪里来

页面上所有数字都来自网关记录的每一次模型调用流水。系统先把每笔请求记下来，再按你选的时间范围汇总成各种统计。

## 时间范围怎么算

- 「今天」「近 7 天」「近 30 天」三种快捷范围按自然日切分，统计窗口起点是**系统时区（默认 Asia/Shanghai）**当天零点，终点是当前时刻（不是整日）。
- 自定义范围选哪两天，就汇总这两天的全部流水（首日零点起到末日零点止，含末日全天）。
- 页面每 10 秒自动刷新一次；如果实时通道在线，新完成的请求会即时累加进来，不需要等刷新。

## 四张核心卡片

| 卡片 | 含义 | 算法 |
| --- | --- | --- |
| 总请求 | 这段时间处理了多少笔模型调用 | 流水条数直接计数 |
| 成功率 | 多少比例的请求正常返回了答案 | 状态为「成功」的笔数 ÷ 总笔数 |
| 总 Token | 这段时间消耗的文字量（输入+输出） | 每笔的输入字量与输出字量分别累加 |
| 总费用 | 这段时间的美元计费金额 | 每笔费用累加（美元口径） |
| 总积分 | 平台内部计费口径的积分数 | ★ 当前显示的是基线快照之后的**实时增量**，不随时间范围变化（见下方说明） |

注意：**费用（美元）和积分是两套口径，不做合计**。费用是给上游供应商的美元成本；积分是本平台向租户收账的单位。两者数值上不可比，页面分开显示。

积分卡的口径特殊：请求级事实表里的积分列当前恒为 0，页面显示的实际是「基线之后的实时增量」——切换「今天 / 近 7 天 / 近 30 天」积分卡的数字完全一样；同一页的用量趋势图里另有积分合计（另一个数据源），与积分卡不是一个数。需要可信的积分账目时，请用「用量成本」「对账报表」页。

## 错误数与失败原因

- 「错误数」优先按失败原因饼图逐类累加；饼图没有时用「总请求 × (1 − 成功率)」推算。
- 点错误数卡片可以跳转到错误分布，看每一类失败各占多少。

## 「活跃」类标签的口径

- 「活跃模型」＝这段时间内**有实际流量**的模型数量，不是「平台可用模型」总数。
- 「活跃密钥」＝当前**启用状态**的密钥数量（配置口径，与时间范围无关）。
- 「供应商数」＝这段时间内**有实际流量**的供应商数量。

## 数字对不上时怎么自查

1. 先确认时间范围一致：两个页面选的窗口不同，数字必然不同。
2. 看卡片是否出现「降级」标记：聚合数据暂不可算时，页面会明确标注，此时的 0 不代表「没有流量」。
3. 积分卡显示「不可信/未算出」时，说明积分账目数据源暂缺，请求数与费用仍然真实。
4. 探测流量不计入业务统计：系统自身的健康检查类请求被排除在总请求与费用之外。
5. 实时刷新与图表口径有秒级差：卡片数字（含实时累加）可能比图表略多几笔，属正常现象。

## 与「会话与统计」页对比

本页是**请求级**口径（每一笔模型调用算一条），「会话与统计」页是**会话级**口径（一个会话算一条，取会话的累计值），两页的时间窗口与探测剔除规则也不同 ⇒ 数字本来就不该相等。需要逐项对照时，看「看板」与「会话与统计」两个页签里的 **统计标准** 按钮（那篇正文给出两页的逐项口径与差异对照表）。
