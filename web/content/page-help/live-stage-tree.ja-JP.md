# リクエスト段階ツリーページのデータ説明

このページでは、1 件のリクエストの「ライフサイクル」を 10 の段階に分解し、タイムライン上に配置しています。問題が発生した場合、どのステップで停滞したかをすぐに確認できます。

## 10 の段階（発生順）

認証・レート制限 → マスキング → 承認 → インジェクション検出 → ルーティング → 圧縮 → プロバイダー・Token プール → 初回バイト → マスキング反映 → 計測・返信。

- 送信レーン（左→右）はリクエストが送信されるプロセス、受信レーン（右→左）は回答が返ってくるプロセスです。
- リクエストがすべての段階を通るとは限りません。承認がトリガーされていないリクエストでは、「承認」段階に「該当なし」と表示されます。

## 7 つの段階ステータス

未到達 / 進行中 / 完了 / 該当なし / 失敗 / 警告あり / 未計測。

- 「失敗」＝このステップでリクエストが遮断されました（例：インジェクション検出に一致、承認が却下されました）。
- 「警告あり」＝リクエストは通過しましたが、疑わしい点が記録されました。
- 「未計測」＝この段階に計測データがありません。失敗を意味するものではありません。

## 段階所要時間

- 各段階の横棒の長さは、その段階にかかった時間を表します。「初回バイト」から「返信」までは、モデルが回答を生成する時間であり、通常最も長くなります。
- 合計所要時間 ≠ 各段階の単純な合計：一部の段階は並行して発生します。

## 数値が合わない場合の確認方法

1. 「進行中」のリクエストでは段階の所要時間がまだ伸びています。完了してから数値が確定します。
2. 特定のリクエストが見つからない場合は、まずフィルターを確認してください。ページには、現在のフィルター条件と時間範囲内のリクエストだけが表示されます。
3. 「未計測」の段階が多い場合、そのリクエストは旧形式のパイプライン（初期データ）を通ったと考えられます。これは履歴データの形式上の特徴であり、システムの障害ではありません。
4. 失敗したリクエストは「失敗段階」を基準にします。問題を特定する際は、最初に「失敗」した段階を確認してください。その後の段階は通常実行されません。
