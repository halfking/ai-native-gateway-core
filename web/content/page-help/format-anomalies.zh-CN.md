# 格式异常页数据说明

这一页盯着两类「不对劲」：上游返回的**格式**突然变了、或请求**出错**了。目标是先于用户发现供应商侧的变化。

## 两个数据源（两页签）

- **响应格式异常**：上游回答的结构不符合预期（字段缺失、类型变了、提取 Token 失败等）。
- **请求错误**：请求本身失败（超时、被拒、参数错等）。

页面顶部徽标数字＝两个数据源的「未解决」条数**之和**，与列表页的「未解决」筛选同口径。

## 「未解决 / 已解决」怎么算

- 新检测到的异常默认「未解决」；人工确认处理过后标「已解决」。
- 「解决」不代表自动消失，是人工确认过的状态——用于区分「看过」和「没看过」。

## 数字对不上时怎么自查

1. 徽标数与列表数不一致：先确认筛选器（是否勾了「仅未解决」、时间范围）。
2. 供应商改版会造成一批同类异常同时出现：按「异常类型」分组看，同一类型的一批通常是一个原因。
3. 探测流量与真实流量都可能触发记录：判定影响面前先区分异常来自哪类流量。
4. 异常自动恢复（供应商改回）不会自动标「已解决」：仍需人工确认，这是刻意设计，防止静默变化被忽略。
