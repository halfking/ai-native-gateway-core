# リアルタイムトポロジーページのデータ説明

このページは、ゲートウェイの「リアルタイムトラフィックマップ」です。どのノードがオンラインか、リクエストが現在どの場所からどの場所へ流れているかを表示します。

## 図の要素

- **ノード**＝リクエストを処理できるサービスポイント（入口側ノード、供給元ノード）。
- **リンク**＝2つのノード間の接続線。線の太さ/本数はトラフィック量を示します。
- 1件のリクエストは「ユーザー側」から入り、ゲートウェイによる経路選択を経て、いずれかの「供給元リンク」 exiting to get answer.

## ノードの状態

- オンライン/オフラインは、ノードのリアルタイム心跳から取得しています。Redisに異常がある場合、ヘルスステータスは「未知」に lowered表示されます。これは収集チャネル上の問題であり、ノードが実際に利用できないことを意味するものではありません。
- 「内部直接接続」バッジ＝その供給元ノードは、プラットフォームが直接接続して管理しており、第三者プロキシを経由しないことを示します。

## リアルタイム性について

- ページは長接続 Via push updates, 通常は秒単位で更新されます。
- 短時間の切断時は、ページが自動的に再接続します。切断中のリクエストも失われず、後から遅れて表示が補完されるだけです。
- 「無効ノードを経由したN件のリクエストを非表示」＝無効ノードを経由すると判定されたリクエストは、デフォルトではリンク上に表示されません。必要に応じて表示設定を有効にできます。

## 数字が一致しない場合の確認方法

1. リアルタイム表示は「現在」のスナップショットであり、統計ページの「過去の一定期間」の累計値とは直接比較できません。照合にはリクエスト記録ページを使用してください。
2. リンク上の数値は、ローリングウィンドウ内で通過したリクエスト数です。ウィンドウは時間とともに移動するため、数値は自然に減少します。
3. リクエストが特定のリンク上で止まっている場合は、まずステータスタグを確認してください。「進行中/完了/失敗」は、それぞれ異なる段階を示します。
4. すべてのノードが「未知」と表示されている場合、メッセージチャネルの障害である可能性が高습니다。ページを更新するか、少し待って再接続すれば復旧します。
