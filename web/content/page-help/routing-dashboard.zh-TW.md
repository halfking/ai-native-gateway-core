# 路由總覽頁資料說明

這一頁回答「一筆請求為什麼被派給某個模型」：把選路過程拆開給你看。

## 核心概念

- **候選**＝按條件篩出來可以接這筆請求的憑據。
- **可路由**＝候選裡當前真正能用的那部分（健康、未被禁用、未在冷卻期）。
- **決策記錄**＝每一次真實請求的選路結果流水。

## 統計口徑

- 「可路由數」按當前時刻判定：同一候選一分鐘前可用、一分鐘後進入冷卻，數字隨之變化。
- 決策明細按「層級」列出候選順序：排在前面的優先接單；前面的失敗時按順序向後回退。
- 「回退」＝首選候選失敗後換下一個候選接手；一次請求最多隻有一條最終成功記錄。

## 頁籤說明

- 實時決策：發起一次試算，看「如果現在來一筆請求會怎麼選」。
- 憑據監控 / 探測健康：上游憑據的可用性詳情。
- 自動運營：系統自動調參與分析工具。

## 數字對不上時怎麼自查

1. 試算結果與實際記錄不同：試算是「當下推演」，實際決策發生在過去；冷卻狀態、臨時禁用都會讓兩者不同。
2. 決策條數與請求記錄頁對不上：決策頁只記選路事件；沒有進入選路的請求（如被前置攔截）不會出現在這裡。
3. 「可路由 = 0」但請求仍成功：說明系統走了跨供應商回退或備用通道，可在決策明細裡看到回退鏈。
4. 時間差：冷卻解除、憑據恢復都是分鐘級變化，兩端查詢時間差幾分鐘結果就不同。
