# データライフサイクルページのデータ説明

このページでは、データの「保管・移行・削除」を管理します。データベース内のどのデータが容量を占めるか、何時にアーカイブするか、どのように回収するかを確認できます。

## タブ一覧

- **ストレージ概要**：各テーブルが使用する容量と、増加のペース。
- **Hot テーブル移行 & パーティション削除**：高頻度に書き込みがある大規模テーブルを月単位のパーティションに格納し、過去の月のデータはまとめてアーカイブします。
- **縮退時の復旧とクリーンアップ**：集計データが破損した場合、明細から再構築します。
- **ストレージ設定**：データベース接続とストレージの保存先の設定。
- **ログ管理**：運用ログの保持と削除。
- **セッション添付ファイル / 大容量フィールド / ファイルシステム**：ファイル系データの容量使用とメンテナンス。

## 重要な定義

- **保持期間**＝データベース内にデータを保持する期間。期限を過ぎたデータは「削除可能」となり、削除前に影響を受ける行数をプレビューできます。
- 「削除可能」は「削除済み」を意味しません。削除する場合はプレビューしてから手動で実行します。プレビューした数と実際の実行との間に新しいデータが書き込まれると、実際の行数は多少ずれることがあります。
- テーブルスペースの使用量は、まず増加し、その後減少します。整理操作（容量の回収）の実行中は古いファイルと新しいファイルが併存するため、ディスク使用量がいったん2倍になり、完了後に解放されます。

## 安全機能

- すべての削除操作では、「プレビュー」と「実行」の2段階に分けて、実行前に必ずプレビューする必要があります。
- アーカイブはデータを低速ストレージへ移す操作であり、削除ではありません。データを復旧する場合も、元のデータを取得できます。

## 数値が一致しない場合の確認方法

1. 使用量の数値はデータベースの統計情報から取得するため、オペレーティングシステムが表示するファイルサイズとは一定の差があります（データベース内部の冗長スペースのため）。おおむね同じ大きさであれば問題ありません。
2. 「削除可能」の行数が時間とともに増えるのは正常です（データの経年によるもの）であり、異常な増加ではありません。
3. 再構築や移行の実行中に見える行数の変動は一時的なものです。タスク完了後の最終状態を確認してください。
4. 最初にタブを確認してください。同じテーブルでも、タブごとに数値の定義が異なります（概要では使用量、パーティションの画面では行数の分布を確認します）。
