# 認証情報監視ページのデータ説明

このページでは、上流の「認証情報」（各モデルプロバイダーに接続するためのアカウントキー）の利用可否を監視し、ユーザーが障害を報告する前に問題を発見できます。

## タブ説明

- **リスト**：各認証情報を1行ずつ表示するヘルスの一覧表（現在のステータス、直近のエラー、無効化理由）。
- **ヒートマップ**：時間ごとに各認証情報のエラー発生状況を確認できます。色が濃いほどエラーが多く発生しています。
- **ルーティングログ**：認証情報単位のイベント履歴（有効化／無効化／切り替え）。
- **エラー推移**：1時間ごとのエラー曲線から、エラーが一時的に集中したのか継続しているかを確認できます。
- **接続テスト結果**（システム管理者のみ）：システムが各認証情報に対して実施するテスト呼び出しの結果。

## ステータスラベルの基準

- 「正常」＝最近失敗の記録はありません。
- 「手動無効」＝管理者が手動でオフライン化した状態。自動接続テストによって再有効化されることはありません。
- 「自動制御」＝システムが連続的な失敗を理由に自動オフライン化した状態（複数の障害確認など）。手動で強制的に無効化することも、自動復旧を待つこともできます。
- 無効化理由のバッジは、ヘルスのステータスより優先して表示されます：エラーと無効化理由の両方がある認証情報では、無効化理由が表示されます。

## ヘルススコアとエラー数

- エラー数に計上されるのは**完了した失敗呼び出し**であり、選択した時間窓内で累加されます。
- 同じリクエストの失敗は、その時点で使用されていた認証情報にのみ計上されます。再試行が成功しても、記録された失敗は取り消されません。

## 数字が一致しない場合の確認方法

1. 時間窓の不一致：このページのフィルターとダッシュボードの時間窓をそろえてから比較してください。
2. 「接続テスト」のトラフィックはシステムが自ら開始する検査用呼び出しであり、ユーザートラフィックとは別に集計されます。認証情報の利用可否は、接続テストと実トラフィックの両方を踏まえて判断してください。
3. 復旧したばかりの認証情報は、短時間でもエラー数が古い値のまま表示されることがあります：グラフは1時間単位に集計されるため、現在の1時間枠の完全な結果を確認するには次の1時間枠まで待つ必要があります。
4. リストが空の場合は、まずフィルターを確認してください：認証情報の種類／テナント／ステータスのフィルター条件の組み合わせによって、結果が空になる場合があります。
