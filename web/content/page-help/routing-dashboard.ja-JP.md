# ルーティング概要ページのデータ説明

このページでは「あるリクエストがなぜ特定のモデルに割り当てられたのか」に答えます。ルーティングの過程を分解して確認できるようにしています。

## 基本概念

- **候補**＝条件に基づいて筛选され、このリクエストを処理できる認証情報。
- **ルーティング可能**＝候補のうち、現時点で実際に使用できるもの（正常、無効化されていない、クールダウン期間中でない）。
- **判断履歴**＝実際のリクエストごとのルーティング結果の記録。

## 集計基準

- 「ルーティング可能数」は現在時刻を基準に判定します。同じ候補でも、1分前時点では利用可能で、1分後にクールダウンに入ると、数値が変化します。
- 判断詳細は「階層」ごとに候補の順序を一覧表示します。先に並んでいる候補が優先して処理され、先の候補が失敗した場合は順番に後続の候補へフォールバックします。
- 「フォールバック」＝優先候補が失敗した後、次の候補に処理を引き継ぎます。リクエスト1件につき、最終的に成功する記録は最大1件です。

## タブの説明

- リアルタイム判断：試算を1回実行し、「今リクエストが来た場合、どの候補が選ばれるか」を確認できます。
- 認証情報の監視 / ヘルスチェック：上流認証情報の利用可否の詳細。
- 自動運用：システムがパラメータを自動調整し、分析ツールを提供します。

## 数値が一致しない場合の確認方法

1. 試算結果と実際の記録が異なる場合：試算は「現時点でのシミュレーション」であり、実際の判断は過去に発生しています。クールダウン状態や一時的な無効化により、両者が異なることがあります。
2. 判断件数がリクエスト記録ページと一致しない場合：判断ページにはルーティングイベントのみが記録されます。ルーティング対象にならなかったリクエスト（例：前段でブロックされたリクエスト）は、ここには表示されません。
3. 「ルーティング可能 = 0」なのにリクエストが成功した場合：プロバイダー間のフォールバックまたは予備経路を使用したことが考えられます。フォールバックの連鎖は、判断詳細で確認できます。
4. 時間の差：クールダウン解除や認証情報の復旧は分単位で変化するため、両端の照会時刻に数分の差があると、結果が異なります。
