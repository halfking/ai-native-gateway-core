# 请求详情页数据说明

这一页展示**一笔请求的完整档案**：从进网关到出答案的全过程与每一项数字。

## 三个区块

- **基本信息**：时间、密钥、模型、状态、总耗时。
- **过程明细**：各环节（鉴权、选路、上游调用、脱敏回填、计量）的耗时与结果。
- **内容与用量**：实际发送/收到的内容摘要、输入/输出文字量、这笔的费用。

## 关键口径

- **总耗时**＝从收到请求到返回完整答案；它包含网关处理时间与上游生成时间两部分，明细里分开列出。
- **费用**按请求发生时的价格表计算；之后调价不改变历史请求的这笔费用。
- 内容摘要可能被截断显示（保护性能）；完整内容看「查看全文」。

## 数字对不上时怎么自查

1. 这笔的费用与模型目录价「对不上」：先确认请求时间与调价时间——价格按**请求时刻**冻结。
2. 输入文字量比你自己统计的多：系统计数包含消息包装（系统提示、历史轮次），不只看你打的那句话。
3. 状态「成功」但用户说没收到：网关视角的成功是「上游完整返回」；之后客户端网络断了属于链路后段问题，看请求的动作时间线确认回包环节。
4. 重试痕迹：一次请求可能内部试了多个候选，最终状态只记最后一次；过程明细能看到完整尝试链。
