# 対帳レポートページのデータ説明

このページは「台帳照合ツール」です。毎日深夜に前日の取引を1ページの台帳にまとめ、サプライヤー、テナント、担当者、モデルなどの異なる視点で照合できます。

## スナップショットの生成方法

- 日次集計ジョブが深夜に**前一日**のスナップショットを生成します。当日分のデータは翌日の深夜までスナップショットがないため、ページには「本日のスナップショットは翌日の深夜に生成されます」と表示されます。
- スナップショットがない日（システムが当時停止していた場合など）は「未集計」と表示されます。「再集計終了日」を指定すると、手動で再計算できます。

## 2つの金額基準（合算しない）

- **サプライヤーコスト（米ドル）**：プラットフォームが上流事業者に支払う金額です。
- **内部ポイント / 内部金額**：プラットフォームがテナントに課金する際の基準です。
- 両者の差額がプラットフォームの粗利です。金額は別々に表示され、異なる単位の合計は算出されません。

## Token の4つの内訳

入力（モデルに送信した文字量）、出力（モデルが生成した回答の文字量）、キャッシュ読み取り（前回の入力を再利用するため、重複して課金されることはなく、割引率が適用される場合があります）、キャッシュ書き込み（初めてキャッシュに保存された入力）。4つの内訳を合計＝総 Token。

## 数字が合わない場合の確認方法

1. スナップショットは「確定台帳」です。リアルタイムダッシュボードと数値が異なるのは正常です。スナップショットは翌日の深夜に固定され、その後は変更されません。リアルタイムダッシュボードには当日分も含まれます。
2. 「未集計」の日付には数値がありません。再集計で再計算してから、もう一度照合してください。
3. サプライヤー別ビューでサプライヤーの管理画面にある請求と照合するときは、タイムゾーンに注意してください。このシステムは UTC で日を区切りますが、サプライヤーの請求は現地時間が使われる場合があり、午前0時をまたぐトラフィックの集計日が異なることがあります。
4. 失敗したリクエストでも少額の料金が発生します（例：上流事業者が中途半端な回答にも課金している場合）。失敗率が高い日は、コスト対リクエスト数の比率が高くなる傾向があります。
