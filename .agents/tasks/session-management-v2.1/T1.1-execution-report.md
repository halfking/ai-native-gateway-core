### 2. API 端点实现

#### 端点 1: 活动趋势
```
GET /api/admin/session-analytics/activity
```
**功能**：
- 按日/周/月聚合会话活动数据
- 返回会话数、请求数、成功/错误计数、成本、Token、独立用户数
- 计算汇总统计（总会话数、平均日会话数、峰值日期）

**实现要点**：
- 使用 `request_logs` 表
- 支持 `date_trunc()` 按粒度聚合
- 缺日补零保证时间序列连续性

#### 端点 2: 成本趋势
```
GET /api/admin/session-analytics/cost-trend
```
**功能**：
- 按日/周/月聚合成本数据
- 拆分 input/output 成本
- 包含缓存读写 Token 统计
- 趋势判定（up/down/flat）

**实现要点**：
- 趋势算法：对比前 50% 和后 50% 均值
- 变化 <5% 判定为 flat
- 返回趋势百分比

#### 端点 3: 延迟趋势
```
GET /api/admin/session-analytics/latency-trend
```
**功能**：
- 计算 p50/p90/p99 延迟百分位
- 包含最大延迟、平均延迟
- 流式首 chunk 延迟 p50

**实现要点**：
- 使用 PostgreSQL `percentile_cont()` 函数
- 精确百分位计算，非近似值

#### 端点 4: 健康趋势
```
GET /api/admin/session-analytics/health-trend
```
**功能**：
- 平均健康评分
- 健康等级分布（A/B/C/D/F）
- 结果分类分布（completed/error/abandoned）

**实现要点**：
- 使用 `session_summaries` 表
- 利用 migration 356 的健康评分列
- 使用 SQL `FILTER` 子句高效分组

## 技术实现细节

### 1. 数据源
- **主表**: `request_logs` (活动/成本/延迟)
- **辅助表**: `session_summaries` (健康)
- **索引**: 利用 migration 355 的优化索引
  - `idx_request_logs_tenant_ts`
  - `idx_request_logs_ts_day`
  - `idx_session_summaries_health_score`

### 2. SQL 优化
- 使用 `date_trunc()` 高效分组
- `percentile_cont()` 精确百分位
- `COUNT(*) FILTER (WHERE ...)` 条件聚合
- `ANY()` 数组过滤

### 3. 性能考虑
- 时间范围限制 ≤90 天
- 超时设置 15 秒
- 索引优化查询路径
- 目标：P90 < 1.5s（7 天范围）

### 4. 租户隔离
- 使用 `EffectiveTenantIDAll(r)`
- super_admin 可查全租户（返回空字符串）
- tenant_admin 只查本租户
