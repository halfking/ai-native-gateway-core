## 技术实现亮点

### 1. 架构设计
- **解耦设计**：Worker 独立实现健康计算逻辑，避免与 admin 包循环依赖
- **灵活集成**：API 可独立使用，Worker 可独立启动
- **可扩展性**：配置集中管理，易于调整评分规则

### 2. 写入策略（多场景触发）
| 场景 | 触发时机 | 实现位置 | 指标标签 |
|------|---------|---------|---------|
| 实时查询 | GET `/health` 时若未计算 | `session_health_api.go` | `source="api"` |
| 手动重算 | POST `/recompute-health` | `session_health_api.go` | `source="api"` |
| 定时批量 | Worker 每小时扫描 | `session_health_worker.go` | worker 自有指标 |
| 会话停止 | session_state_snapshots 写入时（可选集成） | 调用 `ComputeAndPersistHealth()` | `source="snapshot"` |

### 3. 健康评分模型（100 分起扣 penalty）
```
基准分：100
扣分项（8 类）：
  1. 错误主导（error_rate > 50%）       → -30
  2. 会话被放弃（request_count <= 1）   → -15
  3. 错误请求（每次 -3，封顶 -30）       → -30 cap
  4. 合规问题（每次 -10，封顶 -30）      → -30 cap
  5. 高延迟（avg > 5000ms）             → -15
  6. 频繁切换模型（> 3 次）             → -10
  7. 提示注入检测                       → -20
  8. 敏感内容（PII/Toxic，封顶 -30）    → -30 cap

等级映射：A(90+) B(75-89) C(60-74) D(40-59) F(0-39)
结果分类：completed / error / abandoned / unknown
```

## 性能与可靠性

### 1. 性能指标
- **计算性能**：单次健康分计算 < 1ms（Benchmark 验证）
- **批量处理**：Worker 每批 100 条，每小时执行一次
- **API 延迟**：实时计算 + DB 写入 < 50ms

### 2. 可靠性保障
- **优雅关闭**：Worker 支持 `Stop()` 等待当前批次完成
- **错误隔离**：单条会话计算失败不影响批次其他会话
- **重试机制**：Worker 每小时重试未计算的会话（自然重试）
- **幂等性**：重复计算同一会话会覆盖旧值，不会重复扣分
