## Why this approach
Three separate LP6/LP7/LP8 commits had independently introduced the same
debounce-timer + lifecycle-listener + scope-dispose + short-circuit-snapshot
plumbing in three files. The differences (listener function names, short-circuit
condition ordering, immediate-mode default, exposed alias names) created an
audit surface: every new persistence entry point risked re-introducing the
same bugs (missing listener, forgotten snapshot cache clear, scope-dispose
incorrect try/catch swallow).

LP9 consolidates to one shared helper. Each call site keeps its own
serialise/write side effects (user/tenant key generation, legacy migration,
dual-write side effects, module-level cache) — only the persistence plumbing
is shared.

## Risks resolved during this session
1. **TypeScript `WriteCallback` required `boolean`** — broke test-side counters
   that only care about side effects (returning `void`). Resolved by widening
   the type to `boolean | void` and treating `undefined` return as `true` inside
   the helper. Documented in the type's JSDoc.

2. **Test isolation across liveStreamPreferences suites** — `lastPersistedSnapshot`
   inside `createDebouncedFlush` is closure-private, so `_resetPersistState()`
   could not clear it directly. Resolved by extending `cancel()` semantics to
   also clear the snapshot cache (documented in the helper's JSDoc). Module-level
   callers like `liveStreamPreferences` get correct test isolation with no API change.

3. **`installScopeCleanup` interaction with effect-scope** — verified that calling
   it inside `scope.run(() => { installScopeCleanup(...) })` correctly registers
   a dispose hook (16th test added to lock this contract).
