# 提示词注入检测增强 — 审计修正方案（基于 hook 链式架构）

## 架构认知修正

通过重新通读代码，确认正确的接入链：

```
Plugin.Inspect() → security.Registry → SecurityHook(pipeline.Hook)
  → PipelineStage(PhaseGovernance, priority 100)
  → InterceptionHook(priority 200) → Decision → DispatchGate
```

`SetV2DispatchAnalysisResources` 是 pipeline builder 的**依赖注入钩子**（不是直接对接 main 业务）。修正后的方案不改变这条链，只消除链上的代码重复。

## 核心发现

1. **核心 Detector 已实现完整 6 层检测**（`domains/promptinjection/detector.go`：规则+启发式+Canary+向量+LLM+内容替换+评分+决策+日志），返回 `*DetectionResult`（含 Score/RiskLevel/ActionTaken/Blocked/ReplacedContent 等完整字段）。
2. **Plugin 重复实现了其中 5 层**（~300 行），且规则匹配退化为 `strings.Contains`（丢失正则能力，是 bug）。
3. **`db.DB.Stdlib()` 已提供 pgxpool→`*sql.DB` 桥接**，无需新代码。
4. **admin handler 路由直接注册 mux，绕过 `admin.AdminMiddleware`**（auth 绕过漏洞）。
5. **admin handler 重复定义 `getTenantID`/`writeJSONLocal`/`getUserEmail`**，与 `admin.GetTenantID`/`writeJSON`/`GetAuthContext` 冲突。
