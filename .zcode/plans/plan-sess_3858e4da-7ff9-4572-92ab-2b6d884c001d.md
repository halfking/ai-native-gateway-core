# 实现计划：四阶段增强（按序）

## 增强 1：Write-Time 客户端可见脱敏（P0，高风险）

### 目标
让客户端真正收到脱敏后字节（当前仅 telemetry/日志脱敏）。

### 技术方案
复用 `StripMinimaxFields` 函数指针模式，新增 `RedactBodyFn func([]byte, sessionID, tenantID string) []byte`：

**非流式路径**（`executor_chat.go:83-93`）：
```go
// 在 StripMinimaxFields 之后、w.Write 之前插入
if c.RedactBodyFn != nil {
    body = c.RedactBodyFn(body, sessionID, tenantID)
}
```

**流式路径**（`stream.go:391-392`）：
- 已有 `stripFn func([]byte) []byte` 参数传递到 `stripChunkFields`。
- 改造为 `redactFn func([]byte, string, string) []byte`，在 `stripChunkFields` 内调用。
- `main.go:460` 传入新的 `streaming.RedactChunkBody` 函数。

**redact 实现**（新建 `domains/streaming/redact_body.go`）：
```go
func RedactBodyFn(checker *outputcompliance.Checker, ownerFn OwnerContextFunc) func([]byte, string, string) []byte {
    return func(body []byte, sessionID, tenantID string) []byte {
        // 1. 解析 OpenAI response JSON，提取 choices[].message.content
        // 2. 调用 checker.Check 检测 PII
        // 3. 按 redaction_mode + owner 规则判断
        // 4. 调用 checker.redactOutput 位置替换
        // 5. 回填到 JSON，序列化返回
        // （复用 outputcompliance/interceptor.go:rewriteAssistantContent 逻辑）
    }
}
```

### 关键风险
- **性能**：每个流式 chunk 都调用 JSON 解析 + regex 匹配（minimax strip 同样模式，已验证可行）。
- **正确性**：chunk 级脱敏需处理 PII 跨 chunk 边界问题（保守方案：仅在完整 JSON chunk 内脱敏，跨边界的 PII 不处理）。
- **幂等性**：`RedactBodyFn` 和 `OutputComplianceInterceptor` 会重复检测（前者改客户端字节，后者改 telemetry）。

### 集成点
- `cmd/gateway/main.go:570` 新增 `routingExec.RedactBodyFn = buildRedactBodyFn(checker, ownerFn)`
- `cmd/gateway/main.go:460` 流式调用改为 `streaming.StreamChatWithRedact(..., redactFn)`
- `domains/streaming/executors/executor_chat.go` 新增 `RedactBodyFn func([]byte, string, string) []byte` 字段

### 测试
- 非流式：发送包含邮箱的请求，验证客户端收到 `a***@e***.com`
- 流式：发送包含手机号的请求，验证 SSE chunks 包含脱敏后内容
- owner 规则：caller==owner 时验证不脱敏，mismatch 时验证脱敏

## 增强 2：OLAP Tags UI 展示（P1，纯前端）

### 目标
会话详情顶部显示 task/llm/topic tags（第二排 tag bar，样式区分安全类 vs OLAP 类）。

### 技术方案
**后端**：无需修改，`/api/admin/sessions/{id}/compare` 已返回全部 `session_tags`。

**前端**（`web/src/components/SessionTurnsPanel.vue`）：
1. 新增 `olapTags` computed：
```ts
const olapTags = computed(() => {
  if (!data.value?.session_tags) return []
  return data.value.session_tags.filter(t =>
    ['task', 'llm', 'topic', 'intent', 'quality', 'client'].includes(t.tag_key.split(':')[0])
  )
})
```

2. 在 `<div class="tag-bar">` 下方新增第二排：
```vue
<div v-if="olapTags.length" class="tag-bar tag-bar-olap">
  <span v-for="tag in olapTags" :key="tag.tag_key + tag.tag_value"
    class="stag stag-olap" :title="`${tag.tag_key}: ${tag.tag_value} (${tag.tag_source})`">
    {{ tag.tag_key }}: {{ tag.tag_value }}
  </span>
</div>
```

3. CSS 样式区分：
```css
.tag-bar-olap { margin-top: 8px; opacity: 0.8; }
.stag-olap { background: #f3f4f6; color: #6b7280; border-color: #d1d5db; }
```

### 测试
- 后端写入 task/llm tags 到 `session_tags`（手动 INSERT 或等 SessionTagger 投影）
- 前端刷新 session detail，验证第二排显示灰色 OLAP chips

## 增强 3：Per-Turn 脱敏标记（P1，中等）

### 目标
每轮对话独立标记是否脱敏（当前 session-level），TurnStageCard 显示 🔒 图标。

### 技术方案
**后端**：
1. `OutputComplianceInterceptor.processBody` 在检测到脱敏时，写入 `env.Metadata["pii_stripped_turn"]` = true（区别于 session 级的 `pii_stripped`）。
2. Telemetry 写入 `request_logs.compression_meta` 时，保存 `{"pii_strip_turn": true}`（复用既有 `compression_meta` jsonb 列，无需新增列）。

**前端**：
1. `admin/session_compare.go` 在构造 `TurnView` 时，从 `compression_meta` 读取 `pii_strip_turn`，新增字段：
```go
type TurnView struct {
    ...
    PIIStrippedThisTurn bool `json:"pii_stripped_this_turn"`
}
```

2. `web/src/components/TurnStageCard.vue` 新增 props：
```ts
defineProps<{
  ...
  piiStripped?: boolean
}>()
```

3. 在 receive 区域显示 🔒 图标：
```vue
<div class="stage-receive">
  <span class="label">{{ receiveLabel }}</span>
  <span v-if="piiStripped" class="pii-icon" title="此轮响应已脱敏">🔒</span>
  <pre>{{ receive }}</pre>
</div>
```

### 测试
- 发送触发脱敏的请求
- 查看 session detail，验证对应 turn 的 receive 区域显示 🔒
- 验证其他未脱敏的 turn 不显示图标

## 依赖关系
- **增强 1 → 增强 3**：Per-Turn 标记依赖 write-time 脱敏真正生效（否则标记与实际不符）。
- **增强 2/4 独立**：可与其他增强并行。

## 风险缓解
1. **增强 1 性能**：在 dev 环境压测流式请求（1000 QPS），监控 CPU/延迟。若不可行，降级为"仅非流式 write-time 脱敏，流式保持 post-response"。
2. **增强 1 幂等性**：明确 `RedactBodyFn`（客户端） vs `OutputComplianceInterceptor`（观测）职责，文档化两者都会运行。
3. **增强 3 schema 变更**：复用 `compression_meta` jsonb，避免 ALTER TABLE。

## 实现顺序验证
按 1→2→3→4 顺序实现：
- 增强 1 完成后，go test + 手动 curl 验证客户端收到脱敏字节。
- 增强 2 完成后，前端 vue-tsc + 手动浏览器验证第二排 tags。
- 增强 3 完成后，端到端验证 per-turn 🔒 图标。
- 增强 4 完成后，验证 admin 动态切换 redaction_mode。
