# Live Stream 缓存超时后延修复

## 问题根因

`admin/live_stream_sse.go:374-377` 已经在新数据到达时刷新 `lastAccessed`，但 `live_stream_sse.go:370-372` 早返（Redis 短暂返回空 snapshot）时**没有刷新 `lastAccessed`**——`evictStaleCachedSnapshots` 经过 10 分钟 ticker 后会把这条 cache 清掉，导致下一次"清空再重现"。

次要坑：`live_stream_sse.go:266` 把 TTL 同时用作 ticker 周期，一旦 TTL 配成 > 10 分钟，evict 周期也被动放大。

### 2. `admin/live_stream_sse.go` — 核心修复：进入即续命

**`computeScopeDelta`（L344-379）改写逻辑**——把"刷新 lastAccessed"从成功写入路径上移到函数入口，覆盖所有路径（Redis 错误、空 snapshot、成功 delta 都算一次访问）：

```go
func (h *LiveStreamSSEHub) computeScopeDelta(ctx context.Context, tenantID string, isSuper bool) *LiveStreamDelta {
    if h.store == nil {
        return nil
    }
    cacheKey := tenantID
    if isSuper {
        cacheKey = "__super__"
    }

    // [新增] 进入即刷新 lastAccessed —— 任何一次访问都算激活该 entry，
    // 避免 Redis 短暂空帧把仍在订阅中的 cache 饿死。
    // 不创建新的空 entry，避免无界增长（仅在已有 entry 上刷新）。
    h.cachedSnapshotMu.Lock()
    if entry := h.cachedSnapshot[cacheKey]; entry != nil {
        entry.lastAccessed = time.Now()
    }
    h.cachedSnapshotMu.Unlock()

    snapshot, err := h.store.Snapshot(ctx, tenantID, isSuper, h.cfg.InitialReplayLimit)
    if err != nil {
        slog.Debug("live stream scope snapshot failed",
            "scope_tenant", tenantID, "is_super", isSuper, "err", err.Error())
        return nil
    }
    // 空 snapshot 仍不覆盖（保留已有不变式）
    if snapshot == nil || snapshot.Summary.Total == 0 {
        return nil
    }
    h.cachedSnapshotMu.Lock()
    defer h.cachedSnapshotMu.Unlock()
    cached := h.cachedSnapshot[cacheKey].snapshot // 已确认存在的 entry 直接用
    delta := ComputeDelta(cached, snapshot)
    h.cachedSnapshot[cacheKey] = &cachedSnapshotEntry{
        snapshot:     snapshot,
        lastAccessed: time.Now(),
    }
    return delta
}
```

> 注：进入时刷新后，函数尾部又写一次 `lastAccessed` 是冗余但无害，写出 snapshot 才是主要语义。

### 3. `admin/live_stream_sse.go` — 观测指标

**新增 atomic 计数器（紧跟 L230）**：
```go
cachedSnapshotHits          int64 // 访问时已有 entry（命中续命）
cachedSnapshotMisses        int64 // 访问时无 entry（首次订阅）
cachedSnapshotEmptySkips    int64 // 读出空 snapshot 的次数
cachedSnapshotEvictions     int64 // 本次 evict 周期被清掉的数量
```

**`evictStaleCachedSnapshots` 加日志（L384-393）**：
```go
func (h *LiveStreamSSEHub) evictStaleCachedSnapshots() {
    now := time.Now()
    var evicted int64
    h.cachedSnapshotMu.Lock()
    for k, entry := range h.cachedSnapshot {
        if now.Sub(entry.lastAccessed) > h.cachedSnapshotTTL {
            delete(h.cachedSnapshot, k)
            evicted++
        }
    }
    remain := int64(len(h.cachedSnapshot))
    h.cachedSnapshotMu.Unlock()

    atomic.AddInt64(&h.cachedSnapshotEvictions, evicted)

    if evicted > 0 {
        slog.Info("live stream cached snapshot evicted",
            "evicted", evicted,
            "remain", remain,
            "ttl", h.cachedSnapshotTTL.String(),
            "cleanup_interval", h.cachedSnapshotCleanupInterval.String())
    }
}
```

**在 `Stats()`（约 L1208-1226）补字段**：
```go
return map[string]interface{}{

    "cached_snapshot_hits":        atomic.LoadInt64(&h.cachedSnapshotHits),

    "cached_snapshot_empty_skips": atomic.LoadInt64(&h.cachedSnapshotEmptySkips),
```

### 4. `computeScopeDelta` 内计数埋点

进入即刷新 lastAccessed 的分支里同时累计 `hits`/`misses`：
```go
if entry := h.cachedSnapshot[cacheKey]; entry != nil {
    entry.lastAccessed = time.Now()
    atomic.AddInt64(&h.cachedSnapshotHits, 1)
} else {
    atomic.AddInt64(&h.cachedSnapshotMisses, 1)
}
```

空 snapshot 早返分支：
```go
if snapshot == nil || snapshot.Summary.Total == 0 {
    atomic.AddInt64(&h.cachedSnapshotEmptySkips, 1)
    return nil
}
```

> 选用 atomic int64 + `Stats()` 而不是 prometheus，**与 hub 现有指标风格一致**（见 commit `2026-07-03` 的注释 L226）。prometheus 留作后续增强，本轮不做。

```go
func getDurationEnv(key string, def time.Duration) time.Duration {
    v := os.Getenv(key)
    if v == "" {
        return def
    }
    d, err := time.ParseDuration(v)
    if err != nil || d <= 0 {
        slog.Warn("invalid duration env, using default", "key", key, "value", v, "default", def.String())
        return def
    }
    return d
}
```

## 行为不变性

- ✅ `computeScopeDelta` 仍然**不覆盖 cache 为空 snapshot**（早返保护不变）
- ✅ Redis 错误时**仍然 return nil**（仅刷新 lastAccessed）
- ✅ `evictStaleCachedSnapshots` 的淘汰语义不变（按 `lastAccessed` vs TTL）
- ✅ Ticker 周期默认与 TTL 一致，旧部署行为完全无变化
- ✅ 当用户**配置** TTL 时，cleanup interval 默认跟随 TTL（向后兼容），也可独立放宽
